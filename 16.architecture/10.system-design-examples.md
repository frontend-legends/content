# Примеры системного дизайна

Теория [RADIO](/content/architecture/frontend-system-design) оживает на задачах. Разберём три классические задачи фронтенд-собеса, применяя фреймворк. Цель - показать **ход мысли**, а не дать единственно верный ответ.

---

## Пример 1: Автокомплит (typeahead)

Самая частая задача. Поле поиска с подсказками по мере ввода.

**R — Requirements.** Подсказки по мере набора, быстро, с клавиатурной навигацией. Уточнить: сколько подсказок, нужна ли подсветка, мобайл, масштаб?

**A — Architecture.**

```
SearchAutocomplete
├── Input (управляемый, debounced)
├── SuggestionsList
│   └── SuggestionItem
└── useSearch (слой данных: запрос + кеш)
```

**D — Data model.** Текущий запрос, список подсказок, кеш `query → results`, индекс активной подсказки (для клавиатуры).

**I — Interface.** `GET /search?q=term` → массив подсказок. Запрос **дебаунсится**.

**O — Optimizations.**

- **Debounce** ввода (~300мс) - не слать запрос на каждую букву.
- **Отмена гонок** - игнорировать ответ устаревшего запроса (флаг/`AbortController`), иначе старый ответ перезатрёт новый.
- **Кеш по запросу** - повторный ввод отдаёт мгновенно.
- **Клавиатура** - стрелки/Enter/Esc; **a11y** - ARIA combobox (`aria-expanded`, `aria-activedescendant`).
- **Краевые случаи** - минимум символов, состояния загрузки/пусто/ошибка.

<b class="text-on-semi-light">Что тут проверяют</b> - <span class="text-gray">Debounce + отмена гонок + кеш + доступность - джентльменский набор. Гонки запросов ([эффекты](/content/reactjs/effects-and-synchronization)) - любимая ловушка: без отмены подсказки «прыгают».</span>

## Пример 2: Новостная лента (бесконечный скролл)

Лента постов с бесконечной прокруткой, лайками, комментариями.

**R — Requirements.** Лента постов, подгрузка при скролле, лайк/коммент. Уточнить: реалтайм-обновления? медиа? масштаб ленты?

**A — Architecture.**

```
Feed
├── FeedList (бесконечный скролл)
│   └── PostCard (контент, лайк, комменты)
├── Composer (новый пост)
└── useFeed (пагинация + кеш)
```

**D — Data model.** **Нормализованные** посты (`{ id: post }`), порядок - массив id, курсор пагинации. Нормализация важна: один пост может встречаться в нескольких местах.

**I — Interface.** **Курсорная** пагинация: `GET /feed?cursor=X&limit=20` (курсор стабильнее offset при вставках). Лайк: `POST /posts/:id/like`.

**O — Optimizations.**

- **Бесконечный скролл** через `IntersectionObserver` (sentinel внизу), не scroll-событие.
- **Виртуализация** - рендерить только видимые посты, иначе тысячи узлов тормозят.
- **Оптимистичные лайки** - обновить UI сразу, откатить при ошибке.
- **Кеш** stale-while-revalidate, lazy-load изображений.
- **Краевые случаи** - конец ленты, ошибка догрузки (retry), пустая лента.

## Пример 3: Чат

Мессенджер: список диалогов, сообщения в реальном времени.

**R — Requirements.** Реалтайм-сообщения, список диалогов, история, индикатор присутствия. Уточнить: группы? вложения? масштаб?

**A — Architecture.**

```
Chat
├── ConversationList
├── MessageList (история + новые)
├── MessageInput
└── useChat (WebSocket + история)
```

**D — Data model.** Сообщения **по диалогам** (нормализовано), статусы (отправляется/доставлено), курсор истории.

**I — Interface.** **WebSocket** для реалтайма (входящие/исходящие, presence) + **REST** для истории (`GET /conversations/:id/messages?before=...`). Разделение: live-канал и подгрузка прошлого.

**O — Optimizations.**

- **WebSocket с переподключением** ([реалтайм](/content/ecosystem-libs/realtime-and-api-clients)); fallback при разрыве.
- **Оптимистичная отправка** - показать сообщение сразу со статусом «отправляется».
- **Пагинация истории вверх** (обратная) с сохранением позиции скролла.
- **Офлайн-очередь** - копить неотправленное, дослать при реконнекте.
- **Краевые случаи** - дубликаты сообщений, порядок, ошибки доставки.

## Пример 4: Виртуализированная таблица данных

Таблица на десятки тысяч строк с сортировкой и фильтрацией.

**R — Requirements.** Объём данных? Сорт/фильтр на клиенте или сервере? Редактирование? Закреплённые колонки?

**A — Architecture.** `Table → Header (сортировка) → VirtualizedRows → Row`; headless-логика отдельно от рендера.

**D — Data model.** Видимый диапазон строк, состояние сортировки/фильтров, кеш страниц.

**I — Interface.** При больших данных - **серверные** сорт/фильтр/пагинация (`?sort=&filter=&page=`); фронт лишь шлёт параметры.

**O — Optimizations.** **Виртуализация** (рендерим ~20 видимых строк), мемоизация ячеек, дебаунс фильтра, закреплённые колонки, доступность таблицы (роли/навигация). Клиентская обработка - до тысяч строк; дальше - сервер.

## Пример 5: Доступный Select / Combobox

Кастомный выпадающий список с поиском - проверка глубины по доступности.

**R — Requirements.** Одиночный/множественный выбор? Поиск? Асинхронные опции?

**A — Architecture.** `Trigger + Popover(список) + поиск`; **headless** (логика отдельно от стилей).

**O — Optimizations.** **Доступность - ядро задачи:** ARIA combobox (`role`, `aria-expanded`, `aria-activedescendant`), полная клавиатура (стрелки/Enter/Esc/Home/End/typeahead), управление фокусом, позиционирование (Floating UI - не вылезать за экран), виртуализация длинных списков, асинхронная загрузка опций с дебаунсом.

<b class="text-on-semi-light">Что проверяют</b> - <span class="text-gray">Насколько глубоко ты знаешь доступность. Кастомный select - любимый дифференциатor senior: «собрать дропдаун» легко, «собрать **доступный** дропдаун» - это десятки деталей ARIA и клавиатуры.</span>

## Общий чеклист

По любой задаче пройдись по осям (даже кратко):

```
[ ] Уточнил требования и скоуп (R)
[ ] Разбил на компоненты + поток данных (A)
[ ] Форма состояния, нормализация (D)
[ ] API: пагинация/реалтайм, контракт (I)
[ ] Производительность: виртуализация, мемоизация, бандл
[ ] Сеть: debounce, отмена гонок, кеш, оптимизм
[ ] Доступность: клавиатура, ARIA, фокус
[ ] Состояния: загрузка, ошибка, пусто, оффлайн
[ ] Проговорил компромиссы выбора
```

## Вопросы на собеседовании

<b class="text-on-semi-light">Как спроектировать автокомплит?</b>
<span class="text-gray">Input + список подсказок + слой данных. Ключевое: debounce ввода, отмена устаревших запросов (гонки), кеш по запросу, клавиатурная навигация и ARIA combobox, состояния загрузки/пусто.</span>

<b class="text-on-semi-light">Бесконечный скролл - как реализовать правильно?</b>
<span class="text-gray">`IntersectionObserver` на sentinel внизу (не scroll-событие), курсорная пагинация, виртуализация для производительности, оптимистичные действия, обработка конца ленты и ошибок догрузки.</span>

<b class="text-on-semi-light">Offset или cursor пагинация?</b>
<span class="text-gray">Cursor стабильнее при вставках/удалениях (offset «съезжает», дублирует/пропускает элементы при изменении данных между страницами). Для лент предпочтителен курсор.</span>

<b class="text-on-semi-light">Как спроектировать чат?</b>
<span class="text-gray">WebSocket для реалтайма + REST для истории, нормализованные сообщения по диалогам, оптимистичная отправка со статусами, обратная пагинация истории с сохранением скролла, переподключение и офлайн-очередь.</span>

<b class="text-on-semi-light">Зачем отмена гонок в автокомплите?</b>
<span class="text-gray">Быстрый набор шлёт несколько запросов; ответ на старый может прийти позже нового и перезатереть подсказки. Отмена (флаг/AbortController) игнорирует устаревший ответ.</span>
