# Браузерное хранилище

Браузер предоставляет несколько механизмов для хранения данных на стороне клиента. На собеседовании тебя могут спросить «где хранить токен?», «чем cookies отличаются от localStorage?» или «когда использовать IndexedDB?». Разберём каждый механизм, его ограничения и подводные камни.

> Тема тесно связана с [Аутентификацией](/content/network-api/auth) (где хранить токены) и [Кэшированием](/content/network-api/caching) (Cache API для offline).

---

## Cookies

<b class="text-on-semi-light">Самый старый механизм хранения</b>

<span class="text-gray">Cookies были придуманы для обмена состоянием между клиентом и сервером. Главное отличие от остальных хранилищ - cookies автоматически отправляются с каждым HTTP-запросом к серверу (если домен и path совпадают).</span>

### Ограничения

- Размер одной cookie - **~4 KB**
- Количество cookies на домен - **~50** (зависит от браузера)
- Отправляются с **каждым** запросом - увеличивают размер заголовков

### Атрибуты cookies

| Атрибут               | Назначение                                                              |
| --------------------- | ----------------------------------------------------------------------- |
| `HttpOnly`            | Cookie недоступна из JS (`document.cookie`). Защита от XSS              |
| `Secure`              | Отправляется только по HTTPS                                            |
| `SameSite`            | Контролирует отправку при cross-site запросах (`Strict`, `Lax`, `None`) |
| `Expires` / `Max-Age` | Время жизни. Без них - session cookie (удаляется при закрытии браузера) |
| `Domain`              | На какие домены распространяется                                        |
| `Path`                | На какие пути распространяется                                          |

```js
// Установка cookie из JS (без HttpOnly)
document.cookie = "theme=dark; path=/; max-age=31536000; Secure; SameSite=Lax";

// Чтение всех cookies
console.log(document.cookie); // "theme=dark; lang=ru"

// Удаление - установить max-age=0
document.cookie = "theme=; max-age=0";
```

<span class="text-gray">На практике cookies чаще устанавливаются сервером через заголовок `Set-Cookie`. Для auth-токенов всегда используй `HttpOnly` + `Secure` + `SameSite=Strict`.</span>

## localStorage

<b class="text-on-semi-light">Простое key-value хранилище без срока годности</b>

<span class="text-gray">Данные сохраняются между сессиями (даже после закрытия браузера) и доступны всем вкладкам одного origin. API синхронный - вызовы блокируют main thread.</span>

- Размер: **5–10 MB** (зависит от браузера)
- Хранит только **строки** (объекты нужно сериализовать)
- **Не отправляется** на сервер автоматически
- **Синхронный** API - избегай хранения больших объёмов
- Доступен только из main thread (не из Web Worker)

```js
// Запись
localStorage.setItem("user", JSON.stringify({ name: "Alex", role: "dev" }));

// Чтение
const user = JSON.parse(localStorage.getItem("user"));

// Удаление
localStorage.removeItem("user");

// Очистка всего хранилища
localStorage.clear();

// Слушаем изменения из других вкладок
window.addEventListener("storage", (e) => {
  console.log(`${e.key}: ${e.oldValue} -> ${e.newValue}`);
});
```

<span class="text-gray">Событие `storage` срабатывает только в **других** вкладках того же origin - удобно для синхронизации состояния.</span>

## sessionStorage

<b class="text-on-semi-light">Как localStorage, но привязано к вкладке</b>

<span class="text-gray">API идентичен localStorage. Ключевое отличие - данные привязаны к конкретной вкладке (tab/window) и очищаются при её закрытии.</span>

- Размер: **5–10 MB**
- Данные **не расшаряются** между вкладками
- Очищается при закрытии вкладки
- При дупликации вкладки (`Ctrl+Shift+T`, «Дублировать вкладку») данные **копируются**

```js
// API идентичен localStorage
sessionStorage.setItem("form-draft", JSON.stringify(formData));
const draft = JSON.parse(sessionStorage.getItem("form-draft"));
```

<span class="text-gray">Типичное применение: черновики форм, временные фильтры, состояние wizard-а - всё, что не нужно после закрытия вкладки.</span>

## IndexedDB

<b class="text-on-semi-light">Полноценная клиентская база данных</b>

<span class="text-gray">IndexedDB - асинхронное хранилище для больших объёмов структурированных данных. Поддерживает транзакции, индексы и хранение бинарных данных (Blob, ArrayBuffer). Доступна из Web Worker и Service Worker.</span>

- Размер: **сотни MB** (браузер может запросить разрешение)
- **Асинхронный** API (на основе событий или через обёртки с Promise)
- Хранит **структурированные данные** (объекты, массивы, Blob, File)
- Поддерживает **транзакции** и **индексы** для быстрого поиска
- Доступна из **Worker** и **Service Worker**

```js
// Открытие/создание БД
const request = indexedDB.open("myApp", 1);

request.onupgradeneeded = (e) => {
  const db = e.target.result;
  // Создаём object store (аналог таблицы)
  const store = db.createObjectStore("users", { keyPath: "id" });
  store.createIndex("email", "email", { unique: true });
};

request.onsuccess = (e) => {
  const db = e.target.result;

  // Запись
  const tx = db.transaction("users", "readwrite");
  tx.objectStore("users").put({ id: 1, name: "Alex", email: "alex@dev.io" });

  // Чтение
  const readTx = db.transaction("users", "readonly");
  const getReq = readTx.objectStore("users").get(1);
  getReq.onsuccess = () => console.log(getReq.result);
};
```

<span class="text-gray">Нативный API IndexedDB многословен. На практике используют обёртки: **idb** (от Jake Archibald) или **Dexie.js** - они оборачивают API в промисы и делают код читаемым.</span>

```js
// С библиотекой idb (Promise-based)
import { openDB } from "idb";

const db = await openDB("myApp", 1, {
  upgrade(db) {
    db.createObjectStore("users", { keyPath: "id" });
  },
});

await db.put("users", { id: 1, name: "Alex" });
const user = await db.get("users", 1);
```

## Cache API

<b class="text-on-semi-light">Хранилище HTTP-ответов для offline и ускорения</b>

<span class="text-gray">Cache API хранит пары Request/Response. Основной инструмент Service Worker для offline-режима и кэширования ресурсов. Доступен и из main thread.</span>

- Хранит **Request/Response** пары
- Размер: **ограничен квотой origin** (обычно значительная доля диска)
- **Асинхронный** API (Promise-based)
- Основное применение - [PWA](/content/web/pwa) и offline

```js
// Кэширование ресурсов
const cache = await caches.open("static-v1");
await cache.addAll(["/index.html", "/styles.css", "/app.js"]);

// Получение из кэша
const response = await caches.match("/index.html");

// В Service Worker - стратегия cache-first
self.addEventListener("fetch", (e) => {
  e.respondWith(
    caches.match(e.request).then((cached) => cached || fetch(e.request)),
  );
});
```

## Сравнительная таблица

| Хранилище          | Размер       | Persistence             | Sync/Async | Worker | На сервер          |
| ------------------ | ------------ | ----------------------- | ---------- | ------ | ------------------ |
| **Cookies**        | ~4 KB        | Настраивается (Expires) | Sync       | Нет    | Да (автоматически) |
| **localStorage**   | 5–10 MB      | Постоянно               | Sync       | Нет    | Нет                |
| **sessionStorage** | 5–10 MB      | До закрытия вкладки     | Sync       | Нет    | Нет                |
| **IndexedDB**      | Сотни MB     | Постоянно               | Async      | Да     | Нет                |
| **Cache API**      | Квота origin | Постоянно               | Async      | Да     | Нет                |

## Безопасность хранилищ

<b class="text-on-semi-light">Что нельзя хранить в localStorage/sessionStorage</b>

<span class="text-gray">localStorage и sessionStorage доступны из **любого JS-кода** на странице. Если на сайте есть XSS-уязвимость, атакующий получит доступ ко всему содержимому этих хранилищ.</span>

- **Не храни** access/refresh токены в localStorage - XSS позволяет их украсть
- **Не храни** персональные данные (PII) в открытом виде
- Для auth-токенов используй **HttpOnly cookies** - JS не имеет к ним доступа

| Подход                  | XSS-устойчивость | CSRF-устойчивость             |
| ----------------------- | ---------------- | ----------------------------- |
| Токен в localStorage    | Уязвим           | Устойчив                      |
| Токен в HttpOnly cookie | Устойчив         | Требует SameSite / CSRF-token |

> Подробнее о стратегиях хранения токенов - [Аутентификация](/content/network-api/auth).

<b class="text-on-semi-light">Очистка хранилищ браузером</b>

<span class="text-gray">Браузеры могут удалить данные из IndexedDB, Cache API и localStorage при нехватке места (eviction). Данные, сохранённые через `navigator.storage.persist()`, получают приоритет и не удаляются автоматически.</span>

```js
// Запрос на persistent storage
if (navigator.storage && navigator.storage.persist) {
  const granted = await navigator.storage.persist();
  console.log(granted ? "Persistent" : "Best-effort");
}

// Проверка квоты
const estimate = await navigator.storage.estimate();
console.log(`Used: ${estimate.usage}, Quota: ${estimate.quota}`);
```

## Типичные вопросы на собеседовании

> **Где хранить JWT-токен?**
> Лучший вариант - HttpOnly cookie с `Secure` и `SameSite=Strict`. localStorage уязвим к XSS. Если всё же хранишь в памяти (переменная) - токен теряется при перезагрузке.

> **В чём разница между localStorage и sessionStorage?**
> Одинаковый API, но sessionStorage привязан к вкладке и очищается при её закрытии. localStorage расшарен между вкладками и хранится постоянно.

> **Когда использовать IndexedDB вместо localStorage?**
> Когда нужно хранить большие объёмы данных, структурированные объекты, бинарные файлы, или когда важна асинхронность (чтобы не блокировать UI). Также IndexedDB доступна из Web Worker.
