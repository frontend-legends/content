# Безопасность и производительность

Две дисциплины, которые отличают зрелого инженера: приложение должно быть **защищённым** (нельзя украсть данные пользователей) и **быстрым** (иначе пользователи уходят). Обе - сквозные: они касаются каждой части фронтенда и обе любят на senior-собеседованиях.

Это **главный справочник** по обеим темам: где другие главы говорят «подробнее - в безопасности и производительности», имеется в виду именно эта глава.

---

## Зачем это критично

- **Безопасность** - цена ошибки максимальна: утечка данных, угон аккаунтов, репутация, штрафы. Фронтенд - часть поверхности атаки.
- **Производительность** - прямой бизнес-импакт: каждые лишние 100мс загрузки снижают конверсию; скорость влияет на SEO, удержание, доход.
- Обе **сквозные** - не «фича», а свойство всей системы, которое нужно закладывать с самого начала.

## Два принципа

> **Безопасность:** не доверяй никакому вводу и никогда не полагайся на клиент. Всё, что приходит извне (пользователь, сеть), - потенциально враждебно; защиту строят слоями (defense in depth).

> **Производительность:** сначала измерь, потом оптимизируй. Интуиция обманывает; оптимизация без профайлинга - угадывание. И главное - оптимизируй по **полевым** данным реальных пользователей.
