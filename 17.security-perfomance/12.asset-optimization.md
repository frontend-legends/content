# Оптимизация ассетов

Ассеты - изображения, шрифты, JS, CSS, видео - обычно составляют **основной вес** страницы. Изображения и JavaScript чаще всего доминируют. Оптимизация ассетов даёт самый прямой выигрыш в скорости загрузки.

---

## Изображения

Часто **самый тяжёлый** ресурс на странице. Рычаги:

### Современные форматы

```
JPEG/PNG  →  WebP (на ~30% легче)  →  AVIF (ещё легче)
```

WebP и AVIF дают то же качество при меньшем весе. Отдавать с fallback через `<picture>`.

### Адаптивные изображения

Не грузить десктопную картинку на телефон. `srcset`/`sizes` дают браузеру выбрать нужный размер:

```html
<img
  srcset="small.webp 400w, large.webp 1200w"
  sizes="(max-width: 600px) 400px, 1200px"
  src="large.webp" width="1200" height="800" alt="...">
```

### Прочее

- **`loading="lazy"`** для изображений ниже сгиба.
- **`width`/`height`** или `aspect-ratio` - резервируют место, убирают [CLS](/content/security-perfomance/core-web-vitals).
- **`fetchpriority="high"`** для LCP-изображения; его **не** лениво.
- **SVG** для иконок и логотипов (вектор, масштабируется, лёгок).
- **Image CDN** (Cloudinary, imgix, встроенные в Vercel/Next) - ресайз, конвертация, кеш «на лету».

## Шрифты

Шрифты блокируют отрисовку текста и весят немало.

| Приём | Зачем |
|-------|-------|
| **WOFF2** | самый сжатый формат шрифтов |
| **Subsetting** | включить только нужные глифы (например, латиница+кириллица) |
| **`font-display: swap`** | показать текст системным шрифтом, пока грузится свой (нет невидимого текста / FOIT) |
| **preload** критичных шрифтов | загрузить раньше, меньше сдвигов |
| **Variable fonts** | один файл вместо нескольких начертаний |

<b class="text-on-semi-light">FOIT vs FOUT</b> - <span class="text-gray">**FOIT** (Flash of Invisible Text) - текст невидим, пока грузится шрифт; плохо. **FOUT** (Flash of Unstyled Text) - текст виден сразу системным шрифтом, потом заменяется. `font-display: swap` выбирает FOUT - пользователь сразу читает контент. Это и про скорость, и про CLS (если метрики шрифтов сильно различаются - возможен сдвиг, помогает `size-adjust`).</span>

> Самостоятельный хостинг шрифтов часто быстрее и приватнее, чем сторонний (Google Fonts) - нет лишнего соединения к чужому домену.

## JS и CSS

Код - второй главный источник веса.

- **Минификация + tree-shaking** - убрать пробелы и неиспользуемое ([оптимизация сборки](/content/advanced-tooling/optimization)).
- **Code splitting** - грузить только нужное для текущей страницы ([бандлеры](/content/advanced-tooling/bundlers)).
- **Удаление неиспользуемого CSS** - большие CSS-фреймворки тянут лишнее; Tailwind/PurgeCSS оставляют только используемое.
- **Анализ бандла** - найти, что раздувает (rollup-plugin-visualizer): дубли, тяжёлые зависимости, не сработавший tree-shaking.

---

## Видео

- **Не автозагружать** тяжёлое видео; `preload="none"` + `poster` (превью).
- Современные кодеки, адаптивный стриминг (HLS) для длинного видео ([медиа](/content/additional-topics/media-and-webrtc)).
- Короткие зацикленные анимации - видео/`<picture>` вместо тяжёлых GIF.

## Где самый большой выигрыш

<b class="text-on-semi-light">Приоритеты</b> - <span class="text-gray">Не оптимизируй всё подряд - начни с **самого тяжёлого**. Обычно это **изображения** (форматы + размеры + lazy) и **JavaScript** (splitting + tree-shaking). Анализ бандла и аудит изображений показывают, где реальный вес. Сэкономить 500КБ на главной картинке важнее, чем 5КБ на иконке.</span>

## Вопросы на собеседовании

<b class="text-on-semi-light">Как оптимизировать изображения?</b>
<span class="text-gray">Современные форматы (WebP/AVIF), адаптивные размеры (srcset/sizes), lazy-load ниже сгиба, заданные размеры против CLS, fetchpriority для LCP-картинки, SVG для иконок, image CDN.</span>

<b class="text-on-semi-light">Что делает font-display: swap?</b>
<span class="text-gray">Показывает текст системным шрифтом, пока грузится кастомный (FOUT), вместо невидимого текста (FOIT). Пользователь сразу читает контент. Плюс subsetting, WOFF2, preload критичных шрифтов.</span>

<b class="text-on-semi-light">Чем FOIT отличается от FOUT?</b>
<span class="text-gray">FOIT - текст невидим до загрузки шрифта (плохо). FOUT - виден сразу системным, потом заменяется. `font-display: swap` выбирает FOUT; предпочтительнее для скорости восприятия.</span>

<b class="text-on-semi-light">Как уменьшить вес JS?</b>
<span class="text-gray">Минификация, tree-shaking, code splitting (грузить нужное для страницы), удаление неиспользуемого CSS, анализ бандла для поиска тяжёлых зависимостей и дублей.</span>

<b class="text-on-semi-light">С чего начать оптимизацию ассетов?</b>
<span class="text-gray">С самого тяжёлого - обычно изображения и JavaScript. Аудит изображений и анализ бандла показывают реальный вес; экономия на главной картинке важнее микрооптимизаций.</span>
