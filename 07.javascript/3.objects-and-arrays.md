# Объекты и массивы

Как устроены объекты и массивы, как их копировать, обновлять без побочных эффектов и когда вместо объекта брать `Map` и `Set`. Спрашивают разницу поверхностной и глубокой копии, мутирующие методы массивов и деструктуризацию. Глубже — почему объект как ключ превращается в `'[object Object]'`, в каком порядке идут ключи, что теряет `structuredClone` и почему `[10, 9, 1].sort()` даёт `[1, 10, 9]`.

::tldr
- **Объект — набор свойств с ключами-строками и символами.** Любой другой ключ приводится к строке, поэтому объект в роли ключа превращается в `'[object Object]'`. Для ключей любого типа есть `Map`.
- **Массив — объект с числовыми ключами и `length`.** В нём бывают дырки, `sort` по умолчанию сравнивает строки, а мутирующие методы (`sort`, `reverse`, `splice`) меняют исходный массив. Их копии без мутации — `toSorted`, `toReversed`, `toSpliced`, `with`.
- **Spread и `Object.assign` копируют один уровень.** Вложенные объекты остаются общими. Глубокую копию делает `structuredClone`: он понимает `Date`, `Map` и циклы, но не копирует функции и теряет классы.
- **Деструктуризация подставляет значение по умолчанию только вместо `undefined`.** `null` проходит как есть.
- **`Map` — для словарей с произвольными ключами и частыми изменениями, `Set` — для уникальных значений.** Оба сравнивают ключи как `===`, но считают `NaN` равным себе.
::

## Объект — это словарь свойств

Сквозной пример — корзина магазина:

```js
const cart = {
  id: 7,
  items: [
    { sku: 'tea', title: 'Чай', price: 490, qty: 2 },
    { sku: 'pot', title: 'Чайник', price: 2490, qty: 1 },
  ],
  promo: null,
};
```

Объект — набор свойств: пар «ключ — значение». Ключ может быть только **строкой или символом**. Всё остальное приводится к строке:

```js
cart[1] = 'x';
cart['1'];                 // 'x' — число стало строкой

const seen = {};
seen[userA] = 'first';
seen[userB] = 'second';
Object.keys(seen);         // ['[object Object]'] — оба объекта стали одним ключом
```

Отсюда классический баг: попытка использовать объект как словарь для объектов. Второй пользователь затирает первого, потому что оба превращаются в строку `'[object Object]'`. Для таких ключей нужен `Map` (о нём ниже).

### Порядок ключей

Свойства объекта упорядочены, но не совсем в порядке добавления:

1. сначала ключи, похожие на неотрицательные целые числа, — по возрастанию;
2. потом остальные строки — в порядке добавления;
3. потом символы — в порядке добавления.

```js
const o = { b: 1, 10: 1, a: 1, 2: 1, '-1': 1 };
Object.keys(o);   // ['2', '10', 'b', 'a', '-1']
```

Если ключи — id товаров вида `101`, `7`, `42`, объект выдаст их отсортированными, а не в порядке добавления. `Map` хранит строго порядок вставки.

### `__proto__` — не обычный ключ

У обычного объекта есть унаследованный сеттер `__proto__`. Запись `obj['__proto__'] = value` не создаёт свойство, а меняет прототип объекта. Если ключи словаря приходят от пользователя (названия полей, теги), это дыра — так начинается :term[prototype pollution]{def="атака, при которой через ключ __proto__ меняют прототип всех объектов приложения"}. Безопасные варианты словаря: `Map` или объект без прототипа `Object.create(null)`, где `__proto__` — обычная строка. Прототипы — в [Прототипах и классах](/content/javascript/prototypes-and-classes).

Объект — это словарь. Массив — тоже объект, но со своими правилами.

## Массив — объект с length

Массив — объект, у которого ключи — индексы, а свойство `length` всегда на единицу больше наибольшего индекса. Отсюда поведение, которое удивляет:

- **`length` можно присвоить:** `arr.length = 1` обрезает массив, а запись `arr[4] = 'e'` в массив из одного элемента сделает `length` равным 5.
- **Бывают дырки** — индексы без значения. `[1, , 3]` и `Array(3)` содержат дырки, а не `undefined`. `forEach`, `map`, `filter` их пропускают, а `for...of` и spread видят как `undefined`. Поэтому `Array(3).map(() => 0)` не вызовет колбэк ни разу. Массив нужной длины создают через `Array.from({ length: 3 }, (_, i) => i)`.

### Мутирующие и немутирующие методы

Главное деление методов массива — меняют ли они исходный массив:

| Мутирующие | Немутирующие аналоги |
| --- | --- |
| `push`, `unshift` | `[...arr, x]`, `[x, ...arr]`, `concat` |
| `pop`, `shift`, `splice` | `slice`, `filter`, `toSpliced` |
| `sort` | `toSorted` |
| `reverse` | `toReversed` |
| `arr[i] = x` | `with(i, x)`, `map` |
| `fill`, `copyWithin` | `map`, `Array.from` |

Это важно везде, где важны ссылки: состояние React, кеш, история для отмены (подробно — в [State и событиях](/content/reactjs/state-and-events)). `toSorted`, `toReversed`, `toSpliced` и `with` появились именно для этого — раньше приходилось писать `[...arr].sort()`.

### sort

У `sort` две ловушки. Первая — он **мутирует** массив и возвращает тот же массив, а не копию. Вторая — без функции сравнения он **сравнивает строки**:

```js
[10, 9, 1, 100].sort();                 // [1, 10, 100, 9]
[10, 9, 1, 100].sort((a, b) => a - b);  // [1, 9, 10, 100]
```

Функция сравнения возвращает отрицательное число, если `a` должен идти раньше, положительное — если позже, и `0` — если они равны. Сортировка **стабильна**: равные элементы сохраняют исходный порядок. Поэтому сортировку по нескольким полям можно делать последовательно: сначала по второстепенному полю, потом по главному.

### Поиск и сравнение элементов

- `find`, `findIndex`, `findLast`, `findLastIndex` — по условию;
- `includes` — есть ли значение. Он находит `NaN` (`[NaN].includes(NaN)` — `true`), а `indexOf` — нет: первый сравнивает как :term[SameValueZero]{def="сравнение как ===, но NaN равен NaN; так сравнивают includes, Map и Set"}, второй — через `===`;
- `at(-1)` — последний элемент без `arr[arr.length - 1]`.

`reduce` без начального значения берёт первый элемент как аккумулятор и падает с `TypeError` на пустом массиве. Начальное значение передают всегда: `items.reduce((sum, i) => sum + i.price * i.qty, 0)`.

Обновлять данные без мутации — значит создавать новые объекты. Самый частый вопрос здесь — как копировать.

## Копирование

### Поверхностная копия

Spread и `Object.assign` копируют **один уровень**: создаётся новый объект, но вложенные объекты и массивы — те же ссылки.

```js
const draft = { ...cart };
draft.items[0].qty = 5;
cart.items[0].qty;            // 5 — массив items общий
```

Чтобы изменить вложенное значение без мутации, копируют каждый уровень по пути изменения:

```js
const next = {
  ...cart,
  items: cart.items.map((i) => (i.sku === 'tea' ? { ...i, qty: 5 } : i)),
};
```

Новыми оказываются только корзина, массив и изменённый товар. Остальные товары — те же объекты, и это правильно: так `memo` и сравнение по ссылке понимают, что изменилось.

У spread есть две тонкости. Свойства справа перезаписывают свойства слева, поэтому значения по умолчанию пишут первыми: `{ ...defaults, ...options }`. А геттер при копировании **вычисляется**: в копии будет значение, а не геттер.

### Глубокая копия

`structuredClone` копирует всю структуру: вложенные объекты, массивы, `Date`, `Map`, `Set`, `RegExp`, типизированные массивы и даже циклические ссылки. У него есть ограничения:

- **функции не копируются** — объект с методом вызывает `DataCloneError`;
- **классы теряются** — экземпляр `Money` станет обычным объектом без методов;
- геттеры, сеттеры, символьные ключи и дескрипторы свойств не переносятся.

Старый способ `JSON.parse(JSON.stringify(x))` теряет больше: свойства со значением `undefined` пропадают, `Date` становится строкой, `NaN` и `Infinity` — `null`, `Map` и `Set` — пустым объектом, а цикл бросает `TypeError`. Он годится только для данных, которые и так JSON.

Глубокое копирование — дорогая операция. В большинстве задач нужна не копия всего, а точечное обновление по пути, как выше.

## Деструктуризация

Деструктуризация достаёт значения из объектов и массивов в переменные:

```js
const { promo = 'нет', items: [firstItem, ...otherItems] } = cart;
const { qty = 1, title: name } = firstItem;   // переименование: title → name
```

Значение по умолчанию подставляется **только вместо `undefined`**. Если сервер прислал `qty: null`, переменная будет `null`:

```js
const { qty = 1 } = { qty: null };   // qty === null
```

Вложенная деструктуризация падает, если промежуточного объекта нет: `const { address: { city } } = {}` бросает `TypeError`. Защищаются значением по умолчанию на каждом уровне: `const { address: { city } = {} } = user`. В массивах можно пропускать элементы (`const [, second] = arr`) и обменивать значения без временной переменной: `[a, b] = [b, a]`.

Объекты хороши как записи с известными полями. Для словарей и множеств в языке есть отдельные коллекции.

## Map и Set

### Map вместо объекта-словаря

`Map` — словарь, где ключом может быть **что угодно**, включая объекты:

```js
const qtyBySku = new Map();
qtyBySku.set('tea', 2).set('pot', 1);

const notes = new Map();
notes.set(userA, 'постоянный клиент');   // объект — настоящий ключ
```

| | Объект | `Map` |
| --- | --- | --- |
| Ключи | строки и символы | любые значения |
| Порядок | целые по возрастанию, потом строки | порядок вставки |
| Размер | `Object.keys(o).length` | `map.size` |
| Унаследованные ключи | есть (`__proto__`, `toString`) | нет |
| Частые добавления и удаления | медленнее | оптимизирован |
| JSON | напрямую | через `Object.fromEntries` |

Объект — для записей с заранее известными полями и для JSON. `Map` — для словарей, где ключи приходят из данных. Сгруппировать массив можно в обе стороны: `Object.groupBy(items, (i) => i.category)` возвращает объект без прототипа, а `Map.groupBy` — `Map`.

### Set

`Set` хранит уникальные значения в порядке добавления. Самое частое применение — убрать дубликаты: `[...new Set(tags)]`. Сравнение — SameValueZero: как `===`, но `NaN` равен `NaN`, а `0` и `-0` — одно значение. Объекты сравниваются по ссылке, поэтому два одинаковых по содержимому объекта — два элемента.

У `Set` есть операции над множествами: `union`, `intersection`, `difference`, `symmetricDifference`, `isSubsetOf` и другие. Пересечение тегов двух товаров — `a.intersection(b)`, без ручных циклов.

### WeakMap и WeakSet

Слабые коллекции принимают в качестве ключей только объекты (и незарегистрированные символы) и не мешают сборщику мусора удалить ключ. Когда объект больше нигде не нужен, запись исчезает сама. Поэтому их используют для данных, привязанных к чужим объектам: кеш вычислений по объекту, метаданные DOM-узлов. Обойти такую коллекцию или узнать её размер нельзя — её содержимое зависит от сборщика мусора.

> Как сборщик мусора решает, что объект не нужен, и когда слабые ссылки спасают от утечек — в [Памяти и производительности](/content/javascript/memory-and-performance).

## Красные флаги в ответе

- **«Spread делает копию объекта».** Поверхностную: вложенные объекты остаются общими.
- **«Глубокая копия — `JSON.parse(JSON.stringify())`».** Он теряет `undefined`, `Date`, `Map`, `NaN` и падает на циклах. Есть `structuredClone`.
- **«`sort` сортирует числа».** Без функции сравнения он сравнивает строки и мутирует массив.
- **«Значение по умолчанию в деструктуризации защищает от `null`».** Только от `undefined`.
- **«Объект подойдёт как словарь для любых ключей».** Ключи приводятся к строкам, объект-ключ становится `'[object Object]'`, а `__proto__` меняет прототип. Для этого есть `Map`.

## Как спрашивают на собеседовании

::question
Чем поверхностная копия отличается от глубокой?

#answer
Поверхностная копирует только первый уровень: вложенные объекты остаются общими с оригиналом. Глубокая копирует все уровни. Поверхностная — spread и `Object.assign`, глубокая — `structuredClone`.

#more
`structuredClone` понимает `Date`, `Map`, `Set`, типизированные массивы и циклы, но бросает `DataCloneError` на функциях и превращает экземпляры классов в простые объекты. JSON-копия теряет ещё больше. На практике глубокая копия нужна редко: для обновления без мутации копируют только объекты на пути изменения, а остальные ссылки сохраняют — так сравнение по ссылке видит, что поменялось.
::

::question
Какие методы массивов мутируют исходный массив?

#answer
`push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`, `copyWithin`. Не мутируют `map`, `filter`, `reduce`, `slice`, `concat`, `flat` и новые `toSorted`, `toReversed`, `toSpliced`, `with`.

#more
Мутация важна там, где важны ссылки: состояние React, мемоизация, история для отмены. `sort` и `reverse` к тому же возвращают тот же массив, что создаёт иллюзию копии. `toSorted` и компания появились именно для неизменяемых обновлений, раньше писали `[...arr].sort()`. `sort` стабилен, поэтому многоуровневую сортировку можно делать последовательными проходами.
::

::question
Когда использовать Map вместо объекта?

#answer
Когда ключи — не строки (например, объекты), когда нужен размер и порядок вставки, когда ключи часто добавляются и удаляются. Объект — для записей с известными полями и для JSON.

#more
Объект приводит ключи к строкам, сортирует целочисленные ключи и наследует `__proto__`: запись по ключу из пользовательских данных может поменять прототип. `Map` хранит любые ключи в порядке вставки, без унаследованных свойств, и оптимизирован под частые изменения. Если словарь должен быть объектом (например, для JSON), его создают через `Object.create(null)`.
::

::question
Почему `[10, 9, 1, 100].sort()` даёт `[1, 10, 100, 9]`?

#answer
Без функции сравнения `sort` приводит элементы к строкам и сравнивает их как строки: `'10' < '9'`. Для чисел нужна функция `(a, b) => a - b`.

#more
Плюс `sort` мутирует массив и возвращает тот же массив. Функция сравнения возвращает знак: отрицательное — `a` раньше, положительное — позже, `0` — равны. Сортировка стабильна по спецификации, поэтому равные элементы сохраняют порядок. Для строк на разных языках нужен `localeCompare` или `Intl.Collator`, иначе сравнение идёт по кодам UTF-16.
::

::question
Как работает деструктуризация с вложенными объектами и значениями по умолчанию?

#answer
Каждый уровень разворачивают своими фигурными скобками: `const { data: { user: { name } } } = response`. Значение по умолчанию задают через `=`, переименование — через двоеточие: `{ name: userName = 'Гость' }`.

#more
Значение по умолчанию подставляется только вместо `undefined`, `null` проходит как есть. Если промежуточного объекта нет, вложенная деструктуризация бросает `TypeError`, поэтому на каждом уровне ставят `= {}`. Значение по умолчанию вычисляется лениво — только когда оно нужно.
::

::question
Что такое WeakMap и зачем он нужен?

#answer
`Map`, где ключи — только объекты, и эти ключи не мешают сборщику мусора. Если объект больше нигде не используется, запись исчезает сама. Применяют для кешей и метаданных, привязанных к чужим объектам.

#more
Поскольку содержимое зависит от сборщика мусора, `WeakMap` нельзя обойти и у него нет `size` — иначе результат был бы недетерминированным. Ключом могут быть объекты и незарегистрированные символы, но не примитивы. Если нужно знать, когда объект собран, есть `FinalizationRegistry`, но полагаться на момент сборки нельзя.
::

## Практика

::practice{title="Что выведет?"}
```js
const a = [10, 9, 1, 100];
const b = a.sort();
console.log(a === b, a);

console.log(Array(3).map(() => 'x'));
console.log([1, , 3].includes(undefined));

const { qty = 1 } = { qty: null };
console.log(qty);

const key = {};
const store = {};
store[key] = 'v';
console.log(Object.keys(store));
```

#solution
```text
true [ 1, 10, 100, 9 ]
[ <3 empty items> ]
true
null
[ '[object Object]' ]
```

- `sort` мутирует и возвращает тот же массив, а сравнивает по умолчанию строки.
- `Array(3)` — три дырки, и `map` их пропускает: колбэк не вызывается.
- `includes` видит дырку как `undefined`, в отличие от `forEach` и `map`.
- Значение по умолчанию подставляется только вместо `undefined`.
- Объект как ключ превращается в строку `'[object Object]'`.
::

::practice{title="Найди баг"}
Корзина хранит историю для кнопки «Отменить». После изменения количества и отмены корзина не возвращается к прошлому состоянию:

```js
const history = [];

function setQty(cart, sku, qty) {
  history.push({ ...cart });                    // сохранить прошлое состояние
  const item = cart.items.find((i) => i.sku === sku);
  item.qty = qty;
  return cart;
}

function undo() {
  return history.pop();
}
```

#solution
`{ ...cart }` — поверхностная копия: в истории лежит новый объект корзины, но массив `items` и товары в нём — те же. `item.qty = qty` меняет товар, на который ссылается и снимок в истории, поэтому «отменять» нечего.

Правильно — не мутировать, а создавать новую версию корзины. Тогда старая версия остаётся нетронутой и её можно хранить как есть:

```js
function setQty(cart, sku, qty) {
  history.push(cart);                            // старая версия не изменится
  return {
    ...cart,
    items: cart.items.map((i) => (i.sku === sku ? { ...i, qty } : i)),
  };
}
```

Новыми создаются только корзина, массив и изменённый товар, остальные товары переиспользуются. Копировать всю корзину через `structuredClone` перед каждым изменением тоже сработает, но дороже и ломает сравнение по ссылке.
::

::practice{title="Убери дубликаты"}
С сервера приходят товары, некоторые повторяются по `sku` (поздняя версия свежее). Верни список без дубликатов: порядок — по первому появлению, данные — из последней версии.

```js
const items = [
  { sku: 'tea', price: 490 },
  { sku: 'pot', price: 2490 },
  { sku: 'tea', price: 450 },
];
// ожидается: [{ sku: 'tea', price: 450 }, { sku: 'pot', price: 2490 }]
```

#solution
`Map` хранит ключи в порядке первой вставки, а повторный `set` по тому же ключу обновляет значение, не меняя позицию:

```js
function dedupeBySku(items) {
  const bySku = new Map();
  for (const item of items) bySku.set(item.sku, item);
  return [...bySku.values()];
}

dedupeBySku(items);
// [{ sku: 'tea', price: 450 }, { sku: 'pot', price: 2490 }]
```

Решение линейное. Вариант через `filter` и `findIndex` даёт квадратичную сложность, а объект вместо `Map` переупорядочит ключи, если `sku` окажутся числами.
::
