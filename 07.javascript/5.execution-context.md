# Контекст выполнения

Когда JavaScript запускает код, он не просто читает строки сверху вниз. Перед выполнением каждого фрагмента кода движок создаёт **Execution Context** - специальную структуру, которая описывает среду выполнения: какие переменные доступны, какое значение `this`, где искать внешние переменные. Понимание этого механизма - ключ к пониманию hoisting, scope, замыканий и `this`.

---

## Что такое Execution Context

Execution Context (контекст выполнения) - это абстрактная концепция, описывающая **окружение**, в котором JavaScript-код оценивается и выполняется.

### Три типа контекстов

| Тип                       | Когда создаётся                               | Что содержит                          |
| ------------------------- | --------------------------------------------- | ------------------------------------- |
| **Global EC**             | При запуске программы (один на всё приложение) | `window`/`globalThis`, глобальные var |
| **Function EC**           | При каждом вызове функции                      | Параметры, локальные переменные       |
| **Eval EC**               | При вызове `eval()` (не используй)            | Код внутри eval                       |

<span class="text-gray">В одной программе может быть один Global EC и множество Function EC. Каждый вызов функции - новый контекст, даже если функция та же самая. Контексты складываются в **Call Stack** (стек вызовов) - LIFO-структуру.</span>

```js
function first() {
  second();
  console.log('first');
}

function second() {
  console.log('second');
}

first();

// Call Stack:
// 1. [Global EC]
// 2. [Global EC] -> [first() EC]
// 3. [Global EC] -> [first() EC] -> [second() EC]
// 4. [Global EC] -> [first() EC]  (second завершился)
// 5. [Global EC]                   (first завершился)
```

## Фазы контекста выполнения

Каждый Execution Context проходит **две фазы**.

### 1. Creation Phase (фаза создания)

На этой фазе движок:

- Создаёт **Variable Environment** - регистрирует `var`-переменные (со значением `undefined`) и function declarations (целиком)
- Создаёт **Lexical Environment** - регистрирует `let`/`const` (в TDZ, без инициализации)
- Определяет значение **`this`**
- Устанавливает ссылку на **внешнее окружение** (outer environment)

### 2. Execution Phase (фаза выполнения)

Код выполняется строка за строкой. Переменные получают реальные значения, функции вызываются.

```js
console.log(a); // undefined (var - hoisted с undefined)
console.log(b); // ReferenceError (let - в TDZ)
console.log(greet); // function greet() {...} (hoisted целиком)

var a = 10;
let b = 20;

function greet() {
  return 'hello';
}

// Creation Phase для этого кода:
// a -> undefined (var hoisting)
// b -> <uninitialized> (TDZ)
// greet -> function greet() {...} (function hoisting)
```

## Variable Environment и Lexical Environment

Оба - это внутренние структуры контекста выполнения, которые хранят привязки переменных.

<b class="text-on-semi-light">Variable Environment</b> - хранит привязки `var` и `function`. Создаётся один раз для контекста и не меняется при входе в блоки.

<b class="text-on-semi-light">Lexical Environment</b> - хранит привязки `let`, `const` и `class`. При входе в блок (`if`, `for`, `{}`) создаётся **новый** Lexical Environment с ссылкой на внешний.

```js
function example() {
  var x = 1;  // Variable Environment (function scope)
  let y = 2;  // Lexical Environment (block scope)

  if (true) {
    var z = 3;  // Тот же Variable Environment (var не видит блоков)
    let w = 4;  // Новый Lexical Environment для блока if
    console.log(x, y, z, w); // 1, 2, 3, 4
  }

  console.log(x, y, z); // 1, 2, 3
  console.log(w);        // ReferenceError - w не существует здесь
}
```

## Scope

Scope (область видимости) определяет, **где переменная доступна** в коде.

### Глобальный scope

```js
var globalVar = 'global';     // window.globalVar (в браузере)
let globalLet = 'also global'; // НЕ попадает в window

function fn() {
  console.log(globalVar); // доступна
}
```

### Функциональный scope

```js
function outer() {
  var localVar = 'local';
  console.log(localVar); // 'local'
}

console.log(localVar); // ReferenceError
```

`var` ограничен **функцией**, а не блоком. Вот почему `var` внутри `if` или `for` доступен за их пределами:

```js
if (true) {
  var leaked = 'oops';
}
console.log(leaked); // 'oops' - var «утёк» из блока
```

### Блочный scope

```js
if (true) {
  let blockLet = 'block';
  const blockConst = 'also block';
}

console.log(blockLet);   // ReferenceError
console.log(blockConst); // ReferenceError
```

`let` и `const` ограничены **блоком** (`{}`). Это предсказуемее и безопаснее, чем `var`.

## Scope Chain

Когда JavaScript не находит переменную в текущем scope, он ищет её во **внешнем** scope, затем во внешнем внешнего - и так до глобального. Эта цепочка называется Scope Chain.

```js
const global = 'global';

function outer() {
  const outerVar = 'outer';

  function inner() {
    const innerVar = 'inner';
    console.log(innerVar);  // 'inner'   - найдена в inner scope
    console.log(outerVar);  // 'outer'   - найдена в outer scope
    console.log(global);    // 'global'  - найдена в global scope
  }

  inner();
}

outer();
```

```text
Scope Chain для inner():
[inner scope] -> [outer scope] -> [global scope]
```

<b class="text-on-semi-light">Ключевой момент:</b> Scope Chain определяется **местом объявления** функции (лексически), а не местом вызова. Это называется **lexical scoping** и это основа [замыканий](/content/javascript/closures).

```js
const x = 'global';

function foo() {
  console.log(x); // 'global' - определяется по месту объявления foo
}

function bar() {
  const x = 'bar-local';
  foo(); // 'global', а не 'bar-local'!
}

bar();
```

## Hoisting

Hoisting - это поведение, при котором объявления переменных и функций «поднимаются» в начало своего scope на фазе создания контекста.

### var

```js
console.log(x); // undefined (не ReferenceError!)
var x = 5;
console.log(x); // 5

// Движок видит это так:
// var x;           <- creation phase
// console.log(x);  <- undefined
// x = 5;           <- execution phase
// console.log(x);  <- 5
```

### function declaration

```js
greet(); // 'Hello!' - работает до объявления

function greet() {
  console.log('Hello!');
}
```

Function declarations поднимаются **целиком** - и имя, и тело функции.

### let и const - Temporal Dead Zone (TDZ)

```js
console.log(x); // ReferenceError: Cannot access 'x' before initialization

let x = 10;
```

`let` и `const` технически тоже hoisted (движок знает о них на creation phase), но они находятся в **Temporal Dead Zone** от начала scope до строки объявления. Обращение в TDZ вызывает ReferenceError.

```js
{
  // ---- TDZ для myVar начинается ----
  console.log(myVar); // ReferenceError
  // ---- TDZ для myVar продолжается ----
  let myVar = 42;
  // ---- TDZ для myVar закончилась ----
  console.log(myVar); // 42
}
```

### class

```js
const obj = new MyClass(); // ReferenceError - class в TDZ

class MyClass {
  constructor() {
    this.name = 'test';
  }
}
```

Классы ведут себя как `let` - находятся в TDZ до строки объявления.

### Таблица hoisting

| Объявление             | Hoisted? | Значение до объявления         |
| ---------------------- | -------- | ------------------------------ |
| `var x = 5`            | Да       | `undefined`                    |
| `function f() {}`      | Да       | Полноценная функция            |
| `let x = 5`            | Да (TDZ) | ReferenceError                 |
| `const x = 5`          | Да (TDZ) | ReferenceError                 |
| `class C {}`           | Да (TDZ) | ReferenceError                 |
| `const f = function()` | Да (TDZ) | ReferenceError (const в TDZ)   |

## this

`this` - ключевое слово, которое ссылается на **объект**, в контексте которого выполняется функция. Значение `this` определяется **в момент вызова**, а не объявления (кроме arrow functions).

### Default binding

```js
function showThis() {
  console.log(this);
}

showThis(); // window (в браузере, non-strict mode)
            // undefined (в strict mode)
```

В strict mode (`'use strict'` или ES-модули) `this` по умолчанию - `undefined`. Это защита от случайного изменения глобального объекта.

### Implicit binding

Когда функция вызывается как **метод объекта**, `this` ссылается на объект перед точкой.

```js
const user = {
  name: 'Alice',
  greet() {
    console.log(`Hi, I'm ${this.name}`);
  },
};

user.greet(); // "Hi, I'm Alice" - this = user
```

### Explicit binding - call, apply, bind

Можно **явно указать** значение `this`.

```js
function greet(greeting, punctuation) {
  console.log(`${greeting}, ${this.name}${punctuation}`);
}

const user = { name: 'Alice' };

// call - аргументы через запятую
greet.call(user, 'Hello', '!');     // "Hello, Alice!"

// apply - аргументы массивом
greet.apply(user, ['Hello', '!']);   // "Hello, Alice!"

// bind - возвращает новую функцию с привязанным this
const greetAlice = greet.bind(user, 'Hi');
greetAlice('?');                     // "Hi, Alice?"
```

| Метод   | Вызывает сразу? | Аргументы        | Возвращает         |
| ------- | ---------------- | ---------------- | ------------------ |
| `call`  | Да               | Через запятую    | Результат вызова   |
| `apply` | Да               | Массивом         | Результат вызова   |
| `bind`  | Нет              | Через запятую    | Новую функцию      |

<span class="text-gray">`bind` создаёт **новую функцию** с навсегда привязанным `this`. Повторный `bind` не переопределит первый. Также `call`/`apply` не могут изменить `this` у bind-функции.</span>

### new binding

Когда функция вызывается с `new`, создаётся **новый объект**, и `this` внутри конструктора ссылается на него.

```js
function User(name) {
  // this = {} (новый пустой объект)
  this.name = name;
  // return this (неявно)
}

const alice = new User('Alice');
console.log(alice.name); // 'Alice'
```

Что `new` делает под капотом:
1. Создаёт пустой объект `{}`
2. Устанавливает его `__proto__` на `Constructor.prototype`
3. Выполняет конструктор с `this` = новый объект
4. Возвращает этот объект (если конструктор не вернул другой объект явно)

### Arrow function - лексический this

Arrow function **не имеет своего `this`**. Она берёт `this` из окружающего лексического контекста (scope, в котором была создана).

```js
const user = {
  name: 'Alice',
  friends: ['Bob', 'Charlie'],

  showFriends() {
    // this = user (implicit binding)
    this.friends.forEach((friend) => {
      // Arrow function берёт this из showFriends -> user
      console.log(`${this.name} knows ${friend}`);
    });
  },
};

user.showFriends();
// "Alice knows Bob"
// "Alice knows Charlie"
```

Если бы вместо arrow function была обычная функция, `this` внутри `forEach` был бы `undefined` (strict mode) или `window`.

## Приоритет привязок this

Если несколько правил применимы, побеждает правило с **высшим приоритетом**.

| Приоритет | Тип привязки       | Пример                      | this =                       |
| --------- | ------------------ | --------------------------- | ---------------------------- |
| 1 (высш.) | Arrow function     | `() => {}`                  | Лексический (от родителя)    |
| 2         | `new`              | `new Foo()`                 | Новый объект                 |
| 3         | Explicit (`bind`)  | `fn.bind(obj)()`            | obj                          |
| 4         | Explicit (`call`)  | `fn.call(obj)`              | obj                          |
| 5         | Implicit           | `obj.method()`              | obj                          |
| 6 (низш.) | Default            | `fn()`                      | window / undefined           |

<span class="text-gray">Arrow function стоит первой, потому что её `this` нельзя переопределить ни `call`, ни `bind`, ни `new`. `new` побеждает `bind`: `new (fn.bind(obj))()` создаст новый объект, проигнорировав bind.</span>

## Потеря контекста

Одна из самых частых проблем в JS - функция «теряет» свой `this`.

### Ситуация 1 - передача метода как callback

```js
const user = {
  name: 'Alice',
  greet() {
    console.log(`Hi, ${this.name}`);
  },
};

setTimeout(user.greet, 1000); // "Hi, undefined" - this потерян!
```

Метод `greet` передаётся **как ссылка на функцию**, без привязки к `user`. Внутри `setTimeout` он вызывается как обычная функция -> default binding.

### Ситуация 2 - деструктуризация метода

```js
const { greet } = user;
greet(); // "Hi, undefined" - то же самое
```

### Решения

```js
// 1. bind
setTimeout(user.greet.bind(user), 1000);

// 2. Arrow function wrapper
setTimeout(() => user.greet(), 1000);

// 3. Стрелочный метод в классе (автоматически привязан)
class User {
  name = 'Alice';
  greet = () => {
    console.log(`Hi, ${this.name}`);
  };
}
```

<b class="text-on-semi-light">На фронте:</b> Потеря `this` особенно часто встречается в React class components при передаче methods как event handlers. Стрелочные методы в классах или `bind` в конструкторе решают проблему. В функциональных компонентах `this` не используется, поэтому проблема исчезает.

## Частые вопросы на собесе

**Что такое Execution Context?**
Это среда, в которой выполняется JS-код. Содержит Variable Environment (var, function), Lexical Environment (let, const), значение `this` и ссылку на внешнее окружение. Бывает глобальный, функциональный и eval.

**Как работает hoisting?**
На creation phase движок регистрирует объявления: `var` получает значение `undefined`, `function` поднимается целиком, `let`/`const` регистрируются, но остаются в TDZ (Temporal Dead Zone) до строки объявления. Обращение к переменной в TDZ вызывает ReferenceError.

**Объясни scope chain.**
Когда переменная не найдена в текущем scope, движок ищет её во внешнем scope, затем во внешнем внешнего - вплоть до глобального. Цепочка определяется лексически (по месту объявления функции), а не динамически (по месту вызова).

**Как определяется this?**
Пять правил в порядке приоритета: 1) Arrow function - лексический this. 2) `new` - новый объект. 3) `bind`/`call`/`apply` - явно указанный объект. 4) Метод объекта - объект перед точкой. 5) Обычный вызов - window/undefined.

**В чём разница между call, apply и bind?**
`call` вызывает сразу с аргументами через запятую. `apply` вызывает сразу с аргументами массивом. `bind` не вызывает, а возвращает новую функцию с навсегда привязанным `this`. Повторный `bind` не перезапишет первый.

**Что такое потеря контекста и как её избежать?**
Когда метод объекта передаётся как callback (например, в `setTimeout` или `addEventListener`), он теряет привязку к объекту. Решения: `bind`, обёртка в arrow function, стрелочный метод в классе.
