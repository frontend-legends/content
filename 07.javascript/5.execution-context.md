# Контекст выполнения и this

Что происходит, когда код начинает выполняться: откуда функция берёт переменные, почему `var` доступен до объявления, а `let` — нет, и чем определяется `this`. Спрашивают hoisting, TDZ и правила `this`. Глубже — что такое лексическое окружение, почему цепочка областей видимости определяется местом объявления, а не вызова, и что сильнее: `new` или `bind`.

::tldr
- **Каждый вызов функции создаёт контекст выполнения** со своим лексическим окружением: таблицей переменных и ссылкой на окружение, где функция была объявлена. Так строится цепочка областей видимости.
- **Объявления регистрируются до выполнения кода.** `var` получает `undefined`, объявление функции — готовую функцию, а `let`, `const` и `class` до своей строки находятся во временной мёртвой зоне: обращение бросает `ReferenceError`.
- **Цепочка областей видимости лексическая:** функция ищет переменные там, где написана, а не там, где вызвана.
- **`this` определяется способом вызова:** `new` — новый объект, `call`/`apply`/`bind` — указанный, метод — объект перед точкой, обычный вызов — `undefined` в strict mode. У стрелки своего `this` нет, она берёт его снаружи.
- **Метод, оторванный от объекта, теряет `this`:** колбэк, деструктуризация, `setTimeout`. Решения — `bind`, стрелка-обёртка или поле-стрелка в классе.
::

---

## Что такое контекст выполнения

Сквозной пример — модуль оформления заказа:

```js
const currency = '₽';

function format(value) {
  return `${value} ${currency}`;
}

const cart = {
  items: [{ title: 'Чай', price: 490 }],
  total() {
    return format(this.items.reduce((sum, i) => sum + i.price, 0));
  },
};

button.addEventListener('click', cart.total);   // сломается — разберём почему
```

Когда движок выполняет код, он держит **контекст выполнения** — служебную структуру, которая отвечает на вопросы «какие переменные видны?» и «чему равен `this`?». Контексты бывают трёх видов:

- **глобальный** — для скрипта или модуля, создаётся один раз;
- **функциональный** — новый на каждый вызов функции;
- **контекст `eval`** — для кода внутри `eval`.

Контексты складываются в **стек вызовов**: вызов функции кладёт её контекст наверх, возврат — снимает. Когда `total` вызывает `format`, сверху оказывается контекст `format`, под ним — `total`, ниже — глобальный. Тот же стек показывает :term[DevTools]{def="инструменты разработчика в браузере: элементы, сеть, производительность, отладчик"} в отладчике и в трассировке ошибки. Как стек связан с очередями задач — в [Event Loop](/content/javascript/event-loop).

### Лексическое окружение

Главная часть контекста — **лексическое окружение**. Это пара:

1. **запись окружения** — таблица имён и значений, объявленных в этой области: переменные, параметры, функции;
2. **ссылка на внешнее окружение** — то, в котором эта функция была **объявлена**.

У `format` внешнее окружение — модуль, где объявлен `currency`. Ссылку функция получает при создании и хранит всё время жизни. Когда `format` ищет `currency`, она сначала смотрит в своей записи, потом по ссылке во внешнем окружении и так далее до глобального. Эта цепочка и есть **цепочка областей видимости**.

У блоков (`{}`, `if`, `for`) тоже есть свои окружения — для `let`, `const` и `class`. У `var` их нет: `var` видит только функциональное и глобальное окружение.

Окружение создаётся при входе в функцию. Самое интересное происходит между созданием окружения и выполнением первой строки.

## Hoisting и временная мёртвая зона

Выполнение функции идёт в две фазы. Сначала движок **создаёт окружение** и регистрирует в нём все объявления области. Потом **выполняет код** строка за строкой. Поэтому объявления «поднимаются» (hoisting) — не физически, а в смысле «известны с самого начала»:

```js
console.log(typeof price, price);  // 'undefined' undefined
console.log(format(5));            // '5 ₽'

var price = 490;
function format(v) { return `${v} ₽`; }
```

Разные объявления регистрируются по-разному:

| Объявление | Что лежит в окружении до строки объявления |
| --- | --- |
| `function f() {}` | готовая функция — можно вызвать |
| `var x` | `undefined` |
| `let x`, `const x` | ничего: переменная во временной мёртвой зоне |
| `class C {}` | ничего: временная мёртвая зона |
| выражение `const f = () => {}` | как у `const` |

**Временная мёртвая зона** (TDZ) — время от входа в область до строки объявления `let`, `const` или `class`. Переменная уже зарегистрирована — поэтому внешняя переменная с тем же именем недоступна, — но не инициализирована. Любое обращение бросает `ReferenceError: Cannot access 'qty' before initialization`, даже `typeof`, который на необъявленной переменной молча возвращает `'undefined'`.

TDZ — понятие о **времени**, а не о месте в коде. Функция, объявленная выше `let limit`, может читать `limit`, если её **вызывают** после инициализации:

```js
function read() { return limit; }
let limit = 3;
read();   // 3 — к моменту вызова limit инициализирован
```

Зачем нужна TDZ: `undefined` у `var` до объявления скрывает ошибки порядка — код работает с пустым значением и падает где-то дальше. TDZ ломает такой код сразу и громко. А для `const` без неё нельзя было бы гарантировать, что переменная имеет ровно одно значение.

### Глобальная область

В классическом скрипте глобальные `var` и объявления функций становятся **свойствами глобального объекта** (`window` в браузере), а `let`, `const` и `class` — нет. Поэтому `var name` в скрипте конфликтует с `window.name`, а два скрипта на странице видят переменные друг друга. В модулях у каждого файла своя область, и в глобальный объект ничего не попадает. Ссылку на глобальный объект в любом окружении даёт `globalThis`.

Мы знаем, как функция находит переменные. Осталось понять, почему она ищет их именно там, где объявлена.

## Цепочка областей видимости — лексическая

Внешнее окружение функции задаётся местом **объявления**, а не вызова:

```js
const currency = '₽';
function format(v) { return `${v} ${currency}`; }

function invoice() {
  const currency = '$';
  return format(10);
}

invoice();   // '10 ₽'
```

`format` вызвана из `invoice`, где есть свой `currency`, но ищет переменную в окружении, где она написана, — в модуле. Это **лексическая** (статическая) область видимости: какие переменные видит функция, можно понять, просто прочитав код. В языках с динамической областью видимости результат зависел бы от того, кто вызвал функцию.

Если во внутренней области объявить переменную с тем же именем, она **затенит** внешнюю: внутри видна только своя, внешняя остаётся нетронутой.

Ссылка на внешнее окружение живёт вместе с функцией, даже когда внешняя функция уже завершилась. Это и делает возможными замыкания — им отдельная тема: [Замыкания](/content/javascript/closures).

Переменные функция ищет лексически. А вот `this` устроен ровно наоборот.

## this

`this` — не переменная из окружения, а значение, которое определяется **способом вызова** функции. Одна и та же функция при разных вызовах получает разный `this`.

### Четыре правила

**1. Вызов через `new`** — `this` — новый объект, который создаёт конструктор.

```js
function Item(title) { this.title = title; }
const tea = new Item('Чай');   // this — новый объект
```

**2. Явная привязка** — `call`, `apply` и `bind` задают `this` вручную:

```js
function label(prefix) { return `${prefix} ${this.title}`; }

label.call(tea, '—');          // вызвать сейчас, аргументы списком
label.apply(tea, ['—']);       // вызвать сейчас, аргументы массивом
const teaLabel = label.bind(tea, '—'); // новая функция с закреплённым this и аргументами
```

`bind` закрепляет `this` **навсегда**: повторный `bind` и `call` на привязанной функции ничего не меняют. Единственное, что сильнее, — `new`: вызов привязанной функции через `new` создаёт новый объект и игнорирует привязанный `this`, но сохраняет привязанные аргументы.

**3. Вызов как метода** — `this` — объект перед точкой: в `cart.total()` это `cart`.

**4. Обычный вызов** — `total()` без объекта перед точкой. В :term[strict mode]{def="строгий режим: вариант языка без опасных старых правил; включён в модулях и классах"} (модули, классы, `'use strict'`) `this` — `undefined`, в нестрогом коде — глобальный объект.

Приоритет: `new` > явная привязка > метод > обычный вызов.

### Стрелки

У стрелочной функции нет своего `this`. Она берёт `this` из окружения, где объявлена, как обычную переменную, и `call`, `apply`, `bind` его не меняют. Поэтому стрелка внутри метода видит `this` метода:

```js
const shop = {
  title: 'Магазин',
  later() {
    setTimeout(() => console.log(this.title), 100);   // 'Магазин'
  },
};
```

И поэтому стрелка **как метод** объектного литерала — ошибка: она берёт `this` окружения, где объявлен литерал (модуль или функция), а не самого объекта.

### Потеря контекста

Вернёмся к примеру из начала:

```js
button.addEventListener('click', cart.total);
```

`cart.total` — просто ссылка на функцию. Объект перед точкой важен только **в момент вызова**, а вызывает функцию браузер, и не как `cart.total()`. Для слушателей DOM браузер ставит `this` равным элементу, поэтому `this.items` — `undefined`, и `reduce` падает. То же с колбэком в `setTimeout`, `forEach`, промисах и с деструктуризацией метода: `const { total } = cart; total()`.

Решения:

```js
button.addEventListener('click', () => cart.total());   // стрелка вызывает метод на объекте
button.addEventListener('click', cart.total.bind(cart)); // закреплённый this
```

В классах тело всегда работает в strict mode, поэтому извлечённый метод получает `this === undefined` и падает с `Cannot read properties of undefined`. Частое решение — поле-стрелка:

```js
class Checkout {
  items = [];
  submit = () => {          // this закреплён за экземпляром
    send(this.items);
  };
}
```

Цена: поле-стрелка создаётся **для каждого экземпляра**, а обычный метод живёт один раз на прототипе. Для тысяч объектов это заметно, для компонента или сервиса в одном экземпляре — нет. Как устроены методы на прототипе — в [Прототипах и классах](/content/javascript/prototypes-and-classes).

## Красные флаги в ответе

- **«Hoisting физически переносит объявления наверх».** Код не двигается. Объявления регистрируются при создании окружения, до выполнения строк.
- **«`let` и `const` не поднимаются».** Поднимаются — регистрируются в окружении, но до инициализации находятся во временной мёртвой зоне. Поэтому внешняя переменная с тем же именем уже недоступна.
- **«Функция видит переменные того места, где её вызвали».** Область видимости лексическая: важно, где функция объявлена.
- **«`this` — это объект, в котором функция объявлена».** `this` определяется вызовом. У стрелки — окружением, но не объектным литералом.
- **«`bind` можно переопределить через `call`».** Привязанный `this` меняет только вызов через `new`.

## Как спрашивают на собеседовании

::question
Что такое контекст выполнения?

#answer
Служебная структура, в которой выполняется код: какие переменные видны и чему равен `this`. Есть глобальный контекст, контекст каждого вызова функции и контекст `eval`. Контексты складываются в стек вызовов.

#more
Главная часть контекста — лексическое окружение: запись окружения с объявленными именами и ссылка на внешнее окружение, где функция объявлена. Ссылку функция получает при создании, поэтому цепочка областей видимости определяется местом объявления. Блоки с `let`, `const` и `class` создают свои окружения, а `var` видит только функциональное и глобальное.
::

::question
Как работает hoisting?

#answer
Перед выполнением кода движок регистрирует все объявления области. `var` получает `undefined`, объявление функции — готовую функцию, поэтому её можно вызвать выше по коду. `let`, `const` и `class` до строки объявления находятся во временной мёртвой зоне.

#more
Выполнение идёт в две фазы: создание окружения с регистрацией объявлений и выполнение кода. Функциональное выражение и стрелка ведут себя как переменная, в которую их присвоили. В глобальной области скрипта `var` и объявления функций ещё и становятся свойствами глобального объекта, а `let` и `const` — нет. В модулях глобальный объект не затрагивается.
::

::question
Что такое временная мёртвая зона?

#answer
Время от входа в область до строки объявления `let`, `const` или `class`. Обращение к переменной в это время бросает `ReferenceError`, даже через `typeof`.

#more
Переменная уже зарегистрирована, но не инициализирована, поэтому внешняя переменная с тем же именем недоступна. TDZ про время, а не про место: функция, объявленная выше, может читать переменную, если её вызвали после инициализации. TDZ превращает ошибки порядка, которые `var` маскировал значением `undefined`, в явные исключения, и гарантирует единственное значение у `const`. Параметры функции тоже проходят через TDZ: значение по умолчанию не может ссылаться на следующий параметр.
::

::question
Объясни цепочку областей видимости.

#answer
Если переменной нет в текущей области, движок ищет её во внешней, потом во внешней внешней — до глобальной. Если не нашёл, `ReferenceError`.

#more
Цепочка лексическая: внешнее окружение функции — то, где она объявлена, а не то, откуда вызвана. Поэтому функция, вызванная из другой функции с переменной того же имени, всё равно видит свою. Ссылка на внешнее окружение живёт вместе с функцией, и это основа замыканий.
::

::question
Как определяется this?

#answer
По способу вызова. Через `new` — новый объект. Через `call`, `apply`, `bind` — указанный объект. Как метод — объект перед точкой. Обычный вызов — `undefined` в strict mode или глобальный объект в нестрогом. У стрелки своего `this` нет — она берёт его снаружи.

#more
Приоритет: `new` сильнее `bind` (создаётся новый объект, но привязанные аргументы сохраняются), явная привязка сильнее вызова как метода. `bind` закрепляет `this` навсегда: повторный `bind` и `call` его не меняют. Тело класса всегда в strict mode, поэтому извлечённый метод получает `undefined`. Слушатели DOM получают `this` равным элементу.
::

::question
В чём разница между call, apply и bind?

#answer
`call` и `apply` вызывают функцию сразу с указанным `this`: `call` принимает аргументы списком, `apply` — массивом. `bind` не вызывает, а возвращает новую функцию с закреплённым `this` и, при желании, аргументами.

#more
Привязанная функция — отдельный объект с именем `bound name`. Повторный `bind` не меняет `this`, только добавляет аргументы. `apply` раньше использовали для передачи массива аргументов, сейчас для этого есть spread: `fn.call(ctx, ...args)`. Для стрелок все три бесполезны в части `this`.
::

::question
Что такое потеря контекста и как её избежать?

#answer
Метод, переданный как колбэк или извлечённый из объекта, вызывается без объекта перед точкой и теряет `this`. Решения: стрелка-обёртка `() => obj.method()`, `bind`, поле-стрелка в классе.

#more
`obj.method` — просто ссылка на функцию, объект важен только в момент вызова. Колбэки вызывает чужой код: браузер для слушателей ставит `this` на элемент, таймеры и методы массивов вызывают без объекта. Поле-стрелка в классе удобно, но создаёт функцию на каждый экземпляр, тогда как метод живёт на прототипе один раз.
::

## Практика

::practice{title="Что выведет?"}
```js
console.log(typeof hoisted, hoisted);
try { console.log(early); } catch (e) { console.log(e.constructor.name); }
try { console.log(typeof later); } catch (e) { console.log(e.constructor.name); }

var hoisted = 1;
let early = 2;
const later = () => {};

const currency = '₽';
function format(v) { return `${v} ${currency}`; }
function invoice() {
  const currency = '$';
  return format(10);
}
console.log(invoice());
```

#solution
```text
undefined undefined
ReferenceError
ReferenceError
10 ₽
```

- `hoisted` — `var`: до своей строки он зарегистрирован со значением `undefined`.
- `early` — `let` во временной мёртвой зоне: чтение бросает `ReferenceError`.
- `typeof later` тоже бросает: `typeof` безопасен только для необъявленных имён, а `later` объявлен, но ещё не инициализирован.
- `format` ищет `currency` там, где объявлена, а не в `invoice`, — область видимости лексическая.
::

::practice{title="Почему кнопка падает?"}
Клик по кнопке падает с `TypeError: Cannot read properties of undefined (reading 'map')`:

```js
class Checkout {
  constructor(items) {
    this.items = items;
  }

  submit() {
    return api.send(this.items.map((i) => i.sku));
  }
}

const checkout = new Checkout(cart.items);
button.addEventListener('click', checkout.submit);
```

#solution
`checkout.submit` — ссылка на функцию без объекта. Браузер вызовет её со `this`, равным кнопке, у которой нет `items`, поэтому `this.items.map` падает. Если бы метод вызывали как обычную функцию, `this` был бы `undefined`: тело класса работает в strict mode.

Три варианта:

```js
// 1. стрелка-обёртка — вызов как метода
button.addEventListener('click', () => checkout.submit());

// 2. bind — новая функция с закреплённым this
button.addEventListener('click', checkout.submit.bind(checkout));

// 3. поле-стрелка в классе — this закреплён за экземпляром
class Checkout {
  constructor(items) { this.items = items; }
  submit = () => api.send(this.items.map((i) => i.sku));
}
```

Для `removeEventListener` нужна та же ссылка, что и для добавления, поэтому результат `bind` или стрелку сохраняют в переменную. Поле-стрелка создаёт функцию на каждый экземпляр — для одного объекта это неважно.
::

::practice{title="Что выведет?"}
```js
const shop = {
  title: 'Магазин',
  regular() { return this.title; },
  arrow: () => typeof this,
  delayed() { return [1].map(() => this.title)[0]; },
};

const { regular } = shop;
const bound = shop.regular.bind({ title: 'Кофейня' });

console.log(shop.regular());
console.log(shop.arrow());
console.log(shop.delayed());
console.log(bound.call(shop));
try { console.log(regular()); } catch (e) { console.log(e.constructor.name); }
```

Код выполняется как модуль ES.

#solution
```text
Магазин
undefined
Магазин
Кофейня
TypeError
```

- `shop.regular()` — вызов как метода, `this` — `shop`.
- Стрелка как свойство литерала берёт `this` окружения, где объявлен литерал. В модуле ES это `undefined`, поэтому `typeof this` — `'undefined'`.
- Стрелка внутри метода видит `this` метода — `shop`.
- `bind` закрепил `this` навсегда, `call` его не меняет.
- `regular()` — обычный вызов в модуле, то есть в strict mode: `this` — `undefined`, чтение `title` бросает `TypeError`.
::
