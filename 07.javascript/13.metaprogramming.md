# Метапрограммирование

Как управлять поведением объектов на уровне языка: дескрипторы свойств, `Proxy` и `Reflect`, символы. На этом построены реактивность Vue и MobX, валидация моделей, неизменяемые объекты и протоколы языка. Спрашивают, что такое `Proxy`, зачем `Reflect` и что такое символы. Глубже — почему в ловушке `get` нужен `receiver`, какие инварианты прокси нельзя нарушить, почему `Proxy` над `Map` ломает методы и чем `freeze` отличается от `seal`.

::tldr
- **У каждого свойства есть дескриптор:** значение или геттер и сеттер плюс флаги `writable`, `enumerable`, `configurable`. `Object.defineProperty` по умолчанию ставит все флаги в `false`.
- **`Proxy` перехватывает базовые операции с объектом** — чтение, запись, удаление, `in`, перечисление ключей, вызов — через ловушки. Он не может нарушить инварианты: врать про неконфигурируемое свойство нельзя.
- **`Reflect` — те же операции в виде функций.** В ловушке через него передают операцию дальше, и `receiver` обязателен: без него геттер на целевом объекте получит `this` в обход прокси, и реактивность потеряет зависимости.
- **Прокси — отдельный объект.** Методы `Map`, `Set`, `Date` и приватные поля классов работают через внутренние слоты и ломаются, если `this` — прокси.
- **Символ — уникальный ключ свойства.** Символьные свойства не видны в `Object.keys`, `for...in` и JSON. Известные символы (`Symbol.iterator`, `Symbol.toPrimitive`) — точки расширения протоколов языка.
::

## Дескрипторы свойств

Сквозной пример — модель товара в админке: часть полей нельзя менять, часть вычисляется, изменения должны проверяться и автоматически перерисовывать форму.

Свойство объекта — не просто «ключ: значение». У каждого свойства есть **дескриптор**:

```js
Object.getOwnPropertyDescriptor({ title: 'Чай' }, 'title');
// { value: 'Чай', writable: true, enumerable: true, configurable: true }
```

- **`writable`** — можно ли присвоить новое значение;
- **`enumerable`** — видно ли свойство в `Object.keys`, `for...in`, spread и `JSON.stringify`;
- **`configurable`** — можно ли удалить свойство и изменить его дескриптор.

Вместо `value` и `writable` у свойства может быть **геттер и сеттер** — тогда это свойство-аксессор, которое вычисляется при чтении.

### defineProperty

Обычное присваивание создаёт свойство со всеми флагами `true`. `Object.defineProperty` ставит **`false` всё, что не указано**:

```js
Object.defineProperty(product, 'sku', { value: 'TEA-1' });
// { value: 'TEA-1', writable: false, enumerable: false, configurable: false }

Object.defineProperty(order, 'total', {
  get() { return this.items.reduce((sum, i) => sum + i.price, 0); },
  enumerable: true,
});
```

`sku` теперь нельзя изменить, удалить и переопределить, его не видно в `Object.keys` и JSON. Запись в него в strict mode бросает `TypeError`, в нестрогом — молча игнорируется. Повторный `defineProperty` для неконфигурируемого свойства тоже бросает `TypeError`.

### Уровни защиты объекта

| | Добавлять | Удалять | Менять значения |
| --- | --- | --- | --- |
| `Object.preventExtensions` | нет | да | да |
| `Object.seal` | нет | нет | да |
| `Object.freeze` | нет | нет | нет |

Все три поверхностные: `freeze` не замораживает вложенные объекты. Глубокая заморозка — рекурсивный обход, и в production её обычно не делают: она стоит времени, а неизменяемость данных проще обеспечить кодом.

Дескрипторы управляют отдельными свойствами. Чтобы перехватывать любые операции с объектом целиком, нужен `Proxy`.

## Proxy

`Proxy` — объект-обёртка, который перехватывает операции с целевым объектом:

```js
const product = new Proxy(target, {
  get(target, key, receiver) { /* чтение */ },
  set(target, key, value, receiver) { /* запись */ return true; },
});
```

Обработчик (handler) содержит **ловушки** (traps) — по одной на базовую операцию языка:

| Ловушка | Перехватывает |
| --- | --- |
| `get`, `set` | чтение и запись свойства |
| `has` | оператор `in` |
| `deleteProperty` | `delete` |
| `ownKeys` | `Object.keys`, `for...in`, `Reflect.ownKeys` |
| `getOwnPropertyDescriptor`, `defineProperty` | работу с дескрипторами |
| `apply`, `construct` | вызов функции и `new` |
| `getPrototypeOf`, `setPrototypeOf` | прототип |

Если ловушки нет, операция проходит к целевому объекту как есть.

### Валидация

```js
const form = new Proxy({ qty: 1 }, {
  set(target, key, value, receiver) {
    if (key === 'qty' && (!Number.isInteger(value) || value < 1)) {
      throw new RangeError('Количество — целое число от 1');
    }
    return Reflect.set(target, key, value, receiver);
  },
});
```

Ловушка `set` должна вернуть `true`. Если она вернёт что-то ложное (в том числе забытый `return`), в strict mode присваивание бросит `TypeError: 'set' on proxy: trap returned falsish`.

### Инварианты

Прокси может многое, но не всё. Спецификация задаёт **инварианты** — правила, которые ловушки не имеют права нарушить. Главное: прокси не может сообщить неправду о неконфигурируемом свойстве. Если у целевого объекта свойство `id` неизменяемо и неконфигурируемо, ловушка `get`, которая вернёт другое значение, вызовет `TypeError`. Это гарантирует, что `Object.freeze` нельзя обойти прокси.

Ловушки получают аргумент `receiver`, а внутри принято вызывать `Reflect`. Зачем?

---

## Reflect и receiver

`Reflect` — набор функций с теми же именами и аргументами, что у ловушек: `Reflect.get`, `Reflect.set`, `Reflect.has`, `Reflect.ownKeys`, `Reflect.apply`. Он делает три вещи:

- **передаёт операцию дальше без потерь** — в ловушке `return Reflect.get(...arguments)` гарантированно делает то же, что сделал бы объект без прокси;
- **возвращает `boolean` вместо исключения** — `Reflect.defineProperty` вернёт `false` там, где `Object.defineProperty` бросит;
- **даёт операции языка как функции** — `Reflect.ownKeys(obj)` возвращает все ключи, включая неперечисляемые и символы.

Самое важное — **`receiver`**. Это объект, на котором выполняется операция, обычно — сам прокси. Посмотрим, что будет без него:

```js
const state = {
  first: 'Анна',
  last: 'Ли',
  get full() { return `${this.first} ${this.last}`; },
};

const tracked = new Proxy(state, {
  get(target, key, receiver) {
    track(key);
    return target[key];            // ❌ геттер вызовется с this = target
  },
});
```

Чтение `tracked.full` пройдёт через ловушку, но внутри геттера `this.first` и `this.last` читаются у `target` — **мимо прокси**. Система реактивности узнает только о `full` и не перерисует экран, когда изменится `first`. В проверке без `Reflect` отследилось только `full`, а с `Reflect.get(target, key, receiver)` — `full`, `first` и `last`: `receiver` становится `this` внутри геттера.

То же происходит при наследовании: если прокси — прототип другого объекта, `receiver` указывает на объект-наследник, и запись через `Reflect.set` создаст свойство на нём, а не на прототипе.

### Реактивность на Proxy

На `get` и `set` с `Reflect` строится реактивность Vue 3 и :term[MobX]{def="библиотека состояния на наблюдаемых объектах: производные значения и реакции пересчитываются сами"}. Схема в несколько строк:

```js
let activeEffect = null;
const deps = new Map();

function reactive(obj) {
  return new Proxy(obj, {
    get(target, key, receiver) {
      if (activeEffect) (deps.get(key) ?? deps.set(key, new Set()).get(key)).add(activeEffect);
      return Reflect.get(target, key, receiver);
    },
    set(target, key, value, receiver) {
      const ok = Reflect.set(target, key, value, receiver);
      deps.get(key)?.forEach((effect) => effect());
      return ok;
    },
  });
}

function effect(fn) {
  activeEffect = fn;
  fn();
  activeEffect = null;
}
```

Эффект запоминает, какие свойства он прочитал, и перезапускается только при их изменении. В проверке эффект, который читал `qty` и `price`, перезапустился при изменении `qty` и не перезапустился при изменении `note`. Настоящие системы хранят зависимости по объекту и ключу в `WeakMap` и группируют перезапуски. Как это выглядит во фреймворке — в [Реактивности Vue](/content/vuejs/reactivity-fundamentals).

## Ограничения Proxy

### Прокси — другой объект

`proxy !== target`. Код, который сравнивает объекты по ссылке, кладёт их в `Set` или `WeakMap`, увидит два разных объекта. Во Vue из-за этого есть `toRaw`.

### Внутренние слоты

У `Map`, `Set`, `Date`, `Promise` и типизированных массивов данные хранятся не в свойствах, а во **внутренних слотах**, недоступных прокси. Методы проверяют слот у `this`, а `this` при вызове через прокси — сам прокси:

```js
const cache = new Proxy(new Map([['tea', 490]]), {});
cache.get('tea');   // TypeError: Method Map.prototype.get called on incompatible receiver
```

Решение — в ловушке `get` привязывать методы к целевому объекту: `typeof value === 'function' ? value.bind(target) : value`, а для `size` читать геттер с `target` в роли `receiver`. Так делают реактивные коллекции во Vue.

Та же проблема у **приватных полей классов**: `#field` проверяет бренд объекта, и метод, вызванный на прокси, бросает `TypeError` (подробно — в [Прототипах и классах](/content/javascript/prototypes-and-classes)).

### Цена

Каждая операция с прокси — вызов функции-ловушки вместо прямого доступа. Движок не может применить к ней обычные оптимизации доступа к свойствам. На горячих путях (циклы по тысячам объектов) прокси заметно медленнее, поэтому реактивные системы делают глубокие прокси лениво — только при первом обращении к вложенному объекту.

### Отзываемый прокси

`Proxy.revocable(target, handler)` возвращает прокси и функцию `revoke`. После отзыва любая операция с прокси бросает `TypeError`. Так выдают временный доступ к объекту — например, плагину, — и отбирают его после использования.

Прокси перехватывает операции. Ещё один инструмент метапрограммирования — символы — позволяет вмешаться в протоколы самого языка.

## Символы

`Symbol()` создаёт **уникальное** значение, которое используют как ключ свойства:

```js
const meta = Symbol('meta');
const product = { title: 'Чай', [meta]: { createdBy: 'admin' } };

Symbol('meta') === Symbol('meta');   // false — каждый символ уникален
```

Символьные ключи:

- **не конфликтуют** со строковыми и с символами других библиотек;
- **не видны** в `Object.keys`, `for...in` и `JSON.stringify`. Их показывают `Object.getOwnPropertySymbols` и `Reflect.ownKeys`, а spread копирует;
- **не приватны**: символ можно получить через `getOwnPropertySymbols`. Для приватности — поля `#field`.

`Symbol.for('app.cart')` создаёт символ в **глобальном реестре**: один и тот же для всех модулей и даже между iframe. Так библиотеки договариваются об общих ключах, например React помечает элементы символом из реестра.

### Известные символы

Встроенные символы — точки расширения протоколов языка. Определив метод с таким ключом, объект меняет поведение операторов и встроенных функций:

| Символ | Что настраивает | Где разобран |
| --- | --- | --- |
| `Symbol.iterator`, `Symbol.asyncIterator` | `for...of`, spread, `for await` | [Итераторы и генераторы](/content/javascript/iterators-and-generators) |
| `Symbol.toPrimitive` | приведение к примитиву | [Типы и переменные](/content/javascript/types-and-variables) |
| `Symbol.hasInstance` | `instanceof` | [Прототипы и классы](/content/javascript/prototypes-and-classes) |
| `Symbol.toStringTag` | `Object.prototype.toString` | ниже |

`Symbol.toStringTag` меняет метку в `Object.prototype.toString.call(value)`: у класса с `get [Symbol.toStringTag]() { return 'Money'; }` результат — `'[object Money]'`. На этой метке держится надёжная проверка встроенных типов: `Object.prototype.toString.call(null)` даёт `'[object Null]'`.

---

## Красные флаги в ответе

- **«`Object.freeze` делает объект полностью неизменяемым».** Только на первом уровне: вложенные объекты остаются изменяемыми.
- **«В ловушке достаточно `target[key]`».** Без `Reflect.get(target, key, receiver)` геттеры получат `this` в обход прокси, и реактивность потеряет зависимости.
- **«Proxy можно поставить на любой объект без последствий».** Методы `Map`, `Set`, `Date` и приватные поля сломаются: им нужен настоящий объект в роли `this`.
- **«Символьные свойства приватные».** Их видно через `Object.getOwnPropertySymbols` и `Reflect.ownKeys`. Приватность дают поля `#`.
- **«`Reflect` — то же самое, что методы `Object`».** Он повторяет ловушки прокси один в один, передаёт `receiver` и возвращает `boolean` вместо исключений.

## Как спрашивают на собеседовании

::question
Что такое Proxy и зачем он нужен?

#answer
Обёртка над объектом, которая перехватывает операции с ним — чтение, запись, удаление, `in`, вызов — через ловушки. Применяют для валидации, логирования, значений по умолчанию и реактивности (Vue 3, MobX).

#more
Ловушки соответствуют внутренним операциям языка, а инварианты не позволяют врать о неконфигурируемых свойствах. Прокси — отдельный объект: сравнение по ссылке, `Map`, `Set`, `Date` и приватные поля с ним ломаются. Доступ через прокси медленнее прямого, поэтому реактивные системы оборачивают вложенные объекты лениво.
::

::question
Зачем нужен Reflect, если можно обращаться к объекту напрямую?

#answer
`Reflect` повторяет ловушки прокси один в один и правильно передаёт операцию целевому объекту. Он возвращает `boolean` вместо исключений, например `Reflect.defineProperty`.

#more
Главное — `receiver`. `Reflect.get(target, key, receiver)` вызывает геттер с `this`, равным прокси, поэтому чтения внутри геттера тоже проходят через ловушку. С `target[key]` геттер получит `this = target`, и реактивность не узнает о зависимостях. При наследовании от прокси `receiver` указывает на наследника, и `Reflect.set` создаст свойство там, где нужно.
::

::question
Что такое дескриптор свойства?

#answer
Описание свойства: значение или геттер и сеттер плюс флаги `writable` (можно изменить), `enumerable` (видно при переборе и в JSON), `configurable` (можно удалить и переопределить).

#more
`Object.defineProperty` ставит в `false` всё, что не указано, поэтому свойства, созданные им, по умолчанию неизменяемы и невидимы. Неконфигурируемое свойство нельзя переопределить даже через прокси — это инвариант. Методы классов создаются неперечисляемыми, поэтому не видны в `for...in`. Поля классов — через определение, а не присваивание, и не вызывают сеттеры прототипа.
::

::question
Чем отличаются freeze, seal и preventExtensions?

#answer
`preventExtensions` запрещает добавлять свойства. `seal` — добавлять и удалять. `freeze` — ещё и менять значения. Все три поверхностные.

#more
`seal` и `freeze` выставляют всем свойствам `configurable: false`, а `freeze` — ещё и `writable: false`. В strict mode нарушение бросает `TypeError`, в нестрогом — молча игнорируется. Вложенные объекты остаются изменяемыми, глубокая заморозка требует рекурсии. Инварианты прокси гарантируют, что замороженный объект нельзя «разморозить» обёрткой.
::

::question
Что такое Symbol?

#answer
Примитив, каждое значение которого уникально. Используется как ключ свойства, который не конфликтует с другими ключами и не виден в `Object.keys`, `for...in` и JSON.

#more
`Symbol.for` создаёт символ в глобальном реестре — общий для всех модулей и realm. Известные символы (`Symbol.iterator`, `Symbol.toPrimitive`, `Symbol.hasInstance`, `Symbol.toStringTag`) — точки расширения протоколов языка. Символьные свойства не приватные: их видно через `getOwnPropertySymbols`. Символ нельзя неявно привести к строке — шаблонная строка с ним бросает `TypeError`.
::

::question
Почему Proxy над Map ломает методы?

#answer
Методы `Map` работают с внутренним хранилищем, которого у прокси нет. При вызове через прокси `this` — прокси, и метод бросает `incompatible receiver`.

#more
Данные `Map`, `Set`, `Date`, `Promise` лежат во внутренних слотах, а методы проверяют слот у `this`. Решение — в ловушке `get` привязывать функции к целевому объекту (`value.bind(target)`) и читать геттеры вроде `size` с `target` в роли `receiver`, а для реактивности — оборачивать сами методы. Так устроены реактивные коллекции Vue. Та же проблема у приватных полей классов.
::

## Практика

::practice{title="Модель с проверкой"}
Напиши `createModel(schema)`, которая возвращает объект: запись в поле проверяет тип по схеме, неизвестные поля запрещены, а чтение неизвестного поля бросает ошибку вместо `undefined`.

```js
const product = createModel({ title: 'string', price: 'number' });
product.title = 'Чай';
product.price = '490';   // TypeError: price должно быть number
product.sale = true;     // TypeError: неизвестное поле sale
product.titel;           // TypeError: неизвестное поле titel
```

#solution
```js
function createModel(schema) {
  const check = (key) => {
    if (!Object.hasOwn(schema, key)) throw new TypeError(`неизвестное поле ${String(key)}`);
  };

  return new Proxy({}, {
    get(target, key, receiver) {
      if (typeof key === 'symbol') return Reflect.get(target, key, receiver);
      check(key);
      return Reflect.get(target, key, receiver);
    },
    set(target, key, value, receiver) {
      check(key);
      if (typeof value !== schema[key]) {
        throw new TypeError(`${key} должно быть ${schema[key]}, а не ${typeof value}`);
      }
      return Reflect.set(target, key, value, receiver);
    },
    deleteProperty(target, key) {
      check(key);
      return Reflect.deleteProperty(target, key);
    },
  });
}
```

Символьные ключи в `get` пропускаются: их читают встроенные механизмы (`console.log`, приведение к строке через `Symbol.toPrimitive`), и бросать на них нельзя. `set` возвращает результат `Reflect.set`, иначе в strict mode присваивание упадёт.
::

::practice{title="Почему кеш на Proxy падает?"}
Кеш с логированием обращений падает при первом же чтении:

```js
const cache = new Proxy(new Map(), {
  get(target, key) {
    console.log('доступ к', key);
    return target[key];
  },
});

cache.set('tea', 490);   // TypeError: Method Map.prototype.set called on incompatible receiver
```

#solution
`target[key]` возвращает метод `Map.prototype.set`, но вызывается он как `cache.set(...)` — с `this`, равным прокси. Методы `Map` работают с внутренним слотом, которого у прокси нет, и бросают `incompatible receiver`. Свойство `size` — геттер с той же проверкой.

Фикс — привязать методы к настоящему `Map`, а геттеры читать с ним в роли `receiver`:

```js
const cache = new Proxy(new Map(), {
  get(target, key) {
    console.log('доступ к', key);
    const value = Reflect.get(target, key, target);   // size и другие геттеры — с this = Map
    return typeof value === 'function' ? value.bind(target) : value;
  },
});

cache.set('tea', 490);
cache.get('tea');   // 490
cache.size;         // 1
```

В проверке без привязки `get` бросил `incompatible receiver`, с привязкой и `get`, и `size` сработали. Так же устроены реактивные `Map` и `Set` во фреймворках.
::

::practice{title="Что выведет?"}
```js
const id = Symbol('id');
const product = { title: 'Чай', [id]: 7 };
Object.defineProperty(product, 'sku', { value: 'TEA-1' });

console.log(Object.keys(product));
console.log(JSON.stringify(product));
console.log(Reflect.ownKeys(product));
console.log({ ...product }[id], { ...product }.sku);
console.log(Object.getOwnPropertyDescriptor(product, 'sku').writable);
```

#solution
```text
[ 'title' ]
{"title":"Чай"}
[ 'title', 'sku', Symbol(id) ]
7 undefined
false
```

- `Object.keys` и JSON видят только перечисляемые строковые ключи: символ скрыт, `sku` создан через `defineProperty` и по умолчанию неперечисляемый.
- `Reflect.ownKeys` возвращает все собственные ключи: строки, затем символы.
- Spread копирует перечисляемые свойства, включая символьные, но не неперечисляемые — `sku` не скопирован.
- `defineProperty` поставил `writable: false`, потому что флаг не указан.
