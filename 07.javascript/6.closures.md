# Замыкания

Замыкания - одна из тех тем, которые кажутся загадочными, пока не «щёлкнет». После этого ты начинаешь видеть их повсюду: в debounce, в React hooks, в middleware, в любом callback'е с доступом к внешним переменным. Замыкание - это не отдельная конструкция языка, а **следствие** того, как JavaScript работает с областями видимости.

---

## Что такое замыкание

<b class="text-on-semi-light">Простыми словами:</b> Замыкание - это функция, которая **помнит** переменные из того места, где была создана, даже если вызывается совсем в другом месте.

<b class="text-on-semi-light">Формально:</b> Closure - это комбинация функции и **ссылки на Lexical Environment**, в котором эта функция была объявлена. Функция сохраняет доступ к переменным внешнего scope даже после того, как внешняя функция завершила выполнение.

```js
function createGreeter(greeting) {
  // greeting живёт в Lexical Environment createGreeter
  return function (name) {
    // Эта функция замкнула (captured) greeting
    return `${greeting}, ${name}!`;
  };
}

const sayHello = createGreeter('Hello');
const sayHi = createGreeter('Hi');

sayHello('Alice'); // 'Hello, Alice!'
sayHi('Bob');      // 'Hi, Bob!'
```

`createGreeter` завершилась, но `greeting` не уничтожена - внутренняя функция **держит ссылку** на Lexical Environment, в котором `greeting` была объявлена.

---

## Лексическая область видимости

Замыкания возможны благодаря **lexical scoping** - правилу, по которому scope функции определяется **местом её объявления**, а не местом вызова.

```js
const x = 10;

function foo() {
  console.log(x); // 10 - берёт x из scope, где foo объявлена
}

function bar() {
  const x = 20;
  foo(); // всё равно 10, а не 20
}

bar();
```

Каждая функция при создании получает скрытое свойство `[[Environment]]` - ссылку на Lexical Environment, в котором она была создана. При вызове функции это окружение становится «внешним» scope.

---

## Как замыкание работает

Рассмотрим пошагово:

```js
function outer() {
  let count = 0;       // переменная в Lexical Environment outer

  function inner() {
    count++;           // обращается к count из outer
    console.log(count);
  }

  return inner;        // возвращаем inner наружу
}

const fn = outer();    // outer завершилась, но count жив
fn(); // 1
fn(); // 2
fn(); // 3
```

1. Вызов `outer()` создаёт Lexical Environment с `count = 0` и функцией `inner`
2. `inner` получает `[[Environment]]` -> Lexical Environment outer
3. `outer` возвращает `inner` и завершается
4. Но Lexical Environment outer **не уничтожается** - на него есть ссылка из `inner.[[Environment]]`
5. Каждый вызов `fn()` обращается к тому же `count` через scope chain

<b class="text-on-semi-light">Ключевой момент:</b> Замыкание хранит **ссылку** на переменную, а не её копию. Изменения в замкнутой переменной видны при следующем вызове.

## Примеры замыканий

### Counter - классический пример

```js
function createCounter(initial = 0) {
  let count = initial;

  return {
    increment: () => ++count,
    decrement: () => --count,
    getCount: () => count,
    reset: () => { count = initial; },
  };
}

const counter = createCounter(10);
counter.increment(); // 11
counter.increment(); // 12
counter.decrement(); // 11
counter.getCount();  // 11
counter.reset();
counter.getCount();  // 10
```

`count` и `initial` - приватные. Снаружи к ним нет доступа, только через возвращённые методы.

### Private state и Module pattern

```js
const authModule = (function () {
  let token = null;
  let user = null;

  function setAuth(newToken, newUser) {
    token = newToken;
    user = newUser;
  }

  function getToken() {
    return token;
  }

  function isAuthenticated() {
    return token !== null;
  }

  function logout() {
    token = null;
    user = null;
  }

  return { setAuth, getToken, isAuthenticated, logout };
})();

authModule.setAuth('abc123', { name: 'Alice' });
authModule.isAuthenticated(); // true
authModule.getToken();        // 'abc123'
// authModule.token -> undefined (приватно!)
```

<span class="text-gray">До появления ES-модулей и private fields в классах, IIFE + замыкания были единственным способом создать настоящую инкапсуляцию в JS.</span>

### Каррирование через замыкания

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return function (...moreArgs) {
      return curried.apply(this, [...args, ...moreArgs]);
    };
  };
}

const add = curry((a, b, c) => a + b + c);

add(1)(2)(3);    // 6
add(1, 2)(3);    // 6
add(1)(2, 3);    // 6
add(1, 2, 3);    // 6
```

Каждый промежуточный вызов возвращает новую функцию, замкнувшую предыдущие аргументы.

### Event handlers и замыкания

```js
function setupButtons() {
  const buttons = document.querySelectorAll('.btn');

  buttons.forEach((btn, index) => {
    btn.addEventListener('click', () => {
      // Arrow function замыкает index и btn из forEach
      console.log(`Button ${index} clicked`);
    });
  });
}
```

Каждый callback замыкает свою копию `index` и `btn` из итерации `forEach`.

## Замыкания в цикле - классическая ловушка

```js
// Проблема с var
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i); // 3, 3, 3 (не 0, 1, 2!)
  }, 100);
}
```

Почему `3, 3, 3`? Все три callback'а замыкают **одну и ту же** переменную `i` (var имеет function scope, а не block scope). К моменту выполнения `setTimeout` цикл уже завершился, и `i === 3`.

### Решение 1 - let

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i); // 0, 1, 2
  }, 100);
}
```

`let` создаёт **новую привязку** для каждой итерации цикла. Каждый callback замыкает свою собственную копию `i`.

### Решение 2 - IIFE

```js
for (var i = 0; i < 3; i++) {
  (function (j) {
    setTimeout(() => {
      console.log(j); // 0, 1, 2
    }, 100);
  })(i);
}
```

IIFE создаёт новый scope для каждой итерации. Параметр `j` - копия `i` на момент вызова.

### Решение 3 - дополнительная функция

```js
function createLogger(value) {
  return () => console.log(value);
}

for (var i = 0; i < 3; i++) {
  setTimeout(createLogger(i), 100); // 0, 1, 2
}
```

## Практические use cases

### Debounce

```js
function debounce(fn, delay) {
  let timeoutId;           // замкнутая переменная

  return function (...args) {
    clearTimeout(timeoutId);
    timeoutId = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}

const handleSearch = debounce((query) => {
  fetch(`/api/search?q=${query}`);
}, 300);

// При быстром вводе вызовется только один раз через 300ms после последнего нажатия
input.addEventListener('input', (e) => handleSearch(e.target.value));
```

`timeoutId` живёт в замыкании - каждый вызов debounced-функции видит и может отменить предыдущий таймер.

### Throttle

```js
function throttle(fn, interval) {
  let lastTime = 0;        // замкнутая переменная

  return function (...args) {
    const now = Date.now();
    if (now - lastTime >= interval) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}

const handleScroll = throttle(() => {
  console.log('scroll event processed');
}, 200);

window.addEventListener('scroll', handleScroll);
```

### Memoization

```js
function memoize(fn) {
  const cache = new Map();  // замкнутый кэш

  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) {
      return cache.get(key);
    }
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

const expensiveCalc = memoize((n) => {
  console.log('computing...');
  return n * n;
});

expensiveCalc(5); // computing... 25
expensiveCalc(5); // 25 (из кэша, без "computing...")
```

### Partial application

```js
function partial(fn, ...presetArgs) {
  return function (...laterArgs) {
    return fn(...presetArgs, ...laterArgs);
  };
}

const multiply = (a, b) => a * b;
const double = partial(multiply, 2);
const triple = partial(multiply, 3);

double(5); // 10
triple(5); // 15
```

### Factory functions

```js
function createLogger(prefix) {
  return {
    log: (msg) => console.log(`[${prefix}] ${msg}`),
    warn: (msg) => console.warn(`[${prefix}] ${msg}`),
    error: (msg) => console.error(`[${prefix}] ${msg}`),
  };
}

const dbLogger = createLogger('DB');
const apiLogger = createLogger('API');

dbLogger.log('Connected');  // [DB] Connected
apiLogger.error('Timeout'); // [API] Timeout
```

## Замыкания и утечки памяти

Замыкание удерживает ссылку на **весь** Lexical Environment внешней функции, а не только на переменные, которые реально используются (хотя современные движки оптимизируют это).

```js
function createHandler() {
  const hugeData = new Array(1_000_000).fill('x'); // 1M строк

  return function () {
    // hugeData не используется, но может удерживаться в памяти
    console.log('handler called');
  };
}

const handler = createHandler();
// hugeData потенциально жив, пока жив handler
```

### Когда это проблема

- Event listeners, которые не удаляются при размонтировании компонента
- Таймеры (`setInterval`) с замыканием на большие объекты
- Кэш без ограничения размера (растёт бесконечно)

### Решения

```js
// 1. Обнулить ссылку, когда она больше не нужна
function createHandler() {
  let hugeData = new Array(1_000_000).fill('x');
  const summary = hugeData.length; // извлекаем то, что нужно
  hugeData = null; // освобождаем

  return function () {
    console.log(`Processed ${summary} items`);
  };
}

// 2. Использовать WeakRef для кэша
function createCache() {
  const cache = new Map();

  return {
    set(key, value) {
      cache.set(key, new WeakRef(value));
    },
    get(key) {
      const ref = cache.get(key);
      return ref?.deref();
    },
  };
}

// 3. Удалять listeners при размонтировании
function setup() {
  const handler = () => { /* ... */ };
  element.addEventListener('click', handler);

  return function cleanup() {
    element.removeEventListener('click', handler);
  };
}
```

<span class="text-gray">V8 и другие движки оптимизируют замыкания: если переменная не используется во внутренней функции, она обычно не удерживается. Но это оптимизация движка, а не гарантия спецификации. Лучше не полагаться на неё и явно обнулять большие объекты.</span>

## Замыкания на собеседовании

### Задача 1 - counter

```js
// Напиши функцию createCounter, которая возвращает объект с методами
// increment, decrement, getCount

function createCounter() {
  let count = 0;
  return {
    increment: () => ++count,
    decrement: () => --count,
    getCount: () => count,
  };
}

const c = createCounter();
c.increment();
c.increment();
c.getCount(); // 2
```

### Задача 2 - closure in loop

```js
// Что выведет этот код?
for (var i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 0);
}
// Ответ: 5, 5, 5, 5, 5

// Исправь, чтобы выводило 0, 1, 2, 3, 4
for (let i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 0);
}
```

### Задача 3 - private variable

```js
// Создай функцию, хранящую секрет, который можно получить только через метод
function createSecret(secret) {
  return {
    getSecret: (password) => {
      if (password === 'open') return secret;
      return 'Access denied';
    },
  };
}

const vault = createSecret('my-api-key');
vault.secret;                  // undefined
vault.getSecret('wrong');      // 'Access denied'
vault.getSecret('open');       // 'my-api-key'
```

### Задача 4 - что выведет?

```js
function makeAdder(x) {
  return function (y) {
    return x + y;
  };
}

const add5 = makeAdder(5);
const add10 = makeAdder(10);

console.log(add5(3));  // 8
console.log(add10(3)); // 13
console.log(add5(add10(1))); // 16 (add10(1) = 11, add5(11) = 16)
```

## Частые вопросы на собесе

**Что такое замыкание?**
Замыкание - это функция вместе с ссылкой на Lexical Environment, в котором она была создана. Функция «помнит» переменные из внешнего scope даже после того, как внешняя функция завершилась. Это возможно благодаря lexical scoping.

**Приведи практический пример замыкания.**
Debounce: возвращаемая функция замыкает `timeoutId`, чтобы очищать предыдущий таймер при каждом новом вызове. Counter: возвращаемые методы замыкают `count`, создавая приватное состояние. Memoization: функция замыкает `cache` для хранения результатов.

**Почему в цикле с var все callback'ы выводят одно значение?**
`var` имеет function scope, а не block scope. Все итерации цикла используют **одну и ту же** переменную. К моменту выполнения callback'ов цикл завершён, и переменная содержит финальное значение. Решение - `let` (создаёт новую привязку на каждую итерацию) или IIFE.

**Могут ли замыкания вызывать утечки памяти?**
Да. Замыкание удерживает ссылку на Lexical Environment внешней функции. Если замкнутые переменные содержат большие объекты, они не будут собраны GC, пока жива замкнувшая функция. Типичные проблемы: забытые event listeners, незачищенные таймеры, неограниченный кэш.

**Чем замыкание отличается от обычной функции?**
Технически каждая функция в JS - замыкание (она всегда имеет `[[Environment]]`). Но термин обычно используют, когда функция **обращается к переменным из внешнего scope**, которые не являются ни её параметрами, ни локальными переменными - особенно когда внешняя функция уже завершилась.
