# Замыкания

Почему функция помнит переменные, среди которых была создана, даже когда внешняя функция давно завершилась. На mid спрашивают определение, ловушку `var` в цикле и пример с приватным счётчиком. На senior — что именно хранит замыкание (ссылку на переменную, а не значение), почему `let` в цикле работает иначе и как замыкания удерживают память, которую не должны.

::tldr
- **Замыкание — функция вместе с окружением, в котором она создана.** Внешняя функция завершилась, а её переменные живут, пока на них ссылается хотя бы одна внутренняя функция.
- **Замыкание хранит ссылку на переменную, а не копию значения.** Если переменную изменили после создания функции, функция увидит новое значение.
- **Каждый вызов внешней функции создаёт новое окружение.** Два счётчика из одной фабрики независимы, а функции одного вызова делят одни переменные.
- **`var` в цикле — одна переменная на все итерации, `let` — новая на каждую.** Поэтому колбэки с `var` видят последнее значение.
- **Замыкания удерживают память.** В V8 функции одного вызова делят общий контекст: большой объект, который нужен только одной из них, живёт, пока жива любая.
::

---

## Функция помнит, где родилась

Сквозной пример — кнопка «Купить» в каталоге:

```js
function createBuyButton(product) {
  let clicks = 0;

  return function onClick() {
    clicks++;
    analytics.track('buy', { sku: product.sku, clicks });
  };
}

const handler = createBuyButton({ sku: 'tea' });
button.addEventListener('click', handler);
```

`createBuyButton` завершилась сразу, а `onClick` при каждом клике продолжает видеть `product` и увеличивать `clicks`. Это **замыкание**: функция вместе с окружением, в котором она была создана.

Механизм следует из того, как устроены области видимости (подробно — в [Контексте выполнения](/content/javascript/execution-context)). Каждая функция при создании получает ссылку на внешнее лексическое окружение — в спецификации это внутреннее поле `[[Environment]]`. Когда `createBuyButton` завершается, её окружение не удаляется: на него ссылается `onClick`. Сборщик мусора удаляет окружение только тогда, когда не останется ни одной функции, которая на него ссылается.

Формально замыканием является **любая** функция в JavaScript: у каждой есть `[[Environment]]`. Но термин используют, когда функция действительно обращается к внешним переменным — особенно после того, как внешняя функция завершилась.

Из механизма следуют три свойства, которые и спрашивают на собеседованиях. Первое — что именно функция помнит.

## Ссылка на переменную, а не значение

Замыкание не делает снимок значений. Оно держит ссылку на само окружение, поэтому видит переменную в её текущем состоянии:

```js
let currency = '₽';
const format = (v) => `${v} ${currency}`;

currency = '$';
format(10);   // '10 $' — функция видит новое значение
```

Это важно и в обратную сторону: функция, созданная однажды, видит текущие значения переменных окружения, а не те, что были при её создании. В React кажется, что всё наоборот, — колбэк из старого рендера видит старое значение. Но причина та же: каждый рендер — **новый вызов** компонента с **новым окружением** и новыми константами, а старый колбэк ссылается на старое окружение (подробно — в [Механике хуков](/content/reactjs/hooks-mechanics)).

### Каждый вызов — новое окружение

```js
function createCounter() {
  let count = 0;
  return { inc: () => ++count, get: () => count };
}

const a = createCounter();
const b = createCounter();
a.inc(); a.inc(); b.inc();
a.get(); // 2
b.get(); // 1
```

Два вызова `createCounter` — два окружения и два независимых `count`. А `inc` и `get` из **одного** вызова ссылаются на одно окружение и видят одну переменную. На этом построено приватное состояние.

Эти два правила — ссылка на переменную и новое окружение на вызов — объясняют самую знаменитую задачу про замыкания.

## Ловушка с var в цикле

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3, 3, 3
```

`var` объявляет одну переменную на всю функцию. Все три колбэка ссылаются на одну и ту же `i`, а к моменту их вызова цикл давно закончился, и `i` равна 3.

С `let` вывод `0, 1, 2`:

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

Дело не только в том, что `let` блочный. Для `for` с `let` спецификация создаёт **новое окружение на каждую итерацию** и копирует в него текущее значение счётчика. Каждый колбэк замыкает свою переменную. Копирование происходит в начале итерации, поэтому изменение `i` в теле видно следующей итерации: в проверке цикл с `k++` в теле дал замыканиям значения `1`, `3`, `5`.

До `let` проблему решали функцией, которая создаёт новое окружение на каждой итерации, — IIFE:

```js
for (var i = 0; i < 3; i++) {
  (function (copy) {
    setTimeout(() => console.log(copy), 0);
  })(i);
}
```

Это то же самое, что делает `let`, только вручную. В новом коде достаточно `let`, а для обхода массивов — `forEach` или `for...of`.

Цикл показывает, что замыкание держит переменную. Это же свойство превращает замыкания в инструмент.

## Зачем замыкания на практике

### Приватное состояние

До приватных полей классов (`#balance`) замыкание было единственным способом спрятать данные:

```js
function createWallet(initial) {
  let balance = initial;
  return {
    pay(sum) {
      if (sum > balance) throw new RangeError('Недостаточно средств');
      balance -= sum;
      return balance;
    },
    get balance() { return balance; },
  };
}
```

До `balance` нельзя добраться иначе как через методы: свойства с таким именем у объекта нет. Так же устроен паттерн «модуль» — IIFE, которая возвращает публичный API, а внутренние переменные прячет. До ES-модулей это был стандарт организации кода (подробно — в [Модулях](/content/javascript/modules)).

### Функции с настройками

Замыкание позволяет «запечь» параметры в функцию: `withDiscount(10)` возвращает функцию, которая помнит процент. На этом построены фабрики, частичное применение, каррирование и декораторы — `once`, `debounce`, `throttle`, мемоизация. Все они хранят служебное состояние (таймер, флаг, кеш) в замыкании. Сами приёмы разобраны в [Паттернах](/content/javascript/patterns).

### Обработчики событий

Слушатель события почти всегда — замыкание: он помнит элемент, данные и состояние, среди которых был создан, как `onClick` из сквозного примера. Отсюда и главная практическая проблема замыканий.

## Замыкания и память

Замыкание продлевает жизнь окружению. Пока функция жива — а слушатель, таймер или колбэк подписки живут долго, — живы и все переменные, на которые ссылается её окружение.

### Типичные утечки

- **Слушатель не удалён.** Компонент удалён со страницы, а его обработчик на `window` остался — вместе со всем, что он замыкает.
- **Таймер не остановлен.** `setInterval` держит колбэк, а колбэк — данные.
- **Кеш без ограничений.** Мемоизация в замыкании растёт бесконечно.

Лечение одно: у каждой подписки должна быть отписка — `removeEventListener`, `clearInterval`, `AbortController`, cleanup эффекта. Как искать утечки в DevTools — в [Памяти и производительности](/content/javascript/memory-and-performance).

### Общий контекст в V8

Есть тонкость, о которой мало кто знает. Спецификация говорит, что функция хранит ссылку на всё окружение. Движки оптимизируют это: переменные, которые не использует ни одна внутренняя функция, не попадают в долгоживущий контекст и собираются сразу. Но если переменную использует **хотя бы одна** внутренняя функция, V8 кладёт её в **общий контекст**, на который ссылаются все функции этого вызова.

```js
function setup(element) {
  const report = buildHugeReport();              // большой объект

  function exportReport() {                      // использует report
    download(report);
  }

  element.addEventListener('click', () => {      // report не использует
    element.classList.toggle('active');
  });
}
```

Слушатель не трогает `report`, но живёт в том же контексте, что и `exportReport`, а `exportReport` упоминает `report`. Пока слушатель висит на элементе, отчёт не будет собран, хотя `exportReport` никто даже не вызывал. Проверка на настоящем сборщике V8 (`--expose-gc` и `WeakRef`) показала: без соседней функции большой объект собирается, с ней — остаётся в памяти.

Это поведение движка, а не спецификации, но в Chrome и Node.js оно есть. Решения — вынести тяжёлые данные в отдельную функцию, обнулить ссылку, когда она больше не нужна (`report = null`), или не создавать долгоживущие функции рядом с тяжёлыми данными.

### Как увидеть замыкание

Замыкание видно в DevTools. Если поставить точку останова внутри `onClick`, на панели Scope будут разделы `Local` (переменные вызова), `Closure (createBuyButton)` (окружение, которое функция замкнула) и `Script` или `Module`. В `Closure` лежат ровно те переменные, которые движок сохранил в контексте, — так проверяют, что функция держит лишнего. Для поиска утечек в снимке кучи (Memory, Heap snapshot) у объекта есть цепочка удерживающих ссылок (Retainers): в ней замыкание выглядит как `context` функции, через который и держится объект.

## Красные флаги в ответе

- **«Замыкание копирует значения внешних переменных».** Оно держит ссылку на окружение и видит текущие значения.
- **«`let` в цикле работает, потому что блочный».** Блочность нужна, но решает спецификация `for`: на каждой итерации создаётся новое окружение с копией счётчика.
- **«Замыкание — это функция внутри функции».** Это функция вместе с окружением создания. Технически любая функция в JS — замыкание.
- **«Если переменная не используется, движок её не держит».** Не если её использует соседняя функция того же вызова: в V8 они делят общий контекст.
- **«Замыкания — это про приватность».** Приватность — одно из применений. Главное — функции, которые помнят состояние: колбэки, фабрики, декораторы.

## Как спрашивают на собеседовании

::question{level="mid"}
Что такое замыкание?

#mid
Функция вместе с окружением, в котором она была создана. Она помнит внешние переменные даже после того, как внешняя функция завершилась. Например, счётчик: внешняя функция объявляет `count` и возвращает функцию, которая его увеличивает.

#senior
При создании функция получает ссылку на внешнее лексическое окружение (`[[Environment]]`). Окружение завершившейся функции не удаляется, пока на него ссылается хоть одна функция. Замыкание держит ссылку на переменные, а не их значения, поэтому видит изменения. Формально любая функция — замыкание, термин применяют, когда она реально использует внешние переменные.
::

::question{level="mid"}
Почему в цикле с var все колбэки выводят одно значение?

#mid
`var` объявляет одну переменную на всю функцию. Все колбэки замыкают одну и ту же переменную, и к моменту их вызова цикл закончился — переменная равна последнему значению. Решение — `let`.

#senior
Для `for` с `let` спецификация создаёт новое окружение на каждую итерацию и копирует туда текущее значение счётчика, поэтому каждый колбэк замыкает свою переменную. Изменение счётчика в теле видно следующей итерации, потому что копирование идёт в её начале. До ES2015 то же самое делали вручную через IIFE с параметром.
::

::question{level="mid"}
Приведи практический пример замыкания.

#mid
Приватное состояние: фабрика возвращает методы, которые работают с внутренней переменной, недоступной снаружи. Обработчик события, который помнит данные элемента. `debounce`, который хранит id таймера.

#senior
Замыкание — способ дать функции состояние без класса: декораторы (`once`, `debounce`, `throttle`, мемоизация) хранят флаг, таймер или кеш. Фабрики «запекают» настройки: `withDiscount(10)`. Паттерн «модуль» прятал внутренности до ES-модулей. Хуки React тоже опираются на замыкания: колбэк видит значения рендера, в котором создан.
::

::question{level="senior"}
Могут ли замыкания вызывать утечки памяти?

#mid
Да. Пока жива функция, живы все переменные её окружения. Забытый слушатель или незакрытый интервал держат и функцию, и данные, которые она замыкает.

#senior
Помимо забытых подписок, есть особенность V8: переменные, которые использует хотя бы одна внутренняя функция, попадают в общий контекст вызова, и его держит любая функция этого вызова. Большой объект, нужный только одной функции, живёт, пока жива другая — например, слушатель. Лечение: у каждой подписки — отписка, тяжёлые данные — в отдельную функцию или явное обнуление ссылки.
::

::question{level="mid"}
Чем замыкание отличается от обычной функции?

#mid
Технически ничем: у каждой функции в JS есть ссылка на окружение, где она создана. Замыканием обычно называют функцию, которая использует переменные внешней области, особенно после того, как внешняя функция завершилась.

#senior
Разница не в синтаксисе, а во времени жизни окружения. Пока функция существует, её внешнее окружение не удаляется. Если функция не использует внешних переменных, движок может не хранить их вовсе, и в этом смысле она «не замыкает» ничего.
::

::question{level="senior"}
Как замыкания связаны с устаревшими значениями в React?

#mid
Каждый рендер — новый вызов компонента со своими константами. Колбэк, созданный в старом рендере, замыкает старые значения. Если он переживает рендер (интервал, подписка), он видит устаревшие данные.

#senior
Это то же правило «каждый вызов — новое окружение». Замыкание по-прежнему ссылается на переменную, но в старом окружении эта переменная никогда не изменится — это константа старого рендера. Лечится функциональным обновлением состояния, честными зависимостями эффекта или `useEffectEvent`.
::

## Практика

::practice{title="Что выведет?"}
```js
const fns = [];
for (var i = 0; i < 3; i++) fns.push(() => i);

const fns2 = [];
for (let j = 0; j < 6; j++) {
  fns2.push(() => j);
  j++;
}

let currency = '₽';
const format = (v) => `${v} ${currency}`;
currency = '$';

console.log(fns.map((f) => f()));
console.log(fns2.map((f) => f()));
console.log(format(10));
```

#solution
```text
[ 3, 3, 3 ]
[ 1, 3, 5 ]
10 $
```

- `var` — одна переменная на все итерации, к моменту вызова она равна 3.
- С `let` каждая итерация получает свою копию счётчика. Колбэк замыкает переменную итерации, а `j++` в теле меняет её до конца итерации — поэтому `1`, `3`, `5`.
- Замыкание хранит ссылку на переменную, а не значение: `format` видит новое `currency`.
::

::practice{title="Напиши счётчик с лимитом"}
Напиши `createLimiter(max)`, которая возвращает функцию `tryRun(fn)`: она вызывает `fn`, только если лимит ещё не исчерпан, и возвращает `true` или `false`. Счётчики разных лимитеров должны быть независимы, а снаружи изменить счётчик нельзя.

#solution
```js
function createLimiter(max) {
  let used = 0;
  return function tryRun(fn) {
    if (used >= max) return false;
    used++;
    fn();
    return true;
  };
}

const freeSamples = createLimiter(2);
freeSamples(() => send('tea'));   // true
freeSamples(() => send('pot'));   // true
freeSamples(() => send('cup'));   // false

const promoCodes = createLimiter(1); // свой счётчик
```

`used` живёт в окружении вызова `createLimiter`: каждый вызов создаёт новое окружение, поэтому лимитеры независимы. Свойства `used` у функции нет, изменить его снаружи нельзя. Счётчик увеличивается до вызова `fn`, чтобы ошибка внутри `fn` не давала обойти лимит.
::

::practice{title="Найди утечку"}
На странице отчётов память растёт с каждым переходом между отчётами, хотя старые узлы удаляются со страницы:

```js
function mountReport(container, id) {
  const report = loadReportSync(id);          // десятки мегабайт данных

  function exportCsv() {
    download(toCsv(report));
  }
  container.querySelector('.export').onclick = exportCsv;

  window.addEventListener('resize', () => {
    container.style.height = `${window.innerHeight - 100}px`;
  });
}
```

#solution
Слушатель `resize` висит на `window` и никогда не снимается. Он сам не использует `report`, но в V8 функции одного вызова делят общий контекст, а `exportCsv` упоминает `report`. Значит, пока жив слушатель на `window`, живут и `container` (удалённый со страницы узел), и весь отчёт. Каждый переход добавляет новый слушатель и новый отчёт.

Фикс — отписка при размонтировании и разделение тяжёлых данных:

```js
function mountReport(container, id) {
  const controller = new AbortController();

  container.querySelector('.export').onclick = () => {
    download(toCsv(loadReportSync(id)));      // отчёт нужен только при экспорте
  };

  window.addEventListener('resize', () => {
    container.style.height = `${window.innerHeight - 100}px`;
  }, { signal: controller.signal });

  return () => controller.abort();            // вызвать при уходе со страницы
}
```

`AbortController` снимает все слушатели одним вызовом. Если отчёт нужен заранее, его держат в отдельной функции или обнуляют ссылку, когда он больше не нужен.
