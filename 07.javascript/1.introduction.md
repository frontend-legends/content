# Введение в JavaScript

JavaScript - это язык, который начинался как скрипт для оживления веб-страниц, а стал одним из самых распространённых языков программирования в мире. Сегодня на JS пишут фронтенд, бэкенд, мобильные приложения, десктоп, IoT и даже машинное обучение. Для frontend-разработчика понимание природы языка - не бонус, а необходимость: на собеседовании спрашивают не «что делает JS», а **почему он работает именно так**.

---

## Что такое JavaScript

JavaScript - высокоуровневый, динамически и слабо типизированный, однопоточный, интерпретируемый (или компилируемый «на лету» - JIT), встраиваемый, мультипарадигменный язык программирования.

Разберём каждую характеристику:

- <b class="text-on-semi-light">Высокоуровневый</b> - тебе не нужно вручную управлять памятью, регистрами процессора или системными вызовами. Язык абстрагирует всё это: ты работаешь с объектами, строками и функциями, а движок сам решает, как разместить данные в памяти и когда их очистить (garbage collection). Это делает код проще, но ты теряешь контроль - поэтому важно понимать, как GC работает, чтобы не создавать утечки памяти.

- <b class="text-on-semi-light">Динамически типизированный</b> - типы переменных определяются во время выполнения, а не при компиляции. Переменная может сначала хранить число, потом строку, потом объект - движок не запрещает это. Плюс: быстрая разработка, гибкость. Минус: ошибки типов ловятся только в runtime. Именно поэтому появился TypeScript - надстройка со статической типизацией.

- <b class="text-on-semi-light">Слабо типизированный</b> - JS автоматически приводит типы при операциях. `"5" + 3` даст `"53"` (конкатенация), а `"5" - 3` даст `2` (числовое вычитание). Это называется implicit type coercion. Слабая типизация - источник множества gotcha'ов на собеседованиях и багов в продакшене.

- <b class="text-on-semi-light">Однопоточный</b> - JavaScript выполняет код в одном потоке (main thread). Нет параллельного выполнения двух функций одновременно. Но это не значит, что JS «медленный» - асинхронные операции (таймеры, сетевые запросы, I/O) обрабатываются через Event Loop, который позволяет не блокировать основной поток. Web Workers дают возможность запускать код в отдельных потоках, но они не разделяют память с main thread.

- <b class="text-on-semi-light">Интерпретируемый / JIT-компилируемый</b> - исторически JS был чисто интерпретируемым: движок построчно читал и выполнял код. Современные движки (V8, SpiderMonkey, JavaScriptCore) используют JIT (Just-In-Time) компиляцию: сначала код быстро интерпретируется, затем «горячие» участки компилируются в машинный код для максимальной производительности. V8, например, использует два компилятора - Ignition (интерпретатор-байткод) и TurboFan (оптимизирующий компилятор).

- <b class="text-on-semi-light">Встраиваемый</b> - JS не существует сам по себе. Он всегда работает внутри host-окружения (хоста), которое предоставляет ему API. В браузере это DOM, fetch, localStorage. В Node.js - файловая система, потоки, HTTP-сервер. Сам язык (ECMAScript) не знает ни про `document`, ни про `require` - это всё API хоста.

- <b class="text-on-semi-light">Мультипарадигменный</b> - JS поддерживает несколько парадигм программирования одновременно. Императивный стиль (пошаговые инструкции), ООП (прототипы, классы), функциональный стиль (функции как значения, замыкания, `map`/`filter`/`reduce`). Ты сам выбираешь подход в зависимости от задачи, и можешь комбинировать парадигмы в одном проекте.

> Как компьютер выполняет высокоуровневый код - подробнее в [Языки и компиляторы](/content/computer-science/languages-and-compilers).

## Краткая история JavaScript

| Год  | Событие                                                                   |
| ---- | ------------------------------------------------------------------------- |
| 1995 | Brendan Eich создаёт JavaScript за 10 дней в Netscape                     |
| 1996 | Microsoft выпускает JScript для Internet Explorer. Начало «войны браузеров» |
| 1997 | ECMA International стандартизирует язык как ECMAScript (ES1)               |
| 1999 | ES3 - регулярные выражения, try/catch, основа языка на следующие 10 лет   |
| 2009 | ES5 - strict mode, JSON, Array methods (forEach, map, filter)             |
| 2015 | ES6/ES2015 - революция: let/const, arrow functions, classes, Promises, modules |
| 2016+| Ежегодные релизы: ES2016, ES2017 ... ES2025                              |

<b class="text-on-semi-light">Почему ES6 - революция:</b> До ES6 JavaScript не имел блочной области видимости (только `var`), нативных модулей, классов, промисов, шаблонных строк, деструктуризации. ES6 превратил JS из «скриптового языка для формочек» в полноценный инструмент для сложных приложений.

<span class="text-gray">Название «JavaScript» - маркетинговый ход 1995 года. Java была на пике популярности, и Netscape решил использовать её имя. К языку Java JavaScript не имеет никакого отношения.</span>

## Версии ECMAScript

### ES3 (1999)

Фундамент языка. Регулярные выражения, `try/catch`, `switch`, `do...while`. Именно эту версию поддерживал IE6.

### ES5 (2009)

```js
"use strict";                      // strict mode
var nums = [1, 2, 3];
nums.forEach(function(n) {         // Array methods
  console.log(n);
});
JSON.parse('{"a": 1}');            // нативный JSON
Object.keys({ a: 1, b: 2 });      // перечисление ключей
```

### ES6 / ES2015

```js
// let и const вместо var
let count = 0;
const API_URL = "https://api.example.com";

// Arrow functions
const double = (x) => x * 2;

// Template literals
const greeting = `Hello, ${name}!`;

// Destructuring
const { id, title } = response;
const [first, ...rest] = items;

// Promises
fetch(API_URL)
  .then((res) => res.json())
  .then((data) => console.log(data));

// Classes
class Component {
  constructor(props) {
    this.props = props;
  }
}

// Modules
import { useState } from "react";
export default App;
```

### ES2017-ES2025 - ключевые добавления

| Версия  | Фичи                                                          |
| ------- | -------------------------------------------------------------- |
| ES2017  | `async`/`await`, `Object.entries()`, string padding            |
| ES2018  | Rest/spread для объектов, `for await...of`, `Promise.finally()` |
| ES2019  | `Array.flat()`, `Object.fromEntries()`, optional catch binding |
| ES2020  | `?.` (optional chaining), `??` (nullish coalescing), `BigInt`  |
| ES2021  | `??=`, `||=`, `&&=` (logical assignment), `Promise.any()`      |
| ES2022  | Top-level `await`, `.at()`, `Object.hasOwn()`, class fields    |
| ES2023  | `findLast()`, `toSorted()`, `toReversed()`, `toSpliced()`     |
| ES2024  | `Object.groupBy()`, `Promise.withResolvers()`, `ArrayBuffer`  |
| ES2025  | Set methods (union, intersection), RegExp escaping             |

## Strict Mode

Strict mode - это режим, в котором JS-движок применяет более строгие правила. Он устраняет «тихие» ошибки, запрещает небезопасные конструкции и резервирует ключевые слова для будущих версий.

```js
"use strict";

// Без strict mode - создаёт глобальную переменную (тихая ошибка)
// В strict mode - ReferenceError
mistypedVariable = 42;

// Без strict mode - тихо игнорируется
// В strict mode - TypeError
const obj = Object.freeze({ a: 1 });
obj.a = 2;

// Без strict mode - удаление переменной тихо возвращает false
// В strict mode - SyntaxError
var x = 10;
delete x;
```

<b class="text-on-semi-light">Что запрещает strict mode:</b>

- Использование необъявленных переменных (нет случайных глобальных)
- Дублирование параметров функции (`function f(a, a)`)
- Присваивание read-only свойствам и non-writable глобальным (`undefined = 5`)
- `with` statement
- `this` в обычных функциях равен `undefined`, а не `window`
- Восьмеричные литералы (`0123`)

<b class="text-on-semi-light">Как активировать:</b> строка `"use strict";` в начале файла или функции. ES-модули (`import`/`export`) автоматически работают в strict mode.

<span class="text-gray">На практике: если ты используешь ES-модули (а ты используешь) - strict mode уже включён. Но знать, что он делает, нужно обязательно.</span>

## Среды выполнения

JavaScript всегда работает внутри host-окружения. Каждое окружение предоставляет свои API поверх ядра ECMAScript.

| Среда          | Движок         | Что предоставляет                                       |
| -------------- | -------------- | ------------------------------------------------------- |
| **Браузер**    | V8 / SM / JSC  | DOM, BOM, fetch, Web API, localStorage, Canvas, WebGL   |
| **Node.js**    | V8             | fs, http, streams, child_process, Buffer, npm           |
| **Deno**       | V8             | fetch (нативный), Permissions API, TypeScript из коробки |
| **Bun**        | JSC            | Быстрый runtime, bundler, test runner, npm-совместимость |
| **Electron**   | V8 (Chromium)  | Node.js + браузер API в одном процессе                   |
| **React Native** | JSC / Hermes | Нативные мобильные компоненты через JS Bridge           |

<b class="text-on-semi-light">На фронте:</b> Когда ты пишешь `document.querySelector()` - это не JavaScript. Это Web API браузера. Когда пишешь `const x = 5` - это ECMAScript. Различать язык и окружение - важный навык для собеседования.

## JavaScript-движки

Движок - это программа, которая парсит, компилирует и выполняет JavaScript-код.

### V8 (Google)

Используется в Chrome, Node.js, Deno, Electron. Самый распространённый движок. Этапы выполнения:

1. **Parsing** - исходный код -> AST (Abstract Syntax Tree)
2. **Ignition** - AST -> bytecode (быстрая интерпретация)
3. **TurboFan** - «горячий» bytecode -> оптимизированный машинный код
4. **Deoptimization** - если допущения оптимизатора нарушены, откат к bytecode

### SpiderMonkey (Mozilla)

Движок Firefox. Первый JS-движок в истории (создан Brendan Eich). Использует Warp JIT-компилятор.

### JavaScriptCore / Nitro (Apple)

Движок Safari и Bun. Три уровня JIT: LLInt -> Baseline -> DFG -> FTL.

<span class="text-gray">Все три движка реализуют один и тот же стандарт ECMAScript, но внутренняя оптимизация различается. Поэтому производительность одного и того же кода может отличаться в разных браузерах.</span>

> Подробнее о том, как код превращается в машинные инструкции - [Как выполняется код](/content/computer-science/running-the-code).

## Node.js

Node.js - среда выполнения JavaScript вне браузера, построенная на движке V8.

<b class="text-on-semi-light">Архитектура</b>

- **V8** - JS-движок от Google. JIT-компилирует JS в машинный код. Оптимизации: Hidden Classes, Inline Caching
- **libuv** - библиотека для асинхронного I/O. Реализует Event Loop, thread pool для блокирующих операций (fs, crypto, DNS)
- **C++ bindings** - связь JS с системными API (файлы, сеть, процессы)
- **Стандартная библиотека** - встроенные модули: `fs`, `http`, `crypto`, `path`, `stream`
- **npm** - менеджер пакетов с миллионами модулей

<b class="text-on-semi-light">Как выполняется код</b>

<span class="text-gray">JS-код -> V8 (JIT-компиляция) -> Асинхронные операции передаются в libuv -> libuv добавляет задачи в Event Loop -> Результат возвращается в JS через callback/Promise/async-await.</span>

> Подробнее о Event Loop -> [Event Loop](/content/javascript/event-loop)

## Частые вопросы на собесе

**Что такое JavaScript? Охарактеризуй язык.**
Высокоуровневый, динамически и слабо типизированный, однопоточный, JIT-компилируемый, встраиваемый, мультипарадигменный язык. Каждая характеристика имеет конкретные следствия: динамическая типизация - типы определяются в runtime; слабая типизация - автоматическое приведение типов; однопоточный - один call stack, асинхронность через Event Loop.

**В чём разница между JavaScript и ECMAScript?**
ECMAScript - это спецификация (стандарт), JavaScript - это реализация этой спецификации. Спецификация описывает синтаксис, типы, операторы. API вроде DOM, fetch, setTimeout - это не часть ECMAScript, а Web API, предоставляемые host-окружением (браузером).

**Что делает strict mode?**
Включает строгий режим: запрещает необъявленные переменные, дублирование параметров, `with`, делает `this` в обычных функциях `undefined` вместо `window`. Активируется через `"use strict";` или автоматически в ES-модулях.

**Что такое JIT-компиляция?**
Just-In-Time - компиляция во время выполнения. Движок сначала интерпретирует код (быстрый старт), затем профилирует «горячие» участки и компилирует их в оптимизированный машинный код. Если допущения нарушаются - происходит deoptimization (откат к интерпретации).

**Зачем нужны разные среды выполнения (Node, Deno, Bun)?**
Каждая среда использует JS-движок, но предоставляет разные API и модели безопасности. Node.js - стандарт для серверного JS. Deno - безопасный runtime с TypeScript из коробки. Bun - максимальная скорость, совместимость с npm.
