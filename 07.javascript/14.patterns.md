# Паттерны

Паттерны - это проверенные решения типовых задач. В JavaScript они особенно важны, потому что язык мультипарадигменный: можно писать в функциональном, объектно-ориентированном, событийном стиле - и часто комбинировать все три. На собеседованиях паттерны показывают, что ты не просто «пишешь код, который работает», а **думаешь об архитектуре**.

---

## Функциональные паттерны

### Pure functions

Pure function (чистая функция) - функция, которая:
1. При одинаковых аргументах **всегда** возвращает одинаковый результат
2. Не имеет **побочных эффектов** (не изменяет внешнее состояние, DOM, файлы, сеть)

```js
// Pure - зависит только от аргументов
function add(a, b) {
  return a + b;
}

// Impure - зависит от внешнего состояния
let tax = 0.2;
function addTax(price) {
  return price + price * tax; // результат зависит от tax
}

// Impure - побочный эффект (мутация аргумента)
function addItem(cart, item) {
  cart.push(item); // мутирует входной массив
  return cart;
}

// Pure версия - возвращает новый массив
function addItemPure(cart, item) {
  return [...cart, item];
}
```

<b class="text-on-semi-light">Зачем:</b> <span class="text-gray">Pure functions предсказуемы, легко тестируются (не нужны моки), безопасны для параллельного выполнения, легко кэшируются (memoization). React-компоненты - концептуально pure functions от props.</span>

### Immutability

Immutability - принцип: **не мутировать данные**, а создавать новые копии с изменениями.

```js
// Мутация - плохо
const user = { name: 'Alice', age: 25 };
user.age = 26; // мутируем оригинал

// Immutable update - хорошо
const updatedUser = { ...user, age: 26 }; // новый объект
```

```js
// Object.freeze - shallow freeze
const config = Object.freeze({
  api: 'https://api.example.com',
  timeout: 5000,
  headers: { 'Content-Type': 'application/json' }
});

config.timeout = 3000; // тихо игнорируется (strict mode -> TypeError)
config.headers['Accept'] = '*/*'; // РАБОТАЕТ - freeze неглубокий!
```

```js
// Deep immutability: structuredClone + freeze
function deepFreeze(obj) {
  Object.freeze(obj);
  Object.values(obj).forEach(val => {
    if (typeof val === 'object' && val !== null && !Object.isFrozen(val)) {
      deepFreeze(val);
    }
  });
  return obj;
}
```

<span class="text-gray">В больших проектах для immutable updates используют библиотеку Immer: пишешь «мутирующий» код, а Immer под капотом создаёт новый объект через Proxy. Redux Toolkit использует Immer по умолчанию.</span>

### Currying

Currying - трансформация функции с несколькими аргументами в цепочку функций с одним аргументом: `f(a, b)` -> `f(a)(b)`.

```js
// Обычная функция
function multiply(a, b) {
  return a * b;
}

// Каррированная версия
function curriedMultiply(a) {
  return function (b) {
    return a * b;
  };
}

// Или с arrow functions
const curriedMultiply2 = (a) => (b) => a * b;

const double = curriedMultiply(2);
const triple = curriedMultiply(3);

console.log(double(5));  // 10
console.log(triple(5));  // 15
```

```js
// Практический пример: создание formatter'ов
const formatCurrency = (currency) => (amount) =>
  new Intl.NumberFormat('ru-RU', { style: 'currency', currency }).format(amount);

const formatUSD = formatCurrency('USD');
const formatEUR = formatCurrency('EUR');

formatUSD(1234.5); // '$1,234.50'
formatEUR(1234.5); // '€1,234.50'
```

### Partial application

Partial application - фиксация части аргументов функции. В JS это делается через `bind`:

```js
function log(level, timestamp, message) {
  console.log(`[${level}] ${timestamp}: ${message}`);
}

// Фиксируем level
const logError = log.bind(null, 'ERROR');
const logInfo = log.bind(null, 'INFO');

logError(Date.now(), 'Something went wrong');
logInfo(Date.now(), 'Server started');
```

<b class="text-on-semi-light">Currying vs Partial application:</b> <span class="text-gray">Currying всегда превращает f(a, b, c) в f(a)(b)(c) - по одному аргументу. Partial application фиксирует любое количество аргументов: f(a, b, c) -> g(c) где a и b уже заданы.</span>

### Compose и pipe

Compose - объединение нескольких функций в одну: результат одной передаётся в следующую.

```js
// compose: выполнение справа налево
// compose(f, g)(x) = f(g(x))
const compose = (...fns) => (x) => fns.reduceRight((acc, fn) => fn(acc), x);

// pipe: выполнение слева направо
// pipe(f, g)(x) = g(f(x))
const pipe = (...fns) => (x) => fns.reduce((acc, fn) => fn(acc), x);
```

```js
// Пример: обработка строки
const trim = (s) => s.trim();
const toLowerCase = (s) => s.toLowerCase();
const split = (delimiter) => (s) => s.split(delimiter);

const processInput = pipe(trim, toLowerCase, split(' '));

processInput('  Hello World  '); // ['hello', 'world']
```

<span class="text-gray">Pipe читается естественнее (слева направо), поэтому используется чаще. TC39 рассматривает pipe operator (`|>`) как языковую фичу.</span>

### Higher-order functions

Higher-order function (HOF) - функция, которая принимает функцию как аргумент и/или возвращает функцию.

```js
// Retry с экспоненциальной задержкой
function withRetry(fn, maxRetries = 3) {
  return async function (...args) {
    for (let attempt = 0; attempt <= maxRetries; attempt++) {
      try {
        return await fn(...args);
      } catch (error) {
        if (attempt === maxRetries) throw error;
        const delay = Math.pow(2, attempt) * 100;
        await new Promise((r) => setTimeout(r, delay));
      }
    }
  };
}

const fetchWithRetry = withRetry(fetch, 3);
const response = await fetchWithRetry('/api/data');
```

```js
// Memoize - кэширование результатов pure function
function memoize(fn) {
  const cache = new Map();
  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

const factorial = memoize((n) => (n <= 1 ? 1 : n * factorial(n - 1)));
```

## Event-driven паттерны

### EventEmitter

Паттерн, где объект поддерживает регистрацию обработчиков и их вызов при наступлении события:

```js
class EventEmitter {
  #listeners = new Map();

  on(event, callback) {
    if (!this.#listeners.has(event)) {
      this.#listeners.set(event, new Set());
    }
    this.#listeners.get(event).add(callback);
    return this; // chaining
  }

  off(event, callback) {
    this.#listeners.get(event)?.delete(callback);
    return this;
  }

  emit(event, ...args) {
    this.#listeners.get(event)?.forEach((cb) => cb(...args));
    return this;
  }

  once(event, callback) {
    const wrapper = (...args) => {
      callback(...args);
      this.off(event, wrapper);
    };
    return this.on(event, wrapper);
  }
}

// Использование
const bus = new EventEmitter();
bus.on('user:login', (user) => console.log(`${user.name} logged in`));
bus.emit('user:login', { name: 'Alice' });
```

<span class="text-gray">В браузере есть нативный аналог - EventTarget. Node.js предоставляет встроенный EventEmitter в модуле `events`.</span>

### Pub/Sub

Pub/Sub (Publisher/Subscriber) - разновидность event-driven паттерна с промежуточным «брокером». Publisher не знает о subscriber'ах, и наоборот. Связь - через именованные каналы (topics).

```js
// Простой Pub/Sub broker
const PubSub = {
  _topics: new Map(),

  subscribe(topic, callback) {
    if (!this._topics.has(topic)) {
      this._topics.set(topic, new Set());
    }
    this._topics.get(topic).add(callback);

    // Возвращаем функцию отписки
    return () => this._topics.get(topic)?.delete(callback);
  },

  publish(topic, data) {
    this._topics.get(topic)?.forEach((cb) => cb(data));
  }
};

// Модуль A - publisher (не знает о subscriber'ах)
PubSub.publish('cart:updated', { items: 3, total: 2500 });

// Модуль B - subscriber (не знает о publisher'е)
const unsub = PubSub.subscribe('cart:updated', (data) => {
  updateCartBadge(data.items);
});
```

### Observer

Observer - паттерн, где «наблюдаемый» объект (Subject) хранит список наблюдателей (Observers) и уведомляет их об изменениях:

```js
class Subject {
  #observers = new Set();

  subscribe(observer) {
    this.#observers.add(observer);
    return () => this.#observers.delete(observer);
  }

  notify(data) {
    this.#observers.forEach((observer) => observer.update(data));
  }
}

// Наблюдатели реализуют интерфейс с методом update
const logger = { update: (data) => console.log('Log:', data) };
const analytics = { update: (data) => trackEvent(data) };

const store = new Subject();
store.subscribe(logger);
store.subscribe(analytics);
store.notify({ action: 'purchase', amount: 100 });
```

### Observer vs Pub/Sub

| Характеристика    | Observer                      | Pub/Sub                          |
| ----------------- | ----------------------------- | -------------------------------- |
| **Связь**         | Subject знает об Observer'ах  | Publisher не знает о Subscriber'ах |
| **Посредник**     | Нет (прямая подписка)         | Есть (broker / event bus)        |
| **Coupling**      | Tighter                       | Looser                           |
| **Пример**        | DOM events, RxJS Observable   | Redis Pub/Sub, message queues    |
| **Когда**         | Компоненты в одном модуле     | Разные модули, микросервисы      |

## Другие полезные паттерны

### Module pattern

До ESM модули создавались через IIFE + closure:

```js
const Counter = (function () {
  let count = 0; // private

  return {
    increment() { count++; },
    decrement() { count--; },
    getCount() { return count; }
  };
})();

Counter.increment();
Counter.increment();
Counter.getCount(); // 2
// count недоступен снаружи
```

<span class="text-gray">Сейчас Module pattern менее актуален - ESM (import/export) решает проблему инкапсуляции на уровне языка. Но понимание паттерна важно: он объясняет, как работают closures, и встречается в legacy коде. Подробнее -> [Замыкания](/content/javascript/closures).</span>

### Singleton

Singleton - объект, существующий в единственном экземпляре:

```js
// Через модуль (ESM) - самый простой способ
// config.js
class Config {
  #settings = {};

  set(key, value) { this.#settings[key] = value; }
  get(key) { return this.#settings[key]; }
}

export const config = new Config();
// Каждый import получает один и тот же экземпляр
```

```js
// Через closure (до ESM)
const Database = (function () {
  let instance;

  function createInstance() {
    return {
      connection: null,
      connect(url) { this.connection = url; },
      query(sql) { /* ... */ }
    };
  }

  return {
    getInstance() {
      if (!instance) instance = createInstance();
      return instance;
    }
  };
})();

const db1 = Database.getInstance();
const db2 = Database.getInstance();
console.log(db1 === db2); // true
```

### Factory function vs constructor

```js
// Constructor - создаёт экземпляры через new
class UserConstructor {
  constructor(name, role) {
    this.name = name;
    this.role = role;
  }

  greet() { return `Hi, I'm ${this.name}`; }
}

const user1 = new UserConstructor('Alice', 'admin');
```

```js
// Factory function - возвращает объект без new
function createUser(name, role) {
  // Private state через closure
  let loginCount = 0;

  return {
    name,
    role,
    greet() { return `Hi, I'm ${name}`; },
    login() { loginCount++; },
    getLoginCount() { return loginCount; }
  };
}

const user2 = createUser('Bob', 'user');
```

| Характеристика    | Constructor / class         | Factory function              |
| ----------------- | --------------------------- | ----------------------------- |
| **Синтаксис**     | `new Class()`               | `createThing()`               |
| **this**          | Да                          | Нет (можно избежать)          |
| **Private**       | `#field` (ES2022)           | Closure                       |
| **instanceof**    | Работает                    | Не работает                   |
| **Наследование**  | `extends`                   | Composition                   |
| **Flexibility**   | Фиксированная структура     | Может возвращать разные формы |

### Strategy pattern

Стратегия - выбор алгоритма в runtime. В JS функции первого класса делают этот паттерн простым:

```js
// Стратегии валидации
const validators = {
  email: (value) => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value),
  phone: (value) => /^\+?\d{10,15}$/.test(value),
  required: (value) => value !== null && value !== undefined && value !== ''
};

function validate(value, strategies) {
  return strategies.every((strategy) => validators[strategy](value));
}

validate('test@mail.com', ['required', 'email']); // true
validate('', ['required', 'email']);               // false
```

```js
// Стратегии сортировки
const sortStrategies = {
  byName: (a, b) => a.name.localeCompare(b.name),
  byPrice: (a, b) => a.price - b.price,
  byDate: (a, b) => new Date(b.date) - new Date(a.date)
};

function sortProducts(products, strategy) {
  return [...products].sort(sortStrategies[strategy]);
}
```

### Middleware pattern

Middleware - цепочка функций, каждая из которых может обработать запрос и передать его дальше (или прервать цепочку). Используется в Express, Koa, Redux:

```js
class Pipeline {
  #middlewares = [];

  use(fn) {
    this.#middlewares.push(fn);
    return this;
  }

  async execute(context) {
    let index = 0;

    const next = async () => {
      if (index < this.#middlewares.length) {
        const middleware = this.#middlewares[index++];
        await middleware(context, next);
      }
    };

    await next();
    return context;
  }
}

// Использование
const pipeline = new Pipeline();

pipeline
  .use(async (ctx, next) => {
    ctx.startTime = Date.now();
    await next();
    ctx.duration = Date.now() - ctx.startTime;
  })
  .use(async (ctx, next) => {
    console.log(`Request: ${ctx.method} ${ctx.url}`);
    await next();
  })
  .use(async (ctx, next) => {
    ctx.body = { status: 'ok' };
    // Не вызываем next() - конец цепочки
  });

await pipeline.execute({ method: 'GET', url: '/api/data' });
```

<span class="text-gray">Middleware pattern - основа архитектуры Express, Koa, Redux middleware. Понимание этого паттерна помогает писать composable, testable серверный и клиентский код. Подробнее о функциях как аргументах -> [Функции](/content/javascript/functions).</span>

## Частые вопросы на собесе

**Что такое pure function?**
Функция без побочных эффектов, которая при одинаковых аргументах всегда возвращает одинаковый результат. Не изменяет внешнее состояние, не читает его. Легко тестируется, кэшируется, предсказуема.

**В чём разница между currying и partial application?**
Currying трансформирует `f(a, b, c)` в `f(a)(b)(c)` - всегда по одному аргументу. Partial application фиксирует часть аргументов: `f(a, b, c)` -> `g(c)` где `a` и `b` уже заданы. `bind` в JS делает partial application.

**Объясни паттерн Observer**
Subject (наблюдаемый объект) хранит список observer'ов и уведомляет их при изменении состояния. Пример: DOM events - элемент (Subject) уведомляет event listener'ы (Observers) о клике. В отличие от Pub/Sub, Observer - прямая связь без посредника.

**Когда factory function лучше класса?**
Когда не нужен `new`, `this`, `instanceof`, наследование. Factory function проще, гибче (может возвращать разные формы объектов), обеспечивает приватность через closure. Класс лучше для сложных иерархий и когда нужен `instanceof`.

**Что такое middleware pattern?**
Цепочка функций, каждая из которых обрабатывает запрос и решает - передать дальше (`next()`) или остановить. Express, Redux, Koa построены на этом паттерне. Позволяет декомпозировать обработку на независимые шаги.

**Зачем compose/pipe?**
Объединяют несколько простых функций в одну сложную без промежуточных переменных. `pipe(trim, lowercase, split)` читабельнее, чем `split(lowercase(trim(str)))`. Основа функционального стиля.
