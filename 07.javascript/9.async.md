# Асинхронность

Асинхронность - способность выполнять операции **не блокируя** основной поток. Без неё каждый HTTP-запрос, каждое чтение файла, каждый таймер замораживали бы интерфейс. JavaScript прошёл путь от callback hell до элегантного async/await, и на собесе нужно уверенно владеть всеми этапами этой эволюции.

---

## Зачем нужна асинхронность

JavaScript однопоточный. Если выполнить сетевой запрос синхронно - весь UI заблокирован, пока ответ не придёт:

```js
// Гипотетический синхронный fetch (так делать нельзя)
const data = syncFetch("/api/users"); // UI заморожен на 2 секунды
renderUsers(data); // только теперь продолжится работа
```

Асинхронность позволяет:
- **Не блокировать UI** - пользователь может скроллить, кликать, пока данные загружаются
- **Выполнять параллельные операции** - несколько запросов одновременно
- **Реагировать на события** - клики, ввод, таймеры

<span class="text-gray">Под «параллельностью» здесь имеется в виду concurrency (конкурентность), а не parallelism. JS не выполняет код параллельно - он переключается между задачами через [Event Loop](/content/javascript/event-loop).</span>

## Callbacks

Callback - это функция, переданная как аргумент другой функции, которая вызывается по завершении асинхронной операции.

```js
function fetchUser(id, callback) {
  setTimeout(() => {
    const user = { id, name: "Alice" };
    callback(null, user); // error-first convention
  }, 1000);
}

fetchUser(1, (error, user) => {
  if (error) {
    console.error(error);
    return;
  }
  console.log(user);
});
```

### Error-first convention (Node.js style)

В Node.js принято: первый аргумент callback - ошибка, второй - результат:

```js
fs.readFile("data.json", "utf8", (err, data) => {
  if (err) {
    console.error("Ошибка чтения:", err);
    return;
  }
  console.log(data);
});
```

### Callback Hell

Вложенные callbacks создают «пирамиду смерти» - код уходит вправо, его невозможно читать и поддерживать:

```js
getUser(userId, (err, user) => {
  if (err) return handleError(err);
  getOrders(user.id, (err, orders) => {
    if (err) return handleError(err);
    getOrderDetails(orders[0].id, (err, details) => {
      if (err) return handleError(err);
      getShippingInfo(details.shippingId, (err, shipping) => {
        if (err) return handleError(err);
        renderPage(user, orders, details, shipping);
      });
    });
  });
});
```

Проблемы callback hell:
- **Readability** - код сложно читать
- **Error handling** - проверка `err` на каждом уровне
- **Inversion of control** - ты передаёшь управление чужой функции (а вдруг она вызовет callback дважды?)
- **Composability** - сложно комбинировать, отменять, повторять

<b class="text-on-semi-light">Решение:</b> Promises устранили все эти проблемы.

## Promises

Promise - это объект, представляющий **будущий результат** асинхронной операции.

### Три состояния

```text
                  resolve(value)
                ┌──────────────────> fulfilled (значение)
                │
pending ────────┤
(ожидание)      │
                └──────────────────> rejected (причина)
                  reject(reason)
```

- **pending** - начальное состояние, операция выполняется
- **fulfilled** - операция завершена успешно, есть значение
- **rejected** - операция завершена с ошибкой, есть причина

<b class="text-on-semi-light">Важно:</b> Состояние меняется **один раз** и навсегда. Fulfilled или rejected - это финальные состояния (settled). Нельзя перейти из fulfilled в rejected или наоборот.

### Создание Promise

```js
const promise = new Promise((resolve, reject) => {
  // асинхронная операция
  const success = true;

  if (success) {
    resolve("Данные получены"); // -> fulfilled
  } else {
    reject(new Error("Что-то пошло не так")); // -> rejected
  }
});
```

### Цепочки - then, catch, finally

```js
fetch("/api/users")
  .then((response) => response.json()) // получили Response -> парсим JSON
  .then((users) => {
    console.log(users); // получили данные
    return users.length;
  })
  .then((count) => {
    console.log(`Всего ${count} пользователей`);
  })
  .catch((error) => {
    // ловит ошибку из ЛЮБОГО .then() выше
    console.error("Ошибка:", error);
  })
  .finally(() => {
    // выполняется ВСЕГДА (и при успехе, и при ошибке)
    hideLoader();
  });
```

<b class="text-on-semi-light">Ключевое:</b> Каждый `.then()` возвращает **новый Promise**. Это позволяет строить цепочки. Если `.then()` возвращает значение - следующий `.then()` получит его. Если возвращает Promise - следующий `.then()` ждёт его разрешения.

### Promise combinators

Четыре статических метода для работы с массивами промисов:

#### Promise.all - все или ничего

```js
const results = await Promise.all([
  fetch("/api/users"),
  fetch("/api/posts"),
  fetch("/api/comments"),
]);
// results - массив из трёх Response
// Если ЛЮБОЙ промис rejected -> весь Promise.all rejected
```

<span class="text-gray">Используй, когда нужны **все** результаты и нет смысла продолжать, если хоть один запрос упал.</span>

#### Promise.allSettled - все, включая ошибки

```js
const results = await Promise.allSettled([
  fetch("/api/users"),
  fetch("/api/broken-endpoint"),
  fetch("/api/posts"),
]);

results.forEach((result) => {
  if (result.status === "fulfilled") {
    console.log("Успех:", result.value);
  } else {
    console.log("Ошибка:", result.reason);
  }
});
// Ждёт ВСЕ промисы, даже если некоторые rejected
```

<span class="text-gray">Используй, когда нужно выполнить все запросы независимо друг от друга и обработать каждый результат отдельно.</span>

#### Promise.race - первый финишировавший

```js
const result = await Promise.race([
  fetch("/api/data"),
  new Promise((_, reject) =>
    setTimeout(() => reject(new Error("Timeout")), 5000)
  ),
]);
// Возвращает результат ПЕРВОГО settled промиса (fulfilled ИЛИ rejected)
```

<span class="text-gray">Классический паттерн - timeout для запроса. Кто первый: ответ сервера или таймер?</span>

#### Promise.any - первый успешный

```js
const fastest = await Promise.any([
  fetch("https://cdn1.example.com/data"),
  fetch("https://cdn2.example.com/data"),
  fetch("https://cdn3.example.com/data"),
]);
// Возвращает первый FULFILLED промис
// Если ВСЕ rejected -> AggregateError
```

<span class="text-gray">Используй для race между несколькими источниками - кто первый ответит успешно.</span>

### Сравнительная таблица combinators

| Метод              | Ждёт                        | Результат при ошибке одного          | Use case                  |
| ------------------ | ---------------------------- | ------------------------------------ | ------------------------- |
| `Promise.all`      | Все fulfilled                | Reject с первой ошибкой             | Все данные нужны          |
| `Promise.allSettled`| Все settled                 | Массив с status fulfilled/rejected  | Независимые запросы       |
| `Promise.race`     | Первый settled               | Результат первого (любого)          | Timeout, fastest response |
| `Promise.any`      | Первый fulfilled             | AggregateError если все rejected    | Fallback между серверами  |

### Promise.resolve и Promise.reject

Shortcuts для создания уже разрешённых промисов:

```js
// Оборачивает значение в fulfilled Promise
const p1 = Promise.resolve(42);
// эквивалент: new Promise(resolve => resolve(42))

// Создаёт rejected Promise
const p2 = Promise.reject(new Error("fail"));
// эквивалент: new Promise((_, reject) => reject(new Error("fail")))
```

<b class="text-on-semi-light">Полезно для:</b> нормализации API (функция всегда возвращает Promise), создания microtasks (`Promise.resolve().then(fn)`), тестирования.

### Частые ошибки с Promises

```js
// Ошибка 1: забыли return в .then()
fetch("/api/users")
  .then((response) => {
    response.json(); // забыли return! следующий .then получит undefined
  })
  .then((data) => {
    console.log(data); // undefined
  });

// Правильно:
fetch("/api/users")
  .then((response) => {
    return response.json(); // return!
  })
  .then((data) => {
    console.log(data); // данные
  });

// Ошибка 2: unhandled rejection
fetch("/api/data").then((response) => response.json());
// Если fetch упадёт - ошибка "провалится" незамеченной
// Всегда добавляй .catch()!

// Ошибка 3: Promise constructor anti-pattern
// Плохо - оборачивать Promise в new Promise
function getData() {
  return new Promise((resolve, reject) => {
    fetch("/api/data")
      .then((response) => resolve(response.json()))
      .catch((err) => reject(err));
  });
}

// Хорошо - просто вернуть промис
function getData() {
  return fetch("/api/data").then((response) => response.json());
}
```

## async/await

async/await - **синтаксический сахар** над Promises. Код выглядит синхронным, но работает асинхронно.

### Базовый синтаксис

```js
async function fetchUsers() {
  const response = await fetch("/api/users");
  const users = await response.json();
  return users; // автоматически обёрнуто в Promise
}

// async function ВСЕГДА возвращает Promise
fetchUsers().then((users) => console.log(users));
```

### Как работает await

```js
async function example() {
  console.log("before await"); // синхронно

  const result = await someAsyncOperation();
  // await приостанавливает выполнение ВНУТРИ async function
  // но НЕ блокирует основной поток!
  // код после await - microtask (как .then())

  console.log("after await", result); // microtask
}
```

<b class="text-on-semi-light">Важно:</b> `await` не блокирует поток. Он приостанавливает выполнение **только внутри** текущей async-функции. Остальной код продолжает работать. Код после `await` эквивалентен callback в `.then()`.

### Error handling в async/await

Два подхода:

```js
// Подход 1: try/catch (самый распространённый)
async function fetchData() {
  try {
    const response = await fetch("/api/data");
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    const data = await response.json();
    return data;
  } catch (error) {
    console.error("Ошибка:", error);
    throw error; // пробрасываем дальше
  }
}

// Подход 2: .catch() на вызове
const data = await fetchData().catch((error) => {
  console.error(error);
  return null; // fallback значение
});
```

### Параллельные vs последовательные запросы

```js
// ПЛОХО - последовательно (каждый ждёт предыдущий)
async function sequential() {
  const users = await fetch("/api/users"); // ждём 1 сек
  const posts = await fetch("/api/posts"); // ещё 1 сек
  const comments = await fetch("/api/comments"); // ещё 1 сек
  // Итого: ~3 секунды
}

// ХОРОШО - параллельно через Promise.all
async function parallel() {
  const [users, posts, comments] = await Promise.all([
    fetch("/api/users"),
    fetch("/api/posts"),
    fetch("/api/comments"),
  ]);
  // Итого: ~1 секунда (самый медленный запрос)
}
```

⚠️ Последовательные `await` - одна из самых частых ошибок на собесе и в реальном коде. Если запросы **не зависят** друг от друга - всегда используй `Promise.all`.

### Top-level await

В ES Modules (ESM) можно использовать `await` на верхнем уровне без обёртки в async function:

```js
// module.mjs (только ESM, не CommonJS)
const response = await fetch("/api/config");
const config = await response.json();

export default config;
```

<span class="text-gray">Top-level await блокирует загрузку модуля и всех модулей, которые его импортируют. Используй осторожно - только для инициализации, не для тяжёлых операций.</span>

## Паттерны асинхронного кода

### Sequential execution - когда порядок важен

```js
async function processItems(items) {
  const results = [];
  for (const item of items) {
    const result = await processItem(item); // каждый ждёт предыдущий
    results.push(result);
  }
  return results;
}
```

⚠️ Не используй `forEach` с async/await - он не ждёт:

```js
// ПЛОХО - forEach не ждёт async callbacks
items.forEach(async (item) => {
  await processItem(item); // forEach не ждёт завершения
});
console.log("done"); // выводится ДО завершения обработки

// ХОРОШО - for...of
for (const item of items) {
  await processItem(item);
}
console.log("done"); // выводится ПОСЛЕ завершения обработки
```

### Parallel execution с контролем

```js
// Все параллельно
const results = await Promise.all(items.map((item) => processItem(item)));

// С ограничением параллельности (batching)
async function processBatch(items, batchSize = 5) {
  const results = [];
  for (let i = 0; i < items.length; i += batchSize) {
    const batch = items.slice(i, i + batchSize);
    const batchResults = await Promise.all(
      batch.map((item) => processItem(item))
    );
    results.push(...batchResults);
  }
  return results;
}
```

### for await...of - async iteration

```js
async function* generateNumbers() {
  for (let i = 0; i < 5; i++) {
    await new Promise((resolve) => setTimeout(resolve, 100));
    yield i;
  }
}

// Async iteration
for await (const num of generateNumbers()) {
  console.log(num); // 0, 1, 2, 3, 4 (с интервалом 100ms)
}
```

<span class="text-gray">`for await...of` работает с любым объектом, реализующим async iterable protocol (`Symbol.asyncIterator`). Используется для потоковых данных: чтение файлов по частям, WebSocket-сообщения, пагинация API.</span>

### AbortController - отмена асинхронных операций

```js
const controller = new AbortController();
const { signal } = controller;

// Запускаем запрос с signal
fetch("/api/data", { signal })
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((error) => {
    if (error.name === "AbortError") {
      console.log("Запрос отменён");
    } else {
      console.error("Ошибка:", error);
    }
  });

// Отменяем через 5 секунд
setTimeout(() => controller.abort(), 5000);
```

<b class="text-on-semi-light">Типичные use cases:</b> отмена запроса при размонтировании компонента (React useEffect cleanup), отмена предыдущего запроса при новом вводе (search autocomplete), timeout.

```js
// Timeout через AbortSignal.timeout() (современный API)
fetch("/api/data", { signal: AbortSignal.timeout(5000) });

// Отмена при размонтировании (React-паттерн)
useEffect(() => {
  const controller = new AbortController();

  fetch("/api/data", { signal: controller.signal })
    .then((r) => r.json())
    .then(setData)
    .catch((e) => {
      if (e.name !== "AbortError") console.error(e);
    });

  return () => controller.abort(); // cleanup
}, []);
```

## Эволюция асинхронности в JS

| Подход          | Год     | Плюсы                        | Минусы                        |
| --------------- | ------- | ----------------------------- | ----------------------------- |
| Callbacks       | Всегда  | Простота, универсальность     | Callback hell, inversion of control |
| Promises        | ES2015  | Цепочки, combinators, .catch | Verbose для простых случаев   |
| async/await     | ES2017  | Читаемость, try/catch        | Легко забыть о параллельности |
| Top-level await | ES2022  | Удобство в модулях           | Блокирует загрузку модуля     |

## Частые вопросы на собесе

**Чем отличается Promise.all от Promise.allSettled?**
`Promise.all` rejected при первой ошибке - остальные промисы игнорируются. `Promise.allSettled` ждёт ВСЕ промисы и возвращает массив с `{status, value/reason}` для каждого. Используй `allSettled`, когда запросы независимы и нужно обработать каждый результат отдельно.

**Что делает await внутри async function?**
`await` приостанавливает выполнение внутри async-функции (не блокируя поток!) и ждёт разрешения промиса. Код после `await` выполняется как microtask. Это синтаксический сахар над `.then()`.

**Как сделать параллельные запросы с async/await?**
`const [a, b, c] = await Promise.all([fetchA(), fetchB(), fetchC()])`. Последовательные `await` (один за другим) - антипаттерн, если запросы не зависят друг от друга.

**Что такое callback hell и как его избежать?**
Вложенные callbacks, уходящие вправо «пирамидой». Решения: Promises (цепочки вместо вложенности), async/await (синхронный стиль).

**Как отменить fetch-запрос?**
`AbortController`: создать controller, передать `signal` в fetch, вызвать `controller.abort()`. Ловить `AbortError` в catch. Современный вариант: `AbortSignal.timeout(ms)`.

**Почему нельзя использовать forEach с async/await?**
`forEach` вызывает callback, но не ждёт возвращённого Promise. Все итерации запускаются «параллельно» (фактически - друг за другом в один микротик). Используй `for...of` для последовательного выполнения или `Promise.all(arr.map(...))` для параллельного.
