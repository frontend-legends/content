# Прототипы и классы

JavaScript - язык с **прототипным наследованием**. Здесь нет классического наследования как в Java или C++. Когда ты пишешь `class` в JS, под капотом это всё те же прототипы - просто с удобным синтаксисом. Понимание прототипной цепочки объясняет, как работают `instanceof`, наследование, `this` в методах и почему `Object.keys()` не возвращает методы из prototype.

---

## Прототипное наследование

Каждый объект в JS имеет скрытое свойство `[[Prototype]]` - ссылку на другой объект (или `null`). Когда ты обращаешься к свойству объекта, а его нет - движок ищет его в прототипе, затем в прототипе прототипа, и так далее.

### __proto__ vs prototype

Два похожих слова, но **совершенно разные вещи**.

| Понятие        | Что это                                            | Где живёт                |
| -------------- | -------------------------------------------------- | ------------------------ |
| `__proto__`    | Ссылка объекта на его прототип (`[[Prototype]]`)   | На каждом объекте        |
| `prototype`    | Объект, который станет `__proto__` для экземпляров | Только на функциях       |

```js
function User(name) {
  this.name = name;
}

User.prototype.greet = function () {
  return `Hi, ${this.name}`;
};

const alice = new User('Alice');

// alice.__proto__ === User.prototype -> true
// User.prototype.__proto__ === Object.prototype -> true
// Object.prototype.__proto__ === null -> конец цепочки
```

<b class="text-on-semi-light">Object.getPrototypeOf():</b> Правильный способ получить прототип объекта. `__proto__` - legacy accessor, который работает, но не рекомендуется в продакшн-коде.

```js
Object.getPrototypeOf(alice) === User.prototype; // true
Object.getPrototypeOf(User.prototype) === Object.prototype; // true
```

## Prototype chain

Когда JS ищет свойство на объекте, он проходит по цепочке прототипов:

```js
const animal = {
  eats: true,
  walk() {
    return 'walking';
  },
};

const rabbit = {
  jumps: true,
  __proto__: animal,
};

const babyRabbit = {
  size: 'small',
  __proto__: rabbit,
};

babyRabbit.size;  // 'small'   - собственное свойство
babyRabbit.jumps; // true      - найдено в rabbit
babyRabbit.eats;  // true      - найдено в animal
babyRabbit.walk(); // 'walking' - найдено в animal
babyRabbit.fly;   // undefined  - нет нигде в цепочке
```

```text
Prototype chain:
babyRabbit -> rabbit -> animal -> Object.prototype -> null
```

### Запись свойства не затрагивает прототип

```js
babyRabbit.eats = false;
console.log(babyRabbit.eats); // false (собственное свойство)
console.log(animal.eats);     // true (прототип не изменился)
```

При **записи** свойство создаётся на самом объекте (shadowing). При **чтении** - поиск идёт по цепочке.

### hasOwnProperty и in

```js
babyRabbit.hasOwnProperty('size');  // true - собственное
babyRabbit.hasOwnProperty('jumps'); // false - из прототипа

'size' in babyRabbit;  // true
'jumps' in babyRabbit; // true - in проверяет всю цепочку
```

## Object.create()

Создаёт новый объект с указанным прототипом. Самый «чистый» способ настроить прототипное наследование.

```js
const personProto = {
  greet() {
    return `Hi, I'm ${this.name}`;
  },
  toString() {
    return `[Person: ${this.name}]`;
  },
};

const alice = Object.create(personProto);
alice.name = 'Alice';
alice.greet(); // "Hi, I'm Alice"

// Проверяем цепочку
Object.getPrototypeOf(alice) === personProto; // true
```

```js
// Объект без прототипа (совсем пустой - нет даже toString)
const bare = Object.create(null);
bare.key = 'value';
console.log(bare.toString); // undefined (нет Object.prototype)
```

<span class="text-gray">`Object.create(null)` полезен для создания «чистых» словарей без унаследованных свойств. Это гарантирует, что `hasOwnProperty`, `toString` и другие свойства `Object.prototype` не будут мешать.</span>

## Constructor functions (до ES6)

До классов для создания объектов с общим прототипом использовали функции-конструкторы.

```js
function Person(name, age) {
  this.name = name;
  this.age = age;
}

// Методы на prototype - общие для всех экземпляров
Person.prototype.greet = function () {
  return `Hi, I'm ${this.name}, ${this.age} years old`;
};

Person.prototype.isAdult = function () {
  return this.age >= 18;
};

const alice = new Person('Alice', 30);
const bob = new Person('Bob', 17);

alice.greet();   // "Hi, I'm Alice, 30 years old"
bob.isAdult();   // false
```

### Что делает new

1. Создаёт пустой объект `{}`
2. Устанавливает `__proto__` нового объекта на `Constructor.prototype`
3. Вызывает конструктор с `this` = новый объект
4. Если конструктор не возвращает объект явно - возвращает `this`

```js
// Эмуляция new вручную
function myNew(Constructor, ...args) {
  const obj = Object.create(Constructor.prototype); // шаги 1-2
  const result = Constructor.apply(obj, args);       // шаг 3
  return result instanceof Object ? result : obj;    // шаг 4
}

const charlie = myNew(Person, 'Charlie', 25);
charlie.greet(); // "Hi, I'm Charlie, 25 years old"
```

<b class="text-on-semi-light">Зачем методы на prototype, а не в конструкторе?</b> Если поместить метод внутрь конструктора (`this.greet = function() {...}`), каждый экземпляр получит **свою копию** функции. На prototype метод один - и все экземпляры используют его через prototype chain. Экономия памяти.

## ES6 Classes

Классы в ES6 - это **синтаксический сахар** над прототипным наследованием. Под капотом работает то же самое, но синтаксис чище и понятнее.

```js
class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() {
    return `Hi, I'm ${this.name}`;
  }

  get info() {
    return `${this.name}, ${this.age}`;
  }

  static create(name, age) {
    return new Person(name, age);
  }
}

const alice = new Person('Alice', 30);
alice.greet();      // "Hi, I'm Alice"
alice.info;         // "Alice, 30" (getter, без скобок)
Person.create('Bob', 25); // new Person('Bob', 25)
```

### Методы

```js
class Calculator {
  // Instance method - доступен на экземплярах
  add(a, b) {
    return a + b;
  }

  // Static method - доступен только на классе
  static isNumber(val) {
    return typeof val === 'number' && !isNaN(val);
  }
}

const calc = new Calculator();
calc.add(2, 3);           // 5
Calculator.isNumber(42);  // true
calc.isNumber;            // undefined - static не на экземпляре
```

<span class="text-gray">Static methods полезны для utility-функций, factory-методов и операций, которые не зависят от конкретного экземпляра. `Array.isArray()`, `Object.keys()`, `Number.parseInt()` - примеры static methods на встроенных объектах.</span>

## Наследование - extends и super

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} makes a noise`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name); // вызов конструктора родителя - ОБЯЗАТЕЛЬНО перед this
    this.breed = breed;
  }

  speak() {
    return `${this.name} barks`; // переопределение метода
  }

  parentSpeak() {
    return super.speak(); // вызов родительского метода
  }
}

const rex = new Dog('Rex', 'Shepherd');
rex.speak();       // "Rex barks"
rex.parentSpeak(); // "Rex makes a noise"
rex.name;          // "Rex"
rex.breed;         // "Shepherd"
```

⚠️ **Правило:** В constructor наследника нужно вызвать `super()` **до** обращения к `this`. Иначе - ReferenceError.

```js
class Bad extends Animal {
  constructor(name) {
    this.extra = 'oops'; // ReferenceError!
    super(name);
  }
}
```

### Prototype chain с классами

```js
// rex -> Dog.prototype -> Animal.prototype -> Object.prototype -> null

rex instanceof Dog;    // true
rex instanceof Animal; // true
rex instanceof Object; // true
```

## Private fields и methods

ES2022 ввёл настоящие приватные поля и методы через `#`.

```js
class BankAccount {
  #balance;        // private field
  #owner;

  constructor(owner, initialBalance) {
    this.#owner = owner;
    this.#balance = initialBalance;
  }

  deposit(amount) {
    this.#validateAmount(amount);
    this.#balance += amount;
  }

  withdraw(amount) {
    this.#validateAmount(amount);
    if (amount > this.#balance) {
      throw new Error('Insufficient funds');
    }
    this.#balance -= amount;
  }

  get balance() {
    return this.#balance;
  }

  // Private method
  #validateAmount(amount) {
    if (amount <= 0) throw new Error('Amount must be positive');
  }
}

const account = new BankAccount('Alice', 1000);
account.deposit(500);
account.balance;       // 1500 (getter)
account.#balance;      // SyntaxError - настоящая приватность!
account.#validateAmount; // SyntaxError
```

<b class="text-on-semi-light">Отличие от конвенции с _underscore:</b> `this._balance` - это просто соглашение, свойство остаётся публичным. `this.#balance` - синтаксически enforced приватность, недоступно снаружи класса никак (даже через `Object.keys` или `Reflect`).

## Getters и setters

Getters и setters позволяют определить «виртуальные» свойства с логикой при чтении/записи.

### В классах

```js
class Temperature {
  #celsius;

  constructor(celsius) {
    this.#celsius = celsius;
  }

  get fahrenheit() {
    return this.#celsius * 9 / 5 + 32;
  }

  set fahrenheit(f) {
    this.#celsius = (f - 32) * 5 / 9;
  }

  get celsius() {
    return this.#celsius;
  }

  set celsius(c) {
    if (c < -273.15) throw new Error('Below absolute zero');
    this.#celsius = c;
  }
}

const temp = new Temperature(100);
temp.fahrenheit;     // 212
temp.fahrenheit = 32;
temp.celsius;        // 0
```

### В объектных литералах

```js
const user = {
  firstName: 'Alice',
  lastName: 'Smith',

  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  },

  set fullName(value) {
    const [first, last] = value.split(' ');
    this.firstName = first;
    this.lastName = last;
  },
};

user.fullName;           // "Alice Smith"
user.fullName = 'Bob Jones';
user.firstName;          // "Bob"
```

<span class="text-gray">Getters и setters выглядят как обычные свойства при использовании (без скобок), но выполняют код. Полезны для валидации, вычисляемых свойств и совместимости при рефакторинге API объекта.</span>

## instanceof и проверка типов

`instanceof` проверяет, есть ли `Constructor.prototype` в prototype chain объекта.

```js
class Animal {}
class Dog extends Animal {}

const rex = new Dog();

rex instanceof Dog;    // true
rex instanceof Animal; // true
rex instanceof Object; // true

// Под капотом instanceof делает примерно это:
function myInstanceof(obj, Constructor) {
  let proto = Object.getPrototypeOf(obj);
  while (proto !== null) {
    if (proto === Constructor.prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}
```

### Другие способы проверки

```js
// typeof - для примитивов
typeof 'hello';    // 'string'
typeof 42;         // 'number'
typeof null;       // 'object' (исторический баг)

// Object.prototype.toString - надёжный способ
Object.prototype.toString.call([]);     // '[object Array]'
Object.prototype.toString.call(null);   // '[object Null]'

// Array.isArray - для массивов
Array.isArray([1, 2]); // true
Array.isArray('hello'); // false

// constructor
rex.constructor === Dog;    // true
rex.constructor === Animal; // false (constructor - прямой, не по цепочке)
```

## Mixins

JavaScript не поддерживает множественное наследование (класс может extends только один класс). Mixins - паттерн для добавления функциональности из нескольких источников.

```js
// Mixin - обычный объект с методами
const Serializable = {
  toJSON() {
    return JSON.stringify(this);
  },
  fromJSON(json) {
    return Object.assign(this, JSON.parse(json));
  },
};

const Validatable = {
  validate() {
    for (const [key, value] of Object.entries(this)) {
      if (value === null || value === undefined) {
        throw new Error(`${key} is required`);
      }
    }
    return true;
  },
};

class User {
  constructor(name, email) {
    this.name = name;
    this.email = email;
  }
}

// Примешиваем методы
Object.assign(User.prototype, Serializable, Validatable);

const alice = new User('Alice', 'alice@example.com');
alice.validate(); // true
alice.toJSON();   // '{"name":"Alice","email":"alice@example.com"}'
```

### Mixin через функцию (более гибкий подход)

```js
function Timestamped(Base) {
  return class extends Base {
    constructor(...args) {
      super(...args);
      this.createdAt = new Date();
    }

    getAge() {
      return Date.now() - this.createdAt.getTime();
    }
  };
}

function Loggable(Base) {
  return class extends Base {
    log(message) {
      console.log(`[${this.constructor.name}] ${message}`);
    }
  };
}

class User extends Timestamped(Loggable(Object)) {
  constructor(name) {
    super();
    this.name = name;
  }
}

const alice = new User('Alice');
alice.log('created');   // [User] created
alice.createdAt;        // Date object
```

## Class vs prototype - под капотом

Классы в JS - это **syntactic sugar**. Вот доказательство:

```js
class Person {
  constructor(name) {
    this.name = name;
  }
  greet() {
    return `Hi, ${this.name}`;
  }
  static create(name) {
    return new Person(name);
  }
}

// Эквивалент на прототипах:
function PersonOld(name) {
  this.name = name;
}
PersonOld.prototype.greet = function () {
  return `Hi, ${this.name}`;
};
PersonOld.create = function (name) {
  return new PersonOld(name);
};

// Оба варианта дают одинаковый результат
typeof Person;    // 'function' (!)
typeof PersonOld; // 'function'
```

### Но есть отличия

| Аспект               | Constructor function           | ES6 Class                          |
| -------------------- | ------------------------------ | ---------------------------------- |
| Вызов без `new`      | Работает (но `this` = window)  | TypeError                          |
| Hoisting             | Функция поднимается            | Класс в TDZ (как let)             |
| Strict mode          | Нужно включать явно            | Всегда strict                      |
| `prototype` methods  | Enumerable                     | Non-enumerable                     |
| Private fields       | Только через замыкания         | Нативная поддержка через `#`       |
| `super`              | Нет                            | Есть                               |

## Сравнительная таблица

| Критерий              | Constructor function              | ES6 Class                        | Object.create()                |
| --------------------- | --------------------------------- | -------------------------------- | ------------------------------ |
| Синтаксис             | `function F() {}` + `new F()`     | `class C {}` + `new C()`        | `Object.create(proto)`         |
| Наследование          | Ручная настройка prototype        | `extends` + `super`             | Указать прототип напрямую      |
| Private state         | Замыкания                         | `#field`                         | Замыкания или WeakMap          |
| Static methods        | `F.method = ...`                  | `static method() {}`            | Нет (отдельная функция)        |
| `instanceof`          | Работает                          | Работает                         | Работает (если прототип верный)|
| Вызов без new         | Баг (this = window)               | TypeError (защита)               | Не нужен new                   |
| Когда использовать    | Legacy код                        | Современный стандарт             | Простые объекты с прототипом   |

<b class="text-on-semi-light">Рекомендация:</b> Для нового кода используй `class`. Для простых объектов без конструктора - `Object.create()`. Constructor functions - только если работаешь с legacy-кодом.

## Частые вопросы на собесе

**Что такое прототипное наследование?**
Каждый объект в JS имеет скрытую ссылку на другой объект (прототип). При обращении к свойству, которого нет на объекте, JS ищет его по цепочке прототипов вплоть до `null`. Это и есть прототипное наследование - объекты наследуют свойства и методы от других объектов, а не от классов.

**В чём разница между __proto__ и prototype?**
`__proto__` (или `[[Prototype]]`) - это ссылка **экземпляра** на его прототип. `prototype` - свойство **функции-конструктора**, которое станет `__proto__` для объектов, созданных через `new`. Пример: `alice.__proto__ === User.prototype`.

**Что делает new?**
Четыре шага: 1) создаёт пустой объект, 2) устанавливает его `__proto__` на `Constructor.prototype`, 3) вызывает конструктор с `this` = новый объект, 4) возвращает объект (если конструктор не вернул другой объект).

**Classes - это syntactic sugar?**
Да, под капотом `class` создаёт функцию-конструктор и настраивает prototype. Но есть отличия: class всегда в strict mode, нельзя вызвать без `new`, методы non-enumerable, есть `super` и native `#private` fields.

**Что такое private fields (#)?**
ES2022 ввёл `#field` - настоящие приватные свойства. Они недоступны снаружи класса (даже через `Object.keys`, рефлексию или `[]`). В отличие от `_underscore` конвенции, это синтаксически enforced приватность.

**Как работает instanceof?**
`a instanceof B` проверяет, есть ли `B.prototype` где-либо в prototype chain объекта `a`. Проходит по цепочке `__proto__` от `a` до `null`. Если встречает `B.prototype` - `true`.

**Как реализовать множественное наследование?**
JS не поддерживает множественное наследование. Альтернативы: 1) Mixins через `Object.assign(Class.prototype, mixin)`, 2) Mixin-функции `const Mixed = MixinA(MixinB(Base))`, 3) Композиция вместо наследования.
