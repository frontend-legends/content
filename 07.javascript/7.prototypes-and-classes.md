# Прототипы и классы

Как устроено наследование в JavaScript: цепочка прототипов, `new`, классы и что под ними на самом деле. На mid спрашивают разницу `__proto__` и `prototype`, что делает `new` и являются ли классы синтаксическим сахаром. На senior — что происходит при записи свойства, которое есть на прототипе, в каком порядке инициализируется наследник, почему поле класса не вызывает сеттер родителя и почему приватные поля не работают через `Proxy`.

::tldr
- **У каждого объекта есть ссылка на прототип** (`[[Prototype]]`). Если свойства нет на объекте, движок ищет его по цепочке прототипов до `null`. Так объекты наследуют методы.
- **Чтение идёт по цепочке, запись — нет:** присваивание создаёт собственное свойство. Исключения — сеттер на прототипе, который перехватит запись, и свойство только для чтения, которое её запретит.
- **`prototype` — свойство функции, `[[Prototype]]` — свойство любого объекта.** `new F()` создаёт объект, чей прототип — `F.prototype`, и вызывает `F` с этим объектом в роли `this`.
- **Класс — функция-конструктор с прототипом, но не только сахар:** его нельзя вызвать без `new`, тело в strict mode, методы неперечисляемые, наследник обязан вызвать `super()` до `this`, а поля определяются, а не присваиваются.
- **`#private` — настоящая приватность** на уровне языка, но доступ к ней проверяет «бренд» объекта, поэтому вызов метода через `Proxy` падает.
::

## Цепочка прототипов

Сквозной пример — товары магазина: обычные и цифровые, у всех есть цена и описание.

```js
const product = {
  currency: '₽',
  format() { return `${this.price} ${this.currency}`; },
};

const tea = Object.create(product);   // прототип tea — product
tea.price = 490;
tea.format();                         // '490 ₽'
```

У `tea` нет метода `format`, но вызов работает. У каждого объекта есть скрытая ссылка на другой объект — **прототип** (в спецификации `[[Prototype]]`). Когда свойства нет на самом объекте, движок ищет его на прототипе, потом на прототипе прототипа — до `null`. Это **цепочка прототипов**, и это весь механизм наследования в JavaScript: объекты наследуют от объектов, а не от классов.

`this` внутри `format` — по-прежнему `tea`: метод найден на прототипе, но вызван как `tea.format()`, а `this` определяется вызовом (подробно — в [Контексте выполнения](/content/javascript/execution-context)).

Как проверить, где свойство:

- `Object.hasOwn(tea, 'format')` — `false`: только собственные свойства;
- `'format' in tea` — `true`: по всей цепочке;
- `Object.keys(tea)` — только собственные перечисляемые: `['price']`.

### Запись не идёт по цепочке

Чтение ищет по цепочке, а присваивание — нет. `tea.currency = '$'` создаёт у `tea` **собственное** свойство, которое затеняет прототипное. `product.currency` не меняется.

Два исключения, о которых спрашивают на senior:

- **сеттер на прототипе.** Если на прототипе есть сеттер `discount`, присваивание `item.discount = 80` вызовет его, а собственное свойство не появится;
- **свойство только для чтения на прототипе.** Если свойство прототипа неизменяемое (например, прототип заморожен через `Object.freeze`), присваивание наследнику тоже запрещено: в strict mode — `TypeError`, иначе — тихо игнорируется. Эту особенность называют override mistake. Обойти можно только через `Object.defineProperty`.

Объекты связываются прототипами вручную через `Object.create`. Но обычно прототип задаёт конструктор.

## Конструкторы и new

### prototype и [[Prototype]]

Две похожие вещи, которые путают:

- **`[[Prototype]]`** есть у **каждого объекта** — это его прототип. Читают через `Object.getPrototypeOf(obj)`, устаревший способ — `obj.__proto__`.
- **`prototype`** — обычное свойство **функции**. Это объект, который станет `[[Prototype]]` для всех объектов, созданных через `new` этой функцией.

```js
function Product(title) {
  this.title = title;
}
Product.prototype.describe = function () {
  return `Товар: ${this.title}`;
};

const pot = new Product('Чайник');
Object.getPrototypeOf(pot) === Product.prototype;   // true
Product.prototype.constructor === Product;          // true
```

Цепочка `pot` выглядит так: `pot` → `Product.prototype` → `Object.prototype` → `null`. Поэтому у любого объекта есть `toString` и `hasOwnProperty` — они живут в `Object.prototype`. У стрелочных функций и методов объектов нет свойства `prototype`, поэтому их нельзя использовать как конструкторы.

### Что делает new

`new Product('Чайник')` выполняет четыре шага. Их можно написать вручную:

```js
function myNew(Ctor, ...args) {
  const obj = Object.create(Ctor.prototype);      // 1–2. новый объект с прототипом Ctor.prototype
  const result = Ctor.apply(obj, args);           // 3. вызвать конструктор с this = obj
  const isObject = result !== null && (typeof result === 'object' || typeof result === 'function');
  return isObject ? result : obj;                 // 4. объект из return заменяет созданный
}
```

Четвёртый шаг — сюрприз: если конструктор явно вернёт объект, `new` отдаст его вместо созданного. Примитив в `return` игнорируется.

Методы кладут в `prototype`, а не в `this`: так функция существует **один раз** и делится всеми экземплярами. Метод, созданный в конструкторе через `this.describe = function () {...}`, создавался бы заново для каждого объекта.

Конструктор и прототип — рабочий, но многословный способ. Классы дают для него синтаксис — с несколькими важными отличиями.

## Классы

```js
class Product {
  static count = 0;

  constructor(title, price) {
    this.title = title;
    this.price = price;
    Product.count++;
  }

  describe() {
    return `${this.title}: ${this.price} ₽`;
  }

  get label() {
    return this.title.toUpperCase();
  }
}
```

Под капотом это та же функция `Product` с методами на `Product.prototype`: `typeof Product` — `'function'`. Поэтому классы называют синтаксическим сахаром. Но поведение отличается:

- **без `new` не вызвать:** `Product()` бросает `TypeError: Class constructor Product cannot be invoked without 'new'`;
- **тело всегда в strict mode** — извлечённый метод получает `this === undefined`;
- **методы неперечисляемые** — их нет в `for...in` и `Object.keys(Product.prototype)`;
- **класс во временной мёртвой зоне** до объявления, как `let`;
- **есть `super`, приватные поля и статические блоки** — у функций-конструкторов этого нет.

### Наследование

```js
class Digital extends Product {
  constructor(title, price, url) {
    super(title, price);          // сначала конструктор родителя
    this.url = url;
  }

  describe() {
    return `${super.describe()} (скачать)`;   // метод родителя
  }
}
```

`extends` связывает две цепочки: `Digital.prototype` наследует от `Product.prototype` (методы экземпляров), а сам `Digital` — от `Product` (статические свойства и методы). Поэтому `Digital.count` работает.

В наследнике **`this` не существует до вызова `super()`**: объект создаёт конструктор родителя. Обращение к `this` раньше бросает `ReferenceError: Must call super constructor in derived class before accessing 'this'`.

### Порядок инициализации

Поля и конструкторы выполняются в строгом порядке:

1. поля базового класса;
2. тело конструктора базового класса;
3. поля наследника;
4. тело конструктора наследника.

Отсюда ловушка: базовый конструктор, который вызывает переопределяемый метод, видит наследника без полей.

```js
class Base {
  constructor() { this.init(); }
  init() {}
}

class Widget extends Base {
  status = 'ready';
  init() { console.log(this.status); }   // undefined — поле наследника ещё не создано
}
```

Поэтому из конструктора не вызывают методы, которые могут быть переопределены.

### Поля определяются, а не присваиваются

Поле класса создаётся через определение свойства (как `Object.defineProperty`), а не через присваивание. Разница видна, когда у родителя есть сеттер с тем же именем:

```js
class Validated {
  set price(v) {
    if (v < 0) throw new RangeError('Цена не может быть отрицательной');
    this._price = v;
  }
}

class Sale extends Validated {
  price = -1;          // сеттер НЕ вызван: создано собственное свойство
}
```

Поле `price` в наследнике тихо затенило сеттер, и валидация не сработала. Присваивание `this.price = -1` в конструкторе вызвало бы сеттер. В TypeScript такое поведение включает настройка `useDefineForClassFields`, и при переходе на неё ломаются как раз такие классы.

## Приватные поля

До ES2022 приватность обозначали соглашением `_balance`, которое ничего не запрещает. Поля с `#` приватны на уровне языка:

```js
class Wallet {
  #balance = 0;

  deposit(sum) {
    this.#balance += sum;
    return this.#balance;
  }

  static isWallet(obj) {
    return #balance in obj;     // проверка, что объект создан этим классом
  }
}
```

`#balance` нельзя прочитать снаружи, его нет в `Object.keys`, `JSON.stringify` и рефлексии. Доступ проверяет **бренд**: приватное поле существует только у объектов, которые создал конструктор этого класса. Вызов `Wallet.prototype.deposit.call({}, 1)` бросает `TypeError` — у чужого объекта нет поля.

Отсюда неочевидное следствие: **приватные поля не работают через `Proxy`**. Метод, вызванный на прокси, получает `this` равным прокси, а у прокси нет приватного поля — в проверке `proxied.deposit(1)` бросил `Cannot read private member #balance from an object whose class did not declare it`. Библиотеки реактивности, которые оборачивают объекты в `Proxy` (Vue, MobX), поэтому плохо дружат с классами с `#`-полями. Как устроен `Proxy` — в [Метапрограммировании](/content/javascript/metaprogramming).

## instanceof и проверка типов

`obj instanceof C` проверяет, есть ли `C.prototype` где-то в цепочке прототипов `obj`. Это проверка цепочки, а не «типа», и у неё есть особенности:

- **разные realm.** У iframe или `vm` свои глобальные конструкторы. Массив из iframe — не `instanceof Array` текущего окна, поэтому массив проверяют через `Array.isArray`;
- **цепочку можно изменить** через `Object.setPrototypeOf`, а результат — переопределить статическим методом `Symbol.hasInstance`;
- **объекты без прототипа** (`Object.create(null)`) — не `instanceof Object`.

Для приватного состояния надёжнее проверка бренда `#field in obj`: её нельзя подделать.

### Наследование или композиция

Множественного наследования в JavaScript нет: у объекта один прототип. Поведение из нескольких источников добавляют миксинами — функциями, которые расширяют класс (`const Tracked = (Base) => class extends Base { ... }`), — или композицией, когда объект содержит другие объекты вместо того, чтобы наследовать от них. На практике глубокие иерархии классов во фронтенде редки: состояние и поведение собирают из функций и объектов (подробно — в [Паттернах](/content/javascript/patterns)).

Менять прототип существующего объекта через `Object.setPrototypeOf` дорого: движок сбрасывает оптимизации, связанные с формой объекта (подробно — во [Введении](/content/javascript/introduction)). Прототип задают при создании.

## Красные флаги в ответе

- **«В JS классическое наследование, как в Java».** Наследование прототипное: объекты ссылаются на объекты. Классы — синтаксис поверх прототипов.
- **«`__proto__` и `prototype` — одно и то же».** `[[Prototype]]` есть у каждого объекта, `prototype` — свойство функции, которое становится прототипом создаваемых объектов.
- **«Присваивание меняет свойство прототипа».** Оно создаёт собственное свойство — кроме случаев с сеттером или свойством только для чтения на прототипе.
- **«Классы — просто сахар, разницы нет».** Без `new` класс не вызвать, тело в strict mode, методы неперечисляемые, поля определяются, а не присваиваются.
- **«`instanceof` — надёжная проверка типа».** Он ломается между realm и зависит от цепочки, которую можно изменить. Массивы проверяют `Array.isArray`.

## Как спрашивают на собеседовании

::question{level="mid"}
Что такое прототипное наследование?

#mid
У каждого объекта есть ссылка на прототип. Если свойства нет на объекте, движок ищет его по цепочке прототипов до `null`. Так объекты наследуют методы от других объектов.

#senior
Чтение идёт по цепочке, запись — нет: присваивание создаёт собственное свойство, кроме случаев сеттера на прототипе (он перехватит запись) и неизменяемого свойства прототипа (запись запрещена). Методы живут на прототипе один раз и делятся всеми экземплярами. Длинные цепочки и смена прототипа после создания мешают оптимизациям движка.
::

::question{level="mid"}
В чём разница между __proto__ и prototype?

#mid
`__proto__` (правильно — `[[Prototype]]`, читается через `Object.getPrototypeOf`) есть у каждого объекта и указывает на его прототип. `prototype` — свойство функции-конструктора: объект, который станет прототипом созданных через `new` экземпляров. `pot.__proto__ === Product.prototype`.

#senior
`__proto__` — устаревший геттер-сеттер на `Object.prototype`, поэтому у объектов без прототипа его нет, а в обычном объекте запись по ключу `'__proto__'` меняет прототип. У `prototype` есть свойство `constructor`, ссылающееся обратно на функцию. Стрелки и методы не имеют `prototype` и не могут быть конструкторами.
::

::question{level="mid"}
Что делает оператор new?

#mid
Создаёт объект, ставит ему прототип `Constructor.prototype`, вызывает конструктор с `this`, равным этому объекту, и возвращает объект.

#senior
Если конструктор явно вернул объект или функцию, `new` вернёт их вместо созданного; примитив в `return` игнорируется. В классах-наследниках объект создаёт конструктор базового класса, поэтому `this` недоступен до `super()`. `new` сильнее `bind`: привязанная функция, вызванная через `new`, получает новый объект, но сохраняет привязанные аргументы.
::

::question{level="mid"}
Классы — это синтаксический сахар?

#mid
В основном да: класс — функция-конструктор с методами на прототипе. Но класс нельзя вызвать без `new`, его тело в strict mode, методы неперечисляемые, есть `super` и приватные поля.

#senior
Отличий больше, чем сахара. Класс во временной мёртвой зоне до объявления. Поля определяются через defineProperty и не вызывают сеттеры родителя. Порядок инициализации строгий: поля базового, конструктор базового, поля наследника, конструктор наследника — поэтому базовый конструктор видит наследника без полей. `extends` связывает и прототипы экземпляров, и сами конструкторы, поэтому статические члены наследуются.
::

::question{level="senior"}
Как работают приватные поля и чем они отличаются от _underscore?

#mid
`#field` недоступен снаружи класса: его нет в `Object.keys`, его нельзя прочитать через `obj['#field']`. `_field` — только соглашение, свойство обычное и доступное.

#senior
Доступ к `#field` проверяет бренд: поле есть только у объектов, созданных конструктором этого класса, поэтому `#field in obj` — надёжная проверка типа. Метод, вызванный на чужом объекте или на `Proxy`, бросает `TypeError`: у прокси нет приватного поля. Поэтому классы с `#`-полями плохо сочетаются с библиотеками на прокси вроде Vue и MobX. Наследники приватные поля родителя не видят.
::

::question{level="mid"}
Как работает instanceof?

#mid
`a instanceof B` проверяет, есть ли `B.prototype` в цепочке прототипов `a`.

#senior
Это проверка цепочки, а не типа: её меняют `Object.setPrototypeOf` и статический `Symbol.hasInstance`. Объекты из другого realm (iframe, `vm`) не проходят проверку с конструкторами текущего окна, поэтому для массивов есть `Array.isArray`. Для своих классов надёжнее проверка бренда `#field in obj`.
::

::question{level="mid"}
Как реализовать множественное наследование?

#mid
Его нет: у объекта один прототип. Используют миксины — функции, которые добавляют поведение к классу, — или композицию: объект содержит другие объекты вместо наследования.

#senior
Миксин-функция `const Tracked = (Base) => class extends Base {}` строит цепочку классов, и `super` работает. Копирование методов через `Object.assign(C.prototype, mixin)` проще, но ломает `super` и переносит геттеры как значения. Во фронтенде глубокие иерархии редки: поведение собирают композицией функций и объектов.
::

## Практика

::practice{title="Что выведет?"}
```js
class Base {
  name = 'base';
  constructor() {
    console.log(this.name);
    this.init();
  }
  init() { console.log('Base init'); }
}

class Widget extends Base {
  name = 'widget';
  status = 'ready';
  init() { console.log('Widget init', this.status); }
}

new Widget();
```

#solution
```text
base
Widget init undefined
```

Порядок: поля `Base` → конструктор `Base` → поля `Widget` → конструктор `Widget`. В момент работы конструктора `Base` поле `name` ещё базовое, а поля наследника не созданы. Метод `init` при этом уже переопределён — он найден на `Widget.prototype`, поэтому вызывается версия наследника, которая видит `status` как `undefined`.

Вывод: не вызывать переопределяемые методы из конструктора базового класса. Инициализацию переносят в отдельный метод, который вызывают после создания.
::

::practice{title="Почему не срабатывает валидация?"}
Базовый класс проверяет, что цена неотрицательная. В наследнике отрицательная цена проходит без ошибки:

```js
class Product {
  set price(v) {
    if (v < 0) throw new RangeError('Цена не может быть отрицательной');
    this._price = v;
  }
  get price() { return this._price; }
}

class Sale extends Product {
  price = -100;
}

new Sale().price;   // -100, ошибки нет
```

#solution
Поле класса создаётся определением свойства, а не присваиванием. `price = -100` создаёт у экземпляра собственное свойство `price`, которое затеняет геттер и сеттер с прототипа `Product`. Сеттер не вызывается вовсе, и дальше `price` — обычное свойство без валидации.

Фикс — присваивать в конструкторе, тогда запись пойдёт через сеттер:

```js
class Sale extends Product {
  constructor() {
    super();
    this.price = -100;   // RangeError: Цена не может быть отрицательной
  }
}
```

В TypeScript то же самое происходит при `useDefineForClassFields: true` — это поведение по умолчанию для современных целей компиляции.
::

::practice{title="Реализуй new"}
Напиши функцию `myNew(Ctor, ...args)`, которая работает как оператор `new` для обычных функций-конструкторов, включая случай, когда конструктор возвращает объект.

#solution
```js
function myNew(Ctor, ...args) {
  const obj = Object.create(Ctor.prototype);
  const result = Ctor.apply(obj, args);
  const isObject = result !== null && (typeof result === 'object' || typeof result === 'function');
  return isObject ? result : obj;
}

function Product(title) { this.title = title; }
Product.prototype.describe = function () { return `Товар: ${this.title}`; };

const cup = myNew(Product, 'Кружка');
cup.describe();            // 'Товар: Кружка'
cup instanceof Product;    // true
```

`Object.create` задаёт прототип, `apply` вызывает конструктор с новым объектом в роли `this`, а последняя строка повторяет правило `new`: объект из `return` заменяет созданный, примитив игнорируется. С классами так не получится: класс нельзя вызвать через `apply` без `new` — для них есть `Reflect.construct`.
::
