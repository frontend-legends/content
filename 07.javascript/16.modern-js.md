# Современный JavaScript

Что появилось в языке за последние годы и что из этого реально используют и спрашивают: короткие операторы, неизменяемые методы, JSON и его ловушки, `Intl` для чисел, дат и множественного числа, проблемы `Date` и `Temporal`, который их решает. Как предложения попадают в стандарт — во [Введении](/content/javascript/introduction). Спрашивают `??` и `?.`, `toSorted`, `Intl` и проблемы `Date`. Глубже — что теряет `JSON.stringify`, как не потерять большие целые при разборе JSON, почему `??=` не вызывает сеттер и почему месяц к 31 января даёт 3 марта.

::tldr
- **Каждую редакцию ES выпускают раз в год, и большую часть новинок спрашивают по смыслу, а не по году:** `?.`, `??` и логическое присваивание, неизменяемые методы массивов, `Object.groupBy`, `Promise.withResolvers`, iterator helpers и методы `Set`.
- **`JSON.stringify` теряет больше, чем кажется:** `undefined`, функции и символы пропадают, `NaN` становится `null`, `Map` и `Set` — `{}`, `Date` — строкой, а `BigInt` и циклы бросают `TypeError`. Целые больше 2^53 при разборе теряют точность.
- **`Intl` форматирует по правилам языка без библиотек:** деньги, проценты, даты, относительное время, множественное число (у русского — формы one, few, many), сортировку с «ё» и списки.
- **`Date` изменяемый, месяцы считает с нуля, переполняет даты и по-разному разбирает строки.** `Temporal` решает это неизменяемыми типами с часовыми поясами и строгим разбором.
- **Год редакции не равен поддержке у пользователей.** Новинку проверяют по Baseline, а не по номеру ES: Temporal есть в Chrome и Firefox, но ещё нет в стабильном Safari.
::

## Как читать новинки языка

Сквозной пример — карточка заказа в интернет-магазине: сумма в рублях, дата доставки, «3 товара», данные приходят JSON с сервера.

Редакции ECMAScript выходят каждый год: в редакцию попадают предложения, которые дошли до :term[Stage 4]{def="последняя стадия процесса TC39: предложение готово и войдёт в ближайшую редакцию стандарта"} к моменту её утверждения (подробно о процессе — во [Введении](/content/javascript/introduction)). Номер года не означает, что возможность есть у пользователей: браузеры реализуют предложения раньше или позже редакции. Поэтому на собеседовании спрашивают не «что вошло в ES2023», а «как бы ты сделал неизменяемую сортировку» или «как отформатировать цену».

Большая часть новинок разобрана в темах, где они нужны. Здесь — короткая карта и то, у чего нет другого дома.

### Логическое присваивание

`a ??= b`, `a ||= b` и `a &&= b` — короткие формы `a ?? (a = b)` и аналогов. Важно, что они **короткозамкнутые**: если присваивать не нужно, присваивания нет вовсе, и сеттер не вызывается. В проверке `settings.theme ??= 'light'` для свойства с геттером и сеттером не вызвал сеттер ни разу.

```js
order.promo ??= 'NEW10';       // только если промокода нет
cache[key] ||= compute(key);   // посчитать, если пусто
```

Разница `??` и `||` — та же, что в обычных операторах: `||` срабатывает на любом falsy, `??` — только на `null` и `undefined` (подробно — в [Типах и переменных](/content/javascript/types-and-variables)).

Данные карточки заказа приходят с сервера. Формат почти всегда один — JSON, и у него есть ловушки.

## JSON

`JSON.stringify` превращает значение в строку JSON, `JSON.parse` — обратно. JSON — подмножество литералов JavaScript, и многое из языка в нём выразить нельзя:

| Значение | Что делает `JSON.stringify` |
| --- | --- |
| `undefined`, функция, символ в свойстве | свойство пропадает |
| то же в массиве | `null` |
| `NaN`, `Infinity` | `null` |
| `Date` | ISO-строка (через `toJSON`) |
| `Map`, `Set` | `{}` |
| `BigInt` | `TypeError` |
| циклическая ссылка | `TypeError` |

Объект с методом `toJSON` сам решает, как сериализоваться — так работает `Date`. Второй аргумент — `replacer`: функция, которая может заменить или выбросить значение (например, пароль), или массив разрешённых ключей. Третий — отступы для читаемого вывода.

`JSON.parse` возвращает только данные: дата остаётся строкой, деньги — числом с плавающей точкой. Восстанавливают типы функцией-`reviver`:

```js
const order = JSON.parse(text, (key, value) =>
  key === 'deliveryAt' ? new Date(value) : value,
);
```

### Большие целые

Идентификаторы заказов в базе бывают 64-битными. JSON-число `12345678901234567890` при разборе превращается в `number` и теряет точность: в проверке получилось `12345678901234567000`. Раньше единственным решением было присылать такие поля строками. С ES2026 `reviver` получает третий аргумент с исходным текстом значения:

```js
JSON.parse(text, (key, value, context) =>
  key === 'id' ? BigInt(context.source) : value,
);
```

В проверке идентификатор сохранился точно — уже работает в Node.js 24. Строки в API для таких полей по-прежнему надёжнее: не все клиенты поддерживают эту возможность.

Число пришло — теперь его нужно показать человеку на его языке.

## Intl: числа, даты и слова

`Intl` — встроенный API интернационализации. Он форматирует по правилам языка и региона, без библиотек и таблиц переводов для чисел и дат.

### Числа и деньги

```js
new Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB' }).format(2490.5);
// '2 490,50 ₽'
new Intl.NumberFormat('ru-RU', { notation: 'compact' }).format(1_250_000);   // '1,3 млн'
new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' }).format(2490.5); // '$2,490.50'
```

Разделитель тысяч в русской локали — **неразрывный пробел**, а не обычный. Тесты, которые сравнивают с `'2 490,50 ₽'` с обычным пробелом, падают — так было и в проверке, пока пробелы не нормализовали.

`format` дорог при создании форматтера, поэтому форматтер создают один раз и переиспользуют.

### Даты и относительное время

```js
new Intl.DateTimeFormat('ru-RU', { dateStyle: 'long', timeZone: 'UTC' }).format(date);
// '15 ноября 2026 г.'

const rtf = new Intl.RelativeTimeFormat('ru', { numeric: 'auto' });
rtf.format(-1, 'day');     // 'вчера'
rtf.format(2, 'hour');     // 'через 2 часа'
```

Опция `timeZone` решает, в каком поясе показать момент времени, — без неё используется пояс пользователя.

### Множественное число

«1 товар», «3 товара», «11 товаров», «21 товар» — правила русского языка сложнее, чем `n === 1`. `Intl.PluralRules` знает их:

```js
const pr = new Intl.PluralRules('ru-RU');
const forms = { one: 'товар', few: 'товара', many: 'товаров', other: 'товара' };
const label = (n) => `${n} ${forms[pr.select(n)]}`;

label(1);    // '1 товар'
label(3);    // '3 товара'
label(11);   // '11 товаров'
label(21);   // '21 товар'
```

У русского четыре категории: `one` (1, 21, 31…), `few` (2–4, 22–24…), `many` (0, 5–20, 25…) и `other` для дробных. В проверке категории совпали для всех этих чисел, включая `11` (many, хотя оканчивается на 1).

### Сортировка, графемы, списки

- **`Intl.Collator`** сравнивает строки по правилам языка. `sort()` без него сравнивает коды UTF-16: заглавные идут раньше строчных, а «ё» — после «я». В проверке обычная сортировка поставила «ёж» в конец, а `Collator` — между «еда» и «жук».
- **`Intl.Segmenter`** делит строку на графемы, слова или предложения. Буква с отдельным знаком ударения — два кодовых пункта, но один видимый символ: `length` даёт 3 для «е́ж», а сегментатор — 2.
- **`Intl.ListFormat`** склеивает список по правилам языка: `'чай, кофе и какао'`.

Числа и слова отформатированы. Осталась самая проблемная часть карточки заказа — дата доставки.

## Date и почему он плох

`Date` скопирован из Java 1995 года, и его проблемы с тех пор не исправить без поломки старого кода:

- **месяцы с нуля:** `new Date(2026, 0, 31)` — 31 января, а 11 — декабрь;
- **переполнение вместо ошибки:** `setMonth(1)` для 31 января даёт «31 февраля», то есть 3 марта. В проверке именно так;
- **изменяемость:** `date.setDate(date.getDate() + 1)` меняет исходный объект. Функция «прибавь день», которая забыла скопировать дату, портит дату вызывающего кода;
- **непредсказуемый разбор:** `new Date('2026-11-15')` — полночь по :term[UTC]{def="всемирное координированное время: шкала без часовых поясов и переходов на летнее время"}, а `new Date('2026-11-15T00:00')` — полночь по местному времени. Разница — смещение пояса, и у пользователя западнее Гринвича первая дата превращается в 14 ноября. Другие форматы строк разбираются по-разному в разных движках;
- **нет «только даты» и «только времени»:** день рождения — это не момент времени, но `Date` всегда момент;
- **часовые пояса только два:** местный и UTC. Показать время встречи в Нью-Йорке можно только через `Intl` при выводе.

Поэтому годами использовали библиотеки: Moment (устарел), :term[date-fns]{def="библиотека небольших функций для работы с датами"}, Day.js, Luxon.

## Temporal

`Temporal` — новый встроенный API для дат и времени. Он дошёл до Stage 4 в марте 2026 года и войдёт в ES2027. На ноябрь 2026 года он есть в Firefox (с версии 139) и Chrome (с версии 144), но нет в стабильном Safari и в Node.js 24, поэтому в production его используют с полифилом.

```js
const delivery = Temporal.PlainDate.from('2026-01-31');
delivery.add({ months: 1 }).toString();   // '2026-02-28' — без переполнения
delivery.month;                           // 1 — месяцы с единицы
delivery.toString();                      // '2026-01-31' — исходная не изменилась

const meeting = Temporal.ZonedDateTime.from({
  timeZone: 'Europe/Moscow', year: 2026, month: 11, day: 15, hour: 15,
});
meeting.withTimeZone('America/New_York').hour;   // 7

Temporal.Duration.from({ hours: 2, minutes: 30 }).total('minutes');   // 150
```

Все примеры проверены через полифил `temporal-polyfill`. Что меняется:

| Проблема `Date` | В `Temporal` |
| --- | --- |
| изменяемость | все объекты неизменяемы, операции возвращают новые |
| месяцы с нуля | месяцы с 1 |
| переполнение | конец месяца по умолчанию ограничивается (`2026-02-28`) |
| только момент времени | `PlainDate`, `PlainTime`, `PlainDateTime`, `PlainYearMonth` |
| два пояса | `ZonedDateTime` с любым поясом IANA и переходами на летнее время |
| свободный разбор строк | строгий ISO 8601: `'15.11.2026'` — `RangeError` |
| нет длительностей | `Duration` с арифметикой и `until`, `since` |

Выбирать тип — значит отвечать на вопрос «что это за значение». Дата доставки — `PlainDate`, время начала вебинара — `ZonedDateTime`, момент события в логе — `Instant`, продолжительность — `Duration`.

### using

Вместе с `Temporal` в ES2027 войдёт явное управление ресурсами: `using` объявляет переменную, у которой при выходе из блока автоматически вызывается `[Symbol.dispose]()` (или `[Symbol.asyncDispose]()` для `await using`). Это аналог `try`/`finally` для закрытия файлов, соединений и подписок — без ручного `finally`.

## Красные флаги в ответе

- **«`JSON.parse(JSON.stringify(x))` — нормальный способ скопировать данные».** Он теряет `undefined`, `Date`, `Map`, `NaN` и падает на `BigInt` и циклах. Копию делает `structuredClone`.
- **«Цену форматирую через `toFixed(2)` и `replace`».** `Intl.NumberFormat` учитывает разделители, валюту и неразрывные пробелы.
- **«Окончания считаю через `n === 1`».** Для русского нужны четыре категории: `Intl.PluralRules`.
- **«`new Date('2026-11-15')` — это 15 ноября у пользователя».** Это полночь по UTC; западнее Гринвича — ещё 14 ноября.
- **«Фича есть в ES2026 — значит, можно использовать».** Поддержку проверяют по Baseline и браузерам пользователей, а не по году редакции.

## Как спрашивают на собеседовании

::question
В чём разница между ?? и ||?

#answer
`||` возвращает правый операнд при любом falsy-значении — `0`, `''`, `false`, `null`, `undefined`. `??` — только при `null` и `undefined`. Для чисел и строк `??` безопаснее: `0 ?? 10` даёт `0`, а `0 || 10` — `10`.

#more
Логическое присваивание `??=`, `||=`, `&&=` короткозамкнутое: если присваивать не нужно, присваивания нет, и сеттер не вызывается — это важно для реактивных объектов и прокси. `??` нельзя смешивать с `&&` и `||` без скобок — это синтаксическая ошибка, чтобы избежать путаницы с приоритетом.
::

::question
Что такое optional chaining?

#answer
`?.` — безопасный доступ: `user?.address?.city` вернёт `undefined`, если `user` или `address` равны `null` или `undefined`, вместо `TypeError`. Работает с вызовами (`obj.method?.()`) и индексами (`arr?.[0]`).

#more
`?.` обрывает всю цепочку справа: если `user` — `null`, то `user?.address.city` не бросит, хотя у `address` нет `?.`. Он проверяет только `null` и `undefined`, а не falsy. Злоупотребление `?.` прячет ошибки данных: если поле обязано быть, лучше упасть явно, чем показать пустоту.
::

::question
Зачем toSorted вместо sort?

#answer
`sort` мутирует исходный массив, `toSorted` возвращает новый. Неизменяемые обновления нужны для состояния React, Redux и кода, где изменение по ссылке ломает сравнение. Есть ещё `toReversed`, `toSpliced` и `with`.

#more
`sort` к тому же возвращает тот же массив, что создаёт иллюзию копии. Без функции сравнения оба сортируют строки по кодам UTF-16, поэтому числа требуют `(a, b) => a - b`, а строки на русском — `Intl.Collator`. Сортировка стабильна по спецификации.
::

::question
Что теряет JSON.stringify?

#answer
`undefined`, функции и символы в свойствах пропадают, в массивах становятся `null`. `NaN` и `Infinity` — `null`, `Date` — строка, `Map` и `Set` — пустой объект. `BigInt` и циклы бросают `TypeError`.

#more
Сериализацию настраивают через `toJSON` у объекта и `replacer`, разбор — через `reviver`. Целые больше 2^53 при разборе теряют точность: решение — передавать их строками или (ES2026) читать `context.source` в `reviver` и превращать в `BigInt`. Для копирования объектов вместо JSON — `structuredClone`, для обмена с сервером — схемы валидации (Zod) поверх `JSON.parse`.
::

::question
Что такое Intl API?

#answer
Встроенный API интернационализации: `NumberFormat` для чисел и валют, `DateTimeFormat` для дат, `RelativeTimeFormat` для «вчера» и «через 2 часа», `PluralRules` для множественного числа. Работает по правилам языка без библиотек.

#more
Ещё `Collator` для сортировки по правилам языка (без него «ё» идёт после «я»), `Segmenter` для графем и слов, `ListFormat` для списков. В русском у `PluralRules` четыре категории: one, few, many, other. Форматтеры дорогие в создании — их кешируют. Вывод содержит неразрывные пробелы, это ломает наивные тесты.
::

::question
Зачем нужен Temporal?

#answer
`Date` изменяемый, считает месяцы с нуля, переполняет даты и непредсказуемо разбирает строки, а часовых поясов у него только два. `Temporal` даёт неизменяемые типы, месяцы с 1, строгий ISO-разбор и полноценные пояса.

#more
Главное — разные типы для разных смыслов: `PlainDate` для даты без времени, `ZonedDateTime` для события в поясе, `Instant` для момента, `Duration` для длительности. Арифметика не переполняется: месяц к 31 января даёт 28 февраля. Stage 4 в марте 2026 года, войдёт в ES2027. Есть в Chrome 144+ и Firefox 139+, в стабильном Safari ещё нет — в production нужен полифил.
::

## Практика

::practice{title="Карточка заказа"}
Отформатируй строку для карточки заказа по-русски: `«3 товара на 7 470,00 ₽, доставка 15 ноября 2026 г.»`. Данные: `{ count: 3, total: 7470, deliveryAt: '2026-11-15' }`. Функция должна правильно склонять «товар» для любых чисел.

#solution
```js
const money = new Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB' });
const longDate = new Intl.DateTimeFormat('ru-RU', { dateStyle: 'long', timeZone: 'UTC' });
const plural = new Intl.PluralRules('ru-RU');
const goods = { one: 'товар', few: 'товара', many: 'товаров', other: 'товара' };

function orderSummary({ count, total, deliveryAt }) {
  const items = `${count} ${goods[plural.select(count)]}`;
  return `${items} на ${money.format(total)}, доставка ${longDate.format(new Date(deliveryAt))}`;
}

orderSummary({ count: 3, total: 7470, deliveryAt: '2026-11-15' });
// '3 товара на 7 470,00 ₽, доставка 15 ноября 2026 г.'
```

Форматтеры создаются один раз — их создание дорогое. `timeZone: 'UTC'` нужен потому, что `new Date('2026-11-15')` — полночь по UTC, и без него пользователь западнее Гринвича увидел бы 14 ноября. С `Temporal` дата доставки была бы `PlainDate`, и проблема пояса не возникла бы вовсе. В строке — неразрывные пробелы, их учитывают в тестах.
::

::practice{title="Почему дедлайн сдвинулся?"}
Функция считает дату следующего платежа «через месяц». Для подписки от 31 января следующий платёж оказался 3 марта, а дата начала подписки в карточке тоже изменилась:

```js
function nextPayment(start) {
  start.setMonth(start.getMonth() + 1);
  return start;
}

const subscription = { startedAt: new Date(2026, 0, 31) };
const next = nextPayment(subscription.startedAt);
```

#solution
Две проблемы `Date`:

1. **Изменяемость.** `setMonth` меняет объект, который передали, — это та же дата, что в `subscription.startedAt`.
2. **Переполнение.** «31 февраля» не существует, и `Date` переносит лишние дни в март — 3 марта.

С `Date` нужно копировать и самому ограничивать день концом месяца:

```js
function nextPayment(start) {
  const next = new Date(start);
  const day = next.getDate();
  next.setDate(1);                                   // уйти от переполнения
  next.setMonth(next.getMonth() + 1);
  const lastDay = new Date(next.getFullYear(), next.getMonth() + 1, 0).getDate();
  next.setDate(Math.min(day, lastDay));
  return next;
}
```

С `Temporal` это одна строка, и исходная дата не меняется:

```js
const next = Temporal.PlainDate.from('2026-01-31').add({ months: 1 });   // 2026-02-28
```

В проверке `Date` дал 3 марта и испортил исходную дату, а `Temporal` вернул 28 февраля.
