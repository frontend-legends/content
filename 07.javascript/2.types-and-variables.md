# Типы данных и переменные

Какие значения бывают в JavaScript, как они копируются и сравниваются и как язык превращает одни типы в другие. Спрашивают список типов, `typeof null`, разницу `==` и `===` и falsy-значения. Глубже — алгоритм приведения к примитиву, почему `0.1 + 0.2 !== 0.3`, чем `Object.is` отличается от `===` и почему `[] == ![]` даёт `true`.

::tldr
- **Восемь типов: семь примитивов и объект.** `string`, `number`, `bigint`, `boolean`, `undefined`, `null`, `symbol` — неизменяемые значения, всё остальное — объекты, в том числе массивы и функции.
- **Примитивы копируются значением, объекты — ссылкой.** Сравнение объектов — это сравнение ссылок, а параметр функции получает копию ссылки.
- **`number` — 64-битное число с плавающей точкой.** Отсюда `0.1 + 0.2 !== 0.3`, потеря точности после 2^53 и два особых значения: `NaN` не равен себе, а `-0` равен `0`.
- **Приведение типов идёт по правилам:** объект сначала превращается в примитив (`Symbol.toPrimitive`, `valueOf`, `toString`), потом в число, строку или boolean. `+` со строкой склеивает, остальные арифметические операторы считают.
- **`===` сравнивает без приведения, `==` — с приведением, `Object.is` — без исключений для `NaN` и `-0`.** Falsy-значений ровно восемь, а `??` в отличие от `||` пропускает `0` и пустую строку.
::

## Какие бывают значения

Сквозной пример темы — форма заказа: количество приходит из поля ввода строкой, цена — числом с сервера, скидка может отсутствовать.

```js
const qty = form.elements.qty.value;   // '2' — значения полей всегда строки
const price = product.price;           // 2490
const discount = product.discount;     // undefined, если скидки нет
const total = price * qty;             // 4980 — сработало, но почему?
```

Чтобы ответить, почему `price * qty` сработало, а `price + qty` дало бы `'24902'`, нужно знать типы и правила приведения.

### Восемь типов

В JavaScript семь **примитивов** и один объектный тип:

| Тип | Пример | `typeof` |
| --- | --- | --- |
| `string` | `'чай'` | `'string'` |
| `number` | `2490`, `0.1`, `NaN`, `Infinity` | `'number'` |
| `bigint` | `9007199254740993n` | `'bigint'` |
| `boolean` | `true` | `'boolean'` |
| `undefined` | `undefined` | `'undefined'` |
| `null` | `null` | `'object'` — историческая ошибка |
| `symbol` | `Symbol('id')` | `'symbol'` |
| `object` | `{}`, `[]`, `new Date()`, функции | `'object'`, у функций — `'function'` |

`typeof null === 'object'` — ошибка самой первой реализации языка. Значения хранились с тегом типа, у объектов тег был `0`, а `null` представлялся нулевым указателем — с тем же нулевым тегом. Исправить это нельзя: сломается существующий код. Поэтому проверка на объект выглядит так: `value !== null && typeof value === 'object'`.

Ещё одна особенность `typeof` — он не бросает ошибку на необъявленной переменной и возвращает `'undefined'`. Этим пользовались для проверки окружения: `typeof window !== 'undefined'`.

### Значение и ссылка

Примитивы **неизменяемы**: методы строки возвращают новую строку, а не меняют старую. Присваивание копирует само значение. Объекты живут в памяти отдельно, а переменная хранит **ссылку**:

```js
const order = { qty: 1 };
const copy = order;      // та же ссылка
copy.qty = 2;
order.qty;               // 2

({ qty: 1 }) === ({ qty: 1 });  // false — два разных объекта
```

Функция получает **копию ссылки**. Изменить объект через параметр можно, а заменить переменную снаружи — нет:

```js
function mutate(o) { o.qty = 100; }        // меняет исходный объект
function reassign(o) { o = { qty: 100 }; } // меняет только локальную переменную
```

Это не «передача по ссылке» в смысле C++: снаружи переменная по-прежнему указывает на тот же объект. Как копировать объекты, чтобы изменения не утекали, — в [Объектах и массивах](/content/javascript/objects-and-arrays).

Теперь посмотрим на типы, у которых больше всего сюрпризов. Первый — числа.

## Числа

### Один тип для всех чисел

`number` — это 64-битное число с плавающей точкой по стандарту IEEE 754. Отдельного целого типа нет, и у этого три следствия.

**Дроби неточны.** `0.1` в двоичной системе — бесконечная дробь, хранится её округление:

```js
0.1 + 0.2;                                // 0.30000000000000004
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON; // true — сравнение с допуском
(0.615).toFixed(2);                       // '0.61', а не '0.62': хранится 0.61499999...
```

Для денег это не годится. Суммы хранят в минимальных единицах (копейках) целыми числами, а форматируют через `Intl.NumberFormat` (подробно — в [Современном JS](/content/javascript/modern-js)).

**Целые точны только до 2^53.** `Number.MAX_SAFE_INTEGER` равен `2^53 - 1`. Дальше числа идут с шагом больше единицы: `2 ** 53 + 1 === 2 ** 53`. Идентификаторы из базы длиной 19 цифр, пришедшие в JSON числом, теряют точность — их передают строками. Для арифметики больших целых есть `bigint`: `9007199254740993n + 1n` считается точно. Смешивать `bigint` и `number` нельзя — `1n + 1` бросает `TypeError`.

**Особые значения.** `NaN` («не число») — результат бессмысленной операции, и он не равен даже себе: `NaN === NaN` — `false`. Ещё есть `-0`: `0 === -0` — `true`, но `1 / -0` даёт `-Infinity`. Для проверки:

- `Number.isNaN(x)` — только настоящий `NaN`. Глобальный `isNaN('abc')` сначала приводит к числу и даёт `true` для любой нечисловой строки.
- `Object.is(a, b)` — равенство без исключений: `Object.is(NaN, NaN)` — `true`, `Object.is(0, -0)` — `false`.

### Строки

Строка — последовательность 16-битных кодовых единиц UTF-16. Символы за пределами базовой плоскости Unicode (эмодзи, многие математические символы) занимают две единицы:

```js
const x = '𝒳';
x.length;        // 2
[...x].length;   // 1 — итератор строки идёт по кодовым точкам
```

Поэтому `str.length` — не число символов, а `str.slice(0, n)` может разрезать символ пополам. Для подсчёта видимых символов в сложных случаях есть `Intl.Segmenter`.

Числа и строки постоянно превращаются друг в друга — как `qty` в нашей форме. По каким правилам?

## Приведение типов

Приведение бывает явным (`Number(qty)`, `String(price)`) и неявным — когда оператор получает операнды не того типа. Неявное приведение подчиняется нескольким абстрактным операциям из спецификации.

### В число, строку и boolean

| Значение | `Number(x)` | `String(x)` | `Boolean(x)` |
| --- | --- | --- | --- |
| `''` | `0` | `''` | `false` |
| `' 42 '` | `42` | `' 42 '` | `true` |
| `'42px'` | `NaN` | `'42px'` | `true` |
| `null` | `0` | `'null'` | `false` |
| `undefined` | `NaN` | `'undefined'` | `false` |
| `true` | `1` | `'true'` | `true` |
| `[]` | `0` | `''` | `true` |
| `[5]` | `5` | `'5'` | `true` |
| `{}` | `NaN` | `'[object Object]'` | `true` |

`Number` требует всю строку целиком (пробелы по краям допустимы), а `parseInt('42px', 10)` читает до первого нецифрового символа и возвращает `42`. У `parseInt` есть ловушка: число сначала превращается в строку, поэтому `parseInt(0.0000005)` — это `5`, потому что `String(0.0000005)` — `'5e-7'`.

### Объект в примитив

Объект перед приведением превращается в примитив — операция ToPrimitive. Она получает **подсказку** (hint): `'number'`, `'string'` или `'default'`, — и действует по порядку:

1. если у объекта есть `Symbol.toPrimitive`, вызывается он с подсказкой;
2. иначе для `'number'` и `'default'` — сначала `valueOf()`, потом `toString()`; для `'string'` — наоборот;
3. берётся первый результат, который оказался примитивом.

```js
const price = {
  [Symbol.toPrimitive](hint) {
    return hint === 'number' ? 2490 : hint === 'string' ? '2490 ₽' : 'default';
  },
};
+price;       // 2490      — hint 'number'
`${price}`;   // '2490 ₽'  — hint 'string'
price + '';   // 'default' — у бинарного + hint 'default'
```

У обычного объекта `valueOf` возвращает сам объект (не примитив), поэтому срабатывает `toString` — отсюда `'[object Object]'`. У массива `toString` склеивает элементы через запятую: `String([1, 2])` — `'1,2'`. У `Date` подсказка `'default'` обрабатывается как `'string'`.

### Оператор +

`+` — единственный арифметический оператор с двумя смыслами. После приведения обоих операндов к примитивам: если хоть один — строка, это склейка, иначе — сложение чисел. Остальные (`-`, `*`, `/`) всегда приводят к числу:

```js
price + qty;  // 2490 + '2' → '24902'
price * qty;  // 2490 * '2' → 4980
1 + 2 + '3';  // '33' — слева направо: 3 + '3'
'1' + 2 + 3;  // '123'
[] + {};      // '[object Object]' — '' + '[object Object]'
```

Поэтому значения полей формы явно превращают в числа сразу при чтении: `const qty = Number(form.elements.qty.value)` или `valueAsNumber` у `<input type="number">`.

Приведение объясняет и самую обсуждаемую часть языка — сравнение.

## Сравнение: ===, == и Object.is

**`===` (строгое равенство)** сравнивает без приведения: разные типы — сразу `false`. Два исключения: `NaN === NaN` — `false`, `0 === -0` — `true`.

**`==` (нестрогое равенство)** приводит типы по алгоритму IsLooselyEqual. Его можно не помнить целиком, достаточно ключевых правил:

- `null` и `undefined` равны **только друг другу**: `null == undefined` — `true`, `null == 0` — `false`;
- строка и число — строка приводится к числу: `'' == 0` — `true`;
- boolean приводится к числу: `'0' == false` → `'0' == 0` → `true`;
- объект и примитив — объект приводится к примитиву: `[] == false` → `'' == 0` → `true`.

Отсюда знаменитое `[] == ![]` — `true`. `![]` — `false` (массив truthy), а дальше `[] == false` по правилам выше.

Ещё одна ловушка: сравнения `<`, `>`, `>=` приводят `null` к `0`, а `==` — нет. Поэтому `null >= 0` — `true`, но `null == 0` — `false`.

**`Object.is`** — равенство без исключений: `NaN` равен `NaN`, `0` не равен `-0`. Так сравнивает React (подробно — в [Механике хуков](/content/reactjs/hooks-mechanics)) и коллекции `Map` и `Set` — с той разницей, что они считают `0` и `-0` одним ключом.

Правило для кода: всегда `===`. Единственное оправданное исключение — `x == null`, которое проверяет и `null`, и `undefined` одним условием.

Сравнение с boolean — частный случай третьего вида приведения: в логическом контексте.

## Truthy, falsy и операторы по умолчанию

В `if`, `&&`, `||`, `!` значение приводится к boolean. Falsy-значений ровно восемь:

```js
false, 0, -0, 0n, '', null, undefined, NaN
```

Всё остальное — truthy, включая `[]`, `{}`, `'0'`, `'false'` и `' '` (строка из пробела). А также объект-обёртка `new Boolean(false)`: любой объект truthy.

Отсюда ошибка в нашей форме. Количество по умолчанию — 1:

```js
const qty = order.qty || 1;   // при qty === 0 получим 1
```

`||` подставляет значение по умолчанию для **любого** falsy, а `0` — законное количество. Для «нет значения» есть `??` — он реагирует только на `null` и `undefined`:

```js
const qty = order.qty ?? 1;   // 0 остаётся 0
const note = order.note ?? ''; // '' остаётся ''
```

Вместе с ним работает опциональная цепочка `?.`: `order.customer?.address?.city` вернёт `undefined`, если на любом шаге значения нет, вместо `TypeError`.

### Обёртки примитивов

У примитивов нет свойств, но `'чай'.toUpperCase()` работает. При обращении к свойству движок создаёт временный объект-обёртку (`String`, `Number`, `Boolean`), вызывает метод и выбрасывает объект. Поэтому присвоить свойство примитиву нельзя: в strict mode `str.custom = 1` бросает `TypeError`, в обычном — значение теряется.

Создавать обёртки вручную не нужно: `new String('a')` — объект (`typeof` даёт `'object'`), `new String('a') === 'a'` — `false`, а `new Boolean(false)` — truthy. Без `new` эти функции — обычное явное приведение: `String(42)`, `Number('42')`.

## Переменные

Значения хранятся в переменных, и объявить их можно тремя способами:

| | `var` | `let` | `const` |
| --- | --- | --- | --- |
| Область видимости | функция | блок | блок |
| Повторное объявление | можно | нельзя | нельзя |
| Повторное присваивание | можно | можно | нельзя |
| До объявления | `undefined` | `ReferenceError` (TDZ) | `ReferenceError` (TDZ) |
| Свойство глобального объекта | да | нет | нет |

`const` запрещает **переприсваивание**, а не изменение: объект в `const` можно мутировать. Заморозить объект может `Object.freeze`, и то только поверхностно.

Правило современного кода: `const` по умолчанию, `let` — если значение действительно меняется, `var` не используется. Почему `var` ведёт себя так странно — поднятие, область функции, TDZ у `let` — объясняется устройством контекста выполнения и разобрано в [Контексте выполнения](/content/javascript/execution-context).

### null и undefined

Оба означают «нет значения», но в разном смысле:

- **`undefined`** — значение не задано: переменная объявлена без значения, параметр не передан, свойства нет, функция ничего не вернула. Его выставляет язык.
- **`null`** — значение намеренно пустое: «пользователь не выбран», конец цепочки прототипов. Его выставляет программист.

В JSON есть только `null`: свойство со значением `undefined` при `JSON.stringify` пропадает.

## Красные флаги в ответе

- **«`typeof` массива — `'array'`».** `typeof []` — `'object'`. Массив проверяют через `Array.isArray`.
- **«Объекты передаются по ссылке, поэтому функция может заменить переменную снаружи».** Функция получает копию ссылки: мутировать объект может, заменить внешнюю переменную — нет.
- **«`isNaN` проверяет, что значение — `NaN`».** Глобальный `isNaN` сначала приводит к числу: `isNaN('abc')` — `true`. Нужен `Number.isNaN`.
- **«`const` делает объект неизменяемым».** Он запрещает только переприсваивание переменной.
- **«`||` — способ задать значение по умолчанию».** Он заменит и `0`, и пустую строку. Для «нет значения» — `??`.
- **«`==` можно использовать, если знаешь типы».** Правила `==` нелокальны и удивляют даже опытных. Единственное принятое исключение — `x == null`.

## Как спрашивают на собеседовании

::question
Какие типы данных есть в JavaScript?

#answer
Семь примитивов: `string`, `number`, `bigint`, `boolean`, `undefined`, `null`, `symbol`, — и объекты. Массивы, функции и даты — тоже объекты. Примитивы неизменяемы и копируются значением, объекты — по ссылке.

#more
Функция — объект с внутренним методом `[[Call]]`, поэтому `typeof` для неё отдельно возвращает `'function'`. Параметр функции получает копию ссылки (call by sharing): объект можно изменить, но внешнюю переменную заменить нельзя. У примитивов нет свойств: метод `'a'.toUpperCase()` вызывается на временной обёртке, которая сразу выбрасывается.
::

::question
Почему typeof null возвращает 'object'?

#answer
Это ошибка первой реализации JavaScript, которую нельзя исправить, не сломав существующий код. Проверка на объект — `value !== null && typeof value === 'object'`.

#more
Значения хранились с тегом типа в младших битах, и у объектов тег был нулевым. `null` представлялся нулевым указателем, то есть тоже с нулевым тегом, и `typeof` принимал его за объект. Предложение исправить это в ES2015 отклонили из-за совместимости.
::

::question
Почему 0.1 + 0.2 !== 0.3?

#answer
Числа хранятся в двоичном формате с плавающей точкой (IEEE 754), а `0.1` и `0.2` в двоичной системе — бесконечные дроби. Хранятся их округления, и сумма округлений не равна `0.3`. Сравнивают с допуском `Number.EPSILON`.

#more
Это не особенность JS — так работает double в любом языке. Деньги хранят целыми в минимальных единицах или используют библиотеки десятичной арифметики, а для вывода — `Intl.NumberFormat`. Целые точны до `2^53 - 1` (`Number.MAX_SAFE_INTEGER`): длинные идентификаторы из JSON теряют точность, поэтому их передают строками, а для больших целых есть `bigint`.
::

::question
Чем == отличается от ===?

#answer
`===` сравнивает без приведения типов, `==` сначала приводит их по сложным правилам. Используют `===`. Исключение — `x == null`, которое проверяет и `null`, и `undefined`.

#more
`==` следует алгоритму IsLooselyEqual: `null` и `undefined` равны только друг другу, строка и boolean приводятся к числу, объект — к примитиву через ToPrimitive. Отсюда `[] == ![]` — `true`. Есть и третий вид равенства — `Object.is`: в отличие от `===` он считает `NaN` равным себе и различает `0` и `-0`. Так сравнивает, например, React при проверке состояния.
::

::question
Как объект превращается в примитив?

#answer
JS вызывает у объекта `valueOf` или `toString`. У обычного объекта получается `'[object Object]'`, у массива — элементы через запятую.

#more
Операция ToPrimitive получает подсказку `'number'`, `'string'` или `'default'`. Если есть `Symbol.toPrimitive`, вызывается он. Иначе для `'number'` и `'default'` сначала `valueOf`, потом `toString`, для `'string'` — наоборот, и берётся первый примитивный результат. Бинарный `+` передаёт `'default'`, шаблонная строка — `'string'`, унарный `+` — `'number'`. `Date` обрабатывает `'default'` как строку, поэтому `date + 1` склеивает.
::

::question
Какие значения falsy?

#answer
`false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN` — восемь значений. Всё остальное truthy, включая `[]`, `{}` и строку `'0'`.

#more
Отсюда разница между `||` и `??`: `||` подставляет значение по умолчанию для любого falsy и ломает законные `0` и `''`, а `??` реагирует только на `null` и `undefined`. Объекты-обёртки вроде `new Boolean(false)` truthy, как любой объект. В истории языка есть и девятый случай — `document.all`, специально сделанный falsy для совместимости со старыми сайтами.
::

## Практика

::practice{title="Что выведет?"}
```js
console.log(1 + '2' + 3);
console.log(1 + 2 + '3');
console.log('5' - 2);
console.log([] + []);
console.log([1, 2] + [3]);
console.log(null + 1);
console.log(undefined + 1);
console.log(null == 0, null >= 0);
console.log([] == ![]);
```

#solution
```text
123
33
3
(пустая строка)
1,23
1
NaN
false true
true
```

- `+` идёт слева направо: в первой строке `1 + '2'` — уже строка `'12'`, во второй `1 + 2` — сначала число `3`.
- `-` всегда приводит к числу.
- Массивы через `toString` превращаются в строки: `''`, `'1,2'` и `'3'`.
- `null` в арифметике — `0`, `undefined` — `NaN`.
- `null == 0` — `false`: `null` равен только `undefined`. А `>=` приводит `null` к числу.
- `![]` — `false`, затем `[] == false` → `'' == 0` → `true`.

В коде такие выражения не пишут: значения явно приводят к нужному типу при чтении.
::

::practice{title="Найди баг"}
Магазин ввёл бесплатную доставку для некоторых товаров (`shipping: 0`), но в итоге всё равно добавляются 300 рублей. А если очистить поле количества, заказ молча считается на одну штуку:

```js
function total(qtyInput, product) {
  const qty = qtyInput.value || 1;
  const shipping = product.shipping || 300;
  return product.price * qty + shipping;
}

total({ value: '2' }, { price: 2490, shipping: 0 });  // 5280, а должно быть 4980
total({ value: '' }, { price: 2490, shipping: 0 });   // 2790 — пустое поле стало «1»
```

#solution
`||` подставляет значение по умолчанию для любого falsy. `shipping: 0` — законное значение «бесплатно», но `0 || 300` даёт `300`. Пустая строка из поля тоже falsy и превращается в `1`, хотя это ошибка ввода, а не «одна штука».

```js
function total(qtyInput, product) {
  const qty = Number(qtyInput.value);
  if (qtyInput.value.trim() === '' || !Number.isInteger(qty) || qty < 1) {
    throw new RangeError('Укажите количество');
  }
  const shipping = product.shipping ?? 300;   // только «не указано» → 300
  return product.price * qty + shipping;
}

total({ value: '2' }, { price: 2490, shipping: 0 });   // 4980
total({ value: '2' }, { price: 2490 });                // 5280 — доставка не указана
```

`??` срабатывает только на `null` и `undefined`, поэтому `0` остаётся нулём. Количество явно приводится к числу и проверяется: пустое поле — ошибка, а не тихая единица. `qty * price` работало и со строкой, но `price + qtyInput.value` уже склеило бы строки — поэтому значения полей приводят к числу сразу при чтении.
::

::practice{title="Сравни правильно"}
Напиши функцию `same(a, b)`, которая для списка значений работает как `Object.is`, но без вызова `Object.is`. Какие случаи отличают её от `===`?

#solution
`===` и `Object.is` расходятся ровно в двух случаях: `NaN` и знак нуля.

```js
function same(a, b) {
  if (a === b) {
    // 0 === -0, но 1/0 = Infinity, а 1/-0 = -Infinity
    return a !== 0 || 1 / a === 1 / b;
  }
  // только NaN не равен себе
  return a !== a && b !== b;
}

same(NaN, NaN);   // true,  а NaN === NaN — false
same(0, -0);      // false, а 0 === -0 — true
same('1', 1);     // false, как и ===
```

Так выглядел полифил `Object.is`. Деление на ноль различает знак: `1 / -0` — `-Infinity`, а `x !== x` истинно только для `NaN`.
::
