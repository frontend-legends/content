# Типы данных и переменные

Типы данных - фундамент любого языка. В JavaScript всего 7 примитивных типов и один ссылочный (Object). Но за этой простотой скрывается система неявного приведения типов, которая ломает интуицию и порождает самые популярные вопросы на собеседованиях. Понимание типов, переменных и их поведения - первое, что проверяют на техническом интервью.

---

## Примитивные типы

Примитив - это значение, которое **не является объектом** и **не имеет методов**. Хранится непосредственно в переменной (в стеке). При присваивании копируется значение.

### string

```js
const name = "Alice";
const greeting = `Hello, ${name}!`; // template literal
const multiline = `line 1
line 2`;
```

<span class="text-gray">Строки неизменяемы (immutable). `str[0] = "X"` ничего не сделает. Любая «мутация» создаёт новую строку.</span>

### number

```js
const int = 42;
const float = 3.14;
const hex = 0xff;           // 255
const inf = Infinity;       // 1 / 0
const nan = NaN;            // Not a Number, но typeof NaN === "number"
```

<span class="text-gray">Все числа в JS - 64-битные IEEE 754 (double). Отсюда `0.1 + 0.2 !== 0.3`. Целочисленная точность гарантирована до `Number.MAX_SAFE_INTEGER` (2^53 - 1).</span>

### bigint

```js
const big = 9007199254740993n; // суффикс n
const fromStr = BigInt("9007199254740993");
// big + 1n -> 9007199254740994n (точно!)
// big + 1 -> TypeError: нельзя смешивать BigInt и Number
```

### boolean

```js
const yes = true;
const no = false;
// Результат сравнений: 5 > 3 -> true
```

### undefined

```js
let x;              // значение undefined
function f(a) {}    // f() -> a === undefined
const obj = {};
obj.missing;        // undefined
```

<span class="text-gray">`undefined` означает «значение не было присвоено». Это значение по умолчанию для неинициализированных переменных, отсутствующих свойств и параметров.</span>

### null

```js
let user = null; // явно указывает «значение пустое»
```

<span class="text-gray">`null` - намеренное отсутствие значения. `undefined` - ненамеренное. На практике: используй `null`, когда хочешь явно обозначить «пусто»; `undefined` обычно возвращается самим языком.</span>

### symbol

```js
const id = Symbol("id");
const anotherId = Symbol("id");
id === anotherId; // false - каждый Symbol уникален

const obj = { [id]: 123 };
Object.keys(obj); // [] - символьные ключи не видны в обычном перечислении
```

<span class="text-gray">Символы используются для создания уникальных ключей свойств и метапрограммирования (`Symbol.iterator`, `Symbol.toPrimitive`). В повседневной фронтенд-разработке встречаются редко, но спрашивают часто.</span>

## Ссылочные типы (Object)

Всё, что не примитив - это Object. Объекты хранятся в куче (heap), а переменная содержит **ссылку** (указатель) на область памяти, а не само значение.

```js
const a = { x: 1 };
const b = a;       // копируется ссылка, а не объект
b.x = 99;
console.log(a.x);  // 99 - a и b указывают на один объект

// Сравнение по ссылке
{ x: 1 } === { x: 1 }; // false - два разных объекта в памяти
```

К ссылочным типам относятся:

- **Object** - `{}`, `new Object()`
- **Array** - `[]`, `new Array()` (на самом деле объект с числовыми ключами)
- **Function** - `function() {}`, `() => {}` (объект с внутренним методом `[[Call]]`)
- **Date**, **RegExp**, **Map**, **Set**, **WeakMap**, **WeakSet**, **Error**

<b class="text-on-semi-light">На фронте:</b> Мутация объектов по ссылке - один из главных источников багов в React. Если ты изменишь свойство объекта из state напрямую, React не заметит изменения и не перерендерит компонент. Именно поэтому используются immutable-обновления и spread operator.

## typeof

Оператор `typeof` возвращает строку с типом значения. Но у него есть исторические особенности.

| Выражение              | Результат       | Комментарий                                   |
| ---------------------- | --------------- | --------------------------------------------- |
| `typeof 42`            | `"number"`      |                                               |
| `typeof "hello"`       | `"string"`      |                                               |
| `typeof true`          | `"boolean"`     |                                               |
| `typeof undefined`     | `"undefined"`   |                                               |
| `typeof Symbol()`      | `"symbol"`      |                                               |
| `typeof 42n`           | `"bigint"`      |                                               |
| `typeof null`          | `"object"`      | ⚠️ Баг с 1995 года, никогда не исправят        |
| `typeof {}`            | `"object"`      |                                               |
| `typeof []`            | `"object"`      | Массив - это объект. Проверяй `Array.isArray()` |
| `typeof function() {}` | `"function"`    | Единственный объектный тип с особым typeof      |
| `typeof undeclared`    | `"undefined"`   | Не выбрасывает ReferenceError                  |

<b class="text-on-semi-light">typeof null === "object":</b> Это баг первой реализации JS. Внутренне значения хранились с type tag. Tag `000` означал объект, а `null` был нулевым указателем (все биты 0), поэтому type tag совпал с объектом. Исправить нельзя - сломается слишком много кода в интернете.

## Переменные: var vs let vs const

| Характеристика    | `var`                  | `let`                    | `const`                  |
| ----------------- | ---------------------- | ------------------------ | ------------------------ |
| Scope             | Function scope         | Block scope              | Block scope              |
| Hoisting          | Да, инициализируется `undefined` | Да, но TDZ (нет инициализации) | Да, но TDZ (нет инициализации) |
| TDZ               | Нет                    | Да                       | Да                       |
| Повторное объявление | Да                  | Нет (SyntaxError)        | Нет (SyntaxError)        |
| Переприсваивание  | Да                     | Да                       | Нет (TypeError)          |
| Глобальное свойство | Да (`window.x`)      | Нет                      | Нет                      |

```js
// Scope difference
if (true) {
  var a = 1;   // видна за пределами блока
  let b = 2;   // видна только внутри {}
  const c = 3; // видна только внутри {}
}
console.log(a); // 1
console.log(b); // ReferenceError

// const не делает значение неизменяемым!
const arr = [1, 2, 3];
arr.push(4);     // OK - мутация содержимого
arr = [5, 6, 7]; // TypeError - переприсваивание ссылки
```

<b class="text-on-semi-light">Правило:</b> Используй `const` по умолчанию. `let` - когда нужно переприсваивание. `var` - никогда (в современном коде).

## Temporal Dead Zone (TDZ)

TDZ - это зона от начала блока до момента объявления переменной, в которой обращение к `let`/`const` выбрасывает `ReferenceError`.

```js
console.log(a); // undefined (var поднимается и инициализируется undefined)
console.log(b); // ReferenceError: Cannot access 'b' before initialization
console.log(c); // ReferenceError

var a = 1;
let b = 2;
const c = 3;
```

<b class="text-on-semi-light">Почему TDZ существует:</b> `var` поднимается и инициализируется `undefined` - это порождает неочевидные баги. TDZ заставляет тебя объявлять переменные до использования, что делает код предсказуемым.

```js
// TDZ даже в одном выражении
let x = x; // ReferenceError - x в TDZ при инициализации самой себя

// TDZ в параметрах
function f(a = b, b = 1) {} // ReferenceError при f() - b в TDZ когда a вычисляется
```

## Hoisting

Hoisting (подъём) - это поведение, при котором объявления перемещаются в начало своей области видимости на этапе компиляции.

```js
// Что ты пишешь:
console.log(x);  // undefined
greet();         // "Hello!"
var x = 5;
function greet() {
  console.log("Hello!");
}

// Как движок это видит:
function greet() {       // функция поднимается целиком
  console.log("Hello!");
}
var x;                   // var поднимается, но без значения
console.log(x);          // undefined
x = 5;
greet();                 // "Hello!"
```

| Конструкция             | Что поднимается                   | Инициализация        |
| ----------------------- | --------------------------------- | -------------------- |
| `var x = 5`             | Объявление `var x`                | `undefined`          |
| `let x = 5`             | Объявление (в TDZ)                | Нет (ReferenceError) |
| `const x = 5`           | Объявление (в TDZ)                | Нет (ReferenceError) |
| `function f() {}`       | Целиком (имя + тело)              | Функция              |
| `var f = function() {}` | Только `var f`                    | `undefined`          |
| `class C {}`            | Объявление (в TDZ)                | Нет (ReferenceError) |

## Приведение типов (Type Coercion)

### Явное приведение (explicit)

```js
String(123);       // "123"
Number("42");      // 42
Number("");        // 0
Number("hello");   // NaN
Number(true);      // 1
Number(null);      // 0
Number(undefined); // NaN
Boolean(0);        // false
Boolean("");       // false
Boolean("0");      // true (непустая строка!)
```

### Неявное приведение (implicit)

```js
// Оператор + с строкой - конкатенация
"5" + 3;       // "53" (число -> строка)
5 + "3";       // "53"
5 + null;      // 5   (null -> 0)
"5" + null;    // "5null"

// Операторы -, *, / - всегда числовые
"5" - 3;       // 2
"5" * "2";     // 10
true + true;   // 2

// Сравнение
"5" == 5;      // true (строка -> число)
null == undefined; // true (специальное правило)
null == 0;     // false (null == только null и undefined)
```

## Сравнение: == vs ===

### === (строгое равенство)

Сравнивает значения **без приведения типов**. Если типы разные - сразу `false`.

```js
5 === 5;        // true
5 === "5";      // false - разные типы
null === undefined; // false
NaN === NaN;    // false (единственное значение, не равное самому себе)
```

### == (нестрогое равенство)

Приводит типы по сложному алгоритму перед сравнением.

```js
5 == "5";          // true  (строка -> число)
0 == false;        // true  (boolean -> число)
"" == false;       // true  (оба -> 0)
null == undefined; // true  (специальное правило)
null == 0;         // false (null сравнивается только с null и undefined)
[] == false;       // true  ([] -> "" -> 0, false -> 0)
[] == ![];         // true  (одна из самых абсурдных gotcha'ов JS)
```

<b class="text-on-semi-light">Правило:</b> Всегда используй `===`. Единственное исключение, где `==` допустим: `x == null` проверяет и `null`, и `undefined` одним условием.

## Truthy и Falsy

### Falsy-значения (полный список)

```js
Boolean(false);     // false
Boolean(0);         // false
Boolean(-0);        // false
Boolean(0n);        // false (BigInt zero)
Boolean("");        // false (пустая строка)
Boolean(null);      // false
Boolean(undefined); // false
Boolean(NaN);       // false
```

### Всё остальное - truthy

```js
Boolean("0");       // true  - непустая строка!
Boolean(" ");       // true  - пробел тоже строка
Boolean([]);        // true  - пустой массив!
Boolean({});        // true  - пустой объект!
Boolean(-1);        // true
Boolean(Infinity);  // true
Boolean(new Boolean(false)); // true - объект-обёртка!
```

⚠️ Пустой массив `[]` и пустой объект `{}` - truthy. Это частая ловушка.

## Boxing / Unboxing

Примитивы не имеют методов. Но ты вызываешь `"hello".toUpperCase()`. Как это работает?

```js
// Ты пишешь:
"hello".toUpperCase(); // "HELLO"

// Движок делает (boxing):
new String("hello").toUpperCase(); // создаёт временную обёртку
// Сразу после вызова обёртка уничтожается (unboxing)
```

Обёртки: `String`, `Number`, `Boolean`. Никогда не создавай их через `new` напрямую:

```js
// Плохо
const s = new String("hello");
typeof s;       // "object" (не "string"!)
s === "hello";  // false

// Хорошо - используй как функцию для приведения типа
const n = Number("42"); // 42 (примитив)
typeof n;       // "number"
```

## Nullish Coalescing (??) vs OR (||)

```js
const a = 0;
const b = "";

// || возвращает первый truthy
a || "default";   // "default" (0 - falsy)
b || "default";   // "default" ("" - falsy)

// ?? возвращает первый не-null/undefined
a ?? "default";   // 0 (0 не null/undefined)
b ?? "default";   // "" ("" не null/undefined)
```

<b class="text-on-semi-light">Когда использовать ??:</b> Когда `0`, `""` и `false` - допустимые значения. Например, `count ?? 10` - если count равен 0, мы хотим оставить 0, а не заменять на 10.

> Статическая типизация решает многие проблемы с типами - подробнее в [TypeScript](/content/typescript/introduction).

## Методы строк

Строки в JS неизменяемы (immutable) - все методы возвращают новую строку.

<b class="text-on-semi-light">Доступ и длина</b>

- `str.length` - длина строки
- `str.charAt(i)` / `str[i]` - символ по индексу
- `str.at(i)` - поддерживает отрицательные индексы (`str.at(-1)` - последний символ)
- `str.charCodeAt(i)` / `str.codePointAt(i)` - Unicode-код символа

<b class="text-on-semi-light">Поиск</b>

- `str.indexOf(sub)` / `str.lastIndexOf(sub)` - индекс первого/последнего вхождения
- `str.includes(sub)` - содержит ли подстроку (boolean)
- `str.startsWith(sub)` / `str.endsWith(sub)` - начинается/заканчивается
- `str.search(regex)` - индекс первого совпадения с RegExp
- `str.match(regex)` / `str.matchAll(regex)` - поиск по RegExp

<b class="text-on-semi-light">Извлечение</b>

- `str.slice(start, end)` - часть строки (отрицательные индексы)
- `str.substring(start, end)` - аналог slice (без отрицательных)

<b class="text-on-semi-light">Трансформация</b>

- `str.toUpperCase()` / `str.toLowerCase()` - регистр
- `str.trim()` / `str.trimStart()` / `str.trimEnd()` - пробелы
- `str.padStart(len, fill)` / `str.padEnd(len, fill)` - дополнение (`'5'.padStart(3, '0')` -> `'005'`)
- `str.repeat(n)` - повторение
- `str.replace(old, new)` / `str.replaceAll(old, new)` - замена
- `str.split(sep)` - разбиение в массив
- `str.concat(str2)` - объединение (лучше использовать `+` или template literals)

## Number подробно

Все числа в JS - 64-битные float (IEEE 754). Безопасный целочисленный диапазон: -2^53+1 до 2^53-1.

<b class="text-on-semi-light">Свойства</b>

- `Number.MAX_SAFE_INTEGER` - 9007199254740991 (2^53-1)
- `Number.MIN_SAFE_INTEGER` - -9007199254740991
- `Number.MAX_VALUE` / `Number.MIN_VALUE` - максимальное/минимальное представимое число
- `Number.POSITIVE_INFINITY` / `Number.NEGATIVE_INFINITY`
- `Number.NaN` - Not a Number
- `Number.EPSILON` - минимальная разница между двумя числами

<b class="text-on-semi-light">Статические методы</b>

- `Number.isNaN(v)` - проверка на NaN (не путать с глобальным `isNaN()` который приводит тип!)
- `Number.isFinite(v)` - конечное число
- `Number.isInteger(v)` - целое число
- `Number.isSafeInteger(v)` - в безопасном диапазоне
- `Number.parseInt(str, radix)` / `Number.parseFloat(str)` - парсинг строки

<b class="text-on-semi-light">Методы экземпляра</b>

- `num.toFixed(digits)` - фиксированное количество знаков после запятой (`3.14159.toFixed(2)` -> `'3.14'`)
- `num.toPrecision(digits)` - общее количество значащих цифр
- `num.toString(radix)` - в строку с указанной системой счисления (`255..toString(16)` -> `'ff'`)

```js
// Преобразование в Number
Number('42')        // 42
Number('')          // 0
Number(true)        // 1
Number(null)        // 0
Number(undefined)   // NaN
Number('42px')      // NaN

parseInt('42px', 10) // 42 (читает до первого нечислового символа)
parseFloat('3.14')   // 3.14
```

## valueOf() и toString()

Каждый объект в JS наследует от `Object.prototype` два метода для преобразования в примитив:

- `valueOf()` - возвращает примитивное значение объекта
- `toString()` - возвращает строковое представление

```js
const obj = { x: 1 };
obj.valueOf()   // { x: 1 } (сам объект, если не переопределён)
obj.toString()  // '[object Object]'

const num = new Number(42);
num.valueOf()   // 42
num.toString()  // '42'

const arr = [1, 2, 3];
arr.valueOf()   // [1, 2, 3]
arr.toString()  // '1,2,3'
```

При приведении типов JS вызывает эти методы автоматически. Порядок зависит от контекста:
- Числовой контекст (`+`, `-`, `*`): сначала `valueOf()`, потом `toString()`
- Строковый контекст (конкатенация): сначала `toString()`, потом `valueOf()`
- `Symbol.toPrimitive` (если определён) имеет приоритет над обоими

## instanceof

Оператор `instanceof` проверяет, есть ли `Constructor.prototype` в цепочке прототипов объекта.

```js
[] instanceof Array    // true
[] instanceof Object   // true (Array наследует от Object)

new Date() instanceof Date     // true
new Date() instanceof Object   // true

'hello' instanceof String        // false (примитив!)
new String('hello') instanceof String  // true (объект-обёртка)
```

<span class="text-gray">`instanceof` не работает с примитивами - только с объектами. Для надёжной проверки типа используй `Object.prototype.toString.call(value)`:</span>

```js
Object.prototype.toString.call([])        // '[object Array]'
Object.prototype.toString.call(null)      // '[object Null]'
Object.prototype.toString.call(undefined) // '[object Undefined]'
```

> Дополнительные проверки: `Array.isArray()`, `Number.isNaN()`, `Number.isFinite()`, `typeof`, `Object.is()`

## null vs undefined

| | `null` | `undefined` |
|---|--------|-------------|
| Значение | Явное "пустое значение" | Переменная не инициализирована |
| Кто устанавливает | Программист | JS-движок |
| typeof | `'object'` (баг) | `'undefined'` |
| В математике | `Number(null)` -> `0` | `Number(undefined)` -> `NaN` |
| == сравнение | `null == undefined` -> `true` | `null == undefined` -> `true` |
| === сравнение | `null === undefined` -> `false` | `null === undefined` -> `false` |

<span class="text-gray">`null` - "значение известно, но пусто" (конец цепочки прототипов, явная очистка ссылки). `undefined` - "значение не задано" (параметр не передан, свойство не существует, `return` без значения).</span>

## Tagged template literals

Tagged templates позволяют обрабатывать template literal через функцию. Функция-тег получает массив строк и интерполированные значения отдельно.

```js
function highlight(strings, ...values) {
  return strings.reduce((result, str, i) => {
    const value = values[i] ? `<mark>${values[i]}</mark>` : '';
    return result + str + value;
  }, '');
}

const name = 'JavaScript';
const version = 'ES2025';

highlight`Язык ${name} версии ${version}`;
// 'Язык <mark>JavaScript</mark> версии <mark>ES2025</mark>'
```

<b class="text-on-semi-light">Практические use cases</b>

- `html\`...\`` - безопасная вставка HTML (lit-html, Preact htm)
- `css\`...\`` - CSS-in-JS (styled-components, emotion)
- `sql\`...\`` - защита от SQL-инъекций
- `gql\`...\`` - GraphQL запросы (Apollo)
- Sanitization: экранирование пользовательского ввода

## Частые вопросы на собесе

**Какие примитивные типы есть в JavaScript?**
Семь: `string`, `number`, `bigint`, `boolean`, `undefined`, `null`, `symbol`. Всё остальное - объект. Примитивы иммутабельны и копируются по значению. Объекты передаются по ссылке.

**Почему typeof null === "object"?**
Баг первой реализации JS (1995). Значения хранились с type tag, null был нулевым указателем, а tag 000 означал объект. Исправить нельзя - сломает существующий код.

**В чём разница между var, let и const?**
`var` - function scope, поднимается с `undefined`, можно переобъявлять. `let` - block scope, TDZ, нельзя переобъявлять. `const` - как `let`, но нельзя переприсваивать. `const` не делает объект иммутабельным - можно мутировать свойства.

**Что такое TDZ?**
Temporal Dead Zone - зона от начала блока до объявления `let`/`const`. Обращение к переменной в TDZ выбрасывает `ReferenceError`. Существует для предотвращения неочевидных багов, которые возникали с `var`.

**Чем == отличается от ===?**
`===` сравнивает без приведения типов (строгое). `==` приводит типы по сложному алгоритму. Всегда используй `===`. Исключение: `x == null` для проверки null/undefined одним условием.

**Что такое falsy-значения?**
`false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN` - всего 8 значений. Всё остальное truthy, включая `[]`, `{}`, `"0"`.
