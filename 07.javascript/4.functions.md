# Функции

Что такое функция в JavaScript, чем отличаются её формы и как устроены параметры. Спрашивают разницу объявления, выражения и стрелочной функции, rest против `arguments` и функции высшего порядка. Глубже — почему стрелку нельзя вызвать через `new`, как связаны `arguments` и параметры, когда вычисляются значения по умолчанию и почему глубокая рекурсия падает даже с хвостовым вызовом.

::tldr
- **Функция — объект, который можно вызвать.** Её передают, возвращают и хранят как любое значение, у неё есть свойства `name` и `length`. На этом построены колбэки и функции высшего порядка.
- **Формы функций различаются поведением, а не только синтаксисом.** Объявление поднимается целиком, выражение — нет. У стрелки нет своего `this`, `arguments` и `prototype`, её нельзя вызвать через `new`.
- **Значения параметров по умолчанию вычисляются при каждом вызове** и только вместо `undefined`. Каждый вызов получает свой новый массив по умолчанию.
- **`...rest` — настоящий массив, `arguments` — псевдомассив** только в обычных функциях. В нестрогом режиме без значений по умолчанию `arguments` связан с параметрами.
- **Стек вызовов ограничен** — около 10 тысяч вызовов в Node.js. Хвостовые вызовы V8 не оптимизирует, поэтому глубокие структуры обходят итеративно.
::

## Функция — это значение

Сквозной пример темы — модуль цен в магазине:

```js
function formatPrice(value, currency = '₽') {
  return `${value} ${currency}`;
}

const withDiscount = (percent) => (price) => price * (1 - percent / 100);

const total = (items, priceOf) => items.reduce((sum, i) => sum + priceOf(i) * i.qty, 0);
```

В JavaScript функция — **объект**, у которого есть внутренний метод вызова. Поэтому с ней можно делать всё, что с другими значениями: положить в переменную, передать аргументом, вернуть из другой функции, добавить свойство. Это и называют «функции первого класса».

У каждой функции есть служебные свойства:

- **`name`** — имя. Для анонимной функции, присвоенной переменной, имя выводится из переменной: у `const arrow = () => {}` имя `'arrow'`. Имя видно в стеке ошибок и профайлере, поэтому анонимные функции отлаживать сложнее.
- **`length`** — число параметров **до первого со значением по умолчанию или rest**. У `formatPrice(value, currency = '₽')` длина 1. На `length` полагаются библиотеки каррирования, и параметр по умолчанию может неожиданно её изменить.

### Функции высшего порядка

Функция, которая принимает или возвращает функцию, — функция высшего порядка. `withDiscount(10)` возвращает функцию, которая применяет скидку 10%. `total(items, priceOf)` принимает функцию, которая решает, как считать цену. Методы массивов `map`, `filter`, `reduce`, `sort` — тоже функции высшего порядка.

```js
const sale = withDiscount(10);
total(cart.items, (i) => sale(i.price));
```

Функции высшего порядка позволяют передавать **поведение** так же, как данные. Возвращённая функция помнит переменные, среди которых была создана: `percent` живёт после выхода из `withDiscount`. Это замыкание, и о нём отдельная тема — [Замыкания](/content/javascript/closures). Композиция, каррирование и частичное применение как приёмы — в [Паттернах](/content/javascript/patterns).

Функции — значения, но создавать их можно по-разному, и формы ведут себя по-разному.

## Формы функций

```js
function declared() {}              // объявление (declaration)
const expressed = function () {};   // выражение (expression)
const named = function inner() {};  // именованное выражение
const arrow = () => {};             // стрелочная функция
const obj = { method() {} };        // сокращённый метод
```

Различаются они по нескольким признакам:

| | Объявление | Выражение | Стрелка | Метод `{ m() {} }` |
| --- | --- | --- | --- | --- |
| Доступна до своей строки | да, целиком | нет | нет | нет |
| Свой `this` | да, зависит от вызова | да | нет, берёт снаружи | да |
| Свой `arguments` | да | да | нет | да |
| Можно вызвать через `new` | да | да | нет | нет |
| Есть `prototype` | да | да | нет | нет |

**Объявление поднимается целиком**: его можно вызвать выше по коду, чем оно написано. Выражение — обычное присваивание переменной, и до этой строки функции ещё нет. Почему так — разбор контекста выполнения и hoisting в [Контексте выполнения](/content/javascript/execution-context).

**У стрелки нет своего `this` и `arguments`** — она берёт их из окружающей функции, как обычные переменные. Поэтому стрелки подходят для колбэков внутри методов: `this` остаётся тем же. И поэтому они не подходят для методов объекта, которым нужен свой `this`. Как определяется `this` у обычных функций — тоже в [Контексте выполнения](/content/javascript/execution-context).

**Стрелку нельзя вызвать через `new`**: у неё нет внутреннего метода конструирования и свойства `prototype`. `new arrow()` бросает `TypeError: arrow is not a constructor`. То же для сокращённых методов объекта.

**Имя именованного выражения видно только внутри функции.** Это удобно для рекурсии и стеков ошибок: `const fact = function f(n) { return n <= 1 ? 1 : n * f(n - 1); }` вызывает себя через `f`, а снаружи `f` не существует.

### Специальные формы

Ещё три формы разобраны в своих темах: генераторы `function*` — в [Итераторах и генераторах](/content/javascript/iterators-and-generators), `async`-функции — в [Асинхронности](/content/javascript/async), классы — в [Прототипах и классах](/content/javascript/prototypes-and-classes). Конструктор `new Function('a', 'return a')` создаёт функцию из строки в глобальной области видимости — тот же риск, что `eval`, и его блокирует политика безопасности контента.

Форма решает, как функция ведёт себя при вызове. Следующий вопрос — как она получает данные.

## Параметры

### Значения по умолчанию

```js
function addToCart(cart, sku, qty = 1, addedAt = Date.now()) { /* ... */ }
```

Значение по умолчанию:

- **подставляется только вместо `undefined`**. Если передать `null`, параметр будет `null`;
- **вычисляется при каждом вызове**, а не один раз. `addedAt` получит текущее время каждого вызова, а `list = []` — новый массив. В отличие от Python, общего изменяемого значения по умолчанию в JavaScript не бывает;
- **видит предыдущие параметры**: `function f(a, b = a * 2)` работает. Обращение к следующему параметру — ошибка, параметры проходят через ту же «временную мёртвую зону», что и `let`: `function g(a = b, b = 1)` при вызове без аргументов бросает `ReferenceError`.

### rest и arguments

Rest-параметр собирает оставшиеся аргументы в **настоящий массив**:

```js
function log(level, ...messages) {
  messages.forEach((m) => console[level](m));
}
```

`arguments` — старый механизм. Это псевдомассив (есть `length` и индексы, но нет методов массива) со всеми переданными аргументами, и он есть только у обычных функций. У стрелки `arguments` — это `arguments` внешней функции.

У `arguments` есть исторический сюрприз. В нестрогом режиме он **связан** с параметрами: `arguments[0] = 99` меняет первый параметр, и наоборот. В strict mode и в функциях со значениями по умолчанию, rest или деструктуризацией в параметрах связи нет. Это одна из причин, по которой в новом коде `arguments` не используют.

### Деструктуризация параметров

Объект параметров вместо длинного списка позиционных:

```js
function createOrder({ items, promo = null, delivery = 'courier' } = {}) { /* ... */ }

createOrder({ items, delivery: 'pickup' });   // порядок не важен, пропуск — по имени
```

`= {}` в конце нужен, чтобы вызов без аргумента не падал на деструктуризации `undefined`. Правила деструктуризации — в [Объектах и массивах](/content/javascript/objects-and-arrays).

Параметры разобраны. Последний механизм функций, о котором спрашивают отдельно, — вызов функции самой себя.

## Рекурсия

Рекурсия естественна для вложенных структур: дерево категорий, вложенные комментарии, JSON произвольной глубины.

```js
function walk(node, out = []) {
  out.push(node.name);
  node.children.forEach((child) => walk(child, out));
  return out;
}
```

У каждого вызова свой кадр в стеке вызовов, и стек ограничен. В проверке Node.js упал после примерно 10 400 вложенных вызовов с `RangeError: Maximum call stack size exceeded`. Точное число зависит от движка, размера кадров и платформы.

### Хвостовые вызовы не спасут

Хвостовой вызов — когда рекурсивный вызов — последнее действие функции: `return sum(n - 1, acc + n)`. Спецификация ES2015 требует, чтобы такие вызовы не росли в стеке (proper tail calls), но V8 и SpiderMonkey этого не реализовали — только JavaScriptCore в Safari. В проверке хвостовая рекурсия упала на той же глубине, что и обычная.

Поэтому для структур неизвестной глубины рекурсию заменяют явным стеком:

```js
function walkIterative(root) {
  const out = [];
  const stack = [root];
  while (stack.length) {
    const node = stack.pop();
    out.push(node.name);
    for (let i = node.children.length - 1; i >= 0; i--) stack.push(node.children[i]);
  }
  return out;
}
```

Порядок обхода тот же (дети кладутся в обратном порядке, чтобы первый оказался сверху), а глубина ограничена только памятью. В проверке цепочка вдвое глубже предела стека обошлась без ошибки.

### Чистые функции

Удобнее всего тестировать и переиспользовать **чистые функции**: результат зависит только от аргументов, и функция ничего не меняет снаружи. `formatPrice` и `withDiscount` — чистые. Функция, которая читает `Date.now()`, пишет в глобальную переменную или мутирует аргумент, — нет. Это свойство, на котором держатся мемоизация, React и параллельные вычисления (подробно — в [Механике хуков](/content/reactjs/hooks-mechanics)).

## Красные флаги в ответе

- **«Стрелочная функция — короткая запись обычной».** У неё нет своего `this`, `arguments` и `prototype`, её нельзя вызвать через `new`.
- **«Значение по умолчанию вычисляется один раз, как в Python».** Оно вычисляется при каждом вызове, и только вместо `undefined`.
- **«`arguments` — массив».** Это псевдомассив без методов массива, а в нестрогом режиме он ещё и связан с параметрами.
- **«Хвостовая рекурсия не переполняет стек».** В V8 и SpiderMonkey хвостовые вызовы не оптимизируются.
- **«Функция и объект — разные вещи».** Функция — объект с возможностью вызова: у неё есть свойства, и её можно передавать как значение.

## Как спрашивают на собеседовании

::question
В чём разница между объявлением функции и функциональным выражением?

#answer
Объявление поднимается целиком: функцию можно вызвать выше по коду. Выражение — присваивание переменной, и функция доступна только после этой строки. Стрелка — тоже выражение.

#more
При создании контекста выполнения объявления функций создаются сразу вместе с телом, а переменная выражения получает значение только при выполнении присваивания: для `var` до этого там `undefined`, для `let` и `const` — временная мёртвая зона. У именованного выражения имя видно только внутри функции — удобно для рекурсии и стеков ошибок.
::

::question
Чем стрелочная функция отличается от обычной?

#answer
У неё нет своего `this` — она берёт его из внешней области. Нет `arguments`, нельзя вызвать через `new`, нет `prototype`. Подходит для колбэков, не подходит для методов объекта.

#more
У стрелки нет внутреннего метода конструирования, поэтому `new` бросает `TypeError`. `this`, `arguments`, `super` и `new.target` разрешаются лексически, как обычные переменные, и `call`, `apply`, `bind` не могут поменять `this` стрелки. Поэтому стрелка как метод объекта получит `this` модуля или `undefined`, а не объект.
::

::question
Чем rest-параметры отличаются от arguments?

#answer
`...args` — настоящий массив, работает в стрелках и собирает только оставшиеся аргументы. `arguments` — псевдомассив со всеми аргументами, есть только в обычных функциях.

#more
В нестрогом режиме `arguments` связан с параметрами: изменение одного меняет другое. Связь исчезает в strict mode и в функциях со значениями по умолчанию, rest или деструктуризацией параметров. Плюс `arguments` мешал оптимизациям движков, поэтому в новом коде его не используют.
::

::question
Что такое функция высшего порядка?

#answer
Функция, которая принимает другую функцию или возвращает функцию. `map`, `filter`, `reduce` — примеры. Это основа колбэков и функционального стиля.

#more
Это работает, потому что функции в JS — значения первого класса. Возвращённая функция замыкает переменные внешней, поэтому так строят фабрики, частичное применение, декораторы вроде `once`, `debounce` и мемоизации. Ловушка — несовпадение арности: `['1', '2'].map(parseInt)` передаёт индекс вторым аргументом, и он становится основанием системы счисления.
::

::question
Когда вычисляются значения параметров по умолчанию?

#answer
При каждом вызове, если аргумент не передан или равен `undefined`. `null` значение по умолчанию не включает.

#more
Каждое значение по умолчанию — выражение, которое вычисляется заново, поэтому `list = []` даёт новый массив на каждый вызов (в отличие от Python). Параметры инициализируются слева направо в своей области видимости: значение по умолчанию видит предыдущие параметры, а обращение к следующему — `ReferenceError`. Наличие значений по умолчанию отключает связь `arguments` с параметрами и уменьшает `fn.length`.
::

::question
Как работает рекурсия и когда её использовать?

#answer
Функция вызывает себя, пока не дойдёт до базового случая. Удобна для деревьев и вложенных структур. Стек вызовов ограничен, поэтому слишком глубокая рекурсия падает с `RangeError`.

#more
Предел — около 10 тысяч вызовов в Node.js, точное число зависит от движка и размера кадров. Хвостовые вызовы из ES2015 реализованы только в JavaScriptCore, поэтому на V8 даже хвостовая рекурсия переполняет стек. Для данных неизвестной глубины рекурсию заменяют явным стеком или очередью.
::

## Практика

::practice{title="Что выведет?"}
```js
function price(value, currency = '₽', ...rest) {}
console.log(price.name, price.length);

const arrow = () => {};
try { new arrow(); } catch (e) { console.log(e.message); }

function sloppy(a) { arguments[0] = 99; return a; }
console.log(sloppy(1));

console.log(['1', '2', '3'].map(parseInt));
```

#solution
```text
price 1
arrow is not a constructor
99
[ 1, NaN, NaN ]
```

- `length` считает параметры до первого со значением по умолчанию.
- Стрелку нельзя вызвать через `new`.
- В нестрогом режиме без значений по умолчанию `arguments` связан с параметрами.
- `map` передаёт колбэку три аргумента: значение, индекс и массив. `parseInt('2', 1)` — основание 1 недопустимо, `parseInt('3', 2)` — в двоичной системе нет цифры 3. Правильно: `['1', '2', '3'].map(Number)` или `map((s) => parseInt(s, 10))`.
::

::practice{title="Напиши once"}
Кнопка оплаты должна отправить запрос только один раз, даже если по ней кликнули дважды. Напиши функцию высшего порядка `once(fn)`: она возвращает функцию, которая вызывает `fn` только при первом вызове и дальше возвращает тот же результат.

#solution
```js
function once(fn) {
  let called = false;
  let result;
  return function (...args) {
    if (!called) {
      called = true;
      result = fn.apply(this, args);
    }
    return result;
  };
}

const pay = once((orderId) => api.pay(orderId));
pay(7);
pay(7);   // второй запрос не уйдёт, вернётся тот же промис
```

`called` и `result` живут в замыкании. Обычная функция (не стрелка) нужна, чтобы `once` можно было применить к методу объекта: `this` передаётся через `fn.apply(this, args)`. Флаг ставится до вызова, поэтому даже если `fn` бросит ошибку, повторного вызова не будет.
::

::practice{title="Почему падает обход дерева?"}
Функция считает количество комментариев во вложенной ветке. На длинных цепочках ответов она падает с `RangeError: Maximum call stack size exceeded`:

```js
function count(comment) {
  return 1 + comment.replies.reduce((sum, r) => sum + count(r), 0);
}
```

#solution
Каждый уровень вложенности — новый кадр стека, а стек ограничен (около 10 тысяч вызовов в Node.js). Цепочка из 20 тысяч ответов друг другу его переполнит. Переписать в хвостовую форму не поможет: V8 не оптимизирует хвостовые вызовы.

Фикс — явный стек:

```js
function count(root) {
  let total = 0;
  const stack = [root];
  while (stack.length) {
    const comment = stack.pop();
    total++;
    stack.push(...comment.replies);
  }
  return total;
}
```

Глубина теперь ограничена памятью, а не стеком вызовов. Если у одного комментария могут быть сотни тысяч прямых ответов, `push(...replies)` тоже упрётся в лимит аргументов — тогда добавляют циклом.
::
