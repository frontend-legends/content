# Функции

Функции - это основной строительный блок JavaScript. Любая программа состоит из функций: обработчики событий, API-вызовы, трансформации данных, рендеринг UI. JavaScript предлагает несколько способов объявления функций, и каждый ведёт себя по-разному в отношении hoisting, `this`, `arguments` и возможности использовать `new`. Разберём всё по порядку.

---

## Function Declaration vs Function Expression vs Arrow Function

### Function Declaration

```js
function greet(name) {
  return `Hello, ${name}!`;
}
```

Объявляется ключевым словом `function` в начале statement. Главная особенность - **hoisting**: функция доступна до строки объявления, потому что на фазе создания контекста она целиком помещается в memory.

```js
console.log(sum(2, 3)); // 5 - работает до объявления

function sum(a, b) {
  return a + b;
}
```

### Function Expression

```js
const greet = function (name) {
  return `Hello, ${name}!`;
};
```

Функция создаётся как часть выражения и присваивается переменной. **Hoisting не работает** для значения - переменная поднимается, но до строки присваивания содержит `undefined` (var) или находится в TDZ (let/const).

```js
console.log(greet); // ReferenceError (const в TDZ)

const greet = function (name) {
  return `Hello, ${name}!`;
};
```

<b class="text-on-semi-light">Named Function Expression:</b> `const f = function myFunc() {}` - имя `myFunc` доступно **только внутри** самой функции. Полезно для рекурсии и стектрейсов.

### Arrow Function

```js
const greet = (name) => `Hello, ${name}!`;
```

Короткий синтаксис, введённый в ES6. Но дело не только в синтаксисе - arrow functions **принципиально отличаются** от обычных.

### Таблица различий

| Особенность        | Declaration           | Expression            | Arrow                        |
| ------------------ | --------------------- | --------------------- | ---------------------------- |
| Hoisting           | Да (целиком)          | Нет                   | Нет                          |
| `this`             | Динамический          | Динамический          | Лексический (от родителя)    |
| `arguments`        | Есть                  | Есть                  | Нет                          |
| `new`              | Можно                 | Можно                 | Нельзя (TypeError)           |
| `prototype`        | Есть                  | Есть                  | Нет                          |
| Implicit return    | Нет                   | Нет                   | Да (без `{}`)                |

<b class="text-on-semi-light">Когда что использовать:</b> Arrow - для коротких callback'ов, где не нужен свой `this`. Declaration - для «основных» функций, которые должны быть доступны в любом месте модуля. Expression - когда нужно условное объявление или named function expression для рекурсии.

## Параметры функций

### Default values

```js
function createUser(name, role = 'viewer') {
  return { name, role };
}

createUser('Alice');           // { name: 'Alice', role: 'viewer' }
createUser('Bob', 'admin');    // { name: 'Bob', role: 'admin' }
createUser('Eve', undefined);  // { name: 'Eve', role: 'viewer' } - undefined тоже триггерит default
```

<span class="text-gray">Default value вычисляется **при каждом вызове**, а не один раз. Это значит, что можно безопасно использовать объекты и вызовы функций как default values - каждый вызов получит свежую копию.</span>

### Rest parameters (...args)

```js
function sum(...numbers) {
  return numbers.reduce((acc, n) => acc + n, 0);
}

sum(1, 2, 3, 4); // 10
```

Rest parameter - это **настоящий массив** (в отличие от `arguments`). Он должен быть **последним** в списке параметров.

```js
function log(level, ...messages) {
  messages.forEach((msg) => console.log(`[${level}]`, msg));
}

log('ERROR', 'DB timeout', 'Retry failed');
// [ERROR] DB timeout
// [ERROR] Retry failed
```

### Destructuring в параметрах

```js
function renderCard({ title, description, tags = [] }) {
  console.log(title, description, tags);
}

renderCard({ title: 'JS', description: 'Функции' });
// 'JS' 'Функции' []
```

Особенно полезно для функций с множеством опциональных параметров - не нужно помнить порядок аргументов.

```js
// Вместо этого:
function setup(host, port, secure, timeout) { /* ... */ }

// Лучше так:
function setup({ host, port = 3000, secure = false, timeout = 5000 } = {}) { /* ... */ }
```

<span class="text-gray">`= {}` в конце - защита от вызова без аргументов. Без этого `setup()` выбросит TypeError, потому что попытается деструктурировать `undefined`.</span>

## Объект arguments

```js
function showArgs() {
  console.log(arguments);        // { '0': 'a', '1': 'b', '2': 'c' }
  console.log(arguments.length); // 3
  console.log(arguments[0]);     // 'a'
}

showArgs('a', 'b', 'c');
```

`arguments` - array-like объект (имеет `length` и числовые индексы, но **не имеет** методов массива: `map`, `filter`, `forEach`).

```js
function toArray() {
  // Три способа конвертировать в массив:
  return Array.from(arguments);
  // или: return [...arguments];
  // или: return Array.prototype.slice.call(arguments);
}
```

⚠️ **Arrow functions не имеют `arguments`:**

```js
const fn = () => {
  console.log(arguments); // ReferenceError (или arguments из внешней функции)
};
```

<b class="text-on-semi-light">На практике:</b> Используй rest parameters (`...args`) вместо `arguments`. Это настоящий массив, работает в arrow functions и делает код понятнее.

## Return value

### Explicit return

```js
function multiply(a, b) {
  return a * b; // явный возврат
}
```

### Implicit return (только arrow functions)

```js
const double = (n) => n * 2;           // без {} - implicit return
const getObj = () => ({ key: 'value' }); // объект нужно обернуть в ()
```

### Без return

```js
function logMessage(msg) {
  console.log(msg);
  // return undefined; - неявно
}

const result = logMessage('hi'); // undefined
```

<span class="text-gray">Если функция ничего не возвращает, она возвращает `undefined`. Оператор `void` явно подавляет возвращаемое значение: `void someFunction()` всегда вернёт `undefined`. Часто встречается в `void 0` как надёжный способ получить `undefined`.</span>

## IIFE - Immediately Invoked Function Expression

IIFE - это функция, которая вызывается сразу после объявления.

```js
(function () {
  const secret = 'hidden';
  console.log(secret); // 'hidden'
})();

// secret недоступен снаружи
```

### Зачем нужен IIFE

1. **Изоляция scope** - переменные внутри IIFE не загрязняют глобальную область
2. **Module pattern** (до ES-модулей) - создание приватных переменных
3. **Выполнение async кода** на верхнем уровне (до top-level await)

```js
// Module pattern через IIFE
const counter = (function () {
  let count = 0;
  return {
    increment: () => ++count,
    getCount: () => count,
  };
})();

counter.increment();
counter.getCount(); // 1
// count недоступен напрямую
```

### Варианты синтаксиса

```js
(function () { /* ... */ })();  // классический
(function () { /* ... */ }());  // альтернативный (Douglas Crockford)
(() => { /* ... */ })();        // arrow IIFE
```

<b class="text-on-semi-light">Актуальность:</b> С приходом ES-модулей (`import`/`export`) IIFE для изоляции scope стал менее нужен - каждый модуль и так имеет свой scope. Но IIFE по-прежнему полезен в legacy-коде, inline-скриптах и как паттерн для немедленного выполнения.

## First-class functions

В JavaScript функции - это **значения**. Их можно присваивать переменным, передавать как аргументы и возвращать из других функций.

```js
// 1. Присвоить переменной
const sayHi = function () {
  return 'Hi!';
};

// 2. Передать как аргумент
function execute(fn) {
  return fn();
}
execute(sayHi); // 'Hi!'

// 3. Вернуть из функции
function createGreeter(greeting) {
  return function (name) {
    return `${greeting}, ${name}!`;
  };
}

const helloGreeter = createGreeter('Hello');
helloGreeter('Alice'); // 'Hello, Alice!'

// 4. Хранить в структурах данных
const strategies = {
  add: (a, b) => a + b,
  sub: (a, b) => a - b,
};
strategies.add(5, 3); // 8
```

<span class="text-gray">Это фундаментальное свойство языка, которое делает возможным функциональное программирование, callback-паттерны, middleware-цепочки и Higher-Order Functions.</span>

## Higher-Order Functions

Higher-Order Function (функция высшего порядка) - это функция, которая **принимает функцию как аргумент** и/или **возвращает функцию**.

### map, filter, reduce - классические примеры

```js
const numbers = [1, 2, 3, 4, 5];

// map: трансформация каждого элемента
const doubled = numbers.map((n) => n * 2);
// [2, 4, 6, 8, 10]

// filter: отбор по условию
const even = numbers.filter((n) => n % 2 === 0);
// [2, 4]

// reduce: свёртка в одно значение
const sum = numbers.reduce((acc, n) => acc + n, 0);
// 15
```

### Написать свой HOF

```js
// Функция, которая создаёт фильтр по минимальному значению
function createMinFilter(min) {
  return (value) => value >= min;
}

const isAdult = createMinFilter(18);
[12, 18, 25, 8].filter(isAdult); // [18, 25]
```

### Цепочки (chaining)

```js
const result = users
  .filter((u) => u.isActive)
  .map((u) => u.name)
  .sort((a, b) => a.localeCompare(b));
```

<b class="text-on-semi-light">На практике:</b> HOF - основа работы с данными в JS. React-компоненты, Express middleware, Redux reducers - всё это Higher-Order Functions.

## Рекурсия

Рекурсия - когда функция вызывает **саму себя** до достижения **базового условия** (base case).

```js
function factorial(n) {
  if (n <= 1) return 1;  // base case
  return n * factorial(n - 1); // recursive case
}

factorial(5); // 120 (5 * 4 * 3 * 2 * 1)
```

### Обход дерева - типичный кейс

```js
function getTextContent(node) {
  if (node.type === 'text') return node.value;
  return node.children.map(getTextContent).join('');
}

const tree = {
  type: 'div',
  children: [
    { type: 'text', value: 'Hello ' },
    {
      type: 'span',
      children: [{ type: 'text', value: 'world' }],
    },
  ],
};

getTextContent(tree); // 'Hello world'
```

### Tail Call Optimization (TCO)

TCO позволяет оптимизировать рекурсивные вызовы, если recursive call - **последняя операция** в функции (tail position).

```js
// Tail-recursive версия factorial
function factorial(n, acc = 1) {
  if (n <= 1) return acc;
  return factorial(n - 1, n * acc); // tail call
}
```

⚠️ **Реальность:** TCO описана в спецификации ES2015, но на практике поддерживается **только в Safari** (JavaScriptCore). V8 (Chrome, Node.js) и SpiderMonkey (Firefox) её не реализовали. Для глубокой рекурсии используй итеративные решения или trampolining.

## Generator functions

Generator - это функция, которая может **приостанавливать** и **возобновлять** своё выполнение.

```js
function* idGenerator() {
  let id = 0;
  while (true) {
    yield ++id;
  }
}

const gen = idGenerator();
gen.next(); // { value: 1, done: false }
gen.next(); // { value: 2, done: false }
gen.next(); // { value: 3, done: false }
```

<span class="text-gray">Generators используют `function*` синтаксис и `yield` для паузы. Они возвращают iterator и могут быть использованы в `for...of`. Подробнее -> тема iterators and generators.</span>

## Async-функции

Async-функции - отдельный тип, объявленный через `async`. Всегда возвращают Promise, даже если внутри нет `await`.

```js
async function fetchUser() {
  const res = await fetch('/api/user');
  return res.json(); // Обернётся в Promise автоматически
}

// Async arrow function
const getUser = async () => {
  const res = await fetch('/api/user');
  return res.json();
};

// Async method
class Api {
  async get(url) {
    const res = await fetch(url);
    return res.json();
  }
}
```

> Подробнее о Promises и async/await -> [Асинхронность](/content/javascript/async)

## Конструктор Function

Создание функции из строки. Используется крайне редко.

```js
const sum = new Function('a', 'b', 'return a + b');
console.log(sum(2, 3)); // 5
```

- Не имеет доступа к локальным переменным (только global scope)
- Низкая производительность (парсинг строки в runtime)
- Потенциальная уязвимость (аналог eval)
- На практике почти не используется

## Сравнение всех типов функций

| Тип | Hoisting | this | new | arguments | Использование |
|-----|----------|------|-----|-----------|--------------|
| Function Declaration | Да | Динамический | Да | Да | Основные функции |
| Function Expression | Нет | Динамический | Да | Да | Передача как значение |
| Arrow Function | Нет | Лексический | Нет | Нет | Колбэки, короткие функции |
| IIFE | Нет | Динамический | Да | Да | Изоляция scope |
| Async Function | Нет | Динамический | Нет | Да | Асинхронные операции |
| new Function() | Нет | Глобальный | Да | Да | Динамический код (редко) |

## Arrow vs обычная функция

| Отличие | Arrow (`=>`) | Обычная (`function`) |
|---------|-------------|---------------------|
| `this` | Лексический (из внешнего scope) | Динамический (зависит от вызова) |
| `arguments` | Нет (используй `...args`) | Да |
| `new` | Нельзя | Можно |
| `call/apply/bind` | Не меняют `this` | Меняют `this` |
| Генераторы | Не поддерживает `function*` | Поддерживает |
| `prototype` | Нет свойства `prototype` | Есть |

## Частые вопросы на собесе

**В чём разница между Function Declaration и Function Expression?**
Declaration поднимается (hoisting) целиком - можно вызвать до строки объявления. Expression присваивается переменной и доступна только после строки присваивания. Arrow function - это expression с лексическим `this` и без `arguments`.

**Что такое arrow function и чем она отличается от обычной?**
Arrow function не имеет собственного `this` (берёт из лексического окружения), не имеет `arguments`, не может быть вызвана с `new`, не имеет `prototype`. Идеальна для callback'ов, где нужен `this` родительского scope.

**Что такое IIFE и зачем он нужен?**
Immediately Invoked Function Expression - функция, которая вызывается сразу после создания. Используется для изоляции scope: переменные внутри не утекают наружу. До ES-модулей это был основной способ создания приватных переменных (module pattern).

**Чем rest parameters отличаются от arguments?**
`...args` - настоящий массив, работает в arrow functions, может быть не единственным параметром (но должен быть последним). `arguments` - array-like объект, доступен только в обычных функциях, содержит все переданные аргументы.

**Что такое Higher-Order Function?**
Функция, которая принимает другую функцию как аргумент или возвращает функцию. `map`, `filter`, `reduce` - классические примеры. HOF - основа функционального стиля в JS.

**Как работает рекурсия и когда её использовать?**
Функция вызывает саму себя до достижения базового условия. Удобна для обхода деревьев, вложенных структур, задач divide-and-conquer. Важно следить за глубиной вызовов - стек ограничен (~10 000 фреймов).
