# Визуальные эффекты

Что CSS рисует поверх раскладки: фоны и градиенты, картинки в боксе, тени, прозрачность, фильтры, обрезку, маски и смешение цветов. Спрашивают, чем `box-shadow` отличается от `drop-shadow`, чем `opacity` отличается от прозрачного фона, как сделать градиентный текст и зачем `object-fit`. Глубже — почему середина градиента от синего к жёлтому серая, почему стеклянная шапка ломает выпадающее меню и почему тень карточки обрезана.

::tldr
- **Фон — стопка слоёв:** первый в списке рисуется сверху, цвет — всегда под всеми. Картинку в `img` подгоняют под бокс через `object-fit`: `cover` заполняет и обрезает, `contain` вписывает с полями.
- **Градиент между обычными цветами интерполируется в sRGB,** и середина синего и жёлтого получается серой. `linear-gradient(in oklch, …)` даёт яркую середину, а переход к `transparent` браузер делает без серой грязи.
- **`box-shadow` рисуется по прямоугольнику бокса и не занимает места,** `filter: drop-shadow()` — по контуру непрозрачных пикселей. Тень обрезает `overflow: hidden` родителя.
- **`opacity` гасит элемент вместе с детьми,** прозрачный цвет — только фон. `opacity`, `filter`, `backdrop-filter`, `mask`, `clip-path` и `mix-blend-mode` создают контекст наложения, а `filter` и `backdrop-filter` ещё и становятся containing block для `fixed`-потомков.
- **`clip-path` обрезает и рисование, и область кликов, но не раскладку.** `aspect-ratio` вычисляет высоту из ширины, а содержимое может её превысить, пока не задан `min-height: 0`.
::

## Фон

Сквозной пример — карточка товара: фото чая, градиентная подложка с бейджем «−20%», тень, стеклянная шапка магазина над каталогом и длинное описание, которое плавно гаснет к низу.

```css
.hero {
  background:
    linear-gradient(rgb(0 0 0 / 0.5), rgb(0 0 0 / 0.7)),
    url("tea.jpg") center / cover no-repeat,
    #1a1a1a;
}
```

`background` — стопка слоёв через запятую. **Первый слой рисуется сверху**, а цвет может стоять только последним и всегда лежит под всеми картинками. В проверке слой-градиент на левой половине оказался поверх синего цвета фона. Так кладут затемнение поверх фото, чтобы текст на нём читался.

| Свойство | Что задаёт |
| --- | --- |
| `background-size` | `cover` — заполнить бокс, обрезав лишнее; `contain` — вписать целиком, оставив поля |
| `background-position` | точку привязки: `center`, `right 10px bottom 10px` |
| `background-repeat` | повтор: `no-repeat`, `repeat-x`, `space`, `round` |
| `background-clip` | докуда рисовать: `border-box`, `padding-box`, `content-box`, `text` |
| `background-origin` | от какого края отсчитывать позицию |

## Картинки в боксе

Фото товаров приходят разных пропорций, а карточки в сетке одинаковые. По умолчанию `img` с заданными шириной и высотой **растягивается** — `object-fit: fill`. `object-fit` работает для `img` и `video` так же, как `background-size` для фона:

| `object-fit` | Что происходит |
| --- | --- |
| `fill` | растянуть до бокса, пропорции ломаются |
| `cover` | заполнить бокс, лишнее обрезать |
| `contain` | вписать целиком, по краям поля |
| `none` | исходный размер, обрезать по боксу |
| `scale-down` | как `none` или `contain` — что меньше |

В проверке картинку из трёх полос 300×100 поставили в квадрат 100×100. `fill` сжал все три полосы, `cover` показал только среднюю, зелёную, а `contain` вписал картинку полосой по центру с белыми полями сверху и снизу. Какая часть видна при `cover`, задаёт `object-position: top` или `object-position: 30% 50%`.

### aspect-ratio

Чтобы место под картинку было зарезервировано до её загрузки, у бокса должна быть высота. Раньше пропорцию делали трюком `padding-top: 56.25%` — процент `padding` считается от ширины (подробно — в [Каскаде](/content/css/styling)). Сейчас есть свойство:

```css
.video { width: 100%; aspect-ratio: 16 / 9; }
```

Блок шириной 320px в проверке получил высоту 180px. Атрибуты `width` и `height` у `img` браузер тоже переводит в `aspect-ratio`, и это главный способ убрать сдвиг макета от картинок (подробно — в [Core Web Vitals](/content/security-perfomance/core-web-vitals)).

Ловушка: `aspect-ratio` — это предпочтение, а не жёсткий размер. У блока остаётся `min-height: auto`, и содержимое выше пропорции его растягивает: в проверке блок 16:9 с содержимым высотой 400px стал высотой 400px. С `min-height: 0` и `overflow: auto` он остался 180px, а содержимое получило прокрутку.

## Градиенты

Градиент — картинка, которую рисует браузер, поэтому он задаётся в `background-image`, а не в `background-color`.

```css
background: linear-gradient(135deg, #e94560, #0f3460);               /* линейный */
background: radial-gradient(circle at top left, #0f3460, transparent); /* радиальный */
background: conic-gradient(#e94560 0 40%, #0f3460 0 70%, #ccc 0);    /* круговой: диаграмма */
background: repeating-linear-gradient(45deg, #eee 0 10px, #fff 0 20px); /* полосы */
```

Две точки остановки в одном месте дают **жёсткую границу**: `linear-gradient(to right, red 50%, blue 50%)` в проверке был красным за два пикселя до середины и синим через два после. На этом строят полосы, шахматку, круговые диаграммы.

### Пространство интерполяции

Промежуточные цвета браузер считает в каком-то цветовом пространстве. Для градиента из обычных цветов — `#hex`, `rgb()`, именованных — это sRGB, как было всегда. В sRGB середина между синим и жёлтым — это среднее каналов: (128, 128, 128), серый. В проверке именно так. Пространство можно указать:

```css
background: linear-gradient(in oklch to right, blue, yellow);
```

С `in oklch` середина в проверке получилась яркой — разница между каналами больше 60. В OKLCH интерполируются светлота, насыщенность и тон, поэтому промежуточные цвета не теряют насыщенности (подробно о цветовых пространствах — в [Современном CSS](/content/css/modern-css)).

Старая страшилка про `transparent` устарела. `transparent` — это прозрачный чёрный, и раньше градиент «красный → прозрачный» серел в середине. Сейчас браузеры интерполируют с учётом прозрачности: середина такого градиента на белом в проверке — розовая (255, 128, 128), то есть полупрозрачный красный, а не грязная (191, 128, 128).

## Тени

```css
/* смещение x | смещение y | размытие | растяжение | цвет */
box-shadow: 0 4px 12px 0 rgb(0 0 0 / 0.1);

/* несколько слоёв — мягкая и плотная тень */
box-shadow: 0 1px 2px rgb(0 0 0 / 0.06), 0 8px 24px rgb(0 0 0 / 0.12);

/* внутренняя */
box-shadow: inset 0 2px 4px rgb(0 0 0 / 0.2);
```

Тень не участвует в раскладке: в проверке карточка с тенью 20px вниз не сдвинула соседа — он начался ровно там, где кончился бокс карточки.

### box-shadow и drop-shadow

| | `box-shadow` | `filter: drop-shadow()` |
| --- | --- | --- |
| форма | прямоугольник бокса с учётом `border-radius` | контур непрозрачных пикселей |
| PNG и SVG с прозрачностью | квадратная тень вокруг картинки | тень по форме картинки |
| `spread` и `inset` | есть | нет |
| побочные эффекты | нет | создаёт контекст наложения и containing block |

В проверке круглая иконка на прозрачном фоне с `box-shadow` получила тень с квадратным углом, а с `drop-shadow` угол остался пустым — тень повторила круг. Для карточек — `box-shadow`, для иконок и фигурных картинок — `drop-shadow`.

### Тень обрезана

Тень рисуется за пределами бокса и подчиняется `overflow` родителя. Карусель товаров с `overflow: hidden`, высота которой ровно по карточкам, срезает их тени — в проверке тень под карточкой исчезла, когда родитель был той же высоты. Варианты: дать родителю `padding` под тень или заменить `overflow: hidden` на `overflow: clip` с `overflow-clip-margin` — тогда обрезка начинается на заданном расстоянии от края.

Анимация большой размытой тени — например, при наведении — перерисовывает её на каждом кадре. Дешевле нарисовать тень на псевдоэлементе и анимировать его `opacity` (подробно — в [Производительности выполнения](/content/security-perfomance/runtime-performance)).

## Прозрачность и фильтры

### opacity и прозрачный цвет

```css
.badge-a { opacity: 0.5; background: black; }
.badge-b { background: rgb(0 0 0 / 0.5); }
```

Фон у обоих одинаково серый. Но `opacity` применяется к элементу **целиком, вместе с детьми**: в проверке красная метка внутри `.badge-a` стала бледно-розовой, а внутри `.badge-b` осталась яркой. Если полупрозрачной должна быть только подложка, прозрачность задают в цвете, а не через `opacity`. Ещё `opacity` меньше 1 создаёт контекст наложения (подробно — в [Раскладке и потоке](/content/css/flow)).

### filter

`filter` обрабатывает уже нарисованный элемент: `blur()`, `brightness()`, `contrast()`, `grayscale()`, `saturate()`, `sepia()`, `hue-rotate()`, `invert()`, `opacity()`, `drop-shadow()`. Функции применяются по порядку слева направо. `grayscale(1)` в проверке сделал красный блок серым — все три канала равны. Типичное применение — неактивные карточки товаров, которых нет в наличии.

### backdrop-filter

`backdrop-filter` обрабатывает не сам элемент, а то, что **за ним**. Это «стекло»:

```css
.header { background: rgb(255 255 255 / 0.6); backdrop-filter: blur(12px) saturate(180%); }
```

В проверке резкая граница чёрного и белого под стеклом с `blur(10px)` превратилась в серый переход. Фон самого элемента должен быть полупрозрачным, иначе размытия не видно.

У обоих фильтров есть побочные эффекты:

- **контекст наложения** — `z-index` детей перестаёт выходить за элемент;
- **containing block для `fixed`** — выпадающее меню с `position: fixed` внутри стеклянной шапки позиционируется от шапки, а не от окна. В проверке такое меню встало на 300px — на верх шапки, а не окна;
- **цена** — размытие большой области пересчитывается при каждой прокрутке под ним, и на слабых телефонах прокрутка дёргается. Стекло делают на небольших элементах.

## Обрезка и маски

### clip-path

`clip-path` обрезает элемент по фигуре: `circle()`, `ellipse()`, `inset()` со скруглением, `polygon()`, `path()` или фигура из SVG.

```css
.badge { clip-path: polygon(0 0, 100% 0, 100% 75%, 50% 100%, 0 75%); } /* флажок */
.reveal { clip-path: inset(0 100% 0 0); transition: clip-path 0.6s; }
.reveal.visible { clip-path: inset(0); }
```

Срезанная часть **не рисуется и не ловит события**: в проверке клик в угол круглой кнопки с `clip-path: circle(50%)` попал в элемент под ней. Раскладку `clip-path` не меняет — бокс остаётся квадратным 100×100, и соседи стоят как раньше. Фигуры с одинаковым числом точек анимируются переходом.

### mask

Маска задаёт прозрачность по картинке или градиенту: где маска непрозрачна, элемент виден, где прозрачна — нет, между ними — частично.

```css
.description { mask-image: linear-gradient(to bottom, black 50%, transparent); }
```

Длинное описание товара в проверке было полностью видно в верхней половине, серым на трёх четвертях высоты и почти исчезло у нижнего края. В отличие от `clip-path`, маска даёт плавные переходы, но на клики не влияет: в проверке клик в невидимую по маске половину блока всё равно попал в него. Маской же красят иконки из SVG-файла в `currentColor`: `background: currentColor; mask: url(icon.svg) center / contain no-repeat`.

| | `overflow: hidden` | `clip-path` | `mask` |
| --- | --- | --- | --- |
| граница | бокс с `border-radius` | любая фигура | любая картинка или градиент |
| плавный край | нет | нет | да |
| клики снаружи | не ловит | не ловит | ловит по боксу |

## Смешение цветов

`mix-blend-mode` смешивает элемент с тем, что под ним, как режимы слоёв в графическом редакторе:

| Режим | Результат |
| --- | --- |
| `multiply` | умножение: темнее обоих, белый прозрачен |
| `screen` | обратное умножение: светлее обоих, чёрный прозрачен |
| `overlay` | контраст: `multiply` на тёмном, `screen` на светлом |
| `difference` | разность: текст виден на любом фоне |
| `color`, `luminosity` | перенос тона или яркости |

В проверке красный блок с `multiply` на синем фоне стал чёрным: (255, 0, 0) × (0, 0, 255) = (0, 0, 0). Элемент смешивается со всем, что под ним, вплоть до фона страницы. Ограничить смешение группой можно через `isolation: isolate`: тот же красный блок внутри изолированной белой группы на синей странице остался красным — он смешался только с белым. `background-blend-mode` смешивает слои фона одного элемента между собой.

### Градиентный текст

```css
.sale {
  background: linear-gradient(135deg, #e94560, #0f3460);
  background-clip: text;
  color: transparent;
}
```

`background-clip: text` обрезает фон по буквам, а прозрачный цвет текста открывает его. В проверке в боксе заголовка были красные пиксели и ни одного чёрного. Для старых браузеров рядом пишут `-webkit-background-clip: text`. Текст остаётся текстом: его можно выделить, а программы чтения с экрана его читают.

## Красные флаги в ответе

- **«`box-shadow` подойдёт для любой иконки».** У картинки с прозрачностью тень будет квадратной; по контуру — `drop-shadow`.
- **«`opacity: 0.5` — это полупрозрачный фон».** Гаснет и текст, и всё внутри; для подложки прозрачность задают в цвете.
- **«Градиент к `transparent` всегда серый».** Браузеры интерполируют с учётом прозрачности; а серая середина синего и жёлтого лечится `in oklch`.
- **«`backdrop-filter` — просто красивый эффект».** Он создаёт контекст наложения, меняет containing block для `fixed` и стоит дорого на большой площади.
- **«`clip-path` скрывает часть элемента, но кликать по ней можно».** Срезанная область не получает событий.
- **«`aspect-ratio` гарантирует высоту».** Содержимое растягивает блок, пока не задан `min-height: 0`.

## Как спрашивают на собеседовании

::question
Чем box-shadow отличается от filter: drop-shadow()?

#answer
`box-shadow` рисует тень по прямоугольнику бокса с учётом `border-radius`, поддерживает `spread`, `inset` и несколько слоёв. `drop-shadow()` рисует тень по контуру непрозрачных пикселей — у PNG и SVG с прозрачностью она повторяет форму.

#more
`drop-shadow()` — фильтр, поэтому создаёт контекст наложения и containing block для `fixed`-потомков. Обе тени не занимают места в раскладке и обрезаются `overflow: hidden` родителя. Для карточек — `box-shadow`, для иконок — `drop-shadow`.
::

::question
Чем opacity отличается от прозрачного цвета фона?

#answer
`opacity` делает полупрозрачным весь элемент вместе с текстом, иконками и детьми. Цвет с альфой — `rgb(0 0 0 / 0.5)` — делает прозрачным только фон, а содержимое остаётся непрозрачным.

#more
Ребёнок не может вернуть себе полную непрозрачность внутри родителя с `opacity: 0.5`. `opacity` меньше 1 создаёт контекст наложения, а `opacity: 0` оставляет элемент кликабельным и видимым для программ чтения с экрана.
::

::question
Почему середина градиента выглядит серой и грязной?

#answer
Градиент из обычных цветов интерполируется в sRGB: каждый канал усредняется, и между синим и жёлтым получается серый. В CSS можно указать пространство: `linear-gradient(in oklch, blue, yellow)` сохраняет насыщенность в середине.

#more
OKLCH интерполирует светлоту, насыщенность и тон, `in oklch longer hue` идёт по кругу через радугу. Серость градиента к `transparent` — старая проблема: современные браузеры интерполируют с учётом прозрачности, и середина «красный → прозрачный» остаётся полупрозрачным красным.
::

::question
Чем object-fit: cover отличается от contain? Зачем aspect-ratio?

#answer
`cover` заполняет бокс целиком, сохраняя пропорции и обрезая лишнее, `contain` вписывает картинку целиком с полями. По умолчанию `fill` растягивает, ломая пропорции. `aspect-ratio` задаёт пропорцию бокса и вычисляет высоту из ширины.

#more
Видимую часть при `cover` выбирает `object-position`. `aspect-ratio` и атрибуты `width` и `height` у `img` резервируют место до загрузки и убирают сдвиг макета. Высота из `aspect-ratio` — предпочтение: содержимое выше растягивает блок, пока не задан `min-height: 0`.
::

::question
Какие побочные эффекты у filter и backdrop-filter?

#answer
Оба создают контекст наложения и становятся containing block для потомков с `position: fixed`: меню внутри стеклянной шапки позиционируется от шапки, а не от окна. `backdrop-filter` на большой площади дорог — размытие пересчитывается при каждой прокрутке под ним.

#more
Стекло ставят на псевдоэлемент `::before` за содержимым — тогда сама шапка containing block не становится. Таким же эффектом обладают `transform`, `perspective`, `will-change` с ними и `contain: paint`. Для фона за стеклом нужен полупрозрачный цвет, иначе размытия не видно.
::

::question
Чем отличаются overflow: hidden, clip-path и mask?

#answer
`overflow: hidden` обрезает по боксу с учётом `border-radius`. `clip-path` — по любой фигуре: кругу, многоугольнику, пути. `mask` — по картинке или градиенту и даёт плавные края. `clip-path` и `overflow` убирают и рисование, и события в обрезанной области.

#more
`clip-path` не меняет раскладку и анимируется переходом между фигурами с одинаковым числом точек. Маской из SVG красят иконки в `currentColor`. `overflow: hidden` ещё создаёт контейнер прокрутки и BFC, а `overflow: clip` — нет.
::

::question
Как работает mix-blend-mode и зачем isolation?

#answer
`mix-blend-mode` смешивает цвета элемента с тем, что нарисовано под ним: `multiply` затемняет, `screen` осветляет, `difference` вычитает. Элемент смешивается со всем стеком под собой, вплоть до фона страницы.

#more
`isolation: isolate` создаёт группу смешения: элемент смешивается только с содержимым группы. `background-blend-mode` смешивает слои фона одного элемента — например, цвет и фото для эффекта дуотона. `mix-blend-mode` со значением кроме `normal` создаёт контекст наложения.
::

## Практика

::practice{title="Меню выпадает не туда"}
Шапку магазина сделали стеклянной, и выпадающее меню профиля с `position: fixed` теперь прилипает к шапке и уезжает с ней:

```css
.header { position: sticky; top: 0; backdrop-filter: blur(12px); background: rgb(255 255 255 / 0.6); }
.profile-menu { position: fixed; top: 64px; right: 16px; }
```

#solution
`backdrop-filter` делает шапку containing block для `fixed`-потомков: меню отсчитывается от неё, а не от окна. Стекло переносят на псевдоэлемент — у самой шапки фильтра больше нет:

```css
.header { position: sticky; top: 0; }
.header::before {
  content: ""; position: absolute; inset: 0; z-index: -1;
  backdrop-filter: blur(12px); background: rgb(255 255 255 / 0.6);
}
```

В проверке в Chromium меню внутри шапки с `backdrop-filter` встало на 300px — у верха шапки, — а с фильтром на `::before` — на 0, у верха окна. Ещё надёжнее вынести меню из шапки в верхний слой через Popover API.
::

::practice{title="Тени карточек срезаны"}
В карусели товаров у карточек пропала нижняя тень:

```css
.carousel { display: flex; overflow: hidden; }
.card { box-shadow: 0 8px 24px rgb(0 0 0 / 0.12); }
```

#solution
Тень рисуется за пределами бокса карточки, а `overflow: hidden` у карусели обрезает всё, что выходит за её край. Если прокрутка в карусели не нужна, её заменяют на `clip` с запасом:

```css
.carousel { display: flex; overflow: clip; overflow-clip-margin: 24px; }
```

В проверке тень, срезанная родителем той же высоты, вернулась с `overflow-clip-margin: 20px`. Если карусель прокручивается, запас дают отступом: `padding-block: 24px` у контейнера и обратный `margin` снаружи.
::

::practice{title="Плашка бледнеет вместе с текстом"}
Бейдж «Хит продаж» поверх фото должен быть на полупрозрачной подложке, но бледным стал и текст:

```css
.badge { background: black; color: white; opacity: 0.6; }
```

#solution
`opacity` применяется к элементу целиком, вместе с текстом. Прозрачность нужна только подложке — её задают в цвете:

```css
.badge { background: rgb(0 0 0 / 0.6); color: white; }
```

В проверке красная метка внутри элемента с `opacity: 0.5` стала бледно-розовой, а внутри элемента с фоном `rgb(0 0 0 / 0.5)` осталась ярко-красной, хотя серый фон у обоих одинаковый. Для читаемости на пёстром фото добавляют `backdrop-filter: blur()` на саму плашку или затемняющий градиент слоем фона.
::
