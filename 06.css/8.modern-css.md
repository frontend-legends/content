# Современный CSS

Возможности, которые закрыли почти все причины брать препроцессор или писать JavaScript для стилей: CSS-переменные и `@property`, вложенность, новые цветовые функции и темы, якорное позиционирование, стилизация форм. Спрашивают, чем CSS-переменные отличаются от переменных Sass, что даёт `@property`, как работает нативная вложенность и зачем `oklch`. Глубже — почему опечатка в имени переменной сбрасывает цвет к родительскому, почему вложенное правило оказывается сильнее модификатора и почему `light-dark()` не переключает тему.

::tldr
- **CSS-переменные — свойства, которые наследуются и подставляются при вычислении значения.** Их можно менять из JavaScript, медиазапросом и в поддереве. Если после подстановки значение недопустимо, свойство становится `unset` — предыдущее объявление его не спасает.
- **`@property` даёт переменной тип, начальное значение и управление наследованием.** Зарегистрированную переменную можно анимировать, а `em` в ней вычисляется там, где её задали, а не там, где используют.
- **Нативная вложенность разворачивается через `:is()`:** если в списке родителей есть `#id`, специфичность id получают все вложенные правила. Склейка `&__title` из Sass в CSS не работает.
- **`oklch()` описывает цвет светлотой, насыщенностью и тоном так, как их видит глаз.** `color-mix()` и относительный синтаксис `oklch(from …)` строят палитру из одного цвета, а `light-dark()` выбирает цвет темы — только если задан `color-scheme`.
- **Якорное позиционирование привязывает подсказку к кнопке без JavaScript** и само переворачивает её, если не хватает места. `accent-color`, `field-sizing: content` и `appearance: base-select` закрывают частые задачи форм.
::

## CSS-переменные

Сквозной пример — тема интернет-магазина: фирменный акцент, тёмная тема, раздел распродажи со своим цветом, карточка товара, подсказка у кнопки «В корзину» и форма заказа.

```css
:root { --accent: oklch(0.6 0.2 15); --radius: 8px; }
.sale { --accent: oklch(0.55 0.25 25); }

.button { background: var(--accent); border-radius: var(--radius); }
.price  { color: var(--price-color, var(--text)); }
```

CSS-переменная — официально **custom property** — это обычное свойство с именем на `--`. Поэтому она подчиняется каскаду и **наследуется** по DOM: кнопка внутри `.sale` получила красный акцент раздела, остальные — общий. Второй аргумент `var()` — запасное значение, если переменная не задана.

Переменную меняют откуда угодно: медиазапросом, `:hover`, атрибутом `style` и из JavaScript:

```js
document.documentElement.style.setProperty('--accent', 'rgb(0 128 0)');
getComputedStyle(el).getPropertyValue('--accent');
```

В проверке одно присваивание на `html` перекрасило все кнопки, которые не переопределяют переменную. Так строят темы, брендирование под разные продукты и динамические значения — например, ширину полосы рейтинга из данных одним классом на все строки. Переменные наследуются и внутрь Shadow DOM: веб-компонент рейтинга в проверке взял цвет звезды из `--star`, заданной снаружи, — это основной способ темизировать веб-компоненты.

### Подстановка при вычислении

Браузер не проверяет `var()` при разборе CSS — он подставляет значение, когда вычисляет стиль элемента. Если результат недопустим для свойства, объявление уже победило в каскаде, и откатиться к предыдущему нельзя. Свойство становится **`unset`**:

```css
.card  { color: green; }
.price { --size: 20px; color: blue; color: var(--size); }
```

Цена в проверке стала зелёной — цветом родителя, а не синей. У ненаследуемого свойства `unset` даёт начальное значение: `background: var(--size)` сделал фон прозрачным, а не синим из строки выше. Так же ведёт себя ссылка на несуществующую переменную без запасного значения, поэтому опечатка в имени тихо сбрасывает стиль.

Второе следствие: значение переменной — последовательность токенов, а не строка, и склеить её с единицей нельзя. `width: var(--n)px` при `--n: 120` — это два токена, `120` и `px`, и ширина в проверке оказалась недопустимой. Единицу добавляют умножением: `calc(var(--n) * 1px)`.

### Переменные против переменных Sass

| | CSS-переменные | Переменные Sass |
| --- | --- | --- |
| когда работают | в браузере, при вычислении стиля | при сборке, в CSS остаётся число |
| наследование | по DOM | нет, только область видимости в файле |
| меняются из JavaScript и медиазапросом | да | нет |
| тип | без типа, пока не зарегистрирована | типизированы |
| в селекторах и именах медиазапросов | нельзя | можно |

Препроцессорные переменные остались полезны для того, что нужно до браузера: циклы, генерация классов, точки перелома в медиазапросах. Подробно о выборе инструментов — в [Стилизации](/content/ecosystem-libs/styling-solutions).

## @property

Незарегистрированная переменная для браузера — набор токенов без смысла. `@property` объявляет её тип:

```css
@property --angle {
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}
```

Что это даёт:

- **анимацию** — браузер знает, как интерполировать `<angle>`, `<color>`, `<length>`, `<number>`, `<percentage>`. Без регистрации переход между `0deg` и `180deg` — скачок (подробно — в [Анимациях](/content/css/animations));
- **проверку типа** — недопустимое значение заменяется начальным: `--brand: 20px` для переменной типа `<color>` в проверке дал `initial-value`, синий;
- **управление наследованием** — с `inherits: false` дети не получают значение родителя. В проверке ребёнок красного родителя взял синий `initial-value`. Так переменная, нужная только самому элементу, не протекает в потомков;
- **вычисление в момент объявления** — зарегистрированная `<length>` хранит пиксели. `--pad: 2em` у родителя с `font-size: 10px` в проверке превратилась в `20px`, и потомок с шрифтом 20px получил отступ 20px. Незарегистрированная переменная хранит `2em` как текст, и тот же потомок получил 40px — `em` посчитали от его шрифта.

Из JavaScript то же делает `CSS.registerProperty({ name: '--angle', syntax: '<angle>', inherits: false, initialValue: '0deg' })`.

## Вложенность

```css
.card {
  padding: 16px;

  &:hover { outline: 1px solid; }
  &.featured { border: 2px solid var(--accent); }
  .title { font-weight: 700; }
  p { margin: 0; }

  @media (width >= 600px) { padding: 24px; }
}
```

`&` — ссылка на родительский селектор. Он нужен, когда вложенный селектор приклеивается к родителю — `&:hover`, `&.featured`. Для потомков `&` не нужен: `.title` внутри `.card` — это `.card .title`. Селектор типа без `&` тоже работает — в проверке `p` внутри `.card` получил стиль. Медиазапросы и другие условные правила вкладываются прямо в правило.

Отличия от Sass, на которых ломается перенос кода:

- **`&` разворачивается через `:is()`.** `.catalog, #promo { .price { … } }` — это `:is(.catalog, #promo) .price`, и специфичность у него (1, 1, 0) даже для цен в `.catalog`. В проверке такое правило победило `.catalog .price.price.sale` с (0, 4, 0). Sass разворачивает в два отдельных селектора с разной специфичностью;
- **`&` нельзя склеить со строкой.** `&__title` в Sass даёт `.card__title`, а в CSS — это другой селектор, и элемент `.card__title` в проверке стиль не получил. Для БЭМ пишут полное имя класса.

Специфичность обычного вложенного правила — как у полного селектора, который оно заменяет; глубокая вложенность так же раздувает её, как длинная цепочка (подробно — в [Каскаде](/content/css/styling)).

## Цвета

`rgb()`, `hsl()` и `#hex` описывают цвет для экрана, а не для глаза. В :term[HSL]{def="запись цвета через тон, насыщенность и светлоту"} жёлтый `hsl(60 100% 50%)` и синий `hsl(240 100% 50%)` имеют одну «светлоту» 50%, но жёлтый выглядит намного светлее. В проверке относительный синтаксис перевёл оба в :term[OKLCH]{def="цветовое пространство, где светлота, насыщенность и тон соответствуют восприятию глаза"}: светлота жёлтого — 0,97, синего — 0,45.

`oklch(L C H)` — светлота от 0 до 1, насыщенность (chroma) и тон в градусах — построен так, чтобы одинаковая `L` выглядела одинаково светлой при любом тоне. Палитры, оттенки для наведения и контрастные пары в нём получаются предсказуемо. Ещё он умеет цвета за пределами sRGB — на экранах с широким охватом они ярче.

```css
:root { --brand: oklch(0.6 0.2 15); }

.button:hover { background: oklch(from var(--brand) calc(l + 0.1) c h); }  /* светлее на 0,1 */
.tag          { background: color-mix(in oklch, var(--brand) 15%, white); } /* бледная подложка */
.icon         { border: 2px solid currentColor; }                           /* цвет текста */
```

- **относительный синтаксис** `oklch(from цвет l c h)` разбирает цвет на компоненты и позволяет пересчитать любой: в проверке `calc(l + 0.1)` превратил `oklch(0.6 0.2 15)` в `oklch(0.7 0.2 15)`;
- **`color-mix(in пространство, a, b)`** смешивает два цвета в заданной пропорции: красный и синий пополам в sRGB дали `color(srgb 0.5 0 0.5)`;
- **`currentColor`** — текущее значение `color`; рамка и иконка в SVG с `fill: currentColor` перекрашиваются вместе с текстом.

Градиенты в этих пространствах — в [Визуальных эффектах](/content/css/visual-effects).

### Темы

```css
:root { color-scheme: light dark; }
body  { background: light-dark(white, #111); color: light-dark(#222, #eee); }
```

`color-scheme` говорит браузеру, какие темы поддерживает страница: он перекрашивает полосы прокрутки, поля ввода и другие встроенные элементы, а `light-dark(светлый, тёмный)` выбирает значение по теме. Без `color-scheme` функция всегда возвращает первый цвет: в проверке при тёмной системной теме элемент с `color-scheme: light dark` получил тёмный вариант, а без него — светлый.

Переключатель темы на сайте не трогает медиазапрос, а задаёт `color-scheme` на `html`: `light` или `dark` принудительно, `light dark` — по системе. Часть страницы, которая всегда светлая, получает свой `color-scheme: light`. Медиазапрос `prefers-color-scheme` остаётся для того, что не цвет, — например, другой картинки.

## Якорное позиционирование

Подсказка «Доставка завтра» над кнопкой «В корзину» раньше требовала библиотеку вроде :term[Floating UI]{def="библиотека для позиционирования всплывающих подсказок и меню"}: измерить кнопку, посчитать координаты, следить за прокруткой и переворачивать у края окна. Теперь это CSS:

```css
.buy { anchor-name: --buy; }

.tip {
  position: absolute;
  position-anchor: --buy;
  bottom: anchor(top);
  left: anchor(left);
  position-try-fallbacks: flip-block;
}
```

`anchor-name` объявляет якорь, `position-anchor` связывает с ним элемент, а функция `anchor()` подставляет координату края якоря. В проверке нижний край подсказки совпал с верхним краем кнопки, а левые края — между собой. `position-try-fallbacks: flip-block` переворачивает элемент, если он не помещается: у кнопки в самом верху окна подсказка встала под ней. Для простых случаев есть `position-area: top`.

С Popover API (`popover` и `popovertarget`) получается подсказка или меню целиком без JavaScript: popover попадает в верхний слой над всеми контекстами наложения (подробно — в [Раскладке и потоке](/content/css/flow)), а якорь ставит его рядом с кнопкой. Поддержку проверяют через `@supports (anchor-name: --a)` и для остальных браузеров оставляют простое позиционирование.

## Формы

Встроенные элементы форм рисует браузер, и стилизуются они по-разному:

| Элемент | Что можно |
| --- | --- |
| `input`, `textarea`, `button` | всё, как у обычных элементов |
| флажки, переключатели, ползунок, прогресс | цвет через `accent-color` или полностью свой вид через `appearance: none` |
| `input type="file"` | кнопку через `::file-selector-button` |
| `select` | закрытое поле; список — через `appearance: base-select` и `::picker(select)` там, где поддерживается |
| календарь и выбор цвета | почти ничего: это интерфейс браузера |

- **`accent-color`** — фирменный цвет флажков и ползунков одной строкой, с сохранением доступности встроенного элемента. В проверке `accent-color` флажка вычислился в заданный цвет;
- **`appearance: none`** снимает встроенный вид целиком — дальше это пустой бокс, и состояния `:checked`, `:focus-visible`, `:disabled` рисуют самостоятельно;
- **`field-sizing: content`** — поле растёт под текст. Комментарий к заказу с `min-height: 2lh` и `max-height: 6lh` в проверке был 40px пустым, 80px с четырьмя строками и упёрся в 120px на двенадцати, а обычный `textarea` остался 40px. Раньше это делали подсчётом высоты на JavaScript;
- **`appearance: base-select`** — настраиваемый `select`, у которого можно стилизовать список и пункты. В Chromium проверка подтвердила поддержку; в других браузерах он остаётся обычным `select`.

Псевдоклассы состояний форм — `:user-invalid`, `:checked`, `:placeholder-shown` — разобраны в [Селекторах](/content/css/css-rules).

Новые возможности CSS проверяют через `@supports` и вводят как улучшение: базовый вариант работает везде. Как следить за тем, что уже можно использовать, — в [Развитии платформы](/content/modern-dev/web-platform-evolution). Другие новые возможности живут в своих темах: `:has()` и `@scope` — в [Селекторах](/content/css/css-rules), container queries — в [Адаптивном дизайне](/content/css/rwd), `content-visibility` — в [Производительности выполнения](/content/security-perfomance/runtime-performance).

## Красные флаги в ответе

- **«CSS-переменные — то же, что переменные Sass».** Они живут в браузере, наследуются по DOM и меняются из JavaScript и медиазапросов; Sass подставляет значение при сборке.
- **«Если в `var()` попадёт ерунда, сработает предыдущее объявление».** Объявление уже победило, и свойство становится `unset`.
- **«`var(--n)px` даст пиксели».** Переменная — токены, а не строка; нужен `calc(var(--n) * 1px)`.
- **«Перенесу Sass с вложенностью как есть».** `&__title` не склеивается, а список с `#id` поднимает специфичность всех вложенных правил.
- **«`hsl` с одной светлотой — одинаково светлые цвета».** Жёлтый и синий с `L` 50% выглядят по-разному; ровные палитры строят в `oklch`.
- **«`light-dark()` сам следит за темой».** Без `color-scheme` он всегда возвращает светлый вариант.

## Как спрашивают на собеседовании

::question
Чем CSS-переменные отличаются от переменных Sass?

#answer
CSS-переменные — свойства, которые живут в браузере: наследуются по DOM, переопределяются в поддереве, меняются из JavaScript, медиазапросом и `:hover`. Переменные Sass подставляются при сборке, и в итоговом CSS остаются только числа.

#more
Поэтому темы, брендирование и значения из данных делают на CSS-переменных, а циклы, генерацию классов и точки перелома в медиазапросах — на Sass: переменные нельзя использовать в селекторах и условиях медиазапросов. CSS-переменные проникают в Shadow DOM и служат для темизации веб-компонентов.
::

::question
Что будет, если в var() подставить неподходящее значение?

#answer
Браузер подставляет переменную при вычислении стиля, когда объявление уже победило в каскаде. Если результат недопустим, свойство становится `unset`: наследуемое берёт значение родителя, остальные — начальное. Предыдущее объявление того же свойства не используется.

#more
То же при ссылке на несуществующую переменную без запасного значения — опечатка тихо сбрасывает стиль. Защищаются запасным значением `var(--x, fallback)` или регистрацией через `@property`: для зарегистрированной переменной неподходящее значение заменяется её `initial-value`.
::

::question
Что даёт @property?

#answer
Тип, начальное значение и управление наследованием. С типом браузер умеет интерполировать переменную — её можно анимировать. Неподходящее значение заменяется начальным, а `inherits: false` отключает наследование.

#more
Зарегистрированная переменная вычисляется там, где её задали: `--pad: 2em` у родителя хранит пиксели, а незарегистрированная — текст `2em`, который пересчитают от шрифта каждого потомка. Из JavaScript — `CSS.registerProperty`. Анимация угла градиента или процента прогресса — самые частые применения.
::

::question
Как работает нативная вложенность и чем отличается от Sass?

#answer
Правила вкладываются друг в друга, `&` ссылается на родительский селектор и нужен, когда вложенный приклеивается к родителю: `&:hover`, `&.active`. Потомков и селекторы типа можно писать без `&`. Внутрь вкладываются и `@media`, `@supports`, `@container`.

#more
Два отличия от Sass: родитель подставляется через `:is()`, поэтому список с `#id` даёт специфичность id всем вложенным правилам; и `&` нельзя склеить со строкой — `&__title` не превращается в `.card__title`. Глубокая вложенность раздувает специфичность так же, как длинный селектор.
::

::question
Зачем oklch, если есть hsl? Что такое color-mix и относительные цвета?

#answer
В HSL одинаковая «светлота» выглядит по-разному: жёлтый при 50% намного светлее синего. `oklch` описывает светлоту, насыщенность и тон так, как их воспринимает глаз, поэтому палитры и оттенки получаются ровными, а цвета могут выходить за пределы sRGB.

#more
`color-mix(in oklch, a 15%, b)` смешивает цвета в нужной пропорции. Относительный синтаксис `oklch(from var(--brand) calc(l + 0.1) c h)` пересчитывает компоненты готового цвета — так из одного фирменного цвета получают состояния наведения и подложки. `currentColor` связывает рамки и иконки с цветом текста.
::

::question
Как сделать тёмную тему?

#answer
Цвета вынести в переменные или `light-dark(светлый, тёмный)`, а тему задать через `color-scheme`. `color-scheme: light dark` следует системе, `light` или `dark` на `html` — выбор пользователя на сайте. Браузер подстраивает под тему и встроенные элементы: поля, полосы прокрутки.

#more
`light-dark()` работает только при `color-scheme`, в котором есть обе темы, иначе возвращает первый цвет. Части страницы, которые всегда светлые, получают свой `color-scheme: light`. `prefers-color-scheme` в медиазапросе остаётся для нецветовых отличий. Выбор пользователя хранят и применяют до первой отрисовки, чтобы страница не мигала светлой темой.
::

::question
Что такое якорное позиционирование?

#answer
Способ привязать элемент к другому без JavaScript: `anchor-name: --buy` у кнопки, `position-anchor: --buy` у подсказки и `anchor(top)` в её координатах. `position-try-fallbacks: flip-block` переворачивает подсказку, если не хватает места.

#more
Раньше это делали библиотеки вроде Floating UI: измерение, пересчёт при прокрутке, переворот у края. Вместе с Popover API получается меню или подсказка целиком на HTML и CSS, в верхнем слое над всеми контекстами наложения. Поддержку проверяют через `@supports` и оставляют простой вариант для остальных браузеров.
::

## Практика

::practice{title="Цена потеряла цвет"}
После рефакторинга цена в карточке стала цветом текста карточки, хотя строкой выше задан серый:

```css
.card  { color: var(--text); }
.price { color: #666; color: var(--price-colour); }
```

#solution
В имени переменной опечатка — `--price-colour` вместо `--price-color`, — а запасного значения нет. Второе объявление победило в каскаде, при вычислении подстановка не удалась, и свойство стало `unset`: для наследуемого `color` это цвет родителя. `#666` строкой выше уже проиграл и не используется.

```css
.price { color: var(--price-color, #666); }
```

Или зарегистрировать переменную, чтобы неподходящее значение заменялось начальным:

```css
@property --price-color { syntax: "<color>"; inherits: true; initial-value: #666; }
```

В проверке в Chromium цена с `color: blue; color: var(--size)` стала цветом родителя, а не синей. Опечатки в переменных ловит линтер стилей с правилом на неизвестные custom properties.
::

::practice{title="Перенос стилей с Sass"}
Стили перевели с Sass на нативную вложенность. Заголовок карточки потерял цвет, а цены в каталоге перестали краснеть на распродаже:

```css
.card {
  &__title { color: var(--accent); }
}
.catalog, #promo {
  .price { color: var(--text); }
}
.catalog .price.sale { color: var(--sale); }
```

#solution
Две разницы с Sass. `&__title` в CSS не склеивается в `.card__title` — правило не нашло элемент. А `.catalog, #promo` подставляется как `:is(.catalog, #promo)`, и вложенное правило получает специфичность id: (1, 1, 0) против (0, 3, 0) у правила распродажи.

```css
.card__title { color: var(--accent); }

.catalog .price, #promo .price { color: var(--text); }
.catalog .price.sale { color: var(--sale); }
```

В проверке `.card__title` не получил стиль из `&__title`, а `:is()`-вложенность победила даже селектор с четырьмя классами. Если нужен общий родитель без повышения специфичности — `:where(.catalog, #promo) .price`.
::

::practice{title="Тёмная тема не включается"}
Цвета страницы заданы через `light-dark()`, но при тёмной системной теме страница остаётся светлой:

```css
body { background: light-dark(white, #111); color: light-dark(#222, #eee); }
```

#solution
`light-dark()` выбирает цвет по используемой схеме элемента, а она задаётся `color-scheme`. Без него схема светлая, и функция возвращает первый вариант.

```css
:root { color-scheme: light dark; }
:root[data-theme="light"] { color-scheme: light; }
:root[data-theme="dark"]  { color-scheme: dark; }
```

Первая строка включает следование системе, две других — ручной выбор на сайте. В проверке при эмулированной тёмной теме элемент без `color-scheme` получил светлый цвет, с `color-scheme: light dark` — тёмный, а с `color-scheme: light` — снова светлый.
::
