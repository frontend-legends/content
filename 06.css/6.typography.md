# Типографика и шрифты

Как браузер выбирает и загружает шрифт и как CSS управляет текстом: `@font-face` и поднаборы, `font-display`, метрики запасного шрифта, вариативные шрифты, переносы, многоточие и выравнивание строк. Спрашивают, чем `swap` отличается от `optional`, что такое FOIT и FOUT, как обрезать текст многоточием и зачем вариативные шрифты. Глубже — почему `preload` шрифта без `crossorigin` не работает, почему для русского текста качается латинский файл и почему `overflow-wrap: break-word` не спасает flex-карточку.

::tldr
- **`@font-face` только описывает шрифт.** Файл скачивается, когда он нужен тексту на странице, и только поднаборы, символы которых встретились, — по `unicode-range`. Пробел и цифры обычно лежат в латинском поднаборе.
- **`font-display` задаёт два периода:** блокировки, когда текст невидим, и замены, когда запасной шрифт ещё можно подменить. `block` — до 3 секунд пустого места, `swap` — сразу запасной, `optional` — если шрифт не успел, страница так и остаётся с запасным.
- **Шрифты всегда загружаются в режиме CORS,** поэтому `preload` без `crossorigin` не используется, и файл запрашивается второй раз.
- **Подмена шрифта двигает текст, если метрики разные.** `size-adjust`, `ascent-override`, `descent-override` и `line-gap-override` подгоняют запасной шрифт под свой и убирают сдвиг.
- **Вариативный шрифт — один файл на все веса и ширины.** Вес задают через `font-weight`: `font-variation-settings` не складывается с родительским и затирает оси, заданные выше.
::

## Как браузер выбирает шрифт

Сквозной пример — карточка товара и шапка магазина: заголовок «Бесплатная доставка», название чая, цена, таймер акции и адрес пункта выдачи.

```css
body { font-family: "Inter", system-ui, sans-serif; }
```

`font-family` — список. Браузер идёт по нему **для каждого символа**: если в первом шрифте нет глифа, например эмодзи или редкой буквы, берётся следующий. Последним всегда ставят родовое семейство — `sans-serif`, `serif`, `monospace`, `system-ui`, — оно есть везде. `system-ui` — системный шрифт ОС: быстрый, привычный пользователю и не требующий загрузки.

Внутри семейства браузер подбирает начертание по `font-weight`, `font-style` и `font-stretch`. Если нужного нет — например, подключён только обычный вес, а заголовок `font-weight: 700`, — браузер **синтезирует** жирный и курсив сам. В проверке синтезированный жирный дал примерно на 8% больше тёмных пикселей, чем обычный, но ширина букв не изменилась: настоящий жирный шире и рисуется другими контурами. `font-synthesis: none` запрещает подделку — в проверке текст остался честно обычным.

## @font-face

```css
@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-latin.woff2") format("woff2");
  font-weight: 100 900;
  font-display: swap;
  unicode-range: U+0000-00FF, U+2000-206F;
}
```

Правило только описывает шрифт: имя, файл, какие веса и символы он покрывает. **Скачивается файл лениво** — когда при раскладке находится текст, которому нужен этот шрифт. В проверке на странице с объявленным, но неиспользуемым Inter запросов к файлу не было, а после добавления абзаца с `font-family: Inter` — появился один.

Формат сегодня один — WOFF2: сжатый и поддерживается везде. Старые TTF, EOT и SVG-шрифты в `src` больше не перечисляют.

### Поднаборы

Шрифт с латиницей, кириллицей и греческим весит сотни килобайт. Его режут на поднаборы и описывают каждый своим `@font-face` с одним `font-family` и своим `unicode-range`. Браузер качает только те, символы которых есть на странице. В проверке с Inter, разрезанным на латиницу и кириллицу, как делают Google Fonts и Fontsource:

| Текст | Скачанные файлы |
| --- | --- |
| `Tea` | латиница |
| `Доставка` | кириллица |
| `Доставка завтра` | кириллица и латиница |

Пробел U+0020 входит в латинский поднабор, поэтому русская фраза из двух слов тянет и латинский файл. Цифры и знаки препинания — тоже. Это нормально: на настоящей странице оба файла всё равно понадобятся, а экономия — на греческом, вьетнамском и расширенных наборах.

Свой хостинг шрифтов против Google Fonts — вопрос скорости и приватности. Общего кеша шрифтов между сайтами больше нет: браузеры разделили HTTP-кеш по сайтам, и шрифт с CDN не «уже скачан у пользователя». Чужой домен добавляет соединение, а запросы к нему — передачу IP-адреса третьей стороне. Подробно — в [Оптимизации ресурсов](/content/security-perfomance/asset-optimization).

## Пока шрифт грузится

У каждого шрифта при загрузке три периода:

- **блокировки** — текст рисуется невидимым запасным шрифтом: место занято, букв нет;
- **замены** — текст виден запасным шрифтом, и когда придёт свой, его подменят;
- **неудачи** — свой шрифт опоздал и уже не будет использован на этой странице.

`font-display` задаёт их длительность:

| Значение | Блокировка | Замена | Что видно |
| --- | --- | --- | --- |
| `block` | около 3 с | без ограничения | пустое место, потом свой шрифт |
| `swap` | почти нет | без ограничения | сразу запасной, потом подмена |
| `fallback` | около 100 мс | около 3 с | запасной; опоздавший шрифт не подменяют |
| `optional` | около 100 мс | нет | свой шрифт — только если успел почти сразу |
| `auto` | решает браузер | | обычно как `block` |

Всё это видно на скриншотах в проверке, где сервер отдавал шрифт с задержкой 1,5 секунды:

- **`block`** — через 400 мс в боксе заголовка не было ни одного тёмного пикселя, хотя ширина бокса уже была ненулевой: место заняли невидимым запасным шрифтом. Это :term[FOIT]{def="Flash of Invisible Text: текст невидим, пока грузится шрифт"};
- **`swap`** — через 400 мс заголовок был виден системным шрифтом, а после загрузки его ширина изменилась: текст перескочил. Это :term[FOUT]{def="Flash of Unstyled Text: текст сначала виден запасным шрифтом, потом подменяется"};
- **`optional`** — шрифт пришёл, но заголовок остался системным до конца визита. При следующем заходе файл взялся из HTTP-кеша без запроса к серверу, и шрифт применился сразу.

Как выбирать: `swap` — для основного текста, если свой шрифт важен для бренда; `optional` — если важнее стабильность и скорость: на медленной сети пользователь просто увидит системный шрифт без скачков; `block` — только для иконочных шрифтов, где запасной показал бы мусор.

### preload и crossorigin

Шрифт обнаруживается поздно: браузер узнаёт о нём, только когда CSS скачан и разобран, а раскладка дошла до текста. `preload` в `<head>` начинает загрузку сразу:

```html
<link rel="preload" href="/fonts/inter-latin.woff2" as="font" type="font/woff2" crossorigin>
```

Атрибут `crossorigin` обязателен **даже для своего домена**. Шрифты всегда загружаются в режиме CORS, а `preload` без атрибута делает обычный запрос. Режимы не совпадают, и предзагруженный файл не используется. В проверке со шрифтом с другого адреса Chrome предупредил в консоли: «credentials mode does not match». Если ответ шрифта кешируемый, второй запрос взялся из HTTP-кеша. Если сервер отвечает с `Vary: Origin`, как часто бывает у CDN, файл скачался дважды. С `crossorigin` — один раз и без предупреждения.

Предзагружают один-два файла: те, что нужны первому экрану. Предзагрузка всех начертаний отнимает полосу у картинки первого экрана и CSS.

## Подмена без сдвига

При `swap` и `fallback` текст сначала раскладывается запасным шрифтом, а потом своим. Если у них разная ширина букв и высота строки, абзацы перескакивают — это сдвиг макета, который портит [CLS](/content/security-perfomance/core-web-vitals). Решение — подогнать метрики запасного шрифта под свой:

```css
@font-face {
  font-family: "Inter Fallback";
  src: local("Arial");
  size-adjust: 107%;
  ascent-override: 90%;
  descent-override: 22%;
  line-gap-override: 0%;
}
body { font-family: "Inter", "Inter Fallback", sans-serif; }
```

- **`size-adjust`** масштабирует глифы: в проверке тот же Inter с `size-adjust: 50%` дал ровно половину ширины слова;
- **`ascent-override`**, **`descent-override`**, **`line-gap-override`** задают вертикальные метрики, от которых зависит высота строки при `line-height: normal`: с `ascent-override: 150%` строка в проверке стала выше больше чем на 10px.

Числа под пару «свой шрифт — системный» не подбирают вручную: их считают инструменты — модуль шрифтов Next.js, Fontaine, Capsize. Где сдвиг измерить — в [Core Web Vitals](/content/security-perfomance/core-web-vitals).

## Вариативные шрифты

Обычный шрифт — отдельный файл на каждое начертание: Regular, Medium, Bold, Italic. **Вариативный** хранит оси, по которым начертание меняется непрерывно:

| Ось | Свойство CSS | Что меняет |
| --- | --- | --- |
| `wght` | `font-weight` | вес |
| `wdth` | `font-stretch` | ширину |
| `ital`, `slnt` | `font-style` | курсив и наклон |
| `opsz` | `font-optical-sizing` | рисунок под размер: мелкий текст разборчивее |

В `@font-face` для него указывают диапазон `font-weight: 100 900`, и доступен любой вес, а не только кратные ста: в проверке 400, 650 и 900 из одного файла дали три разные ширины слова. Один файл вместо пяти-шести — меньше запросов, а вес можно плавно анимировать.

Оси можно задать и напрямую — `font-variation-settings: "wght" 650`, в проверке это совпало с `font-weight: 650`. Но у низкоуровневого свойства ловушка: **оно не складывается**. Значение задаётся списком целиком, и ребёнок, которому поставили `"opsz" 32`, теряет `"wght" 800` родителя — в проверке он стал обычным по весу. С `font-weight: 800` у родителя и `opsz` у ребёнка оба значения сохранились. Поэтому для стандартных осей используют свойства CSS, а `font-variation-settings` — только для своих осей шрифта.

## Текст на странице

Шрифт загружен — дальше CSS решает, как текст стоит в строках.

### Размер и строка

- **Размер шрифта** — в `rem`, чтобы уважать настройки размера в браузере пользователя (подробно о единицах — в [Каскаде](/content/css/styling)).
- **`line-height`** — без единиц, `1.4`–`1.6` для основного текста: множитель пересчитывается у потомков с другим шрифтом. Почему `1.5em` ломает заголовки — в [Каскаде](/content/css/styling).
- **Длина строки** — 45–75 символов удобны для чтения: `max-width: 65ch`, где `ch` — ширина цифры «0».

### Цифры

У большинства шрифтов цифры по умолчанию **пропорциональные**: единица уже восьмёрки. В таймере акции и колонке цен это значит, что текст дёргается при каждом изменении, а столбцы не выравниваются. В проверке «1111» в Inter был заметно уже «8888», а с `font-variant-numeric: tabular-nums` — ровно той же ширины.

```css
.timer, .price { font-variant-numeric: tabular-nums; }
```

### Пробелы и переносы

| `white-space` | Пробелы | Переводы строк | Перенос по ширине |
| --- | --- | --- | --- |
| `normal` | схлопываются | игнорируются | да |
| `nowrap` | схлопываются | игнорируются | нет |
| `pre` | сохраняются | сохраняются | нет |
| `pre-wrap` | сохраняются | сохраняются | да |
| `pre-line` | схлопываются | сохраняются | да |

`pre-line` удобен для адресов и комментариев из текстового поля: в проверке «Самовывоз:····пункт» с переводом строки превратился в «Самовывоз: пункт» и вторую строку.

Длинные слова без пробелов — ссылки, артикулы, хеши — не переносятся и вылезают из блока. Три свойства решают это по-разному:

- **`overflow-wrap: break-word`** — разрывает слово, только если оно иначе не влезает. Но минимальная ширина блока остаётся шириной слова: flex-элемент и колонка таблицы всё равно раздуваются. В проверке абзац со ссылкой во flex-строке 300px вылез за неё;
- **`overflow-wrap: anywhere`** — то же, но учитывается в минимальной ширине: тот же абзац уместился в 300px;
- **`word-break: break-all`** — разрывает любое слово в любом месте, даже обычное. Годится для хешей и кода, но не для текста.

`hyphens: auto` расставляет мягкие переносы по словарю языка и работает, только если у элемента или предка указан `lang`.

### Многоточие и обрезка строк

Одна строка с многоточием требует трёх свойств сразу:

```css
.title { white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }
```

Без `nowrap` строка просто переносится, без `overflow: hidden` — вылезает. Во flex-строке элементу ещё нужен `min-width: 0` (подробно — в [Раскладке и потоке](/content/css/flow)).

Несколько строк — через `-webkit-line-clamp`, который работает во всех браузерах только в этой связке:

```css
.description {
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 3;
  overflow: hidden;
}
```

В проверке описание при `line-height: 20px` получило высоту ровно 60px — три строки. Обрезка визуальная: полный текст остаётся в DOM и доступен программам чтения с экрана.

### Ровные строки

- **`text-wrap: balance`** выравнивает длины строк заголовка. В проверке «Новые сорта улуна уже в каталоге» в колонке 320px без него разбился на строки 299px и 103px, с ним — 225px и 177px. Браузер балансирует только короткие блоки в несколько строк, поэтому свойство ставят на заголовки и подписи;
- **`text-wrap: pretty`** избегает одного короткого слова на последней строке абзаца. В проверке последняя строка из одного слова «рублей» шириной 84px с ним стала почти вдвое длиннее — 161px — за счёт слова с предыдущей строки. Для основного текста это дешевле, чем `balance`.

## Красные флаги в ответе

- **«`@font-face` загружает шрифт».** Он только описывает; файл скачивается, когда шрифт понадобился тексту, и только нужные поднаборы.
- **«`font-display: swap` убирает все проблемы».** Он убирает невидимый текст, но добавляет скачок при подмене; без подгонки метрик это сдвиг макета.
- **«`crossorigin` нужен только для чужого домена».** Шрифты всегда грузятся в режиме CORS, без атрибута предзагрузка не используется.
- **«Подключу только Regular, жирный браузер сделает».** Синтезированный жирный — это обводка без изменения ширины, а не начертание; лучше вариативный файл или `font-synthesis: none`.
- **«`font-variation-settings` — то же, что `font-weight`».** Оно не складывается и затирает оси родителя.
- **«`break-word` починит ссылку во flex».** Он не уменьшает минимальную ширину; нужен `overflow-wrap: anywhere` или `min-width: 0`.

## Как спрашивают на собеседовании

::question
Когда браузер скачивает шрифт? Что делает unicode-range?

#answer
`@font-face` только описывает шрифт. Файл скачивается, когда при раскладке встречается текст, которому нужен этот шрифт. `unicode-range` говорит, какие символы есть в файле, и браузер качает только поднаборы, символы которых встретились на странице.

#more
Шрифт режут на латиницу, кириллицу, греческий и описывают каждый своим `@font-face` с одним именем. Пробел, цифры и знаки препинания обычно в латинском поднаборе, поэтому русский текст тянет и его. Из-за позднего обнаружения шрифта критичный файл предзагружают через `preload` с `crossorigin`.
::

::question
Какие значения бывают у font-display? Что такое FOIT и FOUT?

#answer
У шрифта два периода: блокировки — текст невидим — и замены — виден запасной, который подменят. `block` — до 3 секунд невидимого текста, это FOIT. `swap` — сразу запасной и подмена, это FOUT. `fallback` — 100 мс невидимости и 3 секунды на подмену. `optional` — шрифт используется, только если успел почти сразу.

#more
`swap` выбирают, когда шрифт важен для бренда, но подмену нужно сгладить метриками запасного. `optional` — когда важнее стабильность: на медленной сети останется системный шрифт без скачков, а при следующем визите шрифт возьмётся из кеша. `block` — для иконочных шрифтов.
::

::question
Зачем preload шрифта и почему без crossorigin он не работает?

#answer
`preload` начинает загрузку шрифта сразу, а не после разбора CSS и раскладки. Шрифты всегда загружаются в режиме CORS, и `preload` должен совпадать с ним по режиму — поэтому `crossorigin` нужен даже для своего домена.

#more
Без атрибута предзагрузка не используется, Chrome пишет в консоль, что режим учётных данных не совпал, и шрифт запрашивается снова: из HTTP-кеша, если ответ кешируемый, или второй загрузкой, если сервер отвечает с `Vary: Origin`. Предзагружают один-два файла первого экрана, иначе они отнимают полосу у важного.
::

::question
Как убрать сдвиг текста при загрузке шрифта?

#answer
Подогнать метрики запасного шрифта под свой: `@font-face` с `src: local("Arial")` и `size-adjust`, `ascent-override`, `descent-override`, `line-gap-override`. Тогда подмена почти не меняет ширину и высоту строк.

#more
Числа считают инструменты — модуль шрифтов Next.js, Fontaine, Capsize. Помогают и `font-display: optional`, при котором подмены нет вовсе, и предзагрузка, сокращающая время до прихода шрифта. Сдвиг измеряют метрикой CLS.
::

::question
Что дают вариативные шрифты? Чем font-variation-settings хуже font-weight?

#answer
Один файл хранит оси — вес, ширину, наклон, оптический размер — и даёт любые значения в диапазоне: не только 400 и 700, но и 650. Меньше файлов и запросов, вес можно анимировать.

#more
В `@font-face` для вариативного шрифта пишут диапазон `font-weight: 100 900`. `font-variation-settings` задаёт оси низкоуровнево и не складывается: ребёнок с `"opsz" 32` теряет `"wght" 800` родителя. Поэтому стандартные оси задают через `font-weight`, `font-stretch`, `font-style` и `font-optical-sizing`.
::

::question
Как обрезать текст многоточием в одну строку и в несколько?

#answer
Одна строка — `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`. Несколько — `display: -webkit-box; -webkit-box-orient: vertical; -webkit-line-clamp: 3; overflow: hidden`.

#more
Во flex-строке элементу с многоточием нужен `min-width: 0`, иначе он не сжимается. `-webkit-line-clamp` работает во всех браузерах только в этой связке. Обрезка визуальная: текст остаётся в DOM, поэтому полный вариант можно показать в `title` или по клику.
::

::question
Чем overflow-wrap: break-word отличается от anywhere и word-break: break-all?

#answer
`break-word` разрывает длинное слово, только если оно не влезает в строку. `anywhere` делает то же, но ещё уменьшает минимальную ширину блока. `word-break: break-all` разрывает любое слово в любом месте, даже то, что влезло бы.

#more
Разница `break-word` и `anywhere` видна во flex и таблицах: их размер считается от минимальной ширины содержимого, и с `break-word` ссылка всё равно раздувает элемент. `break-all` годится для хешей и кода. Для обычного текста с длинными словами — `hyphens: auto` с атрибутом `lang`.
::

## Практика

::practice{title="Шрифт скачивается дважды"}
В панели Network файл шрифта с CDN виден два раза, а в консоли Chrome предупреждение про `preload`:

```html
<link rel="preload" href="https://cdn.shop.example/fonts/inter-latin.woff2" as="font" type="font/woff2">
```

#solution
Шрифты всегда загружаются в режиме CORS, а `preload` без `crossorigin` — обычным запросом. Режимы не совпали, и браузер не взял предзагруженный файл. CDN отвечает с `Vary: Origin`, и у запросов с заголовком `Origin` и без него разные записи в кеше — отсюда вторая загрузка.

```html
<link rel="preload" href="https://cdn.shop.example/fonts/inter-latin.woff2" as="font" type="font/woff2" crossorigin>
```

В проверке в Chromium без атрибута сервер получил два запроса и консоль — предупреждение «credentials mode does not match», с атрибутом — один запрос без предупреждений. Атрибут нужен и для шрифта со своего домена.
::

::practice{title="Таймер акции дрожит"}
Таймер «До конца акции 01:59:59» дёргается каждую секунду, а цены в таблице заказов не встают в столбец:

```css
.timer { font: 600 24px Inter, sans-serif; }
```

#solution
Цифры в шрифте пропорциональные: «1» уже «8». При каждом тике ширина строки меняется, и соседние элементы сдвигаются. Включаем табличные цифры:

```css
.timer, .order-total { font-variant-numeric: tabular-nums; }
```

В проверке с Inter «1111» и «8888» без этого свойства различались по ширине больше чем на 10px, с ним стали одинаковыми. В таблице к этому добавляют выравнивание цен по правому краю.
::

::practice{title="Адрес распирает карточку"}
Ссылка на пункт выдачи в карточке заказа вылезает за край, хотя добавили перенос:

```css
.order { display: flex; width: 300px; }
.address { overflow-wrap: break-word; }
```

#solution
`break-word` разрывает слово при отрисовке, но не уменьшает минимальную ширину содержимого. Flex-элемент по умолчанию не уже своего минимума и растягивается под всю ссылку. Нужен перенос, который учитывается в минимальной ширине:

```css
.address { overflow-wrap: anywhere; }
```

Или разрешить элементу сжиматься — `min-width: 0` — и оставить `break-word`. В проверке с `break-word` абзац во flex-строке 300px вышел шире 300px, с `anywhere` — уместился.
::
