# Раскладка и поток

Как браузер расставляет боксы: обычный поток, `display`, схлопывание отступов, контексты форматирования, позиционирование, наложение слоёв, Flexbox и Grid. Спрашивают, чем `display: none` отличается от `visibility: hidden`, что такое BFC, почему не работает `z-index` и что значит `flex: 1`. Глубже — почему `position: fixed` вдруг прилипает к родителю, почему длинная ссылка разрывает карточку во flex и grid и почему `overflow: hidden` ломает липкую шапку.

::tldr
- **`display` задаёт две вещи:** как бокс стоит среди соседей — блоком или в строке — и как раскладывает своих детей: потоком, flex или grid. Строчный бокс игнорирует `width`, `height` и вертикальные отступы.
- **Вертикальные отступы в потоке схлопываются:** 20px и 30px между соседями дают 30px, а отступ первого ребёнка проваливается сквозь родителя без рамки и `padding`. Во flex и grid отступы не схлопываются.
- **Позиция считается от containing block:** `absolute` — от ближайшего позиционированного предка, `fixed` — от окна, но только пока у предка нет `transform` или `filter`. Липкий `sticky` перестаёт работать, если у предка `overflow: hidden`.
- **`z-index` сравнивается только внутри одного контекста наложения:** 9999 внутри блока с `z-index: 1` окажется ниже соседа с `z-index: 2`. Контекст создают и `opacity`, `transform`, `filter`, `isolation: isolate`.
- **`flex: 1` — это `1 1 0%`, элементы делят место поровну.** Flex- и grid-элементы не сжимаются меньше содержимого, поэтому длинная строка разрывает раскладку, пока не задать `min-width: 0` или `minmax(0, 1fr)`.
::

## Поток и display

Сквозной пример — страница каталога: липкая шапка с меню, боковая панель фильтров, сетка карточек товаров, выпадающее меню и модальное окно.

Пока ничего не задано, элементы стоят в **обычном потоке**. Блочные боксы — `div`, `p`, `section` — занимают всю ширину контейнера и идут сверху вниз. Строчные — `span`, `a`, `strong` — встают в строку, пока она не кончится, и переносятся. Строчный бокс подстраивается под текст: в проверке у `span` с `width: 100px; height: 50px` ширина осталась шириной слова.

`display` описывает две стороны бокса — внешнюю и внутреннюю:

| Значение | Среди соседей | Детей раскладывает |
| --- | --- | --- |
| `block` | блок | потоком |
| `inline` | в строке | потоком |
| `inline-block` | в строке, но с размерами блока | потоком, своим контекстом |
| `flex` / `inline-flex` | блок / в строке | как flex-элементы |
| `grid` / `inline-grid` | блок / в строке | по сетке |
| `flow-root` | блок | потоком, своим контекстом |

Спецификация разрешает писать обе стороны явно: `display: inline flex` — то же, что `inline-flex`, и `getComputedStyle` в проверке вернул `inline-flex`.

`display: contents` убирает бокс самого элемента, а его дети встают на его место. Обёртку внутри flex-строки так можно сделать невидимой для раскладки: в проверке два ребёнка обёртки стали flex-элементами наравне с соседом, а ширина обёртки — нулевой.

### Как спрятать элемент

| Способ | Место в раскладке | Клики | Программы чтения с экрана |
| --- | --- | --- | --- |
| `display: none` | нет | нет | не видят |
| `visibility: hidden` | занимает | проходят сквозь | не видят |
| `opacity: 0` | занимает | ловит | видят |
| визуально скрытый (`.sr-only`) | 1×1 пиксель | нет | видят |

Всё в таблице проверено в Chromium. Две детали:

- **`visibility` наследуется, и потомок может её вернуть:** ребёнок с `visibility: visible` внутри скрытого блока виден и кликабелен. С `display: none` так не выйдет;
- **`opacity: 0` — не скрытие:** прозрачная кнопка ловит клики и есть в дереве доступности. Это ловушка анимаций появления, где элемент «исчезает» прозрачностью и остаётся на пути курсора.

Визуально скрытый текст нужен, когда подпись должна быть только для программ чтения с экрана — «Корзина: 3 товара» у иконки:

```css
.sr-only {
  position: absolute; width: 1px; height: 1px; margin: -1px; padding: 0; border: 0;
  overflow: hidden; clip-path: inset(50%); white-space: nowrap;
}
```

Атрибут `hidden` работает через стиль браузера `[hidden] { display: none }`. Любое свойство `display` в своём CSS его перебивает: в проверке панель с `hidden` и классом `.toolbar { display: flex }` осталась на экране. Поэтому в сбросы добавляют `[hidden] { display: none !important; }`.

## Схлопывание отступов

Вертикальные отступы блоков в потоке не складываются, а **схлопываются** — остаётся больший:

```css
.a { margin-bottom: 20px; }
.b { margin-top: 30px; }   /* между .a и .b 30px, а не 50px */
```

Правила, проверенные в Chromium:

- **соседи** — между ними больший из двух отступов; с отрицательным отступ складывается: 30px и −10px дали 20px;
- **родитель и первый или последний ребёнок** — если между ними нет рамки, `padding` или строки текста, отступ ребёнка выходит наружу. В проверке ребёнок с `margin-top: 40px` прижался к верху родителя, а сдвинулся весь родитель — и сквозь него все предки без рамок;
- **пустой блок** — его верхний и нижний отступы схлопываются между собой.

Не схлопываются горизонтальные отступы, отступы flex- и grid-элементов (в проверке колонка во flex дала честные 50px), а также отступы через границу нового контекста форматирования. Отсюда практическое правило: расстояния между элементами внутри компонента задают `gap` во flex или grid, а не `margin` у детей.

## Контекст форматирования

Когда родитель «не видит» отступ ребёнка или плавающий элемент, помогает **:term[блочный контекст форматирования]{def="Block Formatting Context, BFC: область, внутри которой блоки раскладываются независимо от внешних"}**, BFC. Это изолированная область: что внутри, не влияет на то, что снаружи.

BFC делает три вещи:

- **удерживает float внутри:** родитель, в котором только плавающие элементы, без BFC имеет высоту 0 — в проверке ровно 0, а с `display: flow-root` — 80px, высоту float;
- **не залезает под float:** обычный абзац рядом с float занимает всю ширину, и обтекают картинку только его строки, а блок с BFC встаёт рядом — в проверке начался с 100px, сразу за float;
- **останавливает схлопывание** отступов через свою границу: с `flow-root` родитель удержал отступ ребёнка внутри.

BFC создают `display: flow-root` — специально для этого, — а также `overflow` со значением кроме `visible` и `clip`, float, `position: absolute` и `fixed`, `inline-block`, flex- и grid-элементы, `contain: layout` и `paint`, корень документа.

Раньше float «чинили» через `overflow: hidden`: он создаёт BFC, но обрезает тень и выпадающее меню. `overflow: clip` BFC не создаёт — в проверке родитель с ним остался высотой 0. Правильный инструмент — `flow-root`. Float сегодня нужен только для обтекания текстом; раскладку колонок на нём не строят.

## Позиционирование

| `position` | Место в потоке | Смещается от |
| --- | --- | --- |
| `static` | да | не смещается, значение по умолчанию |
| `relative` | да, исходное место сохраняется | своего обычного положения |
| `absolute` | нет | containing block |
| `fixed` | нет | окна просмотра или containing block |
| `sticky` | да | ведёт себя как `relative`, пока не дойдёт до порога |

`top`, `right`, `bottom`, `left` — или `inset` разом — отсчитываются от **:term[containing block]{def="прямоугольник, от которого считаются положение и проценты размеров элемента"}**. Для `absolute` это ближайший предок с `position` кроме `static`: бейдж «Скидка» с `top: 10px; right: 10px` в карточке с `position: relative` встал в её угол. Без позиционированного предка он отсчитывался бы от начального блока документа.

### fixed, который прилип к родителю

`fixed` отсчитывается от окна, но **предок с `transform`, `filter`, `backdrop-filter`, `perspective`, `will-change: transform` или `contain: paint` сам становится containing block**. В проверке элемент с `position: fixed; top: 0` внутри блока с `transform: translateZ(0)` встал в верх этого блока, а не окна; с `filter: blur(0)` — так же. Модалка внутри анимированной карточки начинает прокручиваться вместе со страницей.

Поэтому оверлеи выносят из дерева компонентов: порталом в конец `body` (подробно — в главах про [React](/content/reactjs/refs-portals-a11y) и [Vue](/content/vuejs/built-in-components)) или в **верхний слой** браузера через `<dialog>` с `showModal()` и Popover API. Элемент верхнего слоя рисуется поверх всего документа — об этом ниже.

### sticky

```css
header { position: sticky; top: 0; }
```

Липкий элемент ведёт себя как `relative`, пока при прокрутке не дойдёт до порога `top`, и дальше держится у края **ближайшего контейнера прокрутки**, но не дальше конца своего родителя. Почему он не липнет:

- **нет порога** — без `top` или `bottom` `sticky` ведёт себя как `relative`;
- **`overflow` у предка** — `hidden`, `auto` или `scroll` делают предка контейнером прокрутки, и шапка липнет к нему, а он сам не прокручивается. В проверке обёртка с `overflow-x: hidden` дала шапке уехать на −1000px вместе со страницей. `overflow-x: clip` обрезает так же, но контейнером прокрутки не становится, и шапка осталась на месте;
- **короткий родитель** — липкий элемент не выходит за его пределы.

## Контекст наложения

Боксы перекрываются, и кто окажется сверху, решает **:term[контекст наложения]{def="stacking context: группа элементов, которая накладывается на соседей целиком, как один слой"}**. `z-index` сравнивается **только внутри одного контекста**: дети контекста не могут подняться выше его соседей, какой бы `z-index` у них ни был.

```html
<div class="sidebar" style="position: relative; z-index: 1">
  <div class="dropdown" style="position: absolute; z-index: 9999"></div>
</div>
<div class="modal" style="position: relative; z-index: 2"></div>
```

Меню фильтров с 9999 оказалось под модалкой: в проверке `elementFromPoint` в зоне перекрытия вернул модалку. Сравниваются `1` и `2` на уровне документа, а 9999 живёт внутри «этажа» сайдбара. Стоило убрать `z-index` у сайдбара — контекст исчез, и меню оказалось сверху.

Контекст наложения создают:

- `position: relative` или `absolute` с `z-index` кроме `auto`; `fixed` и `sticky` — всегда;
- flex- и grid-элементы с `z-index` — им `position` не нужен. В проверке `z-index: 1` у обычного блока проигнорирован, а у flex-элемента сработал;
- `opacity` меньше 1 — в проверке `opacity: 0.99` у сайдбара снова «запер» меню;
- `transform`, `filter`, `backdrop-filter`, `clip-path`, `mask`, `mix-blend-mode`, `will-change` с этими свойствами;
- `isolation: isolate` — создаёт контекст и больше ничего не делает;
- `contain: layout` или `paint`.

Внутри контекста порядок такой: фон и рамка самого контекста, дети с отрицательным `z-index`, блоки потока, float, строчное содержимое, позиционированные с `z-index: auto` и `0`, положительные `z-index`. Отсюда ловушка: декоративная подложка с `z-index: -1` уходит **под фон родителя**, если родитель не создал контекст. В проверке клик попал в родителя; после `isolation: isolate` на родителе подложка оказалась над его фоном.

Над всеми контекстами есть **верхний слой** (top layer): туда попадают модальный `dialog`, `popover` и элемент в полноэкранном режиме. В проверке модальный `dialog` внутри того же сайдбара с `z-index: 1` оказался поверх модалки с `z-index: 2`.

Вместо гонки `999`, `9999`, `99999` делают несколько уровней в переменных — `--z-dropdown`, `--z-sticky`, `--z-toast`, — компоненту дают `isolation: isolate`, чтобы его внутренние `z-index` не выходили наружу, а окна выносят в верхний слой.

## Flexbox

Flexbox раскладывает элементы вдоль одной оси — **главной**. Поперечная ось перпендикулярна ей.

```text
flex-direction: row                 flex-direction: column

главная ось →                       ┌──────┐
┌──────┬──────┬──────┐              │ item │ ↓ главная ось
│ item │ item │ item │ ↓ поперечная ├──────┤
└──────┴──────┴──────┘              │ item │
                                    └──────┘
```

| Свойство контейнера | Что делает |
| --- | --- |
| `flex-direction` | направление главной оси |
| `flex-wrap` | перенос на новые строки |
| `justify-content` | распределение по главной оси |
| `align-items` | выравнивание по поперечной оси; по умолчанию `stretch` — элементы одной высоты |
| `align-content` | распределение строк при переносе |
| `gap` | расстояние между элементами |

Элементы получают размер в три шага: базовый размер `flex-basis`, затем свободное место раздаётся по `flex-grow`, а нехватка отнимается по `flex-shrink`, взвешенному на базовый размер.

### Сокращение flex

| Запись | Значение | Поведение |
| --- | --- | --- |
| по умолчанию | `0 1 auto` | не растёт, сжимается, база — размер содержимого |
| `flex: 1` | `1 1 0%` | база 0, всё место делится поровну |
| `flex: auto` | `1 1 auto` | растёт от размера содержимого |
| `flex: none` | `0 0 auto` | жёсткий размер |

В проверке `getComputedStyle` подтвердил все четыре. Три колонки с `flex: 1` и текстом разной длины в строке 600px получили по 200px. С `flex: auto` те же колонки разошлись — 168, 317 и 115px: свободное место раздали поровну, но база у каждой своя.

### Почему элемент не сжимается

У flex-элементов `min-width: auto`: элемент не становится уже своего самого длинного неразрывного слова. Ссылка из рассылки с UTM-метками в карточке товара вылезла за строку 400px, хотя у текста `flex: 1`. Решение — разрешить сжатие и обрезать:

```css
.text { flex: 1; min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
```

С `min-width: 0` текст занял ровно оставшиеся 350px. В колонке то же самое по высоте: если прокручиваемый список вложен во flex-элемент, элемент вырастает до высоты списка, и прокрутки нет. В проверке тело панели высотой 250px выросло до 1000px, а с `min-height: 0` осталось 250px, и список получил прокрутку.

Ещё два приёма: `margin-left: auto` у последнего пункта меню отодвигает его вправо — в проверке «Корзина» встала к краю строки 800px. `order` и `row-reverse` меняют только визуальный порядок: Tab и программы чтения с экрана идут по DOM, и пользователь клавиатуры прыгает по странице.

## Grid

Grid раскладывает в двух измерениях сразу: контейнер задаёт дорожки — колонки и строки, — а элементы встают в ячейки.

```css
.catalog {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-areas: "filters cards";
  gap: 24px;
}
.filters { grid-area: filters; }
```

`fr` — доля свободного места. `repeat()` повторяет дорожки, `minmax(min, max)` задаёт пределы.

### auto-fill и auto-fit

Сетка карточек без медиазапросов:

```css
.cards { display: grid; grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); }
```

Обе формы создают столько колонок по 200px, сколько влезает. Разница видна, когда карточек мало. В проверке в контейнере 1000px с двумя карточками `auto-fill` создал пять колонок, и карточки остались по 200px, а три пустые колонки заняли место. `auto-fit` схлопнул пустые колонки, и две карточки растянулись по 500px. Для каталога обычно нужен `auto-fit`; `auto-fill` — когда сетка должна выглядеть одинаково при любом числе элементов.

### Почему 1fr не делит поровну

`1fr` — это `minmax(auto, 1fr)`: колонка не сжимается меньше содержимого. Та же длинная ссылка в сетке `1fr 1fr` шириной 400px раздула первую колонку больше 200px. `minmax(0, 1fr)` разрешает колонке быть уже содержимого — в проверке обе колонки стали по 200px.

### Неявная сетка и subgrid

Элементы, которым не хватило заданных дорожек, создают неявные строки размером `grid-auto-rows`. `grid-auto-flow: dense` заполняет дыры элементами из конца списка — как и `order`, визуальный порядок перестаёт совпадать с порядком DOM.

Карточки товаров с заголовками разной длины дают цены на разной высоте. `subgrid` позволяет детям карточки встать на строки общей сетки:

```css
.cards { display: grid; grid-template-columns: repeat(3, 150px); }
.card  { display: grid; grid-row: span 3; grid-template-rows: subgrid; }
```

В проверке без `subgrid` цена под длинным заголовком съехала вниз, а с ним цены всех трёх карточек оказались на одной высоте.

## Flexbox или Grid

| | Flexbox | Grid |
| --- | --- | --- |
| измерения | одно: строка или колонка | два: строки и колонки |
| кто задаёт размеры | элементы своим содержимым | контейнер дорожками |
| типичные задачи | меню, панель кнопок, строка с иконкой и текстом | раскладка страницы, сетка карточек, формы с колонками |

Правило: если элементы просто стоят в ряд и делят место — Flexbox. Если важно выравнивание сразу по строкам и колонкам — Grid. Обычно они вместе: страница на Grid, содержимое ячеек на Flexbox.

### Центрирование

Вопрос «как отцентрировать div» проверяет, знаешь ли ты эти режимы. Все четыре способа поставили элемент 100×50 ровно в центр блока 400×200:

```css
.box { display: flex; justify-content: center; align-items: center; }
.box { display: grid; place-items: center; }
.box { position: relative; } .item { position: absolute; inset: 0; margin: auto; }  /* у .item заданы размеры */
.box { align-content: center; } .item { margin-inline: auto; }                      /* обычный блок */
```

Последний — без flex и grid: `align-content` теперь работает и в обычном блоке. По горизонтали блок с заданной шириной центрирует `margin-inline: auto`, строчное содержимое — `text-align: center`.

## Красные флаги в ответе

- **«Поставлю `z-index: 9999`, и будет сверху».** `z-index` сравнивается внутри контекста наложения; если родитель создал контекст с меньшим номером, никакое число не поможет.
- **«Отступы соседей складываются».** Вертикальные отступы в потоке схлопываются до большего.
- **«`position: fixed` всегда от окна».** Предок с `transform` или `filter` становится его containing block.
- **«Float починю `overflow: hidden`».** Он обрежет тени и меню; для BFC есть `display: flow-root`.
- **«`flex: 1` — это `flex-grow: 1`».** Это `1 1 0%`: с нулевой базой элементы делят место поровну, а не растут от содержимого.
- **«`opacity: 0` — элемент спрятан».** Он ловит клики и читается программами чтения с экрана.

## Как спрашивают на собеседовании

::question
Чем отличаются display: none, visibility: hidden и opacity: 0?

#answer
`display: none` убирает элемент из раскладки и дерева доступности. `visibility: hidden` прячет, но место остаётся, клики проходят сквозь, программы чтения с экрана его не видят. `opacity: 0` делает прозрачным: место занято, клики ловятся, элемент читается.

#more
`visibility` наследуется, и потомок может вернуть себе `visible`. Атрибут `hidden` — это `display: none` из стиля браузера, и любой `display` в своём CSS его перебивает, поэтому в сброс добавляют `[hidden] { display: none !important }`. Текст только для программ чтения с экрана прячут классом `.sr-only` через `clip-path` и размер 1px.
::

::question
Что такое BFC и при чём тут схлопывание отступов?

#answer
Блочный контекст форматирования — изолированная область раскладки. Она удерживает внутри плавающие элементы, не залезает под соседние float и не пропускает схлопывание отступов через свою границу. Создают его `display: flow-root`, `overflow` кроме `visible` и `clip`, float, абсолютное позиционирование, `inline-block`, flex- и grid-элементы.

#more
Вертикальные отступы в потоке схлопываются до большего, отрицательные складываются, а отступ первого ребёнка без рамки и `padding` у родителя выходит наружу и сдвигает родителя. BFC на родителе это останавливает. Во flex и grid отступы не схлопываются, поэтому расстояния внутри компонента задают `gap`.
::

::question
Почему position: sticky не прилипает, а fixed прилипает не к окну?

#answer
`sticky` липнет к ближайшему контейнеру прокрутки, а им становится любой предок с `overflow: hidden`, `auto` или `scroll`. Ещё нужен порог — `top` или `bottom`, — и липкий элемент не выходит за пределы родителя. `fixed` отсчитывается от окна, пока у предка нет `transform`, `filter`, `perspective` или `contain: paint`.

#more
Если обрезать горизонтальное переполнение нужно, а прокрутку создавать нет, вместо `overflow-x: hidden` ставят `overflow-x: clip`. Модальные окна выносят порталом в конец `body` или открывают через `dialog.showModal()` — в верхний слой, где ни containing block, ни `z-index` предков не мешают.
::

::question
Почему не работает z-index?

#answer
`z-index` сравнивается только внутри одного контекста наложения. Если меню лежит внутри блока с `z-index: 1`, а модалка — сосед этого блока с `z-index: 2`, меню будет ниже модалки при любом своём значении. Ещё `z-index` не действует на неспозиционированный обычный блок.

#more
Контекст создают позиционирование с `z-index`, `fixed` и `sticky`, `opacity` меньше 1, `transform`, `filter`, `isolation: isolate`, `will-change`, `contain`. У flex- и grid-элементов `z-index` работает без `position`. Элемент с `z-index: -1` уходит под фон родителя, если родитель не создал контекст. Лекарство — несколько уровней в переменных, `isolation: isolate` на компонентах и верхний слой для окон.
::

::question
Что значит flex: 1? Почему flex-элемент не сжимается?

#answer
`flex: 1` — это `flex-grow: 1; flex-shrink: 1; flex-basis: 0%`. С нулевой базой всё место делится по `flex-grow`, и элементы получаются одинаковыми. `flex: auto` — `1 1 auto`: растут от размера содержимого. `flex: none` — `0 0 auto`.

#more
У flex-элементов `min-width: auto`: элемент не уже своего самого длинного неразрывного слова, поэтому длинная ссылка или код вылезают за контейнер. Лечат `min-width: 0` и обрезкой через `text-overflow: ellipsis`. В колонке то же делает `min-height: 0`. Сжатие отнимается пропорционально `flex-shrink`, умноженному на базовый размер.
::

::question
Когда Flexbox, а когда Grid? Чем auto-fill отличается от auto-fit?

#answer
Flexbox — одно измерение, размеры от содержимого элементов: меню, панели, строки. Grid — два измерения, размеры задаёт контейнер дорожками: страница, сетки карточек, формы. `auto-fill` и `auto-fit` создают столько колонок, сколько влезает; `auto-fill` оставляет пустые колонки, `auto-fit` схлопывает их, и элементы растягиваются.

#more
`1fr` — это `minmax(auto, 1fr)`, колонка не уже содержимого; для честного деления пишут `minmax(0, 1fr)`. `subgrid` выравнивает строки вложенных карточек по общей сетке. `order`, `row-reverse` и `grid-auto-flow: dense` меняют только визуальный порядок, Tab идёт по DOM.
::

::question
Как отцентрировать элемент по горизонтали и вертикали?

#answer
Flex — `justify-content: center; align-items: center`. Grid — `place-items: center`. Абсолютное позиционирование — `position: absolute; inset: 0; margin: auto` при заданных размерах. В обычном блоке — `align-content: center` и `margin-inline: auto` у ребёнка.

#more
`margin-inline: auto` центрирует блок с заданной шириной по горизонтали, `text-align: center` — строчное содержимое. Старый приём `top: 50%; left: 50%; transform: translate(-50%, -50%)` работает, но создаёт контекст наложения, а дробные сдвиги иногда размывают текст.
::

## Практика

::practice{title="Меню фильтров под модалкой"}
Выпадающее меню в боковой панели прячется под баннером, хотя у меню `z-index: 9999`:

```css
.sidebar  { position: sticky; top: 0; z-index: 1; }
.dropdown { position: absolute; z-index: 9999; }
.banner   { position: relative; z-index: 2; }
```

#solution
`sticky` с `z-index: 1` создаёт контекст наложения, и всё внутри сайдбара сравнивается с баннером как один слой с номером 1. Числа внутри не помогают. Варианты по порядку предпочтения:

```html
<!-- 1. меню как popover — в верхнем слое, поверх всего -->
<button popovertarget="filters">Фильтры</button>
<div id="filters" popover>…</div>
```

```css
/* 2. или поднять весь сайдбар над баннером, а уровни держать в переменных */
:root { --z-banner: 2; --z-sidebar: 3; }
.sidebar { z-index: var(--z-sidebar); }
.banner  { z-index: var(--z-banner); }
```

В проверке в Chromium меню с 9999 внутри блока с `z-index: 1` проиграло соседу с `z-index: 2`, а модальный `dialog` из того же блока оказался поверх всего — верхний слой не зависит от контекстов предков.
::

::practice{title="Ссылка разрывает карточку"}
В карточке заказа иконка и адрес ссылки в строку. Длинная ссылка из рассылки вылезает за карточку, а в сетке каталога одна колонка стала шире другой:

```css
.row  { display: flex; }
.icon { flex: none; width: 50px; }
.text { flex: 1; }
.grid { display: grid; grid-template-columns: 1fr 1fr; }
```

#solution
И flex-элементы, и `1fr` по умолчанию не сжимаются меньше самого длинного неразрывного слова: у flex-элемента `min-width: auto`, а `1fr` — это `minmax(auto, 1fr)`. Разрешаем сжатие:

```css
.text { flex: 1; min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
.grid { grid-template-columns: minmax(0, 1fr) minmax(0, 1fr); }
```

В проверке без правки текст в строке 400px оказался шире 350px и строка получила прокрутку; с `min-width: 0` — ровно 350px. Колонки сетки 400px с `minmax(0, 1fr)` стали по 200px. Если ссылку нужно показать целиком, вместо обрезки ставят `overflow-wrap: anywhere`.
::

::practice{title="Липкая шапка уехала"}
Чтобы убрать горизонтальную прокрутку от широкой карусели, на обёртку страницы добавили `overflow-x: hidden`. После этого шапка перестала прилипать:

```css
.page   { overflow-x: hidden; }
.header { position: sticky; top: 0; }
```

#solution
`overflow-x: hidden` делает `.page` контейнером прокрутки. Шапка теперь липнет к нему, а сам `.page` не прокручивается — прокручивается окно, и шапка уезжает вместе с обёрткой. Нужно обрезать, не создавая контейнер прокрутки:

```css
.page { overflow-x: clip; }
```

В проверке с `hidden` шапка после прокрутки на 1000px оказалась на −1000px, с `clip` осталась у верхнего края. Ещё лучше — найти, что вылезает, и ограничить сам элемент: `max-width: 100%` у карусели или `min-width: 0` у её flex-родителя.
::
