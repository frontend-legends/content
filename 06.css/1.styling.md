# Каскад и стилизация

Каскад — алгоритм, по которому браузер выбирает одно значение свойства, когда к элементу подходит несколько правил. Спрашивают, как считается специфичность, что делает `!important`, почему стили библиотеки перебивают твои и чем `inherit` отличается от `unset`. Глубже — почему `!important` в раннем слое сильнее, чем в позднем, почему `getComputedStyle` отдаёт пиксели вместо `em` и почему шрифт растёт с каждым уровнем вложенности.

::tldr
- **Каскад сравнивает объявления по очереди критериев:** происхождение и важность, контекст Shadow DOM, атрибут `style`, слой, специфичность, порядок в коде. Следующий критерий смотрят, только если предыдущий дал ничью — поэтому «побеждает последнее» верно только в самом конце.
- **Специфичность — три счётчика, а не число:** id, затем классы, атрибуты и псевдоклассы, затем типы и псевдоэлементы. Сравнивают слева направо, без переноса: один id сильнее одиннадцати классов. `:where()` даёт ноль, `:is()`, `:not()` и `:has()` — специфичность самого сильного аргумента.
- **`!important` переворачивает порядок:** важное объявление пользователя сильнее важного объявления автора, а важное в раннем каскадном слое — сильнее важного в позднем.
- **Слои сильнее специфичности:** правило с одним классом в позднем слое побеждает `#id` в раннем, а стили вне слоёв сильнее любого слоя. Поэтому CSS библиотеки кладут в слой, и свои стили выигрывают без войны селекторов.
- **Если объявления нет, наследуемые свойства берут значение родителя, остальные — начальное.** Наследуется вычисленное значение: `1.5em` в `line-height` превращается в пиксели у родителя, а множитель `1.5` пересчитывается у каждого потомка.
::

## Почему правило не применилось

Сквозной пример — кнопка «Купить» в карточке товара. Стили к ней приходят из четырёх мест: стиль браузера для `button`, CSS UI-библиотеки, свои стили и атрибут `style`, который выставил JavaScript.

```html
<div class="card">
  <button id="buy" class="btn btn-primary">Купить</button>
</div>
```

```css
#buy { background: gray; }
.card .btn-primary { background: green; }
```

Второе правило ниже и «конкретнее» на вид, но кнопка серая — в проверке в Chromium фон остался `rgb(128, 128, 128)`. Порядок в файле здесь ничего не решил: до него дело не дошло, потому что у `#buy` выше специфичность. Чтобы такие вещи предсказывать, а не подбирать селекторы наугад, нужен весь алгоритм.

CSS попадает на страницу тремя путями: файл через `<link rel="stylesheet">`, блок `<style>` и атрибут `style` на элементе. Есть ещё `@import` внутри CSS, но он строит цепочку запросов: импортированный файл браузер узнаёт, только скачав и разобрав родительский. Почему CSS блокирует отрисовку и как это лечат — в [Производительности загрузки](/content/security-perfomance/loading-performance).

Все объявления из всех источников, которые подходят к элементу, попадают в каскад. Дальше браузер для каждого свойства выбирает одно.

## Каскад по шагам

Спецификация CSS Cascade задаёт очередь критериев. Объявления сравнивают по первому; если он не различает их — по второму, и так далее:

1. **Происхождение и важность** — кто написал стиль и есть ли `!important`.
2. **Контекст** — из какого дерева Shadow DOM пришло правило.
3. **Атрибут `style`** — объявление прямо на элементе сильнее объявления через селектор.
4. **Слой** — в каком `@layer` лежит правило.
5. **Специфичность** — насколько точен селектор.
6. **Порядок появления** — что ниже в коде, то и победило.

### Происхождение и важность

У стилей три :term[происхождения]{def="кто написал стиль: браузер (user agent), пользователь в настройках или автор страницы"}: браузер, пользователь и автор страницы. Анимации и переходы спецификация считает отдельными источниками. Полный порядок, от сильного к слабому:

| Место | Объявления |
| --- | --- |
| 1 | идущие переходы (`transition`) |
| 2 | важные объявления браузера |
| 3 | важные объявления пользователя |
| 4 | важные объявления автора |
| 5 | анимации (`@keyframes`) |
| 6 | обычные объявления автора |
| 7 | обычные объявления пользователя |
| 8 | обычные объявления браузера |

Отсюда два вывода. Анимация перекрывает любое обычное правило, даже с `#id`: в проверке `opacity: 1` у элемента с остановленной анимацией дал `0.5` из ключевого кадра. Но против `opacity: 1 !important` анимация проиграла. А `!important` внутри `@keyframes` браузер просто выбрасывает.

Важные объявления идут в обратном порядке по сравнению с обычными: пользователь, который увеличил шрифт или включил высокий контраст своим стилем с `!important`, сильнее автора. Так задумано ради доступности.

### Контекст и атрибут style

Контекст важен только для Shadow DOM. Если хост веб-компонента стилизуют и снаружи, и изнутри через `:host`, из обычных объявлений побеждает внешнее — страница может настроить компонент. Из важных — внутреннее: компонент может защитить своё. В проверке `#host { color: red }` снаружи победил `:host { color: blue }`, а при `!important` с обеих сторон цвет стал синим.

Атрибут `style` сильнее любого селектора той же важности. В проверке `#buy#buy` проиграл `style="color: green"`. Но `.btn { color: red !important }` атрибут перебил: важность сравнивают раньше. Если же `!important` стоит и там, и там, снова побеждает атрибут.

## Специфичность

Когда происхождение, контекст и слой совпали, сравнивают селекторы. :term[Специфичность]{def="вес селектора: три счётчика — id, классы и псевдоклассы, типы и псевдоэлементы"} — три счётчика (A, B, C):

| Счётчик | Что считается | Пример |
| --- | --- | --- |
| A | id | `#buy` → (1, 0, 0) |
| B | классы, атрибуты, псевдоклассы | `.btn`, `[type="submit"]`, `:hover` → (0, 1, 0) |
| C | типы и псевдоэлементы | `button`, `::before` → (0, 0, 1) |

Универсальный селектор `*` и комбинаторы (пробел, `>`, `+`, `~`) не считаются. `#main .card button:hover` — это (1, 2, 1).

Сравнивают слева направо, и **переноса между разрядами нет**. Это не число 0·100 + 11·10: в проверке `#buy` победил селектор из одиннадцати `.btn` подряд. А `[id="buy"]` выбирает тот же элемент, но это атрибут, (0, 1, 0), — и он проиграл `#buy`.

### Псевдоклассы-функции

- **`:is()`, `:not()`, `:has()`** — специфичность самого сильного аргумента в списке. Причём неважно, по какому аргументу элемент совпал: `:is(#nope, .btn)` весит (1, 0, 0), даже если `#nope` на странице нет. В проверке он победил `.btn.btn-primary`.
- **`:where()`** — всегда ноль. `:where(#buy)` проиграл простому `button`.
- **`:nth-child(2n of .item)`** — псевдокласс плюс самый сильный селектор из списка после `of`.

Отсюда приём для сбросов и библиотек: базовые стили в `:where()` переопределяются любым классом. Сами селекторы разобраны в [Селекторах и at-rules](/content/css/css-rules).

### Как не воевать со специфичностью

```css
#app #main .container .card .title { font-size: 18px; }
#app #main .container .card .title.active { font-size: 20px; }
```

Каждое следующее правило вынуждено повторять цепочку и добавлять сверху. Длинный селектор ещё и привязан к структуре DOM: переставили обёртку — стиль отвалился. Плоская специфичность — один-два класса на селектор, без id в стилях — делает порядок предсказуемым. Как это организуют на уровне проекта — в [CSS-архитектуре](/content/css/architecture).

## !important

`!important` не повышает специфичность, а переносит объявление в другую группу каскада — важную. Внутри неё снова работают слои, специфичность и порядок. Поэтому `!important` против `!important` — та же война, только на этаж выше. В проверке `button { color: red !important }` победил `#buy.btn.btn-primary` без него.

Оправданных случаев немного:

- **утилиты**, которые обязаны сработать всегда: `.hidden { display: none !important; }`;
- **перебить чужой атрибут `style`**, который ставит сторонний скрипт, когда код скрипта не поправить;
- **пользовательские стили** — для доступности.

Во всех остальных случаях `!important` в своём коде — признак, что не настроен порядок слоёв или раздута специфичность.

## Каскадные слои

Слои добавляют в каскад уровень выше специфичности: сначала сравнивают слой, и только при равенстве — селекторы.

```css
@layer reset, base, components, utilities;

@layer components { #buy.btn { color: red; } }
@layer utilities  { .btn { color: green; } }
```

Кнопка зелёная: поздний слой `utilities` с селектором (0, 1, 0) побеждает (1, 1, 0) в раннем. Правила слоёв:

- **порядок задаёт первое упоминание слоя**, а не место блока в файле — поэтому его объявляют одной строкой в начале;
- **стили вне слоёв сильнее любого слоя** — спецификация считает их неявным последним слоем. В проверке простой `button` вне слоёв перебил `#buy.btn.btn-primary` из слоя;
- **важные объявления идут в обратном порядке:** `!important` в раннем слое `reset` сильнее `!important` в позднем `utilities` и сильнее `!important` вне слоёв. Ранний слой так защищает то, что не должно меняться;
- **`revert-layer`** откатывает свойство к значению из предыдущего слоя.

Главное применение — чужой CSS. Библиотека с селектором `.lib-table td.lib-cell` перебивает твой `.price`. Если подключить её в слой, твой стиль вне слоёв победит при любой специфичности библиотеки:

```css
@import url("vendor.css") layer(vendor);
.price { color: green; }
```

В проверке без слоя цена осталась красной, со слоем стала зелёной, а остальные свойства из библиотеки — например, жирность — остались на месте.

## Наследование

Если ни одно объявление к свойству не подошло, значение берётся из наследования или из начального значения. Свойства делятся на две группы:

- **наследуемые** — в основном текстовые: `color`, `font-*`, `line-height`, `letter-spacing`, `text-align`, `visibility`, `cursor`, `list-style`, а также CSS-переменные, если их не зарегистрировали с `inherits: false`;
- **ненаследуемые** — всё про бокс и раскладку: `margin`, `padding`, `border`, `width`, `display`, `position`, `background`, `overflow`, `opacity`, `transform`.

В карточке с `color: green; border: 2px solid red` вложенный `span` получил зелёный текст, но рамки у него нет.

### Ключевые слова

Любому свойству можно явно задать одно из ключевых слов:

| Значение | Что берёт |
| --- | --- |
| `inherit` | значение родителя, даже у ненаследуемого свойства |
| `initial` | начальное значение свойства по спецификации |
| `unset` | `inherit` для наследуемых, `initial` для остальных |
| `revert` | значение из предыдущего происхождения — для стилей автора это обычно стиль браузера |
| `revert-layer` | значение из предыдущего каскадного слоя |

Главная ловушка — `initial`. Это не «стиль браузера», а начальное значение из спецификации. У `display` оно `inline`, поэтому `div { display: initial }` в проверке сделал блок строчным. `display: revert` вернул `block` — стиль браузера для `div`. Сбросить все свойства разом можно через `all: revert` или `all: unset`.

## Вычисленное значение

Победившее в каскаде значение проходит несколько стадий: объявленное, затем вычисленное (computed) — относительные единицы переведены в абсолютные, где это возможно без раскладки, — затем используемое (used) после раскладки. `getComputedStyle` отдаёт для большинства свойств вычисленное значение, а для размеров отрисованного элемента — используемое, поэтому там пиксели. Наследуется именно вычисленное значение, и это объясняет две частые ошибки.

### em и rem

`em` в `font-size` считается от размера шрифта родителя, а в других свойствах — от своего. `rem` — всегда от `font-size` корня, `html`.

```css
.menu { font-size: 1.2em; }
```

Вложенное меню на трёх уровнях получает 16 × 1,2³ = 27,648px — в проверке ровно `27.648px`. С `1.2rem` на любой глубине `19.2px`. Отсюда правило: `rem` — для размеров шрифта и отступов, которые не должны зависеть от места в дереве, `em` — для того, что должно масштабироваться вместе с текстом элемента. Например, `padding: 0.5em` у кнопки с `font-size: 20px` дал `10px`.

### line-height

```css
.article { font-size: 16px; line-height: 1.5em; }
h2 { font-size: 32px; }
```

Строка заголовка внутри статьи в проверке получила `line-height: 24px` — меньше размера шрифта, и строки налезли друг на друга. `1.5em` и `150%` вычисляются у родителя в 24px и наследуются пикселями. Число без единиц, `line-height: 1.5`, наследуется как множитель, и заголовок получил 48px. Поэтому `line-height` задают без единиц.

### Проценты

Процент всегда считается от чего-то своего:

- `width`, `padding`, `margin` — от **ширины** контейнера, даже `padding-top`. В проверке `padding-top: 50%` в контейнере 400×100 дал `200px`. На этом держался старый приём с пропорциями до появления `aspect-ratio`;
- `height` — от высоты контейнера, только если она задана явно;
- `font-size` — от шрифта родителя, `line-height` — от своего шрифта;
- `translate()` в `transform` — от размеров самого элемента.

### Единицы

- `px` — CSS-пиксель, 1/96 дюйма. Сколько физических пикселей экрана в нём, показывает `devicePixelRatio`;
- `em`, `rem` — от размера шрифта;
- `ch` — ширина символа «0», удобна для ширины колонки текста: `max-width: 65ch`;
- `lh` — высота строки элемента;
- `vw`, `vh`, `dvh` и единицы контейнера — в [Адаптивном дизайне](/content/css/rwd).

Функции `calc()`, `min()`, `max()` и `clamp()` смешивают единицы: `width: min(600px, 100%)` — не шире 600px и не шире контейнера.

## Блочная модель

Значения посчитаны — их нужно применить к прямоугольнику. Каждый элемент — бокс из четырёх областей: содержимое, `padding`, `border`, `margin`.

```text
┌──────────── margin ────────────┐
│ ┌────────── border ──────────┐ │
│ │ ┌──────── padding ───────┐ │ │
│ │ │        content         │ │ │
│ │ └────────────────────────┘ │ │
│ └────────────────────────────┘ │
└────────────────────────────────┘
```

Что входит в `width`, решает `box-sizing`:

```css
.box { width: 200px; padding: 20px; border: 2px solid; }
```

- `content-box`, значение по умолчанию, — `width` задаёт только содержимое. В проверке бокс занял 200 + 2·20 + 2·2 = 244px;
- `border-box` — `width` включает `padding` и `border`. Бокс занял ровно 200px, а под содержимое осталось 156px.

С `border-box` сетки считать проще: колонка в 50% с отступами остаётся в 50%. Поэтому его включают для всего документа:

```css
html { box-sizing: border-box; }
*, *::before, *::after { box-sizing: inherit; }
```

Через `inherit` компонент может вернуть себе `content-box`, и это значение унаследуют его потомки. `margin` в размер бокса не входит никогда, а вертикальные отступы соседних блоков ещё и схлопываются — это часть раскладки, разобранной в [Раскладке и потоке](/content/css/flow). `outline` и `box-shadow` рисуются поверх и места не занимают.

## Красные флаги в ответе

- **«Побеждает последнее правило».** Порядок — последний критерий. До него сравнивают важность, слой и специфичность.
- **«Специфичность — число, одиннадцать классов сильнее id».** Счётчики сравнивают по разрядам без переноса: один id сильнее любого числа классов.
- **«`!important` — самый высокий приоритет».** Есть важные стили пользователя, идущие переходы, а в слоях важное в раннем слое сильнее важного в позднем.
- **«Стиль в слое с более сильным селектором победит».** Слой сравнивают раньше специфичности, а стили вне слоёв сильнее всех слоёв.
- **«`initial` возвращает стиль браузера».** Это начальное значение из спецификации: у `display` — `inline`. Стиль браузера возвращает `revert`.
- **«`em` считается от корня».** От корня — `rem`. `em` в `font-size` — от родителя, поэтому накапливается во вложенности.

## Как спрашивают на собеседовании

::question
Как браузер решает, какое правило применить к элементу?

#answer
Каскадом. Объявления сравнивают по очереди: происхождение и важность, контекст Shadow DOM, атрибут `style`, каскадный слой, специфичность, порядок в коде. Следующий критерий смотрят, только если предыдущий не различил объявления.

#more
Происхождений три — браузер, пользователь, автор, — плюс анимации и переходы. Для обычных объявлений автор сильнее пользователя и браузера, для важных порядок обратный, чтобы пользовательские стили доступности нельзя было перебить. Анимация сильнее обычных стилей автора, но слабее важных. Если ни одно объявление не подошло, работает наследование или начальное значение.
::

::question
Как считается специфичность? Что сильнее: один id или одиннадцать классов?

#answer
Три счётчика: id; классы, атрибуты и псевдоклассы; типы и псевдоэлементы. Сравнивают слева направо без переноса, поэтому один id сильнее любого количества классов.

#more
`*` и комбинаторы не считаются. `:is()`, `:not()` и `:has()` берут специфичность самого сильного аргумента, даже если элемент совпал по другому: `:is(#nope, .btn)` весит как id. `:where()` всегда ноль — на нём строят сбросы, которые легко переопределить. `[id="x"]` — атрибут, слабее `#x`.

#followups
- «Какая специфичность у атрибута `style`?» → Никакой: он сравнивается отдельным шагом раньше специфичности и сильнее любого селектора той же важности.
::

::question
Как работает !important и когда он оправдан?

#answer
Он переносит объявление в группу важных, которая сильнее обычных независимо от специфичности. Внутри группы снова работают слои, специфичность и порядок. Оправдан в утилитах вроде `.hidden`, против чужого атрибута `style` и в пользовательских стилях доступности.

#more
Порядок для важных объявлений перевёрнут: пользователь сильнее автора, ранний каскадный слой сильнее позднего, важное в слое сильнее важного вне слоёв. Внутри `@keyframes` `!important` игнорируется. Если в своём коде нужен `!important`, проблема обычно в специфичности или порядке подключения.
::

::question
Что дают каскадные слои? Почему стили вне слоёв сильнее?

#answer
`@layer` задаёт порядок групп стилей, и он сравнивается раньше специфичности: правило в позднем слое побеждает правило в раннем, какими бы ни были селекторы. Стили вне слоёв спецификация считает последним неявным слоем, поэтому они сильнее всех.

#more
Порядок задаёт первое упоминание: `@layer reset, base, components, utilities;` в начале файла. CSS библиотеки подключают через `@import url(lib.css) layer(vendor)` — и свои стили выигрывают без повышения специфичности. Для `!important` порядок обратный, а `revert-layer` откатывает свойство к предыдущему слою.
::

::question
Чем отличаются inherit, initial, unset и revert?

#answer
`inherit` берёт значение родителя. `initial` — начальное значение из спецификации. `unset` ведёт себя как `inherit` у наследуемых свойств и как `initial` у остальных. `revert` откатывает к предыдущему происхождению — для стилей автора это стиль браузера.

#more
`initial` часто путают со стилем браузера: `display: initial` у `div` даёт `inline`, а `display: revert` — `block`. Есть ещё `revert-layer` для каскадных слоёв. Сбросить всё разом — `all: revert` или `all: unset`. Наследуются в основном текстовые свойства и CSS-переменные, свойства бокса — нет.
::

::question
Чем em отличается от rem? Почему getComputedStyle возвращает пиксели?

#answer
`rem` считается от размера шрифта `html`, `em` — от размера шрифта родителя в `font-size` и от своего в остальных свойствах. Поэтому `em` в `font-size` накапливается во вложенных элементах, а `rem` — нет.

#more
`getComputedStyle` возвращает вычисленное значение, где относительные единицы уже переведены в пиксели, а для размеров отрисованного элемента — используемое, после раскладки. Наследуется тоже вычисленное значение: `line-height: 1.5em` у родителя превращается в пиксели и не подстраивается под крупный шрифт потомка, а множитель `1.5` пересчитывается у каждого.
::

::question
Чем box-sizing: content-box отличается от border-box?

#answer
В `content-box`, значении по умолчанию, `width` — только содержимое, а `padding` и `border` добавляются сверху: 200px ширины с отступами 20px и рамкой 2px дают 244px. В `border-box` `width` включает `padding` и `border`, бокс ровно 200px.

#more
`border-box` включают глобально: `html { box-sizing: border-box }` и `*, *::before, *::after { box-sizing: inherit }`. `margin` в размер не входит ни в одном режиме, `outline` и `box-shadow` места не занимают. `padding` в процентах считается от ширины контейнера даже по вертикали.
::

## Практика

::practice{title="Что выведет?"}
Какого цвета будет кнопка?

```html
<div class="card"><button class="btn">Купить</button></div>
```

```css
:where(.card) .btn { color: red; }
.card :where(.btn) { color: blue; }
:is(.card, #main) button { color: green; }
```

#solution
Зелёная. Специфичность первых двух правил — (0, 1, 0): `:where()` обнуляет только своё содержимое, а класс снаружи считается. У третьего `:is(.card, #main)` весит как самый сильный аргумент, `#main`, хотя такого элемента нет, плюс `button`: (1, 0, 1). Оно побеждает, несмотря на то что `.btn` в нём нет. Если нужен стиль, который любой класс переопределит, весь селектор оборачивают в `:where()`:

```css
:where(.card button) { color: green; }  /* (0, 0, 0) */
.btn { color: red; }                    /* победит */
```

В проверке в Chromium кнопка получила `rgb(0, 128, 0)`.
::

::practice{title="Стили библиотеки перебивают свои"}
Цена в таблице из UI-библиотеки должна быть зелёной, но остаётся красной:

```css
/* vendor.css */
.lib-table td.lib-cell { color: red; font-weight: 700; }

/* app.css */
@import url("vendor.css");
.price { color: green; }
```

#solution
У селектора библиотеки специфичность (0, 2, 2), у `.price` — (0, 1, 0). Повышать свою специфичность или ставить `!important` — путь к войне. Библиотеку кладут в каскадный слой:

```css
@import url("vendor.css") layer(vendor);
.price { color: green; }
```

Стили вне слоёв сильнее любого слоя, поэтому `.price` побеждает при любой специфичности библиотеки. В проверке цена стала зелёной, а `font-weight: 700` из библиотеки сохранился. В большом проекте объявляют весь порядок сразу: `@layer reset, vendor, base, components, utilities;` и раскладывают по слоям и свои стили.
::

::practice{title="Шрифт растёт с вложенностью"}
В многоуровневом меню пункты третьего уровня заметно крупнее первого:

```css
html { font-size: 16px; }
.menu { font-size: 1.2em; }
```

#solution
`em` в `font-size` считается от размера шрифта родителя, а вложенное `.menu` — потомок другого `.menu`. Размер умножается на 1,2 на каждом уровне: 19,2px, 23,04px, 27,648px. Нужен размер от корня:

```css
.menu { font-size: 1.2rem; }  /* 19.2px на любой глубине */
```

В проверке третий уровень с `em` получил `27.648px`, с `rem` — `19.2px`. `em` оставляют там, где масштаб от родителя и нужен: отступы внутри кнопки, иконка размером с текст.
::
