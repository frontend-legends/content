# Адаптивный дизайн

Адаптивный дизайн — один сайт, который подстраивается под любой экран, способ ввода и настройки пользователя. Спрашивают, зачем `meta viewport`, что такое mobile-first, чем container queries отличаются от media queries и почему `100vh` на телефоне больше экрана. Глубже — почему меню ломается ровно на 768px, почему шрифт в `vw` не растёт при зуме и почему `container-type: size` схлопывает блок в ноль.

::tldr
- **Без `meta viewport` телефон раскладывает страницу на 980px и уменьшает её.** `width=device-width, initial-scale=1` делает ширину окна равной ширине экрана; запрещать масштабирование нельзя.
- **Mobile-first — базовые стили для узкого экрана, а `min-width` добавляет.** Запросы `max-width: 768px` и `min-width: 768px` пересекаются на самой границе; синтаксис диапазонов `width < 768px` этого не допускает.
- **Container queries реагируют на размер контейнера, а не окна:** одна карточка компактная в сайдбаре и широкая в основной колонке. Контейнер не может запрашивать сам себя, а `container-type: size` без высоты схлопывает его в ноль.
- **На телефоне `100vh` — высота окна со спрятанной панелью браузера.** `svh` — с видимой, `lvh` — со спрятанной, `dvh` меняется вслед за панелью.
- **Размер шрифта только в `vw` не растёт при зуме,** а это требование доступности. В `clamp()` смешивают `rem` и `vw`: `clamp(1rem, 0.75rem + 1.5vw, 3rem)`.
::

## Окно просмотра

Сквозной пример — интернет-магазин: меню, которое на телефоне сворачивается в кнопку, карточка товара в сайдбаре и в основной колонке, баннер на всю ширину, карусель с акциями.

Первое, что проверяют на телефоне, — строка в `<head>`:

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

Без неё мобильный браузер считает, что страница сделана для десктопа: раскладывает её на ширину около 980px и уменьшает, чтобы она влезла. В проверке на эмуляции телефона шириной 390px `innerWidth` без тега был `980`, с тегом — `390`. Медиазапросы при этом считают ширину по тем же 980px, и мобильные стили не срабатывают вовсе.

`user-scalable=no` и `maximum-scale=1` в этом теге не пишут: людям со слабым зрением нужен зум.

## Медиазапросы

Медиазапрос применяет стили при условии на окно или устройство.

### Mobile-first

| Подход | Запросы | Базовые стили |
| --- | --- | --- |
| mobile-first | `min-width` | для узкого экрана, запросы добавляют |
| desktop-first | `max-width` | для широкого экрана, запросы отменяют |

```css
.nav { display: none; }                 /* на телефоне — кнопка меню */
@media (width >= 768px) {
  .nav { display: flex; }
  .burger { display: none; }
}
```

Mobile-first проще поддерживать: узкий макет — самый простой, обычно одна колонка, а широкий добавляет колонки и панели. При desktop-first мобильные стили отменяют сложное: сбрасывают `grid`, `float`, отступы, и каждое изменение десктопа нужно проверять на отмену. Точки перелома ставят там, где ломается содержимое, а не по размерам конкретных телефонов.

### Синтаксис диапазонов

```css
@media (max-width: 768px) { .nav { flex-direction: column; } }
@media (min-width: 768px) { .nav { display: flex; } }
```

Обе границы включительные, и на ширине ровно 768px срабатывают **оба** запроса. В проверке меню на 768px оказалось одновременно flex-строкой из второго запроса и колонкой из первого. Синтаксис диапазонов из Media Queries Level 4 позволяет писать строгие и нестрогие сравнения:

```css
@media (width < 768px)  { … }
@media (width >= 768px) { … }
@media (768px <= width < 1200px) { … }
```

С ним граница принадлежит ровно одному запросу: на 768px сработал только второй, на 767px — только первый.

### Предпочтения и способ ввода

Медиазапросы спрашивают не только про размер:

| Запрос | Что узнаёт |
| --- | --- |
| `prefers-color-scheme: dark` | тёмная тема в системе |
| `prefers-reduced-motion: reduce` | просьба уменьшить движение |
| `prefers-contrast: more`, `forced-colors: active` | повышенный контраст, режим принудительных цветов |
| `hover: hover`, `pointer: fine` | есть наведение и точный указатель — мышь |
| `hover: none`, `pointer: coarse` | сенсорный экран |

В проверке эмуляция телефона дала `hover: none` и `pointer: coarse`, десктоп — `hover: hover` и `pointer: fine`. Эффекты наведения оборачивают в `@media (hover: hover)`, иначе на телефоне `:hover` срабатывает от касания и «залипает» до следующего. Зоны касания на `pointer: coarse` делают крупнее. Как анимации уважают `prefers-reduced-motion` — в [Анимациях](/content/css/animations).

## Container queries

Медиазапрос знает размер окна, но не знает, куда попал компонент. Карточка товара в сайдбаре шириной 300px и в основной колонке шириной 800px на одном экране получила бы одну раскладку. **Container queries** спрашивают размер ближайшего контейнера:

```css
.slot { container-type: inline-size; }

.card { display: block; }
@container (width > 500px) {
  .card { display: grid; grid-template-columns: 200px 1fr; }
}
```

В проверке одна и та же карточка в сайдбаре осталась блоком, а в основной колонке стала сеткой — без JavaScript и без знания о странице. Контейнеру можно дать имя — `container-name: sidebar` и `@container sidebar (…)`, — чтобы запрос не нашёл ближайший неподходящий контейнер.

Единицы контейнера — `cqi` и `cqb` (1% размера по строке и по блоку), `cqw` и `cqh` — работают как `vw`, но от контейнера. `font-size: clamp(16px, 5cqi, 32px)` в проверке дал 16px в сайдбаре и 32px в колонке.

### Ограничения

- **Контейнер не может запрашивать сам себя.** Правило внутри `@container` действует на потомков: в проверке `.card` с `container-type` и запросом на саму `.card` не изменилась, а её абзац — изменился. Поэтому компонент оборачивают: контейнер — обёртка, стили — внутри.
- **`container-type: size` включает изоляцию размера по обеим осям:** высота контейнера больше не зависит от содержимого. Без явной высоты он схлопывается — в проверке боковая панель с `size` получила высоту 0. Для запросов по ширине нужен `inline-size`.
- `inline-size` тоже изолирует, но только ширину: она больше не зависит от детей. В проверке `inline-block` с `container-type: inline-size` и без заданной ширины сжался в ноль.

Есть и запросы к стилю контейнера — `@container style(--variant: compact)`: компонент меняет вид по CSS-переменной предка.

| | Media queries | Container queries |
| --- | --- | --- |
| реагируют на | окно, устройство, предпочтения | размер или стиль контейнера |
| уровень | страница | компонент |
| для чего | раскладка страницы, тема, ввод | переиспользуемые компоненты |

## Единицы окна

`vw` и `vh` — 1% ширины и высоты окна, `vmin` и `vmax` — от меньшей и большей стороны.

### 100vh на телефоне

На телефоне высота видимой области меняется: адресная строка прячется при прокрутке. Какую высоту брать за `vh`, решает браузер, и мобильные браузеры берут **большую** — со спрятанной панелью. Поэтому блок `height: 100vh` на первом экране выше видимой области, и кнопка внизу оказывается под панелью.

| Единица | Высота окна |
| --- | --- |
| `svh` | маленькая: панель браузера видна |
| `lvh` | большая: панель спрятана |
| `dvh` | текущая: меняется вслед за панелью |

На десктопе панели нет, и все четыре совпадают — в проверке `100vh`, `100svh`, `100lvh` и `100dvh` дали по 800px. Первый экран, который должен влезть целиком, делают через `min-height: 100svh`. `dvh` точнее, но при каждом появлении панели пересчитывает раскладку. Те же три варианта есть у ширины и сторон: `svw`, `dvi` и другие.

### 100vw и полоса прокрутки

`vw` включает ширину вертикальной полосы прокрутки. Там, где полоса занимает место, — Windows, Linux, macOS с подключённой мышью, — баннер `width: 100vw` шире страницы на её ширину и даёт горизонтальную прокрутку. В проверке с полосой в 15px так и вышло, а с `width: 100%` прокрутка исчезла. На всю ширину растягивают через `100%` или выносят блок из ограниченного контейнера.

## Плавные размеры

Чтобы шрифт и отступы росли с экраном без ступенек медиазапросов, их задают через `clamp(минимум, желаемое, максимум)`:

```css
h1 { font-size: clamp(1rem, 0.75rem + 1.5vw, 3rem); }
section { padding: clamp(1rem, 3vw, 4rem); }
```

На экране 320px заголовок получил 16,8px (12 + 4,8), на 2560px желаемые 50,4px упёрлись в максимум 48px. Между ними размер растёт плавно.

### Зум

Требование доступности: текст должен увеличиваться при зуме до 200%. Зум в браузере уменьшает ширину окна в CSS-пикселях и увеличивает плотность. Размер только в `vw` при этом не меняется физически: окно в CSS-пикселях стало вдвое уже, и `4vw` стал вдвое меньше. Эмуляция зума 200% в проверке — та же физическая ширина, вдвое больше плотность — дала заголовку `4vw` те же 51,2 физических пикселя, что и без зума. `1.5rem` вырос с 24 до 48, а смесь `0.75rem + 1.5vw` — заметно выросла. Поэтому в желаемом значении `clamp()` всегда есть слагаемое в `rem`.

Многие задачи решаются вообще без запросов — **внутренней адаптивностью** раскладки: `repeat(auto-fit, minmax(200px, 1fr))` в Grid и `flex-wrap: wrap` сами меняют число колонок (подробно — в [Раскладке и потоке](/content/css/flow)). Картинки делают гибкими через `max-width: 100%; height: auto`, а разные размеры файлов для разных экранов отдают через `srcset` и `sizes` — это в [Оптимизации ресурсов](/content/security-perfomance/asset-optimization).

## Логические свойства

`margin-left` всегда слева. В арабском и иврите текст идёт справа налево, и «начало строки» — справа. Логические свойства описывают направление относительно текста:

| Физическое | Логическое |
| --- | --- |
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` |
| `margin-top` / `margin-bottom` | `margin-block-start` / `margin-block-end` |
| `padding-left` и `padding-right` | `padding-inline` |
| `width` / `height` | `inline-size` / `block-size` |
| `top`, `right`, `bottom`, `left` | `inset-block`, `inset-inline`, `inset` |
| `text-align: left` | `text-align: start` |

В проверке карточка с `margin-inline-start: 40px` и `border-inline-start` в `dir="rtl"` получила отступ и рамку справа, а `padding-inline: 10px 30px` — 10px справа. Соседняя с физическим `margin-left` так и осталась с отступом слева. С логическими свойствами отдельный CSS для RTL не нужен, а при вертикальном письме `writing-mode` они поворачиваются вместе с текстом. Как ещё готовят интерфейс к RTL — в [i18n](/content/ecosystem-libs/i18n).

## Прокрутка с привязкой

Карусели акций и галереи раньше писали на JavaScript. **Scroll snap** останавливает прокрутку на заданных точках:

```css
.carousel { display: flex; overflow-x: auto; scroll-snap-type: x mandatory; }
.slide    { flex: none; width: 300px; scroll-snap-align: start; }
```

`mandatory` всегда доводит до точки, `proximity` — только если прокрутка остановилась рядом. В проверке прокрутка карусели до 420px остановилась на 300px — ближайшем начале слайда.

| Свойство | Где | Что делает |
| --- | --- | --- |
| `scroll-snap-type` | контейнер | ось и строгость |
| `scroll-snap-align` | элемент | какая часть прилипает: `start`, `center`, `end` |
| `scroll-padding` | контейнер | отступ области привязки от края |
| `scroll-margin` | элемент | отступ вокруг элемента при привязке |
| `overscroll-behavior: contain` | контейнер | прокрутка не передаётся странице после края |

`scroll-padding` решает и другую задачу: переход по якорю прячет заголовок под фиксированной шапкой. С `html { scroll-padding-top: 80px }` в проверке заголовок после `scrollIntoView()` встал на 80px, сразу под шапкой.

## Красные флаги в ответе

- **«`meta viewport` — для SEO».** Без него телефон раскладывает страницу на 980px, и мобильные медиазапросы не срабатывают.
- **«Точки перелома — 375, 768 и 1024, по устройствам».** Их ставят там, где ломается содержимое, а `max-width` и `min-width` с одним числом пересекаются на границе.
- **«Container queries — это media queries для элемента».** Контейнер не видит сам себя, запрос работает для потомков, а `size` требует явной высоты.
- **«`100vh` — это высота экрана телефона».** Это большая высота окна со спрятанной панелью; видимую дают `svh` и `dvh`.
- **«`font-size: 4vw` — адаптивный шрифт».** Он не растёт при зуме; в формуле нужна часть в `rem`.
- **«`width: 100vw` — на всю ширину».** `vw` включает полосу прокрутки и даёт горизонтальную прокрутку.

## Как спрашивают на собеседовании

::question
Зачем нужен meta viewport? Что будет без него?

#answer
Он говорит мобильному браузеру, что страница рассчитана на ширину экрана: `width=device-width, initial-scale=1`. Без него браузер раскладывает страницу на ширину около 980px и уменьшает, текст становится мелким, а медиазапросы считают по 980px и мобильные стили не срабатывают.

#more
`user-scalable=no` и `maximum-scale=1` не используют: зум нужен людям со слабым зрением, и его запрет нарушает требования доступности. Проверяют на реальном телефоне или в эмуляции DevTools: на ней видно, чему равен `innerWidth`.
::

::question
Что такое mobile-first и почему запросы через min-width?

#answer
Базовые стили пишут для самого узкого экрана, а медиазапросы с `min-width` добавляют колонки и панели для широких. Узкий макет самый простой, поэтому запросы только добавляют, а не отменяют сложное, как при desktop-first.

#more
`max-width: 768px` и `min-width: 768px` пересекаются на ширине ровно 768px — срабатывают оба. Синтаксис диапазонов `width < 768px` и `width >= 768px` делит границу однозначно. Точки перелома выбирают по содержимому. Эффекты наведения оборачивают в `@media (hover: hover)`, чтобы `:hover` не залипал от касания.
::

::question
Чем container queries отличаются от media queries? Какие у них ограничения?

#answer
Media queries реагируют на окно и устройство, container queries — на размер ближайшего контейнера с `container-type`. Так компонент сам выбирает раскладку по месту: карточка компактная в сайдбаре и широкая в основной колонке на одном экране.

#more
Контейнер не может запрашивать себя — стили меняются только у потомков, поэтому нужна обёртка. `container-type: size` изолирует размер по обеим осям, и без явной высоты контейнер схлопывается — для запросов по ширине берут `inline-size`. Есть единицы `cqi`, `cqb`, имена контейнеров и запросы к стилю — `@container style(--variant: compact)`.
::

::question
Почему 100vh на телефоне больше экрана? Чем svh, lvh и dvh отличаются?

#answer
Мобильные браузеры считают `vh` от большой высоты окна — со спрятанной адресной строкой. Когда панель видна, блок высотой `100vh` выходит за экран. `svh` — высота с видимой панелью, `lvh` — со спрятанной, `dvh` — текущая, меняется вслед за панелью.

#more
Первый экран, который должен влезть целиком, задают `min-height: 100svh`. `dvh` точнее, но пересчитывает раскладку при каждом появлении и скрытии панели. На десктопе все четыре одинаковы. Похожая ловушка у `100vw`: он включает полосу прокрутки и даёт горизонтальную прокрутку там, где полоса занимает место.
::

::question
Как сделать плавный размер шрифта и не сломать зум?

#answer
Через `clamp(минимум, желаемое, максимум)`: `clamp(1rem, 0.75rem + 1.5vw, 3rem)`. Желаемое значение растёт с шириной окна, а пределы не дают шрифту стать слишком мелким или огромным.

#more
Зум уменьшает ширину окна в CSS-пикселях, поэтому размер только в `vw` физически не растёт при зуме — нарушение требования увеличивать текст до 200%. Слагаемое в `rem` в желаемом значении растёт с зумом. Для размеров внутри компонента вместо `vw` берут единицы контейнера `cqi`.
::

::question
Зачем нужны логические свойства?

#answer
Они описывают направления относительно письма, а не экрана: `margin-inline-start` вместо `margin-left`, `inline-size` вместо `width`. В языках с письмом справа налево `margin-inline-start` сам становится правым отступом, и отдельный CSS для RTL не нужен.

#more
При вертикальном письме `writing-mode` логические свойства поворачиваются вместе с текстом. Сокращения `margin-inline`, `padding-block`, `inset` делают код короче. `text-align: start` выравнивает по началу строки в любом направлении.
::

::question
Как сделать карусель без JavaScript?

#answer
Scroll snap: контейнеру `overflow-x: auto` и `scroll-snap-type: x mandatory`, слайдам `scroll-snap-align: start`. Прокрутка пальцем, колёсиком или из кода останавливается на ближайшем начале слайда.

#more
`proximity` вместо `mandatory` доводит до точки, только если прокрутка остановилась рядом. `scroll-padding` сдвигает область привязки — тот же приём не даёт фиксированной шапке закрыть заголовок при переходе по якорю. `overscroll-behavior: contain` не отдаёт прокрутку странице, когда карусель кончилась. Кнопки «вперёд» и «назад» всё равно нужны — для клавиатуры и мыши без колёсика.
::

## Практика

::practice{title="Меню ломается ровно на 768px"}
На планшете шириной ровно 768px меню вытянулось в колонку, хотя на 769px оно в строку, а на 767px — свёрнуто в кнопку:

```css
@media (max-width: 768px) {
  .nav { flex-direction: column; }
  .burger { display: block; }
}
@media (min-width: 768px) {
  .nav { display: flex; }
  .burger { display: none; }
}
```

#solution
Обе границы включительные, и на 768px срабатывают оба запроса. Свойства, которые есть в обоих, решает порядок, а остальные складываются: меню стало flex-колонкой. Синтаксис диапазонов делит границу однозначно:

```css
.nav { display: flex; flex-direction: column; }
@media (width >= 768px) {
  .nav { flex-direction: row; }
  .burger { display: none; }
}
```

Заодно стили стали mobile-first: база — для узкого экрана, запрос только добавляет. В проверке в Chromium на 768px с исходным CSS меню было `display: flex` и `flex-direction: column`, а с диапазонами на 768px сработал только широкий вариант, на 767px — только узкий.
::

::practice{title="Сайдбар исчез после container queries"}
Чтобы карточка адаптировалась к сайдбару, сайдбар сделали контейнером. После этого фильтры наложились на подвал страницы, а у сайдбара нулевая высота:

```css
.sidebar { container-type: size; }
@container (width < 400px) { .card { flex-direction: column; } }
```

#solution
`container-type: size` изолирует размер по обеим осям: высота контейнера больше не зависит от содержимого, и без явной высоты он схлопывается в ноль, а содержимое вылезает. Запрос здесь только по ширине — нужен `inline-size`:

```css
.sidebar { container-type: inline-size; container-name: sidebar; }
@container sidebar (width < 400px) { .card { flex-direction: column; } }
```

В проверке блок с `size` получил высоту 0, а с `inline-size` — высоту содержимого. Имя контейнера защищает от случая, когда ближайшим контейнером окажется другая обёртка.
::

::practice{title="Горизонтальная прокрутка на Windows"}
На Mac всё хорошо, а у пользователей Windows на главной появилась горизонтальная прокрутка на пару десятков пикселей:

```css
.promo-banner { width: 100vw; }
```

#solution
`100vw` — ширина окна вместе с вертикальной полосой прокрутки. На Mac с трекпадом полоса накладывается поверх страницы и места не занимает, а в Windows занимает около 15–17px — на столько баннер и шире страницы. В проверке с полосой в 15px документ стал шире окна, а с `100%` прокрутка исчезла:

```css
.promo-banner { width: 100%; }
```

Если баннер лежит в контейнере с ограниченной шириной и должен выйти на всю ширину, его выносят из контейнера в разметке или делают контейнер сеткой с полноширинной областью, а не растягивают через `100vw`.
::
