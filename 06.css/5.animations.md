# Анимации и переходы

Механика CSS-анимаций: когда запускается переход, что и как можно анимировать, ключевые кадры и их заполнение, функции плавности, события и анимации по прокрутке. Спрашивают, чем `transition` отличается от `animation`, что делает `animation-fill-mode` и как анимировать появление из `display: none` и раскрытие до `height: auto`. Глубже — почему вставленный в DOM тост появляется без анимации, почему `transitionend` приходит дважды или не приходит вовсе и почему после `forwards` элемент не слушается классов.

::tldr
- **Переход запускается, только когда вычисленное значение меняется между двумя пересчётами стиля.** Элемент, вставленный в DOM и сразу получивший класс, появляется без анимации: у браузера нет состояния «до». Его задают через `@starting-style`.
- **`transitionend` приходит на каждое свойство отдельно и не приходит, если длительность 0s.** Переход нулевой длительности не стартует вовсе, поэтому в режиме уменьшения движения ставят `0.01ms`, а не `0s`.
- **Дискретные свойства переключаются, а не плавно меняются.** `display: none` анимируют через `transition-behavior: allow-discrete` и `@starting-style`, `height: auto` — через `interpolate-size` или сетку `0fr → 1fr`, CSS-переменную — после регистрации через `@property`.
- **Анимация сильнее обычных стилей,** а `animation-fill-mode: forwards` держит последний кадр после конца. Классы на элементе после такой анимации ничего не меняют, пока анимацию не снять.
- **Анимации по прокрутке — `animation-timeline: scroll()` и `view()` — работают без JavaScript.** Сокращение `animation` сбрасывает `animation-timeline`, поэтому таймлайн пишут после него.
::

## Переход

Сквозной пример — интернет-магазин: тост «Добавлено в корзину», выезжающая панель корзины, аккордеон вопросов о доставке и полоска прогресса чтения.

**Переход** (transition) плавно меняет свойство, когда меняется его значение: наведение, фокус, новый класс.

```css
.toast {
  opacity: 0;
  transform: translateY(20px);
  transition: opacity 200ms ease-out, transform 200ms ease-out;
}
.toast.show { opacity: 1; transform: none; }
```

Сокращение — `transition: свойство длительность функция задержка`, несколько переходов через запятую. `transition: all` подхватывает любое изменённое свойство, в том числе то, которое анимировать не собирались, поэтому свойства перечисляют явно.

### Когда переход стартует

Браузер запускает переход, когда при очередном пересчёте стиля вычисленное значение отличается от прошлого. Если прошлого значения не было, переходить не из чего:

```js
const toast = document.createElement('div');
toast.className = 'toast';
document.body.append(toast);
toast.classList.add('show');   // тост сразу виден, без анимации
```

Вставка и добавление класса попали в один пересчёт стиля: для браузера тост родился с `opacity: 1`. В проверке у такого элемента `getAnimations()` вернул пустой массив. Если между шагами прочитать стиль — `getComputedStyle(toast).opacity` или `toast.offsetWidth`, — браузер пересчитает стиль с `opacity: 0`, и переход запустится: в проверке появилась одна анимация. Это работает, но заставляет считать стиль синхронно. Правильный способ — **`@starting-style`**: стиль «до» для первого появления элемента.

```css
.toast { opacity: 1; transition: opacity 200ms; }
@starting-style { .toast { opacity: 0; } }
```

Теперь просто вставленный тост проявляется — в проверке переход запустился без единой строки JavaScript, кроме вставки.

### События и прерывание

Переход шлёт `transitionrun`, `transitionstart`, `transitionend` и `transitioncancel`, если его прервали. Два свойства поведения, на которых ломается код, ждущий конца анимации:

- **`transitionend` приходит на каждое свойство:** при `transition: all` с `opacity` и `transform` обработчик в проверке сработал дважды, по разу на свойство. Фильтруют по `event.propertyName`;
- **переход нулевой длительности не стартует,** и `transitionend` не приходит вовсе. В проверке с `0s` событий не было, с `0.01ms` — было. Поэтому сброс для `prefers-reduced-motion` пишут как `transition-duration: 0.01ms`, иначе код, ждущий события, повиснет.

Если переход прервать на середине обратным изменением, браузер не гоняет элемент полную длительность назад. Обратный переход укорачивается пропорционально пройденному пути: панель корзины, закрытая на середине открытия за 1000 мс, в проверке получила обратный переход длительностью 500 мс.

## Что можно анимировать

Чтобы анимировать свойство, браузеру нужно уметь вычислить промежуточное значение. По этому признаку свойства делятся на три вида:

| Вид | Как меняется | Примеры |
| --- | --- | --- |
| интерполируемые | плавно | `opacity`, `transform`, цвета, длины, `box-shadow`, `filter` |
| дискретные | скачком в середине | `font-family`, `object-fit`, `display` в ключевых кадрах |
| не анимируемые | не меняются | `animation-*`, `transition-*` и другие служебные свойства |

У `visibility` особое правило: если одно из значений `visible`, он остаётся видимым на всём протяжении. В проверке переход из `visible` в `hidden` длительностью 1000 мс был видим и на 10 мс, и на 990 мс, а скрылся ровно в конце. Поэтому `opacity` и `visibility` анимируют вместе: элемент плавно гаснет и только потом перестаёт ловить клики.

### display: none

`display` — дискретное свойство, и обычный переход его не анимирует: элемент исчезает мгновенно, и затухание `opacity` не успевает показаться. Два механизма это меняют:

```css
.cart-panel {
  opacity: 1;
  transition: opacity 200ms, display 200ms allow-discrete;
}
.cart-panel.hidden { opacity: 0; display: none; }
@starting-style { .cart-panel { opacity: 0; } }
```

- **`transition-behavior: allow-discrete`** (здесь — ключевое слово в сокращении) разрешает переход дискретного свойства. Для `display` браузер держит видимое значение всю длительность: в проверке сразу после добавления `.hidden` панель оставалась `display: block` с двумя идущими переходами, а `none` стала только в конце. Без `allow-discrete` — сразу `none` и ни одного перехода;
- **`@starting-style`** даёт стартовую прозрачность при обратном появлении из `display: none`.

### height: auto

Аккордеон «Сколько идёт доставка?» должен раскрываться плавно, но переход с `height: 0` на `height: auto` в проверке не запустился: высота сразу стала 120px. `auto` — ключевое слово, и между 0 и ним нечего интерполировать. Способы:

```css
/* 1. разрешить интерполяцию ключевых слов размера */
:root { interpolate-size: allow-keywords; }
.answer { height: 0; overflow: hidden; transition: height 300ms; }
.answer.open { height: auto; }

/* 2. сетка: строка от 0fr до 1fr */
.answer { display: grid; grid-template-rows: 0fr; transition: grid-template-rows 300ms; }
.answer.open { grid-template-rows: 1fr; }
.answer > .inner { overflow: hidden; }
```

Оба способа в проверке дали на середине перехода ровно 60px из 120. Есть и функция `calc-size(auto, size)` для отдельного свойства. Старый приём с `max-height: 1000px` работает хуже: время перехода тратится на весь запас в 1000px, и короткий ответ раскрывается с задержкой и закрывается рывком.

### CSS-переменные

Незарегистрированная CSS-переменная для браузера — строка, и переход между `0deg` и `180deg` в проверке был скачком: в середине уже `180deg`. После регистрации типа через `@property` с `syntax: "<angle>"` на середине получилось `90deg`. Так анимируют угол градиента и другие значения внутри сложных свойств (подробно об `@property` — в [Современном CSS](/content/css/modern-css)).

## Ключевые кадры

Переход знает только «было» и «стало». Для многошаговых, повторяющихся или запускаемых сами по себе анимаций есть `@keyframes`:

```css
@keyframes pulse {
  0%, 100% { transform: scale(1); }
  50% { transform: scale(1.1); }
}
.cart-badge { animation: pulse 600ms ease-in-out 2; }
```

| Свойство | Что задаёт |
| --- | --- |
| `animation-name` | имя `@keyframes` |
| `animation-duration`, `animation-delay` | длительность и задержка |
| `animation-timing-function` | функция плавности, может меняться внутри кадров |
| `animation-iteration-count` | число повторов, `infinite` |
| `animation-direction` | `normal`, `reverse`, `alternate` — туда и обратно |
| `animation-fill-mode` | стиль до начала и после конца |
| `animation-play-state` | `running` или `paused` |
| `animation-timeline` | время или прокрутка, ниже |

Если в `@keyframes` нет кадра `from` или `to`, его берут из текущего стиля элемента. События — `animationstart`, `animationiteration`, `animationend`, `animationcancel`.

### fill-mode

| `animation-fill-mode` | Во время задержки | После конца |
| --- | --- | --- |
| `none` | свой стиль | свой стиль |
| `backwards` | первый кадр | свой стиль |
| `forwards` | свой стиль | последний кадр |
| `both` | первый кадр | последний кадр |

Анимации стоят в каскаде выше обычных объявлений автора (подробно — в [Каскаде](/content/css/styling)). Поэтому `forwards` не просто «оставляет элемент в конечном состоянии», а продолжает перекрывать любые обычные стили:

```css
@keyframes fade-out { to { opacity: 0; } }
.toast.closing { animation: fade-out 200ms forwards; }
.toast.visible { opacity: 1; }   /* не поможет */
```

В проверке после конца анимации тост остался с `opacity: 0`, и класс с `opacity: 1` ничего не изменил; помог только `animation: none`. А `backwards` полезен с задержкой: без него элемент с анимацией появления `from { opacity: 0.2 }` и задержкой 5 секунд во время задержки был полностью виден, с ним — сразу получил `0.2`.

### transition или animation

- **`transition`** — реакция на смену состояния: наведение, класс, открытие. Два значения и обратный путь бесплатно.
- **`animation`** — сценарий: несколько шагов, повторы, запуск без смены состояния — индикатор загрузки, пульсация, появление при загрузке страницы.

## Функции плавности

Функция плавности переводит долю прошедшего времени в долю пути:

| Функция | Поведение | Для чего |
| --- | --- | --- |
| `ease` | быстрый разгон, плавный конец; по умолчанию | универсально |
| `ease-out` | резкий старт, медленный конец | появление: элемент «прилетает» и тормозит |
| `ease-in` | медленный старт | уход: элемент разгоняется и исчезает |
| `ease-in-out` | плавно с обеих сторон | перемещения по экрану, циклы |
| `linear` | равномерно | вращение, прогресс |
| `cubic-bezier(x1, y1, x2, y2)` | своя кривая Безье | значения `y` больше 1 дают «перелёт» |
| `steps(n, jump-end)` | n скачков | покадровые спрайты, мигающий курсор |
| `linear(…)` | кусочно-линейная по точкам | отскок и пружина |

`steps(4)` по умолчанию `jump-end`: значение меняется в конце каждого шага. На 300 мс из 1000 полоса шириной 400px в проверке была 100px, а с `jump-start` — уже 200px: первый скачок в самом начале.

`linear()` задаёт кривую точками. `linear(0, 0.25 75%, 1)` за первые 75% времени проходит четверть пути — в проверке на середине 66,67px из 400. А точки выше единицы дают перелёт: `linear(0, 1.2 60%, 0.95 80%, 1)` на 60% времени поставил полосу на 480px из 400. Так делают пружины и отскоки без JavaScript; точки генерируют онлайн-инструментами из физической модели.

## Плавность

Плавность анимации зависит от свойства. `transform` и `opacity` браузер меняет на этапе композиции, часто в отдельном потоке, — анимация не дёргается, даже когда основной поток занят. `width`, `height`, `top`, `left`, `margin` пересчитывают раскладку на каждом кадре, а цвета и тени — отрисовку. Поэтому панель корзины выезжает через `transform: translateX()`, а не через `right`. Почему так и как это проверять — в [Производительности выполнения](/content/security-perfomance/runtime-performance), а как ту же задачу решают библиотеки и Web Animations API — в [Анимациях из экосистемы](/content/ecosystem-libs/animation).

Там же — про уважение к настройке «уменьшить движение»: `@media (prefers-reduced-motion: reduce)` отключает перемещения и параллакс, оставляя мягкие изменения прозрачности.

## Анимации по прокрутке

Ключевые кадры можно привязать не ко времени, а к прокрутке. Полоска прогресса чтения статьи о доставке:

```css
@keyframes grow { from { transform: scaleX(0); } to { transform: scaleX(1); } }

.progress {
  position: fixed; top: 0; left: 0; width: 100%; height: 4px;
  transform-origin: left;
  animation: grow linear both;
  animation-timeline: scroll();
}
```

`scroll()` берёт прогресс ближайшего контейнера прокрутки — здесь страницы. В проверке на середине прокрутки полоса была `scaleX(0.5)`.

`view()` — прогресс видимости самого элемента в области прокрутки, а `animation-range` выбирает участок:

```css
.card {
  animation: appear linear both;
  animation-timeline: view();
  animation-range: entry 0% entry 100%;
}
```

Карточка в проверке была прозрачной до входа в окно, наполовину видимой, когда въехала наполовину своей высоты, и полностью видимой после входа. Раньше это делали через `IntersectionObserver` и обработчики прокрутки.

Порядок свойств здесь важен. Сокращение `animation` сбрасывает все `animation-*`, включая `animation-timeline`. Если таймлайн написать до сокращения, он потеряется:

```css
.progress {
  animation-timeline: scroll();
  animation: grow 1ms linear both;   /* сбросил timeline в auto */
}
```

В проверке `animation-timeline` стал `auto`, анимация отработала по времени за 1 мс, и полоса сразу заполнилась.

## View Transitions

View Transitions API анимирует смену состояния или страницы целиком: браузер снимает снимок «до», применяет изменения и плавно переводит в «после». Как запускать и где они нужны — в [Анимациях из экосистемы](/content/ecosystem-libs/animation). Со стороны CSS важны две вещи:

- **`view-transition-name`** связывает элементы «до» и «после»: картинка товара в каталоге и на странице товара с одним именем перелетает на новое место. Имя должно быть **уникальным** на странице: в проверке два элемента с одинаковым `view-transition-name: hero` отменили переход — промис `ready` отклонился с `InvalidStateError`, а DOM обновился без анимации;
- **псевдоэлементы** `::view-transition-old(имя)`, `::view-transition-new(имя)` и `::view-transition-group(имя)` стилизуют переход обычными `@keyframes`.

## Красные флаги в ответе

- **«Добавлю класс сразу после вставки — и будет анимация».** Без состояния «до» переход не стартует; нужен `@starting-style`.
- **«`transitionend` придёт один раз».** Он приходит на каждое свойство и не приходит при нулевой длительности.
- **«`display` анимировать нельзя, только JavaScript».** `transition-behavior: allow-discrete` и `@starting-style` анимируют появление и исчезновение.
- **«`max-height: 9999px` — нормальный способ анимировать высоту».** Время уходит на запас, раскрытие запаздывает; есть `interpolate-size` и `0fr → 1fr`.
- **«`forwards` просто оставляет конечное состояние».** Анимация продолжает перекрывать обычные стили, и классы перестают действовать.
- **«Анимирую `left` и `width`, это то же самое».** Они пересчитывают раскладку на каждом кадре; движение и размер делают через `transform`.

## Как спрашивают на собеседовании

::question
Чем transition отличается от animation?

#answer
`transition` плавно переводит свойство из старого значения в новое, когда значение меняется: наведение, класс, фокус. `animation` проигрывает сценарий из `@keyframes`: несколько шагов, повторы, задержки, запуск без смены состояния.

#more
У перехода два значения и обратный путь бесплатно; прерванный переход возвращается укороченным. У анимации есть `iteration-count`, `direction`, `fill-mode`, `play-state` и таймлайн прокрутки. Анимация стоит в каскаде выше обычных стилей автора, переход — выше всего, пока идёт.
::

::question
Почему переход не срабатывает, когда элемент появляется?

#answer
Переход стартует, только если между двумя пересчётами стиля значение изменилось. Элемент, вставленный в DOM и сразу получивший класс, проходит один пересчёт — «до» у него нет. Стартовое состояние задают через `@starting-style`.

#more
Старый способ — прочитать стиль между вставкой и классом (`getComputedStyle`, `offsetWidth`) или добавить класс в следующем кадре через двойной `requestAnimationFrame`. Он работает, но заставляет браузер синхронно считать стиль. `@starting-style` работает и для появления из `display: none`.
::

::question
Как анимировать display: none и height: auto?

#answer
`display` — дискретное свойство. С `transition: display 200ms allow-discrete` браузер держит видимое значение до конца перехода, а `@starting-style` задаёт стартовый стиль при появлении. `height: auto` анимируют через `interpolate-size: allow-keywords`, `calc-size()` или сетку с `grid-template-rows` от `0fr` до `1fr`.

#more
`max-height` с запасом — плохая замена: время уходит на весь запас, и короткий блок раскрывается с задержкой. `visibility` при переходе из `visible` остаётся видимым до самого конца, поэтому его анимируют вместе с `opacity`. CSS-переменные анимируются только после регистрации через `@property`.
::

::question
Что делает animation-fill-mode? Чем опасен forwards?

#answer
`backwards` применяет первый кадр во время задержки, `forwards` держит последний кадр после конца, `both` — и то и другое, `none` — ничего. `forwards` нужен, чтобы элемент не «прыгнул» обратно после анимации.

#more
Анимации стоят в каскаде выше обычных стилей автора, и после `forwards` значение из последнего кадра продолжает перекрывать любые классы. Элемент «не слушается», пока анимацию не снимут через `animation: none` или пока сам стиль элемента не станет конечным. Надёжнее после `animationend` выставлять конечный стиль классом и убирать анимацию.
::

::question
Почему transitionend не пришёл или пришёл дважды?

#answer
Событие приходит отдельно на каждое анимируемое свойство: при переходе `opacity` и `transform` — два события. А переход нулевой длительности не стартует, и события нет вовсе. Ещё событие не придёт, если переход прервали — тогда приходит `transitioncancel`.

#more
Обработчик фильтруют по `event.propertyName`. В режиме `prefers-reduced-motion` длительность ставят `0.01ms`, а не `0s`, чтобы код, ждущий `transitionend`, не повис. Надёжнее ждать конца через Web Animations API: `el.getAnimations()` и промис `finished`.
::

::question
Что такое cubic-bezier, steps и linear()?

#answer
Функции плавности: доля времени → доля пути. `cubic-bezier()` — своя гладкая кривая, `y` больше 1 даёт перелёт. `steps(n)` — n скачков, по умолчанию в конце каждого шага. `linear()` — кусочно-линейная кривая по точкам.

#more
`ease-out` для появления, `ease-in` для ухода, `linear` для вращения. `steps(4, jump-start)` делает первый скачок сразу. `linear()` с точками выше единицы рисует отскоки и пружины без JavaScript, точки генерируют из физической модели. Функцию можно менять и внутри `@keyframes` для каждого участка.
::

::question
Как сделать анимацию по прокрутке без JavaScript?

#answer
Через `animation-timeline`. `scroll()` привязывает анимацию к прогрессу прокрутки контейнера — полоска чтения статьи. `view()` — к видимости самого элемента, а `animation-range: entry 0% entry 100%` выбирает участок входа в окно.

#more
Сокращение `animation` сбрасывает `animation-timeline`, поэтому таймлайн пишут после него. Для `transform` и `opacity` такие анимации не требуют обработчиков прокрутки и `IntersectionObserver`. Именованные таймлайны `scroll-timeline-name` и `view-timeline-name` вместе с `timeline-scope` на общем предке связывают анимацию с контейнером прокрутки, который не является её предком.
::

## Практика

::practice{title="Тост появляется без анимации"}
Тост «Добавлено в корзину» должен проявляться, но возникает сразу:

```js
const toast = document.createElement('div');
toast.className = 'toast';
toast.textContent = 'Добавлено в корзину';
document.body.append(toast);
toast.classList.add('show');
```

```css
.toast { opacity: 0; transition: opacity 200ms ease-out; }
.toast.show { opacity: 1; }
```

#solution
Вставка и класс попали в один пересчёт стиля, и у браузера нет значения «до» — переход не стартует. В проверке в Chromium `getAnimations()` у такого тоста был пустым. Стартовое состояние описывают в CSS:

```css
.toast { opacity: 1; transition: opacity 200ms ease-out; }
@starting-style { .toast { opacity: 0; } }
```

```js
document.body.append(toast);   // класс show больше не нужен
```

С `@starting-style` переход запустился сразу после вставки. Для браузеров без поддержки тост просто появится без анимации — это безопасное улучшение.
::

::practice{title="Аккордеон раскрывается рывком"}
Ответы в блоке «Доставка» раскрываются мгновенно, а закрываются с задержкой и рывком:

```css
.answer { max-height: 0; overflow: hidden; transition: max-height 400ms; }
.answer.open { max-height: 2000px; }
```

#solution
Переход идёт до 2000px, а реальная высота ответа — 120px, шестнадцатая часть пути. При раскрытии эти 120px проходятся в самом начале перехода — почти мгновенно. При закрытии большая часть времени уходит на спуск от 2000 до 120, когда визуально ничего не меняется, а потом ответ резко схлопывается. Анимируют настоящую высоту:

```css
:root { interpolate-size: allow-keywords; }
.answer { height: 0; overflow: hidden; transition: height 300ms ease-out; }
.answer.open { height: auto; }
```

Или без новых свойств — сеткой:

```css
.answer { display: grid; grid-template-rows: 0fr; transition: grid-template-rows 300ms ease-out; }
.answer.open { grid-template-rows: 1fr; }
.answer > .inner { overflow: hidden; }
```

В проверке оба варианта на середине перехода дали 60px из 120, а `height: 0 → auto` без `interpolate-size` не дал перехода вовсе.
::

::practice{title="Полоска прогресса сразу полная"}
Полоска прогресса чтения должна расти с прокруткой, но с первой секунды заполнена:

```css
.progress {
  transform-origin: left;
  animation-timeline: scroll();
  animation: grow 1ms linear both;
}
```

#solution
Сокращение `animation` сбрасывает все `animation-*` в начальные значения, включая `animation-timeline`. Оно стоит ниже и перетирает `scroll()`, анимация идёт по времени, заканчивается за 1 мс и с `both` держит последний кадр. Таймлайн пишут после сокращения:

```css
.progress {
  transform-origin: left;
  animation: grow linear both;
  animation-timeline: scroll();
}
```

В проверке с исходным порядком `animation-timeline` был `auto`, а полоса — `scaleX(1)`; с исправленным на середине страницы — `scaleX(0.5)`. Длительность для таймлайна прокрутки не нужна.
::
