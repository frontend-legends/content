# Будущее веба

Платформа быстро догоняет то, что раньше делали библиотеки: роутинг, анимированные переходы, всплывающие окна, позиционирование подсказок. Здесь — как новые API попадают в браузеры, разбор нескольких, у которых нет другого дома в книге, и карта остальных со ссылками. Спрашивают, что нового в браузерах и как пользоваться API, которого ещё нет везде. Глубже — чем Navigation API лучше History API для роутинга, почему код после `startViewTransition` видит старый DOM и почему перестановка списка перезагружает iframe.

::tldr
- **Новый API проходит путь от идеи и спецификации через флаги и origin trial до выпуска во всех движках.** Пользуются им с проверкой наличия, как улучшением, а статус смотрят по Baseline.
- **Navigation API — одно событие `navigate` на все переходы:** ссылки, формы, «назад» и «вперёд», переходы из кода и даже `pushState`. `intercept` превращает переход в переход одностраничного приложения без своих обработчиков кликов.
- **Анимированный переход в SPA — Navigation API и `startViewTransition` вместе.** Колбэк обновления выполняется после снимка, позже вызова: код сразу после вызова видит старый DOM.
- **`moveBefore` перемещает узел без потери состояния:** iframe не перезагружается, фокус не теряется. `append` с подключённым узлом — удаление и вставка заново.
- **`URLPattern` — один синтаксис маршрутов в браузере, Service Worker и Node.**
::

## Как новый API попадает в браузер

Сквозной пример — магазин чая, который хочет мгновенные анимированные переходы между каталогом и товаром, не теряя открытую карту доставки.

Спецификации пишут несколько групп: **WHATWG** — HTML, DOM, Fetch, URL; **W3C** — CSS, доступность, многие API устройства; **TC39** — сам JavaScript (подробно о стадиях — во [Введении в JavaScript](/content/javascript/introduction)). Новые идеи сначала обсуждают в WICG: пишут explainer — описание проблемы и решения, — затем прототип за флагом.

- **флаг** — включается вручную в `chrome://flags`, для экспериментов разработчика;
- **origin trial** — сайт получает токен на ограниченный срок и включает API для своих пользователей тегом `meta http-equiv="origin-trial"` или заголовком `Origin-Trial`. Так браузер собирает обратную связь на реальном трафике, не обещая, что API останется;
- **выпуск** в одном движке, затем в остальных; когда функция есть в последних версиях Chrome, Edge, Firefox и Safari, она становится **Baseline**.

Что такое Baseline и Interop, когда библиотека ещё нужна и как писать с прогрессивным улучшением — в [Развитии веб-платформы](/content/modern-dev/web-platform-evolution). Короткое правило: проверять наличие API, а не браузер, и делать так, чтобы без API всё работало, только проще.

```js
if ('navigation' in window) setupNavigationApiRouter();
else setupHistoryRouter();
```

## Navigation API

Роутер одностраничного приложения на History API собирают из кусков:

- клики по ссылкам перехватывают сами: обработчик на `document`, проверка `target`, `download`, клавиш-модификаторов, чужого origin;
- `history.pushState` меняет адрес, но события не вызывает: `popstate` приходит только при «назад» и «вперёд»;
- отправку форм, `location.href = …` и переходы из чужого кода роутер не видит;
- понятия «переход идёт» нет — индикатор загрузки, отмену и обработку ошибок пишут сами.

**Navigation API** даёт одно событие на все переходы документа:

```js
navigation.addEventListener('navigate', (event) => {
  if (!event.canIntercept || event.hashChange || event.downloadRequest) return;
  const url = new URL(event.destination.url);
  const route = matchRoute(url.pathname);
  if (!route) return;
  event.intercept({
    async handler() {
      const data = await route.load({ signal: event.signal });
      render(route, data);
    },
  });
});
```

- **`intercept`** превращает переход в переход SPA: адрес меняется, документ остаётся, а `handler` загружает и рисует экран. В проверке клик по обычной ссылке `a href="/catalog"` дал событие с типом `push`, адрес сменился на `/catalog`, а переменная из старого документа уцелела — перезагрузки не было;
- **«назад» и «вперёд»** приходят тем же событием с типом `traverse`: в проверке после `goBack` обработчик нарисовал главную;
- **переход идёт** — пока `handler` работает, `navigation.transition` не `null`; по завершении приходит `navigatesuccess` или `navigateerror`. `event.signal` отменяется, если начался другой переход: в проверке второй `navigation.navigate` прервал первый — обработчик увидел `signal.aborted`, а промис `finished` первого перехода отклонился с `AbortError`;
- **программный переход** — `navigation.navigate(url, { state })` возвращает промисы `committed` и `finished`. В проверке после `committed` адрес уже был `/cart`, после `finished` — экран нарисован, а `navigation.currentEntry.getState()` вернул переданное состояние;
- **чужой origin** перехватить нельзя: в проверке у ссылки на другой сайт `canIntercept` был `false`;
- **`pushState` тоже виден:** вызов `history.pushState` из старого кода дал событие `navigate` с типом `push`, а `popstate` на него, как и раньше, не пришёл. Поэтому Navigation API можно внедрять постепенно рядом со старым роутером.

`navigation.entries()` возвращает записи истории этого документа одного origin, чего History API не умеет. Где поддерживается — в таблице статусов ниже.

## Анимированные переходы в SPA

Как работает View Transitions API и как стилизовать переход — в [Анимации](/content/ecosystem-libs/animation) и [CSS-анимациях](/content/css/animations). Для многостраничного сайта хватает CSS-правила `@view-transition { navigation: auto; }`. В одностраничном приложении переход начинает код, и естественное место — обработчик `navigate`:

```js
event.intercept({
  async handler() {
    const data = await loadProduct(url);              // сначала данные — пока показан старый экран
    const vt = document.startViewTransition(() => render(data));
    await vt.updateCallbackDone;                      // DOM уже новый
    document.querySelector('h1').focus();
    await vt.finished;                                // анимация закончилась
  },
});
```

Данные загружают **до** `startViewTransition`: пока колбэк выполняется, страница заморожена. В проверке за 300 мс ожидания внутри колбэка браузер отрисовал один кадр вместо 17, а колбэк длиннее 4 секунд отменился с `TimeoutError: Transition was aborted because of timeout in DOM update`.

Колбэк `startViewTransition` выполняется **не сразу**: браузер сначала снимает снимок старого состояния. В проверке сразу после вызова заголовок был ещё «Главная», а после `updateCallbackDone` — «Каталог». Код, который сразу после вызова ищет новые элементы или ставит фокус, работает со старым DOM.

Во фреймворках это уже собрано:

- **React** — компонент `ViewTransition`: он срабатывает на обновления внутри `startTransition`, `Suspense` или `useDeferredValue`, а `startViewTransition` React вызывает сам — вручную его не вызывают, иначе React прервёт чужой переход. React Router рекомендует этот компонент вместо своей старой опции `viewTransition` у ссылок и предупреждает, что включать оба способа сразу нельзя;
- **SvelteKit** — `onNavigate`: если колбэк вернёт промис, роутер дождётся его перед завершением перехода, и внутри вызывают `startViewTransition`.

## moveBefore

Перестановка уже подключённого узла через `append`, `insertBefore` или `replaceChildren` — это удаление и вставка заново. Браузер сбрасывает всё, что живёт, пока узел в документе:

- iframe перезагружается;
- фокус и выделение теряются;
- CSS-анимации и переходы начинаются заново;
- кастомные элементы получают `disconnectedCallback` и `connectedCallback`.

`parent.moveBefore(node, reference)` перемещает узел атомарно, сохраняя состояние. В проверке блок с картой доставки в iframe и полем поиска с фокусом переставили двумя способами: после `moveBefore` iframe не загрузился заново и фокус остался в поле, после `append` — iframe перезагрузился, а фокус ушёл. Кастомный элемент, у которого есть `connectedMoveCallback`, при таком перемещении получает его вместо пары отключения и подключения, а элемент без него — по-прежнему `disconnectedCallback` и `connectedCallback`: в проверке так и было.

Это нужно фреймворкам при перестановке списков и порталов и виджетам с тяжёлым состоянием: картам, видео, редакторам. Пока API есть не везде, пишут с запасным вариантом:

```js
function move(parent, node, before = null) {
  if ('moveBefore' in Element.prototype) parent.moveBefore(node, before);
  else parent.insertBefore(node, before);
}
```

## URLPattern

`URLPattern` сопоставляет адреса с шаблоном в привычном по Express и роутерам синтаксисе:

```js
const product = new URLPattern({ pathname: '/tea/:slug{/reviews}?' });
product.exec('https://shop.example/tea/oolong/reviews').pathname.groups; // { slug: 'oolong' }
product.test('https://shop.example/tea');                                // false

const order = new URLPattern({ pathname: '/api/orders/:id(\\d+)' });
order.test('https://shop.example/api/orders/42');                        // true
order.test('https://shop.example/api/orders/new');                       // false
```

- **`:name`** — именованный сегмент, `{…}?` — необязательная группа, `(…)` — регулярное выражение, `*` — что угодно;
- **шаблон для всех частей адреса** — `protocol`, `hostname`, `pathname`, `search`, `hash`, а не только путь;
- **везде одинаково** — в проверке те же шаблоны дали те же результаты в Chromium и Node. Один набор маршрутов годится для клиентского роутера, Service Worker (подробно — в [PWA](/content/web/pwa)) и серверного или edge-кода.

## Красные флаги в ответе

- **«Проверю `navigator.userAgent` и включу API для Chrome».** Проверяют наличие API, а не браузер.
- **«Для роутинга SPA достаточно `pushState` и `popstate`».** `popstate` не приходит на `pushState`, а клики, формы и чужие переходы приходится ловить самим; Navigation API даёт одно событие на всё.
- **«После `startViewTransition` новый DOM уже на месте».** Колбэк выполняется после снимка; ждут `updateCallbackDone`.
- **«`appendChild` просто передвигает элемент».** Он удаляет и вставляет заново: iframe перезагружается, фокус теряется. Без потери состояния — `moveBefore`.
- **«Функция в origin trial — можно строить на ней продукт».** Origin trial ограничен по времени и не обещает, что API выйдет в таком виде.
- **«Новое API можно использовать, как только оно вышло в Chrome».** Только как улучшение с запасным вариантом, пока нет Baseline.

## Как спрашивают на собеседовании

::question
Чем Navigation API лучше History API для роутинга в SPA?

#answer
History API только меняет адрес: `pushState` не вызывает событий, `popstate` приходит лишь на «назад» и «вперёд», а клики по ссылкам и формы роутер перехватывает сам. Navigation API даёт одно событие `navigate` на все переходы, а `event.intercept({ handler })` превращает любой из них в переход SPA.

#more
У события есть тип перехода, `canIntercept`, `hashChange`, `downloadRequest` и `signal`, который отменяется при новом переходе. `navigation.transition` показывает, что переход идёт, `navigatesuccess` и `navigateerror` — чем он закончился. `navigation.navigate()` возвращает промисы `committed` и `finished`, а у записей истории есть состояние через `getState()`.
::

::question
Как сделать анимированный переход между экранами SPA?

#answer
Перехватить навигацию — через Navigation API или роутер — загрузить данные и обновить DOM внутри `document.startViewTransition(() => render())`. Браузер снимет снимки до и после и анимирует переход; общие элементы связывают `view-transition-name`.

#more
Данные загружают до `startViewTransition`, иначе интерфейс замрёт на время загрузки. Колбэк выполняется позже вызова — фокус и работу с новым DOM делают после `updateCallbackDone`. В React — компонент `ViewTransition`, в SvelteKit — `onNavigate`. Без поддержки API обновление делают напрямую, без анимации.
::

::question
Как новые API попадают в браузеры?

#answer
Идея и explainer, спецификация в WHATWG, W3C или TC39, прототип за флагом, origin trial на реальных сайтах, выпуск в одном движке и затем в остальных. Когда функция есть во всех основных браузерах, она становится Baseline.

#more
Origin trial — токен для своего сайта на ограниченный срок: API включается у пользователей, браузер собирает обратную связь, но API может измениться или исчезнуть. Статус смотрят на webstatus.dev и в Chrome Platform Status, а совместную работу движков над совместимостью — на дашборде Interop.
::

::question
Чем moveBefore отличается от appendChild?

#answer
`appendChild` и `insertBefore` для подключённого узла — удаление и вставка: iframe перезагружается, фокус теряется, CSS-анимации начинаются заново. `moveBefore` перемещает узел атомарно и сохраняет это состояние.

#more
Кастомные элементы при `moveBefore` получают `connectedMoveCallback` вместо пары отключения и подключения. Пригодится фреймворкам при перестановке списков и порталов, виджетам с картами, видео и редакторами. Пока API есть не везде, его вызывают с запасным `insertBefore`.
::

::question
Что такое URLPattern и где он пригодится?

#answer
Встроенное сопоставление адресов с шаблоном: `new URLPattern({ pathname: '/tea/:slug' })`, затем `test(url)` или `exec(url).pathname.groups`. Синтаксис как у роутеров: именованные сегменты, необязательные группы, регулярные выражения, `*`.

#more
Шаблон задаётся для любых частей адреса — протокола, хоста, пути, параметров, хеша. Работает в браузерах, Service Worker и Node, поэтому один набор маршрутов годится для клиента, офлайн-кеша и edge-кода. Хорошо сочетается с Navigation API в самописном роутере.
::

::question
Как пользоваться API, которого ещё нет во всех браузерах?

#answer
Проверять наличие API — `'navigation' in window`, `CSS.supports()`, `@supports` — и делать его улучшением: без API всё работает, только проще. Статус смотреть по Baseline.

#more
Полифилы годятся для API, которые можно повторить на JavaScript, — например, `URLPattern`; для того, что требует движка, — анимации переходов, сохранение состояния при перемещении — делают запасной путь. Определение по `userAgent` ломается с каждым выпуском браузера.
::

## Практика

::practice{title="Роутер не замечает переходы"}
Самописный роутер магазина работает на `pushState` и обработчике кликов по ссылкам. Не работают: отправка формы поиска методом GET, переход `location.href = '/cart'` из виджета чата и ссылки, на которых виджет вызвал `stopPropagation`. Как переписать?

```js
document.addEventListener('click', (e) => {
  const a = e.target.closest('a');
  if (!a || a.origin !== location.origin || a.target || e.metaKey || e.ctrlKey) return;
  e.preventDefault();
  history.pushState(null, '', a.href);
  render(location.pathname);
});
addEventListener('popstate', () => render(location.pathname));
```

#solution
Роутер ловит только клики, всплывшие до `document`, и не видит формы и переходы из кода. Navigation API даёт одно событие на все переходы документа — ссылки, формы, «назад», `location.href`, `navigation.navigate`:

```js
navigation.addEventListener('navigate', (event) => {
  if (!event.canIntercept || event.hashChange || event.downloadRequest) return;
  const url = new URL(event.destination.url);
  if (!isAppRoute(url.pathname)) return;
  event.intercept({ handler: () => render(url.pathname, url.searchParams, event.signal) });
});
```

Модификаторы и `target` проверять не нужно: такие клики открывают новую вкладку, и событие в этом документе не приходит. В проверке ссылка с `target="_blank"` и клик с Ctrl открыли новую вкладку без события `navigate` в текущей; клик по ссылке, «назад» и `navigation.navigate` пришли одним событием, а чужой origin — с `canIntercept: false`. Пока поддержка неполная, старый роутер оставляют запасным вариантом за проверкой `'navigation' in window`.
::

::practice{title="Фокус не попадает в новое поле"}
После перехода на страницу товара фокус должен встать в поле количества, но остаётся на старой кнопке:

```js
document.startViewTransition(() => renderProduct(data));
document.querySelector('#qty').focus();
```

#solution
Колбэк `startViewTransition` выполняется не сразу: браузер сначала снимает снимок старого состояния. В момент `focus()` нового поля ещё нет — `querySelector` возвращает `null` или старый элемент. В проверке сразу после вызова заголовок был старым, а после `updateCallbackDone` — новым. Ждём обновления DOM:

```js
const vt = document.startViewTransition(() => renderProduct(data));
await vt.updateCallbackDone;
document.querySelector('#qty').focus();
```

`vt.finished` ждать не нужно: фокус можно ставить, пока идёт анимация. Без поддержки API — `renderProduct(data)` и сразу фокус.
::

::practice{title="Карта перезагружается при сортировке"}
В списке пунктов выдачи у каждого — iframe с картой. При сортировке по расстоянию все карты загружаются заново, а фокус из поля фильтра пропадает:

```js
function sortPoints(list, points) {
  for (const point of points) list.append(point.element);
}
```

#solution
`append` уже подключённого элемента — удаление и вставка: iframe перезагружается, фокус теряется. В проверке после `append` карта загрузилась заново и фокус ушёл, а после `moveBefore` — нет. Перемещаем без потери состояния и с запасным вариантом:

```js
function sortPoints(list, points) {
  const canMove = 'moveBefore' in Element.prototype;
  for (const point of points) {
    if (canMove) list.moveBefore(point.element, null);
    else list.append(point.element);
  }
}
```

Где `moveBefore` нет, карты по-прежнему перезагрузятся; если это критично, iframe не переставляют, а меняют порядок через CSS: `order` во flex или grid меняет только отображение, но тогда расходятся визуальный порядок и порядок для клавиатуры и скринридеров.
::
