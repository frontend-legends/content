# Frontend Legends — контент

Репозиторий с текстом книги: справочник для подготовки к фронтенд-собеседованиям — один для всех уровней. Сайт — `frontend/` в соседнем репозитории, он читает эти `.md` через Nuxt Content.

**Перед любой правкой главы прочитай [`CONTENT.md`](CONTENT.md)** — там структура главы, компоненты и стиль. Эталон — `07.javascript/1.introduction.md`.

## Правила

1. **Рассказ, а не набор разделов.** Каждый раздел отвечает на вопрос, которым закончился предыдущий, и заканчивается переходом к следующему.
2. **Не повторяй книгу.** Прежде чем писать про понятие, найди, где оно уже разобрано: [`TOPICS.md`](TOPICS.md) и `grep -rli "<понятие>" --include="*.md" .`. Пересечения допустимы, если тема разбирается с другой стороны или упоминается коротко (2–3 предложения) со ссылкой туда, где она разобрана подробно. Второй полный разбор недопустим. Если видишь дубль — сообщи, в какой главе тема должна жить. `TOPICS.md` руками не правь: его пересобирает `node tools/topics.mjs`.
3. **Не дели по уровням.** Ни свёрнутых блоков «для senior», ни фраз «на mid спрашивают», ни ответов «mid / senior»: глубина — обычные подразделы `###`, в вопросах — `#answer` (хороший ответ) и `#more` (что добавить).
4. **Только компоненты из `CONTENT.md`:** `::tldr`, `::question`, `::practice`, `::pitfall`, `:term`. Новые компоненты не придумывай — сначала спроси.
5. **Без HTML-тегов** в markdown. Тире « — », кавычки «ёлочки», без эмодзи.
6. **Код проверяется.** Каждый пример с выводом или поведением — скрипт в `codes/<глава>/<тема>/` с `node:assert` на значения из текста. TypeScript, React, Vue и браузер — см. таблицу в `CONTENT.md`. Перед тем как закончить, оба зелёные:
   - `node tools/lint.mjs <глава>/<тема>`;
   - `cd codes && node run.mjs <глава>/<тема>`.
7. **Факты — только проверенные.** Не уверен — открой спецификацию, документацию или исходники. Если проверить нечем — не пиши. Версии и даты — только в таблице эволюции, с пометкой «актуально на <месяц год>».
8. **Ссылки.** Внутренние — `/content/<папка главы без номера>/<файл без номера и .md>`, например `/content/javascript/event-loop`. Проверь, что файл существует.
9. **Frontmatter.** Обнови `date`, а после проверки по стандарту — `reviewed`. Не меняй `order` без явной просьбы: от него зависит навигация.

## Чего не делать

- Не переписывай главы, о которых не просили, даже если видишь, что их можно улучшить, — составь список.
- Не удаляй вопросы и задачи, не проверив, что их смысл сохранён в новой версии.
- Не трогай `codes/run.mjs`, `codes/_lib/`, `tools/` и чужие скрипты в `codes/` без необходимости.
- Не меняй имена файлов, папки и `order`: по адресу темы хранится прогресс читателей.
- Главу 02 (алгоритмы) по этому стандарту не переписывай — у неё своя структура.
- Не коммить без просьбы и никогда не пушь в `main`: пуш в `main` сразу деплоит сайт.
