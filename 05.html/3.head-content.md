# Содержимое head

`head` — служебная часть документа: кодировка, метаданные для поиска и соцсетей, стили, скрипты, иконки, подсказки браузеру и политика безопасности. Спрашивают, что обязательно в `head`, чем отличаются `async`, `defer` и модули, зачем `meta viewport` и `link rel="canonical"`. Глубже — почему `meta description` оказывается в `body`, почему `defer` у встроенного скрипта ничего не делает, почему скрипты, добавленные из JavaScript, выполняются вразнобой и почему `<base>` ломает якорные ссылки.

::tldr
- **В `head` — только метаданные:** `title`, `meta`, `link`, `style`, `script`, `base`, `noscript`, `template`. Любой другой элемент или текст закрывает `head` раньше времени, и всё после него попадает в `body`.
- **`meta charset` — первым, в первых 1024 байтах.** Дальше `viewport`, `title`, описание для поиска и Open Graph для соцсетей.
- **`link` подключает не только стили:** иконки, манифест, канонический адрес, языковые версии, подсказки загрузки. Стиль с непопадающим `media` скачивается, но не держит отрисовку.
- **`script` бывает классическим и модулем.** Модуль отложен, строг, выполняется один раз и не видит `document.currentScript`. `defer` у встроенного классического скрипта игнорируется, а скрипты, вставленные из JavaScript, по умолчанию асинхронны.
- **`<base>` меняет адреса и у якорей `#…`, а CSP в `meta` действует только на то, что ниже, и не поддерживает `frame-ancestors`.**
::

## Что можно класть в head

Сквозной пример — `head` страницы товара «Улун молочный» в магазине чая.

```html
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Улун молочный — 990 ₽ — Магазин чая</title>
  <meta name="description" content="Улун с мягким молочным вкусом, 100 г">
  <link rel="canonical" href="https://shop.example/tea/oolong-milk">
  <link rel="preconnect" href="https://cdn.shop.example">
  <link rel="stylesheet" href="/app.css">
  <link rel="icon" href="/favicon.svg" type="image/svg+xml">
  <script type="module" src="/app.js"></script>
</head>
```

В `head` допустимо только содержимое-метаданные: `title`, `base`, `link`, `meta`, `style`, `script`, `noscript`, `template`. Встретив что-то другое, парсер считает, что `head` кончился, и открывает `body`.

```html
<head>
  <meta charset="utf-8">
  <title>Улун</title>
  <img src="/pixel.gif" alt="">                         <!-- пиксель счётчика -->
  <meta name="description" content="Улун с молочным вкусом">
  <link rel="canonical" href="https://shop.example/tea/oolong">
</head>
```

В проверке в `head` остались только `meta charset` и `title`, а `img`, описание и канонический адрес оказались в `body`. Страница выглядит как прежде, но поисковик может не учесть `canonical` из `body`. Так же действует случайный текст, лишний символ или виджет, вставленный в шаблон `head`. Проверяют в :term[DevTools]{def="инструменты разработчика в браузере: элементы, сеть, производительность, отладчик"}: вкладка Elements показывает, где элементы на самом деле.

### Порядок

Первым — `meta charset`: кодировка должна целиком уместиться в первые 1024 байта, иначе браузер начнёт разбор в другой кодировке. Дальше порядок влияет на скорость: подключения к чужим доменам и предзагрузка — пораньше, стили — до синхронных скриптов, потому что скрипт ждёт стили перед собой (подробно — в [Структуре документа](/content/html/structure)).

## meta

| `meta` | Зачем |
| --- | --- |
| `charset="utf-8"` | кодировка документа |
| `name="viewport"` | ширина страницы на телефоне (подробно — в [Адаптивном дизайне](/content/css/rwd)) |
| `name="description"` | описание для выдачи поиска |
| `name="robots"` | `noindex`, `nofollow` — правила для поисковых роботов |
| `property="og:*"`, `name="twitter:*"` | заголовок, описание и картинка превью в соцсетях и мессенджерах |
| `name="theme-color"` | цвет интерфейса браузера на телефоне |
| `name="color-scheme"` | какие темы поддерживает страница |
| `name="referrer"` | политика заголовка `Referer` |
| `http-equiv="refresh"` | перезагрузка или переход по таймеру — плохо для доступности |

Как метатеги работают на поиск, превью ссылок и структурированные данные — в [SEO](/content/web/seo). В одностраничном приложении их меняют при переходах — `useHead` в :term[Nuxt]{def="фреймворк поверх Vue с серверным рендерингом и маршрутами по файлам"}, Metadata API в Next.js, — но поисковые роботы и превью мессенджеров надёжно видят только то, что пришло в HTML, поэтому метаданные отдают с сервера.

`meta name="color-scheme" content="light dark"` — то же, что `color-scheme` в CSS, но действует раньше загрузки стилей: в проверке при тёмной теме системы браузер сам сделал текст страницы белым, без единой строки CSS. Тёмная тема без белой вспышки при загрузке начинается с этого тега (подробно о темах — в [Современном CSS](/content/css/modern-css)).

## link

`link` описывает связь страницы с другим ресурсом. Тип связи — в `rel`:

| `rel` | Что подключает |
| --- | --- |
| `stylesheet` | стили |
| `icon`, `apple-touch-icon` | иконки вкладки и ярлыка |
| `manifest` | манифест веб-приложения |
| `canonical` | основной адрес страницы при дублях |
| `alternate` с `hreflang` | версии страницы на других языках |
| `preload`, `modulepreload`, `preconnect`, `dns-prefetch`, `prefetch` | подсказки загрузки |

Как подсказки ускоряют загрузку и когда ими не злоупотреблять — в [Производительности загрузки](/content/security-perfomance/loading-performance). Про шрифты есть отдельная ловушка: `preload` без `crossorigin` не используется (подробно — в [Типографике](/content/css/typography)).

### media у стилей

```html
<link rel="stylesheet" href="/app.css">
<link rel="stylesheet" href="/print.css" media="print">
```

Стиль, чей `media` сейчас не подходит, браузер скачивает с низким приоритетом и **не ждёт** его для отрисовки. В проверке стиль с задержкой 900 мс отодвинул первую отрисовку на ~900 мс, а тот же стиль с `media="print"` — нет: страница нарисовалась сразу, хотя файл был скачан. Так отделяют стили печати и широких экранов от критических.

## script

Подробно о том, как скрипты влияют на загрузку, — в [Производительности загрузки](/content/security-perfomance/loading-performance). Коротко: синхронный скрипт останавливает разбор, `defer` выполняется после разбора в порядке документа, `async` — как только загрузится. Здесь — правила самого элемента, на которых ошибаются.

### Классический скрипт и модуль

| | `<script>` | `<script type="module">` |
| --- | --- | --- |
| когда выполняется | сразу, если без `defer` и `async` | после разбора, как `defer` |
| режим | обычный | строгий |
| переменные верхнего уровня | глобальные | свои для модуля |
| `import` и `export` | нет | да |
| тот же адрес дважды | выполнится дважды | выполнится один раз |
| `document.currentScript` | элемент `script` | `null` |
| с чужого домена | без CORS | только с CORS |

В проверке классический `/twice.js`, подключённый два раза, выполнился два раза, а модуль `/mod.js` — один: модули кешируются по адресу. `document.currentScript` в модуле — `null`; модуль узнаёт свой адрес через `import.meta.url`.

`nomodule` помечает скрипт для браузеров без модулей — сегодня это пережиток, но его встречают в старых сборках.

### defer, async и встроенные скрипты

```html
<script defer>init()</script>         <!-- defer проигнорирован: выполнится сразу -->
<script type="module" async>track()</script>
```

- **`defer` и `async` у классического скрипта работают только с `src`.** Встроенный скрипт с `defer` в проверке выполнился сразу, раньше следующего обычного;
- **у встроенного модуля `async` работает:** он выполнился, пока разбор ждал медленный скрипт ниже, а обычный модуль — только после разбора.

### Скрипты из JavaScript

```js
for (const src of ['/vendor.js', '/widget.js']) {
  const s = document.createElement('script');
  s.src = src;
  document.head.append(s);
}
```

Скрипты, вставленные из JavaScript, **асинхронны по умолчанию**: каждый выполнится, как только загрузится. В проверке медленный первый и быстрый второй выполнились в обратном порядке — сначала быстрый. Если второй зависит от первого, будет ошибка «не определено», причём только на медленной сети. `s.async = false` возвращает порядок вставки — в проверке так и вышло. Ещё надёжнее — модули с `import` или загрузка через `await import()`.

### Import map

```html
<script type="importmap">{ "imports": { "price": "/price.js" } }</script>
<script type="module">import { format } from 'price';</script>
```

Карта импортов позволяет писать `import 'price'` вместо полного пути — без сборщика. Она должна стоять **до первого модуля**: в проверке модуль перед картой не нашёл `price` и упал с ошибкой, а с картой выше — отформатировал цену.

## base, noscript и CSP

### base

```html
<base href="https://cdn.shop.example/static/">
```

`base` меняет основу для **всех** относительных адресов документа. Картинка `tea.png` станет `https://cdn.shop.example/static/tea.png` — ради этого `base` и ставят. Но так же изменится ссылка `href="#reviews"`: в проверке она стала `https://cdn.shop.example/static/#reviews`, и клик по «Отзывам» уводит со страницы. Поэтому `base` почти не используют, а одностраничные приложения, которым он нужен для роутера, пишут якоря полным путём. Действует только первый `base` в документе.

### noscript

Содержимое `noscript` показывается, только если JavaScript выключен: в проверке с включённым JavaScript абзаца внутри не было в DOM, а с выключенным — был. Для одностраничного приложения это сообщение «включите JavaScript»; для счётчиков — запасной пиксель.

### CSP в meta

Политику безопасности контента задают заголовком ответа, но можно и метатегом:

```html
<meta http-equiv="Content-Security-Policy" content="script-src 'self'">
```

Отличия от заголовка, проверенные в Chromium:

- **действует только на то, что ниже тега:** встроенный скрипт до `meta` выполнился, после — был заблокирован. Поэтому `meta` с :term[CSP]{def="Content Security Policy: правила, откуда странице можно загружать и выполнять код"} ставят первым в `head`;
- **часть директив не поддерживается** — `frame-ancestors`, `report-uri`, `sandbox`. Chrome пишет в консоль, что `frame-ancestors` в `meta` проигнорирован, и защиты от встраивания в чужой фрейм нет.

Как устроена CSP, nonce и заголовки безопасности — в [CSP и заголовках безопасности](/content/security-perfomance/csp-and-security-headers).

## Красные флаги в ответе

- **«В `head` можно положить пиксель счётчика».** Элемент вне метаданных закрывает `head`, и всё ниже оказывается в `body`.
- **«`defer` на встроенном скрипте отложит его».** `defer` и `async` у классического скрипта работают только с `src`.
- **«Скрипты, добавленные циклом, выполнятся по порядку».** Вставленные из JavaScript скрипты асинхронны; порядок даёт `async = false` или модули.
- **«Модуль можно подключить дважды — он выполнится дважды».** Модули выполняются один раз на адрес.
- **«`<base>` влияет только на картинки и стили».** Он меняет все относительные адреса, включая якоря.
- **«CSP в `meta` — то же, что заголовок».** Метатег действует только ниже себя и не поддерживает `frame-ancestors`.

## Как спрашивают на собеседовании

::question
Что обязательно в head и в каком порядке?

#answer
`meta charset` первым, затем `meta viewport` и `title`. Дальше описание и метаданные для соцсетей, канонический адрес, подсказки загрузки, стили, скрипты. `charset` должен уместиться в первые 1024 байта, иначе разбор начнётся в другой кодировке.

#more
В `head` допустимы только метаданные: `title`, `meta`, `link`, `style`, `script`, `base`, `noscript`, `template`. Любой другой элемент или текст закрывает `head`, и последующие метатеги попадают в `body` — поисковик может их не учесть. Синхронные скрипты ставят перед стилями или делают отложенными, потому что скрипт ждёт стили перед собой.
::

::question
Чем отличаются обычный скрипт, async, defer и type="module"?

#answer
Обычный скрипт останавливает разбор до загрузки и выполнения. `defer` грузится параллельно и выполняется после разбора в порядке документа. `async` грузится параллельно и выполняется сразу после загрузки, без гарантий порядка. Модуль ведёт себя как `defer`, а с `async` — как `async`.

#more
`defer` и `async` у классического скрипта работают только с `src`: встроенный `<script defer>` выполнится сразу. Модуль строгий, со своей областью видимости, выполняется один раз на адрес и с чужого домена требует CORS. Отложенные скрипты выполняются до `DOMContentLoaded`.
::

::question
Почему скрипты, добавленные из JavaScript, выполняются не по порядку?

#answer
Скрипты, вставленные через `createElement('script')`, асинхронны по умолчанию: каждый выполняется, как только загрузился. Если второй зависит от первого, а первый грузится дольше, второй упадёт.

#more
`script.async = false` заставляет выполнять вставленные скрипты в порядке вставки. Лучше вообще не зависеть от порядка: модули с `import` или `await import()` сами дожидаются зависимостей. Сканер предзагрузки такие скрипты не видит, поэтому загрузка начинается только после выполнения вставляющего кода.
::

::question
Зачем link rel="canonical" и hreflang?

#answer
`canonical` говорит поисковику, какой адрес основной, если одна страница доступна по нескольким — с параметрами сортировки, метками рассылок, слешем в конце. `alternate` с `hreflang` перечисляет версии страницы на других языках.

#more
Без `canonical` поисковик сам выбирает основной адрес и может делить вес между дублями. Обе ссылки должны быть в `head` и в HTML, пришедшем с сервера: в `body` или добавленные клиентским JavaScript они могут не учитываться. Подробнее о поиске — в главе про SEO.
::

::question
Как стиль с media="print" влияет на загрузку?

#answer
Стиль, чей `media` сейчас не подходит, браузер скачивает с низким приоритетом и не ждёт его для первой отрисовки. Обычный стиль в `head` держит отрисовку до загрузки.

#more
Так стили печати, тёмной темы через медиазапрос или широких экранов выносят из критического пути. Старый приём асинхронной загрузки CSS — `media="print"` с заменой на `all` по `onload` — опирается на то же правило, но сегодня для этого есть `preload` с `as="style"`.
::

::question
Что делает тег base и чем он опасен?

#answer
Задаёт основу для всех относительных адресов документа: ссылок, картинок, форм, скриптов. Ставят его, чтобы относительные пути вели на CDN или в подпапку приложения.

#more
Он меняет и якоря: `href="#reviews"` превращается в адрес на основе `base`, и клик уводит со страницы. Действует только первый `base`, а он должен стоять раньше всех элементов с адресами. Из-за побочных эффектов `base` почти не используют, а роутеры, которым он нужен, рекомендуют якоря с полным путём.
::

::question
Можно ли задать CSP метатегом? Чем это хуже заголовка?

#answer
Можно: `<meta http-equiv="Content-Security-Policy" content="…">`. Но он действует только на то, что ниже него, поэтому ставится первым, и не поддерживает `frame-ancestors`, `report-uri` и `sandbox`.

#more
Защиту от встраивания в чужой фрейм метатегом не задать — только заголовком `Content-Security-Policy: frame-ancestors` или `X-Frame-Options`. Метатег полезен, когда нет доступа к заголовкам сервера, например на статическом хостинге, но заголовок надёжнее.
::

## Практика

::practice{title="Описание страницы не попадает в поиск"}
SEO-аудит говорит, что у страниц нет `canonical`, хотя он есть в шаблоне:

```html
<head>
  <meta charset="utf-8">
  <title>Улун молочный — Магазин чая</title>
  <noscript><img src="https://mc.example/watch/1" alt=""></noscript>
  <meta name="description" content="Улун с мягким молочным вкусом">
  <link rel="canonical" href="https://shop.example/tea/oolong-milk">
</head>
```

#solution
Когда JavaScript выключен — а так работают многие роботы, — `noscript` разбирается как разметка, и `img` внутри закрывает `head`. Описание и `canonical` уезжают в `body`. Тот же эффект даёт любой элемент, кроме метаданных, или случайный текст. Пиксель переносят в `body`:

```html
<head>
  <meta charset="utf-8">
  <title>Улун молочный — Магазин чая</title>
  <meta name="description" content="Улун с мягким молочным вкусом">
  <link rel="canonical" href="https://shop.example/tea/oolong-milk">
</head>
<body>
  <noscript><img src="https://mc.example/watch/1" alt=""></noscript>
```

В проверке в Chromium с выключенным JavaScript `canonical` после такого `noscript` оказался в `body`, а с включённым остался в `head`. Просто `img` в `head` выносит описание и `canonical` в `body` всегда.
::

::practice{title="Виджет падает только у части пользователей"}
Скрипт подключает библиотеку и её виджет. На быстром интернете всё работает, а в Sentry ошибки `Shop is not defined` с мобильных:

```js
for (const src of ['https://cdn.shop.example/sdk.js', '/widget.js']) {
  const s = document.createElement('script');
  s.src = src;
  document.head.append(s);
}
```

#solution
Вставленные из JavaScript скрипты асинхронны: каждый выполняется, как только загрузился. Свой `/widget.js` маленький и приходит раньше, чем SDK с CDN, и обращается к ещё не определённому `Shop`. Порядок возвращает `async = false`:

```js
for (const src of ['https://cdn.shop.example/sdk.js', '/widget.js']) {
  const s = document.createElement('script');
  s.src = src;
  s.async = false;            // выполнять в порядке вставки
  document.head.append(s);
}
```

В проверке без этого медленный первый скрипт выполнился после быстрого второго, с `async = false` — в порядке вставки. Если SDK доступен как модуль, надёжнее `await import()` и вызов виджета после него.
::

::practice{title="Ссылки на отзывы уводят на CDN"}
После добавления `base` картинки стали грузиться с CDN, но клик по «Отзывам» открывает пустую страницу на CDN:

```html
<base href="https://cdn.shop.example/static/">
<a href="#reviews">Отзывы</a>
```

#solution
`base` меняет основу всех относительных адресов, и `#reviews` разрешается в `https://cdn.shop.example/static/#reviews` — в проверке ссылка получила ровно этот адрес. Варианты: убрать `base` и задавать адрес CDN при сборке — `base` в конфигурации Vite или `assetPrefix` в Next.js, — или писать якоря с путём страницы:

```html
<a href="/tea/oolong-milk#reviews">Отзывы</a>
```

Первый вариант лучше: адреса ассетов подставляет сборщик, а `base` в документе не нужен вовсе.
::
