# Формы

Форма — самый интерактивный кусок HTML: поля, подписи, встроенная валидация, отправка, `FormData` и события. Спрашивают, чем `input` отличается от `change`, как провалидировать форму без JavaScript, как отправить файл через `fetch` и зачем `type="button"`. Глубже — почему кнопка «Применить промокод» отправляет заказ, почему `form.submit()` пропускает проверку, почему в данных формы нет отключённого поля и что ломает ручной заголовок `Content-Type`.

::tldr
- **Кнопка внутри формы по умолчанию отправляет её** — у неё `type="submit"`. Enter в поле тоже отправляет форму, если в ней есть кнопка отправки или поле одно.
- **Встроенная валидация:** `required`, `type`, `pattern` — проверяет значение целиком, — `min`, `max`, `step`, `minlength` — проверяется только после ввода пользователя. `setCustomValidity` держит ошибку, пока её не сбросят пустой строкой.
- **`form.submit()` пропускает и проверку, и событие `submit`,** а `requestSubmit()` ведёт себя как нажатие кнопки.
- **`FormData` берёт только поля с `name`, включённые и отмеченные:** неотмеченных флажков и `disabled` в ней нет, а `readonly` есть. `Content-Type` для `FormData` вручную не ставят — пропадёт граница частей.
- **`input` срабатывает на каждое изменение, `change` — когда значение зафиксировано:** у текста при уходе из поля, у флажков и `select` сразу. Событие `invalid` не всплывает.
::

## Форма и кнопки

Сквозной пример — оформление заказа в магазине чая: имя, телефон, почта, промокод, способ доставки, комментарий и кнопки «Применить», «Сохранить черновик» и «Оформить».

```html
<form action="/api/order" method="post">
  <label for="phone">Телефон</label>
  <input id="phone" name="phone" type="tel" autocomplete="tel" required>

  <input name="promo">
  <button id="apply">Применить</button>

  <button type="submit">Оформить</button>
</form>
```

| Атрибут `form` | Что задаёт |
| --- | --- |
| `action` | куда отправлять; без него — текущий адрес |
| `method` | `get` — данные в адресе, для поиска и фильтров; `post` — в теле, для изменений; `dialog` — закрыть родительский `dialog` |
| `enctype` | `application/x-www-form-urlencoded` по умолчанию, `multipart/form-data` для файлов |
| `novalidate` | не проверять при отправке |
| `autocomplete` | разрешить или запретить автозаполнение |

### Кнопка по умолчанию — отправка

У `button` внутри формы `type="submit"` по умолчанию. «Применить промокод» в примере выше — кнопка отправки: в проверке клик по ней вызвал `submit` с `submitter` равным этой кнопке, а кнопка с `type="button"` — нет. Пользователь хотел применить скидку, а заказ ушёл. Каждой кнопке, которая не отправляет форму, пишут `type="button"`.

### Отправка по Enter

Enter в текстовом поле отправляет форму — это **неявная отправка**. Она срабатывает, если в форме есть кнопка отправки или всего одно поле. В проверке из трёх форм отправились две: с кнопкой и с единственным полем, а форма с двумя полями без кнопки — нет. Отсюда два бага: «Enter в поле промокода оформил заказ» и «Enter в форме входа ничего не делает».

### Подписи

Клик по `label` фокусирует или переключает связанное поле — в проверке клик по тексту «Согласен с условиями» и «Подарочная упаковка» отметил оба флажка. Связь задают вложением поля в `label` или парой `for` и `id`. Подпись — ещё и доступное имя поля, без неё программа чтения не скажет, что вводить (подробно — в [Доступности](/content/html/accessibility)).

## Типы полей

| `type` | Что даёт |
| --- | --- |
| `email`, `url` | проверка формата, клавиатура с `@` или `/` |
| `tel` | цифровая клавиатура; формат не проверяется — номера бывают любыми |
| `number` | стрелки, `min`, `max`, `step` |
| `date`, `time`, `datetime-local`, `month` | встроенный выбор даты |
| `search` | крестик очистки, клавиша «Найти» |
| `checkbox`, `radio`, `range`, `color`, `file` | флажок, переключатель, ползунок, цвет, файлы |
| `hidden` | значение без интерфейса |

`type="number"` подходит для количества, но не для телефонов, индексов и номеров карт. Он принимает :term[экспоненту]{def="запись числа через степень десяти: 1e3 — это 1000"} — `1e3` в проверке оказался валидным числом 1000, — колёсико мыши над полем в фокусе меняет значение, а ведущие нули теряются в `valueAsNumber`. Для цифровых кодов берут `type="text"` с `inputmode="numeric"` и `autocomplete="one-time-code"`, `"postal-code"` или `"cc-number"`.

`autocomplete` с правильным значением — `name`, `tel`, `email`, `street-address`, `new-password` — позволяет браузеру и :term[менеджеру паролей]{def="программе или функции браузера, которая хранит пароли и подставляет их в формы"} заполнить форму одним касанием. Это и удобство, и требование доступности.

## Встроенная валидация

Браузер проверяет поля сам и не даёт отправить форму с ошибками:

| Атрибут | Нарушение в `validity` |
| --- | --- |
| `required` | `valueMissing` |
| `type="email"`, `type="url"` | `typeMismatch` |
| `pattern` | `patternMismatch` |
| `min`, `max` | `rangeUnderflow`, `rangeOverflow` |
| `step` | `stepMismatch` |
| `minlength`, `maxlength` | `tooShort`, `tooLong` |
| `setCustomValidity('…')` | `customError` |

В проверке все нарушения сработали, и у каждого есть ловушка:

- **`pattern` проверяет значение целиком** — шаблон оборачивается в `^(?:…)$`. `pattern="\d{6}"` для индекса отклонил `1234567`; якоря писать не нужно;
- **`minlength` проверяется только после ввода пользователем.** Значение «Я», присвоенное из кода, валидно, а то же «Я», набранное с клавиатуры, дало `tooShort`. Предзаполненные короткие значения не ловятся;
- **`step`** — шаг от `min`: `step="0.01"` отклонил `9.995` как `stepMismatch`.

Стиль ошибок — `:user-invalid`, а не `:invalid`: иначе пустая форма встречает пользователя красными рамками (подробно — в [Селекторах](/content/css/css-rules)).

### Constraint Validation API

```js
phone.checkValidity();       // true или false, на ошибке — событие invalid
phone.reportValidity();      // то же и показать сообщение браузера
phone.validationMessage;     // текст ошибки на языке браузера
phone.validity.valueMissing; // конкретная причина
```

Свои правила — через `setCustomValidity`:

```js
repeat.setCustomValidity(repeat.value === password.value ? '' : 'Пароли не совпадают');
```

Ошибка держится, пока её не сбросят пустой строкой. В проверке после `setCustomValidity('Пароли не совпадают')` пароли сделали одинаковыми, но поле осталось невалидным, пока не вызвали `setCustomValidity('')`. Поэтому проверку пересчитывают на каждом `input` обоих полей.

Событие `invalid` **не всплывает**: в проверке обработчик на поле сработал, а на форме — нет. Чтобы ловить ошибки всей формы одним обработчиком, его ставят в фазе перехвата: `form.addEventListener('invalid', handler, true)`.

## Отправка

| Способ | Проверка | Событие `submit` |
| --- | --- | --- |
| клик по кнопке отправки, Enter | да | да |
| `form.requestSubmit(button?)` | да | да |
| `form.submit()` | нет | нет |
| кнопка с `formnovalidate`, форма с `novalidate` | нет | да |

`form.submit()` — старый метод, который просто отправляет: без проверки полей и без события, поэтому обработчики `submit` — отправка через `fetch`, аналитика — не срабатывают. В проверке `requestSubmit()` на форме с пустым обязательным телефоном вызвал `invalid` и не отправил форму, а `submit()` ушёл без события. Кнопка «Сохранить черновик» с `formnovalidate` отправила форму, пропустив проверку.

В одностраничном приложении форму перехватывают:

```js
form.addEventListener('submit', async (event) => {
  event.preventDefault();
  const data = new FormData(form, event.submitter);
  await fetch('/api/order', { method: 'POST', body: data });
});
```

`event.submitter` — кнопка, которой отправили форму: одна форма, две кнопки «Оплатить» и «В черновик» с разными `value`.

## FormData

`new FormData(form)` собирает **успешные** поля формы:

```html
<form id="order">
  <input name="name" value="Анна">
  <input value="без имени">
  <input type="checkbox" name="gift" value="yes">
  <input type="checkbox" name="call" value="yes" checked>
  <input name="city" value="Москва" disabled>
  <input name="promo" value="ЧАЙ10" readonly>
  <fieldset disabled><input name="card" value="4242"></fieldset>
  <select name="tea" multiple>…</select>
  <button name="action" value="pay">Оплатить</button>
</form>
<input name="comment" form="order" value="позвонить за час">
```

В проверке в данные попали `name`, `call`, `promo`, оба выбранных `tea` и `comment`. Не попали:

- **поле без `name`** — у него нет ключа;
- **неотмеченный флажок** — его просто нет, не `false`;
- **`disabled`** — включая все поля внутри `fieldset disabled`. Если поле нужно отправить, но нельзя редактировать, — `readonly`: он в данных есть;
- **кнопка** — только если передать её вторым аргументом: `new FormData(form, button)` добавил `action=pay`.

Поле снаружи формы попало благодаря атрибуту `form="order"`. Повторяющиеся имена читают через `getAll('tea')`. Для GET-запроса данные превращают в строку запроса: `new URLSearchParams(new FormData(form))`.

### Отправка через fetch

```js
await fetch('/api/order', { method: 'POST', body: new FormData(form) });
```

Заголовок `Content-Type` для `FormData` **не пишут**. Браузер сам ставит `multipart/form-data; boundary=…` — граница разделяет части тела. В проверке на настоящем сервере без ручного заголовка сервер увидел границу и разобрал поля, а с `headers: { 'Content-Type': 'multipart/form-data' }` граница пропала, и сервер не нашёл ни одного поля. Так же отправляют файлы: `input type="file"` попадает в `FormData` как `File`.

## События

| Событие | Когда |
| --- | --- |
| `input` | на каждое изменение значения |
| `change` | значение зафиксировано: текст — при уходе из поля, флажок, переключатель, `select` — сразу |
| `beforeinput` | до изменения, можно отменить |
| `submit`, `reset` | отправка и сброс формы |
| `invalid` | поле не прошло проверку; не всплывает |
| `focus`, `blur` | фокус на поле; не всплывают |
| `focusin`, `focusout` | то же, но всплывают — для обработки на форме |

В проверке набор «чай» дал три `input`, `change` пришёл только при уходе из поля, а клик по флажку дал `input` и `change` сразу. Живой поиск и счётчик символов слушают `input`, сохранение поля — `change`.

### Управляемые и неуправляемые поля

Во фреймворках поле бывает **управляемым** — значение хранится в состоянии, каждое изменение проходит через обработчик — и **неуправляемым** — значение живёт в DOM и читается при отправке через `FormData`. Для простой формы заказа неуправляемых полей и `FormData` достаточно. Управление нужно, когда значение поля влияет на интерфейс сразу: маска телефона, зависимые поля, проверка на лету. Подробно — в [Состоянии и событиях React](/content/reactjs/state-and-events) и [библиотеках форм](/content/ecosystem-libs/forms-and-validation).

## Красные флаги в ответе

- **«Кнопка без `type` ничего не отправит».** Внутри формы это `submit`.
- **«`form.submit()` проверит поля».** Он пропускает и проверку, и событие `submit`; нужен `requestSubmit()`.
- **«`pattern="^\d{6}$"`».** Шаблон и так проверяет значение целиком; якоря лишние.
- **«Неотмеченный флажок придёт как `false`».** Его в данных нет вовсе.
- **«Поле только для чтения — `disabled`».** Отключённое поле не отправляется; для этого `readonly`.
- **«Для `FormData` выставлю `Content-Type: multipart/form-data`».** Пропадёт граница, и сервер не разберёт тело.

## Как спрашивают на собеседовании

::question
Чем input отличается от change?

#answer
`input` срабатывает на каждое изменение значения — на каждый символ. `change` — когда значение зафиксировано: у текстового поля при уходе из него, у флажков, переключателей и `select` — сразу при выборе.

#more
Живой поиск, счётчик символов и маски слушают `input`, сохранение поля — `change`. `beforeinput` срабатывает до изменения и позволяет его отменить. `focus` и `blur` не всплывают, поэтому для формы целиком используют `focusin` и `focusout`. `onChange` в React — это на самом деле `input`.
::

::question
Как провалидировать форму без JavaScript?

#answer
Атрибутами: `required`, `type="email"` и `url`, `pattern`, `min`, `max`, `step`, `minlength`, `maxlength`. Браузер не отправит форму с ошибками и покажет сообщение. Стили ошибок — через `:user-invalid`.

#more
`pattern` проверяет значение целиком. `minlength` проверяется только после ввода пользователем, а не для значения из кода. Свои правила — `setCustomValidity`, которую обязательно сбрасывают пустой строкой. Проверку на клиенте дублируют на сервере: она для удобства, а не для защиты.
::

::question
Зачем type="button"? Когда форма отправляется по Enter?

#answer
У `button` внутри формы `type="submit"` по умолчанию, и любая кнопка без типа отправляет форму. `type="button"` пишут кнопкам, которые делают что-то другое: применить промокод, показать пароль, добавить строку.

#more
Enter в поле отправляет форму, если в ней есть кнопка отправки или всего одно поле: в форме из двух полей без кнопки Enter не сработает. Поэтому форму входа делают с настоящей кнопкой отправки, а не с `div`-кнопкой и обработчиком клика.
::

::question
Чем form.submit() отличается от requestSubmit()?

#answer
`submit()` отправляет форму сразу: без проверки полей и без события `submit`, поэтому обработчики отправки не срабатывают. `requestSubmit()` ведёт себя как нажатие кнопки: проверяет поля, вызывает `submit` и принимает кнопку-отправителя.

#more
Программная отправка нужна, например, при автосохранении или отправке по таймеру — и почти всегда это `requestSubmit()`. `formnovalidate` на кнопке и `novalidate` на форме отключают проверку, но событие `submit` остаётся.
::

::question
Что попадает в FormData?

#answer
Включённые поля с `name`: значения текстовых полей, отмеченные флажки и переключатели, выбранные `option`, файлы. Не попадают поля без `name`, неотмеченные флажки, `disabled` — в том числе внутри `fieldset disabled` — и кнопки, если не передать отправителя вторым аргументом.

#more
`readonly` в данных есть, поэтому нередактируемое, но отправляемое поле делают `readonly`. Поля снаружи формы подключают атрибутом `form`. Повторяющиеся имена читают через `getAll`. Для строки запроса — `new URLSearchParams(new FormData(form))`.
::

::question
Как отправить файл через fetch?

#answer
Положить форму или файл в `FormData` и передать как `body`. Заголовок `Content-Type` не писать: браузер сам поставит `multipart/form-data` с границей между частями.

#more
Ручной `Content-Type: multipart/form-data` теряет `boundary`, и сервер не может разобрать тело. Прогресс загрузки `fetch` пока не даёт — для этого используют `XMLHttpRequest` с `upload.onprogress`. Большие файлы режут на части и отправляют по очереди, чтобы обрыв не начинал всё сначала.
::

::question
Чем disabled отличается от readonly?

#answer
`disabled` выключает поле: оно не получает фокус, не отправляется с формой и не проверяется. `readonly` запрещает только редактирование: поле фокусируется, выделяется, копируется, отправляется и читается программой чтения.

#more
`readonly` работает только у текстовых полей; у флажков и `select` его нет — их отключают или делают нередактируемыми иначе. `fieldset disabled` выключает все поля внутри разом — удобно для блокировки формы на время отправки. Отключённая кнопка отправки без объяснения — плохая практика: лучше показать, что не так.
::

## Практика

::practice{title="Промокод оформляет заказ"}
Пользователи жалуются: нажали «Применить промокод» — и заказ ушёл без скидки. Иногда то же происходит по Enter в поле промокода:

```html
<form id="checkout">
  <input name="promo">
  <button onclick="applyPromo()">Применить</button>
  <button>Оформить заказ</button>
</form>
```

#solution
Кнопка «Применить» без `type` — кнопка отправки: её клик и вызывает `applyPromo`, и отправляет форму. Enter в поле тоже отправляет форму, потому что в ней есть кнопка отправки, — и отправителем оказывается первая из них, «Применить». Исправление:

```html
<form id="checkout">
  <input name="promo" enterkeyhint="done">
  <button type="button" onclick="applyPromo()">Применить</button>
  <button type="submit">Оформить заказ</button>
</form>
```

```js
checkout.promo.addEventListener('keydown', (e) => {
  if (e.key === 'Enter') { e.preventDefault(); applyPromo(); }
});
```

В проверке в Chromium клик по кнопке без `type` вызвал `submit` с `submitter` этой кнопки, а с `type="button"` — нет; Enter отправлял форму с кнопкой. Промокод в отдельной форме — тоже вариант.
::

::practice{title="Сервер не видит поля"}
После переноса отправки заказа на `fetch` сервер отвечает «поле name обязательно», хотя в DevTools тело запроса не пустое:

```js
await fetch('/api/order', {
  method: 'POST',
  body: new FormData(form),
  headers: { 'Content-Type': 'multipart/form-data' },
});
```

#solution
Тело `multipart/form-data` состоит из частей, разделённых границей, а граница передаётся в заголовке: `multipart/form-data; boundary=…`. Ручной заголовок перезаписал браузерный, и сервер не знает, где кончается одна часть и начинается другая. Заголовок удаляют:

```js
await fetch('/api/order', { method: 'POST', body: new FormData(form) });
```

В проверке на настоящем сервере без ручного заголовка поля `name` и `tea` разобрались, а с ним — ни одного. Если серверу нужен JSON, отправляют JSON: `body: JSON.stringify(Object.fromEntries(new FormData(form)))` с `Content-Type: application/json` — но файлы так не отправить.
::

::practice{title="Город не дошёл до сервера"}
Город доставки подставляется из профиля и не должен меняться, но в заказе его нет:

```html
<input name="city" value="Москва" disabled>
```

#solution
Отключённые поля не входят в данные формы — ни при обычной отправке, ни в `FormData`. Нередактируемое, но отправляемое поле делают `readonly`:

```html
<input name="city" value="Москва" readonly>
```

В проверке `FormData` не содержала `city` с `disabled`, но содержала `promo` с `readonly`, а поля внутри `fieldset disabled` пропали все. Сервер всё равно проверяет город сам: `readonly` ничего не защищает, его снимают в DevTools.
::
