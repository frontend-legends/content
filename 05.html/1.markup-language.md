# Основы HTML

HTML — язык разметки, и браузер разбирает его по алгоритму из спецификации, который никогда не отказывается от страницы: любую ошибку он «чинит» по своим правилам. Спрашивают, что такое Living Standard, можно ли положить `div` в `p`, зачем `DOCTYPE` и что такое режим совместимости. Глубже — почему `querySelector('table > tr')` возвращает `null`, почему строки таблицы пропадают после `innerHTML` и почему `<div />` в HTML не закрывается.

::tldr
- **HTML — живой стандарт WHATWG без номеров версий.** «HTML5» — название эпохи, а не версия; новые элементы и атрибуты добавляются в один постоянно обновляемый документ.
- **Модель содержимого задаёт, что может быть внутри элемента.** В `p` — только строчное содержимое, поэтому `<p><div>` парсер разрывает на два абзаца, а лишний `</p>` даёт пустой третий.
- **Парсер чинит часть ошибок, а часть оставляет:** вложенную ссылку закроет, форму в форме выкинет, в таблицу вставит `tbody`, текст из таблицы вынесет наружу, — но кнопку внутри ссылки оставит как есть. DOM может не совпадать с исходником.
- **`<!doctype html>` включает стандартный режим.** Без него — режим совместимости, где, например, CSS принимает длины без единиц.
- **Разметку не нужно «закрывать слешем»:** `<div/>` в HTML — открывающий тег, а `<br/>` — то же, что `<br>`. Строгий синтаксис с самозакрытием — у XML и JSX.
::

## Что такое HTML

Сквозной пример — карточка товара в интернет-магазине чая, которую сверстали с ошибками и не заметили, потому что «всё работает».

HTML описывает структуру документа: заголовки, абзацы, ссылки, формы, таблицы. Как это выглядит, решает CSS, а как работает — JavaScript и сам браузер.

Стандарт HTML ведёт **WHATWG** — рабочая группа производителей браузеров. Исторически версии выпускал :term[W3C]{def="Консорциум Всемирной паутины: международная организация, которая выпускает веб-стандарты"}: HTML 4.01, :term[XHTML]{def="HTML в строгом синтаксисе XML: любая ошибка разметки останавливала разбор страницы"} 1.0. В 2004 году разработчики браузеров, недовольные курсом на строгий XHTML 2.0, начали свой стандарт, и победил он. По соглашению 2019 года стандарт один — **HTML Living Standard** на whatwg.org, — а W3C публикует его снимки.

«Живой» значит без номеров: `<dialog>`, атрибут `inert`, Popover API добавляются в тот же документ и появляются в браузерах постепенно. HTML6 не будет. «HTML5» осталось названием эпохи — с семантическими элементами, `video`, `canvas` и новым алгоритмом разбора, — а не версией, которую можно указать.

## Модели содержимого

Спецификация не делит элементы на «блочные» и «строчные» — это деление осталось в CSS как `display`. Вместо него у каждого элемента есть **категории** и **модель содержимого**: что может быть внутри.

| Категория | Что это | Примеры |
| --- | --- | --- |
| потоковое (flow) | почти всё, что бывает в `body` | `div`, `p`, `ul`, `table`, `a`, текст |
| строчное (phrasing) | текст и то, что внутри текста | `span`, `a`, `strong`, `em`, `img`, `input` |
| интерактивное | то, с чем взаимодействуют | `a` с `href`, `button`, `input`, `select`, `details` |
| встроенное (embedded) | внешний контент | `img`, `video`, `iframe`, `svg`, `canvas` |
| секционное и заголовки | разделы и их заголовки | `article`, `section`, `nav`, `aside`, `h1`–`h6` |
| метаданные | то, что не отображается | `title`, `meta`, `link`, `style`, `script` |

Главные правила вложенности:

- **`p` и заголовки** — только строчное содержимое: никаких `div`, списков, других `p`;
- **`a` и `button`** — никакого интерактивного содержимого внутри: ни ссылки в ссылке, ни кнопки в ссылке;
- **`ul` и `ol`** — только `li` прямыми детьми; **`table`** — только строки, группы строк и подпись;
- **`form`** — нельзя вкладывать в другую `form`.

Почему это важно, если «и так отображается»? Потому что на нарушение правил браузер отвечает двумя способами, и оба — источник багов.

### Что парсер чинит

Карточка товара:

```html
<p>Чай улун <div>в наличии</div> скидка</p>
```

Браузер построил:

```html
<p>Чай улун </p><div>в наличии</div> скидка<p></p>
```

Встретив `div`, парсер закрыл абзац — `div` не может быть в `p`. «Скидка» оказалась голым текстом, а закрывающий `</p>` без открытого абзаца породил **пустой** `p`. В проверке Chromium выдал ровно такую разметку. Стили `p .stock` больше не находят элемент, а пустой абзац добавляет отступ.

Похожим образом исправлены:

- **ссылка в ссылке** — вторая `a` закрывает первую, и получаются две соседние ссылки;
- **форма в форме** — внутренний тег `form` просто выброшен, поля попадают во внешнюю форму;
- **необязательные закрывающие теги** — `<li>улун<li>пуэр` и `<p>один<p>два` спецификация разрешает, парсер сам закроет `li`, `p`, `td`, `option`;
- **неправильно вложенное форматирование** — `<b>жирный <i>оба</b> курсив</i>` становится `<b>жирный <i>оба</i></b><i> курсив</i>`: алгоритм adoption agency переоткрывает незакрытый `i`.

### Что парсер оставляет

```html
<a href="/tea"><button>Купить</button></a>
<ul><div><li>улун</li></div></ul>
```

Оба фрагмента в проверке остались в DOM как есть. Ошибка никуда не делась: кнопка внутри ссылки — два вложенных интерактивных элемента. В проверке Tab остановился на одном месте дважды — на ссылке и на кнопке, — и неочевидно, что сработает по клику и по Enter. `div` внутри `ul` Chromium в дереве доступности сгладил и показал два пункта, но разметка остаётся невалидной, и полагаться на такое исправление нельзя. Это ловит только валидатор — браузер молчит.

## Таблицы

Отдельный набор правил — для таблиц, и на нём ломается JavaScript:

```html
<table>
  <tr><td>Улун</td><td>990 ₽</td></tr>
  итого
</table>
```

Браузер построил:

```html
итого<table><tbody><tr><td>Улун</td><td>990 ₽</td></tr></tbody></table>
```

- **неявный `tbody`** — парсер HTML всегда кладёт строки в группу строк, даже если в разметке её нет. Поэтому `document.querySelector('table > tr')` в проверке вернул `null`, а `table > tbody > tr` — строку;
- **вынос текста** — текст, которому не место внутри таблицы, переносится перед ней (foster parenting).

То же правило контекста работает в `innerHTML`: фрагмент разбирается так, как если бы он стоял внутри этого элемента.

```js
const div = document.createElement('div');
div.innerHTML = '<td>Улун</td><td>990 ₽</td>';   // «Улун990 ₽» — ячейки выброшены
```

Ячейки вне таблицы недопустимы, и в проверке от них остался только текст. В `tr` тот же фрагмент дал две ячейки, а `template` принимает любой фрагмент без потерь — поэтому строки таблиц собирают через `<template>` или `insertRow()`. И ещё одно правило `innerHTML`: вставленный так `<script>` не выполняется — в проверке не выполнился, а созданный через `createElement('script')` выполнился. Атрибуты-обработчики при этом работают, поэтому `innerHTML` с чужими данными — путь к :term[XSS]{def="межсайтовый скриптинг: чужой скрипт попадает на страницу через непроверенные данные"} (подробно — в [XSS](/content/security-perfomance/xss)).

## DOCTYPE и режимы

```html
<!doctype html>
```

Это не тег и не ссылка на схему, а переключатель режима. У документа три режима:

| Режим | Когда | Что значит |
| --- | --- | --- |
| стандартный (no-quirks) | `<!doctype html>` | CSS и раскладка по спецификациям |
| почти стандартный (limited-quirks) | некоторые старые DOCTYPE, например HTML 4.01 Transitional с адресом DTD | стандартный, кроме высоты строк с картинками в ячейках таблиц |
| совместимости (quirks) | нет DOCTYPE или старый без адреса DTD | эмуляция поведения браузеров конца 1990-х |

`document.compatMode` показывает режим: в проверке страница без DOCTYPE дала `BackCompat`, с `<!doctype html>` — `CSS1Compat`. Режим совместимости меняет десятки мелочей. Одна из них — в CSS принимаются длины без единиц: `width: 100` в проверке дал 100px, а в стандартном режиме объявление отбросили. Отсюда «вёрстка разъехалась в другом проекте»: шаблон без DOCTYPE переключает всю страницу.

## Как браузер разбирает HTML

```text
байты → символы → токены → узлы → DOM
```

- **декодирование** — байты превращаются в символы по кодировке из заголовка ответа или `<meta charset>` в начале документа (подробно — в [Содержимом head](/content/html/head-content));
- **токенизатор** — конечный автомат, который превращает символы в токены: открывающий тег с атрибутами, закрывающий, текст, комментарий, DOCTYPE;
- **построение дерева** — по токенам строит DOM, держа стек открытых элементов и «режим вставки»: в `head`, в `body`, в таблице. Здесь живут все исправления ошибок выше — для каждого режима спецификация описывает, что делать с неожиданным тегом.

Без явных `html`, `head` и `body` парсер создаёт их сам: `<!doctype html><title>Каталог</title><h1>Чай</h1>` в проверке превратился в полный документ с `head` и `body`. Разбор идёт потоком — DOM строится по мере прихода байтов, а синхронный скрипт останавливает его. Что это значит для загрузки страницы — в [Структуре документа](/content/html/structure).

## Символьные ссылки

Символы, которые иначе будут разметкой, записывают ссылками:

| Ссылка | Символ | Когда нужна |
| --- | --- | --- |
| `&lt;` | `<` | в тексте, чтобы не начался тег |
| `&amp;` | `&` | чтобы не началась другая ссылка |
| `&quot;` | `"` | внутри атрибута в двойных кавычках |
| `&nbsp;` | неразрывный пробел U+00A0 | между числом и единицей: `1&nbsp;000&nbsp;₽` |
| `&#8212;`, `&#x2014;` | `—` | любой символ по коду |

В UTF-8 остальные символы — `«»`, `₽`, `©` — пишут как есть.

Точку с запятой в конце ссылки опускать нельзя, хотя иногда «работает». Ради старых страниц парсер распознаёт около сотни ссылок без `;`: `&copy 2026` в проверке дал «© 2026». Но тот же механизм превратил `&notit;` в «¬it;» — парсер нашёл в начале `&not`. В атрибутах правило другое: адрес `?sort=price&copy=1` остался нетронутым, потому что за `&copy` идёт `=`. Надёжное правило — в тексте и атрибутах писать `&amp;` вместо голого `&`.

## HTML, XHTML и JSX

У HTML свой синтаксис, и он не XML.

```html
<div/>Улун<span/>990 ₽
```

Слеш в открывающем теге HTML **игнорируется**. Браузер построил `<div>Улун<span>990 ₽</span></div>`: `div` и `span` остались открытыми и проглотили всё дальше. Слеш допустим только у пустых элементов — `br`, `img`, `input`, `meta`, — где он ничего не меняет: `<br/>` равен `<br>`. У них закрывающего тега нет вовсе, а у остальных элементов он обязателен. Исключение — SVG и :term[MathML]{def="язык разметки математических формул внутри HTML"} внутри HTML: там самозакрытие работает, и `<circle r="1"/>` в проверке закрылся.

| | HTML | XHTML | JSX |
| --- | --- | --- | --- |
| разбор | терпимый, с исправлением ошибок | строгий XML | компилятор JSX |
| `<div/>` | открывающий тег | пустой элемент | пустой элемент |
| ошибка разметки | DOM «исправлен» | страница не показывается | ошибка компиляции |
| тип ответа | `text/html` | `application/xhtml+xml` | — |

В проверке XML-документ с незакрытым `p` дал ошибку разбора вместо страницы, а `<div/>` в нём — пустой элемент. Из-за этой строгости XHTML не прижился. JSX выглядит как HTML, но живёт по правилам XML: в нём `<div />` закрыт, а `<br>` без слеша — ошибка.

Ошибки разметки браузер не показывает. Их ищут валидатором, линтером шаблонов и в DevTools: вкладка Elements показывает построенный DOM, а не исходник, и расхождение видно сразу.

## Красные флаги в ответе

- **«HTML5 — последняя версия, скоро будет HTML6».** Стандарт живой и без версий.
- **«`div` в `p` — просто плохой стиль».** Парсер разрывает абзац, DOM отличается от исходника, а лишний `</p>` даёт пустой абзац.
- **«Браузер всё исправит».** Часть ошибок он оставляет как есть — например, кнопку внутри ссылки, — и они ломают поведение и доступность.
- **«`table > tr` найдёт строку».** Парсер вставил `tbody`, строка — его ребёнок.
- **«`<div />` — самозакрывающийся тег».** В HTML слеш игнорируется, элемент остаётся открытым.
- **«DOCTYPE ни на что не влияет».** Без него страница работает в режиме совместимости.

## Как спрашивают на собеседовании

::question
Что такое HTML Living Standard и почему нет HTML6?

#answer
Стандарт HTML ведёт WHATWG как один постоянно обновляемый документ без номеров версий. Новые возможности — `dialog`, `inert`, Popover API — добавляются в него и появляются в браузерах по мере реализации.

#more
Исторически версии выпускал W3C. В 2004 году производители браузеров создали WHATWG в ответ на курс W3C на строгий XHTML 2.0, и по соглашению 2019 года стандарт остался один. «HTML5» — название эпохи с семантическими элементами, медиа и новым алгоритмом разбора, а не версия. Поддержку конкретной возможности проверяют по таблицам совместимости, а не по номеру HTML.
::

::question
Можно ли положить div внутрь p? Что сделает браузер?

#answer
Нельзя: в `p` допустимо только строчное содержимое, а `div` — потоковое. Встретив `div`, парсер закроет абзац, `div` станет соседом, а закрывающий `</p>` без открытого абзаца создаст пустой `p`.

#more
`<p>Текст <div>блок</div> ещё</p>` превращается в `<p>Текст </p><div>блок</div> ещё<p></p>`. Ломаются стили по вложенности, появляются лишние отступы, а JavaScript не находит ожидаемые элементы. Внутри `p` используют `span` и другие строчные элементы; блочная обёртка — `div` снаружи.
::

::question
Какие ошибки разметки браузер исправляет, а какие оставляет?

#answer
Исправляет то, что описано в алгоритме разбора: закрывает `p` перед блоком, разделяет вложенные ссылки, выбрасывает вложенный `form`, вставляет `tbody` и неявные `html`, `head`, `body`, выносит текст из таблицы, переоткрывает неправильно вложенное форматирование. Оставляет то, что парсер не трогает: кнопку внутри ссылки, `div` внутри `ul`.

#more
В обоих случаях страница «работает», поэтому ошибки годами живут в коде. Исправленные дают DOM, который отличается от исходника, — ломаются селекторы и скрипты. Оставленные ломают поведение и доступность. Ловят их валидатором и линтером шаблонов, а DOM смотрят во вкладке Elements, а не в исходнике.
::

::question
Зачем нужен DOCTYPE? Что такое режим совместимости?

#answer
`<!doctype html>` включает стандартный режим. Без него или со старым DOCTYPE браузер работает в режиме совместимости — эмулирует поведение старых браузеров ради древних сайтов. Режим виден в `document.compatMode`: `CSS1Compat` или `BackCompat`.

#more
В режиме совместимости меняются раскладка таблиц, высота строк, обработка CSS — например, длины без единиц принимаются как пиксели. Есть и почти стандартный режим для некоторых старых DOCTYPE: отличается только высотой строк с картинками в ячейках. Шаблон без DOCTYPE переключает всю страницу, и вёрстка компонентов неожиданно разъезжается.
::

::question
Как браузер разбирает HTML?

#answer
Байты декодируются в символы, токенизатор превращает их в токены — теги, текст, комментарии, — а построитель дерева создаёт из токенов DOM. Он держит стек открытых элементов и режим вставки и по правилам спецификации исправляет ошибки.

#more
Разбор потоковый: DOM строится по мере прихода байтов. Синхронный скрипт останавливает разбор, а сканер предзагрузки тем временем ищет дальше ресурсы для загрузки. `innerHTML` разбирает фрагмент в контексте элемента: `td` внутри `div` выбрасываются, а в `template` сохраняются. Скрипты, вставленные через `innerHTML`, не выполняются.
::

::question
Почему `<div />` в HTML не закрывается?

#answer
В синтаксисе HTML слеш в открывающем теге игнорируется. `<div/>` — это просто `<div>`, и всё после него окажется внутри. Слеш допустим только у пустых элементов вроде `br`, `img`, `input`, у которых нет закрывающего тега, и там он ничего не меняет. Самозакрытие работает лишь внутри SVG и MathML.

#more
Самозакрытие — синтаксис XML: в XHTML, отданном как `application/xhtml+xml`, и в JSX `<div />` — пустой элемент. Но XHTML строг: одна ошибка разметки, и вместо страницы ошибка разбора. С веб-компонентами то же самое: `<my-card/>` в HTML не закрыт.
::

::question
Когда нужны символьные ссылки вроде `&amp;` и `&nbsp;`?

#answer
Для символов, которые иначе станут разметкой: `&lt;` и `&amp;` в тексте, `&quot;` внутри атрибута. `&nbsp;` — неразрывный пробел, чтобы число не отрывалось от единицы. Остальные символы в UTF-8 пишут как есть.

#more
Точка с запятой обязательна: ради старых страниц парсер распознаёт часть ссылок без неё, и `&notit;` в тексте превращается в «¬it;». В адресах в атрибутах `&` перед параметром обычно переживает разбор, но правило простое — всегда `&amp;`. Для вывода пользовательского текста не экранируют вручную, а используют `textContent` или экранирование шаблонизатора.
::

## Практика

::practice{title="Что построит браузер?"}
Какой DOM получится из этой разметки и сколько в нём абзацев?

```html
<p class="card">Чай улун <div class="stock">в наличии</div> скидка 10%</p>
```

#solution
Три абзаца, два из них пустые или без класса:

```html
<p class="card">Чай улун </p><div class="stock">в наличии</div> скидка 10%<p></p>
```

`div` нельзя класть в `p`, поэтому парсер закрыл абзац перед ним. «Скидка 10%» стала текстом в родителе, а `</p>` без открытого абзаца создал новый пустой `p`. Селектор `.card .stock` ничего не найдёт. Исправление — строчный элемент внутри абзаца или блочная обёртка снаружи:

```html
<div class="card">Чай улун <span class="stock">в наличии</span> скидка 10%</div>
```

В проверке Chromium построил из исходной разметки ровно `<p>Чай улун </p><div>в наличии</div> скидка<p></p>`.
::

::practice{title="Строка таблицы не находится"}
Тест падает: `row` равен `null`, хотя строка в таблице есть:

```html
<table id="cart"><tr><td>Улун</td><td>990 ₽</td></tr></table>
```

```js
const row = document.querySelector('#cart > tr');
```

#solution
Парсер HTML всегда кладёт строки в `tbody`, даже если его нет в разметке: в DOM получилось `table > tbody > tr`. Селектор с `>` ищет непосредственного ребёнка и ничего не находит.

```js
const row = document.querySelector('#cart tr');           // потомок на любой глубине
// или явно
const row2 = document.querySelector('#cart > tbody > tr');
```

Надёжнее писать `tbody` в разметке самому — тогда исходник и DOM совпадают. В проверке `table > tr` вернул `null`, а `table > tbody > tr` — строку.
::

::practice{title="Ячейки пропали после innerHTML"}
Корзина добавляет строку товара, но в таблице появляется текст без ячеек:

```js
const row = document.createElement('div');
row.innerHTML = `<td>${name}</td><td>${price}</td>`;
table.tBodies[0].append(...row.childNodes);
```

#solution
`innerHTML` разбирает фрагмент в контексте элемента. Внутри `div` ячейки недопустимы, и парсер выбросил теги `td`, оставив текст. Разбирать нужно в правильном контексте или через `template`, а данные вставлять как текст:

```js
const row = table.tBodies[0].insertRow();
row.insertCell().textContent = name;
row.insertCell().textContent = price;
```

```js
// или шаблоном, который принимает любой фрагмент
const tpl = document.createElement('template');
tpl.innerHTML = '<tr><td class="name"></td><td class="price"></td></tr>';
```

В проверке `<td>Улун</td><td>990 ₽</td>` в `div` превратился в «Улун990 ₽», в `tr` дал две ячейки, а в `template` сохранился полностью. `textContent` вместо подстановки в `innerHTML` заодно закрывает XSS через название товара.
::
