# Атрибуты

Атрибуты настраивают элементы: состояние, данные, поведение, доступность и безопасность. Спрашивают, чем атрибут отличается от свойства DOM, что будет с `disabled="false"`, зачем `data-*` и `rel="noopener"`. Глубже — почему `setAttribute('value')` перестаёт менять поле после ввода, почему `draggable="false"` работает, а `disabled="false"` — нет, и откуда взялась глобальная переменная `cart`.

::tldr
- **Атрибут — то, что в разметке, свойство — поле DOM-объекта.** Большинство стандартных атрибутов отражаются в свойства, но `value` и `checked` задают только начальное значение: после ввода пользователя свойство живёт отдельно.
- **Булевый атрибут работает наличием:** `disabled="false"` кнопку отключает. А перечислимые — `contenteditable`, `draggable`, `spellcheck` — понимают слово `"false"`.
- **`data-*` читаются через `dataset` в camelCase и всегда строки.** Свои атрибуты без `data-` не создают свойств и невалидны.
- **`id` должен быть уникальным и становится глобальной переменной `window`.** `id`, начинающийся с цифры, требует `CSS.escape` в селекторе.
- **`inert` выключает поддерево целиком, `popover` и `commandfor` открывают меню и окна без JavaScript,** а `target="_blank"` сам добавляет `noopener`.
::

## Атрибут и свойство

Сквозной пример — карточка товара: поле количества, кнопка «В корзину» с данными о товаре, меню фильтров и окно подтверждения.

```html
<input id="qty" value="1">
```

У элемента два мира:

- **атрибуты** — то, что пришло из разметки: `getAttribute('value')`, `setAttribute`, `attributes`;
- **свойства** — поля JavaScript-объекта элемента: `qty.value`, `qty.disabled`, `qty.id`.

Большинство стандартных атрибутов **отражаются** в свойства: прочитал свойство — получил атрибут, записал — изменил атрибут. Но не все и не всегда одинаково.

### value и checked

`value` у `input` — **начальное** значение поля. Текущее хранит свойство:

```js
// пользователь ввёл 3
qty.getAttribute('value');   // "1" — атрибут не изменился
qty.value;                   // "3" — текущее значение
qty.defaultValue;            // "1" — свойство, которое отражает атрибут
```

Всё это в проверке так и вышло. Хуже того, после ввода `setAttribute('value', '5')` поле уже **не меняет**: значение помечено как изменённое пользователем, и атрибут влияет только на `defaultValue`. В поле, которого не касались, тот же вызов значение поменял. А `form.reset()` вернул поле к атрибуту — `"1"`. С `checked` и `defaultChecked` у флажков то же самое.

Отсюда правило: текущее состояние читают и пишут через свойства, а атрибут — это значение по умолчанию. Так и устроены фреймворки: в React `defaultValue` — начальное значение неуправляемого поля, `value` — управляемое (подробно — в [Состоянии и событиях React](/content/reactjs/state-and-events)).

### Как отражаются остальные

| Атрибут | Свойство | Особенность |
| --- | --- | --- |
| `id` | `id` | в обе стороны |
| `class` | `className`, `classList` | другое имя: `class` — зарезервированное слово |
| `for` | `htmlFor` | так же |
| `href`, `src` | `href`, `src` | свойство — **полный** адрес: `/tea?sort=price` превратился в `http://localhost:…/tea?sort=price` |
| `type` | `type` | неверное значение даёт значение по умолчанию: `type="phone"` — свойство `"text"`, атрибут остаётся `"phone"` |
| `style` | `style` | строка против объекта `CSSStyleDeclaration` |
| свой атрибут `price="990"` | — | свойства не появится: `box.price` — `undefined` |

И наоборот: своё свойство `box.discount = 10` атрибута не создаёт. В проверке оба направления подтвердились.

## Булевые и перечислимые атрибуты

**Булевый атрибут** работает присутствием: есть — `true`, нет — `false`. Значение не важно.

```html
<button disabled="false">Купить</button>   <!-- отключена! -->
```

В проверке `disabled` у этой кнопки — `true`. Включают её удалением атрибута или свойством: `button.disabled = false` атрибут удалил. Булевые: `disabled`, `checked`, `selected`, `required`, `readonly`, `hidden`, `open`, `multiple`, `autofocus`, `inert`, `novalidate`.

**Перечислимые атрибуты** выглядят похоже, но принимают слова:

```html
<img src="tea.png" alt="" draggable="false">   <!-- не перетаскивается -->
<div contenteditable="false">…</div>            <!-- не редактируется -->
```

`draggable`, `contenteditable`, `spellcheck` и `aria-*` понимают `"true"` и `"false"` как слова, а `translate` — `"yes"` и `"no"` — в проверке `draggable="false"` выключил перетаскивание, а `contenteditable="false"` — редактирование. Тот же `hidden="false"` скрыл элемент, потому что `hidden` булевый. Отличить их помогает только спецификация, поэтому в шаблонах для булевых атрибутов используют условное добавление, а не значение `"false"`.

## data-атрибуты

Свои данные на элементе хранят в атрибутах с префиксом `data-`:

```html
<button id="add" data-product-id="42" data-in-stock="true" data-price="990">В корзину</button>
```

```js
add.dataset.productId;   // "42" — data-product-id → productId
add.dataset.inStock;     // "true" — строка, а не true
add.dataset.isAdded = true;   // создаст data-is-added="true"
delete add.dataset.inStock;   // удалит атрибут
```

- **имена** переводятся из kebab-case в camelCase и обратно;
- **значения — всегда строки:** `dataset.price` — `"990"`, а записанные `true` и `2` превратились в `"true"` и `"2"`;
- **из CSS** их видно селектором `[data-in-stock="true"]` и функцией `attr()` в `content`.

Атрибут без `data-` — `price="990"` — невалиден и в будущем может столкнуться с новым стандартным атрибутом. `data-testid` — стабильная зацепка для тестов, но тесты лучше ищут элементы по роли и тексту (подробно — в [E2E-тестировании](/content/testing-deploying/e2e-testing)).

## Глобальные атрибуты

Глобальные атрибуты допустимы на любом элементе:

| Атрибут | Что делает |
| --- | --- |
| `id` | уникальный идентификатор |
| `class`, `style` | классы и встроенный стиль |
| `lang`, `dir` | язык и направление текста |
| `hidden` | скрыть; `hidden="until-found"` — скрыть, но раскрыть при поиске по странице |
| `inert` | выключить поддерево целиком |
| `popover` | сделать элемент всплывающим |
| `tabindex` | управлять фокусом (подробно — в [Доступности](/content/html/accessibility)) |
| `title` | всплывающая подсказка — не видна на телефоне и для клавиатуры, поэтому не единственная подпись |
| `translate="no"` | не переводить автоматически: названия товаров, бренды |
| `contenteditable`, `spellcheck`, `autocapitalize` | редактирование, проверка орфографии, заглавные буквы на телефоне |
| `inputmode`, `enterkeyhint` | вид экранной клавиатуры и подпись клавиши ввода |
| `autofocus` | фокус при загрузке или открытии `dialog` |
| `nonce`, `part`, `slot` | CSP, стилизация и слоты веб-компонентов |

### id

```html
<div id="cart">корзина</div>
```

У `id` три неочевидных свойства:

- **глобальная переменная** — элемент доступен как `window.cart`; в проверке так и было. Объявленная переменная с тем же именем его затеняет, а опечатка в имени переменной находит элемент вместо ошибки;
- **уникальность** — два `id="cart"` браузер принимает молча: `getElementById` вернул первый, а `window.cart` стал коллекцией. Ломаются `label for`, `aria-labelledby` и якоря;
- **селектор** — `id="1st"` допустим в HTML, но `querySelector('#1st')` бросил `SyntaxError`: идентификатор в CSS не может начинаться с цифры. Работает `querySelector('#' + CSS.escape('1st'))` или `getElementById('1st')`.

### Обработчики в атрибутах

```html
<form>
  <input name="qty" value="3">
  <button type="button" onclick="addToCart(qty.value)">В корзину</button>
</form>
```

Атрибут `onclick` — строка кода, которую браузер оборачивает в функцию с необычной областью видимости: внутри видны `this` — элемент, `event` и **поля формы по имени**. В проверке обработчик прочитал `qty.value` без единого `querySelector`. Такие обработчики не используют в приложениях:

- их блокирует CSP без `'unsafe-inline'` (подробно — в [CSP и заголовках безопасности](/content/security-perfomance/csp-and-security-headers));
- свойство `onclick` одно: второе присваивание затёрло первое, а `addEventListener` в проверке добавил двух слушателей и оба сработали;
- код в строке не проверяет ни линтер, ни TypeScript.

## inert, popover и commandfor

### inert

```html
<main inert>…</main>
```

`inert` выключает поддерево целиком. В проверке кнопка внутри не получила фокус ни через `focus()`, ни по Tab, клик мышью по ней не вызвал обработчик, а в дереве доступности Chromium осталась только кнопка снаружи. Так отключают фон под самописным окном или неактивный шаг формы. Модальный `dialog` делает фон инертным сам.

### popover

```html
<button popovertarget="filters">Фильтры</button>
<div id="filters" popover>…</div>
<div id="toast" popover="manual">Добавлено в корзину</div>
```

Атрибут `popover` превращает элемент во всплывающий: он показывается в верхнем слое поверх всего, а кнопка с `popovertarget` открывает и закрывает его без JavaScript.

- **`popover` или `popover="auto"`** — закрывается кликом мимо и по Esc, а открытие другого такого же закрывает предыдущий. В проверке «Сортировка» закрыла «Фильтры», клик мимо закрыл «Сортировку», Esc закрыл «Фильтры»;
- **`popover="manual"`** — закрывается только кодом или своей кнопкой: тост пережил и клик мимо, и Esc.

`:popover-open` стилизует открытое состояние, а привязать окно к кнопке помогает якорное позиционирование (подробно — в [Современном CSS](/content/css/modern-css)).

### commandfor

```html
<button commandfor="confirm" command="show-modal">Удалить</button>
<dialog id="confirm"><button commandfor="confirm" command="close">Отмена</button></dialog>
```

`commandfor` указывает, каким элементом управляет кнопка, а `command` — что сделать: `show-modal`, `close`, `toggle-popover` и другие. В проверке кнопка открыла модальный `dialog`, а «Отмена» закрыла его — без строки JavaScript. Свои команды начинаются с `--` и ловятся событием `command` на целевом элементе.

## Атрибуты безопасности

- **`target="_blank"` и `rel`.** Раньше новая вкладка получала `window.opener` и могла подменить адрес исходной страницы на фишинговую. Сейчас браузеры добавляют `noopener` к `target="_blank"` сами: в проверке открытая так страница увидела `opener` равным `null`, а с явным `rel="opener"` — получила доступ. `rel="noreferrer"` ещё и не передаёт адрес страницы;
- **`crossorigin`, `integrity`, `referrerpolicy`** — режим CORS, проверка целостности файла с CDN и политика заголовка `Referer` (подробно — в [Цепочке поставок](/content/security-perfomance/supply-chain-and-vulnerabilities));
- **`sandbox`, `allow` у `iframe`** — в [Медиа](/content/html/media).

## Красные флаги в ответе

- **«`getAttribute('value')` вернёт то, что ввёл пользователь».** Атрибут — начальное значение, текущее — в свойстве.
- **«`disabled="false"` включит кнопку».** Булевый атрибут работает наличием.
- **«`draggable="false"` тоже не сработает».** Это перечислимый атрибут, он понимает `"false"`.
- **«`dataset.count` вернёт число».** Значения `data-*` всегда строки.
- **«Два одинаковых `id` — не страшно».** Ломаются `label`, ARIA и якоря, а `window.id` становится коллекцией.
- **«`rel="noopener"` обязателен на каждой ссылке с `target="_blank"`».** Браузеры добавляют его сами; явно пишут для старых браузеров или когда нужен `noreferrer`.

## Как спрашивают на собеседовании

::question
Чем атрибут отличается от свойства DOM?

#answer
Атрибут — то, что записано в разметке, читается через `getAttribute`. Свойство — поле объекта элемента. Большинство стандартных атрибутов отражаются в свойства, но `value` и `checked` задают только начальное значение: после ввода пользователя `input.value` меняется, а атрибут — нет.

#more
У отражения есть особенности: `class` — это `className`, `for` — `htmlFor`, `href` в свойстве — полный адрес, неверный `type` в свойстве превращается в значение по умолчанию. После ввода `setAttribute('value')` уже не меняет видимое значение — только `defaultValue`. Свои атрибуты не создают свойств, а свои свойства — атрибутов.
::

::question
Что будет, если написать disabled="false"?

#answer
Кнопка останется отключённой: `disabled` — булевый атрибут, и важно только его наличие. Включают её удалением атрибута или `button.disabled = false`, которое атрибут удаляет.

#more
Перечислимые атрибуты устроены иначе: `draggable`, `contenteditable`, `spellcheck`, `aria-*` понимают слово `"false"`. Поэтому `draggable="false"` работает, а `disabled="false"` — нет. В шаблонах булевые атрибуты добавляют условно; фреймворки делают это сами для известных атрибутов.
::

::question
Зачем нужны data-атрибуты?

#answer
Чтобы хранить свои данные на элементе валидно: `data-product-id="42"`. Из JavaScript они доступны через `dataset` с переводом в camelCase, из CSS — селекторами атрибутов и `attr()`.

#more
Значения всегда строки: записанное `true` станет `"true"`. Атрибут без `data-` невалиден и может однажды совпасть со стандартным. Для состояния интерфейса удобно `data-state="open"` вместо набора классов. Для тестов `data-testid` работает, но поиск по роли и тексту проверяет ещё и доступность.
::

::question
Что не так с id?

#answer
`id` должен быть уникальным, но браузер не проверяет это: `getElementById` вернёт первый, а `label for`, `aria-labelledby` и якоря будут указывать не туда. Ещё каждый `id` становится глобальной переменной `window` с тем же именем.

#more
Глобальная переменная из `id` маскирует опечатки: обращение к необъявленной `cart` вернёт элемент вместо ошибки. `id`, начинающийся с цифры, допустим в HTML, но в CSS-селекторе требует `CSS.escape`. В компонентах уникальные `id` для связи подписей генерируют — в React через `useId`.
::

::question
Почему не используют onclick в разметке?

#answer
Его блокирует CSP без `'unsafe-inline'`, свойство `onclick` одно и перезаписывается, а код в строке не видят линтер и TypeScript. Вместо этого `addEventListener`: несколько слушателей, опции `once`, `passive`, `signal`.

#more
Область видимости у обработчика в атрибуте необычная: внутри видны `this` — элемент, `event` и поля формы по имени, поэтому старый код работает «магически». Обработчики в JSX и шаблонах Vue — не атрибуты HTML: фреймворк навешивает их через `addEventListener`.
::

::question
Что делают inert и popover?

#answer
`inert` выключает поддерево: элементы не получают фокус и клики и пропадают из дерева доступности. `popover` делает элемент всплывающим в верхнем слое; кнопка с `popovertarget` открывает и закрывает его без JavaScript.

#more
`popover="auto"` закрывается кликом мимо и по Esc, а открытие другого `auto` закрывает предыдущий; `manual` закрывается только кодом. `commandfor` с `command` управляет `dialog` и `popover` из разметки: `show-modal`, `close`, `toggle-popover`. Модальный `dialog` делает фон инертным сам.
::

::question
Зачем rel="noopener" у ссылок с target="_blank"?

#answer
Без него новая вкладка получала `window.opener` и могла перенаправить исходную страницу на фишинговую копию. `noopener` обнуляет `opener`. Сейчас браузеры добавляют его к `target="_blank"` автоматически, а доступ возвращает только явный `rel="opener"`.

#more
`noreferrer` дополнительно не передаёт адрес страницы в `Referer` и тоже отключает `opener`. Для окон из JavaScript — `window.open(url, '_blank', 'noopener')`. Такая атака называется tabnabbing; явный `rel` пишут для старых браузеров и ради `noreferrer`.
::

## Практика

::practice{title="Количество не сбрасывается"}
После добавления в корзину поле количества должно вернуться к 1, но остаётся то, что ввёл пользователь:

```js
addButton.addEventListener('click', () => {
  addToCart(productId, Number(qty.value));
  qty.setAttribute('value', '1');
});
```

#solution
Атрибут `value` — начальное значение. Как только пользователь ввёл своё, поле помечено изменённым, и атрибут больше не влияет на видимое значение — только на `defaultValue`. Текущее значение меняют свойством:

```js
addButton.addEventListener('click', () => {
  addToCart(productId, Number(qty.value));
  qty.value = '1';
});
```

В проверке в Chromium после ввода `setAttribute('value', '5')` оставил в поле введённое `"3"`, а в нетронутом поле тот же вызов поменял значение. Если сбросить нужно всю форму к исходным значениям — `form.reset()`.
::

::practice{title="Кнопка не включается"}
Шаблон выводит состояние кнопки из данных, но кнопка «Оформить заказ» всегда неактивна:

```js
button.outerHTML = `<button disabled="${cart.length === 0}">Оформить заказ</button>`;
```

#solution
`disabled` — булевый атрибут: при непустой корзине получается `disabled="false"`, и кнопка всё равно отключена. Атрибут нужно добавлять или не добавлять, а надёжнее — управлять свойством:

```js
button.disabled = cart.length === 0;
```

```js
// в шаблонной строке — условно
`<button ${cart.length === 0 ? 'disabled' : ''}>Оформить заказ</button>`
```

В проверке `disabled="false"` дал `disabled === true`, а `button.disabled = false` удалил атрибут. Во фреймворках `:disabled="false"` во Vue и `disabled={false}` в React атрибут убирают сами.
::

::practice{title="Меню фильтров без JavaScript"}
Меню фильтров открывается скриптом с обработчиками кликов мимо, Esc и закрытием соседних меню — двести строк и баги с фокусом. Как сделать проще?

#solution
`popover` даёт всё это из коробки:

```html
<button popovertarget="filters">Фильтры</button>
<div id="filters" popover>
  <label><input type="checkbox" name="type" value="oolong"> Улун</label>
  <label><input type="checkbox" name="type" value="puer"> Пуэр</label>
</div>
<button popovertarget="sort">Сортировка</button>
<div id="sort" popover>…</div>
```

Меню открывается кнопкой, рисуется в верхнем слое над любым `z-index`, закрывается кликом мимо и по Esc, а открытие сортировки закрывает фильтры. В проверке в Chromium всё это подтвердилось без строки JavaScript. Положение рядом с кнопкой задаёт якорное позиционирование.
::
