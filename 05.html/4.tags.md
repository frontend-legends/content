# Семантика и теги

Семантика — это выбор элемента по смыслу, а не по виду: браузер превращает её в роли дерева доступности, и по ним ходят программы чтения с экрана, поисковики, режим чтения и ИИ-агенты. Спрашивают, чем `section` отличается от `article` и `div`, сколько `h1` должно быть на странице, когда ссылка, а когда кнопка. Глубже — почему `header` внутри статьи не ориентир, почему `section` без заголовка ничего не значит и что `dialog` даёт бесплатно по сравнению с самописной модалкой.

::tldr
- **Семантика — это роли в дереве доступности.** `header`, `nav`, `main`, `aside`, `footer` становятся ориентирами, между которыми прыгают программы чтения с экрана; `div` и `span` ролей не дают.
- **`header` и `footer` — ориентиры только на уровне страницы,** внутри `article` или `section` они обычные. `section` становится регионом, только если у неё есть имя.
- **Алгоритма outline нет:** уровень заголовка — цифра в `h1`–`h6`, и `h1` внутри `section` остаётся первым уровнем. Иерархию строят цифрами без пропусков.
- **Ссылка ведёт, кнопка действует.** `a` без `href` — не ссылка: её нет ни в дереве как ссылки, ни в порядке Tab.
- **`dialog` с `showModal()` даёт верхний слой, перенос фокуса, закрытие по Esc и инертный фон,** а `details` с общим `name` — аккордеон, где открыта одна секция, без JavaScript.
::

## Зачем семантика

Сквозной пример — страница блога магазина чая «Как заваривать улун» с шапкой, навигацией, статьёй, блоком похожих сортов и подвалом.

Браузер строит из DOM **дерево доступности**: у каждого узла есть роль, имя и состояние. Программа чтения с экрана читает не пиксели, а это дерево. Роль берётся из элемента: `button` — кнопка, `a` с `href` — ссылка, `nav` — навигация. У `div` и `span` роли нет.

| Кому | Что даёт семантика |
| --- | --- |
| программам чтения с экрана | переходы по ориентирам, заголовкам, спискам и таблицам одной клавишей |
| клавиатуре | кнопки и ссылки в порядке Tab, Enter и пробел работают сами |
| поисковикам и режиму чтения | понимают, где основное содержимое, а где меню и реклама |
| разработчику | `nav` и `article` читаются лучше, чем `div class="nav"` |

Div-суп — шапка, меню и «кнопка» из `div` с `onclick` — в проверке не дал в дереве ни одного ориентира, ссылки или кнопки: только текст. Как дерево доступности используют и как его дополняет :term[ARIA]{def="атрибуты, которые сообщают вспомогательным технологиям роль, состояние и имя элемента"} — в [Доступности](/content/html/accessibility).

## Ориентиры

```html
<header>Магазин чая</header>
<nav aria-label="Основная">…</nav>
<main>
  <article>
    <header>Как заваривать улун</header>
    <section aria-labelledby="temp"><h2 id="temp">Температура</h2>…</section>
    <footer>Автор: сомелье магазина</footer>
  </article>
  <aside>Похожие сорта</aside>
</main>
<footer>© Магазин чая</footer>
```

| Элемент | Роль-ориентир | Условие |
| --- | --- | --- |
| `header` | `banner` | только если не внутри `article`, `aside`, `main`, `nav`, `section` |
| `footer` | `contentinfo` | так же |
| `nav` | `navigation` | всегда; несколько меню различают через `aria-label` |
| `main` | `main` | один видимый на странице |
| `aside` | `complementary` | всегда |
| `section` | `region` | только с именем — `aria-label` или `aria-labelledby` |
| `article` | `article` | всегда |

В проверке на странице выше оказался один `banner` и один `contentinfo` — шапка и подвал статьи ориентирами не стали. `section` без имени — просто группа, а с `aria-labelledby` на заголовок — регион «Температура».

### section, article или div

```text
Самостоятельный кусок, который имеет смысл отдельно — пост, комментарий, карточка товара?
  да  → article
  нет → Раздел со своим заголовком?
          да  → section
          нет → div: обёртка для раскладки, без смысла
```

`article` — то, что можно вынести в :term[RSS]{def="формат ленты обновлений сайта, на которую подписываются в программах-читалках"} или на другую страницу и оно не потеряет смысла. `section` — тематический раздел внутри чего-то, и без заголовка он бессмыслен. `div` — честная обёртка для стилей, и это нормально: семантика нужна там, где она что-то сообщает.

## Заголовки

Программы чтения с экрана чаще всего ходят по заголовкам, поэтому уровни `h1`–`h6` — главная структура страницы.

Спецификация HTML5 когда-то описывала «алгоритм outline»: уровень заголовка определялся бы вложенностью секций, и в каждой `section` можно было бы начинать с `h1`. Его не реализовал ни один браузер и ни одна программа чтения, и из спецификации его убрали. В проверке `h1` внутри `section` в дереве доступности остался заголовком первого уровня. Стиль браузера тоже больше не уменьшает такой `h1` — оба `h1` на странице получили по 32px.

Правила:

- **уровень — это цифра:** главный заголовок страницы — `h1`, разделы — `h2`, подразделы — `h3`;
- **без пропусков:** после `h1` идёт `h2`, а не `h3`. Пропуск никто не «исправит» — в проверке `h3` так и остался третьим уровнем;
- **один `h1`** — общепринятая практика: он совпадает с темой страницы и `title`. Спецификация несколько `h1` не запрещает, но для навигации по заголовкам один понятнее;
- **уровень — по структуре, а не по размеру:** нужен мелкий шрифт — меняют CSS, а не цифру.

## Текст и списки

| Элемент | Смысл |
| --- | --- |
| `strong` | важность: «Не заваривайте кипятком» |
| `em` | смысловое ударение, меняющее смысл фразы |
| `b` | выделение без важности: ключевые слова, название товара в обзоре |
| `i` | другой голос: термин, иностранное слово, мысль |
| `mark` | подсветка: найденное в поиске |
| `time datetime="2026-11-16"` | дата в машиночитаемом виде |
| `del` и `ins` | удалённое и добавленное: старая и новая цена |
| `s` | устаревшее, уже неверное |
| `code`, `kbd`, `abbr`, `small` | код, клавиша, аббревиатура, мелкий шрифт для оговорок |

`b` и `i` не устарели — в HTML5 им дали смысл. Устарели элементы оформления: `center`, `font`, `marquee`, `big`, `frameset`. Их заменяет CSS.

Списки — `ul`, `ol`, `dl`. Меню навигации — тоже список ссылок: программа чтения объявит «список, 5 пунктов», и пользователь сразу знает размер. `dl` с `dt` и `dd` — пары «термин — описание»: характеристики товара, параметры доставки.

## Ссылка или кнопка

- **ссылка** (`a href`) ведёт куда-то: на другую страницу, раздел, файл. Открывается в новой вкладке, копируется, сохраняется в закладках;
- **кнопка** (`button`) делает что-то здесь: добавляет в корзину, открывает окно, отправляет форму.

`a` без `href` — не ссылка. В проверке на странице с `<a href="/cart">`, `<a onclick="openCart()">` и кнопкой в дереве оказалась одна ссылка, а Tab перешёл с первой ссылки сразу на кнопку, пропустив `a` без адреса. Пользователь клавиатуры до такой «ссылки» не доберётся. Нужна кнопка, а если это переход — нужен `href`.

## Таблицы

Таблица — для табличных данных, а не для раскладки. Её структуру программа чтения объявляет при переходе по ячейкам: «Цена, столбец 2, Улун, 990 ₽».

```html
<table>
  <caption>Сравнение сортов</caption>
  <thead><tr><th scope="col">Сорт</th><th scope="col">Цена</th></tr></thead>
  <tbody><tr><th scope="row">Улун</th><td>990 ₽</td></tr></tbody>
</table>
```

В проверке `caption` дал таблице имя «Сравнение сортов», `th` в шапке стали заголовками столбцов, а `th scope="row"` — заголовком строки «Улун». Без `th` и `caption` таблица — сетка безымянных ячеек. Для сложных таблиц с объединёнными заголовками есть атрибут `headers` со ссылками на `id` заголовков.

## dialog и details

### dialog

Самописная модалка из `div` требует полсотни строк: перенести фокус внутрь, удержать его там, закрыть по Esc, вернуть фокус, спрятать фон от программ чтения, нарисовать затемнение поверх всего. `dialog` с `showModal()` делает это сам:

```html
<dialog id="confirm" aria-labelledby="ct">
  <h2 id="ct">Удалить улун из корзины?</h2>
  <form method="dialog">
    <button value="cancel">Отмена</button>
    <button value="confirm">Удалить</button>
  </form>
</dialog>
```

В проверке после `showModal()`:

- фокус перешёл на первую кнопку окна;
- окно оказалось в верхнем слое (`:modal`) поверх любого `z-index`, с затемнением `::backdrop` (подробно о верхнем слое — в [Раскладке и потоке](/content/css/flow));
- фон стал инертным: ссылка за окном пропала из дерева доступности Chromium, не получила фокус по `focus()` и не ловила клики, а Tab не выводил фокус на страницу;
- Esc закрыл окно;
- кнопка в `form method="dialog"` закрыла окно и записала свой `value` в `returnValue` — `"confirm"`.

`show()` открывает немодальное окно: фон остаётся доступным. Для всплывающих меню и подсказок без блокировки фона есть атрибут `popover` (подробно — в [Атрибутах](/content/html/attributes)).

### details

```html
<details name="faq" open><summary>Доставка</summary>Завтра с 10 до 18</details>
<details name="faq"><summary>Оплата</summary>Картой или при получении</details>
```

`details` и `summary` — раскрывающийся блок без JavaScript: клавиатура, состояние «развёрнуто/свёрнуто» для программ чтения и событие `toggle` есть из коробки. Общий атрибут `name` превращает группу в аккордеон, где открыта одна секция: в проверке открытие «Оплаты» закрыло «Доставку», а блок без `name` открывался независимо. Маркер стилизуют через `summary::marker`.

### Пустые и замещаемые элементы

У **пустых** элементов — `br`, `hr`, `img`, `input`, `meta`, `link`, `source`, `track`, `wbr`, `area`, `col`, `embed` — нет содержимого и закрывающего тега (подробно — в [Основах HTML](/content/html/markup-language)). **Замещаемые** — `img`, `video`, `iframe`, `canvas` — рисуют содержимое, которое не описано в HTML: картинку, видео, чужой документ. Поэтому у них есть собственный размер, а как картинка вписывается в бокс, задают `object-fit` и `object-position` (подробно — в [Визуальных эффектах](/content/css/visual-effects)).

## Красные флаги в ответе

- **«`section` — это `div` с красивым именем».** Без заголовка и имени она ничего не сообщает, а с именем становится регионом.
- **«В каждой `section` можно начинать с `h1`».** Алгоритм outline не реализован; уровень — цифра в теге.
- **«`header` всегда ориентир».** Внутри `article` и `section` — нет.
- **«`<a onclick>` — нормальная кнопка».** Без `href` это не ссылка и не кнопка: её нет в порядке Tab.
- **«Модалку проще сделать на `div`».** Фокус, Esc, инертный фон и верхний слой придётся писать самому — и обычно с ошибками.
- **«`b` и `i` устарели».** У них в HTML5 свой смысл; устарели `font`, `center`, `marquee`.

## Как спрашивают на собеседовании

::question
Зачем семантические теги, если всё можно сделать на div?

#answer
Браузер превращает элементы в роли дерева доступности: `nav`, `main`, `header`, `footer`, `aside` становятся ориентирами, `button` — кнопкой с клавиатурой, `h2` — заголовком. Программы чтения с экрана, поисковики и режим чтения работают с этими ролями. `div` роли не даёт.

#more
Пользователь программы чтения прыгает по ориентирам и заголовкам одной клавишей, слышит «список, 5 пунктов», «кнопка, развёрнуто». На `div` всё это придётся добавлять через ARIA и обработчики клавиш, а первое правило ARIA — не использовать её там, где есть подходящий элемент. Семантика не про внешний вид: стили к ней отношения не имеют.
::

::question
Чем section отличается от article и div?

#answer
`article` — самостоятельный кусок, который имеет смысл отдельно: пост, комментарий, карточка товара. `section` — тематический раздел внутри чего-то, обычно со своим заголовком. `div` — обёртка без смысла для стилей и раскладки.

#more
В дереве доступности `article` всегда статья, а `section` становится регионом только с именем — `aria-labelledby` на заголовок или `aria-label`. `article` может содержать `section`, и наоборот. Если не можешь назвать раздел заголовком — нужен `div`.
::

::question
Сколько h1 должно быть на странице? Что с алгоритмом outline?

#answer
Один — совпадающий с темой страницы, дальше `h2`–`h6` по структуре без пропусков уровней. Алгоритм outline, по которому `h1` в каждой `section` считался бы вложенным уровнем, не реализовал ни один браузер, и из спецификации его убрали.

#more
Уровень заголовка — цифра в теге: `h1` внутри `section` для программ чтения остаётся первым уровнем. Пропуск уровня никто не исправит, а пользователь подумает, что пропустил раздел. Размер шрифта меняют CSS, а не цифрой. Несколько `h1` спецификация не запрещает, но один понятнее для навигации.
::

::question
Когда ссылка, а когда кнопка?

#answer
Ссылка ведёт куда-то — на страницу, раздел, файл — и поддерживает открытие в новой вкладке и копирование адреса. Кнопка делает действие здесь: добавляет в корзину, открывает окно, отправляет форму.

#more
`a` без `href` — не ссылка: её нет в порядке Tab и в дереве как ссылки. Кнопка, стилизованная как ссылка, остаётся кнопкой, и это правильно. Переход в одностраничном приложении — ссылка с `href`, которую роутер перехватывает, иначе ломается открытие в новой вкладке.
::

::question
Что dialog даёт по сравнению с самописной модалкой?

#answer
С `showModal()`: окно в верхнем слое поверх любого `z-index`, затемнение `::backdrop`, перенос фокуса внутрь, закрытие по Esc, инертный фон — он не получает фокус и клики и пропадает для программ чтения. `form method="dialog"` закрывает окно и записывает `value` кнопки в `returnValue`.

#more
Остаётся сделать имя окна через `aria-labelledby` и вернуть фокус на кнопку, которая окно открыла, если браузер не сделал этого сам. `show()` открывает немодальное окно, где фон доступен. Для меню и подсказок без блокировки фона — `popover`.
::

::question
Как сделать аккордеон без JavaScript?

#answer
`details` и `summary`: блок раскрывается по клику и с клавиатуры, программа чтения объявляет состояние, есть событие `toggle`. Общий атрибут `name` у нескольких `details` делает так, что открыта только одна секция.

#more
Маркер стилизуют через `summary::marker` или убирают и рисуют свой. Плавное раскрытие делают через `::details-content` и анимацию высоты до `auto`. Если аккордеону нужна сложная логика — несколько открытых по правилам, загрузка содержимого, — пишут компонент, но поведение клавиатуры берут из паттерна ARIA.
::

::question
Как сделать таблицу доступной?

#answer
`caption` — имя таблицы, `th` — заголовки, `scope="col"` и `scope="row"` — их направление, `thead` и `tbody` — группы строк. Тогда программа чтения при переходе по ячейке называет её заголовки.

#more
Таблицы для раскладки не используют — для этого Grid. Для сложных шапок с объединёнными ячейками есть `headers` со ссылками на `id` заголовков. Если таблицу делают из `div` ради виртуализации, роли `table`, `row`, `cell` придётся назначать вручную.
::

## Практика

::practice{title="Найди ошибки семантики"}
Шапка магазина и карточка в каталоге:

```html
<div class="header">
  <div class="logo" onclick="location = '/'">Магазин чая</div>
  <div class="menu"><a onclick="go('/catalog')">Каталог</a><a onclick="go('/delivery')">Доставка</a></div>
</div>
<div class="card">
  <h4>Улун молочный</h4>
  <div class="btn" onclick="addToCart(7)">В корзину</div>
</div>
```

#solution
Нет ни одного ориентира, ссылки и кнопки: логотип и пункты меню — не ссылки и не в порядке Tab, «В корзину» — не кнопка, заголовок карточки начинается с `h4` без `h2` и `h3`. В проверке такая разметка не дала в дереве доступности ни ориентиров, ни ссылок, ни кнопок.

```html
<header>
  <a href="/">Магазин чая</a>
  <nav aria-label="Основная">
    <ul><li><a href="/catalog">Каталог</a></li><li><a href="/delivery">Доставка</a></li></ul>
  </nav>
</header>
<article class="card">
  <h2>Улун молочный</h2>
  <button type="button" onclick="addToCart(7)">В корзину</button>
</article>
```

Переходы — ссылки с `href`, которые роутер перехватывает, действие — `button`. Уровень заголовка выбирают по структуре страницы, а размер задают в CSS.
::

::practice{title="Модалка подтверждения"}
Самописное окно удаления из корзины: фокус остаётся на странице, Esc не работает, программа чтения продолжает читать каталог за окном.

```html
<div class="modal" style="display: block">
  <div class="modal-title">Удалить улун?</div>
  <div class="btn" onclick="confirmDelete()">Удалить</div>
</div>
```

#solution
Нужен `dialog` с `showModal()`:

```html
<dialog id="confirm" aria-labelledby="confirm-title">
  <h2 id="confirm-title">Удалить улун из корзины?</h2>
  <form method="dialog">
    <button value="cancel">Отмена</button>
    <button value="confirm">Удалить</button>
  </form>
</dialog>
```

```js
const dialog = document.getElementById('confirm');
openButton.addEventListener('click', () => dialog.showModal());
dialog.addEventListener('close', () => {
  if (dialog.returnValue === 'confirm') removeFromCart(7);
  openButton.focus();
});
```
