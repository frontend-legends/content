# Веб-компоненты

Веб-компоненты — встроенный в браузер способ делать свои элементы: пользовательские элементы, Shadow DOM, `template` и слоты. Они работают в любом фреймворке и без него. Спрашивают, чем Shadow DOM отличается от Virtual DOM, как стилизовать компонент снаружи, зачем `composed: true` и когда веб-компоненты оправданы. Глубже — почему свойство, записанное до регистрации элемента, ломает его, почему `::slotted` не видит вложенных элементов и как компонент участвует в форме наравне с `input`.

::tldr
- **Три стандарта:** пользовательские элементы (`customElements.define`), Shadow DOM (изолированное дерево с обёрткой стилей) и `template` со слотами. Имя элемента обязано содержать дефис.
- **До регистрации элемент — обычный `HTMLElement`,** а `:not(:defined)` позволяет его спрятать. Свойство, записанное до `define`, становится собственным и затеняет сеттер класса.
- **Порядок колбэков:** конструктор, `attributeChangedCallback` для начальных атрибутов, `connectedCallback`. В конструкторе нельзя трогать атрибуты и детей.
- **Shadow DOM закрывает разметку и стили.** Наружу ведут слоты, `::part`, CSS-переменные и события с `composed: true`, причём снаружи `target` события подменяется на сам элемент.
- **Декларативный Shadow DOM позволяет отдавать компоненты с сервера готовой разметкой,** а `ElementInternals` делает элемент полем формы: значение в `FormData`, своя валидация, `reset`.
::

## Что такое веб-компоненты

Сквозной пример — виджет рейтинга `<tea-rating>` и карточка `<tea-card>` из общей дизайн-системы магазина, которые используют приложения на React, Vue и страницы без фреймворка, а также поле количества `<qty-input>` для формы заказа.

| Технология | Что даёт |
| --- | --- |
| пользовательские элементы | свой тег с классом, жизненным циклом и атрибутами |
| Shadow DOM | скрытое дерево внутри элемента со своими стилями |
| `template` и `slot` | инертная разметка для клонирования и места для содержимого снаружи |

Это стандарт платформы, а не библиотека: элементы работают везде, где есть DOM. Цена — меньше удобств, чем у фреймворков: реактивности нет, рендер и синхронизацию атрибутов пишут сами или берут библиотеку вроде :term[Lit]{def="лёгкая библиотека Google для веб-компонентов с реактивными свойствами"}.

## Пользовательские элементы

```js
class TeaRating extends HTMLElement {
  static observedAttributes = ['value'];

  connectedCallback() { this.render(); }
  attributeChangedCallback(name, oldValue, newValue) { this.render(); }

  get value() { return Number(this.getAttribute('value') ?? 0); }
  set value(v) { this.setAttribute('value', String(v)); }

  render() { this.textContent = '★'.repeat(this.value); }
}

customElements.define('tea-rating', TeaRating);
```

Имя **обязано содержать дефис**: `define('rating', …)` в проверке бросил `SyntaxError`. Так пользовательские элементы не столкнутся с будущими стандартными, у которых дефиса не бывает.

### Жизненный цикл

| Колбэк | Когда |
| --- | --- |
| `constructor` | создание или обновление элемента |
| `attributeChangedCallback` | изменился атрибут из `observedAttributes` — в том числе для начальных значений |
| `connectedCallback` | элемент вставлен в документ |
| `disconnectedCallback` | элемент удалён — снять подписки и таймеры |
| `adoptedCallback` | элемент перенесён в другой документ |

Порядок в проверке: `constructor`, `attributeChangedCallback` для `value="4"` из разметки, `connectedCallback`. Перенос элемента в другое место дал `disconnected` и снова `connected`, а атрибут `title`, которого нет в `observedAttributes`, колбэк не вызвал. Поэтому подписки ставят в `connectedCallback`, снимают в `disconnectedCallback` и готовы к повторному подключению.

**В конструкторе нельзя добавлять атрибуты и детей** — элемент ещё не до конца создан, и у элемента из `createElement` их быть не должно. В проверке конструктор с `setAttribute('role', …)` привёл к ошибке «The result must not have attributes»: `createElement` вернул `HTMLUnknownElement` без атрибута. Атрибуты и разметку добавляют в `connectedCallback`, а в конструкторе — только поля и `attachShadow`.

### Обновление и ленивые свойства

Элемент может появиться в DOM раньше, чем загрузился его класс. До `define` он — обычный `HTMLElement`, а после регистрации браузер **обновляет** его: меняет прототип и вызывает конструктор. Пока элемент не обновлён, `:defined` не срабатывает, и мигание сырой разметки прячут:

```css
tea-rating:not(:defined) { visibility: hidden; }
```

Ловушка — **свойство, записанное до регистрации**. Фреймворк или скрипт сделали `el.rating = 5`, когда класса ещё не было: у объекта появилось собственное свойство `rating`. После обновления оно затеняет геттер и сеттер класса — в проверке значение осталось `5` как собственное свойство, а сеттер класса не был вызван ни разу. Лечат в `connectedCallback`: проверяют `Object.hasOwn(this, 'rating')`, забирают значение, удаляют собственное свойство и записывают через сеттер. Lit и другие библиотеки делают это сами.

## Shadow DOM

```js
class TeaCard extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: 'open' }).innerHTML = `
      <style>h3 { margin: 0 } ::slotted(p) { color: var(--card-text, #333) }</style>
      <h3><slot name="title">Без названия</slot></h3>
      <slot></slot>
      <button part="buy">В корзину</button>`;
  }
}
```

Shadow DOM — отдельное дерево внутри элемента. Внешние селекторы в него не заходят, а внутренние стили не выходят наружу. Что проходит сквозь границу — наследуемые свойства, CSS-переменные, `::part` — и как это сравнивается с CSS Modules и `scoped` во Vue, разобрано в [CSS-архитектуре](/content/css/architecture).

- **`mode: 'open'`** — дерево доступно через `element.shadowRoot`;
- **`mode: 'closed'`** — `shadowRoot` снаружи равен `null`, как в проверке; ссылку на дерево имеет только сам компонент. Это не защита — код на странице всё равно может многое, — а только сокрытие, поэтому почти всегда используют `open`.

Shadow DOM — **не** Virtual DOM: первое — настоящее изолированное дерево в браузере, второе — описание интерфейса в JavaScript-объектах, по которому фреймворк считает изменения.

### Селекторы внутри

| Селектор | Что выбирает |
| --- | --- |
| `:host`, `:host(.compact)` | сам элемент, в том числе с условием |
| `:host-context(.dark)` | элемент, если условие выполняется у предка |
| `::slotted(p)` | элементы, распределённые в слот, — только верхнего уровня |
| `::part(buy)` | снаружи: элемент с `part="buy"` внутри тени |

`::slotted` видит только элементы, которые сами распределены в слот. В проверке `::slotted(p)` покрасил абзац, а `::slotted(b)` не сработал для `b` внутри этого абзаца — тот стал красным только по наследству от `p`. Глубже слота компонент не стилизует: это содержимое страницы. `::part(buy)` снаружи изменил кнопку внутри тени — так компонент открывает отдельные элементы для стилизации.

## template и слоты

### template

`template` — инертная разметка: она разбирается, но не отображается, картинки в ней не загружаются, а скрипты не выполняются. В проверке картинка внутри `template` не была запрошена, а скрипт не выполнился. После вставки клона `content.cloneNode(true)` в документ картинка загрузилась. На этом строят шаблоны компонентов: разобрать один раз, клонировать много.

### Слоты

```html
<tea-card>
  <span slot="title">Улун молочный</span>
  <p>Мягкий вкус со сливочным послевкусием.</p>
</tea-card>
```

- **именованный слот** `<slot name="title">` получает элементы с `slot="title"`;
- **слот по умолчанию** — всё остальное;
- **запасное содержимое** — то, что внутри `slot`, показывается, когда ничего не передали: у пустой карточки в проверке заголовок был «Без названия».

Содержимое слота остаётся в обычном DOM страницы — его можно искать `querySelector` и стилизовать снаружи, — а слот только показывает его в нужном месте. `slot.assignedElements()` возвращает распределённые элементы, а событие `slotchange` сообщает об их изменении: в проверке добавление абзаца в пустую карточку вызвало его один раз.

## События через границу

```js
this.dispatchEvent(new CustomEvent('add-to-cart', { bubbles: true, composed: true, detail: { id: 7 } }));
```

- **`composed: true`** выпускает событие из Shadow DOM наружу. Без него событие всплывает только внутри тени: в проверке `inner-only` без `composed` до документа не дошло, а `add-to-cart` дошло с `detail.id` равным 7;
- **подмена `target`** — снаружи событие выглядит так, будто его вызвал сам элемент. В проверке обработчик клика на документе увидел `target` — хост `buy-button`, хотя кликнули по кнопке внутри тени. Реальный путь — в `event.composedPath()`, у открытой тени он начинается с внутренней кнопки.

Встроенные события пользовательского ввода — `click`, `input`, `focus` — уже `composed`. Свои события компонента делают `bubbles: true, composed: true` и называют в :term[kebab-case]{def="запись слов в нижнем регистре через дефис: tea-card"}.

## Сервер и формы

### Декларативный Shadow DOM

Shadow DOM, созданный в конструкторе, требует JavaScript — до его загрузки компонент пуст, а с сервера его не отрендерить. **Декларативный Shadow DOM** описывает тень прямо в HTML:

```html
<price-tag>
  <template shadowrootmode="open">
    <style>span { font-weight: 700 }</style>
    <span>990 ₽</span>
  </template>
</price-tag>
```

Парсер превращает `template` с `shadowrootmode` в настоящий shadow root: в проверке у элемента со страницы появился `shadowRoot` с ценой без единой строки JavaScript. Так рендерят веб-компоненты на сервере. Но `innerHTML` декларативную тень **не** разбирает — в проверке `shadowRoot` после `innerHTML` был `null`; для вставки из JavaScript есть `setHTMLUnsafe()`, который её разобрал.

### Элементы формы

Обычный пользовательский элемент для формы невидим: его значения нет в `FormData`, валидации нет, `reset` его не касается. `ElementInternals` это исправляет:

```js
class QtyInput extends HTMLElement {
  static formAssociated = true;
  #internals = this.attachInternals();

  set value(v) {
    this.#internals.setFormValue(String(v));
    this.#internals.setValidity(v < 1 ? { rangeUnderflow: true } : {}, 'Минимум 1 упаковка');
  }
  formResetCallback() { this.value = Number(this.getAttribute('value') ?? 0); }
}
```

В проверке `<qty-input name="qty" value="2">` попал в `FormData` как `qty=2`, при значении 0 форма стала невалидной, а сам элемент — `:invalid`; `form.reset()` вернул 2. Ещё `ElementInternals` даёт элементу роль и состояние для дерева доступности без атрибутов `aria-*` на хосте.

## Когда нужны веб-компоненты

| Подходят | Не лучший выбор |
| --- | --- |
| дизайн-система для нескольких фреймворков | компоненты внутри одного приложения на React или Vue |
| виджеты для чужих сайтов: оплата, чат, отзывы | когда нужна реактивность и богатый рендер без библиотеки |
| микрофронтенды, где важна изоляция стилей | когда команда не готова писать синхронизацию атрибутов и свойств |
| долгоживущие компоненты, переживающие смену фреймворков | — |

Фреймворки работают с ними по-разному. React до версии 19 передавал данные только атрибутами-строками и не умел подписываться на пользовательские события; в React 19 свойства и события пользовательских элементов поддерживаются полностью. Vue и Angular поддерживают их давно. Совместимость каждого фреймворка проверяет набор тестов Custom Elements Everywhere. Lit, :term[Stencil]{def="компилятор веб-компонентов с JSX и TypeScript"} и :term[FAST]{def="библиотека веб-компонентов от Microsoft"} убирают шаблонный код: реактивные свойства, рендер, синхронизацию атрибутов. Как веб-компоненты используют в микрофронтендах — в [Микрофронтендах](/content/architecture/micro-frontends).

## Красные флаги в ответе

- **«Shadow DOM — то же, что Virtual DOM».** Первое — изолированное дерево в браузере, второе — объекты для расчёта изменений во фреймворке.
- **«Атрибуты удобно выставить в конструкторе».** Это запрещено: браузер сообщит об ошибке, а элемент из `createElement` станет `HTMLUnknownElement`.
- **«`closed` защищает компонент».** Это только сокрытие `shadowRoot`, а не граница безопасности.
- **«Событие из тени всплывёт само».** Без `composed: true` оно не выйдет за границу Shadow DOM.
- **«`::slotted` стилизует всё содержимое слота».** Только элементы верхнего уровня, распределённые в слот.
- **«Веб-компонент не может быть полем формы».** С `formAssociated` и `ElementInternals` он участвует в `FormData`, валидации и `reset`.

## Как спрашивают на собеседовании

::question
Что такое веб-компоненты и из чего они состоят?

#answer
Встроенный в браузер способ делать свои элементы. Три части: пользовательские элементы — класс, наследующий `HTMLElement`, и `customElements.define` с именем через дефис; Shadow DOM — изолированное дерево со своими стилями; `template` и `slot` — инертная разметка и места для содержимого снаружи.

#more
Они работают в любом фреймворке и без него, поэтому подходят для дизайн-систем на несколько фреймворков и виджетов для чужих сайтов. Реактивности и удобного рендера нет — это берут из Lit или подобных. Для рендера на сервере есть декларативный Shadow DOM.
::

::question
Какой жизненный цикл у пользовательского элемента?

#answer
`constructor` — создание; `attributeChangedCallback` — изменение атрибутов из `observedAttributes`, в том числе начальных; `connectedCallback` — вставка в документ; `disconnectedCallback` — удаление; `adoptedCallback` — перенос в другой документ. Перенос в другое место документа вызывает отключение и повторное подключение.

#more
В конструкторе нельзя добавлять атрибуты и детей — только поля и `attachShadow`. Разметку и подписки делают в `connectedCallback`, отписки — в `disconnectedCallback`. Атрибуты без `observedAttributes` колбэк не вызывают. Свойство, записанное до регистрации элемента, затеняет сеттер класса, и его забирают в `connectedCallback`.
::

::question
Чем Shadow DOM отличается от Virtual DOM?

#answer
Shadow DOM — настоящее изолированное дерево внутри элемента в браузере: внешние стили и селекторы в него не заходят, внутренние не выходят. Virtual DOM — описание интерфейса в JavaScript-объектах, по которому фреймворк вычисляет, что изменить в реальном DOM.

#more
Они решают разные задачи и сочетаются: компонент на Lit рендерит в свой Shadow DOM, React-приложение может использовать такой компонент. Shadow DOM — про изоляцию, Virtual DOM — про эффективные обновления. Многие современные фреймворки вообще обходятся без Virtual DOM.
::

::question
Как стилизовать веб-компонент снаружи?

#answer
Через CSS-переменные, которые наследуются внутрь, `::part()` для элементов, которые компонент пометил атрибутом `part`, наследуемые свойства вроде `color` и `font`, и стили самого элемента-хоста. Обычные селекторы внутрь тени не проходят.

#more
Это контролируемый API стилизации: компонент решает, что можно менять, — переменные для темы, `part` для ключевых элементов. Внутри компонент стилизует себя через `:host`, а переданное содержимое — через `::slotted()`, причём только элементы верхнего уровня слота.
::

::question
Зачем composed: true у события?

#answer
Чтобы событие вышло из Shadow DOM наружу. Без него оно всплывает только внутри тени, и обработчик на странице его не получит. Свои события компонента делают `bubbles: true, composed: true`.

#more
Снаружи `target` такого события подменяется на сам элемент-хост — страница не видит внутреннего устройства. Реальный путь — `event.composedPath()`; у закрытой тени внутренние узлы в нём скрыты. Встроенные события ввода — `click`, `input`, `focus` — уже `composed`.
::

::question
Можно ли отрендерить веб-компонент на сервере?

#answer
Да, через декларативный Shadow DOM: `<template shadowrootmode="open">` внутри элемента парсер превращает в настоящий shadow root без JavaScript. Сервер отдаёт готовую разметку и стили, а класс компонента позже подключает интерактивность.

#more
`innerHTML` декларативную тень не разбирает — для этого есть `setHTMLUnsafe()`. Lit умеет рендерить компоненты на сервере в такую разметку. Без декларативной тени компонент пуст до загрузки JavaScript, и его прячут через `:not(:defined)`, чтобы не мигала сырая разметка.
::

::question
Как сделать веб-компонент полем формы?

#answer
`static formAssociated = true` и `this.attachInternals()`. Через `ElementInternals` элемент задаёт значение для `FormData` — `setFormValue`, — состояние валидности — `setValidity` — и получает колбэки `formResetCallback`, `formDisabledCallback`.

#more
Такой элемент работает с `label for`, `form.reset()`, `checkValidity()` и `:invalid` как нативное поле. `ElementInternals` ещё задаёт роль и состояния для дерева доступности без `aria-*` на хосте. Без этого значение пользовательского поля приходилось дублировать в скрытый `input`.
::

## Практика

::practice{title="Рейтинг не обновляется"}
React-приложение на старой версии React рендерит `<tea-rating>` до загрузки модуля компонента. Рейтинг показывает пусто и не реагирует на изменения:

```js
// приложение
el.rating = 4;          // выполнилось до customElements.define

// компонент
class TeaRating extends HTMLElement {
  #rating = 0;
  get rating() { return this.#rating; }
  set rating(v) { this.#rating = v; this.render(); }
}
customElements.define('tea-rating', TeaRating);
```

#solution
Присваивание до регистрации создало у объекта собственное свойство `rating`. После обновления оно затеняет геттер и сеттер класса: `render` не вызывается, а приватное поле остаётся 0. В проверке в Chromium после `define` у элемента было собственное свойство со значением 5, а сеттер класса так и не вызвался. Значение забирают при подключении:

```js
connectedCallback() {
  if (Object.hasOwn(this, 'rating')) {
    const value = this.rating;
    delete this.rating;         // убрать собственное свойство
    this.rating = value;        // записать через сеттер класса
  }
  this.render();
}
```

Lit делает это сам. Ещё вариант — грузить модуль компонента раньше, чем приложение начнёт с ним работать, и ждать `customElements.whenDefined('tea-rating')`.
::

::practice{title="Обработчик не видит событие"}
Страница не получает событие «добавить в корзину» из карточки:

```js
// внутри компонента, в Shadow DOM
this.shadowRoot.querySelector('button').addEventListener('click', () => {
  this.shadowRoot.querySelector('button').dispatchEvent(new CustomEvent('add-to-cart', { detail: { id: 7 } }));
});

// на странице
document.addEventListener('add-to-cart', (e) => addToCart(e.detail.id));
```

#solution
Событие без `bubbles` не всплывает вовсе, а без `composed` не выходит за границу Shadow DOM. Его вызывают на самом элементе с обоими флагами:

```js
this.shadowRoot.querySelector('button').addEventListener('click', () => {
  this.dispatchEvent(new CustomEvent('add-to-cart', { bubbles: true, composed: true, detail: { id: 7 } }));
});
```

В проверке событие без `composed` до документа не дошло, а с ним дошло с `detail.id` равным 7. Снаружи `event.target` — сама карточка, а не внутренняя кнопка.
::

::practice{title="Количество не уходит с заказом"}
Компонент количества выглядит и работает как поле, но сервер не получает `qty`, а `form.reset()` его не сбрасывает:

```html
<form id="order"><qty-input name="qty" value="2"></qty-input><button>Оформить</button></form>
```

#solution
Обычный пользовательский элемент форма не видит. Нужна связь с формой через `ElementInternals`:

```js
class QtyInput extends HTMLElement {
  static formAssociated = true;
  #internals = this.attachInternals();
  #value = 0;

  connectedCallback() { this.value = Number(this.getAttribute('value') ?? 0); }
  get value() { return this.#value; }
  set value(v) {
    this.#value = v;
    this.#internals.setFormValue(String(v));
    this.#internals.setValidity(v < 1 ? { rangeUnderflow: true } : {}, 'Минимум 1 упаковка');
  }
  formResetCallback() { this.value = Number(this.getAttribute('value') ?? 0); }
}
```

В проверке в Chromium такой элемент попал в `FormData` как `qty=2`, со значением 0 сделал форму невалидной, а `reset()` вернул 2.
::
