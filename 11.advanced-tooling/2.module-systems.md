# Модульные системы

Прежде чем понять бандлеры, надо понять **модули** - то, что они собирают. Модульная система определяет, как код делится на файлы и как они ссылаются друг на друга. От выбора системы зависит, можно ли статически анализировать код и делать tree-shaking.

> Семантика `import`/`export` в самом языке разобрана в [JS-модулях](/content/javascript). Здесь - **тулинговый угол**: чем системы различаются и почему это важно для сборки.

---

## Зачем модули

До модулей весь JS жил в глобальной области: скрипты переопределяли друг другу переменные, порядок подключения был критичен. Модули дают **инкапсуляцию** (своя область видимости), **явные зависимости** (видно, что откуда) и **переиспользование**.

Эволюция: глобальные `<script>` → IIFE → **CommonJS** (Node) → AMD → UMD → **ES Modules** (стандарт языка).

---

## CommonJS (CJS)

Модульная система Node.js (исторически). Синхронная, **динамическая**.

```js
// экспорт
const add = (a, b) => a + b;
module.exports = { add };

// импорт
const { add } = require('./math');
```

- `require` - обычная функция, выполняется **в рантайме**, можно вызывать условно (`if (x) require(...)`).
- Резолвинг и значение экспорта определяются **во время выполнения** - статически непредсказуемы.

---

## ES Modules (ESM)

Стандарт языка, работает нативно в браузере и Node.

```js
// экспорт
export const add = (a, b) => a + b;
export default Calculator;

// импорт
import Calculator, { add } from './math.js';
import('./lazy.js').then(...); // динамический импорт
```

- `import`/`export` - **статические**: связи известны до выполнения, на этапе парсинга.
- Асинхронная загрузка, поддержка **top-level await**.

---

## Главное различие: статика vs динамика

Это ключ к теме. ESM **статичен** - какие импорты что используют, известно **без запуска кода**. CJS **динамичен** - `require` может зависеть от условий рантайма.

```js
// ESM: анализатор видит, что используется только add → square можно выкинуть
import { add } from './math.js';

// CJS: что реально нужно из mod - неизвестно до выполнения
const mod = require('./math');
```

<b class="text-on-semi-light">Почему это критично</b> - <span class="text-gray">Статичность ESM позволяет бандлеру **tree-shaking** (выкинуть неиспользуемый экспорт), анализ зависимостей и оптимизации. С CJS это невозможно надёжно - неизвестно, что используется. Поэтому современные библиотеки публикуют ESM, а tree-shaking «не работает» именно на CJS-пакетах.</span>

## Named vs default

```js
export const a = 1;          // именованный
export default function () {} // дефолтный

import def, { a } from './m'; // def - дефолт, a - именованный
```

> Именованные экспорты лучше для tree-shaking и автоимпорта IDE. Дефолтные удобны для «одна сущность на модуль» (компонент). Спор стилистический, но именованные чаще предпочитают в библиотеках.

---

## Динамический import()

`import()` возвращает промис и грузит модуль **по требованию** - основа **code splitting**.

```js
button.onclick = async () => {
  const { heavy } = await import('./heavy.js'); // загрузится только при клике
};
```

Бандлер видит `import()` и выделяет модуль в **отдельный чанк**, который подгрузится в рантайме. На этом стоят `React.lazy` и ленивые маршруты (см. [оптимизацию](/content/advanced-tooling/optimization)).

---

## UMD

**Universal Module Definition** - обёртка, которая работает **везде**: как глобальная переменная (browser `<script>`), как AMD и как CommonJS. Использовалась библиотеками, чтобы один файл подходил любому окружению. Сейчас вытесняется ESM, но встречается в legacy-сборках и CDN-бандлах.

---

## Разрешение модулей

Как `import x from 'lib'` находит файл:

1. **Относительный путь** (`./utils`) - ищется прямо.
2. **Bare-спецификатор** (`lib`) - ищется в `node_modules`, поднимаясь вверх по дереву.
3. Внутри пакета точку входа определяет **`package.json`**: поле `exports` (современное, с условиями) или `main`/`module`/`browser`.

```jsonc
// package.json пакета: разные входы для ESM и CJS
"exports": {
  ".": {
    "types": "./dist/index.d.ts",
    "import": "./dist/index.mjs",   // для ESM
    "require": "./dist/index.cjs"   // для CJS
  }
}
```

## Боль interop (ESM ↔ CJS)

Частый источник проблем на практике и вопрос на собесе.

- **ESM-only пакеты** не импортируются через `require` в старых CJS-проектах (`ERR_REQUIRE_ESM`).
- В ESM **нет** `__dirname`/`require` (используют `import.meta.url`).
- **Dual packages** (и ESM, и CJS) рискуют «двойной загрузкой» - два экземпляра одного модуля.
- Дефолтный импорт CJS-пакета из ESM иногда «оборачивается» неожиданно.

<b class="text-on-semi-light">Куда движется индустрия</b> - <span class="text-gray">К **ESM-only**. Node давно поддерживает ESM нативно, инструменты - тоже. Но переходный период порождает interop-конфликты, которые надо уметь диагностировать.</span>

---

## Tree-shakeability - сводка

Чтобы пакет хорошо «тряс дерево»:

1. публиковаться в **ESM**;
2. помечать `"sideEffects": false` в `package.json` (нет побочных эффектов на уровне модуля);
3. избегать кода, выполняющегося при импорте.

## Вопросы на собеседовании

<b class="text-on-semi-light">Чем ESM отличается от CommonJS?</b>
<span class="text-gray">ESM статичен (import/export известны до выполнения), асинхронен, стандарт языка. CommonJS динамичен (`require` в рантайме), синхронен, исторический формат Node. Статичность ESM включает tree-shaking и анализ.</span>

<b class="text-on-semi-light">Почему tree-shaking работает с ESM, но не с CJS?</b>
<span class="text-gray">ESM статичен - бандлер видит, какие экспорты используются, и выкидывает остальные. В CJS `require` динамический, реально используемое неизвестно до выполнения.</span>

<b class="text-on-semi-light">Что такое динамический import() и зачем он нужен?</b>
<span class="text-gray">Асинхронная загрузка модуля по требованию (возвращает промис). Бандлер выделяет его в отдельный чанк - основа code splitting и ленивой загрузки.</span>

<b class="text-on-semi-light">Как import 'lib' находит пакет?</b>
<span class="text-gray">Bare-спецификатор ищется в node_modules вверх по дереву; точку входа задаёт `exports`/`main`/`module` в package.json пакета, с условиями для ESM/CJS и типов.</span>

<b class="text-on-semi-light">Что такое проблема ESM/CJS interop?</b>
<span class="text-gray">ESM-only пакеты ломаются в CJS (`ERR_REQUIRE_ESM`), в ESM нет `__dirname`/`require`, dual packages рискуют двойной загрузкой. Переходный период между форматами.</span>
