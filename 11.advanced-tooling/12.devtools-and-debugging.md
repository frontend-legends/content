# DevTools и отладка

Браузерные DevTools - главный инструмент фронтендера для отладки, профилирования и анализа. Умение находить проблему через DevTools (а не `console.log` наугад) - то, что отличает уверенного инженера. Плюс есть DevTools под React/Vue.

---

## Панели Chrome DevTools

| Панель | Для чего |
|--------|----------|
| **Elements** | DOM-дерево, применённые стили, box-model, изменение на лету |
| **Console** | логи, ошибки, выполнение JS в контексте страницы |
| **Sources** | исходники, брейкпоинты, пошаговая отладка |
| **Network** | запросы, тайминги, водопад, заголовки, троттлинг |
| **Performance** | профиль выполнения, flame chart, нагрузка на главный поток |
| **Memory** | снимки кучи, поиск утечек |
| **Application** | хранилища (localStorage, cookies), Service Workers, кеш |
| **Lighthouse** | аудит: производительность, доступность, SEO, PWA |

---

## Network

Показывает все запросы: статус, размер, время, **водопад** (когда что началось/закончилось).

- **Throttling** - эмуляция медленной сети (Slow 3G), чтобы увидеть загрузку как у реальных пользователей.
- **Водопад** выявляет узкие места: последовательные запросы (см. waterfall в [загрузке данных](/content/reactjs/data-fetching)), долгий TTFB, блокирующие ресурсы.
- Заголовки, payload, ответ - для отладки API и кеширования.

---

## Performance

Профилировщик исполнения: записываешь сценарий и видишь **flame chart** - что грузило главный поток, где долгие задачи (long tasks), просадки FPS, layout/paint.

> Здесь ищут причины «тормозит интерфейс»: тяжёлые ререндеры, долгие вычисления в главном потоке, частые reflow. Связано с [производительностью React](/content/reactjs/performance) и Core Web Vitals.

---

## Memory

Снимки кучи (heap snapshots) и сравнение их во времени - чтобы найти **утечки**: объекты, которые должны были удалиться, но удерживаются (забытые слушатели, таймеры, замыкания, ссылки на отсоединённые DOM-узлы).

---

## Application

Инспекция клиентских хранилищ: `localStorage`, `sessionStorage`, cookies (включая флаги httpOnly/Secure), IndexedDB, **Service Workers** и Cache Storage (для PWA). Здесь же чистят состояние при отладке.

---

## Отладка с брейкпоинтами

Вместо `console.log` - брейкпоинты в панели **Sources**. Виды:

| Брейкпоинт | Когда срабатывает |
|------------|-------------------|
| Line | на строке кода |
| **Conditional** | на строке, если условие истинно |
| **Logpoint** | логирует без остановки (console.log без правки кода) |
| DOM | при изменении узла/атрибута |
| Event listener | на событии (click, ...) |
| XHR/fetch | на запросе по URL |

Остановившись, идёшь по коду (step over/into/out), смотришь **scope** (значения переменных), **call stack** (как сюда попали), **watch** (следить за выражением).

```js
function buggy() {
  debugger; // остановит выполнение здесь при открытых DevTools
}
```

<b class="text-on-semi-light">Почему брейкпоинты лучше логов</b> - <span class="text-gray">`console.log` показывает одно значение в одной точке; брейкпоинт даёт **всё состояние** в момент паузы - все переменные, стек вызовов, возможность шагать дальше. Быстрее и точнее, особенно в незнакомом коде.</span>

---

## Source maps в отладке

Браузер исполняет собранный/минифицированный код, но благодаря [source maps](/content/advanced-tooling/optimization) DevTools показывает **оригинальный TypeScript** - брейкпоинты ставятся в исходнике, стектрейсы читаемы. Без них отладка прода - чтение `a.4f3b.js`. Поэтому source maps генерируют даже для прода (и грузят в трекеры ошибок).

---

## DevTools фреймворков

Браузерные DevTools работают с DOM, но не знают про компоненты. Для этого - расширения:

- **React DevTools** - дерево компонентов, их props/state/hooks, и **Profiler**: что рендерилось, как долго и **почему перерисовалось** (включи «Record why each component rendered»). Незаменимо для отладки лишних ререндеров ([согласование](/content/reactjs/reconciliation-and-fiber)).
- **Vue DevTools** - дерево компонентов, реактивное состояние, сторы Pinia, таймлайн событий.

---

## Console - больше, чем log

```js
console.table(users);     // массив объектов таблицей
console.group('API'); ... console.groupEnd();
console.time('fetch'); ... console.timeEnd('fetch'); // замер времени
console.assert(x > 0, 'x должен быть > 0');
console.dir(domNode);     // объектное представление
```

## Lighthouse

Автоматический аудит страницы: **производительность** (Core Web Vitals - LCP, CLS, INP), **доступность**, SEO, лучшие практики, PWA. Даёт оценку и конкретные рекомендации. Запускается из DevTools или в CI (как гейт качества).

## Вопросы на собеседовании

<b class="text-on-semi-light">Как искать причину «тормозит интерфейс»?</b>
<span class="text-gray">Панель Performance: записать сценарий, посмотреть flame chart - долгие задачи в главном потоке, тяжёлые ререндеры, layout/paint. Для React - Profiler в React DevTools.</span>

<b class="text-on-semi-light">Чем брейкпоинт лучше console.log?</b>
<span class="text-gray">Даёт всё состояние в точке паузы (переменные, scope, call stack) и возможность шагать по коду, а не одно значение. Есть условные брейкпоинты и логпоинты без правки кода.</span>

<b class="text-on-semi-light">Как отлаживать минифицированный прод-код?</b>
<span class="text-gray">Через source maps: DevTools сопоставляет собранный код с исходным TS - брейкпоинты и стектрейсы в оригинале. Поэтому source maps генерируют и для прода (грузят в трекеры ошибок).</span>

<b class="text-on-semi-light">Как найти утечку памяти?</b>
<span class="text-gray">Панель Memory: снимки кучи и их сравнение во времени - удерживаемые объекты (забытые слушатели, таймеры, отсоединённые DOM-узлы), которые должны были освободиться.</span>

<b class="text-on-semi-light">Что показывает React DevTools Profiler?</b>
<span class="text-gray">Какие компоненты рендерились, как долго и почему (изменение props/state/контекста) - инструмент для поиска и устранения лишних ререндеров.</span>

<b class="text-on-semi-light">Что измеряет Lighthouse?</b>
<span class="text-gray">Аудит производительности (Core Web Vitals: LCP, CLS, INP), доступности, SEO, PWA с оценкой и рекомендациями. Можно гонять в CI как гейт.</span>
