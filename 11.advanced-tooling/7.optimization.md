# Оптимизация сборки

Что сборщик делает с кодом, чтобы пользователь скачал меньше: минификация, tree shaking глазами бандлера, побочные эффекты и `/*#__PURE__*/`, поле `sideEffects` и его ловушки, разбиение на чанки, сжатие и анализ бандла. Спрашивают, что такое tree shaking и почему он иногда не срабатывает, что даёт разбиение на чанки и чем минификация отличается от сжатия. Глубже — почему неиспользуемый вызов остался в бандле, почему после `sideEffects: false` пропали стили и как найти, что раздувает бандл.

::tldr
- **Минификатор укорачивает имена, сворачивает константы и удаляет мёртвые ветки,** а сжатие gzip или brotli уменьшает уже минифицированный текст при передаче. Это разные шаги, и они складываются.
- **Бандлер выбрасывает только то, что точно ничего не делает.** Вызов функции на верхнем уровне модуля остаётся, даже если результат не используется, — пока его не пометили `/*#__PURE__*/`.
- **`"sideEffects": false` разрешает выбросить неиспользуемый модуль целиком.** Но если CSS импортирует модуль-«бочка», стили пропадут вместе с ней: их импортируют из модуля, который их использует, или перечисляют в `sideEffects`.
- **Разбиение на чанки** грузит только нужное для текущей страницы и отделяет редко меняющиеся зависимости от часто меняющегося кода, чтобы кеш жил дольше.
- **Оптимизация начинается с измерения:** анализатор бандла показывает, что весит, а самые частые находки — дубли версий, целые библиотеки ради одной функции и CommonJS-зависимости.
::

## Минификация

Сквозной пример — функция расчёта корзины:

```js
export function calculateTotal(items) {
  const TAX_RATE = 0.2;
  let subtotal = 0;
  for (const item of items) subtotal += item.price * item.quantity;
  if (process.env.NODE_ENV !== 'production') console.warn('debug total', subtotal);
  return subtotal * (1 + TAX_RATE);
}
```

Минификатор (в Vite 8 — Oxc, раньше esbuild и Terser) делает несколько вещей. В проверке результат оказался меньше половины исходника:

- **удаляет пробелы, переносы и комментарии;**
- **укорачивает локальные имена:** `subtotal` и `TAX_RATE` исчезли, а экспорт `calculateTotal` сохранил имя — его видят другие модули;
- **сворачивает константы:** `1 + TAX_RATE` стало `1.2`;
- **удаляет мёртвые ветки:** после подстановки `"production"` условие `'production' !== 'production'` ложно, и `console.warn` исчез вместе со строкой.

Последнее — основа того, как фреймворки выбрасывают предупреждения из продакшен-сборки (подробно — во [Введении в тулинг](/content/advanced-tooling/introduction)).

CSS минифицирует отдельный инструмент — в Vite 8 это Lightning CSS: удаляет пробелы, объединяет правила, сокращает цвета и значения.

## Tree shaking глазами бандлера

Почему tree shaking возможен только со статическими ES-модулями, и почему CommonJS ему мешает, — разобрано в [Модулях](/content/javascript/modules). Здесь — как бандлер решает, что можно выбросить.

Правило одно: **удалить можно только то, что точно ничего не делает.** Неиспользуемая функция — да. Неиспользуемая константа с литералом — да. А вызов функции на верхнем уровне модуля — нет:

```js
// lib.js
export const a = 1;
export const registry = createRegistry();            // вызов может что-то делать
export const cache = /*#__PURE__*/ createCache();    // помечен чистым
```

Приложение импортирует только `a`. Бандлер не знает, что делает `createRegistry`: может, регистрирует что-то глобально. Поэтому вызов **остаётся** в бандле, хотя `registry` никто не использует. Комментарий `/*#__PURE__*/` перед вызовом — обещание «у этого вызова нет побочных эффектов», и такой вызов выбрасывается. В проверке на Rolldown `createRegistry` остался, `createCache` — исчез.

Аннотации `/*#__PURE__*/` расставляют компиляторы фреймворков: компилятор Vue помечает `defineComponent`, Babel и TypeScript — помощники классов. В своём коде её ставят там, где вызов на верхнем уровне действительно чистый — фабрики объектов, `Object.freeze`, `new Map()`.

### Что ещё мешает

- **код верхнего уровня:** присваивание в `window`, регистрация плагина, полифил;
- **чтение свойств, у которых могут быть геттеры:** `obj.prop` на верхнем уровне бандлер обычно считает возможным побочным эффектом;
- **CommonJS-зависимости:** `module.exports` — объект, и что из него используется, неизвестно (подробно — в [Бандлерах](/content/advanced-tooling/bundlers));
- **экспорт объекта по умолчанию:** `export default { formatPrice, formatDate }` — свойства объекта не вычищаются по отдельности;
- **динамические обращения:** `utils[name]()` требует сохранить всё.

## Поле sideEffects

Модуль, из которого ничего не импортировано, бандлер всё равно включит, если в нём есть код верхнего уровня. Поле `sideEffects` в `package.json` библиотеки разрешает больше:

```json
{ "name": "ui-kit", "sideEffects": false }
```

Это обещание «ни один модуль пакета ничего не делает при загрузке». Тогда модуль, из которого ничего не используется, выбрасывается **целиком**, вместе с его кодом верхнего уровня и его импортами. Подробности для своего пакета — в [Модулях](/content/javascript/modules).

### Ловушка со стилями

Импорт CSS — тоже побочный эффект: он ничего не экспортирует, но подключает стили. Пример — библиотека, где стили подключает модуль-«бочка»:

```js
// node_modules/ui-kit/index.js
import './button.css';
export { button } from './button.js';
export { chart } from './chart.js';
```

Приложение импортирует `button`. С `"sideEffects": false` бандлер идёт к `button.js` напрямую, в обход `index.js`, — и вместе с `index.js` выбрасывает импорт стилей. Кнопка без стилей. В проверке на Vite 8:

| `sideEffects` | Стили | Неиспользуемый `chart.js` с кодом верхнего уровня |
| --- | --- | --- |
| не указано | есть | в бандле |
| `false` | пропали | выброшен |
| `["*.css"]` | пропали | выброшен |
| `["*.css"]` и стили импортирует `button.js` | есть | выброшен |
| `["*.css", "./index.js"]` | есть | выброшен |

Неочевидная строка — третья: исключение для CSS не помогает, потому что сам `index.js` по-прежнему считается чистым и обходится. Правильно — импортировать стили из модуля, который их использует, или явно пометить «бочку». В webpack то же поведение описано в документации: файлы, которые подключаются ради эффекта, нужно перечислить в `sideEffects`.

## Разбиение на чанки

**По маршрутам.** Каждая ленивая страница — свой чанк: `component: () => import('./ReportsPage.vue')`. Пользователь главной не скачивает код отчётов (подробно — в [Маршрутизации Vue](/content/vuejs/routing) и [Бандлерах](/content/advanced-tooling/bundlers)).

**По тяжёлым виджетам.** Редактор, график, карта — через `defineAsyncComponent`, `React.lazy` или динамический `import()` по событию.

**Зависимости отдельно.** Код приложения меняется каждый деплой, а зависимости — редко. Если они в одном чанке, любое изменение сбрасывает кеш всего. Отдельный чанк для `node_modules` переживает деплои:

```js
// rolldown.config.js или build.rolldownOptions в Vite 8
export default {
  output: {
    codeSplitting: {
      groups: [{ name: 'vendor', test: /node_modules/ }],
    },
  },
};
```

В проверке библиотека оказалась в чанке `vendor`, а точка входа — без неё. В Vite 8 эта опция живёт в `build.rolldownOptions.output.codeSplitting`, а прежняя `advancedChunks` объявлена устаревшей — Rolldown предупредил об этом в проверке. Ручное разбиение легко перестараться: один гигантский `vendor` скачивается целиком на любой странице, а десятки мелких чанков — это лишние запросы. Обычно хватает автоматического разбиения плюс одной-двух групп для крупных стабильных зависимостей.

## Сжатие

Минификация меняет **код**, сжатие — **передачу**. Сервер или CDN сжимает файлы алгоритмом без потерь, браузер распаковывает:

| | Минификация | Сжатие |
| --- | --- | --- |
| Что | код: имена, пробелы, мёртвые ветки | байты: повторяющиеся последовательности |
| Когда | при сборке | при отдаче или заранее при сборке |
| Результат | валидный JavaScript | архив, который распаковывает браузер |
| Кто | Oxc, esbuild, Terser | gzip, brotli, zstd |

Они складываются. В проверке минифицированная продакшен-сборка рантайма Vue весила 113 КБ, после gzip — 42 КБ, после brotli — 38 КБ. Brotli сжимает плотнее gzip и поддерживается всеми браузерами, поэтому для статики его включают на CDN или собирают `.br`-файлы заранее на максимальном уровне. Заголовки и кеш — в [CDN и кешировании](/content/testing-deploying/cdn-and-caching).

## Анализ бандла

Прежде чем оптимизировать, смотрят, что весит. Анализаторы — `rollup-plugin-visualizer`, `vite-bundle-analyzer`, `webpack-bundle-analyzer` — рисуют карту бандла, где площадь модуля пропорциональна его размеру.

Частые находки:

- **две версии одной библиотеки** — от разных зависимостей. Проверяют `npm ls имя` и выравнивают через `overrides`;
- **целая библиотека ради одной функции** — `lodash` вместо `lodash-es`, `moment` с локалями вместо `Intl` или `date-fns`;
- **CommonJS-зависимость**, которую не вычистить;
- **полифилы для браузеров, которых нет в аудитории** (подробно — в [Транспиляции](/content/advanced-tooling/transpilation));
- **данные и картинки, встроенные в JavaScript** — большие JSON и SVG лучше отдавать отдельными файлами.

Бюджет размера в CI — проверка, что точка входа не выросла выше порога, — ловит регресс до выкладки (подробно — в [CI/CD](/content/advanced-tooling/ci-cd)). Влияние на метрики загрузки и картинки — в [Производительности загрузки](/content/security-perfomance/loading-performance) и [Оптимизации ассетов](/content/security-perfomance/asset-optimization). Source maps — в [Отладке](/content/advanced-tooling/devtools-and-debugging).

## Красные флаги в ответе

- **«Минификация и gzip — одно и то же».** Минификация меняет код при сборке, сжатие — байты при передаче, и они складываются.
- **«Tree shaking выбросит всё, что не импортировано».** Вызов на верхнем уровне остаётся, пока его не пометили `/*#__PURE__*/`.
- **«`sideEffects: false` безопасен для любой библиотеки».** Импорты ради эффекта, например CSS, пропадут, если модуль, который их делает, обходится.
- **«Чем больше чанков, тем лучше».** Мелкие чанки — лишние запросы, гигантский `vendor` — лишний код на каждой странице.
- **«Бандл большой — надо переписать на другой бандлер».** Обычно причина в зависимостях, и её показывает анализатор.

## Как спрашивают на собеседовании

::question
Что такое tree shaking и когда он не срабатывает?

#answer
Удаление неиспользуемого кода при сборке: бандлер по статическим импортам ESM знает, что используется, и выбрасывает остальное. Не срабатывает для CommonJS, экспортов-объектов, динамических обращений и кода с побочными эффектами на верхнем уровне.

#more
Вызов функции на верхнем уровне остаётся, даже если результат не нужен: бандлер не знает, что вызов ничего не делает. `/*#__PURE__*/` перед вызовом и `"sideEffects": false` в `package.json` дают бандлеру разрешение выбросить больше. Подробности языка — в [Модулях](/content/javascript/modules).
::

::question
Зачем аннотация PURE?

#answer
`/*#__PURE__*/` перед вызовом говорит бандлеру и минификатору, что у вызова нет побочных эффектов. Если результат не используется, вызов можно удалить. Без неё вызов на верхнем уровне остаётся в бандле.

#more
Аннотации расставляют компиляторы фреймворков и TypeScript — для `defineComponent`, помощников классов. В своём коде её ставят на чистые фабрики. Если пометить вызов с реальным эффектом, бандлер его удалит, и поведение сломается.
::

::question
Почему после sideEffects: false пропали стили?

#answer
Импорт CSS — побочный эффект без экспортов. С `"sideEffects": false` бандлер выбрасывает неиспользуемые модули вместе с их импортами. Если стили подключает модуль-«бочка», а приложение импортирует компонент мимо неё, импорт стилей пропадёт.

#more
Исключение `["*.css"]` не помогает, если стили импортирует сама «бочка»: она по-прежнему считается чистой. Правильно — импортировать стили из модуля компонента или перечислить «бочку» в `sideEffects`. Это поведение есть и в Vite, и в webpack.
::

::question
Что даёт разбиение на чанки?

#answer
Пользователь скачивает только код текущей страницы, а остальное — по требованию. Отдельный чанк для редко меняющихся зависимостей переживает деплои в кеше браузера.

#more
Разбивают по маршрутам, по тяжёлым виджетам и группам зависимостей. Перебор вредит: мелкие чанки — лишние запросы, огромный `vendor` — лишний код везде. Vite добавляет `modulepreload`, чтобы зависимости ленивого чанка не грузились водопадом.
::

::question
Чем минификация отличается от сжатия?

#answer
Минификация при сборке переписывает код: убирает пробелы, укорачивает имена, сворачивает константы, удаляет мёртвые ветки — результат остаётся JavaScript. Сжатие gzip или brotli уменьшает байты при передаче, а браузер распаковывает их.

#more
Они складываются: рантайм Vue весит около 113 КБ минифицированным, 42 КБ в gzip и 38 КБ в brotli. Brotli плотнее gzip и поддерживается всеми браузерами. Статику выгодно сжимать заранее на максимальном уровне.
::

::question
Как найти, что раздувает бандл?

#answer
Запустить анализатор — `rollup-plugin-visualizer`, `vite-bundle-analyzer`, `webpack-bundle-analyzer` — и посмотреть карту модулей по размеру.

#more
Обычные находки — две версии одной библиотеки, целая библиотека ради одной функции, CommonJS-зависимости, лишние полифилы, встроенные данные и картинки. Регресс ловит бюджет размера в CI. Дубли проверяют `npm ls` и выравнивают через `overrides`.
::

## Практика

::practice{title="Кнопки библиотеки без стилей"}
После обновления внутренней UI-библиотеки кнопки в приложении остались без стилей. В новой версии в `package.json` добавили `"sideEffects": false`:

```js
// ui-kit/index.js
import './button.css';
export { button } from './button.js';
export { chart } from './chart.js';
```

#solution
Приложение импортирует `button`, и бандлер, получив разрешение `sideEffects: false`, пошёл к `button.js` в обход `index.js`. Импорт стилей жил в `index.js` и пропал вместе с ним. Исправление в библиотеке — стили импортирует компонент, которому они нужны, и CSS помечен как побочный эффект:

```js
// ui-kit/button.js
import './button.css';
export const button = () => document.createElement('button');
```

```json
{ "sideEffects": ["*.css"] }
```

Только `["*.css"]` без переноса импорта не помогло бы: «бочка» `index.js` по-прежнему считалась бы чистой. Второй рабочий вариант — `["*.css", "./index.js"]`. В проверке на Vite 8 стили вернулись в обоих вариантах, а неиспользуемый `chart.js` остался выброшенным.
::

::practice{title="Неиспользуемый код остался"}
Приложение импортирует из модуля только константу, но в бандле остаётся тяжёлая инициализация:

```js
// analytics.js
export const VERSION = '2.1';
export const tracker = createTracker({ endpoint: '/collect' });   // создаёт объект и таймеры
```

#solution
Бандлер не знает, что делает `createTracker`, и не может удалить вызов: вдруг он регистрирует что-то глобально. Два варианта. Если вызов действительно чистый, его помечают:

```js
export const tracker = /*#__PURE__*/ createTracker({ endpoint: '/collect' });
```

Но здесь он создаёт таймеры — это побочный эффект, и пометка была бы ложью. Правильнее не делать работу при импорте:

```js
let tracker;
export const getTracker = () => (tracker ??= createTracker({ endpoint: '/collect' }));
```

Ленивое создание убирает и побочный эффект, и лишнюю работу при загрузке страницы. В проверке на Rolldown непомеченный вызов остался в бандле, а помеченный `/*#__PURE__*/` — исчез.
::
