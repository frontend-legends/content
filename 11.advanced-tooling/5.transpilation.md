# Транспиляция

Как новый синтаксис и TypeScript превращаются в JavaScript, который понимают целевые браузеры: понижение синтаксиса и полифилы, цели и browserslist, что понизить нельзя, инструменты от Babel до Oxc, AST и кодмоды. Спрашивают, чем транспиляция отличается от полифила, что такое browserslist и чем Babel отличается от SWC и esbuild. Глубже — почему `items.at(-1)` упал в старом браузере после сборки, почему регулярное выражение с флагом `v` прошло сборку и упало у пользователя и почему трансформатор пропускает ошибки типов.

::tldr
- **Транспиляция переписывает синтаксис:** `?.`, `??`, классы, `async` превращаются в код, понятный целевой версии языка. Новые API — `Array.prototype.at`, `Object.groupBy`, `structuredClone` — синтаксисом не являются и не переписываются, для них нужны полифилы.
- **Что понижать, решает цель:** список браузеров через browserslist или версия ECMAScript. Для современной цели код почти не меняется, и это лучший вариант — меньше и быстрее.
- **Не всё можно понизить:** top-level await для старой цели — ошибка сборки, а регулярное выражение с флагом `v` молча превращается в `new RegExp(…, "v")` и падает уже в браузере.
- **Трансформаторы стирают типы, не проверяя их.** esbuild, SWC, Oxc и Babel скомпилируют `const n: number = 'строка'` без ошибки, типы проверяет только `tsc`.
- **Все они работают через AST:** разобрать код в дерево, изменить узлы, напечатать обратно. На этом построены плагины, минификаторы и кодмоды для массовых изменений кода.
::

## Синтаксис и API

Сквозной пример — строка из карточки заказа:

```js
const city = user?.address?.city ?? 'не указан';
const last = items.at(-1);
const grouped = Object.groupBy(items, (i) => i.type);
```

В ней три разные вещи. `?.` и `??` — **синтаксис**: парсер старого браузера их не поймёт, и весь файл не загрузится. `items.at` и `Object.groupBy` — **API**: синтаксически это обычные вызовы методов, просто в старом браузере такого метода нет, и упадёт конкретная строка при выполнении.

Транспилятор умеет только первое. Для цели Chrome 79 все четыре проверенных инструмента — esbuild, SWC, Babel и Oxc — переписали `?.` и `??` в тернарные проверки, а `.at(-1)` и `Object.groupBy` оставили как есть.

```js
// после понижения синтаксиса (упрощённо)
const city = (_a = user == null ? void 0 : user.address) == null ? void 0 : _a.city;
const last = items.at(-1);                        // упадёт, если нет Array.prototype.at
```

### Полифилы

Недостающие API добавляет **полифил** — код, который реализует метод, если его нет:

```js
if (!Array.prototype.at) {
  Array.prototype.at = function (i) { i = Math.trunc(i) || 0; return this[i < 0 ? this.length + i : i]; };
}
```

На практике полифилы не пишут вручную. Их подключают из `core-js`: Babel с `@babel/preset-env` и опцией `useBuiltIns: 'usage'` смотрит на используемые API и цели и добавляет только нужные. Для старых браузеров есть и плагины сборщиков, например `@vitejs/plugin-legacy`, который собирает отдельную версию с полифилами для старых браузеров.

Полифил не может всё: нельзя добавить то, что требует движка, — например, `Proxy` или слабые ссылки. И каждый полифил — это килобайты кода у всех пользователей, если не выбирать их по целям.

| | Транспиляция | Полифил |
| --- | --- | --- |
| Что | синтаксис | API: методы, глобальные объекты |
| Когда | при сборке | при выполнении, до кода приложения |
| Чем | esbuild, SWC, Babel, Oxc | `core-js`, отдельные пакеты |
| Ошибка, если забыть | файл не разбирается | падает конкретный вызов |

Что понижать и какие полифилы добавлять, зависит от целевых браузеров.

## Цели и browserslist

**Browserslist** — общий для инструментов способ описать целевые браузеры запросом:

```text
# .browserslistrc
> 0.5%, last 2 versions, not dead
```

Запрос превращается в список вида `chrome 140`, `safari 18.5`, `firefox 145`. В проверке такой запрос дал больше десяти браузеров и не включил Internet Explorer — он «мёртв». Запрос `defaults` — разумный выбор по умолчанию. Список читают Babel, Autoprefixer, Lightning CSS, Stylelint и другие инструменты.

Vite использует цель **Baseline Widely Available** — функции, которые работают во всех основных браузерах не меньше двух с половиной лет. Для неё современный синтаксис почти не понижается. В проверке с целью `es2022` строка с `?.` и `??` осталась нетронутой.

Чем старше цель, тем больше и медленнее код: понижение классов, `async` и генераторов порождает громоздкие помощники. Поэтому цель выбирают по реальной аудитории из аналитики, а не «на всякий случай».

### Значения по умолчанию

Здесь инструменты расходятся, и это частый источник сюрпризов:

- **Babel 8** без `targets` и без конфигурации browserslist берёт запрос `defaults` и почти ничего не понижает — в проверке стрелочная функция осталась стрелкой. Babel 7 в той же ситуации понижал всё до ES5;
- **SWC** без `jsc.target` понижает до **ES5**: в проверке `const` превратился в `var`;
- **esbuild** без `target` ничего не понижает.

Если инструмент выбирают в обход Vite, цель стоит задавать явно.

## Что понизить нельзя

Не каждую возможность можно выразить старым синтаксисом. Инструменты ведут себя по-разному, и это проверено на esbuild:

- **top-level await и `for await`** для старой цели — **ошибка сборки** «Top-level await is not available in the configured target environment». Это лучший вариант: проблема видна сразу;
- **регулярное выражение с флагом `v`** превращается в `new RegExp("[\\p{L}--[a-z]]", "v")` **без ошибки и без предупреждения**. Сборка проходит, а в браузере без поддержки флага конструктор бросит `SyntaxError`;
- **BigInt-литерал** `10n` становится вызовом `BigInt("10")` с предупреждением «may crash at run-time»: если в браузере нет `BigInt`, код упадёт;
- **приватные поля `#items`** понижаются корректно — через `WeakMap`-помощники, ценой размера и скорости.

Вывод: понижение не гарантирует, что код заработает в старом браузере. Предупреждения сборки читают, а целевые браузеры проверяют реальными тестами.

## Типы стираются без проверки

TypeScript и JSX — тоже работа трансформатора: он **стирает** аннотации типов и превращает JSX в вызовы функций. Проверки типов при этом нет:

```ts
const total: number = 'не число';   // esbuild и SWC: const total = 'не число'
```

Оба инструмента в проверке скомпилировали это без ошибки. Причина в устройстве: трансформатор обрабатывает **один файл** и не знает о типах из других модулей, поэтому проверить их не может. Проверку типов делает отдельный шаг — `tsc --noEmit` в редакторе и CI. Как это устроено в конвейере и зачем `isolatedModules`, — в [Инструментах TypeScript](/content/advanced-tooling/typescript-tooling).

## Инструменты

| Инструмент | На чём | Где используется | Особенность |
| --- | --- | --- | --- |
| Babel | JavaScript | легаси-проекты, редкие плагины, кодмоды | огромная экосистема плагинов, самый медленный |
| SWC | Rust | Next.js, Rspack, Deno | быстрый, плагины на Wasm |
| esbuild | Go | Vite до восьмой версии, сборка утилит | очень быстрый, плагинов трансформации нет |
| Oxc | Rust | Vite 8, Rolldown, Oxlint | парсер, трансформатор и минификатор одного проекта |
| `tsc` | Go в TypeScript 7 | проверка типов, выпуск `.d.ts` | единственный, кто проверяет типы |

Разница в скорости — на порядок. В проверке на файле из 400 функций Babel работал около 190 мс, а SWC и esbuild — 12–16 мс. На проекте из тысяч файлов это разница между минутами и секундами, поэтому Babel уходит из конвейеров сборки и остаётся там, где нужны его плагины.

Babel 8 вышел в 2026 году: только ESM, типы для всех пакетов и современная цель по умолчанию.

## AST и кодмоды

Все трансформаторы работают одинаково:

```text
исходный код → парсер → AST (дерево узлов) → обход и изменение узлов → печать → новый код
```

**AST** — абстрактное синтаксическое дерево. `console.log(x)` — это узел `ExpressionStatement` с выражением `CallExpression`, у которого вызываемое — `MemberExpression` из `console` и `log`. Проверено на парсере Babel. Посмотреть дерево любого кода удобно в AST Explorer.

Плагин трансформации — это посетитель узлов определённого типа:

```js
// плагин Babel: удалить console.log при сборке
const removeConsoleLog = ({ types: t }) => ({
  visitor: {
    CallExpression(path) {
      const callee = path.get('callee');
      if (
        callee.isMemberExpression() &&
        t.isIdentifier(callee.node.object, { name: 'console' }) &&
        t.isIdentifier(callee.node.property, { name: 'log' })
      ) {
        path.remove();
      }
    },
  },
});
```

В проверке плагин удалил `console.log('debug')` и оставил `console.error` и остальной код.

**Кодмод** — такой же обход AST, но применённый к исходникам проекта один раз, чтобы массово изменить код: переименовать API при обновлении библиотеки, заменить устаревший импорт, перейти с одного паттерна на другой. Так распространяют миграции React, Next.js и Vue. Инструменты — jscodeshift, ast-grep, а для простых случаев — правила линтера с автоисправлением.

## Красные флаги в ответе

- **«Babel добавит недостающие методы».** Транспиляция меняет только синтаксис, для API нужны полифилы.
- **«Если сборка прошла, код работает в целевых браузерах».** Флаг `v` и BigInt понижаются в код, который упадёт при выполнении.
- **«esbuild и SWC проверяют TypeScript».** Они стирают типы без проверки.
- **«Понижать до ES5 — безопаснее».** Код становится больше и медленнее для всех ради браузеров, которых может не быть в аудитории.
- **«У всех инструментов одинаковые значения по умолчанию».** Babel 8 берёт `defaults`, SWC — ES5, esbuild ничего не понижает.

## Как спрашивают на собеседовании

::question
Чем транспиляция отличается от полифила?

#answer
Транспиляция при сборке переписывает новый синтаксис — `?.`, `??`, классы, `async` — в старый. Полифил при выполнении добавляет недостающие API — `Array.prototype.at`, `Object.groupBy`, `structuredClone`, — если их нет в браузере.

#more
Забытый синтаксис ломает разбор всего файла, забытый полифил — конкретный вызов. Полифилы обычно берут из `core-js` и подключают по целям и реальному использованию. Возможности движка вроде `Proxy` полифилом не добавить.
::

::question
Что такое browserslist и зачем он нужен?

#answer
Общий формат описания целевых браузеров запросом, например `> 0.5%, last 2 versions, not dead` или `defaults`. Запрос превращается в список браузеров и версий, и по нему инструменты решают, что понижать и какие полифилы и префиксы добавить.

#more
Его читают Babel, Autoprefixer, Lightning CSS, Stylelint. Vite по умолчанию использует цель Baseline Widely Available. Цель выбирают по аналитике аудитории: чем она старше, тем больше и медленнее код для всех.
::

::question
Почему сборка прошла, а в старом браузере ошибка?

#answer
Скорее всего, не хватает полифила: транспилятор не трогает вызовы новых методов вроде `items.at(-1)` или `Object.groupBy`. Либо возможность нельзя понизить: регулярное выражение с флагом `v` превращается в `new RegExp(…, "v")`, а BigInt — в вызов `BigInt()`, и оба упадут при выполнении.

#more
Часть таких случаев видна в предупреждениях сборки, часть — нет. Защита — явная цель, полифилы по использованию и проверка в реальных целевых браузерах, например через тесты Playwright в нужных движках.
::

::question
Почему трансформатор не ловит ошибки типов?

#answer
esbuild, SWC, Oxc и Babel обрабатывают каждый файл отдельно и только стирают аннотации типов. Для проверки нужно знать типы из всех модулей проекта, а это делает только `tsc`.

#more
Поэтому проверка типов — отдельный шаг: `tsc --noEmit` или `vue-tsc` в редакторе и CI. Пофайловая трансформация не поддерживает конструкции, которым нужна вся программа, — отсюда настройка `isolatedModules`.
::

::question
Чем Babel отличается от SWC и esbuild?

#answer
Babel написан на JavaScript, у него огромная экосистема плагинов, но он на порядок медленнее. SWC на Rust и esbuild на Go делают ту же работу в десятки раз быстрее, но с меньшей расширяемостью.

#more
В Vite 8 трансформации делает Oxc на Rust, в Next.js — SWC. Babel остаётся для специфических плагинов и кодмодов. Значения по умолчанию у них разные: Babel 8 берёт цель `defaults`, SWC понижает до ES5, esbuild без цели не понижает ничего.
::

::question
Что такое AST и кодмод?

#answer
AST — абстрактное синтаксическое дерево: код, разобранный в узлы вроде `CallExpression` и `MemberExpression`. Трансформаторы разбирают код в AST, меняют узлы и печатают обратно. Кодмод — такая трансформация, применённая к исходникам проекта, чтобы массово изменить код.

#more
Кодмодами распространяют миграции фреймворков: переименование API, замену импортов. Инструменты — jscodeshift, ast-grep, плагины Babel, правила линтера с автоисправлением. AST удобно изучать в AST Explorer.
::

## Практика

::practice{title="Ошибка только у части пользователей"}
После выкладки у части пользователей на старых iPad пустая страница и в мониторинге `TypeError: items.at is not a function`. Сборка на Vite с целью по умолчанию.

#solution
`items.at(-1)` — вызов метода, а не синтаксис, и никакой трансформатор его не перепишет. Цель по умолчанию у Vite — Baseline Widely Available, и старые браузеры в неё не входят. Если такие пользователи важны, есть два пути:

```js
// 1. не использовать метод, если он не нужен
const last = items[items.length - 1];

// 2. собирать отдельную версию с полифилами для старых браузеров
// vite.config.js
import legacy from '@vitejs/plugin-legacy';
export default { plugins: [legacy({ targets: ['defaults', 'iOS >= 15'] })] };
```

`@vitejs/plugin-legacy` собирает вторую версию с понижением синтаксиса и полифилами из `core-js` и подключает её только старым браузерам. Решение — по аналитике: если таких пользователей единицы, дешевле сообщить им об обновлении браузера. В проверке все трансформаторы оставили `.at(-1)` нетронутым.
::

::practice{title="Убрать отладочные вызовы"}
Перед выкладкой нужно удалить все `console.log`, но оставить `console.error` и `console.warn`.

#solution
Это задача для трансформации AST. Плагин находит вызовы, где вызываемое — `console.log`, и удаляет их:

```js
const removeConsoleLog = ({ types: t }) => ({
  visitor: {
    CallExpression(path) {
      const callee = path.get('callee');
      if (
        callee.isMemberExpression() &&
        t.isIdentifier(callee.node.object, { name: 'console' }) &&
        t.isIdentifier(callee.node.property, { name: 'log' })
      ) {
        path.remove();
      }
    },
  },
});
```

В Vite то же самое проще сделать настройкой минификатора — `drop_console` или список чистых функций, — но плагин показывает, как это работает. Ещё лучше не допускать таких вызовов вовсе: правило линтера `no-console` с исключениями для `error` и `warn`. В проверке плагин удалил `console.log('debug')` и оставил `console.error('fail')` и `run()`.
::
