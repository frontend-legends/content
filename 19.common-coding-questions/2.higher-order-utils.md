# Утилиты высшего порядка

Это самый частый блок на фронтенд-собесах. Все эти функции - **функции, которые принимают или возвращают функции**: `debounce`, `throttle`, `curry`, `memoize`, `compose`. Их любят, потому что они короткие, но требуют понимания **замыканий, `this`, таймеров и аргументов**.

---

## debounce

<b class="text-on-semi-light">debounce</b> <span class="text-gray">- откладывает вызов функции, пока не пройдёт `delay` мс «тишины». Каждый новый вызов сбрасывает таймер. Применяют для поиска по вводу, ресайза, автосохранения.</span>

```ts
function debounce<T extends (...args: any[]) => any>(fn: T, delay = 300) {
  let timer: ReturnType<typeof setTimeout> | null = null;

  return function (this: unknown, ...args: Parameters<T>) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args); // сохраняем this и аргументы последнего вызова
    }, delay);
  };
}
```

**На что смотрит интервьюер:**

1. **`this` и `args`** - через обычную функцию + `apply`, а не стрелку (иначе потеряешь `this`).
2. **Сброс таймера** - `clearTimeout` перед новым `setTimeout`.
3. **Замыкание** - `timer` живёт между вызовами.

**Расширенная версия** часто спрашивается дополнительно - с немедленным вызовом (`leading`) и отменой:

```ts
function debounce<T extends (...args: any[]) => any>(
  fn: T,
  delay = 300,
  { leading = false } = {}
) {
  let timer: ReturnType<typeof setTimeout> | null = null;

  function debounced(this: unknown, ...args: Parameters<T>) {
    const callNow = leading && !timer;
    if (timer) clearTimeout(timer);

    timer = setTimeout(() => {
      timer = null;
      if (!leading) fn.apply(this, args);
    }, delay);

    if (callNow) fn.apply(this, args);
  }

  debounced.cancel = () => {
    if (timer) clearTimeout(timer);
    timer = null;
  };

  return debounced;
}
```

> ⚠️ Частая ошибка - стрелочная функция вместо `function`. Тогда `this` берётся из места объявления, а не вызова, и для методов объекта всё ломается.

## throttle

<b class="text-on-semi-light">throttle</b> <span class="text-gray">- пропускает вызов не чаще, чем раз в `limit` мс. В отличие от `debounce`, гарантирует регулярные вызовы во время непрерывной активности. Применяют для скролла, мышиных событий, частых API.</span>

```ts
function throttle<T extends (...args: any[]) => any>(fn: T, limit = 300) {
  let last = 0;
  let timer: ReturnType<typeof setTimeout> | null = null;

  return function (this: unknown, ...args: Parameters<T>) {
    const now = Date.now();
    const remaining = limit - (now - last);

    if (remaining <= 0) {
      // прошло достаточно времени - вызываем сразу
      if (timer) { clearTimeout(timer); timer = null; }
      last = now;
      fn.apply(this, args);
    } else if (!timer) {
      // планируем «хвостовой» вызов на конец окна
      timer = setTimeout(() => {
        last = Date.now();
        timer = null;
        fn.apply(this, args);
      }, remaining);
    }
  };
}
```

**debounce vs throttle - ключевое отличие:**

| | debounce | throttle |
| --- | --- | --- |
| Когда вызывает | после паузы в активности | равномерно во время активности |
| Поиск по вводу | ✅ | ❌ |
| Скролл / ресайз | при остановке | каждые N мс |
| Мысль | «подожди, пока перестанут» | «не чаще раза в N мс» |

> На собесе почти всегда просят оба и **разницу между ними** - это любимый уточняющий вопрос.

## curry

<b class="text-on-semi-light">Каррирование</b> <span class="text-gray">- преобразование функции от N аргументов в цепочку функций от одного. `sum(1)(2)(3)` или `sum(1, 2)(3)` - оба должны работать.</span>

```ts
function curry(fn: (...args: any[]) => any) {
  return function curried(this: unknown, ...args: any[]) {
    if (args.length >= fn.length) {
      return fn.apply(this, args); // аргументов хватает - вызываем
    }
    // не хватает - возвращаем функцию, копящую аргументы
    return (...next: any[]) => curried.apply(this, [...args, ...next]);
  };
}

const sum = (a: number, b: number, c: number) => a + b + c;
const curried = curry(sum);
curried(1)(2)(3);   // 6
curried(1, 2)(3);   // 6
curried(1)(2, 3);   // 6
```

Ключевая идея - сравнивать `args.length` с `fn.length` (числом объявленных параметров).

## memoize

<b class="text-on-semi-light">Мемоизация</b> <span class="text-gray">- кэширование результата функции по её аргументам. Повторный вызов с теми же аргументами возвращает значение из кэша, а не считает заново.</span>

```ts
function memoize<T extends (...args: any[]) => any>(
  fn: T,
  resolver: (...args: Parameters<T>) => string = (...a) => JSON.stringify(a)
) {
  const cache = new Map<string, ReturnType<T>>();

  return function (this: unknown, ...args: Parameters<T>): ReturnType<T> {
    const key = resolver(...args);
    if (cache.has(key)) return cache.get(key)!;

    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}
```

> ⚠️ `JSON.stringify` как ключ - простой, но ломается на функциях, `undefined`, циклах и порядке ключей. На собесе упомяни это и предложи кастомный `resolver`. Для одного аргумента-объекта лучше `WeakMap` (не держит ссылку, не течёт память).

## compose и pipe

<b class="text-on-semi-light">compose / pipe</b> <span class="text-gray">- собирают одну функцию из нескольких. `compose` применяет справа налево (как в математике), `pipe` - слева направо (как читаем).</span>

```ts
const compose = (...fns: Function[]) =>
  (x: unknown) => fns.reduceRight((acc, fn) => fn(acc), x);

const pipe = (...fns: Function[]) =>
  (x: unknown) => fns.reduce((acc, fn) => fn(acc), x);

const inc = (n: number) => n + 1;
const double = (n: number) => n * 2;

compose(inc, double)(5); // inc(double(5)) = 11
pipe(inc, double)(5);    // double(inc(5)) = 12
```

Разница - только направление и `reduce` vs `reduceRight`. Любимый уточняющий вопрос: «а в каком порядке выполнятся функции?»

## once

<b class="text-on-semi-light">once</b> <span class="text-gray">- оборачивает функцию так, что она выполнится **только один раз**, а дальше возвращает закэшированный результат. Полезно для инициализации.</span>

```ts
function once<T extends (...args: any[]) => any>(fn: T) {
  let called = false;
  let result: ReturnType<T>;

  return function (this: unknown, ...args: Parameters<T>): ReturnType<T> {
    if (!called) {
      called = true;
      result = fn.apply(this, args);
    }
    return result;
  };
}
```

## Вопросы на собеседовании

<b class="text-on-semi-light">В чём разница между debounce и throttle?</b>
<span class="text-gray">debounce ждёт паузу в активности и вызывает один раз после неё (поиск по вводу). throttle вызывает равномерно, не чаще раза в N мс, во время непрерывной активности (скролл). debounce - «подожди тишины», throttle - «не чаще чем».</span>

<b class="text-on-semi-light">Почему в debounce нельзя использовать стрелочную функцию для возвращаемой обёртки?</b>
<span class="text-gray">Стрелка не имеет своего `this` - возьмёт его из места объявления, а не вызова. Для методов объекта `this` будет неверным. Нужна обычная `function` + `fn.apply(this, args)`.</span>

<b class="text-on-semi-light">Как curry понимает, что аргументов достаточно?</b>
<span class="text-gray">Сравнивает число накопленных аргументов с `fn.length` (количеством объявленных параметров). Хватает - вызывает оригинал, нет - возвращает функцию, продолжающую копить аргументы.</span>

<b class="text-on-semi-light">Чем плох JSON.stringify как ключ кэша в memoize?</b>
<span class="text-gray">Не сериализует функции и `undefined`, падает на циклах, чувствителен к порядку ключей объекта. Для объектов-аргументов лучше `WeakMap` - он не держит ссылку и не течёт памятью.</span>

<b class="text-on-semi-light">compose vs pipe?</b>
<span class="text-gray">Одно и то же, разное направление. compose применяет функции справа налево (`reduceRight`), pipe - слева направо (`reduce`). pipe читается естественнее.</span>
