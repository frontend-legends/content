# Утилиты высшего порядка

Самый частый блок фронтенд-задач: функции, которые принимают или возвращают функции, — `debounce`, `throttle`, `curry`, `memoize`, `compose`, `once`. Они короткие, но держатся на замыканиях, `this`, таймерах и аргументах, поэтому на каждой легко ошибиться. Спрашивают разницу `debounce` и `throttle`, почему обёртка — не стрелка и как `curry` понимает, что аргументов хватает. Глубже — почему наивный `throttle` теряет последнее значение, почему `curry` ломается на параметрах по умолчанию и почему `JSON.stringify` как ключ кеша путает `null` и `undefined`.

::tldr
- **debounce ждёт тишины, throttle ограничивает частоту:** первый вызывает один раз после паузы (поиск по вводу), второй — равномерно во время активности (прокрутка).
- **Обёртка — обычная `function` с `fn.apply(this, args)`:** в проверке стрелочная обёртка потеряла `this` метода объекта.
- **Хвостовой вызов throttle должен нести последние аргументы:** в проверке наивная версия потеряла последнее положение прокрутки, исправленная — доставила.
- **curry сравнивает число аргументов с `fn.length`:** но `fn.length` не считает параметры по умолчанию и rest — в проверке каррирование «закончилось» раньше времени.
- **Ключ кеша в memoize — главная тонкость:** `JSON.stringify` даёт один ключ для `null`, `undefined` и функции; для аргумента-объекта лучше `WeakMap` по ссылке.
::

## debounce

`debounce` откладывает вызов функции, пока не пройдёт `delay` миллисекунд тишины; каждый новый вызов сбрасывает таймер. Применяют для поиска по вводу, ресайза, автосохранения.

```ts
function debounce<T extends (...args: any[]) => any>(fn: T, delay = 300) {
  let timer: ReturnType<typeof setTimeout> | null = null;
  return function (this: unknown, ...args: Parameters<T>) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args); // this и аргументы последнего вызова
    }, delay);
  };
}
```

В проверке на фейковых таймерах три вызова поиска с интервалом 100 мс не вызвали функцию ни разу, пока шёл набор, и ровно один раз — с последним аргументом «чай» — через 300 мс тишины. На что смотрит интервьюер:

1. **сброс таймера** — `clearTimeout` перед новым `setTimeout`;
2. **замыкание** — `timer` живёт между вызовами;
3. **`this` и аргументы** — обёртка обычная `function`, а вызов через `apply`.

### Почему не стрелка

Стрелочная функция не имеет своего `this` и берёт его из места объявления, а не вызова. Если обёртку сделать стрелкой, метод объекта потеряет `this`. В проверке метод `save`, обёрнутый «стрелочным» дебаунсом, получил `this === undefined` вместо объекта, а с обычной `function` — сам объект и записал `форма:черновик`. TypeScript, кстати, подсвечивает проблему: без аннотации `this` в такой обёртке он выдаёт ошибку TS2683.

### leading и cancel

Часто дополнительно просят немедленный вызов в начале серии (`leading`) и отмену:

```ts
function debounce<T extends (...args: any[]) => any>(fn: T, delay = 300, { leading = false } = {}) {
  let timer: ReturnType<typeof setTimeout> | null = null;
  function debounced(this: unknown, ...args: Parameters<T>) {
    const callNow = leading && !timer;
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      if (!leading) fn.apply(this, args);
    }, delay);
    if (callNow) fn.apply(this, args);
  }
  debounced.cancel = () => {
    if (timer) clearTimeout(timer);
    timer = null;
  };
  return debounced;
}
```

В проверке с `leading: true` первый клик серии выполнился сразу, а второй и третий погасли; после паузы следующий клик снова выполнился сразу. `cancel` отменил отложенный вызов — это нужно при размонтировании компонента, чтобы функция не сработала уже на удалённом интерфейсе.

## throttle

`throttle` пропускает вызов не чаще раза в `limit` миллисекунд. В отличие от `debounce`, он гарантирует регулярные вызовы во время непрерывной активности. Применяют для прокрутки, движения мыши, частых событий.

Важная тонкость — хвостовой вызов в конце окна. Наивная реализация планирует его с аргументами того вызова, который попал в окно первым, и последние значения теряются. В проверке на одиннадцати событиях прокрутки (положения 0…250 каждые 25 мс) с лимитом 100 мс наивная версия вызвала обработчик с положениями `0, 25, 100, 200` — последнее положение 250 до обработчика так и не дошло, и экран остался бы «недокрученным». Исправленная версия запоминает последние аргументы и `this`:

```ts
function throttle<T extends (...args: any[]) => any>(fn: T, limit = 300) {
  let last = 0;
  let timer: ReturnType<typeof setTimeout> | null = null;
  let lastArgs: Parameters<T> | null = null;
  let lastThis: unknown;
  return function (this: unknown, ...args: Parameters<T>) {
    const now = Date.now();
    const remaining = limit - (now - last);
    lastArgs = args;
    lastThis = this;
    if (remaining <= 0) {
      if (timer) { clearTimeout(timer); timer = null; }
      last = now;
      fn.apply(this, args);         // ведущий вызов — сразу
      lastArgs = null;
    } else if (!timer) {
      timer = setTimeout(() => {    // хвостовой — в конце окна, со свежими аргументами
        last = Date.now();
        timer = null;
        if (lastArgs) { fn.apply(lastThis, lastArgs); lastArgs = null; }
      }, remaining);
    }
  };
}
```

С ней обработчик получил `0, 75, 175, 250` в моменты 0, 100, 200 и 300 мс: ведущий вызов сразу, дальше не чаще раза в 100 мс, и последнее положение доставлено.

| | debounce | throttle |
| --- | --- | --- |
| Когда вызывает | после паузы в активности | равномерно во время активности |
| Поиск по вводу | подходит | не подходит |
| Прокрутка и ресайз | один раз при остановке | каждые N мс |
| Мысль | «подожди, пока перестанут» | «не чаще раза в N мс» |

Где эти функции применяют в производительности интерфейса — в [производительности выполнения](/content/security-perfomance/runtime-performance).

## curry

Каррирование превращает функцию от N аргументов в цепочку функций, которая принимает аргументы по одному или группами: `sum(1)(2)(3)`, `sum(1, 2)(3)` и `sum(1)(2, 3)` должны давать одно и то же.

```ts
function curry(fn: (...args: any[]) => any) {
  return function curried(this: unknown, ...args: any[]): any {
    if (args.length >= fn.length) return fn.apply(this, args); // аргументов хватает
    return (...next: any[]) => curried.apply(this, [...args, ...next]);
  };
}
const sum = (a: number, b: number, c: number) => a + b + c;
curry(sum)(1)(2)(3); // 6
```

Ключевая идея — сравнивать число накопленных аргументов с `fn.length`, числом объявленных параметров. В проверке все четыре формы вызова дали 6. Но у `fn.length` есть ловушка: он не считает параметры со значением по умолчанию и rest-параметры. В проверке у `(a, b = 10) => a + b` длина оказалась 1, и каррирование выполнило функцию уже после первого аргумента, а у `(...xs) => …` длина 0. Для таких функций арность передают явно: `curry(fn, 3)`. Это хороший пункт, чтобы назвать его самому.

## memoize

Мемоизация запоминает результат функции по её аргументам: повторный вызов с теми же аргументами возвращает значение из кеша.

```ts
function memoize<T extends (...args: any[]) => any>(
  fn: T,
  resolver: (...args: Parameters<T>) => string = (...a) => JSON.stringify(a),
) {
  const cache = new Map<string, ReturnType<T>>();
  return function (this: unknown, ...args: Parameters<T>): ReturnType<T> {
    const key = resolver(...args);
    if (cache.has(key)) return cache.get(key)!;
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}
```

В проверке второй вызов `square(4)` вернул 16 из кеша, не вычисляя заново. Главная тонкость — ключ. `JSON.stringify` прост, но ошибается в обе стороны:

- **разные аргументы — один ключ:** `[undefined]`, `[null]` и `[() => 1]` сериализуются одинаково, в `"[null]"`. В проверке мемоизированная `typeof` для `undefined` и для функции вернула закешированный ответ для `null` — `'object'`;
- **одинаковые по смыслу — разные ключи:** `{ a: 1, b: 2 }` и `{ b: 2, a: 1 }` дают разные строки — лишний промах кеша;
- ещё он падает на циклических ссылках.

Для одного аргумента-объекта лучше `WeakMap` по ссылке: без сериализации, а запись исчезает вместе с объектом, так что кеш не держит память:

```ts
function memoizeByObject<A extends object, R>(fn: (a: A) => R) {
  const cache = new WeakMap<A, R>();
  return (a: A): R => { if (!cache.has(a)) cache.set(a, fn(a)); return cache.get(a)!; };
}
```

В проверке тот же объект корзины второй раз взялся из кеша, а другой объект с тем же содержимым посчитался заново — ключ здесь ссылка, а не содержимое. Ограниченный по размеру кеш для общего случая — [LRU](/content/common-coding-questions/caching-and-state).

## compose и pipe

`compose` и `pipe` собирают одну функцию из нескольких. `compose` применяет их справа налево, как в математике, `pipe` — слева направо, в порядке чтения.

```ts
const compose = (...fns: Function[]) => (x: unknown) => fns.reduceRight((acc, fn) => fn(acc), x);
const pipe = (...fns: Function[]) => (x: unknown) => fns.reduce((acc, fn) => fn(acc), x);
const inc = (n: number) => n + 1;
const double = (n: number) => n * 2;
compose(inc, double)(5); // inc(double(5)) = 11
pipe(inc, double)(5);    // double(inc(5)) = 12
```

Разница только в направлении — `reduceRight` против `reduce`. В проверке `compose` дал 11, `pipe` — 12, а `pipe()` без функций вернул аргумент как есть. Теория композиции и чистых функций — в [функциональном программировании](/content/computer-science/fp).

## once

`once` оборачивает функцию так, что она выполнится один раз, а дальше вернёт сохранённый результат. Полезно для инициализации.

```ts
function once<T extends (...args: any[]) => any>(fn: T) {
  let called = false;
  let result: ReturnType<T>;
  return function (this: unknown, ...args: Parameters<T>): ReturnType<T> {
    if (!called) { called = true; result = fn.apply(this, args); }
    return result;
  };
}
```

В проверке второй вызов с другим аргументом вернул первый результат, а сама функция выполнилась один раз. Флаг ставят до вызова `fn`: если `fn` рекурсивно вызовет обёртку, второй раз она не выполнится.

## Красные флаги в ответе

- Стрелочная функция в качестве обёртки — теряется `this` методов.
- Нет `clearTimeout` перед новым таймером в `debounce`.
- Хвостовой вызов `throttle` с аргументами первого вызова в окне — последнее значение теряется.
- `curry` по `fn.length` без оговорки про параметры по умолчанию и rest.
- `JSON.stringify` как ключ кеша без упоминания коллизий и циклов.
- Кеш без ограничения размера для потока разных аргументов — утечка памяти.
- Путают направление `compose` и `pipe`.

## Как спрашивают на собеседовании

::question
В чём разница между debounce и throttle?

#answer
`debounce` ждёт паузу в активности и вызывает функцию один раз после неё — для поиска по вводу и автосохранения. `throttle` вызывает равномерно, не чаще раза в N мс, во время непрерывной активности — для прокрутки и движения мыши. Коротко: «подожди тишины» против «не чаще чем».

#more
У обоих бывают ведущий и хвостовой вызовы. Для `throttle` важно, чтобы хвостовой вызов нёс последние аргументы: в проверке наивная версия потеряла последнее положение прокрутки. Часто спрашивают и про отмену — `cancel` при размонтировании компонента.
::

::question
Почему обёртку в debounce нельзя делать стрелкой?

#answer
Стрелочная функция не имеет своего `this` и берёт его из места объявления, а не вызова. Если обёрнутую функцию вызывают как метод объекта, `this` внутри будет не объект. Нужна обычная `function` и вызов `fn.apply(this, args)`.

#more
В проверке метод, обёрнутый стрелочным дебаунсом, получил `this === undefined`, а с обычной функцией — сам объект. TypeScript подсвечивает такую обёртку ошибкой TS2683, если не указать тип `this`. Стрелка внутри `setTimeout` при этом уместна — она как раз захватывает `this` обёртки.
::

::question
Как curry понимает, что аргументов достаточно?

#answer
Сравнивает число накопленных аргументов с `fn.length` — количеством объявленных параметров. Хватает — вызывает исходную функцию, не хватает — возвращает функцию, которая продолжает копить аргументы.

#more
`fn.length` не считает параметры со значением по умолчанию и rest: у `(a, b = 10) => …` длина 1, у `(...xs) => …` — 0. В проверке каррирование первой функции выполнилось уже после одного аргумента. Для таких случаев арность передают явно вторым параметром `curry`.
::

::question
Чем плох JSON.stringify как ключ кеша в memoize?

#answer
Он путает разные аргументы: `undefined`, `null` и функция сериализуются одинаково, в `null`, — в проверке мемоизированная функция вернула для `undefined` ответ, закешированный для `null`. Чувствителен к порядку ключей объекта и падает на циклических ссылках.

#more
Для одного аргумента-объекта лучше `WeakMap` по ссылке: не нужна сериализация, и запись исчезает вместе с объектом, не держа память. Для примитивов — `Map` по значению. Для множества разных аргументов кеш ограничивают по размеру, например LRU, иначе он растёт бесконечно.
::

::question
Чем compose отличается от pipe?

#answer
Направлением. `compose` применяет функции справа налево (`reduceRight`), как в математической записи `f(g(x))`. `pipe` — слева направо (`reduce`), в порядке чтения. В проверке `compose(inc, double)(5)` дал 11, а `pipe(inc, double)(5)` — 12.

#more
`pipe` обычно читается естественнее, поэтому его чаще используют в прикладном коде. Краевой случай — пустой список функций: оба должны вернуть аргумент без изменений. Асинхронный вариант собирают через `reduce` по промисам.
::

::question
Как реализовать once и что вернуть при повторном вызове?

#answer
Замыкание с флагом и сохранённым результатом: при первом вызове выставить флаг, выполнить функцию и запомнить результат, при следующих — вернуть его. Повторные аргументы игнорируются.

#more
Флаг ставят до вызова, чтобы рекурсивный вызов обёртки изнутри `fn` не выполнил её второй раз. Если `fn` бросила ошибку, решают явно: считать ли вызов состоявшимся. Для асинхронной инициализации сохраняют промис — тогда параллельные вызовы ждут один и тот же результат.
::

## Практика

::practice{title="Прокрутка останавливается «недокрученной»"}
Индикатор прочитанного обновляется при прокрутке через `throttle`, но после остановки показывает не то положение, где остановился пользователь, а чуть раньше. Реализация:

```ts
function throttle(fn, limit) {
  let last = 0, timer = null;
  return function (...args) {
    const remaining = limit - (Date.now() - last);
    if (remaining <= 0) { last = Date.now(); fn.apply(this, args); }
    else if (!timer) {
      timer = setTimeout(() => { last = Date.now(); timer = null; fn.apply(this, args); }, remaining);
    }
  };
}
```

#solution
Хвостовой вызов планируется с аргументами того события, которое первым попало в окно, а все следующие события в этом окне просто игнорируются. В проверке на прокрутке до 250 обработчик получил последним положение 200 — 250 потерялось. Нужно запоминать последние аргументы и `this` при каждом вызове и брать их в хвостовом вызове:

```ts
lastArgs = args; lastThis = this;              // при каждом вызове
// …
timer = setTimeout(() => {
  last = Date.now(); timer = null;
  if (lastArgs) { fn.apply(lastThis, lastArgs); lastArgs = null; }
}, remaining);
```

С этим исправлением в проверке обработчик получил `0, 75, 175, 250` — последнее положение доставлено. Так работает и `throttle` из lodash: хвостовой вызов всегда несёт последние аргументы.
::

::practice{title="Кеш возвращает ответ от другого аргумента"}
Мемоизированная функция форматирования иногда возвращает результат для `null`, когда её вызывают с `undefined`. Ключ кеша — `JSON.stringify(args)`.

#solution
`JSON.stringify` сериализует `undefined` в массиве как `null`, поэтому `[undefined]` и `[null]` дают одну строку `"[null]"`, — так же и функции. В проверке мемоизированная `typeof` для `undefined` вернула закешированный ответ для `null`. Решения зависят от аргументов. Для примитивов — составной ключ, различающий типы:

```ts
const key = (...args: unknown[]) => args.map((a) => `${typeof a}:${String(a)}`).join('|');
const format = memoize(formatValue, key);
```

Для одного аргумента-объекта — `WeakMap` по ссылке, без сериализации:

```ts
const cache = new WeakMap<object, string>();
const formatObj = (o: object) => { if (!cache.has(o)) cache.set(o, formatValue(o)); return cache.get(o)!; };
```

Отдельно решают, сколько хранить: кеш без ограничения на потоке разных аргументов растёт бесконечно — тогда берут [LRU](/content/common-coding-questions/caching-and-state).
::
