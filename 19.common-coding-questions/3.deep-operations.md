# Глубокие операции с данными

Вторая по частоте группа задач — рекурсивная работа со вложенными структурами: `deepClone`, `deepEqual`, `flatten` массива и объекта, доступ по пути `get` и `set`. Проверяют рекурсию, различение типов и краевые случаи — циклы, `null`, массивы против объектов, даты. Спрашивают, чем плох JSON-клон, как обработать циклические ссылки и зачем `get`, если есть `?.`. Глубже — почему наивный `deepEqual` считает равными любые две даты, почему `deepClone` теряет `Set`, когда рекурсия падает, а стек нет, и как `set` по пути загрязняет прототип.

::tldr
- **Сначала назвать встроенное:** `structuredClone` понимает `Date`, `Map`, `Set` и циклы, но не клонирует функции и теряет класс. JSON-клон теряет ещё больше: `Map` становится `{}`, `Date` — строкой, на цикле — ошибка.
- **deepClone — рекурсия с `WeakMap` против циклов:** копию записывают в `WeakMap` до обхода вложенных значений. Каждый особый тип — `Date`, `RegExp`, `Map`, `Set` — разбирают отдельно, иначе в проверке `Set` превращался в `{}`.
- **deepEqual сравнивает прототипы до ключей:** без этого в проверке `[1]` и `{0: 1}` оказались равными, как и любые две даты — у `Date` нет собственных ключей.
- **flatten через стек не падает на глубине:** в проверке рекурсивная версия на 20 000 уровнях вложенности упала с `RangeError`, а итеративная справилась.
- **get и set по пути — для динамических путей:** `?.` работает только с путём в коде. `set` с путём из внешних данных проверяет ключи, иначе `__proto__` загрязнит прототип.
::

## deepClone

Глубокое клонирование создаёт полную копию, в которой вложенные объекты тоже скопированы: изменение копии не задевает оригинал.

### Сначала встроенное

На интервью начинают с того, что есть в платформе, и называют ограничения:

- **`structuredClone`** понимает `Date`, `Map`, `Set`, типизированные массивы и циклические ссылки. Но функции он не клонирует — бросает `DataCloneError`, — а экземпляр класса превращает в обычный объект без прототипа. В проверке всё это подтвердилось: клон с циклом, датой, `Map` и `Set` получился правильным, функция вызвала `DataCloneError`, а копия `new Point()` перестала быть `instanceof Point`. Подробнее — в [объектах и массивах](/content/javascript/objects-and-arrays).
- **`JSON.parse(JSON.stringify(x))`** теряет ещё больше. В проверке `Map` стал `{}`, `Date` — строкой, `undefined` и функция просто исчезли, а циклическая ссылка вызвала `TypeError`. Годится только для данных, которые и так приходят из JSON.

### Рекурсивная реализация

После этого обычно просят написать рекурсию руками:

```ts
function deepClone<T>(value: T, seen = new WeakMap<object, unknown>()): T {
  if (value === null || typeof value !== 'object') return value; // примитивы и функции — как есть
  if (seen.has(value)) return seen.get(value) as T;               // цикл: вернуть уже созданную копию
  if (value instanceof Date) return new Date(value) as T;
  if (value instanceof RegExp) return new RegExp(value.source, value.flags) as T;
  if (value instanceof Map) {
    const map = new Map();
    seen.set(value, map);
    value.forEach((v, k) => map.set(k, deepClone(v, seen))); // ключи — по ссылке
    return map as T;
  }
  if (value instanceof Set) {
    const set = new Set();
    seen.set(value, set);
    value.forEach((v) => set.add(deepClone(v, seen)));
    return set as T;
  }
  if (Array.isArray(value)) {
    const arr: unknown[] = [];
    seen.set(value, arr);
    value.forEach((item, i) => { arr[i] = deepClone(item, seen); });
    return arr as T;
  }
  const result = Object.create(Object.getPrototypeOf(value)); // прототип сохраняется
  seen.set(value, result);                                     // записываем ДО рекурсии
  for (const key of Object.keys(value)) result[key] = deepClone((value as any)[key], seen);
  return result;
}
```

Ключевые моменты:

1. **базовый случай** — примитивы, `null` и функции возвращают как есть;
2. **циклы** — `WeakMap` сопоставляет оригинал и уже созданную копию. Записывать в него нужно до обхода вложенных значений: тогда повторная встреча того же объекта вернёт готовую копию, а не уйдёт в бесконечную рекурсию;
3. **особые типы** — у `Date`, `RegExp`, `Map`, `Set` нет собственных ключей с данными, их разбирают отдельно. Частая ошибка — упомянуть `Set` и не обработать: тогда он проходит в ветку обычного объекта и в проверке превращался в `{}`;
4. **прототип** — `Object.create(Object.getPrototypeOf(value))` сохраняет класс, в отличие от `structuredClone`.

В проверке копия объекта с циклом, датой, регулярным выражением, `Set`, `Map` и экземпляром класса получилась независимой: изменение вложенного массива и значения в `Map` у копии не задело оригинал, цикл воспроизвёлся, `Set` остался `Set`, а метод класса работал. Ключи `Map` копируют по ссылке, как и lodash: ключ — это идентичность, и клон ключа уже не найдёт исходное значение.

`WeakMap`, а не `Map`, потому что ключи держатся слабо: после клонирования исходные объекты могут быть собраны сборщиком мусора, и вспомогательная таблица не держит память.

## deepEqual

Глубокое сравнение проверяет, что две структуры равны по значению на всех уровнях, а не по ссылке. Наивная версия сравнивает только ключи — и ошибается там, где у разных значений одинаковые ключи:

```ts
function deepEqual(a: unknown, b: unknown): boolean {
  if (a === b || (a !== a && b !== b)) return true;  // NaN равен NaN, 0 равен -0
  if (typeof a !== 'object' || typeof b !== 'object' || a === null || b === null) return false;
  if (Object.getPrototypeOf(a) !== Object.getPrototypeOf(b)) return false; // массив ≠ объект, Date ≠ {}
  if (a instanceof Date) return a.getTime() === (b as Date).getTime();
  if (a instanceof Map) {
    const m = b as Map<unknown, unknown>;
    return a.size === m.size && [...a].every(([k, v]) => m.has(k) && deepEqual(v, m.get(k)));
  }
  if (a instanceof Set) {
    const s = b as Set<unknown>;
    return a.size === s.size && [...a].every((v) => s.has(v));
  }
  const keysA = Object.keys(a), keysB = Object.keys(b);
  if (keysA.length !== keysB.length) return false;
  return keysA.every((k) => Object.prototype.hasOwnProperty.call(b, k) && deepEqual((a as any)[k], (b as any)[k]));
}
```

Без проверки прототипа в проверке `[1]` и `{ 0: 1 }` оказались «равны» — у них одинаковые ключи, — а любые две даты тоже: у `Date` нет собственных ключей, и сравнение `Object.keys` всегда даёт совпадение. С проверкой прототипа и отдельной веткой для `Date` оба случая дали `false`, а одинаковые даты — `true`. Первая строка реализует SameValueZero: `NaN` равен `NaN`, хотя `NaN !== NaN`. Порядок ключей не важен, а `{ a: 1 }` и `{ a: 1, b: undefined }` различаются числом ключей. Уточняющие вопросы на интервью — ровно об этом: как сравнивать `NaN`, даты, `Map`, нужно ли учитывать прототип.

## flatten массива

`flatten` превращает вложенный массив в плоский, обычно с параметром глубины, как `Array.prototype.flat`:

```ts
function flatten<T>(arr: unknown[], depth = Infinity): T[] {
  return arr.reduce<T[]>((acc, item) => {
    if (Array.isArray(item) && depth > 0) acc.push(...flatten<T>(item, depth - 1));
    else acc.push(item as T);
    return acc;
  }, []);
}
flatten([1, [2, [3, [4]]]]);  // [1, 2, 3, 4]
flatten([1, [2, [3]]], 1);    // [1, 2, [3]]
```

В проверке результат совпал со встроенным `flat` на тех же глубинах. Если просят без рекурсии, используют стек:

```ts
function flattenIter(arr: unknown[]): unknown[] {
  const stack = [...arr];
  const result: unknown[] = [];
  while (stack.length) {
    const next = stack.pop();
    if (Array.isArray(next)) stack.push(...next);
    else result.push(next);
  }
  return result.reverse(); // pop идёт с конца — порядок разворачиваем
}
```

Это не только упражнение. В проверке массив с 20 000 уровнями вложенности рекурсивная версия обработать не смогла — упала с `RangeError: Maximum call stack size exceeded`, — а версия со стеком вернула `[0]`. Стек вызовов ограничен, стек в куче — нет.

## flatten объекта

`flattenObject` превращает вложенный объект в плоский, где ключи — пути через точку. Частая задача для конфигов и форм. Главная тонкость — решить, во что рекурсивно заходить. Проверка `typeof value === 'object'` заходит и в `Date`: у даты нет собственных ключей, и в проверке она вместе с пустым объектом просто исчезла из результата. Поэтому заходят только в обычные непустые объекты:

```ts
const isPlainObject = (v: unknown): v is Record<string, unknown> =>
  v !== null && typeof v === 'object' && [Object.prototype, null].includes(Object.getPrototypeOf(v));

function flattenObject(obj: Record<string, unknown>, prefix = ''): Record<string, unknown> {
  const result: Record<string, unknown> = {};
  for (const key of Object.keys(obj)) {
    const path = prefix ? `${prefix}.${key}` : key;
    const value = obj[key];
    if (isPlainObject(value) && Object.keys(value).length) Object.assign(result, flattenObject(value, path));
    else result[path] = value; // массивы, даты, пустые объекты и примитивы — листья
  }
  return result;
}
flattenObject({ a: { b: { c: 1 } }, d: 2 }); // { 'a.b.c': 1, d: 2 }
```

В проверке дата, массив, пустой объект и `null` сохранились как листья под своими путями.

## get и set по пути

`get(obj, path, def)` безопасно достаёт значение по пути вида `'a.b[0].c'` и возвращает значение по умолчанию, если пути нет. `set` — наоборот, создаёт путь:

```ts
const toKeys = (path: string | string[]) =>
  Array.isArray(path) ? path : path.replace(/\[(\w+)\]/g, '.$1').split('.').filter(Boolean);

function get(obj: unknown, path: string | string[], def?: unknown) {
  let result: any = obj;
  for (const key of toKeys(path)) {
    if (result == null) return def;
    result = result[key];
  }
  return result === undefined ? def : result;
}

const FORBIDDEN = new Set(['__proto__', 'constructor', 'prototype']);
function set(obj: any, path: string | string[], value: unknown) {
  const keys = toKeys(path);
  if (keys.some((k) => FORBIDDEN.has(k))) throw new Error(`запрещённый ключ в пути: ${keys.join('.')}`);
  let curr = obj;
  keys.forEach((key, i) => {
    if (i === keys.length - 1) curr[key] = value;
    else {
      if (curr[key] == null) curr[key] = /^\d+$/.test(keys[i + 1]) ? [] : {}; // числовой следующий ключ → массив
      curr = curr[key];
    }
  });
  return obj;
}
```

В проверке `get` достал 42 и по строке `'a.b[0].c'`, и по массиву ключей, вернул значение по умолчанию на несуществующем пути без ошибки, а для поля со значением `null` вернул `null` — значение по умолчанию подставляется только вместо `undefined`. `set({}, 'form.items[0].title', 'чай')` создал объект, затем массив, затем объект — потому что следующий ключ `0` числовой.

Зачем это, если есть `?.`: оператор работает только с путём, записанным в коде. `get` и `set` нужны для динамических путей — из схемы формы, конфига, URL. А раз путь приходит снаружи, `set` проверяет ключи: путь `'__proto__.isAdmin'` без проверки записал бы свойство в `Object.prototype` и добавил бы его всем объектам — это [prototype pollution](/content/security-perfomance/supply-chain-and-vulnerabilities). В проверке такой путь отклонён, и прототип остался чистым.

## Красные флаги в ответе

- `JSON.parse(JSON.stringify())` как универсальный клон без оговорок про `Date`, `Map`, функции и циклы.
- `deepClone` без защиты от циклов или с записью в `WeakMap` после рекурсии.
- Упомянули `Set` и `Map`, но не обработали — они превращаются в `{}`.
- `deepEqual`, который не различает массив и объект и считает равными любые две даты.
- `NaN` не равен самому себе в `deepEqual` без оговорки.
- Рекурсивный `flatten` без упоминания глубины стека.
- `set` по пути из внешних данных без проверки `__proto__`.

## Как спрашивают на собеседовании

::question
Чем плох JSON.parse(JSON.stringify()) для клонирования?

#answer
Теряет `undefined`, функции и `Symbol`, превращает `Date` в строку, `Map` и `Set` — в пустые объекты, падает на циклических ссылках. В проверке `Map` стал `{}`, дата — строкой, а цикл вызвал `TypeError`. Годится только для простых данных, пришедших из JSON.

#more
Встроенная альтернатива — `structuredClone`: понимает `Date`, `Map`, `Set` и циклы, но бросает `DataCloneError` на функциях и теряет класс экземпляра. Если нужно сохранить класс или обработать нестандартные типы, пишут свою рекурсию с `Object.create(Object.getPrototypeOf(value))`.
::

::question
Как обработать циклические ссылки в deepClone?

#answer
Через `WeakMap`, который сопоставляет оригинал и уже созданную копию. Записывать в него нужно до рекурсивного обхода: тогда повторная встреча того же объекта вернёт готовую копию вместо бесконечной рекурсии.

#more
Если записать копию после обхода, цикл всё равно уйдёт в рекурсию — до записи дело не дойдёт. В проверке копия объекта со ссылкой на самого себя ссылалась на саму копию, а не на оригинал. Та же таблица сохраняет и общие ссылки: если два поля указывали на один объект, в копии они тоже укажут на одну копию.
::

::question
Почему WeakMap, а не Map?

#answer
`WeakMap` держит ключи слабо: когда исходные объекты больше нигде не нужны, сборщик мусора может их собрать, и вспомогательная таблица не держит память. Ключами могут быть только объекты — ровно то, что нужно для отслеживания уже скопированных структур.

#more
Для одного вызова клонирования разница мала — таблица живёт до конца вызова. Но тот же приём в мемоизации или кешах по объектам важен: `Map` держал бы каждый объект вечно. `WeakMap` нельзя перебрать и у неё нет `size` — это цена слабых ссылок.
::

::question
Что может пойти не так в deepEqual?

#answer
Сравнение только по ключам считает равными разные значения с одинаковыми ключами: массив `[1]` и объект `{0: 1}`, любые две даты (у `Date` нет собственных ключей). Нужно сравнивать прототипы, отдельно разбирать `Date`, `Map`, `Set`, а `NaN` считать равным `NaN`.

#more
В проверке наивная версия ошиблась на массиве против объекта и на датах, исправленная — нет. На интервью ценят уточняющие вопросы: учитывать ли прототип, порядок элементов `Set`, ключи-символы, `+0` и `-0`. Готовые реализации вроде `isEqual` из lodash используют SameValueZero.
::

::question
Как реализовать flatten без рекурсии и зачем?

#answer
Через стек: кладём элементы, достаём `pop`, массив разворачиваем обратно в стек, остальное — в результат, в конце разворачиваем порядок. Защищает от переполнения стека вызовов на очень глубоких структурах.

#more
В проверке рекурсивная версия на 20 000 уровнях вложенности упала с `RangeError`, а стековая вернула результат: стек вызовов ограничен, а массив-стек живёт в куче. Для обычных данных рекурсия читается проще; стек выбирают, когда глубина не контролируется — например, для данных пользователя.
::

::question
Зачем lodash get, если есть оператор ?.?

#answer
`?.` работает со статическими путями, записанными в коде. `get` принимает путь строкой или массивом — для динамических путей из конфига, схемы формы, URL — и возвращает единое значение по умолчанию.

#more
Значение по умолчанию подставляется только вместо `undefined`: в проверке поле со значением `null` вернуло `null`. Парный `set` создаёт недостающие уровни (массив, если следующий ключ числовой) и должен отклонять ключи `__proto__`, `constructor`, `prototype`, иначе путь из внешних данных загрязнит прототип.
::

## Практика

::practice{title="Две разные даты считаются равными"}
Проверка «изменилась ли форма» использует самописный `deepEqual` и не замечает смену даты доставки:

```ts
function deepEqual(a, b) {
  if (a === b) return true;
  if (typeof a !== 'object' || typeof b !== 'object' || !a || !b) return false;
  const ka = Object.keys(a), kb = Object.keys(b);
  return ka.length === kb.length && ka.every((k) => deepEqual(a[k], b[k]));
}
```

#solution
У `Date` нет собственных перечислимых ключей, поэтому `Object.keys` у любых двух дат пустой и сравнение всегда «совпадает». В проверке такая версия считала равными `new Date(1)` и `new Date(2)`, а заодно `[1]` и `{0: 1}`. Сравнивают прототипы и отдельно разбирают особые типы:

```ts
if (Object.getPrototypeOf(a) !== Object.getPrototypeOf(b)) return false;
if (a instanceof Date) return a.getTime() === b.getTime();
if (a instanceof Map) return a.size === b.size && [...a].every(([k, v]) => b.has(k) && deepEqual(v, b.get(k)));
```

С этими строками даты сравниваются по времени, а массив больше не равен объекту. Первую строку заодно меняют на `a === b || (a !== a && b !== b)`, чтобы `NaN` был равен `NaN`.
::

::practice{title="Сохранение пути из формы сломало все объекты"}
Форма-конструктор сохраняет значения по путям, которые приходят из её схемы, через `set(state, path, value)`. После импорта чужой схемы у всех объектов в приложении появилось свойство `isAdmin`.

#solution
В схеме был путь `__proto__.isAdmin`. Наивный `set` прошёл по ключу `__proto__` к `Object.prototype` и записал свойство туда — теперь оно есть у каждого объекта. Пути из внешних данных проверяют:

```ts
const FORBIDDEN = new Set(['__proto__', 'constructor', 'prototype']);
function set(obj, path, value) {
  const keys = toKeys(path);
  if (keys.some((k) => FORBIDDEN.has(k))) throw new Error(`запрещённый ключ в пути: ${keys.join('.')}`);
  // …дальше как обычно
}
```

В проверке путь `'__proto__.isAdmin'` отклонён, и `({}).isAdmin` остался `undefined`. Ещё надёжнее хранить состояние формы в объекте без прототипа (`Object.create(null)`) или в `Map` и валидировать схему перед использованием. Подробнее о классе уязвимости — в [цепочке поставок и уязвимостях](/content/security-perfomance/supply-chain-and-vulnerabilities).
::
