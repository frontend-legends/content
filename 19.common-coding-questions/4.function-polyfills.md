# Полифилы функций и языка

«Реализуй `bind` руками», «что делает `new` под капотом», «напиши `instanceof`» — проверка того, понимаешь ли ты `this`, прототипы и устройство вызова функций. Код короткий, но за ним вся объектная модель JavaScript. Здесь — `call`, `apply`, `bind`, `new`, `instanceof`, `Object.create` и наследование на прототипах. Спрашивают, как `call` работает под капотом, что делает `new` и во что компилируется `class extends`. Глубже — почему наивный `bind` ломается под `new`, почему `new` должен вернуть функцию из конструктора и где полифил `call` расходится с нативным.

::tldr
- **call — вызов функции как метода:** её временно кладут в объект-контекст под ключом-`Symbol`, вызывают и удаляют. `apply` — то же с массивом аргументов. В проверке полифил расходится с нативным на примитивах и замороженных объектах.
- **bind должен работать под `new`:** при вызове через `new` привязанный `this` игнорируется. В проверке наивный полифил вернул пустой объект и записал имя в контекст; исправленный с `new.target` и связанным прототипом повёл себя как нативный.
- **new — четыре шага:** объект с прототипом `Constructor.prototype`, вызов конструктора с этим `this`, возврат объекта — или того объекта (включая функцию), который вернул конструктор.
- **instanceof идёт по цепочке прототипов:** ищет `Constructor.prototype` до `null`. Функции — тоже объекты, их нельзя отсекать проверкой `typeof === 'object'`.
- **class — сахар над прототипами:** свойства наследуются вызовом родителя, методы — через `Object.create(Parent.prototype)`.
::

## call и apply

`call` вызывает функцию с явно заданным `this` и аргументами по одному. Идея полифила: если положить функцию в объект как метод и вызвать `obj.fn()`, `this` внутри станет `obj`.

```ts
Function.prototype.myCall = function (context: any, ...args: unknown[]) {
  context = context == null ? globalThis : Object(context); // примитив — в объект-обёртку
  const key = Symbol('fn');                                   // уникальный ключ — не затрёт свойство
  context[key] = this;                                        // this здесь — вызываемая функция
  try {
    return context[key](...args);                             // вызов как метода
  } finally {
    delete context[key];                                      // убираем за собой даже при ошибке
  }
};
Function.prototype.myApply = function (context: unknown, args: unknown[] = []) {
  return this.myCall(context, ...args);
};
```

В проверке `greet.myCall(anna, 'Привет')` вернул `'Привет, Анна!'`, `myApply` с массивом аргументов — тоже, а у объекта после вызова не осталось временного символьного свойства. `Symbol` нужен, чтобы не перезаписать существующее свойство с тем же именем, а `finally` — чтобы убрать его, даже если функция бросила ошибку.

Где полифил расходится с нативным — и это хорошо назвать самому:

- **примитивы.** Без `Object(context)` присваивание свойства строке падает с `TypeError`. С ним полифил работает, но передаёт обёртку: в проверке `typeof this` внутри был `'object'`, а нативный `call` в strict-режиме передал строку как есть — `'string'`;
- **замороженный объект.** В него нельзя добавить временное свойство, и полифил бросил `TypeError`, а нативный `call` отработал;
- **`null` и `undefined`.** Полифил подставляет `globalThis`, как нестрогий режим; в strict-режиме нативный `call(null)` передаёт `null`.

Полифил моделирует механизм, а не повторяет спецификацию: настоящий `call` задаёт `this` напрямую, без временного свойства. Сам механизм `this` — в [контексте выполнения](/content/javascript/execution-context).

## bind

`bind` возвращает новую функцию с навсегда привязанным `this` и, при желании, частью аргументов — частичное применение. Каверзный момент: если связанную функцию вызвать через `new`, привязанный `this` должен игнорироваться, а `this` — быть новым объектом.

Популярный полифил проверяет это через `this instanceof fn`:

```ts
Function.prototype.myBind = function (context, ...bound) {
  const fn = this;
  return function (...args) {
    const isNew = this instanceof fn;              // не сработает: прототип не связан с fn
    return fn.apply(isNew ? this : context, [...bound, ...args]);
  };
};
```

Проверка не срабатывает: `new` создаёт объект с прототипом возвращённой анонимной функции, а не `fn.prototype`, поэтому `this instanceof fn` ложно. В проверке `new (Person.myBind(ctx, 'Анна'))()` вернул пустой объект, не являющийся `Person`, а имя записалось в привязанный контекст `ctx`. Исправление — отличать вызов через `new` по `new.target` и связать прототип:

```ts
Function.prototype.myBind = function (context: unknown, ...bound: unknown[]) {
  const fn = this;
  function boundFn(this: unknown, ...args: unknown[]) {
    const isNew = new.target !== undefined;          // вызвали через new
    return fn.apply(isNew ? this : context, [...bound, ...args]);
  }
  if (fn.prototype) boundFn.prototype = Object.create(fn.prototype); // экземпляры — instanceof fn
  return boundFn;
};
```

С ним в проверке экземпляр получил имя, оказался `instanceof Person`, а контекст остался нетронутым — так же, как с нативным `bind`. Обычный вызов и частичное применение тоже работают: `greet.myBind(anna, 'Привет')('?')` дал `'Привет, Анна?'`, и привязанный `this` не удалось перебить через `call`.

## new

Оператор `new` делает четыре вещи: создаёт пустой объект, ставит ему прототип `Constructor.prototype`, вызывает конструктор с этим объектом как `this` и возвращает его — если только конструктор не вернул свой объект.

```ts
function myNew(Constructor: Function, ...args: unknown[]) {
  const obj = Object.create(Constructor.prototype);      // 1–2: объект с нужным прототипом
  const result = Constructor.apply(obj, args);           // 3: конструктор с this = obj
  const isObject = (result !== null && typeof result === 'object') || typeof result === 'function';
  return isObject ? result : obj;                        // 4: вернул объект — он, иначе obj
}
```

Тонкость в четвёртом шаге: «объект» включает функции. Частая версия с одной проверкой `typeof result === 'object'` в проверке вернула созданный `obj` там, где конструктор вернул функцию, — а нативный `new` вернул функцию. Примитивный результат (`return 42`) игнорируется: в проверке объект всё равно получил свойство, которое записал конструктор.

## instanceof

`instanceof` проверяет, встречается ли `Constructor.prototype` в цепочке прототипов объекта:

```ts
function myInstanceof(obj: unknown, Constructor: Function): boolean {
  if (obj === null || (typeof obj !== 'object' && typeof obj !== 'function')) return false;
  let proto = Object.getPrototypeOf(obj);
  const target = Constructor.prototype;
  while (proto !== null) {
    if (proto === target) return true;   // нашли в цепочке
    proto = Object.getPrototypeOf(proto);
  }
  return false;                          // дошли до конца цепочки
}
```

Идём вверх по цепочке, пока не упрёмся в `null`. В проверке экземпляр `Person` оказался и `Person`, и `Object` (`Object.prototype` в конце почти любой цепочки), массив — `Array`, а объект без прототипа — не `Object`. Ранняя проверка не должна отсекать функции: с условием `typeof obj !== 'object'` стрелочная функция давала `false` для `Function`, а нативный `instanceof` — `true`. Для примитивов ответ `false`, как и у нативного. Нативный оператор ещё учитывает `Symbol.hasInstance` — его стоит упомянуть. Устройство цепочки прототипов — в [прототипах и классах](/content/javascript/prototypes-and-classes).

## Object.create и наследование

Иногда просят показать, как `Object.create` выражается через `new`:

```ts
function myObjectCreate(proto: object | null) {
  function F() {}
  F.prototype = proto as object;
  return new (F as any)();
}
```

С обычным объектом это работает. С `null` — нет: если `prototype` конструктора не объект, `new` берёт `Object.prototype`. В проверке `myObjectCreate(null)` дал объект с прототипом, а нативный `Object.create(null)` — без. Это настоящая причина, по которой `Object.create` добавили в язык.

И «классическое» наследование до классов — его спрашивают как теорию:

```ts
function Animal(this: any, name: string) { this.name = name; }
Animal.prototype.speak = function () { return `${this.name} издаёт звук`; };

function Dog(this: any, name: string) { Animal.call(this, name); }  // свойства — вызовом родителя
Dog.prototype = Object.create(Animal.prototype);                     // методы — через прототип
Dog.prototype.constructor = Dog;                                     // чиним constructor
Dog.prototype.speak = function () { return `${Animal.prototype.speak.call(this)}: гав`; };
```

В проверке `new Dog('Рекс').speak()` дал `'Рекс издаёт звук: гав'`, экземпляр оказался и `Dog`, и `Animal`, а `constructor` указывал на `Dog`. Тот же результат дали классы `Dog2 extends Animal2` с `super.speak()`, и прототип `Dog2.prototype` указывал на `Animal2.prototype` — `class` строится на той же цепочке.

## Красные флаги в ответе

- Полифил `call` через строковое имя свойства вместо `Symbol` — затирает существующее.
- Временное свойство не удаляется при ошибке — нет `try/finally`.
- `bind` с проверкой `this instanceof fn` без связанного прототипа — под `new` не работает.
- `new`, который не возвращает функцию из конструктора.
- `instanceof`, отсекающий функции проверкой `typeof === 'object'`.
- Наследование без `Dog.prototype.constructor = Dog`.
- «class — это новая объектная модель», а не сахар над прототипами.

## Как спрашивают на собеседовании

::question
Как работает call под капотом?

#answer
Функцию временно кладут в объект-контекст под уникальным ключом (`Symbol`, чтобы не затереть существующее), вызывают как метод — тогда `this` становится этим объектом — и удаляют свойство. `apply` отличается только тем, что аргументы приходят массивом.

#more
Полифил расходится с нативным на краях: примитив приходится оборачивать через `Object()` (нативный в strict-режиме передаёт примитив как есть), в замороженный объект свойство не добавить, а `null` превращается в `globalThis`. Удаляют временное свойство в `finally`, чтобы оно не осталось при ошибке.
::

::question
Что делает оператор new?

#answer
Создаёт пустой объект, ставит ему прототип `Constructor.prototype`, вызывает конструктор с `this`, равным этому объекту, и возвращает его — либо объект, который конструктор вернул явно. Примитивный результат игнорируется.

#more
«Объект» здесь включает функции: если конструктор вернул функцию, `new` возвращает её. В проверке версия с одной проверкой `typeof result === 'object'` этого не делала. Шаги удобно объяснять через `Object.create(Constructor.prototype)` и `Constructor.apply(obj, args)`.
::

::question
В чём сложность bind и new?

#answer
При вызове связанной функции через `new` нативный `bind` игнорирует привязанный `this` и использует новый объект, а экземпляр оказывается `instanceof` исходной функции. Полифил должен это повторить: отличать вызов через `new` и связать прототип связанной функции с `fn.prototype`.

#more
Популярная проверка `this instanceof fn` без связанного прототипа не срабатывает: в проверке такой полифил вернул пустой объект и записал имя в привязанный контекст. Надёжный способ — `new.target !== undefined` и `boundFn.prototype = Object.create(fn.prototype)`.
::

::question
Как работает instanceof?

#answer
Идёт по цепочке прототипов объекта вверх и проверяет, встретится ли `Constructor.prototype`. Дошли до `null` — не встретился. Для примитивов ответ `false`.

#more
Функции — тоже объекты, и `(() => {}) instanceof Function` даёт `true`, поэтому ранняя проверка не должна отсекать их. Нативный оператор сначала смотрит `Symbol.hasInstance` у конструктора — им можно переопределить поведение. Объект из `Object.create(null)` не `instanceof Object`.
::

::question
Во что компилируется class extends?

#answer
В прототипную цепочку: свойства наследуются вызовом родительского конструктора (`Parent.call(this, …)`), методы — через `Object.create(Parent.prototype)`, плюс восстановление `constructor`. `class` — синтаксический сахар над этим механизмом.

#more
В проверке версия на прототипах и версия на классах дали одинаковый результат, а `Object.getPrototypeOf(Dog2.prototype)` оказался `Animal2.prototype`. Отличия у классов всё же есть: их нельзя вызвать без `new`, тело выполняется в strict-режиме, а `super` и приватные поля в ES5 так просто не выразить.
::

::question
Почему Object.create(null) нельзя выразить через new?

#answer
Если `prototype` конструктора не объект, `new` подставляет `Object.prototype`. Поэтому трюк с `F.prototype = proto; new F()` работает для обычного объекта, но для `null` даёт объект с прототипом `Object.prototype`.

#more
В проверке `myObjectCreate(null)` вернул объект с прототипом, а нативный `Object.create(null)` — без. Объекты без прототипа нужны для словарей: у них нет унаследованных свойств вроде `toString` и `__proto__`, поэтому ключи из внешних данных не сталкиваются со служебными.
::

## Практика

::practice{title="Связанный конструктор пишет не туда"}
Фабрика создаёт экземпляры через связанный конструктор, но экземпляры приходят пустыми, а свойства оказываются на объекте конфигурации. Используется самописный `bind`:

```ts
Function.prototype.myBind = function (context, ...bound) {
  const fn = this;
  return function (...args) {
    return fn.apply(this instanceof fn ? this : context, [...bound, ...args]);
  };
};
const User = Person.myBind(config, 'Анна');
const u = new User();
```

#solution
`new User()` создаёт объект с прототипом анонимной функции из `myBind`, а не `Person.prototype`, поэтому `this instanceof fn` ложно и конструктор вызывается с `config` в роли `this`. В проверке экземпляр получился пустым, а имя записалось в контекст. Вызов через `new` определяют по `new.target` и связывают прототип:

```ts
Function.prototype.myBind = function (context, ...bound) {
  const fn = this;
  function boundFn(...args) {
    return fn.apply(new.target !== undefined ? this : context, [...bound, ...args]);
  }
  if (fn.prototype) boundFn.prototype = Object.create(fn.prototype);
  return boundFn;
};
```

Теперь экземпляр получает свойства, оказывается `instanceof Person`, а `config` не меняется — как с нативным `bind`, что в проверке и подтвердилось.
::

::practice{title="Фабрика через new возвращает не то"}
Конструктор возвращает функцию-обработчик, и с оператором `new` это работает. Но собственная реализация `myNew` возвращает пустой объект:

```ts
function myNew(C, ...args) {
  const obj = Object.create(C.prototype);
  const r = C.apply(obj, args);
  return r !== null && typeof r === 'object' ? r : obj;
}
```

#solution
По спецификации `new` возвращает результат конструктора, если это любой объект, а функции — тоже объекты, хотя `typeof` для них даёт `'function'`. В проверке такая версия вернула `obj`, а нативный `new` — функцию. Проверку расширяют:

```ts
function myNew(C, ...args) {
  const obj = Object.create(C.prototype);
  const r = C.apply(obj, args);
  const isObject = (r !== null && typeof r === 'object') || typeof r === 'function';
  return isObject ? r : obj;
}
```

Примитивный результат по-прежнему игнорируется — в проверке конструктор с `return 42` вернул созданный объект со своим свойством. Та же ошибка встречается в `myInstanceof`, где функции отсекают ранней проверкой `typeof obj !== 'object'`.
::
