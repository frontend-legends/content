# Полифилы функций и языка

«Реализуй `bind` руками», «что такое `new` под капотом», «напиши `instanceof`» - это проверка того, **понимаешь ли ты прототипы, `this` и устройство вызова функций**. Код короткий, но за ним стоит вся модель объектов JS.

---

## call

<b class="text-on-semi-light">call</b> <span class="text-gray">- вызывает функцию с явно заданным `this` и аргументами по одному. Под капотом - временно делаем функцию методом нужного объекта.</span>

```ts
Function.prototype.myCall = function (context: any, ...args: any[]) {
  context = context ?? globalThis;     // null/undefined -> глобальный объект
  const key = Symbol("fn");            // уникальный ключ, чтобы не затереть
  context[key] = this;                 // this здесь - вызываемая функция
  const result = context[key](...args);
  delete context[key];                 // убираем за собой
  return result;
};

function greet(this: any, greeting: string) {
  return `${greeting}, ${this.name}`;
}
greet.myCall({ name: "Анна" }, "Привет"); // "Привет, Анна"
```

**Идея:** если положить функцию в объект как метод и вызвать `obj.fn()`, то `this` внутри станет `obj`. `Symbol` нужен, чтобы не перезаписать существующее свойство.

## apply

`apply` - то же, что `call`, но аргументы приходят **массивом**:

```ts
Function.prototype.myApply = function (context: any, args: any[] = []) {
  context = context ?? globalThis;
  const key = Symbol("fn");
  context[key] = this;
  const result = context[key](...args);
  delete context[key];
  return result;
};
```

---

## bind

<b class="text-on-semi-light">bind</b> <span class="text-gray">- возвращает новую функцию с навсегда привязанным `this` и, опционально, частью аргументов (частичное применение). Не вызывает сразу.</span>

```ts
Function.prototype.myBind = function (context: any, ...bound: any[]) {
  const fn = this;
  return function (this: any, ...args: any[]) {
    // если вызвали через new - this уже новый объект, его и используем
    const isNew = this instanceof fn;
    return fn.apply(isNew ? this : context, [...bound, ...args]);
  };
};
```

> ⚠️ Каверзный момент: «настоящий» `bind` сохраняет работу через `new`. Если связанную функцию вызвать как конструктор, `this` должен быть новым объектом, а не привязанным контекстом. На мидл+ это любят спрашивать.

---

## new

<b class="text-on-semi-light">Оператор new</b> <span class="text-gray">- делает 4 вещи: создаёт пустой объект, привязывает его прототип к `Constructor.prototype`, вызывает конструктор с этим объектом как `this`, и возвращает его (если конструктор не вернул свой объект).</span>

```ts
function myNew(Constructor: Function, ...args: any[]) {
  // 1. новый объект с правильным прототипом
  const obj = Object.create(Constructor.prototype);
  // 2. вызываем конструктор с this = obj
  const result = Constructor.apply(obj, args);
  // 3. если конструктор вернул объект - возвращаем его, иначе наш obj
  return result !== null && typeof result === "object" ? result : obj;
}

function Person(this: any, name: string) {
  this.name = name;
}
const p = myNew(Person, "Анна"); // { name: "Анна" }, p instanceof Person === true
```

Эти 4 шага - один из самых частых теоретических вопросов про `new`, и просьба написать их кодом закрепляет понимание.

## instanceof

<b class="text-on-semi-light">instanceof</b> <span class="text-gray">- проверяет, есть ли `Constructor.prototype` где-нибудь в цепочке прототипов объекта.</span>

```ts
function myInstanceof(obj: any, Constructor: Function): boolean {
  if (obj === null || typeof obj !== "object") return false;

  let proto = Object.getPrototypeOf(obj);
  const target = Constructor.prototype;

  while (proto !== null) {
    if (proto === target) return true; // нашли в цепочке
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}
```

Идём по цепочке прототипов вверх, пока не упрёмся в `null`. Это прямая иллюстрация прототипного наследования.

## Object.create и наследование

Иногда просят показать, как `Object.create` лежит в основе прототипов:

```ts
function myObjectCreate(proto: object | null) {
  function F() {}
  F.prototype = proto as object;
  return new F();
}
```

И «классическое» наследование до классов (всё ещё спрашивают как теорию):

```ts
function Animal(this: any, name: string) {
  this.name = name;
}
Animal.prototype.speak = function () {
  return `${this.name} издаёт звук`;
};

function Dog(this: any, name: string) {
  Animal.call(this, name);           // наследуем свойства
}
Dog.prototype = Object.create(Animal.prototype); // наследуем методы
Dog.prototype.constructor = Dog;     // чиним constructor
```

> Современно это пишется через `class extends`, но интервьюер часто просит «то же самое на прототипах» - проверить, что ты понимаешь, во что компилируется `class`.

## Вопросы на собеседовании

<b class="text-on-semi-light">Как работает call под капотом?</b>
<span class="text-gray">Кладём функцию во временное свойство объекта-контекста (через `Symbol`, чтобы не затереть существующее), вызываем как метод - тогда `this` становится этим объектом, - и удаляем свойство. apply отличается только тем, что аргументы приходят массивом.</span>

<b class="text-on-semi-light">Что делает оператор new?</b>
<span class="text-gray">Создаёт пустой объект, ставит ему прототип `Constructor.prototype`, вызывает конструктор с `this`, равным этому объекту, и возвращает его - либо объект, который конструктор вернул явно.</span>

<b class="text-on-semi-light">В чём сложность с bind и new?</b>
<span class="text-gray">Нативный `bind` устроен так, что при вызове связанной функции через `new` привязанный `this` игнорируется и используется новый объект. В полифиле это проверяют через `this instanceof fn`.</span>

<b class="text-on-semi-light">Как работает instanceof?</b>
<span class="text-gray">Идёт по цепочке прототипов объекта вверх и проверяет, встретится ли там `Constructor.prototype`. Дошли до `null` - значит нет. Это и есть прототипное наследование «руками».</span>

<b class="text-on-semi-light">Во что компилируется class extends?</b>
<span class="text-gray">В прототипную цепочку: свойства наследуются через вызов родительского конструктора (`Parent.call(this)`), методы - через `Object.create(Parent.prototype)`. `class` - синтаксический сахар над этим.</span>
