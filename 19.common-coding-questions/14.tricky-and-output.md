# Задачи «что выведет»

«Что выведет этот код?» — отдельный жанр. Ничего писать не нужно: нужно точно предсказать поведение и объяснить механизм — порядок event loop, замыкания в циклах, `this`, подъём объявлений, приведение типов, ссылки и значения. Сами механизмы подробно разобраны в главе о JavaScript; здесь — как они выглядят в задачах и где ответ зависит от режима и окружения. Все примеры запущены — в Node в обычном и строгом режиме и в браузере. Глубже — почему оторванный метод в строгом режиме бросает ошибку, почему в браузере он возвращает пустую строку и почему `{} + []` бывает и `0`, и `"[object Object]"`.

::tldr
- **Порядок event loop:** синхронный код, затем все микрозадачи, затем одна макрозадача и снова все микрозадачи. В проверке сложный пример с `then`, `queueMicrotask`, `await` и таймерами дал `1, 6, 8, 3, 5, 7, 2, 4`.
- **`await` делит функцию:** код до `await` синхронный, после — микрозадача. Поэтому `start, A, end, B`.
- **`var` в цикле — одна переменная, `let` — новая на каждый шаг:** `3, 3, 3` против `0, 1, 2`. Чинят `let` или IIFE.
- **`this` определяется вызовом и режимом:** оторванный метод в модуле или strict-режиме бросает `TypeError`, в обычном скрипте Node даёт `undefined`, а в браузере — пустую строку, потому что у `window` есть `name`.
- **Приведение — по правилам операторов:** `+` со строкой склеивает, остальная арифметика приводит к числу, `==` приводит, `===` нет. `{} + []` — `0`, только когда `{}` разобран как блок.
::

## Порядок event loop

Самая частая задача. Правило: сначала весь синхронный код, затем все микрозадачи (`then`, `queueMicrotask`, продолжения после `await`), затем одна макрозадача (`setTimeout`), после неё снова все микрозадачи. Устройство очередей — в [event loop](/content/javascript/event-loop).

```js
console.log('1');
setTimeout(() => console.log('2'), 0);          // макрозадача
Promise.resolve().then(() => console.log('3')); // микрозадача
console.log('4');
// 1, 4, 3, 2
```

`1` и `4` — синхронные, `3` — микрозадача, она выполняется до любой макрозадачи, `2` — последним. С `async` и `await`:

```js
async function f() {
  console.log('A');
  await null;          // всё после await — микрозадача
  console.log('B');
}
console.log('start');
f();
console.log('end');
// start, A, end, B
```

До `await` тело функции выполняется синхронно — `A` печатается сразу при вызове. Остаток ставится в очередь микрозадач и выполняется, когда синхронный код закончился.

### Посложнее

На интервью любят смешать всё сразу:

```js
console.log('1');
setTimeout(() => console.log('2'));
Promise.resolve().then(() => { console.log('3'); setTimeout(() => console.log('4')); });
queueMicrotask(() => console.log('5'));
(async () => { console.log('6'); await null; console.log('7'); })();
console.log('8');
// 1, 6, 8, 3, 5, 7, 2, 4
```

Разбор по шагам. Синхронно: `1`, тело асинхронной функции до `await` — `6`, затем `8`. Микрозадачи в порядке постановки: `then` печатает `3` и ставит новый таймер, `queueMicrotask` — `5`, продолжение после `await` — `7`. Макрозадачи по порядку: первый таймер — `2`, таймер из `then` — `4`. В проверке Node выдал ровно эту последовательность. Ещё одна деталь: микрозадачи, появившиеся внутри таймера, выполняются до следующего таймера — в проверке `t1, m1, t2`.

## Замыкания в цикле

```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);
// 3, 3, 3 — var: одна переменная на весь цикл, к моменту таймеров i === 3

for (let i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);
// 0, 1, 2 — let: новая привязка на каждую итерацию
```

У `var` функциональная область видимости: переменная одна, и все три замыкания видят её финальное значение. `let` блочная, и цикл создаёт новую привязку `i` на каждой итерации — каждое замыкание захватывает свою. Если надо «починить» `var` без `let`, значение передают в :term[IIFE]{def="функция, которая вызывается сразу после объявления: (function () { … })()"} аргументом:

```js
for (var i = 0; i < 3; i++) ((j) => setTimeout(() => console.log(j), 0))(i); // 0, 1, 2
```

В проверке все три варианта дали заявленный вывод. Механизм замыканий — в [замыканиях](/content/javascript/closures).

## this и контекст вызова

Здесь ответ зависит от режима и окружения — и это лучший момент, чтобы показать понимание:

```js
const obj = {
  name: 'obj',
  regular() { return this.name; },
  arrow: () => this?.name,
};
obj.regular();   // 'obj' — this = объект слева от точки
obj.arrow();     // undefined — стрелка берёт this из места объявления
const fn = obj.regular;
fn();            // зависит от режима
```

`fn()` — вызов без объекта, и `this` внутри — `undefined` в строгом режиме или глобальный объект в обычном. В проверке это дало три разных ответа:

| Где | `fn()` |
| --- | --- |
| модуль ES или `'use strict'` | `TypeError` — чтение `name` у `undefined` |
| обычный скрипт в Node | `undefined` — у `globalThis` нет `name` |
| обычный скрипт в браузере | `''` — у `window` есть свойство `name`, пустая строка |

То же с методом, переданным колбэком. `setTimeout` вызывает функцию со своим `this`: в браузере это `window`, и в проверке метод вернул пустую строку, а в Node — объект таймера, и метод вернул `undefined`. Сохранить контекст можно стрелкой или `bind`:

```js
setTimeout(() => obj.regular(), 0);       // 'obj' — вызов через объект
setTimeout(obj.regular.bind(obj), 0);     // 'obj' — привязали
```

Правило: у обычной функции `this` определяется в момент вызова, у стрелочной — лексически, из места объявления, и его не изменить. Подробнее — в [контексте выполнения](/content/javascript/execution-context).

## Подъём и TDZ

```js
console.log(a);   // undefined — var поднят со значением undefined
var a = 1;

console.log(b);   // ReferenceError — let в «мёртвой зоне» до объявления
let b = 2;

foo();            // 'ok' — объявление функции поднято целиком
function foo() { console.log('ok'); }

bar();            // TypeError: bar is not a function — var поднят, но там ещё undefined
var bar = () => {};
```

Объявления поднимаются в начало своей области: `var` — со значением `undefined`, `let` и `const` — без инициализации, и обращение к ним до строки объявления бросает `ReferenceError` (это и есть временная мёртвая зона, TDZ), объявление функции — целиком. Тонкость, которую любят спрашивать: TDZ действует, даже если снаружи есть переменная с тем же именем.

```js
let x = 'внешняя';
{
  console.log(x); // ReferenceError, а не 'внешняя'
  let x = 'внутренняя';
}
```

Внутренний `let x` поднят в начало блока и затеняет внешний уже с первой строки, но до объявления недоступен. В проверке все случаи дали заявленный результат.

## Приведение типов

```js
[] + []            // '' — оба массива приводятся к пустой строке
[] + {}            // '[object Object]'
1 + '2'            // '12' — со строкой + склеивает
'3' * 2            // 6 — остальная арифметика приводит к числу
true + 1           // 2 — true → 1
[1, 2, 3] + ''     // '1,2,3'
null == undefined  // true — особое правило
null === undefined // false
NaN === NaN        // false — NaN не равен ничему, включая себя
Object.is(NaN, NaN) // true
0.1 + 0.2          // 0.30000000000000004 — двоичная дробь
0 == ''            // true
'' == '0'          // false
0 == '0'           // true — нетранзитивность ==
```

Отдельный случай — `{} + []`. Как отдельная инструкция `{}` разбирается как пустой блок, остаётся `+[]`, то есть `0`; в выражении `({} + [])` это объект плюс массив — `'[object Object]'`. В проверке оба варианта дали именно это. Последние три строки — почему `==` не используют: он нетранзитивен, `0` равен и `''`, и `'0'`, а они друг другу — нет. Правила приведения — в [типах и переменных](/content/javascript/types-and-variables).

## Ссылка и значение

```js
let a = { x: 1 };
let b = a;
b.x = 2;
console.log(a.x);                // 2 — a и b указывают на один объект

function change(obj) { obj.x = 10; }       // мутирует объект
function reassign(obj) { obj = { x: 99 }; } // меняет только локальный параметр
const o = { x: 1 };
change(o);   console.log(o.x);   // 10
reassign(o); console.log(o.x);   // 10
```

JavaScript передаёт аргументы по значению, но значение объекта — ссылка. Поэтому изменение поля видно снаружи, а присваивание параметру нового объекта — нет. В проверке вывод — `2`, `10`, `10`.

## Красные флаги в ответе

- «then и setTimeout(0) — как получится»: порядок строго определён.
- Код до `await` считают асинхронным.
- «`var` и `let` в цикле одинаковы» или объяснение без слова «привязка».
- Один ответ про `this` без оговорки о строгом режиме и окружении.
- «`let` не поднимается» вместо объяснения TDZ.
- Приведение типов наизусть без правил операторов.
- «Объекты передаются по ссылке» без различия мутации и переприсваивания.

## Как спрашивают на собеседовании

::question
В каком порядке выполнятся console.log, setTimeout и Promise.then?

#answer
Сначала весь синхронный код, затем все микрозадачи (`then`, `queueMicrotask`, продолжения после `await`), затем одна макрозадача (`setTimeout`), и после неё снова опустошается очередь микрозадач. Поэтому `then` всегда раньше `setTimeout(0)`.

#more
В проверке сложный пример с `then`, `queueMicrotask`, `await` и таймерами дал `1, 6, 8, 3, 5, 7, 2, 4`, а микрозадача, поставленная внутри таймера, выполнилась раньше следующего таймера. Микрозадача, бесконечно порождающая новые, не даст выполниться ни одной макрозадаче — и отрисовке тоже.
::

::question
Почему цикл с var и setTimeout печатает одно число три раза?

#answer
У `var` функциональная область видимости: переменная одна на весь цикл. К моменту срабатывания таймеров цикл закончился, и все замыкания видят финальное значение. `let` создаёт новую привязку на каждой итерации, поэтому печатает `0, 1, 2`.

#more
Без `let` значение фиксируют аргументом IIFE или третьим аргументом `setTimeout(fn, 0, i)`. В проверке и `let`, и IIFE дали `0, 1, 2`. Та же проблема возникает с обработчиками событий, навешанными в цикле на `var`.
::

::question
Как определяется this в обычной и стрелочной функции?

#answer
У обычной функции — в момент вызова: объект слева от точки, значение из `call`, `apply` или `bind`, а при «голом» вызове — `undefined` в строгом режиме и глобальный объект в обычном. У стрелочной — лексически, из места объявления, и переопределить его нельзя.

#more
Поэтому ответ на «что выведет оторванный метод» зависит от режима: в проверке модуль бросил `TypeError`, обычный скрипт в Node дал `undefined`, а браузер — пустую строку, потому что у `window` есть свойство `name`. Колбэк `setTimeout` в браузере вызывается с `this = window`, в Node — с объектом таймера.
::

::question
Что такое TDZ?

#answer
Временная мёртвая зона — промежуток от начала блока до строки объявления `let` или `const`. Переменная уже поднята и известна, но обращение к ней бросает `ReferenceError`. `var` в том же месте был бы доступен как `undefined`.

#more
TDZ затеняет внешнюю переменную с тем же именем уже с первой строки блока: в проверке `console.log(x)` перед внутренним `let x` бросил ошибку, а не вывел внешнее значение. Объявление функции поднимается целиком, а функция-выражение в `var` — только как `undefined`, отсюда «bar is not a function».
::

::question
Чем == отличается от ===?

#answer
`==` сравнивает с приведением типов: `0 == '0'` и `null == undefined` — `true`. `===` сравнивает без приведения и требует одинакового типа. На практике почти всегда используют `===`.

#more
`==` нетранзитивен: в проверке `0 == ''` и `0 == '0'` дали `true`, а `'' == '0'` — `false`. Единственный распространённый осознанный случай `==` — `x == null`, который проверяет сразу `null` и `undefined`. Для `NaN` и `-0` есть `Object.is`.
::

::question
Почему `{} + []` иногда `0`, а иногда `"[object Object]"`?

#answer
Всё зависит от того, как разобран `{}`. В начале инструкции это пустой блок, и остаётся унарный плюс `+[]`, то есть `0`. В выражении — например, в скобках или справа от присваивания — это пустой объект, и `{} + []` склеивает строки, давая `'[object Object]'`.

#more
В проверке `eval('{} + []')` дал `0`, а `({} + [])` — `'[object Object]'`. Поэтому консоль браузера и код в файле иногда «показывают разное»: консоль может обернуть ввод в выражение. Это вопрос о грамматике, а не о приведении типов.
::

## Практика

::practice{title="Обработчики в цикле выводят одно и то же"}
Кнопки создаются в цикле, но при клике каждая выводит одно и то же число — количество кнопок:

```js
for (var i = 0; i < buttons.length; i++) {
  buttons[i].addEventListener('click', () => console.log(i));
}
```

#solution
Все обработчики замыкают одну переменную `i` с функциональной областью `var`, и к моменту клика цикл давно закончился. В проверке на таймерах такой код вывел `3, 3, 3`. Достаточно `let` — у каждой итерации своя привязка:

```js
for (let i = 0; i < buttons.length; i++) {
  buttons[i].addEventListener('click', () => console.log(i));
}
```

В проверке это дало `0, 1, 2`. Если менять `var` нельзя — фиксируют значение аргументом IIFE. Ещё чище не зависеть от индекса вовсе: `buttons.forEach((btn, i) => …)` или одно делегированное событие с `data-index` на кнопке.
::

::practice{title="Метод в колбэке ведёт себя по-разному"}
Код работает в старом скрипте, но после перевода на модули начал падать с `TypeError: Cannot read properties of undefined`:

```js
const counter = { count: 0, inc() { this.count++; return this.count; } };
const inc = counter.inc;
inc();
```

#solution
`inc()` — вызов без объекта, и `this` внутри зависит от режима. В обычном скрипте это глобальный объект, и код «работал», молча создавая глобальное `count`. Модули всегда в строгом режиме, там `this` — `undefined`, и чтение свойства падает. В проверке оторванный метод в модуле бросил `TypeError`, а в обычном скрипте — нет. Контекст сохраняют явно:

```js
const inc = counter.inc.bind(counter); // привязали навсегда
inc();                                 // 1
// или вызывают через объект: () => counter.inc()
```

Падение здесь — благо: строгий режим превратил тихую ошибку (запись в глобальный объект) в явную. В браузере тот же код в обычном скрипте вёл бы себя ещё неочевиднее: у `window` есть свои свойства вроде `name`, и метод мог бы прочитать чужое значение.
::
