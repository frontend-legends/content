# Output-задачи и трюки

«Что выведет этот код?» - отдельный жанр. Проверяют не реализацию, а **глубокое понимание языка**: event loop, замыкания, `this`, всплытие, приведение типов. Здесь не нужно ничего писать - нужно точно предсказать поведение и объяснить почему.

---

## Порядок event loop

Самый частый output-вопрос. Нужно знать: **синхронный код → все микротаски → одна макротаска → снова микротаски**.

```ts
console.log("1");
setTimeout(() => console.log("2"), 0);     // макротаска
Promise.resolve().then(() => console.log("3")); // микротаска
console.log("4");

// Вывод: 1, 4, 3, 2
```

**Разбор:**

1. `1` и `4` - синхронные, идут сразу.
2. `3` - микротаска, выполняется после синхронного кода, но **до** любых макротасок.
3. `2` - макротаска (`setTimeout`), последней.

Усложнённый вариант с `async/await`:

```ts
async function f() {
  console.log("A");
  await null;                    // всё после await - микротаска
  console.log("B");
}
console.log("start");
f();
console.log("end");
// Вывод: start, A, end, B
```

> `await` ставит остаток функции в микротаск-очередь. До `await` код синхронный, после - асинхронный. Это ключ к большинству таких задач. Подробнее - [как выполняется код](/content/computer-science/running-the-code).

## Замыкания в цикле

Классика с `var` vs `let`:

```ts
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// Вывод: 3, 3, 3 - var одна переменная на всё, к моменту таймера i === 3

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// Вывод: 0, 1, 2 - let создаёт новую привязку на каждую итерацию
```

<b class="text-on-semi-light">var</b> <span class="text-gray">- функциональная область видимости, одна переменная `i` на весь цикл. К моменту таймеров она уже 3.</span>
<b class="text-on-semi-light">let</b> <span class="text-gray">- блочная область, новая привязка `i` на каждую итерацию, каждое замыкание захватывает свою.</span>

> Как починить `var`? IIFE с передачей `i` аргументом, или просто `let`. Это любят спрашивать как «почини этот код».

## this и контекст вызова

```ts
const obj = {
  name: "obj",
  regular() { return this.name; },
  arrow: () => this?.name,
};

obj.regular();              // "obj" - this = объект вызова
obj.arrow();                // undefined - стрелка взяла this из объявления (модуль)

const fn = obj.regular;
fn();                       // undefined (strict) - this потерян при «отрыве» метода
```

**Правило `this`:** определяется **в момент вызова** (кто слева от точки), кроме стрелочных функций - те берут `this` лексически, из места объявления.

```ts
// классическая ловушка - метод в колбэке теряет this
setTimeout(obj.regular, 0);          // undefined
setTimeout(() => obj.regular(), 0);  // "obj" - вызвали через объект
setTimeout(obj.regular.bind(obj), 0);// "obj" - привязали
```

## Hoisting и TDZ

```ts
console.log(a);   // undefined - var поднят, но не инициализирован
var a = 1;

console.log(b);   // ReferenceError - let в "временной мёртвой зоне" (TDZ)
let b = 2;

foo();            // "ok" - объявление функции поднято целиком
function foo() { console.log("ok"); }

bar();            // TypeError: bar is not a function - var с функцией-выражением
var bar = () => {};
```

<b class="text-on-semi-light">Hoisting</b> <span class="text-gray">- объявления поднимаются вверх области. `var` поднимается со значением `undefined`; `let`/`const` поднимаются, но недоступны до строки объявления (TDZ); function declaration поднимается целиком.</span>

## Приведение типов

```ts
[] + []        // "" - оба приводятся к строке (пустые)
[] + {}        // "[object Object]"
{} + []        // 0 в некоторых контекстах ({} - блок, +[] -> 0)
1 + "2"        // "12" - число к строке (конкатенация)
"3" * 2        // 6 - строка к числу (умножение)
true + 1       // 2 - true -> 1
null == undefined   // true - спец-правило
null === undefined  // false - разные типы
NaN === NaN    // false - NaN не равен ничему, включая себя
0.1 + 0.2      // 0.30000000000000004 - float
```

> ⚠️ Эти примеры скорее «знать про подвох», чем писать так в коде. Главное - объяснить *механику*: `+` со строкой конкатенирует, остальные арифметические операторы приводят к числу; `==` запускает приведение типов, `===` нет.

## Reference vs value

```ts
let a = { x: 1 };
let b = a;
b.x = 2;
console.log(a.x);    // 2 - объекты по ссылке, a и b - один объект

function change(obj: { x: number }) { obj.x = 10; }      // мутирует
function reassign(obj: { x: number }) { obj = { x: 99 }; } // не влияет на внешний
const o = { x: 1 };
change(o);   console.log(o.x); // 10
reassign(o); console.log(o.x); // 10 - переприсваивание параметра локально
```

Объекты передаются по «ссылке на значение»: мутация поля видна снаружи, а переприсваивание самого параметра - нет.

## Вопросы на собеседовании

<b class="text-on-semi-light">В каком порядке выполнятся console.log, setTimeout и Promise.then?</b>
<span class="text-gray">Сначала весь синхронный код, потом все микротаски (`Promise.then`, `queueMicrotask`), затем макротаски (`setTimeout`). После каждой макротаски снова опустошается очередь микротасок. Поэтому then всегда раньше setTimeout(0).</span>

<b class="text-on-semi-light">Почему цикл с var и setTimeout печатает одно число три раза?</b>
<span class="text-gray">`var` имеет функциональную область - переменная одна на весь цикл. К моменту срабатывания таймеров цикл закончился и `i` равно финальному значению. `let` создаёт новую привязку на каждую итерацию, поэтому печатает 0, 1, 2.</span>

<b class="text-on-semi-light">Как определяется this в обычной и стрелочной функции?</b>
<span class="text-gray">У обычной - в момент вызова: объект слева от точки, либо undefined/global при «голом» вызове, либо заданный через call/apply/bind. У стрелочной - лексически, из места объявления; её this нельзя переопределить.</span>

<b class="text-on-semi-light">Что такое TDZ?</b>
<span class="text-gray">Temporal Dead Zone - промежуток от начала блока до строки объявления `let`/`const`, где переменная уже «поднята», но обращение к ней бросает ReferenceError. В отличие от `var`, который доступен как `undefined` до инициализации.</span>

<b class="text-on-semi-light">Чем == отличается от ===?</b>
<span class="text-gray">`==` сравнивает с приведением типов (`0 == "0"` → true, `null == undefined` → true). `===` сравнивает без приведения, требует одинакового типа. На практике почти всегда используют `===`, чтобы избежать сюрпризов приведения.</span>
