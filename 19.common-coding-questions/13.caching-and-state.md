# Кэши и маленькие системы

Промежуточный уровень между утилитой и system-design: **LRU-кэш, rate limiter, мемоизированный селектор, мини-стор**. Просят, когда хотят проверить выбор структур данных и понимание производительности на маленькой, но «системной» задаче.

---

## LRU Cache

<b class="text-on-semi-light">LRU (Least Recently Used)</b> <span class="text-gray">- кэш фиксированного размера, который при переполнении вытесняет **давно не используемый** элемент. Любимая задача, потому что требует структуру с O(1) на чтение, запись и вытеснение.</span>

Трюк - использовать `Map`, который **сохраняет порядок вставки**. «Освежаем» элемент, удаляя и вставляя заново (он уходит в конец):

```ts
class LRUCache<K, V> {
  private cache = new Map<K, V>();
  constructor(private capacity: number) {}

  get(key: K): V | undefined {
    if (!this.cache.has(key)) return undefined;
    const value = this.cache.get(key)!;
    this.cache.delete(key);          // удаляем и
    this.cache.set(key, value);      // вставляем заново -> уходит в конец (свежий)
    return value;
  }

  put(key: K, value: V): void {
    if (this.cache.has(key)) this.cache.delete(key); // обновим позицию
    this.cache.set(key, value);

    if (this.cache.size > this.capacity) {
      // первый ключ итерации = самый старый
      const oldest = this.cache.keys().next().value;
      this.cache.delete(oldest);
    }
  }
}
```

**Почему это работает:**

1. **`Map` хранит порядок** - первый ключ итерации самый старый, последний - свежий.
2. **`get` освежает** - delete + set переносит элемент в конец.
3. **Вытеснение** - при переполнении удаляем `keys().next().value` (самый старый).
4. **Сложность** - всё O(1).

> На сеньорных собесах могут запросить классическую реализацию на **двусвязном списке + хэш-мапе** (как в LeetCode 146). `Map`-версия - тот же O(1), но короче; стоит назвать оба варианта.

## Rate limiter

<b class="text-on-semi-light">Rate limiter</b> <span class="text-gray">- ограничивает число действий за окно времени (например, «не больше 5 запросов в секунду»). Алгоритмы: фиксированное окно, скользящее окно, token bucket.</span>

```ts
function rateLimiter(limit: number, windowMs: number) {
  let timestamps: number[] = [];

  return function allow(): boolean {
    const now = Date.now();
    // выкидываем метки старше окна (скользящее окно)
    timestamps = timestamps.filter((t) => now - t < windowMs);

    if (timestamps.length < limit) {
      timestamps.push(now);
      return true;            // разрешаем
    }
    return false;             // лимит исчерпан
  };
}

const allow = rateLimiter(3, 1000); // 3 раза в секунду
allow(); allow(); allow();          // true, true, true
allow();                            // false
```

> Token bucket (ведро токенов) - более «плавный» вариант: токены капают с постоянной скоростью, каждое действие тратит токен. Хорошо упомянуть как альтернативу со сглаживанием всплесков.

## Мемоизированный селектор

<b class="text-on-semi-light">Селектор</b> <span class="text-gray">- функция, выводящая данные из состояния. Мемоизированный (как `reselect`) пересчитывает только при изменении входов - оптимизация ре-рендеров.</span>

```ts
function createSelector<S, A, R>(
  inputFn: (state: S) => A,
  resultFn: (input: A) => R
) {
  let lastInput: A;
  let lastResult: R;
  let hasRun = false;

  return (state: S): R => {
    const input = inputFn(state);
    if (!hasRun || input !== lastInput) {  // вход не изменился по ссылке -> отдаём кэш
      lastResult = resultFn(input);
      lastInput = input;
      hasRun = true;
    }
    return lastResult;
  };
}
```

Это ядро `reselect`: пока ссылка на вход та же, отдаём прошлый результат - и зависящий компонент не перерисовывается.

## Мини-стор с подпиской

Связка с [pub/sub](/content/common-coding-questions/events-and-pubsub) - state-контейнер для React-подобной подписки:

```ts
function createStore<S>(initial: S) {
  let state = initial;
  const listeners = new Set<() => void>();

  return {
    getState: () => state,
    setState(partial: Partial<S>) {
      state = { ...state, ...partial };   // иммутабельное обновление
      listeners.forEach((l) => l());
    },
    subscribe(listener: () => void) {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
  };
}
```

Это, по сути, ядро Zustand. Поверх такого стора `useSyncExternalStore` даёт интеграцию с React в несколько строк - хороший ответ на «как сделать свой стейт-менеджер».

## Вопросы на собеседовании

<b class="text-on-semi-light">Как сделать LRU-кэш с O(1) операциями?</b>
<span class="text-gray">Через `Map`, который хранит порядок вставки: `get` удаляет и заново вставляет элемент (освежает), при переполнении удаляем первый ключ итерации - самый старый. Классическая альтернатива - двусвязный список + хэш-мапа. Обе дают O(1).</span>

<b class="text-on-semi-light">Почему именно Map, а не объект для LRU?</b>
<span class="text-gray">`Map` гарантирует порядок вставки и даёт удобную итерацию ключей от старых к новым плюс O(1) delete/set. У обычного объекта порядок ключей формально не гарантирован для всех типов ключей, и нет такого же удобного API.</span>

<b class="text-on-semi-light">Какие есть алгоритмы rate limiting?</b>
<span class="text-gray">Фиксированное окно (счётчик на интервал, прост, но всплески на границе), скользящее окно (метки времени за последнее окно, точнее), token bucket (токены капают с постоянной скоростью, сглаживает всплески). Выбор - по требованиям к точности и нагрузке.</span>

<b class="text-on-semi-light">Как работает мемоизированный селектор (reselect)?</b>
<span class="text-gray">Запоминает последний вход и результат. Если вход не изменился по ссылке - возвращает закэшированный результат, не пересчитывая. Это требует иммутабельных обновлений состояния, чтобы сравнение по ссылке было осмысленным.</span>

<b class="text-on-semi-light">Как устроен минимальный стейт-менеджер?</b>
<span class="text-gray">State + множество подписчиков: `setState` иммутабельно обновляет состояние и уведомляет подписчиков, `subscribe` возвращает отписку. Это ядро Zustand/Redux; интеграция с React - через `useSyncExternalStore`.</span>
