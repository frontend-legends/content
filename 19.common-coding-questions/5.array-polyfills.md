# Полифилы методов массива

«Реализуй `map`, `filter`, `reduce` без встроенных», «напиши `flat`», «сделай `groupBy`» — проверяют понимание колбэков, аккумуляторов и краевых случаев: `thisArg`, разреженных массивов, начального значения `reduce`. Спрашивают, какие аргументы получает колбэк, как обработать необязательный `initial` и как дедуплицировать объекты. Глубже — почему полифил `map` должен зафиксировать длину до обхода, почему `reduce` без начального значения не может брать `this[0]` и почему `groupBy` на обычном объекте падает на ключе `__proto__`.

::tldr
- **Колбэк получает три аргумента:** `(value, index, array)`, а у `reduce` — ещё аккумулятор первым. `thisArg` передают через `callback.call(thisArg, …)`; со стрелочными колбэками он бесполезен.
- **Длину фиксируют до обхода:** в проверке полифил, читающий `this.length` на каждом шаге, посетил 12 элементов вместо 3, потому что колбэк добавлял новые.
- **Дыры пропускают, но длину сохраняют:** `map` возвращает массив той же длины с теми же дырами, `flat` дыры удаляет. Проверка `i in this`, а не `for…of`.
- **У reduce главная ловушка — начальное значение:** наличие проверяют по `arguments.length`, а первый аккумулятор — первый существующий элемент. В проверке версия с `this[0]` дала `NaN` на `[, 1, 2]` вместо 3.
- **groupBy — на объекте без прототипа:** с обычным `{}` ключ `__proto__` вызвал `TypeError`. Для этого есть и встроенные `Object.groupBy` и `Map.groupBy`.
::

## map

`map` создаёт новый массив, применяя колбэк к каждому элементу, и не меняет исходный. Полифил, который проходит сверку с нативным на краевых случаях:

```ts
Array.prototype.myMap = function (cb, thisArg) {
  const len = this.length;          // длину фиксируем до обхода
  const result = new Array(len);    // та же длина и те же дыры
  for (let i = 0; i < len; i++) {
    if (i in this) result[i] = cb.call(thisArg, this[i], i, this); // дыры пропускаем
  }
  return result;
};
```

На что смотрят:

1. **три аргумента колбэка** — `value, index, array`, а не только значение. В проверке колбэк `forEach` получил `[2, 1, true]` для второго элемента — значение, индекс и сам массив;
2. **`thisArg`** — через `cb.call(thisArg, …)`. В проверке с обычной функцией `this.k` взялся из переданного объекта, а стрелочный колбэк вернул свой внешний `this` и `thisArg` проигнорировал;
3. **новый массив** — `this` не мутируется;
4. **разреженные массивы** — проверка `i in this` пропускает пустые ячейки.

Две тонкости отличают правильный полифил от почти правильного. Первая — длина результата. Версия с `const result = []` и присваиванием по индексу теряет дыру в конце: в проверке для `[1, , ]` (длина 2) она вернула массив длины 1, а нативный `map` — длины 2 с той же дырой. Вторая — длину читают один раз. Нативный `map` не посещает элементы, добавленные во время обхода; версия с `i < this.length` в условии цикла в проверке, где колбэк добавлял элемент на каждом шаге, сделала 12 вызовов вместо 3 — а без ограничения ушла бы в бесконечный цикл.

## filter и forEach

Устроены так же: фиксированная длина, проверка `i in this`, вызов через `call`:

```ts
Array.prototype.myFilter = function (cb, thisArg) {
  const len = this.length;
  const result = [];
  for (let i = 0; i < len; i++) {
    if (i in this && cb.call(thisArg, this[i], i, this)) result.push(this[i]);
  }
  return result;
};

Array.prototype.myForEach = function (cb, thisArg) {
  const len = this.length;
  for (let i = 0; i < len; i++) if (i in this) cb.call(thisArg, this[i], i, this);
};
```

`filter` возвращает плотный массив — дыры в нём не сохраняются, а `forEach` ничего не возвращает: в проверке результат был `undefined`. Отсюда частый вопрос: `forEach` нельзя прервать `break` и нельзя дождаться в нём `await` — для этого берут обычный цикл.

## reduce

`reduce` сворачивает массив в одно значение, прокидывая аккумулятор. Самый каверзный из-за необязательного начального значения:

```ts
Array.prototype.myReduce = function (cb, initial) {
  const len = this.length;
  let i = 0;
  let acc;
  if (arguments.length >= 2) acc = initial;   // наличие initial — по числу аргументов
  else {
    while (i < len && !(i in this)) i++;      // первый существующий элемент, а не this[0]
    if (i >= len) throw new TypeError('Reduce of empty array with no initial value');
    acc = this[i++];
  }
  for (; i < len; i++) if (i in this) acc = cb(acc, this[i], i, this);
  return acc;
};
```

Три ловушки:

- **проверять `arguments.length`, а не истинность `initial`.** Иначе `reduce(fn, 0)` и `reduce(fn, '')` сломаются. В проверке даже явный `undefined` считается начальным значением: `[1, 2].myReduce((a, b) => a + b, undefined)` дал `NaN`, как и нативный;
- **первый аккумулятор — первый существующий элемент.** Версия с `acc = this[0]` в проверке на `[, 1, 2]` дала `NaN` (сложение с `undefined`), а нативный `reduce` — 3;
- **пустой массив без начального значения бросает `TypeError`**, как и массив из одних дыр. А массив из одного элемента без начального значения возвращает этот элемент, не вызывая колбэк вовсе.

Частый дополнительный вопрос — выразить `map` через `reduce`:

```ts
const map = <T, U>(arr: T[], fn: (x: T) => U) => arr.reduce<U[]>((acc, x) => [...acc, fn(x)], []);
```

Это показывает, что `reduce` — универсальный примитив. Но спред на каждом шаге копирует весь аккумулятор, и обход становится O(n²): в проверке на 20 000 элементах этот вариант оказался в десятки раз медленнее версии с `acc.push(fn(x))`. В реальном коде так не пишут.

## flat

Полифил `flat` с глубиной — та же рекурсия, что в [глубоких операциях](/content/common-coding-questions/deep-operations), но с поведением встроенного метода:

```ts
Array.prototype.myFlat = function (depth = 1) {
  const result = [];
  for (let i = 0; i < this.length; i++) {
    if (!(i in this)) continue;       // flat удаляет дыры
    const item = this[i];
    if (Array.isArray(item) && depth > 0) result.push(...item.myFlat(depth - 1));
    else result.push(item);
  }
  return result;
};
```

Ловушка — обход через `for…of`: он выдаёт для дыр `undefined`, и в проверке такая версия превратила `[1, , 3]` в `[1, undefined, 3]`, тогда как нативный `flat` дал `[1, 3]`. С проверкой `i in this` результаты совпали и для глубины 2, и для `Infinity`.

## groupBy

`groupBy` группирует элементы по ключу, который возвращает функция. Частая «продуктовая» задача:

```ts
function groupBy<T>(arr: T[], keyFn: (item: T) => PropertyKey) {
  const groups: Record<PropertyKey, T[]> = Object.create(null); // объект без прототипа
  for (const item of arr) (groups[keyFn(item)] ??= []).push(item);
  return groups;
}
groupBy([6.1, 4.2, 6.3], Math.floor); // { 4: [4.2], 6: [6.1, 6.3] }
```

`??=` создаёт массив только при первой встрече ключа. Почему `Object.create(null)`, а не `{}`: у обычного объекта уже есть унаследованные ключи. В проверке группировка на `{}` с ключом `'__proto__'` упала с `TypeError`: `acc.__proto__` — это `Object.prototype`, он не `null`, поэтому `??=` его не заменил, а у прототипа нет `push`. На объекте без прототипа `'__proto__'` — обычный ключ.

С ES2024 есть встроенные `Object.groupBy` и `Map.groupBy`. В проверке `Object.groupBy` вернул как раз объект без прототипа, а `Map.groupBy` — `Map`, где ключи могут быть любого типа, не только строками. На интервью стоит назвать их, а потом написать полифил.

## unique

Для примитивов достаточно `Set`, для объектов нужен ключ:

```ts
const unique = <T>(arr: T[]): T[] => [...new Set(arr)];

function uniqueBy<T>(arr: T[], keyFn: (item: T) => unknown): T[] {
  const map = new Map<unknown, T>();
  for (const item of arr) {
    const key = keyFn(item);
    if (!map.has(key)) map.set(key, item); // первый на ключ
  }
  return [...map.values()];
}
```

В проверке `Set` дедуплицировал и `NaN` (он сравнивает по SameValueZero), но оставил разными `1` и `'1'`, а два одинаковых по содержимому объекта не схлопнул — объекты он сравнивает по ссылке. `uniqueBy` по `id` оставил первый элемент на каждый ключ. Почему `Set`, а не `indexOf` в `filter`, — в [введении](/content/common-coding-questions/introduction): разница O(n) против O(n²).

## Красные флаги в ответе

- Колбэк получает только значение, без индекса и массива.
- `thisArg` не поддержан или вызов не через `call`.
- `this.length` в условии цикла — обход элементов, добавленных во время обхода.
- `reduce` проверяет `if (initial)` вместо `arguments.length`.
- `acc = this[0]` без учёта дыр и без `TypeError` для пустого массива.
- `flat` через `for…of` — дыры превращаются в `undefined`.
- `groupBy` на обычном `{}` без мысли о ключах вроде `__proto__`.

## Как спрашивают на собеседовании

::question
Какие аргументы получает колбэк map, filter и reduce?

#answer
`map`, `filter`, `forEach` передают `(value, index, array)`. `reduce` передаёт `(accumulator, value, index, array)`. Многие забывают про индекс и массив — интервьюер это проверяет.

#more
Отсюда классическая ловушка `['1', '2', '3'].map(parseInt)`: индекс уходит в `parseInt` вторым аргументом как основание системы счисления, и получается `[1, NaN, NaN]`. Вторым аргументом `map`, `filter`, `forEach` принимают `thisArg`, а у `reduce` второй аргумент — начальное значение.
::

::question
Как в reduce правильно обработать необязательное начальное значение?

#answer
Проверять `arguments.length >= 2`, а не истинность `initial`, иначе `reduce(fn, 0)` сломается. Если начального значения нет, аккумулятором становится первый существующий элемент и обход идёт со следующего; пустой массив без начального значения бросает `TypeError`.

#more
В проверке версия с `this[0]` дала `NaN` на `[, 1, 2]`, а нативный `reduce` — 3, потому что берёт первый существующий элемент. Массив из одного элемента без начального значения возвращает его, не вызывая колбэк. Явный `undefined` — тоже начальное значение.
::

::question
Зачем полифилу map фиксировать длину до обхода?

#answer
Нативный `map` вычисляет длину один раз и не посещает элементы, добавленные во время обхода. Если читать `this.length` в условии цикла, колбэк, добавляющий элементы, растянет обход или сделает его бесконечным.

#more
В проверке колбэк добавлял элемент на каждом шаге, и полифил с `i < this.length` сделал 12 вызовов вместо 3. Заодно результат создают как `new Array(len)`, чтобы сохранить длину и дыры: версия с `[]` потеряла дыру в конце массива.
::

::question
Что такое thisArg и зачем он?

#answer
Второй аргумент `map`, `filter`, `forEach` — значение `this` внутри колбэка. Реализуется через `cb.call(thisArg, …)`. Со стрелочными колбэками он бесполезен: стрелка берёт `this` из места объявления.

#more
В проверке обычная функция-колбэк прочитала `this.k` из переданного объекта, а стрелка вернула свой внешний `this`, проигнорировав `thisArg`. В современном коде `thisArg` почти не используют — проще замкнуть нужное значение в стрелке.
::

::question
Как сделать map через reduce и почему так не пишут?

#answer
`arr.reduce((acc, x) => [...acc, fn(x)], [])`. Это показывает, что `reduce` — универсальный примитив, через который выражаются `map` и `filter`. Но спред копирует весь аккумулятор на каждом шаге, и обход становится O(n²).

#more
В проверке на 20 000 элементах вариант со спредом был в десятки раз медленнее варианта с `acc.push(fn(x)); return acc`. Мутировать собственный аккумулятор внутри `reduce` безопасно — он создан в этом же вызове и снаружи не виден.
::

::question
Как дедуплицировать массив объектов?

#answer
`Set` не подойдёт — он сравнивает объекты по ссылке. Нужен `Map` по вычисленному ключу (например, `id`), с первым встреченным элементом на ключ. Для примитивов достаточно `[...new Set(arr)]`.

#more
В проверке `Set` не схлопнул два одинаковых по содержимому объекта, но дедуплицировал `NaN` — он сравнивает по SameValueZero. Уточняющие вопросы: оставлять первый или последний элемент на ключ, сохранять ли порядок, что считать ключом, если `id` нет.
::

## Практика

::practice{title="reduce без начального значения даёт NaN"}
Сумма по массиву, где часть ячеек ещё не заполнена, иногда даёт `NaN`. Используется самописный `reduce`:

```ts
Array.prototype.myReduce = function (cb, initial) {
  let acc = initial === undefined ? this[0] : initial;
  for (let i = initial === undefined ? 1 : 0; i < this.length; i++) {
    if (i in this) acc = cb(acc, this[i], i, this);
  }
  return acc;
};
[, 1, 2].myReduce((a, b) => a + b); // NaN
```

#solution
Две ошибки. Если первая ячейка — дыра, `this[0]` даёт `undefined`, и `undefined + 1` — `NaN`; нативный `reduce` берёт первый существующий элемент. И наличие начального значения проверяется через `=== undefined`, а не по числу аргументов. Исправленная версия:

```ts
Array.prototype.myReduce = function (cb, initial) {
  const len = this.length;
  let i = 0, acc;
  if (arguments.length >= 2) acc = initial;
  else {
    while (i < len && !(i in this)) i++;
    if (i >= len) throw new TypeError('Reduce of empty array with no initial value');
    acc = this[i++];
  }
  for (; i < len; i++) if (i in this) acc = cb(acc, this[i], i, this);
  return acc;
};
```

В проверке она дала 3 на `[, 1, 2]`, как нативный `reduce`, бросила `TypeError` для пустого массива и для массива из одних дыр и вернула единственный элемент, не вызывая колбэк.
::

::practice{title="Группировка тегов падает на одном из тегов"}
Посты группируют по тегу, и на одном импорте всё падает с `acc[key].push is not a function`. Тег, на котором падает, — `__proto__`:

```ts
const byTag = posts.reduce((acc, p) => { (acc[p.tag] ??= []).push(p); return acc; }, {});
```

#solution
У обычного объекта есть унаследованные ключи: `acc['__proto__']` возвращает `Object.prototype`, он не `null` и не `undefined`, поэтому `??=` его не заменяет, а `push` у прототипа нет. В проверке такая группировка упала с `TypeError`. Группируют в объект без прототипа или в `Map`:

```ts
const byTag = Object.groupBy(posts, (p) => p.tag);   // ES2024, объект без прототипа
// или сам:
const groups = Object.create(null);
for (const p of posts) (groups[p.tag] ??= []).push(p);
```

В проверке группировка с `Object.create(null)` положила пост под ключ `'__proto__'` как под любой другой, а `Object.groupBy` вернул объект без прототипа. `Map.groupBy` ещё и позволяет ключи не-строки. Ключи из внешних данных на обычном объекте — тот же класс проблем, что [prototype pollution](/content/security-perfomance/supply-chain-and-vulnerabilities).
::
