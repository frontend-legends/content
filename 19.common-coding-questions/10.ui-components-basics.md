# UI-компоненты: база

Machine-coding раунд — собрать рабочий компонент за ограниченное время. Начинают с простых компонентов-автоматов: табы, аккордеон, модалка, рейтинг, секундомер, поле для кода из SMS. Проверяют минимальное состояние, доступность и краевые случаи. Примеры на React, но идея переносится на любой фреймворк. Спрашивают, с чего начинать, как хранить состояние аккордеона и что входит в правильную модалку. Глубже — почему аккордеон «одна секция» часто не закрывается, почему `setTime(time + 1)` застревает на единице и почему ячейка кода не даёт перезаписать цифру.

::tldr
- **Сначала поведение и состояние, потом стили:** минимальное состояние без дублирования, краевые случаи, доступность. Интервьюер ценит работающее поведение выше красоты.
- **Табы по APG:** роли `tablist`, `tab`, `tabpanel`, связи через `aria-controls`, в Tab-порядке только активный таб, стрелки по кругу, Home и End.
- **Состояние решают по прошлому значению:** в проверке аккордеон, который сначала создаёт пустой набор, а потом смотрит в него, не закрывал открытую секцию.
- **Модалка — чеклист:** портал, Escape, клик по фону, блокировка прокрутки, `role="dialog"`, фокус внутрь и возврат фокуса. Нативный `<dialog>` с `showModal()` даёт большую часть этого сам.
- **Интервал — функциональное обновление и очистка:** в проверке `setTime(time + 1)` после трёх секунд показал 1, а `setTime((t) => t + 1)` — 3.
::

---

## Что оценивают

1. **состояние** — минимальное и без дублирования, один источник истины;
2. **краевые случаи** — пустые данные, границы (первый и последний таб), быстрые клики, повторный клик;
3. **доступность** — роли, `aria-*`, клавиатура. Это сильный плюс: образцы для каждого виджета — в [ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/patterns/), подробно о ролях — в [доступности](/content/html/accessibility);
4. **чистота** — разбиение на компоненты, понятные имена.

Главная ошибка — начать со стилей. Сначала рабочая логика и состояние, оформление — в последнюю очередь.

## Табы

Первая классическая задача: состояние и рендер по состоянию. Один индекс активного таба — источник истины, а доступность по образцу :term[APG]{def="ARIA Authoring Practices Guide: образцы доступных виджетов и их поведения с клавиатуры"} — то, что отличает сильный ответ:

```tsx
function Tabs({ tabs }: { tabs: { label: string; content: ReactNode }[] }) {
  const [active, setActive] = useState(0);
  const refs = useRef<(HTMLButtonElement | null)[]>([]);
  const id = useId();
  if (tabs.length === 0) return null;                    // нечего показывать
  const current = Math.min(active, tabs.length - 1);     // табы могли уменьшиться
  const focusTab = (i: number) => { setActive(i); refs.current[i]?.focus(); };
  const onKeyDown = (e: React.KeyboardEvent) => {
    const last = tabs.length - 1;
    const next = { ArrowRight: current === last ? 0 : current + 1, ArrowLeft: current === 0 ? last : current - 1, Home: 0, End: last }[e.key];
    if (next !== undefined) { e.preventDefault(); focusTab(next); }
  };
  return (
    <div>
      <div role="tablist" onKeyDown={onKeyDown}>
        {tabs.map((tab, i) => (
          <button
            key={tab.label}
            ref={(el) => { refs.current[i] = el; }}
            role="tab"
            id={`${id}-tab-${i}`}
            aria-selected={current === i}
            aria-controls={`${id}-panel`}
            tabIndex={current === i ? 0 : -1}             // в Tab-порядке только активный
            onClick={() => setActive(i)}
          >
            {tab.label}
          </button>
        ))}
      </div>
      <div role="tabpanel" id={`${id}-panel`} aria-labelledby={`${id}-tab-${current}`}>{tabs[current].content}</div>
    </div>
  );
}
```

В проверке на настоящем React клик переключил панель и `aria-selected`; только активный таб имел `tabIndex` 0 (это называют roving tabindex: Tab переходит к группе один раз, а внутри — стрелки); стрелка вправо с последнего таба вернула фокус на первый, `End` — на последний; панель ссылалась на свой таб через `aria-labelledby`. Пустой список табов отрисовал ничего, а не упал на `tabs[0].content`.

## Аккордеон

Первый уточняющий вопрос: открыта одна секция или несколько? Это меняет поведение. `Set` индексов покрывает оба режима, но есть ловушка:

```tsx
const toggle = (i: number) => setOpen((prev) => {
  const next = single ? new Set<number>() : new Set(prev);
  next.has(i) ? next.delete(i) : next.add(i);   // в режиме single next пуст — проверка всегда ложна
  return next;
});
```

В режиме «одна секция» `next` создаётся пустым, и `next.has(i)` всегда ложно — открытую секцию повторным кликом не закрыть. В проверке после двух кликов по «Доставке» она осталась открытой. Решают по прошлому состоянию:

```tsx
const toggle = (i: number) => setOpen((prev) => {
  const wasOpen = prev.has(i);
  const next = single ? new Set<number>() : new Set(prev);
  if (!wasOpen) next.add(i); else next.delete(i);
  return next;
});
```

С исправлением в проверке открытие второй секции закрыло первую, повторный клик закрыл открытую, а в режиме «несколько» открылись обе. Кнопка-заголовок держит `aria-expanded` — так скринридер узнаёт, раскрыта ли секция.

## Модалка

Здесь проверяют целый набор деталей: портал, закрытие по Escape и клику на фон, блокировку прокрутки, роли и фокус.

```tsx
function Modal({ isOpen, onClose, children }: ModalProps) {
  const dialogRef = useRef<HTMLDivElement>(null);
  useEffect(() => {
    if (!isOpen) return;
    const opener = document.activeElement as HTMLElement | null;  // кто открыл
    const onKey = (e: KeyboardEvent) => { if (e.key === 'Escape') onClose(); };
    document.addEventListener('keydown', onKey);
    const prevOverflow = document.body.style.overflow;
    document.body.style.overflow = 'hidden';                       // блокируем прокрутку фона
    dialogRef.current?.focus();                                    // фокус внутрь
    return () => {
      document.removeEventListener('keydown', onKey);
      document.body.style.overflow = prevOverflow;                 // восстанавливаем прежнее
      opener?.focus();                                             // возврат фокуса
    };
  }, [isOpen, onClose]);
  if (!isOpen) return null;
  return createPortal(
    <div className="overlay" onClick={onClose}>
      <div role="dialog" aria-modal="true" aria-label="Подтверждение" tabIndex={-1}
           ref={dialogRef} onClick={(e) => e.stopPropagation()}>
        {children}
      </div>
    </div>,
    document.body,
  );
}
```

В проверке при открытии фокус ушёл в диалог, а прокрутка фона заблокировалась; клик по содержимому модалку не закрыл (его останавливает `stopPropagation`); Escape закрыл, прокрутка вернулась, а фокус — на кнопку «Удалить», которая открывала модалку; клик по фону тоже закрыл. Прежнее значение `overflow` сохраняют и восстанавливают, а не обнуляют: две модалки подряд иначе сломают друг другу состояние. Как устроен портал — в [реализации фреймворков](/content/common-coding-questions/framework-implementation).

Полноценный фокус-трап (Tab не уходит на фон) руками пишут долго. Современный ответ — нативный `<dialog>` с `showModal()`. В проверке в Chromium он сам перевёл фокус на первую кнопку внутри, сделал фон неактивным — точка на кнопке фона попала в слой диалога, а Tab не увёл фокус на фон, — закрылся по Escape и вернул фокус кнопке, которая его открыла. Хороший ответ — назвать оба пути.

## Рейтинг

Небольшой компонент с нюансом — превью при наведении поверх выбранного значения:

```tsx
function StarRating({ count = 5, value, onChange }: RatingProps) {
  const [hover, setHover] = useState(0);
  return (
    <div role="group" aria-label="Оценка" onMouseLeave={() => setHover(0)}>
      {Array.from({ length: count }, (_, i) => i + 1).map((star) => (
        <button key={star} type="button" aria-label={`${star} из ${count}`}
                aria-pressed={star <= value}
                data-lit={star <= (hover || value)}         // превью при наведении, иначе выбранное
                onMouseEnter={() => setHover(star)} onClick={() => onChange(star)}>★</button>
      ))}
    </div>
  );
}
```

Ключевой приём — `hover || value`: при наведении показываем превью, без него — реальное значение. В проверке при значении 2 и наведении на четвёртую звезду подсветились четыре, после ухода курсора — снова две, а клик по пятой выставил 5. Звёзды — кнопки, а не `<span>`: на них можно перейти с клавиатуры, и у каждой есть понятное имя «3 из 5».

## Секундомер

Проверяет работу с `setInterval` и очисткой в `useEffect` — любимая тема про утечки и замыкания:

```tsx
function Stopwatch() {
  const [time, setTime] = useState(0);
  const [running, setRunning] = useState(false);
  useEffect(() => {
    if (!running) return;
    const id = setInterval(() => setTime((t) => t + 1), 1000);  // функциональное обновление
    return () => clearInterval(id);                              // обязательная очистка
  }, [running]);
  return (
    <div>
      <span>{time}</span>
      <button onClick={() => setRunning((r) => !r)}>{running ? 'Пауза' : 'Старт'}</button>
      <button onClick={() => { setRunning(false); setTime(0); }}>Сброс</button>
    </div>
  );
}
```

Частая ошибка — `setTime(time + 1)`. Эффект запускается при `running`, и колбэк интервала замыкает `time` того рендера — 0. Каждую секунду он ставит `0 + 1`, и счётчик застревает. В проверке на фейковых таймерах после трёх секунд версия с `time + 1` показала 1, а с функциональным обновлением — 3. На паузе интервал очищается: после двух секунд и паузы в пять секунд в проверке осталось 2. Для точного секундомера хранят время старта и считают `Date.now() - start`: интервалы в браузере не гарантируют ровно 1000 мс между срабатываниями.

## Код из SMS

Поле из ячеек: автопереход к следующей, Backspace к предыдущей, вставка кода целиком:

```tsx
function OTPInput({ length = 6, onComplete }: OTPProps) {
  const [values, setValues] = useState<string[]>(Array(length).fill(''));
  const refs = useRef<(HTMLInputElement | null)[]>([]);
  const update = (next: string[], focusIndex: number) => {
    setValues(next);
    refs.current[Math.min(focusIndex, length - 1)]?.focus();
    if (next.every(Boolean)) onComplete(next.join(''));
  };
  const handleChange = (i: number, raw: string) => {
    const digit = raw.replace(/\D/g, '').slice(-1);       // последняя введённая цифра
    if (!digit) return;
    const next = [...values]; next[i] = digit;
    update(next, i + 1);                                   // автопереход
  };
  const handlePaste = (i: number, e: React.ClipboardEvent) => {
    const digits = e.clipboardData.getData('text').replace(/\D/g, '').slice(0, length - i).split('');
    if (!digits.length) return;
    e.preventDefault();
    const next = [...values];
    digits.forEach((d, k) => { next[i + k] = d; });       // вставка целиком
    update(next, i + digits.length);
  };
  const handleKeyDown = (i: number, e: React.KeyboardEvent) => {
    if (e.key !== 'Backspace') return;
    e.preventDefault();
    const next = [...values];
    if (next[i]) { next[i] = ''; setValues(next); }
    else if (i > 0) { next[i - 1] = ''; setValues(next); refs.current[i - 1]?.focus(); }
  };
  return (
    <div role="group" aria-label="Код из SMS">
      {values.map((val, i) => (
        <input key={i} ref={(el) => { refs.current[i] = el; }} aria-label={`Цифра ${i + 1}`}
               inputMode="numeric" autoComplete={i === 0 ? 'one-time-code' : 'off'} value={val}
               onChange={(e) => handleChange(i, e.target.value)}
               onPaste={(e) => handlePaste(i, e)} onKeyDown={(e) => handleKeyDown(i, e)} />
      ))}
    </div>
  );
}
```

Частая версия с проверкой `/^\d?$/` и `maxLength={1}` не даёт перезаписать цифру: в заполненную ячейку приходит значение из двух символов, проверка его отвергает. Берут последнюю цифру. В проверке набор «9» в ячейке с «1» заменил цифру, буква проигнорировалась, вставка «72-58» во вторую ячейку разложилась по ячейкам до конца и вызвала `onComplete('9725')`, а два Backspace стёрли последнюю цифру и, на пустой ячейке, предыдущую с переходом к ней. `autoComplete="one-time-code"` и `inputMode="numeric"` подсказывают телефону подставить код из SMS и показать цифровую клавиатуру.

## Красные флаги в ответе

- Начать со стилей, а не с состояния и поведения.
- Табы без ролей и клавиатуры, падение на пустом списке.
- Аккордеон, решающий по только что созданному пустому набору.
- Модалка без возврата фокуса, с обнулением `overflow` вместо восстановления.
- `setTime(time + 1)` в интервале и эффект без очистки.
- Рейтинг из `<span>` — недоступен с клавиатуры.
- Поле кода, которое не даёт перезаписать цифру и не принимает вставку.

## Как спрашивают на собеседовании

::question
С чего начинать machine-coding задачу?

#answer
С уточнения требований и краевых случаев, затем минимальное состояние и рабочая логика, и только потом стили. Решения по структуре состояния проговаривают вслух: «индекс активного таба — единственный источник истины».

#more
Удобный порядок: разметка и роли, состояние и переходы, клавиатура, краевые случаи, оформление. Если время кончается, работающий компонент без стилей лучше красивого, который не закрывается или падает на пустых данных.
::

::question
Как хранить состояние аккордеона?

#answer
Зависит от режима, поэтому его уточняют. Для «одна секция» хватает индекса или `null`, для «несколько» — `Set` индексов. `Set` покрывает оба режима, если в режиме «одна» каждый раз начинать с пустого набора.

#more
Ловушка — решать, открыть или закрыть, по новому пустому набору: тогда открытая секция повторным кликом не закрывается, что в проверке и случилось. Решают по прошлому состоянию: `const wasOpen = prev.has(i)`. Кнопка-заголовок держит `aria-expanded`.
::

::question
Что входит в правильную модалку?

#answer
Портал, закрытие по Escape и клику на фон, `stopPropagation` на содержимом, блокировка прокрутки с восстановлением прежнего значения, `role="dialog"` и `aria-modal`, фокус внутрь при открытии, фокус-трап и возврат фокуса при закрытии, очистка слушателей.

#more
В проверке все пункты, кроме полного фокус-трапа, сработали на React-версии. Нативный `<dialog>` с `showModal()` в проверке сам перевёл фокус внутрь, сделал фон неактивным, закрылся по Escape и вернул фокус — современный ответ называет его как альтернативу.
::

::question
Почему setTime(time + 1) в интервале — баг?

#answer
Колбэк интервала замыкает `time` того рендера, в котором запустился эффект, и не видит обновлений. Каждый тик ставит одно и то же значение, и счётчик застревает. Нужно функциональное обновление `setTime((t) => t + 1)`, которое получает актуальное значение.

#more
В проверке за три секунды версия с `time + 1` показала 1, а функциональная — 3. Добавить `time` в зависимости тоже «чинит», но пересоздаёт интервал каждую секунду. Линтер `react-hooks/exhaustive-deps` предупреждает о пропущенной зависимости — это подсказка, что замыкание устареет.
::

::question
Зачем cleanup в useEffect с интервалом или слушателем?

#answer
Чтобы не копить интервалы и подписки при повторных запусках эффекта и при размонтировании. Иначе утечка памяти, двойные срабатывания и обновления уже удалённого компонента. Функция, возвращённая из эффекта, освобождает ресурс перед следующим запуском и при размонтировании.

#more
В проверке на паузе интервал очищался, и время не шло дальше. В StrictMode в разработке React специально вызывает эффект, cleanup и эффект снова — если без cleanup таймеров становится два, это видно сразу. Модалка в проверке через cleanup и снимала слушатель Escape, и возвращала фокус.
::

::question
Как сделать табы доступными?

#answer
По образцу APG: `role="tablist"`, у кнопок `role="tab"`, `aria-selected` и `aria-controls`, у панели `role="tabpanel"` и `aria-labelledby`. В Tab-порядке только активный таб (`tabIndex` 0, остальные −1), а между табами переходят стрелками, `Home` и `End`.

#more
Такой приём называют roving tabindex: пользователь клавиатуры один раз заходит в группу табов, а не проходит через каждый. В проверке стрелка с последнего таба вернула фокус на первый. Идентификаторы для связей дают через `useId`, чтобы два экземпляра табов на странице не конфликтовали.
::

## Практика

::practice{title="Секция аккордеона не закрывается повторным кликом"}
Аккордеон в режиме «одна секция» открывает секции, но повторный клик по открытой ничего не делает:

```tsx
const toggle = (i) => setOpen((prev) => {
  const next = single ? new Set() : new Set(prev);
  next.has(i) ? next.delete(i) : next.add(i);
  return next;
});
```

#solution
В режиме «одна секция» `next` — новый пустой набор, поэтому `next.has(i)` всегда ложно и секция всегда добавляется. В проверке после двух кликов секция осталась открытой. Решение должно опираться на прошлое состояние:

```tsx
const toggle = (i) => setOpen((prev) => {
  const wasOpen = prev.has(i);
  const next = single ? new Set() : new Set(prev);
  if (!wasOpen) next.add(i); else next.delete(i);
  return next;
});
```

С исправлением в проверке повторный клик закрыл секцию, открытие другой закрыло первую, а режим «несколько» продолжил работать. Общий урок: решение «что поменять» принимают по `prev`, а не по объекту, который сами только что создали.
::

::practice{title="Секундомер показывает 1 и дальше не идёт"}
Секундомер стартует, показывает 1 и больше не меняется:

```tsx
useEffect(() => {
  if (!running) return;
  const id = setInterval(() => setTime(time + 1), 1000);
  return () => clearInterval(id);
}, [running]);
```

#solution
Эффект запускается один раз при `running`, и колбэк интервала замыкает `time` из того рендера — 0. Каждую секунду он ставит `0 + 1`, то есть 1. В проверке после трёх секунд на экране была 1. Функциональное обновление получает актуальное значение:

```tsx
const id = setInterval(() => setTime((t) => t + 1), 1000);
```

С ним в проверке после трёх секунд было 3, а на паузе время не шло — интервал очищался. Для точности лучше хранить момент старта и показывать `Math.floor((Date.now() - start) / 1000)`: так счётчик не отстаёт, даже если браузер замедлил таймеры в фоновой вкладке.
