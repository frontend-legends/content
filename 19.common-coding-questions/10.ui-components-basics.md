# UI-компоненты: база

Machine-coding раунд - собрать рабочий компонент. Начинаем с **простых, преимущественно state-машин**: табы, аккордеон, модалка, рейтинг, таймер, OTP-инпут. Проверяют чистоту состояния, доступность (a11y) и обработку краевых случаев. Примеры на React, но идея переносится на любой фреймворк.

---

## Что оценивают в machine-coding

1. **Состояние** - минимальное и без дублирования (один источник истины).
2. **Краевые случаи** - пустые данные, границы (первый/последний таб), быстрые клики.
3. **Доступность** - роли, `aria-*`, навигация с клавиатуры. Это сильный плюс.
4. **Чистота** - разбиение на компоненты, понятные имена, отсутствие магии.

> ⚠️ Главная ошибка - сразу лезть в стили. Сначала рабочая логика и состояние, стили в последнюю очередь. Интервьюер ценит работающее поведение выше красоты.

## Tabs (табы)

Классическая первая задача - проверка «состояние + рендер по состоянию».

```tsx
function Tabs({ tabs }: { tabs: { label: string; content: React.ReactNode }[] }) {
  const [active, setActive] = useState(0);

  return (
    <div>
      <div role="tablist">
        {tabs.map((tab, i) => (
          <button
            key={i}
            role="tab"
            aria-selected={active === i}        // a11y: какой таб активен
            onClick={() => setActive(i)}
          >
            {tab.label}
          </button>
        ))}
      </div>
      <div role="tabpanel">{tabs[active].content}</div>
    </div>
  );
}
```

Один `active` индекс - источник истины. Плюс за `role`/`aria-selected` и за навигацию стрелками (частый «а сделай ещё клавиатуру»).

## Accordion (аккордеон)

Уточняющий вопрос: **одна секция открыта или несколько**? Это меняет тип состояния.

```tsx
function Accordion({ items, single = true }: { items: Item[]; single?: boolean }) {
  // single -> число, multiple -> Set индексов
  const [open, setOpen] = useState<Set<number>>(new Set());

  const toggle = (i: number) => {
    setOpen((prev) => {
      const next = single ? new Set<number>() : new Set(prev);
      next.has(i) ? next.delete(i) : next.add(i);
      return next;
    });
  };

  return (
    <div>
      {items.map((item, i) => (
        <div key={i}>
          <button aria-expanded={open.has(i)} onClick={() => toggle(i)}>
            {item.title}
          </button>
          {open.has(i) && <div>{item.content}</div>}
        </div>
      ))}
    </div>
  );
}
```

`Set` элегантно покрывает оба режима - в `single` просто создаём пустой набор перед добавлением.

## Modal (модальное окно)

Тут проверяют **порталы, фокус-трап, закрытие по Escape и клику на оверлей** - целый набор a11y-нюансов.

```tsx
function Modal({ isOpen, onClose, children }: ModalProps) {
  useEffect(() => {
    if (!isOpen) return;
    const onKey = (e: KeyboardEvent) => e.key === "Escape" && onClose();
    document.addEventListener("keydown", onKey);
    document.body.style.overflow = "hidden";       // блокируем скролл фона
    return () => {
      document.removeEventListener("keydown", onKey);
      document.body.style.overflow = "";           // чистим за собой
    };
  }, [isOpen, onClose]);

  if (!isOpen) return null;

  // портал - рендерим вне дерева, поверх всего
  return createPortal(
    <div className="overlay" onClick={onClose} role="presentation">
      <div role="dialog" aria-modal="true" onClick={(e) => e.stopPropagation()}>
        {children}
      </div>
    </div>,
    document.body
  );
}
```

**Чеклист модалки** (его и хотят услышать): портал, закрытие по Escape/оверлею, `stopPropagation` на контенте, блокировка скролла, `role="dialog"` + `aria-modal`, фокус-трап и возврат фокуса. Реализацию портала разбираем в [фреймворках](/content/common-coding-questions/framework-implementation).

## Star rating (рейтинг)

Маленькая, но с приятным нюансом - **hover-превью поверх выбранного значения**.

```tsx
function StarRating({ count = 5, value, onChange }: RatingProps) {
  const [hover, setHover] = useState(0);

  return (
    <div onMouseLeave={() => setHover(0)}>
      {Array.from({ length: count }, (_, i) => i + 1).map((star) => (
        <span
          key={star}
          onMouseEnter={() => setHover(star)}
          onClick={() => onChange(star)}
          // подсвечиваем по hover, если он есть, иначе по выбранному
          style={{ color: star <= (hover || value) ? "gold" : "gray" }}
        >
          ★
        </span>
      ))}
    </div>
  );
}
```

`hover || value` - ключевой приём: при наведении показываем превью, без него - реальное значение.

## Stopwatch / Timer (секундомер)

Проверяет работу с `setInterval` и **очисткой в `useEffect`** (любимая тема про утечки).

```tsx
function Stopwatch() {
  const [time, setTime] = useState(0);
  const [running, setRunning] = useState(false);

  useEffect(() => {
    if (!running) return;
    const id = setInterval(() => setTime((t) => t + 1), 1000);
    return () => clearInterval(id);     // обязательная очистка
  }, [running]);

  return (
    <div>
      <span>{time}s</span>
      <button onClick={() => setRunning((r) => !r)}>{running ? "Pause" : "Start"}</button>
      <button onClick={() => { setRunning(false); setTime(0); }}>Reset</button>
    </div>
  );
}
```

> ⚠️ Частая ошибка - `setTime(time + 1)` вместо `setTime(t => t + 1)`. Без функционального апдейта замыкание захватит устаревший `time`, и счётчик «застрянет». Это любимый каверзный момент.

## OTP input (код из ячеек)

Поле для ввода кода: автопереход к следующей ячейке, backspace к предыдущей, вставка кода целиком.

```tsx
function OTPInput({ length = 6, onComplete }: OTPProps) {
  const [values, setValues] = useState<string[]>(Array(length).fill(""));
  const refs = useRef<(HTMLInputElement | null)[]>([]);

  const handleChange = (i: number, char: string) => {
    if (!/^\d?$/.test(char)) return;           // только одна цифра
    const next = [...values];
    next[i] = char;
    setValues(next);

    if (char && i < length - 1) refs.current[i + 1]?.focus();  // автопереход
    if (next.every(Boolean)) onComplete(next.join(""));        // код собран
  };

  return (
    <div>
      {values.map((val, i) => (
        <input
          key={i}
          ref={(el) => (refs.current[i] = el)}
          value={val}
          maxLength={1}
          onChange={(e) => handleChange(i, e.target.value)}
          onKeyDown={(e) => {
            // backspace на пустой ячейке -> назад
            if (e.key === "Backspace" && !values[i]) refs.current[i - 1]?.focus();
          }}
        />
      ))}
    </div>
  );
}
```

## Вопросы на собеседовании

<b class="text-on-semi-light">С чего начинать machine-coding задачу?</b>
<span class="text-gray">С уточнения требований и краевых случаев, затем минимальное состояние и рабочая логика, и только потом стили. Сначала рабочее поведение, красота - в конце. Не молчать, проговаривать решения по структуре состояния.</span>

<b class="text-on-semi-light">Как хранить состояние аккордеона?</b>
<span class="text-gray">Зависит от режима: для «открыта одна секция» хватит индекса/числа, для «несколько» - `Set` индексов. Стоит сразу уточнить режим у интервьюера - это влияет на тип состояния.</span>

<b class="text-on-semi-light">Что входит в правильную модалку?</b>
<span class="text-gray">Портал, закрытие по Escape и клику на оверлей, `stopPropagation` на контенте, блокировка скролла фона, `role="dialog"`/`aria-modal`, фокус-трап и возврат фокуса при закрытии. Очистка слушателей в cleanup.</span>

<b class="text-on-semi-light">Почему setTime(time + 1) в интервале - баг?</b>
<span class="text-gray">Колбэк интервала замыкает `time` на момент создания эффекта и не видит обновлений. Нужен функциональный апдейт `setTime(t => t + 1)`, который получает актуальное значение. Иначе счётчик застревает.</span>

<b class="text-on-semi-light">Зачем cleanup в useEffect с интервалом/слушателем?</b>
<span class="text-gray">Чтобы не накапливать интервалы и подписки при ре-рендерах/анмаунте - иначе утечка памяти и дублирующиеся вызовы. Возвращаемая из эффекта функция чистит ресурс перед следующим запуском и при размонтировании.</span>
