# События и pub/sub

`EventEmitter`, шина событий, observable - это паттерн «издатель/подписчик», на котором стоят Node.js, DOM-события, стейт-менеджеры и реактивность. Задача проверяет работу с **коллекциями колбэков, отпиской и порядком вызова**.

---

## EventEmitter

<b class="text-on-semi-light">EventEmitter</b> <span class="text-gray">- объект, на события которого можно подписываться (`on`), отписываться (`off`) и которые можно генерировать (`emit`). Сердце Node.js и многих библиотек.</span>

```ts
type Listener = (...args: any[]) => void;

class EventEmitter {
  private events = new Map<string, Set<Listener>>();

  on(event: string, listener: Listener): this {
    if (!this.events.has(event)) this.events.set(event, new Set());
    this.events.get(event)!.add(listener);
    return this; // для чейнинга emitter.on().on()
  }

  off(event: string, listener: Listener): this {
    this.events.get(event)?.delete(listener);
    return this;
  }

  emit(event: string, ...args: any[]): boolean {
    const listeners = this.events.get(event);
    if (!listeners || listeners.size === 0) return false;
    // копируем перед обходом: слушатель может отписаться во время emit
    [...listeners].forEach((listener) => listener(...args));
    return true;
  }

  once(event: string, listener: Listener): this {
    const wrapper: Listener = (...args) => {
      this.off(event, wrapper); // отписываемся перед вызовом
      listener(...args);
    };
    return this.on(event, wrapper);
  }
}
```

**На что смотрит интервьюер:**

1. **Структура хранения** - `Map<event, Set<listener>>`. `Set` сам отсекает дубли подписок.
2. **`once`** - оборачиваем слушатель, который сам себя отписывает. Отписать надо **до** вызова - иначе рекурсивный `emit` зациклит.
3. **Копия при emit** - `[...listeners]`, иначе отписка во время обхода сломает итерацию.
4. **Чейнинг** - возвращаем `this`.

> ⚠️ Тонкость с `once`: если хранить оригинальный слушатель, `off` не найдёт обёртку. Нужно либо хранить ссылку оригинал→обёртка, либо (проще) отписывать саму обёртку изнутри.

## Pub/Sub (шина событий)

<b class="text-on-semi-light">Pub/Sub</b> <span class="text-gray">- то же по сути, но подписка обычно возвращает функцию отписки (`unsubscribe`) - удобнее для React `useEffect` и компонентов.</span>

```ts
class PubSub {
  private subscribers = new Map<string, Set<Listener>>();

  subscribe(event: string, callback: Listener): () => void {
    if (!this.subscribers.has(event)) this.subscribers.set(event, new Set());
    this.subscribers.get(event)!.add(callback);

    // возвращаем функцию отписки - её удобно вернуть из useEffect
    return () => this.subscribers.get(event)?.delete(callback);
  }

  publish(event: string, data?: unknown) {
    this.subscribers.get(event)?.forEach((cb) => cb(data));
  }
}

const bus = new PubSub();
const unsub = bus.subscribe("login", (user) => console.log(user));
bus.publish("login", { name: "Анна" });
unsub(); // отписка одним вызовом
```

| | EventEmitter | Pub/Sub |
| --- | --- | --- |
| Отписка | `off(event, listener)` | возвращённый `unsubscribe()` |
| Стиль | Node.js | фронтенд / реактивность |
| Связанность | издатель знает событие | издатель и подписчик развязаны темой |

## Observable (мини-реактивность)

<b class="text-on-semi-light">Observable</b> <span class="text-gray">- значение, на изменения которого можно подписаться. Это мостик к реактивности фреймворков - подробнее в [реализации фреймворков](/content/common-coding-questions/framework-implementation).</span>

```ts
class Observable<T> {
  private observers = new Set<(value: T) => void>();

  constructor(private value: T) {}

  get(): T {
    return this.value;
  }

  set(next: T) {
    if (next === this.value) return;   // не уведомляем, если не изменилось
    this.value = next;
    this.observers.forEach((fn) => fn(next));
  }

  subscribe(fn: (value: T) => void): () => void {
    this.observers.add(fn);
    fn(this.value);                    // сразу отдаём текущее значение
    return () => this.observers.delete(fn);
  }
}
```

## Простой Store (Redux-lite)

Частое продолжение - «сделай мини-стор с подпиской». Это pub/sub + состояние:

```ts
function createStore<S>(reducer: (state: S, action: any) => S, initial: S) {
  let state = initial;
  const listeners = new Set<() => void>();

  return {
    getState: () => state,
    dispatch(action: any) {
      state = reducer(state, action);   // чистое обновление
      listeners.forEach((l) => l());    // уведомляем подписчиков
    },
    subscribe(listener: () => void) {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
  };
}
```

Это буквально ядро Redux в 12 строк - хороший ответ на «как устроен Redux под капотом».

## Вопросы на собеседовании

<b class="text-on-semi-light">Почему при emit нужно копировать список слушателей?</b>
<span class="text-gray">Слушатель может отписаться (или подписать новый) прямо во время обработки события. Если итерировать оригинальную коллекцию, это собьёт обход. Копия `[...listeners]` делает emit устойчивым к мутациям.</span>

<b class="text-on-semi-light">Как реализовать once?</b>
<span class="text-gray">Оборачиваем слушатель в функцию, которая сначала отписывает саму себя, потом вызывает оригинал. Отписать нужно до вызова - иначе повторный emit внутри обработчика зациклит. Для `off` хранят связь оригинал→обёртка.</span>

<b class="text-on-semi-light">Чем pub/sub отличается от EventEmitter?</b>
<span class="text-gray">Концептуально это одно. Различие в API и связанности: EventEmitter в стиле Node (`on/off/emit`), pub/sub обычно возвращает `unsubscribe` и сильнее развязывает издателя и подписчика через тему. Pub/sub удобнее во фронтенде и React.</span>

<b class="text-on-semi-light">Как устроен Redux под капотом?</b>
<span class="text-gray">Это pub/sub поверх состояния: хранит state, `dispatch` прогоняет его через чистый reducer и уведомляет подписчиков, `subscribe` добавляет слушатель и возвращает отписку. Всё ядро - около десятка строк.</span>

<b class="text-on-semi-light">Почему Set, а не массив для слушателей?</b>
<span class="text-gray">`Set` автоматически отсекает повторную подписку одной функции и даёт O(1) удаление при отписке. С массивом пришлось бы искать индекс через `indexOf` и следить за дублями.</span>
