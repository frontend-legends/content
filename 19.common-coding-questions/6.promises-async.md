# Промисы и асинхронность

Асинхронные задачи - визитная карточка фронтенд-собеса, потому что без них не написать ни одного реального приложения. Здесь - **комбинаторы промисов руками** (`all`, `race`, `any`, `allSettled`), `promisify`, `retry`, ограничение конкурентности и очереди задач.

---

## Promise.all

<b class="text-on-semi-light">Promise.all</b> <span class="text-gray">- ждёт все промисы, возвращает массив результатов **в исходном порядке**. Падает целиком при первой же ошибке (fail-fast).</span>

```ts
function promiseAll<T>(promises: Array<Promise<T> | T>): Promise<T[]> {
  return new Promise((resolve, reject) => {
    const results: T[] = [];
    let completed = 0;

    if (promises.length === 0) return resolve([]); // краевой случай

    promises.forEach((p, index) => {
      // Promise.resolve оборачивает не-промисы
      Promise.resolve(p).then((value) => {
        results[index] = value;       // по индексу - сохраняем порядок!
        completed++;
        if (completed === promises.length) resolve(results);
      }, reject);                      // первый reject рушит всё
    });
  });
}
```

**Ключевые моменты:**

1. **Порядок** - пишем по `index`, а не `push` (промисы резолвятся в произвольном порядке).
2. **Счётчик** - резолвим, когда `completed === length`, а не когда массив «выглядит полным».
3. **Краевой случай** - пустой массив резолвится сразу в `[]`.
4. **Не-промисы** - оборачиваем в `Promise.resolve`.

## Promise.allSettled

<b class="text-on-semi-light">allSettled</b> <span class="text-gray">- ждёт все промисы и **никогда не падает**: возвращает массив `{status, value | reason}`. Нужен, когда важны все результаты, и успешные, и провалившиеся.</span>

```ts
function promiseAllSettled<T>(promises: Array<Promise<T>>) {
  return Promise.all(
    promises.map((p) =>
      Promise.resolve(p).then(
        (value) => ({ status: "fulfilled" as const, value }),
        (reason) => ({ status: "rejected" as const, reason })
      )
    )
  );
}
```

Изящный трюк - превратить каждый промис в «всегда успешный» через `.then(onOk, onErr)`, и тогда `Promise.all` уже не упадёт.

## Promise.race и Promise.any

<b class="text-on-semi-light">race</b> <span class="text-gray">- резолвится/реджектится первым *завершившимся* промисом (любым исходом).</span>
<b class="text-on-semi-light">any</b> <span class="text-gray">- резолвится первым *успешным*; если все упали - реджектится `AggregateError`.</span>

```ts
function promiseRace<T>(promises: Array<Promise<T>>): Promise<T> {
  return new Promise((resolve, reject) => {
    for (const p of promises) {
      Promise.resolve(p).then(resolve, reject); // кто первый - тот и выиграл
    }
  });
}

function promiseAny<T>(promises: Array<Promise<T>>): Promise<T> {
  return new Promise((resolve, reject) => {
    let rejected = 0;
    const errors: any[] = [];

    promises.forEach((p, i) => {
      Promise.resolve(p).then(resolve, (err) => {
        errors[i] = err;
        if (++rejected === promises.length) {
          reject(new AggregateError(errors, "All promises were rejected"));
        }
      });
    });
  });
}
```

| Комбинатор | Резолвится | Реджектится |
| --- | --- | --- |
| `all` | все успешны | первый упавший |
| `allSettled` | всегда (все завершились) | никогда |
| `race` | первый завершившийся | первый завершившийся (если ошибка) |
| `any` | первый успешный | все упали (AggregateError) |

> Этот разбор различий - один из самых частых устных вопросов. Знать таблицу наизусть.

## promisify

<b class="text-on-semi-light">promisify</b> <span class="text-gray">- превращает функцию с колбэком в стиле Node (`(err, data) => ...`) в функцию, возвращающую промис.</span>

```ts
function promisify<T>(
  fn: (...args: [...any[], (err: any, data: T) => void]) => void
) {
  return (...args: any[]): Promise<T> =>
    new Promise((resolve, reject) => {
      fn(...args, (err: any, data: T) => {
        if (err) reject(err);
        else resolve(data);
      });
    });
}
```

## sleep и retry

`sleep` - база, с которой начинаются многие async-задачи:

```ts
const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));
```

<b class="text-on-semi-light">retry</b> <span class="text-gray">- повторяет асинхронную операцию N раз с паузой, пока не получится. Часто с экспоненциальной задержкой.</span>

```ts
async function retry<T>(
  fn: () => Promise<T>,
  retries = 3,
  delay = 500
): Promise<T> {
  try {
    return await fn();
  } catch (err) {
    if (retries <= 0) throw err;
    await sleep(delay);
    return retry(fn, retries - 1, delay * 2); // exponential backoff
  }
}
```

## Ограничение конкурентности (mapLimit)

<b class="text-on-semi-light">Пул конкурентности</b> <span class="text-gray">- выполнить много async-задач, но не больше `limit` одновременно. Классика для «не положи сервер 1000 параллельных запросов».</span>

```ts
async function mapLimit<T, U>(
  items: T[],
  limit: number,
  fn: (item: T) => Promise<U>
): Promise<U[]> {
  const results: U[] = new Array(items.length);
  let index = 0;

  // worker берёт следующую задачу, пока они есть
  async function worker() {
    while (index < items.length) {
      const current = index++;             // захватываем индекс атомарно
      results[current] = await fn(items[current]);
    }
  }

  // запускаем limit воркеров параллельно
  const workers = Array.from({ length: Math.min(limit, items.length) }, worker);
  await Promise.all(workers);
  return results;
}
```

**Идея:** запускаем ровно `limit` «воркеров», каждый в цикле берёт следующую свободную задачу. Как только освободился - берёт ещё. Это держит ровно `limit` промисов в полёте.

## Очередь задач (async series)

Иногда нужно наоборот - выполнять задачи **строго по очереди**:

```ts
class AsyncQueue {
  private queue: Array<() => Promise<void>> = [];
  private running = false;

  add(task: () => Promise<void>) {
    this.queue.push(task);
    this.run();
  }

  private async run() {
    if (this.running) return;       // уже крутится - не запускаем второй раз
    this.running = true;
    while (this.queue.length) {
      const task = this.queue.shift()!;
      await task();                 // ждём каждую перед следующей
    }
    this.running = false;
  }
}
```

## Вопросы на собеседовании

<b class="text-on-semi-light">Как Promise.all сохраняет порядок результатов?</b>
<span class="text-gray">Записывает результат каждого промиса по его индексу (`results[index] = value`), а не через `push`. Промисы завершаются в произвольном порядке, индекс гарантирует исходный порядок. Резолв - по счётчику завершённых.</span>

<b class="text-on-semi-light">Чем allSettled отличается от all?</b>
<span class="text-gray">`all` падает при первой ошибке (fail-fast). `allSettled` ждёт все и никогда не падает, возвращая массив `{status, value/reason}`. Реализуется оборачиванием каждого промиса в «всегда успешный».</span>

<b class="text-on-semi-light">В чём разница race и any?</b>
<span class="text-gray">`race` завершается первым *завершившимся* промисом - любым исходом, включая ошибку. `any` завершается первым *успешным*; реджектится только если упали все - с `AggregateError`.</span>

<b class="text-on-semi-light">Как ограничить число одновременных запросов?</b>
<span class="text-gray">Пул воркеров: запускаем `limit` параллельных «воркеров», каждый в цикле берёт следующую свободную задачу по общему индексу. В полёте всегда не больше `limit` промисов. Альтернатива - рекурсивный запуск следующего в `.then` завершившегося.</span>

<b class="text-on-semi-light">Как сделать retry с backoff?</b>
<span class="text-gray">Рекурсивно: пытаемся выполнить, при ошибке ждём `delay`, уменьшаем счётчик попыток и удваиваем задержку (`delay * 2`). Когда попытки кончились - пробрасываем последнюю ошибку.</span>
