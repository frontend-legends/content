# Реализация фреймворка

Раунд уровня senior - **«реализуй кусок React/Vue»**: сигнал, `ref`, хук, `Teleport`, мини-VDOM, или весь крошечный фреймворк целиком. Это проверка, что ты понимаешь **как работает реактивность и рендеринг под капотом**, а не только используешь API.

## signal / effect / computed

<b class="text-on-semi-light">Сигнал</b> <span class="text-gray">- хранимое значение, которое автоматически отслеживает, кто его читает, и уведомляет читателей при изменении. Модель Solid, Preact Signals, Angular Signals. Ядро укладывается в ~30 строк.</span>

```ts
let currentEffect: (() => void) | null = null; // кто сейчас «слушает» чтения

function signal<T>(initial: T) {
  let value = initial;
  const subscribers = new Set<() => void>();

  const read = () => {
    if (currentEffect) subscribers.add(currentEffect); // авто-подписка при чтении
    return value;
  };
  const write = (next: T) => {
    if (next === value) return;
    value = next;
    [...subscribers].forEach((fn) => fn());            // уведомляем читателей
  };
  return [read, write] as const;
}

function effect(fn: () => void) {
  const run = () => {
    currentEffect = run;        // помечаем себя активным
    try { fn(); } finally { currentEffect = null; }  // чтения внутри fn подпишутся на run
  };
  run();
}

function computed<T>(fn: () => T) {
  const [get, set] = signal<T>(undefined as T);
  effect(() => set(fn()));      // computed = эффект, пишущий в сигнал
  return get;
}
```

```ts
const [count, setCount] = signal(0);
effect(() => console.log("count:", count())); // печатает 0, подписался
setCount(1);                                   // автоматически печатает 1
```

**Магия в трёх строках:**

1. **Глобальный `currentEffect`** - пока эффект выполняется, любое прочтённое значение «видит», кто читает.
2. **Чтение подписывает** - `read()` добавляет текущий эффект в подписчики (это **dependency tracking**).
3. **Запись уведомляет** - `write()` перезапускает все подписанные эффекты.

> Это и есть «fine-grained reactivity»: перезапускается только тот код, что реально читал изменившийся сигнал, - без VDOM-диффинга. Любимый вопрос: «чем сигналы отличаются от React-стейта?» - сигналы точечны, React перерисовывает компонент целиком.

## Vue ref и reactive

<b class="text-on-semi-light">ref / reactive</b> <span class="text-gray">- реактивность Vue 3. `reactive` оборачивает объект в `Proxy` и перехватывает чтение (`track`) и запись (`trigger`). `ref` - то же для примитивов через `.value`.</span>

```ts
let activeEffect: (() => void) | null = null;
const targetMap = new WeakMap<object, Map<string | symbol, Set<() => void>>>();

function track(target: object, key: string | symbol) {
  if (!activeEffect) return;
  let deps = targetMap.get(target);
  if (!deps) targetMap.set(target, (deps = new Map()));
  let dep = deps.get(key);
  if (!dep) deps.set(key, (dep = new Set()));
  dep.add(activeEffect);                       // запоминаем зависимость target.key -> effect
}

function trigger(target: object, key: string | symbol) {
  targetMap.get(target)?.get(key)?.forEach((fn) => fn());
}

function reactive<T extends object>(obj: T): T {
  return new Proxy(obj, {
    get(target, key, receiver) {
      track(target, key);                       // читают -> подписываем
      return Reflect.get(target, key, receiver);
    },
    set(target, key, value, receiver) {
      const result = Reflect.set(target, key, value, receiver);
      trigger(target, key);                     // пишут -> уведомляем
      return result;
    },
  });
}

function ref<T>(initial: T) {
  const wrapper = reactive({ value: initial }); // ref - это reactive c одним полем value
  return wrapper;
}
```

> Почему у `ref` нужен `.value`? Примитив нельзя обернуть в Proxy - его передают по значению. Поэтому Vue кладёт его в объект `{ value }` и проксирует объект. Это частый вопрос «зачем `.value` в `ref`, но не в `reactive`».

Сравнение моделей реактивности:

| | Signals (Solid) | Vue 3 (Proxy) | React |
| --- | --- | --- | --- |
| Что отслеживает | чтение функции-геттера | доступ к свойствам через Proxy | ничего, ре-рендер по setState |
| Гранулярность | точечная (DOM-узел) | точечная (компонент/эффект) | компонент целиком |
| Цена | подписки | Proxy на каждый доступ | диффинг VDOM |

## Хуки React (useState с нуля)

<b class="text-on-semi-light">useState</b> <span class="text-gray">- объясняет «почему хуки нельзя вызывать условно». Состояние хранится в массиве по **порядковому индексу**, а индекс растёт при каждом вызове хука.</span>

```ts
let hooks: any[] = [];
let hookIndex = 0;

function useState<T>(initial: T): [T, (next: T) => void] {
  const i = hookIndex++;                         // фиксируем «слот» по порядку вызова
  hooks[i] = hooks[i] ?? initial;

  const setState = (next: T) => {
    hooks[i] = next;
    render();                                     // перерисовываем компонент
  };
  return [hooks[i], setState];
}

function render() {
  hookIndex = 0;                                  // сбрасываем индекс перед рендером
  Component();                                    // хуки вызываются в том же порядке
}
```

> ⚠️ Вот почему **правило хуков**: порядок вызова должен быть стабильным. Условный `if (x) useState()` сдвинет индексы, и состояние «съедет» на чужой слот. Этот код - лучший ответ на «почему нельзя вызывать хуки в условии».

`useEffect` и `useReducer` строятся так же - слот по индексу плюс сравнение зависимостей:

```ts
function useEffect(fn: () => void, deps: any[]) {
  const i = hookIndex++;
  const prev = hooks[i];
  // запускаем, если deps изменились (или первый рендер)
  const changed = !prev || deps.some((d, j) => d !== prev.deps[j]);
  if (changed) { fn(); hooks[i] = { deps }; }
}
```

## Кастомные хуки

Частая разминка перед «реализуй useState» - написать прикладной хук:

```ts
// useDebounce - дебаунс значения
function useDebounce<T>(value: T, delay = 300): T {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);
  return debounced;
}

// usePrevious - предыдущее значение
function usePrevious<T>(value: T): T | undefined {
  const ref = useRef<T>();
  useEffect(() => { ref.current = value; }, [value]);
  return ref.current;        // вернётся ДО обновления эффектом
}
```

## Teleport / createPortal

<b class="text-on-semi-light">Teleport (Vue) / createPortal (React)</b> <span class="text-gray">- рендер содержимого в другой узел DOM (обычно `body`), сохраняя его логически в дереве компонентов. Нужно для модалок, тултипов, тостов - чтобы вырваться из `overflow: hidden` и контекста наложения.</span>

```ts
// упрощённый портал на ваниль
function portal(content: HTMLElement, target: HTMLElement = document.body) {
  target.appendChild(content);                  // физически - в target
  return () => target.removeChild(content);     // cleanup
}
```

Суть: **физически** узел живёт в `target`, но **логически** (события, контекст, реактивность) - там, где объявлен. React реализует это, направляя коммит в другой контейнер, но сохраняя дерево Fiber на месте - поэтому всплытие событий и контекст работают «как будто внутри».

## Мини-VDOM и render

<b class="text-on-semi-light">Virtual DOM</b> <span class="text-gray">- JS-описание UI (`{ type, props, children }`), которое рендерится в реальный DOM, а при обновлении - диффится со старым деревом. Просят написать `h` → `render` → наивный `diff`.</span>

```ts
type VNode = { type: string; props: Record<string, any>; children: (VNode | string)[] };

// h / createElement - создаём виртуальный узел
function h(type: string, props: Record<string, any> = {}, ...children: any[]): VNode {
  return { type, props, children: children.flat() };
}

// render - VNode -> реальный DOM-узел
function render(vnode: VNode | string): Node {
  if (typeof vnode === "string") return document.createTextNode(vnode);

  const el = document.createElement(vnode.type);
  for (const [key, value] of Object.entries(vnode.props || {})) {
    if (key.startsWith("on")) {
      el.addEventListener(key.slice(2).toLowerCase(), value); // onClick -> click
    } else {
      el.setAttribute(key, value);
    }
  }
  vnode.children.forEach((child) => el.appendChild(render(child)));
  return el;
}

const tree = h("div", { class: "box" }, h("span", {}, "Привет"));
document.body.appendChild(render(tree));
```

Наивный **diff/patch** (минимальный, для понимания согласования):

```ts
function patch(parent: Node, oldVNode: any, newVNode: any, index = 0) {
  const existing = parent.childNodes[index];

  if (!oldVNode) parent.appendChild(render(newVNode));          // добавили
  else if (!newVNode) parent.removeChild(existing);             // удалили
  else if (changed(oldVNode, newVNode)) parent.replaceChild(render(newVNode), existing); // заменили
  else if (newVNode.type) {                                     // тот же тег -> вглубь
    const max = Math.max(oldVNode.children.length, newVNode.children.length);
    for (let i = 0; i < max; i++) {
      patch(existing, oldVNode.children[i], newVNode.children[i], i);
    }
  }
}

const changed = (a: any, b: any) =>
  typeof a !== typeof b || (typeof a === "string" && a !== b) || a.type !== b.type;
```

> Это и есть упрощённое «согласование» (reconciliation). Настоящий React использует Fiber, ключи (`key`) и эвристики, но идея - сравнить два дерева и применить к DOM только разницу.

## Мини-фреймворк (всё вместе)

Финальный senior-вопрос - **связать сигналы и рендер в крошечный реактивный фреймворк**:

```ts
function mount(component: () => VNode, container: HTMLElement) {
  let current: Node | null = null;

  // эффект перезапустится при изменении любого прочитанного сигнала
  effect(() => {
    const next = render(component());
    if (current) container.replaceChild(next, current);
    else container.appendChild(next);
    current = next;
  });
}

// использование
const [count, setCount] = signal(0);
mount(
  () => h("button", { onClick: () => setCount(count() + 1) }, `Clicks: ${count()}`),
  document.getElementById("app")!
);
```

`mount` оборачивает рендер в `effect`. Компонент читает `count()` - эффект подписывается. `setCount` меняет сигнал - эффект перерисовывает. **Реактивность + рендеринг = фреймворк** в 8 строк.

## Вопросы на собеседовании

<b class="text-on-semi-light">Как сигнал узнаёт своих подписчиков?</b>
<span class="text-gray">Через глобальный «текущий эффект»: пока эффект выполняется, он помечает себя активным, и любое чтение сигнала добавляет этот эффект в свои подписчики. Это dependency tracking - подписка происходит автоматически в момент чтения.</span>

<b class="text-on-semi-light">Почему у Vue ref нужен .value, а у reactive нет?</b>
<span class="text-gray">`reactive` оборачивает объект в Proxy и перехватывает доступ к свойствам. Примитив в Proxy обернуть нельзя (передаётся по значению), поэтому `ref` кладёт его в объект `{ value }` и проксирует объект - доступ идёт через `.value`.</span>

<b class="text-on-semi-light">Почему хуки нельзя вызывать условно?</b>
<span class="text-gray">Состояние хуков хранится по порядковому индексу вызова, а не по имени. Условный вызов сдвинет индексы между рендерами, и состояние «съедет» на чужой слот. Поэтому порядок и количество хуков должны быть стабильны.</span>

<b class="text-on-semi-light">Чем сигналы отличаются от React-стейта?</b>
<span class="text-gray">Сигналы точечны: при изменении перезапускается только код, реально читавший сигнал (вплоть до конкретного DOM-узла), без диффинга. React по setState перерисовывает весь компонент и сверяет VDOM. Сигналы - fine-grained, React - компонентная грануляция.</span>

<b class="text-on-semi-light">Как работает Teleport/createPortal?</b>
<span class="text-gray">Содержимое физически вставляется в другой DOM-узел (обычно body), но логически остаётся в дереве компонентов - события всплывают и контекст работает «как изнутри». Нужно, чтобы вырваться из `overflow:hidden`/`z-index` родителя для модалок и тултипов.</span>

<b class="text-on-semi-light">Что такое reconciliation и зачем ключи?</b>
<span class="text-gray">Согласование - сравнение нового VDOM-дерева со старым и применение к реальному DOM только различий. `key` помогает сопоставить элементы списка между рендерами, чтобы переиспользовать узлы вместо пересоздания и не терять состояние/фокус.</span>
