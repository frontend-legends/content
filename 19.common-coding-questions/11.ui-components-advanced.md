# UI-компоненты: продвинутые

Вторая половина machine-coding - **компоненты с асинхронностью и сложным состоянием**: автокомплит, бесконечный скролл, пагинация, карусель, todo. Здесь к UI добавляются `debounce`, отмена запросов, гонки, `IntersectionObserver`. Это любимый раунд для mid+/senior.

---

## Autocomplete / Typeahead

Самая частая «большая» задача. Соединяет всё: [`debounce`](/content/common-coding-questions/higher-order-utils), асинхронность, гонки запросов, клавиатуру, a11y.

```tsx
function Autocomplete({ fetchSuggestions }: { fetchSuggestions: (q: string) => Promise<string[]> }) {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState<string[]>([]);
  const [active, setActive] = useState(-1);
  const lastQuery = useRef("");                  // защита от гонок

  useEffect(() => {
    if (!query) return setResults([]);
    const id = setTimeout(async () => {          // debounce внутри эффекта
      lastQuery.current = query;
      const data = await fetchSuggestions(query);
      // игнорируем ответ, если запрос уже устарел
      if (lastQuery.current === query) setResults(data);
    }, 300);
    return () => clearTimeout(id);               // отмена при новом вводе
  }, [query, fetchSuggestions]);

  return (
    <div role="combobox" aria-expanded={results.length > 0}>
      <input
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        onKeyDown={(e) => {
          if (e.key === "ArrowDown") setActive((i) => Math.min(i + 1, results.length - 1));
          if (e.key === "ArrowUp") setActive((i) => Math.max(i - 1, 0));
          if (e.key === "Enter" && active >= 0) setQuery(results[active]);
        }}
      />
      <ul role="listbox">
        {results.map((r, i) => (
          <li key={r} role="option" aria-selected={i === active}>{r}</li>
        ))}
      </ul>
    </div>
  );
}
```

**Что проверяет интервьюер (и это весь чеклист автокомплита):**

1. **Debounce** - не дёргать API на каждый символ.
2. **Гонки (race conditions)** - старый ответ может прийти позже нового. Защита через `lastQuery.current` или `AbortController`.
3. **Клавиатура** - стрелки, Enter, Escape.
4. **A11y** - `role="combobox"/listbox/option"`, `aria-selected`.
5. **Краевые случаи** - пустой ввод, нет результатов, ошибка запроса.

> ⚠️ Гонки - то, на чём валятся даже сильные кандидаты. Без проверки «актуален ли ещё запрос» автокомплит будет показывать результаты для уже стёртого текста.

## Бесконечный скролл

<b class="text-on-semi-light">Infinite scroll</b> <span class="text-gray">- подгрузка следующей порции данных при приближении к концу списка. Современно - через `IntersectionObserver` на «маяке» внизу, а не на событии scroll.</span>

```tsx
function InfiniteList({ loadMore }: { loadMore: () => Promise<Item[]> }) {
  const [items, setItems] = useState<Item[]>([]);
  const [loading, setLoading] = useState(false);
  const sentinel = useRef<HTMLDivElement>(null);

  useEffect(() => {
    const observer = new IntersectionObserver(async ([entry]) => {
      if (entry.isIntersecting && !loading) {     // маяк виден -> грузим
        setLoading(true);
        const next = await loadMore();
        setItems((prev) => [...prev, ...next]);
        setLoading(false);
      }
    });
    if (sentinel.current) observer.observe(sentinel.current);
    return () => observer.disconnect();           // отписка
  }, [loadMore, loading]);

  return (
    <div>
      {items.map((item) => <Row key={item.id} item={item} />)}
      <div ref={sentinel}>{loading && "Загрузка..."}</div>
    </div>
  );
}
```

> Сравнение со `scroll` + `throttle`: `IntersectionObserver` эффективнее (браузер сам считает пересечение, без обработчика на каждый пиксель скролла). Стоит назвать оба подхода.

## Пагинация

Часто просят чистую функцию **генерации диапазона страниц с многоточием** (`1 ... 4 5 6 ... 20`):

```ts
function getPaginationRange(current: number, total: number, siblings = 1): (number | "...")[] {
  const range: (number | "...")[] = [];
  const left = Math.max(2, current - siblings);
  const right = Math.min(total - 1, current + siblings);

  range.push(1);                                  // всегда первая
  if (left > 2) range.push("...");                // разрыв слева
  for (let i = left; i <= right; i++) range.push(i);
  if (right < total - 1) range.push("...");       // разрыв справа
  if (total > 1) range.push(total);               // всегда последняя

  return range;
}

getPaginationRange(5, 20); // [1, "...", 4, 5, 6, "...", 20]
```

Чистая логика без UI - удобно тестировать и легко обсуждать краевые случаи (мало страниц, текущая у края).

## Todo (mini-app)

Take-home классика. Главное - **минимальное состояние, иммутабельные обновления, фильтрация**.

```tsx
function TodoApp() {
  const [todos, setTodos] = useState<Todo[]>([]);
  const [filter, setFilter] = useState<"all" | "active" | "done">("all");

  const add = (text: string) =>
    setTodos((prev) => [...prev, { id: crypto.randomUUID(), text, done: false }]);

  const toggle = (id: string) =>
    setTodos((prev) => prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));

  const remove = (id: string) =>
    setTodos((prev) => prev.filter((t) => t.id !== id));

  // производное состояние, не дублируем в useState
  const visible = todos.filter((t) =>
    filter === "all" ? true : filter === "done" ? t.done : !t.done
  );

  return <>{/* input + список visible + кнопки фильтра */}</>;
}
```

> Ключевой принцип - `visible` вычисляется из `todos` и `filter`, его **не хранят** отдельным состоянием. Дублирование состояния = рассинхрон. Это частая обратная связь на take-home.

## Tic-tac-toe (крестики-нолики)

Любимая «логическая» задача - state-машина + проверка победителя:

```ts
const LINES = [
  [0, 1, 2], [3, 4, 5], [6, 7, 8],   // ряды
  [0, 3, 6], [1, 4, 7], [2, 5, 8],   // колонки
  [0, 4, 8], [2, 4, 6],              // диагонали
];

function getWinner(board: (string | null)[]): string | null {
  for (const [a, b, c] of LINES) {
    if (board[a] && board[a] === board[b] && board[a] === board[c]) {
      return board[a];               // три в ряд
    }
  }
  return null;
}
```

Победителя проверяют табличкой выигрышных линий - чисто и без вложенных циклов по координатам.

## Вопросы на собеседовании

<b class="text-on-semi-light">Как защититься от гонок запросов в автокомплите?</b>
<span class="text-gray">Запоминать «актуальный» запрос (ref на последний текст) и игнорировать ответ, если он устарел; либо отменять предыдущий запрос через `AbortController`. Иначе медленный старый ответ перезапишет свежий.</span>

<b class="text-on-semi-light">Зачем в автокомплите debounce?</b>
<span class="text-gray">Чтобы не отправлять запрос на каждый символ - ждём паузу ~300мс. Экономит запросы и нагрузку на API. Реализуется через `setTimeout` в эффекте с очисткой при новом вводе.</span>

<b class="text-on-semi-light">Почему IntersectionObserver лучше scroll-события для бесконечного скролла?</b>
<span class="text-gray">Браузер сам асинхронно вычисляет пересечение элемента-маяка с вьюпортом, без обработчика, который дёргается на каждый пиксель скролла. Это эффективнее и не требует throttle. Не забыть `disconnect` при размонтировании.</span>

<b class="text-on-semi-light">Почему отфильтрованный список не стоит хранить в state?</b>
<span class="text-gray">Это производное состояние - вычисляется из исходных данных и фильтра при рендере. Хранить отдельно = два источника истины и риск рассинхрона. Держим только todos и filter, visible считаем на лету.</span>

<b class="text-on-semi-light">Как проверить победителя в крестиках-ноликах?</b>
<span class="text-gray">Заранее задать массив выигрышных линий (индексы тройками: ряды, колонки, диагонали) и проверить, есть ли линия с тремя одинаковыми непустыми ячейками. Чище и быстрее, чем перебор координат вложенными циклами.</span>
