# Реализация Promise

«Напиши свой Promise» - задача уровня мидл+/сеньор. Она проверяет всё сразу: **состояния, микротаски, цепочки `.then`, обработку ошибок**. Полную спецификацию Promises/A+ на собесе не пишут, но рабочее ядро с правильной асинхронностью - вполне реальная просьба.

---

## Три состояния

<b class="text-on-semi-light">Promise</b> <span class="text-gray">- объект с одним из трёх состояний: `pending` (ожидает), `fulfilled` (успех со значением), `rejected` (ошибка с причиной). Переход возможен только из `pending` и только один раз.</span>

```ts
type State = "pending" | "fulfilled" | "rejected";
```

---

## Минимальное ядро

Сначала - простейшая версия с состоянием и `then`, но **без** цепочек:

```ts
class MyPromise<T> {
  private state: State = "pending";
  private value: any;
  private callbacks: Array<() => void> = []; // подписчики, ждущие resolve/reject

  constructor(executor: (resolve: (v: T) => void, reject: (e: any) => void) => void) {
    const resolve = (value: T) => this.transition("fulfilled", value);
    const reject = (reason: any) => this.transition("rejected", reason);
    try {
      executor(resolve, reject);
    } catch (err) {
      reject(err);               // ошибка в executor -> reject
    }
  }

  private transition(state: State, value: any) {
    if (this.state !== "pending") return; // переход только один раз
    this.state = state;
    this.value = value;
    this.callbacks.forEach((cb) => cb()); // будим подписчиков
    this.callbacks = [];
  }
}
```

## then с цепочками

Самая сложная часть - `then` должен **возвращать новый промис** и правильно прокидывать значение/ошибку дальше. И колбэки должны вызываться **асинхронно** (в микротаске).

```ts
then<U>(
  onFulfilled?: (value: T) => U | MyPromise<U>,
  onRejected?: (reason: any) => U | MyPromise<U>
): MyPromise<U> {
  return new MyPromise<U>((resolve, reject) => {
    const handle = () => {
      // microtask: колбэки всегда асинхронны, даже если промис уже завершён
      queueMicrotask(() => {
        try {
          if (this.state === "fulfilled") {
            // нет onFulfilled - пробрасываем значение дальше
            if (!onFulfilled) return resolve(this.value);
            resolve(this.resolveValue(onFulfilled(this.value)) as U);
          } else if (this.state === "rejected") {
            // нет onRejected - пробрасываем ошибку дальше
            if (!onRejected) return reject(this.value);
            resolve(this.resolveValue(onRejected(this.value)) as U);
          }
        } catch (err) {
          reject(err);            // ошибка в колбэке -> reject следующего
        }
      });
    };

    if (this.state === "pending") {
      this.callbacks.push(handle); // ещё не готов - подписываемся
    } else {
      handle();                    // уже готов - планируем микротаску
    }
  });
}

// если колбэк вернул промис - дожидаемся его (thenable)
private resolveValue(value: any) {
  if (value instanceof MyPromise) {
    return value.then.bind(value);
  }
  return value;
}
```

> Полная Promises/A+ обрабатывает «thenable» сложнее (рекурсивная адаптация любого объекта с `.then`). На собесе достаточно поддержать возврат `MyPromise` из колбэка и проговорить, что настоящий стандарт идёт глубже.

## catch и finally через then

`catch` и `finally` - это сахар над `then`, их просят дописать:

```ts
catch<U>(onRejected: (reason: any) => U) {
  return this.then(undefined, onRejected);
}

finally(onFinally: () => void) {
  return this.then(
    (value) => { onFinally(); return value; },     // прокидываем значение
    (reason) => { onFinally(); throw reason; }      // прокидываем ошибку
  );
}
```

---

## Почему именно микротаска

<b class="text-on-semi-light">queueMicrotask</b> <span class="text-gray">- ставит колбэк в очередь микротасок, которая выполняется после текущего синхронного кода, но до макротасок (`setTimeout`). Без этого порядок вывода будет неправильным.</span>

```ts
const p = new MyPromise((res) => res(1));
p.then(() => console.log("then"));
console.log("sync");
// Правильный порядок: "sync", потом "then"
// Если вызвать колбэк синхронно - порядок сломается
```

> ⚠️ Самая частая ошибка - вызывать `onFulfilled` синхронно. Спецификация требует, чтобы `.then` всегда был асинхронным. Поэтому `queueMicrotask` (или `setTimeout` как грубый аналог - но это уже макротаска, что менее точно).

## Статические методы

Финальный штрих - `resolve`, `reject` и комбинаторы (`all` из [прошлой главы](/content/common-coding-questions/promises-async) реализуется на этом классе):

```ts
static resolve<T>(value: T) {
  return new MyPromise<T>((res) => res(value));
}

static reject(reason: any) {
  return new MyPromise((_, rej) => rej(reason));
}
```

## Простой планировщик задач (бонус)

Иногда вместо Promise просят «планировщик с приоритетами» или «отложенный запуск» - смежная тема про event loop:

```ts
class Scheduler {
  private tasks: Array<() => void> = [];

  schedule(task: () => void) {
    this.tasks.push(task);
    queueMicrotask(() => this.flush());
  }

  private flush() {
    const task = this.tasks.shift();
    task?.();
  }
}
```

## Вопросы на собеседовании

<b class="text-on-semi-light">Какие состояния у промиса и какие переходы возможны?</b>
<span class="text-gray">`pending`, `fulfilled`, `rejected`. Переход возможен только из `pending` ровно один раз - в fulfilled или rejected. После этого состояние и значение неизменны (промис «заморожен»).</span>

<b class="text-on-semi-light">Почему колбэк then должен вызываться асинхронно?</b>
<span class="text-gray">Спецификация требует, чтобы `.then` исполнялся в микротаске - даже если промис уже завершён. Это гарантирует предсказуемый порядок: синхронный код целиком, потом колбэки. Реализуется через `queueMicrotask`.</span>

<b class="text-on-semi-light">Что возвращает then и как работают цепочки?</b>
<span class="text-gray">`then` возвращает новый промис. Значение, которое вернул колбэк, резолвит этот новый промис; если вернул другой промис - дожидается его; если колбэк бросил - новый промис реджектится. Так строится цепочка.</span>

<b class="text-on-semi-light">Как реализованы catch и finally?</b>
<span class="text-gray">`catch(fn)` = `then(undefined, fn)`. `finally(fn)` = `then`, который вызывает `fn` и прокидывает дальше исходное значение или ошибку, не меняя их.</span>

<b class="text-on-semi-light">Микротаска или setTimeout для then?</b>
<span class="text-gray">Микротаска (`queueMicrotask` / очередь промисов). `setTimeout` - макротаска, она выполняется позже всех микротасок, поэтому порядок будет неверным относительно других промисов.</span>
