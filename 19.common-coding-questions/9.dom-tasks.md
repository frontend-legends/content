# Задачи на DOM

Задачи на живой DOM отличают «писал только на React» от «понимаю платформу»: делегирование событий, обход дерева, свои реализации `getElementsByClassName` и `querySelector`, утилита `classNames`. Спрашивают, что такое делегирование, чем `children` отличается от `childNodes` и что делать с событиями, которые не всплывают. Глубже — зачем в делегировании проверка `parent.contains`, почему самописный `getElementsByClassName` расходится с нативным и почему очередь BFS на `shift` тормозит на больших деревьях.

::tldr
- **Делегирование — один обработчик на родителе:** работает за счёт всплытия, покрывает элементы, добавленные позже. Цель ищут через `event.target.closest(selector)`.
- **closest может выйти за пределы родителя:** в проверке без `parent.contains(target)` обработчик сработал на элементе-предке вне контейнера.
- **focus не всплывает:** в проверке делегирование на `focus` не сработало ни разу, а через фазу перехвата и через `focusin` — на каждом поле.
- **Свои селекторы сверяют с нативными:** нативный `getElementsByClassName` ищет только среди потомков и понимает несколько классов через пробел. Исходная версия включала сам корень и проверяла один класс.
- **Обход дерева — DFS и BFS:** DFS в проверке совпал с порядком `TreeWalker`. Очередь BFS ведут указателем: `shift` на 100 000 элементах занял 634 мс против 3 мс.
::

## Делегирование событий

Вместо обработчика на каждом потомке вешают один на родителя. Это работает за счёт всплытия: событие идёт от цели вверх по предкам, поэтому родитель его «слышит». Экономит память и автоматически работает для элементов, добавленных позже. Механика всплытия и фаз события — в [событиях DOM](/content/web/dom-events).

```ts
function delegate(
  parent: HTMLElement,
  eventType: string,
  selector: string,
  handler: (event: Event, target: Element) => void,
  options?: boolean | AddEventListenerOptions,
) {
  const listener = (event: Event) => {
    const target = (event.target as Element).closest?.(selector); // ближайший подходящий вверх
    if (target && parent.contains(target)) handler(event, target);  // и только внутри parent
  };
  parent.addEventListener(eventType, listener, options);
  return () => parent.removeEventListener(eventType, listener, options);
}
```

В проверке в Chromium обработчик на `<ul>` получил `<li>` при клике по `<span>` внутри него, сработал для `<li>`, добавленного после подписки, промолчал при клике по самому списку мимо пунктов и затих после вызова возвращённой функции отписки.

### Зачем parent.contains

`closest` поднимается от цели до самого корня документа и может найти элемент, который находится выше `parent`. В проверке обработчик висел на панели внутри строки `.row`, а селектор был `.row`: при клике по кнопке в панели `closest('.row')` нашёл строку — предка панели. С проверкой `parent.contains(target)` обработчик не сработал, без неё — сработал на элементе вне контейнера. На вложенных списках и в повторяющихся компонентах это реальная ошибка.

### События, которые не всплывают

`focus`, `blur`, `mouseenter`, `mouseleave` не всплывают. Для них делегирование делают на фазе перехвата (`capture`) — событие проходит от корня вниз через родителя — или берут всплывающие аналоги: `focusin` и `focusout` вместо `focus` и `blur`, `mouseover` и `mouseout` с проверкой цели вместо `mouseenter` и `mouseleave`. В проверке при фокусе на двух полях формы делегирование `focus` не сработало ни разу, а с `capture: true` и через `focusin` — по два раза.

## Свой getElementsByClassName

Проверяет понимание обхода дерева и того, как устроен нативный метод:

```ts
function getElementsByClassName(root: Element, classNames: string): Element[] {
  const wanted = classNames.trim().split(/\s+/).filter(Boolean);
  const result: Element[] = [];
  function traverse(node: Element) {
    for (const child of node.children) {        // только потомки, сам root не входит
      if (wanted.length && wanted.every((c) => child.classList.contains(c))) result.push(child);
      traverse(child);
    }
  }
  traverse(root);
  return result;
}
```

Это обход в глубину по `children`. В проверке результат совпал с нативным `root.getElementsByClassName` в двух местах, где частая реализация ошибается:

- **сам корень не входит.** Версия, которая проверяет класс у `node` перед обходом детей, включила сам `root` — в проверке результатов оказалось на один больше, чем у нативного;
- **несколько классов.** `getElementsByClassName('a b')` ищет элементы, у которых есть оба класса; в проверке нашлись ровно два таких абзаца, как и нативным методом.

Ещё одно отличие стоит назвать: нативный метод возвращает живую `HTMLCollection`. В проверке коллекция выросла с 3 до 4 элементов после добавления нового узла с классом, а наш массив — снимок на момент вызова. Разница `children` и `childNodes`: первое — только элементы, второе — все узлы, включая текст и комментарии; для обхода элементов нужен `children`, иначе зацепятся переносы строк.

## Свой querySelector

Полный CSS-селектор на интервью разбирать не просят — достаточно по тегу, классу или id, проговорив, что настоящий парсер разбирает комбинаторы (`>`, пробел, `+`, `~`), атрибуты и псевдоклассы:

```ts
function querySelectorAllByTag(root: Element, tag: string): Element[] {
  const result: Element[] = [];
  const name = tag.toUpperCase();               // tagName у HTML-элементов в верхнем регистре
  function walk(node: Element) {
    for (const child of node.children) {
      if (child.tagName === name) result.push(child);
      walk(child);
    }
  }
  walk(root);
  return result;
}
```

В проверке результат совпал с `root.querySelectorAll('p')` и по составу, и по порядку — порядку документа. `querySelector` — первый элемент того же обхода.

## Обход дерева

Посчитать узлы, найти максимальную глубину, собрать теги по уровням — нужны и :term[DFS]{def="обход в глубину: идём до конца ветки, потом возвращаемся"}, и :term[BFS]{def="обход в ширину: по уровням, сначала все ближние узлы"}:

```ts
function dfs(root: Element): Element[] {
  const out: Element[] = [];
  (function visit(node: Element) { out.push(node); for (const child of node.children) visit(child); })(root);
  return out;
}

function bfs(root: Element): Element[] {
  const queue: Element[] = [root];
  for (let i = 0; i < queue.length; i++) queue.push(...queue[i].children); // указатель вместо shift
  return queue;
}

function maxDepth(node: Element): number {
  if (node.children.length === 0) return 1;
  return 1 + Math.max(...[...node.children].map(maxDepth));
}
```

В проверке DFS дал тот же порядок, что встроенный `TreeWalker`, — порядок документа. BFS сначала выдал всех детей корня, потом их детей. Глубина тестового дерева — 3.

Очередь BFS ведут указателем, а не `shift`: `shift` сдвигает все элементы массива. На небольших массивах V8 делает это быстро, но в проверке очередь из 100 000 элементов через `shift` разбиралась 634 мс, а проход указателем — около 3 мс. Встроенный способ обхода — `TreeWalker` и `NodeIterator`, их стоит упомянуть.

## classNames

`classNames` собирает строку классов из строк, объектов и массивов, отбрасывая пустые значения, — та самая `cn` или `clsx` во всех React-проектах:

```ts
type ClassValue = string | number | null | undefined | false | ClassDict | ClassValue[];
interface ClassDict { [key: string]: unknown }

function classNames(...args: ClassValue[]): string {
  const classes: string[] = [];
  for (const arg of args) {
    if (!arg) continue;                                   // falsy пропускаем, включая 0
    if (typeof arg === 'string' || typeof arg === 'number') classes.push(String(arg));
    else if (Array.isArray(arg)) {
      const inner = classNames(...arg);                   // рекурсия для массивов
      if (inner) classes.push(inner);
    } else if (typeof arg === 'object') {
      for (const key of Object.keys(arg)) if (arg[key]) classes.push(key);
    }
  }
  return classes.join(' ');
}
classNames('btn', { active: true, disabled: false }, ['lg', null]); // 'btn active lg'
```

В проверке результат совпал с настоящим `clsx` на пяти разных наборах входов — с вложенными массивами, числами, пустыми строками и объектами. `0` отбрасывается как falsy, а `1` становится классом `'1'`. Одно осознанное отличие: `clsx` перебирает ключи объекта через `for…in` и включает унаследованные, а `Object.keys` — только собственные. В проверке для объекта с ключом в прототипе `clsx` вернул `'own inherited'`, наша версия — `'own'`.

## Красные флаги в ответе

- Обработчик на каждом элементе списка вместо делегирования.
- Делегирование через `event.target.matches(selector)` — клик во вложенный элемент мимо.
- `closest` без `parent.contains` — срабатывание на элементах вне контейнера.
- Делегирование `focus` или `mouseenter` «как обычно» — они не всплывают.
- Свой `getElementsByClassName`, включающий сам корень.
- Обход по `childNodes` с ожиданием только элементов.
- BFS на `shift` для больших деревьев без оговорки о сложности.

## Как спрашивают на собеседовании

::question
Что такое делегирование событий и зачем оно?

#answer
Один обработчик на родителе вместо обработчика на каждом потомке — работает благодаря всплытию. Экономит память и автоматически покрывает элементы, добавленные позже. Внутри цель ищут через `event.target.closest(selector)`, потому что клик мог попасть во вложенный элемент.

#more
Найденную цель проверяют `parent.contains(target)`: `closest` может подняться выше контейнера, и в проверке без этой проверки обработчик сработал на предке вне его. Функцию делегирования стоит делать с отпиской — она возвращает `removeEventListener` для того же слушателя.
::

::question
Чем children отличается от childNodes?

#answer
`children` — только элементы. `childNodes` — все узлы, включая текстовые и комментарии. Для обхода дерева элементов нужен `children`, иначе в обход попадут пробелы и переносы строк между тегами.

#more
Оба — живые коллекции: меняются вместе с DOM. Если во время обхода удалять или добавлять узлы, коллекцию сначала копируют в массив. Аналогично для навигации: `firstElementChild` и `nextElementSibling` идут по элементам, `firstChild` и `nextSibling` — по всем узлам.
::

::question
Что делать, если событие не всплывает?

#answer
Ловить на фазе перехвата — `addEventListener(type, handler, true)` — или брать всплывающие аналоги: `focusin` и `focusout` вместо `focus` и `blur`, `mouseover` и `mouseout` с проверкой цели вместо `mouseenter` и `mouseleave`.

#more
В проверке делегирование `focus` не сработало, а через перехват и `focusin` — да. Фаза перехвата идёт от корня вниз, поэтому родитель получает событие раньше цели, даже если оно не всплывает. Свойство `event.bubbles` показывает, всплывает ли конкретное событие.
::

::question
Как обойти всё DOM-дерево?

#answer
DFS — рекурсией или стеком по `children`, BFS — очередью по уровням. Встроенный способ — `TreeWalker` и `NodeIterator`. DFS даёт порядок документа: в проверке он совпал с `TreeWalker`.

#more
Очередь BFS ведут указателем, а не `shift`: в проверке на 100 000 элементах `shift` занял 634 мс против 3 мс у указателя. На очень глубоких деревьях рекурсия упирается в стек вызовов — тогда DFS делают со своим стеком, как в [глубоких операциях](/content/common-coding-questions/deep-operations).
::

::question
Чем свой getElementsByClassName отличается от нативного?

#answer
Нативный ищет только среди потомков, понимает несколько классов через пробел (`'a b'` — элементы с обоими) и возвращает живую `HTMLCollection`. Простая реализация часто включает сам корень и проверяет один класс.

#more
В проверке исходная версия вернула на один элемент больше — сам корень, — а исправленная совпала с нативной и для одного, и для двух классов. Живая коллекция в проверке выросла после добавления узла, а наш массив — нет: это снимок, и об этом стоит сказать.
::

::question
Как работает утилита classNames или clsx?

#answer
Принимает строки, числа, объекты `{ класс: условие }` и массивы, рекурсивно разбирает массивы, отбрасывает falsy-значения и склеивает оставшиеся классы через пробел. Из объекта класс попадает в результат, если его значение truthy.

#more
В проверке наша версия совпала с `clsx` на всех наборах, кроме объекта с унаследованным ключом: `clsx` перебирает `for…in` и включает его, `Object.keys` — нет. `0` пропускается как falsy — если нужен класс `'0'`, передают строку.
::

## Практика

::practice{title="Клик по иконке в пункте меню не срабатывает"}
Меню обрабатывает клики делегированием, но клик по иконке внутри пункта ничего не делает — только клик по тексту:

```ts
menu.addEventListener('click', (e) => {
  if (e.target.matches('.menu-item')) open(e.target.dataset.id);
});
```

#solution
`e.target` — самый глубокий элемент под курсором, то есть иконка, а не пункт меню, и `matches('.menu-item')` для неё ложно. Ищут ближайший подходящий элемент вверх и проверяют, что он внутри меню:

```ts
menu.addEventListener('click', (e) => {
  const item = e.target.closest('.menu-item');
  if (item && menu.contains(item)) open(item.dataset.id);
});
```

В проверке так обработчик получил `<li>` при клике по `<span>` внутри него. Проверка `menu.contains(item)` нужна на случай, если само меню лежит внутри элемента с тем же классом: в проверке без неё обработчик сработал на внешнем элементе.
::

::practice{title="Подсветка поля при фокусе через делегирование не работает"}
Форма подсвечивает активное поле одним обработчиком на форме, но подсветка не появляется:

```ts
form.addEventListener('focus', (e) => {
  if (e.target.matches('input')) e.target.classList.add('active');
});
```

#solution
`focus` не всплывает — до формы оно не доходит. В проверке такой обработчик не сработал ни разу при фокусе на двух полях. Берут всплывающий аналог или фазу перехвата:

```ts
form.addEventListener('focusin', (e) => {
  if (e.target.matches('input')) e.target.classList.add('active');
});
form.addEventListener('focusout', (e) => {
  if (e.target.matches('input')) e.target.classList.remove('active');
});
// или: form.addEventListener('focus', handler, true)
```

В проверке и `focusin`, и `focus` с `capture: true` сработали на каждом поле. Для чистой подсветки JavaScript не нужен вовсе: `input:focus` и `form:focus-within` в CSS делают то же самое.
::
