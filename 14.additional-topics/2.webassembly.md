# WebAssembly

**WebAssembly (WASM)** - бинарный формат инструкций, который выполняется в браузере на скорости, близкой к нативной. Он позволяет компилировать код на C/C++/Rust/Go и запускать его на веб-странице рядом с JavaScript. Это не замена JS, а **дополнение** для тяжёлых вычислений.

---

## Что это и зачем

JavaScript универсален, но для интенсивных вычислений (обработка видео, 3D, физика) его производительности не всегда хватает. WASM решает это:

- **Скорость** - компилируется в машинно-близкий байткод, выполняется почти как нативный код.
- **Языки** - можно писать на Rust, C++, Go и запускать в браузере.
- **Портативность** - один `.wasm` работает в любом браузере (и на сервере/edge).
- **Безопасность** - выполняется в той же песочнице, что и JS.

```
C / C++ / Rust / Go  ──компиляция──►  module.wasm  ──►  браузер (рядом с JS)
```

---

## Не замена JavaScript

Частое заблуждение. WASM **не вытесняет** JS:

- у WASM **нет прямого доступа к DOM** - вся работа с интерфейсом идёт через JS;
- JS **оркестрирует** приложение (UI, события, сеть), а WASM берёт на себя **вычислительные горячие точки**;
- они вызывают друг друга и работают вместе.

<b class="text-on-semi-light">Модель</b> - <span class="text-gray">JS - «дирижёр» (управляет приложением и DOM), WASM - «тяжёлая артиллерия» для CPU-интенсивных задач. Типичное приложение остаётся на JS, а в WASM выносят конкретные узкие места.</span>

---

## Как работает

```js
const { instance } = await WebAssembly.instantiateStreaming(
  fetch('module.wasm')
);
const result = instance.exports.heavyCompute(42); // вызов экспортированной функции
```

WASM-модуль экспортирует функции, которые JS вызывает как обычные. Память WASM - это **линейный буфер** (`ArrayBuffer`); передача простых чисел тривиальна, а сложных данных (строки, объекты) - через «клей» (glue code), который генерируют инструменты.

---

## Сценарии использования

WASM силён там, где JS буксует:

- **Графические редакторы** - Figma, Photoshop Web (рендеринг, обработка).
- **Видео/аудио** - кодеки, `ffmpeg.wasm` (конвертация в браузере).
- **Игры и 3D** - движки (Unity/Unreal экспортируют в WASM).
- **Крипто и хеширование**, сжатие.
- **БД в браузере** - SQLite через `sql.js`/`wa-sqlite`.
- **Симуляции, CAD, научные расчёты**.
- **ML-инференс** - модели прямо в браузере (ONNX Runtime Web).

---

## Инструменты

| Язык | Тулинг |
|------|--------|
| **Rust** | `wasm-bindgen` + `wasm-pack` (лучший DX для веба) |
| **C / C++** | Emscripten |
| **TypeScript-подобный** | AssemblyScript |
| **Go** | встроенная компиляция в WASM |

`wasm-bindgen` и подобные генерируют JS-обёртки, чтобы передавать строки/объекты без ручной работы с памятью.

---

## WASM за пределами браузера

**WASI** (WebAssembly System Interface) позволяет запускать WASM **вне браузера** - на сервере и на **edge**. Лёгкие, быстро стартующие, безопасные модули WASM используют для serverless/edge-функций (Fastly, Cloudflare) и плагинных систем.

---

## Ограничения

- **Нет прямого DOM** - только через JS-мост.
- **Стоимость загрузки** - `.wasm`-модуль нужно скачать и инстанцировать; для мелких задач это не окупается.
- **Отладка** сложнее, чем JS (хотя source maps для WASM существуют).
- **Передача сложных данных** требует glue-кода.

<b class="text-on-semi-light">Когда НЕ нужен</b> - <span class="text-gray">Для обычного UI, форм, запросов - JavaScript более чем достаточно, а WASM добавит сложности без выигрыша. WASM берут точечно для **вычислительных горячих точек**, измеренных профайлером, а не «для скорости вообще».</span>

## Вопросы на собеседовании

<b class="text-on-semi-light">Что такое WebAssembly?</b>
<span class="text-gray">Бинарный формат инструкций, выполняемый в браузере на скорости, близкой к нативной. Цель компиляции для C/C++/Rust/Go, работает рядом с JS в той же песочнице.</span>

<b class="text-on-semi-light">Заменяет ли WASM JavaScript?</b>
<span class="text-gray">Нет, дополняет. У WASM нет прямого доступа к DOM - UI и оркестрацию делает JS, а WASM берёт вычислительные горячие точки. Они работают вместе.</span>

<b class="text-on-semi-light">Когда стоит использовать WASM?</b>
<span class="text-gray">CPU-интенсивные задачи: обработка изображений/видео, кодеки, игры, крипто, симуляции, ML-инференс. Для обычного UI он избыточен.</span>

<b class="text-on-semi-light">Почему передавать данные между JS и WASM непросто?</b>
<span class="text-gray">Память WASM - линейный буфер; числа передаются легко, а строки/объекты требуют клей-кода (wasm-bindgen), который сериализует их в память и обратно.</span>

<b class="text-on-semi-light">Что такое WASI?</b>
<span class="text-gray">WebAssembly System Interface - стандарт запуска WASM вне браузера (сервер, edge). Лёгкие, быстро стартующие, безопасные модули для serverless и плагинов.</span>
