# Медиа и WebRTC

За пределами тега `<video>` платформа даёт богатый набор API для **захвата, обработки и передачи** медиа: доступ к камере и микрофону, запись, обработка звука и - вершина - **WebRTC** для видеозвонков peer-to-peer. Это специализированная, но впечатляющая область.

> Теги `<audio>`/`<video>` и базовое встраивание медиа - в [HTML](/content/html). Здесь - **JS-API** поверх них.

---

## Захват медиа

`getUserMedia` запрашивает доступ к камере/микрофону и возвращает **MediaStream**.

```js
const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
videoEl.srcObject = stream; // показать поток с камеры
```

- **`getDisplayMedia`** - захват экрана (демонстрация экрана).
- **MediaRecorder** - записать поток в файл (видео/аудио).

```js
const recorder = new MediaRecorder(stream);
recorder.ondataavailable = (e) => chunks.push(e.data);
recorder.start();
```

## Web Audio API

Низкоуровневая работа со звуком: построение **графа аудио-узлов** (источник → эффекты → выход) для обработки, синтеза и визуализации.

```js
const ctx = new AudioContext();
const source = ctx.createMediaElementSource(audioEl);
const gain = ctx.createGain();
source.connect(gain).connect(ctx.destination); // источник → громкость → колонки
```

Применение: музыкальные приложения, эквалайзеры, визуализаторы (через `AnalyserNode`), игры, синтез звука.

## WebRTC

**WebRTC** даёт **peer-to-peer** связь в реальном времени между браузерами - видеозвонки, аудио, демонстрация экрана и произвольные данные (**data channels**) - **без сервера-посредника** для самого медиапотока.

### Как устанавливается соединение

P2P напрямую - сложная задача (NAT, файрволы). WebRTC решает её через несколько механизмов:

```
1. Signaling  - обмен метаданными (SDP) через ВАШ сервер (WebSocket)
2. ICE        - поиск рабочего сетевого пути между пирами
3. STUN       - узнать свой публичный IP (за NAT)
4. TURN       - relay-сервер, если прямое соединение невозможно
→ установлено P2P-соединение, медиа идёт напрямую
```

<b class="text-on-semi-light">Главная тонкость</b> - <span class="text-gray">«P2P без сервера» - не совсем: сам **медиапоток** идёт напрямую между пирами, но для **знакомства** (signaling) нужен твой сервер, чтобы пиры обменялись параметрами (SDP, ICE-кандидаты). А если прямое соединение не проходит (строгий NAT) - трафик идёт через **TURN-relay**. Полностью без серверов WebRTC не работает.</span>

---

## Стриминг

Для **одностороннего** вещания (видео на тысячи зрителей) WebRTC не подходит - используют **адаптивный стриминг**:

- **HLS / DASH** - видео нарезано на сегменты разного качества; плеер переключает битрейт под скорость сети.
- **MSE (Media Source Extensions)** - подавать сегменты в `<video>` из JS; на этом работает `hls.js`, dash.js.
- **WebCodecs** - новый низкоуровневый API кодирования/декодирования кадров (для своих пайплайнов).

> Звонок 1-на-1 или небольшая группа → WebRTC. Трансляция на массу зрителей → HLS/DASH.

---

## На практике - сервисы

Сырой WebRTC сложен (signaling, TURN-инфраструктура, масштабирование на много участников через SFU-серверы). Поэтому в проде берут **сервисы**: **LiveKit**, **Daily**, **Twilio**, **Agora**, **100ms** - они дают готовую инфраструктуру и SDK.

## Сценарии

- Видео/аудиозвонки, конференции, вебинары.
- Демонстрация экрана, совместная работа.
- P2P-передача файлов (data channels).
- Запись с камеры, голосовые сообщения.
- Аудиоприложения, визуализаторы.

## Вопросы на собеседовании

<b class="text-on-semi-light">Что такое WebRTC?</b>
<span class="text-gray">API для peer-to-peer связи в реальном времени между браузерами - видео, аудио, демонстрация экрана, data channels. Медиапоток идёт напрямую между пирами.</span>

<b class="text-on-semi-light">Правда ли WebRTC работает совсем без сервера?</b>
<span class="text-gray">Нет. Медиа идёт P2P, но для знакомства пиров нужен signaling-сервер (обмен SDP/ICE), а при строгом NAT трафик идёт через TURN-relay. Без серверов не обойтись.</span>

<b class="text-on-semi-light">Зачем нужны STUN и TURN?</b>
<span class="text-gray">STUN помогает узнать свой публичный IP за NAT для прямого соединения. TURN - relay-сервер, через который идёт трафик, когда прямое P2P-соединение невозможно.</span>

<b class="text-on-semi-light">Когда WebRTC не подходит?</b>
<span class="text-gray">Для одностороннего вещания на массу зрителей - там используют адаптивный стриминг (HLS/DASH через MSE). WebRTC - для интерактивной двусторонней связи небольших групп.</span>

<b class="text-on-semi-light">Как получить доступ к камере и записать видео?</b>
<span class="text-gray">`getUserMedia` для MediaStream с камеры/микрофона, `MediaRecorder` для записи потока в файл, `getDisplayMedia` для захвата экрана.</span>
