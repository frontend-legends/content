# За пределами фронтенда

Фронтенд - одна из многих областей разработки. Понимать **карту смежных доменов** полезно: чтобы лучше работать с коллегами, осознанно выбирать, куда расти, и видеть, как твои навыки переносятся. Эта глава - не учебник по каждому, а **обзор территории** и путей перехода.

> Кроссплатформа (мобайл/десктоп **на вебе**) разобрана отдельно в [кроссплатформенной разработке](/content/additional-topics/cross-platform). Здесь - домены, требующие **других** языков и подходов.

---

## Карта доменов

| Домен | Языки/стек | Близость к фронтенду |
|-------|-----------|----------------------|
| **Backend** | Node, Go, Python, Java, Rust | очень близко (особенно Node) |
| **Browser extensions** | JS + web API | это и есть веб-стек |
| **Native mobile** | Swift, Kotlin | средне (или RN) |
| **Game dev** | C#, C++, GDScript | далеко (другая парадигма) |
| **Web3** | Solidity + JS | средне (фронт + контракты) |
| **AI/ML** | Python | далеко (математика, данные) |
| **DevOps/SRE** | YAML, Go, Bash | средне (касается деплоя) |
| **Embedded/IoT** | C, C++ | далеко (железо) |

---

## Backend - ближайший шаг

Самый естественный рост фронтендера - в **fullstack**. Ты уже знаешь JavaScript/Node, асинхронность, HTTP, JSON. Остаётся: проектирование API, базы данных (SQL/NoSQL), авторизация, бизнес-логика, очереди.

- **Node.js** (Express, Fastify, NestJS) - меньше всего нового, тот же язык.
- **Go**, **Python** (FastAPI/Django), **Java/Kotlin**, **Rust** - если хочется дальше.

<b class="text-on-semi-light">Почему легко</b> - <span class="text-gray">С Node фронтендер пишет бэкенд на том же языке. Многое уже знакомо (модули, npm, async). Главное новое - данные (БД, транзакции, индексы - см. [интро в БД](/content/computer-science)) и серверная архитектура. Fullstack - самый востребованный и доступный путь расширения.</span>

---

## Browser extensions - почти фронтенд

Расширения браузера пишут на **обычном веб-стеке** (HTML/CSS/JS) - ближе всего к твоим навыкам. Специфика - архитектура **Manifest V3**: content scripts (внедряются в страницы), background service worker, ограничения безопасности, кросс-браузерность (Chrome/Firefox API). Низкий порог входа для фронтендера.

---

## Native mobile

Нативная мобильная разработка - **iOS** (Swift, SwiftUI) и **Android** (Kotlin, Jetpack Compose). Интересно, что современные нативные UI-фреймворки (SwiftUI, Compose) **декларативные** - идейно близки к React, так что ментальная модель переносится. Альтернатива без смены языка - [React Native](/content/additional-topics/cross-platform).

---

## Game development

Совсем другая парадигма: вместо «UI = f(state)» - **игровой цикл** (60 раз в секунду обновляй и рисуй мир), физика, ECS-архитектура.

- **Unity** (C#), **Unreal** (C++), **Godot** (GDScript/C#).
- **Веб-игры** - через [Canvas/WebGL](/content/additional-topics/graphics-canvas-webgl), Three.js, PixiJS - тут фронтенд-навыки пригодятся напрямую.

---

## Web3 / блокчейн

Децентрализованные приложения (**dApps**): логика - в **смарт-контрактах** (Solidity на Ethereum), а фронтенд - привычный React, который **подключается к блокчейну** через кошелёк (MetaMask) и библиотеки (**viem/wagmi, ethers.js**).

<b class="text-on-semi-light">Роль фронтендера</b> - <span class="text-gray">Фронт остаётся фронтом (React), но взаимодействует не с REST API, а с блокчейном: подключение кошелька, подпись транзакций, чтение состояния контракта. Новое - концепции цепочки (газ, транзакции, кошельки), не язык интерфейса.</span>

---

## AI / ML инженерия

В отличие от [интеграции AI в приложения](/content/additional-topics/ai-in-the-frontend) (где фронт строит UI), **ML-инженерия** - это **обучение и развёртывание моделей**: Python, математика, работа с данными, MLOps. Далеко от фронтенда по навыкам, но смежно через AI-функции в продуктах.

---

## DevOps / SRE / Platform

Инфраструктура, на которой всё работает: облака (AWS/GCP), контейнеры и **Kubernetes**, CI/CD, мониторинг, надёжность. Фронтендер уже касается этого в [деплое](/content/testing-deploying) и [тулинге](/content/advanced-tooling) - DevOps углубляет эту сторону. Платформенные команды строят инструменты для других разработчиков.

---

## Embedded / IoT и системное

- **Embedded/IoT** - программирование микроконтроллеров и устройств на **C/C++** в условиях жёстких ограничений по памяти и питанию. Далеко от веба, ближе к железу.
- **Системное/низкоуровневое** - ОС, компиляторы, движки на **Rust/C/C++**. Связано с фронтендом неожиданно через [тулинг на Rust](/content/advanced-tooling/rust-and-the-future): esbuild, SWC, Turbopack пишут именно системные инженеры.

---

## Как переходить

<b class="text-on-semi-light">Переносимые навыки</b> - <span class="text-gray">Многое не привязано к фронтенду и едет с тобой: алгоритмическое мышление, Git, отладка, чтение чужого кода, работа с API, инженерная дисциплина (тесты, ревью), сам JavaScript (Node, расширения, RN, web3-фронты, веб-игры). Поэтому шаги «вбок» проще, чем кажется.</span>

Стратегия: начни с **ближайшего** (backend через Node, расширения, веб-игры на Canvas), наращивай по одному новому измерению (новый язык **или** новая парадигма, не всё сразу).

> Цель - не стать всем сразу, а быть **T-образным** инженером: глубина во фронтенде + широкое понимание соседних областей. Это делает тебя сильнее в команде и устойчивее в карьере - и это финальная идея всего справочника: видеть систему целиком.

## Вопросы на собеседовании

<b class="text-on-semi-light">Какой переход из фронтенда самый естественный?</b>
<span class="text-gray">В backend/fullstack через Node.js - тот же язык и многое знакомо (async, npm, HTTP). Новое - базы данных и серверная архитектура. Самый востребованный и доступный путь.</span>

<b class="text-on-semi-light">Чем разработка игр принципиально отличается от UI?</b>
<span class="text-gray">Вместо «UI = f(state)» - игровой цикл (постоянное обновление и отрисовка мира 60 раз/с), физика, ECS. Другая парадигма; веб-навыки переносятся только в веб-играх (Canvas/WebGL).</span>

<b class="text-on-semi-light">Какова роль фронтендера в web3?</b>
<span class="text-gray">Тот же React, но вместо REST API - взаимодействие с блокчейном через кошелёк и библиотеки (viem/wagmi): подключение кошелька, подпись транзакций, чтение контрактов. Логика - в смарт-контрактах (Solidity).</span>

<b class="text-on-semi-light">Какие навыки переносятся в другие домены?</b>
<span class="text-gray">Алгоритмическое мышление, Git, отладка, работа с API, тесты, сам JavaScript (Node, расширения, RN, web3). «Шаги вбок» проще, чем кажется, благодаря переносимой базе.</span>

<b class="text-on-semi-light">Что значит быть T-образным инженером?</b>
<span class="text-gray">Глубина в одной области (фронтенд) плюс широкое понимание смежных. Делает сильнее в команде, устойчивее в карьере и помогает видеть систему целиком.</span>
