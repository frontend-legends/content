# Графика: Canvas и WebGL

Когда DOM и CSS не справляются - сложные визуализации, игры, 3D, обработка изображений - в дело идут графические примитивы платформы: **SVG**, **Canvas**, **WebGL** и **WebGPU**. Понимать спектр и ключевое различие **SVG vs Canvas** - частый вопрос про графику.

> Готовые библиотеки графики (Three.js, Recharts, D3) - в [визуализации данных](/content/ecosystem-libs/data-visualization). Здесь - **платформенные примитивы** под ними.

---

## Спектр графики

```
DOM/CSS  →  SVG  →  Canvas 2D  →  WebGL  →  WebGPU
декларативно        императивно   GPU       GPU (новый)
мало элементов      много         3D/тысячи объектов
```

Чем правее - тем больше элементов и производительности, но меньше удобства и доступности.

---

## SVG

**Векторная** графика на основе DOM: каждый элемент (`<circle>`, `<path>`) - узел в дереве, который можно стилизовать CSS, навешивать события и анимировать.

```html
<svg viewBox="0 0 100 100">
  <circle cx="50" cy="50" r="40" fill="tomato" />
</svg>
```

- **Плюсы:** масштабируется без потери качества, доступна (можно добавить ARIA), стилизуется CSS, элементы интерактивны (события на каждом).
- **Минусы:** каждый элемент - узел DOM, поэтому **тормозит на тысячах** объектов.

Идеальна для иконок, логотипов, графиков с десятками-сотнями элементов.

---

## Canvas 2D

**Растровая**, immediate-mode графика: ты императивно **рисуешь пиксели** на одном `<canvas>`-элементе. После отрисовки браузер не помнит «фигуры» - только пиксели.

```js
const ctx = canvas.getContext('2d');
ctx.fillStyle = 'tomato';
ctx.beginPath();
ctx.arc(50, 50, 40, 0, Math.PI * 2);
ctx.fill();
```

- **Плюсы:** быстро рисует **много** объектов (один DOM-узел вместо тысяч), хорош для динамики (игры, частицы, обработка изображений по пикселям).
- **Минусы:** **нет DOM** - нет встроенной доступности и событий на фигурах (попадание по клику считаешь сам), при ресайзе нужно перерисовывать.

---

## SVG vs Canvas

Ключевое сравнение для собеса.

| | SVG | Canvas |
|--|-----|--------|
| Модель | retained (DOM-дерево) | immediate (пиксели) |
| Масштабирование | без потерь (вектор) | пикселизуется (растр) |
| Доступность | да (ARIA, фокус) | нет (вручную) |
| События на элементах | да | нет (свой hit-test) |
| Много элементов | тормозит | быстро |
| Стилизация | CSS | только через API |

<b class="text-on-semi-light">Правило выбора</b> - <span class="text-gray">**Мало** элементов, нужны интерактивность/доступность/масштабирование → **SVG**. **Тысячи** объектов, динамика, обработка пикселей → **Canvas**. Это та же дихотомия, что в [визуализации](/content/ecosystem-libs/data-visualization): Recharts (SVG) для обычных графиков, Canvas/WebGL для больших данных.</span>

---

## WebGL

Низкоуровневый доступ к **GPU** (на основе OpenGL ES) для аппаратно-ускоренной 2D и **3D** графики. Работаешь с шейдерами (программами на GPU), буферами вершин - мощно, но сложно.

Применение: 3D-сцены, тысячи частиц, тяжёлые визуализации, игры, карты. Писать на «голом» WebGL тяжело, поэтому используют обёртки: **Three.js / React Three Fiber** (3D), **PixiJS** (быстрая 2D), **deck.gl** (гео-визуализация).

---

## WebGPU

**Современный преемник** WebGL: ниже накладные расходы, доступ к **compute-шейдерам** (вычисления общего назначения на GPU), API в духе современных графических (Vulkan/Metal). Это будущее веб-графики и GPU-вычислений (включая ML в браузере). Постепенно появляется во всех браузерах.

---

## OffscreenCanvas

Рендеринг Canvas/WebGL можно вынести в **Web Worker** через `OffscreenCanvas`, чтобы тяжёлая отрисовка не блокировала главный поток ([Web Workers](/content/additional-topics/web-workers-and-concurrency)).

---

## Как выбрать

```
Иконки, логотипы, простые графики     → SVG
Графики с тысячами точек, обработка    → Canvas 2D
3D, частицы, игры, тяжёлая визуализация → WebGL (Three.js / PixiJS)
GPU-вычисления, будущее                → WebGPU
```

## Вопросы на собеседовании

<b class="text-on-semi-light">В чём ключевое различие SVG и Canvas?</b>
<span class="text-gray">SVG - векторный retained-mode на DOM: масштабируется, доступен, элементы интерактивны, но тормозит на тысячах. Canvas - растровый immediate-mode: быстрый для множества объектов и пиксельной работы, но без DOM, доступности и событий на фигурах.</span>

<b class="text-on-semi-light">Когда выбрать SVG, а когда Canvas?</b>
<span class="text-gray">SVG - мало элементов, нужны интерактивность/масштабирование/a11y (иконки, простые графики). Canvas - тысячи объектов, динамика, обработка пикселей (игры, большие визуализации).</span>

<b class="text-on-semi-light">Зачем нужен WebGL?</b>
<span class="text-gray">Аппаратно-ускоренная 2D/3D-графика на GPU через шейдеры - для 3D, частиц, тяжёлых визуализаций и игр. Обычно используют обёртки (Three.js, PixiJS).</span>

<b class="text-on-semi-light">Чем WebGPU отличается от WebGL?</b>
<span class="text-gray">Современный преемник: ниже накладные расходы, доступ к compute-шейдерам (вычисления на GPU), API в духе Vulkan/Metal. Будущее веб-графики и GPU-вычислений.</span>

<b class="text-on-semi-light">Как не заблокировать UI тяжёлой графикой?</b>
<span class="text-gray">OffscreenCanvas - вынести рендеринг Canvas/WebGL в Web Worker, чтобы отрисовка шла вне главного потока.</span>
