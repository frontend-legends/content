# Кроссплатформенная разработка

Веб-навыки переносимы: на JavaScript, React и вебе можно делать **мобильные** и **десктопные** приложения. Это позволяет фронтендеру выйти за пределы браузера, переиспользуя знания. Главное - понимать спектр подходов: **нативный UI** vs **webview**.

---

## Спектр подходов

```
нативный UI ◄──────────────────────────► webview (веб внутри обёртки)
React Native        Flutter      Capacitor/Ionic    Electron/Tauri    PWA
(нативные виджеты)  (свой движок) (web в webview)   (web на десктопе) (браузер)
```

Чем левее - тем «нативнее» ощущается и быстрее, но дальше от веба. Чем правее - тем ближе к обычному веб-стеку, но компромисс в нативности.

---

## Мобайл

### React Native

Пишешь компоненты на React, но они рендерятся в **настоящие нативные виджеты** (не webview). Тот же React, хуки, JS - но `<View>`/`<Text>` вместо `<div>`/`<span>`.

```jsx
import { View, Text, Pressable } from 'react-native';

function Counter() {
  const [n, setN] = useState(0);
  return (
    <View>
      <Text>{n}</Text>
      <Pressable onPress={() => setN(n + 1)}><Text>+</Text></Pressable>
    </View>
  );
}
```

<b class="text-on-semi-light">Плюсы и нюансы</b> - <span class="text-gray">Переиспользуешь знание React, один код под iOS и Android, нативная производительность UI. Новая архитектура (JSI/Fabric) убрала старый «мост» между JS и нативом. **Expo** - тулчейн, упрощающий сборку и доступ к нативным API. Минусы: тонкости под каждую платформу всё равно есть, тяжёлые нативные модули иногда нужно писать самому.</span>

### Capacitor / Ionic

Берут **обычное веб-приложение** и упаковывают в нативную обёртку с **webview** + доступом к нативным API (камера, геолокация) через плагины. Ближе всего к «мой веб-сайт стал приложением».

### Flutter

Альтернатива на **Dart** (не JS): свой движок рендеринга рисует UI сам. Не использует веб-навыки напрямую, но популярен в кроссплатформе - стоит знать о существовании.

---

## Десктоп

### Electron

Упаковывает **Chromium + Node.js** вместе с твоим веб-приложением в десктопное. На нём построены **VS Code, Slack, Discord, Figma**.

<b class="text-on-semi-light">Компромисс Electron</b> - <span class="text-gray">Плюс - полноценный веб-стек и доступ к ОС через Node; один код под Windows/Mac/Linux. Минус - **тяжёлый**: каждое приложение тащит **целый браузер** (100+ МБ, заметное потребление памяти), потому что не использует системный webview.</span>

### Tauri

Современная альтернатива: бэкенд на **Rust** + **системный webview** ОС (не бандлит Chromium). Поэтому приложения **в разы меньше и легче** Electron (мегабайты вместо сотен), безопаснее. Растущий выбор, когда важен размер.

| | Electron | Tauri |
|--|----------|-------|
| Рантайм | свой Chromium + Node | системный webview + Rust |
| Размер | сотни МБ | единицы МБ |
| Зрелость | очень зрелый | новее, растёт |

---

## PWA как приложение

Самый лёгкий путь: **PWA** ([Web/PWA](/content/web)) можно «установить» на телефон/десктоп без магазина приложений - иконка, офлайн, push. Не нужна обёртка вообще, но доступ к нативным возможностям ограничен тем, что даёт браузер.

---

## Переиспользование кода

Главная ценность - **один стек на несколько платформ**. React-знание работает в вебе и React Native; логику (хуки, утилиты, типы, API-слой) шарят через [монорепо](/content/advanced-tooling/monorepo-tooling). UI обычно адаптируют под платформу, а бизнес-логику переиспользуют.

---

## Как выбрать

```
Мобильное приложение, нативный UX     → React Native (+ Expo)
Веб-сайт → быстро в сторы              → Capacitor
Десктоп, не критичен размер           → Electron
Десктоп, важен лёгкий размер           → Tauri
Минимум усилий, без магазинов          → PWA
```

## Вопросы на собеседовании

<b class="text-on-semi-light">Чем React Native отличается от Capacitor/Ionic?</b>
<span class="text-gray">React Native рендерит настоящие нативные виджеты (не webview) - ближе к нативному UX и производительности. Capacitor упаковывает веб-приложение в webview-обёртку с плагинами к нативным API.</span>

<b class="text-on-semi-light">Чем Tauri лучше Electron?</b>
<span class="text-gray">Tauri использует системный webview и бэкенд на Rust вместо бандла Chromium+Node, поэтому приложения в разы меньше и легче (мегабайты вместо сотен) и безопаснее. Electron зрелее и тащит полный браузер.</span>

<b class="text-on-semi-light">Почему Electron-приложения такие тяжёлые?</b>
<span class="text-gray">Каждое включает целый Chromium и Node.js, а не использует системный браузер - отсюда 100+ МБ и высокое потребление памяти.</span>

<b class="text-on-semi-light">Как переиспользовать код между вебом и мобайлом?</b>
<span class="text-gray">Шарить логику (хуки, утилиты, типы, API-слой) через монорепо; React-знание переносится в React Native. UI адаптируют под платформу, бизнес-логику переиспользуют.</span>

<b class="text-on-semi-light">Когда достаточно PWA вместо нативного приложения?</b>
<span class="text-gray">Когда хватает возможностей браузера и не нужен магазин: установка с иконкой, офлайн и push есть, но доступ к нативным API ограничен.</span>
