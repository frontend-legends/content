# ИИ во фронтенде

Как встроить языковую модель в продукт: что делает фронтенд, почему ключ живёт только на сервере, потоковый ответ и его ловушки, отмена генерации, структурированный ответ по схеме, вызов инструментов, поиск по смыслу и RAG, AI SDK, интерфейс и безопасность, модели в браузере. Спрашивают, можно ли держать ключ на клиенте, зачем стримить ответ и что такое RAG. Глубже — откуда «кракозябры» в потоковом ответе, почему кнопка «Стоп» должна останавливать сервер и почему ответу модели нельзя верить без схемы.

::tldr
- **Ключ модели — только на сервере:** клиент ходит в свой эндпоинт, а тот добавляет ключ, авторизацию, лимиты и учёт расходов. Ключ в бандле — чужой счёт на твои деньги.
- **Ответ стримят:** первые слова появляются через десятки миллисекунд вместо ожидания всего ответа. Поток читают через `response.body` с декодером в режиме потока — иначе многобайтовые символы на стыке фрагментов превращаются в `�`.
- **«Стоп» — это отмена запроса,** которая доходит до сервера и прекращает генерацию, а не просто скрывает текст.
- **Ответу модели не верят:** структурированный ответ проверяют схемой, инструменты выполняют только из белого списка, текст выводят без HTML или через санитайзер.
- **RAG — ответы по своим данным:** найти близкие по смыслу фрагменты через векторы и подложить их в запрос. Модели в браузере — для приватности и офлайна, ценой размера.
::

## Что делает фронтенд

Сквозной пример — ассистент магазина: отвечает на вопросы о чае, подбирает товары, проверяет наличие на складе и составляет карточку товара для админки.

Модель работает у провайдера или на своих серверах. Задачи фронтенда:

- **интерфейс** — чат, подсказки при вводе, генерация прямо в поле формы, кнопка «улучшить текст»;
- **поток** — показывать ответ по мере генерации;
- **состояние диалога** — история, повтор, редактирование вопроса, остановка;
- **состояния** — отправлено, генерируется, ошибка, превышен лимит;
- **безопасность** — что можно показать и что можно выполнить из ответа модели.

Как ИИ помогает самой разработке — ассистенты, агенты в редакторе — разобрано в [ИИ в разработке](/content/modern-dev/ai-assisted-development) и [Агентах и MCP](/content/modern-dev/ai-agents-and-mcp). Здесь — модель как часть продукта.

## Ключ на сервере

Ключ API модели — это деньги: оплата идёт за каждый токен. Клиентский бандл публичен (подробно — в [Окружениях и конфигурации](/content/testing-deploying/environments-and-config)), поэтому ключ в нём — то же, что опубликованный.

```text
браузер → POST /api/chat (своя сессия) → сервер: ключ, авторизация, лимит → провайдер модели
```

Сервер-посредник делает то, чего не может клиент:

- хранит ключ и выбирает модель;
- проверяет пользователя и права;
- ограничивает частоту и объём — на пользователя и на всех, чтобы один скрипт не сжёг месячный бюджет за ночь;
- добавляет системные инструкции и контекст, которые пользователь не должен видеть и менять;
- пишет журнал расходов и ошибок.

В проверке клиент обращался к своему `/api/chat` и не отправлял никакого ключа — его знал только сервер.

## Поток

Модель генерирует ответ постепенно, и полный ответ может идти секунды. Ждать его целиком — плохо; ответ передают **потоком**, обычно в формате SSE (подробно о транспортах — в [Реалтайме](/content/network-api/realtime)).

В проверке первый фрагмент пришёл примерно через 26 мс, а весь ответ — через 324 мс. Для настоящей модели разница — доли секунды против нескольких секунд, и именно она даёт ощущение скорости.

### Чтение потока

`EventSource` умеет только `GET` без тела, а запросу к модели нужны история диалога и заголовки — поэтому поток читают через `fetch`:

```js
const res = await fetch('/api/chat', { method: 'POST', body: JSON.stringify({ messages }) });
const reader = res.body.pipeThrough(new TextDecoderStream()).getReader();

for (;;) {
  const { value, done } = await reader.read();
  if (done) break;
  feed(value);   // разбор событий и дописывание текста
}
```

### Разорванные символы

Сеть режет поток на фрагменты где угодно — в том числе посреди символа. Русская буква в UTF-8 занимает два байта. В проверке «Пуэр», разрезанное посреди «у» и декодированное по фрагментам отдельно, превратилось в `П��эр`. Декодер в режиме потока хранит неполный символ до следующего фрагмента:

```js
const decoder = new TextDecoder();
text += decoder.decode(chunk, { stream: true });
```

`TextDecoderStream` делает это сам. В проверке тот же разрыв с `stream: true` дал «Пуэр».

### Разорванные события

По той же причине событие SSE может прийти половиной. Разбор копит буфер и выдаёт событие только после пустой строки:

```js
let buffer = '';
function feed(text) {
  buffer += text;
  let i;
  while ((i = buffer.indexOf('\n\n')) !== -1) {
    const event = buffer.slice(0, i);
    buffer = buffer.slice(i + 2);
    handle(event);
  }
}
```

В проверке событие, разрезанное посреди JSON — `data: {"delta":"Пу` и `эр"}`, — собралось правильно. Готовые клиенты — AI SDK, `@microsoft/fetch-event-source`, SDK провайдеров — делают это сами.

## Остановка генерации

Кнопка «Стоп» должна отменять запрос, а не прятать текст: иначе модель продолжает генерировать, а ты — платить за токены, которых никто не увидит.

```js
const controller = new AbortController();
fetch('/api/chat', { method: 'POST', body, signal: controller.signal });
stopButton.onclick = () => controller.abort();
```

В проверке после отмены сервер увидел закрытое соединение и прекратил отправку, не дойдя до конца ответа. На сервере отмену передают дальше — в запрос к провайдеру через тот же `AbortSignal`, — иначе остановится только последний участок пути.

## Структурированный ответ

Когда ответ нужен не человеку, а коду — карточка товара, фильтры поиска, разметка категорий, — его просят в JSON по схеме и **проверяют**:

```js
const Product = z.object({
  title: z.string(),
  price: z.number().positive(),
  tags: z.array(z.string()).max(5),
});
```

В проверке правильный JSON прошёл схему, а типичные ответы модели — нет: JSON в обёртке из markdown упал в `JSON.parse`, а цена строкой `'1200 ₽'` не прошла `z.number()`. Провайдеры умеют ограничивать ответ схемой, но проверка на своей стороне остаётся: модель — внешний источник данных, как любой API (подробно о схемах — в [Формах и валидации](/content/ecosystem-libs/forms-and-validation)). При ошибке — повтор с сообщением об ошибке или запасной вариант в интерфейсе.

## Вызов инструментов

Модель может вернуть не текст, а просьбу вызвать функцию — «проверь наличие товара 7». Код выполняет её, отдаёт результат модели, и она продолжает:

```text
вопрос → модель: вызвать getStock({ id: 7 }) → код выполняет → результат → модель: «На складе 3 упаковки»
```

Главное правило — модель **предлагает**, код **решает**. В проверке модель в цикле попросила `getStock` и `deleteAllOrders`. Выполнилась только `getStock` из белого списка, а на вторую модель получила ответ «не разрешён» и закончила текстом «На складе 3 упаковки». Аргументы проверяют схемой, действия с последствиями — оплату, удаление, отправку письма — подтверждает пользователь, а инструменты выполняются с правами пользователя, а не сервера. Подробнее о циклах агентов — в [Агентах и MCP](/content/modern-dev/ai-agents-and-mcp).

## Поиск по смыслу и RAG

Модель не знает каталог, условия доставки и правила возврата конкретного магазина. **RAG** — генерация с поиском — подкладывает нужные знания в запрос:

```text
подготовка: документы → фрагменты → векторы (эмбеддинги) → векторное хранилище
запрос:     вопрос → вектор → ближайшие фрагменты → в запрос к модели → ответ по ним
```

**Эмбеддинг** — вектор, отражающий смысл текста: близкие по смыслу тексты дают близкие векторы. Близость обычно считают косинусом угла между векторами. В проверке на игрушечных трёхмерных векторах вопрос «когда привезут заказ» оказался ближе всего к «Срокам доставки по России» — с близостью больше 0,95, — хотя общих слов у них нет.

Векторное хранилище и подготовку документов обычно делает бэкенд — pgvector, Qdrant, встроенные хранилища облаков. Фронтенду важно понимать идею: почему ответ ссылается на источники, почему он может быть устаревшим, и показывать пользователю, на какие документы опирается ответ.

## AI SDK

**AI SDK** от Vercel — библиотека с общим API для разных провайдеров, потоками и хуками для интерфейса. Сервер:

```ts
import { streamText, convertToModelMessages } from 'ai';

export async function POST(req: Request) {
  const { messages } = await req.json();
  const result = streamText({ model, messages: await convertToModelMessages(messages) });
  return result.toUIMessageStreamResponse();
}
```

Клиент:

```tsx
import { useChat } from '@ai-sdk/react';

function Chat() {
  const { messages, sendMessage, status, stop } = useChat();
  return (
    <>
      {messages.map((m) => (
        <p key={m.id}>
          {m.parts.map((part, i) => (part.type === 'text' ? <span key={i}>{part.text}</span> : null))}
        </p>
      ))}
      {status === 'streaming' && <button onClick={stop}>Стоп</button>}
    </>
  );
}
```

В проверке AI SDK 7 с тестовой моделью отдал ответ как поток событий — `Content-Type: text/event-stream`, события `text-delta` с фрагментами «Пуэр — » и «чай», затем `finish`. Структурированный ответ через `Output.object` со схемой прошёл для правильного JSON, а для цены строкой — бросил `NoObjectGeneratedError`. Тестовые модели из `ai/test` позволяют проверять такой код без вызова настоящей модели.

| Версии в проверке | |
| --- | --- |
| `ai` | 7.0 |
| сообщения в интерфейсе | массив `parts`, а не строка `content`, как в старых версиях |

Актуально на ноябрь 2026. API AI SDK заметно менялся между мажорными версиями, поэтому примеры из старых статей часто не работают.

## Интерфейс и безопасность

### Состояния

- **отправлено** — сообщение пользователя видно сразу, ответ ещё не начался;
- **генерируется** — индикатор, кнопка «Стоп», прокрутка за новым текстом без рывков;
- **готово** — повторить, скопировать, оценить ответ;
- **ошибка** — понятное сообщение и повтор; отдельно — превышен лимит;
- **частичный ответ** при обрыве — показать, что ответ неполный.

Ответ модели часто в markdown: его отрисовывают безопасным парсером, а поток с незакрытыми блоками кода — так, чтобы разметка не прыгала (подробно о markdown и XSS — в [Контенте и взаимодействиях](/content/ecosystem-libs/rich-content-and-interactions)).

### Внедрение инструкций

**Prompt injection** — текст, который переписывает инструкции модели: в вопросе пользователя, в отзыве о товаре, попавшем в контекст через RAG, на странице, которую модель читает. Полностью от этого не защититься фильтрами, поэтому строят так, чтобы последствия были ограничены:

- вывод модели — недоверенные данные: без `dangerouslySetInnerHTML` и `v-html`, ссылки и картинки — через проверку;
- инструменты — из белого списка, с правами пользователя, опасные действия — с подтверждением;
- секреты и чужие данные не попадают в контекст, который пользователь может «вытащить» вопросом.

### Цена и задержка

Токены стоят денег и времени: ограничивают длину истории и ответа, кешируют одинаковые запросы, выбирают модель под задачу — маленькую для подсказок при вводе, большую для сложных ответов.

## Модели в браузере

Небольшие модели запускаются прямо в браузере — **Transformers.js**, **WebLLM**, ONNX Runtime Web — через WebGPU и WebAssembly (подробно — в [WebAssembly](/content/additional-topics/webassembly) и [Графике](/content/additional-topics/graphics-canvas-webgl)). Браузеры добавляют и встроенные модели с API для перевода, суммаризации и подсказок.

| Плюсы | Минусы |
| --- | --- |
| данные не уходят с устройства | модели весят от десятков мегабайт до гигабайт |
| нет оплаты за токены | качество ниже больших серверных моделей |
| работает офлайн | зависит от устройства и поддержки WebGPU |

Подходит для распознавания и классификации, эмбеддингов для поиска по локальным данным, подсказок при вводе и задач, где приватность важнее качества.

## Красные флаги в ответе

- **«Положу ключ в переменную `VITE_`».** Он окажется в бандле и в чужих руках.
- **«Подожду полный ответ и покажу».** Потеря ощущения скорости; ответ стримят.
- **«Декодирую каждый фрагмент отдельно».** Символы на стыке фрагментов превращаются в `�`.
- **«Стоп — просто перестану показывать текст».** Модель продолжит генерировать за твой счёт.
- **«Модель вернёт правильный JSON».** Проверяют схемой и обрабатывают ошибку.
- **«Модель сама решит, какие функции вызвать».** Выполняется только белый список с правами пользователя.

## Как спрашивают на собеседовании

::question
Можно ли хранить ключ API модели на фронтенде?

#answer
Нет. Клиентский бандл публичен, а ключ — это оплата за токены. Клиент обращается к своему эндпоинту, а сервер хранит ключ, проверяет пользователя, ограничивает частоту и объём запросов и ведёт учёт расходов.

#more
Сервер же добавляет системные инструкции и контекст, которые пользователь не должен видеть и менять, и передаёт отмену запроса провайдеру.
::

::question
Зачем стримить ответ модели и как его читать?

#answer
Модель генерирует ответ постепенно, и поток показывает первые слова почти сразу вместо ожидания всего ответа. Читают через `fetch` и `response.body` — `EventSource` не умеет `POST` с телом.

#more
Декодер должен работать в режиме потока — `TextDecoderStream` или `decode(chunk, { stream: true })`, — иначе многобайтовые символы на стыке фрагментов ломаются. События SSE собирают в буфер до пустой строки.
::

::question
Как правильно сделать кнопку «Стоп»?

#answer
Отменять запрос через `AbortController`, чтобы закрытие соединения дошло до сервера, а сервер передал отмену в запрос к провайдеру. Тогда генерация действительно прекращается.

#more
Если только скрыть текст, модель продолжит генерировать, и расходы останутся. Частичный ответ в интерфейсе помечают как остановленный.
::

::question
Что такое RAG?

#answer
Генерация с поиском: документы режут на фрагменты и превращают в векторы, при вопросе находят ближайшие по смыслу фрагменты и подкладывают их в запрос, чтобы модель отвечала по своим данным без дообучения.

#more
Близость считают косинусом между векторами, хранят их в векторной базе. Качество зависит от нарезки и поиска; в интерфейсе полезно показывать источники ответа.
::

::question
Что такое вызов инструментов и как сделать его безопасным?

#answer
Модель возвращает просьбу вызвать функцию с аргументами, код выполняет её и отдаёт результат модели. Безопасность — в коде: только белый список функций, проверка аргументов схемой, права пользователя и подтверждение опасных действий.

#more
Модель может попросить что угодно — в том числе под влиянием внедрённых инструкций, — поэтому решение о выполнении всегда за кодом, а не за моделью.
::

::question
Какой риск безопасности специфичен для ИИ-функций?

#answer
Внедрение инструкций: текст пользователя, документа или страницы переписывает поведение модели. Поэтому её вывод считают недоверенными данными, а возможности ограничивают.

#more
Вывод — без вставки как HTML, инструменты — из белого списка с подтверждением, секреты — вне контекста. Полностью отфильтровать внедрения нельзя, можно только ограничить последствия.
::

## Практика

::practice{title="Кракозябры в потоковом ответе"}
Ассистент магазина изредка показывает в ответе символы `�` посреди русских слов. В логах сервера текст правильный.

```js
const reader = res.body.getReader();
for (;;) {
  const { value, done } = await reader.read();
  if (done) break;
  text += new TextDecoder().decode(value);
}
```

#solution
Новый декодер на каждый фрагмент не знает о байтах, оставшихся от предыдущего. Когда сеть режет поток посреди двухбайтовой буквы, обе половины декодируются как `�`. В проверке «Пуэр» с разрывом посреди «у» дало `П��эр`.

```js
const reader = res.body.pipeThrough(new TextDecoderStream()).getReader();
for (;;) {
  const { value, done } = await reader.read();
  if (done) break;
  feed(value);   // уже строка, неполные символы декодер держит у себя
}
```

С декодером в режиме потока в проверке получилось «Пуэр». Ошибка редкая, потому что зависит от того, где сеть разрежет данные, — поэтому её и не ловят локально.
::

::practice{title="«Стоп» не экономит деньги"}
После нажатия «Стоп» текст в чате перестаёт появляться, но в отчёте провайдера длина ответов не уменьшилась.

#solution
Кнопка только перестаёт дописывать текст, а запрос продолжает жить: модель генерирует ответ до конца. Отмену нужно провести через всю цепочку:

```js
// клиент
const controller = new AbortController();
const res = await fetch('/api/chat', { method: 'POST', body, signal: controller.signal });
stopButton.onclick = () => controller.abort();
```

```js
// сервер: закрытие соединения клиентом отменяет запрос к провайдеру
const result = streamText({ model, messages, abortSignal: req.signal });
```

В проверке после отмены сервер увидел закрытое соединение и перестал отправлять фрагменты. С AI SDK на клиенте то же даёт `stop()` из `useChat`.
