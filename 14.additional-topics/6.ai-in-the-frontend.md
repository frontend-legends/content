# AI во фронтенде

AI-функции стали обычной частью продуктов: чат-ассистенты, генерация текста, семантический поиск, «копилоты». Задача фронтенда - **встроить LLM в приложение**: построить UI, вызвать модель, **стримить** ответ и управлять состоянием диалога. Это растущая тема интервью 2025–2026.

> Здесь - **интеграция AI в приложения**. AI-ассистированная **разработка** (Copilot, AI-инструменты в работе инженера) - в [современной разработке](/content/modern-dev).

---

## Роль фронтенда

Сам LLM живёт на сервере провайдера (OpenAI, Anthropic, Google) или у тебя. Фронтенд:

- строит **интерфейс** AI-функции (чат, инлайн-генерация, автодополнение);
- **отправляет** запросы к модели и **стримит** ответы токен за токеном;
- управляет **состоянием диалога** (история, контекст, прерывание);
- обрабатывает загрузку, ошибки, повторы, лимиты.

---

## Главное правило: ключи на сервере

```js
// ❌ КАТАСТРОФА: ключ модели в браузере = украденный ключ + счёт на тысячи $
const res = await openai.chat({ apiKey: 'sk-...' }); // в клиентском коде - НЕЛЬЗЯ
```

<b class="text-on-semi-light">Почему</b> - <span class="text-gray">API-ключи LLM - это деньги (оплата за токены). Клиентский бандл публичен ([безопасность](/content/reactjs/security)), поэтому ключ нельзя класть на фронт. Все запросы идут **через твой бэкенд/edge-функцию**, которая хранит ключ, добавляет авторизацию и **лимиты** (rate limiting), чтобы не разорить тебя. Фронтенд зовёт **свой** эндпоинт, а не провайдера напрямую.</span>

---

## Стриминг

LLM генерирует ответ постепенно. Ждать весь ответ (несколько секунд) - плохой UX; вместо этого его **стримят** токен за токеном через **SSE** ([реалтайм](/content/ecosystem-libs/realtime-and-api-clients)), и текст «печатается» на глазах.

```
запрос → сервер вызывает LLM (stream) → токены идут потоком (SSE) → UI дописывает текст
```

Стриминг - не украшение, а ключ к ощущению скорости: пользователь видит ответ сразу, а не через паузу.

## Vercel AI SDK

Де-факто стандарт интеграции LLM во фронтенд. Даёт **единый API** поверх разных провайдеров и готовые хуки со стримингом.

```jsx
'use client';
import { useChat } from 'ai/react';

function Chat() {
  const { messages, input, handleInputChange, handleSubmit } = useChat();
  return (
    <form onSubmit={handleSubmit}>
      {messages.map((m) => <p key={m.id}>{m.role}: {m.content}</p>)}
      <input value={input} onChange={handleInputChange} />
    </form>
  );
}
```

`useChat`/`useCompletion` берут на себя стриминг, состояние сообщений, загрузку и ошибки. SDK поддерживает смену провайдера, **tool calling** и структурированный вывод.

## Tool calling и структурированный вывод

Современные модели умеют **вызывать функции**: LLM возвращает не текст, а запрос «выполни функцию X с аргументами», твой код выполняет её и возвращает результат модели. Так AI взаимодействует с приложением (получить данные, выполнить действие).

**Структурированный вывод** - заставить модель вернуть JSON по схеме (часто [Zod](/content/ecosystem-libs/forms-and-validation)), чтобы надёжно использовать результат в UI, а не парсить свободный текст.

## Embeddings и RAG

**RAG (Retrieval-Augmented Generation)** - как дать модели знание о **твоих** данных, которых не было в обучении.

```
документы → embeddings (векторы) → векторная БД
запрос → найти похожие фрагменты → вставить в промпт → LLM отвечает по ним
```

<b class="text-on-semi-light">Идея</b> - <span class="text-gray">**Embedding** превращает текст в вектор, отражающий смысл. Похожие по смыслу тексты - близкие векторы. RAG: находишь релевантные куски твоих данных по близости векторов и **подкладываешь** их в контекст модели. Так бот отвечает по твоей документации без дообучения. Векторную часть обычно делает бэкенд, но концепцию спрашивают и на фронтенд-собесах.</span>

## UI-паттерны и риски

- **Состояния:** стриминг, «думает», частичный ответ, остановка генерации, повтор при ошибке.
- **Оптимистичность и отзывчивость** - показывать сообщение пользователя сразу.
- **Стоимость и латентность** - токены стоят денег и времени; кешируй, ограничивай длину.
- **Безопасность - prompt injection:** пользовательский ввод может «переписать» инструкции модели. Нельзя доверять выводу LLM как безопасному - особенно если он попадает в `dangerouslySetInnerHTML` или вызывает действия. Санитизируй и ограничивай права.

## Модели в браузере

Появляется возможность запускать **небольшие модели прямо в браузере** - **transformers.js**, WebLLM (через [WebGPU](/content/additional-topics/graphics-canvas-webgl) и [WASM](/content/additional-topics/webassembly)). Плюсы - приватность (данные не уходят) и отсутствие платы за API; минусы - размер моделей и ограниченная мощность. Ниша, но растущая.

## Вопросы на собеседовании

<b class="text-on-semi-light">Можно ли хранить ключ LLM-API на фронтенде?</b>
<span class="text-gray">Нет. Клиентский бандл публичен, а ключ - это деньги. Запросы идут через свой бэкенд/edge, который хранит ключ, добавляет авторизацию и rate limiting. Фронт зовёт свой эндпоинт.</span>

<b class="text-on-semi-light">Зачем стримить ответы LLM?</b>
<span class="text-gray">Модель генерирует текст постепенно; стриминг (через SSE) показывает ответ токен за токеном сразу, а не после многосекундной паузы - решающее для UX.</span>

<b class="text-on-semi-light">Что такое RAG?</b>
<span class="text-gray">Retrieval-Augmented Generation: данные превращают в embeddings (векторы), при запросе находят релевантные фрагменты по близости векторов и подкладывают в контекст модели - так LLM отвечает по твоим данным без дообучения.</span>

<b class="text-on-semi-light">Что такое tool calling и структурированный вывод?</b>
<span class="text-gray">Tool calling - модель запрашивает выполнение функции с аргументами, код выполняет и возвращает результат. Структурированный вывод - модель возвращает JSON по схеме (Zod) для надёжного использования в UI.</span>

<b class="text-on-semi-light">Какой риск безопасности специфичен для AI-функций?</b>
<span class="text-gray">Prompt injection: пользовательский ввод может переопределить инструкции модели. Вывод LLM нельзя считать доверенным - санитизировать перед вставкой в DOM и ограничивать права действий.</span>
