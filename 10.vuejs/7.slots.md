# Слоты

Как передать компоненту не данные, а разметку: слот по умолчанию и именованные слоты, запасное содержимое, scoped-слоты с данными ребёнка, динамические имена и renderless-компоненты. Спрашивают, что такое scoped slot и чем слоты отличаются от `children` в React. Глубже — почему слот не видит данные ребёнка, почему содержимое невызванного слота не создаётся и почему изменение данных в слоте перерисовывает ребёнка, а не родителя.

::tldr
- **Слот — место в шаблоне ребёнка, куда родитель передаёт разметку.** Содержимое слота компилируется в области видимости родителя: оно видит данные родителя и не видит данные ребёнка.
- **Scoped-слот передаёт данные обратно:** ребёнок пишет `<slot :item="item" />`, родитель получает `v-slot="{ item }"`. Так ребёнок управляет логикой и перебором, а родитель — видом.
- **Слот — функция, которую вызывает ребёнок.** Если ребёнок слот не отрисовал, содержимое не создаётся. Реактивные данные, прочитанные в слоте, становятся зависимостью рендера ребёнка.
- **Именованные слоты пишут через `<template #name>`,** а наличие слота проверяют через `$slots.name`, чтобы не рисовать пустую обёртку.
- **Renderless-компонент отдаёт только логику через scoped-слот.** В Composition API эту роль чаще играет композабл, а renderless оставляют для случаев, где нужна разметка-обёртка.
::

## Слот по умолчанию

Сквозной пример — карточка товара, которую используют в каталоге, корзине и избранном с разным содержимым:

```vue
<!-- ProductCard.vue -->
<template>
  <article class="card">
    <header><slot name="header">Без названия</slot></header>
    <slot />
    <footer v-if="$slots.footer"><slot name="footer" /></footer>
  </article>
</template>
```

```vue
<ProductCard>
  <template #header>{{ product.title }}</template>
  <p>{{ product.description }}</p>
  <template #footer><BuyButton :id="product.id" /></template>
</ProductCard>
```

`<slot />` — место, куда попадёт всё, что передано между тегами компонента. Пропсы передают **данные**, слоты — **разметку**: карточка задаёт рамку, а содержимое решает тот, кто её использует.

### Область видимости

Содержимое слота пишет родитель, и **компилируется оно в области видимости родителя**. `{{ product.title }}` берёт `product` у родителя. Данные ребёнка из слота не видны: в проверке обращение к внутренней переменной карточки дало `undefined` и предупреждение «Property was accessed during render but is not defined». Правило звучит так: всё в шаблоне родителя видит данные родителя, всё в шаблоне ребёнка — данные ребёнка.

Как тогда отрисовать в слоте данные, которые есть только у ребёнка? Об этом — scoped-слоты. Сначала про несколько мест для разметки.

---

## Именованные слоты и запасное содержимое

У компонента может быть несколько слотов с именами. Родитель обращается к ним через `<template v-slot:header>`, сокращённо `<template #header>`. Всё, что не обёрнуто в `<template #…>`, уходит в слот по умолчанию (`#default`).

**Запасное содержимое** — то, что внутри `<slot>` в шаблоне ребёнка. Оно показывается, если родитель слот не передал: в проверке карточка без `#header` показала «Без названия».

### Проверка наличия слота

Обёртку вокруг необязательного слота рисуют, только если слот передан:

```vue
<footer v-if="$slots.footer"><slot name="footer" /></footer>
```

Без проверки у каждой карточки был бы пустой `<footer>` с отступами. В проверке карточка без `#footer` вообще не отрисовала элемент. В `<script setup>` слоты доступны через `useSlots()`.

### Динамические имена

Имя слота может быть выражением: `<slot :name="active" />` у ребёнка или `<template #[tabName]>` у родителя. Так делают вкладки: ребёнок рисует слот текущей вкладки, родитель передаёт содержимое для каждой. В проверке смена `active` переключила «Описание» на «Отзывы».

## Scoped-слоты

Список товаров должен сам перебирать элементы, а вид элемента — задавать тот, кто использует список. Ребёнок передаёт данные в слот как атрибуты:

```vue
<!-- ProductList.vue -->
<script setup>
defineProps(['items']);
</script>

<template>
  <ul>
    <li v-for="(item, index) in items" :key="item.id">
      <slot :item="item" :index="index">{{ item.title }}</slot>
    </li>
  </ul>
  <slot v-if="!items.length" name="empty" />
</template>
```

Родитель получает их деструктуризацией:

```vue
<ProductList :items="products" v-slot="{ item, index }">
  {{ index + 1 }}. {{ item.title }} — {{ item.price }} ₽
</ProductList>

<ProductList :items="[]">
  <template #empty>Ничего не найдено</template>
</ProductList>
```

Это **scoped-слот**: содержимое по-прежнему пишет родитель, но данные приходят от ребёнка через пропсы слота. Если `v-slot` не указан, работает запасное содержимое — `{{ item.title }}`. Всё это проверено.

`v-slot` прямо на теге компонента — сокращение для единственного слота по умолчанию. Если есть именованные слоты, все слоты пишут через `<template>`, иначе компилятор выдаёт ошибку `Mixed v-slot usage on both the component and nested <template>`.

Так устроены компоненты таблиц, списков и выпадающих списков в UI-библиотеках: компонент отвечает за перебор, виртуализацию, выбор и клавиатуру, а ячейку рисует пользователь.

---

## Как работают слоты

Компилятор превращает содержимое слота у родителя в **функцию**, а `<slot>` у ребёнка — в её вызов с пропсами слота. Слоты — это функции, которые ребёнок вызывает в своём рендере. Отсюда два следствия, оба проверены.

### Невызванный слот ничего не создаёт

```vue
<!-- Collapse.vue -->
<template><div><slot v-if="open" /></div></template>
```

```vue
<Collapse :open="open"><HeavyChart /></Collapse>
```

Пока `open` ложно, `HeavyChart` не создаётся и не монтируется — функция слота просто не вызывалась. В проверке счётчик `onMounted` был `0` до открытия и `1` после.

### Зависимость слота принадлежит ребёнку

Если родитель использует в слоте реактивное значение, это значение читается в момент вызова функции слота — то есть **внутри рендера ребёнка**. Изменение значения перерисует ребёнка, а родителя — нет:

```vue
<Box>{{ count }}</Box>
```

В проверке после изменения `count` хук `onUpdated` сработал только у `Box`. Это продолжение точечных обновлений Vue (подробно — во [Введении](/content/vuejs/introduction)): компилятор знает, что слоты стабильны, и не перерисовывает родителя ради содержимого, которое он передал.

## Renderless-компоненты

Компонент может не иметь своей разметки и отдавать только логику через scoped-слот:

```vue
<!-- MouseTracker.vue -->
<script setup>
import { ref } from 'vue';
const x = ref(0);
const y = ref(0);
function onMove(e) { x.value = e.clientX; y.value = e.clientY; }
</script>

<template>
  <slot :x="x" :y="y" :on-move="onMove" />
</template>
```

```vue
<MouseTracker v-slot="{ x, y, onMove }">
  <div class="area" @mousemove="onMove">{{ x }}, {{ y }}</div>
</MouseTracker>
```

До Composition API это был главный способ переиспользовать логику без миксинов. Сейчас ту же задачу решает композабл `useMouse()` — без лишнего компонента в дереве (подробно — в [Композаблах](/content/vuejs/composables)). Renderless-компонент остаётся полезным, когда логика привязана к месту в шаблоне: провайдер контекста, граница ошибок, компонент формы, который регистрирует поля.

## Слоты и React

| | Vue | React |
| --- | --- | --- |
| Разметка по умолчанию | слот по умолчанию | `children` |
| Несколько мест | именованные слоты | пропсы с JSX: `header={…}` |
| Данные от ребёнка | scoped-слот | render prop: `renderItem={(item) => …}` |
| Ленивость | слот — функция, вызывается ребёнком | `children` — уже созданные элементы, render prop — функция |
| Зависимости содержимого | у рендера ребёнка | содержимое создаёт родитель при своём рендере |

В React `children` — уже созданные элементы: родитель создаёт их при каждом своём рендере, даже если ребёнок их не покажет. Ближе всего к слоту Vue — render prop (подробно — в [Паттернах и дизайне компонентов](/content/reactjs/patterns-and-component-design)).

---

## Красные флаги в ответе

- **«В слоте доступны данные дочернего компонента».** Содержимое слота видит только данные родителя, данные ребёнка приходят через scoped-слот.
- **«Содержимое слота создаётся, даже если ребёнок его не показал».** Слот — функция, невызванный слот ничего не создаёт.
- **«Изменение данных в слоте перерисует родителя».** Значение читается в рендере ребёнка, и перерисуется ребёнок.
- **«`v-slot` на компоненте можно смешивать с именованными `<template>`».** Компилятор выдаст ошибку, при нескольких слотах все пишут через `<template>`.
- **«Renderless-компоненты — основной способ переиспользовать логику».** В Composition API для этого есть композаблы.

## Как спрашивают на собеседовании

::question
Что такое слоты и зачем они нужны?

#answer
Способ передать компоненту разметку. Ребёнок объявляет `<slot />` — место для содержимого, родитель пишет содержимое между тегами компонента. Пропсы передают данные, слоты — разметку: компонент задаёт рамку и поведение, а содержимое решает использующий.

#more
Слотов может быть несколько — именованные, через `<template #name>`. Содержимое внутри `<slot>` у ребёнка — запасное, показывается, если родитель слот не передал. Наличие слота проверяют через `$slots.name`, чтобы не рисовать пустую обёртку.
::

::question
Что такое scoped slot?

#answer
Слот, в который ребёнок передаёт данные: `<slot :item="item" />`. Родитель получает их через `v-slot="{ item }"` и решает, как отрисовать элемент. Ребёнок отвечает за данные и перебор, родитель — за вид.

#more
Так устроены списки, таблицы и выпадающие списки в UI-библиотеках. Аналог в React — render prop. `v-slot` на теге компонента — сокращение для одного слота по умолчанию, при именованных слотах все слоты пишут через `<template>`.
::

::question
Почему в слоте не видны данные ребёнка?

#answer
Содержимое слота пишет родитель, и компилируется оно в области видимости родителя. Всё в шаблоне родителя видит данные родителя, всё в шаблоне ребёнка — данные ребёнка.

#more
Обращение к переменной ребёнка из слота даёт `undefined` и предупреждение «Property was accessed during render but is not defined». Чтобы использовать данные ребёнка, он передаёт их через пропсы слота — это и есть scoped-слот.
::

::question
Как работают слоты внутри?

#answer
Компилятор превращает содержимое слота у родителя в функцию, а `<slot>` у ребёнка — в её вызов с пропсами слота. Ребёнок вызывает функцию в своём рендере.

#more
Поэтому невызванный слот ничего не создаёт: компонент внутри `<slot v-if="false">` не монтируется. А реактивные данные родителя, прочитанные в слоте, становятся зависимостью рендера ребёнка: их изменение перерисует ребёнка, а не родителя.
::

::question
Что такое renderless-компонент и нужен ли он сейчас?

#answer
Компонент без своей разметки, который отдаёт состояние и функции через scoped-слот. Родитель получает логику и рисует что угодно. До Composition API это был основной способ переиспользовать логику без миксинов.

#more
Сейчас переиспользуемую логику выносят в композаблы — без лишнего компонента в дереве. Renderless-компонент полезен, когда логика привязана к месту в шаблоне: границы ошибок, провайдеры, компоненты форм, которые регистрируют поля.
::

::question
Чем слоты Vue отличаются от children в React?

#answer
`children` в React — уже созданные элементы, их создаёт родитель при своём рендере. Слот Vue — функция, которую вызывает ребёнок. Именованным слотам в React соответствуют пропсы с JSX, scoped-слотам — render props.

#more
Из-за этого во Vue невызванный слот ничего не создаёт, а зависимости содержимого принадлежат рендеру ребёнка. В React содержимое `children` создаётся заранее, даже если ребёнок его не покажет, а ленивость дают только render props.
::

## Практика

::practice{title="Пустая обёртка"}
У карточек без кнопки внизу пустой блок с отступами:

```vue
<!-- ProductCard.vue -->
<template>
  <article>
    <slot />
    <footer class="card-footer"><slot name="footer" /></footer>
  </article>
</template>
```

#solution
Обёртка `footer` рисуется всегда, даже если слот не передан. Нужно проверить, есть ли слот:

```vue
<footer v-if="$slots.footer" class="card-footer">
  <slot name="footer" />
</footer>
```

`$slots.footer` — функция, если родитель передал `#footer`, и `undefined`, если нет. В `<script setup>` то же через `const slots = useSlots()`. Проверка срабатывает при каждом рендере, поэтому если родитель передаёт слот по условию, обёртка появится и исчезнет вместе с ним. В проверке карточка без `#footer` не отрисовала элемент.
::

::practice{title="Список с разным видом элемента"}
Список товаров используется в каталоге (название и цена) и в корзине (название, количество и кнопка удаления). Сделай один компонент списка.

#solution
```vue
<!-- ProductList.vue -->
<script setup>
defineProps(['items']);
</script>

<template>
  <ul v-if="items.length">
    <li v-for="(item, index) in items" :key="item.id">
      <slot :item="item" :index="index">{{ item.title }}</slot>
    </li>
  </ul>
  <slot v-else name="empty">Список пуст</slot>
</template>
```

```vue
<!-- каталог -->
<ProductList :items="products">
  <template #default="{ item }">{{ item.title }} — {{ item.price }} ₽</template>
</ProductList>

<!-- корзина -->
<ProductList :items="cart">
  <template #default="{ item }">
    {{ item.title }} × {{ item.qty }}
    <button @click="remove(item.id)">Удалить</button>
  </template>
  <template #empty>Корзина пуста</template>
</ProductList>
```

Список отвечает за перебор, ключи и пустое состояние, а вид элемента задаёт использующий. `remove` берётся из области родителя — это его данные и его логика. В проверке список с scoped-слотом отрисовал «1. Чай — 490», без слота — запасное содержимое, а пустой список — `#empty`.
::
