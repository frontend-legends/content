# Рендеринг и Nuxt

Где формируется HTML - в браузере или на сервере - определяет скорость, SEO и сложность приложения. Стратегии те же, что в React, а инструмент для серверного Vue - мета-фреймворк **Nuxt**. За ним почти всегда следует вопрос про гидратацию.

---

## Стратегии рендеринга

| | Где генерируется HTML | Плюсы | Минусы |
|--|------------------------|-------|--------|
| **CSR** | в браузере после JS | просто, SPA-навигация | пустой экран до JS, слабый SEO |
| **SSR** | на сервере на каждый запрос | быстрый контент, SEO | нагрузка на сервер, гидратация |
| **SSG** | заранее при сборке | очень быстро, CDN | данные застывают |
| **ISR** | сборка + перегенерация | свежесть SSG + скорость CDN | привязка к платформе |

Подробный разбор каждой стратегии и компромиссов - в [рендеринге React](/content/reactjs/rendering-and-hydration); здесь - Vue-специфика.

---

## SSR во Vue

Vue рендерит компоненты в HTML-строку на сервере (`renderToString`), браузер показывает готовую разметку, затем подгружается JS и **гидратирует** её.

```js
import { renderToString } from 'vue/server-renderer';
const html = await renderToString(app); // HTML на сервере
```

Ручной SSR-сетап сложен (сервер, сборка для двух сред, передача состояния), поэтому на практике берут **Nuxt**.

---

## Гидратация

**Гидратация** - «оживление» серверного HTML: Vue проходит по существующему DOM, привязывает реактивность и обработчики, **не перерисовывая** разметку заново.

До гидратации HTML виден, но **не интерактивен** - та же «зловещая долина», что в React.

### Hydration mismatch

Vue ожидает, что HTML с сервера **совпадёт** с первым клиентским рендером. Если нет - предупреждение и перерисовка поддерева.

```vue
<!-- ❌ источник mismatch -->
<span>{{ new Date().toLocaleTimeString() }}</span>  <!-- время на сервере ≠ клиент -->
<span>{{ Math.random() }}</span>
```

Причины те же: время/случайность, обращение к `window`/`localStorage` при рендере, неверная HTML-вложенность. Лечение - выносить такое в `onMounted` (выполняется только на клиенте) или использовать `<ClientOnly>` в Nuxt.

<b class="text-on-semi-light">Цена гидратации</b> - <span class="text-gray">Чтобы привязать реактивность, клиент выполняет тот же код компонентов, что и сервер. SSR ускоряет первый показ (FCP), но не время до интерактивности (TTI). Эту проблему адресуют islands и серверные компоненты.</span>

## Nuxt

**Nuxt** - мета-фреймворк для Vue, как Next.js для React. Берёт на себя то, что в чистом Vue приходится собирать руками.

- **Файловый роутинг** - файлы в `pages/` становятся маршрутами автоматически.
- **Рендеринг** - SSR, SSG, SPA, гибрид - из коробки.
- **Загрузка данных** - `useFetch`/`useAsyncData`: SSR-aware, данные грузятся на сервере и переиспользуются на клиенте без повторного запроса.
- **Авто-импорты** - компоненты, composables и API Vue без ручных `import`.
- **Серверная часть (Nitro)** - серверные маршруты/API в той же кодовой базе, деплой на разные платформы.

```vue
<!-- pages/users/[id].vue - маршрут /users/:id -->
<script setup>
const route = useRoute();
const { data: user } = await useFetch(`/api/users/${route.params.id}`); // SSR-загрузка
</script>
```

## Режимы рендеринга Nuxt

Nuxt позволяет выбирать стратегию **на уровне маршрута** через `routeRules` - гибридный рендеринг.

```js
// nuxt.config
routeRules: {
  '/': { prerender: true },              // SSG - статика
  '/blog/**': { swr: 3600 },             // ISR-подобное: кэш с перегенерацией
  '/admin/**': { ssr: false },           // SPA (CSR) - SEO не нужен
  '/news/**': { ssr: true },             // SSR на каждый запрос
}
```

Одно приложение может смешивать статические, серверные и клиентские страницы - то, что нужно реальным сайтам.

---

## Islands и серверные компоненты

Nuxt развивает **острова (islands)** и **серверные компоненты** - подход, при котором большая часть страницы статична, а интерактивность «вкраплена» островками. Это снижает объём JS и стоимость гидратации - идейно близко к React Server Components.

> На собесе достаточно знать направление: индустрия (и React, и Vue/Nuxt) движется к меньшему объёму клиентского JS - серверный рендер + точечная гидратация островов.

---

## Как выбрать

- **Блог, лендинг, доки** → SSG/ISR.
- **Каталог, страница товара** (SEO + свежесть) → SSR.
- **Дашборд за логином** → CSR/SPA.
- Реальные сайты **смешивают** стратегии по маршрутам - это и даёт Nuxt.

## Вопросы на собеседовании

<b class="text-on-semi-light">Что такое гидратация и какова её цена?</b>
<span class="text-gray">Привязка реактивности и обработчиков к серверному HTML без перерисовки. Клиент выполняет тот же код, что и сервер, - SSR ускоряет FCP, но не TTI.</span>

<b class="text-on-semi-light">Что вызывает hydration mismatch?</b>
<span class="text-gray">Несовпадение серверного HTML с первым клиентским рендером: время, random, доступ к window, неверная вложенность тегов. Лечится выносом в onMounted или `<ClientOnly>`.</span>

<b class="text-on-semi-light">Что даёт Nuxt поверх Vue?</b>
<span class="text-gray">Файловый роутинг, SSR/SSG/гибрид, SSR-aware загрузку (useFetch), авто-импорты, серверную часть (Nitro) - всё, что в чистом Vue собирают вручную.</span>

<b class="text-on-semi-light">Что такое гибридный рендеринг в Nuxt?</b>
<span class="text-gray">Выбор стратегии на уровне маршрута через `routeRules`: одни страницы статические (prerender), другие SSR, третьи SPA, четвёртые с ISR-подобным кэшем.</span>

<b class="text-on-semi-light">Что такое islands и зачем они нужны?</b>
<span class="text-gray">Подход, где страница в основном статична, а интерактивность - островками. Меньше клиентского JS и стоимости гидратации; идейно близко к серверным компонентам React.</span>
