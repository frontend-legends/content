# Шаблоны и директивы

Vue описывает UI **шаблонами** - HTML-подобным синтаксисом, а не JSX. Динамику добавляют **директивы** - специальные атрибуты с префиксом `v-`. Компилятор превращает шаблон в render-функцию, попутно анализируя зависимости для тонкой реактивности.

---

## Интерполяция и привязки

```vue
<template>
  <h1>{{ title }}</h1>                  <!-- текст -->
  <img :src="avatarUrl" :alt="name" />  <!-- v-bind: атрибут -->
  <button @click="onClick">OK</button>  <!-- v-on: событие -->
</template>
```

- `{{ выражение }}` - текстовая интерполяция.
- `v-bind:attr` (сокращённо `:attr`) - привязка атрибута к выражению.
- `v-on:event` (сокращённо `@event`) - обработчик события.

В фигурных скобках и привязках - **JS-выражения**, не инструкции (как и в JSX).

---

## Условный рендеринг: v-if vs v-show

```vue
<p v-if="status === 'loading'">Загрузка</p>
<p v-else-if="error">Ошибка</p>
<p v-else>Готово</p>

<div v-show="isVisible">Переключаюсь через display</div>
```

| | `v-if` | `v-show` |
|--|--------|----------|
| Что делает | добавляет/удаляет элемент из DOM | переключает `display: none` |
| Стоимость переключения | высокая (монтаж/размонтаж) | низкая (только стиль) |
| Начальная стоимость | низкая (если false - не рендерит) | высокая (рендерит всегда) |
| Когда | условие меняется редко | часто переключается |

<b class="text-on-semi-light">Правило выбора</b> - <span class="text-gray">`v-show` - для частого переключения видимости (элемент всегда в DOM, прячется стилем). `v-if` - когда условие меняется редко или блок дорогой и не нужен в DOM до поры.</span>

## Списки: v-for и key

```vue
<ul>
  <li v-for="todo in todos" :key="todo.id">{{ todo.text }}</li>
</ul>
```

Как и в React, каждому элементу нужен **`:key`** - стабильный уникальный идентификатор. По нему Vue понимает идентичность элементов при изменении списка и переиспользует/переставляет DOM корректно.

⚠️ <b class="text-on-semi-light">Индекс как key - антипаттерн</b> - <span class="text-gray">`:key="index"` ломается при вставке/удалении/сортировке: Vue сопоставляет по позиции и переиспользует не тот узел и его состояние. Используй стабильный `id`.</span>

> Не используй `v-if` и `v-for` на одном элементе - приоритет и поведение неочевидны. Фильтруй данные через `computed` или оборачивай в `<template v-for>` с `v-if` внутри.

## Привязка классов и стилей

`:class` и `:style` понимают объекты и массивы - удобно для условных стилей.

```vue
<div :class="{ active: isActive, disabled: isDisabled }"></div>
<div :class="['base', isActive ? 'on' : 'off']"></div>
<div :style="{ color: textColor, fontSize: size + 'px' }"></div>
```

---

## Модификаторы директив

Модификаторы - постфиксы через точку, меняющие поведение директивы. Убирают рутинный код в обработчиках.

```vue
<form @submit.prevent="onSubmit">         <!-- e.preventDefault() -->
  <input @keyup.enter="search" />          <!-- только по Enter -->
  <input v-model.trim.number="age" />      <!-- обрезать пробелы + число -->
  <div @click.stop="...">                  <!-- e.stopPropagation() -->
</form>
```

Частые: `.prevent`, `.stop`, `.self`, `.once`, `.lazy` (обновлять `v-model` по `change`, а не `input`), `.number`, `.trim`, клавиши (`.enter`, `.esc`).

## v-model

Двусторонняя привязка - сахар над `:value` + `@input`. На нативных полях даёт «значение ↔ состояние».

```vue
<input v-model="name" />
<!-- эквивалентно: -->
<input :value="name" @input="name = $event.target.value" />
```

На **компонентах** `v-model` работает иначе (через `props` + `emit`) - это разбираем в [коммуникации компонентов](/content/vuejs/components-communication).

<b class="text-on-semi-light">Vue и controlled/uncontrolled</b> - <span class="text-gray">В отличие от React, во Vue нет дихотомии controlled/uncontrolled: `v-model` всегда связывает поле с реактивным состоянием. Источник истины - реактивная переменная.</span>

---

## Динамические компоненты

`<component :is="...">` рендерит компонент по имени/ссылке - для табов, мастеров, условного выбора.

```vue
<component :is="currentTab" />
```

В связке с [`<KeepAlive>`](/content/vuejs/built-in-components) переключаемые компоненты сохраняют состояние.

---

## Кастомные директивы

Можно объявить свою `v-`директиву для низкоуровневой работы с DOM (фокус, клик-вне, ленивые картинки).

```js
const vFocus = {
  mounted: (el) => el.focus(),
};
// <input v-focus />
```

> Кастомные директивы - для прямого доступа к DOM-элементу. Логику без DOM лучше выносить в composables, а не в директивы.

---

## Шаблоны vs JSX

Vue компилирует шаблоны и **на этапе компиляции знает структуру** - это даёт оптимизации, недоступные JSX: статический подъём (hoisting) неизменных узлов, patch-флаги (помечает, что именно в узле динамическое), tree-flattening. Поэтому Vue часто обновляет DOM эффективнее «из коробки».

> Vue поддерживает и JSX (через плагин), но идиоматичный путь - шаблоны: они дают компилятору больше информации для оптимизации.

## Вопросы на собеседовании

<b class="text-on-semi-light">Чем v-if отличается от v-show?</b>
<span class="text-gray">`v-if` добавляет/удаляет элемент из DOM (дорогое переключение, дешёвый старт). `v-show` переключает `display` (дешёвое переключение, элемент всегда в DOM). v-show - для частых переключений.</span>

<b class="text-on-semi-light">Зачем нужен :key в v-for?</b>
<span class="text-gray">Для идентификации элементов при изменении списка - корректного переиспользования и перестановки DOM. Индекс как key - антипаттерн при вставках/сортировке.</span>

<b class="text-on-semi-light">Почему не стоит сочетать v-if и v-for на одном элементе?</b>
<span class="text-gray">Неочевидный приоритет и лишняя работа. Лучше фильтровать через computed или разнести по `<template>`.</span>

<b class="text-on-semi-light">Что такое модификаторы директив?</b>
<span class="text-gray">Постфиксы (`.prevent`, `.stop`, `.lazy`, `.number`), меняющие поведение директивы - убирают шаблонный код в обработчиках.</span>

<b class="text-on-semi-light">Во что компилируется v-model на input?</b>
<span class="text-gray">В привязку `:value` и обработчик `@input` (двусторонняя связь). На компонентах - в prop + emit.</span>

<b class="text-on-semi-light">Какое преимущество шаблонов перед JSX?</b>
<span class="text-gray">Компилятор знает структуру заранее и применяет оптимизации (hoisting статики, patch-флаги), обновляя DOM эффективнее без ручной мемоизации.</span>
