# Шаблоны и директивы

Синтаксис шаблона Vue: интерполяция и привязки, условия и списки, классы и стили, события и модификаторы, `v-model`, динамические компоненты и свои директивы — и во что всё это компилируется. Спрашивают, чем `v-if` отличается от `v-show`, зачем `key` в `v-for` и почему `v-if` нельзя ставить рядом с `v-for`. Глубже — что именно ломает ключ-индекс, во что раскрывается `v-model` и почему поле возвращает строку вместо числа.

::tldr
- **Шаблон — не HTML, а исходник для компилятора.** В фигурных скобках и атрибутах — одно JavaScript-выражение, а из глобальных объектов доступны только разрешённые вроде `Math`.
- **`v-if` создаёт и уничтожает элемент вместе с состоянием, `v-show` только прячет его через `display: none`.** Первый дешевле при редком переключении, второй — при частом.
- **`key` в `v-for` — идентичность элемента.** С индексом в качестве ключа после удаления или сортировки состояние «переезжает» к соседнему элементу.
- **`v-if` выполняется раньше `v-for`,** поэтому на одном элементе переменная цикла в условии недоступна. Фильтруют в `computed` или ставят `v-if` на вложенный элемент.
- **`v-model` — сокращение для значения и обработчика.** На поле ввода — `value` и `input`, на компоненте — проп `modelValue` и событие `update:modelValue`. Значение поля — строка, если не указать `.number` или `type="number"`.
::

## Что такое шаблон

Шаблон выглядит как HTML, но браузер его не видит: компилятор превращает его в render-функцию (подробно — во [Введении](/content/vuejs/introduction)). Поэтому правила у шаблона свои.

Сквозной пример — карточка товара:

```vue
<script setup>
import { ref } from 'vue';

const product = ref({ id: 7, title: 'Улун', price: 490, inStock: true });
const qty = ref(1);
</script>

<template>
  <article class="card" :class="{ soldout: !product.inStock }">
    <h3>{{ product.title }}</h3>
    <p v-if="product.inStock">{{ product.price * qty }} ₽</p>
    <p v-else>Нет в наличии</p>
    <input v-model.number="qty" type="number" min="1">
    <button :disabled="!product.inStock" @click="addToCart(product.id, qty)">В корзину</button>
  </article>
</template>
```

### Интерполяция

`{{ }}` выводит значение как **текст**: HTML экранируется. Строка `<img src=x onerror=alert(1)>` отобразится буквами, элемента не появится — в проверке так и вышло. Вставить HTML можно только явно, через `v-html`, и это главный источник XSS во Vue (подробно — в [Безопасности](/content/vuejs/security)).

### Выражения

Внутри `{{ }}` и привязок — **одно выражение**: `price * qty`, `ok ? 'да' : 'нет'`, вызов функции. Инструкции `if`, `for`, `const` — ошибка компиляции «Error parsing JavaScript expression».

Выражения выполняются в контексте компонента: видны его переменные и небольшой белый список глобальных — `Math`, `Date`, `JSON` и другие. `window` и `document` из шаблона недоступны: в проверке `typeof window` в шаблоне дал `undefined`. Если глобальное значение нужно, его кладут в переменную компонента.

### Привязки атрибутов

`v-bind:title="…"`, сокращённо `:title="…"`, связывает атрибут с выражением:

- **`false` у булева атрибута убирает его:** `:disabled="false"` — кнопки без `disabled`;
- **`null` и `undefined` убирают любой атрибут;**
- **одинаковое имя сокращается:** `:id` вместо `:id="id"`;
- **объект раскладывается на атрибуты:** `v-bind="{ role: 'button', 'data-sku': 'tea' }"`.

Привязки описывают, что показать. Следующий вопрос — показать ли вообще.

## Условия: v-if и v-show

```vue
<p v-if="product.inStock">{{ product.price }} ₽</p>
<p v-else-if="product.preorder">Под заказ</p>
<p v-else>Нет в наличии</p>

<details v-show="expanded">…</details>
```

Обе директивы прячут элемент, но по-разному:

| | `v-if` | `v-show` |
| --- | --- | --- |
| Ложное условие | элемента нет в DOM | элемент есть, `display: none` |
| Переключение | создание и уничтожение, хуки жизненного цикла | смена стиля |
| Состояние внутри | сбрасывается | сохраняется |
| Начальная стоимость | ничего не рендерит, пока ложно | рендерит всегда |
| `v-else`, `<template>` | работает | нет |

Сброс состояния — то, о чём часто забывают. В проверке счётчик внутри `v-if` после скрытия и показа начал с нуля, а внутри `v-show` сохранил значение. Если в блоке форма с введёнными данными, `v-if` их потеряет.

Правило выбора: **`v-show` — для частого переключения** (вкладки, раскрывающиеся блоки), **`v-if` — для редкого** или когда содержимое тяжёлое и не нужно до поры. Если нужно и не рендерить заранее, и сохранять состояние, есть `KeepAlive` (подробно — во [Встроенных компонентах](/content/vuejs/built-in-components)).

Одно значение — одно условие. Когда значений много, нужен список.

## Списки: v-for и key

```vue
<li v-for="p in products" :key="p.id">{{ p.title }}</li>
<li v-for="(p, index) in products" :key="p.id">{{ index + 1 }}. {{ p.title }}</li>
<span v-for="(value, key, index) in prices" :key="key">{{ key }}: {{ value }}</span>
<span v-for="n in 3" :key="n">{{ n }}</span>   <!-- 1 2 3 — диапазон начинается с 1 -->
```

### Зачем key

При обновлении списка Vue сопоставляет старые и новые элементы. Без ключа — **по позиции**: первый со первым, второй со вторым, и элемент обновляется на месте. С ключом — **по идентичности**: элемент с тем же `key` переиспользуется, даже если сменил позицию, новые создаются, исчезнувшие удаляются.

Для статичного текста разницы не видно. Она появляется, когда у элемента есть своё состояние: значение поля, фокус, локальный `ref` дочернего компонента, анимация.

```vue
<Row v-for="(p, index) in list" :key="index" :title="p.title" />
<!-- у каждой Row — своё поле «заметка» -->
```

Пользователь написал заметку у «Чая» и удалил его из списка. Ключи были `0, 1`, стали `0`. Для Vue элемент с ключом `0` остался — изменился только его проп `title` на «Кофе». Компонент переиспользован, и заметка про чай теперь стоит у кофе. В проверке с `:key="index"` поле у кофе содержало «про чай», а с `:key="p.id"` — было пустым.

Поэтому ключ — **стабильный уникальный идентификатор данных**: `id` из базы, артикул. Индекс годится, только если список никогда не переставляется и не фильтруется, а у элементов нет состояния. `Math.random()` — худший вариант: каждый рендер пересоздаёт все элементы.

### v-if и v-for вместе

```vue
<li v-for="p in products" v-if="p.inStock" :key="p.id">{{ p.title }}</li>
```

Во Vue 3 у `v-if` **приоритет выше**, чем у `v-for`: условие проверяется до цикла, когда `p` ещё не существует. В проверке рендер упал с `Cannot read properties of undefined (reading 'ok')`, а Vue предупредил «Property "p" was accessed during render but is not defined». Во Vue 2 приоритет был обратный, поэтому старые статьи советуют противоположное.

Решения:

```vue
<!-- 1. отфильтровать заранее — лучший вариант -->
<li v-for="p in available" :key="p.id">{{ p.title }}</li>
<!-- const available = computed(() => products.value.filter((p) => p.inStock)) -->

<!-- 2. цикл на обёртке, условие внутри -->
<template v-for="p in products" :key="p.id">
  <li v-if="p.inStock">{{ p.title }}</li>
</template>
```

`computed` лучше: фильтрация кешируется и пересчитывается только при изменении `products`, а шаблон остаётся простым (подробно — в [Computed и наблюдателях](/content/vuejs/computed-and-watchers)).

Список отрисован. Теперь — как он выглядит.

## Классы и стили

`:class` и `:style` принимают не только строку:

```vue
<div class="card" :class="[{ active, error }, size]"></div>
<!-- active = true, error = false, size = 'lg' → class="card active lg" -->

<div :style="{ fontSize: '14px', '--accent': accent }"></div>
```

- **объект** — класс добавляется, если значение истинно;
- **массив** — набор классов или объектов;
- **статический `class` и `:class` сливаются,** а не заменяют друг друга;
- **в `:style`** имена пишут в camelCase или как CSS, работают и CSS-переменные.

Если компонент принимает `class` от родителя, он попадает на корневой элемент и сливается с его классами — это fallthrough-атрибуты (подробно — в [Связи компонентов](/content/vuejs/components-communication)).

## События и модификаторы

`v-on:click`, сокращённо `@click`, подписывает на событие. Обработчик — имя функции или выражение: `@click="count++"`, `@click="add(product.id, $event)"`.

**Модификаторы** убирают типовой код из обработчиков:

| Модификатор | Что делает |
| --- | --- |
| `.prevent` | `event.preventDefault()` — форма не перезагрузит страницу |
| `.stop` | `event.stopPropagation()` — событие не дойдёт до родителя |
| `.self` | обработчик срабатывает, только если событие на самом элементе, а не на потомке |
| `.once` | обработчик срабатывает один раз |
| `.capture` | подписка на фазе перехвата |
| `.passive` | `{ passive: true }` — браузер не ждёт обработчик перед прокруткой |
| `.enter`, `.esc`, `.ctrl` | клавиши и сочетания: `@keyup.enter`, `@click.ctrl` |
| `.exact` | только это сочетание, без других клавиш-модификаторов |

В проверке `@submit.prevent` отменил отправку формы, `.stop` не пустил клик к родителю, `.once` сработал один раз, а `@keyup.enter` проигнорировал другие клавиши. `.prevent` вместе с `.passive` не работает: пассивный обработчик не может отменить действие по умолчанию.

События идут от элемента к коду. Для полей ввода нужна связь в обе стороны.

## v-model

`v-model` — двусторонняя привязка: поле показывает значение переменной и записывает в неё ввод. Это не магия, а сокращение:

```vue
<input v-model="query">
<!-- примерно то же, что -->
<input :value="query" @input="query = $event.target.value">
```

Компилятор раскрывает `v-model` на поле в директиву `vModelText` с обработчиком `onUpdate:modelValue`, а на компоненте — в проп `modelValue` и событие `update:modelValue`. Как сделать свой компонент с `v-model` — в [Связи компонентов](/content/vuejs/components-communication).

Под разные поля Vue подставляет нужные свойство и событие:

| Поле | Свойство | Событие |
| --- | --- | --- |
| текст, `textarea` | `value` | `input` |
| `checkbox`, `radio` | `checked` | `change` |
| `select` | `value` | `change` |

У чекбоксов с одним `v-model` на массив значения собираются в массив, а `true-value` и `false-value` задают свои значения вместо `true` и `false`.

### Модификаторы

- **`.lazy`** — обновлять по `change` (потеря фокуса), а не на каждый ввод;
- **`.number`** — привести к числу;
- **`.trim`** — обрезать пробелы.

Значение текстового поля всегда **строка**. Без `.number` выражение `qty + 1` при вводе `490` даёт `"4901"`. У `type="number"` Vue приводит значение к числу сам — в проверке оба варианта дали `491`.

### Ввод через IME

При наборе на японском, китайском или с некоторыми раскладками текст сначала собирается (composition) и только потом подтверждается. `v-model` ждёт конца набора: пока идёт composition, переменная не меняется. В проверке после `compositionstart` ввод не попал в модель, а после `compositionend` — попал. Если нужно реагировать на каждый символ и при :term[IME]{def="метод ввода: система, через которую набирают иероглифы и другие символы в несколько нажатий"}, используют `:value` и `@input` вручную.

Во Vue нет деления на контролируемые и неконтролируемые поля, как в React (подробно — в [Состоянии и событиях React](/content/reactjs/state-and-events)): источник истины — переменная, и `v-model` синхронизирует с ней поле в обе стороны.

## Динамические компоненты и свои директивы

### `component :is`

Какой компонент показать, можно решить во время выполнения:

```vue
<component :is="tabs[current]" />
```

`:is` принимает объект компонента или имя зарегистрированного компонента. Компонент в переменной хранят в `shallowRef`: глубокая реактивность объекту компонента не нужна. При смене `:is` старый компонент уничтожается вместе с состоянием, сохранить его помогает `KeepAlive`.

### Свои директивы

Директива — способ получить прямой доступ к элементу, когда нужна низкоуровневая работа с DOM: фокус, подсветка, внешний клик.

```vue
<script setup>
const vFocus = {
  mounted: (el) => el.focus(),
};
</script>

<template>
  <input v-focus>
</template>
```

В `<script setup>` переменная с префиксом `v` и camelCase-именем (`vFocus`) автоматически становится директивой `v-focus`. Хуки директивы повторяют жизненный цикл: `created`, `beforeMount`, `mounted`, `beforeUpdate`, `updated`, `beforeUnmount`, `unmounted`. Аргументы приходят во втором параметре: `binding.value`, `binding.arg`, `binding.modifiers`. В проверке `mounted` поставил фокус, а при удалении элемента сработал `unmounted`.

Директива нужна для работы с DOM. Если же переиспользуется логика без DOM — это композабл (подробно — в [Композаблах](/content/vuejs/composables)).

## Шаблоны или JSX

Vue поддерживает и render-функции, и :term[JSX]{def="синтаксис разметки внутри JavaScript, который компилируется в вызовы функций"} через плагин. Шаблоны остаются основным вариантом не из-за привычки:

- **компилятор анализирует шаблон** и даёт подсказки рантайму: статичные узлы выносятся, у динамических есть patch flags (подробно — в [Производительности](/content/vuejs/performance));
- **шаблон ограничен**, и это помогает: в нём нет произвольного кода, его легче читать и проверять (`vue-tsc` проверяет шаблоны по типам);
- **JSX гибче:** условия и циклы — обычный JavaScript, удобно для библиотек, которые генерируют разметку программно.

Во что превращаются директивы, видно на выводе компилятора: `v-if` — тернарный оператор, `v-for` — вызов `_renderList`, `v-model` — директива `vModelText` с обработчиком.

## Красные флаги в ответе

- **«`v-if` и `v-show` — одно и то же».** `v-if` удаляет элемент и сбрасывает его состояние, `v-show` только меняет `display`.
- **«`key` нужен, чтобы убрать предупреждение».** Он задаёт идентичность элемента. Индекс в качестве ключа переносит состояние на соседний элемент.
- **«`v-for` выполняется раньше `v-if`».** Во Vue 3 наоборот: на одном элементе переменная цикла в условии недоступна.
- **«`v-model` — особая двусторонняя связь».** Это сокращение для значения и обработчика, на компоненте — `modelValue` и `update:modelValue`.
- **«Из шаблона можно обратиться к `window`».** Доступен только белый список глобальных объектов.

## Как спрашивают на собеседовании

::question
Чем v-if отличается от v-show?

#answer
`v-if` добавляет и удаляет элемент: при ложном условии его нет в DOM, а при показе он создаётся заново. `v-show` всегда рендерит элемент и переключает `display: none`. `v-show` — для частого переключения, `v-if` — для редкого.

#more
`v-if` при скрытии уничтожает компоненты внутри: срабатывают хуки размонтирования, сбрасывается состояние и введённые данные. `v-show` состояние сохраняет, но рендерит содержимое сразу, даже если его никогда не покажут. `v-show` не работает с `v-else` и `<template>`. Сохранить состояние при `v-if` или `:is` помогает `KeepAlive`.
::

::question
Зачем нужен key в v-for?

#answer
`key` задаёт идентичность элемента. При обновлении Vue сопоставляет элементы по ключу: тот же ключ — тот же элемент, даже если он сдвинулся. Без ключа сопоставление идёт по позиции, и элементы обновляются на месте.

#more
С индексом в качестве ключа после удаления или сортировки состояние элемента — значение поля, фокус, локальное состояние компонента — переезжает к соседу. Ключ должен быть стабильным уникальным идентификатором данных. Случайный ключ пересоздаёт все элементы на каждом рендере. Тот же механизм используют, чтобы пересоздать компонент: смена `key` сбрасывает его состояние.
::

::question
Почему нельзя ставить v-if и v-for на один элемент?

#answer
Во Vue 3 `v-if` выполняется раньше `v-for`, поэтому в условии переменная цикла ещё не определена — рендер падает. Фильтруют заранее в `computed` или ставят `v-for` на `<template>`, а `v-if` — на вложенный элемент.

#more
Во Vue 2 приоритет был обратный, и такой код работал, но фильтровал список на каждом рендере. `computed` кеширует результат и пересчитывается только при изменении исходного массива. Если условие не зависит от элемента («показать список, если он не пуст»), `v-if` ставят на обёртку списка.
::

::question
Во что компилируется v-model на input?

#answer
В привязку значения и обработчик: на текстовом поле — свойство `value` и событие `input`, на чекбоксе — `checked` и `change`, на `select` — `value` и `change`. На компоненте — проп `modelValue` и событие `update:modelValue`.

#more
Модификаторы `.lazy` (обновлять по `change`), `.number` и `.trim`. Значение текстового поля — строка, у `type="number"` Vue приводит его к числу. Во время ввода через IME `v-model` ждёт `compositionend`. На своём компоненте `v-model` удобно объявлять через `defineModel`.
::

::question
Что такое модификаторы директив?

#answer
Суффиксы через точку, которые меняют поведение директивы: `@submit.prevent` вызывает `preventDefault`, `@click.stop` — `stopPropagation`, `@keyup.enter` срабатывает только на Enter, `v-model.trim` обрезает пробелы.

#more
Модификаторы событий: `.prevent`, `.stop`, `.self`, `.once`, `.capture`, `.passive`, клавиши и `.exact`. Их можно комбинировать, порядок важен: `@click.prevent.self` отменит действие у кликов по потомкам тоже, а `@click.self.prevent` — только у кликов по самому элементу. В своих директивах модификаторы приходят в `binding.modifiers`.
::

::question
Как написать свою директиву и когда она нужна?

#answer
Объект с хуками жизненного цикла элемента: `mounted`, `updated`, `unmounted` и другими. В `<script setup>` переменная `vFocus` автоматически становится директивой `v-focus`. Нужна для низкоуровневой работы с DOM: фокус, внешний клик, подсветка.

#more
Хук получает элемент и `binding` со значением, аргументом и модификаторами. Глобально директиву регистрируют через `app.directive`. Если логика не работает с конкретным элементом, это композабл, а не директива. На компоненте директива применяется к его корневому элементу.
::

::question
Чем шаблоны лучше JSX?

#answer
Компилятор видит весь шаблон и знает, что в нём статично, а что меняется, — отсюда patch flags и вынос статичных узлов. Шаблон проще читать и проверять, а `vue-tsc` проверяет его по типам.

#more
JSX во Vue поддерживается через плагин и удобен там, где разметку генерируют программно. Но с JSX компилятор не может дать те же подсказки рантайму. Vapor mode тоже работает только с шаблонами.
::

## Практика

::practice{title="Почему упал список?"}
Нужно показать только товары в наличии:

```vue
<li v-for="p in products" v-if="p.inStock" :key="p.id">{{ p.title }}</li>
```

В консоли `Property "p" was accessed during render but is not defined` и `Cannot read properties of undefined`.

#solution
Во Vue 3 `v-if` обрабатывается раньше `v-for`, и в условии `p` ещё нет. Лучшее решение — отфильтровать в `computed`:

```vue
<script setup>
import { computed } from 'vue';

const available = computed(() => products.value.filter((p) => p.inStock));
</script>

<template>
  <li v-for="p in available" :key="p.id">{{ p.title }}</li>
</template>
```

`computed` пересчитается только при изменении `products`, а шаблон остался простым. Если фильтр нужен только для части разметки, цикл переносят на `<template v-for>`, а условие — на вложенный элемент. В проверке оба варианта показали только «Чай».
::

::practice{title="Почему итог «4901»?"}
```vue
<script setup>
import { ref, computed } from 'vue';
const qty = ref(0);
const next = computed(() => qty.value + 1);
</script>

<template>
  <input v-model="qty">   <!-- пользователь ввёл 490 -->
  <p>{{ next }}</p>       <!-- 4901 -->
</template>
```

#solution
Значение текстового поля — строка, и `v-model` записал в `qty` строку `"490"`. `"490" + 1` — конкатенация. Два исправления:

```vue
<input v-model.number="qty">
<input v-model="qty" type="number">
```

`.number` приводит значение через `parseFloat`, а у `type="number"` Vue делает это сам. Если ввод не превращается в число, остаётся исходная строка, поэтому значения формы всё равно проверяют перед отправкой. В проверке без модификатора получилось `"4901"`, в обоих исправленных вариантах — `491`.
::

::practice{title="Заметка переехала к другому товару"}
У каждой строки списка своё поле «заметка». Пользователь написал заметку у первого товара и удалил его — заметка оказалась у следующего:

```vue
<Row v-for="(p, index) in list" :key="index" :title="p.title" />
```

#solution
Ключи были `0, 1`, после удаления стали `0`. Для Vue строка с ключом `0` никуда не делась — у неё сменился только проп `title`. Компонент переиспользован вместе с внутренним состоянием, а удалена последняя строка.

```vue
<Row v-for="p in list" :key="p.id" :title="p.title" />
```

С ключом-идентификатором удаляется именно строка удалённого товара, а остальные сохраняют своё состояние. В проверке с `:key="index"` поле у «Кофе» содержало «про чай», с `:key="p.id"` — было пустым.
::
