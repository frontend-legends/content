# Provide / Inject

`provide`/`inject` - встроенный механизм **dependency injection** во Vue. Он решает ту же проблему, что и Context в React: передать данные глубоко вниз по дереву, минуя промежуточные компоненты и prop drilling.

---

## Проблема prop drilling

```
App (theme)
 └─ Layout (theme прокидывает)
     └─ Sidebar (theme прокидывает)
         └─ Button (наконец использует theme)
```

`Layout` и `Sidebar` вынуждены принимать и передавать `theme`, хотя сами им не пользуются. `provide`/`inject` убирает это посредничество.

---

## Как работает

**Предок** предоставляет значение через `provide(key, value)`. **Любой потомок** получает его через `inject(key)`.

```vue
<!-- предок -->
<script setup>
import { provide, ref } from 'vue';
const theme = ref('dark');
provide('theme', theme); // ключ + значение
</script>
```

```vue
<!-- любой потомок ниже по дереву -->
<script setup>
import { inject } from 'vue';
const theme = inject('theme'); // получаем напрямую
</script>

<template>
  <button :class="theme">OK</button>
</template>
```

Промежуточные компоненты ничего не знают про `theme` - связь прямая от предка к потомку.

---

## Реактивность инъекций

Чтобы потомки **реагировали** на изменение, предоставляй **реактивное** значение (`ref`/`reactive`), а не «сырое».

```js
const count = ref(0);
provide('count', count);   // ✅ реактивно: потомки обновятся при count.value++

provide('count', count.value); // ❌ передали число - связь с реактивностью потеряна
```

<b class="text-on-semi-light">Контроль изменений</b> - <span class="text-gray">Чтобы потомки не мутировали предоставленное состояние напрямую, отдавай `readonly`-обёртку, а для изменений - функцию-«мутатор». Это сохраняет однонаправленный поток.</span>

```js
provide('theme', {
  theme: readonly(theme),
  setTheme: (v) => { theme.value = v; }, // менять только так
});
```

---

## Injection keys и значения по умолчанию

Строковые ключи могут конфликтовать. Для крупных приложений и типобезопасности используют **Symbol-ключи**.

```js
// keys.js
export const themeKey = Symbol('theme');

// provide(themeKey, value) / inject(themeKey)
```

`inject` принимает значение по умолчанию на случай отсутствия предка:

```js
const theme = inject('theme', 'light'); // 'light', если никто не provide
```

> С TypeScript ключи типизируют через `InjectionKey<T>` - тогда `inject` выводит тип значения. Подробнее - в [TS с Vue](/content/typescript/ts-with-vue).

## Уровень приложения

Можно предоставить значение глобально, на уровне всего приложения:

```js
const app = createApp(App);
app.provide('config', { apiUrl: '/api' }); // доступно всем компонентам
```

Удобно для глобальной конфигурации, плагинов, i18n.

## Сравнение с React Context

| | Vue provide/inject | React Context |
|--|---------------------|----------------|
| Назначение | DI: значение вниз по дереву | то же |
| Реактивность | предоставляешь ref/reactive | значение провайдера |
| Ререндеры при смене | **точечные** (тонкая реактивность) | **все** потребители контекста |
| Ключи | строка или Symbol | объект контекста |

<b class="text-on-semi-light">Важное отличие</b> - <span class="text-gray">В React смена значения контекста перерисовывает **всех** потребителей. Во Vue потомок зависит только от тех реактивных данных, которые реально читает, - обновится лишь он, без массовых ререндеров. Поэтому у Vue нет «проблемы лишних ререндеров от контекста», которую в React лечат разделением контекстов и мемоизацией.</span>

---

## Когда использовать

- ✅ Тема, локаль, текущий пользователь, конфигурация, плагины.
- ✅ Дизайн-системы: компоненты-наборы, делящие состояние (как compound components).
- ❌ Полноценное глобальное состояние приложения - для него [Pinia](/content/vuejs/state-management): стор даёт devtools, структуру и доступ из любого места, не только из потомков.

## Вопросы на собеседовании

<b class="text-on-semi-light">Какую проблему решает provide/inject?</b>
<span class="text-gray">Prop drilling - проброс данных через промежуточные компоненты. Предок предоставляет значение, любой потомок получает его напрямую.</span>

<b class="text-on-semi-light">Как сделать инъекцию реактивной?</b>
<span class="text-gray">Предоставлять реактивное значение (ref/reactive), а не развёрнутый примитив. Тогда потомки реагируют на изменения.</span>

<b class="text-on-semi-light">Как запретить потомкам мутировать предоставленное состояние?</b>
<span class="text-gray">Отдавать `readonly`-обёртку и функцию-мутатор для изменений - сохраняя однонаправленный поток.</span>

<b class="text-on-semi-light">Зачем Symbol-ключи?</b>
<span class="text-gray">Избежать коллизий строковых ключей и обеспечить типобезопасность через `InjectionKey<T>`.</span>

<b class="text-on-semi-light">Чем provide/inject лучше Context по ререндерам?</b>
<span class="text-gray">Благодаря тонкой реактивности обновляется только потомок, читающий изменившиеся данные, а не все потребители - нет проблемы массовых ререндеров, как в React Context.</span>

<b class="text-on-semi-light">provide/inject или Pinia?</b>
<span class="text-gray">provide/inject - для DI вниз по дереву (тема, конфиг). Pinia - для полноценного глобального состояния с devtools и доступом откуда угодно.</span>
