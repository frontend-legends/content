# Продвинутая реактивность

Базовые `ref`/`reactive` покрывают 90% работы. Остальные 10% - инструменты для производительности, интеграции с внешним кодом и тонкого контроля над отслеживанием. Их знание - признак уверенного senior-уровня.

---

## shallowRef и shallowReactive

Обычный `reactive` делает реактивными **все вложенные** свойства (глубоко). Иногда это лишняя работа - например, для большого объекта или внешней структуры, которую ты заменяешь целиком.

```js
const state = shallowRef({ huge: data }); // реактивна только сама .value, не вложенное
state.value = { huge: newData };          // ✅ замена .value триггерит обновление
state.value.huge.x = 1;                   // ❌ мутация вложенного НЕ отследится
```

- **`shallowRef`** - отслеживает только присваивание `.value`, не вложенные мутации.
- **`shallowReactive`** - реактивны только свойства верхнего уровня.

<b class="text-on-semi-light">Зачем</b> - <span class="text-gray">Производительность: для больших структур, неизменяемых данных или объектов из сторонних библиотек глубокая реактивность - дорогая и ненужная. `shallowRef` + замена целиком дешевле. `triggerRef(state)` позволяет вручную форсировать обновление при мутации внутри shallow.</span>

## readonly

Создаёт **доступную только для чтения** обёртку над реактивным объектом - попытка изменить даст warning. Используется, чтобы отдавать состояние наружу без права мутации (например, в [provide/inject](/content/vuejs/provide-inject)).

```js
const state = reactive({ count: 0 });
const ro = readonly(state);
ro.count++; // ⚠️ warning, изменение не пройдёт
```

`shallowReadonly` делает readonly только верхний уровень.

## toRaw и markRaw

- **`toRaw`** - получить исходный (нереактивный) объект из Proxy. Для тяжёлых операций чтения без накладных расходов на отслеживание.
- **`markRaw`** - пометить объект, чтобы Vue **никогда** не делал его реактивным.

```js
const raw = toRaw(reactiveObj);          // оригинал без Proxy

const heavy = markRaw(new ThirdPartyMap()); // не оборачивать в реактивность
const state = reactive({ heavy });          // heavy останется «сырым»
```

<b class="text-on-semi-light">Когда `markRaw`</b> - <span class="text-gray">Для инстансов классов сторонних библиотек (карты Leaflet, чарты, WebGL-объекты), больших неизменяемых данных - чтобы Vue не тратил ресурсы на их проксирование и не ломал внутреннюю логику библиотеки.</span>

## customRef

Позволяет создать **свой** ref с кастомной логикой `track`/`trigger`. Классический пример - debounce-ref.

```js
function useDebouncedRef(value, delay = 300) {
  let timeout;
  return customRef((track, trigger) => ({
    get() { track(); return value; },
    set(newVal) {
      clearTimeout(timeout);
      timeout = setTimeout(() => { value = newVal; trigger(); }, delay);
    },
  }));
}

const search = useDebouncedRef(''); // обновляет зависимости с задержкой
```

Ты сам решаешь, когда собрать зависимость (`track`) и когда оповестить (`trigger`).

## effectScope

Группирует реактивные эффекты (`computed`, `watch`, `watchEffect`), чтобы остановить их **все разом**. Нужно, когда эффекты создаются **вне** компонента (в библиотеках, глобальных сторах) и автоматическая привязка к жизненному циклу не работает.

```js
const scope = effectScope();

scope.run(() => {
  watch(source, cb);
  watchEffect(() => { /* ... */ });
});

scope.stop(); // остановит все эффекты внутри scope - защита от утечек
```

> Внутри composable для cleanup вне компонента используется `onScopeDispose` - аналог `onUnmounted`, но привязанный к scope.

## nextTick

Vue обновляет DOM **асинхронно**, батчируя изменения. Чтобы получить доступ к **обновлённому** DOM после изменения состояния, используют `nextTick`.

```js
count.value++;
await nextTick();      // ждём, пока Vue применит изменения к DOM
console.log(el.textContent); // уже обновлено
```

<b class="text-on-semi-light">Почему асинхронно</b> - <span class="text-gray">Если в одном тике изменить состояние несколько раз, Vue применит все изменения **одним** обновлением DOM (батчинг), а не на каждое присваивание. `nextTick` даёт точку «после применения».</span>

## toRef / toRefs / toValue - напоминание

- **`toRefs(reactive)`** - превратить все свойства reactive в ref'ы (для деструктуризации без потери реактивности).
- **`toRef(obj, key)`** - один реактивный ref из свойства.
- **`toValue(x)`** - нормализовать «ref или значение» в значение (для гибких composables).

Базовая роль `toRefs` против потери реактивности при деструктуризации разобрана в [основах реактивности](/content/vuejs/reactivity-fundamentals).

## Вопросы на собеседовании

<b class="text-on-semi-light">Зачем нужен shallowRef?</b>
<span class="text-gray">Отслеживать только присваивание `.value`, без глубокой реактивности вложенного. Для производительности с большими/внешними структурами, которые заменяются целиком.</span>

<b class="text-on-semi-light">Что делает markRaw и когда он нужен?</b>
<span class="text-gray">Помечает объект, чтобы Vue никогда не делал его реактивным. Нужен для инстансов сторонних библиотек и тяжёлых неизменяемых данных - чтобы не тратить ресурсы и не ломать чужую логику.</span>

<b class="text-on-semi-light">Для чего customRef?</b>
<span class="text-gray">Создать ref с собственной логикой track/trigger - например, debounce-ref, который оповещает зависимости с задержкой.</span>

<b class="text-on-semi-light">Что решает effectScope?</b>
<span class="text-gray">Группирует эффекты, чтобы остановить их одним вызовом. Нужен, когда эффекты создаются вне компонента (сторы, библиотеки) и не привязываются к жизненному циклу автоматически.</span>

<b class="text-on-semi-light">Зачем nextTick?</b>
<span class="text-gray">Vue обновляет DOM асинхронно и батчированно. `nextTick` даёт точку после применения изменений к DOM - для измерений и доступа к обновлённой разметке.</span>

<b class="text-on-semi-light">Чем readonly полезен?</b>
<span class="text-gray">Отдавать реактивное состояние наружу без права мутации - например, в provide/inject, сохраняя однонаправленный поток.</span>
