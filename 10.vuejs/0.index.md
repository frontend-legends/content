# Vue

**Vue** - прогрессивный фреймворк для построения интерфейсов. Как и React, он строит UI из компонентов и держит его в синхроне с состоянием. Но делает это иначе: вместо «перерисуй компонент и сравни» Vue использует **тонкую реактивность** - точно знает, какие данные читает каждый кусок шаблона, и обновляет только его.

Именно реактивность - то, вокруг чего крутятся собеседования по Vue. Не «как написать `v-for`», а **почему `ref` нужно разыменовывать через `.value`**, **что теряется при деструктуризации `reactive`** и **чем `computed` отличается от `watch`**.

---

## Зачем это нужно фронтенд-инженеру

Vue - вторая по распространённости технология во фронтенде, и в ряде регионов и продуктов - основная. На собесе ждут понимания:

- как устроена **Proxy-реактивность** и чем она отличается от модели ре-рендера React;
- когда брать `ref`, а когда `reactive`, и где реактивность **молча ломается**;
- как `computed`, `watch` и `watchEffect` соотносятся и что выбрать;
- как Composition API заменил Options API и mixins, и почему;
- как работают слоты, `provide/inject`, Pinia, гидратация и Nuxt.

## Vue или React?

> Они решают одну задачу разными моделями. React: «состояние сменилось → перерисуй компонент → продиффь». Vue: «отследи, какие реактивные данные читает шаблон → при их изменении обнови ровно эти места». Поэтому в React ты вручную заботишься о мемоизации, а во Vue зависимости отслеживаются автоматически.

Если знаешь React - 80% идей перенесутся (компоненты, однонаправленный поток, гидратация). Оставшиеся 20% - реактивность - и есть то, ради чего эту главу читают.
