# Роутинг

Как и React, Vue сам по себе не знает про «страницы» - роутинг добавляет официальная библиотека **Vue Router**. Концепции клиентского роутинга те же (History API, навигация без перезагрузки), а специфика Vue - реактивный доступ к маршруту и навигационные guard'ы.

---

## SPA-роутинг кратко

В SPA загрузка происходит один раз, дальше навигация идёт на клиенте: меняется URL и рендерится другой компонент, без перезагрузки. Под капотом - **History API** браузера. Подробно механика разобрана в [роутинге React](/content/reactjs/routing) - здесь сосредоточимся на Vue Router.

---

## Vue Router

Маршруты сопоставляют путь с компонентом. Роутер монтируется в приложение, а `<RouterView>` рендерит компонент текущего маршрута.

```js
import { createRouter, createWebHistory } from 'vue-router';

const router = createRouter({
  history: createWebHistory(),       // HTML5 history (или createWebHashHistory)
  routes: [
    { path: '/', component: Home },
    { path: '/users/:id', component: User }, // динамический сегмент
    { path: '/:pathMatch(.*)*', component: NotFound }, // 404
  ],
});

app.use(router);
```

```vue
<template>
  <nav><RouterLink to="/users/1">User</RouterLink></nav>
  <RouterView />  <!-- сюда рендерится текущий маршрут -->
</template>
```

- `<RouterLink>` вместо `<a>` - клиентский переход без перезагрузки.
- `createWebHistory` - «чистые» URL (нужен history fallback на сервере); `createWebHashHistory` - URL с `#` (работает без серверной настройки).

## Доступ к маршруту

```vue
<script setup>
import { useRoute, useRouter } from 'vue-router';

const route = useRoute();   // реактивный текущий маршрут (params, query)
const router = useRouter(); // методы навигации

const id = route.params.id;       // реактивно
router.push('/users/2');          // программный переход
router.push({ name: 'user', params: { id: 2 } }); // по имени
</script>
```

<b class="text-on-semi-light">route реактивен</b> - <span class="text-gray">`route.params`/`route.query` реактивны: при переходе между `/users/1` и `/users/2` (тот же компонент) `params.id` обновится, но компонент **не пересоздаётся**. Чтобы среагировать на смену параметра - `watch(() => route.params.id, ...)`.</span>

## Вложенные маршруты

Маршруты образуют иерархию через `children`; родитель рендерит общий layout с вложенным `<RouterView>`.

```js
{
  path: '/user/:id',
  component: UserLayout,
  children: [
    { path: 'profile', component: Profile },
    { path: 'posts', component: Posts },
  ],
}
```

`UserLayout` содержит свой `<RouterView>`, куда подставляется `Profile` или `Posts` - аналог `<Outlet>` в React Router.

## Навигационные guard'ы

Главная Vue-специфика: **guard'ы** - перехватчики навигации для авторизации, подтверждений, аналитики.

```js
// глобальный - перед каждым переходом
router.beforeEach((to, from) => {
  if (to.meta.requiresAuth && !isLoggedIn()) {
    return { name: 'login' }; // редирект
  }
});
```

```js
// на уровне маршрута
{ path: '/admin', component: Admin, beforeEnter: (to) => checkAdmin() }
```

Есть и **внутрикомпонентные** guard'ы (`onBeforeRouteLeave` - например, предупредить о несохранённых данных).

> Guard на клиенте - это UX, **не безопасность**. Реальную проверку прав делает сервер; guard лишь прячет UI и редиректит.

## Ленивые маршруты

Code splitting по маршрутам - `component` задаётся динамическим импортом, грузится при переходе.

```js
{ path: '/dashboard', component: () => import('./Dashboard.vue') }
```

Это основной способ уменьшить начальный бандл - см. [производительность](/content/vuejs/performance).

---

## URL как состояние

Фильтры, страница, поисковый запрос логично хранить в **query-параметрах**, а не в `ref`.

```js
router.push({ query: { page: 2, sort: 'name' } });
const page = computed(() => Number(route.query.page) || 1);
```

<b class="text-on-semi-light">Зачем</b> - <span class="text-gray">URL становится шарабельным и переживает перезагрузку и навигацию назад/вперёд. Дублировать это в локальном состоянии - частая ошибка.</span>

## Роутинг в Nuxt

**Nuxt** даёт роутинг **по файловой системе**: файлы в `pages/` автоматически становятся маршрутами, без ручной конфигурации. Отдельная настройка Vue Router не нужна (см. [рендеринг и Nuxt](/content/vuejs/rendering-and-nuxt)).

## Вопросы на собеседовании

<b class="text-on-semi-light">Чем createWebHistory отличается от createWebHashHistory?</b>
<span class="text-gray">`createWebHistory` даёт чистые URL, но требует history fallback на сервере (любой путь отдаёт index.html). `createWebHashHistory` использует `#` и работает без серверной настройки.</span>

<b class="text-on-semi-light">Что происходит при переходе между /users/1 и /users/2?</b>
<span class="text-gray">Тот же компонент переиспользуется, `route.params` реактивно обновляется, но компонент не пересоздаётся. Чтобы среагировать - watch на `route.params.id` (или `:key`).</span>

<b class="text-on-semi-light">Что такое навигационные guard'ы?</b>
<span class="text-gray">Перехватчики навигации (`beforeEach`, `beforeEnter`, внутрикомпонентные) для авторизации, редиректов, подтверждений. Guard на клиенте - UX, не безопасность.</span>

<b class="text-on-semi-light">Как сделать ленивую загрузку маршрута?</b>
<span class="text-gray">Задать `component: () => import('...')` - код страницы грузится при переходе (code splitting).</span>

<b class="text-on-semi-light">Где хранить фильтры и пагинацию?</b>
<span class="text-gray">В query-параметрах URL - они шарабельны и переживают перезагрузку/навигацию, в отличие от локального ref.</span>
