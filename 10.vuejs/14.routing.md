# Маршрутизация

Как устроена маршрутизация во Vue: Vue Router, режимы истории, параметры и переиспользование компонента, вложенные маршруты, навигационные хуки, ленивые страницы, адрес как состояние и файловая маршрутизация. Спрашивают, чем `createWebHistory` отличается от hash-режима, как защитить страницу и как сделать ленивую загрузку маршрута. Глубже — почему при переходе между товарами не срабатывает `onMounted`, что возвращает `router.push` при отменённом переходе и что сервер должен отдавать на прямой заход по адресу.

::tldr
- **Vue Router сопоставляет адрес с деревом маршрутов и рисует компоненты в `RouterView`.** `createWebHistory` даёт обычные адреса, но сервер должен отдавать `index.html` на любой путь, иначе прямой заход даст 404.
- **При смене только параметров компонент переиспользуется:** `/products/1 → /products/2` не вызовет `setup` и `onMounted` снова. Реагируют через `watch` на параметр, `onBeforeRouteUpdate` или ключ у `RouterView`.
- **Навигационные хуки решают, разрешён ли переход:** глобальный `beforeEach` для доступа, `beforeEnter` у маршрута, `onBeforeRouteLeave` в компоненте для несохранённых данных. Хук возвращает `false` или новый адрес вместо вызова `next`.
- **`router.push` не бросает исключение при отменённом переходе, а возвращает объект сбоя.** Его проверяют через `isNavigationFailure`, а успешный переход возвращает `undefined`.
- **Страницы подключают лениво:** `component: () => import('./Page.vue')`. Файловая маршрутизация теперь встроена в Vue Router и генерирует маршруты и типы из файлов страниц.
::

## Как работает роутер

Клиентская маршрутизация в целом — History API, перехват ссылок, дерево маршрутов, фокус и прокрутка — разобрана в [Маршрутизации React](/content/reactjs/routing). Здесь — как это устроено во Vue Router.

Сквозной пример — магазин: главная, страница товара, кабинет с заказами, оформление заказа.

```js
// router.js
import { createRouter, createWebHistory } from 'vue-router';

export const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: HomePage },
    { path: '/products/:id', name: 'product', component: () => import('./ProductPage.vue'), props: true },
    {
      path: '/account',
      component: AccountLayout,
      meta: { auth: true },
      children: [{ path: 'orders', component: () => import('./OrdersPage.vue') }],
    },
    { path: '/checkout', component: () => import('./CheckoutPage.vue') },
    { path: '/:pathMatch(.*)*', component: NotFound },
  ],
});
```

```vue
<!-- App.vue -->
<template>
  <nav>
    <RouterLink to="/">Главная</RouterLink>
    <RouterLink :to="{ name: 'product', params: { id: 7 } }">Улун</RouterLink>
  </nav>
  <RouterView />
</template>
```

`RouterView` — место, где рисуется компонент текущего маршрута. `RouterLink` рисует обычную ссылку `<a href>`, перехватывает клик и меняет адрес без перезагрузки. Он же добавляет классы `router-link-active` и `router-link-exact-active` — в проверке активная ссылка получила точный класс, а ссылка на главную — нет.

### Режимы истории

| Режим | Адрес | Что нужно от сервера |
| --- | --- | --- |
| `createWebHistory()` | `/products/7` | отдавать `index.html` на любой неизвестный путь |
| `createWebHashHistory()` | `/#/products/7` | ничего: часть после `#` не уходит на сервер |
| `createMemoryHistory()` | адрес не меняется | для SSR и тестов |

В веб-режиме адреса обычные, их индексируют поисковики и удобно передавать. Но при прямом заходе на `/products/7` браузер запросит этот путь у сервера, и если сервер знает только `index.html`, ответом будет 404. Отсюда настройка `try_files $uri /index.html` в nginx и правила перезаписи на хостингах (подробно — в [Контейнерах и Docker](/content/testing-deploying/containers-and-docker)). Последний маршрут `/:pathMatch(.*)*` ловит всё остальное и показывает свою страницу 404 — в проверке `pathMatch` содержал части неизвестного адреса.

## Параметры и текущий маршрут

`useRoute()` возвращает **реактивный** текущий маршрут: `route.params.id`, `route.query.sort`, `route.meta`. `useRouter()` — сам роутер для переходов: `router.push`, `router.replace`, `router.back`.

Опция `props: true` передаёт параметры компоненту пропсами. Тогда компонент не знает о роутере: его проще переиспользовать и тестировать.

### Компонент переиспользуется

Главная ловушка. Пользователь со страницы `/products/1` перешёл по ссылке «Похожие» на `/products/2`. Маршрут тот же — изменился только параметр. Vue Router **не пересоздаёт** компонент: он остаётся смонтированным, меняются только пропсы.

```text
/products/1 → /products/2
setup: 1 раз, onMounted: 1 раз, onBeforeRouteUpdate: сработал, watch(route.params.id): сработал
```

Это проверено: `setup` выполнился один раз, `onMounted` не повторился. Если загрузка товара написана в `onMounted`, на странице останется первый товар. Решения:

- **реагировать на параметр:** `watch(() => props.id, load, { immediate: true })` или библиотека загрузки с реактивным ключом (подробно — в [Загрузке данных](/content/vuejs/data-fetching));
- **`onBeforeRouteUpdate`** — хук перед сменой параметров того же маршрута, может отменить переход;
- **ключ у `RouterView`:** `<RouterView :key="$route.fullPath" />` пересоздаёт компонент при каждой смене адреса. Это просто, но выбрасывает всё состояние и перерисовывает страницу целиком.

### Вложенные маршруты

У маршрута могут быть дети, а у его компонента — свой `RouterView`. Для `/account/orders` роутер нарисует `AccountLayout`, а внутри его `RouterView` — `OrdersPage`. Проверено: кабинет показал заголовок и вложенную страницу заказов. Так общая рамка раздела — меню, заголовок — не перерисовывается при переходах внутри него.

## Навигационные хуки

Хук решает, можно ли выполнить переход. Он возвращает:

- `undefined` или `true` — разрешить;
- `false` — отменить;
- адрес — перенаправить.

Старая форма с третьим аргументом `next` работает, но новый код возвращает значение: так нельзя забыть вызвать `next` или вызвать его дважды.

### Доступ к страницам

```js
router.beforeEach((to) => {
  const auth = useAuthStore();
  if (to.meta.auth && !auth.isLoggedIn) {
    return { path: '/login', query: { redirect: to.fullPath } };
  }
});
```

В проверке переход на `/account/orders` без входа привёл на `/login?redirect=/account/orders`, а после входа переход по `redirect` открыл заказы. `meta` наследуется вложенными маршрутами: признак `auth` на `/account` защищает и `/account/orders`. Стор внутри хука вызывают в теле функции — к этому моменту Pinia уже установлена (подробно — в [Управлении состоянием](/content/vuejs/state-management)).

Проверка на клиенте — это удобство, а не защита: данные кабинета должен закрывать сервер (подробно — в [Аутентификации и токенах](/content/security-perfomance/authentication-and-tokens)).

### Уход со страницы

```js
// CheckoutPage.vue
onBeforeRouteLeave(() => {
  if (form.dirty) return window.confirm('Уйти без сохранения?');
});
```

`onBeforeRouteLeave` вызывается, когда пользователь уходит с маршрута этого компонента. В проверке хук вернул `false`, и адрес остался `/checkout`. Закрытие вкладки роутер не перехватывает — для него нужен `beforeunload`.

Хуки по уровням: `beforeEach` и `afterEach` — глобальные, `beforeEnter` — в описании маршрута, `onBeforeRouteUpdate` и `onBeforeRouteLeave` — в компоненте.

### Результат перехода

`router.push` возвращает промис. Если переход отменён хуком, перенаправлен или ведёт туда же, промис **не отклоняется**, а разрешается объектом сбоя:

```js
const failure = await router.push('/');
if (isNavigationFailure(failure, NavigationFailureType.aborted)) {
  showToast('Сначала сохраните заказ');
}
```

В проверке отменённый переход вернул сбой типа `aborted`, повторный переход на текущий адрес — `duplicated`, а успешный — `undefined`. Поэтому `await router.push(...)` в `try/catch` не поймает отмену — её проверяют явно.

## Ленивые маршруты

```js
{ path: '/reports', component: () => import('./ReportsPage.vue') }
```

Функция вместо компонента говорит роутеру загрузить код при первом переходе. Сборщик выносит страницу в отдельный чанк (подробно — в [Модулях](/content/javascript/modules)). В проверке загрузчик не вызывался, пока на страницу не перешли, и вызвался один раз при переходе.

Если чанк не загрузился — обычно после деплоя, когда старые файлы удалены, — роутер вызывает `router.onError`. Типичная обработка — перезагрузить страницу по целевому адресу.

## Адрес как состояние

Фильтры, сортировку, страницу и выбранную вкладку держат в `query`, а не в `ref`: тогда ссылкой можно поделиться, кнопка «Назад» работает, а перезагрузка не теряет выбор.

```js
const route = useRoute();
const router = useRouter();

const sort = computed({
  get: () => route.query.sort ?? 'popular',
  set: (value) => router.replace({ query: { ...route.query, sort: value } }),
});
```

`replace` меняет адрес без новой записи в истории — для фильтров это правильно: «Назад» должен вернуть на прошлую страницу, а не на прошлую сортировку. Значения `query` — строки, числа и булевы значения приводят явно. В проверке `replace` дописал `?sort=price` к адресу без новой записи.

Позицию прокрутки при переходах задаёт опция `scrollBehavior` роутера: вернуть сохранённую позицию при «Назад», к началу — при новом переходе.

## Файловая маршрутизация и Nuxt

Писать массив маршрутов вручную необязательно. В Vue Router 5 встроена **файловая маршрутизация**, которая раньше была отдельным пакетом `unplugin-vue-router`: плагин сборки `vue-router/vite` генерирует маршруты из файлов страниц и **типы** для них.

```text
src/pages/
  index.vue              → /
  products/[id].vue      → /products/:id
  account.vue            → /account (рамка с RouterView)
  account/orders.vue     → /account/orders
  [...path].vue          → всё остальное
```

С типами `router.push({ name: '/products/[id]', params: { id: 7 } })` проверяется компилятором: опечатка в имени или забытый параметр — ошибка. Для существующих проектов без файловой маршрутизации переход с версии 4 на 5 не требует изменений кода, а следующая версия будет только :term[ESM]{def="ES-модули: стандартная система модулей JavaScript с import и export"} и уберёт устаревшие API.

Nuxt использует ту же схему с папкой `pages/`, плюс `definePageMeta` для мета-данных, `middleware` вместо глобальных хуков и `<NuxtLink>` с предзагрузкой страниц (подробно — в [Рендеринге и Nuxt](/content/vuejs/rendering-and-nuxt)).

## Красные флаги в ответе

- **«При смене параметра компонент создаётся заново».** Он переиспользуется, `onMounted` не повторится.
- **«`createWebHistory` работает без настройки сервера».** Прямой заход на вложенный адрес даст 404, если сервер не отдаёт `index.html`.
- **«`try/catch` вокруг `router.push` поймает отменённый переход».** Отмена — не исключение, а объект сбоя.
- **«Проверка в `beforeEach` защищает данные».** Это удобство интерфейса, защищать должен сервер.
- **«Фильтры удобно держать в `ref`».** Они теряются при перезагрузке и не попадают в ссылку, их место — `query`.

## Как спрашивают на собеседовании

::question
Чем createWebHistory отличается от createWebHashHistory?

#answer
`createWebHistory` использует History API и обычные адреса `/products/7`. `createWebHashHistory` держит путь после `#`: `/#/products/7`. Часть после `#` не уходит на сервер, поэтому hash-режиму не нужна настройка сервера.

#more
В веб-режиме сервер должен отдавать `index.html` на любой неизвестный путь, иначе прямой заход или перезагрузка вложенной страницы даст 404. Hash-адреса хуже для SEO и выглядят непривычно. `createMemoryHistory` не трогает адрес браузера — для SSR и тестов.
::

::question
Почему при переходе между товарами не обновляются данные?

#answer
Маршрут тот же, меняется только параметр, и Vue Router переиспользует компонент: `setup` и `onMounted` второй раз не выполняются. Если загрузка в `onMounted`, на странице остаётся первый товар.

#more
Решения: `watch(() => props.id, load, { immediate: true })`, `onBeforeRouteUpdate`, библиотека загрузки с реактивным ключом или `<RouterView :key="$route.fullPath" />`. Последний вариант пересоздаёт компонент целиком и выбрасывает его состояние, поэтому его используют осознанно.
::

::question
Как защитить страницу от неавторизованного пользователя?

#answer
Глобальным хуком `router.beforeEach`: если у маршрута `meta.auth`, а пользователь не вошёл, вернуть адрес входа с параметром `redirect`. После входа вернуть пользователя по этому параметру.

#more
`meta` наследуется вложенными маршрутами. Хук возвращает `false`, адрес или ничего — без `next`. Стор вызывают внутри хука. Клиентская проверка — только удобство: сервер обязан проверять доступ к данным сам.
::

::question
Как сделать ленивую загрузку маршрута?

#answer
Указать вместо компонента функцию с динамическим импортом: `component: () => import('./ReportsPage.vue')`. Сборщик выносит страницу в отдельный чанк, и он загружается при первом переходе.

#more
Ошибку загрузки чанка, частую после деплоя, ловят через `router.onError` и перезагружают страницу. Предзагрузка — `<link rel="prefetch">` или подгрузка при наведении на ссылку; `NuxtLink` в Nuxt делает её сам.
::

::question
Что вернёт router.push, если переход отменён?

#answer
Промис разрешится объектом сбоя, а не отклонится. Тип проверяют через `isNavigationFailure(failure, NavigationFailureType.aborted)`. Успешный переход возвращает `undefined`.

#more
Типы сбоев: `aborted` — хук вернул `false`, `cancelled` — начался другой переход, `duplicated` — переход на текущий адрес. Поэтому `try/catch` вокруг `await router.push` отмену не поймёт. Исключения бывают только при ошибках внутри хуков и загрузке компонентов.
::

::question
Как предупредить о несохранённых данных при уходе со страницы?

#answer
`onBeforeRouteLeave` в компоненте: вернуть `false`, если пользователь не подтвердил уход. Роутер отменит переход, и адрес останется прежним.

#more
Хук срабатывает только на переходах внутри приложения. Закрытие вкладки и перезагрузку перехватывает событие `beforeunload`. Если форма большая, черновик стоит сохранять в хранилище, чтобы уход не терял данные вовсе.
::

## Практика

::practice{title="На странице остаётся старый товар"}
```vue
<!-- ProductPage.vue, маршрут /products/:id с props: true -->
<script setup>
const props = defineProps({ id: String });
const product = ref(null);

onMounted(async () => {
  product.value = await api.product(props.id);
});
</script>
```

Ссылки «Похожие товары» меняют адрес, но карточка не обновляется.

#solution
`/products/1` и `/products/2` — один маршрут, и роутер переиспользовал компонент: `onMounted` больше не вызывается. Загрузку привязывают к параметру:

```js
watch(() => props.id, async (id, _, onCleanup) => {
  let stale = false;
  onCleanup(() => { stale = true; });
  const data = await api.product(id);
  if (!stale) product.value = data;
}, { immediate: true });
```

`immediate` загружает первый товар, `watch` — следующие, а флаг не даёт медленному ответу перезаписать новый. С библиотекой загрузки достаточно ключа `['product', () => props.id]`. В проверке при переходе с товара 1 на товар 2 `setup` и `onMounted` выполнились один раз, а `watch` и `onBeforeRouteUpdate` — сработали.
::

::practice{title="Перезагрузка страницы даёт 404"}
Приложение с `createWebHistory` работает при переходах по ссылкам, но перезагрузка на `/account/orders` показывает 404 от сервера.

#solution
Адрес обрабатывает клиентский роутер, а при перезагрузке браузер запрашивает `/account/orders` у сервера. Сервер знает только статические файлы и такого файла не находит. Нужно отдавать `index.html` на все пути, кроме существующих файлов:

```text
location / {
  try_files $uri $uri/ /index.html;
}
```

Тогда сервер вернёт приложение, а роутер покажет нужную страницу — или свою страницу 404 через маршрут `/:pathMatch(.*)*`. У такого 404 статус ответа 200, поэтому для поисковиков неизвестные адреса лучше обрабатывать на сервере или через SSR. Альтернатива без настройки сервера — `createWebHashHistory`, ценой адресов с `#`.
::
