# Управление состоянием

Как и в React, выбор инструмента начинается с вопроса «**какой это тип состояния?**». Большая часть «глобального состояния» - это серверные данные, которым стор не нужен. Для настоящего глобального состояния во Vue есть **Pinia** (заменил Vuex).

---

## Таксономия состояния

| Тип | Что это | Чем управлять |
|-----|---------|---------------|
| **Local UI state** | открыт ли модал, значение поля, активный таб | `ref`/`reactive` в компоненте |
| **Server state** | данные с бэкенда | TanStack Query / `useFetch` |
| **Global client state** | тема, авторизация, корзина | Pinia / provide-inject |
| **URL state** | фильтры, страница, поиск | Vue Router (query) |

<b class="text-on-semi-light">Главное</b> - <span class="text-gray">Server state - это кэш удалённых данных (асинхронный, устаревает, разделяемый), а не состояние приложения. Держать его в сторе вручную - переизобретать кэш. Для него - [загрузка данных](/content/vuejs/data-fetching). После выноса server state глобального состояния часто почти не остаётся.</span>

---

## Лестница решений

1. **`ref`/`reactive`** - локальное состояние компонента.
2. **Подъём состояния** в общего родителя - для соседей.
3. **[provide/inject](/content/vuejs/provide-inject)** - DI вниз по дереву (тема, конфиг).
4. **Pinia** - полноценное глобальное состояние с devtools и доступом откуда угодно.

---

## Pinia

Официальный стейт-менеджер Vue. Стор объявляется через `defineStore` и состоит из **state**, **getters** (производные, как computed) и **actions** (методы/мутации, в т.ч. асинхронные).

### Setup-стор (рекомендуется)

Выглядит как composable - те же `ref`/`computed`/функции.

```js
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';

export const useCounterStore = defineStore('counter', () => {
  const count = ref(0);                          // state
  const double = computed(() => count.value * 2); // getter
  function increment() { count.value++; }        // action
  return { count, double, increment };
});
```

### Options-стор

Альтернативный синтаксис, похожий на Options API:

```js
export const useCounterStore = defineStore('counter', {
  state: () => ({ count: 0 }),
  getters: { double: (s) => s.count * 2 },
  actions: { increment() { this.count++; } },
});
```

### Использование

```vue
<script setup>
import { storeToRefs } from 'pinia';
import { useCounterStore } from '@/stores/counter';

const store = useCounterStore();
const { count, double } = storeToRefs(store); // деструктуризация без потери реактивности
const { increment } = store;                   // методы берём напрямую
</script>
```

<b class="text-on-semi-light">storeToRefs</b> - <span class="text-gray">Прямая деструктуризация стора (`const { count } = store`) **теряет реактивность** - та же проблема, что у `reactive` ([основы реактивности](/content/vuejs/reactivity-fundamentals)). `storeToRefs` оборачивает свойства в ref'ы и сохраняет связь. Методы можно деструктурировать как есть.</span>

## Pinia vs Vuex (legacy)

**Vuex** - прежний официальный стор. Pinia стал стандартом в Vue 3, а Vuex - legacy.

| | Vuex (legacy) | Pinia |
|--|----------------|-------|
| Мутации | отдельная концепция `mutations` | **нет** - меняешь state в actions напрямую |
| Модули | вложенные, громоздкие | плоские сторы, каждый - свой `useXStore` |
| TypeScript | слабый | отличный из коробки |
| API | `state/getters/mutations/actions` | `state/getters/actions` |
| Boilerplate | много | мало |

<b class="text-on-semi-light">Почему Pinia</b> - <span class="text-gray">Главное упрощение - **убрали mutations**: в Vuex нужно было `commit('mutation')` для синхронных изменений и `dispatch('action')` для асинхронных. В Pinia всё - actions, state меняется напрямую. Плюс плоская структура и хорошая типизация.</span>

> Знать Vuex стоит для legacy-проектов; новое пишут на Pinia.

## Реактивность вместо селекторов

В Redux нужны **селекторы**, чтобы подписаться на срез и не ловить лишние ререндеры. В Pinia это не нужно: благодаря [тонкой реактивности](/content/vuejs/reactivity-fundamentals) компонент автоматически зависит только от тех полей стора, которые читает, и обновляется точечно.

```js
const store = useCounterStore();
// компонент, читающий store.count, реагирует только на count - без ручных селекторов
```

<b class="text-on-semi-light">Это важное отличие от React-экосистемы</b> - <span class="text-gray">В Redux/Zustand селекторы - часть API именно из-за модели ре-рендера. Во Vue реактивность даёт точечные обновления «бесплатно».</span>

## Вопросы на собеседовании

<b class="text-on-semi-light">Как выбрать инструмент для состояния во Vue?</b>
<span class="text-gray">Классифицировать: server state → TanStack Query, локальное → ref, DI вниз → provide/inject, глобальное → Pinia. Стор - не выбор по умолчанию.</span>

<b class="text-on-semi-light">Чем Pinia отличается от Vuex?</b>
<span class="text-gray">Нет mutations (state меняется в actions напрямую), плоские сторы вместо вложенных модулей, отличный TypeScript, меньше бойлерплейта.</span>

<b class="text-on-semi-light">Зачем нужен storeToRefs?</b>
<span class="text-gray">Прямая деструктуризация стора теряет реактивность (как у reactive). `storeToRefs` оборачивает поля в ref'ы, сохраняя связь.</span>

<b class="text-on-semi-light">Нужны ли в Pinia селекторы, как в Redux?</b>
<span class="text-gray">Нет. Тонкая реактивность даёт точечные обновления: компонент зависит только от читаемых полей стора - без ручных селекторов.</span>

<b class="text-on-semi-light">Из чего состоит стор Pinia?</b>
<span class="text-gray">State (реактивные данные), getters (производные, как computed) и actions (методы, включая асинхронные). В setup-сторе это ref/computed/функции.</span>
