# Основы реактивности

Как Vue узнаёт, что данные изменились и кого обновить: Proxy, отслеживание зависимостей и эффекты, `ref` и `reactive`, разворачивание `.value` и места, где реактивность молча пропадает. Спрашивают, чем `ref` отличается от `reactive`, зачем нужен `.value` и как работает реактивность под капотом. Глубже — почему изменение исходного объекта ничего не обновляет, почему деструктуризация рвёт связь и чем живая ссылка Vue отличается от снимка состояния в React.

::tldr
- **Реактивность — это эффекты, которые запоминают, какие данные прочитали.** Чтение через Proxy записывает зависимость, запись запускает зависящие эффекты: рендер компонента, `computed`, `watch`.
- **`ref` — объект с полем `.value`, `reactive` — Proxy над объектом.** `.value` нужен, потому что чтение и запись примитива перехватить нельзя. Объект в `ref` автоматически становится `reactive`.
- **Proxy — не исходный объект.** Изменения в обход Proxy не отслеживаются, а `reactive(obj) !== obj`. Вложенные объекты становятся реактивными при обращении к ним.
- **Реактивность теряется, когда значение копируется:** деструктуризация `reactive`, передача `state.count` в функцию, замена переменной с `reactive` целиком. Спасают `toRefs`, `toRef`, геттеры и `ref`.
- **Изменение синхронное, обновление DOM — нет.** `count.value` сразу новый, а DOM обновится в следующем такте; колбэки видят актуальное значение, а не снимок.
::

## Что такое реактивность

Сквозной пример — строка корзины:

```js
const qty = ref(1);
const price = ref(490);
const total = computed(() => qty.value * price.value);

qty.value = 2;   // total сам станет 980, а шаблон с {{ total }} обновится
```

Мы нигде не написали «при изменении `qty` пересчитай `total`». Vue понял это сам: функция `computed` при выполнении **прочитала** `qty` и `price`, и Vue запомнил эти зависимости. Это и есть реактивность — данные знают, кто их читает, и при изменении сообщают именно этим читателям.

Общая идея реактивного программирования — в [Реактивном программировании](/content/computer-science/reactive-programming), а связь с сигналами других фреймворков — в [Сигналах и реактивности](/content/modern-dev/signals-and-reactivity). Здесь — как это устроено во Vue.

## Как это работает

Механизм — три части.

**Эффект** — функция, которую Vue умеет перезапускать: render-функция компонента, `computed`, `watch` и `watchEffect`. Пока эффект выполняется, Vue помнит, какой эффект сейчас активен.

**track** — при **чтении** реактивного свойства Vue записывает: «активный эффект зависит от этого свойства этого объекта».

**trigger** — при **записи** Vue находит все эффекты, зависящие от свойства, и запускает их.

Упрощённая модель, которая работает так же (проверено):

```js
const targetMap = new WeakMap();   // объект → ключ → эффекты
let activeEffect = null;

function track(target, key) {
  if (!activeEffect) return;
  let deps = targetMap.get(target);
  if (!deps) targetMap.set(target, (deps = new Map()));
  let effects = deps.get(key);
  if (!effects) deps.set(key, (effects = new Set()));
  effects.add(activeEffect);
}

function trigger(target, key) {
  targetMap.get(target)?.get(key)?.forEach((fn) => fn());
}

function reactive(target) {
  return new Proxy(target, {
    get(t, key, receiver) {
      track(t, key);
      return Reflect.get(t, key, receiver);
    },
    set(t, key, value, receiver) {
      const old = t[key];
      const ok = Reflect.set(t, key, value, receiver);
      if (!Object.is(old, value)) trigger(t, key);
      return ok;
    },
  });
}

function effect(fn) {
  const run = () => { activeEffect = run; try { fn(); } finally { activeEffect = null; } };
  run();
}
```

`WeakMap` не держит объекты в памяти, если на них больше никто не ссылается. Как устроены `Proxy` и `Reflect` — в [Метапрограммировании](/content/javascript/metaprogramming). Настоящая реализация сложнее: связи эффектов и зависимостей хранятся двусвязными списками, у зависимостей есть версии, а `computed` пересчитывается лениво. Но модель та же. Реализовать её с нуля просят на кодинг-интервью (подробно — в [Реализации фреймворков](/content/common-coding-questions/framework-implementation)).

### Следствия механизма

- **Зависимость — это то, что прочитано, а не то, что упомянуто в коде.** Если эффект читает `price` только при `showPrice === true`, то пока условие ложно, изменение `price` эффект не запускает. Зависимости собираются заново при каждом запуске — в проверке эффект начал реагировать на `price` только после включения условия.
- **Запись того же значения ничего не запускает:** сравнение через `Object.is`.
- **Изменение в обход Proxy не видно.** Если поменять исходный объект напрямую, `set` у Proxy не вызывается и `trigger` не происходит.

Модель работает с объектами: у Proxy есть ловушки для свойств. А как быть с числом `qty`?

## ref и reactive

### Зачем .value

Proxy можно создать только над объектом. У числа нет свойств, чтение и запись переменной `let qty = 1` перехватить невозможно. Поэтому `ref` кладёт значение в объект, у которого есть свойство `.value` с геттером и сеттером — а в них те же `track` и `trigger`:

```js
const qty = ref(1);
qty.value++;            // запись через сеттер → trigger
```

В шаблоне `.value` не пишут: ref верхнего уровня разворачивается автоматически (подробности ниже). В `<script>` `.value` обязателен, и забытый `.value` — самая частая ошибка: `if (qty)` всегда истинно, потому что `qty` — объект.

### ref с объектом

Если положить в `ref` объект, его `.value` становится `reactive`-прокси, и реактивность работает вглубь:

```js
const product = ref({ title: 'Чай', tags: ['зелёный'] });
product.value.tags.push('байховый');   // отслеживается
product.value = { title: 'Кофе', tags: [] };   // замена целиком — тоже
```

Если глубина не нужна (большие неизменяемые данные), есть `shallowRef` — подробно в [Продвинутой реактивности](/content/vuejs/reactivity-advanced).

### reactive

`reactive` возвращает Proxy над объектом, без `.value`:

```js
const cart = reactive({ items: [], coupon: null });
cart.items.push('чай');
```

Три факта про идентичность, которые проверены и на которых часто ловят:

- **`reactive(obj) !== obj`.** Proxy — другой объект. Код, который хранит ссылку на исходный объект и меняет его, реактивность обходит. В проверке запись в исходный объект не запустила эффект, а та же запись через Proxy — запустила.
- **Proxy кешируется:** `reactive(obj) === reactive(obj)`, а `reactive(proxy)` возвращает тот же прокси.
- **Вложенные объекты оборачиваются лениво** — при обращении к ним, а не при создании.

`reactive` работает с обычными объектами, массивами, `Map` и `Set`. Для примитива вернёт его же и предупредит «value cannot be made reactive».

### Почему Proxy, а не геттеры

Vue 2 строил реактивность на `Object.defineProperty`: при создании обходил объект и превращал каждое существующее свойство в геттер и сеттер.

| | Vue 2: `Object.defineProperty` | Vue 3: `Proxy` |
| --- | --- | --- |
| Новые свойства | не отслеживались, нужен `Vue.set` | отслеживаются |
| Удаление | не отслеживалось, нужен `Vue.delete` | отслеживается |
| Запись по индексу, `length` | не отслеживались | отслеживаются |
| `Map`, `Set` | не поддерживались | поддерживаются |
| Инициализация | обход всех свойств сразу | ленивая обёртка при доступе |

В проверке эффект сработал на запись по индексу, новое свойство, `delete`, `Set.add` и `length = 0`. Отсюда в старом коде `this.$set(obj, 'key', value)` — во Vue 3 это просто присваивание.

С созданием состояния разобрались. Осталось понять, где Vue сам снимает `.value`.

## Разворачивание ref

`.value` снимается автоматически в трёх местах:

- **в шаблоне** — ref верхнего уровня `<script setup>`: `{{ qty + 1 }}`;
- **в `reactive`-объекте** — ref в свойстве: `reactive({ qty }).qty` — число, и запись идёт в исходный ref;
- **в деструктурированных пропсах** — это делает компилятор.

И не снимается:

- **в массивах и коллекциях:** `reactive([ref(1)])[0]` — всё ещё ref, `reactive(new Map([['a', ref(1)]])).get('a')` — тоже;
- **в обычном объекте в шаблоне:** если `plain = { count: ref(1) }` — не реактивный объект, то `{{ plain.count }}` покажет `1` (вывод текста разворачивает ref), а `{{ plain.count + 1 }}` — строку `[object Object]1`. Проверено: в выражении разворачиваются только переменные верхнего уровня.

Разворачивание удобно, но создаёт иллюзию, что `.value` не важен. А потеря `.value` и есть главный способ сломать реактивность.

## Где реактивность теряется

Реактивность живёт в объекте-Proxy или в ref. Всё, что **копирует значение**, рвёт связь — и без ошибок.

### Деструктуризация reactive

```js
const user = reactive({ name: 'Аня', age: 30 });
let { age } = user;   // копия числа 30
user.age = 31;
age;                  // 30
```

Нужна ссылка на свойство, а не значение:

```js
const { name, age } = toRefs(user);   // каждое поле — ref, связанный с user
const ageRef = toRef(user, 'age');    // одно поле
```

В проверке ref из `toRefs` видел изменения `user` и сам менял его. Деструктуризация пропсов в `<script setup>` — исключение: компилятор переписывает обращения к `props.x`, и связь сохраняется (подробно — в [Связи компонентов](/content/vuejs/components-communication)).

### Передача значения в функцию

```js
function useDiscount(price) {
  return computed(() => price * 0.9);
}

const discount = useDiscount(price.value);   // передано число — computed навсегда 90
```

Функция получила число, а не ссылку, и `computed` не читает ничего реактивного. Композаблы принимают ref или геттер и читают через `toValue`:

```js
function useDiscount(price) {
  return computed(() => toValue(price) * 0.9);   // ref, геттер или число
}

useDiscount(price);               // ref
useDiscount(() => props.price);   // геттер
```

В проверке версия с числом осталась `90` после изменения цены, а версии с ref и геттером дали `180`.

### Замена reactive целиком

```js
let form = reactive({ email: '', agree: false });

function reset() {
  form = reactive({ email: '', agree: false });   // шаблон и эффекты смотрят на старый Proxy
}
```

Эффекты подписаны на старый объект. Для `reactive` меняют содержимое — `Object.assign(form, initial())`, — либо хранят состояние в `ref` и заменяют `.value`. Оба варианта проверены.

### Деструктуризация в шаблоне и при возврате

Та же ошибка встречается при возврате из композабла: `return { ...toRefs(state) }` сохраняет связь, а `return { ...state }` — нет.

## ref или reactive

Официальная рекомендация — **`ref` по умолчанию**:

- работает с любыми значениями, включая примитивы;
- заменяется целиком через `.value`;
- деструктуризация объекта с ref-ами не рвёт связь — ref остаётся ref;
- по коду видно, где реактивное значение: `.value` — явный маркер.

`reactive` удобен для группы тесно связанных полей, например состояния формы, если помнить о деструктуризации и замене. Смешивать можно, главное — единообразие в команде.

## Когда обновится DOM

Запись в реактивное значение **синхронна**: сразу после `qty.value = 2` чтение `qty.value` вернёт `2`, а `computed` при следующем чтении пересчитается. Но эффект рендера компонента не запускается сразу — он встаёт в очередь, и DOM обновится чуть позже, один раз на все изменения:

```js
qty.value = 2;
el.textContent;    // ещё старое значение
await nextTick();
el.textContent;    // новое
```

Как устроена очередь — в [Продвинутой реактивности](/content/vuejs/reactivity-advanced).

### Живая ссылка и снимок

Здесь главное отличие от React. Там значение состояния — **снимок** рендера: колбэк, созданный в рендере, видит то значение, которое было в момент рендера (подробно — в [Состоянии и событиях React](/content/reactjs/state-and-events)). Во Vue `qty` — **живая ссылка**: колбэк в `setTimeout` прочитает `qty.value` в момент вызова и получит актуальное значение. В проверке таймер, созданный при `0`, прочитал `3`. Устаревших замыканий, как в React, во Vue почти нет, зато нет и неизменяемых снимков: если нужно значение «на момент события», его копируют явно.

---

## Красные флаги в ответе

- **«Vue сравнивает старое и новое состояние, чтобы найти изменения».** Vue перехватывает запись через Proxy и сразу знает, какие эффекты зависят от свойства.
- **«`reactive(obj)` делает `obj` реактивным».** Реактивен возвращённый Proxy, изменения исходного объекта не отслеживаются.
- **«`.value` нужен для совместимости».** Без обёртки в объект запись примитива перехватить невозможно.
- **«Деструктуризация `reactive` сохраняет реактивность».** Она копирует значения, нужны `toRefs` или `toRef`.
- **«После `count.value++` DOM уже новый».** Значение новое, DOM обновится после `nextTick`.

## Как спрашивают на собеседовании

::question
Чем ref отличается от reactive?

#answer
`ref` оборачивает любое значение в объект с `.value`, работает и с примитивами, его можно заменить целиком. `reactive` возвращает Proxy объекта, без `.value`, но не работает с примитивами и теряет связь при деструктуризации и замене переменной.

#more
Объект внутри `ref` автоматически становится `reactive`. Ref в свойстве `reactive`-объекта разворачивается, а в массиве и `Map` — нет. По умолчанию рекомендуют `ref`: явный маркер `.value` и меньше способов потерять реактивность.
::

::question
Зачем ref нужен .value?

#answer
Чтение и запись примитива нельзя перехватить: у числа нет свойств, на которые можно поставить ловушку. `ref` кладёт значение в объект, где у `.value` есть геттер и сеттер — в них Vue отслеживает чтение и запускает эффекты при записи.

#more
В шаблоне ref верхнего уровня разворачивается, в `<script>` — нет, и забытый `.value` даёт объект вместо значения: `if (flag)` всегда истинно. В выражениях шаблона разворачиваются только переменные верхнего уровня, ref внутри обычного объекта — нет.
::

::question
Как работает реактивность Vue 3 под капотом?

#answer
Через Proxy и эффекты. Эффект — рендер компонента, `computed`, `watch` — при выполнении читает реактивные свойства, и Proxy записывает зависимость (track). При записи Proxy находит зависящие эффекты и запускает их (trigger).

#more
Зависимости собираются заново при каждом запуске, поэтому учитывается только реально прочитанное. Запись того же значения ничего не запускает. Связи хранятся по объекту и ключу в `WeakMap`. Эффекты компонентов не выполняются сразу, а ставятся в очередь, поэтому DOM обновляется асинхронно, одним проходом.
::

::question
Почему Vue 3 перешёл на Proxy?

#answer
`Object.defineProperty` во Vue 2 перехватывал только существующие свойства: не отслеживались новые свойства, удаление, запись по индексу и `length`, отсюда `Vue.set` и `Vue.delete`. Proxy перехватывает операции над объектом целиком.

#more
Proxy также поддерживает `Map` и `Set` и позволяет оборачивать вложенные объекты лениво, при доступе, а не обходить всё дерево при создании. Цена — Proxy не равен исходному объекту, и изменения в обход прокси не отслеживаются.
::

::question
Почему деструктуризация reactive ломает реактивность?

#answer
Реактивность работает через обращение к Proxy. `const { age } = user` копирует значение в локальную переменную, и дальнейшие изменения `user.age` её не трогают. Нужна ссылка: `toRefs(user)` или `toRef(user, 'age')`.

#more
Та же проблема — при передаче `state.count` в функцию и при `return { ...state }` из композабла. Композаблы принимают ref или геттер и читают через `toValue`. Деструктуризация пропсов в `<script setup>` — исключение: компилятор сохраняет связь.
::

::question
Почему изменение объекта не обновило интерфейс?

#answer
Скорее всего, изменение прошло мимо Proxy: код держит ссылку на исходный объект, который передали в `reactive`, и меняет его. `set` у Proxy не вызывается, эффекты не узнают об изменении.

#more
Другие причины: заменили переменную с `reactive` целиком, и шаблон смотрит на старый Proxy; объект помечен `markRaw` или лежит в `shallowRef`, где отслеживается только замена `.value`; значение скопировали деструктуризацией. Отладить зависимости помогают `onRenderTracked` и `onRenderTriggered`.
::

## Практика

::practice{title="Почему скидка не пересчитывается?"}
```js
function useDiscount(price) {
  return computed(() => price * 0.9);
}

const price = ref(100);
const discount = useDiscount(price.value);
price.value = 200;
discount.value;   // 90, а ожидали 180
```

#solution
В функцию передано число `100`, а не ссылка. Внутри `computed` ничего реактивного не читается, поэтому он вычислился один раз и больше не пересчитывается.

```js
import { computed, toValue } from 'vue';

function useDiscount(price) {
  return computed(() => toValue(price) * 0.9);
}

useDiscount(price);               // ref
useDiscount(() => props.price);   // геттер — для пропсов и вычислений
useDiscount(50);                  // обычное число тоже работает
```

`toValue` разворачивает ref, вызывает геттер и возвращает остальное как есть, и чтение происходит внутри `computed` — там, где Vue отслеживает зависимости. В проверке версия с числом осталась `90`, версии с ref и геттером дали `180`.
::

::practice{title="Форма не сбрасывается"}
```js
let form = reactive({ email: '', agree: false });

function reset() {
  form = reactive({ email: '', agree: false });
}
```

После `reset()` поля в интерфейсе остаются заполненными.

#solution
Шаблон и эффекты подписаны на тот Proxy, который был при рендере. Новый объект в переменной `form` им неизвестен. Два варианта:

```js
// reactive: меняем содержимое, а не объект
const initial = () => ({ email: '', agree: false });
const form = reactive(initial());
function reset() {
  Object.assign(form, initial());
}

// ref: заменяем .value целиком
const form = ref(initial());
function reset() {
  form.value = initial();
}
```

`const` вместо `let` сразу запрещает ошибочное переприсваивание. Фабрика `initial()` нужна, чтобы не делить один объект между состоянием и сбросом. В проверке переприсваивание не дошло до эффекта, а `Object.assign` и замена `.value` — дошли.
::

::practice{title="Что выведет шаблон?"}
```vue
<script setup>
import { ref } from 'vue';

const count = ref(1);
const plain = { count: ref(1) };
</script>

<template>
  <p>{{ count + 1 }} | {{ plain.count }} | {{ plain.count + 1 }}</p>
</template>
```

#solution
```text
2 | 1 | [object Object]1
```

- `count` — ref верхнего уровня, в выражении он разворачивается: `1 + 1 = 2`.
- `plain` — обычный объект, не `reactive`. `plain.count` — ref, но вывод текста сам разворачивает ref, поэтому видно `1`.
- В выражении `plain.count + 1` разворачивания нет: объект ref превращается в строку `[object Object]` и склеивается с `1`.

Исправления — `plain.count.value + 1`, вынести ref на верхний уровень (`const { count: c } = plain`) или сделать `plain` реактивным: `reactive({ count: ref(1) })` разворачивает свойства. Проверено на смонтированном компоненте: `2|1|[object Object]1|2`.
::
