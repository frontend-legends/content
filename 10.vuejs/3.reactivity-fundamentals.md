# Основы реактивности

Реактивность - сердце Vue и тема, которую на собеседованиях разбирают глубже всего. Понять её - значит понять, **почему `ref` требует `.value`**, **где реактивность молча ломается** и чем модель Vue отличается от ре-рендера React.

---

## ref и reactive

Два способа создать реактивное состояние.

```js
import { ref, reactive } from 'vue';

const count = ref(0);              // ref - для любого значения (примитивы и объекты)
const user = reactive({ name: 'Аня', age: 30 }); // reactive - только для объектов

count.value++;                    // ref читается/меняется через .value
user.age++;                       // reactive - как обычный объект
```

- **`ref`** оборачивает значение в объект с полем `.value`. Работает с примитивами **и** объектами.
- **`reactive`** возвращает реактивный **Proxy** объекта. Только для объектов/массивов/Map/Set; примитивы не оборачивает.

---

## Зачем .value

`ref` нужен `.value`, потому что в JS **нельзя отследить чтение/запись примитива** - у числа нет «перехватчика». Поэтому Vue кладёт значение в объект-обёртку и перехватывает доступ к `.value`.

```js
const count = ref(0);
count.value++;          // в JS-коде - через .value
```

```vue
<template>
  <button @click="count++">{{ count }}</button> <!-- в шаблоне .value не нужен -->
</template>
```

<b class="text-on-semi-light">Авторазворачивание (unwrap)</b> - <span class="text-gray">В шаблоне ref верхнего уровня разворачивается автоматически - пишешь `count`, а не `count.value`. Но в обычном JS-коде (`<script>`, методах) `.value` обязателен. Забыть `.value` - частая ошибка новичков.</span>

---

## Как работает реактивность

Под капотом - связка **Proxy + эффекты** (track/trigger).

1. **Track (сбор зависимостей).** Когда выполняется реактивный эффект (рендер компонента, `computed`, `watchEffect`) и он **читает** реактивное свойство, Proxy-геттер запоминает: «этот эффект зависит от этого свойства».
2. **Trigger (запуск).** Когда свойство **меняется**, Proxy-сеттер находит все зависящие эффекты и перезапускает их.

```js
// упрощённая идея
const obj = new Proxy(target, {
  get(t, key) { track(t, key); return t[key]; },     // запомнить зависимость
  set(t, key, val) { t[key] = val; trigger(t, key); return true; }, // оповестить
});
```

<b class="text-on-semi-light">Главный вывод</b> - <span class="text-gray">Vue **точно знает**, какие эффекты читают какие данные. Поэтому при изменении он обновляет ровно зависящие места, а не «перерисовывает компонент и диффит всё». Это и есть тонкая (fine-grained) реактивность.</span>

## Vue 2 vs Vue 3: почему Proxy

| | Vue 2 (`Object.defineProperty`) | Vue 3 (`Proxy`) |
|--|----------------------------------|------------------|
| Перехват | геттеры/сеттеры на существующих свойствах | весь объект целиком |
| Новые свойства | **не отслеживались** (нужен `Vue.set`) | отслеживаются автоматически |
| Удаление свойств | не отслеживалось (`Vue.delete`) | отслеживается |
| Индексы/длина массива | проблемы | работают |
| Стоимость | обход всех свойств при инициализации | ленивый перехват |

> Главная боль Vue 2 - реактивность не видела добавления новых свойств в объект и изменения массива по индексу. `Proxy` в Vue 3 это полностью решил.

## Подводные камни реактивности

Здесь живут самые частые вопросы. Реактивность ломается тихо - без ошибок.

### 1. Деструктуризация reactive теряет реактивность

```js
const user = reactive({ name: 'Аня', age: 30 });
let { name, age } = user;  // ❌ name и age - обычные значения, связь с Proxy потеряна
age++;                     // ничего не обновится
```

`reactive` реактивен только при доступе **через сам Proxy**. Деструктуризация копирует примитив и рвёт связь. Решение - `toRefs`:

```js
const { name, age } = toRefs(user); // ✅ каждое поле - ref, реактивность сохранена
age.value++;                        // работает
```

### 2. Переприсваивание reactive рвёт связь

```js
let state = reactive({ count: 0 });
state = reactive({ count: 5 }); // ❌ старые зависимости смотрят на прежний Proxy
```

Реактивность завязана на конкретный Proxy-объект. Замена переменной целиком теряет отслеживание. Для «заменяемого» состояния используй `ref` (можно присвоить `.value`).

### 3. reactive не работает с примитивами

```js
const n = reactive(5); // ❌ бессмысленно - Proxy нельзя повесить на число
const n = ref(5);      // ✅
```

### 4. ref внутри reactive разворачивается

```js
const count = ref(0);
const state = reactive({ count });
state.count;       // 0 - ref развернулся, .value не нужен
state.count++;     // работает, и count.value тоже обновится
```

---

## Тонкости разворачивания ref

Авторазворачивание `.value` работает не везде - частый источник тонких багов:

```js
const count = ref(0);

// ✅ ref как свойство reactive-объекта - разворачивается
const state = reactive({ count });
state.count; // 0 (без .value)

// ❌ ref в массиве или Map/Set НЕ разворачивается
const arr = reactive([ref(0)]);
arr[0].value;  // нужен .value - в массиве не развернулся
```

<b class="text-on-semi-light">Правило</b> - <span class="text-gray">ref разворачивается автоматически как свойство **объекта** (reactive или верхний уровень шаблона), но **не** внутри массивов и коллекций (Map/Set) - там обращайся через `.value`. Это частое «почему не работает».</span>

> Vue 3.5+ сохраняет реактивность при **деструктуризации props** (компилятор оборачивает доступ): `const { count } = defineProps(...)` остаётся реактивным. Раньше это её ломало.

---

## ref или reactive: что выбирать

<b class="text-on-semi-light">Рекомендация Vue</b> - <span class="text-gray">По умолчанию используй `ref` - он работает с любыми типами, легко переприсваивается (`.value = ...`) и не теряет реактивность при деструктуризации (ref остаётся ref). `reactive` бери для тесно связанных групп полей, помня про его ограничения. На практике многие команды используют `ref` почти везде.</span>

Утилиты: `isRef`, `unref` (вернуть значение из ref или как есть), `isReactive`, `toRef` (сделать ref из одного свойства reactive).

## Сравнение с React

| | Vue | React |
|--|-----|-------|
| Модель обновления | отслеживание зависимостей, точечное обновление | ре-рендер компонента + diff |
| Что отслеживается | конкретные читаемые свойства | весь компонент |
| Мемоизация | в основном не нужна | `memo`/`useMemo`/`useCallback` вручную |
| «Снапшот» состояния | состояние мутабельно-реактивное | состояние иммутабельно, снапшот на рендер |

> В React `count` - снапшот рендера, ты вызываешь `setCount`. Во Vue `count` - живая реактивная ссылка, ты меняешь `count.value`, и зависимости реагируют. Разные ментальные модели.

## Вопросы на собеседовании

<b class="text-on-semi-light">Чем ref отличается от reactive?</b>
<span class="text-gray">`ref` оборачивает любое значение в объект с `.value`, работает с примитивами. `reactive` - Proxy для объектов, без `.value`, но не работает с примитивами и теряет реактивность при деструктуризации/переприсваивании.</span>

<b class="text-on-semi-light">Зачем ref нужен .value?</b>
<span class="text-gray">В JS нельзя перехватить чтение/запись примитива. Vue кладёт значение в объект-обёртку и отслеживает доступ к `.value`. В шаблоне разворачивается автоматически.</span>

<b class="text-on-semi-light">Как работает реактивность Vue 3 под капотом?</b>
<span class="text-gray">Через Proxy: геттер собирает зависимости (track), сеттер запускает зависящие эффекты (trigger). Vue точно знает, какие эффекты читают какие данные, и обновляет точечно.</span>

<b class="text-on-semi-light">Почему Vue 3 перешёл на Proxy?</b>
<span class="text-gray">`Object.defineProperty` в Vue 2 не отслеживал добавление/удаление свойств и изменения массива по индексу. Proxy перехватывает весь объект и решает это.</span>

<b class="text-on-semi-light">Почему деструктуризация reactive ломает реактивность?</b>
<span class="text-gray">Реактивность работает через доступ к Proxy. Деструктуризация копирует примитив и рвёт связь. Решение - `toRefs`, превращающий поля в ref.</span>

<b class="text-on-semi-light">Что выбрать по умолчанию - ref или reactive?</b>
<span class="text-gray">`ref`: универсален по типам, переприсваивается, не ломается при деструктуризации. `reactive` - для групп связанных полей с оглядкой на ограничения.</span>
