# Безопасность во Vue

Vue, как и React, **по умолчанию защищает от XSS**, экранируя данные в шаблонах. Но есть лазейки, через которые уязвимость легко вернуть - `v-html`, ссылки и компиляция пользовательских шаблонов. Это типичные вопросы senior-собеса.

---

## XSS и автоэкранирование

**XSS** - внедрение чужого скрипта, выполняемого в браузере жертвы. Главная защита: всё, что вставляется в шаблон как **текст** (интерполяция `{{ }}` и привязка `:attr`), Vue экранирует автоматически.

```vue
<template>
  <div>{{ userInput }}</div>  <!-- выведется как ТЕКСТ, скрипт не выполнится -->
</template>
```

Если `userInput` содержит `<img src=x onerror=...>`, Vue покажет это строкой, а не HTML. Обычный рендеринг пользовательских данных безопасен.

---

## v-html

Директива `v-html` вставляет **сырой HTML** в обход экранирования - и это главный источник XSS во Vue.

```vue
<!-- ⚠️ опасно, если html содержит пользовательский ввод -->
<div v-html="html"></div>
```

Если в `html` попадёт ввод пользователя - получаем XSS. Решение - **санитизация**:

```vue
<script setup>
import DOMPurify from 'dompurify';
const safe = computed(() => DOMPurify.sanitize(rawHtml.value));
</script>

<template>
  <div v-html="safe"></div>
</template>
```

<b class="text-on-semi-light">Правило</b> - <span class="text-gray">Никогда не передавай в `v-html` неочищенные пользовательские данные. Санитизируй через DOMPurify или рендери HTML на доверенном бэкенде. Лучше вообще избегать `v-html`.</span>

---

## Инъекции через URL

Автоэкранирование **не защищает протокол** в `:href`/`:src`. `javascript:`-URL выполнит код при клике.

```vue
<!-- ⚠️ если userUrl = "javascript:alert(1)" -->
<a :href="userUrl">сайт</a>
```

Валидируй протокол перед привязкой:

```js
function safeUrl(url) {
  try {
    const u = new URL(url, location.origin);
    return ['http:', 'https:', 'mailto:'].includes(u.protocol) ? url : '#';
  } catch { return '#'; }
}
```

---

## Не компилируй пользовательские шаблоны

Особенность Vue: его шаблоны компилируются в render-функции. **Никогда не подставляй пользовательский ввод в шаблон или в `v-html` так, чтобы он мог стать частью компилируемого шаблона.** Динамическая компиляция пользовательского контента = выполнение произвольного кода.

```js
// ❌ катастрофа: пользовательский ввод как шаблон компонента
const Comp = { template: `<div>${userInput}</div>` };
```

> Пользовательские данные - всегда **данные** (привязки, текст), никогда не **код** (шаблон). Это Vue-специфичный пункт, которого нет в React.

---

## Секреты не живут на клиенте

Клиентский бандл публичен. Любая «переменная окружения» в сборке (`VITE_*`) видна в DevTools.

```js
const key = import.meta.env.VITE_SECRET; // ❌ опубликованный секрет
```

<b class="text-on-semi-light">Принцип</b> - <span class="text-gray">На клиенте - только публичные ключи. Приватные ключи, токены и проверку прав держат на сервере. Навигационные guard'ы и любые клиентские проверки - это UX, не безопасность.</span>

---

## Прочее

- **SSR-инъекции.** При серверном рендере (Nuxt) не вставляй неэкранированные данные в HTML/состояние - то же правило, что для `v-html`.
- **Зависимости.** Регулярно `npm audit`, минимизируй пакеты (supply chain).
- **CSP** - заголовок Content-Security-Policy снижает урон от XSS; настраивается на сервере.
- **Хранение токенов** - `localStorage` уязвим к XSS, httpOnly-cookie недоступны JS, но требуют защиты от CSRF. Подробно - в [безопасности и производительности](/content/security-perfomance).

## Вопросы на собеседовании

<b class="text-on-semi-light">Как Vue защищает от XSS по умолчанию?</b>
<span class="text-gray">Данные в интерполяции `{{ }}` и привязках атрибутов автоматически экранируются - вставляются как текст, скрипт не исполняется.</span>

<b class="text-on-semi-light">Чем опасен v-html?</b>
<span class="text-gray">Вставляет сырой HTML в обход экранирования. С пользовательским вводом - прямой XSS. Нужно санитизировать (DOMPurify) или не использовать.</span>

<b class="text-on-semi-light">Защищает ли Vue от javascript:-ссылок?</b>
<span class="text-gray">Нет, экранирование текста не касается протокола в `:href`/`:src`. Нужно самому валидировать URL.</span>

<b class="text-on-semi-light">Какая XSS-опасность специфична для Vue?</b>
<span class="text-gray">Компиляция пользовательского ввода как шаблона. Пользовательские данные должны быть данными (привязки/текст), а не частью компилируемого шаблона.</span>

<b class="text-on-semi-light">Можно ли хранить API-ключи во Vue-приложении?</b>
<span class="text-gray">Только публичные. Бандл открыт всем; приватные ключи и авторизацию держат на сервере.</span>
