# Composables

**Composable** - функция, которая использует Composition API, чтобы инкапсулировать и переиспользовать **логику с состоянием**. Это прямой аналог кастомных хуков в React и современная замена mixins. Если ты понял React-хуки - composables дадутся легко.

---

## Что это и зачем

Когда логика (отслеживание мыши, работа с localStorage, загрузка данных) нужна в нескольких компонентах, её выносят в функцию `useX`, возвращающую реактивное состояние и методы.

```js
// composables/useMouse.js
import { ref, onMounted, onUnmounted } from 'vue';

export function useMouse() {
  const x = ref(0);
  const y = ref(0);

  function update(e) { x.value = e.clientX; y.value = e.clientY; }

  onMounted(() => window.addEventListener('mousemove', update));
  onUnmounted(() => window.removeEventListener('mousemove', update)); // cleanup

  return { x, y };
}
```

```vue
<script setup>
import { useMouse } from '@/composables/useMouse';
const { x, y } = useMouse(); // переиспользуем в любом компоненте
</script>

<template>Курсор: {{ x }}, {{ y }}</template>
```

<b class="text-on-semi-light">Ключевая идея</b> - <span class="text-gray">Composable переиспользует **логику**, а не состояние. Каждый вызов `useMouse()` создаёт **свой** изолированный набор `x`/`y`. Два компонента не делят состояние - они делят поведение.</span>

## Конвенции

- Имя начинается с **`use`** (`useFetch`, `useTheme`).
- Возвращай **объект из ref'ов** (или reactive) - чтобы потребитель мог деструктурировать, не теряя реактивность (ref остаётся ref).
- Регистрируй хуки жизненного цикла (`onMounted`/`onUnmounted`) прямо внутри - они привяжутся к компоненту, который вызвал composable.
- Делай **cleanup** (отписки, таймеры) в `onUnmounted`/`onScopeDispose`.

```js
const { data, error, isLoading } = useFetch(url); // деструктуризация ref'ов - ок
```

### Принимай и значения, и ref'ы

Гибкие composables принимают как «сырой» аргумент, так и ref. Хелпер `toValue` нормализует это, а реакцию на изменение даёт `watchEffect`.

```js
import { toValue, ref, watchEffect } from 'vue';

export function useFetch(url) {            // url может быть строкой ИЛИ ref
  const data = ref(null);
  watchEffect(() => {
    fetch(toValue(url)).then((r) => r.json()).then((d) => (data.value = d));
  });                                       // перезапросит, если url - ref и изменится
  return { data };
}
```

## Composables vs кастомные хуки React

Очень похожи, но есть отличия из-за разных моделей реактивности.

| | Vue composables | React hooks |
|--|------------------|-------------|
| Переиспользование логики | да | да |
| Возвращают | ref'ы / reactive | значения + сеттеры |
| Правила вызова | синхронно в `setup` (для привязки хуков жизненного цикла) | строгий порядок (rules of hooks) |
| Зависимости эффектов | авто-отслеживание | массив вручную |
| Проблема stale closure | практически нет | есть |

<b class="text-on-semi-light">Почему у Vue нет «правила хуков» как у React</b> - <span class="text-gray">React связывает состояние с хуком по **порядку вызова**, поэтому нельзя вызывать в условиях. Vue хранит состояние в реактивных ссылках, не зависящих от порядка, - условные вызовы реактивной части не ломают её. Ограничение лишь в том, что хуки жизненного цикла нужно регистрировать синхронно в `setup`, чтобы они привязались к текущему компоненту.</span>

## Composables vs mixins (legacy)

Mixins - старый (Vue 2) способ переиспользовать логику через объекты с опциями. Их заменили composables.

| | Mixins (legacy) | Composables |
|--|------------------|-------------|
| Источник свойств | неявный («откуда взялось это поле?») | явный (что вернул `useX`) |
| Конфликты имён | да, молча перезатираются | нет (свои переменные) |
| Несколько источников | запутанно | просто комбинируются |
| TypeScript | плохо | хорошо |

> Те же проблемы, что у HOC в React: «магия», неясный источник, коллизии. Composables решают их так же, как хуки.

## Композиция composables

Composables комбинируются друг с другом - один использует другой.

```js
export function useUserPosts(userId) {
  const { data: user } = useFetch(() => `/api/users/${toValue(userId)}`);
  const { data: posts } = useFetch(() => `/api/users/${toValue(userId)}/posts`);
  return { user, posts };
}
```

## VueUse

**VueUse** - большая библиотека готовых composables (`useLocalStorage`, `useDark`, `useDebounce`, `useIntersectionObserver` и сотни других). Де-факто стандарт - незачем переписывать типовые хуки самому.

## Вопросы на собеседовании

<b class="text-on-semi-light">Что такое composable?</b>
<span class="text-gray">Функция на Composition API, инкапсулирующая переиспользуемую логику с состоянием. Возвращает реактивное состояние и методы. Аналог кастомного хука React.</span>

<b class="text-on-semi-light">Делят ли состояние компоненты с одним composable?</b>
<span class="text-gray">Нет. Каждый вызов создаёт свой изолированный набор реактивного состояния - переиспользуется логика, не данные. (Если нужно общее состояние - выноси `ref` в модуль или используй стор.)</span>

<b class="text-on-semi-light">Почему у Vue нет строгих «правил хуков», как в React?</b>
<span class="text-gray">React связывает состояние с хуком по порядку вызова, поэтому запрещены условные вызовы. Vue хранит состояние в реактивных ссылках вне зависимости от порядка; лишь хуки жизненного цикла нужно регистрировать синхронно в setup.</span>

<b class="text-on-semi-light">Чем composables лучше mixins?</b>
<span class="text-gray">Явный источник свойств, отсутствие коллизий имён, простая комбинация нескольких источников, хорошая типизация. Mixins прятали источник и конфликтовали.</span>

<b class="text-on-semi-light">Как сделать composable, реагирующий на изменение аргумента?</b>
<span class="text-gray">Принимать аргумент как значение или ref, нормализовать через `toValue` и обернуть логику в `watchEffect`/`watch` - тогда при изменении ref логика перезапустится.</span>
