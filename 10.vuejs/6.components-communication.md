# Связь компонентов

Как компоненты обмениваются данными: пропсы вниз, события вверх, `v-model` и `defineModel` для двусторонней привязки, fallthrough-атрибуты для обёрток. Спрашивают, можно ли менять пропсы, как ребёнок сообщает родителю об изменении и как работает `v-model` на компоненте. Глубже — почему вложенное изменение пропса проходит молча, почему необъявленное событие срабатывает дважды и как событие внука «доходит» до компонента, хотя события не всплывают.

::tldr
- **Данные идут вниз через пропсы, сообщения — вверх через события.** Пропсы ребёнка только для чтения, но поверхностно: изменение вложенного объекта пройдёт без предупреждения и изменит данные родителя.
- **События компонентов не всплывают.** Событие получает только непосредственный родитель. Иллюзию всплытия создают fallthrough-атрибуты: необъявленный слушатель уходит на корневой элемент.
- **Объявляй события в `defineEmits`.** Необъявленный `click` попадёт на корневой элемент как нативный слушатель и сработает дважды — от `emit` и от настоящего клика.
- **`v-model` на компоненте — проп `modelValue` и событие `update:modelValue`.** `defineModel` объявляет оба и возвращает ref, который работает и как локальное состояние, если родитель модель не передал.
- **Атрибуты, которые не объявлены пропсами, сливаются с корневым элементом:** `class`, `style`, `data-*`, слушатели. `inheritAttrs: false` и `v-bind="$attrs"` переносят их на нужный элемент.
::

## Пропсы

Сквозной пример — строка корзины `CartLine`, которая показывает товар и меняет количество:

```vue
<!-- CartLine.vue -->
<script setup>
const props = defineProps({
  product: { type: Object, required: true },
  qty: { type: Number, default: 1, validator: (v) => v > 0 },
  disabled: Boolean,
});
</script>

<template>
  <li>{{ product.title }} × {{ qty }}</li>
</template>
```

```vue
<CartLine :product="tea" :qty="2" />
```

### Проверки

Объектный синтаксис `defineProps` описывает тип, обязательность, значение по умолчанию и свою проверку. Нарушения — предупреждения в режиме разработки, все проверены: «Missing required prop», «custom validator check failed», «type check failed … Expected Number with value 5, got String». Последнее — частая ошибка: `max-items="5"` передаёт строку, а число — `:max-items="5"`.

Особенности:

- **`Boolean` приводится:** атрибут без значения (`<CartLine disabled />`) — `true`, отсутствие атрибута — `false`, а не `undefined`;
- **значение по умолчанию для объектов и массивов — фабрика:** `default: () => []`, иначе все экземпляры делили бы один массив;
- **имена:** в JavaScript — `maxItems`, в шаблоне можно писать `max-items`, Vue сопоставит.

С TypeScript пропсы описывают типом — подробно в [TypeScript с Vue](/content/typescript/ts-with-vue).

### Пропсы только для чтения

Ребёнок не может присвоить проп:

```js
props.qty = 3;   // предупреждение, значение не изменилось
```

Пропсы — `readonly`-прокси. Иначе родитель при следующем рендере перезаписал бы значение, и состояние разошлось бы.

Но защита **поверхностная**. `props.product.price = 1` изменит объект родителя без единого предупреждения — в проверке так и вышло. Это работает, но ломает однонаправленный поток: данные родителя меняет ребёнок, и найти, откуда пришло изменение, трудно. Изменения объекта делает тот, кто им владеет.

### Свой экземпляр значения

Если ребёнку нужно своё состояние, начиная с пропса, его копируют:

```js
const { initialQty } = defineProps({ initialQty: Number });
const qty = ref(initialQty);   // начальное значение, дальше живёт само
```

Такая копия **не следит** за пропсом — в проверке родитель поменял цену, а копия осталась прежней. Это правильно, если проп действительно начальный, и имя `initialQty` это подчёркивает. Если же значение должно следовать за пропсом, это `computed` от пропса или двусторонняя модель, о которой ниже.

Деструктуризация пропсов в `<script setup>` реактивна: компилятор переписывает `price` в `props.price`. В обычном `setup(props)` деструктуризация `const { price } = props` даёт копию — там нужны `toRefs(props)` (подробно — в [Основах реактивности](/content/vuejs/reactivity-fundamentals)).

Пропсы описывают данные сверху. Как строке корзины сообщить, что пользователь нажал «+»?

## События

```vue
<!-- CartLine.vue -->
<script setup>
const emit = defineEmits(['change-qty', 'remove']);
</script>

<template>
  <button @click="emit('change-qty', product.id, qty + 1)">+</button>
  <button @click="emit('remove', product.id)">Удалить</button>
</template>
```

```vue
<CartLine :product="tea" :qty="qty" @change-qty="setQty" @remove="removeLine" />
```

Ребёнок не меняет данные, а **сообщает**, что случилось, — с аргументами. Решает родитель: это и есть однонаправленный поток.

### События не всплывают

В отличие от DOM-событий, событие компонента получает только **непосредственный родитель**. Если `CartLine` лежит внутри `CartList`, а слушатель стоит на `CartList`, событие до него не дойдёт — его нужно переизлучить или передать данные иначе.

Тонкость, которая сбивает с толку: иногда кажется, что событие всплыло. Если `CartList` не объявил событие `change-qty` и его корень — сам `CartLine`, слушатель `@change-qty` на `CartList` уходит на корень как fallthrough-атрибут, то есть на `CartLine`, и срабатывает. В проверке слушатель на промежуточном компоненте получил событие внука, только когда внук был его единственным корнем. С корнем-`div` или с объявленным событием — нет. Это не всплытие, а побочный эффект проброса атрибутов, и на него не стоит полагаться.

### Зачем объявлять события

`defineEmits` — не формальность:

- **документирует** API компонента и даёт типы;
- **убирает слушатель из fallthrough.** Если событие не объявлено, слушатель считается атрибутом и попадает на корневой элемент как **нативный**.

Последнее даёт реальный баг. Компонент кнопки испускает свой `click`, но не объявил его:

```vue
<!-- BuyButton.vue: события не объявлены -->
<template>
  <button @click="emit('click', 'кастомный')">Купить</button>
</template>
```

Слушатель `@click` родителя сработает дважды: от `emit` и от нативного клика по `<button>`, куда он попал как атрибут. В проверке без объявления обработчик получил `['кастомный', 'native']`, с `defineEmits(['click'])` — один вызов.

Объектный синтаксис `defineEmits({ remove: (id) => typeof id === 'number' })` добавляет проверку аргументов в режиме разработки.

## v-model на компоненте

Для поля ввода `v-model` — сокращение для значения и обработчика (подробно — в [Шаблонах и директивах](/content/vuejs/templates-and-directives)). На компоненте это **соглашение**:

```vue
<QtyInput v-model="qty" />
<!-- то же, что -->
<QtyInput :modelValue="qty" @update:modelValue="(v) => (qty = v)" />
```

Вручную компонент принимает проп и испускает событие:

```vue
<script setup>
defineProps(['modelValue']);
const emit = defineEmits(['update:modelValue']);
</script>

<template>
  <input :value="modelValue" @input="emit('update:modelValue', $event.target.value)">
</template>
```

### defineModel

`defineModel` объявляет оба и возвращает ref:

```vue
<!-- QtyInput.vue -->
<script setup>
const qty = defineModel({ type: Number, default: 1 });
</script>

<template>
  <button @click="qty--">−</button>
  <span>{{ qty }}</span>
  <button @click="qty++">+</button>
</template>
```

Запись `qty.value++` отправляет родителю `update:modelValue`. Если родитель не передал `v-model`, ref ведёт себя как **локальное состояние** компонента — в проверке такой `QtyInput` сам увеличивал счётчик, не трогая родителя. Поэтому один компонент работает и «управляемым», и самостоятельным.

### Несколько моделей и модификаторы

Модели можно назвать:

```vue
<CartLine v-model:qty="line.qty" v-model:note.upper="line.note" />
```

```js
const qty = defineModel('qty');
const [note, modifiers] = defineModel('note');   // modifiers.upper === true
```

Модификаторы приходят вторым элементом, и компонент сам решает, что они значат. В проверке модификатор `.upper` превратил ввод «срочно» в «СРОЧНО». Для преобразования есть и опции `get` и `set` в `defineModel`.

В React двусторонней привязки нет: передают `value` и `onChange` вручную. `v-model` стандартизирует этот же паттерн и даёт несколько привязок на компонент.

## Fallthrough-атрибуты

Всё, что передано компоненту, но не объявлено как проп или событие, — **fallthrough-атрибуты**. Если у компонента один корневой элемент, они применяются к нему:

```vue
<!-- ProductCard.vue -->
<template>
  <article class="card"><slot /></article>
</template>
```

```vue
<ProductCard class="highlight" data-sku="tea" style="color: red" @click="open" />
<!-- <article class="card highlight" data-sku="tea" style="color: red"> + нативный click -->
```

`class` и `style` **сливаются** с собственными, остальное добавляется, слушатели становятся нативными слушателями корня. Всё это проверено. Обёртки поэтому гибкие: пользователь компонента навешивает класс или `aria-*`, не требуя от автора объявлять их.

### Когда корень не тот

Для обёртки над полем ввода атрибуты нужны на `input`, а не на корневом `label`:

```vue
<!-- TextField.vue -->
<script setup>
defineOptions({ inheritAttrs: false });
defineProps(['label']);
</script>

<template>
  <label class="field">
    {{ label }}
    <input v-bind="$attrs">
  </label>
</template>
```

```vue
<TextField label="Email" type="email" placeholder="a@shop.ru" />
```

`inheritAttrs: false` отключает автоматический проброс, а `v-bind="$attrs"` кладёт атрибуты, куда нужно. В проверке `type`, `placeholder` и `class` оказались на `input`, а `label` сохранил только свой класс.

Если корней несколько, Vue не знает, куда положить атрибуты, и предупреждает «Extraneous non-props attributes» — тогда `$attrs` привязывают явно. В `<script setup>` атрибуты доступны через `useAttrs()`, но они не реактивны для `watch`: для реакции на изменение атрибута его объявляют пропсом.

## Как выбрать способ связи

| Задача | Способ |
| --- | --- |
| передать данные ребёнку | пропсы |
| сообщить родителю о действии | события |
| двусторонняя привязка значения | `v-model`, `defineModel` |
| передать разметку | слоты ([Слоты](/content/vuejs/slots)) |
| данные для всего поддерева без пробрасывания | `provide`/`inject` ([Provide и inject](/content/vuejs/provide-inject)) |
| общее состояние независимых компонентов | стор ([Управление состоянием](/content/vuejs/state-management)) |
| вызвать метод ребёнка | ссылка на шаблон и `defineExpose` ([Composition API](/content/vuejs/composition-api)) |

Шина событий (`mitt`, `$on` из Vue 2) решает «всё со всем», но связи становятся невидимыми. В новом коде её заменяют стор и `provide`.

## Красные флаги в ответе

- **«Пропсы можно менять в ребёнке, если очень нужно».** Присваивание отклоняется, а изменение вложенного объекта молча меняет данные родителя.
- **«События компонентов всплывают, как DOM-события».** Их получает только непосредственный родитель, «всплытие» — это fallthrough на единственный корень.
- **«`defineEmits` нужен только для документации».** Необъявленный слушатель уходит на корневой элемент и может сработать дважды.
- **«`v-model` на компоненте — особый механизм».** Это `modelValue` и `update:modelValue`, `defineModel` их объявляет.
- **«Копия пропса в ref обновится вместе с пропсом».** Копия хранит начальное значение и дальше не следит.

## Как спрашивают на собеседовании

::question
Можно ли менять пропсы?

#answer
Нет. Пропсы — данные родителя, ребёнок получает их только для чтения: присваивание отклоняется с предупреждением, а родитель при следующем рендере всё равно передал бы своё значение. Ребёнок сообщает об изменении событием или работает с локальной копией.

#more
Защита поверхностная: изменение вложенного объекта `props.product.price = 1` проходит молча и меняет данные родителя. Это ломает однонаправленный поток. Локальная копия `ref(props.initialQty)` хранит начальное значение и не следит за пропсом. Для двусторонней связи — `v-model` и `defineModel`.
::

::question
Как ребёнок сообщает родителю об изменении?

#answer
Испускает событие: `emit('change-qty', id, qty)`, родитель слушает `@change-qty`. События объявляют в `defineEmits`.

#more
События не всплывают: их получает только непосредственный родитель. Необъявленное событие считается атрибутом и уходит на корневой элемент как нативный слушатель, поэтому `click` может сработать дважды. Объектный синтаксис `defineEmits` проверяет аргументы в режиме разработки.
::

::question
Как работает v-model на компоненте?

#answer
Это сокращение для пропа `modelValue` и события `update:modelValue`. Компонент принимает значение и испускает новое. `defineModel()` объявляет оба и возвращает ref: запись в него отправляет событие родителю.

#more
Моделей может быть несколько: `v-model:qty`, `v-model:note`. Модификаторы приходят вторым элементом `defineModel`, например `const [note, mods] = defineModel('note')`. Если родитель не передал модель, ref от `defineModel` работает как локальное состояние.
::

::question
Что такое fallthrough-атрибуты?

#answer
Атрибуты и слушатели, которые переданы компоненту, но не объявлены как пропсы или события. При одном корневом элементе они применяются к нему: `class` и `style` сливаются, слушатели становятся нативными.

#more
`inheritAttrs: false` отключает автоматический проброс, а `v-bind="$attrs"` переносит атрибуты на нужный элемент — типично для обёрток над `input`. При нескольких корнях Vue предупреждает «Extraneous non-props attributes». Fallthrough объясняет, почему необъявленное событие срабатывает дважды.
::

::question
Почему событие сработало дважды?

#answer
Скорее всего, компонент испускает событие с именем нативного (`click`), но не объявил его в `defineEmits`. Тогда слушатель родителя попадает на корневой элемент как нативный и срабатывает и от `emit`, и от настоящего клика.

#more
Объявление события убирает слушатель из fallthrough-атрибутов. Второй вариант — назвать событие иначе (`buy` вместо `click`), чтобы оно не совпадало с DOM-событием. По той же причине у компонентов-обёрток слушатель родителя иногда «доходит» до вложенного компонента — если тот единственный корень.
::

::question
Чем v-model во Vue отличается от подхода React?

#answer
В React двусторонней привязки нет: передают `value` и `onChange` вручную. Во Vue `v-model` стандартизирует этот паттерн: проп `modelValue` и событие `update:modelValue`, с поддержкой нескольких моделей и модификаторов.

#more
Под капотом данные всё равно однонаправленные: ребёнок не меняет значение родителя, а испускает событие, и родитель обновляет своё состояние. `defineModel` сокращает это до одного ref. Деления на контролируемые и неконтролируемые поля во Vue нет: `defineModel` без модели родителя ведёт себя как локальное состояние.
::

## Практика

::practice{title="Ребёнок меняет пропс"}
Строка корзины сама увеличивает количество, и в консоли предупреждение, а число не меняется:

```vue
<script setup>
const props = defineProps({ qty: Number });
function inc() { props.qty++; }
</script>
```

#solution
Проп только для чтения. Если количество хранит родитель, ребёнок сообщает о желании изменить его — проще всего через двустороннюю модель:

```vue
<!-- CartLine.vue -->
<script setup>
const qty = defineModel('qty', { type: Number, default: 1 });
function inc() { qty.value++; }
</script>
```

```vue
<CartLine v-model:qty="line.qty" />
```

`qty.value++` испускает `update:qty`, родитель обновляет своё состояние, и новое значение приходит пропсом обратно. Если количество — забота только этой строки, это локальное состояние `ref(props.initialQty)` с пропсом-начальным значением. В проверке присваивание пропсу отклонено, а `defineModel` изменил значение у родителя.
::

::practice{title="Двойная покупка"}
По клику на кнопку «Купить» товар добавляется в корзину дважды:

```vue
<!-- BuyButton.vue -->
<script setup>
const emit = defineEmits([]);
</script>

<template>
  <button @click="emit('click', productId)">Купить</button>
</template>
```

```vue
<BuyButton @click="addToCart" />
```

#solution
Событие `click` не объявлено, поэтому слушатель `@click` — fallthrough-атрибут. Он попал на корневой `<button>` как нативный слушатель. Один клик вызывает `addToCart` дважды: через `emit` с `productId` и как нативный обработчик с объектом события.

```js
const emit = defineEmits(['click']);   // слушатель теперь только для emit
```

Ещё лучше назвать событие по смыслу — `buy`: оно не совпадает с DOM-событием, и путаницы не будет. В проверке без объявления обработчик вызвался дважды, с объявлением — один раз.
::

::practice{title="Атрибуты не на том элементе"}
Обёртка над полем ввода: `type` и `placeholder` оказались на `label`, а не на `input`.

```vue
<!-- TextField.vue -->
<template>
  <label class="field">{{ label }}<input></label>
</template>
```

```vue
<TextField label="Email" type="email" placeholder="a@shop.ru" />
```

#solution
Необъявленные атрибуты применяются к корневому элементу, а корень здесь — `label`. Нужно отключить автоматический проброс и указать место явно:

```vue
<script setup>
defineOptions({ inheritAttrs: false });
defineProps(['label']);
</script>

<template>
  <label class="field">
    {{ label }}
    <input v-bind="$attrs">
  </label>
</template>
```

Теперь `type`, `placeholder`, `class`, слушатели и `aria-*` попадают на `input`, а пользователь компонента пишет атрибуты так же, как у обычного поля. Если поле должно поддерживать `v-model`, добавляют `defineModel` и `v-model` на `input`. В проверке все атрибуты оказались на `input`, а `label` сохранил только свой класс.
::
