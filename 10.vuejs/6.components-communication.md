# Коммуникация компонентов

Как и в React, во Vue данные текут **вниз** через props, а наверх компонент сообщает через **события** (emits). Понимание `props`/`emits`, того, как устроен `v-model` на компонентах, и fallthrough-атрибутов - база, которую проверяют на каждом собесе.

---

## Props - данные вниз

`defineProps` объявляет входные параметры. Props **только для чтения** - однонаправленный поток.

```vue
<script setup>
const props = defineProps({
  title: { type: String, required: true },
  count: { type: Number, default: 0 },
  user: { type: Object, default: () => ({}) }, // дефолт объекта - через фабрику
});
</script>

<template>
  <h2>{{ title }} ({{ count }})</h2>
</template>
```

<b class="text-on-semi-light">Props нельзя мутировать</b> - <span class="text-gray">Изменение prop внутри компонента - предупреждение Vue и баг: при следующем обновлении родителя значение перезатрётся. Нужно своё состояние - скопируй prop в `ref`/`computed` или сообщи родителю через `emit`.</span>

> С TypeScript props типизируют через generic: `defineProps<{ title: string; count?: number }>()`. Подробно - в [TS с Vue](/content/typescript/ts-with-vue).

---

## Emits - события вверх

`defineEmits` объявляет события, которые компонент посылает родителю.

```vue
<script setup>
const emit = defineEmits(['submit', 'cancel']);

function onSave() {
  emit('submit', { id: 1 }); // событие с payload
}
</script>

<template>
  <button @click="onSave">Сохранить</button>
  <button @click="emit('cancel')">Отмена</button>
</template>
```

Родитель слушает их как обычные события:

```vue
<MyForm @submit="handleSubmit" @cancel="handleCancel" />
```

> Объявлять события в `defineEmits` не обязательно, но полезно: документирует API компонента и отделяет настоящие emits от fallthrough-атрибутов.

## v-model на компонентах

`v-model` на компоненте - это сахар над **prop + событием**. Он реализует двустороннюю привязку «значение ↔ состояние родителя».

```vue
<!-- родитель -->
<CustomInput v-model="text" />

<!-- разворачивается в: -->
<CustomInput :model-value="text" @update:model-value="text = $event" />
```

Внутри компонента:

```vue
<script setup>
defineProps(['modelValue']);
const emit = defineEmits(['update:modelValue']);
</script>

<template>
  <input :value="modelValue" @input="emit('update:modelValue', $event.target.value)" />
</template>
```

### defineModel (Vue 3.4+)

Современный сахар, убирающий бойлерплейт prop+emit:

```vue
<script setup>
const model = defineModel(); // ref, двусторонне связанный с v-model родителя
</script>

<template>
  <input v-model="model" />
</template>
```

### Несколько v-model и аргументы

В Vue 3 на одном компоненте можно несколько `v-model` с именами:

```vue
<UserForm v-model:name="name" v-model:email="email" />
<!-- внутри: defineModel('name'), defineModel('email') -->
```

<b class="text-on-semi-light">Vue vs React</b> - <span class="text-gray">В React нет встроенного двустороннего связывания - ты вручную прокидываешь `value` + `onChange`. Vue `v-model` стандартизирует этот паттерн и даёт несколько привязок на компонент.</span>

## Fallthrough-атрибуты

Если на компонент навесили атрибут, который **не объявлен** как prop или emit (`class`, `id`, `@click`, `data-*`), Vue автоматически «пробрасывает» его на **корневой элемент** компонента. Это **fallthrough**.

```vue
<!-- использование -->
<MyButton class="primary" @click="save" />

<!-- внутри MyButton: class и click автоматически попадут на корневой <button> -->
<template>
  <button>...</button>
</template>
```

- Доступ к таким атрибутам - через `$attrs` (в шаблоне) или `useAttrs()` (в скрипте).
- Отключить авто-проброс - `inheritAttrs: false`, тогда привязать `v-bind="$attrs"` куда нужно (например, на внутренний `<input>`, а не на корневую обёртку).

```vue
<script setup>
defineOptions({ inheritAttrs: false });
</script>
<template>
  <div class="wrapper">
    <input v-bind="$attrs" /> <!-- атрибуты идут на input, а не на div -->
  </div>
</template>
```

<b class="text-on-semi-light">Зачем это знать</b> - <span class="text-gray">Fallthrough делает компоненты-обёртки гибкими: пользователь навешивает `class`/обработчики, не объявляя их как props. Аналог `...rest` спреда в React, но автоматический.</span>

---

## Способы обмена данными - сводка

| Направление | Механизм |
|-------------|----------|
| Родитель → ребёнок | props |
| Ребёнок → родитель | emits (события) |
| Двусторонне | `v-model` (props + update-событие) |
| Родитель → разметка ребёнка | [слоты](/content/vuejs/slots) |
| Предок → глубокий потомок | [provide/inject](/content/vuejs/provide-inject) |
| Между не связанными | [стор (Pinia)](/content/vuejs/state-management) |

## Вопросы на собеседовании

<b class="text-on-semi-light">Можно ли мутировать props?</b>
<span class="text-gray">Нет, props только для чтения (однонаправленный поток). Мутация даёт warning и перезатрётся при обновлении родителя. Нужно своё состояние - копируй в ref/computed или emit наверх.</span>

<b class="text-on-semi-light">Как ребёнок сообщает родителю об изменении?</b>
<span class="text-gray">Через события: `defineEmits` + `emit('event', payload)`, родитель слушает `@event`.</span>

<b class="text-on-semi-light">Как работает v-model на компоненте?</b>
<span class="text-gray">Это сахар над prop `modelValue` и событием `update:modelValue` (или `defineModel`). Даёт двустороннюю привязку, можно несколько именованных моделей.</span>

<b class="text-on-semi-light">Что такое fallthrough-атрибуты?</b>
<span class="text-gray">Необъявленные атрибуты (class, id, обработчики) автоматически пробрасываются на корневой элемент компонента. Управляются через `$attrs` и `inheritAttrs: false`.</span>

<b class="text-on-semi-light">Чем v-model отличается от подхода React?</b>
<span class="text-gray">В React двустороннее связывание делают вручную (value + onChange). Vue стандартизирует это в `v-model` и поддерживает несколько привязок.</span>

<b class="text-on-semi-light">Зачем объявлять emits в defineEmits?</b>
<span class="text-gray">Документирует API компонента, валидирует события и отделяет настоящие emits от fallthrough-атрибутов.</span>
