# Computed и наблюдатели

Два способа реагировать на изменение данных: `computed` для производных значений и `watch` или `watchEffect` для побочных эффектов. Спрашивают, чем `computed` отличается от метода, когда брать `watch`, а когда `computed`, и чем `watch` отличается от `watchEffect`. Глубже — почему `computed` не пересчитывается сразу, почему `watch(state.count)` не работает, когда колбэк видит старый DOM и как не дать устаревшему ответу перезаписать новый.

::tldr
- **`computed` — производное значение с кешем.** Он ленив: вычисляется при первом чтении и пересчитывается, только если изменились зависимости и его снова прочитали. Зависимых он оповещает, только если результат изменился.
- **`watch` — побочный эффект в ответ на изменение конкретного источника:** запрос, запись в `localStorage`, аналитика. Для производных значений он не нужен — это лишнее состояние, которое может разойтись с исходным.
- **Источник `watch` — ref, `reactive`-объект, геттер или массив из них.** `watch(state.count)` передаёт число и не работает. `reactive`-объект отслеживается глубоко, геттер объекта — только замена.
- **`watchEffect` сам собирает зависимости из того, что прочитал,** но в асинхронной функции — только до первого `await`.
- **Колбэк по умолчанию вызывается до обновления DOM и один раз на пачку изменений.** Для доступа к новому DOM — `flush: 'post'`, для отмены устаревшей работы — `onWatcherCleanup`.
::

## computed

Сквозной пример — корзина:

```js
const items = ref([
  { sku: 'tea', price: 490, qty: 2 },
  { sku: 'pot', price: 1500, qty: 1 },
]);

const total = computed(() => items.value.reduce((s, i) => s + i.price * i.qty, 0));
```

`computed` — эффект особого вида (подробно о модели — в [Основах реактивности](/content/vuejs/reactivity-fundamentals)). Его поведение проверено по шагам:

- **ленивость** — пока `total.value` никто не прочитал, функция не выполняется ни разу;
- **кеш** — повторное чтение без изменений возвращает сохранённое значение;
- **отложенный пересчёт** — изменение `items` не пересчитывает `total` сразу, а только помечает его устаревшим. Пересчёт произойдёт при следующем чтении.

### computed или метод

В шаблоне можно вызвать функцию: `{{ totalM() }}`. Результат тот же, но метод выполняется на **каждый** рендер компонента — даже если перерисовка вызвана чем-то посторонним. В проверке после двух посторонних перерисовок метод вызвался три раза, а `computed` — один. Для всего, что зависит от реактивных данных и стоит хоть что-то, — `computed`.

### Стабильность значения

`computed` оповещает зависимых, только если **новое значение отличается** от прошлого (через `Object.is`). `isEven` при смене `n` с `1` на `3` остался `false`, и зависящий эффект не запустился.

Для объектов это значит обратное: если getter каждый раз возвращает новый объект, `computed` каждый раз «изменился», и зависимые перезапускаются. Getter получает предыдущее значение аргументом, и его можно вернуть, если по смыслу ничего не изменилось:

```js
const query = computed((prev) => {
  const next = { q: filters.value.q };
  return prev && prev.q === next.q ? prev : next;
});
```

### Правила

- **getter без побочных эффектов:** не делать запросов, не менять другое состояние, не трогать DOM. Он может выполниться в неожиданный момент или не выполниться вовсе;
- **не мутировать результат:** `total.value` — снимок вычисления, изменение его объекта не изменит источник.

Если запись всё-таки нужна, есть **writable computed**:

```js
const fullName = computed({
  get: () => `${first.value} ${last.value}`,
  set: (v) => { [first.value, last.value] = v.split(' '); },
});
```

Запись идёт в исходные ref, а `computed` по-прежнему производный. Это удобно для `v-model` на составном значении.

`computed` отвечает на вопрос «что показать». Но иногда на изменение нужно **сделать** что-то: отправить запрос, сохранить в хранилище. Для этого — наблюдатели.

## watch

```js
watch(query, async (q, oldQ) => {
  results.value = await search(q);
});
```

`watch` — явный наблюдатель: следит за источником и вызывает колбэк с новым и старым значением. Колбэк не выполняется при создании, только при изменении.

### Источники

Источник должен быть **реактивным**:

| Источник | Что отслеживается |
| --- | --- |
| `ref` | замена `.value`; объект внутри — только замена, если не `deep` |
| `reactive`-объект | **глубоко**, любое вложенное изменение |
| геттер `() => state.count` | результат геттера |
| массив `[a, () => b]` | любой из источников |

Частая ошибка — передать значение:

```js
watch(state.count, cb);          // передано число 0 — Vue: «Invalid watch source»
watch(() => state.count, cb);    // правильно
```

Две тонкости, обе проверены:

- **для `reactive`-объекта `newValue === oldValue`**: это тот же Proxy, мутированный на месте. Старое значение объекта при мутации не сохраняется.
- **геттер объекта** `() => state.user` срабатывает только на **замену** `state.user`. Изменение `state.user.name` его не запускает — нужен `{ deep: true }` или геттер конкретного поля `() => state.user.name`.

### Опции

- **`immediate: true`** — вызвать колбэк сразу при создании;
- **`deep: true`** — следить за всеми вложенными изменениями. Глубокий обход дорог на больших структурах, `deep` можно задать числом — глубину обхода. Лучше следить за конкретным геттером, чем за всем объектом;
- **`once: true`** — один вызов, после чего наблюдатель останавливается;
- **`flush`** — когда вызывать колбэк, об этом ниже.

### Пачка изменений — один вызов

Колбэк не вызывается на каждую запись. Наблюдатель ставится в очередь, и три изменения подряд дают один вызов с итоговым значением. В проверке `n.value++` три раза подряд вызвали колбэк один раз, а с `flush: 'sync'` — на каждую запись. `sync` нужен редко: он отключает объединение и легко становится причиной лишней работы.

`watch` требует явно назвать источник. Есть вариант, где источник собирается сам.

## watchEffect

```js
watchEffect(() => {
  localStorage.setItem('cart', JSON.stringify(items.value));
});
```

`watchEffect` выполняет функцию **сразу** и запоминает всё, что она прочитала. Это удобно, когда зависимостей много и они совпадают с тем, что используется.

Ловушка асинхронных функций: зависимости собираются, только пока функция выполняется синхронно. Всё, что прочитано **после первого `await`**, не отслеживается:

```js
watchEffect(async () => {
  const currentId = id.value;           // зависимость
  await Promise.resolve();
  render(currentId, lang.value);        // lang — НЕ зависимость
});
```

В проверке изменение `lang` эффект не запустило, а изменение `id` — запустило. Всё, от чего зависит эффект, читают до первого `await`.

### watch или watchEffect

| | `watch` | `watchEffect` |
| --- | --- | --- |
| Зависимости | явный источник | всё, что прочитано синхронно |
| Первый запуск | только при изменении (или `immediate`) | сразу |
| Старое значение | есть | нет |
| Когда удобнее | реакция на конкретное изменение, нужно сравнить с прошлым | эффект зависит от многих значений, которые он и так читает |

`watch` точнее: видно, что вызывает эффект. `watchEffect` короче, но легко случайно добавить зависимость или потерять её после `await`.

## Когда вызывается колбэк

Опция `flush` решает, в какой момент относительно обновления DOM выполняется колбэк:

| `flush` | Когда | DOM в колбэке |
| --- | --- | --- |
| `'pre'` (по умолчанию) | до обновления компонента | старый |
| `'post'` | после обновления DOM | новый |
| `'sync'` | сразу при записи | старый, и без объединения |

В проверке колбэк с `pre` прочитал из элемента `0`, а с `post` — `1`. Если в колбэке нужно измерить элемент или передать его сторонней библиотеке, — `flush: 'post'` или `watchPostEffect`. Как устроена очередь, — в [Продвинутой реактивности](/content/vuejs/reactivity-advanced).

## Очистка и гонки

Пользователь печатает в поиске «ч», потом «чай». Запрос на «ч» медленный и приходит **позже** ответа на «чай»:

```js
watch(query, async (q) => {
  results.value = await search(q);   // ответ на «ч» перезапишет ответ на «чай»
});
```

В проверке на экране остались результаты для «ч». Это та же гонка запросов, что в эффектах React (подробно — в [Асинхронности](/content/javascript/async)). Решение — отменять устаревшую работу при следующем запуске:

```js
import { watch, onWatcherCleanup } from 'vue';

watch(query, async (q) => {
  const controller = new AbortController();
  onWatcherCleanup(() => controller.abort());   // вызовется перед следующим запуском и при остановке
  results.value = await search(q, controller.signal);
});
```

Функция очистки вызывается перед повторным запуском колбэка и при остановке наблюдателя. В проверке запрос на «ч» был отменён, а на экране остались результаты для «чай». `onWatcherCleanup` нужно вызвать до первого `await`. Та же функция приходит третьим аргументом колбэка `watch(src, (v, old, onCleanup) => …)` и аргументом `watchEffect` — этот вариант работает и в старых версиях.

## Остановка

Наблюдатель, созданный **синхронно в `setup`**, привязан к компоненту и останавливается при его размонтировании — проверено. Созданный после `await`, в `setTimeout` или вне компонента — не привязан и будет жить, пока его не остановят:

```js
const handle = watch(source, cb);
handle.pause();    // временно не вызывать
handle.resume();   // продолжить; пропущенное изменение доставляется одним вызовом
handle.stop();     // навсегда
```

Несколько наблюдателей вне компонента удобно собрать в `effectScope` и остановить разом (подробно — в [Продвинутой реактивности](/content/vuejs/reactivity-advanced)).

## Что выбрать

- **Значение выводится из других** — `computed`. Всегда, когда можно.
- **Нужно сделать что-то при изменении** — запрос, запись, аналитика, работа с DOM — `watch` или `watchEffect`.
- **Нужно реагировать на событие пользователя** — обработчик события, а не наблюдатель за состоянием, которое этот обработчик меняет.

Главный антипаттерн — синхронизировать состояние наблюдателем:

```js
const count = ref(0);
watch(items, (v) => { count.value = v.length; }, { deep: true, immediate: true });   // лишнее состояние

const count = computed(() => items.value.length);                                    // производное
```

Первый вариант — два источника правды, которые могут разойтись, и лишний проход. Это то же правило, что «You Might Not Need an Effect» в React (подробно — в [Производном состоянии React](/content/reactjs/derived-state-and-data-flow)).

## Красные флаги в ответе

- **«`computed` пересчитывается при каждом изменении зависимостей».** Он ленив: пересчёт происходит при следующем чтении.
- **«`watch(state.count, cb)` следит за полем».** Передано значение, нужен геттер `() => state.count`.
- **«`watchEffect` следит за всем, что прочитано в функции».** В асинхронной функции — только до первого `await`.
- **«Колбэк `watch` видит обновлённый DOM».** По умолчанию — старый, нужен `flush: 'post'`.
- **«Производное значение удобно держать в ref и обновлять через `watch`».** Это лишнее состояние, для этого есть `computed`.

## Как спрашивают на собеседовании

::question
Чем computed отличается от метода?

#answer
`computed` кеширует результат и пересчитывается, только когда изменились его зависимости. Метод в шаблоне вызывается на каждый рендер компонента, даже если его данные не менялись.

#more
`computed` ленив: не вычисляется, пока его не прочитали, а после изменения зависимостей пересчитывается при следующем чтении. Зависимых он оповещает, только если значение изменилось. Метод нужен, когда результат зависит от аргумента, который меняется при каждом вызове, или когда кеш не нужен.
::

::question
Когда использовать computed, а когда watch?

#answer
`computed` — когда значение выводится из других данных: сумма, фильтр, форматирование. `watch` — когда на изменение нужно выполнить побочный эффект: запрос, запись в хранилище, аналитику, работу с DOM.

#more
Производное состояние через `watch` — антипаттерн: два источника правды, которые могут разойтись, и лишний проход. Getter `computed` должен быть чистым. Если нужна запись в производное значение, есть writable computed с `get` и `set`.
::

::question
В чём разница между watch и watchEffect?

#answer
`watch` следит за явным источником, вызывается только при изменении и получает новое и старое значение. `watchEffect` выполняется сразу и сам собирает зависимости из того, что прочитал.

#more
У `watchEffect` нет старого значения, и в асинхронной функции он отслеживает только то, что прочитано до первого `await`. `watch` точнее: видно, что вызывает эффект, и можно сравнить с прошлым значением. Оба останавливаются вместе с компонентом, если созданы синхронно в `setup`.
::

::question
Почему watch(state.count, cb) не работает?

#answer
`state.count` вычисляется до вызова `watch`, и передаётся число, а не реактивный источник. Vue выводит «Invalid watch source». Нужен геттер: `watch(() => state.count, cb)`.

#more
Источник — ref, `reactive`-объект, геттер или массив из них. Весь `reactive`-объект отслеживается глубоко, и `newValue === oldValue`, потому что это тот же Proxy. Геттер объекта `() => state.user` срабатывает только на замену объекта, для вложенных изменений нужен `deep` или геттер конкретного поля.
::

::question
Что делает опция flush?

#answer
Решает, когда вызвать колбэк. `'pre'` по умолчанию — до обновления компонента, DOM ещё старый. `'post'` — после обновления DOM, для измерений и сторонних библиотек. `'sync'` — сразу при записи.

#more
С `pre` и `post` несколько изменений подряд дают один вызов колбэка. `sync` отключает объединение и вызывает колбэк на каждую запись — это редко нужно и легко приводит к лишней работе. Сокращения — `watchPostEffect` и `watchSyncEffect`.
::

::question
Как избежать гонки запросов в watch?

#answer
Отменять устаревший запрос при следующем запуске. `onWatcherCleanup(() => controller.abort())` регистрирует очистку, которая вызывается перед повторным запуском колбэка и при остановке наблюдателя.

#more
Без очистки медленный ответ на старый запрос может прийти позже нового и перезаписать результат. Функцию очистки также дают третьим аргументом колбэка `watch` и аргументом `watchEffect`. `onWatcherCleanup` нужно вызвать до первого `await`. Для загрузки данных часто удобнее библиотека с кешем, которая решает это сама.
::

::question
Чем опасен deep: true?

#answer
Глубокий наблюдатель обходит весь объект при каждой проверке, и на больших структурах это дорого. К тому же колбэк срабатывает на любое вложенное изменение, а не только на нужное.

#more
Лучше следить за конкретным геттером: `() => user.id` вместо всего `user`. `deep` можно задать числом, чтобы ограничить глубину обхода. При мутации объекта `newValue` и `oldValue` — один и тот же объект, поэтому сравнить их нельзя.
::

## Практика

::practice{title="Лишнее состояние"}
```js
const items = ref([]);
const count = ref(0);

watch(items, (v) => {
  count.value = v.length;
}, { deep: true, immediate: true });
```

#solution
`count` полностью выводится из `items`. Хранить его отдельно — значит держать два источника правды и следить, чтобы они не разошлись:

```js
const count = computed(() => items.value.length);
```

`computed` всегда согласован с `items`, пересчитывается лениво и без глубокого обхода массива. `watch` с `deep` при каждом изменении любого товара обходил весь массив. Наблюдатель нужен для действий вовне — сохранить корзину, отправить событие, — а не для вычислений.
::

::practice{title="Старые результаты поиска"}
Пользователь быстро ввёл «чай», но на экране результаты для «ч»:

```js
watch(query, async (q) => {
  results.value = await search(q);
});
```

#solution
Запрос на «ч» оказался медленнее и пришёл после ответа на «чай». Каждый запуск колбэка записывает свой результат, и последним записал устаревший. Устаревший запрос нужно отменять:

```js
import { watch, onWatcherCleanup } from 'vue';

watch(query, async (q) => {
  const controller = new AbortController();
  onWatcherCleanup(() => controller.abort());
  try {
    results.value = await search(q, controller.signal);
  } catch (e) {
    if (e.name !== 'AbortError') throw e;
  }
});
```

При вводе «чай» Vue вызывает очистку прошлого запуска, и запрос на «ч» отменяется. Если API не поддерживает отмену, достаточно флага `let stale = false; onWatcherCleanup(() => { stale = true })` и проверки перед записью. В проверке без очистки на экране осталось «ч», с очисткой — «чай», а запрос на «ч» был отменён.
::

::practice{title="Наблюдатель молчит"}
```js
const state = reactive({ count: 0, user: { name: 'Аня' } });

watch(state.count, (v) => console.log('count', v));
watch(() => state.user, (u) => console.log('user', u.name));

state.count++;
state.user.name = 'Оля';
```

Ни один колбэк не вызвался.

#solution
- `watch(state.count)` получил число `0`, а не источник. Vue предупредил «Invalid watch source», наблюдатель ни за чем не следит.
- `() => state.user` возвращает тот же объект, изменилось только его поле. Геттер объекта реагирует на замену, а не на вложенные изменения.

```js
watch(() => state.count, (v) => console.log('count', v));
watch(() => state.user.name, (name) => console.log('user', name));   // конкретное поле
// или: watch(() => state.user, cb, { deep: true })
```

Геттер конкретного поля точнее и дешевле `deep`. В проверке оба исправленных варианта сработали, а исходные — нет.
::
