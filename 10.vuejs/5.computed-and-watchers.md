# Computed и watchers

`computed`, `watch` и `watchEffect` - три способа реагировать на изменение реактивных данных. Их различие («что выбрать?») - один из самых частых вопросов на собесе по Vue. Короткий ответ: **`computed` - для производных значений, watchers - для побочных эффектов**.

---

## computed - кэшируемое производное значение

`computed` вычисляет значение из реактивных данных и **кэширует** его: пересчитывается только когда меняются зависимости.

```js
const firstName = ref('Ада');
const lastName = ref('Лавлейс');

const fullName = computed(() => `${firstName.value} ${lastName.value}`);
```

`fullName` пересчитается, только если изменится `firstName` или `lastName`. Множественные обращения к `fullName.value` между изменениями берут результат из кэша.

### computed vs метод

```vue
<p>{{ fullName }}</p>      <!-- computed: закэшировано -->
<p>{{ getFullName() }}</p> <!-- метод: выполняется на каждый рендер -->
```

<b class="text-on-semi-light">Ключевое отличие</b> - <span class="text-gray">Метод вызывается при **каждом** рендере. `computed` пересчитывается **только при изменении зависимостей**, иначе отдаёт кэш. Для дорогих вычислений - всегда `computed`.</span>

### Writable computed

По умолчанию `computed` только для чтения, но можно задать `get`/`set`.

```js
const fullName = computed({
  get: () => `${firstName.value} ${lastName.value}`,
  set: (val) => { [firstName.value, lastName.value] = val.split(' '); },
});
```

> `computed` должен быть **чистым**: только вычислять значение, без побочных эффектов (запросов, мутаций других состояний). Для эффектов - watchers.

---

## watch - явное наблюдение

`watch` следит за **конкретным источником** и запускает колбэк при его изменении, давая старое и новое значение. Это место для **побочных эффектов**.

```js
watch(query, (newVal, oldVal) => {
  fetchResults(newVal);   // побочный эффект - запрос
});

// несколько источников
watch([a, b], ([newA, newB]) => { /* ... */ });

// свойство reactive-объекта - через геттер
watch(() => user.id, (id) => loadUser(id));
```

### Опции watch

```js
watch(source, cb, {
  immediate: true,  // запустить сразу при создании, не дожидаясь изменения
  deep: true,       // глубоко следить за вложенными свойствами объекта
  flush: 'post',    // когда запускать (см. ниже)
});
```

<b class="text-on-semi-light">deep - осторожно</b> - <span class="text-gray">Глубокое наблюдение обходит весь объект и дорого на больших структурах. Часто лучше следить за конкретным геттером (`() => user.id`), чем за всем объектом с `deep: true`.</span>

---

## watchEffect - автоматические зависимости

`watchEffect` запускается **сразу** и **автоматически** отслеживает все реактивные данные, прочитанные внутри. Не нужно перечислять источники.

```js
watchEffect(() => {
  console.log(`Поиск: ${query.value}`); // query собрался в зависимости автоматически
});
```

Перезапустится при изменении любого прочитанного реактивного значения. Похоже на `useEffect` без массива зависимостей - но Vue **сам** определяет зависимости (в React их перечисляешь руками).

---

## watch vs watchEffect

| | `watch` | `watchEffect` |
|--|---------|----------------|
| Источник | указываешь явно | собирается автоматически из чтений |
| Старое значение | доступно | недоступно |
| Запуск сразу | по умолчанию нет (`immediate`) | да, всегда |
| Когда | реагировать на конкретное изменение, нужен old/new | эффект зависит от многих значений |

> `watch` - точечно и с контролем (есть старое значение, ленивый старт). `watchEffect` - удобно, когда эффект завязан на несколько значений и перечислять их лень.

---

## Время срабатывания (flush)

Когда именно выполнить колбэк относительно обновления DOM - управляется опцией `flush`.

| `flush` | Когда | Зачем |
|---------|-------|-------|
| `'pre'` (по умолчанию) | перед перерисовкой DOM | обычный случай |
| `'post'` | после обновления DOM | нужен доступ к обновлённому DOM (измерения) |
| `'sync'` | синхронно, сразу при изменении | редко; может бить по производительности |

```js
watch(source, cb, { flush: 'post' }); // DOM уже обновлён
// или специальный хелпер:
watchPostEffect(() => { /* DOM актуален */ });
```

## Остановка наблюдателей

`watch`/`watchEffect`, созданные в `setup`, останавливаются автоматически при размонтировании. Созданные асинхронно - нужно останавливать вручную возвращённой функцией.

```js
const stop = watchEffect(() => { /* ... */ });
stop(); // остановить вручную
```

> Watcher, созданный вне синхронного `setup` (например, внутри `setTimeout`), не привязан к компоненту и **не остановится сам** - это источник утечек.

---

## Что выбрать

- **Производное значение** (отформатированная строка, отфильтрованный список, сумма) → `computed`.
- **Побочный эффект в ответ на изменение** (запрос, запись в localStorage, императивная работа с DOM) → `watch`/`watchEffect`.
- Нужно **старое значение** или ленивый старт → `watch`. Эффект зависит от **многих** значений → `watchEffect`.

<b class="text-on-semi-light">Антипаттерн</b> - <span class="text-gray">Использовать `watch` для вычисления производного состояния (следить за `items` и писать в `count`). Это лишнее состояние и рассинхрон - ровно как «You Might Not Need an Effect» в React. Для производных - `computed`.</span>

## Вопросы на собеседовании

<b class="text-on-semi-light">Чем computed отличается от метода?</b>
<span class="text-gray">`computed` кэширует результат и пересчитывается только при изменении зависимостей. Метод выполняется при каждом рендере. Для дорогих вычислений нужен computed.</span>

<b class="text-on-semi-light">Когда использовать computed, а когда watch?</b>
<span class="text-gray">`computed` - для производных значений (чистое вычисление). `watch`/`watchEffect` - для побочных эффектов в ответ на изменение (запросы, запись, DOM).</span>

<b class="text-on-semi-light">В чём разница watch и watchEffect?</b>
<span class="text-gray">`watch` следит за явным источником, даёт старое/новое значение, по умолчанию ленив. `watchEffect` запускается сразу и сам собирает зависимости из прочитанного.</span>

<b class="text-on-semi-light">Что делает опция flush?</b>
<span class="text-gray">Определяет момент колбэка: `pre` (до перерисовки, по умолчанию), `post` (после обновления DOM - для измерений), `sync` (синхронно).</span>

<b class="text-on-semi-light">Чем опасен deep: true?</b>
<span class="text-gray">Глубокое наблюдение обходит всю структуру и дорого на больших объектах. Лучше следить за конкретным геттером.</span>

<b class="text-on-semi-light">Можно ли вычислять производное состояние через watch?</b>
<span class="text-gray">Не нужно - это лишнее состояние и рассинхрон. Для производных значений используется computed (аналог «не нужен Effect» в React).</span>
