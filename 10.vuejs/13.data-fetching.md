# Загрузка данных

Загрузка данных - это работа с **server state**: данными, которые живут на сервере, а в приложении существуют как кэш. Концепции те же, что в React; меняются инструменты. Понимание, что server state - это не обычное состояние, проверяют на собесе и во Vue.

---

## Почему server state особенный

Серверные данные нельзя класть в `ref`, как локальное состояние, потому что они:

- **асинхронные** - приходят с задержкой, могут упасть;
- **разделяемые** - один ресурс нужен в разных местах;
- **устаревают** - на сервере данные меняются;
- требуют **кэш, дедупликацию, фоновое обновление**.

Это кэш удалённого источника, а не состояние приложения - отсюда отдельный класс инструментов.

---

## Наивная загрузка и её проблемы

```vue
<script setup>
import { ref, watchEffect } from 'vue';

const props = defineProps(['id']);
const user = ref(null), loading = ref(true), error = ref(null);

watchEffect(async () => {
  loading.value = true;
  try {
    user.value = await fetch(`/api/users/${props.id}`).then((r) => r.json());
  } catch (e) {
    error.value = e;
  } finally {
    loading.value = false;
  }
});
</script>
```

На масштабе те же беды, что в React:

- **Гонки запросов** - быстрый перебор `id`, старый ответ затирает новый.
- **Нет кэша и дедупликации** - тот же запрос идёт повторно.
- **Водопады** - вложенные компоненты грузят последовательно.
- **Ручные loading/error** в каждом компоненте.

> Поэтому в проде fetching руками почти не пишут - берут библиотеку.

## TanStack Query (Vue Query)

`@tanstack/vue-query` - тот же TanStack Query, что и в React, с Vue-адаптером. Даёт кэш, дедупликацию и фоновое обновление.

```vue
<script setup>
import { useQuery } from '@tanstack/vue-query';

const props = defineProps(['id']);
const { data, isLoading, error } = useQuery({
  queryKey: ['user', props.id],                  // ключ кэша
  queryFn: () => fetch(`/api/users/${props.id}`).then((r) => r.json()),
});
</script>

<template>
  <Spinner v-if="isLoading" />
  <Error v-else-if="error" />
  <Profile v-else :user="data" />
</template>
```

Из коробки: **кэш по `queryKey`**, **дедупликация** параллельных запросов, **stale-while-revalidate** (показать кэш, обновить в фоне), refetch на фокус/реконнект, отмена гонок.

---

## Кэш и инвалидация

Логика идентична React-версии: данные «свежи» (`staleTime`), потом «протухают», но показываются из кэша, пока обновляются в фоне. После мутации кэш **инвалидируют**, чтобы перезапросить.

```js
import { useMutation, useQueryClient } from '@tanstack/vue-query';

const qc = useQueryClient();
const mutation = useMutation({
  mutationFn: updateUser,
  onSuccess: () => qc.invalidateQueries({ queryKey: ['user', id] }),
});
```

Оптимистичные обновления (мгновенный UI с откатом при ошибке) - через `onMutate`, как в React.

## Suspense для async setup

Vue умеет «приостанавливать» компонент с `await` в `setup` через [`<Suspense>`](/content/vuejs/built-in-components). Это декларативная загрузка без флагов.

```vue
<!-- родитель -->
<Suspense>
  <template #default><UserProfile :id="id" /></template>
  <template #fallback><Spinner /></template>
</Suspense>
```

```vue
<!-- UserProfile.vue -->
<script setup>
const props = defineProps(['id']);
const user = await fetch(`/api/users/${props.id}`).then((r) => r.json());
</script>
```

> Удобно, но «голый» await в setup не даёт кэша и обработки гонок - в продакшене это комбинируют с Vue Query или используют серверную загрузку Nuxt.

---

## Загрузка в Nuxt

Мета-фреймворк **Nuxt** даёт `useFetch`/`useAsyncData` - SSR-aware загрузку: данные грузятся **на сервере** при первом рендере и переиспользуются на клиенте без повторного запроса (через гидратацию состояния). Это убирает водопады и дублирование запросов. Подробнее - в [рендеринге и Nuxt](/content/vuejs/rendering-and-nuxt).

```js
const { data, pending, error } = await useFetch('/api/users'); // Nuxt, работает на SSR
```

---

## Водопады запросов

**Waterfall** - последовательные зависимые запросы. Лечение то же, что в React: параллелить независимые, префетчить, поднимать загрузку к роуту/серверу.

## Вопросы на собеседовании

<b class="text-on-semi-light">Чем server state отличается от обычного состояния?</b>
<span class="text-gray">Асинхронный, разделяемый, устаревает, требует кэша и дедупликации. Это кэш удалённых данных - для него отдельные инструменты, а не ref.</span>

<b class="text-on-semi-light">Чем плох fetching в watchEffect/onMounted?</b>
<span class="text-gray">Гонки запросов, нет кэша и дедупликации, водопады, ручные loading/error. TanStack Query решает это из коробки.</span>

<b class="text-on-semi-light">Что такое stale-while-revalidate?</b>
<span class="text-gray">Показать данные из кэша сразу, а в фоне перезапросить и обновить. Быстрый UI без ожидания сети.</span>

<b class="text-on-semi-light">Как загрузить данные через Suspense во Vue?</b>
<span class="text-gray">Использовать `await` в `setup` дочернего компонента и обернуть его в `<Suspense>` с fallback. Но голый await не даёт кэша - комбинируют с Query или Nuxt.</span>

<b class="text-on-semi-light">Чем полезен useFetch в Nuxt?</b>
<span class="text-gray">SSR-aware загрузка: данные грузятся на сервере при первом рендере и переиспользуются на клиенте без повторного запроса - убирает водопады и дубли.</span>
