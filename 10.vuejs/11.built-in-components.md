# Встроенные компоненты

Компоненты, которые Vue даёт из коробки: `Teleport` для отрисовки в другом месте DOM, `Suspense` для ожидания асинхронных потомков, `KeepAlive` для кеша переключаемых компонентов, `defineAsyncComponent` для загрузки по требованию и `Transition` для анимаций. Спрашивают, зачем `Teleport`, что делает `KeepAlive` и как загрузить компонент лениво. Глубже — куда всплывает клик внутри телепорта, какие компоненты `KeepAlive` вытесняет и почему `include` не срабатывает.

::tldr
- **`Teleport` переносит узлы в другое место DOM, но оставляет компонент на месте в дереве компонентов:** пропсы, `inject` и события компонентов работают как обычно. А DOM-события всплывают по реальному DOM — до элементов родителя клик не дойдёт.
- **`Suspense` показывает запасное содержимое, пока не разрешатся асинхронные `setup` потомков.** Он всё ещё помечен экспериментальным.
- **`KeepAlive` не уничтожает скрытые компоненты, а кеширует их вместе с состоянием.** `include` и `exclude` сравнивают имена компонентов, `max` вытесняет давно не использованный, а вместо монтирования срабатывают `onActivated` и `onDeactivated`.
- **`defineAsyncComponent` загружает код компонента, только когда он нужен,** и показывает компоненты загрузки и ошибки. Сборщик выносит такой компонент в отдельный чанк.
- **`Transition` анимирует появление и исчезновение через классы `*-enter-from`, `*-enter-active`, `*-enter-to` и такие же `leave`.** Ребёнок — один элемент с `v-if` или `v-show`, а у `TransitionGroup` нужны ключи.
::

## Teleport

Сквозной пример — карточка товара открывает модальное окно быстрого просмотра. Логически окно — часть карточки: ему нужны данные товара и тема. Но отрисовать его внутри карточки нельзя: `overflow: hidden` обрежет окно, а `z-index` родителя не даст ему оказаться поверх страницы.

```vue
<!-- QuickView.vue -->
<script setup>
const emit = defineEmits(['close']);
defineProps({ product: Object });
</script>

<template>
  <Teleport to="body">
    <div class="modal" role="dialog" aria-modal="true">
      <h2>{{ product.title }}</h2>
      <button @click="emit('close')">Закрыть</button>
    </div>
  </Teleport>
</template>
```

Узлы внутри `Teleport` вставляются в `body`, а компонент остаётся на своём месте в **дереве компонентов**. Проверено:

- в разметке карточки окна нет, оно — прямой потомок `body`;
- `inject` внутри окна получил тему от предка карточки;
- событие компонента `close` дошло до родителя;
- при удалении карточки окно исчезло вместе с ней.

### Куда всплывает клик

Есть разница, которая отличает Vue от React. События компонентов идут по дереву компонентов, а **DOM-события — по реальному DOM**. Обработчики Vue — обычные нативные слушатели, поэтому клик внутри окна всплывает от `body`, а не от карточки. Слушатель `@click` на элементе карточки его не получит — в проверке так и было. В React порталы передают события по дереву React, и клик в портале доходит до обработчиков родителя (подробно — в [Рефах, порталах и доступности](/content/reactjs/refs-portals-a11y)).

На практике это значит: закрытие по клику вне окна и делегирование событий пишут с учётом реального DOM.

### Цель и отключение

- **цель должна существовать до монтирования.** Иначе Vue предупредит «Failed to locate Teleport target» и ничего не отрисует. Атрибут `defer` откладывает поиск цели до конца отрисовки — так можно телепортировать в элемент, который создаётся в том же шаблоне;
- **`disabled`** рисует содержимое на месте. Удобно для адаптивности: на мобильном окно встраивается в страницу, на десктопе всплывает;
- **несколько `Teleport` в одну цель** добавляют содержимое по порядку.

Для модальных окон стоит посмотреть на нативный `dialog` с `showModal()`: он сам рисуется поверх страницы, управляет фокусом и закрывается по Esc.

## Suspense

Компонент может быть асинхронным: верхнеуровневый `await` в `<script setup>` или `async setup()` (подробно — в [Composition API](/content/vuejs/composition-api)). `Suspense` ждёт, пока разрешатся все асинхронные потомки, и до этого показывает запасное содержимое:

```vue
<Suspense>
  <ProductPage :id="id" />
  <template #fallback>
    <PageSkeleton />
  </template>
</Suspense>
```

```vue
<!-- ProductPage.vue -->
<script setup>
const props = defineProps({ id: Number });
const product = await fetch(`/api/products/${props.id}`).then((r) => r.json());
</script>
```

В проверке до разрешения промиса был виден текст загрузки, после — данные. Один `Suspense` ждёт всё асинхронное дерево внутри, поэтому несколько асинхронных компонентов показываются одновременно, без мигания по частям.

Особенности:

- **`Suspense` экспериментальный:** Vue пишет об этом в консоль, и API может измениться. В продакшене его используют, но с оглядкой — чаще всего вместе с Nuxt и роутером;
- **ошибки асинхронного `setup`** ловят `onErrorCaptured` в предке или обработчик ошибок приложения;
- **при повторной загрузке** (сменился `id`) `Suspense` по умолчанию показывает прежнее содержимое, пока не готово новое, а атрибут `timeout` задаёт, через сколько миллисекунд переключиться на запасное.

Загрузка с кешем, повторными запросами и состояниями ошибки — в [Загрузке данных](/content/vuejs/data-fetching).

## KeepAlive

Когда пользователь переключает вкладки, компонент старой вкладки уничтожается, а при возврате создаётся заново: введённое в форму, прокрутка и загруженные данные теряются. `KeepAlive` кеширует скрытые компоненты:

```vue
<KeepAlive include="CartTab" :max="5">
  <component :is="tabs[current]" />
</KeepAlive>
```

### Что меняется

- **состояние сохраняется:** в проверке счётчик вкладки «Корзина» после ухода и возврата остался `1`;
- **жизненный цикл другой:** вместо `onUnmounted` и `onMounted` срабатывают `onDeactivated` и `onActivated`. В `onActivated` обновляют данные, которые могли устареть, в `onDeactivated` останавливают таймеры и подписки — компонент жив, но не виден.

### include, exclude и max

`include` и `exclude` принимают строку, регулярное выражение или массив и сравнивают **имя компонента**. Компонент на `<script setup>` получает имя из имени файла, а явно — через `defineOptions({ name: 'CartTab' })`. Если `include` «не работает», причина почти всегда в имени.

`max` ограничивает размер кеша. Когда он заполнен, вытесняется **давно не использованный** компонент. В проверке с `max: 2` после открытия `A`, `B`, `C` компонент `A` был вытеснен и при возврате создан заново, а `B` достался из кеша.

В React встроенного аналога нет: сохранение состояния при скрытии решают подъёмом состояния, `display: none` или компонентом `Activity` (подробно — в [RSC и React 19](/content/reactjs/rsc-and-react-19)). Во Vue похожий приём без кеша — `v-show` (подробно — в [Шаблонах и директивах](/content/vuejs/templates-and-directives)).

## Асинхронные компоненты

Тяжёлый компонент — редактор, график, карта — не нужен на первом экране. `defineAsyncComponent` загружает его код, только когда компонент впервые отрисуется:

```js
import { defineAsyncComponent } from 'vue';

const PriceChart = defineAsyncComponent(() => import('./PriceChart.vue'));
```

Динамический `import()` сборщик превращает в отдельный файл-чанк, и он загружается по требованию (подробно — в [Модулях](/content/javascript/modules)). В проверке загрузчик не вызывался, пока компонент был скрыт, и вызвался один раз при показе.

Расширенная форма задаёт состояния:

```js
const PriceChart = defineAsyncComponent({
  loader: () => import('./PriceChart.vue'),
  loadingComponent: ChartSkeleton,
  delay: 200,            // не показывать загрузку, если успели быстрее
  errorComponent: ChartError,
  timeout: 10_000,
});
```

`delay` убирает мигание индикатора на быстрых соединениях. `errorComponent` показывается, если чанк не загрузился — после деплоя старый файл мог исчезнуть, и в проверке вместо графика появилось «Не удалось загрузить». Асинхронный компонент внутри `Suspense` ждёт его, а не свой `loadingComponent`.

Для страниц то же делает роутер: `component: () => import('./ProductPage.vue')` (подробно — в [Маршрутизации](/content/vuejs/routing)). При SSR асинхронные компоненты можно гидратировать лениво — при появлении в зоне видимости или во время простоя (подробно — в [Рендеринге и Nuxt](/content/vuejs/rendering-and-nuxt)).

## Transition и TransitionGroup

`Transition` анимирует появление и исчезновение одного элемента или компонента:

```vue
<Transition name="fade">
  <p v-if="added" class="toast">Добавлено в корзину</p>
</Transition>
```

```css
.fade-enter-active, .fade-leave-active { transition: opacity 0.2s; }
.fade-enter-from, .fade-leave-to { opacity: 0; }
```

Vue добавляет классы по шагам:

```text
появление: enter-from + enter-active → (следующий кадр) enter-to + enter-active → (конец перехода) классы сняты
исчезновение: leave-from + leave-active → leave-to + leave-active → элемент удалён
```

В проверке в первом кадре у элемента были `fade-enter-from` и `fade-enter-active`, а после завершения перехода остался только собственный класс. Конец перехода Vue определяет по `transitionend` и `animationend` или по длительности из вычисленных стилей. Элемент удаляется только после окончания анимации исчезновения.

Правила:

- **ребёнок — один элемент или компонент,** и анимация срабатывает на `v-if`, `v-show`, смену `:is` или `key`;
- **`mode="out-in"`** сначала прячет старый элемент, потом показывает новый — без наложения при переключении;
- **`TransitionGroup`** анимирует элементы списка, у каждого нужен `key`, а перемещения анимирует класс `*-move`;
- **JavaScript-хуки** `@enter`, `@leave` позволяют анимировать библиотекой, вызывая `done()` по окончании.

Анимации уважают настройки пользователя: под `@media (prefers-reduced-motion: reduce)` переходы отключают или сокращают. Анимация между страницами в современных браузерах — View Transitions API (подробно — в [Будущем веба](/content/web/future-of-web)).

## Красные флаги в ответе

- **«`Teleport` выносит компонент из дерева».** Компонент остаётся на месте: `inject`, пропсы и события компонентов работают как обычно.
- **«Клик внутри телепорта дойдёт до родителя, как в React».** DOM-события всплывают по реальному DOM, от места назначения.
- **«`KeepAlive` просто прячет компонент».** Он кеширует экземпляр, меняет жизненный цикл на `activated` и `deactivated` и вытесняет старое по `max`.
- **«`include` сравнивает имена файлов или тегов».** Он сравнивает имя компонента — из имени файла или `defineOptions`.
- **«`Suspense` — стабильный механизм загрузки данных».** Он экспериментальный и ждёт только асинхронные `setup`, без кеша и повторов.

## Как спрашивают на собеседовании

::question
Что делает Teleport и зачем он нужен?

#answer
Отрисовывает содержимое в другом месте DOM — обычно в `body` — при этом компонент остаётся на своём месте в дереве компонентов. Нужен для модальных окон, всплывающих подсказок и уведомлений, которые иначе обрежет `overflow` или перекроет `z-index` родителя.

#more
Пропсы, `inject` и события компонентов работают как без телепорта. DOM-события всплывают по реальному DOM, поэтому клик внутри окна не дойдёт до элементов родителя — в отличие от порталов React. Цель должна существовать до монтирования, `defer` откладывает поиск, `disabled` рисует на месте.
::

::question
Для чего Suspense во Vue?

#answer
Показывает запасное содержимое, пока не разрешатся асинхронные `setup` потомков — верхнеуровневый `await` в `<script setup>` или `async setup()`. Несколько асинхронных компонентов внутри появляются одновременно.

#more
`Suspense` экспериментальный. Ошибки асинхронного `setup` ловит `onErrorCaptured` предка. При повторной загрузке по умолчанию показывается прежнее содержимое, `timeout` переключает на запасное. Кеша, повторов и отмены у `Suspense` нет — это задача библиотек загрузки данных.
::

::question
Что делает KeepAlive?

#answer
Кеширует переключаемые компоненты вместо того, чтобы уничтожать их: при возврате компонент показывается с прежним состоянием. Вместо размонтирования и монтирования срабатывают `onDeactivated` и `onActivated`.

#more
`include` и `exclude` фильтруют по имени компонента, `max` ограничивает кеш и вытесняет давно не использованный. В `onActivated` обновляют устаревшие данные, в `onDeactivated` останавливают таймеры. Кешированные компоненты занимают память, поэтому `max` стоит задавать.
::

::question
Как сделать ленивую загрузку компонента?

#answer
`defineAsyncComponent(() => import('./Chart.vue'))`. Сборщик вынесет компонент в отдельный чанк, и он загрузится, только когда будет впервые отрисован.

#more
Расширенная форма задаёт `loadingComponent` с задержкой `delay`, `errorComponent` и `timeout`. Ошибка загрузки чанка — частая ситуация после деплоя, для неё нужен понятный `errorComponent`. Для страниц ленивую загрузку делает роутер, при SSR есть ленивая гидратация.
::

::question
Как Vue анимирует появление и исчезновение?

#answer
Компонент `Transition` добавляет элементу классы по шагам: `*-enter-from` и `*-enter-active`, в следующем кадре `*-enter-to`, и снимает их по окончании перехода. При исчезновении — такие же `leave`, а элемент удаляется после анимации.

#more
Ребёнок — один элемент с `v-if`, `v-show` или сменой `key`. `mode="out-in"` убирает наложение при переключении. `TransitionGroup` анимирует списки, требует ключей и анимирует перемещения классом `*-move`. Для анимаций библиотеками есть JavaScript-хуки с `done()`.
::

::question
Почему KeepAlive include не работает?

#answer
`include` сравнивает имя компонента, а не имя тега или переменной. Если у компонента нет имени или оно другое, он не попадёт в кеш.

#more
Компонент на `<script setup>` получает имя из имени файла, явное имя задают через `defineOptions({ name })`. Ещё одна причина — у динамического компонента меняется `key`, и `KeepAlive` видит новый экземпляр. Проверить имя можно в Vue DevTools.
::

## Практика

::practice{title="Модалка не закрывается по клику вне"}
Окно быстрого просмотра телепортировано в `body`. Закрытие по клику вне окна написано через слушатель на обёртке карточки, и окно закрывается даже при клике внутри него:

```vue
<template>
  <section class="card" @click="onCardClick">
    <QuickView v-if="open" @close="open = false" />   <!-- внутри Teleport to="body" -->
  </section>
</template>
```

#solution
Клики внутри окна всплывают по реальному DOM — от `body`, а не через `section.card`. Обработчик карточки рассчитывал на структуру DOM, которой больше нет. Закрытие по клику вне надо вешать на сам слой окна:

```vue
<!-- QuickView.vue -->
<template>
  <Teleport to="body">
    <div class="backdrop" @click.self="emit('close')">
      <div class="modal" role="dialog" aria-modal="true">…</div>
    </div>
  </Teleport>
</template>
```

`.self` срабатывает, только если клик пришёл на сам фон, а не на окно внутри него. Ещё проще — нативный `dialog`: клик по `::backdrop` приходит на сам элемент `dialog`. В проверке клик внутри телепортированного окна не дошёл до слушателя родительской секции, а событие компонента `close` — дошло.
::

::practice{title="Вкладка теряет введённые данные"}
В личном кабинете вкладки переключаются через `component :is`. При возврате на вкладку с формой адреса введённое пропадает.

#solution
При смене `:is` старый компонент уничтожается вместе с состоянием. Если форма должна пережить переключение, её кешируют:

```vue
<KeepAlive include="AddressTab" :max="3">
  <component :is="tabs[current]" />
</KeepAlive>
```

```vue
<!-- AddressTab.vue -->
<script setup>
defineOptions({ name: 'AddressTab' });
onActivated(() => refreshDeliveryZones());   // данные могли устареть
</script>
```

Имя в `include` должно совпадать с именем компонента. Альтернатива без кеша экземпляра — держать состояние формы выше, в родителе или сторе, и тогда вкладку можно спокойно пересоздавать. В проверке состояние вкладки из `include` сохранилось, а вкладка вне `include` создалась заново.
::
