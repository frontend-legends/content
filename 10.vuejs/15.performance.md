# Производительность

Хорошая новость: Vue делает много оптимизаций **автоматически** - тонкая реактивность и компилятор снимают значительную часть ручной работы, которая в React ложится на `memo`/`useMemo`. Но senior всё равно должен знать инструменты для тяжёлых случаев.

---

## Что Vue оптимизирует сам

- **Тонкая реактивность** - обновляется только то, что реально зависит от изменённых данных. Не нужно мемоизировать компоненты, чтобы избежать лишних ререндеров (как `React.memo`).
- **Компиляторные оптимизации** - анализируя шаблон, Vue **поднимает статические узлы** (hoisting) и помечает динамические **patch-флагами**, чтобы при обновлении проверять только изменяемые части, а не весь VDOM.

<b class="text-on-semi-light">Следствие для собеса</b> - <span class="text-gray">Во Vue реже встречается «лишний ререндер всего поддерева» из-за рендера родителя - реактивность точечная. Поэтому базовая производительность Vue из коробки выше, а ручная мемоизация нужна реже.</span>

---

## v-once

Рендерит элемент/поддерево **один раз** и больше никогда не обновляет - для статического контента, который точно не изменится.

```vue
<header v-once>
  <h1>{{ siteTitle }}</h1> <!-- зафиксируется при первом рендере -->
</header>
```

---

## v-memo

Мемоизирует поддерево по массиву зависимостей - пропускает обновление, если значения не изменились. Аналог `React.memo`, но точечный, на уровне разметки. Применяют в **больших списках**.

```vue
<div v-for="item in list" :key="item.id" v-memo="[item.id, item.selected]">
  <!-- перерисуется, только если изменился id или selected -->
</div>
```

> `v-memo` - инструмент «по требованию» для длинных списков с дорогими строками. В обычном коде не нужен.

---

## computed-кэш

`computed` кэширует производные значения и пересчитывает только при изменении зависимостей - базовый инструмент против повторных дорогих вычислений (см. [computed и watchers](/content/vuejs/computed-and-watchers)).

---

## KeepAlive

`<KeepAlive>` избавляет от стоимости пересоздания компонентов при переключении - кэширует их вместе с состоянием (см. [встроенные компоненты](/content/vuejs/built-in-components)).

---

## Code splitting

Не грузить весь JS сразу - лениво подгружать по маршрутам и тяжёлым компонентам.

```js
const Dashboard = defineAsyncComponent(() => import('./Dashboard.vue'));
// и ленивые маршруты: component: () => import('./Page.vue')
```

Снижает начальный бандл и время до интерактивности.

---

## Виртуализация списков

Рендерить тысячи DOM-узлов - дорого. Виртуализация рендерит только видимые строки.

```
vue-virtual-scroller / @tanstack/vue-virtual - рендерят ~20 видимых строк вместо 10 000
```

---

## Реактивность под нагрузкой

Для больших или внешних структур данных глубокая реактивность - лишняя стоимость. `shallowRef`/`markRaw` отключают её там, где она не нужна (см. [продвинутую реактивность](/content/vuejs/reactivity-advanced)). Также избегай `deep: true` в watcher'ах на больших объектах.

---

## Vapor mode

**Vapor mode** - новый режим компиляции Vue (развивается в 2024–2026), который **не использует Virtual DOM**. Вместо рендер-функций, создающих VDOM, компилятор генерирует **прямые операции с DOM**, привязанные к реактивности, - подход в духе Solid.js.

<b class="text-on-semi-light">Зачем</b> - <span class="text-gray">Меньше рантайма, меньше памяти, быстрее обновления - VDOM-слой убирается совсем. Это opt-in режим, совместимый с существующими компонентами по мере готовности. На собесе 2026 - хороший признак, если знаешь про него: Vue движется от VDOM к компиляции в прямые DOM-инструкции.</span>

> Тонкая реактивность Vue делает такой переход естественным: раз зависимости и так известны, можно генерировать точечные обновления DOM без diffing.

## Профайлинг

- **Vue DevTools** - инспекция компонентов, таймлайн событий, граф зависимостей.
- **Performance-вкладка** браузера и Lighthouse - метрики загрузки и Core Web Vitals.

> Как и в React: сначала измерь, потом оптимизируй. Преждевременные `v-memo`/`shallowRef` усложняют код без выигрыша.

---

## Чеклист

1. Измерь в Vue DevTools / Performance.
2. Дорогие производные - в `computed`.
3. Длинные списки - виртуализация (+ `v-memo` для тяжёлых строк).
4. Переключаемые компоненты - `KeepAlive`.
5. Бандл - ленивые маршруты и async-компоненты.
6. Большие/внешние данные - `shallowRef`/`markRaw`, без `deep`-watcher'ов.

## Вопросы на собеседовании

<b class="text-on-semi-light">Почему во Vue реже нужна ручная мемоизация, чем в React?</b>
<span class="text-gray">Тонкая реактивность обновляет только зависящие места, а компилятор поднимает статику и помечает динамику patch-флагами. Лишних ререндеров поддерева из-за родителя меньше.</span>

<b class="text-on-semi-light">Чем v-once отличается от v-memo?</b>
<span class="text-gray">`v-once` рендерит один раз и никогда не обновляет. `v-memo` обновляет при изменении значений из массива зависимостей - мемоизация поддерева, обычно для больших списков.</span>

<b class="text-on-semi-light">Как ускорить длинный список во Vue?</b>
<span class="text-gray">Виртуализация (vue-virtual-scroller / vue-virtual), стабильные ключи, при необходимости `v-memo` для тяжёлых строк.</span>

<b class="text-on-semi-light">Как уменьшить стоимость реактивности больших данных?</b>
<span class="text-gray">`shallowRef`/`shallowReactive`, `markRaw` для внешних объектов, отказ от `deep: true` в watcher'ах.</span>

<b class="text-on-semi-light">Что такое Vapor mode?</b>
<span class="text-gray">Режим компиляции без Virtual DOM: компилятор генерирует прямые DOM-операции, привязанные к реактивности (как Solid). Меньше рантайма и памяти, быстрее обновления; opt-in.</span>
