# Введение в Vue

Вводная история главы: что такое Vue, как шаблон превращается в DOM, что запускает обновление и из чего состоит однофайловый компонент. Спрашивают, что значит «прогрессивный фреймворк», чем модель Vue отличается от React и что принёс Vue 3. Глубже — почему при изменении состояния родителя дочерний компонент не перерисовывается, что компилятор знает о шаблоне и почему шаблон-строка не работает в части сборок.

::tldr
- **Vue — декларативный компонентный фреймворк с реактивностью.** Ты описываешь, как интерфейс зависит от состояния, а Vue сам отслеживает, какие данные прочитал каждый компонент, и обновляет только его.
- **Шаблон компилируется в render-функцию,** обычно при сборке. Компилятор видит, какие части шаблона статичны, и помечает динамические — поэтому обновление сравнивает меньше, чем обычный virtual DOM.
- **Единица обновления — компонент.** Изменилось состояние родителя, а пропсы ребёнка прежние — ребёнок не перерисуется. Несколько изменений подряд дают одну перерисовку.
- **SFC — файл `.vue` с шаблоном, логикой и стилями.** `scoped`-стили работают через атрибут `data-v-…` и не доходят до внутренностей дочерних компонентов.
- **«Прогрессивный» — значит, берёшь столько, сколько нужно:** от скрипта на готовой странице до приложения с роутером, стором и SSR. Роутер, стор и мета-фреймворк — официальные.
::

## Что такое Vue

Короткий ответ на собесе: **Vue — фреймворк для построения интерфейсов, декларативный, компонентный и реактивный.** Каждое слово — следствие в коде.

Сквозной пример этой истории — значок корзины:

```vue
<script setup>
import { ref } from 'vue';

const count = ref(0);
</script>

<template>
  <button @click="count++">В корзине: {{ count }}</button>
</template>
```

- **Декларативный** — нет кода «найди кнопку и поменяй текст». Шаблон описывает результат для любого `count`, а синхронизацию с DOM берёт на себя Vue.
- **Компонентный** — интерфейс собирается из таких файлов, у каждого своё состояние и свой шаблон.
- **Реактивный** — `count` не просто переменная. Vue знает, что шаблон её прочитал, и при изменении обновит именно этот компонент. Как это устроено — в [Основах реактивности](/content/vuejs/reactivity-fundamentals).

Слово **прогрессивный** — о масштабе. Vue можно подключить одним `<script>` к странице, которую рендерит сервер, и оживить на ней виджет. А можно построить одностраничное приложение с роутером, стором, SSR и типизацией. Ядро одно, а остальное добавляется по мере необходимости.

Шаблон похож на HTML, но браузер его не понимает. Что с ним происходит до того, как пользователь увидит кнопку?

## Как шаблон становится DOM

Путь шаблона — три шага:

```text
шаблон  ──компилятор──►  render-функция  ──вызов──►  virtual DOM  ──patch──►  DOM
(.vue)                   (JavaScript)                 (дерево объектов)        (реальные узлы)
```

**Компилятор** превращает шаблон в обычную JavaScript-функцию. Для кнопки из примера получается примерно такое (вывод `@vue/compiler-dom`):

```js
export function render(_ctx, _cache) {
  return (_openBlock(), _createElementBlock("button", {
    onClick: _cache[0] || (_cache[0] = $event => (_ctx.count++))
  }, _toDisplayString(_ctx.count), 1 /* TEXT */))
}
```

**Render-функция** при вызове возвращает virtual DOM — описание узлов в виде объектов. При первом показе Vue создаёт по нему реальные элементы, а при обновлении сравнивает новое дерево со старым и меняет в DOM только различия (этот шаг называется patch).

Обычно компиляция происходит **при сборке**: плагин Vite обрабатывает `.vue`-файлы, и в браузер уходят готовые render-функции. Компилятор в браузере не нужен, поэтому в приложении работает сборка «только рантайм». Если же передать шаблон строкой (`template: '<p>…</p>'`), эта сборка его не поймёт — в проверке она вывела предупреждение «runtime compilation is not supported in this build of Vue». Полная сборка с компилятором нужна только тогда, когда шаблоны появляются во время выполнения, например при подключении Vue скриптом к готовой странице.

### Что компилятор знает о шаблоне

У компилятора есть преимущество перед JSX: он видит весь шаблон и знает, что в нём может измениться. Комментарий `1 /* TEXT */` в выводе выше — **patch flag**: у этого узла при обновлении достаточно проверить текст, атрибуты и детей сравнивать не нужно. Статичные части шаблона компилятор выносит из render-функции и вообще не сравнивает. Поэтому подход Vue называют **virtual DOM с подсказками компилятора**. Подробно об этих оптимизациях и о Vapor mode, где virtual DOM нет совсем, — в [Производительности](/content/vuejs/performance).

Шаблон превратился в DOM. Но кто решает, когда вызвать render-функцию ещё раз?

## Что запускает обновление

Render-функция компонента выполняется внутри **эффекта** — функции, которую Vue перезапускает, когда меняются данные, прочитанные в прошлый раз. Компонент прочитал `count` — значит, зависит от `count`. Других подписок нет.

Отсюда главное отличие от React. В React изменение состояния родителя по умолчанию перерисовывает и всех его детей, а пропуск ребёнка — ручная оптимизация через `memo` (подробно — в [Производительности React](/content/reactjs/performance)). Во Vue каждый компонент — свой эффект со своими зависимостями:

- изменилось состояние родителя, а пропсы ребёнка прежние — **перерисуется только родитель**;
- изменилось состояние ребёнка — **перерисуется только ребёнок**, родитель о нём не знает;
- изменился проп ребёнка — перерисуются оба.

В проверке ровно так и вышло: счётчики рендеров родителя и ребёнка росли независимо. Ручная мемоизация компонентов во Vue почти не нужна — зависимости собираются сами.

Второе свойство — **обновления складываются**. Три изменения подряд не дают трёх перерисовок: Vue ставит эффект компонента в очередь и выполняет его один раз, асинхронно, перед следующей отрисовкой. Поэтому сразу после изменения данных DOM ещё старый, и чтобы прочитать обновлённый DOM, ждут `nextTick()`. Как устроены очередь и `nextTick` — в [Продвинутой реактивности](/content/vuejs/reactivity-advanced).

Так работает один компонент. Как выглядит файл, в котором его пишут?

## Однофайловые компоненты

Канонический формат Vue — **SFC** (Single-File Component), файл `.vue` из трёх блоков:

```vue
<script setup>
import { ref } from 'vue';
const name = ref('Vue');
</script>

<template>
  <h1>Привет, {{ name }}</h1>
</template>

<style scoped>
h1 { color: #42b883; }
</style>
```

- **`<script setup>`** — логика компонента. Всё, что объявлено на верхнем уровне, доступно в шаблоне без явного `return` (подробно — в [Composition API](/content/vuejs/composition-api)).
- **`<template>`** — разметка с директивами вроде `v-if`, `v-for`, `@click` (подробно — в [Шаблонах и директивах](/content/vuejs/templates-and-directives)).
- **`<style scoped>`** — стили только этого компонента.

### Как работает scoped

Компилятор даёт компоненту уникальный идентификатор, добавляет атрибут `data-v-…` его элементам и переписывает селекторы:

```css
h1 { color: #42b883; }
/* превращается в */
h1[data-v-7ba5bd90] { color: #42b883; }
```

Изоляция — это специфичность селектора, а не Shadow DOM. Отсюда две особенности:

- **корневой элемент дочернего компонента** получает атрибут родителя, поэтому родитель может стилизовать его как свой;
- **внутренние элементы ребёнка** атрибута родителя не получают, и селектор `.card .title` из родителя до них не дойдёт. Для этого есть `:deep()`: `.card :deep(.title)` превращается в `.card[data-v-…] .title`.

Оба правила проверены — и на выводе компилятора стилей, и на смонтированном компоненте.

Разметка и стили понятны. Остаётся логика — и здесь у Vue два стиля.

## Два API

У Vue 3 два способа описать логику компонента:

```js
// Options API — логика разложена по опциям
export default {
  data() { return { count: 0 }; },
  computed: { double() { return this.count * 2; } },
  methods: { add() { this.count++; } },
};
```

```js
// Composition API — логика собрана функциями
const count = ref(0);
const double = computed(() => count.value * 2);
function add() { count.value++; }
```

Options API раскладывает код по типам — данные отдельно, методы отдельно, — и логика одной задачи разбегается по файлу. Composition API группирует код по смыслу и позволяет вынести логику в функцию-композабл. В новом коде используют Composition API с `<script setup>`, а Options API остаётся поддерживаемым и встречается в легаси-проектах. Подробное сравнение — в [Composition API](/content/vuejs/composition-api).

### Vue, React и Angular

| | Vue | React | Angular |
| --- | --- | --- | --- |

## Как менялся Vue

Актуально на ноябрь 2026.

| Версия | Изменения |
| --- | --- |
| 2014 | первый релиз |
| Vue 2 (2016) | virtual DOM, официальные Vuex и Vue Router, реактивность на `Object.defineProperty` |
| Vue 3 (2020) | реактивность на Proxy, Composition API, компилятор с patch flags, `<script setup>` |
| 2022 | Vue 3 стал версией по умолчанию, Pinia — рекомендуемым стором |
| конец 2023 | завершена поддержка Vue 2 |
| Vue 3.4 | новый парсер шаблонов, `defineModel` |
| Vue 3.5 | переработанная реактивность с меньшим расходом памяти, реактивная деструктуризация пропсов, `useTemplateRef`, `useId`, ленивая гидратация |
| Vue 3.6 | в стадии RC: Vapor mode — компиляция без virtual DOM для отдельных компонентов, ядро реактивности на alien-signals |

Главный сдвиг — переход Vue 3 на Proxy. Реактивность Vue 2 не видела добавление новых свойств и запись по индексу массива, отсюда `Vue.set` в старом коде (подробно — в [Основах реактивности](/content/vuejs/reactivity-fundamentals)).

## Красные флаги в ответе

- **«Vue перерисовывает дерево целиком, как React».** Единица обновления — компонент: ребёнок с прежними пропсами не перерисуется.
- **«Vue работает без virtual DOM».** В обычных компонентах virtual DOM есть, но с подсказками компилятора. Без него работает только Vapor mode.
- **«Шаблон интерпретируется в браузере».** Обычно он компилируется в render-функцию при сборке, и компилятора в браузере нет.
- **«`scoped` изолирует стили, как Shadow DOM».** Это атрибут `data-v-…` в селекторе: корень ребёнка стилизуется, внутренности — только через `:deep()`.
- **«После `count.value++` DOM уже обновлён».** Обновление асинхронное и складывается в одно, DOM читают после `nextTick()`.

## Как спрашивают на собеседовании

::question
Что значит «прогрессивный фреймворк»?

#answer
Vue масштабируется по потребности: можно подключить его одним скриптом к готовой странице и оживить виджет, а можно построить приложение с роутером, стором, SSR и типизацией. Ядро одно, остальное добавляется постепенно.

#more
Для встраивания в страницу используют полную сборку с компилятором шаблонов, для приложения — сборку при помощи Vite, где шаблоны компилируются заранее и в браузер уходит только рантайм. Роутер, стор и Nuxt — официальные проекты, поэтому «дорасти» можно без смены экосистемы.
::

::question
Как шаблон Vue превращается в DOM?

#answer
Компилятор превращает шаблон в render-функцию, обычно при сборке. Render-функция возвращает virtual DOM, и Vue создаёт по нему элементы, а при обновлении сравнивает новое дерево со старым и меняет только различия.

#more
Компилятор помечает динамические узлы флагами (patch flags) и выносит статичные части, поэтому сравнение проверяет только то, что может измениться. Шаблон-строка во время выполнения требует полной сборки с компилятором — сборка «только рантайм» выдаст предупреждение. Vapor mode в Vue 3.6 компилирует шаблон сразу в операции с DOM, без virtual DOM.
::

::question
Чем модель обновления Vue отличается от React?

#answer
В React обновление начинается с вызова `setState`, компонент перерисовывается вместе с потомками, а пропуск детей — ручная оптимизация через `memo`. Во Vue каждый компонент — эффект, который знает, какие данные прочитал, и перерисовывается только при их изменении.

#more
Ребёнок с прежними пропсами не перерисуется при изменении состояния родителя, а изменение состояния ребёнка не трогает родителя. Несколько изменений подряд складываются в одну асинхронную перерисовку. Поэтому `computed` — основной инструмент, а мемоизация компонентов во Vue почти не нужна.
::

::question
Что такое SFC и как работают scoped-стили?

#answer
SFC — файл `.vue` с блоками `<script>`, `<template>` и `<style>`, который компилятор превращает в JavaScript-модуль компонента. `scoped` добавляет элементам компонента атрибут `data-v-…` и переписывает селекторы: `h1` становится `h1[data-v-…]`.

#more
Корневой элемент дочернего компонента получает атрибут и родителя, поэтому родитель может его стилизовать. Внутренние элементы ребёнка — нет, для них есть `:deep()`. Это не Shadow DOM: глобальные стили по-прежнему действуют на компонент. Альтернатива — CSS Modules через `<style module>`.
::

::question
Что нового принёс Vue 3?

#answer
Реактивность на Proxy вместо `Object.defineProperty`, Composition API и `<script setup>`, компилятор с patch flags, полноценную поддержку TypeScript, `Teleport`, `Suspense` и несколько корневых узлов в шаблоне.

#more
Proxy видит добавление свойств и запись по индексу, которые реактивность Vue 2 пропускала. Vue 2 больше не поддерживается. Дальше Vue 3.5 переработал реактивность и сократил расход памяти, а 3.6 (RC) добавляет Vapor mode и ядро на alien-signals.
::

::question
Чем Options API отличается от Composition API?

#answer
Options API раскладывает логику по опциям `data`, `computed`, `methods`, и код одной задачи разбегается по файлу. Composition API собирает логику функциями `ref`, `computed`, `watch` по смыслу и позволяет вынести её в композабл.

#more
Composition API лучше выводит типы и не зависит от `this`. Options API поддерживается и встречается в легаси, оба стиля можно смешивать в одном проекте. Подробно — в [Composition API](/content/vuejs/composition-api).
::

## Практика

::practice{title="Сколько раз перерисуется?"}
В корзине поле поиска и значок с количеством. Что будет перерисовано при вводе в поле и при вызове `add()`?

```vue
<script setup>
import { ref } from 'vue';
import Badge from './Badge.vue';   // <span>{{ count }}</span>, пропс count

const items = ref([]);
const query = ref('');

function add() {
  items.value.push('чай');
  items.value.push('кофе');
}
</script>

<template>
  <input v-model="query">
  <Badge :count="items.length" />
</template>
```

#solution
- **Ввод в поле** меняет `query`. Его читает шаблон корзины, поэтому корзина перерисуется. `Badge` — нет: его проп `count` остался прежним.
- **`add()`** делает два `push`. Изменения складываются, и корзина перерисуется один раз. Новый `items.length` изменил проп `Badge`, поэтому он тоже перерисуется — тоже один раз.

```text
ввод в поле:  Cart
add():        Badge, Cart     ← по одному разу, хотя push было два
```

Это и есть точечное обновление: родитель не тянет за собой ребёнка, если пропсы ребёнка не изменились. В проверке хуки `onUpdated` записали `['cart']` после ввода и `['cart', 'badge', 'cart']` после `add()`, а значок показал `2`.
::

::practice{title="Почему стиль не применился?"}
Родитель пытается покрасить заголовок внутри дочерней карточки, но стиль не действует:

```vue
<!-- Page.vue -->
<template>
  <div class="card"><ProductTitle /></div>   <!-- внутри: <div><h3 class="title">…</h3></div> -->
</template>

<style scoped>
.card .title { color: red; }
</style>
```

#solution
`scoped` переписывает селектор в `.card .title[data-v-родителя]`. Атрибут родителя получает только корневой элемент `ProductTitle`, а `h3` внутри него помечен атрибутом самого `ProductTitle`. Селектор не совпадает.

```css
.card :deep(.title) { color: red; }
/* → .card[data-v-родителя] .title */
```

`:deep()` переносит атрибут на левую часть селектора, и правило начинает действовать на потомков. Но это вмешательство во внутренности чужого компонента: лучше, если `ProductTitle` сам принимает цвет через проп, класс или CSS-переменную. В проверке атрибут родителя оказался на корне ребёнка, а на `h3` — нет; компилятор стилей выдал оба варианта селектора ровно в таком виде.
::
