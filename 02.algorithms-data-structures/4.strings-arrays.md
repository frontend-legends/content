# Строки и массивы

С задач на массивы и строки начинается почти любое алгоритмическое собеседование. Отдельного алгоритма за ними нет — проверяют, видит ли кандидат линейное решение там, где напрашивается квадратичное, и умеет ли менять массив на месте без лишней памяти. Решения держатся на нескольких приёмах: запись на месте указателем, проход с конца, два прохода — слева и справа, жадный выбор с доказательством и аккуратная работа с индексами строк. Здесь 24 задачи первого блока LeetCode Top Interview 150.

::tldr
- **Изменение на месте — указатель записи:** читаем все элементы, а подходящие переписываем на позицию `k`. Так удаляют элементы и дубликаты за O(n) и O(1) памяти.
- **Если впереди нет места, заполняют с конца:** слияние в массив со свободным хвостом не затирает непрочитанные элементы.
- **Два прохода — слева направо и справа налево — заменяют вложенный цикл:** произведение без текущего, вода между столбиками, конфеты по рейтингу.
- **Жадный выбор работает, если его можно обосновать:** прыжки, заправки, акции с неограниченным числом сделок. Без обоснования жадность — частая ошибка.
- **Строки в JavaScript неизменяемы:** склейка в цикле создаёт новые строки, поэтому для длинных результатов собирают массив и делают `join`.
::

## Как узнать паттерн

- **«На месте», «O(1) дополнительной памяти»** — указатель записи, развороты, обмены.
- **Ответ для каждого элемента зависит от всех слева и справа** — префиксы и суффиксы.
- **Нужна одна величина за один проход** — минимум до текущего дня, самый дальний прыжок, накопленный бензин.
- **Строки** — разбор символов, таблицы соответствий, поиск подстроки.

Если в задаче два указателя идут навстречу или с разной скоростью — это [Два указателя](/content/algorithms-data-structures/two-pointers); если отрезок растёт и сжимается — [Скользящее окно](/content/algorithms-data-structures/sliding-window); если нужен подсчёт или поиск пары — [Хеш-таблицы](/content/algorithms-data-structures/hashmap). Как массивы и строки устроены в памяти — в [Структурах данных](/content/algorithms-data-structures/data-structures).

## Шаблоны

**Запись :term[на месте]{def="без второго массива: результат пишется в тот же массив, дополнительной памяти O(1)"} указателем.** Читаем всё подряд, а нужные элементы переписываем на позицию `k`; в конце `nums[0..k)` — результат. Условию можно смотреть на уже записанное:

```ts
function keepIf(nums: number[], keep: (x: number, written: number) => boolean): number {
  let k = 0;                                      // сколько элементов уже записано
  for (const x of nums) {
    if (keep(x, k)) nums[k++] = x;                // переписать на место k
  }
  return k;                                       // nums[0..k) — результат
}
```

**Два прохода.** Когда ответ для позиции зависит от всего слева и всего справа, один проход собирает информацию слева, второй — справа:

```ts
function maxToLeftAndRight(nums: number[]): [number[], number[]] {
  const n = nums.length;
  const left = new Array(n);                      // left[i] — максимум nums[0..i]
  const right = new Array(n);                     // right[i] — максимум nums[i..n)
  for (let i = 0; i < n; i++) left[i] = Math.max(nums[i], i > 0 ? left[i - 1] : -Infinity);
  for (let i = n - 1; i >= 0; i--) right[i] = Math.max(nums[i], i < n - 1 ? right[i + 1] : -Infinity);
  return [left, right];
}
```

Оба — O(n). Запись на месте не выделяет память; два прохода тратят O(n) на массивы, но часто их сворачивают в переменные — как в задачах 238 и 42 ниже.

::practice{title="88. Merge Sorted Array"}
Отсортированные массивы `nums1` (первые `m` элементов, дальше `n` нулей-заглушек) и `nums2` длины `n`. Слить `nums2` в `nums1` на месте. Пример: `[1, 2, 3, 0, 0, 0], 3` и `[2, 5, 6], 3` → `[1, 2, 2, 3, 5, 6]`. [Задача на LeetCode](https://leetcode.com/problems/merge-sorted-array/)

#solution
Слияние с начала затёрло бы ещё не прочитанные элементы `nums1`. Свободное место — в конце, поэтому заполняем с конца, выбирая больший из двух хвостов:

```ts
function merge(nums1: number[], m: number, nums2: number[], n: number): void {
  let i = m - 1;
  let j = n - 1;
  for (let k = m + n - 1; j >= 0; k--) {         // заполнять с конца — там свободное место
    nums1[k] = i >= 0 && nums1[i] > nums2[j] ? nums1[i--] : nums2[j--];
  }
}
```

O(m + n), O(1). Цикл идёт, пока не кончился `nums2`: оставшиеся элементы `nums1` уже на своих местах. «Скопировать и отсортировать» — O((m + n) log(m + n)); искать заглушки по значению 0 нельзя — нули бывают и настоящими. В проверке результат совпал с сортировкой объединения.
::

::practice{title="27. Remove Element"}
Удалить на месте все вхождения `val` и вернуть число оставшихся `k`; первые `k` элементов — оставшиеся, порядок не важен. Пример: `[3, 2, 2, 3], 3` → 2, `[2, 2]`. [Задача на LeetCode](https://leetcode.com/problems/remove-element/)

#solution
Указатель записи из шаблона:

```ts
function removeElement(nums: number[], val: number): number {
  return keepIf(nums, (x) => x !== val);
}
```

O(n), O(1). `splice` в цикле — O(n) на каждое удаление и O(n²) в сумме, плюс сдвиг индексов при обходе. Раз порядок не важен, можно переставлять удаляемый элемент с последним и укорачивать массив — меньше записей, когда удаляемых мало.
::

::practice{title="26. Remove Duplicates from Sorted Array"}
В отсортированном массиве оставить на месте по одному экземпляру каждого значения и вернуть их число. Пример: `[0, 0, 1, 1, 1, 2, 2, 3, 3, 4]` → 5, `[0, 1, 2, 3, 4]`. [Задача на LeetCode](https://leetcode.com/problems/remove-duplicates-from-sorted-array/)

#solution
В отсортированном массиве дубликаты стоят подряд — элемент новый, если отличается от последнего записанного:

```ts
function removeDuplicates(nums: number[]): number {
  return keepIf(nums, (x, k) => k < 1 || x !== nums[k - 1]);
}
```

O(n), O(1). Сравнивать с записанным, а не с предыдущим прочитанным: в общем виде (следующая задача) это важно. `[...new Set(nums)]` даёт тот же результат, но не на месте.
::

::practice{title="80. Remove Duplicates from Sorted Array II"}
То же, но каждое значение может остаться до двух раз. Пример: `[0, 0, 1, 1, 1, 1, 2, 3, 3]` → 7, `[0, 0, 1, 1, 2, 3, 3]`. [Задача на LeetCode](https://leetcode.com/problems/remove-duplicates-from-sorted-array-ii/)

#solution
Элемент лишний, если совпадает с записанным два шага назад: тогда между ними уже два таких значения:

```ts
function removeDuplicatesII(nums: number[]): number {
  return keepIf(nums, (x, k) => k < 2 || x !== nums[k - 2]);   // третий подряд совпадёт с записанным два шага назад
}
```

O(n), O(1). Для «до t раз» — `nums[k - t]`. Сравнение с прочитанным `nums[i - 2]` ошибочно: эту позицию уже могли перезаписать. В проверке ни одно значение не осталось больше двух раз, а результат совпал с фильтром по отсортированному массиву.
::

::practice{title="169. Majority Element"}
Найти элемент, который встречается больше `n / 2` раз (он гарантированно есть). Продолжение: O(n) времени и O(1) памяти. Пример: `[2, 2, 1, 1, 1, 2, 2]` → 2. [Задача на LeetCode](https://leetcode.com/problems/majority-element/)

#solution
Подсчёт в `Map` — O(n) памяти. Голосование Бойера — Мура: если вычёркивать пары разных элементов, элемент большинства останется — его больше, чем всех остальных вместе. Счётчик — сколько невычеркнутых копий кандидата:

```ts
function majorityElement(nums: number[]): number {
  let candidate = nums[0];
  let count = 0;
  for (const x of nums) {
    if (count === 0) candidate = x;               // пары «кандидат — другой» взаимно вычеркнулись
    count += x === candidate ? 1 : -1;
  }
  return candidate;
}
```

O(n), O(1). Если большинство не гарантировано, нужен второй проход — проверить, что кандидат действительно встречается больше `n / 2` раз. Сортировка и средний элемент — O(n log n). В проверке кандидат всегда оказывался большинством на перемешанных массивах.
::

::practice{title="189. Rotate Array"}
Сдвинуть массив вправо на `k` шагов на месте. Пример: `[1, 2, 3, 4, 5, 6, 7], 3` → `[5, 6, 7, 1, 2, 3, 4]`. [Задача на LeetCode](https://leetcode.com/problems/rotate-array/)

#solution
Сдвиг вправо на k — это «последние k элементов, потом остальные». Разворот всего массива ставит их в начало, но в обратном порядке; ещё два разворота восстанавливают порядок внутри частей:

```ts
function rotate(nums: number[], k: number): void {
  const n = nums.length;
  k %= n;
  const reverse = (lo: number, hi: number) => {
    for (; lo < hi; lo++, hi--) [nums[lo], nums[hi]] = [nums[hi], nums[lo]];
  };
  reverse(0, n - 1);                              // 1 2 3 4 5 → 5 4 3 2 1
  reverse(0, k - 1);                              // k = 2: 4 5 | 3 2 1
  reverse(k, n - 1);                              //        4 5 | 1 2 3
}
```

O(n), O(1). `k %= n` обязателен — k может быть больше длины. Копия массива с `nums[(i + k) % n]` — O(n) памяти; `unshift(pop())` k раз — O(n · k). В проверке результат совпал с формулой индексов для k до 25.
::

::practice{title="121. Best Time to Buy and Sell Stock"}
Цены акции по дням; одна покупка и одна продажа позже. Найти наибольшую прибыль или 0. Пример: `[7, 1, 5, 3, 6, 4]` → 5. [Задача на LeetCode](https://leetcode.com/problems/best-time-to-buy-and-sell-stock/)

#solution
Если продавать сегодня, покупать нужно по минимальной цене до сегодняшнего дня. Минимум и лучший ответ обновляются за один проход:

```ts
function maxProfitOnce(prices: number[]): number {
  let minPrice = Infinity;
  let best = 0;
  for (const p of prices) {
    minPrice = Math.min(minPrice, p);             // лучшая покупка до сегодняшнего дня
    best = Math.max(best, p - minPrice);          // продать сегодня
  }
  return best;
}
```

O(n), O(1) вместо перебора пар за O(n²). Ошибка — взять глобальные минимум и максимум: минимум может стоять после максимума. Если записать разности соседних цен, задача становится максимальной суммой подмассива ([Алгоритм Кадане](/content/algorithms-data-structures/kadanes-algorithm)).
::

::practice{title="122. Best Time to Buy and Sell Stock II"}
То же, но сделок сколько угодно (держать можно одну акцию за раз). Пример: `[7, 1, 5, 3, 6, 4]` → 7 (1 → 5 и 3 → 6). [Задача на LeetCode](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-ii/)

#solution
Любой подъём цены можно забрать: купить вчера, продать сегодня. Длинный подъём — сумма дневных подъёмов, поэтому ответ — сумма всех положительных разностей:

```ts
function maxProfitMany(prices: number[]): number {
  let profit = 0;
  for (let i = 1; i < prices.length; i++) profit += Math.max(0, prices[i] - prices[i - 1]);   // каждый подъём
  return profit;
}
```

O(n), O(1). Это не значит, что торговать надо каждый день, — сумма та же, что у сделок «от дна до пика». Общее решение — DP с состояниями «держим акцию» и «не держим»; оно же решает варианты с комиссией, паузой и ограничением числа сделок ([Многомерное DP](/content/algorithms-data-structures/multidimensional-dp)). В проверке ответ совпал с перебором таких состояний.
::

::practice{title="55. Jump Game"}
`nums[i]` — наибольшая длина прыжка из позиции `i`. Можно ли из начала добраться до последнего индекса? Пример: `[2, 3, 1, 1, 4]` — да; `[3, 2, 1, 0, 4]` — нет. [Задача на LeetCode](https://leetcode.com/problems/jump-game/)

#solution
Достижимые позиции образуют отрезок от 0 до `farthest`: если достижима позиция `i`, достижимы и все до неё. Идём слева и расширяем отрезок; если `i` вышел за него — дальше не попасть:

```ts
function canJump(nums: number[]): boolean {
  let farthest = 0;
  for (let i = 0; i < nums.length; i++) {
    if (i > farthest) return false;               // до i не допрыгнуть
    farthest = Math.max(farthest, i + nums[i]);
  }
  return true;
}
```

O(n), O(1). DP по позициям — O(n²) в худшем случае; перебор прыжков рекурсией — экспоненциально. В проверке ответ совпал с DP по числу прыжков.
::

::practice{title="45. Jump Game II"}
Найти наименьшее число прыжков до последнего индекса (он гарантированно достижим). Пример: `[2, 3, 1, 1, 4]` → 2. [Задача на LeetCode](https://leetcode.com/problems/jump-game-ii/)

#solution
Это обход в ширину без очереди: позиции, достижимые за `jumps` прыжков, — отрезок до `end`. Проходя его, считаем `farthest` — границу для следующего прыжка. Дошли до `end` — уровень кончился, прыжок нужен:

```ts
function jump(nums: number[]): number {
  let jumps = 0;
  let end = 0;                                    // граница достижимого за jumps прыжков
  let farthest = 0;                               // граница за jumps + 1
  for (let i = 0; i < nums.length - 1; i++) {
    farthest = Math.max(farthest, i + nums[i]);
    if (i === end) {                              // уровень пройден — нужен ещё прыжок
      jumps++;
      end = farthest;
    }
  }
  return jumps;
}
```

O(n), O(1). Цикл до `length - 1`: если дойти до последнего индекса, лишний прыжок посчитается, когда он совпадёт с `end`. Жадное «прыгать как можно дальше» неверно — прыгать нужно туда, откуда дальше всего следующий прыжок. В проверке ответ совпал с DP.
::

::practice{title="274. H-Index"}
`citations[i]` — цитирования i-й статьи. Индекс Хирша — наибольшее h, при котором есть h статей, процитированных не меньше h раз. Пример: `[3, 0, 6, 1, 5]` → 3. [Задача на LeetCode](https://leetcode.com/problems/h-index/)

#solution
С сортировкой по убыванию ответ — наибольшее i, при котором `sorted[i - 1] >= i`, это O(n log n). Быстрее: h не больше числа статей n, поэтому цитирования больше n можно считать равными n и разложить по корзинам. Идём от n вниз, накапливая число статей с не меньше чем h цитированиями:

```ts
function hIndex(citations: number[]): number {
  const n = citations.length;
  const count = new Array(n + 1).fill(0);         // count[c] — статей с c цитированиями (больше n — в n)
  for (const c of citations) count[Math.min(c, n)]++;
  let atLeast = 0;
  for (let h = n; h >= 0; h--) {
    atLeast += count[h];                          // статей с не меньше чем h цитированиями
    if (atLeast >= h) return h;
  }
  return 0;
}
```

O(n) по времени и памяти — сортировка подсчётом с отсечкой. В проверке ответ совпал с перебором всех h.
::

::practice{title="380. Insert Delete GetRandom O(1)"}
Множество с `insert`, `remove` и `getRandom` (равновероятный элемент), все — O(1) в среднем. [Задача на LeetCode](https://leetcode.com/problems/insert-delete-getrandom-o1/)

#solution
`Set` умеет вставку и удаление, но не случайный доступ — пришлось бы обходить его за O(n). Массив даёт случайный элемент по индексу, но удаление из середины — O(n). Вместе: значения в массиве, их позиции в `Map`, а удаление — обмен с последним и `pop`:

```ts
class RandomizedSet {
  private values: number[] = [];
  private index = new Map<number, number>();      // значение → позиция в values

  insert(val: number): boolean {
    if (this.index.has(val)) return false;
    this.index.set(val, this.values.length);
    this.values.push(val);
    return true;
  }

  remove(val: number): boolean {
    const i = this.index.get(val);
    if (i === undefined) return false;
    const last = this.values.pop()!;
    if (last !== val) {                           // поставить последний на место удалённого
      this.values[i] = last;
      this.index.set(last, i);
    }
    this.index.delete(val);
    return true;
  }

  getRandom(): number {
    return this.values[Math.floor(Math.random() * this.values.length)];
  }
}
```

Все операции O(1) в среднем. Порядок важен: если сначала удалить запись `val` из `Map`, а последний элемент и есть `val`, он запишется обратно. Проверка `i === undefined`, а не `!i`, — позиция 0 ложна. В проверке операции совпали с эталонным `Set`, а на 30 000 вызовах три значения выпали примерно поровну.

::practice{title="238. Product of Array Except Self"}
Вернуть массив, где `answer[i]` — произведение всех элементов, кроме `nums[i]`, без деления и за O(n). Продолжение: O(1) памяти кроме ответа. Пример: `[1, 2, 3, 4]` → `[24, 12, 8, 6]`. [Задача на LeetCode](https://leetcode.com/problems/product-of-array-except-self/)

#solution
Произведение без `nums[i]` — произведение всего слева на произведение всего справа. Первый проход пишет в ответ префиксы, второй домножает на суффиксы, которые держатся в одной переменной:

```ts
function productExceptSelf(nums: number[]): number[] {
  const n = nums.length;
  const result = new Array(n).fill(1);
  let prefix = 1;
  for (let i = 0; i < n; i++) {
    result[i] = prefix;                           // произведение всего слева
    prefix *= nums[i];
  }
  let suffix = 1;
  for (let i = n - 1; i >= 0; i--) {
    result[i] *= suffix;                          // умножить на всё справа
    suffix *= nums[i];
  }
  return result;
}
```

O(n), O(1) кроме ответа. Деление общего произведения запрещено условием и ломается на нулях: при одном нуле ненулевой ответ только у него, при двух — все нули. В JavaScript произведение с отрицательными числами и нулём даёт `-0`; при сравнении через `Object.is` или `deepStrictEqual` это отличается от `0`.

::practice{title="134. Gas Station"}
Заправки по кругу: на станции `i` можно залить `gas[i]`, путь до следующей стоит `cost[i]`. С какой станции можно проехать полный круг с пустым баком в начале? Ответ единственный или −1. Пример: `gas = [1, 2, 3, 4, 5]`, `cost = [3, 4, 5, 1, 2]` → 3. [Задача на LeetCode](https://leetcode.com/problems/gas-station/)

#solution
Два факта. Если бензина всего меньше, чем расходов, круг невозможен. Если, выехав из `start`, мы не доехали до `i + 1`, то ни одна станция между `start` и `i` тоже не годится: к каждой из них мы приезжали с неотрицательным баком, а начать там с пустым — только хуже. Поэтому старт сразу переносится за `i`:

```ts
function canCompleteCircuit(gas: number[], cost: number[]): number {
  let total = 0;
  let tank = 0;
  let start = 0;
  for (let i = 0; i < gas.length; i++) {
    const diff = gas[i] - cost[i];
    total += diff;
    tank += diff;
    if (tank < 0) {                               // от start до i не доехать — и ни от какой станции между
      start = i + 1;
      tank = 0;
    }
  }
  return total >= 0 ? start : -1;
}
```

O(n), O(1) вместо проверки каждого старта за O(n²). Если `total >= 0`, найденный старт доезжает: остаток пути до `start` покрывается суммарным запасом. В проверке найденный старт всегда проходил круг, а −1 выдавался только когда не годился ни один.

::practice{title="135. Candy"}
Дети в ряд с рейтингами. Каждому — хотя бы одна конфета, а ребёнок с большим рейтингом, чем у соседа, получает больше этого соседа. Найти минимум конфет. Пример: `[1, 0, 2]` → 5; `[1, 2, 2]` → 4. [Задача на LeetCode](https://leetcode.com/problems/candy/)

#solution
Правило с левым соседом выполняет проход слева направо, с правым — справа налево. Во втором проходе берётся максимум, чтобы не сломать выполненное первым:

```ts
function candy(ratings: number[]): number {
  const n = ratings.length;
  const candies = new Array(n).fill(1);
  for (let i = 1; i < n; i++) {
    if (ratings[i] > ratings[i - 1]) candies[i] = candies[i - 1] + 1;   // правило с левым соседом
  }
  for (let i = n - 2; i >= 0; i--) {
    if (ratings[i] > ratings[i + 1]) candies[i] = Math.max(candies[i], candies[i + 1] + 1);   // с правым
  }
  return candies.reduce((a, b) => a + b, 0);
}
```

O(n), O(n). Равные рейтинги ничего не требуют — во втором примере третий ребёнок получает одну конфету. Наивный способ — повторять проходы, пока правила нарушены, — O(n²); в проверке ответ совпал с ним. Есть решение за O(1) памяти через подсчёт длин возрастающих и убывающих участков, но оно сложнее.

::practice{title="42. Trapping Rain Water"}
Высоты столбиков ширины 1. Сколько воды задержится после дождя? Пример: `[0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]` → 6. [Задача на LeetCode](https://leetcode.com/problems/trapping-rain-water/)

#solution
Над столбиком `i` стоит `min(максимум слева, максимум справа) − height[i]` воды. Два прохода из шаблона дают ответ за O(n) памяти. Без массивов: два указателя с краёв. Если левый столбик ниже правого, то справа точно есть стена не ниже, и уровень над левым определяет только `leftMax` — его можно посчитать и сдвинуться:

```ts
function trap(height: number[]): number {
  let lo = 0;
  let hi = height.length - 1;
  let leftMax = 0;
  let rightMax = 0;
  let water = 0;
  while (lo < hi) {
    if (height[lo] < height[hi]) {                // справа есть стена выше — уровень задаёт leftMax
      leftMax = Math.max(leftMax, height[lo]);
      water += leftMax - height[lo++];
    } else {
      rightMax = Math.max(rightMax, height[hi]);
      water += rightMax - height[hi--];
    }
  }
  return water;
}
```

O(n), O(1). Третий вариант — монотонный стек: считает воду слоями по горизонтали ([Стек](/content/algorithms-data-structures/stack)). В проверке ответ совпал с формулой через массивы максимумов слева и справа.
::

::practice{title="13. Roman to Integer"}
Перевести римское число (1–3999) в целое. Пример: `"LVIII"` → 58; `"MCMXCIV"` → 1994. [Задача на LeetCode](https://leetcode.com/problems/roman-to-integer/)

#solution
Обычно символы складываются, но если меньший стоит перед большим (`IV`, `XC`, `CM`), он вычитается. Проверять шесть особых пар не нужно — достаточно сравнить символ со следующим:

```ts
function romanToInt(s: string): number {
  const value: Record<string, number> = { I: 1, V: 5, X: 10, L: 50, C: 100, D: 500, M: 1000 };
  let total = 0;
  for (let i = 0; i < s.length; i++) {
    const v = value[s[i]];
    total += i + 1 < s.length && v < value[s[i + 1]] ? -v : v;   // меньший перед большим вычитается
  }
  return total;
}
```

O(n), O(1).

::practice{title="12. Integer to Roman"}
Перевести целое от 1 до 3999 в римское число. Пример: 1994 → `"MCMXCIV"`; 3749 → `"MMMDCCXLIX"`. [Задача на LeetCode](https://leetcode.com/problems/integer-to-roman/)

#solution
Если добавить вычитательные пары в таблицу как отдельные «цифры», задача становится жадным разменом: каждый раз берём наибольшее значение, которое помещается:

```ts
function intToRoman(num: number): string {
  const table: [number, string][] = [
    [1000, 'M'], [900, 'CM'], [500, 'D'], [400, 'CD'], [100, 'C'], [90, 'XC'],
    [50, 'L'], [40, 'XL'], [10, 'X'], [9, 'IX'], [5, 'V'], [4, 'IV'], [1, 'I'],
  ];
  let result = '';
  for (const [value, symbol] of table) {
    for (; num >= value; num -= value) result += symbol;   // жадно: самое крупное, что помещается
  }
  return result;
}
```

O(1): диапазон ограничен, итераций не больше 15. Жадность здесь верна, потому что таблица устроена как «каноническая система монет». В проверке для всех чисел от 1 до 3999 перевод туда и обратно дал исходное число, записи были различны и без `IIII`, `VV` и подобных.

::practice{title="58. Length of Last Word"}
Длина последнего слова в строке из букв и пробелов. Пример: `"   fly me   to   the moon  "` → 4. [Задача на LeetCode](https://leetcode.com/problems/length-of-last-word/)

#solution
С конца: пропустить пробелы, потом считать символы до пробела или начала строки:

```ts
function lengthOfLastWord(s: string): number {
  let i = s.length - 1;
  while (i >= 0 && s[i] === ' ') i--;             // пропустить пробелы в конце
  let length = 0;
  for (; i >= 0 && s[i] !== ' '; i--) length++;
  return length;
}
```

O(длины хвоста), O(1). `s.trim().split(' ').at(-1).length` тоже верно, но проходит и копирует всю строку. Ловушка — пробелы в конце.

::practice{title="14. Longest Common Prefix"}
Найти самый длинный общий префикс массива строк. Пример: `["flower", "flow", "flight"]` → `"fl"`; `["dog", "racecar", "car"]` → `""`. [Задача на LeetCode](https://leetcode.com/problems/longest-common-prefix/)

#solution
Сравнение по столбцам: берём i-й символ первой строки и проверяем его во всех; при первом расхождении или конце строки — ответ найден:

```ts
function longestCommonPrefix(strs: string[]): string {
  for (let i = 0; i < strs[0].length; i++) {
    const ch = strs[0][i];
    if (strs.some((s) => s[i] !== ch)) return strs[0].slice(0, i);   // столбец i разошёлся
  }
  return strs[0];
}
```

O(S), где S — сумма длин, а на практике меньше: остановка на первом расхождении. Выход за конец короткой строки даёт `undefined`, и сравнение само его ловит. Другой способ — отсортировать строки и сравнить первую с последней: они различаются сильнее всех, но сортировка — O(S log n). Для многих запросов к одному набору — префиксное дерево ([Префиксное дерево](/content/algorithms-data-structures/trie)).

function reverseWords(s: string): string {

::practice{title="6. Zigzag Conversion"}
Записать строку зигзагом в `numRows` рядов (вниз по столбцу, потом по диагонали вверх) и прочитать построчно. Пример: `"PAYPALISHIRING", 3` → `"PAHNAPLSIIGYIR"`. [Задача на LeetCode](https://leetcode.com/problems/zigzag-conversion/)

#solution
Моделируем запись: держим текущий ряд и направление, отражаясь от верхнего и нижнего ряда. Каждый ряд копит свою строку:

```ts
function convert(s: string, numRows: number): string {
  if (numRows === 1) return s;
  const rows: string[] = new Array(Math.min(numRows, s.length)).fill('');
  let row = 0;
  let step = 1;
  for (const ch of s) {
    rows[row] += ch;
    if (row === 0) step = 1;                      // отразиться от верхнего ряда
    else if (row === numRows - 1) step = -1;      // и от нижнего
    row += step;
  }
  return rows.join('');
}
```

O(n). При одном ряде направление не определено — отдельный случай. Без моделирования ряд символа считают формулой: период зигзага `2 · (numRows − 1)`, и ряд символа `i` — `min(i mod период, период − i mod период)`. В проверке результат совпал с этой формулой.

::practice{title="28. Find the Index of the First Occurrence in a String"}
Найти индекс первого вхождения `needle` в `haystack`, или −1. Пример: `"sadbutsad", "sad"` → 0; `"leetcode", "leeto"` → −1. [Задача на LeetCode](https://leetcode.com/problems/find-the-index-of-the-first-occurrence-in-a-string/)

#solution
`haystack.indexOf(needle)` — правильный ответ в работе, но на собеседовании просят алгоритм. Наивное сравнение с каждой позиции — O(n · m) в худшем случае, например на `"aaaa…ab"`. Алгоритм Кнута — Морриса — Пратта (KMP) не откатывает указатель в тексте: при несовпадении образец сдвигается на длину уже совпавшего префикса, который одновременно его суффикс. Эти длины заранее считаются в таблице `lps`:

```ts
function strStr(haystack: string, needle: string): number {
  // lps[i] — длина наибольшего собственного префикса needle[0..i], который одновременно суффикс
  const lps = new Array(needle.length).fill(0);
  for (let i = 1, len = 0; i < needle.length; ) {
    if (needle[i] === needle[len]) lps[i++] = ++len;
    else if (len > 0) len = lps[len - 1];
    else lps[i++] = 0;
  }
  for (let i = 0, j = 0; i < haystack.length; ) {
    if (haystack[i] === needle[j]) {
      i++;
      j++;
      if (j === needle.length) return i - j;
    } else if (j > 0) {
      j = lps[j - 1];                             // не откатывать i: совпавший префикс уже известен
    } else {
      i++;
    }
  }
  return needle.length === 0 ? 0 : -1;
}
```

O(n + m), O(m). Для `"aabaaac"` таблица — `[0, 1, 0, 1, 2, 2, 0]`: после несовпадения на последнем символе образец сдвигается так, что совпавшие `"aa"` в тексте становятся его началом. Другие подходы — Рабин — Карп с кольцевым хешем и Бойер — Мур, который на практике часто быстрее. В проверке результат совпал с `indexOf` на двух тысячах пар.
::

::practice{title="68. Text Justification"}
Разбить слова на строки ширины `maxWidth` с выравниванием по ширине: в строку жадно помещаем максимум слов, пробелы распределяем поровну, лишние — в левые промежутки. Строка из одного слова и последняя строка — по левому краю, дополненные пробелами. [Задача на LeetCode](https://leetcode.com/problems/text-justification/)

#solution
Сначала набираем слова в строку, пока помещаются с минимальным пробелом между ними. Потом распределяем свободные `maxWidth − длина слов` пробелов по промежуткам: каждому поровну, а остаток от деления — по одному в первые промежутки:

```ts
function fullJustify(words: string[], maxWidth: number): string[] {
  const lines: string[] = [];
  let i = 0;
  while (i < words.length) {
    let j = i;
    let width = 0;                                // длина слов без пробелов
    while (j < words.length && width + words[j].length + (j - i) <= maxWidth) width += words[j++].length;
    const gaps = j - i - 1;
    if (j === words.length || gaps === 0) {       // последняя строка или одно слово — влево
      const line = words.slice(i, j).join(' ');
      lines.push(line + ' '.repeat(maxWidth - line.length));
    } else {
      const spaces = maxWidth - width;
      const base = Math.floor(spaces / gaps);
      const extra = spaces % gaps;                // лишние пробелы — в левые промежутки
      let line = words[i];
      for (let g = 1; g <= gaps; g++) line += ' '.repeat(base + (g <= extra ? 1 : 0)) + words[i + g];
      lines.push(line);
    }
    i = j;
  }
  return lines;
}
```

O(L) по суммарной длине результата. Сложность задачи — не в алгоритме, а в трёх особых случаях: одно слово в строке (деление на ноль промежутков), последняя строка и распределение остатка. Пример: слова `This is an example of text justification.` при ширине 16 дают `"This    is    an"`, `"example  of text"`, `"justification.  "`. В проверке на случайных входах все строки имели нужную ширину, слова шли в исходном порядке, а промежутки отличались не больше чем на один и не возрастали слева направо.

## Красные флаги в ответе

- **`splice` или `shift` в цикле** для удаления на месте — O(n²).
- **Слияние в `nums1` с начала** — затирает непрочитанные элементы.
- **Глобальный минимум и максимум в задаче про акции** — минимум может быть позже максимума.
- **Деление в «произведении без себя»** — запрещено и ломается на нулях.
- **Жадность без обоснования** — «прыгать как можно дальше» в Jump Game II.
- **Склейка длинной строки `+=` в цикле на миллионы символов** без мысли о стоимости и альтернативе `join`.

## Как спрашивают на собеседовании

::question
Как удалить элементы из массива на месте за O(n)?

#answer
Указателем записи: идём по массиву, а каждый нужный элемент переписываем на позицию `k` и увеличиваем `k`. В конце первые `k` элементов — результат, остальное можно отрезать `length = k`. Одна запись на элемент, O(n) по времени и O(1) по памяти.

#more
`splice` в цикле сдвигает хвост при каждом удалении — O(n²). `filter` проще и быстр, но создаёт новый массив. Указатель записи с условием «сравнить с записанным `k − t` назад» удаляет дубликаты сверх t в отсортированном массиве. Если порядок не важен, удаляемый элемент меняют с последним и укорачивают массив.
::

::question
Как найти элемент большинства за O(1) памяти?

#answer
Голосованием Бойера — Мура: держим кандидата и счётчик; совпадение увеличивает счётчик, несовпадение уменьшает, при нуле кандидат меняется на текущий элемент. Элемент, которого больше половины, переживает все взаимные вычёркивания пар. O(n) по времени, O(1) по памяти.

#more
Если большинство не гарантировано, кандидата проверяют вторым проходом. Обобщение — элементы, встречающиеся больше `n / k` раз: держат k − 1 кандидатов со счётчиками (алгоритм Мисры — Гриса), его используют для поиска частых элементов в потоках.
::

::question
Как посчитать воду между столбиками?

#answer
Над столбиком стоит `min(максимум слева, максимум справа) − его высота`. Максимумы слева и справа считают двумя проходами — O(n) времени и памяти. Без массивов — двумя указателями с краёв: двигаем тот, что ниже, потому что уровень над ним уже определён его стороной, и держим `leftMax` и `rightMax`. O(n), O(1).

#more
Монотонный стек считает воду слоями: при встрече столбика выше вершины стека вода заполняет «яму» между ним и предыдущим. Двумерный вариант (407) решают кучей, начиная с границы и поднимаясь от самой низкой клетки.
::

::question
Как найти подстроку быстрее, чем за O(n · m)?

#answer
Алгоритмом Кнута — Морриса — Пратта: заранее для каждого префикса образца считают длину наибольшего собственного префикса, совпадающего с суффиксом. При несовпадении указатель в тексте не откатывается, а образец сдвигается по этой таблице. O(n + m).

#more
Рабин — Карп сравнивает кольцевые хеши окон — удобен для поиска многих образцов одной длины и обнаружения плагиата. Бойер — Мур сравнивает с конца образца и умеет прыгать на длину образца — на практике часто быстрее. Встроенные `indexOf` и `includes` в движках оптимизированы и для работы предпочтительнее самописного кода.
