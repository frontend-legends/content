# Графы

Граф — вершины и рёбра между ними: клетки поля, курсы с зависимостями, переменные, связанные отношениями, модули с импортами. Задача на граф часто прячется за другой формулировкой, и половина решения — увидеть граф и выбрать представление. Дальше почти всё делают два обхода — в глубину и в ширину — и топологическая сортировка для зависимостей. Спрашивают острова на карте, захват областей, копирование графа, вычисление отношений по цепочке и расписание курсов с проверкой циклов.

::tldr
- **Сначала — увидеть граф и представить его:** список смежности для разреженных графов, неявный граф для поля (соседи — четыре клетки) или словаря.
- **Обход отмечает вершины посещёнными, иначе зациклится.** Отмечать нужно при добавлении в стек или очередь, а не при снятии, — иначе вершина попадёт туда много раз.
- **Связные компоненты считают запуском обхода из каждой непосещённой вершины;** заливка на поле — то же самое.
- **Зависимости — ориентированный граф, порядок выполнения — топологическая сортировка.** Алгоритм Кана заодно находит цикл: если вершины остались, выполнить всё нельзя.
- **Рекурсивный обход на большом поле переполнит стек** — для сеток в тысячи клеток берут явный стек или очередь.
::

## Как узнать паттерн

- Есть **связи** между объектами: «соседние клетки», «курс требует курс», «a / b = 2», «друзья друзей».
- Нужны **компоненты**: острова, группы, области, связана ли пара.
- Нужен **порядок с зависимостями** или проверка, что зависимости **не циклические**.
- Нужно **скопировать** структуру со ссылками, где возможны циклы.
- Нужен **кратчайший путь** без весов — это обход в ширину ([Графы: BFS](/content/algorithms-data-structures/graph-bfs)).

Графы, их представления и виды — в [Структурах данных](/content/algorithms-data-structures/data-structures), основы теории графов и топологическая сортировка — в [Математике для CS](/content/computer-science/math-for-cs).

## Шаблон

**Список смежности** из списка рёбер:

```ts
function buildGraph(n: number, edges: [number, number][]): number[][] {
  const graph: number[][] = Array.from({ length: n }, () => []);
  for (const [a, b] of edges) {
    graph[a].push(b);
    graph[b].push(a);                             // неориентированный: ребро в обе стороны
  }
  return graph;
}
```

**Обход в глубину и связные компоненты:**

```ts
function countComponents(graph: number[][]): number {
  const seen = new Array(graph.length).fill(false);
  const dfs = (v: number): void => {
    seen[v] = true;
    for (const u of graph[v]) if (!seen[u]) dfs(u);
  };
  let components = 0;
  for (let v = 0; v < graph.length; v++) {
    if (!seen[v]) {
      components++;
      dfs(v);
    }
  }
  return components;
}
```

Обход — O(V + E): каждая вершина посещается раз, каждое ребро просматривается раз (в неориентированном — дважды). Память — O(V) на отметки и стек. Рекурсия здесь читается лучше, но на графе-цепочке в десятки тысяч вершин переполнит стек; в задачах на поле ниже — явный стек.

::practice{title="200. Number of Islands"}
Поле из `'1'` (суша) и `'0'` (вода). Остров — суша, связанная по горизонтали и вертикали. Посчитать острова. [Задача на LeetCode](https://leetcode.com/problems/number-of-islands/)

#solution
Каждая клетка суши — вершина, соседние клетки суши — рёбра. Острова — связные компоненты. Проходим поле; найдя сушу, считаем остров и «топим» его целиком обходом, чтобы не посчитать снова:

```ts
function numIslands(grid: string[][]): number {
  const m = grid.length;
  const n = grid[0].length;
  const sink = (r: number, c: number): void => {
    const stack: [number, number][] = [[r, c]];
    grid[r][c] = '0';
    while (stack.length) {
      const [x, y] = stack.pop()!;
      for (const [nx, ny] of [[x + 1, y], [x - 1, y], [x, y + 1], [x, y - 1]]) {
        if (nx >= 0 && nx < m && ny >= 0 && ny < n && grid[nx][ny] === '1') {
          grid[nx][ny] = '0';                     // отметить при добавлении, а не при снятии
          stack.push([nx, ny]);
        }
      }
    }
  };
  let islands = 0;
  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      if (grid[r][c] === '1') {
        islands++;
        sink(r, c);
      }
    }
  }
  return islands;
}
```

O(m · n). Поле меняется на месте — если нельзя, отметки держат в отдельном массиве. Явный стек вместо рекурсии: поле 1000 × 1000 из одной суши дало бы миллион вложенных вызовов. В проверке ответ совпал с подсчётом компонент по явному графу клеток. Альтернатива — система непересекающихся множеств, удобная, если суша добавляется по одной клетке.
::

::practice{title="130. Surrounded Regions"}
Поле из `'X'` и `'O'`. Область `'O'`, полностью окружённая `'X'` (не касающаяся края), захватывается — все её `'O'` становятся `'X'`. Изменить поле на месте. [Задача на LeetCode](https://leetcode.com/problems/surrounded-regions/)

#solution
Проверять каждую область «окружена ли» сложно. Проще наоборот: область не захватывается, только если связана с краем. Запускаем заливку от всех `'O'` на краях и помечаем их `'#'`; потом всё, что осталось `'O'`, захватываем, а `'#'` возвращаем в `'O'`.

```ts
function solve(board: string[][]): void {
  const m = board.length;
  const n = board[0].length;
  const keep = (r: number, c: number): void => {
    if (r < 0 || r >= m || c < 0 || c >= n || board[r][c] !== 'O') return;
    board[r][c] = '#';                            // связано с краем — не захватывается
    keep(r + 1, c);
    keep(r - 1, c);
    keep(r, c + 1);
    keep(r, c - 1);
  };
  for (let r = 0; r < m; r++) {
    keep(r, 0);
    keep(r, n - 1);
  }
  for (let c = 0; c < n; c++) {
    keep(0, c);
    keep(m - 1, c);
  }
  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) board[r][c] = board[r][c] === '#' ? 'O' : 'X';
  }
}
```

O(m · n). Приём «искать от границы» часто упрощает задачу: вместо «какие клетки окружены» — «какие достижимы с края». Здесь рекурсия для краткости; на больших полях её заменяют стеком, как в предыдущей задаче. В проверке результат совпал с проверкой каждой `'O'` поиском пути до края.
::

::practice{title="133. Clone Graph"}
Дана вершина связного неориентированного графа; у вершины — значение и список соседей. Вернуть глубокую копию графа. [Задача на LeetCode](https://leetcode.com/problems/clone-graph/)

#solution
Вершина для этой задачи:

```ts
class GraphNode {
  val: number;
  neighbors: GraphNode[];
  constructor(val?: number, neighbors?: GraphNode[]) {
    this.val = val ?? 0;
    this.neighbors = neighbors ?? [];
  }
}
```

Обход с таблицей «оригинал → копия». Копию кладём в таблицу **до** копирования соседей: в графе есть циклы, и сосед может сослаться обратно на ещё не достроенную вершину.

```ts
function cloneGraph(node: GraphNode | null): GraphNode | null {
  if (!node) return null;
  const copies = new Map<GraphNode, GraphNode>();
  const clone = (v: GraphNode): GraphNode => {
    const existing = copies.get(v);
    if (existing) return existing;
    const copy = new GraphNode(v.val);
    copies.set(v, copy);                          // записать до обхода соседей — циклы
    copy.neighbors = v.neighbors.map(clone);
    return copy;
  };
  return clone(node);
}
```

O(V + E). В проверке у каждой вершины ровно одна копия, ни одна копия не совпала с оригиналом, а соседи совпали по значениям. Тот же приём делает глубокое копирование объектов с циклическими ссылками ([Глубокие операции](/content/common-coding-questions/deep-operations)).
::

::practice{title="399. Evaluate Division"}
Даны равенства вида `a / b = 2.0` и запросы `a / c`. Ответить на каждый запрос, или −1, если ответ не вывести. Пример: `a / b = 2`, `b / c = 3` → `a / c = 6`, `b / a = 0.5`, `a / e = -1`, `a / a = 1`, `x / x = -1` (переменной `x` нет в данных). [Задача на LeetCode](https://leetcode.com/problems/evaluate-division/)

#solution
Переменные — вершины, равенство `a / b = w` — ребро `a → b` с весом `w` и обратное `b → a` с весом `1 / w`. Ответ на `x / y` — произведение весов на любом пути от `x` до `y`:

```ts
function calcEquation(equations: string[][], values: number[], queries: string[][]): number[] {
  const graph = new Map<string, [string, number][]>();
  const add = (a: string, b: string, w: number) => {
    if (!graph.has(a)) graph.set(a, []);
    graph.get(a)!.push([b, w]);
  };
  equations.forEach(([a, b], i) => {
    add(a, b, values[i]);                         // a / b = w
    add(b, a, 1 / values[i]);                     // b / a = 1 / w
  });
  const query = (from: string, to: string): number => {
    if (!graph.has(from) || !graph.has(to)) return -1;
    const seen = new Set([from]);
    const stack: [string, number][] = [[from, 1]];
    while (stack.length) {
      const [v, product] = stack.pop()!;
      if (v === to) return product;
      for (const [u, w] of graph.get(v)!) {
        if (!seen.has(u)) {
          seen.add(u);
          stack.push([u, product * w]);           // произведение весов по пути
        }
      }
    }
    return -1;
  };
  return queries.map(([a, b]) => query(a, b));
}
```

O(Q · (V + E)) — обход на каждый запрос. Ловушка — `x / x` для неизвестной `x`: ответ −1, а не 1. Для многих запросов эффективнее взвешенная система непересекающихся множеств: каждая переменная хранит отношение к корню своего множества. В проверке на случайных системах ответы совпали с отношением заданных значений там, где переменные связаны, и были −1, где нет.
::

::practice{title="207. Course Schedule"}
Есть `numCourses` курсов; пара `[a, b]` значит, что перед `a` нужно пройти `b`. Можно ли пройти все курсы? Пример: `2, [[1, 0]]` — да; `2, [[1, 0], [0, 1]]` — нет. [Задача на LeetCode](https://leetcode.com/problems/course-schedule/)

#solution
Курсы и зависимости — ориентированный граф; пройти все можно, если в нём нет цикла. Алгоритм Кана: берём курсы без невыполненных зависимостей (входящая степень 0), «проходим» их и уменьшаем степень зависящих. Если в конце пройдены не все — оставшиеся ждут друг друга по кругу.

```ts
function canFinish(numCourses: number, prerequisites: number[][]): boolean {
  const graph: number[][] = Array.from({ length: numCourses }, () => []);
  const indegree = new Array(numCourses).fill(0);
  for (const [course, pre] of prerequisites) {
    graph[pre].push(course);
    indegree[course]++;
  }
  const queue = indegree.flatMap((d, v) => (d === 0 ? [v] : []));
  let taken = 0;
  for (let head = 0; head < queue.length; head++) {
    taken++;
    for (const next of graph[queue[head]]) if (--indegree[next] === 0) queue.push(next);
  }
  return taken === numCourses;                    // остались курсы — есть цикл
}
```

O(V + E). Альтернатива — обход в глубину с тремя цветами: «не посещена», «в обработке», «готова»; ребро в вершину «в обработке» — цикл. В проверке ответ совпал с таким поиском цикла на тысяче случайных графов. То же самое находит циклические импорты между модулями и порядок сборки пакетов.
::

::practice{title="210. Course Schedule II"}
То же, но вернуть порядок прохождения всех курсов или пустой массив, если это невозможно. [Задача на LeetCode](https://leetcode.com/problems/course-schedule-ii/)

#solution
Порядок, в котором алгоритм Кана снимает вершины, — это и есть топологическая сортировка:

```ts
function findOrder(numCourses: number, prerequisites: number[][]): number[] {
  const graph: number[][] = Array.from({ length: numCourses }, () => []);
  const indegree = new Array(numCourses).fill(0);
  for (const [course, pre] of prerequisites) {
    graph[pre].push(course);
    indegree[course]++;
  }
  const order = indegree.flatMap((d, v) => (d === 0 ? [v] : []));
  for (let head = 0; head < order.length; head++) {
    for (const next of graph[order[head]]) if (--indegree[next] === 0) order.push(next);
  }
  return order.length === numCourses ? order : [];
}
```

O(V + E). Массив порядка сам служит очередью — указатель `head` идёт по нему. Ответов может быть много; в проверке каждый курс в ответе шёл после всех своих зависимостей, а при цикле ответ был пустым.
::

## Красные флаги в ответе

- **Обход без отметок посещённых.** На графе с циклами — бесконечный цикл.
- **Отметка при снятии со стека или очереди.** Вершина попадёт в очередь много раз, и время вырастет.
- **Рекурсия на поле в тысячи клеток.** Переполнение стека; нужен явный стек.
- **Не увидеть граф в формулировке** про отношения, зависимости или соседние клетки.
- **«Цикл в зависимостях найду, если вершина встретилась дважды».** В ориентированном графе это не цикл; нужны цвета или алгоритм Кана.

## Как спрашивают на собеседовании

::question
Как представить граф и как его обойти?

#answer
Чаще всего — списком смежности: для каждой вершины массив соседей, память O(V + E). Матрица смежности — O(V²), подходит для плотных графов и быстрой проверки ребра. Поле или словарь можно не строить явно: соседи вычисляются на лету. Обходят в глубину (стек или рекурсия) или в ширину (очередь), отмечая посещённые вершины; оба — O(V + E).

#more
В глубину удобно искать компоненты, циклы и пути; в ширину — кратчайшие пути без весов. Для весов — Дейкстра на куче. Во фронтенде графы — это зависимости модулей в бандлере, DOM как дерево и графы состояний.
::

::question
Как определить, можно ли выполнить задачи с зависимостями?

#answer
Построить ориентированный граф зависимостей и проверить его на циклы. Алгоритм Кана: снимать вершины с нулевой входящей степенью и уменьшать степень соседей. Если сняты все вершины — цикла нет, а порядок снятия — допустимый порядок выполнения. O(V + E).

#more
Вариант через обход в глубину с тремя цветами находит цикл, а обратный порядок завершения вершин даёт топологическую сортировку. Алгоритм Кана ещё и показывает, какие вершины застряли в цикле, — так инструменты сообщают о циклических импортах.
::

::question
Как скопировать граф с циклами?

#answer
Обходом с таблицей «оригинал → копия». Копию создают и кладут в таблицу до того, как копировать соседей, — тогда ссылка на уже начатую вершину возьмёт её копию из таблицы, и цикл не уведёт в бесконечность. O(V + E).

#more
Без таблицы цикл даст бесконечную рекурсию, а вершина, достижимая двумя путями, скопируется дважды. Тот же приём лежит в `structuredClone` и самописном `deepClone` с `WeakMap` для объектов с циклическими ссылками.
::
