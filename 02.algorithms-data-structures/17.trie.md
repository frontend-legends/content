# Префиксное дерево

Префиксное дерево (trie) хранит строки по символам: путь от корня — префикс, а отметка в узле — «здесь кончается слово». Поиск слова и проверка префикса стоят O(длины строки) независимо от числа слов, а слова с общим началом делят узлы. Отсюда применения: автодополнение, проверка орфографии, маршрутизация по префиксам и поиск многих слов сразу. Спрашивают реализацию trie, поиск с шаблоном «любая буква» и поиск списка слов на доске.

::tldr
- **Узел trie — словарь детей по символу и флаг конца слова.** Вставка, поиск и проверка префикса — один спуск, O(длины строки).
- **Флаг конца слова обязателен:** без него `"app"` найдётся, если вставлено только `"apple"`.
- **Шаблон с «любым символом» — обход в глубину по всем детям** на месте точки; на остальных символах путь один.
- **Для поиска многих слов trie заменяет много отдельных поисков:** обход идёт по доске один раз и сразу отсекает ветки, которые не начало ни одного слова.
::

---

## Как узнать паттерн

- Много строк и вопросы про **префиксы**: «есть ли слово с таким началом», «все слова на префикс», автодополнение.
- Нужно найти **сразу много слов** в тексте или на поле.
- Поиск с **шаблоном** по символам.

Если нужен только точный поиск слова, хватит `Set` — O(1) в среднем. Trie выигрывает именно на префиксах и на общем обходе для многих слов. Устройство trie и его сжатые варианты — в [Структурах данных](/content/algorithms-data-structures/data-structures).

::practice{title="208. Implement Trie (Prefix Tree)"}
Реализовать префиксное дерево: `insert(word)`, `search(word)` — есть ли слово целиком, `startsWith(prefix)` — есть ли слово с таким началом. [Задача на LeetCode](https://leetcode.com/problems/implement-trie-prefix-tree/)

#solution
Узел хранит детей в `Map` и флаг конца слова. Общий спуск по строке вынесен в `walk`:

```ts
class TrieNode {
  children = new Map<string, TrieNode>();
  isWord = false;
}

class Trie {
  private root = new TrieNode();

  insert(word: string): void {
    let node = this.root;
    for (const c of word) {
      if (!node.children.has(c)) node.children.set(c, new TrieNode());
      node = node.children.get(c)!;
    }
    node.isWord = true;                           // здесь кончается слово
  }

  private walk(prefix: string): TrieNode | null {
    let node: TrieNode | undefined = this.root;
    for (const c of prefix) {
      node = node.children.get(c);
      if (!node) return null;
    }
    return node;
  }

  search(word: string): boolean {
    return this.walk(word)?.isWord ?? false;
  }

  startsWith(prefix: string): boolean {
    return this.walk(prefix) !== null;
  }
}
```

Каждая операция — O(L), где L — длина строки. Для 26 строчных букв `Map` можно заменить массивом из 26 элементов — быстрее, но больше памяти на редких ветвях. В проверке ответы совпали с проверками по массиву вставленных слов.
::

::practice{title="211. Design Add and Search Words Data Structure"}
Словарь с `addWord(word)` и `search(word)`, где в запросе точка `.` означает любую одну букву. Пример: после `bad, dad, mad` — `search("pad")` ложь, `search(".ad")` и `search("b..")` истина. [Задача на LeetCode](https://leetcode.com/problems/design-add-and-search-words-data-structure/)

#solution
Хранение — тот же trie. Поиск — обход в глубину: на обычном символе путь один, на точке пробуем всех детей.

```ts
class WordDictionary {
  private root = new TrieNode();

  addWord(word: string): void {
    let node = this.root;
    for (const c of word) {
      if (!node.children.has(c)) node.children.set(c, new TrieNode());
      node = node.children.get(c)!;
    }
    node.isWord = true;
  }

  search(word: string): boolean {
    const match = (node: TrieNode, i: number): boolean => {
      if (i === word.length) return node.isWord;
      if (word[i] === '.') {                      // точка — любой символ: пробуем всех детей
        for (const child of node.children.values()) if (match(child, i + 1)) return true;
        return false;
      }
      const child = node.children.get(word[i]);
      return child ? match(child, i + 1) : false;
    };
    return match(this.root, 0);
  }
}
```

Без точек — O(L); каждая точка умножает число путей на ветвление, худший случай — O(26^L). В проверке ответы совпали с проверкой регулярным выражением по всем добавленным словам. Если слова сгруппировать по длине, запрос с точками сразу отсекает слова другой длины.
::

::practice{title="212. Word Search II"}
Дана доска букв и список слов. Найти все слова, которые можно составить из соседних по горизонтали и вертикали клеток, не используя клетку дважды в одном слове. [Задача на LeetCode](https://leetcode.com/problems/word-search-ii/)

#solution
Искать каждое слово отдельно — повторять один и тот же обход доски для каждого. Вместо этого строим trie из всех слов и обходим доску один раз: путь по доске одновременно спускается по trie, и как только префикса нет в trie, ветка обрезается. Найденное слово стираем из узла, чтобы не добавить дважды, а исчерпанные ветки удаляем из trie — так следующие обходы короче.

```ts
function findWords(board: string[][], words: string[]): string[] {
  type Node = { children: Map<string, Node>; word: string | null };
  const root: Node = { children: new Map(), word: null };
  for (const w of words) {
    let node = root;
    for (const c of w) {
      if (!node.children.has(c)) node.children.set(c, { children: new Map(), word: null });
      node = node.children.get(c)!;
    }
    node.word = w;
  }
  const m = board.length;
  const n = board[0].length;
  const found: string[] = [];
  const dfs = (r: number, c: number, parent: Node): void => {
    const ch = board[r][c];
    const node = parent.children.get(ch);
    if (!node) return;                            // такого префикса нет ни у одного слова
    if (node.word) {
      found.push(node.word);
      node.word = null;                           // не находить слово дважды
    }
    board[r][c] = '#';                            // клетку не использовать повторно в этом слове
    for (const [dr, dc] of [[1, 0], [-1, 0], [0, 1], [0, -1]]) {
      const nr = r + dr;
      const nc = c + dc;
      if (nr >= 0 && nr < m && nc >= 0 && nc < n && board[nr][nc] !== '#') dfs(nr, nc, node);
    }
    board[r][c] = ch;
    if (node.children.size === 0 && !node.word) parent.children.delete(ch);   // обрезать исчерпанную ветку
  };
  for (let r = 0; r < m; r++) for (let c = 0; c < n; c++) dfs(r, c, root);
  return found;
}
```

В узле хранится само слово, а не флаг, — чтобы не собирать строку по пути. Клетка временно заменяется на `#` вместо отдельного множества посещённых — это возврат состояния после рекурсии, как в переборе с возвратом ([Перебор с возвратом](/content/algorithms-data-structures/backtracking)). В проверке ответ совпал с отдельным поиском каждого слова на случайных досках, и `"abcb"` на доске `ab / cd` не нашлось — клетку нельзя взять дважды.
::

## Красные флаги в ответе

- **Trie без флага конца слова.** Префикс начнёт считаться словом.
- **Trie для одного точного поиска.** `Set` проще и быстрее; trie нужен для префиксов.
- **Поиск каждого слова на доске отдельно.** Дорогой повтор работы; trie объединяет обходы.
- **Забыть вернуть клетку после обхода** в поиске на доске — следующие слова её не увидят.

## Как спрашивают на собеседовании

::question
Что такое префиксное дерево и когда оно лучше хеш-таблицы?

#answer
Дерево, где каждый узел — символ, путь от корня — префикс, а отметка в узле — конец слова. Поиск слова и префикса — O(длины строки). Хеш-таблица быстрее для точного поиска, но не умеет искать по префиксу без перебора всех ключей; trie отвечает на «есть ли слова с таким началом» и «все слова на префикс» сразу.

#more
Trie тратит много памяти на узлы; сжатое префиксное дерево (radix tree) склеивает цепочки из одного ребёнка. Префиксные деревья используют роутеры для сопоставления путей, автодополнение и IP-маршрутизация. Для автодополнения в узлах часто хранят несколько лучших продолжений, чтобы не обходить поддерево.
::

::question
Как реализовать автодополнение?

#answer
Положить словарь в trie. По введённому префиксу спуститься до его узла за O(длины префикса) и обойти поддерево, собирая слова. Чтобы не обходить всё поддерево на коротком префиксе, в каждом узле заранее хранят k лучших продолжений по популярности.

#more
На фронтенде автодополнение по небольшому списку проще сделать фильтром по `startsWith` — trie нужен на больших словарях. Важнее сетевые детали: `debounce`, отмена устаревших запросов и кеш ответов ([Задачи на интерфейс](/content/common-coding-questions/ui-components-advanced)).
::

::question
Как найти на доске сразу много слов?

#answer
Построить trie из слов и обойти доску в глубину из каждой клетки, спускаясь по trie вместе с путём. Ветку обрывают, как только текущего префикса нет в trie; найденное слово записывают и стирают из узла. Так доска обходится один раз для всех слов.

#more
Дополнительное ускорение — удалять из trie исчерпанные ветки, чтобы следующие обходы в них не заходили. Посещённые клетки временно помечают на самой доске и возвращают после обхода. Худший случай остаётся экспоненциальным по длине слова, но на практике отсечение делает поиск быстрым.
::
