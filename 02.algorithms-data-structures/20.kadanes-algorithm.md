# Алгоритм Кадане

Алгоритм Кадане находит подмассив с максимальной суммой за один проход и O(1) памяти. Перебор всех подмассивов — O(n²), «разделяй и властвуй» — O(n log n), а Кадане держит одно число: лучшую сумму подмассива, который кончается в текущей позиции. Это самый короткий пример динамического программирования, и на нём проверяют, видит ли кандидат состояние «лучшее, кончающееся здесь». Спрашивают классическую задачу и её кольцевой вариант.

::tldr
- **Состояние — лучшая сумма подмассива, кончающегося в i:** `current = max(nums[i], current + nums[i])`. Ответ — максимум `current` по всем i.
- **Если накопленная сумма отрицательна, её выбрасывают** и начинают заново с текущего элемента — отрицательный префикс только уменьшает любую сумму.
- **Ответ инициализируют первым элементом, а не нулём:** в массиве из одних отрицательных чисел ответ — наибольшее из них.
- **Кольцевой вариант — максимум из двух случаев:** обычный подмассив или «всё минус минимальный подмассив». Если все числа отрицательные, второй случай даёт пустой подмассив и не годится.
::

---

## Как узнать паттерн

- Нужен **непрерывный** подмассив с максимальной (или минимальной) суммой.
- Нужен **максимум по подмассивам** другой величины, которую можно продолжать: произведение (задача 152 — держат и максимум, и минимум), сумма с одним удалением.
- Ответ — одно число, а n большой: O(n²) не пройдёт.

Если нужен подмассив с **заданной** суммой, а не максимальной, — это префиксные суммы с хеш-таблицей ([Хеш-таблицы](/content/algorithms-data-structures/hashmap)). Если элементы неотрицательны и нужна длина при ограничении на сумму — скользящее окно ([Скользящее окно](/content/algorithms-data-structures/sliding-window)).

## Шаблон

Кадане с границами подмассива — на собеседовании часто просят вернуть не только сумму, но и сам подмассив:

```ts
function maxSubArrayRange(nums: number[]): [number, number, number] {
  let best = nums[0];
  let bestFrom = 0;
  let bestTo = 0;
  let current = nums[0];
  let from = 0;
  for (let i = 1; i < nums.length; i++) {
    if (current < 0) {                            // отрицательный хвост только мешает — начать заново
      current = nums[i];
      from = i;
    } else {
      current += nums[i];
    }
    if (current > best) [best, bestFrom, bestTo] = [current, from, i];
  }
  return [best, bestFrom, bestTo];
}
```

O(n) по времени, O(1) по памяти. Для `[-2, 1, -3, 4, -1, 2, 1, -5, 4]` ответ — сумма 6 на отрезке с индексами 3–6, `[4, -1, 2, 1]`. В проверке сумма совпала с перебором всех подмассивов, а элементы на найденном отрезке давали ровно эту сумму.

## Задачи

| Задача | Идея | Время | Память |
| --- | --- | --- | --- |
| 53. Maximum Subarray | лучшая сумма, кончающаяся здесь | O(n) | O(1) |
| 918. Maximum Sum Circular Subarray | максимум или «всё минус минимум» | O(n) | O(1) |

::practice{title="53. Maximum Subarray"}
Найти непустой подмассив с наибольшей суммой и вернуть эту сумму. Пример: `[-2, 1, -3, 4, -1, 2, 1, -5, 4]` → 6; `[5, 4, -1, 7, 8]` → 23. Продолжение: решить ещё и «разделяй и властвуй». [Задача на LeetCode](https://leetcode.com/problems/maximum-subarray/)

#solution
Лучший подмассив, кончающийся в `i`, — либо один `nums[i]`, либо лучший подмассив, кончающийся в `i - 1`, плюс `nums[i]`:

```ts
function maxSubArray(nums: number[]): number {
  let best = nums[0];
  let current = nums[0];                          // лучшая сумма подмассива, кончающегося здесь
  for (let i = 1; i < nums.length; i++) {
    current = Math.max(nums[i], current + nums[i]);
    best = Math.max(best, current);
  }
  return best;
}
```

O(n), O(1). Частая ошибка — `best = 0`: для `[-3, -1, -2]` получится 0, хотя пустой подмассив запрещён и ответ −1. Ответ на продолжение: лучший подмассив целиком в левой половине, целиком в правой или пересекает середину — последний считается двумя проходами от середины. Это O(n log n), хуже Кадане, но такую схему можно распараллелить и обобщить на дерево отрезков. В проверке ответ совпал с перебором на тысяче случайных массивов.
::

::practice{title="918. Maximum Sum Circular Subarray"}
Массив закольцован: после последнего элемента идёт первый. Найти непустой подмассив с наибольшей суммой; каждый элемент берётся не больше раза. Пример: `[5, -3, 5]` → 10 (`5` с конца и `5` с начала); `[-3, -2, -3]` → −2. [Задача на LeetCode](https://leetcode.com/problems/maximum-sum-circular-subarray/)

#solution
Лучший подмассив либо не переходит через конец — тогда это обычный Кадане, — либо переходит. Во втором случае он состоит из суффикса и префикса, а невзятая часть посередине — обычный подмассив. Сумма взятого = сумма всего − сумма невзятого, и она максимальна, когда невзятое — подмассив с минимальной суммой. Оба Кадане — на максимум и на минимум — считаются за один проход:

```ts
function maxSubarraySumCircular(nums: number[]): number {
  let total = 0;
  let curMax = 0;
  let curMin = 0;
  let best = -Infinity;
  let worst = Infinity;
  for (const x of nums) {
    total += x;
    curMax = Math.max(x, curMax + x);
    best = Math.max(best, curMax);
    curMin = Math.min(x, curMin + x);
    worst = Math.min(worst, curMin);
  }
  // кольцевой подмассив = всё минус минимальный подмассив; но если всё отрицательное, «всё минус всё» пусто
  return best < 0 ? best : Math.max(best, total - worst);
}
```

O(n), O(1). Ловушка — массив из отрицательных чисел: минимальный подмассив — весь массив, и `total - worst = 0` соответствует пустому подмассиву, который запрещён. Поэтому, если даже лучший обычный подмассив отрицателен, ответ — он. Альтернатива — удвоить массив и искать максимум по окнам длины до n с префиксными суммами и монотонным деком, но это сложнее. В проверке ответ совпал с перебором всех подмассивов кольца.
::

## Красные флаги в ответе

- **`best = 0` в начале.** Для массива из отрицательных чисел вернётся 0 — сумма пустого подмассива.
- **Перебор всех подмассивов за O(n²)** без попытки улучшить.
- **В кольцевом варианте забыть случай «все отрицательные».** «Всё минус минимум» даёт пустой подмассив.
- **Сбрасывать сумму на каждом отрицательном элементе,** а не когда отрицательна сама накопленная сумма: `[3, -1, 4]` даёт 6, а не 4.

## Как спрашивают на собеседовании

::question
Как найти подмассив с максимальной суммой за O(n)?

#answer
Алгоритмом Кадане: идём по массиву и держим лучшую сумму подмассива, кончающегося в текущем элементе, — `current = max(nums[i], current + nums[i])`. Ответ — максимум `current` за весь проход. Если накопленная сумма стала отрицательной, её выгоднее выбросить и начать с текущего элемента. O(n) по времени, O(1) по памяти.

#more
Это динамическое программирование с состоянием «лучшее, кончающееся в i», где от массива состояний осталась одна переменная. Чтобы вернуть сам подмассив, запоминают, где начался текущий отрезок, и границы лучшего. Для произведения держат и максимум, и минимум: отрицательное число меняет их местами.
::

::question
Как решить задачу для закольцованного массива?

#answer
Ответ — большее из двух: обычный Кадане (подмассив без перехода через конец) и сумма всего массива минус минимальный подмассив (подмассив, который переходит через конец). Оба считаются в одном проходе. Особый случай — все числа отрицательные: тогда второй вариант означает пустой подмассив, и ответ — результат обычного Кадане.

#more
Идея «дополнение минимального — максимальное кольцевое» встречается и в других задачах на кольца. Общий способ для колец — удвоить массив и ограничить длину окна n; с монотонным деком это тоже O(n), но кода больше.
::

::question
Почему алгоритм Кадане корректен?

#answer
Любой подмассив кончается в каком-то i. Лучший подмассив, кончающийся в i, либо состоит из одного `nums[i]`, либо продолжает лучший подмассив, кончающийся в i − 1: если бы продолжение было не лучшим, замена на лучшее увеличила бы сумму. Значит, `current` в каждой позиции точен, а максимум по всем позициям — ответ.

#more
Так же доказывают большинство решений динамикой: определить состояние, показать, что оптимум для него складывается из оптимума меньшего состояния, и взять максимум по состояниям. Подробнее о динамике — в [Одномерном DP](/content/algorithms-data-structures/1d-dp).
::
