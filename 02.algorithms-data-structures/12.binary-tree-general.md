# Двоичные деревья

Двоичное дерево — узлы, у каждого не больше двух детей: левого и правого. Почти любая задача на дерево решается одной мыслью: ответ для узла собирается из ответов для его поддеревьев. Глубина, зеркальность, сумма пути, общий предок — всё это рекурсия в несколько строк. Спрашивают обходы, построение дерева по двум обходам, максимальный путь, общего предка и превращение дерева в список на месте. Фронтенду деревья знакомы по DOM, JSON и виртуальному DOM — те же обходы и рекурсия.

::tldr
- **Рекурсия «ответ из ответов детей»:** функция возвращает результат для поддерева, а узел комбинирует результаты левого и правого. Базовый случай — `null`.
- **Три обхода в глубину — когда обрабатывается корень:** до детей (прямой), между ними (симметричный) и после (обратный). Симметричный обход BST идёт по возрастанию.
- **Если ответ не совпадает с тем, что возвращает рекурсия, заводят внешнюю переменную:** максимальный путь возвращает «лучший путь вниз», а ответ — путь через узел с двумя ветвями.
- **Дерево однозначно восстанавливается по симметричному обходу и прямому или обратному:** корень берётся из прямого или обратного, а симметричный делит остальное на левое и правое.
- **Рекурсия тратит стек O(высоты):** на вырожденном дереве это O(n), и глубокое дерево переполнит стек — тогда нужен явный стек.
::

## Как узнать паттерн

- Вход — `TreeNode`, и нужно **свойство всего дерева**: глубина, сбалансированность, симметрия, равенство деревьев.
- Нужно что-то про **пути**: сумма от корня до листа, максимальный путь, все пути.
- Нужно **построить** дерево по обходам или **перестроить** его на месте.
- Нужна **связь двух узлов**: общий предок, расстояние.
- Нужен обход **по уровням** — это обход в ширину ([Обход в ширину](/content/algorithms-data-structures/binary-tree-bfs)); в отсортированном дереве — свои приёмы ([Двоичное дерево поиска](/content/algorithms-data-structures/binary-search-tree)).

Если рекурсию разбирать руками сложно, полезно сформулировать **контракт функции**: «возвращает глубину поддерева», «возвращает лучшую сумму пути, идущего вниз из узла». Дальше код пишется почти механически.

## Шаблоны

Узел в задачах LeetCode:

```ts
export class TreeNode {
  val: number;
  left: TreeNode | null;
  right: TreeNode | null;
  constructor(val?: number, left?: TreeNode | null, right?: TreeNode | null) {
    this.val = val ?? 0;
    this.left = left ?? null;
    this.right = right ?? null;
  }
}
```

**Обход в глубину рекурсией** — симметричный порядок для примера:

```ts
function inorder(root: TreeNode | null, out: number[] = []): number[] {
  if (!root) return out;
  inorder(root.left, out);                        // левое поддерево
  out.push(root.val);                             // корень
  inorder(root.right, out);                       // правое поддерево
  return out;
}
```

**Тот же обход с явным стеком** — когда глубина дерева может переполнить :term[стек вызовов]{def="стек, где движок хранит кадры активных вызовов функций; его глубина ограничена"} ([Функции](/content/javascript/functions)):

```ts
function preorderIterative(root: TreeNode | null): number[] {
  const out: number[] = [];
  const stack = root ? [root] : [];
  while (stack.length) {
    const node = stack.pop()!;
    out.push(node.val);
    if (node.right) stack.push(node.right);       // правый кладём первым — снимется вторым
    if (node.left) stack.push(node.left);
  }
  return out;
}
```

Любой обход посещает каждый узел один раз — O(n) по времени; память — O(h), где h — высота: O(log n) у сбалансированного дерева и O(n) у вытянутого в линию.

::practice{title="104. Maximum Depth of Binary Tree"}
Найти глубину дерева — число узлов на самом длинном пути от корня до листа. Пример: `[3, 9, 20, null, null, 15, 7]` → 3. [Задача на LeetCode](https://leetcode.com/problems/maximum-depth-of-binary-tree/)

#solution
Глубина пустого дерева — 0, глубина узла — 1 плюс большая из глубин детей:

```ts
function maxDepth(root: TreeNode | null): number {
  if (!root) return 0;
  return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}
```

O(n) по времени, O(h) стека. Обход в ширину тоже работает: число уровней — это глубина. Эта задача — эталон рекурсии на дереве, и на ней удобно объяснить контракт функции.
::

::practice{title="100. Same Tree"}
Одинаковы ли два дерева — по структуре и значениям? Пример: `[1, 2, 3]` и `[1, 2, 3]` — да; `[1, 2]` и `[1, null, 2]` — нет. [Задача на LeetCode](https://leetcode.com/problems/same-tree/)

#solution
Оба пусты — равны; пуст только один — нет; иначе равны значения и оба поддерева:

```ts
function isSameTree(p: TreeNode | null, q: TreeNode | null): boolean {
  if (!p || !q) return p === q;                   // оба пусты — равны, один пуст — нет
  return p.val === q.val && isSameTree(p.left, q.left) && isSameTree(p.right, q.right);
}
```

O(n) по времени. Сравнение обходов в одну строку не годится: разные деревья могут давать одинаковый прямой обход, если не записывать `null`. Та же рекурсия — основа глубокого сравнения объектов ([Глубокие операции](/content/common-coding-questions/deep-operations)).
::

::practice{title="226. Invert Binary Tree"}
Отразить дерево зеркально: у каждого узла поменять левое и правое поддерево местами. Пример: `[4, 2, 7, 1, 3, 6, 9]` → `[4, 7, 2, 9, 6, 3, 1]`. [Задача на LeetCode](https://leetcode.com/problems/invert-binary-tree/)

#solution
Отражаем поддеревья и ставим их на места друг друга:

```ts
function invertTree(root: TreeNode | null): TreeNode | null {
  if (!root) return null;
  [root.left, root.right] = [invertTree(root.right), invertTree(root.left)];
  return root;
}
```

O(n) по времени. Деструктуризация вычисляет правую часть целиком до присваивания, поэтому временная переменная не нужна. В проверке симметричный обход отражённого дерева совпал с развёрнутым обходом исходного.
::

::practice{title="101. Symmetric Tree"}
Симметрично ли дерево относительно своей вертикальной оси? Пример: `[1, 2, 2, 3, 4, 4, 3]` — да; `[1, 2, 2, null, 3, null, 3]` — нет. [Задача на LeetCode](https://leetcode.com/problems/symmetric-tree/)

#solution
Дерево симметрично, если левое поддерево — зеркало правого. Два дерева зеркальны, если корни равны, а левое первого зеркально правому второго и наоборот:

```ts
function isSymmetric(root: TreeNode | null): boolean {
  const mirror = (a: TreeNode | null, b: TreeNode | null): boolean => {
    if (!a || !b) return a === b;
    return a.val === b.val && mirror(a.left, b.right) && mirror(a.right, b.left);
  };
  return mirror(root?.left ?? null, root?.right ?? null);
}
```

O(n) по времени. Ошибка — сравнивать `left` с `left`: это проверка равенства, а не зеркальности. В проверке ответ совпал с «дерево равно своему отражению».
::

::practice{title="105. Construct Binary Tree from Preorder and Inorder Traversal"}
Даны прямой и симметричный обходы дерева с уникальными значениями. Восстановить дерево. Пример: `preorder = [3, 9, 20, 15, 7]`, `inorder = [9, 3, 15, 20, 7]` → `[3, 9, 20, null, null, 15, 7]`. [Задача на LeetCode](https://leetcode.com/problems/construct-binary-tree-from-preorder-and-inorder-traversal/)

#solution
Первый элемент прямого обхода — корень. В симметричном обходе всё левее корня — левое поддерево, правее — правое. Рекурсивно строим левое, потом правое, беря корни из прямого обхода по порядку. Позицию значения в симметричном обходе заранее кладём в `Map`, иначе поиск сделает решение O(n²).

```ts
function buildTree(preorder: number[], inorder: number[]): TreeNode | null {
  const index = new Map(inorder.map((v, i) => [v, i]));   // значение → позиция в inorder
  let next = 0;                                           // следующий корень в preorder
  const build = (lo: number, hi: number): TreeNode | null => {
    if (lo > hi) return null;
    const val = preorder[next++];
    const mid = index.get(val)!;
    const node = new TreeNode(val);
    node.left = build(lo, mid - 1);               // сначала левое — так идёт preorder
    node.right = build(mid + 1, hi);
    return node;
  };
  return build(0, inorder.length - 1);
}
```

O(n) по времени и памяти. Порядок «сначала левое» обязателен: прямой обход перечисляет все узлы левого поддерева раньше правого. Без уникальных значений дерево однозначно не восстанавливается. В проверке случайные деревья восстановились по своим обходам точно.
::

::practice{title="106. Construct Binary Tree from Inorder and Postorder Traversal"}
То же по симметричному и обратному обходу. Пример: `inorder = [9, 3, 15, 20, 7]`, `postorder = [9, 15, 7, 20, 3]` → `[3, 9, 20, null, null, 15, 7]`. [Задача на LeetCode](https://leetcode.com/problems/construct-binary-tree-from-inorder-and-postorder-traversal/)

#solution
В обратном обходе корень — последний. Если читать его с конца, получается «корень, правое, левое», поэтому строим сначала правое поддерево:

```ts
function buildTreeFromPostorder(inorder: number[], postorder: number[]): TreeNode | null {
  const index = new Map(inorder.map((v, i) => [v, i]));
  let next = postorder.length - 1;                // корни идут с конца postorder
  const build = (lo: number, hi: number): TreeNode | null => {
    if (lo > hi) return null;
    const val = postorder[next--];
    const mid = index.get(val)!;
    const node = new TreeNode(val);
    node.right = build(mid + 1, hi);              // сначала правое — с конца postorder идёт оно
    node.left = build(lo, mid - 1);
    return node;
  };
  return build(0, inorder.length - 1);
}
```

O(n). Частый вопрос: можно ли восстановить дерево по прямому и обратному обходу без симметричного? В общем случае нет — у узла с одним ребёнком непонятно, левый он или правый.
::

::practice{title="117. Populating Next Right Pointers in Each Node II"}
У узла есть ещё ссылка `next`. Проставить в ней правого соседа на том же уровне, у последнего на уровне — `null`. Дерево произвольное, не обязательно полное. Продолжение: с O(1) дополнительной памяти. [Задача на LeetCode](https://leetcode.com/problems/populating-next-right-pointers-in-each-node-ii/)

#solution
Узел для этой задачи:

```ts
class NextNode {
  val: number;
  left: NextNode | null;
  right: NextNode | null;
  next: NextNode | null;
  constructor(val?: number, left?: NextNode | null, right?: NextNode | null, next?: NextNode | null) {
    this.val = val ?? 0;
    this.left = left ?? null;
    this.right = right ?? null;
    this.next = next ?? null;
  }
}
```

Обход в ширину с очередью решает задачу за O(n) памяти. Без очереди: текущий уровень уже связан через `next` — идём по нему как по списку и собираем детей в список следующего уровня с фиктивным узлом.

```ts
function connect(root: NextNode | null): NextNode | null {
  let level = root;                               // идём по уровню через уже проставленные next
  while (level) {
    const dummy = new NextNode();                 // начало следующего уровня
    let tail = dummy;
    for (let node: NextNode | null = level; node; node = node.next) {
      if (node.left) tail = tail.next = node.left;
      if (node.right) tail = tail.next = node.right;
    }
    level = dummy.next;
  }
  return root;
}
```

O(n) по времени, O(1) по памяти. Фиктивный узел решает главную сложность неполного дерева — не надо искать первого ребёнка на следующем уровне. В проверке порядок по ссылкам `next` совпал с уровнями обхода в ширину.
::

::practice{title="114. Flatten Binary Tree to Linked List"}
Превратить дерево на месте в «список» по ссылкам `right` в порядке прямого обхода; все `left` — `null`. Продолжение: O(1) памяти. Пример: `[1, 2, 5, 3, 4, null, 6]` → `1 → 2 → 3 → 4 → 5 → 6`. [Задача на LeetCode](https://leetcode.com/problems/flatten-binary-tree-to-linked-list/)

#solution
Идём вправо по будущему списку. Если у узла есть левое поддерево, оно в прямом обходе стоит между узлом и правым поддеревом. Значит, правое поддерево надо прицепить к самому правому узлу левого, а левое перенести направо:

```ts
function flatten(root: TreeNode | null): void {
  for (let node = root; node; node = node.right) {
    if (!node.left) continue;
    let rightmost = node.left;                    // самый правый в левом поддереве
    while (rightmost.right) rightmost = rightmost.right;
    rightmost.right = node.right;                 // прицепить правое поддерево к нему
    node.right = node.left;
    node.left = null;
  }
}
```

O(n) по времени — каждое ребро в поиске самого правого проходится ограниченное число раз — и O(1) по памяти. В проверке порядок по `right` совпал с прямым обходом исходного дерева, а все `left` стали `null`.
::

::practice{title="112. Path Sum"}
Есть ли путь от корня до **листа** с суммой значений `targetSum`? Пример: дерево `[5, 4, 8, 11, null, 13, 4, 7, 2, null, null, null, 1]`, сумма 22 — да (5 → 4 → 11 → 2). [Задача на LeetCode](https://leetcode.com/problems/path-sum/)

#solution
Спускаясь, вычитаем значение узла из цели; в листе проверяем, что осталось ровно его значение:

```ts
function hasPathSum(root: TreeNode | null, targetSum: number): boolean {
  if (!root) return false;
  if (!root.left && !root.right) return root.val === targetSum;   // только лист
  const rest = targetSum - root.val;
  return hasPathSum(root.left, rest) || hasPathSum(root.right, rest);
}
```

O(n) по времени. Главная ловушка — проверять сумму в `null`, а не в листе: тогда у узла с одним ребёнком «пустая» сторона засчитается как путь. Дерево `[1, 2]` с суммой 1 — ответ «нет»: 1 — не лист. В проверке ответ совпал с перебором всех путей до листьев.
::

::practice{title="129. Sum Root to Leaf Numbers"}
Каждый путь от корня до листа образует число из цифр узлов. Найти сумму всех таких чисел. Пример: `[1, 2, 3]` → 12 + 13 = 25. [Задача на LeetCode](https://leetcode.com/problems/sum-root-to-leaf-numbers/)

#solution
Передаём вниз уже набранное число: дописать цифру — умножить на 10 и прибавить. В листе возвращаем число, выше — сумму по детям:

```ts
function sumNumbers(root: TreeNode | null): number {
  const dfs = (node: TreeNode | null, prefix: number): number => {
    if (!node) return 0;
    const value = prefix * 10 + node.val;
    if (!node.left && !node.right) return value;
    return dfs(node.left, value) + dfs(node.right, value);
  };
  return dfs(root, 0);
}
```

O(n). Это пример рекурсии, где информация идёт **вниз** параметром, а результат — **вверх** возвращаемым значением. Строки вместо чисел тоже работают, но медленнее.
::

::practice{title="124. Binary Tree Maximum Path Sum"}
Путь — последовательность узлов, соединённых рёбрами, без повторов; он не обязан проходить через корень. Найти наибольшую сумму значений на пути. Значения могут быть отрицательными. Пример: `[-10, 9, 20, null, null, 15, 7]` → 42 (15 → 20 → 7). [Задача на LeetCode](https://leetcode.com/problems/binary-tree-maximum-path-sum/)

#solution
Лучший путь где-то «перегибается» в верхнем узле: из него идёт вниз до двух ветвей. Рекурсия возвращает лучший путь **вниз** из узла — только одну ветвь, потому что родитель может продолжить путь лишь через одну. А ответ — путь через узел с обеими ветвями — обновляем во внешней переменной. Отрицательные ветви не берём.

```ts
function maxPathSum(root: TreeNode | null): number {
  let best = -Infinity;
  // возвращает лучший путь, идущий вниз от node; ответ — путь через node с двумя ветвями
  const down = (node: TreeNode | null): number => {
    if (!node) return 0;
    const left = Math.max(0, down(node.left));    // отрицательную ветвь не берём
    const right = Math.max(0, down(node.right));
    best = Math.max(best, node.val + left + right);
    return node.val + Math.max(left, right);
  };
  down(root);
  return best;
}
```

O(n). Начальное `-Infinity`, а не 0: если все значения отрицательные, ответ — самое большое из них (`[-3]` → −3). В проверке ответ совпал с перебором путей между всеми парами узлов. Тот же приём «вернуть одно, а ответ хранить снаружи» решает диаметр дерева.
::

::practice{title="173. Binary Search Tree Iterator"}
Итератор по BST в порядке возрастания: `next()` возвращает следующее число, `hasNext()` — есть ли ещё. Обе операции в среднем O(1), память O(h). [Задача на LeetCode](https://leetcode.com/problems/binary-search-tree-iterator/)

#solution
Симметричный обход с явным стеком, разрезанный на шаги. В стеке — путь к следующему наименьшему: всю левую ветвь кладём сразу, а после выдачи узла — левую ветвь его правого поддерева.

```ts
class BSTIterator {
  private stack: TreeNode[] = [];

  constructor(root: TreeNode | null) {
    this.pushLeft(root);
  }
  private pushLeft(node: TreeNode | null): void {
    for (; node; node = node.left) this.stack.push(node);
  }
  next(): number {
    const node = this.stack.pop()!;
    this.pushLeft(node.right);
    return node.val;
  }
  hasNext(): boolean {
    return this.stack.length > 0;
  }
}
```

Каждый узел один раз кладётся и снимается — n операций на n вызовов, O(1) в среднем. Память O(h) вместо O(n) у варианта «обойти всё в массив». В JavaScript то же самое красиво пишется генератором ([Итераторы и генераторы](/content/javascript/iterators-and-generators)).
::

::practice{title="222. Count Complete Tree Nodes"}
Посчитать узлы **полного** дерева — все уровни, кроме последнего, заполнены, а последний заполнен слева. Быстрее, чем O(n). [Задача на LeetCode](https://leetcode.com/problems/count-complete-tree-nodes/)

#solution
Если высота по самой левой и самой правой ветви совпадает, дерево совершенное, и узлов `2^h - 1`. Иначе считаем рекурсивно — но одно из двух поддеревьев полного дерева всегда совершенное и посчитается сразу:

```ts
function countNodes(root: TreeNode | null): number {
  if (!root) return 0;
  let leftHeight = 0;
  let rightHeight = 0;
  for (let n: TreeNode | null = root; n; n = n.left) leftHeight++;
  for (let n: TreeNode | null = root; n; n = n.right) rightHeight++;
  if (leftHeight === rightHeight) return 2 ** leftHeight - 1;    // совершенное дерево
  return 1 + countNodes(root.left) + countNodes(root.right);
}
```

O(log² n): на каждом из log n уровней рекурсии измеряем высоту за O(log n). В проверке ответ совпал с n для полных деревьев от 0 до 200 узлов.
::

::practice{title="236. Lowest Common Ancestor of a Binary Tree"}
Найти наименьшего общего предка двух узлов `p` и `q` — самый глубокий узел, у которого оба в поддереве; узел считается предком самого себя. Пример: в `[3, 5, 1, 6, 2, 0, 8, null, null, 7, 4]` предок 5 и 1 — 3, а 5 и 4 — 5. [Задача на LeetCode](https://leetcode.com/problems/lowest-common-ancestor-of-a-binary-tree/)

#solution
Функция возвращает `p`, `q` или их предка, если найдены в поддереве, иначе `null`. Если из левого и правого поддеревьев пришло что-то непустое, `p` и `q` по разные стороны, и текущий узел — их предок. Если только с одной стороны — передаём это вверх.

```ts
function lowestCommonAncestor(root: TreeNode | null, p: TreeNode, q: TreeNode): TreeNode | null {
  if (!root || root === p || root === q) return root;
  const left = lowestCommonAncestor(root.left, p, q);
  const right = lowestCommonAncestor(root.right, p, q);
  if (left && right) return root;                 // p и q по разные стороны
  return left ?? right;
}
```

O(n). Если `p` — предок `q`, функция вернёт `p`, не спускаясь ниже, — и это правильный ответ. В проверке результат совпал с поиском первого общего узла на путях от `p` и `q` к корню. В BST предка находят быстрее — по значениям, без обхода всего дерева.
::

---

## Красные флаги в ответе

- **Рекурсия без базового случая для `null`** или проверка суммы пути в `null` вместо листа.
- **Поиск индекса в симметричном обходе через `indexOf` при построении дерева.** Это O(n²); нужна `Map`.
- **«Рекурсия по дереву — O(1) памяти».** Стек вызовов — O(высоты), на вытянутом дереве O(n).
- **Сравнение деревьев по обходу без `null`.** Разные деревья дают одинаковую последовательность.
- **Ответ и возвращаемое значение рекурсии путаются.** В максимальном пути возвращают одну ветвь, а ответ считают с двумя.

## Как спрашивают на собеседовании

::question
Какие бывают обходы двоичного дерева и чем они отличаются?

#answer
В глубину — прямой (корень, левое, правое), симметричный (левое, корень, правое) и обратный (левое, правое, корень) — и в ширину, по уровням. Прямой удобен для копирования и сериализации, симметричный обходит BST по возрастанию, обратный — когда ответ узла зависит от ответов детей, например при удалении или подсчёте размеров.

#more
Все обходы — O(n) по времени. В глубину — O(h) памяти на стек, в ширину — O(ширины уровня) на очередь. Рекурсию заменяют явным стеком, если дерево может быть глубоким. Обход Морриса делает симметричный обход за O(1) памяти, временно меняя ссылки дерева.
::

::question
Как восстановить дерево по двум обходам?

#answer
По прямому и симметричному: первый элемент прямого — корень, его позиция в симметричном делит остальные на левое и правое поддеревья. Рекурсивно строим левое, затем правое, беря корни из прямого обхода по порядку. Позиции в симметричном обходе кладут в `Map`, чтобы искать за O(1). Итог O(n).

#more
По симметричному и обратному — то же, но корни берутся с конца обратного обхода, и сначала строится правое поддерево. По прямому и обратному без симметричного дерево однозначно не восстанавливается. Значения должны быть уникальными.
::

::question
Как найти наименьшего общего предка двух узлов?

#answer
Рекурсией: функция возвращает найденный узел `p` или `q` (или их предка) из поддерева, иначе `null`. Если и левое, и правое поддерево вернули не `null`, `p` и `q` по разные стороны, и текущий узел — предок. Иначе передаём вверх то, что нашлось. O(n) по времени, O(h) по памяти.

#more
Если у узлов есть ссылки на родителей, задача сводится к пересечению двух списков: поднять оба указателя до одной глубины и идти вверх вместе. В BST предка ищут по значениям: если оба меньше узла — влево, оба больше — вправо, иначе нашли. Для множества запросов — двоичный подъём за O(log n) на запрос.
::

::question
Как найти максимальную сумму пути в дереве?

#answer
Рекурсия возвращает лучшую сумму пути, идущего вниз из узла, — значение узла плюс большая из неотрицательных ветвей. А ответ — путь, который перегибается в узле, — это значение узла плюс обе неотрицательные ветви; его обновляют во внешней переменной. O(n).

#more
Разделение «что вернуть родителю» и «что считать ответом» — общий приём: так же считают диаметр дерева (длина пути через узел — сумма глубин детей). Начальное значение ответа — `-Infinity`, иначе дерево из отрицательных чисел даст 0.
::
