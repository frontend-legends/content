# Интервалы

Интервал — пара «начало и конец»: время встречи, диапазон дат, отрезок на прямой, бронь переговорки. Задачи на интервалы почти всегда начинаются с сортировки, а дальше один проход решает слияние, вставку, поиск пересечений или минимальное число точек, покрывающих все отрезки. Спрашивают слияние пересекающихся интервалов, вставку нового, сводку диапазонов и задачу про стрелы и шарики — пример жадного алгоритма.

::tldr
- **Сначала сортировка по началу:** после неё пересекающиеся интервалы стоят рядом, и слияние делается одним проходом за O(n log n).
- **Два отрезка `[a1, b1]` и `[a2, b2]` пересекаются, если `a1 <= b2` и `a2 <= b1`.** Касание концами — тоже пересечение, если граница включена.
- **Вставка в уже отсортированный список — O(n) без сортировки:** интервалы левее, сливающиеся с новым, правее.
- **Минимум точек, протыкающих все интервалы, — жадно по концам:** сортировка по концу и точка в конец первого непроткнутого интервала.
- **Внимательно с границами:** включены ли концы, что делать с вложенными интервалами, и не мутировать ли входной массив сортировкой.
::

## Как узнать паттерн

- Вход — список пар `[start, end]`: встречи, брони, диапазоны.
- Нужно **слить**, **вставить**, **пересечь** интервалы или посчитать **перекрытия**.
- Нужно **минимальное число** чего-то, что покрывает все интервалы: стрелы, переговорки, точки.
- Есть отсортированные числа, которые надо свернуть в **диапазоны**.

Для вопроса «сколько интервалов перекрывается в самой загруженной точке» (сколько нужно переговорок) удобнее **метод событий**: разложить интервалы на события «начало +1» и «конец −1», отсортировать и пройти со счётчиком. Для динамических вставок и запросов есть деревья интервалов и отрезков ([Структуры данных](/content/algorithms-data-structures/data-structures)).

## Шаблон

Проверка пересечения двух отрезков с включёнными концами:

```ts
function overlaps([a1, b1]: number[], [a2, b2]: number[]): boolean {
  return a1 <= b2 && a2 <= b1;                    // начало каждого не позже конца другого
}
```

Проще рассуждать от противного: отрезки не пересекаются, если один целиком левее другого — `b1 < a2` или `b2 < a1`. Отрицание этого — условие выше.

Общая схема: отсортировать по началу и идти слева направо, держа «текущий» интервал. Следующий либо пересекается с ним — тогда текущий расширяется, — либо начинается правее — тогда текущий закрыт и начинается новый. Сортировка O(n log n), проход O(n).

Сортировка в JavaScript меняет исходный массив, поэтому в функциях ниже копируют вход — `[...intervals].sort(...)` — или берут `toSorted`.

::practice{title="228. Summary Ranges"}
Дан отсортированный массив уникальных целых чисел. Свернуть его в наименьший список диапазонов: `"a->b"` для отрезка из нескольких подряд идущих чисел и `"a"` для одиночного. Пример: `[0, 1, 2, 4, 5, 7]` → `["0->2", "4->5", "7"]`. [Задача на LeetCode](https://leetcode.com/problems/summary-ranges/)

#solution
Запоминаем начало диапазона и двигаемся, пока следующее число ровно на единицу больше текущего:

```ts
function summaryRanges(nums: number[]): string[] {
  const result: string[] = [];
  for (let i = 0; i < nums.length; i++) {
    const start = nums[i];
    while (i + 1 < nums.length && nums[i + 1] === nums[i] + 1) i++;
    result.push(start === nums[i] ? `${start}` : `${start}->${nums[i]}`);
  }
  return result;
}
```

O(n) по времени. Проверка `nums[i + 1] === nums[i] + 1`, а не `nums[i + 1] - nums[i] === 1`, — в языках с 32-битными целыми разность у границ диапазона переполняется; в JavaScript числа — `double`, и обе записи безопасны до 2^53. В проверке развёрнутые обратно диапазоны совпали с исходным массивом.
::

::practice{title="56. Merge Intervals"}
Слить все пересекающиеся интервалы и вернуть непересекающиеся, покрывающие те же точки. Пример: `[[1, 3], [2, 6], [8, 10], [15, 18]]` → `[[1, 6], [8, 10], [15, 18]]`; `[[1, 4], [4, 5]]` → `[[1, 5]]`. [Задача на LeetCode](https://leetcode.com/problems/merge-intervals/)

#solution
После сортировки по началу интервал пересекается только с последним слитым — если его начало не правее конца последнего. Тогда расширяем конец, иначе начинаем новый:

```ts
function merge(intervals: number[][]): number[][] {
  const sorted = [...intervals].sort((a, b) => a[0] - b[0]);
  const result: number[][] = [];
  for (const [start, end] of sorted) {
    const last = result.at(-1);
    if (last && start <= last[1]) last[1] = Math.max(last[1], end);   // пересекается — расширяем
    else result.push([start, end]);
  }
  return result;
}
```

O(n log n) по времени. `Math.max` обязателен: вложенный интервал `[2, 3]` внутри `[1, 4]` не должен укоротить конец до 3. Ошибка — сортировать без компаратора: интервалы — массивы и превратятся в строки `"10,16"` и `"2,8"`. В проверке слияние покрывало те же точки, что и вход, а результат шёл по возрастанию без пересечений.
::

::practice{title="57. Insert Interval"}
Дан отсортированный по началу список непересекающихся интервалов и новый интервал. Вставить новый, слив его с пересекающимися, чтобы список остался отсортированным и без пересечений. Пример: `[[1, 3], [6, 9]]` и `[2, 5]` → `[[1, 5], [6, 9]]`. [Задача на LeetCode](https://leetcode.com/problems/insert-interval/)

#solution
Список уже отсортирован, поэтому сортировка не нужна — три прохода по частям: интервалы целиком левее нового, интервалы, пересекающиеся с ним (сливаются в один), и интервалы целиком правее.

```ts
function insert(intervals: number[][], newInterval: number[]): number[][] {
  const result: number[][] = [];
  let [start, end] = newInterval;
  let i = 0;
  while (i < intervals.length && intervals[i][1] < start) result.push(intervals[i++]);   // целиком левее
  while (i < intervals.length && intervals[i][0] <= end) {                                // пересекаются — сливаем
    start = Math.min(start, intervals[i][0]);
    end = Math.max(end, intervals[i][1]);
    i++;
  }
  result.push([start, end]);
  while (i < intervals.length) result.push(intervals[i++]);                               // целиком правее
  return result;
}
```

O(n) по времени. В проверке результат совпал с «добавить и слить заново» на случайных списках. Сравнение `intervals[i][1] < start` строгое: интервал `[1, 2]` и новый `[2, 3]` касаются и должны слиться.
::

::practice{title="452. Minimum Number of Arrows to Burst Balloons"}
Шарики — отрезки `[xstart, xend]` на прямой. Стрела, выпущенная вертикально в точке `x`, лопает все шарики с `xstart <= x <= xend`. Найти минимальное число стрел, чтобы лопнуть все. Пример: `[[10, 16], [2, 8], [1, 6], [7, 12]]` → 2. [Задача на LeetCode](https://leetcode.com/problems/minimum-number-of-arrows-to-burst-balloons/)

#solution
Жадно: сортируем по концу. Шарик, который кончается раньше всех, надо лопнуть хоть чем-то, и лучшая точка для этой стрелы — его конец: она заденет максимум шариков, начавшихся до неё. Следующая стрела нужна только для шарика, который начинается правее последнего выстрела.

```ts
function findMinArrowShots(points: number[][]): number {
  const sorted = [...points].sort((a, b) => a[1] - b[1]);   // по концу
  let arrows = 0;
  let shot = -Infinity;
  for (const [start, end] of sorted) {
    if (start > shot) {                           // текущая стрела не задевает — новая, в конец шарика
      arrows++;
      shot = end;
    }
  }
  return arrows;
}
```

O(n log n) по времени. Сортировка по началу тоже решает задачу, но тогда приходится сжимать конец текущей группы `Math.min` — легко ошибиться. В проверке ответ совпал с перебором всех наборов точек-концов. Та же жадная идея — «выбирать то, что кончается раньше» — решает задачу о максимальном числе непересекающихся встреч.
::

---

## Красные флаги в ответе

- **Слияние без сортировки или сортировка без компаратора.** Пересекающиеся интервалы оказываются не рядом, а массивы сравниваются как строки.
- **Новый конец без `Math.max`.** Вложенный интервал укорачивает уже слитый.
- **Строгое сравнение там, где границы включены.** `[1, 4]` и `[4, 5]` касаются и сливаются.
- **Сортировка во вставке в уже отсортированный список.** Это O(n log n) вместо O(n).
- **«Жадно — значит, правильно».** Жадный выбор надо обосновать: почему стрела в конец самого раннего шарика не хуже любой другой.

## Как спрашивают на собеседовании

::question
Как слить пересекающиеся интервалы и какая сложность?

#answer
Отсортировать по началу, затем идти слева направо: если начало очередного интервала не больше конца последнего слитого, расширить его конец до максимума, иначе добавить новый. Сортировка O(n log n), проход O(n).

#more
После сортировки интервал может пересекаться только с последним слитым: все более ранние кончаются раньше. `Math.max` нужен для вложенных интервалов. Если на вход приходит поток интервалов и нужно поддерживать слитое множество, используют упорядоченную структуру — дерево — с поиском соседей за O(log n).
::

::question
Как понять, сколько переговорок нужно для списка встреч?

#answer
Методом событий: каждое начало — `+1`, каждый конец — `−1`, события сортируются по времени, и при равном времени конец идёт раньше начала. Проход со счётчиком даёт максимум одновременных встреч — это и есть число переговорок. O(n log n).

#more
Другой способ — сортировка по началу и мин-куча концов занятых переговорок: если самая ранняя освободится до начала новой встречи, переиспользуем её. Порядок «конец раньше начала» при равном времени важен: встреча до 10:00 и встреча с 10:00 не конфликтуют. Тот же счётчик событий отвечает на вопрос «сколько пользователей онлайн одновременно».
::

::question
Почему в задаче про стрелы сортируют по концу?

#answer
Шарик с самым ранним концом надо лопнуть, и стрела в его конец — лучший выбор: любая другая стрела для него левее и задевает не больше шариков. После этого выбрасываем все шарики, которые эта стрела задела, и повторяем. Сортировка по концу делает этот выбор одним проходом.

#more
Это классическое доказательство жадного алгоритма заменой: оптимальное решение можно перестроить так, чтобы первая стрела стояла в конце самого раннего шарика, не увеличив число стрел. Та же схема решает задачу о выборе максимального числа непересекающихся интервалов: берём тот, что кончается раньше.
::
