# Битовые операции

Задачи на биты проверяют, умеет ли кандидат смотреть на число как на набор битов. Почти все решения держатся на нескольких свойствах: `x ^ x = 0`, `x & (x - 1)` сбрасывает младшую единицу, сдвиг — умножение или деление на 2. С ними поиск одиночного числа среди пар занимает одну строку, а подсчёт единиц — столько шагов, сколько единиц. В JavaScript есть своя ловушка: побитовые операторы работают с 32-битными целыми со знаком.

::tldr
- **XOR сокращает пары:** `x ^ x = 0`, `x ^ 0 = x`, порядок не важен. XOR всех чисел, где все кроме одного встречаются дважды, — это одиночное число.
- **`x & (x - 1)` сбрасывает младшую единицу,** `x & -x` оставляет только её. Отсюда подсчёт единиц и проверка степени двойки.
- **Бит i — `(x >> i) & 1`,** установить — `x | (1 << i)`, сбросить — `x & ~(1 << i)`.
- **В JavaScript побитовые операторы приводят к 32-битному целому со знаком:** старший бит становится знаком. `>>> 0` читает те же биты как беззнаковое число.
- **Если пары не помогают, считают биты по модулю:** для «все по три раза, одно — один» сумма каждого бита по модулю 3 — бит ответа.
::

## Как узнать паттерн

- В условии **«каждый элемент встречается дважды (трижды), кроме одного»** и просьба O(1) памяти.
- Работа с **двоичным представлением**: число единиц, разворот битов, двоичные строки.
- **Множество из малого числа элементов** (до 20–30) — его удобно хранить битовой маской.
- Операции **AND, OR, XOR над диапазоном** или над всеми парами.

Как числа хранятся в битах, дополнительный код, приведение к 32 битам в JavaScript и битовые флаги — в [Представлении данных](/content/computer-science/data-representation). Здесь — приёмы для задач.

## Шаблон

Основные операции с битами:

```ts
const getBit = (x: number, i: number) => (x >> i) & 1;
const setBit = (x: number, i: number) => x | (1 << i);
const clearBit = (x: number, i: number) => x & ~(1 << i);
const dropLowest = (x: number) => x & (x - 1);    // сбросить младшую единицу
const lowest = (x: number) => x & -x;             // оставить только младшую единицу
const isPowerOfTwo = (x: number) => x > 0 && (x & (x - 1)) === 0;
```

Почему `x & (x - 1)` сбрасывает младшую единицу: вычитание единицы превращает младшую единицу в 0, а все нули правее неё — в 1. Например, `10100 - 1 = 10011`, и `10100 & 10011 = 10000`. Степень двойки — ровно одна единица, поэтому после сброса остаётся 0. `-x` в дополнительном коде — `~x + 1`, и с `x` у него совпадает только младшая единица.

::practice{title="67. Add Binary"}
Сложить два числа, записанных двоичными строками. Пример: `"11" + "1"` → `"100"`; `"1010" + "1011"` → `"10101"`. [Задача на LeetCode](https://leetcode.com/problems/add-binary/)

#solution
Сложение столбиком с конца: сумма двух битов и переноса — от 0 до 3; младший бит идёт в результат, старший — в перенос:

```ts
function addBinary(a: string, b: string): string {
  let result = '';
  let carry = 0;
  for (let i = a.length - 1, j = b.length - 1; i >= 0 || j >= 0 || carry; i--, j--) {
    const sum = (i >= 0 ? +a[i] : 0) + (j >= 0 ? +b[j] : 0) + carry;
    result = (sum & 1) + result;                  // младший бит суммы
    carry = sum >> 1;                             // перенос
  }
  return result;
}
```

O(max(m, n)). `parseInt(a, 2) + parseInt(b, 2)` ломается на строках длиннее 53 бит — точность `double` кончается. `BigInt('0b' + a)` работает, но на собеседовании ждут столбик. Приписывание в начало строки на каждом шаге формально O(n²); для длинных строк собирают массив и разворачивают. В проверке результат совпал с `BigInt` на строках до 60 бит.
::

::practice{title="190. Reverse Bits"}
Развернуть порядок битов 32-битного беззнакового числа. Пример: `00000010100101000001111010011100` → `00111001011110000010100101000000`, то есть 43261596 → 964176192. [Задача на LeetCode](https://leetcode.com/problems/reverse-bits/)

#solution
32 раза снимаем младший бит `n` и дописываем его справа к результату:

```ts
function reverseBits(n: number): number {
  let result = 0;
  for (let i = 0; i < 32; i++) {
    result = (result << 1) | (n & 1);             // взять младший бит n и дописать справа
    n >>>= 1;
  }
  return result >>> 0;                            // в беззнаковое: иначе старший бит даст минус
}
```

O(32). Две JavaScript-ловушки: сдвигать `n` нужно `>>>`, иначе знаковый `>>` размножит старший бит, а результат — привести `>>> 0`, иначе число с единицей в старшем бите выйдет отрицательным. Если функцию вызывают много раз, разворачивают по байтам с таблицей из 256 заранее развёрнутых значений. В проверке ответ совпал с разворотом строки из 32 символов.
::

::practice{title="191. Number of 1 Bits"}
Посчитать единицы в двоичной записи положительного числа (вес Хэмминга). Пример: 11 (`1011`) → 3; 2147483645 → 30. [Задача на LeetCode](https://leetcode.com/problems/number-of-1-bits/)

#solution
`n & (n - 1)` сбрасывает младшую единицу — итераций столько, сколько единиц, а не 32:

```ts
function hammingWeight(n: number): number {
  let count = 0;
  while (n !== 0) {
    n &= n - 1;                                   // каждая итерация сбрасывает одну единицу
    count++;
  }
  return count;
}
```

O(число единиц). Простой вариант — 32 раза проверить младший бит и сдвинуть. Цикл `while (n !== 0)` со знаковым сдвигом `>>` на отрицательном числе не кончится: сдвиг размножает знаковую единицу. Во многих процессорах есть отдельная инструкция подсчёта единиц, но в JavaScript её нет — есть только `Math.clz32` для подсчёта ведущих нулей.
::

::practice{title="136. Single Number"}
Каждый элемент массива встречается дважды, кроме одного. Найти его за O(n) и O(1) памяти. Пример: `[4, 1, 2, 1, 2]` → 4. [Задача на LeetCode](https://leetcode.com/problems/single-number/)

#solution
XOR коммутативен и ассоциативен, `x ^ x = 0`, `x ^ 0 = x`. В XOR всех чисел пары сокращаются, и остаётся одиночное:

```ts
function singleNumber(nums: number[]): number {
  return nums.reduce((acc, x) => acc ^ x, 0);     // пары сокращаются: x ^ x = 0
}
```

O(n), O(1). С `Set` или подсчётом в `Map` тоже O(n), но O(n) памяти. Числа в задаче — 32-битные целые; для чисел вне этого диапазона XOR в JavaScript их обрежет. Вариант задачи — два одиночных числа (260): XOR всех даёт `a ^ b`, любой его единичный бит различает `a` и `b`, и по нему числа делят на две группы.
::

::practice{title="137. Single Number II"}
Каждый элемент встречается трижды, кроме одного, который встречается один раз. Найти его за O(n) и O(1) памяти. Пример: `[2, 2, 3, 2]` → 3; `[0, 1, 0, 1, 0, 1, 99]` → 99. [Задача на LeetCode](https://leetcode.com/problems/single-number-ii/)

#solution
XOR не поможет: тройка не сокращается. Но если сложить i-е биты всех чисел, тройки дадут кратное 3, и остаток от деления на 3 — i-й бит ответа. Это можно посчитать 32 проходами, а можно одним — держа счётчик по модулю 3 для всех битов сразу в двух масках: `ones` — биты, встреченные 1 раз, `twos` — 2 раза. На третьей встрече бит сбрасывается из обеих:

```ts
function singleNumberII(nums: number[]): number {
  let ones = 0;                                   // биты, встреченные 1 раз (по модулю 3)
  let twos = 0;                                   // биты, встреченные 2 раза
  for (const x of nums) {
    ones = (ones ^ x) & ~twos;
    twos = (twos ^ x) & ~ones;
  }
  return ones;
}
```

O(n), O(1). Каждый бит проходит состояния 0 → `ones` → `twos` → 0. Решение работает и для отрицательных чисел: знаковый бит считается так же, а результат в 32-битном представлении сразу со знаком. Если не получается вывести маски на собеседовании, вариант с 32 проходами по битам тоже принимают. В проверке одиночное число нашлось на тысяче перемешанных массивов с числами во всём 32-битном диапазоне.
::

::practice{title="201. Bitwise AND of Numbers Range"}
Вернуть побитовое AND всех чисел от `left` до `right` включительно, где `0 ≤ left ≤ right ≤ 2^31 − 1`. Пример: `5, 7` → 4. [Задача на LeetCode](https://leetcode.com/problems/bitwise-and-of-numbers-range/)

#solution
Перебор по диапазону до двух миллиардов слишком долог. Если в каком-то разряде `left` и `right` различаются, то между ними есть число, где этот разряд и все младшие меняются — значит, в AND они станут нулями. Остаётся общий двоичный префикс:

```ts
function rangeBitwiseAnd(left: number, right: number): number {
  let shift = 0;
  while (left !== right) {                        // ответ — общий двоичный префикс
    left >>= 1;
    right >>= 1;
    shift++;
  }
  return left << shift;
}
```

O(32). Для `5 = 101` и `7 = 111` общий префикс `1`, ответ `100` = 4. Другой вариант — сбрасывать младшую единицу `right`, пока он больше `left`: `right &= right - 1`. В проверке ответ совпал с AND по всему диапазону.
::

## Красные флаги в ответе

- **`>>` вместо `>>>` для беззнаковых чисел** в JavaScript — знак размножается, цикл не кончается.
- **`parseInt` для длинной двоичной строки.** Точность теряется после 53 бит.
- **`Map` или `Set` там, где просят O(1) памяти** в задаче про одиночное число.
- **Перебор диапазона** в задаче про AND диапазона.
- **Не уметь объяснить `x & (x - 1)`** — его часто просят расписать на примере.

## Как спрашивают на собеседовании

::question
Как найти единственное число без пары?

#answer
XOR всех элементов: одинаковые числа дают 0, ноль не меняет XOR, а порядок не важен, поэтому остаётся одиночное число. O(n) по времени, O(1) по памяти.

#more
Если одиночных два, XOR всех даёт `a ^ b`; берут любой единичный бит (например, `x & -x`) и делят числа на две группы по этому биту — в каждой группе одно одиночное. Если остальные встречаются трижды, считают каждый бит по модулю 3. Пропущенное число в `0..n` находят так же: XOR индексов и значений.
::

::question
Что делает `x & (x - 1)` и где это применяют?

#answer
Сбрасывает младшую единицу числа: вычитание единицы меняет младшую единицу на 0, а нули правее неё — на 1, и AND оставляет только старшие разряды. Применения: подсчёт единиц за число единиц итераций, проверка степени двойки (`x > 0 && (x & (x - 1)) === 0`), перебор подмножеств маски.

#more
Парный приём — `x & -x`: оставляет только младшую единицу. На нём построено дерево Фенвика: переход к следующему отрезку — прибавить или вычесть младшую единицу индекса. Перебор всех подмасок маски `m`: `for (s = m; s; s = (s - 1) & m)`.
::

::question
Какие особенности побитовых операций в JavaScript?

#answer
Все побитовые операторы, кроме `>>>`, приводят операнды к 32-битному целому со знаком — числа больше 2^31 − 1 переходят в отрицательные, а старше 32 бит отбрасываются. `>>>` даёт беззнаковое 32-битное число, и `x >>> 0` — способ прочитать биты без знака. Для произвольной длины есть `BigInt`, у которого свои побитовые операторы без ограничения разрядности.

#more
Из-за этого `~~x` и `x | 0` как замена `Math.trunc` ломаются на временных метках в миллисекундах. В задачах это значит: для 32-битных чисел всё работает, а результат с единицей в старшем бите надо привести `>>> 0`, если ждут беззнаковый.
::
