# Подходы к решению задач

Алгоритмическая задача на собеседовании проверяет не память на решения, а умение прийти к решению: по ограничениям понять, какая сложность нужна, по формулировке узнать паттерн, начать с перебора и улучшать его, а потом убедиться, что код правильный. Эта тема собирает главу в одну карту: какие сигналы в условии ведут к какому приёму, как превратить перебор в линейное решение, как проверить решение стресс-тестом и какие ловушки JavaScript ломают правильные алгоритмы. Общий порядок работы над задачей — уточнить, привести примеры, решить, проверить — разобран в [Как подходить к любой задаче](/content/common-coding-questions/how-to-approach).

::tldr
- **Ограничения подсказывают сложность:** n до 20 — перебор подмножеств, до 10⁴ — O(n²), до 10⁵–10⁶ — O(n log n) или O(n), больше — O(log n) или формула.
- **Формулировка подсказывает паттерн:** «отсортированный массив» — два указателя или двоичный поиск, «подотрезок» — окно или префиксные суммы, «все варианты» — перебор с возвратом, «число способов» — динамика.
- **Начинают с перебора и ищут в нём повторную работу:** её убирают хеш-таблицей, сортировкой, предподсчётом или запоминанием.
- **Правильность проверяют стресс-тестом:** быстрое решение сравнивают с перебором на тысячах маленьких случайных входов — расхождение сразу даёт короткий контрпример.
- **JavaScript добавляет свои ловушки:** `sort` без компаратора сравнивает строки, `Math.min(...arr)` падает на больших массивах, `shift` — O(n), рекурсия упирается в стек, а числа точны только до 2^53.
::

## От ограничений к сложности

Ограничения на размер входа — главная подсказка, о которой часто забывают. Грубый ориентир: за секунду проходит порядка 10⁸ простых операций, а дальше считают, какая сложность в это укладывается.

| Размер n | Допустимая сложность | Типичные приёмы |
| --- | --- | --- |
| до 10–12 | O(n!) | перестановки |
| до 20–25 | O(2^n) | подмножества, битовые маски |
| до 500 | O(n³) | тройные циклы, динамика по отрезкам |
| до 5 000–10 000 | O(n²) | пары, двумерная динамика |
| до 10⁵–10⁶ | O(n log n) или O(n) | сортировка, куча, двоичный поиск, два указателя, хеш-таблица |
| больше 10⁸ или само число | O(log n) или O(1) | двоичный поиск по ответу, формула, быстрое возведение в степень |

Если интервьюер не назвал ограничения, их стоит спросить — от ответа зависит, хватит ли простого решения.

## От перебора к оптимальному решению

Перебор — не провал, а начало: он фиксирует понимание задачи, служит эталоном для проверки и показывает, где лишняя работа. Дальше ищут, что перебор делает повторно, и убирают это одним из приёмов:

- **Запомнить увиденное** — хеш-таблица вместо внутреннего цикла поиска.
- **Отсортировать** — после сортировки работают два указателя, двоичный поиск и жадные проходы.
- **Предподсчитать** — префиксные суммы, максимумы слева и справа, таблицы позиций.
- **Не пересчитывать подзадачи** — мемоизация, а затем таблица динамики.
- **Отбросить заведомо лишнее** — двоичный поиск, отсечения в переборе, жадный выбор с обоснованием.

Пример: посчитать пары с суммой k. Перебор пар — O(n²):

```ts
function countPairsBrute(nums: number[], k: number): number {
  let count = 0;
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) if (nums[i] + nums[j] === k) count++;
  }
  return count;
}
```

Внутренний цикл ищет все `j`, где `nums[j] === k - nums[i]`. Если для каждого элемента помнить, сколько раз встречались числа слева, этот поиск — одно обращение к `Map`:

```ts
function countPairs(nums: number[], k: number): number {
  const seen = new Map<number, number>();         // сколько раз встречалось число слева
  let count = 0;
  for (const x of nums) {
    count += seen.get(k - x) ?? 0;                // все пары, где x — правый элемент
    seen.set(x, (seen.get(x) ?? 0) + 1);
  }
  return count;
}
```

O(n) по времени и памяти. В проверке на 100 000 элементов быстрая версия отработала за доли секунды — перебору понадобилось бы около 5 · 10⁹ сравнений.

## Проверка решения стресс-тестом

Самый надёжный способ найти ошибку в быстром решении — сравнить его с перебором на тысячах случайных входов. Перебор медленный, но его правильность очевидна. Входы начинают с маленьких: если ошибка есть, первый найденный контрпример будет коротким, и его легко разобрать руками:

```ts
function stressTest<I, O>(
  fast: (input: I) => O,
  slow: (input: I) => O,
  generate: (size: number) => I,
  rounds = 1000,
): I | null {
  for (let round = 0; round < rounds; round++) {
    const size = 1 + Math.floor(round / 100);     // сначала маленькие входы — контрпример будет коротким
    const input = generate(size);
    if (JSON.stringify(fast(input)) !== JSON.stringify(slow(input))) return input;
  }
  return null;                                    // расхождений не нашлось
}
```

Решение задачи о максимальной сумме подмассива с типичной ошибкой — ответ начинается с нуля:

```ts
function maxSubArrayBuggy(nums: number[]): number {
  let best = 0;
  let current = 0;
  for (const x of nums) {
    current = Math.max(x, current + x);
    best = Math.max(best, current);
  }
  return best;
}
```

Перебор для сравнения:

```ts
function maxSubArrayBrute(nums: number[]): number {
  let best = -Infinity;
  for (let i = 0; i < nums.length; i++) {
    let sum = 0;
    for (let j = i; j < nums.length; j++) best = Math.max(best, (sum += nums[j]));
  }
  return best;
}
```

В проверке стресс-тест сразу нашёл контрпример из одного отрицательного числа: для `[-3]` ошибочная версия вернула 0, а правильный ответ −3. После исправления тот же тест расхождений не нашёл. Все решения в этой главе проверены именно так — на примерах из условий и на случайных входах против перебора. На собеседовании полный стресс-тест писать некогда, но та же идея работает вручную: прогнать решение на крошечных и крайних входах — пустом, из одного элемента, из одинаковых, из отрицательных.

## Ловушки JavaScript в алгоритмах

Правильный алгоритм может сломаться на особенностях языка:

- **`sort()` без компаратора сравнивает строки:** `[10, 9, 1].sort()` даёт `[1, 10, 9]`. Для чисел — `sort((a, b) => a - b)` ([Объекты и массивы](/content/javascript/objects-and-arrays)).
- **`Math.min(...arr)` и `Math.max(...arr)` на больших массивах падают:** spread превращает элементы в аргументы, а их число ограничено. В проверке на миллионе элементов вызов бросил `RangeError`. Минимум ищут циклом или `reduce`.
- **`shift` и `unshift` — O(n):** очередь на них делает обход в ширину квадратичным ([Обход дерева в ширину](/content/algorithms-data-structures/binary-tree-bfs)).
- **Глубина рекурсии ограничена** — около десяти тысяч вызовов в Node.js ([Функции](/content/javascript/functions)). Обход в глубину по вытянутому дереву или длинной цепочке переписывают на явный стек.
- **Числа точны только до 2^53:** `2 ** 53 + 1 === 2 ** 53`. Большие произведения, факториалы и суммы по модулю считают в `BigInt` ([Представление данных](/content/computer-science/data-representation)).
- **Побитовые операторы работают с 32-битными целыми со знаком:** `(2 ** 31) | 0` — отрицательное число ([Битовые операции](/content/algorithms-data-structures/bit-manipulation)).
- **Строки неизменяемы:** изменение символа — новая строка. Для правок «на месте» работают с массивом символов, а длинный результат собирают массивом и `join`.

## Красные флаги в ответе

- **Сразу писать «оптимальное» решение,** не проговорив перебор и не проверив понимание задачи.
- **Не спросить ограничения** и потратить время на O(n log n), когда хватает O(n²), или наоборот.
- **Называть паттерн по одному слову условия,** не проверив его условия применимости — окно на отрицательных числах.
- **Проверить решение только на примере из условия.** Ошибки прячутся в пустом входе, одном элементе, повторах и отрицательных числах.
- **Не знать ловушек языка** — `sort` без компаратора, `Math.max(...arr)`, `shift` в очереди.

## Как спрашивают на собеседовании

::question
Как по ограничениям понять, какое решение нужно?

#answer
Оценить, сколько операций допустимо: грубо — около 10⁸ простых операций в секунду. При n до 20 проходит перебор подмножеств O(2^n), до нескольких тысяч — O(n²), до миллиона — O(n log n) или O(n). Если n — само число вроде 10¹⁸, нужен O(log n) или формула. Это сразу отсекает неподходящие подходы.

#more
Память тоже ограничена: таблица n × n при n = 10⁵ — 10¹⁰ ячеек, что не поместится. Если ограничения не названы, их уточняют у интервьюера — в реальных задачах это вопрос о масштабе данных.
::

::question
Как улучшить решение, если первым получился перебор?

#answer
Найти, что перебор делает повторно. Внутренний цикл поиска заменяется хеш-таблицей, повторный пересчёт сумм — префиксными суммами, повторное решение подзадач — мемоизацией. Если порядок не важен, сортировка открывает два указателя и двоичный поиск. Каждый шаг улучшения стоит проговорить вслух вместе со сложностью.

#more
Полезно назвать нижнюю границу: если ответ требует прочитать весь вход, быстрее O(n) не будет, и после O(n) улучшать имеет смысл только память. Если ответ сам экспоненциально велик, как все перестановки, разговор — об отсечениях, а не о полиноме.
::

::question
Как проверить, что решение правильное?

#answer
Прогнать на примерах из условия и на краевых: пустой вход, один элемент, все одинаковые, отрицательные, максимальные значения. Надёжнее — стресс-тест: сравнить быстрое решение с очевидным перебором на тысячах маленьких случайных входов. Первый найденный контрпример сразу показывает ошибку.

#more
Стресс-тест начинают с маленьких размеров: контрпример из двух-трёх элементов разбирается руками. Идея та же, что у тестирования на основе свойств — библиотеки вроде fast-check генерируют входы и уменьшают контрпример сами.
::

::question
Как узнать, какой паттерн применить?

#answer
По сигналам в условии: отсортированный массив — два указателя или двоичный поиск; подотрезок с условием — окно; поиск пары или подсчёт — хеш-таблица; вложенность — стек; кратчайший путь без весов — обход в ширину; все варианты — перебор с возвратом; число способов или оптимум с выбором — динамика. Дальше проверяют условия применимости приёма.

#more
Многие задачи сочетают приёмы: сортировка плюс два указателя, обход графа плюс куча, двоичный поиск по ответу плюс жадная проверка. Если паттерн не узнаётся, помогает решить задачу руками на маленьком примере и посмотреть, какую работу вы делаете повторно.
::

::question
Какие особенности JavaScript мешают в алгоритмических задачах?

#answer
`sort` без компаратора сравнивает строки, `shift` и `unshift` — O(n), `Math.max(...arr)` падает на больших массивах, рекурсия ограничена примерно десятью тысячами вызовов, числа точны до 2^53, а побитовые операции работают с 32-битными целыми. Нет встроенной кучи, дека и упорядоченного словаря — их пишут сами или обходятся массивом с указателем.

#more
Зато есть `Map` и `Set` с порядком вставки, `BigInt` для точной арифметики и типизированные массивы для компактных числовых данных. На собеседовании полезно сказать, что встроенной кучи нет, и спросить, можно ли считать, что она есть, — это экономит время.
::

## Практика

::practice{title="Найти ошибку стресс-тестом"}
Напишите функцию, которая сравнивает быстрое решение с перебором на случайных входах растущего размера и возвращает первый вход, на котором ответы разошлись. Проверьте ею решение максимальной суммы подмассива, где ответ начинается с нуля.

#solution
Функция `stressTest` из раздела выше. Применение:

```ts
const counterexample = stressTest(maxSubArrayBuggy, maxSubArrayBrute, (size) => randArray(size, -10, 10));
```

`randArray(size, lo, hi)` — массив случайных целых. Тест находит контрпример из одного отрицательного числа: ошибочная версия возвращает для него 0 — сумму пустого подмассива, который запрещён. Исправление — начинать с первого элемента, а не с нуля ([Алгоритм Кадане](/content/algorithms-data-structures/kadanes-algorithm)). Сравнение через `JSON.stringify` годится для чисел и массивов; если допустим любой из нескольких ответов, сравнивают не ответы, а их проверку — например, что найденная пара действительно даёт сумму.
::

::practice{title="Пары с суммой k"}
Посчитайте число пар индексов `i < j`, где `nums[i] + nums[j] === k`, за O(n). Пример: `[1, 5, 7, -1, 5]`, k = 6 → 3; `[1, 1, 1, 1]`, k = 2 → 6.

#solution
Решение `countPairs` из раздела «От перебора к оптимальному»: для каждого элемента прибавить, сколько раз слева встречалось `k - x`, затем учесть сам `x`. Порядок важен — если сначала добавить `x` в таблицу, при `k = 2x` элемент составит пару сам с собой. Во втором примере каждая из шести пар единиц считается ровно один раз: вторая единица добавляет 1, третья — 2, четвёртая — 3:

```ts
assert.equal(countPairs([1, 5, 7, -1, 5], 6), 3);
assert.equal(countPairs([1, 1, 1, 1], 2), 6);
```

В проверке результат совпал и с перебором на случайных входах.
::

::practice{title="Минимум миллиона чисел"}
`Math.min(...nums)` для массива из миллиона чисел бросает `RangeError`. Почему, и как найти минимум правильно?

#solution
Spread передаёт каждый элемент отдельным аргументом, а число аргументов вызова ограничено размером стека — миллион не помещается. Минимум ищут одним проходом:

```ts
function minOf(nums: number[]): number {
  let min = Infinity;
  for (const x of nums) if (x < min) min = x;
  return min;
}
```

O(n), без ограничения на размер. `nums.reduce((a, b) => (a < b ? a : b))` тоже работает, но бросает ошибку на пустом массиве без начального значения. Для пустого массива `minOf` возвращает `Infinity` — как и `Math.min()` без аргументов. В проверке на миллионе чисел `Math.min(...)` бросил `RangeError`, а цикл вернул тот же ответ, что `reduce`.
::
