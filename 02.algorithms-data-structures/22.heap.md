# Куча

Куча — двоичное дерево в массиве, где каждый родитель не больше своих детей (min-куча) или не меньше (max-куча). Она отдаёт минимум за O(1) и добавляет или снимает элемент за O(log n) — это и есть приоритетная очередь. Кучу берут, когда нужно «k лучших», «следующий по приоритету» или медиана потока. В JavaScript встроенной кучи нет, поэтому на собеседовании её пишут сами или договариваются, что она есть, — полезно уметь и то и другое.

::tldr
- **Куча хранится в массиве:** дети узла `i` — `2i + 1` и `2i + 2`, родитель — `(i - 1) >> 1`. Указатели не нужны.
- **Вставка — в конец и просеивание вверх, удаление вершины — последний на место корня и просеивание вниз.** Обе операции O(log n), вершина — O(1).
- **k наибольших держат в min-куче размера k:** на вершине — наименьший из лучших, его выбрасывают, когда приходит больший. O(n log k) вместо O(n log n) сортировки.
- **Медиана потока — две кучи:** max-куча меньшей половины и min-куча большей; их вершины — середина.
- **Куча не отсортирована:** быстро доступен только минимум, поиск произвольного элемента — O(n).
::

---

## Как узнать паттерн

- Нужно **k наибольших, наименьших или ближайших** — «top k», «k-й по величине».
- Нужно многократно брать **лучший из доступных** элементов, а набор доступных меняется: жадные алгоритмы, расписания, Дейкстра.
- **Слияние** k отсортированных источников.
- **Медиана** или другая порядковая статистика потока данных.

Если k-й элемент нужен один раз, а массив можно менять, есть быстрый выбор (quickselect) — O(n) в среднем ([Сортировка](/content/algorithms-data-structures/sorting)). Устройство кучи как структуры, пирамидальная сортировка и другие виды куч — в [Структурах данных](/content/algorithms-data-structures/data-structures).

## Шаблон

Двоичная куча с компаратором: `before(a, b)` истинно, если `a` должен быть ближе к вершине. `(a, b) => a < b` — min-куча, `(a, b) => a > b` — max-куча.

```ts
class Heap<T> {
  private items: T[] = [];

  constructor(private before: (a: T, b: T) => boolean) {}   // true — a ближе к вершине

  get size(): number {
    return this.items.length;
  }

  peek(): T | undefined {
    return this.items[0];
  }

  push(value: T): void {
    const a = this.items;
    a.push(value);
    let i = a.length - 1;
    while (i > 0) {                               // просеять вверх
      const parent = (i - 1) >> 1;
      if (!this.before(a[i], a[parent])) break;
      [a[i], a[parent]] = [a[parent], a[i]];
      i = parent;
    }
  }

  pop(): T | undefined {
    const a = this.items;
    if (a.length === 0) return undefined;
    const top = a[0];
    const last = a.pop()!;
    if (a.length > 0) {
      a[0] = last;
      let i = 0;
      for (;;) {                                  // просеять вниз
        const l = 2 * i + 1;
        const r = l + 1;
        let best = i;
        if (l < a.length && this.before(a[l], a[best])) best = l;
        if (r < a.length && this.before(a[r], a[best])) best = r;
        if (best === i) break;
        [a[i], a[best]] = [a[best], a[i]];
        i = best;
      }
    }
    return top;
  }
}
```

`push` и `pop` — O(log n): высота полного дерева. Просеивание вниз меняет узел с **лучшим** из детей — иначе свойство кучи нарушится между детьми. В проверке элементы, снятые из кучи по одному, всегда шли в отсортированном порядке — это пирамидальная сортировка.

::practice{title="215. Kth Largest Element in an Array"}
Найти k-й по величине элемент массива (не k-й различный). Можно ли без полной сортировки? Пример: `[3, 2, 1, 5, 6, 4], k = 2` → 5; `[3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4` → 4. [Задача на LeetCode](https://leetcode.com/problems/kth-largest-element-in-an-array/)

#solution
Держим min-кучу из k наибольших увиденных. Когда в ней становится k + 1 элемент, выбрасываем наименьший. В конце на вершине — наименьший из k наибольших, то есть k-й:

```ts
function findKthLargest(nums: number[], k: number): number {
  const heap = new Heap<number>((a, b) => a < b); // min-куча из k наибольших
  for (const x of nums) {
    heap.push(x);
    if (heap.size > k) heap.pop();                // выбросить наименьший
  }
  return heap.peek()!;
}
```

O(n log k) по времени, O(k) по памяти. Min-куча, а не max: нужен быстрый доступ к самому слабому из лучших, чтобы его заменить. Быстрый выбор даёт O(n) в среднем, но O(n²) в худшем и меняет массив. В проверке ответ совпал с элементом отсортированного массива.
::

::practice{title="502. IPO"}
Есть начальный капитал `w` и проекты: проект `i` требует капитал `capital[i]` и приносит чистую прибыль `profits[i]`, которая добавляется к капиталу. Выбрать не больше `k` проектов, чтобы максимизировать итоговый капитал. Пример: `k = 2, w = 0, profits = [1, 2, 3], capital = [0, 1, 1]` → 4. [Задача на LeetCode](https://leetcode.com/problems/ipo/)

#solution
Жадно: на каждом шаге брать самый прибыльный из доступных — капитал только растёт, поэтому доступные проекты остаются доступными. Проекты сортируем по требуемому капиталу и по мере роста `w` перекладываем ставшие доступными в max-кучу прибылей:

```ts
function findMaximizedCapital(k: number, w: number, profits: number[], capital: number[]): number {
  const projects = capital.map((c, i) => [c, profits[i]]).sort((a, b) => a[0] - b[0]);
  const available = new Heap<number>((a, b) => a > b);   // max-куча прибылей доступных проектов
  let i = 0;
  for (let round = 0; round < k; round++) {
    while (i < projects.length && projects[i][0] <= w) available.push(projects[i++][1]);
    if (available.size === 0) break;              // ничего не по карману
    w += available.pop()!;
  }
  return w;
}
```

O(n log n) на сортировку и кучу. Жадность здесь верна: самый прибыльный доступный проект не хуже любого другого — он открывает не меньше новых проектов. В проверке ответ совпал с перебором всех порядков выбора на маленьких входах.
::

::practice{title="373. Find K Pairs with Smallest Sums"}
Даны два отсортированных массива. Вернуть k пар `[a, b]` (a из первого, b из второго) с наименьшими суммами. Пример: `[1, 7, 11], [2, 4, 6], k = 3` → `[1, 2], [1, 4], [1, 6]`. [Задача на LeetCode](https://leetcode.com/problems/find-k-pairs-with-smallest-sums/)

#solution
Суммы `nums1[i] + nums2[j]` образуют таблицу, где каждая строка `i` отсортирована по `j`. Это слияние отсортированных строк: в куче держим по текущему кандидату из строки, снимаем наименьший и кладём следующий элемент его строки. Сначала в куче — первые элементы первых `min(n, k)` строк:

```ts
function kSmallestPairs(nums1: number[], nums2: number[], k: number): number[][] {
  const heap = new Heap<[number, number, number]>((a, b) => a[0] < b[0]);   // [сумма, i, j]
  for (let i = 0; i < Math.min(nums1.length, k); i++) heap.push([nums1[i] + nums2[0], i, 0]);
  const result: number[][] = [];
  while (result.length < k && heap.size > 0) {
    const [, i, j] = heap.pop()!;
    result.push([nums1[i], nums2[j]]);
    if (j + 1 < nums2.length) heap.push([nums1[i] + nums2[j + 1], i, j + 1]);   // следующий в строке i
  }
  return result;
}
```

O(k log k): куча не больше k элементов, снимаем k раз. Строить все m · n пар и сортировать — O(mn log(mn)) при том, что нужно лишь k. Строк больше k не берут — в ответ они не попадут. При равных суммах допустим любой порядок; в проверке суммы совпали с k наименьшими из всех пар.
::

::practice{title="295. Find Median from Data Stream"}
Структура с `addNum(num)` и `findMedian()` — медиана всех добавленных чисел. Пример: после 1 и 2 медиана 1.5, после 3 — 2. [Задача на LeetCode](https://leetcode.com/problems/find-median-from-data-stream/)

#solution
Делим числа на две половины: меньшая — в max-куче `low`, большая — в min-куче `high`. Поддерживаем, что все в `low` не больше всех в `high`, а размер `low` равен размеру `high` или больше на один. Тогда медиана — вершина `low` или среднее двух вершин:

```ts
class MedianFinder {
  private low = new Heap<number>((a, b) => a > b);   // max-куча: меньшая половина
  private high = new Heap<number>((a, b) => a < b);  // min-куча: большая половина

  addNum(num: number): void {
    this.low.push(num);
    this.high.push(this.low.pop()!);              // наибольший из меньших — в большую половину
    if (this.high.size > this.low.size) this.low.push(this.high.pop()!);   // low больше на 0 или 1
  }

  findMedian(): number {
    if (this.low.size > this.high.size) return this.low.peek()!;
    return (this.low.peek()! + this.high.peek()!) / 2;
  }
}
```

`addNum` — O(log n), `findMedian` — O(1). Прогон через `low` в `high` гарантирует порядок между половинами без лишних сравнений, а последняя строка — баланс размеров. Отсортированный массив со вставкой — O(n) на вставку. В проверке медиана после каждого добавления совпала с медианой отсортированного префикса.
::

## Красные флаги в ответе

- **Сортировка всего массива ради k элементов.** O(n log n) вместо O(n log k).
- **Max-куча для k наибольших.** Придётся хранить все n элементов.
- **`array.sort()` после каждой вставки** как «приоритетная очередь» — O(n log n) на операцию.
- **Просеивание вниз с любым из детей**, а не с лучшим.
- **«Куча отсортирована».** Упорядочены только родитель и дети; поиск — O(n).

## Как спрашивают на собеседовании

::question
Как устроена двоичная куча и почему операции стоят O(log n)?

#answer
Это полное двоичное дерево, записанное в массив по уровням: дети узла `i` — `2i + 1` и `2i + 2`. Свойство кучи — родитель не больше детей (для min-кучи), поэтому минимум в корне. Вставка кладёт элемент в конец и поднимает, пока он меньше родителя; удаление ставит последний элемент в корень и опускает, меняя с меньшим из детей. Высота полного дерева — log n, отсюда O(log n).

#more
Построить кучу из массива можно за O(n), а не O(n log n): просеивать вниз узлы от середины к началу — большинство узлов внизу и опускаются недалеко. Пирамидальная сортировка — O(n log n) и O(1) памяти, но неустойчива и медленнее быстрой на практике из-за плохой локальности.
::

::question
Как найти k наибольших элементов в большом потоке?

#answer
Держать min-кучу размера k: каждый новый элемент добавить и, если размер стал k + 1, снять минимум. На вершине — k-й наибольший, а в куче — все k наибольших. O(n log k) по времени и O(k) по памяти — поток не нужно хранить целиком.

#more
Если все данные уже в памяти и нужен только k-й, быстрый выбор даёт O(n) в среднем. Для частых запросов «топ k» по меняющимся данным — сбалансированное дерево или отсортированная структура. Для приблизительного топа в огромных потоках используют вероятностные структуры вроде Count-Min Sketch.
::

::question
Как поддерживать медиану потока чисел?

#answer
Двумя кучами: max-куча хранит меньшую половину, min-куча — большую. Размеры отличаются не больше чем на один, и каждый элемент меньшей половины не больше любого из большей. Медиана — вершина большей кучи или среднее двух вершин. Вставка O(log n), медиана O(1).

#more
Если нужно ещё и удалять элементы (медиана в скользящем окне), куче нужна ленивая отметка удалённых или сбалансированное дерево. Для чисел из маленького диапазона хватит массива счётчиков — медиана за O(диапазона).
::
