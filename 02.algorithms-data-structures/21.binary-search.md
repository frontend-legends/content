# Двоичный поиск

Двоичный поиск за O(log n) находит границу в упорядоченных данных: каждое сравнение отбрасывает половину оставшегося. Сама идея проста, а ошибаются в деталях — бесконечный цикл на двух элементах, промах на единицу, неверная граница. Поэтому полезно мыслить не «ищу элемент», а «ищу первую позицию, где условие становится истинным». Так решаются и поиск позиции вставки, и диапазон одинаковых элементов, и повёрнутый массив, и пик, и даже медиана двух массивов.

::tldr
- **Двоичный поиск ищет границу монотонного условия:** слева от неё условие ложно, справа истинно. Отсортированность — частный случай.
- **Один шаблон на всё — полуинтервал `[lo, hi)` и `while (lo < hi)`:** если `mid` не подходит — `lo = mid + 1`, иначе `hi = mid`. Цикл кончается, когда `lo === hi`, — это и есть ответ.
- **Каждая ветка должна сужать интервал,** иначе цикл бесконечен. `hi = mid` безопасно только при `mid`, округлённом вниз.
- **Отсортированности целиком не нужно:** в повёрнутом массиве одна из половин всегда отсортирована, в поиске пика достаточно знать, куда идёт подъём.
- **Поиск по ответу:** если по числу x можно проверить «хватит ли x», двоичный поиск идёт по значениям x, а не по индексам.
::

## Как узнать паттерн

- Массив **отсортирован** (или почти: повёрнут, отсортирован по строкам), а ожидается O(log n).
- Нужна **первая или последняя** позиция, позиция вставки, ближайший элемент.
- Есть **монотонное условие**: «если x подходит, то и все большие подходят» — минимальная скорость, минимальная вместимость, минимальное время.
- Ограничения огромные (n до 10⁹ или значения до 10¹⁸) — линейный проход не успеет.

Общие алгоритмы поиска — линейный, интерполяционный, экспоненциальный — в [Поиске](/content/algorithms-data-structures/searching). Здесь — двоичный поиск как приём для задач.

## Шаблон

Первая позиция, где `nums[i] >= target`, — в других языках её называют `lower_bound`:

```ts
function lowerBound(nums: number[], target: number): number {
  let lo = 0;
  let hi = nums.length;                           // полуинтервал [lo, hi): ответ может быть равен length
  while (lo < hi) {
    const mid = (lo + hi) >>> 1;
    if (nums[mid] < target) lo = mid + 1;         // mid точно не ответ
    else hi = mid;                                // mid может быть ответом
  }
  return lo;
}
```

O(log n). Почему так надёжно: интервал `[lo, hi)` всегда содержит ответ, каждая ветка его строго сужает (`mid < hi`, потому что округление вниз), а при `lo === hi` остаётся одна позиция. Если `target` больше всех, ответ — `nums.length`, позиция за концом. В проверке результат совпал с `findIndex(x => x >= target)` на тысяче случайных массивов.

**Средняя точка.** В языках с 32-битными целыми `lo + hi` переполняется на больших индексах, и пишут `lo + (hi - lo) / 2`. В JavaScript числа — `double`, сумма не переполнится; `>>> 1` делит пополам без знака и корректен для сумм до 2^32, а `>> 1` и `| 0` уже на 2^31 дают отрицательное число.

::practice{title="35. Search Insert Position"}
Отсортированный массив различных чисел и `target`. Вернуть индекс `target` или позицию, куда его вставить, чтобы порядок сохранился. Пример: `[1, 3, 5, 6]`: 5 → 2, 2 → 1, 7 → 4. [Задача на LeetCode](https://leetcode.com/problems/search-insert-position/)

#solution
Позиция элемента и позиция вставки — одно и то же: первая позиция, где значение не меньше `target`:

```ts
function searchInsert(nums: number[], target: number): number {
  return lowerBound(nums, target);
}
```

O(log n). Если писать с `lo <= hi` и возвратом при равенстве, в конце надо вернуть именно `lo` — это частая точка ошибки, которой шаблон с полуинтервалом избегает.
::

::practice{title="74. Search a 2D Matrix"}
Матрица `m × n`: каждая строка отсортирована, первый элемент строки больше последнего элемента предыдущей. Есть ли в ней `target`? [Задача на LeetCode](https://leetcode.com/problems/search-a-2d-matrix/)

#solution
Если прочитать матрицу построчно, получится один отсортированный массив длины m · n. Индекс `k` в нём — клетка `[k / n, k % n]`:

```ts
function searchMatrix(matrix: number[][], target: number): boolean {
  const m = matrix.length;
  const n = matrix[0].length;
  let lo = 0;
  let hi = m * n - 1;
  while (lo <= hi) {
    const mid = (lo + hi) >>> 1;
    const value = matrix[Math.floor(mid / n)][mid % n];   // матрица как один отсортированный массив
    if (value === target) return true;
    if (value < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return false;
}
```

O(log(m · n)). Здесь ищем точное значение, поэтому подходит и вариант с закрытым интервалом `[lo, hi]` и тремя ветками. В задаче 240, где отсортированы только строки и столбцы по отдельности, это не работает — там идут из правого верхнего угла за O(m + n).
::

::practice{title="162. Find Peak Element"}
Найти индекс любого пика — элемента, строго большего соседей; за краями массива — минус бесконечность, соседние элементы различны. Нужно O(log n). Пример: `[1, 2, 3, 1]` → 2; `[1, 2, 1, 3, 5, 6, 4]` → 1 или 5. [Задача на LeetCode](https://leetcode.com/problems/find-peak-element/)

#solution
Массив не отсортирован, но монотонное условие есть. Если `nums[mid] < nums[mid + 1]`, справа подъём, и пик там точно есть: идём вверх, пока не начнётся спуск или не кончится массив. Иначе пик есть в `[lo, mid]`.

```ts
function findPeakElement(nums: number[]): number {
  let lo = 0;
  let hi = nums.length - 1;
  while (lo < hi) {
    const mid = (lo + hi) >>> 1;
    if (nums[mid] < nums[mid + 1]) lo = mid + 1;  // справа подъём — пик точно справа
    else hi = mid;                                // спуск — пик в [lo, mid]
  }
  return lo;
}
```

O(log n). `mid + 1` всегда в массиве: при `lo < hi` и округлении вниз `mid < hi`. Эта задача — лучший пример того, что двоичному поиску нужна не сортировка, а способ отбросить половину. В проверке найденный индекс всегда был пиком.
::

::practice{title="33. Search in Rotated Sorted Array"}
Отсортированный массив различных чисел повёрнут в неизвестной точке: `[0, 1, 2, 4, 5, 6, 7]` → `[4, 5, 6, 7, 0, 1, 2]`. Найти индекс `target` или −1 за O(log n). [Задача на LeetCode](https://leetcode.com/problems/search-in-rotated-sorted-array/)

#solution
Разрез в одном месте, поэтому из двух половин вокруг `mid` хотя бы одна отсортирована. Определяем какая, сравнив края, и проверяем, лежит ли `target` в её диапазоне — если да, ищем там, иначе в другой:

```ts
function search(nums: number[], target: number): number {
  let lo = 0;
  let hi = nums.length - 1;
  while (lo <= hi) {
    const mid = (lo + hi) >>> 1;
    if (nums[mid] === target) return mid;
    if (nums[lo] <= nums[mid]) {                  // левая половина отсортирована
      if (nums[lo] <= target && target < nums[mid]) hi = mid - 1;
      else lo = mid + 1;
    } else {                                      // правая половина отсортирована
      if (nums[mid] < target && target <= nums[hi]) lo = mid + 1;
      else hi = mid - 1;
    }
  }
  return -1;
}
```

O(log n). `<=` в `nums[lo] <= nums[mid]` важен: при `lo === mid` левая половина из одного элемента отсортирована. С повторами (задача 81) края могут быть равны, и тогда половину не определить — приходится сдвигать `lo` на один, и худший случай становится O(n). В проверке ответ совпал с `indexOf` на тысяче повёрнутых массивов.
::

::practice{title="34. Find First and Last Position of Element in Sorted Array"}
В отсортированном массиве найти первую и последнюю позицию `target`, или `[-1, -1]`, за O(log n). Пример: `[5, 7, 7, 8, 8, 10]`, 8 → `[3, 4]`. [Задача на LeetCode](https://leetcode.com/problems/find-first-and-last-position-of-element-in-sorted-array/)

#solution
Первая позиция — `lowerBound(target)`. Последняя — позиция перед первым элементом, большим `target`; для целых чисел это `lowerBound(target + 1) - 1`:

```ts
function searchRange(nums: number[], target: number): number[] {
  const first = lowerBound(nums, target);
  if (first === nums.length || nums[first] !== target) return [-1, -1];
  return [first, lowerBound(nums, target + 1) - 1];   // последняя — перед первой большей
}
```

O(log n). Найти один элемент и расширяться в стороны — O(n) на массиве из одинаковых чисел. Для нецелых значений вместо `target + 1` пишут второй поиск с условием `nums[mid] <= target` — `upper_bound`. В проверке ответ совпал с `indexOf` и `lastIndexOf`.
::

::practice{title="153. Find Minimum in Rotated Sorted Array"}
Найти минимум в повёрнутом отсортированном массиве различных чисел за O(log n). Пример: `[3, 4, 5, 1, 2]` → 1; `[11, 13, 15, 17]` → 11. [Задача на LeetCode](https://leetcode.com/problems/find-minimum-in-rotated-sorted-array/)

#solution
Минимум — точка разреза. Если `nums[mid] > nums[hi]`, разрез справа от `mid`; иначе отрезок `[mid, hi]` отсортирован, и минимум в `[lo, mid]`:

```ts
function findMin(nums: number[]): number {
  let lo = 0;
  let hi = nums.length - 1;
  while (lo < hi) {
    const mid = (lo + hi) >>> 1;
    if (nums[mid] > nums[hi]) lo = mid + 1;       // минимум правее mid
    else hi = mid;                                // mid может быть минимумом
  }
  return nums[lo];
}
```

O(log n). Сравнивать с правым краем, а не с левым: для неповёрнутого массива `nums[mid] > nums[lo]` ничего не говорит о том, где минимум. Индекс минимума — это величина поворота, и через него задачу 33 можно решить двумя обычными поисками.
::

::practice{title="4. Median of Two Sorted Arrays"}
Найти медиану объединения двух отсортированных массивов за O(log(m + n)). Пример: `[1, 3]` и `[2]` → 2; `[1, 2]` и `[3, 4]` → 2.5. [Задача на LeetCode](https://leetcode.com/problems/median-of-two-sorted-arrays/)

#solution
Медиана делит объединение на левую и правую части равного размера (левая на один больше при нечётной длине). Если взять `i` элементов из первого массива, из второго нужно взять `j = half - i`. Разрез правильный, когда всё левое не больше всего правого: `left1 <= right2` и `left2 <= right1`. По `i` ищем двоичным поиском: если `left1 > right2`, из первого взяли слишком много.

```ts
function findMedianSortedArrays(nums1: number[], nums2: number[]): number {
  if (nums1.length > nums2.length) return findMedianSortedArrays(nums2, nums1);   // искать по короткому
  const m = nums1.length;
  const n = nums2.length;
  const half = (m + n + 1) >> 1;                  // размер левой части
  let lo = 0;
  let hi = m;
  while (lo <= hi) {
    const i = (lo + hi) >> 1;                     // сколько взять из nums1 в левую часть
    const j = half - i;                           // остальное — из nums2
    const left1 = i > 0 ? nums1[i - 1] : -Infinity;
    const right1 = i < m ? nums1[i] : Infinity;
    const left2 = j > 0 ? nums2[j - 1] : -Infinity;
    const right2 = j < n ? nums2[j] : Infinity;
    if (left1 > right2) hi = i - 1;               // из nums1 взяли слишком много
    else if (left2 > right1) lo = i + 1;          // слишком мало
    else {
      const leftMax = Math.max(left1, left2);
      if ((m + n) % 2) return leftMax;
      return (leftMax + Math.min(right1, right2)) / 2;
    }
  }
  throw new Error('массивы должны быть отсортированы');
}
```

O(log min(m, n)). Поиск идёт по короткому массиву — тогда `j` всегда в пределах длинного. Бесконечности на краях избавляют от отдельных случаев «взяли ноль» и «взяли всё». Слияние до середины — O(m + n) — проще и на собеседовании годится как первый шаг. В проверке ответ совпал с медианой отсортированного объединения на двух тысячах пар, включая пустой массив.
::

## Красные флаги в ответе

- **`hi = mid` с `while (lo <= hi)`.** На одном элементе интервал не сужается — бесконечный цикл.
- **`lo = mid` при округлении вниз.** На двух элементах `mid === lo`, и цикл стоит.
- **Поиск одного вхождения и расширение в стороны** для диапазона — O(n) в худшем случае.
- **«Двоичный поиск только для отсортированных массивов».** Нужна монотонность условия, а не сортировка.
- **Сравнение с левым краем в повёрнутом массиве** при поиске минимума.

## Как спрашивают на собеседовании

::question
Как написать двоичный поиск без ошибок на границах?

#answer
Зафиксировать инвариант: ответ всегда в полуинтервале `[lo, hi)`. Тогда цикл `while (lo < hi)`, `mid` с округлением вниз, и две ветки: `mid` не подходит — `lo = mid + 1`, подходит — `hi = mid`. Каждая ветка сужает интервал, а после цикла `lo === hi` указывает на первую подходящую позицию или на `length`, если подходящих нет.

#more
Формулировка «первая позиция, где условие истинно» покрывает позицию вставки, левую и правую границы, минимум в повёрнутом массиве и поиск по ответу. Проверять стоит на массивах из 0, 1 и 2 элементов и на `target` меньше и больше всех.
::

::question
Что такое двоичный поиск по ответу?

#answer
Когда нужно минимальное x, при котором выполняется условие, а условие монотонно — если x подходит, то и любое большее, — ищут двоичным поиском по значениям x, а проверку делают отдельной функцией. Например, минимальная скорость, чтобы съесть бананы за h часов: проверка «успеем ли со скоростью x» — O(n), поиск — по скоростям от 1 до максимума.

#more
Итог — O(n log диапазона). Так решают задачи о минимальной вместимости, разбиении массива на k частей с минимальной наибольшей суммой, минимальном времени. Признак — фраза «минимизировать максимум» или «максимизировать минимум».
::

::question
Как искать в повёрнутом отсортированном массиве?

#answer
В повёрнутом массиве по одну сторону от `mid` всегда отсортированная половина. Сравнив `nums[lo]` и `nums[mid]`, узнаём, какая, и проверяем, лежит ли `target` в её диапазоне: если да — ищем в ней, иначе в другой. O(log n).

#more
Минимум (точку поворота) ищут сравнением `mid` с правым краем. С повторяющимися элементами половину не всегда можно определить — при `nums[lo] === nums[mid] === nums[hi]` сдвигают края на один, и худший случай O(n).
::
