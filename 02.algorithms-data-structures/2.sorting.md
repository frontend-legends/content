# Сортировка

Сортировка — самая изученная задача в алгоритмах и частая подготовка данных для других: после неё работают двоичный поиск, два указателя, слияние интервалов и поиск дубликатов. В работе сортируют встроенным `sort`, но на собеседовании спрашивают, как устроены основные алгоритмы, почему быстрее O(n log n) сравнениями не сделать, чем быстрая сортировка отличается от сортировки слиянием, что такое устойчивость и когда можно сортировать за линейное время. Здесь — алгоритмы с проверенным кодом и их свойства.

::tldr
- **Сортировки сравнениями не бывают быстрее O(n log n) в худшем случае:** нужно различить n! перестановок, а каждое сравнение даёт один бит.
- **Слиянием — O(n log n) всегда и устойчиво, но O(n) памяти. Быстрая — O(n log n) в среднем, на месте, но O(n²) при неудачных опорных.** Пирамидальная — O(n log n) всегда и на месте, но неустойчива и медленнее на практике.
- **Вставками — O(n²), но O(n) на почти отсортированных данных** и быстрее всех на маленьких массивах; поэтому гибридные сортировки добивают ею короткие куски.
- **Устойчивая сортировка сохраняет порядок равных элементов** — это нужно для сортировки по нескольким полям.
- **Без сравнений можно быстрее:** подсчётом и поразрядная сортировка — O(n + k) для целых ключей из небольшого диапазона.
::

---

## Как сравнивать сортировки

Каждый алгоритм описывают несколькими свойствами:

- **Время** в худшем, среднем и лучшем случае.
- **Память** — сортирует ли на месте (O(1) или O(log n) на стек) или нужен второй массив.
- **Устойчивость** — сохраняется ли исходный порядок элементов с равными ключами.
- **Адаптивность** — работает ли быстрее на почти отсортированных данных.

| Алгоритм | Худший | Средний | Лучший | Память | Устойчива |
| --- | --- | --- | --- | --- | --- |
| Пузырьком | O(n²) | O(n²) | O(n) | O(1) | да |
| Выбором | O(n²) | O(n²) | O(n²) | O(1) | нет |
| Вставками | O(n²) | O(n²) | O(n) | O(1) | да |
| Шелла | зависит от шагов, O(n^1.5) и лучше | — | O(n log n) | O(1) | нет |
| Слиянием | O(n log n) | O(n log n) | O(n log n) | O(n) | да |
| Быстрая | O(n²) | O(n log n) | O(n log n) | O(log n) | нет |
| Пирамидальная | O(n log n) | O(n log n) | O(n log n) | O(1) | нет |
| TimSort | O(n log n) | O(n log n) | O(n) | O(n) | да |
| Подсчётом | O(n + k) | O(n + k) | O(n + k) | O(n + k) | да |
| Поразрядная | O(d · (n + b)) | — | — | O(n + b) | да |

Пузырьком и выбором на собеседовании разбирают редко: у них нет преимуществ перед вставками. Сортировка Шелла — вставки с убывающим шагом — интересна исторически.

## Сортировка вставками

Идём слева направо и вставляем очередной элемент в уже отсортированный префикс, сдвигая большие вправо:

```ts
function insertionSort<T>(arr: T[], cmp: Compare<T>): T[] {
  for (let i = 1; i < arr.length; i++) {
    const x = arr[i];
    let j = i - 1;
    while (j >= 0 && cmp(arr[j], x) > 0) {        // сдвигать вправо всё, что больше x
      arr[j + 1] = arr[j];
      j--;
    }
    arr[j + 1] = x;
  }
  return arr;
}
```

`Compare<T>` — функция сравнения как у `Array.prototype.sort`: отрицательное число — `a` раньше. Число сдвигов равно числу инверсий — пар, стоящих не по порядку. В проверке на отсортированном массиве из 1000 элементов было 999 сравнений, на обратном — 499 500, то есть n(n − 1)/2. Поэтому вставки адаптивны и отлично работают на почти отсортированных данных, а на массивах из десятков элементов обгоняют O(n log n) алгоритмы за счёт простоты. Сравнение строгое (`> 0`), поэтому равные элементы не переставляются — сортировка устойчива.

## Сортировка слиянием

Разделить массив пополам, отсортировать половины рекурсивно и слить два отсортированных массива за линейное время:

```ts
function mergeSort<T>(arr: T[], cmp: Compare<T>): T[] {
  if (arr.length <= 1) return arr;
  const mid = arr.length >> 1;
  const left = mergeSort(arr.slice(0, mid), cmp);
  const right = mergeSort(arr.slice(mid), cmp);
  const out: T[] = [];
  let i = 0;
  let j = 0;
  while (i < left.length && j < right.length) {
    out.push(cmp(left[i], right[j]) <= 0 ? left[i++] : right[j++]);   // <= — равные берём слева: устойчивость
  }
  return out.concat(left.slice(i), right.slice(j));
}
```

O(n log n) в любом случае: log n уровней по O(n) на слияние ([Разделяй и властвуй](/content/algorithms-data-structures/divide-and-conquer)). Нужно O(n) дополнительной памяти. При равенстве берётся элемент из левой половины — отсюда устойчивость; с `<` вместо `<=` она пропадёт. Слияние не требует произвольного доступа, поэтому им сортируют связные списки и данные, которые не помещаются в память: куски сортируют по отдельности и сливают потоком — это внешняя сортировка.

## Быстрая сортировка

Выбрать **опорный** элемент, разложить массив на меньшие, равные и большие него и рекурсивно отсортировать меньшие и большие. Разбиение на три части (схема Дейкстры, «флаг Нидерландов») не даёт алгоритму деградировать на повторяющихся значениях:

```ts
function quickSort(arr: number[], lo = 0, hi = arr.length - 1): number[] {
  if (lo >= hi) return arr;
  const pivot = arr[lo + Math.floor(Math.random() * (hi - lo + 1))];   // случайный опорный
  let lt = lo;                                    // arr[lo..lt) < pivot
  let gt = hi;                                    // arr(gt..hi] > pivot
  let i = lo;                                     // arr[lt..i) === pivot
  while (i <= gt) {
    if (arr[i] < pivot) {
      [arr[lt], arr[i]] = [arr[i], arr[lt]];
      lt++;
      i++;
    } else if (arr[i] > pivot) {
      [arr[i], arr[gt]] = [arr[gt], arr[i]];
      gt--;                                       // i не двигаем: пришёл непроверенный элемент
    } else {
      i++;
    }
  }
  quickSort(arr, lo, lt - 1);                     // равные опорному уже на месте
  quickSort(arr, gt + 1, hi);
  return arr;
}
```

В среднем O(n log n) и на месте. Худший случай — O(n²), когда опорный раз за разом оказывается минимумом или максимумом. Классическая ловушка — брать первый элемент на уже отсортированных данных: в проверке такая версия на 2000 отсортированных числах сделала 1 999 000 сравнений, ровно n(n − 1)/2. Случайный опорный делает худший случай маловероятным для любых входных данных, а медиана из трёх — дешёвая эвристика. Без трёхчастного разбиения массив из одинаковых чисел тоже даёт O(n²); с ним 200 000 одинаковых элементов в проверке отсортировались за доли секунды.

На практике быстрая сортировка обычно быстрее слияния: она работает на месте, проходит память подряд и делает меньше перемещений. **Интроспективная** сортировка (`std::sort` в C++) начинает с быстрой, переключается на пирамидальную при слишком глубокой рекурсии и добивает короткие куски вставками — гарантируя O(n log n).

## Пирамидальная сортировка

Построить из массива max-кучу, затем n раз менять корень (максимум) с последним элементом кучи и восстанавливать кучу на оставшейся части:

```ts
function heapSort(arr: number[]): number[] {
  const n = arr.length;
  const siftDown = (i: number, size: number) => {
    for (;;) {
      const l = 2 * i + 1;
      const r = l + 1;
      let big = i;
      if (l < size && arr[l] > arr[big]) big = l;
      if (r < size && arr[r] > arr[big]) big = r;
      if (big === i) return;
      [arr[i], arr[big]] = [arr[big], arr[i]];
      i = big;
    }
  };
  for (let i = (n >> 1) - 1; i >= 0; i--) siftDown(i, n);   // построить max-кучу за O(n)
  for (let end = n - 1; end > 0; end--) {
    [arr[0], arr[end]] = [arr[end], arr[0]];      // максимум — в конец
    siftDown(0, end);
  }
  return arr;
}
```

O(n log n) в худшем случае и O(1) памяти — единственная из классических с обоими свойствами. Но она неустойчива: в проверке три равных ключа после сортировки встали в обратном порядке. И на практике медленнее быстрой: просеивание прыгает по массиву, и кеш процессора помогает хуже. Куча как структура — в [Куче](/content/algorithms-data-structures/heap).

## Нижняя граница O(n log n)

Сортировка сравнениями — это дерево решений: каждый узел — сравнение двух элементов, каждый лист — одна из перестановок. Чтобы различить все n! перестановок, дереву нужно не меньше n! листьев, а значит, высота не меньше log₂(n!) ≈ n log₂ n − 1,44 n. Для 1000 элементов это 8530 сравнений в худшем случае; в проверке сортировка слиянием случайного массива из 1000 элементов уложилась между этой границей и n log₂ n ≈ 9966.

Граница касается только сравнений. Если ключи — целые из небольшого диапазона, их можно не сравнивать, а раскладывать по позициям.

---

## Сортировки без сравнений

**Подсчётом.** Посчитать, сколько раз встречается каждый ключ, превратить счётчики в начальные позиции и разложить элементы. Проход слева направо сохраняет порядок равных — сортировка устойчива:

```ts
function countingSort<T>(items: T[], key: (item: T) => number, k: number): T[] {
  const count = new Array(k + 1).fill(0);
  for (const item of items) count[key(item) + 1]++;
  for (let v = 0; v < k; v++) count[v + 1] += count[v];   // count[v] — где начинаются ключи v
  const out = new Array<T>(items.length);
  for (const item of items) out[count[key(item)]++] = item;   // проход слева — порядок равных сохранён
  return out;
}
```

O(n + k) для ключей из `[0, k)`. Если k сравнимо с n — линейное время; если ключи — 64-битные числа, массив счётчиков не поместится в память.

**Поразрядная** (radix sort) сортирует по цифрам, начиная с младшей, каждый раз устойчивой сортировкой подсчётом. Устойчивость обязательна: она сохраняет порядок, установленный младшими разрядами:

```ts
function radixSort(nums: number[]): number[] {
  let out = nums;
  const max = Math.max(0, ...nums);
  for (let place = 1; Math.floor(max / place) > 0; place *= 10) {
    out = countingSort(out, (x) => Math.floor(x / place) % 10, 10);   // устойчиво по очередной цифре
  }
  return out;
}
```

O(d · (n + b)) для d разрядов в системе с основанием b. Так сортируют целые числа, строки фиксированной длины, IP-адреса. **Карманная** сортировка (bucket sort) раскладывает равномерно распределённые числа по корзинам-диапазонам и сортирует каждую — O(n) в среднем на равномерных данных.

## Сортировка в стандартных библиотеках

Встроенные сортировки — гибридные. **TimSort** ищет во входе уже упорядоченные участки (возрастающие или строго убывающие, которые разворачивает), короткие доращивает вставками до минимальной длины и сливает участки с хитрым правилом, чтобы слияния были сбалансированы. На случайных данных это O(n log n), на почти отсортированных — близко к O(n), и сортировка устойчива. TimSort и его варианты использует V8 для `Array.prototype.sort`, Python для `list.sort` и Java для сортировки объектов. Для массивов примитивов Java использует быструю сортировку с двумя опорными — там устойчивость не нужна.

Особенности `sort` в JavaScript — строковое сравнение по умолчанию, функция сравнения, устойчивость по спецификации и немутирующий `toSorted` — в [Объектах и массивах](/content/javascript/objects-and-arrays).

## Красные флаги в ответе

- **«Быстрая сортировка — O(n log n)»** без оговорки про худший случай и выбор опорного.
- **Первый или последний элемент как опорный** без мысли об отсортированных данных.
- **Не знать, что такое устойчивость,** и зачем она для сортировки по нескольким полям.
- **«Быстрее O(n log n) сортировать нельзя»** — для сравнений да, для целых ключей из малого диапазона — можно за линейное время.
- **`arr.sort()` для чисел** без функции сравнения — сортирует как строки: `[10, 9, 1]` → `[1, 10, 9]`.
- **Сортировка ради k-го элемента или топа k** — хватает быстрого выбора или кучи.

## Как спрашивают на собеседовании

::question
Чем быстрая сортировка отличается от сортировки слиянием?

#answer
Слиянием делит массив пополам механически, а работа — в слиянии отсортированных половин. Быстрая делает работу в разбиении вокруг опорного, а «слияние» тривиально. Слиянием — O(n log n) всегда, устойчива, но требует O(n) памяти. Быстрая — O(n log n) в среднем, на месте, неустойчива, а в худшем случае O(n²) при неудачных опорных.

#more
На практике быстрая обычно быстрее за счёт работы на месте и хорошей локальности. Худший случай лечат случайным опорным, медианой из трёх и переключением на пирамидальную при глубокой рекурсии (интроспективная сортировка). Слияние выбирают, когда нужна устойчивость, гарантия времени, сортировка списков или внешних данных.
::

::question
Почему сортировка сравнениями не может быть быстрее O(n log n)?

#answer
Любой такой алгоритм — дерево решений, где каждое сравнение ветвит на два исхода, а листья — перестановки входа. Чтобы различить все n! перестановок, нужно не меньше n! листьев, то есть высота не меньше log₂(n!), а это порядка n log n. Значит, в худшем случае нужно Ω(n log n) сравнений.

#more
Граница не касается сортировок без сравнений: подсчётом и поразрядная работают за O(n + k) и O(d · n), используя то, что ключи — небольшие целые. Для 1000 элементов log₂(1000!) — около 8530 сравнений.
::

::question
Что такое устойчивая сортировка и зачем она нужна?

#answer
Устойчивая сортировка сохраняет исходный порядок элементов с равными ключами. Это нужно, чтобы сортировать по нескольким полям последовательно: сначала по второстепенному, потом по главному — и внутри равных главных ключей сохранится порядок второстепенного. Слиянием, вставками, подсчётом и TimSort устойчивы; быстрая и пирамидальная — нет.

#more
`Array.prototype.sort` в JavaScript устойчив по спецификации. Неустойчивую сортировку можно сделать устойчивой, добавив исходный индекс как дополнительный ключ сравнения. Поразрядная сортировка работает только потому, что сортировка по каждому разряду устойчива.
::

::question
Когда сортировка вставками лучше O(n log n) алгоритмов?

#answer
На маленьких массивах — из-за простоты и малой константы — и на почти отсортированных: её время пропорционально числу инверсий, и для массива, где каждый элемент стоит недалеко от своего места, это почти O(n). Поэтому гибридные сортировки добивают ею короткие куски, а TimSort доращивает ею короткие упорядоченные участки.

#more
Ещё она устойчива, работает на месте и онлайн — может сортировать данные по мере поступления. Типичный пример из интерфейса — поддержание отсортированного списка, в который элементы добавляются по одному: вставка на место двоичным поиском и сдвигом.
::

::question
Как отсортировать данные, которые не помещаются в память?

#answer
Внешней сортировкой слиянием: читать данные кусками, которые помещаются в память, сортировать каждый и записывать на диск, а затем сливать отсортированные куски потоком — k-путевым слиянием с кучей из k текущих голов. Память — на буферы чтения, а не на все данные.

#more
Число проходов по диску определяет время, поэтому кусков стараются сделать как можно больше за раз и сливать сразу многие. Так работают сортировка в базах данных при `ORDER BY` больших таблиц и утилита `sort` в Unix.
::

## Практика

::practice{title="75. Sort Colors"}
Массив из 0, 1 и 2 (цвета). Отсортировать на месте за один проход и O(1) памяти, без встроенной сортировки. Пример: `[2, 0, 2, 1, 1, 0]` → `[0, 0, 1, 1, 2, 2]`. [Задача на LeetCode](https://leetcode.com/problems/sort-colors/)

#solution
Это трёхчастное разбиение быстрой сортировки с опорным 1: нули собираются в начале, двойки — в конце, единицы остаются посередине:

```ts
function sortColors(nums: number[]): void {
  let lo = 0;                                     // [0, lo) — нули
  let hi = nums.length - 1;                       // (hi, end] — двойки
  for (let i = 0; i <= hi; ) {
    if (nums[i] === 0) {
      [nums[lo], nums[i]] = [nums[i], nums[lo]];
      lo++;
      i++;
    } else if (nums[i] === 2) {
      [nums[i], nums[hi]] = [nums[hi], nums[i]];
      hi--;                                       // i не двигаем: пришёл непроверенный элемент
    } else {
      i++;
    }
  }
}
```

O(n), O(1). После обмена с концом `i` не увеличивают: элемент с конца ещё не проверен. Подсчёт нулей, единиц и двоек с перезаписью тоже O(n), но делает два прохода. В проверке результат совпал с сортировкой на тысяче массивов.
::

::practice{title="k-й наименьший без полной сортировки"}
Найти k-й наименьший элемент массива (k с нуля) в среднем за O(n). Пример: `[7, 2, 9, 4, 1]`, k = 2 → 4.

#solution
Быстрый выбор — быстрая сортировка, которая после разбиения уходит только в ту часть, где лежит k-я позиция:

```ts
function quickSelect(arr: number[], k: number): number {
  let lo = 0;
  let hi = arr.length - 1;
  for (;;) {
    const pivot = arr[lo + Math.floor(Math.random() * (hi - lo + 1))];
    let lt = lo;
    let gt = hi;
    let i = lo;
    while (i <= gt) {
      if (arr[i] < pivot) {
        [arr[lt], arr[i]] = [arr[i], arr[lt]];
        lt++;
        i++;
      } else if (arr[i] > pivot) {
        [arr[i], arr[gt]] = [arr[gt], arr[i]];
        gt--;
      } else {
        i++;
      }
    }
    if (k < lt) hi = lt - 1;                      // ответ среди меньших
    else if (k > gt) lo = gt + 1;                 // среди больших
    else return pivot;                            // попал в равные опорному
  }
}
```

В среднем n + n/2 + n/4 + … = O(n), в худшем O(n²); алгоритм «медиана медиан» гарантирует O(n), но медленнее на практике. Массив меняется — если нельзя, работают с копией. Для потока или когда нужны все k наименьших — куча размера k ([Куча](/content/algorithms-data-structures/heap)). В проверке ответ совпал с элементом отсортированного массива.
::

::practice{title="347. Top K Frequent Elements"}
Вернуть k самых частых элементов массива быстрее, чем O(n log n). Пример: `[1, 1, 1, 2, 2, 3], k = 2` → `[1, 2]`. [Задача на LeetCode](https://leetcode.com/problems/top-k-frequent-elements/)

#solution
Посчитать частоты, а потом не сортировать их, а разложить по корзинам: частота — число от 1 до n, поэтому корзин n. Обход корзин от больших частот к меньшим даёт ответ:

```ts
function topKFrequent(nums: number[], k: number): number[] {
  const freq = new Map<number, number>();
  for (const x of nums) freq.set(x, (freq.get(x) ?? 0) + 1);
  const buckets: number[][] = Array.from({ length: nums.length + 1 }, () => []);
  for (const [x, f] of freq) buckets[f].push(x);  // корзина по частоте: частота не больше n
  const result: number[] = [];
  for (let f = nums.length; f > 0 && result.length < k; f--) result.push(...buckets[f]);
  return result.slice(0, k);
}
```

O(n) по времени и памяти — сортировка подсчётом по частоте. Альтернатива — min-куча размера k за O(n log k). При равных частотах допустим любой выбор; в проверке каждый возвращённый элемент встречался не реже, чем k-й по частоте.
::
