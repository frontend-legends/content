# Перебор с возвратом

Перебор с возвратом (backtracking) строит решение по шагу: делает выбор, идёт дальше, а если путь не привёл к ответу или ответ записан — отменяет выбор и пробует следующий. Так перечисляют все подмножества, сочетания, перестановки, расстановки ферзей и правильные скобочные последовательности. Ответов экспоненциально много, поэтому быстрее перечисления не сделать; искусство в том, чтобы не заходить в ветки, где ответа заведомо нет, — это называют отсечением.

::tldr
- **Три шага на каждом уровне: выбрать, продолжить рекурсией, отменить выбор.** Состояние — общий массив пути, который растёт и укорачивается.
- **В ответ кладут копию пути** (`[...path]`), иначе все ответы окажутся одним и тем же массивом.
- **Порядок и повторы задаёт параметр `start`:** сочетания идут от `start` вперёд, перестановки перебирают всё с массивом `used`, повторное использование числа — рекурсия с тем же `i`.
- **Отсечения решают скорость:** сортировка и выход из цикла, когда число уже больше остатка, ограничения на открытые скобки, множества занятых столбцов и диагоналей.
- **Сложность — число ответов на длину ответа:** 2^n подмножеств, n! перестановок. Это нормально: сам ответ такого размера.
::

## Как узнать паттерн

- Нужно **все** варианты: «все комбинации», «все перестановки», «все способы».
- Нужно **посчитать** или **найти** расстановку с ограничениями: ферзи, судоку, путь по клеткам без повторов.
- Ограничения на входе маленькие — n до 10–20: это намёк, что экспоненциальный перебор ожидаем.

Если нужно только **число** способов или **лучший** вариант, а подзадачи повторяются, перебор заменяют динамическим программированием ([Одномерное DP](/content/algorithms-data-structures/1d-dp)). Перебор с возвратом — это обход в глубину по дереву решений ([Графы](/content/algorithms-data-structures/graph-general)).

## Шаблон

Все подмножества — каждый узел дерева решений сам является ответом:

```ts
function subsets(nums: number[]): number[][] {
  const result: number[][] = [];
  const path: number[] = [];
  const backtrack = (start: number): void => {
    result.push([...path]);                       // копия: path ещё будет меняться
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);                         // выбрать
      backtrack(i + 1);                           // продолжить
      path.pop();                                 // отменить выбор
    }
  };
  backtrack(0);
  return result;
}
```

2^n подмножеств по O(n) на копию — O(n · 2^n); стек рекурсии O(n). Остальные задачи меняют три вещи: **когда записывать ответ** (в каждом узле или на нужной глубине), **откуда начинать цикл** (`start`, `i` или 0 с `used`) и **что отсекать**. В проверке для n от 0 до 10 подмножеств оказалось ровно 2^n.

::practice{title="17. Letter Combinations of a Phone Number"}
Дана строка цифр 2–9. Вернуть все строки, которые можно набрать на кнопочном телефоне: 2 — `abc`, 3 — `def` и так далее, 7 — `pqrs`, 9 — `wxyz`. Пример: `"23"` → `ad, ae, af, bd, be, bf, cd, ce, cf`. [Задача на LeetCode](https://leetcode.com/problems/letter-combinations-of-a-phone-number/)

#solution
Уровень рекурсии — позиция в строке цифр, ветки — буквы этой цифры. Строки неизменяемы, поэтому «отменять» ничего не нужно — префикс передаётся новой строкой:

```ts
function letterCombinations(digits: string): string[] {
  if (!digits) return [];
  const keys: Record<string, string> = {
    2: 'abc', 3: 'def', 4: 'ghi', 5: 'jkl', 6: 'mno', 7: 'pqrs', 8: 'tuv', 9: 'wxyz',
  };
  const result: string[] = [];
  const backtrack = (i: number, prefix: string): void => {
    if (i === digits.length) {
      result.push(prefix);
      return;
    }
    for (const letter of keys[digits[i]]) backtrack(i + 1, prefix + letter);
  };
  backtrack(0, '');
  return result;
}
```

До 4^n строк длины n. Пустой ввод — пустой массив, а не `[""]`: без этой проверки рекурсия сразу запишет пустую строку.
::

::practice{title="77. Combinations"}
Вернуть все сочетания по `k` чисел из `1..n`. Пример: `n = 4, k = 2` → `[1,2], [1,3], [1,4], [2,3], [2,4], [3,4]`. [Задача на LeetCode](https://leetcode.com/problems/combinations/)

#solution
Как подмножества, но ответ записывается только на глубине k. Отсечение: если после `x` осталось меньше чисел, чем не хватает до k, дальше идти бессмысленно — верхняя граница цикла `n - (k - path.length) + 1`:

```ts
function combine(n: number, k: number): number[][] {
  const result: number[][] = [];
  const path: number[] = [];
  const backtrack = (start: number): void => {
    if (path.length === k) {
      result.push([...path]);
      return;
    }
    // отсечение: чисел после start должно хватить, чтобы добрать до k
    for (let x = start; x <= n - (k - path.length) + 1; x++) {
      path.push(x);
      backtrack(x + 1);
      path.pop();
    }
  };
  backtrack(1);
  return result;
}
```

O(C(n, k) · k). Начало цикла с `start`, а не с 1, — то, что отличает сочетания от размещений: `[1, 2]` и `[2, 1]` не появятся оба. В проверке для всех n до 10 число ответов совпало с биномиальным коэффициентом, а сами ответы — с подмножествами размера k.
::

::practice{title="46. Permutations"}
Вернуть все перестановки массива различных чисел. Пример: `[1, 2, 3]` → 6 перестановок. [Задача на LeetCode](https://leetcode.com/problems/permutations/)

#solution
На каждом уровне можно взять любой ещё не использованный элемент — цикл всегда с 0, а занятые отмечаются в `used`:

```ts
function permute(nums: number[]): number[][] {
  const result: number[][] = [];
  const path: number[] = [];
  const used = new Array(nums.length).fill(false);
  const backtrack = (): void => {
    if (path.length === nums.length) {
      result.push([...path]);
      return;
    }
    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;
      used[i] = true;
      path.push(nums[i]);
      backtrack();
      path.pop();
      used[i] = false;
    }
  };
  backtrack();
  return result;
}
```

O(n! · n). Отменять нужно оба изменения — и `path`, и `used`. В проверке для n до 7 перестановок ровно n!, и все различны. Если в массиве есть повторы (задача 47), его сортируют и пропускают элемент, равный предыдущему, если предыдущий сейчас не используется.
::

::practice{title="39. Combination Sum"}
Даны различные положительные числа и `target`. Вернуть все комбинации с суммой `target`; каждое число можно брать сколько угодно раз, комбинации не должны повторяться с точностью до порядка. Пример: `[2, 3, 6, 7], 7` → `[2, 2, 3], [7]`. [Задача на LeetCode](https://leetcode.com/problems/combination-sum/)

#solution
Как сочетания, но после выбора `sorted[i]` рекурсия продолжается с тем же `i` — число можно взять снова, а к меньшим вернуться нельзя, поэтому порядок не дублируется. Отсортированные числа дают отсечение: если текущее больше остатка, все следующие тоже больше.

```ts
function combinationSum(candidates: number[], target: number): number[][] {
  const sorted = [...candidates].sort((a, b) => a - b);
  const result: number[][] = [];
  const path: number[] = [];
  const backtrack = (start: number, rest: number): void => {
    if (rest === 0) {
      result.push([...path]);
      return;
    }
    for (let i = start; i < sorted.length && sorted[i] <= rest; i++) {   // дальше только больше — стоп
      path.push(sorted[i]);
      backtrack(i, rest - sorted[i]);             // i, а не i + 1: число можно брать снова
      path.pop();
    }
  };
  backtrack(0, target);
  return result;
}
```

Число ответов экспоненциально; глубина рекурсии — до `target / min`. Три варианта задачи отличаются одним символом: `i` — числа повторяются (39), `i + 1` — каждое по разу (40, с пропуском одинаковых соседей), цикл с 0 — порядок важен. В проверке ответы совпали с перебором кратностей каждого числа.
::

::practice{title="52. N-Queens II"}
Сколько способов расставить n ферзей на доске n × n так, чтобы они не били друг друга? Пример: n = 4 → 2, n = 8 → 92. [Задача на LeetCode](https://leetcode.com/problems/n-queens-ii/)

#solution
В каждой строке ровно один ферзь — ставим по строкам и перебираем столбец. Клетка под боем, если занят её столбец или одна из диагоналей. На диагонали «\» одинакова разность `r - c`, на диагонали «/» — сумма `r + c`, поэтому проверка — три поиска во множествах за O(1):

```ts
function totalNQueens(n: number): number {
  const cols = new Set<number>();
  const diagonals = new Set<number>();            // r - c одинаково на диагонали «\»
  const antiDiagonals = new Set<number>();        // r + c одинаково на диагонали «/»
  const place = (r: number): number => {
    if (r === n) return 1;
    let count = 0;
    for (let c = 0; c < n; c++) {
      if (cols.has(c) || diagonals.has(r - c) || antiDiagonals.has(r + c)) continue;
      cols.add(c);
      diagonals.add(r - c);
      antiDiagonals.add(r + c);
      count += place(r + 1);
      cols.delete(c);
      diagonals.delete(r - c);
      antiDiagonals.delete(r + c);
    }
    return count;
  };
  return place(0);
}
```

Не больше O(n!) — в каждой следующей строке свободных столбцов меньше, а диагонали отсекают ещё больше. В проверке для n от 1 до 9 получилось 1, 0, 0, 2, 10, 4, 40, 92, 352 — известные числа решений. Задача 51 — то же самое, но с выводом досок.
::

::practice{title="22. Generate Parentheses"}
Вернуть все правильные скобочные последовательности из n пар. Пример: n = 3 → `((())), (()()), (())(), ()(()), ()()()`. [Задача на LeetCode](https://leetcode.com/problems/generate-parentheses/)

#solution
Перебирать все 2^(2n) строк и проверять каждую не нужно — отсечение строит только правильные. Открыть скобку можно, пока открытых меньше n; закрыть — пока закрытых меньше открытых:

```ts
function generateParenthesis(n: number): string[] {
  const result: string[] = [];
  const backtrack = (s: string, open: number, close: number): void => {
    if (s.length === 2 * n) {
      result.push(s);
      return;
    }
    if (open < n) backtrack(s + '(', open + 1, close);
    if (close < open) backtrack(s + ')', open, close + 1);   // закрыть можно только открытую
  };
  backtrack('', 0, 0);
  return result;
}
```

Ответов столько, сколько n-е число Каталана, — около 4^n / (n^1.5 · √π). В проверке для n до 8 их было 1, 2, 5, 14, 42, 132, 429, 1430, и в каждой строке глубина вложенности не уходила ниже нуля. Проверка правильности скобок стеком — в [Стеке](/content/algorithms-data-structures/stack).
::

::practice{title="79. Word Search"}
Есть ли на доске букв слово из соседних по горизонтали и вертикали клеток, где клетка не используется дважды? Пример: на доске `ABCE / SFCS / ADEE` есть `"ABCCED"` и `"SEE"`, но нет `"ABCB"`. [Задача на LeetCode](https://leetcode.com/problems/word-search/)

#solution
Из каждой клетки — обход в глубину по буквам слова. Клетку на время пути заменяем на `#`, чтобы не взять её снова, и возвращаем при откате:

```ts
function exist(board: string[][], word: string): boolean {
  const m = board.length;
  const n = board[0].length;
  const dfs = (r: number, c: number, i: number): boolean => {
    if (i === word.length) return true;
    if (r < 0 || r >= m || c < 0 || c >= n || board[r][c] !== word[i]) return false;
    const saved = board[r][c];
    board[r][c] = '#';                            // занять клетку на время пути
    const found = dfs(r + 1, c, i + 1) || dfs(r - 1, c, i + 1) || dfs(r, c + 1, i + 1) || dfs(r, c - 1, i + 1);
    board[r][c] = saved;                          // вернуть при откате
    return found;
  };
  for (let r = 0; r < m; r++) for (let c = 0; c < n; c++) if (dfs(r, c, 0)) return true;
  return false;
}
```

O(m · n · 3^L) для слова длины L: из каждой клетки, кроме первой, три направления — назад нельзя. Отметка обязательно снимается и при успехе: иначе доска останется испорченной. В проверке ответ совпал с перебором всех простых путей, и доска после поиска всегда была прежней. Для многих слов сразу — префиксное дерево ([Префиксное дерево](/content/algorithms-data-structures/trie)).
::

## Красные флаги в ответе

- **`result.push(path)` без копии.** Все ответы — ссылки на один массив, в конце пустой.
- **Забыть отменить выбор** (`pop`, `used[i] = false`, вернуть клетку). Следующие ветки увидят чужое состояние.
- **Путаница сочетаний и перестановок.** Цикл с 0 в сочетаниях даёт дубли `[1, 2]` и `[2, 1]`.
- **Генерировать всё и фильтровать** вместо отсечения — скобки за 2^(2n) вместо числа Каталана.
- **Ожидать полиномиальную сложность.** Ответов экспоненциально много; разговор — об отсечениях.

## Как спрашивают на собеседовании

::question
Что такое перебор с возвратом и чем он отличается от полного перебора?

#answer
Это обход дерева частичных решений в глубину: на каждом шаге делаем выбор, рекурсивно продолжаем и отменяем выбор при возврате. Отличие от полного перебора — отсечение: как только частичное решение нарушает ограничение, всё поддерево пропускается. Ферзи не ставятся на побитые клетки, скобка не закрывается без открытой.

#more
Хорошие отсечения меняют время на порядки, хотя оценка в худшем случае остаётся экспоненциальной. Помогает сортировка входа (обрыв цикла, пропуск дублей) и порядок перебора — сначала самые ограниченные варианты, как в судоку. Если подзадачи повторяются, перебор с мемоизацией становится динамическим программированием.
::

::question
Как перебрать сочетания, перестановки и подмножества и не получить дубли?

#answer
Подмножества — цикл от `start`, ответ в каждом узле. Сочетания — то же, но ответ на глубине k. Перестановки — цикл от 0 с массивом `used`. Если во входе есть одинаковые элементы, его сортируют и пропускают элемент, равный предыдущему на том же уровне рекурсии.

#more
Для подмножеств есть итеративный способ — битовые маски от 0 до 2^n − 1, где бит i значит «элемент i взят». Для перестановок — алгоритм «следующая перестановка», который выдаёт их в лексикографическом порядке без рекурсии.
::

::question
Как оценить сложность перебора с возвратом?

#answer
Как число узлов дерева решений, умноженное на работу в узле. Подмножеств 2^n, перестановок n!, сочетаний C(n, k); на запись каждого ответа уходит O(длины). Память — глубина рекурсии плюс сам ответ.

#more
Для задач с отсечением точную оценку дать трудно, называют верхнюю: ферзи — не больше O(n!), поиск слова — O(m · n · 3^L). Правильных скобочных последовательностей — число Каталана, примерно 4^n / n^1.5. Понимание, что ответ сам экспоненциален, — аргумент, почему быстрее не сделать.
::
