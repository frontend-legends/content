# Связный список

Связный список — цепочка узлов, где каждый хранит значение и ссылку на следующий. Вставка и удаление в известном месте — O(1), но доступ по индексу — O(n), а обход медленнее массива из-за промахов кеша. На собеседовании список проверяет работу со ссылками: развернуть, слить, найти цикл, удалить n-й с конца, не потеряв голову и не создав петлю. Задачи короткие, но ошибаться в них легко, поэтому важны три приёма — фиктивный узел, два указателя разной скорости и разворот ссылок.

::tldr
- **Фиктивный узел перед головой убирает особый случай «изменилась голова»:** удаление первого узла и вставка в начало делаются тем же кодом, что и в середине.
- **Быстрый и медленный указатели находят середину, цикл и n-й узел с конца за один проход** и O(1) памяти.
- **Разворот — три переменные `prev`, `node`, `next`:** сначала запомнить хвост, потом развернуть ссылку, потом сдвинуться.
- **Перед изменением ссылки сохрани то, на что она указывала:** иначе остаток списка потерян.
- **Связный список в JavaScript почти не нужен:** массив быстрее для большинства задач, а LRU-кеш строят на `Map`, который помнит порядок вставки.
::

## Как узнать паттерн

Задачи на списки узнаются по входу — `ListNode`. Решение подсказывают ключевые слова:

- **«середина», «цикл», «n-й с конца», «пересечение»** — два указателя с разной скоростью или с разрывом;
- **«развернуть», «повернуть», «группами по k»** — перестановка ссылок на месте;
- **«слить», «разделить», «отсортировать»** — фиктивные узлы для собираемых списков;
- **«удалить» с условием** — фиктивный узел и указатель на узел **перед** удаляемым;
- **«скопировать» со случайными ссылками** — таблица «старый узел → новый».

Почему списки на практике медленнее массивов при той же асимптотике — в [Архитектуре компьютера](/content/computer-science/computer-architecture). Устройство односвязных, двусвязных и кольцевых списков — в [Структурах данных](/content/algorithms-data-structures/data-structures).

## Шаблоны

Узел в задачах LeetCode:

```ts
export class ListNode {
  val: number;
  next: ListNode | null;
  constructor(val?: number, next?: ListNode | null) {
    this.val = val ?? 0;
    this.next = next ?? null;
  }
}
```

**Разворот.** Перед тем как развернуть стрелку, запоминаем, куда она вела:

```ts
function reverseList(head: ListNode | null): ListNode | null {
  let prev: ListNode | null = null;
  let node = head;
  while (node) {
    const next = node.next;                       // запомнить хвост
    node.next = prev;                             // развернуть стрелку
    prev = node;
    node = next;
  }
  return prev;
}
```

**Быстрый и медленный указатели.** Быстрый делает два шага, медленный — один; когда быстрый дошёл до конца, медленный — в середине:

```ts
function middleNode(head: ListNode | null): ListNode | null {
  let slow = head;
  let fast = head;
  while (fast && fast.next) {
    slow = slow!.next;                            // шаг на один
    fast = fast.next.next;                        // шаг на два
  }
  return slow;
}
```

При чётной длине так получается второй из двух средних. **Фиктивный узел** — `const dummy = new ListNode(0, head)` и `return dummy.next` — используется почти в каждой задаче ниже.

::practice{title="141. Linked List Cycle"}
Есть ли в списке цикл — узел, до которого можно снова дойти по ссылкам `next`? Решить с O(1) памяти. [Задача на LeetCode](https://leetcode.com/problems/linked-list-cycle/)

#solution
С `Set` посещённых узлов — O(n) памяти. Без памяти — алгоритм Флойда: быстрый указатель идёт по два узла, медленный — по одному. Если цикла нет, быстрый упрётся в `null`. Если есть, внутри цикла быстрый сокращает разрыв на один узел за шаг и обязательно догонит медленного.

```ts
function hasCycle(head: ListNode | null): boolean {
  let slow = head;
  let fast = head;
  while (fast && fast.next) {
    slow = slow!.next;
    fast = fast.next.next;
    if (slow === fast) return true;
  }
  return false;
}
```

O(n) по времени, O(1) по памяти. Продолжение — найти начало цикла: после встречи поставить один указатель в голову и двигать оба по одному шагу; они встретятся в начале цикла. Сравнение — по ссылке на узел, а не по значению: значения могут повторяться.
::

::practice{title="2. Add Two Numbers"}
Два неотрицательных числа записаны списками цифр в обратном порядке, без ведущих нулей. Вернуть их сумму в таком же виде. Пример: `[2, 4, 3] + [5, 6, 4]` (342 + 465) → `[7, 0, 8]` (807). [Задача на LeetCode](https://leetcode.com/problems/add-two-numbers/)

#solution
Сложение столбиком: младшие разряды уже первые. Идём по обоим спискам, пока остались цифры или перенос:

```ts
function addTwoNumbers(l1: ListNode | null, l2: ListNode | null): ListNode | null {
  const dummy = new ListNode();
  let tail = dummy;
  let carry = 0;
  while (l1 || l2 || carry) {
    const sum = (l1?.val ?? 0) + (l2?.val ?? 0) + carry;
    carry = Math.floor(sum / 10);
    tail.next = new ListNode(sum % 10);
    tail = tail.next;
    l1 = l1?.next ?? null;
    l2 = l2?.next ?? null;
  }
  return dummy.next;
}
```

O(max(n, m)) по времени. Переводить списки в числа нельзя: на 100 цифрах `number` потеряет точность ([Представление данных](/content/computer-science/data-representation)). Ошибка — забыть перенос в последнем разряде: `[5] + [5]` даёт `[0, 1]`. В проверке результат совпал со сложением `BigInt` на случайных числах.
::

::practice{title="21. Merge Two Sorted Lists"}
Слить два отсортированных списка в один отсортированный, переиспользуя их узлы. Пример: `[1, 2, 4]` и `[1, 3, 4]` → `[1, 1, 2, 3, 4, 4]`. [Задача на LeetCode](https://leetcode.com/problems/merge-two-sorted-lists/)

#solution
Фиктивный узел — начало результата; к хвосту цепляем меньшую из двух голов. Когда один список кончился, хвост второго цепляется целиком:

```ts
function mergeTwoLists(a: ListNode | null, b: ListNode | null): ListNode | null {
  const dummy = new ListNode();
  let tail = dummy;
  while (a && b) {
    if (a.val <= b.val) {
      tail.next = a;
      a = a.next;
    } else {
      tail.next = b;
      b = b.next;
    }
    tail = tail.next;
  }
  tail.next = a ?? b;                             // остаток одного из списков
  return dummy.next;
}
```

O(n + m) по времени, O(1) по памяти. `<=` сохраняет порядок равных элементов — слияние устойчиво. Это шаг сортировки слиянием ([Разделяй и властвуй](/content/algorithms-data-structures/divide-and-conquer)).
::

::practice{title="138. Copy List with Random Pointer"}
У каждого узла кроме `next` есть `random` — ссылка на любой узел списка или `null`. Сделать глубокую копию: новые узлы, у которых `next` и `random` указывают на соответствующие новые узлы. [Задача на LeetCode](https://leetcode.com/problems/copy-list-with-random-pointer/)

#solution
Узел в этой задаче свой:

```ts
class Node {
  val: number;
  next: Node | null;
  random: Node | null;
  constructor(val?: number, next?: Node | null, random?: Node | null) {
    this.val = val ?? 0;
    this.next = next ?? null;
    this.random = random ?? null;
  }
}
```

Два прохода с таблицей «старый узел → копия»: первый создаёт копии, второй проводит в них ссылки по таблице. `random` может указывать вперёд, поэтому в один проход без таблицы не обойтись.

```ts
function copyRandomList(head: Node | null): Node | null {
  const copies = new Map<Node, Node>();
  for (let n = head; n; n = n.next) copies.set(n, new Node(n.val));
  for (let n = head; n; n = n.next) {
    const copy = copies.get(n)!;
    copy.next = n.next ? copies.get(n.next)! : null;
    copy.random = n.random ? copies.get(n.random)! : null;
  }
  return head ? copies.get(head)! : null;
}
```

O(n) по времени и памяти. Вариант на O(1) памяти: вплести копии между оригиналами (`A → A' → B → B'`), тогда копия `random` — это `node.random.next`, а потом расплести списки. Та же задача в общем виде — глубокое копирование графа с циклами ([Глубокие операции](/content/common-coding-questions/deep-operations)).
::

::practice{title="92. Reverse Linked List II"}
Развернуть часть списка с позиции `left` по `right` (с единицы) за один проход. Пример: `[1, 2, 3, 4, 5]`, `left = 2`, `right = 4` → `[1, 4, 3, 2, 5]`. [Задача на LeetCode](https://leetcode.com/problems/reverse-linked-list-ii/)

#solution
Находим узел **перед** отрезком — с фиктивным узлом он есть даже при `left = 1`. Дальше `right - left` раз берём узел, следующий за первым узлом отрезка, и переносим его в начало отрезка:

```ts
function reverseBetween(head: ListNode | null, left: number, right: number): ListNode | null {
  const dummy = new ListNode(0, head);
  let before = dummy;
  for (let i = 1; i < left; i++) before = before.next!;     // узел перед отрезком
  const start = before.next!;
  for (let i = 0; i < right - left; i++) {
    const moved = start.next!;                    // следующий за start переносим в начало отрезка
    start.next = moved.next;
    moved.next = before.next;
    before.next = moved;
  }
  return dummy.next;
}
```

O(n) по времени, O(1) по памяти. Первый узел отрезка `start` при этом сам «уплывает» в конец отрезка. В проверке результат совпал с разворотом части массива на случайных входах.
::

::practice{title="25. Reverse Nodes in k-Group"}
Развернуть список группами по `k` узлов; последняя неполная группа остаётся как есть. Пример: `[1, 2, 3, 4, 5]`, `k = 2` → `[2, 1, 4, 3, 5]`; `k = 3` → `[3, 2, 1, 4, 5]`. [Задача на LeetCode](https://leetcode.com/problems/reverse-nodes-in-k-group/)

#solution
Тот же перенос узлов в начало отрезка, что и в предыдущей задаче, повторённый для каждой группы. Перед разворотом проверяем, что впереди есть k узлов; после разворота первый узел группы стал её концом и служит «узлом перед» следующей группой.

```ts
function reverseKGroup(head: ListNode | null, k: number): ListNode | null {
  const dummy = new ListNode(0, head);
  let before = dummy;
  for (;;) {
    let check = before;
    for (let i = 0; i < k && check; i++) check = check.next!;
    if (!check) break;                            // в остатке меньше k узлов
    const start = before.next!;
    for (let i = 0; i < k - 1; i++) {
      const moved = start.next!;
      start.next = moved.next;
      moved.next = before.next;
      before.next = moved;
    }
    before = start;                               // start стал концом группы
  }
  return dummy.next;
}
```

O(n) по времени: каждый узел проверяется и переносится константное число раз. O(1) по памяти — без рекурсии. Ошибка — развернуть и неполную группу в конце.
::

::practice{title="19. Remove Nth Node From End of List"}
Удалить n-й узел с конца списка за один проход. Пример: `[1, 2, 3, 4, 5]`, `n = 2` → `[1, 2, 3, 5]`. [Задача на LeetCode](https://leetcode.com/problems/remove-nth-node-from-end-of-list/)

#solution
Два указателя с разрывом: быстрый уходит вперёд на n + 1 узел от фиктивного, потом оба идут до конца. Когда быстрый вышел за конец, медленный стоит **перед** удаляемым.

```ts
function removeNthFromEnd(head: ListNode | null, n: number): ListNode | null {
  const dummy = new ListNode(0, head);
  let fast: ListNode | null = dummy;
  let slow: ListNode = dummy;
  for (let i = 0; i <= n; i++) fast = fast!.next;           // разрыв в n + 1 узел
  while (fast) {
    fast = fast.next;
    slow = slow.next!;
  }
  slow.next = slow.next!.next;                    // slow — перед удаляемым
  return dummy.next;
}
```

O(n) по времени, O(1) по памяти. Фиктивный узел нужен для удаления головы: `[1]` с `n = 1` → пустой список. Без него этот случай пришлось бы обрабатывать отдельно.
::

::practice{title="82. Remove Duplicates from Sorted List II"}
В отсортированном списке удалить все значения, которые встречаются больше одного раза, — целиком, оставив только уникальные. Пример: `[1, 2, 3, 3, 4, 4, 5]` → `[1, 2, 5]`; `[1, 1, 1, 2, 3]` → `[2, 3]`. [Задача на LeetCode](https://leetcode.com/problems/remove-duplicates-from-sorted-list-ii/)

#solution
`prev` — последний узел, который точно остаётся (сначала фиктивный). Если текущий узел равен следующему, пропускаем все узлы с этим значением и прицепляем к `prev` то, что после них. Иначе узел остаётся, и `prev` сдвигается.

```ts
function deleteDuplicates(head: ListNode | null): ListNode | null {
  const dummy = new ListNode(0, head);
  let prev = dummy;
  let node = head;
  while (node) {
    if (node.next && node.next.val === node.val) {
      const v = node.val;
      while (node && node.val === v) node = node.next;    // пропустить все копии
      prev.next = node;
    } else {
      prev = node;
      node = node.next;
    }
  }
  return dummy.next;
}
```

O(n) по времени, O(1) по памяти. Фиктивный узел снова спасает случай, когда удаляется голова. После пропуска копий `prev` не сдвигается: следующий узел тоже может оказаться дубликатом.
::

::practice{title="61. Rotate List"}
Сдвинуть список вправо на `k` позиций. Пример: `[1, 2, 3, 4, 5]`, `k = 2` → `[4, 5, 1, 2, 3]`; `[0, 1, 2]`, `k = 4` → `[2, 0, 1]`. [Задача на LeetCode](https://leetcode.com/problems/rotate-list/)

#solution
Считаем длину и хвост, сокращаем `k` по модулю длины, замыкаем список в кольцо и разрезаем после узла `length - k - 1` от головы:

```ts
function rotateRight(head: ListNode | null, k: number): ListNode | null {
  if (!head || !head.next) return head;
  let length = 1;
  let tail = head;
  while (tail.next) {
    tail = tail.next;
    length++;
  }
  k %= length;
  if (k === 0) return head;
  tail.next = head;                               // замкнуть в кольцо
  let newTail = head;
  for (let i = 0; i < length - k - 1; i++) newTail = newTail.next!;
  const newHead = newTail.next;
  newTail.next = null;                            // разрезать
  return newHead;
}
```

O(n) по времени, O(1) по памяти. `k` может быть больше длины — без `k %= length` цикл сдвигов был бы огромным. Ошибка — забыть разрезать кольцо: список станет бесконечным.
::

::practice{title="86. Partition List"}
Переставить узлы так, чтобы все со значением меньше `x` шли перед остальными, сохранив исходный порядок внутри каждой части. Пример: `[1, 4, 3, 2, 5, 2]`, `x = 3` → `[1, 2, 2, 4, 3, 5]`. [Задача на LeetCode](https://leetcode.com/problems/partition-list/)

#solution
Собираем два списка — «меньше» и «остальные» — каждый со своим фиктивным узлом, потом склеиваем:

```ts
function partition(head: ListNode | null, x: number): ListNode | null {
  const lessDummy = new ListNode();
  const restDummy = new ListNode();
  let less = lessDummy;
  let rest = restDummy;
  for (let node = head; node; node = node.next) {
    if (node.val < x) less = less.next = node;
    else rest = rest.next = node;
  }
  rest.next = null;                               // иначе может остаться цикл
  less.next = restDummy.next;
  return lessDummy.next;
}
```

O(n) по времени, O(1) по памяти. `rest.next = null` обязателен: последний «остальной» узел может по-прежнему ссылаться на узел из списка «меньше», и получится цикл. Это устойчивое разбиение — тот же шаг, что в быстрой сортировке списков.
::

::practice{title="146. LRU Cache"}
Реализовать кеш с вытеснением давно не использованных записей: `get(key)` возвращает значение или −1, `put(key, value)` добавляет или обновляет запись, а при превышении ёмкости удаляет ту, к которой дольше всех не обращались. Обе операции — O(1). [Задача на LeetCode](https://leetcode.com/problems/lru-cache/)

#solution
Классическое решение — хеш-таблица и двусвязный список: таблица находит узел за O(1), список хранит порядок использования. В JavaScript `Map` уже хранит ключи в порядке вставки, поэтому список не нужен: чтобы отметить использование, ключ удаляют и вставляют заново, а самый давний — первый ключ.

```ts
class LRUCache {
  private map = new Map<number, number>();       // Map помнит порядок вставки
  constructor(private capacity: number) {}

  get(key: number): number {
    if (!this.map.has(key)) return -1;
    const value = this.map.get(key)!;
    this.map.delete(key);                         // переставить в конец — самый свежий
    this.map.set(key, value);
    return value;
  }

  put(key: number, value: number): void {
    this.map.delete(key);
    this.map.set(key, value);
    if (this.map.size > this.capacity) {
      this.map.delete(this.map.keys().next().value!);   // первый — самый давний
    }
  }
}
```

O(1) в среднем на операцию. В проверке поведение совпало с моделью на массиве на сотнях случайных последовательностей операций. На собеседовании могут попросить и версию с двусвязным списком — она нужна в языках без упорядоченной хеш-таблицы; реализация — в [Кешировании и состоянии](/content/common-coding-questions/caching-and-state).
::

## Красные флаги в ответе

- **Изменить `node.next`, не сохранив старое значение.** Остаток списка потерян.
- **Отдельные ветки кода для «удалить голову».** Фиктивный узел делает этот случай обычным.
- **Сравнение узлов по значению при поиске цикла.** Значения повторяются; сравнивают ссылки.
- **Переводить список цифр в число.** Длинные числа теряют точность; складывают столбиком.
- **Забыть оборвать хвост** после перестановок — в разбиении и повороте получится цикл.

## Как спрашивают на собеседовании

::question
Как найти цикл в связном списке без дополнительной памяти?

#answer
Алгоритм Флойда: медленный указатель идёт на один узел, быстрый — на два. Без цикла быстрый дойдёт до `null`, а в цикле догонит медленного: внутри цикла разрыв между ними сокращается на один узел за шаг. Время O(n), память O(1).

#more
Начало цикла: после встречи один указатель ставят в голову и двигают оба по одному — встретятся в начале цикла. Это следует из того, что расстояние от головы до начала цикла равно расстоянию от точки встречи до начала по циклу (с точностью до целого числа оборотов). Тот же алгоритм находит повтор в последовательности, например в задаче о счастливых числах.
::

::question
Зачем нужен фиктивный узел?

#answer
Он стоит перед головой и превращает «изменение головы» в обычный случай: удаление первого узла, вставка в начало, сборка нового списка. Без него код обрастает проверками `if (head === …)`. В конце возвращают `dummy.next`.

#more
Фиктивные узлы используют при слиянии, разбиении, удалении по условию и развороте части списка. В двусвязных списках часто держат два фиктивных узла — голову и хвост, — и тогда у каждого настоящего узла всегда есть оба соседа: так устроен классический LRU-кеш.
::

::question
Как развернуть связный список?

#answer
Итеративно тремя переменными: `prev` — уже развёрнутая часть, `node` — текущий, `next` — сохранённый хвост. На каждом шаге сохраняем `next = node.next`, разворачиваем `node.next = prev`, сдвигаем `prev = node`, `node = next`. В конце `prev` — новая голова. O(n) по времени, O(1) по памяти.

#more
Рекурсивная версия короче, но тратит O(n) стека и на длинном списке переполнит его. Развернуть часть списка или группы по k — тот же приём «перенести следующий узел в начало отрезка». Разворот половины списка помогает проверить список на палиндром за O(1) памяти.
::

::question
Как реализовать LRU-кеш с операциями за O(1)?

#answer
Хеш-таблица ключ → узел и двусвязный список узлов в порядке использования. `get` находит узел и переносит его в начало, `put` добавляет в начало и, если места нет, удаляет узел с конца. Всё O(1). В JavaScript `Map` хранит порядок вставки, поэтому достаточно удалить и заново вставить ключ, а вытеснять первый.

#more
На собеседовании часто просят именно версию со списком, чтобы проверить работу со ссылками. Варианты: TTL — запись устаревает по времени, LFU — вытесняется реже всего используемая (две таблицы и списки по частоте). Во фронтенде LRU используют для кеша запросов, мемоизации и картинок.
::
