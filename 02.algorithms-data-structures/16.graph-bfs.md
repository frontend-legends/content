# Графы: обход в ширину

Обход в ширину находит кратчайший путь в графе без весов: вершины выходят из очереди в порядке расстояния от старта, и первый раз, когда мы дошли до цели, — это и есть минимальное число шагов. Сложность задач этой категории не в самом обходе, а в том, чтобы увидеть граф: клетки доски с лестницами, гены, отличающиеся одной буквой, слова в словаре. Спрашивают «Змеи и лестницы», минимальную мутацию гена и лестницу слов.

::tldr
- **BFS даёт кратчайший путь по числу рёбер:** вершины обрабатываются слоями по расстоянию, и первое достижение цели — минимальное.
- **Отмечать вершину посещённой нужно при добавлении в очередь** — иначе одна вершина попадёт туда много раз.
- **Граф часто неявный:** соседи вычисляются на лету — шесть ходов кубика, замена одной буквы. Строить все рёбра заранее не нужно.
- **Для весов BFS не подходит:** нужен алгоритм Дейкстры, а для весов 0 и 1 — дек вместо очереди.
::

---

## Как узнать паттерн

- Нужно **минимальное число шагов**, ходов, преобразований.
- Каждый шаг **стоит одинаково** — один ход, одна замена.
- Состояние меняется **маленькими переходами**: ход на доске, замена буквы, поворот колёсика замка.

Если шаги стоят по-разному, BFS даст неправильный ответ — нужен алгоритм Дейкстры с кучей ([Куча](/content/algorithms-data-structures/heap)). Если путь не обязан быть кратчайшим, проще обход в глубину ([Графы](/content/algorithms-data-structures/graph-general)).

## Шаблон

Расстояния от стартовой вершины до всех остальных:

```ts
function bfsDistances(graph: number[][], start: number): number[] {
  const dist = new Array(graph.length).fill(-1);
  dist[start] = 0;
  const queue = [start];
  for (let head = 0; head < queue.length; head++) {
    const v = queue[head];
    for (const u of graph[v]) {
      if (dist[u] === -1) {                       // первый раз нашли — это и есть кратчайший путь
        dist[u] = dist[v] + 1;
        queue.push(u);
      }
    }
  }
  return dist;
}
```

O(V + E). Массив расстояний заодно служит отметкой посещения: −1 — не посещена. Очередь — массив с указателем головы, без `shift` ([Обход дерева в ширину](/content/algorithms-data-structures/binary-tree-bfs)).

**Двусторонний BFS** — обход одновременно от старта и от цели до встречи. При ветвлении b и расстоянии d он просматривает около 2 · b^(d/2) вершин вместо b^d — полезно в лестнице слов на большом словаре.

::practice{title="909. Snakes and Ladders"}
Доска `n × n`, клетки пронумерованы от 1 до n² змейкой снизу вверх: нижний ряд слева направо, следующий — справа налево. В клетке `-1` или номер клетки, куда ведёт лестница или змея. Ход — бросок кубика 1–6; если клетка с лестницей или змеёй, сразу переходишь по ней (только один раз за ход). Найти минимальное число ходов от клетки 1 до n², или −1. [Задача на LeetCode](https://leetcode.com/problems/snakes-and-ladders/)

#solution
Клетки — вершины, из каждой шесть рёбер — броски кубика с учётом лестниц и змей. Все ходы стоят одинаково, значит, кратчайший путь ищет BFS. Главная сложность — перевести номер клетки в координаты:

```ts
function snakesAndLadders(board: number[][]): number {
  const n = board.length;
  const cell = (k: number): number => {           // номер клетки 1..n² → значение на доске
    const row = Math.floor((k - 1) / n);
    const col = (k - 1) % n;
    const r = n - 1 - row;                        // ряды снизу вверх
    const c = row % 2 === 0 ? col : n - 1 - col;  // змейкой: чётные слева направо
    return board[r][c];
  };
  const target = n * n;
  const dist = new Map<number, number>([[1, 0]]);
  const queue = [1];
  for (let head = 0; head < queue.length; head++) {
    const k = queue[head];
    if (k === target) return dist.get(k)!;
    for (let step = 1; step <= 6 && k + step <= target; step++) {
      let next = k + step;
      if (cell(next) !== -1) next = cell(next);   // лестница или змея — переход сразу
      if (!dist.has(next)) {
        dist.set(next, dist.get(k)! + 1);
        queue.push(next);
      }
    }
  }
  return -1;
}
```

O(n²) — каждая клетка обрабатывается раз с шестью бросками. Ошибки: перепутать направление рядов, пройти по двум лестницам подряд за ход, отмечать посещённой клетку броска, а не клетку после лестницы. В проверке ответ совпал с поиском минимума ходов перебором по раундам на сотнях случайных досок.
::

::practice{title="433. Minimum Genetic Mutation"}
Ген — строка из 8 букв `A`, `C`, `G`, `T`. Мутация меняет одну букву, и полученный ген должен быть в банке допустимых. Найти минимальное число мутаций от `startGene` до `endGene`, или −1. [Задача на LeetCode](https://leetcode.com/problems/minimum-genetic-mutation/)

#solution
Гены — вершины, мутации — рёбра; соседей перебираем на лету: 8 позиций × 4 буквы. BFS по уровням:

```ts
function minMutation(startGene: string, endGene: string, bank: string[]): number {
  const allowed = new Set(bank);
  if (!allowed.has(endGene)) return -1;
  const seen = new Set([startGene]);
  let level = [startGene];
  for (let steps = 0; level.length; steps++) {
    const next: string[] = [];
    for (const gene of level) {
      if (gene === endGene) return steps;
      for (let i = 0; i < gene.length; i++) {
        for (const c of 'ACGT') {
          const mutated = gene.slice(0, i) + c + gene.slice(i + 1);
          if (allowed.has(mutated) && !seen.has(mutated)) {
            seen.add(mutated);
            next.push(mutated);
          }
        }
      }
    }
    level = next;
  }
  return -1;
}
```

O(B · L · 4) для банка из B генов длины L. Стартовый ген не обязан быть в банке, а конечный — обязан. Проверить конечный в банке заранее — дешёвая отсечка.
::

::practice{title="127. Word Ladder"}
Найти длину кратчайшей цепочки слов от `beginWord` до `endWord`, где соседние слова отличаются одной буквой, а все слова кроме первого — из словаря. Длина считается в словах; если цепочки нет — 0. Пример: `"hit"` → `"cog"` через `hot, dot, dog` — 5. [Задача на LeetCode](https://leetcode.com/problems/word-ladder/)

#solution
То же, что мутация гена, но с алфавитом из 26 букв. Чтобы не хранить отдельно посещённые, слово удаляют из словаря, как только положили в очередь:

```ts
function ladderLength(beginWord: string, endWord: string, wordList: string[]): number {
  const words = new Set(wordList);
  if (!words.has(endWord)) return 0;
  let level = [beginWord];
  words.delete(beginWord);
  for (let length = 1; level.length; length++) {
    const next: string[] = [];
    for (const word of level) {
      if (word === endWord) return length;
      for (let i = 0; i < word.length; i++) {
        for (let code = 97; code <= 122; code++) {
          const candidate = word.slice(0, i) + String.fromCharCode(code) + word.slice(i + 1);
          if (words.has(candidate)) {
            words.delete(candidate);              // удалить — значит отметить посещённым
            next.push(candidate);
          }
        }
      }
    }
    level = next;
  }
  return 0;
}
```

O(N · L · 26) для словаря из N слов длины L. Перебор «каждая пара слов — соседи?» стоил бы O(N² · L) — на больших словарях это главная разница. Длина в словах, а не в шагах: ответ на единицу больше числа замен. В проверке результат совпал с BFS по явному графу слов.
::

## Красные флаги в ответе

- **Обход в глубину для кратчайшего пути.** DFS находит какой-то путь, но не кратчайший.
- **BFS на графе с весами.** Вес ребра игнорируется; нужен Дейкстра.
- **Строить все рёбра «каждый с каждым» заранее.** O(N²); соседей перебирают заменой символа.
- **Отмечать посещённые при снятии из очереди.** Вершина успеет попасть в очередь несколько раз.
- **Путаница длины в вершинах и в рёбрах.** В лестнице слов ответ — число слов.

## Как спрашивают на собеседовании

::question
Почему обход в ширину находит кратчайший путь?

#answer
Очередь выпускает вершины в порядке расстояния от старта: сначала все на расстоянии 1, потом 2 и так далее. Поэтому, когда вершина впервые попадает в очередь, путь до неё минимален — более короткий был бы найден на предыдущем уровне. Это верно, только если все рёбра стоят одинаково.

#more
Для весов — алгоритм Дейкстры с приоритетной очередью, O((V + E) log V). Для весов 0 и 1 — BFS с деком: ребро веса 0 кладёт вершину в начало, веса 1 — в конец. С отрицательными весами — Беллман — Форд. Двусторонний BFS ускоряет поиск на больших графах.
::

::question
Как решать задачи, где граф не задан явно?

#answer
Определить, что такое вершина (состояние) и как получить её соседей (допустимые переходы), и перебирать соседей на лету внутри обхода. Посещённые состояния хранить во множестве. Строить граф целиком заранее обычно дороже: число рёбер может быть квадратичным.

#more
Примеры: клетка доски и шесть бросков, слово и замены одной буквы, положение колёсиков замка и повороты. Состояние должно быть хешируемым — строкой или числом, — чтобы хранить его во множестве. Если состояний слишком много, помогает двусторонний поиск или эвристика (A*).
::

::question
Чем двусторонний BFS лучше обычного?

#answer
Он ищет одновременно от старта и от цели и останавливается при встрече. При ветвлении b и расстоянии d обычный BFS просматривает порядка b^d состояний, а двусторонний — порядка 2 · b^(d/2). На лестнице слов с большим словарём разница — порядки величины.

#more
Удобно каждый раз расширять меньший из двух фронтов. Нужно знать цель заранее и уметь искать соседей в обратную сторону — для неориентированных переходов, как замена буквы, это одно и то же.
::
