# Хеш-таблицы

Хеш-таблица отвечает на вопрос «есть ли такое значение» и «что лежит по этому ключу» в среднем за O(1). Поэтому её первой достают, когда перебор пар даёт O(n²): вместо поиска партнёра для каждого элемента заглядывают в таблицу уже виденных. Спрашивают Two Sum, анаграммы, изоморфные строки, счётчики символов и самую длинную последовательность подряд идущих чисел за O(n).

::tldr
- **Хеш-таблица превращает поиск партнёра из O(n) в O(1):** «есть ли `target - x` среди уже виденных» — и Two Sum решается одним проходом.
- **Три приёма покрывают большинство задач:** счётчик частот, таблица «значение → индекс» для уже виденного и префиксные суммы с подсчётом.
- **Ключ группы — канонический вид элемента:** у анаграмм это отсортированные буквы или вектор частот.
- **Взаимно однозначное соответствие проверяют двумя таблицами** — в обе стороны, иначе `"badc"` и `"baba"` сойдутся.
- **В JavaScript для таких задач берут `Map` и `Set`, а не объект:** ключи любого типа, порядок вставки, честный `size` и никаких унаследованных ключей.
::

---

## Как узнать паттерн

- Перебор **пар** элементов: «найти два с суммой», «есть ли дубликат на расстоянии k».
- Нужно **посчитать** что-то: частоты символов, количество отрезков с суммой.
- Нужно **сгруппировать** по признаку: анаграммы, одинаковая форма.
- Нужно **соответствие** между двумя последовательностями: изоморфизм, шаблон слов.
- Нужна проверка «есть ли x» **много раз**: `includes` в цикле превращается в `Set.has` ([Математика для CS](/content/computer-science/math-for-cs)).

Цена — память O(n). Если массив отсортирован и память ограничена, пару ищут двумя указателями ([Два указателя](/content/algorithms-data-structures/two-pointers)). Как хеш-таблица устроена внутри — корзины, :term[коллизии]{def="совпадения номеров корзин у разных ключей"}, перестроение — в [Структурах данных](/content/algorithms-data-structures/data-structures).

## Шаблоны

**Счётчик частот:**

```ts
function countBy<T>(items: Iterable<T>): Map<T, number> {
  const count = new Map<T, number>();
  for (const x of items) count.set(x, (count.get(x) ?? 0) + 1);
  return count;
}
```

**Уже виденное:** таблица «значение → индекс» заполняется по ходу прохода, и для каждого элемента проверяется партнёр среди предыдущих. Так решаются Two Sum и поиск близких дубликатов — ниже в задачах.

**Префиксные суммы с подсчётом.** Сумма отрезка `[i, j]` — это `prefix[j] - prefix[i - 1]`. Чтобы найти количество отрезков с суммой `k`, на каждом шаге спрашиваем, сколько раз раньше встречалась префиксная сумма `prefix - k`:

```ts
function subarraySum(nums: number[], k: number): number {
  const seen = new Map<number, number>([[0, 1]]); // префиксная сумма → сколько раз встречалась
  let prefix = 0;
  let count = 0;
  for (const x of nums) {
    prefix += x;
    count += seen.get(prefix - k) ?? 0;           // отрезки, которые кончаются здесь и дают k
    seen.set(prefix, (seen.get(prefix) ?? 0) + 1);
  }
  return count;
}
```

Начальная запись `0 → 1` отвечает за отрезки с самого начала массива. Этот приём работает и с отрицательными числами — там, где скользящее окно ломается ([Скользящее окно](/content/algorithms-data-structures/sliding-window)): в проверке `[1, -1, 0]` с `k = 0` дал три отрезка, как и перебор.

::practice{title="383. Ransom Note"}
Можно ли составить строку `ransomNote` из букв строки `magazine`, если каждую букву журнала можно использовать один раз? Пример: `"aa"` из `"aab"` — да, из `"ab"` — нет. [Задача на LeetCode](https://leetcode.com/problems/ransom-note/)

#solution
Считаем буквы журнала, потом тратим их на записку. Не хватило буквы — нельзя.

```ts
function canConstruct(ransomNote: string, magazine: string): boolean {
  const count = new Map<string, number>();
  for (const c of magazine) count.set(c, (count.get(c) ?? 0) + 1);
  for (const c of ransomNote) {
    const left = count.get(c) ?? 0;
    if (left === 0) return false;
    count.set(c, left - 1);
  }
  return true;
}
```

O(n + m) по времени. Для 26 строчных латинских букв `Map` можно заменить массивом из 26 чисел. Ошибка — проверять `magazine.includes(c)`: не учитывает, что буква уже потрачена.
::

::practice{title="205. Isomorphic Strings"}
Строки `s` и `t` изоморфны, если символы `s` можно заменить так, чтобы получилась `t`: каждый символ заменяется всегда одним и тем же, и два разных символа не могут перейти в один. Примеры: `"egg"` и `"add"` — да, `"foo"` и `"bar"` — нет. [Задача на LeetCode](https://leetcode.com/problems/isomorphic-strings/)

#solution
Соответствие должно быть взаимно однозначным, поэтому таблиц две: `s → t` и `t → s`. Любое противоречие в одной из них — не изоморфны.

```ts
function isIsomorphic(s: string, t: string): boolean {
  const st = new Map<string, string>();
  const ts = new Map<string, string>();
  for (let i = 0; i < s.length; i++) {
    const a = s[i];
    const b = t[i];
    if ((st.has(a) && st.get(a) !== b) || (ts.has(b) && ts.get(b) !== a)) return false;
    st.set(a, b);
    ts.set(b, a);
  }
  return true;
}
```

O(n) по времени. С одной таблицей `"badc"` и `"baba"` пройдут проверку: `b → b`, `a → a`, `d → b`, `c → a` — разные символы ушли в один, и это ловит только обратная таблица. В проверке решение совпало со сравнением «формы» строк — списка индексов первого вхождения каждого символа.
::

::practice{title="290. Word Pattern"}
Дан шаблон из букв и строка из слов через пробел. Строка подходит под шаблон, если между буквами и словами есть взаимно однозначное соответствие. Примеры: `"abba"` и `"dog cat cat dog"` — да, `"abba"` и `"dog dog dog dog"` — нет. [Задача на LeetCode](https://leetcode.com/problems/word-pattern/)

#solution
То же, что изоморфные строки, только второй алфавит — слова. Сначала сравниваем длины, потом две таблицы:

```ts
function wordPattern(pattern: string, s: string): boolean {
  const words = s.split(' ');
  if (words.length !== pattern.length) return false;
  const pw = new Map<string, string>();
  const wp = new Map<string, string>();
  for (let i = 0; i < words.length; i++) {
    const p = pattern[i];
    const w = words[i];
    if ((pw.has(p) && pw.get(p) !== w) || (wp.has(w) && wp.get(w) !== p)) return false;
    pw.set(p, w);
    wp.set(w, p);
  }
  return true;
}
```

O(n) по времени, где n — длина строки. Ошибки: забыть сравнить длины (`"aaa"` и четыре слова), одна таблица вместо двух.
::

::practice{title="242. Valid Anagram"}
Является ли строка `t` анаграммой `s` — те же буквы в том же количестве, в другом порядке? Пример: `"anagram"` и `"nagaram"` — да. [Задача на LeetCode](https://leetcode.com/problems/valid-anagram/)

#solution
Сортировка обеих строк и сравнение — O(n log n). Счётчик — O(n): прибавляем буквы одной строки и вычитаем буквы другой.

```ts
function isAnagram(s: string, t: string): boolean {
  if (s.length !== t.length) return false;
  const count = new Map<string, number>();
  for (const c of s) count.set(c, (count.get(c) ?? 0) + 1);
  for (const c of t) {
    const left = count.get(c) ?? 0;
    if (left === 0) return false;
    count.set(c, left - 1);
  }
  return true;
}
```

Продолжение из условия — что если строки в Unicode? `for…of` идёт по кодовым точкам, поэтому эмодзи и символы вне базовой плоскости посчитаются правильно, а составные символы с диакритикой лучше сначала нормализовать ([Представление данных](/content/computer-science/data-representation)).
::

::practice{title="49. Group Anagrams"}
Сгруппировать строки массива по анаграммам. Пример: `["eat", "tea", "tan", "ate", "nat", "bat"]` → `[["bat"], ["nat", "tan"], ["ate", "eat", "tea"]]` в любом порядке. [Задача на LeetCode](https://leetcode.com/problems/group-anagrams/)

#solution
Ключ группы — канонический вид строки, одинаковый у всех анаграмм. Отсортированные буквы дают O(k log k) на строку; вектор частот 26 букв — O(k):

```ts
function groupAnagrams(strs: string[]): string[][] {
  const groups = new Map<string, string[]>();
  for (const s of strs) {
    const freq = new Array(26).fill(0);
    for (const c of s) freq[c.charCodeAt(0) - 97]++;
    const key = freq.join(',');                   // одинаковые частоты — одна группа
    const group = groups.get(key);
    if (group) group.push(s);
    else groups.set(key, [s]);
  }
  return [...groups.values()];
}
```

O(n · k) по времени, где k — длина строки. Ключ собирают с разделителем: без запятых частоты `[1, 11]` и `[11, 1]` склеились бы в одинаковую строку `"111"`. В проверке группировка совпала с группировкой по отсортированным буквам.
::

::practice{title="1. Two Sum"}
Найти индексы двух разных элементов массива с суммой `target`. Решение гарантированно одно. Пример: `[2, 7, 11, 15]`, `target = 9` → `[0, 1]`. [Задача на LeetCode](https://leetcode.com/problems/two-sum/)

#solution
Перебор пар — O(n²). Один проход с таблицей уже виденных значений: для каждого числа проверяем, встречался ли раньше его партнёр `target - x`.

```ts
function twoSum(nums: number[], target: number): number[] {
  const seen = new Map<number, number>();         // значение → индекс
  for (let i = 0; i < nums.length; i++) {
    const j = seen.get(target - nums[i]);
    if (j !== undefined) return [j, i];
    seen.set(nums[i], i);
  }
  return [];
}
```

O(n) по времени и памяти. Проверка партнёра **до** записи текущего числа не даёт взять один элемент дважды: на `[3, 3]` с целью 6 ответ `[0, 1]`, а на `[3]` — пусто. Проверка `if (j)` вместо `j !== undefined` — классическая ошибка: индекс 0 — ложное значение. Сортировка с двумя указателями тоже работает, но теряет исходные индексы.
::

::practice{title="202. Happy Number"}
Число «счастливое», если, заменяя его суммой квадратов цифр, в итоге получаем 1. Если процесс зацикливается, не дойдя до 1, — нет. Пример: 19 → 82 → 68 → 100 → 1 — счастливое; 2 — нет. [Задача на LeetCode](https://leetcode.com/problems/happy-number/)

#solution
Последовательность либо приходит в 1, либо попадает в цикл: сумма квадратов цифр быстро уменьшает большие числа, и значения остаются в небольшом диапазоне. Цикл находим множеством уже виденных чисел:

```ts
function isHappy(n: number): boolean {
  const next = (x: number) => {
    let sum = 0;
    for (; x > 0; x = Math.floor(x / 10)) sum += (x % 10) ** 2;
    return sum;
  };
  const seen = new Set<number>();
  while (n !== 1 && !seen.has(n)) {
    seen.add(n);
    n = next(n);
  }
  return n === 1;
}
```

Вариант без памяти — быстрый и медленный указатели Флойда, как поиск цикла в связном списке ([Связный список](/content/algorithms-data-structures/linked-list)). В проверке ответы для чисел от 1 до 2000 совпали с прямым моделированием на 1000 шагов.
::

::practice{title="219. Contains Duplicate II"}
Есть ли в массиве два одинаковых элемента на расстоянии индексов не больше `k`? Пример: `[1, 2, 3, 1]`, `k = 3` — да; `[1, 2, 3, 1, 2, 3]`, `k = 2` — нет. [Задача на LeetCode](https://leetcode.com/problems/contains-duplicate-ii/)

#solution
Для каждого значения храним последний индекс: ближайший предыдущий дубль — всегда последний, более ранние только дальше.

```ts
function containsNearbyDuplicate(nums: number[], k: number): boolean {
  const last = new Map<number, number>();         // значение → последний индекс
  for (let i = 0; i < nums.length; i++) {
    const j = last.get(nums[i]);
    if (j !== undefined && i - j <= k) return true;
    last.set(nums[i], i);
  }
  return false;
}
```

O(n) по времени и памяти. Вариант на O(k) памяти — скользящее окно из множества последних k элементов: добавить текущий, удалить выпавший из окна.
::

::practice{title="128. Longest Consecutive Sequence"}
Найти длину самой длинной последовательности подряд идущих целых чисел, которые есть в массиве (в любом порядке), за O(n). Пример: `[100, 4, 200, 1, 3, 2]` → 4 (`1, 2, 3, 4`). [Задача на LeetCode](https://leetcode.com/problems/longest-consecutive-sequence/)

#solution
Сортировка даёт O(n log n). За O(n): кладём числа во множество и начинаем считать последовательность только с её начала — с числа `x`, у которого нет `x - 1`. Тогда каждое число просматривается во внутреннем цикле один раз.

```ts
function longestConsecutive(nums: number[]): number {
  const set = new Set(nums);
  let best = 0;
  for (const x of set) {
    if (set.has(x - 1)) continue;                 // не начало последовательности
    let len = 1;
    while (set.has(x + len)) len++;
    best = Math.max(best, len);
  }
  return best;
}
```

Без проверки `x - 1` решение становится O(n²) на массиве `[1, 2, …, n]`. Перебирать нужно множество, а не исходный массив: при множестве дублей начала последовательности иначе посчитались бы много раз. В проверке миллион чисел обработался быстро, а на случайных массивах ответ совпал с решением через сортировку.
::

## Красные флаги в ответе

- **«Хеш-таблица — всегда O(1)».** В среднем; при плохой хеш-функции или атаке коллизиями — O(n). Плюс O(n) памяти.
- **Объект вместо `Map` для произвольных ключей.** Ключи превращаются в строки, `'__proto__'` ведёт себя особо, а числовые ключи меняют порядок.
- **`if (map.get(x))` для проверки наличия.** Значения 0, пустая строка и `false` ложны; нужно `has` или сравнение с `undefined`.
- **Одна таблица там, где нужно взаимно однозначное соответствие.** Изоморфизм и шаблон слов проверяют в обе стороны.
- **Ключ группы без разделителей.** `[1, 11].join('')` и `[11, 1].join('')` дают одну строку.

## Как спрашивают на собеседовании

::question
Как решить Two Sum за O(n)? А если массив отсортирован?

#answer
Одним проходом с `Map` «значение → индекс»: для каждого числа проверяем, есть ли среди уже виденных `target - x`, и только потом добавляем текущее. Время O(n), память O(n). Если массив отсортирован, двумя указателями с концов — O(n) времени и O(1) памяти.

#more
Проверка до добавления не даёт использовать элемент дважды. Если нужны все пары или пары без повторов, к таблице добавляют счётчики. Для 3Sum хеш-таблица тоже работает, но сортировка с указателями проще убирает дубликаты троек.
::

::question
Почему для этих задач берут `Map`, а не обычный объект?

#answer
У `Map` ключи любого типа без превращения в строку, нет унаследованных ключей из прототипа, есть `size` и порядок вставки, и он быстрее при частых добавлениях и удалениях. У объекта ключи — строки и символы: число `1` и строка `'1'` совпадут, а ключ `'__proto__'` поведёт себя особо.

#more
Для простого словаря с известными строковыми ключами объект подходит. `Object.create(null)` убирает прототип, но остальные отличия остаются. Подробно о различиях — в главе про объекты и коллекции JavaScript.
::

::question
Как посчитать количество подмассивов с суммой k, если числа могут быть отрицательными?

#answer
Префиксными суммами с хеш-таблицей. Сумма отрезка — разность двух префиксных сумм, поэтому на каждом шаге прибавляем к ответу, сколько раз раньше встречалась сумма `prefix - k`. Начальная запись `0 → 1` учитывает отрезки с начала массива. Время и память O(n).

#more
Скользящее окно здесь не работает: с отрицательными числами сжатие окна может увеличить сумму. Тот же приём находит самый длинный отрезок с суммой k (хранить первый индекс каждой префиксной суммы) и отрезки с суммой, кратной k (хранить остатки).
::

::question
Как найти самую длинную последовательность подряд идущих чисел за O(n)?

#answer
Сложить числа во множество и для каждого числа, у которого нет предшественника `x - 1`, считать длину последовательности вверх, пока есть `x + 1`. Каждое число внутренним циклом просматривается один раз, поэтому итог O(n).

#more
Без проверки начала последовательности сложность становится O(n²). Сортировка решает за O(n log n) и проще, но условие требует O(n). Альтернатива — система непересекающихся множеств, объединяющая соседние числа, но она сложнее и не быстрее.
::
