# Одномерное динамическое программирование

Динамическое программирование (DP) — это рекурсия, которая не решает одну подзадачу дважды. Если ответ складывается из ответов на меньшие подзадачи, а подзадачи повторяются, их результаты запоминают — и экспоненциальный перебор становится полиномиальным. В одномерном DP состояние — одно число: позиция в массиве, длина префикса, сумма. Спрашивают лестницу, грабителя, разбиение строки на слова, размен монет и наибольшую возрастающую подпоследовательность.

::tldr
- **DP применимо, когда есть оптимальная подструктура и пересекающиеся подзадачи:** ответ для состояния выражается через ответы меньших состояний, и одни и те же состояния встречаются много раз.
- **Решение начинается с формулировки состояния:** «`dp[i]` — число способов дойти до ступени i», «минимум монет для суммы a». Дальше — переход, базовый случай и порядок вычисления.
- **Сверху вниз — рекурсия с мемоизацией, снизу вверх — таблица.** Ответы одинаковые; таблица не тратит стек, мемоизация считает только нужные состояния.
- **Если переход смотрит на k предыдущих состояний, хранят только их:** лестница и грабитель — O(1) памяти.
- **Жадный выбор и DP легко перепутать:** для монет `[1, 3, 4]` и суммы 6 жадный даёт 4 + 1 + 1, а оптимум — 3 + 3.
::

---

## Как узнать паттерн

- Нужно **число способов**, **минимум** или **максимум**, а не сами варианты.
- Решение строится **последовательностью выборов**: шагнуть на 1 или на 2, взять дом или пропустить, какую монету положить.
- Перебор с возвратом работает, но **одни и те же подзадачи** считаются заново.
- Ограничения средние — n до 10⁴–10⁵: O(n²) или O(n · k) проходит, 2^n — нет.

Если нужны **все** варианты, а не их число, — это перебор с возвратом ([Перебор с возвратом](/content/algorithms-data-structures/backtracking)). Если состояние — пара индексов или позиция на сетке, — многомерное DP ([Многомерное DP](/content/algorithms-data-structures/multidimensional-dp)).

## Шаблон

Числа Фибоначчи трижды. Наивная рекурсия:

```ts
let naiveCalls = 0;
function fibNaive(n: number): number {
  naiveCalls++;
  return n < 2 ? n : fibNaive(n - 1) + fibNaive(n - 2);
}
```

**Сверху вниз** — та же рекурсия, но каждое состояние считается один раз:

```ts
function fibMemo(n: number, memo = new Map<number, number>()): number {
  if (n < 2) return n;
  if (!memo.has(n)) memo.set(n, fibMemo(n - 1, memo) + fibMemo(n - 2, memo));   // каждое n — один раз
  return memo.get(n)!;
}
```

**Снизу вверх** — состояния по порядку, и хранить нужно только два последних:

```ts
function fibTable(n: number): number {
  if (n < 2) return n;
  let prev = 0;
  let cur = 1;
  for (let i = 2; i <= n; i++) [prev, cur] = [cur, prev + cur];   // нужны только два последних
  return cur;
}
```

Наивная версия для n = 25 сделала 242 785 вызовов — это 2 · F(26) − 1, рост как φ^n ≈ 1.618^n. Мемоизация и таблица — O(n). В `number` числа Фибоначчи точны до F(78); F(79) уже больше `Number.MAX_SAFE_INTEGER`, и дальше нужен `BigInt`.

Порядок построения решения: **состояние** (что значит `dp[i]`), **переход** (как `dp[i]` выражается через меньшие), **база** (`dp[0]`), **порядок** (чтобы нужные состояния были готовы), **ответ** (`dp[n]` или максимум по всем). Мемоизация на фронтенде — тот же принцип, что `useMemo` и кеш селекторов ([Функции высшего порядка](/content/common-coding-questions/higher-order-utils)).

::practice{title="70. Climbing Stairs"}
Лестница из n ступеней, за шаг можно подняться на 1 или 2. Сколько способов дойти до верха? Пример: 2 → 2; 3 → 3 (`1+1+1`, `1+2`, `2+1`). [Задача на LeetCode](https://leetcode.com/problems/climbing-stairs/)

#solution
На ступень `i` приходят с `i - 1` или с `i - 2`, поэтому способов `dp[i] = dp[i-1] + dp[i-2]` — это Фибоначчи со сдвигом. Хранить нужно два последних значения:

```ts
function climbStairs(n: number): number {
  let oneBack = 1;                                // способов дойти до ступени i - 1
  let twoBack = 1;                                // до ступени i - 2 (для i = 1 — «с земли»)
  for (let i = 2; i <= n; i++) [twoBack, oneBack] = [oneBack, oneBack + twoBack];
  return oneBack;
}
```

O(n), O(1). Ответ — F(n + 1); в проверке это выполнилось для всех n до 40. Если шаги бывают из набора `steps`, переход — сумма `dp[i - s]` по всем `s`, и задача становится разменом с учётом порядка.
::

::practice{title="198. House Robber"}
Дома на улице, в каждом сумма денег. Нельзя грабить два соседних дома. Найти наибольшую сумму. Пример: `[1, 2, 3, 1]` → 4; `[2, 7, 9, 3, 1]` → 12. [Задача на LeetCode](https://leetcode.com/problems/house-robber/)

#solution
Для каждого дома два варианта: взять его — тогда предыдущий пропущен, или пропустить — тогда берём лучшее из двух вариантов для предыдущего. Две переменные вместо массива:

```ts
function rob(nums: number[]): number {
  let skip = 0;                                   // лучшее, если предыдущий дом не взят
  let take = 0;                                   // лучшее до предыдущего дома включительно
  for (const x of nums) [skip, take] = [Math.max(skip, take), skip + x];
  return Math.max(skip, take);
}
```

O(n), O(1). Жадное «брать каждый второй» не работает: для `[2, 1, 1, 2]` ответ 4 — первый и последний, между ними два пропуска. В проверке ответ совпал с перебором всех наборов домов без соседей. В варианте с домами по кругу (213) решают дважды — без первого дома и без последнего.
::

::practice{title="139. Word Break"}
Можно ли разбить строку `s` на слова из словаря (слова можно повторять)? Пример: `"leetcode"`, `["leet", "code"]` — да; `"catsandog"`, `["cats", "dog", "sand", "and", "cat"]` — нет. [Задача на LeetCode](https://leetcode.com/problems/word-break/)

#solution
`ok[i]` — префикс длины `i` разбивается. Он разбивается, если для какого-то слова длины `len` префикс `i - len` разбивается, а последние `len` символов — это слово. Перебирать стоит длины слов из словаря, а не все позиции разреза:

```ts
function wordBreak(s: string, wordDict: string[]): boolean {
  const words = new Set(wordDict);
  const lengths = [...new Set(wordDict.map((w) => w.length))];
  const ok = new Array(s.length + 1).fill(false);  // ok[i] — префикс длины i разбивается
  ok[0] = true;
  for (let i = 1; i <= s.length; i++) {
    for (const len of lengths) {
      if (len <= i && ok[i - len] && words.has(s.slice(i - len, i))) {
        ok[i] = true;
        break;
      }
    }
  }
  return ok[s.length];
}
```

O(n · L · ℓ), где L — число разных длин слов, ℓ — длина среза для хеширования. Перебор без запоминания экспоненциален: строка из двухсот `a` и `b` в конце со словами `a`, `aa`, … пробует все разбиения префикса, а с таблицей — отвечает сразу. Если нужны сами разбиения (140), к таблице добавляют перебор с возвратом.
::

::practice{title="322. Coin Change"}
Монеты номиналов `coins` в неограниченном количестве. Найти наименьшее число монет для суммы `amount`, или −1. Пример: `[1, 2, 5], 11` → 3 (`5 + 5 + 1`); `[2], 3` → −1. [Задача на LeetCode](https://leetcode.com/problems/coin-change/)

#solution
`dp[a]` — минимум монет для суммы `a`. Последняя монета — какая-то `c`, и до неё оптимально набрана сумма `a - c`:

```ts
function coinChange(coins: number[], amount: number): number {
  const dp = new Array(amount + 1).fill(Infinity); // dp[a] — минимум монет для суммы a
  dp[0] = 0;
  for (let a = 1; a <= amount; a++) {
    for (const c of coins) if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
  }
  return dp[amount] === Infinity ? -1 : dp[amount];
}
```

O(amount · k) для k номиналов. Жадный выбор «сначала крупные» верен для рублей и евро, но не в общем случае: для `[1, 3, 4]` и 6 жадный даёт три монеты, а DP — две. В проверке ответ совпал с обходом в ширину по суммам — каждая монета это ребро веса 1. Число способов размена (518) — тот же цикл с суммой вместо минимума, но монеты во внешнем цикле, чтобы не считать перестановки.
::

::practice{title="300. Longest Increasing Subsequence"}
Найти длину наибольшей строго возрастающей подпоследовательности (элементы не обязательно подряд). Продолжение: O(n log n). Пример: `[10, 9, 2, 5, 3, 7, 101, 18]` → 4 (`2, 3, 7, 18`). [Задача на LeetCode](https://leetcode.com/problems/longest-increasing-subsequence/)

#solution
Прямое DP: `dp[i]` — длина наибольшей возрастающей подпоследовательности, кончающейся в `i`; её продолжают от любого меньшего элемента слева:

```ts
function lengthOfLISQuadratic(nums: number[]): number {
  const dp = nums.map(() => 1);                   // dp[i] — длина НВП, кончающейся в i
  for (let i = 1; i < nums.length; i++) {
    for (let j = 0; j < i; j++) if (nums[j] < nums[i]) dp[i] = Math.max(dp[i], dp[j] + 1);
  }
  return Math.max(0, ...dp);
}
```

Это O(n²). Быстрее: `tails[k]` — наименьший последний элемент среди возрастающих подпоследовательностей длины `k + 1`. Массив `tails` возрастает, поэтому место для нового элемента ищется двоичным поиском: он либо продлевает самую длинную, либо улучшает хвост какой-то длины.

```ts
function lengthOfLIS(nums: number[]): number {
  const tails: number[] = [];                     // tails[k] — наименьший хвост НВП длины k + 1
  for (const x of nums) {
    let lo = 0;
    let hi = tails.length;
    while (lo < hi) {                             // первая позиция, где tails[mid] >= x
      const mid = (lo + hi) >>> 1;
      if (tails[mid] < x) lo = mid + 1;
      else hi = mid;
    }
    tails[lo] = x;                                // продлить или улучшить хвост
  }
  return tails.length;
}
```

O(n log n). Сам `tails` — не подпоследовательность ответа, только длины; чтобы восстановить её, хранят индексы и ссылки на предыдущий элемент. Для нестрого возрастающей ищут первую позицию с `tails[mid] > x`. В проверке обе версии совпали с перебором всех подпоследовательностей. Тот же алгоритм Vue 3 использует при перестановке дочерних узлов с ключами: узлы из наибольшей возрастающей подпоследовательности остаются на месте, двигаются остальные ([Reconciliation и Fiber](/content/reactjs/reconciliation-and-fiber)).
::

## Красные флаги в ответе

- **Рекурсия без мемоизации** там, где подзадачи повторяются, — экспоненциальное время.
- **Жадный выбор вместо DP** в размене монет и грабителе без доказательства.
- **Не сформулировано состояние.** Код с `dp[i]`, смысл которого кандидат не может назвать.
- **Таблица O(n) там, где хватает двух переменных,** если об этом спросили.
- **Возвращать `tails` как саму подпоследовательность** в НВП.

## Как спрашивают на собеседовании

::question
Что такое динамическое программирование и когда его применять?

#answer
Метод решения задач, где ответ складывается из ответов на меньшие подзадачи (оптимальная подструктура), а подзадачи повторяются (пересекаются). Ответы подзадач запоминают — в таблице снизу вверх или мемоизацией сверху вниз, — и каждая решается один раз. Признаки: просят число способов, минимум или максимум, а решение — последовательность выборов.

#more
Отличие от «разделяй и властвуй» — пересечение подзадач; от жадного алгоритма — что рассматриваются все варианты выбора, а не только локально лучший. Сложность — число состояний, умноженное на стоимость перехода. Для объяснения на собеседовании полезно сначала написать рекурсию, потом добавить мемоизацию, потом перейти к таблице и сжать память.
::

::question
Чем мемоизация сверху вниз отличается от таблицы снизу вверх?

#answer
Мемоизация — рекурсия с кешем: проще написать из перебора, считает только достижимые состояния, но тратит стек и может его переполнить на глубине в десятки тысяч. Таблица — цикл по состояниям в правильном порядке: нет рекурсии, легко сжать память до нескольких последних строк или значений, но нужно продумать порядок вычисления.

#more
Асимптотика одинаковая. Мемоизация выигрывает, когда достижимых состояний мало по сравнению со всеми (например, в разреженных переходах). Таблица выигрывает по константе и памяти. В JavaScript для кеша по нескольким параметрам ключ собирают в строку или вкладывают `Map` — строковые ключи медленнее.
::

::question
Почему жадный алгоритм не решает задачу размена монет?

#answer
Жадный берёт самую крупную подходящую монету, но локально лучший выбор не всегда ведёт к лучшему ответу: для `[1, 3, 4]` и суммы 6 он даёт 4 + 1 + 1 (три монеты), а оптимум 3 + 3 (две). DP перебирает все варианты последней монеты: `dp[a] = 1 + min(dp[a - c])` — и находит оптимум за O(amount · k).

#more
Для «канонических» систем монет, как у большинства валют, жадный оптимален, но это свойство набора, а не алгоритма. Жадный выбор допустим, когда его можно доказать — например, в задаче о выборе непересекающихся интервалов по раннему концу ([Интервалы](/content/algorithms-data-structures/intervals)).
::
