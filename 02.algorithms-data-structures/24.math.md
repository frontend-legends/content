# Математика в задачах

Математические задачи на собеседовании редко требуют теорем — они проверяют, видит ли кандидат короткий путь вместо перебора и помнит ли о краях: переполнении, отрицательных числах, нуле, точности. Палиндром без перевода в строку, нули факториала без вычисления факториала, корень двоичным поиском, степень за O(log n) и точки на одной прямой без деления с плавающей точкой — всё это на нескольких строках.

::tldr
- **Цифры числа — `x % 10` и `Math.floor(x / 10)`.** Так разворачивают, проверяют палиндром и складывают числа без перевода в строку.
- **Не вычислять то, что можно посчитать косвенно:** нули в конце n! — число множителей 5, а не сам факториал.
- **Быстрое возведение в степень — O(log n):** x^n раскладывают по битам n, возводя основание в квадрат.
- **Наклон прямой хранят несократимой дробью через НОД,** а не числом с плавающей точкой — иначе одинаковые наклоны дадут разные ключи.
- **Края важнее формулы:** отрицательные числа, ноль, все девятки, `n = -2^31`, точность после 2^53.
::

---

## Как узнать паттерн

- Вход — **одно число**, а не массив: палиндром, корень, степень, факториал.
- Ограничения огромные — перебор до n не пройдёт, нужна формула или O(log n).
- Геометрия на **целых координатах**: прямые, площади, расстояния.
- Числа **в виде массива цифр или строки** — длиннее, чем помещается в `number`.

Как устроены числа в JavaScript, почему `0.1 + 0.2 !== 0.3` и где кончаются точные целые — в [Представлении данных](/content/computer-science/data-representation). Сложность через логарифмы и комбинаторика — в [Математике для CS](/content/computer-science/math-for-cs).

## Шаблон

Наибольший общий делитель — алгоритм Евклида: `gcd(a, b) = gcd(b, a mod b)`:

```ts
function gcd(a: number, b: number): number {
  while (b !== 0) [a, b] = [b, a % b];
  return Math.abs(a);
}
```

O(log min(a, b)): каждые два шага меньшее число уменьшается хотя бы вдвое. Через НОД сокращают дроби, считают наименьшее общее кратное (`a / gcd(a, b) * b` — сначала деление, чтобы не переполнить) и нормализуют направления, как в задаче 149. В проверке результат совпал с перебором делителей.

::practice{title="9. Palindrome Number"}
Является ли целое число палиндромом? Без перевода в строку. Пример: 121 — да; −121 — нет (`121-`); 10 — нет. [Задача на LeetCode](https://leetcode.com/problems/palindrome-number/)

#solution
Разворачиваем младшую половину цифр и сравниваем со старшей. Остановка, когда развёрнутое догнало оставшееся, — на середине. При нечётной длине средняя цифра оказывается в развёрнутой части, и её отбрасывают делением на 10:

```ts
function isPalindrome(x: number): boolean {
  if (x < 0 || (x % 10 === 0 && x !== 0)) return false;   // минус или ноль в конце — не палиндром
  let reversed = 0;
  while (x > reversed) {                          // развернуть только половину цифр
    reversed = reversed * 10 + (x % 10);
    x = Math.floor(x / 10);
  }
  return x === reversed || x === Math.floor(reversed / 10);   // нечётная длина — средняя цифра лишняя
}
```

O(log x) — по числу цифр. Половина нужна не для скорости, а чтобы в языках с 32-битными целыми разворот не переполнился. Числа, оканчивающиеся на 0, отсекаются заранее: развёрнутое начиналось бы с нуля, и условие остановки сработало бы неверно. В проверке ответ совпал со сравнением строки с её разворотом.
::

::practice{title="66. Plus One"}
Большое неотрицательное число записано массивом цифр, старшая — первая. Прибавить единицу. Пример: `[1, 2, 3]` → `[1, 2, 4]`; `[9, 9, 9]` → `[1, 0, 0, 0]`. [Задача на LeetCode](https://leetcode.com/problems/plus-one/)

#solution
С конца: цифра меньше 9 — увеличить и закончить; 9 — стать нулём и передать перенос дальше. Если перенос прошёл через все цифры, число состояло из девяток, и спереди появляется 1:

```ts
function plusOne(digits: number[]): number[] {
  const result = [...digits];
  for (let i = result.length - 1; i >= 0; i--) {
    if (result[i] < 9) {
      result[i]++;
      return result;
    }
    result[i] = 0;                                // 9 + 1 = 10: ноль и перенос дальше
  }
  return [1, ...result];                          // все девятки: 999 + 1 = 1000
}
```

O(n) в худшем случае, в среднем O(1) — перенос редко идёт далеко. Перевод в число и обратно ломается после 15–16 цифр: `Number` точен только до 2^53. В проверке результат совпал с `BigInt` на числах до 30 цифр.
::

::practice{title="172. Factorial Trailing Zeroes"}
Сколько нулей в конце n!? Нужно O(log n). Пример: 5! = 120 → 1; 25 → 6. [Задача на LeetCode](https://leetcode.com/problems/factorial-trailing-zeroes/)

#solution
Ноль в конце — множитель 10 = 2 · 5. Двоек среди множителей больше, чем пятёрок, поэтому нулей столько, сколько пятёрок. Каждое пятое число даёт пятёрку, каждое двадцать пятое — ещё одну, каждое сто двадцать пятое — ещё:

```ts
function trailingZeroes(n: number): number {
  let count = 0;
  for (let p = 5; p <= n; p *= 5) count += Math.floor(n / p);   // множители 5, 25, 125…
  return count;
}
```

O(log₅ n). Вычислять факториал нельзя: 25! уже не помещается точно в `number`. Частая ошибка — `n / 5` без учёта 25, 125: для 25 получится 5 вместо 6. В проверке для всех n до 300 ответ совпал с подсчётом нулей в факториале, вычисленном через `BigInt`.
::

::practice{title="69. Sqrt(x)"}
Вернуть целую часть квадратного корня из неотрицательного целого `x` без `Math.sqrt` и `**`. Пример: 4 → 2; 8 → 2. [Задача на LeetCode](https://leetcode.com/problems/sqrtx/)

#solution
Ищем наибольшее `m`, у которого `m · m ≤ x`, — двоичный поиск по ответу. Нужна последняя подходящая позиция, поэтому `lo = mid`, и середину округляем вверх, иначе на двух элементах цикл встанет:

```ts
function mySqrt(x: number): number {
  let lo = 0;
  let hi = x;
  while (lo < hi) {
    const mid = Math.ceil((lo + hi) / 2);         // вверх — иначе lo = mid не сдвинется
    if (mid * mid <= x) lo = mid;
    else hi = mid - 1;
  }
  return lo;
}
```

O(log x). В языках с 32-битными целыми `mid * mid` переполняется — сравнивают `mid <= x / mid`; в JavaScript произведение до 2^62 теряет точность только в младших битах и сравнение для x до 2^31 верно. Метод Ньютона `r = (r + x / r) / 2` сходится быстрее. В проверке ответ совпал с `Math.floor(Math.sqrt(x))` на двух тысячах чисел до 2^31 − 1. Шаблоны двоичного поиска — в [Двоичном поиске](/content/algorithms-data-structures/binary-search).
::

::practice{title="50. Pow(x, n)"}
Вычислить x^n для вещественного x и целого n, в том числе отрицательного. Пример: `2, 10` → 1024; `2, -2` → 0.25. [Задача на LeetCode](https://leetcode.com/problems/powx-n/)

#solution
Наивное умножение n раз — O(n), а n до 2^31. Быстрое возведение: x^13 = x^8 · x^4 · x^1, потому что 13 = 1101 в двоичной. Идём по битам n, возводя основание в квадрат, и домножаем результат там, где бит равен 1. Отрицательная степень — обратное число:

```ts
function myPow(x: number, n: number): number {
  if (n < 0) return 1 / myPow(x, -n);
  let result = 1;
  let base = x;
  for (let e = n; e > 0; e = Math.floor(e / 2)) {
    if (e % 2 === 1) result *= base;              // бит степени равен 1 — домножить
    base *= base;                                 // x, x², x⁴, x⁸…
  }
  return result;
}
```

O(log n) умножений: для n = 2^30 цикл проходит 31 раз. Деление и остаток, а не `>>` и `&`, — потому что `-n` для n = −2^31 равно 2^31, а это за пределами 32-битного целого со знаком. В языках с фиксированными целыми `-n` для −2^31 переполняется — там переходят на 64 бита. Тот же приём возводит в степень матрицы, что даёт n-е число Фибоначчи за O(log n). В проверке результат совпал с `**` с точностью до 10^−9.
::

::practice{title="149. Max Points on a Line"}
Даны различные точки на плоскости с целыми координатами. Найти наибольшее число точек на одной прямой. Пример: `[[1, 1], [2, 2], [3, 3]]` → 3. [Задача на LeetCode](https://leetcode.com/problems/max-points-on-a-line/)

#solution
Для каждой точки `i` группируем остальные по направлению на них: точки с одинаковым направлением лежат с `i` на одной прямой. Направление хранится несократимой дробью `dx/dy` с нормализованным знаком — тогда одинаковые наклоны дают одинаковый ключ, а вертикаль и горизонталь не требуют особых случаев:

```ts
function maxPoints(points: number[][]): number {
  let best = Math.min(points.length, 1);
  for (let i = 0; i < points.length; i++) {
    const slopes = new Map<string, number>();
    for (let j = i + 1; j < points.length; j++) {
      let dx = points[j][0] - points[i][0];
      let dy = points[j][1] - points[i][1];
      const g = gcd(dx, dy);
      dx /= g;
      dy /= g;
      if (dx < 0 || (dx === 0 && dy < 0)) [dx, dy] = [-dx, -dy];   // одно направление — один ключ
      const key = `${dx}/${dy}`;
      const count = (slopes.get(key) ?? 1) + 1;   // точка i плюс найденные
      slopes.set(key, count);
      best = Math.max(best, count);
    }
  }
  return best;
}
```

O(n²) по времени, O(n) на таблицу. Наклон `dy / dx` числом с плавающей точкой — классическая ловушка: близкие наклоны могут округлиться одинаково, вертикаль даёт `Infinity` или `-Infinity` в зависимости от порядка точек. Перебирать только `j > i` достаточно: прямую через точки `i` и `j` уже учла точка с меньшим индексом. В проверке ответ совпал с перебором пар через векторное произведение — целочисленную проверку коллинеарности.
::

## Красные флаги в ответе

- **Вычислять факториал или степень целиком,** когда нужна только часть ответа.
- **Наклон через деление с плавающей точкой** в задаче про прямые.
- **Перевод массива цифр в `Number`** — после 2^53 цифры теряются.
- **Возведение в степень циклом за O(n)** при n до 2^31.
- **Забыть отрицательные числа, ноль и `n = -2^31`.**

## Как спрашивают на собеседовании

::question
Как быстро возвести число в степень?

#answer
Двоичным возведением: показатель раскладывают по битам, основание последовательно возводят в квадрат (x, x², x⁴…) и домножают результат на те степени, где бит показателя равен 1. Число умножений — O(log n). Отрицательную степень сводят к положительной через `1 / x^(-n)`.

#more
Тот же приём работает для любой ассоциативной операции: возведение в степень по модулю (основа RSA), степень матрицы — n-е число Фибоначчи за O(log n), композиция перестановок. В модульной арифметике результат берут по модулю после каждого умножения, а в JavaScript для больших модулей нужен `BigInt`: произведение двух чисел до 10⁹ уже больше 2^53.
::

::question
Как проверить, что три точки лежат на одной прямой?

#answer
Через векторное произведение: `(b.x − a.x) · (c.y − a.y) − (b.y − a.y) · (c.x − a.x) === 0`. Это целочисленная проверка без деления, поэтому нет проблем с вертикальными прямыми и точностью. Для группировки многих точек по наклону берут несократимую дробь `dx/dy` с нормализованным знаком.

#more
Знак векторного произведения говорит, по какую сторону от прямой лежит точка, — на этом построены выпуклая оболочка и проверка пересечения отрезков. Модуль — удвоенная площадь треугольника.
::

::question
Как посчитать нули в конце факториала?

#answer
Нули дают множители 10 = 2 · 5, а двоек всегда больше, поэтому считаем пятёрки: `⌊n/5⌋ + ⌊n/25⌋ + ⌊n/125⌋ + …`. Каждое кратное 25 даёт две пятёрки, кратное 125 — три. O(log n), сам факториал не вычисляется.

#more
Это формула Лежандра для степени простого p в n!. Тот же подход отвечает, на какую наибольшую степень числа k делится n!: разложить k на простые и для каждого взять минимум по степеням.
::
