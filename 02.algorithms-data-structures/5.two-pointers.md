# Два указателя

Два указателя — два индекса, которые идут по массиву или строке навстречу друг другу или в одном направлении с разной скоростью. Техника превращает перебор пар за O(n²) в один проход за O(n) и часто обходится без дополнительной памяти. На собеседовании это одна из самых частых тем: палиндромы, пары с заданной суммой, удаление дубликатов на месте, «контейнер с водой» и тройки с нулевой суммой.

::tldr
- **Указатели навстречу** работают на отсортированных данных и симметричных задачах: по сравнению текущей пары понятно, какой конец сдвинуть, и каждая пара проверяется не больше одного раза.
- **Быстрый и медленный указатели** идут в одну сторону: быстрый читает, медленный отмечает, куда писать. Так удаляют элементы и дубликаты на месте за O(1) памяти.
- **Главное в решении — доказать, что сдвиг не теряет ответ.** В «контейнере с водой» двигают меньшую стенку: с ней площадь больше уже не станет.
- **Сортировка за O(n log n) часто окупается:** после неё задачу о парах и тройках решают указателями, а дубли пропускают сравнением соседей.
::

## Как узнать паттерн

Задача, скорее всего, на два указателя, если:

- данные — массив или строка, и **отсортированы** или их можно отсортировать без потери смысла;
- нужно найти **пару** (или тройку) элементов с условием на сумму, разность, площадь;
- нужно проверить **симметрию**: палиндром, зеркальность;
- нужно изменить массив **на месте**, без второго массива: удалить, сдвинуть, развернуть;
- нужно пройти **две последовательности параллельно**: слить отсортированные, проверить подпоследовательность.

Если вместо пары нужен **непрерывный отрезок** с условием, это близкий родственник — скользящее окно ([Скользящее окно](/content/algorithms-data-structures/sliding-window)). Если данные не отсортированы и сортировать нельзя, пару с суммой ищут хеш-таблицей ([Хеш-таблицы](/content/algorithms-data-structures/hashmap)).

## Шаблоны

**Навстречу друг другу.** Левый указатель с начала, правый с конца, на каждом шаге хотя бы один сдвигается — поэтому шагов не больше n:

```ts
function reverseInPlace(a: number[]): number[] {
  let left = 0;
  let right = a.length - 1;
  while (left < right) {
    [a[left], a[right]] = [a[right], a[left]];
    left++;
    right--;
  }
  return a;
}
```

**Быстрый и медленный.** Быстрый указатель читает каждый элемент, медленный — позиция, куда записать следующий подходящий. Всё левее медленного — уже готовый результат:

```ts
function dedupeSorted(a: number[]): number {
  let write = 0;                              // медленный: куда писать
  for (let read = 0; read < a.length; read++) { // быстрый: что читать
    if (read === 0 || a[read] !== a[read - 1]) a[write++] = a[read];
  }
  return write;                               // длина без повторов
}
```

Сложность обоих шаблонов — O(n) по времени и O(1) по памяти. На том же медленном и быстром указателе устроены удаление элементов, дубликатов и слияние массивов из [Массивов и строк](/content/algorithms-data-structures/strings-arrays); в связном списке быстрый и медленный указатели находят середину и цикл ([Связный список](/content/algorithms-data-structures/linked-list)).

### Почему сдвиг не теряет ответ

Корректность двух указателей держится на одном рассуждении: после сдвига мы не пропустили ни одной пары, которая могла бы быть ответом. В Two Sum II на отсортированном массиве, если сумма меньше цели, левый элемент не подойдёт ни с одним правым — правый и так самый большой из оставшихся. Значит, левый можно выбросить. На собеседовании это рассуждение просят проговорить: без него решение выглядит угаданным.

::practice{title="125. Valid Palindrome"}
Строка — палиндром, если после удаления всего, кроме латинских букв и цифр, и приведения к нижнему регистру она читается одинаково в обе стороны. Проверить строку `s`. Пример: `"A man, a plan, a canal: Panama"` — да, `"race a car"` — нет. [Задача на LeetCode](https://leetcode.com/problems/valid-palindrome/)

#solution
Можно очистить строку и сравнить с развёрнутой, но это лишняя память O(n). Указатели с двух концов пропускают неподходящие символы и сравнивают остальные без учёта регистра:

```ts
function isPalindrome(s: string): boolean {
  const isAlnum = (c: string) => /[a-z0-9]/i.test(c);
  let left = 0;
  let right = s.length - 1;
  while (left < right) {
    if (!isAlnum(s[left])) left++;
    else if (!isAlnum(s[right])) right--;
    else if (s[left].toLowerCase() !== s[right].toLowerCase()) return false;
    else {
      left++;
      right--;
    }
  }
  return true;
}
```

O(n) по времени, O(1) по памяти. Ошибки: забыть цифры (`"0P"` — не палиндром: `0` и `p` разные), сравнивать с учётом регистра, считать пустую строку не палиндромом — после очистки `" "` пуста, и это палиндром.
::

::practice{title="392. Is Subsequence"}
Строка `s` — подпоследовательность `t`, если её можно получить из `t`, удалив некоторые символы и не меняя порядок остальных. Проверить это. Пример: `"abc"` в `"ahbgdc"` — да, `"axc"` — нет. [Задача на LeetCode](https://leetcode.com/problems/is-subsequence/)

#solution
По указателю на каждую строку. Идём по `t`; если текущий символ совпал с ожидаемым символом `s`, переходим к следующему символу `s`. Жадно брать первое совпадение безопасно: более позднее совпадение оставило бы меньше символов `t` для хвоста `s`.

```ts
function isSubsequence(s: string, t: string): boolean {
  let i = 0;
  for (let j = 0; j < t.length && i < s.length; j++) {
    if (s[i] === t[j]) i++;
  }
  return i === s.length;
}
```

O(|t|) по времени, O(1) по памяти. Продолжение, которое любят спрашивать: если строк `s` миллиард, а `t` одна, заранее строят для `t` списки позиций каждого символа и для каждого символа `s` двоичным поиском ищут следующую позицию — O(|s| log |t|) на строку.
::

::practice{title="167. Two Sum II - Input Array Is Sorted"}
Массив `numbers` отсортирован по неубыванию. Найти два элемента с суммой `target` и вернуть их номера, считая с единицы. Решение гарантированно есть, один элемент дважды брать нельзя, память — O(1). Пример: `[2, 7, 11, 15]`, `target = 9` → `[1, 2]`. [Задача на LeetCode](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/)

#solution
Указатели на концах. Сумма меньше цели — левый элемент слишком мал даже в паре с самым большим, сдвигаем его вправо. Больше — правый слишком велик даже с самым маленьким, сдвигаем влево.

```ts
function twoSum(numbers: number[], target: number): number[] {
  let left = 0;
  let right = numbers.length - 1;
  while (left < right) {
    const sum = numbers[left] + numbers[right];
    if (sum === target) return [left + 1, right + 1];
    if (sum < target) left++;
    else right--;
  }
  return [];
}
```

O(n) по времени, O(1) по памяти. Ошибки: вернуть индексы с нуля вместо единицы, применить хеш-таблицу — это O(n) памяти, а условие требует O(1), и забыть, что сортированность — главная подсказка.
::

::practice{title="11. Container With Most Water"}
Дан массив высот `height`: вертикальная линия `i` идёт от 0 до `height[i]`. Две линии и ось образуют контейнер; вода в нём — `min(height[i], height[j]) * (j - i)`. Найти наибольший объём. Пример: `[1, 8, 6, 2, 5, 4, 8, 3, 7]` → 49. [Задача на LeetCode](https://leetcode.com/problems/container-with-most-water/)

#solution
Начинаем с самого широкого контейнера. Площадь ограничивает меньшая стенка. Если сдвинуть большую, ширина уменьшится, а высота не вырастет — меньшая всё равно ограничивает. Значит, с меньшей стенкой лучший контейнер уже посчитан, и её можно отбросить.

```ts
function maxArea(height: number[]): number {
  let left = 0;
  let right = height.length - 1;
  let best = 0;
  while (left < right) {
    const h = Math.min(height[left], height[right]);
    best = Math.max(best, h * (right - left));
    if (height[left] < height[right]) left++;
    else right--;
  }
  return best;
}
```

O(n) по времени, O(1) по памяти. В проверке ответ совпал с перебором всех пар на случайных массивах. Если стенки равны, сдвигать можно любую: ни одна из них с другой стенкой не даст больше текущего.
::

::practice{title="15. 3Sum"}
Найти все тройки чисел массива с суммой ноль. Тройки в ответе не должны повторяться, хотя числа в массиве могут. Пример: `[-1, 0, 1, 2, -1, -4]` → `[[-1, -1, 2], [-1, 0, 1]]`. [Задача на LeetCode](https://leetcode.com/problems/3sum/)

#solution
Сортируем, перебираем первый элемент, а пару к нему ищем двумя указателями, как в Two Sum II. Дубли убираем, пропуская одинаковых соседей — и для первого элемента, и для пары после найденного ответа.

```ts
function threeSum(nums: number[]): number[][] {
  const a = [...nums].sort((x, y) => x - y);
  const result: number[][] = [];
  for (let i = 0; i < a.length - 2; i++) {
    if (a[i] > 0) break;                      // дальше только положительные
    if (i > 0 && a[i] === a[i - 1]) continue; // тот же первый элемент
    let left = i + 1;
    let right = a.length - 1;
    while (left < right) {
      const sum = a[i] + a[left] + a[right];
      if (sum < 0) left++;
      else if (sum > 0) right--;
      else {
        result.push([a[i], a[left], a[right]]);
        while (left < right && a[left] === a[left + 1]) left++;
        while (left < right && a[right] === a[right - 1]) right--;
        left++;
        right--;
      }
    }
  }
  return result;
}
```

O(n²) по времени, O(1) дополнительной памяти, не считая ответа и копии для сортировки. Частые ошибки: `sort()` без компаратора сортирует числа как строки — `[-1, -4]` встанут не по порядку; дедупликация через `Set` строк вместо пропуска соседей — работает, но выдаёт непонимание; пропуск дублей только для первого элемента. В проверке результат совпал с перебором всех троек на тысяче случайных массивов, и дублей не было.
::

## Красные флаги в ответе

- **«Отсортирую и пройду двумя указателями» — без объяснения, почему сдвиг корректен.** Ключевое — доказать, что отброшенный элемент не входит в ответ.
- **`nums.sort()` для чисел.** Без компаратора числа сравниваются как строки: `[10, 9, 1].sort()` даёт `[1, 10, 9]`.
- **Хеш-таблица там, где массив отсортирован и требуется O(1) памяти.** Сортированность — подсказка на указатели.
- **Дедупликация троек через `Set` и `JSON.stringify`.** Работает, но медленнее и показывает, что идея с пропуском соседей не понята.
- **Указатели, которые могут не сдвинуться.** Если на какой-то ветке ни один указатель не двигается, цикл бесконечен.

## Как спрашивают на собеседовании

::question
Когда задачу можно решить двумя указателями?

#answer
Когда данные — массив или строка, и есть монотонность: по сравнению текущей пары можно понять, какой конец сдвинуть, не потеряв ответ. Обычно это отсортированный массив и поиск пары с условием, проверка симметрии или изменение массива на месте. Указатели идут навстречу или в одну сторону с разной скоростью.

#more
Признак ошибки — если сдвиг одного указателя может пропустить ответ, нужен другой подход: хеш-таблица для неотсортированных данных, скользящее окно для отрезков, двоичный поиск, если для каждого элемента ищется один партнёр. Сортировка за O(n log n) обычно не ухудшает итоговую сложность, если дальше O(n) или O(n²).
::

::question
Почему в задаче о контейнере с водой двигают меньшую стенку?

#answer
Площадь ограничена меньшей стенкой и шириной. Если сдвинуть большую стенку, ширина уменьшится, а высота останется не больше меньшей стенки — площадь только уменьшится. Значит, все контейнеры с меньшей стенкой и любой стенкой внутри хуже текущего, и меньшую можно отбросить.

#more
Это типичное доказательство для двух указателей: каждый шаг отбрасывает целый ряд пар, которые заведомо не лучше уже найденного. При равных стенках можно двигать любую. Решение перебором — O(n²), указателями — O(n).
::

::question
Как найти все уникальные тройки с нулевой суммой? Какая сложность?

#answer
Отсортировать массив, перебирать первый элемент, а пару к нему с суммой `-a[i]` искать двумя указателями на оставшейся части. Дубли пропускать сравнением с соседом: одинаковый первый элемент — `continue`, после найденной тройки — сдвигать указатели мимо одинаковых значений. Время O(n²), дополнительная память O(1).

#more
Ускорение: если `a[i] > 0`, дальше все числа положительные, и сумма нулём быть не может — цикл можно прервать. Обобщение на k чисел — рекурсия до двух указателей, O(n^(k−1)). Быстрее O(n²) для 3Sum в общем случае неизвестно.
::

::question
Как удалить дубликаты из отсортированного массива на месте?

#answer
Медленный указатель отмечает конец готового результата, быстрый читает все элементы. Если текущий элемент отличается от предыдущего, копируем его на место медленного и сдвигаем медленный. В конце медленный указатель — длина массива без дублей. O(n) по времени, O(1) по памяти.

#more
Тот же шаблон удаляет элементы с условием (`a[read] !== val`), оставляет не больше двух повторов (сравнение с `a[write - 2]`) и сжимает строку. На JavaScript для массивов это ещё и способ не создавать новый массив через `filter`, когда память важна или массив нужно изменить на месте по условию задачи.
::
