# Обход дерева в ширину

Обход в ширину (BFS) идёт по дереву уровнями: сначала корень, потом все его дети, потом внуки. Он нужен, когда ответ зависит от уровня: что видно справа, среднее по уровню, обход зигзагом, ближайший лист. Реализуется очередью, а главный приём — обрабатывать уровень целиком, зная его размер. Те же идеи дальше работают на графах, где BFS находит кратчайший путь ([Графы: BFS](/content/algorithms-data-structures/graph-bfs)).

::tldr
- **BFS — очередь:** взяли узел из начала, положили его детей в конец. Узлы выходят в порядке уровней.
- **Чтобы знать границы уровня, обрабатывают его целиком:** запомнили размер очереди в начале уровня или собрали следующий уровень в отдельный массив.
- **`shift()` у массива — O(n):** очередь на массиве с `shift` делает обход квадратичным. Нужен указатель головы или массив следующего уровня.
- **BFS тратит O(ширины) памяти, DFS — O(высоты):** у широкого дерева выгоднее в глубину, у глубокого — в ширину.
::

---

## Как узнать паттерн

- В условии есть **уровень**: «по уровням», «каждый уровень», «самый правый на уровне», «среднее по уровню».
- Нужен **ближайший** узел: минимальная глубина, ближайший лист — BFS остановится на первом найденном.
- Нужен порядок, в котором узлы **ближе к корню идут раньше**.

Если ответ не зависит от уровня, обход в глубину обычно проще ([Двоичные деревья](/content/algorithms-data-structures/binary-tree-general)). Многие «уровневые» задачи решаются и :term[DFS]{def="обход в глубину: идём до конца ветки, потом возвращаемся"} с параметром глубины — так проверяются решения ниже.

## Шаблон

Уровни дерева — массив текущего уровня и массив следующего:

```ts
function levels(root: TreeNode | null): number[][] {
  const result: number[][] = [];
  let level = root ? [root] : [];
  while (level.length) {
    result.push(level.map((n) => n.val));
    const next: TreeNode[] = [];
    for (const n of level) {
      if (n.left) next.push(n.left);
      if (n.right) next.push(n.right);
    }
    level = next;
  }
  return result;
}
```

O(n) по времени и O(ширины дерева) по памяти. Классический вариант — одна очередь и размер уровня — в задаче 102 ниже.

### Почему не shift

Очередь в JavaScript часто пишут на массиве: `push` в конец и `shift` из начала. Но `shift` сдвигает все элементы — O(n), и обход превращается в O(n²). В проверке опустошение очереди из 80 000 элементов через `shift` шло в 2,5 с лишним раза дольше, чем из 40 000 — рост квадратичный, — и в десятки раз медленнее прохода указателем. Поэтому очередь делают с указателем головы или по уровням, как выше. Почему массив сдвигается и как устроены настоящие очереди — в [Структурах данных](/content/algorithms-data-structures/data-structures).

::practice{title="199. Binary Tree Right Side View"}
Вернуть значения узлов, которые видно, если смотреть на дерево справа: по одному на уровень, сверху вниз. Пример: `[1, 2, 3, null, 5, null, 4]` → `[1, 3, 4]`; `[1, 2, 3, 4]` → `[1, 3, 4]`. [Задача на LeetCode](https://leetcode.com/problems/binary-tree-right-side-view/)

#solution
Справа виден последний узел каждого уровня:

```ts
function rightSideView(root: TreeNode | null): number[] {
  const result: number[] = [];
  let level = root ? [root] : [];
  while (level.length) {
    result.push(level.at(-1)!.val);               // последний на уровне виден справа
    level = level.flatMap((n) => [n.left, n.right].filter((c): c is TreeNode => c !== null));
  }
  return result;
}
```

O(n). Ловушка — смотреть только на правые ветви: во втором примере на третьем уровне есть лишь левый узел 4, и его видно, потому что правее никого. В проверке ответ совпал с последними элементами уровней, найденных обходом в глубину.
::

::practice{title="637. Average of Levels in Binary Tree"}
Вернуть среднее значение узлов на каждом уровне. Пример: `[3, 9, 20, null, null, 15, 7]` → `[3, 14.5, 11]`. [Задача на LeetCode](https://leetcode.com/problems/average-of-levels-in-binary-tree/)

#solution
Сумма уровня, делённая на число узлов в нём:

```ts
function averageOfLevels(root: TreeNode | null): number[] {
  const result: number[] = [];
  let level = root ? [root] : [];
  while (level.length) {
    result.push(level.reduce((sum, n) => sum + n.val, 0) / level.length);
    level = level.flatMap((n) => [n.left, n.right].filter((c): c is TreeNode => c !== null));
  }
  return result;
}
```

O(n). В языках с 32-битными целыми сумма уровня может переполниться, и её считают в 64 битах; в JavaScript сумма — `double`, точная до 2^53.
::

::practice{title="102. Binary Tree Level Order Traversal"}
Вернуть значения по уровням: массив уровней, каждый — слева направо. Пример: `[3, 9, 20, null, null, 15, 7]` → `[[3], [9, 20], [15, 7]]`. [Задача на LeetCode](https://leetcode.com/problems/binary-tree-level-order-traversal/)

#solution
Классический BFS с одной очередью: в начале уровня запоминаем, сколько в очереди узлов, — ровно столько и принадлежит текущему уровню. Вместо `shift` — указатель головы:

```ts
function levelOrder(root: TreeNode | null): number[][] {
  const result: number[][] = [];
  const queue: TreeNode[] = root ? [root] : [];
  let head = 0;                                   // указатель вместо shift — O(1)
  while (head < queue.length) {
    const size = queue.length - head;             // столько узлов на текущем уровне
    const row: number[] = [];
    for (let i = 0; i < size; i++) {
      const node = queue[head++];
      row.push(node.val);
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }
    result.push(row);
  }
  return result;
}
```

O(n) по времени и памяти. Размер уровня фиксируют до цикла: внутри очередь растёт за счёт детей. В проверке дерево из 200 000 узлов обработалось мгновенно и дало 18 уровней.
::

::practice{title="103. Binary Tree Zigzag Level Order Traversal"}
Обход по уровням змейкой: первый уровень слева направо, второй справа налево и так далее. Пример: `[3, 9, 20, null, null, 15, 7]` → `[[3], [20, 9], [15, 7]]`. [Задача на LeetCode](https://leetcode.com/problems/binary-tree-zigzag-level-order-traversal/)

#solution
Обычный обход по уровням и разворот нечётных:

```ts
function zigzagLevelOrder(root: TreeNode | null): number[][] {
  return levelOrder(root).map((row, depth) => (depth % 2 ? row.reverse() : row));
}
```

O(n): каждый уровень разворачивается за его длину. Можно класть значения то в конец, то в начало строки, но `unshift` — снова O(n) на вставку. Порядок обхода детей при этом не меняют: змейка — это только порядок записи.
::

## Красные флаги в ответе

- **`queue.shift()` в цикле обхода.** На больших деревьях это O(n²); нужен указатель головы.
- **Определять уровень без размера очереди.** Без границы уровня узлы разных уровней перемешаются.
- **«Вид справа — это правые ветви».** Если справа никого нет, виден левый узел.
- **Менять порядок обхода детей для зигзага.** Проще и надёжнее развернуть записанный уровень.

## Как спрашивают на собеседовании

::question
Чем обход в ширину отличается от обхода в глубину?

#answer
В ширину — по уровням с помощью очереди: сначала все узлы на расстоянии 1, потом 2. В глубину — до листа и назад, стеком или рекурсией. Оба посещают каждый узел один раз — O(n). Память: BFS держит целый уровень — O(ширины), DFS — путь от корня — O(высоты).

#more
BFS находит ближайшее: минимальную глубину листа или кратчайший путь в невзвешенном графе — первый найденный и есть ближайший. DFS проще для свойств поддеревьев и путей. В DOM `querySelector` идёт в глубину в порядке документа, а при поиске ближайшего элемента с условием BFS остановится раньше.
::

::question
Как в BFS понять, где кончается уровень?

#answer
Запомнить размер очереди в начале уровня и обработать ровно столько узлов — их дети добавятся в конец и составят следующий уровень. Или держать два массива: текущий уровень и собираемый следующий.

#more
Ещё вариант — класть в очередь пары «узел и глубина». Он проще, но тратит больше памяти. Для обхода по уровням без очереди в деревьях со ссылкой `next` можно идти по уже связанному уровню как по списку.
::

::question
Почему очередь на массиве с `shift` — плохая идея?

#answer
`shift` удаляет первый элемент и сдвигает все остальные — O(n) на операцию, и обход на n узлов становится O(n²). В проверке опустошение очереди из 80 000 элементов через `shift` было во много раз медленнее прохода указателем, а время росло квадратично.

#more
Решения: указатель головы на массиве (память освобождается в конце), обход по уровням двумя массивами, кольцевой буфер или очередь на двух стеках. Для маленьких очередей `shift` приемлем — движок оптимизирует небольшие массивы, — но в задачах на большие данные это видимая ошибка.
::
