# Разделяй и властвуй

«Разделяй и властвуй» решает задачу в три шага: разбить её на независимые части того же вида, решить каждую рекурсивно и объединить ответы. Так устроены сортировка слиянием и быстрая сортировка, двоичный поиск, построение сбалансированного дерева и слияние многих списков. На собеседовании важно не только написать рекурсию, но и оценить её: сколько частей, какого размера и сколько стоит объединение.

::tldr
- **Три шага: разделить, решить части рекурсивно, объединить.** Части не пересекаются — этим метод отличается от динамического программирования, где подзадачи повторяются.
- **Сложность задаёт рекуррентное соотношение:** две половины и линейное объединение — T(n) = 2T(n/2) + O(n) = O(n log n); одна половина и O(1) — O(log n), как в двоичном поиске.
- **Делить пополам выгоднее, чем откусывать по одному:** слияние k списков попарно — O(N log k), а по одному в общий результат — O(N · k).
- **Глубина рекурсии при делении пополам — log n,** поэтому стек не переполняется даже на сотнях тысяч элементов.
::

---

## Как узнать паттерн

- Задача **естественно делится** на половины или четверти: массив, отсортированный массив, квадрат поля, список списков.
- Ответ для целого **собирается из ответов частей**: слить две отсортированные половины, сделать середину корнем, склеить четыре одинаковых квадранта.
- Наивное решение — O(n²) или O(n · k), а ожидается O(n log n) или O(N log k).

Сортировки слиянием и быстрая разобраны в [Сортировке](/content/algorithms-data-structures/sorting), двоичный поиск — в [Двоичном поиске](/content/algorithms-data-structures/binary-search). Здесь — тот же приём на деревьях и списках.

## Шаблон

```ts
// схема
function solve(problem) {
  if (problem is small) return solveDirectly(problem);   // базовый случай
  const [left, right] = split(problem);                  // разделить
  return combine(solve(left), solve(right));              // решить и объединить
}
```

### Как оценить сложность

Если задача размера n делится на a частей размера n / b, а разбиение и объединение стоят f(n), время подчиняется соотношению T(n) = a · T(n / b) + f(n). Основная теорема даёт ответ для типичных случаев:

| Соотношение | Пример | Время |
| --- | --- | --- |
| T(n) = T(n/2) + O(1) | двоичный поиск | O(log n) |
| T(n) = 2T(n/2) + O(1) | построение дерева из массива | O(n) |
| T(n) = 2T(n/2) + O(n) | сортировка слиянием | O(n log n) |
| T(n) = T(n − 1) + O(n) | быстрая сортировка на неудачном опорном | O(n²) |

Интуиция для O(n log n): дерево рекурсии имеет log n уровней, и на каждом уровне вся работа по объединению вместе стоит O(n). Последняя строка — почему делить нужно на сравнимые части: деление «1 и n − 1» даёт n уровней.

::practice{title="108. Convert Sorted Array to Binary Search Tree"}
Построить из отсортированного массива сбалансированное двоичное дерево поиска — высоты поддеревьев любого узла отличаются не больше чем на 1. Пример: `[-10, -3, 0, 5, 9]` → `[0, -3, 9, -10, null, 5]` (возможны и другие ответы). [Задача на LeetCode](https://leetcode.com/problems/convert-sorted-array-to-binary-search-tree/)

#solution
Середина массива — корень: слева от неё меньшие значения, справа большие, и их поровну. Каждая половина рекурсивно становится поддеревом:

```ts
function sortedArrayToBST(nums: number[]): TreeNode | null {
  const build = (lo: number, hi: number): TreeNode | null => {
    if (lo > hi) return null;
    const mid = (lo + hi) >> 1;                   // середина — корень, половины — поддеревья
    return new TreeNode(nums[mid], build(lo, mid - 1), build(mid + 1, hi));
  };
  return build(0, nums.length - 1);
}
```

O(n) — каждый элемент становится узлом один раз, T(n) = 2T(n/2) + O(1). Индексы вместо `slice` экономят копирование: со срезами было бы O(n log n). В проверке для всех n до 200 симметричный обход дал исходный массив, дерево было сбалансировано, а высота — минимально возможной, ⌊log₂ n⌋ + 1. Свойства BST — в [Двоичном дереве поиска](/content/algorithms-data-structures/binary-search-tree).
::

::practice{title="148. Sort List"}
Отсортировать связный список. Продолжение: O(n log n) по времени и O(1) дополнительной памяти. Пример: `4 → 2 → 1 → 3` → `1 → 2 → 3 → 4`. [Задача на LeetCode](https://leetcode.com/problems/sort-list/)

#solution
Для списка естественна сортировка слиянием: разрезать посередине медленным и быстрым указателем, отсортировать половины и слить их — слияние двух отсортированных списков разобрано в задаче 21 ([Связные списки](/content/algorithms-data-structures/linked-list)). Быстрый указатель стартует с `head.next`: тогда на двух узлах `slow` остаётся на первом и список делится пополам, а не на «два и ноль».

```ts
function sortList(head: ListNode | null): ListNode | null {
  if (!head || !head.next) return head;
  let slow = head;
  let fast = head.next;                           // с head.next — чтобы на двух узлах разрезать пополам
  while (fast && fast.next) {
    slow = slow.next!;
    fast = fast.next.next!;
  }
  const second = slow.next;
  slow.next = null;                               // разрезать список на две половины
  return mergeTwoLists(sortList(head), sortList(second));
}
```

O(n log n) по времени, O(log n) на стек рекурсии. Строгое O(1) памяти даёт итеративная версия снизу вверх: сливать соседние куски длины 1, 2, 4 и так далее. Быстрая сортировка для списка хуже: нет доступа по индексу для выбора опорного элемента. В проверке список из 100 000 случайных чисел отсортировался правильно — глубина рекурсии около 17.
::

::practice{title="427. Construct Quad Tree"}
Дана квадратная матрица из 0 и 1 размером 2^k. Построить дерево квадрантов: если весь квадрат одного значения — лист с этим значением; иначе внутренний узел с четырьмя детьми — левый верхний, правый верхний, левый нижний и правый нижний квадранты. [Задача на LeetCode](https://leetcode.com/problems/construct-quad-tree/)

#solution
Узел для этой задачи:

```ts
class QuadNode {
  constructor(
    public val: boolean,
    public isLeaf: boolean,
    public topLeft: QuadNode | null = null,
    public topRight: QuadNode | null = null,
    public bottomLeft: QuadNode | null = null,
    public bottomRight: QuadNode | null = null,
  ) {}
}
```

Строим четыре квадранта рекурсивно; если все четыре — листья с одинаковым значением, склеиваем их в один лист:

```ts
function construct(grid: number[][]): QuadNode {
  const build = (r: number, c: number, size: number): QuadNode => {
    if (size === 1) return new QuadNode(grid[r][c] === 1, true);
    const half = size / 2;
    const tl = build(r, c, half);
    const tr = build(r, c + half, half);
    const bl = build(r + half, c, half);
    const br = build(r + half, c + half, half);
    const parts = [tl, tr, bl, br];
    if (parts.every((p) => p.isLeaf && p.val === tl.val)) return new QuadNode(tl.val, true);   // склеить одинаковые
    return new QuadNode(true, false, tl, tr, bl, br);
  };
  return build(0, 0, grid.length);
}
```

Снизу вверх каждая клетка посещается один раз — O(n²) для матрицы n × n, а не O(n² log n), как при проверке «весь ли квадрат одинаков» перебором на каждом уровне. У внутреннего узла `val` может быть любым — по условию его не проверяют. В проверке каждый лист покрывал квадрат одного значения, а одинаковые соседние листья всегда были склеены. Деревья квадрантов применяют для сжатия изображений и поиска объектов на карте.
::

::practice{title="23. Merge k Sorted Lists"}
Слить `k` отсортированных связных списков в один отсортированный. Пример: `[1 → 4 → 5, 1 → 3 → 4, 2 → 6]` → `1 → 1 → 2 → 3 → 4 → 4 → 5 → 6`. [Задача на LeetCode](https://leetcode.com/problems/merge-k-sorted-lists/)

#solution
Если сливать списки по одному в общий результат, каждый элемент перекладывается до k раз — O(N · k) для N элементов всего. Попарное слияние раундами — как сортировка слиянием над списками: после каждого раунда списков вдвое меньше, раундов log k, и в каждом раунде каждый элемент перекладывается раз.

```ts
function mergeKLists(lists: (ListNode | null)[]): ListNode | null {
  if (lists.length === 0) return null;
  let round = lists;
  while (round.length > 1) {
    const next: (ListNode | null)[] = [];
    for (let i = 0; i < round.length; i += 2) next.push(mergeTwoLists(round[i], round[i + 1] ?? null));   // сливать попарно
    round = next;
  }
  return round[0];
}
```

O(N log k) по времени. Другой стандартный ответ — куча из k голов списков: снимаем минимум, кладём его следующий узел — тоже O(N log k) ([Куча](/content/algorithms-data-structures/heap)). Куча удобнее для потоков, где списки приходят постепенно; попарное слияние не требует дополнительной структуры. В проверке результат совпал с сортировкой всех элементов, включая пустые списки и пустой вход.
::

## Красные флаги в ответе

- **Срезы массивов в каждом вызове** там, где хватает индексов, — лишние O(n log n) копирования.
- **Деление на неравные части** — «первый и остальные» превращает O(n log n) в O(n²).
- **Слияние k списков по одному.** O(N · k) вместо O(N log k).
- **Неверный разрез списка на двух узлах:** быстрый указатель с `head` оставляет оба узла в одной половине, и рекурсия не кончается.
- **Не уметь вывести O(n log n)** из рекуррентного соотношения.

## Как спрашивают на собеседовании

::question
Что такое «разделяй и властвуй» и чем он отличается от динамического программирования?

#answer
Задачу делят на независимые подзадачи того же вида, решают их рекурсивно и объединяют ответы. Подзадачи не пересекаются, поэтому каждая решается один раз и мемоизация не нужна. В динамическом программировании подзадачи повторяются — без запоминания рекурсия решает одно и то же экспоненциально много раз.

#more
Примеры «разделяй и властвуй»: сортировка слиянием, быстрая сортировка, двоичный поиск, быстрое возведение в степень, умножение Карацубы. Числа Фибоначчи — пример, где наивная рекурсия выглядит как «разделяй», но подзадачи пересекаются, и правильный подход — DP.
::

::question
Как оценить сложность рекурсивного алгоритма?

#answer
Записать рекуррентное соотношение: сколько вызовов, какого размера и сколько работы вне них. T(n) = 2T(n/2) + O(n) — log n уровней по O(n) работы, итого O(n log n). T(n) = T(n/2) + O(1) — O(log n). T(n) = 2T(n/2) + O(1) — O(n): число узлов дерева рекурсии.

#more
Для общего вида T(n) = a · T(n/b) + f(n) есть основная теорема: сравнивают f(n) с n^(log_b a) — если f меньше, побеждают листья, если равны — добавляется множитель log n, если больше — побеждает корень. Память — глубина рекурсии плюс то, что выделяется на уровне.
::

::question
Как слить k отсортированных списков?

#answer
Попарно раундами: слить 1-й со 2-м, 3-й с 4-м и так далее; после каждого раунда списков вдвое меньше. Всего log k раундов по O(N) — O(N log k). Или кучей из k текущих голов: снять минимум, положить следующий узел того же списка — тоже O(N log k).

#more
Наивное слияние по одному — O(N · k), потому что первые элементы перекладываются k раз. Куча подходит, если списки потоковые и бесконечные. То же слияние k отсортированных частей лежит в основе внешней сортировки — когда данные не влезают в память.
::
