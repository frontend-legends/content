# Стек

Стек — структура «последним пришёл — первым ушёл»: добавить и снять можно только верхний элемент, оба действия за O(1). Он нужен везде, где обработка вложена: парные скобки, пути с `..`, выражения со скобками и приоритетами, отложенные элементы, ждущие ответа. Спрашивают проверку скобок, упрощение пути, стек с минимумом за O(1), вычисление обратной польской записи и калькулятор со скобками.

::tldr
- **Стек — для вложенности и отката:** открывающая скобка ждёт закрывающую, `..` отменяет последний каталог, `(` откладывает текущий результат.
- **В JavaScript стек — обычный массив с `push` и `pop`:** оба O(1), верх — `at(-1)`.
- **Стек с минимумом за O(1) хранит рядом второй стек минимумов** на каждой глубине — после `pop` прежний минимум уже лежит наготове.
- **Монотонный стек находит «следующий больший» для всех элементов за O(n):** элементы ждут в стеке, пока не придёт тот, кто их больше.
- **Выражения считают стеком:** обратная польская запись — стек чисел, скобки в калькуляторе — стек отложенных результатов и знаков.
::

---

## Как узнать паттерн

- Есть **парные** элементы с вложенностью: скобки, теги, начало и конец блока.
- Нужно **отменять** последнее действие: `..` в пути, backspace в строке, история.
- Для каждого элемента ищется **ближайший слева или справа** с условием: следующий больший, предыдущий меньший, сколько дней до тёплой погоды — это монотонный стек.
- Нужно **вычислить выражение** со скобками или в постфиксной записи.
- Рекурсию нужно заменить **итерацией**: явный стек вместо стека вызовов ([Функции](/content/javascript/functions)).

Почему стек, а не что-то ещё: последнее открытое закрывается первым. Это та же причина, по которой регулярным выражением нельзя проверить скобки произвольной вложенности, а стеком — можно ([Теория вычислений](/content/computer-science/theory-of-computation)).

## Шаблон

Стек в JavaScript — массив: `push` кладёт, `pop` снимает, `at(-1)` смотрит на верх, пустой — `length === 0`.

**Монотонный стек** держит индексы элементов, для которых ответ ещё не найден, в монотонном порядке значений. Пришёл больший элемент — он и есть ответ для всех меньших на вершине:

```ts
function nextGreater(a: number[]): number[] {
  const result = new Array(a.length).fill(-1);
  const stack: number[] = [];                     // индексы, ждущие своего большего
  for (let i = 0; i < a.length; i++) {
    while (stack.length && a[stack.at(-1)!] < a[i]) result[stack.pop()!] = a[i];
    stack.push(i);
  }
  return result;
}
```

Каждый индекс один раз кладётся и один раз снимается, поэтому O(n), несмотря на `while`. Так решают «следующий больший элемент», «дни до потепления», «наибольший прямоугольник в гистограмме» и «сколько воды задержат столбики».

::practice{title="20. Valid Parentheses"}
Строка из скобок `()[]{}`. Проверить, что каждая открывающая закрыта скобкой того же типа и в правильном порядке. Примеры: `"()[]{}"` — да, `"(]"` и `"([)]"` — нет, `"{[]}"` — да. [Задача на LeetCode](https://leetcode.com/problems/valid-parentheses/)

#solution
Открывающие кладём в стек; закрывающая должна совпасть по типу с вершиной. В конце стек должен быть пуст — иначе остались незакрытые.

```ts
function isValid(s: string): boolean {
  const pairs: Record<string, string> = { ')': '(', ']': '[', '}': '{' };
  const stack: string[] = [];
  for (const c of s) {
    if (c in pairs) {
      if (stack.pop() !== pairs[c]) return false;
    } else stack.push(c);
  }
  return stack.length === 0;
}
```

O(n) по времени и памяти. `pop()` пустого стека возвращает `undefined`, и сравнение с ожидаемой скобкой сразу даёт `false` — отдельная проверка на пустоту не нужна. Ошибки: забыть проверку пустого стека в конце (`"(("`), считать скобки счётчиками — не поймает `"([)]"`. В проверке ответ совпал с многократным удалением пар `()`, `[]`, `{}`.
::

::practice{title="71. Simplify Path"}
Дан абсолютный путь в стиле Unix. Привести его к каноническому виду: `.` — текущий каталог, `..` — родитель, несколько `/` подряд — один, без завершающего `/`. Имена вроде `...` — обычные. Пример: `"/home/user/Documents/../Pictures"` → `"/home/user/Pictures"`, `"/../"` → `"/"`. [Задача на LeetCode](https://leetcode.com/problems/simplify-path/)

#solution
Разбиваем по `/`, пустые части и `.` пропускаем, `..` снимает последний каталог со стека, остальное кладём:

```ts
function simplifyPath(path: string): string {
  const stack: string[] = [];
  for (const part of path.split('/')) {
    if (part === '' || part === '.') continue;
    if (part === '..') stack.pop();
    else stack.push(part);
  }
  return '/' + stack.join('/');
}
```

O(n) по времени. `pop()` на пустом стеке ничего не делает — так `..` в корне остаётся в корне. В проверке результат совпал с `path.posix.normalize` из Node.js на случайных путях с `.`, `..`, `...` и двойными слешами. Во фронтенде та же логика нормализует пути в роутерах и сборщиках.
::

::practice{title="155. Min Stack"}
Реализовать стек с операциями `push`, `pop`, `top` и `getMin` — последняя возвращает минимум в стеке. Все операции — O(1). [Задача на LeetCode](https://leetcode.com/problems/min-stack/)

#solution
Хранить один минимум недостаточно: после `pop` минимума нужен предыдущий. Поэтому рядом второй стек: на каждой глубине — минимум всех элементов до неё включительно.

```ts
class MinStack {
  private values: number[] = [];
  private mins: number[] = [];                    // минимум на каждой глубине

  push(val: number): void {
    this.values.push(val);
    this.mins.push(this.mins.length ? Math.min(val, this.mins.at(-1)!) : val);
  }
  pop(): void {
    this.values.pop();
    this.mins.pop();
  }
  top(): number {
    return this.values.at(-1)!;
  }
  getMin(): number {
    return this.mins.at(-1)!;
  }
}
```

Все операции O(1), память O(n). В проверке на случайных последовательностях `push` и `pop` минимум всегда совпадал с `Math.min` по модели. Экономнее по памяти — класть в стек минимумов только новые минимумы (с учётом повторов `<=`), но код сложнее. Тот же приём даёт очередь с минимумом из двух стеков.
::

::practice{title="150. Evaluate Reverse Polish Notation"}
Вычислить выражение в обратной польской записи: операторы `+ - * /` стоят после операндов, деление целочисленное с отбрасыванием дробной части к нулю. Пример: `["2", "1", "+", "3", "*"]` → 9; `["4", "13", "5", "/", "+"]` → 6. [Задача на LeetCode](https://leetcode.com/problems/evaluate-reverse-polish-notation/)

#solution
Числа кладём в стек; оператор снимает два верхних, применяется к ним и кладёт результат обратно. Скобки не нужны — порядок уже задан записью.

```ts
function evalRPN(tokens: string[]): number {
  const stack: number[] = [];
  for (const t of tokens) {
    if (!['+', '-', '*', '/'].includes(t)) {
      stack.push(Number(t));
      continue;
    }
    const b = stack.pop()!;
    const a = stack.pop()!;                       // порядок важен для - и /
    if (t === '+') stack.push(a + b);
    else if (t === '-') stack.push(a - b);
    else if (t === '*') stack.push(a * b);
    else stack.push(Math.trunc(a / b));           // деление к нулю
  }
  return stack[0];
}
```

O(n) по времени. Ошибки: перепутать порядок операндов — первым снимается правый; `Math.floor` вместо `Math.trunc` — для `-7 / 2` первый даёт −4, а нужно −3; проверка «число ли это» через `isNaN` — `"-11"` число, а `"-"` — оператор. Постфиксную запись выдаёт парсер выражений, и её же исполняют стековые виртуальные машины ([Языки и компиляторы](/content/computer-science/languages-and-compilers)).
::

::practice{title="224. Basic Calculator"}
Вычислить строку с целыми неотрицательными числами, `+`, `-`, скобками и пробелами. Минус может быть унарным: `"-(2 + 3)"`. Двух операторов подряд нет, `eval` использовать нельзя. Пример: `"(1+(4+5+2)-3)+(6+8)"` → 23. [Задача на LeetCode](https://leetcode.com/problems/basic-calculator/)

#solution
Без умножения приоритетов нет, поэтому выражение — сумма чисел со знаками. Держим текущий результат и знак следующего числа. Открывающая скобка откладывает в стек результат и знак перед ней и начинает считать заново; закрывающая достаёт их и прибавляет посчитанное внутри со своим знаком.

```ts
function calculate(s: string): number {
  let result = 0;
  let sign = 1;
  const stack: number[] = [];                     // результат и знак перед скобкой
  for (let i = 0; i < s.length; i++) {
    const c = s[i];
    if (c >= '0' && c <= '9') {
      let n = 0;
      while (i < s.length && s[i] >= '0' && s[i] <= '9') n = n * 10 + Number(s[i++]);
      i--;
      result += sign * n;
    } else if (c === '+') sign = 1;
    else if (c === '-') sign = -1;
    else if (c === '(') {
      stack.push(result, sign);
      result = 0;
      sign = 1;
    } else if (c === ')') {
      const before = stack.pop()!;
      result = stack.pop()! + before * result;
    }
  }
  return result;
}
```

O(n) по времени, память — по глубине скобок. Унарный минус обрабатывается сам: знак −1 применяется к числу или скобке после него. В проверке результат совпал с вычислением JavaScript на двух тысячах случайных выражений со скобками и унарным минусом. Многоцифровые числа собираются в цикле — частая ошибка читать по одной цифре. Калькулятор с умножением и приоритетами пишут рекурсивным спуском — он разобран в [Языках и компиляторах](/content/computer-science/languages-and-compilers).
::

## Красные флаги в ответе

- **Проверка скобок счётчиком.** Не различает типы и порядок: `"([)]"` пройдёт.
- **Минимум стека в одной переменной.** После `pop` минимума нужен предыдущий; нужен второй стек.
- **`shift` и `unshift` для стека.** Это O(n); стек работает с концом массива.
- **`Math.floor` для деления к нулю.** На отрицательных числах результат другой; нужен `Math.trunc`.
- **«Вложенный `while` в монотонном стеке — O(n²)».** Каждый элемент снимается один раз, итог O(n).

## Как спрашивают на собеседовании

::question
Как проверить правильность скобок и почему нужен стек, а не счётчик?

#answer
Открывающие скобки кладём в стек, закрывающая должна совпасть по типу с вершиной, а в конце стек должен быть пуст. Счётчик знает только количество открытых скобок, но не их типы и порядок, поэтому пропустит `"([)]"`. Время и память O(n).

#more
Для одного типа скобок счётчика достаточно: стек одинаковых элементов и есть счётчик. Та же задача — проверка вложенности тегов, баланс в шаблонах. Из теории вычислений: вложенность произвольной глубины требует стека, конечный автомат и регулярное выражение её не проверят.
::

::question
Как сделать стек с получением минимума за O(1)?

#answer
Хранить рядом второй стек, где на каждой глубине лежит минимум всех элементов до неё включительно. `push` кладёт `min(val, текущий минимум)`, `pop` снимает из обоих, `getMin` смотрит на вершину второго. Все операции O(1), дополнительная память O(n).

#more
Экономный вариант кладёт во второй стек только новые минимумы и снимает его, когда снимается элемент, равный минимуму — с повторами нужно `<=`. Есть вариант без второго стека: хранить разности с текущим минимумом, но он сложнее и опасен переполнением в языках с фиксированными целыми.
::

::question
Что такое монотонный стек и где он применяется?

#answer
Стек, где элементы лежат в монотонном порядке значений. Новый элемент снимает с вершины всех, кто нарушает порядок, — и для каждого снятого он и есть ответ: ближайший больший или меньший. Каждый элемент кладётся и снимается один раз — O(n).

#more
Применения: следующий больший элемент, дни до потепления, наибольший прямоугольник в гистограмме, вода между столбиками, акции «сколько дней цена не превышала сегодняшнюю». Решение перебором для каждого элемента — O(n²). Монотонная очередь — то же для максимума в скользящем окне.
::
