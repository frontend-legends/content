# Многомерное динамическое программирование

Когда состояние не помещается в одно число, таблица становится двумерной: позиция на сетке, пара индексов в двух строках, отрезок строки, день и число сделок. Принцип тот же, что в одномерном DP, — состояние, переход, база, порядок, — но ошибиться в индексах и порядке обхода проще. Спрашивают пути по сетке и треугольнику, расстояние редактирования, чередование строк, самую длинную подстроку-палиндром, наибольший квадрат и акции с ограниченным числом сделок.

::tldr
- **Состояние из двух индексов — таблица `(m + 1) × (n + 1)`:** лишняя строка и столбец для пустых префиксов убирают особые случаи на краях.
- **Для двух строк переход смотрит на последние символы:** совпали — диагональ `dp[i-1][j-1]`, иначе — лучший из соседей `dp[i-1][j]` и `dp[i][j-1]`.
- **Если переход смотрит только на предыдущую строку, хранят одну строку** — O(n) памяти вместо O(m · n). Нужно следить, чтобы значение не перезаписалось раньше, чем прочитано.
- **Направление обхода выбирают так, чтобы нужные состояния были готовы:** треугольник выгоднее считать снизу вверх, отрезки — по возрастанию длины.
- **Для «не больше k действий» в состояние добавляют счётчик:** акции с k сделками — состояния «сделок сделано и держим ли акцию».
::

## Как узнать паттерн

- **Сетка** и движение только вправо и вниз: число путей, минимальная сумма.
- **Две строки или массива**: общая подпоследовательность, расстояние редактирования, чередование.
- **Подстроки или отрезки** одной строки: палиндромы, разбиение на отрезки.
- **Ограничение по ресурсу**: k сделок, вместимость рюкзака, число операций.

Основы — состояние, переход, мемоизация и таблица — в [Одномерном DP](/content/algorithms-data-structures/1d-dp). Обход двумерных массивов и индексы — в [Матрицах](/content/algorithms-data-structures/matrix).

## Шаблон

Наибольшая общая подпоследовательность двух строк — эталон DP по двум индексам. `dp[i][j]` — ответ для префиксов `a[0..i)` и `b[0..j)`:

```ts
function longestCommonSubsequence(a: string, b: string): number {
  const dp = Array.from({ length: a.length + 1 }, () => new Array(b.length + 1).fill(0));
  for (let i = 1; i <= a.length; i++) {
    for (let j = 1; j <= b.length; j++) {
      dp[i][j] = a[i - 1] === b[j - 1]
        ? dp[i - 1][j - 1] + 1                    // последние символы совпали — берём оба
        : Math.max(dp[i - 1][j], dp[i][j - 1]);   // иначе выбрасываем один из них
    }
  }
  return dp[a.length][b.length];
}
```

O(m · n) по времени и памяти. Нулевая строка и нулевой столбец — пустые префиксы, ответ для них 0. `Array.from` с функцией создаёт отдельный массив на каждую строку; `new Array(m).fill(new Array(n))` положил бы во все строки один и тот же массив. На этой таблице построен `diff`: по ней восстанавливают, какие строки общие, а какие добавлены и удалены. В проверке ответ совпал с перебором подпоследовательностей.

::practice{title="120. Triangle"}
Треугольник чисел. Найти минимальную сумму пути сверху вниз, где из клетки `c` строки `r` можно перейти в `c` или `c + 1` следующей строки. Продолжение: O(n) памяти. Пример: `[[2], [3, 4], [6, 5, 7], [4, 1, 8, 3]]` → 11 (2 + 3 + 5 + 1). [Задача на LeetCode](https://leetcode.com/problems/triangle/)

#solution
Сверху вниз у крайних клеток один родитель, у остальных два — нужны проверки краёв, а в конце минимум по нижней строке. Снизу вверх проще: лучший путь от клетки до низа — её значение плюс меньший из двух путей под ней, и ответ оказывается в вершине:

```ts
function minimumTotal(triangle: number[][]): number {
  const best = [...triangle.at(-1)!];             // снизу вверх: лучший путь от клетки до низа
  for (let r = triangle.length - 2; r >= 0; r--) {
    for (let c = 0; c <= r; c++) best[c] = triangle[r][c] + Math.min(best[c], best[c + 1]);
  }
  return best[0];
}
```

O(n²) для n строк, O(n) памяти. Перезаписывать `best[c]` можно: `best[c + 1]` ещё не тронут, а старый `best[c]` больше не понадобится. Жадный спуск к меньшему соседу не работает — путь может пойти через большое число к очень маленьким. В проверке ответ совпал с рекурсивным перебором всех путей.
::

::practice{title="64. Minimum Path Sum"}
Сетка неотрицательных чисел. Найти путь из левого верхнего угла в правый нижний с минимальной суммой; ходить можно только вправо и вниз. Пример: `[[1, 3, 1], [1, 5, 1], [4, 2, 1]]` → 7. [Задача на LeetCode](https://leetcode.com/problems/minimum-path-sum/)

#solution
В клетку приходят сверху или слева. Храним одну строку: перед обновлением `dp[c]` содержит значение для клетки сверху, а `dp[c - 1]` уже обновлён — это клетка слева:

```ts
function minPathSum(grid: number[][]): number {
  const n = grid[0].length;
  const dp = new Array(n).fill(Infinity);         // одна строка: dp[c] — лучший путь до клетки
  dp[0] = 0;
  for (const row of grid) {
    dp[0] += row[0];
    for (let c = 1; c < n; c++) dp[c] = row[c] + Math.min(dp[c], dp[c - 1]);   // сверху или слева
  }
  return dp[n - 1];
}
```

O(m · n), O(n). `Infinity` в начальной строке означает «сверху пути нет», поэтому первая строка сама собой считается только слева. Если ходить можно в четыре стороны, это уже не DP — путь может вернуться, — а кратчайший путь в графе с весами (алгоритм :term[Дейкстры]{def="алгоритм кратчайших путей в графе с неотрицательными весами рёбер"}). В проверке ответ совпал с рекурсивным перебором путей.
::

::practice{title="63. Unique Paths II"}
Сетка с препятствиями (1 — препятствие). Сколько путей из левого верхнего угла в правый нижний, если ходить только вправо и вниз? Пример: `[[0, 0, 0], [0, 1, 0], [0, 0, 0]]` → 2. [Задача на LeetCode](https://leetcode.com/problems/unique-paths-ii/)

#solution
Путей в клетку — сумма путей сверху и слева, в препятствие — 0. Одна строка, как в предыдущей задаче:

```ts
function uniquePathsWithObstacles(grid: number[][]): number {
  const n = grid[0].length;
  const dp = new Array(n).fill(0);
  dp[0] = 1;
  for (const row of grid) {
    for (let c = 0; c < n; c++) {
      if (row[c] === 1) dp[c] = 0;                // в препятствие путей нет
      else if (c > 0) dp[c] += dp[c - 1];         // сверху (уже в dp[c]) плюс слева
    }
  }
  return dp[n - 1];
}
```

O(m · n), O(n). Препятствие в стартовой клетке обнуляет `dp[0]` и, значит, все пути — отдельная проверка не нужна. Без препятствий ответ — :term[биномиальный коэффициент]{def="число способов выбрать k элементов из n без учёта порядка"} C(m + n − 2, m − 1): из m + n − 2 шагов выбрать, какие m − 1 будут вниз. В проверке ответ совпал с рекурсивным подсчётом путей.
::

::practice{title="5. Longest Palindromic Substring"}
Найти самую длинную подстроку-палиндром. Пример: `"babad"` → `"bab"` или `"aba"`; `"cbbd"` → `"bb"`. [Задача на LeetCode](https://leetcode.com/problems/longest-palindromic-substring/)

#solution
Классическое DP — таблица `isPal[i][j]` по отрезкам: отрезок палиндром, если крайние символы равны и внутренний отрезок палиндром. Это O(n²) времени и памяти. Без таблицы: у каждого палиндрома есть центр — символ или промежуток между символами, — и из каждого из 2n − 1 центров расширяемся, пока края совпадают:

```ts
function longestPalindrome(s: string): string {
  let start = 0;
  let length = 0;
  const expand = (lo: number, hi: number): void => {
    while (lo >= 0 && hi < s.length && s[lo] === s[hi]) {
      lo--;
      hi++;
    }
    if (hi - lo - 1 > length) {
      start = lo + 1;
      length = hi - lo - 1;
    }
  };
  for (let i = 0; i < s.length; i++) {
    expand(i, i);                                 // нечётная длина: центр — символ
    expand(i, i + 1);                             // чётная: центр между символами
  }
  return s.slice(start, start + length);
}
```

O(n²) по времени, O(1) по памяти. После цикла `lo` и `hi` стоят на первых несовпадающих символах, поэтому длина — `hi - lo - 1`. Забыть чётный центр — потерять `"bb"`. Алгоритм Манакера решает задачу за O(n), но на собеседовании его ждут редко. В проверке длина ответа совпала с перебором всех подстрок.
::

::practice{title="97. Interleaving String"}
Можно ли получить `s3`, чередуя символы `s1` и `s2` с сохранением порядка внутри каждой? Пример: `"aabcc"`, `"dbbca"` → `"aadbbcbcac"` — да; `"aadbbbaccc"` — нет. [Задача на LeetCode](https://leetcode.com/problems/interleaving-string/)

#solution
`dp[i][j]` — префиксы `s1[0..i)` и `s2[0..j)` собирают `s3[0..i+j)`. Последний символ `s3` взят либо из `s1`, либо из `s2`. Переход смотрит на ячейку сверху и слева — хватает одной строки:

```ts
function isInterleave(s1: string, s2: string, s3: string): boolean {
  const m = s1.length;
  const n = s2.length;
  if (m + n !== s3.length) return false;
  const dp = new Array(n + 1).fill(false);        // dp[j] — из s1[0..i) и s2[0..j) собирается s3[0..i+j)
  for (let i = 0; i <= m; i++) {
    for (let j = 0; j <= n; j++) {
      if (i === 0 && j === 0) dp[j] = true;
      else {
        const fromS1 = i > 0 && dp[j] && s1[i - 1] === s3[i + j - 1];
        const fromS2 = j > 0 && dp[j - 1] && s2[j - 1] === s3[i + j - 1];
        dp[j] = fromS1 || fromS2;
      }
    }
  }
  return dp[n];
}
```

O(m · n), O(n). Два указателя с жадным выбором ломаются, когда очередной символ `s3` подходит к обеим строкам — нужно помнить оба варианта, что DP и делает. Проверка длины в начале — обязательна. В проверке ответ совпал с рекурсивным перебором.
::

::practice{title="72. Edit Distance"}
Найти минимальное число операций, превращающих `word1` в `word2`; операции — вставить, удалить или заменить символ. Пример: `"horse"` → `"ros"` — 3; `"intention"` → `"execution"` — 5. [Задача на LeetCode](https://leetcode.com/problems/edit-distance/)

#solution
`dp[i][j]` — расстояние между префиксами длины `i` и `j`. Пустой префикс превращается в префикс длины `j` за `j` вставок — это база. Если последние символы равны, они ничего не стоят. Иначе последняя операция — одна из трёх:

```ts
function minDistance(word1: string, word2: string): number {
  const m = word1.length;
  const n = word2.length;
  const dp = Array.from({ length: m + 1 }, (_, i) => Array.from({ length: n + 1 }, (_, j) => (i === 0 ? j : j === 0 ? i : 0)));
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (word1[i - 1] === word2[j - 1]) dp[i][j] = dp[i - 1][j - 1];
      else dp[i][j] = 1 + Math.min(
        dp[i - 1][j - 1],                         // заменить
        dp[i - 1][j],                             // удалить из word1
        dp[i][j - 1],                             // вставить в word1
      );
    }
  }
  return dp[m][n];
}
```

O(m · n). Это расстояние Левенштейна; его используют в подсказках «возможно, вы имели в виду», нечётком поиске и проверке опечаток. Память сжимается до двух строк, но для восстановления самих операций нужна вся таблица. В проверке ответ совпал с обходом в ширину по строкам, где каждая операция — ребро.
::

::practice{title="123. Best Time to Buy and Sell Stock III"}
Цены акции по дням. Не больше двух сделок (покупка и продажа), одновременно держать можно одну акцию. Найти наибольшую прибыль. Пример: `[3, 3, 5, 0, 0, 3, 1, 4]` → 6. [Задача на LeetCode](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-iii/)

#solution
Это частный случай следующей задачи с k = 2:

```ts
function maxProfit(prices: number[]): number {
  return maxProfitK(2, prices);
}
```

Решение с одной сделкой и с неограниченным числом сделок — в [Строках и массивах](/content/algorithms-data-structures/strings-arrays). Здесь же главное — увидеть состояние «сколько сделок уже сделано и держим ли акцию».
::

::practice{title="188. Best Time to Buy and Sell Stock IV"}
То же, но не больше `k` сделок. Пример: `k = 2, [3, 2, 6, 5, 0, 3]` → 7 (купить за 2, продать за 6, купить за 0, продать за 3). [Задача на LeetCode](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-iv/)

#solution
Состояния для каждой сделки `t`: `buy[t]` — лучший баланс, если t-я акция куплена и ещё держится; `sell[t]` — лучший баланс после t завершённых сделок. Каждый день каждое состояние либо остаётся, либо переходит: купить можно после `t - 1` сделок, продать — купленную в `t`-й:

```ts
function maxProfitK(k: number, prices: number[]): number {
  const buy = new Array(k + 1).fill(-Infinity);   // buy[t] — лучший баланс с открытой t-й сделкой
  const sell = new Array(k + 1).fill(0);          // sell[t] — лучший баланс после t закрытых сделок
  for (const p of prices) {
    for (let t = 1; t <= k; t++) {
      buy[t] = Math.max(buy[t], sell[t - 1] - p); // купить сегодня после t - 1 сделок
      sell[t] = Math.max(sell[t], buy[t] + p);    // продать сегодня
    }
  }
  return sell[k];
}
```

O(n · k), O(k). Обновлять `buy` и `sell` в одном дне подряд безопасно: купить и продать в один день — нулевая сделка, она не увеличит прибыль. Если `k ≥ n / 2`, ограничение не мешает, и ответ — сумма всех подъёмов цены. В проверке ответ совпал с перебором состояний «день, сделок осталось, держим ли».
::

::practice{title="221. Maximal Square"}
Матрица из `'0'` и `'1'`. Найти площадь наибольшего квадрата из единиц. Пример: в матрице `10100 / 10111 / 11111 / 10010` — 4. [Задача на LeetCode](https://leetcode.com/problems/maximal-square/)

#solution
`dp[r][c]` — сторона наибольшего квадрата с правым нижним углом в клетке. Квадрат стороны s возможен, если в клетке 1, а сверху, слева и по диагонали есть квадраты стороны не меньше s − 1. Отсюда `1 + min` трёх соседей. Одна строка и переменная для диагонали:

```ts
function maximalSquare(matrix: string[][]): number {
  const n = matrix[0].length;
  const dp = new Array(n + 1).fill(0);            // dp[c + 1] — сторона квадрата с правым нижним углом в клетке
  let side = 0;
  for (const row of matrix) {
    let diagonal = 0;                             // dp[c] из предыдущей строки
    for (let c = 0; c < n; c++) {
      const above = dp[c + 1];
      dp[c + 1] = row[c] === '1' ? 1 + Math.min(above, dp[c], diagonal) : 0;
      diagonal = above;
      side = Math.max(side, dp[c + 1]);
    }
  }
  return side * side;
}
```

O(m · n), O(n). Диагональ — значение `dp[c]` из предыдущей строки, а оно уже перезаписано, поэтому его сохраняют до перезаписи. Значения в матрице — строки `'1'`, а не числа: сравнение с `1` дало бы всегда ложь. В проверке ответ совпал с перебором всех квадратов.

## Красные флаги в ответе

- **`new Array(m).fill(new Array(n))`** — все строки таблицы указывают на один массив.
- **Нет строки и столбца для пустых префиксов** — десяток проверок краёв и ошибки на единицу.
- **Сжатие памяти с перезаписью значения до его чтения** — диагональ в квадрате, порядок в рюкзаке.
- **Жадные решения** в треугольнике и чередовании строк.
- **Забыть чётный центр** в задаче про палиндром.

## Как спрашивают на собеседовании

::question
Как посчитать расстояние редактирования между строками?

#answer
Таблицей `dp[i][j]` — расстояние между префиксами длины i и j. База: `dp[i][0] = i`, `dp[0][j] = j`. Если последние символы равны — `dp[i-1][j-1]`, иначе 1 плюс минимум из замены `dp[i-1][j-1]`, удаления `dp[i-1][j]` и вставки `dp[i][j-1]`. O(m · n) по времени, память можно сжать до двух строк.

#more
Это расстояние Левенштейна. Операции восстанавливают обратным проходом по таблице — так работает `diff`. Если нужно только проверить, что расстояние не больше k, достаточно полосы шириной 2k + 1 вокруг диагонали — O(n · k). Вариант с перестановкой соседних символов — расстояние Дамерау — Левенштейна.
::

::question
Как сократить память в двумерном DP?

#answer
Если переход смотрит только на предыдущую строку, хранят одну или две строки вместо всей таблицы — O(n) вместо O(m · n). При обновлении на месте следят за порядком: значение сверху лежит в `dp[c]` до перезаписи, слева — уже обновлённое `dp[c - 1]`, а диагональ сохраняют во временной переменной.

#more
Цена сжатия — нельзя восстановить само решение, только его значение. Если нужно и то и другое при малой памяти, есть алгоритм Хиршберга: делит задачу пополам и восстанавливает путь за O(n) памяти. В рюкзаке 0/1 одну строку обходят справа налево, чтобы предмет не взяли дважды.
::

::question
Как решать задачи об акциях с ограничением на число сделок?

#answer
Описать состояние: день, число совершённых сделок и держим ли акцию. Для каждой сделки t хранят лучший баланс с купленной акцией `buy[t]` и после продажи `sell[t]`; каждый день `buy[t] = max(buy[t], sell[t-1] - p)` и `sell[t] = max(sell[t], buy[t] + p)`. O(n · k) по времени и O(k) по памяти.

#more
Вся серия задач об акциях — один автомат состояний с разными ограничениями: одна сделка, без ограничений, k сделок, пауза после продажи, комиссия за сделку. Пауза добавляет состояние «отдыхаем», комиссия вычитается при продаже. При k ≥ n / 2 ограничение не действует, и ответ — сумма всех подъёмов.
::
