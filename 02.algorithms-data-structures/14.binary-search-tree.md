# Двоичное дерево поиска

Двоичное дерево поиска (BST) — двоичное дерево с порядком: всё в левом поддереве меньше узла, всё в правом — больше. Поэтому поиск, вставка и удаление идут по одной ветви — O(высоты), а симметричный обход выдаёт значения по возрастанию. На собеседовании BST проверяют через это свойство: проверить, что дерево — BST, найти k-й по величине элемент, минимальную разницу между значениями.

::tldr
- **Свойство BST — для всего поддерева, а не только для детей:** каждый узел справа от корня больше корня, даже правнук левого ребёнка правого поддерева.
- **Симметричный обход BST отсортирован.** Минимальная разница, k-й элемент и проверка корректности сводятся к сравнению соседей в этом обходе.
- **Поиск и вставка — O(высоты):** O(log n) у сбалансированного дерева и O(n) у вырожденного, построенного из отсортированных данных.
- **Проверку BST делают с границами `(low, high)`, которые передаются вниз,** — сравнение только с родителем пропускает ошибку в глубине.
::

---

## Как узнать паттерн

- В условии сказано «двоичное дерево **поиска**» — значит, есть порядок, и его надо использовать: отбрасывать половину дерева, обходить по возрастанию.
- Нужен **k-й по порядку**, ближайший к значению, **диапазон** значений, соседний элемент.
- Нужно **проверить** порядок или **восстановить** его.

Если про порядок ничего не сказано, это обычное дерево, и приёмы BST неприменимы ([Двоичные деревья](/content/algorithms-data-structures/binary-tree-general)). Почему BST вырождается и как его балансируют :term[AVL]{def="самобалансирующееся дерево поиска: высоты поддеревьев любого узла различаются не больше чем на 1"} и красно-чёрные деревья — в [Структурах данных](/content/algorithms-data-structures/data-structures).

## Шаблоны

**Поиск** — один спуск: меньше — влево, больше — вправо:

```ts
function searchBST(root: TreeNode | null, val: number): TreeNode | null {
  let node = root;
  while (node && node.val !== val) node = val < node.val ? node.left : node.right;
  return node;
}
```

**Вставка** — тот же спуск до пустого места:

```ts
function insertIntoBST(root: TreeNode | null, val: number): TreeNode {
  if (!root) return new TreeNode(val);
  if (val < root.val) root.left = insertIntoBST(root.left, val);
  else root.right = insertIntoBST(root.right, val);
  return root;
}
```

Обе операции — O(h). Если вставлять числа по возрастанию, каждое уйдёт вправо, и дерево станет списком с h = n. В проверке симметричный обход дерева, собранного из случайных чисел, всегда совпадал с отсортированным массивом.

::practice{title="530. Minimum Absolute Difference in BST"}
Найти минимальную разницу между значениями любых двух узлов BST. Пример: `[4, 2, 6, 1, 3]` → 1. [Задача на LeetCode](https://leetcode.com/problems/minimum-absolute-difference-in-bst/)

#solution
В отсортированном порядке минимальная разница — между соседями. Симметричный обход даёт этот порядок, поэтому достаточно помнить предыдущее значение:

```ts
function getMinimumDifference(root: TreeNode | null): number {
  let best = Infinity;
  let prev: number | null = null;
  const inorder = (node: TreeNode | null): void => {
    if (!node) return;
    inorder(node.left);
    if (prev !== null) best = Math.min(best, node.val - prev);   // соседи в отсортированном порядке
    prev = node.val;
    inorder(node.right);
  };
  inorder(root);
  return best;
}
```

O(n) по времени, O(h) по памяти. Ошибка — сравнивать узел только с детьми: в примере `[1, 0, 48, null, null, 12, 49]` разница 1 — между 48 и 49, а между 12 и 1 — 11, хотя 12 и 1 не соседи по ребру. В проверке ответ совпал с минимумом разностей соседей в отсортированном массиве.
::

::practice{title="230. Kth Smallest Element in a BST"}
Найти k-е по величине (с единицы) значение в BST. Продолжение: что если дерево часто меняется, а запросы частые? [Задача на LeetCode](https://leetcode.com/problems/kth-smallest-element-in-a-bst/)

#solution
Симметричный обход с явным стеком, остановленный на k-м узле, — не нужно обходить всё дерево:

```ts
function kthSmallest(root: TreeNode | null, k: number): number {
  const stack: TreeNode[] = [];
  let node = root;
  for (;;) {
    while (node) {
      stack.push(node);
      node = node.left;
    }
    node = stack.pop()!;
    if (--k === 0) return node.val;               // k-й в симметричном обходе
    node = node.right;
  }
}
```

O(h + k) по времени. Ответ на продолжение: хранить в каждом узле размер его поддерева. Тогда k-й ищется спуском за O(h): если в левом поддереве не меньше k узлов — идём влево, иначе вычитаем их и корень и идём вправо. Вставки и удаления обновляют размеры на пути.
::

::practice{title="98. Validate Binary Search Tree"}
Проверить, что дерево — корректное BST: в левом поддереве каждого узла все значения строго меньше, в правом — строго больше. Пример: `[2, 1, 3]` — да; `[5, 1, 4, null, null, 3, 6]` — нет. [Задача на LeetCode](https://leetcode.com/problems/validate-binary-search-tree/)

#solution
Каждый узел должен лежать в интервале, который задают все его предки: уходя влево, сужаем верхнюю границу значением узла, вправо — нижнюю.

```ts
function isValidBST(root: TreeNode | null, low = -Infinity, high = Infinity): boolean {
  if (!root) return true;
  if (root.val <= low || root.val >= high) return false;      // границы от всех предков
  return isValidBST(root.left, low, root.val) && isValidBST(root.right, root.val, high);
}
```

O(n). Классическая ошибка — сравнивать узел только с детьми: дерево `[5, 4, 6, null, null, 3, 7]` пройдёт такую проверку, хотя 3 лежит справа от 5. `-Infinity` и `Infinity` в качестве начальных границ безопасны и для крайних значений вроде `-2147483648`. Альтернатива — симметричный обход и проверка строгого возрастания. В проверке ответ совпал с этой альтернативой на тысяче случайных деревьев.
::

## Красные флаги в ответе

- **Проверка BST только по родителю и детям.** Нарушение может быть в глубине поддерева.
- **«Поиск в BST — всегда O(log n)».** Только в сбалансированном; в вырожденном — O(n).
- **k-й элемент через полный обход в массив и сортировку.** Симметричный обход BST уже отсортирован, и его можно остановить на k-м.
- **Нестрогое сравнение в проверке**, когда дубликаты запрещены условием.

## Как спрашивают на собеседовании

::question
Как проверить, что дерево — двоичное дерево поиска?

#answer
Передавать вниз допустимый интервал `(low, high)`: в левое поддерево — `(low, node.val)`, в правое — `(node.val, high)`, и проверять, что каждый узел строго внутри. Или выполнить симметричный обход и проверить, что значения строго возрастают. Оба способа — O(n).

#more
Сравнение только с детьми — самая частая ошибка: дерево `[5, 4, 6, null, null, 3, 7]` его пройдёт. Если дубликаты разрешены, договариваются, в какую сторону они идут, и одна из границ становится нестрогой.
::

::question
Как найти k-й наименьший элемент в BST? А если дерево часто меняется?

#answer
Симметричный обход с явным стеком до k-го снятого узла — O(h + k). Если запросов и изменений много, в каждом узле хранят размер поддерева и спускаются: если слева не меньше k узлов — влево, иначе вычитают их и корень и идут вправо. Это O(h) на запрос и O(h) на обновление.

#more
Дерево с размерами поддеревьев называют порядково-статистическим. В сбалансированном дереве все операции становятся O(log n). Без своего дерева похожую задачу для потока чисел решают двумя кучами — для медианы ([Куча](/content/algorithms-data-structures/heap)).
::

::question
Почему BST может работать за O(n) и как этого избежать?

#answer
Высота BST зависит от порядка вставок. Если вставлять отсортированные данные, каждое значение уходит в одну сторону, и дерево вырождается в список — поиск становится O(n). Самобалансирующиеся деревья (AVL, красно-чёрные) поворотами держат высоту O(log n) после каждой вставки и удаления.

#more
Красно-чёрные деревья лежат в основе упорядоченных словарей во многих стандартных библиотеках — `TreeMap` в Java, `std::map` в C++. В JavaScript встроенного упорядоченного словаря нет: `Map` хранит порядок вставки, а не порядок ключей, поэтому для упорядоченных данных берут отсортированный массив с двоичным поиском или библиотеку.
::
