# Скользящее окно

Скользящее окно — отрезок массива или строки между двумя указателями, который двигается вперёд: правый край добавляет элемент, левый убирает. Вместо пересчёта каждого отрезка заново окно обновляет своё состояние за O(1), и перебор всех отрезков за O(n²) или O(n³) превращается в один проход. Спрашивают задачи про подстроки и подмассивы: самый длинный без повторов, самый короткий с суммой не меньше заданной, минимальное окно, покрывающее все символы.

::tldr
- **Окно — непрерывный отрезок, состояние которого пересчитывается при сдвиге краёв:** сумма, счётчики символов, число нужных элементов. Каждый элемент входит и выходит из окна один раз, поэтому проход — O(n).
- **Окно бывает фиксированной длины и переменной.** Фиксированное сдвигается целиком; переменное расширяется правым краем и сжимается левым, пока условие нарушено.
- **Переменное окно работает, когда условие монотонно:** если отрезок плох, любой больший отрезок с тем же левым краем тоже плох (или хорош для «минимального» варианта). На отрицательных числах сумма немонотонна, и окно ломается.
- **Состояние окна — обычно хеш-таблица счётчиков** или число «ещё не хватает», чтобы проверять условие за O(1), а не пересчитывать окно.
::

## Как узнать паттерн

- Нужен **непрерывный** подмассив или подстрока — не подпоследовательность, не пара элементов.
- Ищется **самый длинный или самый короткий** отрезок с условием, или **все отрезки** заданной длины.
- Условие можно **поддерживать при добавлении и удалении** одного элемента: сумма, количество различных символов, покрытие набора.
- Наивное решение перебирает все отрезки — O(n²) — и для каждого считает условие заново.

Если элементы могут быть отрицательными, а условие — на сумму, окно не работает: сжатие может и увеличить, и уменьшить сумму. Тогда нужны :term[префиксные суммы]{def="массив накопленных сумм: сумма отрезка — разность двух его элементов"} с хеш-таблицей ([Хеш-таблицы](/content/algorithms-data-structures/hashmap)) или алгоритм Кадане для максимальной суммы ([Алгоритм Кадане](/content/algorithms-data-structures/kadanes-algorithm)).

## Шаблоны

**Окно фиксированной длины k:** первое окно считаем целиком, дальше при сдвиге добавляем вошедший элемент и вычитаем вышедший.

```ts
function maxSumOfK(a: number[], k: number): number {
  let sum = 0;
  for (let i = 0; i < k; i++) sum += a[i];
  let best = sum;
  for (let right = k; right < a.length; right++) {
    sum += a[right] - a[right - k];           // вошёл правый, вышел левый
    best = Math.max(best, sum);
  }
  return best;
}
```

**Окно переменной длины:** правый край всегда идёт вперёд, левый догоняет, пока окно нарушает условие. После сжатия окно снова корректно, и можно обновить ответ. Пример — самая длинная подстрока, где не больше k разных символов:

```ts
function longestWithAtMostKDistinct(s: string, k: number): number {
  const count = new Map<string, number>();
  let left = 0;
  let best = 0;
  for (let right = 0; right < s.length; right++) {
    count.set(s[right], (count.get(s[right]) ?? 0) + 1);   // расширяем
    while (count.size > k) {                                // окно сломалось — сжимаем
      const c = s[left++];
      const n = count.get(c)! - 1;
      if (n === 0) count.delete(c);
      else count.set(c, n);
    }
    best = Math.max(best, right - left + 1);                // окно снова корректно
  }
  return best;
}
```

Хотя внутри цикла есть `while`, сложность O(n): левый край за всё время сдвигается не больше n раз. Память — O(размера алфавита) на счётчики.

### Самое длинное и самое короткое

Две разновидности переменного окна отличаются местом обновления ответа:

- **самое длинное корректное окно** — сжимаем, пока окно некорректно, и обновляем ответ **после** сжатия;
- **самое короткое окно, которое выполняет условие** — сжимаем, **пока** условие выполнено, и обновляем ответ **внутри** сжатия, перед удалением левого элемента.

Перепутать эти места — главная ошибка в задачах на окно.

::practice{title="209. Minimum Size Subarray Sum"}
Дан массив положительных чисел `nums` и число `target`. Найти длину самого короткого непрерывного подмассива с суммой не меньше `target`, или 0, если такого нет. Пример: `target = 7`, `[2, 3, 1, 2, 4, 3]` → 2 (подмассив `[4, 3]`). [Задача на LeetCode](https://leetcode.com/problems/minimum-size-subarray-sum/)

#solution
Числа положительные, поэтому сумма окна растёт при расширении и падает при сжатии — условие монотонно. Расширяем правым краем, а пока сумма не меньше цели — записываем длину и сжимаем левым:

```ts
function minSubArrayLen(target: number, nums: number[]): number {
  let left = 0;
  let sum = 0;
  let best = Infinity;
  for (let right = 0; right < nums.length; right++) {
    sum += nums[right];
    while (sum >= target) {
      best = Math.min(best, right - left + 1);
      sum -= nums[left++];
    }
  }
  return best === Infinity ? 0 : best;
}
```

O(n) по времени, O(1) по памяти. Ошибки: вернуть `Infinity` вместо 0, обновлять ответ после цикла сжатия (окно уже некорректно). Есть решение за O(n log n) через префиксные суммы и двоичный поиск — его спрашивают как продолжение.
::

::practice{title="3. Longest Substring Without Repeating Characters"}
Найти длину самой длинной подстроки без повторяющихся символов. Примеры: `"abcabcbb"` → 3, `"bbbbb"` → 1, `"pwwkew"` → 3. [Задача на LeetCode](https://leetcode.com/problems/longest-substring-without-repeating-characters/)

#solution
Окно без повторов. Вместо пошагового сжатия запоминаем последнюю позицию каждого символа: если символ уже встречался **внутри окна**, левый край прыгает сразу за его прошлое вхождение.

```ts
function lengthOfLongestSubstring(s: string): number {
  const last = new Map<string, number>();
  let left = 0;
  let best = 0;
  for (let right = 0; right < s.length; right++) {
    const seen = last.get(s[right]);
    if (seen !== undefined && seen >= left) left = seen + 1;
    last.set(s[right], right);
    best = Math.max(best, right - left + 1);
  }
  return best;
}
```

O(n) по времени, O(алфавит) по памяти. Главная ловушка — условие `seen >= left`: на строке `"abba"` у второй `a` прошлое вхождение (0) уже левее окна, и без проверки левый край откатится назад, а ответ станет 3 вместо 2. В проверке решение совпало с перебором на случайных строках, включая этот случай.
::

::practice{title="30. Substring with Concatenation of All Words"}
Дана строка `s` и массив `words` из слов одинаковой длины. Найти все начальные индексы подстрок `s`, которые являются склейкой всех слов в любом порядке, каждое слово ровно столько раз, сколько оно встречается в `words`. Пример: `"barfoothefoobarman"`, `["foo", "bar"]` → `[0, 9]`. [Задача на LeetCode](https://leetcode.com/problems/substring-with-concatenation-of-all-words/)

#solution
Слова одной длины `len`, поэтому подходящая подстрока режется на слова по границам, кратным `len` от её начала. Запускаем окно отдельно для каждого сдвига от 0 до `len - 1` и двигаем его по целым словам. Окно — счётчик слов; чужое слово обнуляет окно, лишний экземпляр слова сдвигает левый край.

```ts
function findSubstring(s: string, words: string[]): number[] {
  const len = words[0].length;
  const need = new Map<string, number>();
  for (const w of words) need.set(w, (need.get(w) ?? 0) + 1);
  const result: number[] = [];
  for (let offset = 0; offset < len; offset++) {
    const have = new Map<string, number>();
    let left = offset;
    let used = 0;
    for (let right = offset; right + len <= s.length; right += len) {
      const word = s.slice(right, right + len);
      if (!need.has(word)) {                  // чужое слово — окно начинается заново
        have.clear();
        used = 0;
        left = right + len;
        continue;
      }
      have.set(word, (have.get(word) ?? 0) + 1);
      used++;
      while (have.get(word)! > need.get(word)!) {   // слово лишнее — сдвигаем левый край
        const first = s.slice(left, left + len);
        have.set(first, have.get(first)! - 1);
        used--;
        left += len;
      }
      if (used === words.length) result.push(left);
    }
  }
  return result.sort((x, y) => x - y);
}
```

Время O(n · len): для каждого сдвига окно проходит строку по словам, а `slice` стоит O(len). Ошибки: забыть повторяющиеся слова в `words` (нужны счётчики, а не множество) и перебирать каждую позицию как начало — это O(n · m · len). В проверке ответ совпал с перебором всех позиций на случайных строках с повторами слов.
::

::practice{title="76. Minimum Window Substring"}
Даны строки `s` и `t`. Найти самую короткую подстроку `s`, которая содержит все символы `t` с учётом повторов, или пустую строку. Пример: `s = "ADOBECODEBANC"`, `t = "ABC"` → `"BANC"`. [Задача на LeetCode](https://leetcode.com/problems/minimum-window-substring/)

#solution
Короткое окно. Счётчик `need` хранит, сколько каждого символа `t` ещё нужно, а `missing` — сколько символов не покрыто всего: так проверка «окно покрывает `t`» стоит O(1). Расширяем, пока `missing > 0`; когда стало ноль — записываем ответ и сжимаем.

```ts
function minWindow(s: string, t: string): string {
  const need = new Map<string, number>();
  for (const c of t) need.set(c, (need.get(c) ?? 0) + 1);
  let missing = t.length;                     // сколько символов t ещё не покрыто
  let left = 0;
  let bestStart = 0;
  let bestLen = Infinity;
  for (let right = 0; right < s.length; right++) {
    const c = s[right];
    if (need.has(c)) {
      if (need.get(c)! > 0) missing--;
      need.set(c, need.get(c)! - 1);
    }
    while (missing === 0) {
      if (right - left + 1 < bestLen) {
        bestLen = right - left + 1;
        bestStart = left;
      }
      const d = s[left++];
      if (need.has(d)) {
        need.set(d, need.get(d)! + 1);
        if (need.get(d)! > 0) missing++;
      }
    }
  }
  return bestLen === Infinity ? '' : s.slice(bestStart, bestStart + bestLen);
}
```

O(|s| + |t|) по времени. Счётчик может уходить в минус — это лишние экземпляры символа в окне, и при сжатии они не увеличивают `missing`. Ошибки: сравнивать карты счётчиков целиком на каждом шаге (O(алфавит) на шаг), хранить в ответе `slice` на каждом улучшении вместо начала и длины.
::

## Красные флаги в ответе

- **Окно на массиве с отрицательными числами для условия на сумму.** Сжатие не всегда уменьшает сумму; нужны префиксные суммы.
- **Пересчёт всего окна на каждом шаге.** Это возвращает O(n²); состояние обновляется только по вошедшему и вышедшему элементу.
- **«Внутри `while`, значит, O(n²)».** Левый край сдвигается не больше n раз за всё время — итог O(n).
- **Ответ обновляется не в том месте.** Для самого длинного — после сжатия, для самого короткого — внутри сжатия.
- **Подпоследовательность вместо подстроки.** Окно работает только для непрерывных отрезков.

## Как спрашивают на собеседовании

::question
Когда работает скользящее окно и почему решение — O(n)?

#answer
Когда ищется непрерывный отрезок, и условие монотонно по длине окна: расширение может только «сломать» окно, а сжатие — только «починить» (или наоборот). Тогда правый край идёт вперёд, левый догоняет, и каждый элемент один раз входит и один раз выходит из окна — O(n), несмотря на вложенный `while`.

#more
Состояние окна хранят так, чтобы обновлять и проверять за O(1): сумма, счётчики в `Map`, число недостающих символов. Если условие немонотонно — например, сумма с отрицательными числами, — окно не годится, и используют префиксные суммы с хеш-таблицей.
::

::question
Чем окно для «самого длинного» отличается от окна для «самого короткого»?

#answer
Для самого длинного корректного отрезка окно сжимают, пока оно некорректно, и обновляют ответ после сжатия — окно уже корректное и максимальное для этого правого края. Для самого короткого отрезка, выполняющего условие, сжимают, пока условие выполнено, и обновляют ответ внутри сжатия, до удаления левого элемента.

#more
Примеры: подстрока без повторов и подстрока с не более чем k различными символами — «длинные»; минимальная сумма не меньше цели и минимальное окно, покрывающее `t`, — «короткие». Путаница мест обновления — самая частая ошибка: ответ получается на единицу длиннее или пропускается.
::

::question
Как найти самую длинную подстроку без повторов за O(n)?

#answer
Окно и `Map` с последней позицией каждого символа. Если текущий символ уже встречался внутри окна, левый край прыгает за его прошлое вхождение. Ответ — максимум длины окна. Время O(n), память — по размеру алфавита.

#more
Важна проверка, что прошлое вхождение внутри окна (`seen >= left`): иначе на `"abba"` левый край откатится назад. Вместо `Map` для ASCII можно взять массив на 128 элементов. Вариант с пошаговым сжатием через `Set` тоже O(n), но делает больше операций.
::
