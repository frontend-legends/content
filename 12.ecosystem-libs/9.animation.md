# Анимации

Чем анимировать интерфейс: CSS, Web Animations API, View Transitions и библиотеки — Motion, GSAP, Vue Transition, AutoAnimate, — как они устроены внутри и что стоят. Спрашивают, когда хватает CSS, а когда нужна библиотека, чем Motion отличается от GSAP и как уважать настройки пользователя. Глубже — почему одни анимации плавные даже при загруженном потоке, а другие дёргаются, и как анимировать переход между страницами.

::tldr
- **CSS-переходы и анимации закрывают большинство задач:** наведение, появление, раскрытие. Основы — свойства, ключевые кадры, тайминги — разобраны в главе CSS.
- **Плавность определяет не библиотека, а свойство:** `transform` и `opacity` браузер анимирует на композиторе без пересчёта раскладки, а `width`, `top`, `height` — на каждом кадре через раскладку в основном потоке.
- **Web Animations API — анимации из JavaScript тем же движком, что CSS:** `el.animate()` возвращает объект с промисом `finished`. На нём построен Motion, а GSAP — собственный движок, который меняет inline-стили каждый кадр.
- **View Transitions API анимирует смену состояния или страницы целиком:** браузер снимает снимки до и после и плавно переводит одно в другое.
- **`prefers-reduced-motion: reduce` — просьба пользователя убрать движение.** Её уважают и в CSS, и в библиотеках: большие перемещения и параллакс отключают, оставляя мягкие изменения прозрачности.
::

## Сначала — CSS

Сквозной пример — уведомление «Добавлено в корзину», значок количества на корзине и переход со страницы каталога на страницу товара.

Для появления уведомления и реакции кнопки на наведение библиотека не нужна:

```css
.toast { transition: opacity 0.2s ease-out, transform 0.2s ease-out; }
.toast[hidden] { opacity: 0; transform: translateY(20px); }
```

Переходы, ключевые кадры, функции плавности и что можно анимировать — в [Анимациях CSS](/content/css/animations). Новые возможности CSS расширили этот набор: `@starting-style` анимирует появление элемента из `display: none`, `transition-behavior: allow-discrete` — анимацию дискретных свойств, а анимации, привязанные к прокрутке, работают без JavaScript.

### Что делает анимацию плавной

Браузер выводит кадр в несколько этапов: стили, раскладка, отрисовка, композиция (подробно — в [Рендеринге](/content/web/rendering)). От анимируемого свойства зависит, какие этапы повторяются на каждом кадре:

- **`transform` и `opacity`** — только композиция, и её часто делает отдельный поток композитора. Анимация остаётся плавной, даже если основной поток занят JavaScript;
- **`width`, `height`, `top`, `left`, `margin`** — раскладка и отрисовка на каждом кадре в основном потоке. На загруженной странице такие анимации дёргаются.

Поэтому движение делают через `transform: translate()`, а изменение размера — через `transform: scale()` или техникой FLIP: измерить начальное и конечное положение, а анимировать разницу трансформом.

## Web Animations API

Анимация из JavaScript без библиотеки:

```js
const animation = el.animate(
  [{ opacity: 0, transform: 'translateY(20px)' }, { opacity: 1, transform: 'none' }],
  { duration: 200, easing: 'ease-out' },
);
await animation.finished;
```

WAAPI использует тот же движок, что CSS-анимации, поэтому `transform` и `opacity` так же уходят на композитор. В проверке в Chromium во время анимации `el.getAnimations()` вернул одну анимацию, а после `await animation.finished` её состояние стало `finished`. Анимацию можно поставить на паузу, развернуть, изменить скорость и дождаться — то, что в CSS приходилось ловить событиями `transitionend`.

## Библиотеки

### Motion

Motion (бывший Framer Motion) — библиотека для React, Vue и обычного JavaScript. Под капотом — гибридный движок: `transform` и `opacity` он анимирует через WAAPI, а то, что WAAPI не умеет, — пружины с физикой, анимацию произвольных значений — своим кодом.

```js
import { animate } from 'motion';

await animate(badge, { transform: ['scale(0.5)', 'scale(1)'], opacity: [0, 1] }, { duration: 0.2 });
```

В проверке у элемента появились WAAPI-анимации, а промис завершился с итоговой непрозрачностью `1`. В React Motion даёт компоненты `motion.div` с `initial`, `animate`, `exit`, анимацию раскладки `layout` (FLIP автоматически) и `AnimatePresence` для анимации ухода из дерева — именно это сложно сделать вручную, потому что компонент исчезает раньше, чем закончится анимация. Для Vue есть Motion for Vue с тем же API.

### GSAP

GSAP — библиотека с таймлайнами, точной последовательностью, анимацией по прокрутке через ScrollTrigger, морфингом SVG и текстовыми эффектами. Стандарт для сложных маркетинговых и иллюстративных анимаций. С 2025 года все её плагины бесплатны.

Устроена иначе, чем Motion: **собственный движок** на `requestAnimationFrame`, который на каждом кадре записывает значения в inline-стили. В проверке во время анимации у элемента не было ни одной WAAPI-анимации, а `style.transform` менялся несколько раз, пока не дошёл до `translate(100px)`. Это даёт полный контроль и одинаковое поведение везде, но анимация зависит от основного потока: если он занят, кадры пропускаются.

### Размер

В проверке:

| Импорт | gzip |
| --- | --- |
| `animate` из `motion` | ≈25 КБ |
| `animate` из `motion/mini` — только WAAPI | ≈3 КБ |
| ядро GSAP | ≈27 КБ |
| WAAPI и CSS | 0 |

Для простых анимаций мини-версия Motion или голый WAAPI дают то же поведение без десятков килобайт.

### Остальное

- **Vue `<Transition>` и `<TransitionGroup>`** — встроенные компоненты для появления, ухода и перестановки элементов списка через классы (подробно — во [Встроенных компонентах Vue](/content/vuejs/built-in-components));
- **AutoAnimate** — одна строка, чтобы список плавно анимировал добавление, удаление и перестановку;
- **react-spring** — анимации на пружинной физике для React;
- **Lottie** — проигрывание анимаций, экспортированных из After Effects, для иллюстраций и онбординга;
- **Rive** — интерактивная векторная анимация со своим редактором и рантаймом.

## View Transitions

Переход между страницами или большими состояниями — каталог → товар — раньше требовал держать обе страницы в DOM одновременно. **View Transitions API** делает это браузером:

```js
document.startViewTransition(() => {
  renderProductPage();   // изменить DOM как обычно
});
```

Браузер снимает снимок до изменения, выполняет функцию, снимает снимок после и плавно переводит один в другой. В проверке промис `finished` разрешился, а изменение DOM внутри функции применилось. Элементы с одинаковым `view-transition-name` на обеих страницах — например, картинка товара — анимируются как один объект, «перелетая» на новое место. Для многостраничных сайтов то же включается CSS-правилом `@view-transition { navigation: auto; }` без JavaScript. Во фреймворках для этого есть готовые средства: компонент `ViewTransition` в React, `onNavigate` в SvelteKit, `ClientRouter` в Astro и экспериментальная опция `experimental.viewTransition` в Nuxt; с обычным Vue Router переход оборачивают в `startViewTransition` вручную (подробно — в [Будущем веба](/content/web/future-of-web)).

## Уважение к пользователю

У части людей движение на экране вызывает головокружение и тошноту, и они включают в системе настройку «уменьшить движение». Браузер сообщает её медиазапросом:

```css
@media (prefers-reduced-motion: reduce) {
  .card { transition: none; }
}
```

В проверке при эмулированной настройке `matchMedia('(prefers-reduced-motion: reduce)')` вернул `true`, а длительность перехода стала `0s`. Правила:

- большие перемещения, параллакс, зум и автоматически запускающиеся анимации **отключают**;
- мягкие изменения прозрачности и цвета обычно **оставляют** — они не вызывают дискомфорта и помогают понять, что произошло;
- в JavaScript проверяют `matchMedia` или используют поддержку библиотеки: в Motion — `useReducedMotion` и `MotionConfig reducedMotion="user"`.

Анимация должна объяснять — откуда появилось окно, куда ушёл товар, — а не украшать. Длительность интерфейсных анимаций — обычно 150–300 мс.

## Как выбрать

| Задача | Выбор |
| --- | --- |
| наведение, появление, раскрытие | CSS-переходы, `@starting-style` |
| анимация из JavaScript с ожиданием конца | WAAPI или `motion/mini` |
| появление и уход компонентов, анимация раскладки в React | Motion |
| списки и переходы во Vue | `<Transition>`, `<TransitionGroup>`, Motion for Vue |
| сложные таймлайны, анимация по прокрутке, SVG | GSAP с ScrollTrigger или CSS-анимации, привязанные к прокрутке |
| переход между страницами | View Transitions |
| иллюстрации и онбординг от дизайнера | Lottie или Rive |

---

## Красные флаги в ответе

- **«Для анимаций нужна библиотека».** CSS, WAAPI и View Transitions закрывают большинство задач без килобайт.
- **«Плавность зависит от библиотеки».** Она зависит от свойства: `transform` и `opacity` на композиторе, `width` и `top` — через раскладку на каждом кадре.
- **«Motion и GSAP устроены одинаково».** Motion опирается на WAAPI для `transform` и `opacity`, GSAP — свой движок на inline-стилях.
- **«`prefers-reduced-motion` — значит, убрать все анимации».** Убирают движение, а мягкие изменения прозрачности оставляют.
- **«Анимация ухода компонента делается через `useEffect`».** Компонент исчезает раньше, нужен механизм вроде `AnimatePresence` или `<Transition>`.

## Как спрашивают на собеседовании

::question
Когда достаточно CSS, а когда нужна библиотека?

#answer
CSS хватает для переходов состояний — наведение, появление, раскрытие — и для ключевых кадров. Библиотека нужна для анимации ухода компонентов из дерева, анимации раскладки, пружинной физики, сложных таймлайнов и синхронизации с прокруткой.

#more
Между ними — WAAPI: анимации из JavaScript с промисом `finished`, паузой и разворотом без библиотеки. Новые возможности CSS — `@starting-style`, анимации по прокрутке — сокращают список задач для библиотек ещё больше.
::

::question
Почему одни анимации плавные, а другие дёргаются?

#answer
От анимируемого свойства зависит, какие этапы рендеринга повторяются на каждом кадре. `transform` и `opacity` требуют только композиции, и её часто делает отдельный поток. `width`, `height`, `top` вызывают раскладку и отрисовку в основном потоке, и при загруженном JavaScript кадры пропускаются.

#more
Поэтому движение делают через `translate`, изменение размера — через `scale` или FLIP. `will-change: transform` заранее выносит элемент в отдельный слой, но злоупотребление им тратит память. Проверяют в панели Performance: есть ли раскладка в кадрах анимации.
::

::question
Чем Motion отличается от GSAP?

#answer
Motion анимирует `transform` и `opacity` через Web Animations API, а остальное и пружины — своим движком; в React даёт декларативные компоненты, анимацию ухода и раскладки. GSAP — собственный движок на `requestAnimationFrame` с таймлайнами, ScrollTrigger и плагинами для SVG и текста.

#more
Motion лучше для анимаций интерфейса в React и Vue, GSAP — для сложных иллюстративных и маркетинговых сцен. Оба около 25 КБ gzip, у Motion есть мини-версия на WAAPI около 3 КБ. Все плагины GSAP бесплатны.
::

::question
Что такое View Transitions API?

#answer
API браузера для анимации смены состояния или страницы: `document.startViewTransition(() => обновитьDOM())` снимает снимки до и после и плавно переводит один в другой. Элементы с одинаковым `view-transition-name` анимируются как один объект.

#more
Для многостраничных сайтов включается CSS-правилом `@view-transition { navigation: auto; }`. В SPA переход оборачивают в `startViewTransition` в роутере: у React, SvelteKit, Astro и Nuxt для этого есть готовые средства. Без поддержки в браузере изменение просто применяется без анимации, поэтому API безопасно использовать как улучшение.
::

::question
Как учитывать prefers-reduced-motion?

#answer
Медиазапросом `@media (prefers-reduced-motion: reduce)` в CSS и `matchMedia` в JavaScript. При этой настройке отключают большие перемещения, параллакс, зум и автозапуск анимаций, а мягкие изменения прозрачности оставляют.

#more
Библиотеки поддерживают настройку сами: в Motion — `useReducedMotion` и `MotionConfig reducedMotion="user"`. Видео и карусели с автозапуском при этой настройке не запускают. Это требование доступности, а не пожелание.
::

## Практика

::practice{title="Панель дёргается при открытии"}
Боковая корзина выезжает рывками, особенно на телефонах и когда на странице идёт загрузка товаров:

```css
.drawer { position: fixed; right: -400px; width: 400px; transition: right 0.3s; }
.drawer.open { right: 0; }
```

#solution
Анимируется `right` — свойство раскладки. На каждом кадре браузер пересчитывает раскладку и перерисовывает в основном потоке, а он занят загрузкой товаров. Движение переносят на `transform`:

```css
.drawer { position: fixed; right: 0; width: 400px; transform: translateX(100%); transition: transform 0.3s ease-out; }
.drawer.open { transform: translateX(0); }

@media (prefers-reduced-motion: reduce) {
  .drawer { transition: none; }
}
```

`transform` анимируется композицией, часто в отдельном потоке, и остаётся плавным при занятом основном потоке. В проверке анимация `transform` через WAAPI завершилась промисом `finished`, а эмуляция `prefers-reduced-motion` обнулила длительность перехода.
::

::practice{title="Уведомление исчезает без анимации"}
В React-приложении уведомление красиво появляется, но при закрытии пропадает мгновенно:

```jsx
{visible && <div className="toast toast-enter">Добавлено в корзину</div>}
```

#solution
Анимация появления срабатывает при монтировании, а при `visible = false` React сразу удаляет элемент — анимировать уже нечего. Нужен механизм, который задержит удаление до конца анимации:

```jsx
import { AnimatePresence, motion } from 'motion/react';

<AnimatePresence>
  {visible && (
    <motion.div
      key="toast"
      initial={{ opacity: 0, y: 20 }}
      animate={{ opacity: 1, y: 0 }}
      exit={{ opacity: 0, y: 20 }}
    >
      Добавлено в корзину
    </motion.div>
  )}
</AnimatePresence>
```

`AnimatePresence` оставляет элемент в DOM, пока не закончится `exit`. Без библиотеки то же делают вручную: держат элемент, запускают `el.animate(...)` и удаляют после `await animation.finished`. Во Vue эту задачу решает встроенный `<Transition>`.
::
