# Интернационализация (i18n)

Как сделать интерфейс на нескольких языках: переводы по ключам, формат сообщений ICU с множественным числом и родом, библиотеки i18next, FormatJS, Lingui и vue-i18n, ленивая загрузка переводов, выбор языка, серверный рендер и письмо справа налево. Спрашивают, что входит в i18n кроме перевода строк, почему окончания нельзя выбирать через `n === 1` и что такое ICU MessageFormat. Глубже — почему vue-i18n по умолчанию пишет «2 товаров», откуда hydration mismatch с датами и почему фразу нельзя склеивать из кусочков.

::tldr
- **i18n — не только перевод строк:** множественное число, род, числа, даты и валюты по правилам языка, направление текста, выбор и переключение языка. Сокращение — 18 букв между i и n.
- **Форматирование умеет встроенный `Intl`,** библиотеки нужны для управления переводами: ключи, файлы по языкам, подстановки, загрузка.
- **ICU MessageFormat** описывает множественное число, выбор по роду и форматирование чисел в одной строке, а формы выбирает по правилам CLDR. Перевод целой фразы, а не склейка кусочков, — переводчик сам ставит порядок слов.
- **Формы библиотек разные:** у i18next — суффиксы ключа `_one`, `_few`, `_many`, у FormatJS — ICU, у vue-i18n — свой формат через `|`, и для русского ему нужно своё правило.
- **Переводы грузят лениво по разделам,** а язык определяют на сервере — иначе серверный и клиентский рендер разойдутся.
::

---

## Что входит в i18n

Сквозной пример — интернет-магазин на русском, английском и арабском. Кнопка «Добавить в корзину», строка «В корзине 21 товар», уведомление «Аня добавила 2 товара», цена «1 234,50 ₽» и дата доставки.

Что для этого нужно:

- **переводы** строк по ключам и языкам;
- **множественное число** — «1 товар», «3 товара», «5 товаров»;
- **выбор** по роду или другому признаку — «добавил», «добавила»;
- **форматирование** чисел, валют, дат и относительного времени;
- **направление текста** — арабский и иврит пишутся справа налево;
- **выбор языка** и его переключение.

---

## Intl и библиотеки

Форматирование уже есть в языке: `Intl.NumberFormat` для чисел и валют, `Intl.DateTimeFormat` и `Intl.RelativeTimeFormat` для дат, `Intl.PluralRules` для категорий множественного числа, `Intl.Collator` для сортировки по правилам языка. Подробно — в [Современном JavaScript](/content/javascript/modern-js).

У русского четыре категории множественного числа: `one` (1, 21, 31), `few` (2–4, 22–24), `many` (0, 5–20, 25) и `other` для дробных. Поэтому `n === 1 ? 'товар' : 'товара'` ломается уже на 5 и 21.

Чего в `Intl` нет — это самих переводов: где лежат строки, как подставить в них значения, как выбрать форму внутри фразы, как загрузить нужный язык. Это и делают библиотеки.

## ICU MessageFormat

**ICU MessageFormat** — стандартный формат сообщений, который используют :term[FormatJS]{def="набор библиотек интернационализации на стандартах Intl и ICU"}, :term[Lingui]{def="библиотека переводов для JavaScript, которая извлекает строки из кода"} и многие системы перевода. Множественное число, выбор и форматирование описываются прямо в строке:

```js
import { IntlMessageFormat } from 'intl-messageformat';

const items = new IntlMessageFormat(
  '{count, plural, one {# товар} few {# товара} many {# товаров} other {# товара}}',
  'ru',
);

items.format({ count: 21 });     // '21 товар'
items.format({ count: 11 });     // '11 товаров'
items.format({ count: 1.5 });    // '1,5 товара'
items.format({ count: 1000 });   // '1 000 товаров'
```

Категорию выбирают правила :term[CLDR]{def="общий репозиторий данных о локалях от Unicode: форматы чисел и дат, правила множественного числа"} — те же, что у `Intl.PluralRules`, а `#` форматируется по локали: дробная часть через запятую, тысячи через неразрывный пробел. Ветка `other` обязательна: без неё сообщение не компилируется, ошибка `MISSING_OTHER_CLAUSE`.

Выбор и вложенные конструкции:

```js
const added = new IntlMessageFormat(
  '{gender, select, female {{name} добавила} male {{name} добавил} other {{name} добавили}} ' +
  '{count, plural, one {# товар} few {# товара} many {# товаров} other {# товара}}',
  'ru',
);

added.format({ gender: 'female', name: 'Аня', count: 2 });   // 'Аня добавила 2 товара'

new IntlMessageFormat('Итого: {sum, number, ::currency/RUB}', 'ru').format({ sum: 1234.5 });
// 'Итого: 1 234,50 ₽'
```

### Почему не склеивать фразы

```js
// плохо
t('added') + ' ' + count + ' ' + t('items');
```

В другом языке порядок слов, падежи и число форм другие: где-то число стоит в конце, где-то глагол зависит от рода, где-то форм шесть, как в арабском. Переводчик получает целую фразу с подстановками и сам расставляет слова. Поэтому правило — **одно сообщение на одну фразу**, а не кусочки.

## Библиотеки

### i18next

Самая распространённая библиотека, обёртки для React, Vue, Angular, Svelte и серверов. У неё свой формат: подстановки в двойных фигурных скобках, а формы множественного числа — отдельные ключи с суффиксами категорий:

```json
{
  "item_one": "{{count}} товар",
  "item_few": "{{count}} товара",
  "item_many": "{{count}} товаров",
  "item_other": "{{count, number}} товара"
}
```

```js
t('item', { count: 21 });   // '21 товар'
```

Категорию выбирает `Intl.PluralRules` по параметру `count`. В проверке `t('item', { count: 1.5 })` без форматтера вернул `'1.5 товара'` — число подставляется как есть. Форматтер `{{count, number}}` даёт `'1,5 товара'`.

Если ключа нет в текущем языке, берётся язык из `fallbackLng`. Если нет нигде, возвращается сам ключ — `'cart.title'` на экране вместо текста. Подключение ICU — плагин `i18next-icu`.

### FormatJS и Lingui

**FormatJS** (`react-intl`) построен на ICU и `Intl`: компонент `FormattedMessage` и хук `useIntl` с `formatMessage`, `formatNumber`, `formatDate`. Строгий стандарт и инструменты извлечения сообщений.

**Lingui** тоже использует ICU, но компилирует сообщения при сборке: в рантайм попадают готовые функции, а не строки, которые нужно разбирать. Пишут прямо в коде — `` t`Добавить в корзину` `` — и инструмент сам собирает каталог для переводчиков.

### vue-i18n

Стандарт для Vue, но формат — свой, не ICU. Формы перечисляются через `|`:

```js
const i18n = createI18n({
  legacy: false,
  locale: 'ru',
  messages: { ru: { item: '{n} товар | {n} товара | {n} товаров' } },
});

i18n.global.t('item', 2);   // '2 товаров'
```

Правило выбора по умолчанию рассчитано на «ноль | один | много», поэтому в проверке получилось «1 товара», «2 товаров», «21 товаров». Для русского правило задают сами, через `Intl.PluralRules`:

```js
const ru = new Intl.PluralRules('ru');
const index = { one: 0, few: 1, many: 2, other: 1 };

createI18n({
  legacy: false,
  locale: 'ru',
  pluralRules: { ru: (n) => index[ru.select(n)] },
  messages,
});
// 1 товар, 2 товара, 5 товаров, 11 товаров, 21 товар
```

### Размер

| Библиотека | Формат | Рантайм, gzip |
| --- | --- | --- |
| intl-messageformat (ядро FormatJS) | ICU | около 9,5 KB |
| i18next | свой, ICU плагином | около 15 KB |

Актуально на ноябрь 2026, измерено сборкой с минификацией. У Lingui рантайм меньше за счёт компиляции сообщений при сборке.

## Организация переводов

### Ключи и файлы

Переводы хранят в JSON-файлах по языкам, а в коде — ключи вида `cart.title`. Инструменты извлечения — `i18next-parser`, `formatjs extract`, `lingui extract` — собирают ключи из кода, чтобы новые строки не терялись, а платформы перевода вроде Crowdin, Lokalise или Weblate синхронизируют файлы с переводчиками.

### Ленивая загрузка

Все переводы всех разделов в основном бандле — лишний вес. Их делят на **неймспейсы** по разделам и грузят, когда раздел открывается:

```js
await i18next.use(Backend).init({ lng: 'ru', ns: ['common'], defaultNS: 'common' });

t('pay', { ns: 'checkout' });     // 'pay' — раздел ещё не загружен
await i18next.loadNamespaces('checkout');
t('pay', { ns: 'checkout' });     // 'Оплатить'
```

В проверке при старте загрузился только `ru/common`, а `ru/checkout` — после `loadNamespaces`. В Vue и других сборках то же делают динамическим `import()` файла локали.

### Выбор языка

Язык выбирают по порядку: явный выбор пользователя в URL (`/en/catalog`) или cookie, затем заголовок `Accept-Language`, затем язык по умолчанию. Язык в URL лучше для поисковиков и ссылок: у каждой версии свой адрес, а связи между версиями указывают `hreflang`.

## Серверный рендер

Если язык определяется только в браузере после загрузки, сервер отрисует страницу на языке по умолчанию, а клиент — на другом. Это и мигание текста, и **hydration mismatch** — несовпадение серверной и клиентской разметки (подробно — в [Рендеринге и гидратации React](/content/reactjs/rendering-and-hydration)).

Правило — определить язык на сервере и передать клиенту тот же язык и те же переводы. С датами есть второй источник расхождений — часовой пояс:

```js
const moment = new Date('2026-11-15T22:30:00Z');

// сервер в UTC
new Intl.DateTimeFormat('ru', { dateStyle: 'short', timeStyle: 'short', timeZone: 'UTC' }).format(moment);
// '15.11.2026, 22:30'

// браузер в Москве
new Intl.DateTimeFormat('ru', { dateStyle: 'short', timeStyle: 'short', timeZone: 'Europe/Moscow' }).format(moment);
// '16.11.2026, 01:30'
```

Один момент — разные строки и даже разные дни. Часовой пояс пользователя тоже передают явно или форматируют такие даты только на клиенте.

## Справа налево

Арабский, иврит и персидский пишутся справа налево. Направление задаёт атрибут `dir` на корне документа:

```html
<html lang="ar" dir="rtl">
```

Направление языка знает `Intl.Locale`: `new Intl.Locale('ar').getTextInfo().direction` возвращает `'rtl'`, а для `ru` — `'ltr'`.

Атрибута мало: интерфейс должен зеркалиться — отступы, выравнивание, стрелки «назад» и «вперёд», положение боковой панели. Логические свойства CSS — `margin-inline-start` вместо `margin-left` — переворачиваются сами (подробно — в [Адаптивной вёрстке](/content/css/rwd)). Иконки со смыслом направления зеркалят, а логотипы, часы и медиаплеер — нет.

## Как выбрать

| Ситуация | Выбор |
| --- | --- |
| React, Vue или несколько фреймворков, большая экосистема плагинов | i18next |
| строгий ICU, переводчики работают в ICU | FormatJS (`react-intl`) |
| минимальный рантайм, сообщения прямо в коде | Lingui |
| Vue | vue-i18n со своим правилом для русского |
| только числа и даты, один язык | `Intl`, без библиотеки |

## Красные флаги в ответе

- **«Окончания — через `n === 1`».** У русского четыре категории, это ломается на 5 и 21.
- **«Фразу соберу из переведённых кусочков».** В другом языке другой порядок слов и согласование — переводят целую фразу.
- **«i18n — это перевод строк».** Ещё множественное число, род, форматирование, направление текста, выбор языка.
- **«Для RTL достаточно `dir="rtl"`».** Нужно зеркалить раскладку — логическими свойствами CSS.
- **«Язык определю в браузере после загрузки».** При серверном рендере это мигание и hydration mismatch.
- **«vue-i18n сам знает русские формы».** Правило по умолчанию даёт «2 товаров», нужен `pluralRules`.

## Как спрашивают на собеседовании

::question
Что входит в i18n помимо перевода строк?

#answer
Множественное число, выбор по роду, форматирование чисел, валют и дат по правилам языка, относительное время, направление текста, определение и переключение языка.

#more
Отдельно — организация переводов: ключи, файлы по языкам, извлечение ключей из кода, ленивая загрузка разделов. И серверный рендер: язык определяют на сервере, чтобы серверная и клиентская разметка совпали.
::

::question
Почему множественное число сложнее, чем «один или много»?

#answer
В разных языках разное число форм. В русском четыре категории: `one` для 1 и 21, `few` для 2–4, `many` для 0, 5–20 и 11, `other` для дробных. Правила берут из CLDR — через `Intl.PluralRules` или библиотеку на нём.

#more
В английском две формы, в арабском шесть. Форма зависит не от последней цифры, а от правила: 11 — `many`, хотя оканчивается на 1. В ICU ветка `other` обязательна — без неё сообщение не компилируется.
::

::question
Что умеет встроенный `Intl` и зачем тогда библиотеки?

#answer
`Intl` форматирует числа, валюты, даты, относительное время и списки, выбирает категорию множественного числа и сортирует по правилам языка. Библиотеки добавляют управление переводами: где хранятся строки, как подставить значения, как выбрать форму внутри фразы и загрузить нужный язык.

#more
Если язык один и нужно только форматирование, библиотека не нужна. Подробно об `Intl` — в главе про JavaScript.
::

::question
Что такое ICU MessageFormat?

#answer
Стандартный формат сообщений: подстановки, множественное число через `plural`, выбор через `select`, форматирование чисел и дат — всё в одной строке, например `{count, plural, one {# товар} few {# товара} many {# товаров} other {# товара}}`.

#more
Его используют FormatJS, Lingui, i18next через плагин и системы перевода. Главная польза — переводчик получает целую фразу с ветками и сам решает, сколько форм и какой порядок слов нужен в его языке.
::

::question
Как избежать hydration mismatch при i18n с серверным рендером?

#answer
Определить язык на сервере — по URL, cookie или `Accept-Language` — и отдать клиенту тот же язык и те же переводы, чтобы обе разметки совпали.

#more
Второй источник — часовой пояс: одна и та же дата на сервере в UTC и в браузере в Москве форматируется по-разному, иногда другим днём. Часовой пояс передают явно или форматируют такие значения только на клиенте.
::

::question
Как организовать переводы в большом приложении?

#answer
Ключи в коде, JSON-файлы по языкам, разбитые на неймспейсы по разделам. Основной раздел грузится сразу, остальные — когда открывается раздел.

#more
Ключи извлекают из кода инструментами — `i18next-parser`, `formatjs extract`, `lingui extract`, — а переводчики работают на платформах вроде Crowdin. Для пропущенных переводов задают язык-запасной, иначе на экране появится сам ключ.
::

## Практика

::practice{title="«2 товаров» в корзине"}
Магазин на Vue с vue-i18n. В корзине написано «1 товара», «2 товаров», «21 товаров». Сообщение: `'{n} товар | {n} товара | {n} товаров'`.

#solution
Правило выбора формы по умолчанию в vue-i18n рассчитано на «ноль | один | много», а не на русские категории. Правило задают через `pluralRules`:

```js
const ru = new Intl.PluralRules('ru');
const index = { one: 0, few: 1, many: 2, other: 1 };

const i18n = createI18n({
  legacy: false,
  locale: 'ru',
  pluralRules: { ru: (n) => index[ru.select(n)] },
  messages: { ru: { item: '{n} товар | {n} товара | {n} товаров' } },
});

i18n.global.t('item', 21);   // '21 товар'
```

В проверке до исправления было «1 товара», «2 товаров», «21 товаров», после — «1 товар», «2 товара», «5 товаров», «11 товаров», «21 товар». Дробные числа (`other`) получают форму «товара».
::

::practice{title="Уведомление из кусочков"}
Строка уведомления собрана так: `user.name + ' ' + t('added') + ' ' + count + ' ' + t('items')`. Переводчики жалуются, что на их языках получается бессмыслица, а в русском — «Аня добавил 5 товар».

#solution
Род, число и порядок слов зависят друг от друга, поэтому фраза — одно сообщение с подстановками:

```js
const added = new IntlMessageFormat(
  '{gender, select, female {{name} добавила} male {{name} добавил} other {{name} добавили}} ' +
  '{count, plural, one {# товар} few {# товара} many {# товаров} other {# товара}}',
  'ru',
);

added.format({ gender: 'female', name: 'Аня', count: 2 });   // 'Аня добавила 2 товара'
added.format({ gender: 'male', name: 'Петя', count: 5 });    // 'Петя добавил 5 товаров'
added.format({ gender: 'other', name: 'Саша', count: 21 });  // 'Саша добавили 21 товар'
```

Каждый язык получает ту же структуру и сам решает, сколько веток и в каком порядке слова. В i18next то же — через контекст (`context: 'female'`) и суффиксы множественного числа или через плагин ICU.
::

::practice{title="Выбор языка по заголовку"}
Сайт поддерживает русский и английский. Пользователь из Украины с браузером `uk-UA,uk;q=0.9,ru;q=0.8,en;q=0.7` видит английскую версию, хотя русский у него в списке выше английского.

#solution
Код, скорее всего, берёт первый язык из заголовка и при промахе сразу идёт к языку по умолчанию. Нужно пройти по списку в порядке веса `q` и взять первый поддерживаемый, сравнивая и полный тег, и основной язык:

```js
function negotiate(header, supported, fallback) {
  const wanted = header.split(',').map((part) => {
    const [tag, q = 'q=1'] = part.trim().split(';');
    return { tag: tag.toLowerCase(), q: Number(q.split('=')[1]) };
  }).sort((a, b) => b.q - a.q);

  for (const { tag } of wanted) {
    const hit = supported.find((s) => s === tag || s === tag.split('-')[0]);
    if (hit) return hit;
  }
  return fallback;
}

negotiate('uk-UA,uk;q=0.9,ru;q=0.8,en;q=0.7', ['ru', 'en'], 'en');   // 'ru'
negotiate('en-GB,en;q=0.9', ['ru', 'en'], 'ru');                      // 'en'
```

Заголовок — только первая догадка: явный выбор пользователя в URL или cookie важнее. В проверке все три случая, включая неподдерживаемый `de`, дали ожидаемый язык.
::
