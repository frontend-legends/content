# Интернационализация (i18n)

**i18n** (internationalization - 18 букв между i и n) - это больше, чем перевод строк. Это плюрализация, род, форматирование чисел/дат/валют по локали, направление текста (RTL), определение языка. Многое умеет нативный `Intl`, а для переводов берут библиотеки.

---

## Что входит в i18n

- **Переводы** строк по ключам и языкам.
- **Плюрализация** - разные формы по числу (и это сложнее, чем «один/много»).
- **Интерполяция** и **род/выбор** (select) - «{name} оставил(а) комментарий».
- **Форматирование** чисел, дат, валют, относительного времени по локали.
- **Направление** текста (LTR/RTL для арабского, иврита).
- **Определение локали** и переключение.

---

## Нативный Intl

Браузерный объект `Intl` решает форматирование **без библиотек** - это часто недооценивают.

```js
new Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB' }).format(1234.5);
// "1 234,50 ₽"

new Intl.DateTimeFormat('ru-RU', { dateStyle: 'long' }).format(new Date());
// "6 июня 2026 г."

new Intl.RelativeTimeFormat('ru').format(-3, 'day'); // "3 дня назад"
new Intl.PluralRules('ru').select(2);                // "few"
```

<b class="text-on-semi-light">Что покрывает Intl</b> - <span class="text-gray">`NumberFormat`, `DateTimeFormat`, `RelativeTimeFormat`, `PluralRules`, `Collator` (сортировка с учётом локали), `ListFormat`. Для форматирования это почти всё, что нужно - библиотеки добавляют сверху именно **управление переводами**.</span>

---

## Плюрализация - почему это сложно

Частая ловушка, особенно близкая русскоязычной аудитории. В английском две формы (`1 item` / `2 items`), а в **русском - три**:

```
1 товар      (one)
2 товара     (few)
5 товаров    (many)
21 товар     (снова one!)
```

Нельзя хардкодить `count === 1 ? 'товар' : 'товары'` - это сломается на 2 и 21. Правильно - использовать **CLDR-правила плюрализации** (`Intl.PluralRules` или библиотека), которые знают формы каждого языка.

> ICU-формат описывает это декларативно: `{count, plural, one {# товар} few {# товара} many {# товаров}}`.

---

## ICU MessageFormat

**ICU** - индустриальный стандарт формата сообщений: плюрализация, выбор по роду, интерполяция, вложенность - в одной строке.

```
"{gender, select, male {Он добавил} female {Она добавила} other {Добавили}} {count, plural, ...}"
```

Библиотеки на ICU гарантируют корректную локализацию для любого языка.

## Библиотеки

- **i18next** (+ **react-i18next**, **vue-i18n** совместим по идеям) - самый популярный, огромная экосистема: бэкенды загрузки переводов, неймспейсы, определение языка, ленивая подгрузка. Универсальный выбор.
- **FormatJS / react-intl** - построен на **ICU MessageFormat**, силён в форматировании и плюрализации, использует нативный Intl.
- **Lingui** - компиляция сообщений на этапе сборки, очень лёгкий рантайм, ICU.
- **vue-i18n** - стандарт для Vue, ICU-совместимый.

```jsx
// react-i18next
const { t } = useTranslation();
<p>{t('cart.items', { count })}</p>; // подставит правильную форму по локали
```

| Библиотека   | Основа        | Фреймворк      | Заметка                |
| ------------ | ------------- | -------------- | ---------------------- |
| i18next      | свой + плагины| React/Vue/др.  | самый популярный       |
| FormatJS     | ICU + Intl    | React          | строгий стандарт ICU   |
| Lingui       | ICU, компиляция| React/др.     | лёгкий рантайм         |
| vue-i18n     | ICU           | Vue            | стандарт для Vue       |

## Организация переводов

- **Ключи** (`t('cart.title')`) с JSON-файлами по языкам - самый распространённый подход.
- **Неймспейсы** - дробление переводов по разделам, ленивая загрузка только нужных.
- **Извлечение** - инструменты вытаскивают ключи из кода в файлы переводов для переводчиков.
- **Серверная отдача** локали для SSR (чтобы не было FOUC и hydration mismatch).

---

## RTL

Для арабского/иврита текст идёт **справа налево**. Это не только `dir="rtl"` - зеркалятся отступы, иконки, направление. Современный CSS помогает **логическими свойствами** (`margin-inline-start` вместо `margin-left`), которые автоматически учитывают направление.

---

## Как выбрать

```
Универсально, большая экосистема     → i18next (react-i18next)
Строгий ICU, форматирование          → FormatJS / react-intl
Минимальный рантайм                  → Lingui
Vue                                  → vue-i18n
Только форматирование чисел/дат      → нативный Intl, без библиотеки
```

## Вопросы на собеседовании

<b class="text-on-semi-light">Что входит в i18n помимо перевода строк?</b>
<span class="text-gray">Плюрализация, род/выбор, форматирование чисел/дат/валют по локали, относительное время, направление текста (RTL), определение и переключение языка.</span>

<b class="text-on-semi-light">Почему плюрализация сложнее, чем «один/много»?</b>
<span class="text-gray">В разных языках разное число форм: в русском три (товар/товара/товаров), причём 21 снова «один». Нельзя хардкодить - нужны CLDR-правила (`Intl.PluralRules` или ICU).</span>

<b class="text-on-semi-light">Что умеет нативный Intl?</b>
<span class="text-gray">`NumberFormat`, `DateTimeFormat`, `RelativeTimeFormat`, `PluralRules`, `Collator`, `ListFormat` - форматирование чисел, дат, валют, плюрализацию и сортировку по локали без библиотек.</span>

<b class="text-on-semi-light">Что такое ICU MessageFormat?</b>
<span class="text-gray">Стандартный формат сообщений с плюрализацией, выбором по роду и интерполяцией в одной строке - гарантирует корректную локализацию для любого языка.</span>

<b class="text-on-semi-light">Как избежать hydration mismatch при i18n с SSR?</b>
<span class="text-gray">Отдавать правильную локаль уже на сервере, чтобы серверный и клиентский рендер совпадали, и не определять язык только на клиенте после монтирования.</span>
