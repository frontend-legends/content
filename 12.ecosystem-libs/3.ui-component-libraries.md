# UI-библиотеки компонентов

Кнопки, модалки, дропдауны, табы - писать их с нуля (с доступностью, клавиатурой, фокусом) дорого. UI-библиотеки решают это. Но они делятся на **три принципиально разных подхода**, и понимание различий - частый senior-вопрос.

---

## Три подхода

| Подход                    | Что даёт                           | Кто                                    |
| ------------------------- | ---------------------------------- | -------------------------------------- |
| **Styled** (готовые)      | компоненты со встроенными стилями  | MUI, Ant Design, Mantine, Chakra       |
| **Headless** (без стилей) | логика + доступность, стили твои   | Radix UI, Headless UI, React Aria, Ark |
| **Copy-paste** (свой код) | код компонента копируется в проект | shadcn/ui                              |

---

## Styled - «всё в комплекте»

Готовые компоненты с дизайном из коробки. Поставил - и сразу красиво.

- **MUI** (Material UI) - огромный, Material Design, зрелый.
- **Ant Design** - богатый набор для админок/энтерпрайза.
- **Mantine** - современный, много хуков и компонентов.
- **Chakra UI** - акцент на DX и доступность.

<b class="text-on-semi-light">Плюсы и минусы</b> - <span class="text-gray">Плюс - скорость: прототип за часы. Минусы - тяжело **перестилизовать** под свой бренд (борьба с дефолтными стилями), вес бандла, **vendor lock-in**, и «эффект одинаковости» - приложения на MUI узнаваемы. Хороши для админок и внутренних инструментов, где дизайн вторичен.</span>

---

## Headless - логика без стилей

Дают **поведение и доступность** (управление фокусом, ARIA, клавиатура, позиционирование), но **не навязывают внешний вид** - стили полностью твои.

- **Radix UI** (Reka UI / Radix Vue для Vue) - набор примитивов (Dialog, Popover, Dropdown).
- **Headless UI** - от команды Tailwind, базовый набор.
- **React Aria** (Adobe) - самая глубокая проработка доступности.
- **Ark UI** - кросс-фреймворк (React/Vue/Solid) на базе state machines.

<b class="text-on-semi-light">Зачем headless</b> - <span class="text-gray">Доступная модалка или комбобокс - это сотни строк сложной логики (focus trap, ARIA, навигация стрелками). Headless даёт всё это, оставляя дизайн тебе. Идеально для **своей дизайн-системы**: уникальный вид + надёжная механика. Это золотая середина между «готовым, но чужим» и «своим, но дорогим».</span>

```tsx
// Radix: вся механика (фокус, Esc, ARIA, портал) - готова, стили твои
import * as Dialog from '@radix-ui/react-dialog';

<Dialog.Root>
  <Dialog.Trigger className="btn">Открыть</Dialog.Trigger>
  <Dialog.Portal>
    <Dialog.Overlay className="overlay" />
    <Dialog.Content className="modal">  {/* focus trap и aria-modal - из коробки */}
      <Dialog.Title>Заголовок</Dialog.Title>
      <Dialog.Close className="btn">Закрыть</Dialog.Close>
    </Dialog.Content>
  </Dialog.Portal>
</Dialog.Root>;
```

### Узкоспециализированные примитивы

Помимо больших наборов, есть точечные headless-библиотеки под одну сложную задачу:

- **Floating UI** - позиционирование «плавающих» элементов (тултипы, поповеры, дропдауны) с учётом краёв экрана; на нём построены многие другие.
- **downshift** / **cmdk** - автокомплиты и командные палитры (combobox) с правильной a11y и клавиатурой.
- **TanStack Table / Virtual** - headless-логика таблиц и виртуализации (см. [таблицы и гриды](/content/ecosystem-libs/tables-and-grids)).
- **Base UI** - новый headless-набор от команды MUI и Floating UI; претендует на «общий стандарт» примитивов.

> Тенденция 2025–2026: индустрия сходится на **headless-ядре + своих стилях**. Даже крупные styled-библиотеки выносят логику в headless-слой (MUI Base, Mantine headless-хуки), чтобы дать выбор.

## Copy-paste - ты владеешь кодом

Тренд 2024–2026, заданный **shadcn/ui**. Это **не пакет-зависимость**: ты копируешь код компонента (Radix + Tailwind) прямо в свой проект через CLI и дальше владеешь им.

```bash
npx shadcn@latest add button dialog
# код кнопки и модалки появляется в твоём src/components/ui
```

<b class="text-on-semi-light">Почему это взлетело</b> - <span class="text-gray">Нет зависимости и lock-in: код твой, меняй как хочешь. Доступность - от Radix под капотом, стили - Tailwind, которые легко править. Минус - обновления не приходят сами (ты «владеешь» и копией багов тоже). Концептуально это «библиотека как стартовый код, а не как пакет».</span>

## Дизайн-системы

Когда компонентов много и их используют несколько команд/приложений, их оформляют в **дизайн-систему**: единый набор токенов (цвета, отступы, типографика) + компоненты на их основе. Headless и copy-paste подходы - база для своей дизайн-системы; готовые styled-библиотеки - сами по себе дизайн-системы (но чужие).

> Документируют дизайн-системы обычно в **Storybook** - изолированная витрина компонентов (подробнее - в [тулинге](/content/advanced-tooling)).

## Стоимость, бандл и RSC

Выбор библиотеки - это не только DX, но и runtime-последствия.

- **Вес бандла.** Styled-наборы (особенно MUI/Ant) тяжёлые; импортируй точечно и проверяй на [bundlephobia](https://bundlephobia.com). Headless-примитивы обычно легче, потому что не тащат стили и тему.
- **Способ стилизации.** Часть styled-библиотек построена на **runtime CSS-in-JS** (Emotion). В React Server Components такие стили не работают в серверных компонентах - это толкает экосистему к Tailwind и zero-runtime решениям (см. [стилизация](/content/ecosystem-libs/styling-solutions)).
- **Tree-shaking.** Хорошая библиотека - ESM с `sideEffects: false`, чтобы в бандл попадали только используемые компоненты.

<b class="text-on-semi-light">Что спрашивают</b> - <span class="text-gray">«Почему MUI может конфликтовать с серверными компонентами?» - потому что его рантайм CSS-in-JS требует клиента. Это типичный senior-вопрос про пересечение UI-библиотек и RSC.</span>

## Когда UI-библиотека не нужна

Не каждый проект требует библиотеку компонентов.

- **Маленький лендинг** - проще обычный HTML/CSS, чем тащить набор.
- **Жёсткий уникальный дизайн** без сложных виджетов - своя пара компонентов дешевле борьбы с чужими стилями.
- **Нужен один сложный виджет** (датапикер, комбобокс) - возьми точечный headless-примитив, а не весь набор.

> Антипаттерн - ставить MUI ради трёх кнопок. Зависимость должна окупать вес и lock-in.

---

## Как выбрать

```
Нужно быстро, дизайн вторичен (админка)      → styled (MUI/Ant/Mantine)
Нужен уникальный бренд + надёжная механика    → headless (Radix/React Aria)
Хочешь владеть кодом, Tailwind-стек           → copy-paste (shadcn/ui)
Большая команда, единый язык дизайна          → своя дизайн-система на headless
```

## Вопросы на собеседовании

<b class="text-on-semi-light">Чем headless-библиотека отличается от обычной UI-библиотеки?</b>
<span class="text-gray">Headless даёт логику и доступность без стилей - внешний вид полностью твой. Styled-библиотека приходит с готовым дизайном, который тяжело перекрасить.</span>

<b class="text-on-semi-light">Когда брать MUI, а когда Radix?</b>
<span class="text-gray">MUI - когда нужно быстро и дизайн вторичен (админки). Radix (headless) - когда нужен уникальный бренд при надёжной механике и доступности, обычно для своей дизайн-системы.</span>

<b class="text-on-semi-light">Что такое shadcn/ui и чем он необычен?</b>
<span class="text-gray">Это не зависимость, а код компонентов (Radix + Tailwind), который копируется в проект. Ты владеешь кодом - нет lock-in, но и автообновлений нет.</span>

<b class="text-on-semi-light">Почему доступную модалку сложно написать самому?</b>
<span class="text-gray">Нужны focus trap, возврат фокуса, ARIA, закрытие по Esc, навигация с клавиатуры - сотни строк тонкой логики. Headless-библиотеки решают это за тебя.</span>

<b class="text-on-semi-light">В чём минус готовых styled-библиотек?</b>
<span class="text-gray">Тяжело перестилизовать под бренд, вес бандла, vendor lock-in и узнаваемая «одинаковость» приложений.</span>

<b class="text-on-semi-light">Почему некоторые UI-библиотеки конфликтуют с серверными компонентами?</b>
<span class="text-gray">Если библиотека построена на runtime CSS-in-JS (Emotion), стили вычисляются в браузере и не работают в React Server Components. Это сдвигает выбор к Tailwind/zero-runtime и headless-наборам.</span>

<b class="text-on-semi-light">Когда UI-библиотеку лучше вообще не брать?</b>
<span class="text-gray">Для маленьких лендингов, жёсткого уникального дизайна без сложных виджетов или когда нужен один сложный компонент - тогда берут точечный headless-примитив, а не весь набор.</span>
