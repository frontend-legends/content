# Стилизация

Как выбрать инструмент стилизации в 2026 году: CSS и Sass, CSS Modules, Tailwind, CSS-in-JS во время выполнения и при сборке — и что каждый стоит в размере, скорости и совместимости с серверными компонентами. Спрашивают, чем Tailwind лучше или хуже CSS Modules, почему уходят от styled-components и как стилизовать серверные компоненты. Глубже — почему класс `bg-${color}-500` не работает, что CSS Modules оставляют в сборке и сколько классов создаёт CSS-in-JS на динамических данных.

::tldr
- **Подходы и методологии CSS — BEM, модули, утилиты, токены — разобраны в архитектуре CSS.** Здесь выбор инструмента и его цена.
- **Tailwind генерирует только классы, которые нашёл в исходниках как целые строки.** `bg-${color}-500` сканер не видит, и стиль не появится; нужны полные имена классов.
- **CSS Modules изолируют имена хешами,** но не выбрасывают неиспользуемые классы: правило, которое никто не применяет, останется в сборке.
- **CSS-in-JS во время выполнения вставляет стили в рантайме и создаёт класс на каждое значение:** это библиотека в бандле, работа при рендере и несовместимость с серверными компонентами. Поэтому выбирают Tailwind, CSS Modules или CSS-in-JS, который извлекается при сборке.
- **Выбор определяется командой и рендерингом:** серверные компоненты и SSR исключают рантайм-стилизацию, дизайн-система требует токенов, а большая команда выигрывает от одного предсказуемого способа.
::

---

## Варианты

Сквозной пример — карточка товара: отступы, заголовок, цвет статуса «в наличии» или «нет в наличии», ширина полосы рейтинга из данных.

| Подход | Инструменты | Где стили | Работа при выполнении |
| --- | --- | --- | --- |
| CSS и препроцессоры | CSS, Sass, Less, PostCSS | `.css`, `.scss` | нет |
| модули | CSS Modules, `<style scoped>` во Vue | `.module.css` | нет |
| утилиты | Tailwind, UnoCSS | классы в разметке | нет |
| CSS-in-JS при сборке | vanilla-extract, Panda CSS, StyleX, Linaria | JS или TS, извлекается в `.css` | нет или минимум |
| CSS-in-JS при выполнении | styled-components, Emotion | JS, вставляется в `<style>` | да |

Как устроены методологии — BEM, CSS Modules и `composes`, утилиты, токены, слои, — в [Архитектуре CSS](/content/css/architecture). Дальше — что показывают сборка и бандл.

## Современный CSS как основа

Значительная часть причин, по которым брали препроцессоры и :term[CSS-in-JS]{def="подход, при котором стили описывают в JavaScript, а библиотека генерирует и вставляет их на страницу"}, закрыта самим CSS:

- **вложенность** — нативная, `&` работает без Sass;
- **переменные** — custom properties, причём меняются при выполнении и наследуются, в отличие от переменных Sass;
- **изоляция** — `@scope` и каскадные слои `@layer` для управления приоритетом;
- **адаптивность компонента** — container queries;
- **цвета** — `oklch`, `color-mix()`, относительные цвета для тем.

Подробно — в [Современном CSS](/content/css/modern-css). Поэтому обычный CSS с CSS-переменными и `@layer` — реальный выбор и для больших проектов.

## CSS Modules

```css
/* card.module.css */
.card { padding: 16px; }
.title { font-weight: 700; }
.unusedLegacy { color: hotpink; }
```

```js
import s from './card.module.css';
// <div class={s.card}> → <div class="_card_17704_1">
```

Сборщик превращает имена в уникальные с хешем — в проверке Vite выдал `._card_17704_1`, а глобального `.card` в сборке не было. Конфликтов имён между компонентами не бывает. Во Vue ту же задачу решает `<style scoped>` через атрибут `data-v-…` (подробно — во [Введении в Vue](/content/vuejs/introduction)).

Чего модули не делают: **не выбрасывают неиспользуемые классы.** В проверке `.unusedLegacy` никто не импортировал, но правило осталось в CSS — минификатор только сократил `hotpink` до `#ff69b4`. CSS лежит отдельно от кода, и сборщик не знает, какие классы используются. Мёртвые правила копятся годами и чистятся вручную или линтером.

## Tailwind

```html
<p class="p-4 text-lg bg-blue-500">Улун</p>
```

Tailwind сканирует исходники, находит строки, похожие на имена утилит, и генерирует CSS **только для них**. В проверке итоговый CSS страницы с несколькими утилитами весил около 4,6 КБ, а неиспользуемых классов в нём не было. CSS растёт медленно: утилиты переиспользуются, и новый компонент добавляет мало нового.

### Главная ловушка

Сканер ищет **целые имена классов как текст**. Он не выполняет код:

```js
const color = status === 'error' ? 'red' : 'green';

`bg-${color}-500`                                            // не найден — стиля не будет
status === 'error' ? 'text-red-700' : 'text-green-700'       // оба имени целиком — найдены
```

В проверке `.bg-red-500` в сборке не появился, хотя на странице такой класс был собран, а `.text-red-700` и `.text-green-700` — появились оба. Правило: **имена классов пишутся целиком**, а выбор делают картой или условием. Если имя действительно приходит из данных, его перечисляют в `@source inline(...)` или используют CSS-переменную: `style="--w: 137px" class="w-(--w)"`.

Произвольные значения тоже работают — `w-[137px]` в проверке дал `.w-\[137px\]{width:137px}`, — но их обилие — признак, что значения стоит вынести в токены темы.

### Цена

- разметка с длинными списками классов — компоненты и утилиты `clsx`/`cn` для условий;
- своя дизайн-система — через тему в `@theme`, иначе каждый пишет свои значения;
- Tailwind 4 настраивается в CSS (`@import "tailwindcss"`, `@theme`), без JavaScript-конфигурации, и работает как плагин Vite.

Tailwind — основа shadcn/ui (подробно — в [UI-библиотеках](/content/ecosystem-libs/ui-component-libraries)) и один из самых частых выборов в новых проектах на React и Vue.

## CSS-in-JS

### Во время выполнения

```js
import { css } from '@emotion/css';

const bar = (rating) => css({ height: 4, width: `${rating}%`, background: rating > 80 ? 'green' : 'orange' });
```

Удобно: стили рядом с логикой, значения из пропсов, автоматическая изоляция. Цена видна в проверке:

- **библиотека в бандле** — `@emotion/css` дал около 6 КБ gzip, styled-components тяжелее;
- **работа при каждом рендере** — сериализовать объект, посчитать хеш, вставить правило в `<style>`;
- **класс на каждое значение** — 50 разных ширин дали 50 классов и 50 правил в документе. Для динамических данных правильно передавать значение через CSS-переменную, а не через новый класс;
- **SSR требует настройки** — собрать стили на сервере и передать клиенту, иначе страница мигнёт без стилей;
- **несовместимость с серверными компонентами React:** библиотеке нужен контекст и выполнение на клиенте, поэтому компоненты со стилями приходится делать клиентскими.

Из-за этого рантайм-CSS-in-JS уходит из новых проектов. Авторы styled-components объявили его поддержку без развития, а UI-библиотеки, построенные на Emotion, переходят на стили, извлекаемые при сборке.

### При сборке

:term[vanilla-extract]{def="стили на TypeScript, которые при сборке превращаются в обычные CSS-файлы"}, Panda CSS, :term[StyleX]{def="библиотека стилей Meta: стили в JavaScript компилируются в атомарный CSS при сборке"} и Linaria сохраняют удобство — стили в TypeScript, типизированные токены, варианты, — но **извлекают** CSS при сборке в обычные `.css`-файлы. При выполнении остаются только имена классов. StyleX использует Meta, Panda — основа Park UI. Динамические значения задаются через CSS-переменные.

## Серверные компоненты и SSR

Серверные компоненты React не выполняются в браузере, поэтому стилизация, которой нужен JavaScript при рендере, им не подходит (подробно — в [RSC и React 19](/content/reactjs/rsc-and-react-19)). Работают всё, что даёт обычный CSS к моменту сборки:

- CSS и CSS Modules;
- Tailwind;
- CSS-in-JS, извлекаемый при сборке.

При SSR в любом фреймворке выигрывают те же варианты: CSS приходит отдельным файлом с первым HTML, кешируется и не блокирует гидратацию.

---

## Как выбрать

| Ситуация | Выбор |
| --- | --- |
| новый проект на React или Vue, своя дизайн-система | Tailwind с темой или CSS Modules с токенами |
| компонентная библиотека, которую используют другие | CSS Modules или CSS-in-JS при сборке, без зависимости от Tailwind потребителя |
| серверные компоненты React | Tailwind, CSS Modules, vanilla-extract, StyleX |
| Vue | `<style scoped>` или CSS Modules, Tailwind по желанию |
| большой легаси-код на styled-components | постепенный переход: новые компоненты — на CSS Modules или Tailwind, общие токены — CSS-переменные |
| небольшой проект | обычный CSS с переменными, `@layer` и вложенностью |

Главное — **один основной способ на проект**. Три системы стилизации в одном приложении — три способа задать отступ и три источника конфликтов.

---

## Красные флаги в ответе

- **«`bg-${color}-500` сработает».** Tailwind ищет имена как текст и не найдёт собранный класс.
- **«CSS Modules удалят неиспользуемые стили».** Они изолируют имена, но правило без использования остаётся.
- **«styled-components — стандарт для React».** Рантайм-CSS-in-JS несовместим с серверными компонентами и уходит из новых проектов.
- **«CSS-in-JS ничего не стоит».** Это библиотека в бандле, работа при рендере и класс на каждое значение.
- **«Без Sass нет вложенности и переменных».** В CSS есть и то, и другое.

## Как спрашивают на собеседовании

::question
Чем Tailwind отличается от CSS Modules?

#answer
Tailwind даёт готовые утилитарные классы прямо в разметке и генерирует CSS только для найденных утилит, поэтому CSS растёт медленно. CSS Modules — обычный CSS в отдельных файлах с уникальными именами классов через хеш.

#more
У Tailwind ловушка — имена классов должны встречаться целиком, `bg-${color}-500` не сработает. У CSS Modules — неиспользуемые классы не выбрасываются. Оба подхода работают без JavaScript при выполнении и совместимы с серверными компонентами. Для дизайн-системы Tailwind настраивают темой, CSS Modules — токенами в CSS-переменных.
::

::question
Почему уходят от styled-components и Emotion?

#answer
Рантайм-CSS-in-JS требует библиотеку в бандле, работу при каждом рендере и вставку правил в `<style>`, на каждое значение создаёт новый класс, сложен при SSR и несовместим с серверными компонентами React.

#more
Альтернативы с тем же удобством — vanilla-extract, Panda CSS, StyleX, Linaria: стили в TypeScript, но CSS извлекается при сборке. Динамические значения передают через CSS-переменные, а не через новые классы. styled-components переведён в режим поддержки без развития.
::

::question
Почему класс bg-${color}-500 не работает в Tailwind?

#answer
Tailwind не выполняет код, а ищет в исходниках строки, похожие на имена утилит. Собранного из частей имени нет в тексте целиком, поэтому стиль не генерируется.

#more
Нужно писать имена полностью: условием или картой `{ error: 'bg-red-500', ok: 'bg-green-500' }`. Если имя действительно приходит из данных, его явно перечисляют через `@source inline(...)` или используют CSS-переменную и класс вида `bg-(--status-color)`.
::

::question
Как стилизовать серверные компоненты?

#answer
Тем, что не требует JavaScript при рендере: CSS, CSS Modules, Tailwind или CSS-in-JS, который извлекается при сборке, — vanilla-extract, StyleX, Panda CSS.

#more
Рантайм-библиотекам нужен контекст и выполнение на клиенте, поэтому компонент с ними становится клиентским. При SSR в любом фреймворке выигрывает отдельный CSS-файл: он приходит с первым HTML и кешируется.
::

::question
Нужен ли Sass в 2026 году?

#answer
Чаще нет. В CSS есть вложенность, переменные, которые меняются при выполнении, `@layer`, `@scope`, container queries и функции цвета. Sass остаётся полезен для миксинов, циклов и легаси-кода.

#more
CSS-переменные мощнее переменных Sass: они наследуются, меняются в рантайме и подходят для тем. Препроцессор добавляет шаг сборки и свой синтаксис, поэтому в новых проектах его берут осознанно, а не по привычке.
::

## Практика

::practice{title="Цвет статуса не применяется"}
В проде у бейджа статуса нет фона, хотя в DevTools класс на месте:

```jsx
const color = { paid: 'green', pending: 'yellow', failed: 'red' }[order.status];
<span className={`px-2 rounded bg-${color}-100 text-${color}-800`}>{order.status}</span>
```

#solution
Tailwind не нашёл классы `bg-green-100`, `text-red-800` и остальные: в исходниках их нет целиком, а есть только `bg-${color}-100`. CSS для них не сгенерирован.

```jsx
const badge = {
  paid: 'bg-green-100 text-green-800',
  pending: 'bg-yellow-100 text-yellow-800',
  failed: 'bg-red-100 text-red-800',
};

<span className={`px-2 rounded ${badge[order.status]}`}>{order.status}</span>
```

Теперь все имена встречаются в коде целиком, и сканер их находит. В проверке собранный из частей `bg-${color}-500` не дал правила, а полные имена в условии — дали оба.
::

::practice{title="Тысячи стилей в документе"}
Таблица товаров с полосой рейтинга на Emotion тормозит при прокрутке, а в `<head>` тысячи правил:

```js
const bar = (rating) => css({ height: 4, width: `${rating}%`, background: 'gold' });
```

#solution
Каждое новое значение `rating` даёт новый объект стилей, новый хеш и новое правило в документе. В проверке 50 разных значений дали 50 классов. Динамическое значение передают через CSS-переменную, а класс оставляют один:

```css
/* rating.module.css */
.bar { height: 4px; width: var(--rating); background: gold; }
```

```jsx
<div className={s.bar} style={{ '--rating': `${rating}%` }} />
```

Одно правило на все строки, а значение меняется атрибутом `style`, без новых правил и без вставки в `<head>`. Это же решение работает в серверных компонентах. Если таблица на Emotion целиком, переход на CSS Modules или Tailwind делают постепенно, начиная с горячих компонентов.
::
