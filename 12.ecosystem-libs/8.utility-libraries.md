# Утилиты

Что брать для повседневных задач — коллекций, копирования, дат, неизменяемых обновлений, HTTP и мелочей вроде классов и ID — и что из этого уже есть в языке и браузере. Спрашивают, нужен ли lodash в 2026 году, чем `structuredClone` отличается от `cloneDeep` и зачем axios, если есть `fetch`. Глубже — почему копия потеряла методы, почему «плюс сутки» в марте дают не тот час и почему `fetch` не бросает на 404.

::tldr
- **Сначала — язык:** `Object.groupBy`, `toSorted`, `findLast`, операции над `Set`, `structuredClone`, `Promise.withResolvers`, `crypto.randomUUID` закрывают большую часть того, ради чего ставили lodash и uuid.
- **`structuredClone` копирует глубоко, с `Date`, `Map`, `Set` и циклами, но экземпляр класса становится обычным объектом без методов,** а функции копировать отказывается. `cloneDeep` из lodash прототип сохраняет.
- **Даты — это часовые пояса:** прибавить 24 часа и прибавить один день — разное в день перехода на летнее время. Форматирование — `Intl`, арифметика — `date-fns` или `Temporal`.
- **Immer даёт писать мутации, а возвращает новое неизменяемое состояние,** где неизменённые ветки — те же объекты. Поэтому сравнение по ссылке и мемоизация продолжают работать.
- **`fetch` не бросает исключение на 404 и 500 — только на сетевой ошибке.** axios, ky и ofetch бросают на ошибочном статусе; маленькая обёртка над `fetch` часто достаточна.
::

## Сначала — язык

Сквозной пример — список заказов магазина:

```js
const orders = [
  { id: 3, status: 'paid', total: 980 },
  { id: 1, status: 'new', total: 490 },
  { id: 2, status: 'paid', total: 1500 },
];
```

| Задача | Раньше | Сейчас |
| --- | --- | --- |
| сгруппировать | `_.groupBy` | `Object.groupBy(orders, (o) => o.status)` |
| отсортировать без мутации | `[...a].sort()` или `_.sortBy` | `orders.toSorted((a, b) => a.id - b.id)` |
| последний подходящий | `_.findLast` | `orders.findLast((o) => o.status === 'paid')` |
| объединение и пересечение | `_.union`, `_.intersection` | `setA.union(setB)`, `setA.intersection(setB)` |
| глубокая копия | `_.cloneDeep` | `structuredClone(value)` |
| промис с внешним `resolve` | своя обёртка | `Promise.withResolvers()` |
| уникальный ID | `uuid` | `crypto.randomUUID()` |

Все примеры проверены на Node.js 24; в браузерах они входят в Baseline. `debounce` и `throttle` — несколько строк, их устройство разобрано в [Паттернах JavaScript](/content/javascript/patterns). Новинки языка по редакциям — в [Современном JavaScript](/content/javascript/modern-js).

lodash по-прежнему полезен для редких вещей — `merge` с глубоким слиянием, `isEqual`, `get` по пути, — но берут его через `lodash-es`, иначе в бандл попадает весь пакет (подробно — во [Введении в экосистему](/content/ecosystem-libs/introduction)). Альтернатива с типами и современным API — es-toolkit.

## Глубокая копия

```js
class Money { constructor(v) { this.v = v; } format() { return `${this.v} ₽`; } }

const cart = { createdAt: new Date(), tags: new Set(['gift']), total: new Money(980) };
cart.self = cart;
```

Три способа ведут себя по-разному, все проверены:

| | `JSON.parse(JSON.stringify())` | `structuredClone` | `_.cloneDeep` |
| --- | --- | --- | --- |
| Цикл `cart.self` | `TypeError` | сохраняется | сохраняется |
| `Date` | превращается в строку | остаётся `Date` | остаётся `Date` |
| `Map`, `Set` | теряются | сохраняются | сохраняются |
| экземпляр класса | обычный объект | обычный объект, без методов | сохраняет прототип |
| функции | теряются | `DataCloneError` | копируются ссылкой |

Главная ловушка `structuredClone` — классы: после копии `total` — объект `{ v: 980 }`, и `total.format` — `undefined`. Алгоритм структурного копирования переносит данные, а не поведение: тот же, что используется в `postMessage` и IndexedDB. Для данных из API и состояния он идеален, для доменных объектов с методами — нет.

## Неизменяемые обновления

В React и Redux состояние обновляют без мутаций: новая версия объекта — новая ссылка, иначе изменение не заметят (подробно — в [Состоянии и событиях React](/content/reactjs/state-and-events)). Для глубоких структур это превращается в лестницу спредов:

```js
const next = {
  ...state,
  cart: { ...state.cart, items: state.cart.items.map((i, idx) => (idx === 0 ? { ...i, qty: i.qty + 1 } : i)) },
};
```

**Immer** позволяет писать мутации черновика, а возвращает новое состояние:

```js
import { produce } from 'immer';

const next = produce(state, (draft) => {
  draft.cart.items[0].qty++;
});
```

В проверке исходное состояние не изменилось, изменённая ветка `cart` стала новым объектом, неизменённая `user` осталась **той же ссылкой**, а результат заморожен, и случайная мутация бросит ошибку. Общие неизменённые ветки — это структурное разделение: сравнение по ссылке и мемоизация работают так же, как с ручными спредами. Immer встроен в Redux Toolkit, около 4 КБ gzip отдельно. Во Vue он не нужен: там состояние меняют напрямую.

## Даты

Форматирование дат по локали — `Intl.DateTimeFormat` и `Intl.RelativeTimeFormat`, без библиотек. `Date`, его ловушки и `Temporal` разобраны в [Современном JavaScript](/content/javascript/modern-js). Библиотеки нужны для арифметики и часовых поясов.

Почему арифметика — не умножение миллисекунд. В Берлине 29 марта 2026 года часы переводят на летнее время:

```js
const start = new Date(2026, 2, 28, 12, 0);              // 28 марта, 12:00
new Date(start.getTime() + 24 * 60 * 60 * 1000);          // 29 марта, 13:00
addDays(start, 1);                                        // 29 марта, 12:00
```

В проверке в часовом поясе Европы/Берлина «плюс 24 часа» дали 13:00, а `addDays` из `date-fns` — 12:00. В сутках перехода 23 часа, и «через день в то же время» — это не 24 часа. Срок доставки, напоминание, подписка — всё, что считается в днях, считают календарной арифметикой.

| Библиотека | gzip форматирования | Модель |
| --- | --- | --- |
| `date-fns` | ≈5 КБ | функции над обычным `Date`, вычищаются при сборке |
| `dayjs` | ≈3 КБ | обёртка с цепочками, плагины для поясов и локалей |
| `luxon` | больше | обёртка с поясами через `Intl` |
| `moment` | ≈20 КБ | режим поддержки, для новых проектов не берут |
| `Temporal` | 0 там, где встроен | стандарт: даты без времени, время, пояса, длительности |

Размеры — из проверки во [Введении в экосистему](/content/ecosystem-libs/introduction). Где `Temporal` уже доступен или подключён полифилом, он заменяет библиотеку целиком.

## HTTP-клиенты

`fetch` и `AbortController` закрывают большинство запросов (подробно — в [Загрузке данных](/content/network-api/fetching)). Главное, чем отличаются обёртки, — **обработка ошибочного статуса**. Проверено на локальном сервере, который отвечает 404:

| Клиент | На ответ 404 | Тело ошибки | gzip |
| --- | --- | --- | --- |
| `fetch` | **не бросает**, `res.ok === false` | разбирать самому | 0 |
| axios | бросает, `e.response.status` | `e.response.data` | ≈21 КБ |
| ky | бросает `HTTPError` | `e.response` | ≈10 КБ |
| ofetch | бросает `FetchError`, `e.status` | `e.data` уже разобран | ≈4 КБ |

`fetch` отклоняет промис только при сетевой ошибке или отмене. Ответ 404 или 500 — успешный ответ с точки зрения сети, и код без проверки `res.ok` примет страницу ошибки за данные. Обёртки добавляют ещё повторы, тайм-ауты, перехватчики, базовый адрес и разбор JSON.

Часто хватает своей обёртки на десяток строк:

```js
async function api(path, init) {
  const res = await fetch(`/api${path}`, { headers: { accept: 'application/json' }, ...init });
  if (!res.ok) throw Object.assign(new Error(`HTTP ${res.status}`), { status: res.status, body: await res.json().catch(() => null) });
  return res.json();
}
```

axios оправдан в старых проектах с перехватчиками и для прогресса загрузки файлов; в новых — ofetch, ky или своя обёртка. Генерация клиента из :term[OpenAPI]{def="формат описания REST API, по которому генерируют клиенты и типы"} — в [Клиентах API](/content/ecosystem-libs/realtime-and-api-clients).

## Мелочи

- **классы по условию** — `clsx` или его производная `cn` в shadcn/ui: `clsx('btn', { active, disabled }, size)` в проверке дал `'btn active lg'`, около 0,2 КБ;
- **короткие ID** — `nanoid`: 21 символ, безопасный для URL, около 0,2 КБ; для :term[UUID]{def="универсальный идентификатор из 128 бит; в версии 4 почти все биты случайные"} — `crypto.randomUUID()`;
- **деньги** — целые копейки или `Intl.NumberFormat` с `style: 'currency'` для вывода, а для точной десятичной арифметики — `decimal.js` или `big.js`;
- **сравнение и слияние** — `isEqual`, `merge` из `lodash-es` или es-toolkit, если они действительно нужны.

## Красные флаги в ответе

- **«lodash нужен в любом проекте».** Большая часть его функций уже есть в языке, а остальное берут из `lodash-es` по одной.
- **«`structuredClone` — полная замена `cloneDeep`».** Он не сохраняет прототипы классов и не копирует функции.
- **«Чтобы прибавить день, прибавь 24 часа».** В день перехода на летнее время сутки длиннее или короче.
- **«`fetch` бросит исключение на 404».** Он бросает только на сетевой ошибке, статус проверяют через `res.ok`.
- **«Immer копирует всё состояние».** Неизменённые ветки остаются теми же объектами.

## Как спрашивают на собеседовании

::question
Нужен ли lodash в 2026 году?

#answer
Чаще нет. `Object.groupBy`, `toSorted`, `findLast`, операции над `Set`, `structuredClone`, `Array.prototype.at` закрывают большую часть его использования, а `debounce` — несколько строк.

#more
Если нужны `merge`, `isEqual` или `get` по пути, берут `lodash-es` или es-toolkit: импорт из CommonJS-пакета `lodash` тянет весь пакет, около 25 КБ gzip ради одной функции. Новые проекты обычно обходятся без него.
::

::question
Чем structuredClone отличается от cloneDeep и JSON?

#answer
`structuredClone` копирует глубоко и сохраняет `Date`, `Map`, `Set`, типизированные массивы и циклы. JSON теряет даты, коллекции и падает на циклах. `cloneDeep` сохраняет прототипы классов.

#more
Ловушка `structuredClone` — экземпляр класса становится обычным объектом без методов, а функции вызывают `DataCloneError`. Это тот же алгоритм, что в `postMessage` и IndexedDB: копирует данные, а не поведение. Для состояния и ответов API он подходит идеально.
::

::question
Зачем Immer?

#answer
Чтобы писать неизменяемые обновления как обычные мутации черновика. `produce` возвращает новое состояние, где изменённые ветки — новые объекты, а неизменённые — те же ссылки.

#more
Структурное разделение сохраняет работу сравнения по ссылке и мемоизации. Результат заморожен, и случайная мутация бросит ошибку. Immer встроен в Redux Toolkit. Во Vue и с прокси-сторами он не нужен — там состояние меняют напрямую.
::

::question
Почему прибавить 24 часа — не то же, что прибавить день?

#answer
В дни перехода на летнее и зимнее время сутки длятся 23 или 25 часов. «Плюс 24 часа» от полудня перед переходом даст 13:00, а календарная арифметика — 12:00 следующего дня.

#more
Поэтому даты считают календарными функциями: `addDays` из `date-fns` или `Temporal`, где есть отдельные типы для даты без времени и для времени с поясом. Хранить и передавать — в UTC или ISO-строках с поясом, показывать — через `Intl` в поясе пользователя.
::

::question
Зачем axios, если есть fetch?

#answer
`fetch` встроен и закрывает большинство запросов, но не бросает исключение на ошибочный статус, не разбирает JSON сам и не умеет повторы и тайм-ауты без кода. axios, ky и ofetch добавляют это и бросают на 404 и 500.

#more
axios — самый тяжёлый, около 21 КБ gzip; ofetch — около 4 КБ. В новых проектах берут ofetch, ky или свою обёртку на десяток строк. axios остаётся в старом коде и там, где нужен прогресс загрузки через XHR.
::

## Практика

::practice{title="Ошибка сервера показана как товар"}
При падении API на странице товара появляется пустая карточка, а в консоли ничего:

```js
const product = await fetch(`/api/products/${id}`).then((r) => r.json());
render(product);
```

#solution
`fetch` вернул ответ 500 как успешный: промис отклоняется только при сетевой ошибке. `r.json()` разобрал тело ошибки, и оно ушло в отрисовку. Статус нужно проверять:

```js
async function getJson(url, init) {
  const res = await fetch(url, init);
  if (!res.ok) {
    const body = await res.json().catch(() => null);
    throw Object.assign(new Error(`HTTP ${res.status}`), { status: res.status, body });
  }
  return res.json();
}

const product = await getJson(`/api/products/${id}`);
```

Теперь ошибочный статус — исключение, которое ловят и показывают пользователю. Ту же семантику дают ofetch и ky. Данные с сервера стоит ещё и проверять схемой (подробно — в [Асинхронности и DOM в TypeScript](/content/typescript/async-and-dom)). В проверке `fetch` на 404 вернул ответ с `ok: false`, а axios, ky и ofetch бросили ошибку со статусом.
::

::practice{title="Корзина потеряла методы"}
После сохранения и восстановления черновика корзины падает `cart.total.format is not a function`:

```js
const draft = structuredClone(cart);   // cart.total — экземпляр класса Money
```

#solution
`structuredClone` копирует данные, а не поведение: экземпляр `Money` превратился в обычный объект `{ v: 980 }` без методов класса. Варианты:

```js
// 1. хранить данные, а поведение держать в функциях
const cart = { total: 980 };
const formatMoney = (v) => `${v} ₽`;

// 2. восстанавливать экземпляр после копии
const copy = structuredClone(cart);
copy.total = new Money(copy.total.v);
```

Состояние приложения удобнее держать простыми данными — их можно копировать, сериализовать, хранить в `localStorage` и передавать в воркер. Если нужна копия с прототипами, это `cloneDeep`, но такая структура уже не сериализуется без потерь. В проверке копия через `structuredClone` потеряла метод `format`, а `cloneDeep` его сохранил.
::
