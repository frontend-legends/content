# Визуализация данных

Графики, диаграммы, дашборды, 3D. Ключ к выбору - понять **спектр уровней абстракции**: от низкоуровневого D3, где ты рисуешь всё сам, до высокоуровневых библиотек, где график - это один компонент. Чем выше уровень, тем быстрее, но меньше контроля.

---

## Спектр абстракции

```
низкий уровень  ←—————————————————————————→  высокий уровень
D3.js        visx        ECharts        Recharts / Chart.js
(всё сам)   (примитивы)  (мощно)        (готовые графики)
больше контроля                         больше скорости
```

---

## D3.js

**D3** (Data-Driven Documents) - не библиотека графиков, а **низкоуровневый инструментарий** для привязки данных к DOM/SVG. Даёт полный контроль: шкалы, оси, проекции, переходы - но ты строишь визуализацию вручную.

```js
d3.select('svg').selectAll('rect')
  .data(values)
  .join('rect')
  .attr('height', (d) => scale(d)); // ты управляешь каждым элементом
```

<b class="text-on-semi-light">Когда D3</b> - <span class="text-gray">Кастомные, нестандартные визуализации, которых нет в готовых библиотеках. Высокий порог входа и много кода. Часто D3 используют не целиком, а точечно - его шкалы и геометрию (`d3-scale`, `d3-shape`) - внутри React-компонентов.</span>

> Важный нюанс с React: D3 хочет сам управлять DOM, а React тоже - это конфликт. Поэтому в React либо отдают D3 один SVG-узел через ref, либо используют только вычислительные модули D3, а рендерят сам React.

## Готовые графики

Когда нужны стандартные графики (линии, бары, пироги) - берут высокоуровневые библиотеки.

- **Chart.js** - простой, на canvas, основные типы графиков, быстрый старт. React-обёртка - `react-chartjs-2`.
- **Recharts** - **декларативный**, построен на React + D3: график собирается из компонентов (`<LineChart><Line/><XAxis/></LineChart>`). Популярнейший выбор в React за DX.
- **ECharts** (Apache) - очень мощный: десятки типов, canvas/SVG, хорошо тянет **большие датасеты**, богатые интерактивные дашборды.
- **Nivo**, **Victory** - наборы готовых React-компонентов-графиков.

```jsx
// Recharts - график как композиция компонентов
<LineChart data={data}>
  <XAxis dataKey="date" /><YAxis />
  <Line dataKey="value" />
</LineChart>;
```

| Библиотека | Уровень   | Рендер      | Когда                          |
| ---------- | --------- | ----------- | ------------------------------ |
| D3         | низкий    | SVG/Canvas  | кастомные визуализации          |
| visx       | низкий    | SVG (React) | свои графики на React-примитивах|
| Recharts   | высокий   | SVG         | стандартные графики в React     |
| Chart.js   | высокий   | Canvas      | простые графики быстро          |
| ECharts    | высокий   | Canvas/SVG  | большие данные, дашборды        |

## visx

**visx** (Airbnb) - золотая середина: **низкоуровневые React-примитивы** поверх D3 (шкалы, оси, формы). Ты собираешь свой график из React-компонентов, но не пишешь всё с нуля, как в D3. Для команд, которым нужны нестандартные графики, но в React-парадигме.

---

## SVG vs Canvas

Важный для собеса нюанс производительности:

- **SVG** (Recharts, D3 по умолчанию) - каждый элемент в DOM: легко стилизовать и навешивать события, но **тормозит на тысячах точек**.
- **Canvas** (Chart.js, ECharts) - рисует пиксели, нет DOM-узлов: **держит большие датасеты**, но интерактивность и стилизация сложнее.

<b class="text-on-semi-light">Правило</b> - <span class="text-gray">Мало элементов + нужна интерактивность/стили → SVG. Десятки тысяч точек → Canvas (или WebGL). Это частый вопрос «почему график тормозит».</span>

---

## 3D и WebGL

- **Three.js** - стандарт для 3D в браузере (WebGL): сцены, камеры, материалы, свет.
- **React Three Fiber (R3F)** - декларативная обёртка Three.js для React: 3D-сцена как дерево компонентов. С экосистемой `drei` (готовые хелперы).
- **Babylon.js** - альтернативный 3D-движок, ближе к игровым.

```jsx
// React Three Fiber - 3D как JSX
<Canvas><mesh><boxGeometry /><meshStandardMaterial /></mesh></Canvas>;
```

> Карты - смежная тема: **Leaflet**, **Mapbox GL**, **MapLibre** (open-source) для интерактивных карт.

---

## Как выбрать

```
Стандартные графики в React        → Recharts
Простые графики быстро             → Chart.js
Большие датасеты, дашборды         → ECharts
Кастомная визуализация             → D3 (или visx в React)
3D / WebGL                         → Three.js / React Three Fiber
Карты                              → Mapbox / MapLibre / Leaflet
```

## Вопросы на собеседовании

<b class="text-on-semi-light">Чем D3 отличается от Chart.js или Recharts?</b>
<span class="text-gray">D3 - низкоуровневый инструментарий: полный контроль, но всё рисуешь сам. Chart.js/Recharts - готовые графики из коробки: быстро, но меньше гибкости. D3 берут для нестандартных визуализаций.</span>

<b class="text-on-semi-light">Почему D3 и React конфликтуют?</b>
<span class="text-gray">Оба хотят управлять DOM. Решение - отдать D3 один SVG через ref, либо использовать только вычислительные модули D3 (шкалы, формы), а рендерить React.</span>

<b class="text-on-semi-light">SVG или Canvas для графика?</b>
<span class="text-gray">SVG - мало элементов, нужна интерактивность и стилизация (DOM-узлы). Canvas - большие датасеты (тысячи точек), где DOM не потянет. Это про производительность.</span>

<b class="text-on-semi-light">Что такое React Three Fiber?</b>
<span class="text-gray">Декларативная React-обёртка над Three.js: 3D-сцена описывается как дерево компонентов вместо императивного API.</span>

<b class="text-on-semi-light">Чем хорош Recharts в React?</b>
<span class="text-gray">Декларативный API - график собирается из компонентов, естественно ложится в React. Под капотом D3 для расчётов, рендер - SVG.</span>
