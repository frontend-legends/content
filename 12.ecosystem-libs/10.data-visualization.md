# Визуализация данных

Чем рисовать графики: D3 как набор математических модулей, готовые библиотеки графиков, обёртки для React и Vue, SVG против Canvas и WebGL — и как выбрать уровень абстракции. Спрашивают, чем D3 отличается от Chart.js, когда брать SVG, а когда Canvas, и как сделать график доступным. Глубже — почему D3 не обязательно управляет DOM, почему график на 20 000 точек в SVG тормозит и почему в Canvas нельзя просто повесить обработчик на точку.

::tldr
- **Библиотеки отличаются уровнем абстракции:** D3 — кирпичи для любых визуализаций, visx и Observable Plot — строительные блоки поверх них, Chart.js, ECharts и Recharts — готовые типы графиков из конфигурации.
- **D3 — в первую очередь математика:** шкалы переводят данные в пиксели и обратно, генераторы строят строки путей SVG. Отрисовку можно отдать React или Vue, а D3 оставить для расчётов.
- **SVG — элемент DOM на каждую фигуру:** удобно стилизовать, подписывать и вешать события, но тысячи элементов тормозят. Canvas рисует пиксели на одном холсте — быстро на десятках тысяч точек, но события и доступность приходится делать самому.
- **На сотнях тысяч точек и в 3D — WebGL:** deck.gl, regl, three.js, а некоторые библиотеки графиков сами переключаются на WebGL.
- **График — тоже интерфейс:** ему нужны подпись, текстовая альтернатива или таблица данных, цвета, различимые при нарушениях цветового зрения, и управление с клавиатуры.
::

## Уровни абстракции

Сквозной пример — график продаж магазина по дням и карта точек доставки.

| Уровень | Библиотеки | Что даёт | Цена |
| --- | --- | --- | --- |
| кирпичи | D3 | шкалы, оси, генераторы путей, раскладки, геопроекции | всё остальное — своими руками |
| блоки | visx (React), Observable Plot, Layer Cake (Svelte) | компоненты осей, сеток, фигур поверх D3 | меньше готовых графиков |
| готовые графики | Chart.js, ECharts, Recharts, ApexCharts, Highcharts | типы графиков из конфигурации, легенды, подсказки, анимации | нестандартное делается трудно или никак |
| быстрые | uPlot, ECharts в режиме WebGL | десятки и сотни тысяч точек | меньше гибкости |
| WebGL | deck.gl, three.js, regl | миллионы точек, карты, 3D | сложность, своя модель |

Для дашборда с линейными и столбчатыми графиками выигрывают готовые библиотеки. Для уникальной визуализации — блоки или D3.

## D3 — это математика

D3 известен как библиотека, которая сама создаёт и обновляет DOM через выборки. Но большая часть D3 — модули расчётов, которые к DOM отношения не имеют.

**Шкалы** переводят данные в пиксели:

```js
import { scaleLinear } from 'd3-scale';

const y = scaleLinear().domain([0, 480]).range([300, 0]).nice();
y.domain();   // [0, 500] — nice() округлил границу
y(250);       // 150 — пиксель для значения
y.invert(150);// 250 — значение под курсором
y.ticks(5);   // [0, 100, 200, 300, 400, 500] — деления оси
```

Все значения проверены. Шкалы бывают линейные, логарифмические, временные, категориальные (`scaleBand` для столбцов) и цветовые. `invert` нужен для подсказок: по координате мыши получить значение.

**Генераторы** строят строку пути:

```js
import { line, curveMonotoneX } from 'd3-shape';

const d = line().x((p) => x(p.day)).y((p) => y(p.sum)).curve(curveMonotoneX)(sales);
// 'M0,228C…' — готовый атрибут d для <path>
```

Отсюда главный приём для React и Vue: **D3 считает, фреймворк рисует**.

```jsx
<svg width={400} height={300}>
  <path d={line()(points)} fill="none" stroke="currentColor" />
  {y.ticks(5).map((t) => <text key={t} y={y(t)}>{t}</text>)}
</svg>
```

Фреймворк управляет DOM как обычно, без конфликта двух систем, которые одновременно меняют одни и те же узлы. Именно так устроены visx и многие обёртки.

### Размер

D3 — набор отдельных пакетов: `d3-scale`, `d3-shape`, `d3-array`, `d3-geo` и десятки других. В проверке шкалы и генератор пути заняли около 12 КБ gzip, а `import * as d3 from 'd3'` — около 91 КБ. Импортируют модули, которые нужны.

## SVG, Canvas и WebGL

**SVG** — каждая фигура — элемент DOM. **Canvas** — пиксели на одном холсте. Проверено в Chromium на 20 000 точек:

| | SVG | Canvas |
| --- | --- | --- |
| Узлы DOM | 20 000 | 1 |
| Время отрисовки | ≈34 мс и раскладка | ≈8 мс |
| Событие на точке | элемент под курсором — `circle` | только холст, точку нужно искать самому |
| Стили и подписи | CSS, `<title>`, ARIA | всё вручную |
| Чёткость при масштабе | вектор | зависит от размера холста и `devicePixelRatio` |

**SVG** удобен, пока элементов немного — сотни, низкие тысячи: стили из CSS, события на каждой фигуре, доступность через атрибуты, печать без потери качества. На десятках тысяч он упирается в DOM: каждый элемент — память, раскладка и отрисовка.

**Canvas** рисует быстро, но ничего не помнит: после отрисовки это картинка. Подсказка по наведению требует найти точку под курсором самому — перебором или пространственным индексом, например `d3-quadtree` или `d3-delaunay`. Доступность — отдельной таблицей или скрытым описанием. Для чёткости на экранах высокой плотности холст делают в `devicePixelRatio` раз больше и масштабируют.

**WebGL** рисует на видеокарте и справляется с сотнями тысяч и миллионами точек, картами и 3D: deck.gl для геоданных, three.js для 3D. Подробно о графике в браузере — в [Графике: Canvas и WebGL](/content/additional-topics/graphics-canvas-webgl).

Готовые библиотеки выбирают сами: Chart.js рисует на Canvas, Recharts — на SVG, ECharts умеет оба режима и WebGL.

## Доступность графиков

График без текста — пустое место для скринридера и для человека, который не различает цвета серии.

- **подпись и описание** — `role="img"` с `aria-label` для простого графика или `<figure>` с `<figcaption>`, где сказан главный вывод: «Продажи выросли в четыре раза за неделю»;
- **данные текстом** — таблица рядом или по кнопке «Показать данные»;
- **цвет — не единственный признак:** подписи серий прямо у линий, разные маркеры и штриховки, палитры, различимые при дальтонизме;
- **клавиатура** — для интерактивных графиков фокус на точках и подсказка по стрелкам;
- **движение** — анимации появления уважают `prefers-reduced-motion` (подробно — в [Анимациях](/content/ecosystem-libs/animation)).

Основы ARIA — в [Доступности](/content/html/accessibility).

## Как выбрать

| Задача | Выбор |
| --- | --- |
| дашборд со стандартными графиками | ECharts, Chart.js, Recharts, ApexCharts |
| свой дизайн графиков в React | visx или D3 для расчётов плюс SVG в JSX |
| исследовательская аналитика, быстрые графики по данным | Observable Plot |
| временные ряды на десятки тысяч точек, мониторинг | uPlot или Canvas вручную |
| уникальная визуализация, сложные раскладки, карты | D3 |
| миллионы точек, геоданные, 3D | deck.gl, three.js |

## Красные флаги в ответе

- **«D3 — это библиотека для работы с DOM».** Большая часть D3 — шкалы, генераторы и раскладки без DOM, рисовать может фреймворк.
- **«SVG подходит для любого объёма данных».** Каждая фигура — элемент DOM, и на десятках тысяч он тормозит.
- **«На Canvas можно повесить обработчик на точку».** Обработчик вешается только на холст, точку под курсором ищут сами.
- **«`import * as d3` — нормально».** Это около 90 КБ gzip, импортируют нужные модули.
- **«График не требует доступности».** Нужны подпись, данные текстом и цвета, различимые без цвета.

## Как спрашивают на собеседовании

::question
Чем D3 отличается от Chart.js?

#answer
D3 — набор низкоуровневых модулей: шкалы, оси, генераторы путей, раскладки, проекции. Из них можно собрать любую визуализацию, но легенды, подсказки и адаптивность — своими руками. Chart.js даёт готовые типы графиков из конфигурации и рисует на Canvas.

#more
Между ними — visx и Observable Plot: блоки поверх D3. В React и Vue D3 удобно использовать только для расчётов, а SVG рисовать компонентами — так нет конфликта двух систем управления DOM. Готовые библиотеки быстрее для стандартных графиков, D3 — для уникальных.
::

::question
Когда брать SVG, а когда Canvas?

#answer
SVG — когда элементов сотни или низкие тысячи и нужны стили из CSS, события на каждой фигуре, доступность и печать. Canvas — когда точек десятки тысяч: он рисует пиксели на одном холсте и не создаёт узлов DOM.

#more
На 20 000 точек SVG создал 20 000 элементов и рисовал в несколько раз дольше Canvas. Цена Canvas — события и доступность: точку под курсором ищут через `d3-quadtree` или `d3-delaunay`, подписи и таблицу данных делают отдельно. На сотнях тысяч точек и в 3D — WebGL.
::

::question
Как D3 работает вместе с React или Vue?

#answer
D3 считает, фреймворк рисует. Шкалы и генераторы путей дают числа и строки атрибутов, а SVG рендерится компонентами: `<path d={line()(points)} />`, деления оси из `scale.ticks()`.

#more
Если отдать D3 управление DOM внутри компонента через `ref`, две системы будут менять одни и те же узлы, и состояние разойдётся. Выборки D3 оставляют для сложных переходов и сторонних виджетов, изолированных в одном узле. Так устроены visx и многие обёртки.
::

::question
Как сделать график доступным?

#answer
Подписать его и сказать главный вывод текстом, дать данные таблицей, не кодировать смысл только цветом и для интерактивных графиков обеспечить управление с клавиатуры.

#more
Простой график — `role="img"` с `aria-label`, сложный — `<figure>` с `<figcaption>` и таблицей. Подписи серий у линий и разные маркеры помогают при нарушениях цветового зрения. Анимации появления уважают `prefers-reduced-motion`.
::

::question
Как отрисовать сотни тысяч точек?

#answer
Не через SVG. На десятках тысяч — Canvas или быстрые библиотеки вроде uPlot, на сотнях тысяч и миллионах — WebGL: deck.gl, regl, ECharts в режиме WebGL.

#more
Помогает и агрегация: показывать не все точки, а бины или прореживание по разрешению экрана — пикселей всё равно меньше, чем точек. Тяжёлые расчёты выносят в воркер, а на холст переносят через `OffscreenCanvas` (подробно — в [Web Workers и параллельности](/content/additional-topics/web-workers-and-concurrency)).
::

## Практика

::practice{title="График тормозит на 50 000 точек"}
График мониторинга нарисован в SVG компонентом React: на каждую точку — `<circle>`. На 50 000 точек вкладка подвисает при каждом обновлении данных.

#solution
50 000 элементов DOM — это память, раскладка и отрисовка на каждое обновление, плюс сравнение 50 000 элементов в React. Точки переносят на Canvas, а оси и подписи оставляют в SVG:

```jsx
function Points({ points, x, y }) {
  const ref = useRef(null);
  useEffect(() => {
    const canvas = ref.current;
    const dpr = window.devicePixelRatio || 1;
    canvas.width = 800 * dpr; canvas.height = 400 * dpr;
    const ctx = canvas.getContext('2d');
    ctx.scale(dpr, dpr);
    ctx.clearRect(0, 0, 800, 400);
    for (const p of points) { ctx.beginPath(); ctx.arc(x(p.t), y(p.v), 1.5, 0, Math.PI * 2); ctx.fill(); }
  }, [points, x, y]);
  return <canvas ref={ref} style={{ width: 800, height: 400 }} />;
}
```

Подсказку по наведению делают поиском ближайшей точки через `d3-quadtree` по координате мыши. Если точек сотни тысяч — uPlot или WebGL. В проверке 20 000 точек в SVG дали 20 000 узлов и рисовались в несколько раз дольше, чем на Canvas.
::

::practice{title="Ось с некрасивыми делениями"}
Деления оси графика продаж посчитаны вручную — максимум, делённый на пять: `0, 96, 192, 288, 384, 480`. Подписи читаются плохо, а верхняя точка упирается в край.

```js
const step = maxSum / 5;
const ticks = Array.from({ length: 6 }, (_, i) => i * step);
```

#solution
Деление максимума на равные части даёт неудобные числа, а домен ровно по максимуму прижимает верхнюю точку к краю. Шкала умеет и то, и другое: `nice()` расширяет домен до округлых границ, а `ticks()` подбирает удобные деления:

```js
const y = scaleLinear()
  .domain([0, max(sales, (d) => d.sum)])   // [0, 480]
  .range([300, 0])
  .nice();                                  // [0, 500]

y.ticks(5);   // [0, 100, 200, 300, 400, 500]
```

Верхняя точка больше не касается края, а деления читаются. Форматирование подписей — через `Intl.NumberFormat` для денег и процентов. В проверке `nice()` превратил домен `[0, 480]` в `[0, 500]`, а `ticks(5)` дал шесть округлых значений.
::
