# Мета-фреймворки

**Мета-фреймворк** - это фреймворк поверх библиотеки UI (React, Vue), добавляющий то, чего в ней нет: роутинг, серверный рендеринг, сборку, загрузку данных, деплой. React - это «всего лишь UI», и в проде его почти всегда используют через мета-фреймворк.

---

## Зачем они нужны

Чистый React не даёт ни роутинга, ни SSR, ни конвенций загрузки данных - всё это надо собирать самому из разрозненных пакетов. Мета-фреймворк даёт **интегрированное решение**:

- файловый или конфигурируемый **роутинг**;
- **стратегии рендеринга** (SSR/SSG/ISR/RSC) из коробки;
- **загрузку данных** на сервере (loaders, server components);
- **сборку и оптимизацию** (код-сплиттинг, изображения, бандл);
- **серверную часть** (API-роуты, server actions) и деплой.

Подробно о самих стратегиях рендеринга - в [рендеринге и гидратации](/content/reactjs/rendering-and-hydration).

---

## Next.js

Доминирующий мета-фреймворк для React (от Vercel).

- **App Router** (современный) - построен на **React Server Components**, server actions, вложенные layout'ы, стриминг. Рекомендуемый путь.
- **Pages Router** (классический) - предыдущая модель (`getServerSideProps`/`getStaticProps`); всё ещё поддерживается, много проектов на нём.
- Гибкий рендеринг **на уровне страницы**: статика, SSR, ISR.
- Встроенные оптимизации: `next/image`, шрифты, код-сплиттинг.

```jsx
// app/users/[id]/page.tsx - серверный компонент, данные грузятся на сервере
export default async function User({ params }) {
  const user = await db.users.find(params.id); // прямой доступ к данным
  return <h1>{user.name}</h1>;
}
```

> Next - дефолт для большинства новых React-приложений, особенно если нужен SSR/SEO. Минусы: завязка на модель Vercel, сложность App Router, быстрая смена рекомендаций.

## Remix / React Router 7

**Remix** - мета-фреймворк с упором на **веб-стандарты** (Web Fetch API, формы, прогрессивное улучшение) и вложенные маршруты с `loader`/`action` для данных. В 2024–2025 Remix **слился с React Router**: его возможности вошли в **React Router 7**, который теперь работает и как библиотека роутинга, и как фреймворк.

```jsx
export async function loader({ params }) {     // данные грузятся до рендера
  return getUser(params.id);
}
export default function User() {
  const user = useLoaderData();
}
```

> Философия Remix - меньше клиентского JS, больше платформы (формы работают без JS). Хороший выбор, когда важны веб-стандарты и прогрессивное улучшение.

## Astro

Мета-фреймворк, заточенный под **контентные сайты** (блоги, доки, маркетинг). Ключевая идея - **ноль JS по умолчанию**: страницы рендерятся в статический HTML, а интерактивность добавляется **островами**.

```astro
---
const posts = await getPosts(); // выполняется на сборке/сервере
---
<ul>{posts.map((p) => <li>{p.title}</li>)}</ul>
<SearchWidget client:load />  <!-- остров: гидратируется только этот компонент -->
```

<b class="text-on-semi-light">Чем уникален</b> - <span class="text-gray">Astro **агностичен к фреймворку**: на одной странице можно смешать React, Vue и Svelte-компоненты. Отправляет минимум JS (только острова), поэтому контентные сайты на нём очень быстрые. Для тяжёлых интерактивных приложений - не его ниша.</span>

---

## Другие

- **Nuxt** - мета-фреймворк для Vue: файловый роутинг, SSR/SSG/гибрид, `useFetch`, Nitro-сервер (см. [рендеринг и Nuxt](/content/vuejs/rendering-and-nuxt)).
- **SvelteKit** - официальный фреймворк Svelte.
- **SolidStart** - для Solid.js.
- **TanStack Start** - новый, типобезопасный, на базе TanStack Router; полный SSR с акцентом на типы.
- **Qwik (City)** - фокус на «resumability» вместо гидратации - минимальный JS при загрузке.

## Сравнение

| Фреймворк      | UI        | Сильная сторона                    |
| -------------- | --------- | ---------------------------------- |
| Next.js        | React     | RSC, экосистема, дефолт для апп     |
| React Router 7 | React     | веб-стандарты, гибкость (ex-Remix)  |
| Astro          | любой     | контент, ноль JS, острова          |
| Nuxt           | Vue       | DX, гибридный рендеринг             |
| SvelteKit      | Svelte    | компактность, скорость             |
| TanStack Start | React     | типобезопасность                   |

---

## Как выбрать

```
React-приложение с SSR/SEO        → Next.js (App Router)
Веб-стандарты, прогрессивное улучшение → React Router 7 (Remix)
Блог / доки / маркетинг            → Astro
Vue                                → Nuxt
Максимальная типобезопасность       → TanStack Start
SPA без SSR                         → чистый Vite + роутер (без мета-фреймворка)
```

> Не каждому проекту нужен мета-фреймворк. Внутренний дашборд за логином без SEO прекрасно живёт на Vite + React Router как SPA.

## Вопросы на собеседовании

<b class="text-on-semi-light">Что такое мета-фреймворк и зачем он нужен?</b>
<span class="text-gray">Фреймворк поверх UI-библиотеки, добавляющий роутинг, SSR, загрузку данных, сборку и деплой. React - только UI, в проде его используют через мета-фреймворк.</span>

<b class="text-on-semi-light">Чем App Router отличается от Pages Router в Next.js?</b>
<span class="text-gray">App Router построен на серверных компонентах, server actions, вложенных layout'ах и стриминге - современный путь. Pages Router - классическая модель с getServerSideProps/getStaticProps.</span>

<b class="text-on-semi-light">Что особенного в Astro?</b>
<span class="text-gray">Ноль JS по умолчанию: статический HTML + острова интерактивности. Агностичен к фреймворку (React/Vue/Svelte вместе). Идеален для контентных сайтов, не для тяжёлых приложений.</span>

<b class="text-on-semi-light">Что случилось с Remix?</b>
<span class="text-gray">Remix слился с React Router: его возможности (loaders/actions, веб-стандарты) вошли в React Router 7, который теперь и библиотека роутинга, и фреймворк.</span>

<b class="text-on-semi-light">Всегда ли нужен мета-фреймворк?</b>
<span class="text-gray">Нет. SPA за логином без SEO отлично работает на Vite + роутер. Мета-фреймворк нужен ради SSR/SEO, серверной загрузки и интегрированных конвенций.</span>

<b class="text-on-semi-light">Какой выбрать для контентного сайта и почему?</b>
<span class="text-gray">Astro - отправляет минимум JS (острова), быстрый, удобен для контента. Next тоже умеет SSG, но Astro легче по клиентскому коду.</span>
