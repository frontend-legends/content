# Контент и взаимодействия

Редакторы текста, рендеринг markdown, подсветка кода, drag-and-drop, загрузка файлов. Объединяет их одно: это **сложные взаимодействия**, которые почти невозможно сделать правильно с нуля. Здесь особенно важно знать, какую категорию библиотек брать.

---

## Редакторы форматированного текста

Самая коварная задача фронтенда. Нативный `contenteditable` печально известен непредсказуемостью: разные браузеры по-разному вставляют HTML, ломают undo, путают выделение. Поэтому богатый редактор **всегда** строят на библиотеке, которая управляет своей моделью документа поверх `contenteditable`.

- **ProseMirror** - низкоуровневый, мощный «движок» с собственной моделью документа и схемой. Основа для многих редакторов; высокий порог входа.
- **TipTap** - **headless**-редактор поверх ProseMirror: даёт расширения и API, стили твои. Самый популярный современный выбор.
- **Lexical** - от Meta: современный, производительный, расширяемый, хорошая a11y. Растущая альтернатива ProseMirror.
- **Slate** - кастомизируемый редактор для React с моделью на основе React-дерева.
- **Editor.js** - **блочный** редактор (как Notion): документ из блоков, выдаёт JSON.
- **Quill**, **CKEditor**, **TinyMCE** - классические «коробочные» WYSIWYG с готовым UI.

<b class="text-on-semi-light">Как выбирать</b> - <span class="text-gray">Нужен полный контроль и свой UI - TipTap (на ProseMirror) или Lexical. Нужен готовый WYSIWYG быстро - Quill/CKEditor. Блочный «notion-like» опыт - Editor.js. Писать на голом `contenteditable` - почти всегда ошибка.</span>

## Markdown

Отрисовка markdown в HTML - частая задача (комментарии, доки, контент).

- **react-markdown** - рендерит markdown в React-компоненты (не через `innerHTML`), на экосистеме **remark/rehype** (плагины: GFM, подсветка, сноски).
- **markdown-it**, **marked** - быстрые парсеры markdown → HTML (фреймворк-агностичные).
- **MDX** - markdown с **встроенным JSX**: можно использовать React-компоненты прямо в тексте. Стандарт для документации и контентных сайтов.

<b class="text-on-semi-light">Не забудь про безопасность</b> - <span class="text-gray">Markdown может содержать сырой HTML и `javascript:`-ссылки. Если источник - пользователь, **санитизируй** результат (DOMPurify / rehype-sanitize), иначе получишь XSS (см. [безопасность React](/content/reactjs/security)). `react-markdown` безопаснее, чем `dangerouslySetInnerHTML` с `marked`.</span>

## Подсветка синтаксиса

- **Shiki** - использует движок и темы VS Code (TextMate-грамматики): максимально точная подсветка, может работать на этапе сборки/сервера (отлично для RSC и статики).
- **Prism**, **highlight.js** - классические, лёгкие, рантайм-подсветка в браузере.

> Shiki стал предпочтительным для статического контента и документации в 2025–2026 за качество и серверный рендер.

## Drag and drop

Перетаскивание - ещё одна задача со скрытой сложностью (a11y, сенсорные экраны, автоскролл, анимация).

- **dnd-kit** - современный, лёгкий, **доступный** (клавиатура, скринридеры), модульный. Предпочтительный выбор для React.
- **Pragmatic drag and drop** (Atlassian) - на нативном HTML5 DnD, производительный, фреймворк-агностичный.
- **react-dnd** - зрелый, на HTML5-backend; мощный, но тяжелее.
- **SortableJS** - простая сортировка списков, фреймворк-агностичная (есть Vue/React-обёртки).

<b class="text-on-semi-light">Почему не нативный DnD</b> - <span class="text-gray">Нативный HTML5 Drag and Drop капризен, плохо работает на тач-устройствах и недоступен с клавиатуры. Библиотеки вроде dnd-kit решают доступность и сенсорный ввод - то, что почти невозможно дописать самому корректно.</span>

---

## Загрузка файлов

- **react-dropzone** - drag-and-drop зона загрузки, простая.
- **Uppy** - полноценный аплоадер: прогресс, возобновление (tus), источники (Dropbox, камера), плагины. Для серьёзной загрузки.
- **FilePond** - красивый аплоадер с превью и обработкой.

---

## Как выбрать

```
Богатый редактор, свой UI            → TipTap / Lexical
Готовый WYSIWYG быстро               → Quill / CKEditor
Блочный «notion-like»                → Editor.js
Markdown в React                     → react-markdown (+ санитизация)
Markdown + компоненты (доки)         → MDX
Подсветка кода (статика/RSC)         → Shiki
Drag-and-drop с a11y                 → dnd-kit
Серьёзная загрузка файлов            → Uppy
```

## Вопросы на собеседовании

<b class="text-on-semi-light">Почему богатый текстовый редактор не пишут на contenteditable?</b>
<span class="text-gray">`contenteditable` непредсказуем между браузерами (вставка HTML, undo, выделение). Библиотеки (ProseMirror, Lexical) держат свою модель документа поверх него и дают надёжность.</span>

<b class="text-on-semi-light">Чем TipTap отличается от ProseMirror?</b>
<span class="text-gray">TipTap - headless-обёртка над ProseMirror: удобный API и расширения, стили твои. ProseMirror - низкоуровневый движок, на котором TipTap построен.</span>

<b class="text-on-semi-light">Какой риск при рендеринге пользовательского markdown?</b>
<span class="text-gray">XSS: markdown может содержать сырой HTML и javascript:-ссылки. Нужно санитизировать (rehype-sanitize/DOMPurify); react-markdown безопаснее, чем innerHTML с marked.</span>

<b class="text-on-semi-light">Что такое MDX?</b>
<span class="text-gray">Markdown с возможностью использовать JSX/React-компоненты прямо в тексте. Стандарт для документации и контентных сайтов.</span>

<b class="text-on-semi-light">Почему для drag-and-drop берут dnd-kit, а не нативный API?</b>
<span class="text-gray">Нативный HTML5 DnD капризен, плох на тач-устройствах и недоступен с клавиатуры. dnd-kit решает доступность, сенсорный ввод и автоскролл.</span>
