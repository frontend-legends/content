# Контент и взаимодействия

Библиотеки для сложного контента и взаимодействий: редакторы форматированного текста на ProseMirror и Lexical, отрисовка markdown и MDX, подсветка кода, перетаскивание и загрузка файлов. Спрашивают, почему редактор не пишут на `contenteditable`, чем опасен пользовательский markdown и почему для перетаскивания берут библиотеку. Глубже — какие markdown-библиотеки пропускают `<script>` и `javascript:`-ссылки, почему Shiki не нужен в браузере и почему тип файла нельзя проверять по имени.

::tldr
- **Редактор не пишут на голом `contenteditable`:** браузеры по-разному вставляют и правят разметку. ProseMirror, TipTap и Lexical держат свою модель документа по схеме и сами рисуют её в DOM.
- **Схема редактора — ещё и фильтр:** что в ней не описано, при вставке отбрасывается. Документ хранят как JSON, а не как HTML.
- **Пользовательский markdown — путь к XSS:** marked пропускает сырой HTML и `javascript:`-ссылки, markdown-it и react-markdown по умолчанию нет. Если HTML включён — нужен санитайзер.
- **Shiki подсвечивает при сборке или на сервере,** отдавая HTML с цветами внутри; Prism и highlight.js работают в браузере и красят классами по CSS-теме.
- **Перетаскивание и загрузка — библиотекой:** dnd-kit добавляет клавиатуру и объявления для скринридера, которых нет у нативного API, а Uppy — возобновляемую загрузку частями.
::

## Редакторы форматированного текста

Сквозной пример — админка магазина: описание товара в редакторе с форматированием, отзывы покупателей в markdown, документация API с примерами кода, сортировка товаров на витрине перетаскиванием и загрузка фотографий.

### Почему не `contenteditable`

`contenteditable` превращает элемент в редактируемый, но результат — произвольный HTML, который каждый браузер создаёт по-своему: перенос строки даёт `<div>`, `<p>` или `<br>`, жирный — `<b>` или `<strong>`, вставка из Word приносит стили и мусорные теги. Выделение, отмена и составной ввод — китайский или японский с подтверждением слова — работают по-разному.

Поэтому редакторы используют `contenteditable` только как поверхность для ввода, а документ держат **в своей модели**:

```text
ввод пользователя → транзакция → новая модель документа → редактор перерисовывает DOM
```

### ProseMirror и TipTap

**ProseMirror** — движок с моделью документа по **схеме**: какие узлы бывают (абзац, заголовок, список), какие на них метки (жирный, ссылка) и что может быть внутри чего. **TipTap** — headless-обёртка над ProseMirror: расширения, команды и адаптеры для React и Vue, а интерфейс и стили — свои.

В проверке TipTap со стандартным набором расширений разобрал вставку с картинкой с `onerror`, `<script>`, `onclick`, `javascript:`-ссылкой и `<div>`:

```js
editor.getHTML();
// '<p>Привет <strong>мир</strong> красный ссылка <a … href="https://shop.example">магазин</a></p><p>блок</p>'
```

Картинки нет в схеме, скрипта и обработчиков тоже — они отброшены. Ссылка с `javascript:` осталась текстом, с `https:` — ссылкой, `<b>` стал `<strong>`, а `<div>` — абзацем. Документ — данные:

```json
{ "type": "text", "marks": [{ "type": "bold" }], "text": "мир" }
```

JSON хранят в базе, а HTML строят при показе. Схема гарантирует структуру, но не заменяет проверку на сервере: запрос можно отправить в обход редактора.

### Другие редакторы

- **Lexical** от Meta — своя модель и состояние, без ProseMirror, расширяется узлами и плагинами.
- **Slate** — модель на простых объектах для React, гибкий, но многое делается вручную.
- **BlockNote**, **Editor.js** — блочные редакторы, как в Notion: документ из блоков, перетаскивание блоков, меню по `/`.
- **CKEditor**, **TinyMCE**, **Quill** — готовые редакторы с панелью инструментов; у CKEditor и TinyMCE часть функций платная.

Для совместного редактирования к ProseMirror, TipTap и Lexical подключают Yjs — слияние правок через CRDT (подробно — в [Реалтайме и API-клиентах](/content/ecosystem-libs/realtime-and-api-clients)).

## Markdown

### Парсеры и XSS

Markdown разрешает вставлять сырой HTML, а ссылка может вести на `javascript:`. Если текст пишет пользователь, это прямой путь к XSS (что это и чем опасно — в [XSS](/content/security-perfomance/xss)). Библиотеки ведут себя по-разному — в проверке одна и та же строка:

```md
Привет **мир** <img src=x onerror="alert(1)"> [клик](javascript:alert(1)) <script>alert(2)</script>
```

| Библиотека | Сырой HTML | `javascript:`-ссылка |
| --- | --- | --- |
| marked | пропускает как есть | делает ссылкой |
| markdown-it | экранирует, с `html: true` пропускает | не делает ссылкой |
| react-markdown | показывает как текст | вычищает адрес |
| react-markdown с `rehype-raw` | `<script>` попадает в разметку | вычищает адрес |

Если HTML нужен или парсер его пропускает, результат прогоняют через санитайзер:

```js
import DOMPurify from 'dompurify';

const html = DOMPurify.sanitize(marked.parse(comment));
// '<p>Привет <strong>мир</strong> <img src="x"> <a>клик</a> </p>'
```

Для react-markdown — `rehype-sanitize` после `rehype-raw`: в проверке `<script>`, `onerror` и `javascript:` исчезли, а форматирование осталось. Санитайзер ставят последним, после плагинов, которые могут добавить опасное.

### MDX

**MDX** — markdown, в котором можно использовать JSX-компоненты:

```md
# Оплата

<PaymentDemo amount={1200} />

Подробнее — в разделе про возвраты.
```

MDX компилируется в JavaScript и выполняется как код, поэтому его пишут авторы документации, а не пользователи. Стандарт для документации и контентных сайтов: Next.js, Astro, Docusaurus, Nextra.

## Подсветка кода

| | Shiki | Prism, highlight.js |
| --- | --- | --- |
| Где работает | при сборке или на сервере | в браузере |
| Результат | HTML с цветами в `style` | HTML с классами |
| Грамматики | TextMate, как в VS Code | свои, на регулярных выражениях |
| В браузере нужно | ничего | библиотека и CSS-тема |

В проверке Shiki вернул готовую разметку с цветами:

```html
<pre class="shiki github-light" style="background-color:#fff;color:#24292e"><code>
  <span style="color:#D73A49">const</span><span style="color:#005CC5"> a</span>…
```

А highlight.js — только классы, цвета которым даёт подключённая тема:

```html
<span class="hljs-keyword">const</span> a = <span class="hljs-number">1</span>
```

Shiki тяжёлый — грамматики и движок регулярных выражений — и точный, поэтому его запускают там, где размер не важен: при сборке статики, в серверных компонентах, в MDX-плагине. Для кода, который появляется в браузере на лету, — например, в чате — остаются Prism, highlight.js или Shiki с ленивой загрузкой нужных языков.

## Перетаскивание

### Что не так с нативным API

У HTML Drag and Drop API — атрибут `draggable` и события `dragstart`, `dragover`, `drop` — три проблемы:

- **клавиатура:** перетаскивание работает только мышью, а сам элемент с `draggable` не получает фокус — в проверке `tabIndex` был `-1`;
- **сенсорные экраны:** на мобильных браузерах поддержка неполная и ведёт себя по-разному;
- **оформление:** перетаскиваемый «призрак» рисует браузер, автопрокрутку и анимацию перестановки нужно писать самим.

### dnd-kit и другие

**dnd-kit** работает на событиях указателя и клавиатуры, а не на нативном API. В проверке перетаскиваемый элемент получил `role="button"`, `tabindex="0"` и описание с подсказкой про пробел, а с клавиатуры:

```text
Пробел   → onDragStart, скринридер слышит «Picked up draggable item card-1.»
Стрелки  → перемещение
Пробел   → onDragEnd,   «Draggable item card-1 was dropped.»
```

Объявления идут через live-регион с `aria-live` и переводятся своими строками. Для сортировки списков — пакет `@dnd-kit/sortable`.

Другие библиотеки:

- **Pragmatic drag and drop** от Atlassian — поверх нативного API, маленький, без привязки к фреймворку, доступность — отдельными пакетами;
- **SortableJS** и обёртки `vuedraggable` или `vue-draggable-plus` — простая сортировка списков, популярна во Vue;
- **react-dnd** — зрелая, но тяжелее и сложнее, новых проектов на ней мало.

Перетаскивание не должно быть единственным способом: у сортировки оставляют кнопки «вверх» и «вниз» или меню «переместить» (подробно о доступности — в [Доступности](/content/html/accessibility)).

## Загрузка файлов

Простая загрузка — `<input type="file">` и `FormData`. Библиотеки добавляют остальное:

- **react-dropzone** — зона перетаскивания файлов и проверка типа и размера;
- **Uppy** — загрузчик с прогрессом, превью, источниками вроде камеры и Google Drive и возобновляемой загрузкой по протоколу tus;
- **FilePond** — загрузчик с превью и обработкой изображений.

### Что важно знать

- **Прогресс отправки** даёт `XMLHttpRequest` через `upload.onprogress` — у `fetch` прогресса отправки нет (подробно — в [Утилитах](/content/ecosystem-libs/utility-libraries)).
- **Большие файлы** режут на части через `Blob.slice` и отправляют по одной: при обрыве продолжают с последней дошедшей. В проверке 12 МБ кусками по 5 МБ дали три запроса, последний — 2 МБ. Так работает tus.
- **Превью** без загрузки — `URL.createObjectURL(file)`, адрес вида `blob:…`, который потом освобождают `URL.revokeObjectURL`.
- **Тип файла** по имени и атрибуту `accept` — только подсказка выбору файлов. Настоящую проверку делает сервер, а на клиенте можно посмотреть первые байты:

```js
const head = new Uint8Array(await file.slice(0, 8).arrayBuffer());
// PNG начинается с 89 50 4E 47 0D 0A 1A 0A
```

В проверке файл `photo.png` с HTML внутри сигнатуру не прошёл.

- **Прямая загрузка в хранилище:** сервер выдаёт подписанный адрес S3 или аналога, и браузер отправляет файл туда, минуя свой бэкенд.

| Задача | Выбор |

| большие файлы и возобновление | Uppy с tus |

## Красные флаги в ответе

- **«Сделаю редактор на `contenteditable`».** Получится браузерозависимый HTML, сломанная отмена и выделение.
- **«Сохраню HTML из редактора и покажу как есть».** Запрос можно отправить в обход редактора — нужна санитизация при показе или JSON по схеме.
- **«Markdown безопасен, это же не HTML».** Он разрешает сырой HTML и `javascript:`-ссылки, marked пропускает их как есть.
- **«MDX для комментариев пользователей».** MDX выполняется как код.
- **«Нативный drag and drop достаточно».** Он не работает с клавиатуры и капризен на сенсорных экранах.
- **«Проверю тип файла по расширению».** Расширение и `accept` — подсказки, проверяет сервер.

## Как спрашивают на собеседовании

::question
Почему богатый текстовый редактор не пишут на `contenteditable`?

#answer
Браузеры по-разному создают и правят разметку в `contenteditable`: переносы строк, форматирование, вставка из других программ, отмена, выделение и составной ввод работают по-разному. Библиотеки — ProseMirror, TipTap, Lexical — держат свою модель документа и сами рисуют её в DOM.

#more
Модель описывается схемой: что не описано, при вставке отбрасывается. Документ хранят как JSON, изменения — транзакции, на них строятся своя история отмены и совместное редактирование через Yjs.
::

::question
Чем TipTap отличается от ProseMirror?

#answer
ProseMirror — низкоуровневый движок: схема, модель документа, транзакции, отображение. TipTap построен на нём и даёт готовые расширения, команды вроде `toggleBold` и адаптеры для React и Vue, оставаясь headless — интерфейс и стили свои.

#more
Внутри TipTap всё ещё ProseMirror, и к нему можно спуститься за плагинами и схемой. Альтернатива на своём движке — Lexical от Meta.
::

::question
Какой риск при отображении пользовательского markdown?

#answer
XSS: markdown разрешает сырой HTML и ссылки на `javascript:`. marked пропускает их как есть, поэтому его вывод нужно прогонять через DOMPurify. markdown-it по умолчанию экранирует HTML, react-markdown показывает его как текст и вычищает опасные адреса.

#more
Включение HTML — `html: true` в markdown-it или `rehype-raw` в react-markdown — возвращает риск, и после него ставят `rehype-sanitize` или DOMPurify. Санитайзер идёт последним, после всех плагинов. Дополнительно страхует Content Security Policy.
::

::question
Что такое MDX?

#answer
Markdown, в котором можно использовать JSX-компоненты: интерактивные примеры, предупреждения, вкладки прямо в тексте. Он компилируется в JavaScript-модуль.

#more
Поскольку MDX выполняется как код, его пишут авторы, а не пользователи. Стандарт для документации: Next.js, Astro, Docusaurus, Nextra; подсветку кода в нём обычно делает Shiki при сборке.
::

::question
Почему для перетаскивания берут dnd-kit, а не нативный API?

#answer
Нативный Drag and Drop API работает только мышью, элемент с `draggable` не получает фокус, на сенсорных экранах поддержка неполная, а призрак, автопрокрутку и анимацию приходится делать самим. dnd-kit работает на событиях указателя и клавиатуры и объявляет действия скринридеру.

#more
С dnd-kit элемент становится кнопкой с фокусом, перетаскивается пробелом и стрелками, а live-регион сообщает «поднят» и «отпущен». Перетаскивание всё равно не должно быть единственным способом — нужны кнопки или меню перемещения.
::

::question
Чем Shiki отличается от Prism и highlight.js?

#answer
Shiki использует грамматики и темы VS Code и обычно работает при сборке или на сервере, отдавая HTML с цветами прямо в `style` — в браузере ничего не нужно. Prism и highlight.js работают в браузере и расставляют классы, а цвета даёт CSS-тема.

#more
Shiki точнее, но тяжелее, поэтому в браузере его грузят лениво и только с нужными языками. Для кода, появляющегося на лету, — в чате или редакторе — часто проще Prism или highlight.js.
::

## Практика

::practice{title="Отзывы с картинками-сюрпризами"}
Отзывы покупателей пишутся в markdown и показываются так:

```jsx
<div dangerouslySetInnerHTML={{ __html: marked.parse(review.text) }} />
```

Один отзыв при открытии карточки показывает `alert`.

#solution
marked пропускает сырой HTML и `javascript:`-ссылки как есть: в проверке `<img onerror>`, `<script>` и `href="javascript:…"` дошли до разметки. Варианты:

```jsx
// 1. парсер, который не пропускает HTML
<Markdown>{review.text}</Markdown>

// 2. если HTML нужен — санитайзер последним
<Markdown rehypePlugins={[rehypeRaw, rehypeSanitize]}>{review.text}</Markdown>

// 3. оставить marked, но очистить результат
<div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(marked.parse(review.text)) }} />
```

В проверке react-markdown показал HTML как текст и вычистил адрес, а DOMPurify оставил `<strong>` и убрал `onerror`, скрипт и `javascript:`. Подробно о `dangerouslySetInnerHTML` — в [Безопасности React](/content/reactjs/security).
::

::practice{title="Описание товара с мусором из Word"}
Менеджеры копируют описания из Word в редактор на `contenteditable`. В базе — HTML со шрифтами, стилями, `<span>` в несколько слоёв и иногда `onclick` из сторонних источников. На витрине вёрстка разъезжается.

#solution
`contenteditable` сохраняет всё, что вставили. Редактор со схемой оставит только описанное:

```js
const editor = new Editor({
  element,
  extensions: [StarterKit],
  content: pastedHtml,
});

editor.getJSON();   // документ по схеме — его и хранят
```

В проверке TipTap отбросил картинку с `onerror`, `<script>`, `onclick` и стиль, превратил `<b>` в `<strong>`, а `<div>` в абзац. Хранить лучше JSON и строить HTML при показе, а на сервере проверять документ или санитизировать HTML — запрос можно отправить в обход редактора.
::

::practice{title="Загрузка фотографий обрывается"}
Продавцы загружают фотографии товаров по 30–50 МБ через мобильный интернет. При обрыве загрузка начинается заново, а иногда вместо фото приходит не тот файл.

#solution
Две проблемы. Первая — загрузка одним запросом: файл режут на части и отправляют по одной, запоминая, сколько дошло:

```js
const CHUNK = 5 * 1024 * 1024;
for (let offset = uploaded; offset < file.size; offset += CHUNK) {
  await sendChunk(file.slice(offset, offset + CHUNK), offset);
}
```

Готовое решение — Uppy с протоколом tus, который хранит смещение на сервере и продолжает с него. Вторая — тип по имени: проверяют сигнатуру первых байтов и на сервере — повторно. В проверке 12 МБ разрезались на 5, 5 и 2 МБ, а `photo.png` с HTML внутри сигнатуру PNG не прошёл.
::
