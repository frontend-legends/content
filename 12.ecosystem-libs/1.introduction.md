# Введение в экосистему

Вводная история главы: как решать, писать самому или брать библиотеку, по каким признакам сравнивать кандидатов и сколько на самом деле стоит зависимость — в килобайтах, транзитивных пакетах и обязательствах. Спрашивают, как ты выбираешь библиотеку и когда лучше написать самому. Глубже — почему одна функция из пакета весит 25 КБ, сколько пакетов приходит вместе с одним и что делать, когда экосистема меняется быстрее, чем успеваешь её выучить.

::tldr
- **Зависимость — обязательство, а не подарок:** её обновляют, проверяют на уязвимости, чинят при поломке и тянут в каждый бандл. Брать стоит то, что сложно сделать хорошо: доступный выпадающий список, редактор текста, виртуализацию, даты с часовыми поясами.
- **Цена в бандле зависит от формата пакета больше, чем от его функций:** `debounce` из CommonJS-пакета `lodash` весит около 25 КБ gzip, тот же `debounce` из ESM-пакета `lodash-es` — около 1 КБ.
- **Часто правильная библиотека — платформа:** `Intl` форматирует даты и числа без единого килобайта, `structuredClone` копирует глубоко, `fetch` и `AbortController` закрывают большинство запросов.
- **Кандидатов сравнивают по признакам, которые проверяются:** формат ESM и `exports`, встроенные типы, размер, число транзитивных зависимостей, активность поддержки, лицензия.
- **Учить концепции, а не API:** серверное состояние, headless-компоненты, схемы валидации живут дольше конкретных библиотек, и переход между ними — вопрос дня.
::

## Писать самому или брать готовое

Сквозной пример — магазин, которому нужны: задержка поиска при вводе, форматирование дат заказов, выпадающий список выбора города и редактор описания товара.

Вопрос перед каждой установкой: **сколько стоит написать и поддерживать самому, и сколько стоит взять.**

| Задача | Решение | Почему |
| --- | --- | --- |
| задержка поиска | своя функция на 5 строк | задача маленькая, поведение понятно |
| форматирование дат | `Intl.DateTimeFormat` | уже в браузере, с локалями |
| выпадающий список | библиотека | клавиатура, фокус, ARIA, мобильные — недели работы и ошибок |
| редактор текста | библиотека | выделение, история, вставка, IME — годы работы |

Брать библиотеку стоит, когда задача **сложная и хорошо решена**: доступность, браузерные особенности, крайние случаи, которые не видны на первый взгляд. Писать самому — когда нужно немного, поведение очевидно, а зависимость тянет килобайты и риски.

Зависимость — это **обязательство**: её обновляют вместе с мажорными версиями фреймворка, следят за уязвимостями, читают changelog, чинят, когда автор бросил проект. Каждая транзитивная зависимость — ещё один пакет, который может быть взломан: атаки на цепочку поставок через npm случаются регулярно (подробно — в [Цепочке поставок](/content/security-perfomance/supply-chain-and-vulnerabilities)).

## Сначала — платформа

Многое, ради чего раньше ставили библиотеки, теперь есть в языке и браузере:

| Задача | Раньше | Сейчас |
| --- | --- | --- |
| даты и числа по локали | `moment`, `numeral` | `Intl.DateTimeFormat`, `Intl.NumberFormat` |
| глубокая копия | `lodash.cloneDeep` | `structuredClone` |
| группировка | `lodash.groupBy` | `Object.groupBy` |
| неизменяемая сортировка | копия и `sort` | `toSorted`, `toReversed`, `with` |
| запросы и отмена | `axios`, `superagent` | `fetch` и `AbortController` |
| уникальный ID | `uuid` | `crypto.randomUUID()` |
| диалог | библиотека модалок | `<dialog>` с `showModal()` |

Подробно о новинках языка и `Intl` — в [Современном JavaScript](/content/javascript/modern-js), об утилитах — в [Утилитарных библиотеках](/content/ecosystem-libs/utility-libraries).

## Сколько стоит зависимость

### Размер в бандле

Пользователь скачивает и разбирает каждую зависимость. Цена одной и той же функции зависит не от её сложности, а от того, как опубликован пакет. В проверке Rolldown собрал по одной функции из разных пакетов с минификацией и gzip:

| Импорт | gzip |
| --- | --- |
| `debounce` из `lodash` | ≈25 КБ |
| `debounce` из `lodash-es` | ≈1 КБ |
| своя `debounce` на 5 строк | ≈0,1 КБ |
| форматирование даты через `moment` | ≈20 КБ |
| через `date-fns` | ≈5 КБ |
| через `dayjs` | ≈3 КБ |
| через `Intl.DateTimeFormat` | ≈0,1 КБ — только сам вызов |

`lodash` опубликован в CommonJS, и бандлер не может выбросить неиспользуемые функции — в бандл попадает весь пакет. `lodash-es` — те же функции в ESM, и остаётся только нужная (подробно — в [Оптимизации](/content/advanced-tooling/optimization)). `moment` целиком объектный и не делится на части по смыслу.

Размер до установки смотрят на bundlephobia или pkg-size, а точнее — собирают у себя: значение зависит от того, что именно импортировано.

### Транзитивные зависимости

Одна строка в `package.json` приносит дерево пакетов. В проверке по lock-файлу проекта у `eslint` оказалось больше 70 транзитивных зависимостей, а у `oxlint` — ни одной: это нативный бинарник, который приходит одним платформенным пакетом. Каждая транзитивная зависимость — ещё одна точка для уязвимости, конфликта версий и задержки установки. Посмотреть дерево — `npm ls имя --all`, а объяснить, зачем пакет в проекте, — `npm explain имя`.

## Критерии выбора

Когда решили брать, кандидатов сравнивают по проверяемым признакам:

| Критерий | Что проверить |
| --- | --- |
| формат | ESM, поле `exports`, `"sideEffects"` — от этого зависит размер в бандле |
| типы | встроены в пакет или нужны `@types/*`; насколько точны |
| размер | собранный размер нужного импорта, а не всего пакета |
| зависимости | число транзитивных пакетов, есть ли тяжёлые |
| поддержка | дата последнего релиза, реакция на issue, больше одного мейнтейнера |
| совместимость | поддержка текущих версий фреймворка, SSR, серверных компонентов |
| доступность | для UI — клавиатура, фокус, ARIA, проверено ли на скринридерах |
| лицензия | MIT, Apache, BSD — без ограничений; GPL и AGPL — осторожно в закрытом продукте |
| документация | примеры, руководства по миграции, changelog |

Лицензия указана в `package.json` и в файле `LICENSE` пакета. В проверке у `vue` и `lodash-es` — MIT.

### Красные флаги

- давно нет релизов, а issue копятся без ответа;
- единственный мейнтейнер без доступа у кого-то ещё — риск остановки и угона пакета;
- огромный размер ради простой задачи;
- только CommonJS в 2026 году;
- нет типов или они расходятся с поведением;
- `postinstall`-скрипты, которые что-то скачивают или выполняют (подробно — в [Управлении пакетами](/content/ecosystem-libs/package-management));
- популярность только в соцсетях, без использования в продакшене.

## Как жить с меняющейся экосистемой

Каждый год появляются новые инструменты и библиотеки — это называют **JavaScript fatigue**. Разумный ответ:

- **учить концепции, а не API.** Понял, что такое серверное состояние и кеш запросов, — переход с одной библиотеки на другую займёт день. Понял headless-компоненты — неважно, какая библиотека их даёт;
- **скучные решения для основы, эксперименты на краях.** Фреймворк, роутер, стор — проверенные; новую библиотеку пробуют в изолированной части;
- **предпочитать стандарты.** Код на `fetch`, `Intl`, Web Components и Standard Schema переживает смену библиотек;
- **совместимые API облегчают переход:** многие новые инструменты повторяют API старых (подробно — в [Rust и будущем тулинга](/content/advanced-tooling/rust-and-the-future)).

Дальше в главе — ландшафт библиотек по задачам: что есть, чем отличается и как выбрать. Механика каждой темы — в своей главе, а здесь — выбор инструмента.

---

## Красные флаги в ответе

- **«Беру самую популярную библиотеку».** Популярность — один признак из многих, важнее формат, размер, поддержка и совместимость.
- **«Размер не важен, всё равно сожмётся».** Сжатие не выбросит неиспользуемый код CommonJS-пакета, а 25 КБ ради одной функции — это реальная цена.
- **«Для дат нужен moment».** Он в поддержке без развития и тяжёлый, а форматирование даёт `Intl`.
- **«Своё решение всегда лучше зависимости».** Доступность, редакторы и даты с часовыми поясами самостоятельно делаются плохо.
- **«Зависимость поставил и забыл».** Её обновляют, проверяют на уязвимости и иногда заменяют.

## Как спрашивают на собеседовании

::question
Как ты выбираешь библиотеку для задачи?

#answer
Сначала решаю, нужна ли она: есть ли решение в платформе и насколько сложно сделать самому. Если брать — сравниваю кандидатов по формату ESM и типам, собранному размеру нужного импорта, транзитивным зависимостям, активности поддержки, совместимости с фреймворком и SSR, лицензии.

#more
Для UI добавляется доступность: клавиатура, фокус, ARIA. Размер смотрю собранным у себя, а не по весу пакета на диске. Проверяю changelog и руководства по миграции: как библиотека переживала мажорные версии. Красные флаги — заброшенность, единственный мейнтейнер, только CommonJS, тяжёлый `postinstall`.
::

::question
Когда лучше написать самому, а не тянуть зависимость?

#answer
Когда задача маленькая и понятная — задержка ввода, форматирование строки, — а зависимость тянет килобайты, транзитивные пакеты и обязательства по обновлению. Или когда решение уже есть в платформе: `Intl`, `structuredClone`, `fetch`.

#more
Своя `debounce` весит около 0,1 КБ, а импорт из CommonJS-пакета `lodash` — около 25 КБ. Но доступные компоненты, редакторы текста и даты с часовыми поясами самостоятельно делаются долго и с ошибками — там библиотека выигрывает.
::

::question
Почему одна функция из библиотеки может весить десятки килобайт?

#answer
Если пакет опубликован в CommonJS, бандлер не знает, что из него используется, и включает весь пакет. Из ESM-пакета он берёт только импортированное.

#more
`debounce` из `lodash` — около 25 КБ gzip, из `lodash-es` — около 1 КБ. Мешают и побочные эффекты при импорте, и экспорт одного большого объекта. Поэтому при выборе смотрят на формат, `exports` и `"sideEffects"` и измеряют собранный размер нужного импорта.
::

::question
На что смотреть, кроме размера и популярности?

#answer
На поддержку — дату последнего релиза, реакцию на issue, число мейнтейнеров; на встроенные типы; на транзитивные зависимости; на совместимость с версией фреймворка, SSR и серверными компонентами; на лицензию.

#more
Транзитивные зависимости — это поверхность атаки и конфликтов: одна строка в `package.json` может принести десятки пакетов. GPL и AGPL требуют осторожности в закрытом продукте. Тяжёлые `postinstall`-скрипты — повод присмотреться.
::

::question
Что такое JavaScript fatigue и как с ней жить?

#answer
Усталость от постоянной смены инструментов и библиотек. Ответ — учить концепции, а не API: серверное состояние, headless-компоненты, схемы валидации. Тогда смена библиотеки — вопрос дня.

#more
Для основы проекта выбирать проверенные решения, экспериментировать на краях. Предпочитать стандарты платформы — `fetch`, `Intl`, Standard Schema, — которые переживают смену библиотек. Не переходить на новое, пока оно не доказало стабильность в чужом продакшене.
::

## Практика

::practice{title="Бандл вырос на 25 КБ ради одной функции"}
После добавления поиска с задержкой точка входа выросла почти на 25 КБ gzip:

```js
import { debounce } from 'lodash';

const search = debounce((q) => api.search(q), 300);
```

#solution
`lodash` опубликован в CommonJS, и бандлер включил весь пакет, а не одну функцию. Три варианта по возрастанию простоты:

```js
import { debounce } from 'lodash-es';   // ESM: в бандле только debounce, около 1 КБ
```

```js
import debounce from 'lodash/debounce';   // отдельный файл CommonJS-пакета
```

```js
const debounce = (fn, ms) => {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), ms);
  };
};
```

Для такой маленькой задачи своя функция — разумный выбор: 0,1 КБ и никаких зависимостей. Если `lodash` уже используется в проекте широко, переход на `lodash-es` уменьшит бандл везде. В проверке три варианта дали около 25 КБ, 1 КБ и 0,1 КБ gzip.
::

::practice{title="Выбери библиотеку дат"}
В проекте дат немного: показать дату заказа и «3 дня назад», посчитать срок доставки. Сейчас подключён `moment`. Что делать?

#solution
`moment` тяжёлый — около 20 КБ gzip в проверке — и находится в режиме поддержки без развития. Для форматирования библиотека не нужна:

```js
const date = new Intl.DateTimeFormat('ru', { dateStyle: 'long' }).format(order.createdAt);
const ago = new Intl.RelativeTimeFormat('ru', { numeric: 'auto' }).format(-3, 'day');   // «3 дня назад»
```

Для арифметики дат — `date-fns` с импортом отдельных функций, около 5 КБ, или `dayjs`, около 3 КБ. Где Temporal уже есть или его можно подключить полифилом, он решает и арифметику, и часовые пояса стандартным API (подробно — в [Современном JavaScript](/content/javascript/modern-js)). Переход делают постепенно: сначала форматирование на `Intl`, потом арифметика.
::
