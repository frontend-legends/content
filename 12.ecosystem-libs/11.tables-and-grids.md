# Таблицы и гриды

Таблица данных - обманчиво сложный компонент: сортировка, фильтрация, пагинация, изменение размера и порядка колонок, выделение строк, инлайн-редактирование, группировка и - главное - **производительность на больших объёмах**. Поэтому почти всегда берут библиотеку.

---

## Почему таблицы сложные

«Просто `<table>`» хватает для статичных данных. Но как только появляются:

- сортировка/фильтрация по колонкам и **серверная** пагинация;
- тысячи и десятки тысяч строк (DOM не тянет);
- ресайз/переупорядочивание колонок, закреплённые колонки;
- выделение, инлайн-редактирование, группировка, разворачивание;

...самописное решение быстро превращается в маленький фреймворк. Библиотеки дают это из коробки.

---

## Headless vs полный грид

Главное различие в категории:

| | Headless | Полный грид |
|--|----------|-------------|
| Что даёт | логику (сортировка, фильтры, пагинация) | логику **и** готовый рендер/стили |
| Рендер | пишешь сам | встроенный |
| Гибкость | полная | ограничена темой грида |
| Примеры | TanStack Table | AG Grid, MUI Data Grid |

---

## TanStack Table

**Headless** библиотека таблиц: даёт всю логику (модели сортировки, фильтрации, пагинации, группировки), но **не рендерит ничего сама** - разметку и стили пишешь ты. Кросс-фреймворк (React/Vue/Solid/Svelte).

```jsx
const table = useReactTable({
  data, columns,
  getCoreRowModel: getCoreRowModel(),
  getSortedRowModel: getSortedRowModel(),     // включаем сортировку
  getFilteredRowModel: getFilteredRowModel(), // и фильтрацию
});
// дальше ты сам рендеришь table.getRowModel().rows как хочешь
```

<b class="text-on-semi-light">Почему headless</b> - <span class="text-gray">Ты получаешь сложную логику, но полный контроль над разметкой и стилями - таблица выглядит как часть твоего дизайна, а не как чужой грид. Идеально для кастомного UI. Цена - сам пишешь рендер. В паре с виртуализацией тянет большие данные.</span>

---

## AG Grid

**Полнофункциональный enterprise-грид**: логика **и** рендеринг, с огромным набором возможностей - виртуализация из коробки, группировка, агрегация, pivot, экспорт, инлайн-редактирование, закрепление.

<b class="text-on-semi-light">Когда AG Grid</b> - <span class="text-gray">Сложные «экселеподобные» таблицы в энтерпрайзе, где нужно много возможностей сразу и некогда собирать самому. Минусы: вес, своя система стилизации (труднее вписать в дизайн), часть фич - в **платной** Enterprise-версии. Community-версия бесплатна и покрывает базовое.</span>

Похожие: **MUI Data Grid** (если уже на MUI), **Handsontable** (спредшит-стиль с формулами).

---

## Виртуализация

Ключ к производительности больших таблиц/списков: рендерить **только видимые строки** (+ небольшой буфер), а не все 10 000.

- **TanStack Virtual** - headless-виртуализация, кросс-фреймворк; естественно сочетается с TanStack Table.
- **react-window** - лёгкий, простой (преемник react-virtualized).
- **react-virtualized** - старший, мощнее, но тяжелее.

```jsx
// рендерим ~20 видимых строк вместо 10 000
const rowVirtualizer = useVirtualizer({ count: rows.length, getScrollElement, estimateSize });
```

<b class="text-on-semi-light">Связка для больших данных</b> - <span class="text-gray">TanStack Table (логика) + TanStack Virtual (виртуализация) - типовое решение для кастомной таблицы с десятками тысяч строк. AG Grid делает то же самое, но «всё в одном».</span>

---

## Клиентская vs серверная обработка

Важный архитектурный вопрос: где сортировать/фильтровать/пагинировать.

- **Клиент** - данные целиком на фронте; библиотека сортирует/фильтрует в браузере. Хорошо до нескольких тысяч строк.
- **Сервер** - данные не помещаются/секьюрны; фронт лишь шлёт параметры (page, sort, filter), сервер возвращает нужную страницу. Обязательно для очень больших данных.

> TanStack Table и AG Grid поддерживают оба режима (`manual*` модели для серверного).

---

## Как выбрать

```
Кастомный дизайн, контроль разметки   → TanStack Table (+ TanStack Virtual)
Много фич сразу, энтерпрайс           → AG Grid
Уже используешь MUI                   → MUI Data Grid
Спредшит с формулами                  → Handsontable
Просто длинный список                 → react-window / TanStack Virtual
```

## Вопросы на собеседовании

<b class="text-on-semi-light">Почему для таблиц берут библиотеку, а не просто `<table>`?</b>
<span class="text-gray">Из-за сортировки, фильтрации, серверной пагинации, ресайза колонок, выделения, редактирования и производительности на больших данных - самописное быстро становится мини-фреймворком.</span>

<b class="text-on-semi-light">Чем TanStack Table отличается от AG Grid?</b>
<span class="text-gray">TanStack Table headless - даёт логику, рендер пишешь сам (полный контроль над дизайном). AG Grid - полный грид с рендером и множеством фич из коробки, но со своими стилями и весом.</span>

<b class="text-on-semi-light">Как отрендерить таблицу с десятками тысяч строк?</b>
<span class="text-gray">Виртуализация - рендерить только видимые строки (TanStack Virtual, react-window). Часто плюс серверная пагинация/сортировка, чтобы не грузить все данные на клиент.</span>

<b class="text-on-semi-light">Где лучше сортировать и фильтровать - на клиенте или сервере?</b>
<span class="text-gray">На клиенте - пока данных немного (тысячи). На сервере - для больших объёмов: фронт шлёт параметры, сервер возвращает страницу. Библиотеки поддерживают оба режима.</span>

<b class="text-on-semi-light">Что значит «headless» для таблицы?</b>
<span class="text-gray">Библиотека даёт логику (модели сортировки/фильтрации/пагинации), но не рендерит разметку - ты пишешь UI сам, получая полный контроль над дизайном.</span>
