# Раннеры тестов

**Раннер** - инструмент, который находит тесты, запускает их, проверяет ассершены и выдаёт отчёт. Для фронтенда это в основном **Vitest** и **Jest**. Понимать, что делает раннер и почему Vitest вытеснил Jest в Vite-проектах, - база для разговора о тестах.

---

## Что делает раннер

Тестовый раннер берёт на себя инфраструктуру:

- **находит** тестовые файлы (`*.test.ts`, `*.spec.ts`);
- **запускает** их в изолированном окружении;
- даёт **ассершены** (`expect(...).toBe(...)`);
- встроенный **мокинг** ([моки и дублёры](/content/testing-deploying/mocking-and-test-doubles));
- считает **покрытие**;
- **watch-режим** - перезапуск при изменении;
- предоставляет **DOM** в Node (jsdom/happy-dom), чтобы тестировать компоненты без браузера.

---

## Анатомия теста

```js
import { describe, test, expect, beforeEach } from 'vitest';

describe('Cart', () => {              // группа
  beforeEach(() => { /* подготовка перед каждым тестом */ });

  test('суммирует цены', () => {       // отдельный тест
    expect(total([{ p: 10 }, { p: 5 }])).toBe(15); // ассершен (matcher)
  });
});
```

- `describe` - группирует связанные тесты.
- `test`/`it` - один тест-кейс.
- `expect(...).matcher(...)` - проверка (`toBe`, `toEqual`, `toContain`, `toThrow`, ...).
- `beforeEach`/`afterEach`/`beforeAll` - хуки подготовки и очистки.

## Vitest vs Jest

| | Jest | Vitest |
|--|------|--------|
| Происхождение | Meta, эра Webpack/Babel | команда Vite |
| Скорость | медленнее | быстрый (esbuild, параллелизм) |
| ESM | проблемно (нужны хаки) | нативно |
| Конфиг | свой (transform/babel-jest) | переиспользует Vite-конфиг |
| API | стандарт де-факто | **совместим с Jest** |
| Watch | есть | мгновенный, как HMR |

<b class="text-on-semi-light">Почему Vitest победил в Vite-проектах</b> - <span class="text-gray">Jest тянул свой пайплайн трансформации (babel-jest), отдельный от сборки, - медленно и с трением вокруг ESM. Vitest **переиспользует ту же конфигурацию и трансформацию, что и Vite** (esbuild): тесты видят код так же, как приложение, запускаются быстро, а API почти полностью совместим с Jest (миграция простая). Для не-Vite проектов Jest всё ещё валиден.</span>

## DOM-окружение

Тесты идут в Node, где нет `document`/`window`. Раннер подставляет **эмуляцию DOM**:

- **jsdom** - полная, зрелая реализация DOM на JS.
- **happy-dom** - легче и быстрее, покрывает большинство кейсов.

```js
// vitest.config.ts
test: { environment: 'jsdom' } // дать компонентам DOM
```

> Это эмуляция, а не настоящий браузер - поэтому тонкости рендеринга/лейаута тестируют через [e2e](/content/testing-deploying/e2e-testing) в реальном браузере.

---

## Покрытие

Раннеры считают покрытие встроенно (через `v8` или `istanbul`):

```bash
vitest --coverage
```

Метрики и их пределы - в [покрытии и TDD](/content/testing-deploying/coverage-and-tdd).

---

## Watch и фильтрация

В разработке тесты гоняют в **watch-режиме**: при изменении файла перезапускаются только затронутые тесты - мгновенная обратная связь. Можно фильтровать по имени/файлу (`vitest Cart`).

---

## Другие раннеры

- **node:test** - встроенный в Node тест-раннер (без зависимостей); набирает популярность для библиотек.
- **Mocha + Chai** - классика, гибкие, но требуют сборки из кусков; legacy.
- **Jasmine** - старый all-in-one, реже в новых проектах.

## Вопросы на собеседовании

<b class="text-on-semi-light">Что делает тестовый раннер?</b>
<span class="text-gray">Находит и запускает тесты в изолированном окружении, даёт ассершены и мокинг, считает покрытие, поддерживает watch и подставляет DOM (jsdom) для компонентов.</span>

<b class="text-on-semi-light">Чем Vitest отличается от Jest?</b>
<span class="text-gray">Vitest переиспользует конфиг и трансформацию Vite (esbuild) - быстрый, нативный ESM, мгновенный watch, API совместим с Jest. Jest тянет свой пайплайн (babel-jest), медленнее и с трением вокруг ESM.</span>

<b class="text-on-semi-light">Зачем нужен jsdom?</b>
<span class="text-gray">Тесты идут в Node без браузера. jsdom/happy-dom эмулируют DOM (`document`, `window`), чтобы тестировать компоненты без запуска реального браузера.</span>

<b class="text-on-semi-light">Достаточно ли jsdom для всех тестов?</b>
<span class="text-gray">Нет, это эмуляция - тонкости реального рендеринга, лейаута и кросс-браузерности проверяют e2e в настоящем браузере.</span>

<b class="text-on-semi-light">Что такое watch-режим и зачем он?</b>
<span class="text-gray">Автоперезапуск затронутых тестов при изменении файлов - мгновенная обратная связь в разработке, ускоряет цикл «изменил - проверил».</span>
