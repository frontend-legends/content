# Будущее фронтенда

Тренды главы в одной картине: ИИ в процессе разработки, возврат работы на сервер, отказ от дорогой гидратации, сигналы, компиляторы, платформа вместо библиотек, edge, сквозные типы и local-first — и то, что не меняется под всеми этими сдвигами. Спрашивают, куда движется фронтенд, что не изменится, какой фреймворк учить и заменит ли ИИ разработчиков. Глубже — почему фреймворки становятся похожими друг на друга и почему компилятор, а не разработчик, теперь пишет `useMemo`.

::tldr
- **Направления:** ИИ-агенты в разработке, меньше JavaScript на клиенте через серверные компоненты и острова, возобновление вместо гидратации, сигналы, компиляторы, встроенные возможности платформы, edge, сквозная типобезопасность и local-first.
- **Фреймворки сходятся:** сигналы пришли из Solid почти везде, острова и серверные компоненты — в мета-фреймворки, компиляция из Svelte — в React Compiler и Vue Vapor.
- **Компилятор берёт рутину на себя:** React Compiler сам вставляет мемоизацию, Svelte компилирует компонент в статический шаблон и точечные обновления.
- **Фундамент не меняется:** браузер, сеть, JavaScript, рендеринг, алгоритмы, доступность, производительность и инженерные практики переживают любой фреймворк.
- **Ставка — на понимание:** кто понимает принципы, осваивает новый инструмент за дни и проверяет ИИ, а не верит ему.
::

---

## Направления

Сквозной пример — магазин через пять лет: та же витрина, но меньше JavaScript у пользователя, часть кода пишут агенты, а админка работает офлайн.

### ИИ в разработке

От автодополнения — к агентам, которые читают код, запускают тесты и готовят PR (подробно — в [ИИ в разработке](/content/modern-dev/ai-assisted-development) и [Агентах и MCP](/content/modern-dev/ai-agents-and-mcp)). Роль инженера смещается к постановке задач, ограничениям, проверке и архитектуре.

### Меньше JavaScript на клиенте

Маятник качнулся обратно к серверу, но иначе, чем в эпоху серверных шаблонов: серверные компоненты React, острова Astro, потоковый рендеринг (подробно — в [Серверных компонентах и React 19](/content/reactjs/rsc-and-react-19) и [Мета-фреймворках](/content/ecosystem-libs/meta-frameworks)). Чистое SPA перестаёт быть вариантом по умолчанию для сайтов с контентом.

### Без дорогой гидратации

Гидратация выполняет на клиенте тот же код, что сервер уже выполнил, чтобы «оживить» HTML (подробно — в [Рендеринге и гидратации React](/content/reactjs/rendering-and-hydration)). Альтернативы — частичная гидратация островов, ленивая гидратация по видимости и **возобновление** в Qwik: приложение продолжает работу с того места, где остановился сервер, загружая код только для того, с чем взаимодействуют.

### Сигналы

Точечная реактивность стала общей моделью: Solid, Vue, Svelte, Angular, Preact, предложение TC39 (подробно — в [Сигналах и реактивности](/content/modern-dev/signals-and-reactivity)).

### Компиляторы

Фреймворк всё чаще — компилятор, а не только библиотека: работа переносится из рантайма в сборку.

### Платформа

Встроенные возможности браузера забирают задачи у библиотек, а Baseline и Interop делают платформу предсказуемой (подробно — в [Эволюции веб-платформы](/content/modern-dev/web-platform-evolution)).

### Edge, типы, local-first

Вычисления — ближе к пользователю (подробно — в [Edge-вычислениях](/content/modern-dev/edge-computing)), типы — через весь стек (подробно — в [Сквозной типобезопасности](/content/modern-dev/end-to-end-typesafety)), данные — на устройстве (подробно — в [Local-first](/content/modern-dev/local-first-software)). То, что было продвинутым, становится ожидаемым.

## Компиляторы

В проверке два компилятора показали, как это выглядит в коде.

**React Compiler** взял обычный компонент без мемоизации:

```jsx
export function Card({ product }) {
  const label = product.title + ' — ' + product.price + ' ₽';
  return <article><h2>{label}</h2></article>;
}
```

и вставил кеш из двух ячеек — JSX пересоздаётся, только если изменилась строка:

```js
import { c as _c } from "react/compiler-runtime";
export function Card(t0) {
  const $ = _c(2);
  // …
  if ($[0] !== label) { t1 = <article>…</article>; $[0] = label; $[1] = t1; } else { t1 = $[1]; }
  return t1;
}
```

Ни `useMemo`, ни `memo` в исходнике не было — их работу сделал компилятор (подробно — в [Производительности React](/content/reactjs/performance)).

**Svelte 5** скомпилировал компонент с рунами `$state` и `$derived` в статический шаблон — список товаров стал готовой строкой HTML — и **один** эффект, который обновляет только текст кнопки:

```js
var root = $.from_html(`<button> </button><ul><li>Пуэр</li><li>Улун</li></ul>`, 1);
// …
$.template_effect(() => $.set_text(text, $.get(label)));
```

Два разных пути к одной цели: минимум лишней работы во время выполнения без ручной оптимизации.

## Фреймворки сходятся

```text
сигналы          Solid           → Vue, Svelte 5, Angular, Preact, Qwik
острова, RSC     Astro, Marko    → Next.js, Nuxt, React Router
возобновление    Qwik            → идеи ленивой гидратации в остальных
компиляция       Svelte          → React Compiler, Vue Vapor
серверные функции Remix, Next.js → TanStack Start, SvelteKit, Nuxt
```

Конкуренция идёт идеями, и лучшие быстро расходятся. Поэтому вопрос «какой фреймворк учить» теряет остроту: модели сближаются, а понявший один глубоко осваивает другой быстро. Различаются они всё больше экосистемой, компромиссами и вкусом, а не принципами.

---

## Что не изменится

Под слоем меняющихся инструментов — стабильный фундамент:

- **браузер** — DOM, события, рендеринг, конвейер кадра (подробно — в [Вебе](/content/web));
- **сеть** — HTTP, кеширование, безопасность (подробно — в [Сети и API](/content/network-api));
- **JavaScript** — event loop, замыкания, асинхронность, модули (подробно — в [JavaScript](/content/javascript));
- **основы информатики** — алгоритмы, структуры данных, память (подробно — в [Computer Science](/content/computer-science));
- **пользователь** — производительность, доступность, понятный интерфейс;
- **инженерия** — тесты, ревью, проектирование, разбор ошибок.

Каждый тренд из списка выше стоит на этом фундаменте. Сигналы — это граф зависимостей и очередь обновлений. Edge — это сеть и задержки. Компилятор — это анализ кода. ИИ-агент — это инструменты, которые нужно направлять и проверять.

## Как оставаться в курсе

Без выгорания от потока новинок (подробно — в [Непрерывном обучении](/content/final-steps/continuous-learning)):

- учить **принципы**, а не каждый API;
- оценивать новое через **компромиссы**: что решает, чем платим, насколько стабильно;
- осваивать тренды **по одному и глубоко**;
- помнить, что многие «революции» — переосмысление старых идей: сигналы напоминают наблюдатели Knockout, серверный рендеринг — серверные шаблоны, острова — прогрессивное улучшение. Но переосмысление с новым опытом: серверные компоненты стримятся и смешиваются с клиентскими, чего старые шаблоны не умели.

## На что ставить

| Меняется — учить по мере надобности | Стабильно — вкладываться глубоко |
| --- | --- |
| конкретные фреймворки и их API | браузер, рендеринг, события |
| библиотеки и сборщики | JavaScript и TypeScript |
| синтаксис и соглашения | сеть, HTTP, кеширование |
| модные архитектуры | производительность и доступность |
| инструменты ИИ | умение ставить задачу и проверять результат |

Будущее за инженерами, которые понимают систему целиком и используют новые инструменты — в том числе ИИ — осознанно. Дальше — [подготовка к собеседованиям](/content/preparing-for-interviews) и [финальные шаги](/content/final-steps).

## Красные флаги в ответе

- **«Через год всё будет другим, учить основы бессмысленно».** Основы — то, что не меняется под трендами.
- **«ИИ заменит фронтендеров».** Он меняет роль, но проверять и направлять его без понимания нельзя.
- **«SPA устарели».** Для сложных интерфейсов и приложений за логином SPA по-прежнему уместны.
- **«Серверные компоненты — это просто PHP заново».** Они стримятся и смешиваются с клиентскими компонентами в одном дереве.
- **«Надо выбрать единственный правильный фреймворк».** Модели сходятся, важнее понимать принципы.

## Как спрашивают на собеседовании

::question
Куда движется фронтенд?

#answer
ИИ-агенты в разработке, меньше JavaScript на клиенте через серверные компоненты и острова, ленивая гидратация и возобновление, сигналы как модель реактивности, компиляторы, встроенные возможности платформы вместо библиотек, edge, сквозные типы и local-first.

#more
Хорошо показать связь трендов с фундаментом: сигналы — граф зависимостей, компиляторы — анализ кода, edge — задержки сети. И назвать компромиссы каждого, а не только плюсы.
::

::question
Что не изменится при всех этих сдвигах?

#answer
Фундамент: как работают браузер, DOM, рендеринг, сеть и HTTP, семантика JavaScript, основы информатики, а также производительность, доступность и инженерные практики. Они переживают любой фреймворк.

#more
Каждый новый инструмент стоит на этом фундаменте, поэтому понимание основ — самый быстрый путь освоить и новинку.
::

::question
Какой фреймворк учить, если всё меняется?

#answer
Любой популярный, но глубоко, вместе с принципами. Модели фреймворков сходятся — сигналы, серверный рендеринг, компиляция, — и понявший один переходит на другой за дни.

#more
Выбор для работы — по задаче, команде и экосистеме. На собеседовании важнее объяснить, как фреймворк устроен и почему, чем знать каждый API.
::

::question
Почему фреймворки становятся похожими?

#answer
Они заимствуют удачные идеи: сигналы из Solid пришли во Vue, Svelte, Angular и Preact, острова и серверный рендеринг — в мета-фреймворки, компиляция из Svelte — в React Compiler и Vue Vapor.

#more
Все решают одну задачу — минимум лишней работы у пользователя без ручной оптимизации у разработчика. React идёт через компилятор поверх модели перерисовки, остальные — через сигналы и компиляцию шаблонов.
::

::question
Заменит ли ИИ фронтенд-разработчиков?

#answer
Он меняет работу: меньше набора кода, больше постановки задач, проверки и архитектуры. Понимание остаётся обязательным — без него нельзя направить агента и отличить правильный результат от правдоподобного.

#more
Ценнее становятся суждение, видение системы целиком, умение писать понятные требования и строить проверки — тесты, типы, ревью.
::

## Практика

::practice{title="Убрать ручную мемоизацию"}
В компонентах каталога десятки `useMemo`, `useCallback` и `memo`. Часть из них устарела, часть с неверными зависимостями, и команда спорит, где они нужны.

#solution
Мемоизацию можно отдать компилятору. В проверке React Compiler сам добавил кеш к компоненту без единого `useMemo`: JSX пересоздаётся, только если изменилась строка.

```js
// babel.config.js или плагин сборщика
export default { plugins: ['babel-plugin-react-compiler'] };
```

План: включить компилятор сначала для части каталога, проверить тестами и профилировщиком, затем убирать ручную мемоизацию там, где компилятор её покрывает. Компилятор требует соблюдать правила React — чистые компоненты, без мутаций пропсов и состояния, — и линтер `eslint-plugin-react-hooks` с правилами компилятора находит нарушения заранее (подробно — в [Производительности React](/content/reactjs/performance)).
::

::practice{title="Выбрать стек для нового проекта"}
Команде предлагают для нового каталога «самый современный стек»: другой фреймворк, edge-рендеринг, local-first и сигналы. Каталог — публичные страницы товаров с поиском и корзиной, данные в Postgres во Франкфурте.

#solution
Тренды оценивают по задаче, а не по моде:

```text
каталог с SEO          → серверный рендеринг или статика с кешем — да
edge-рендеринг         → данные во Франкфурте — только middleware и кеш на edge
local-first            → корзина и заказы — арбитр на сервере; local-first не нужен
сигналы, смена фреймворка → только если команда знает его или выигрыш измерим
```

В проверках главы видно, где каждый тренд выигрывает: edge — без запросов к далёкой базе, local-first — для документов и черновиков, сигналы и компиляторы — против лишних перерисовок. Решение пишут дизайн-документом с альтернативами и компромиссами (подробно — в [Инженерной зрелости](/content/final-steps/engineering-maturity)).
::
