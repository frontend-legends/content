# AI-агенты и MCP

Следующий шаг после ассистентов - **агенты**. Ассистент *подсказывает*, агент *действует*: сам планирует и выполняет многошаговые задачи - читает файлы, пишет код, запускает команды, проверяет результат и итерирует. А **MCP** стал стандартом, которым агенты подключаются к инструментам и данным. Это горячая тема 2025–2026.

---

## От ассистента к агенту

```
Ассистент:  ты просишь → он предлагает код → ты вставляешь
Агент:      ты ставишь задачу → он сам планирует, правит файлы,
            запускает тесты, исправляет ошибки → показывает результат
```

<b class="text-on-semi-light">Ключевое различие</b> - <span class="text-gray">Агент **автономно выполняет** задачу целиком, а не выдаёт фрагмент. Он работает в цикле: понять → спланировать → **действовать инструментами** → посмотреть результат → повторить, пока не готово. Инженер задаёт цель и проверяет итог, а не диктует каждый шаг.</span>

Инструменты: **Claude Code**, агентный режим Cursor, Aider, Devin, Copilot agent. (Этот справочник, к слову, писался с помощью такого агента.)

---

## Цикл работы агента

```
       ┌─────────────────────────────┐
       ▼                             │
   спланировать → выполнить действие (tool) → наблюдать результат
       ▲                                              │
       └──────────── повторять до завершения ─────────┘
```

Агент действует через **инструменты** (tool use / function calling): читать и писать файлы, запускать команды в терминале, искать по коду, вызывать API. Модель не «угадывает» состояние - она его **узнаёт**, вызывая инструменты, и реагирует на реальный результат (ошибку теста, вывод команды).

---

## MCP - Model Context Protocol

Проблема: чтобы агент был полезен, его надо подключить к **множеству** систем - файлам, GitHub, базам, Slack, Figma. Раньше каждый AI-инструмент интегрировал каждый сервис по-своему - комбинаторный взрыв.

**MCP** (открытый стандарт, представлен Anthropic в конце 2024) - единый протокол подключения AI к инструментам и данным. Его называют **«USB-C для AI»**.

```
    MCP-серверы (предоставляют инструменты/данные)
   ┌─────────┬─────────┬─────────┬─────────┐
 GitHub    Postgres   Slack    Figma    файлы
   └─────────┴────┬────┴─────────┴─────────┘
              MCP-протокол
                  │
        AI-приложение (клиент): Claude, IDE, агент
```

<b class="text-on-semi-light">Почему это важно</b> - <span class="text-gray">MCP превращает проблему «M инструментов × N сервисов» в «M + N»: сервис пишет **один** MCP-сервер, и его видят **все** MCP-совместимые AI-клиенты. Появилась экосистема готовых серверов (GitHub, БД, браузеры, дизайн-инструменты), которые подключаются к любому агенту без кастомной интеграции. Это стандартизировало то, как AI «дотягивается» до мира.</span>

MCP-сервер предоставляет **tools** (действия), **resources** (данные) и **prompts**; клиент (AI-приложение) их вызывает.

---

## Context engineering

Агенту критичен **контекст** - что он видит в ограниченном окне модели. Управление этим - новый навык:

- **что подать** - релевантные файлы, а не весь репозиторий;
- **память** - сохранять важное между шагами/сессиями;
- **retrieval** - находить нужные куски кода по запросу;
- **сжатие** - суммировать длинную историю, чтобы не переполнить окно.

> «Context engineering» приходит на смену «prompt engineering» как главный навык: для агента важнее **правильно собрать контекст и инструменты**, чем идеально сформулировать одну фразу.

---

## Что умеют агенты

- Реализовать фичу по описанию, тронув много файлов.
- Чинить баг по тексту issue (воспроизвести → исправить → проверить тестом).
- Большие **миграции** и рефакторинги по всей кодовой базе.
- Писать и прогонять тесты, чинить упавшее.
- Ревью, исследование кода, генерация документации.

---

## Риски и границы

| Риск | Суть |
|------|------|
| **Нужен надзор** | агент может уверенно пойти не туда |
| **Проверка результата** | диффы надо ревьюить, тесты - доверять, но проверять |
| **Безопасность** | агент запускает команды - нужны песочница и права |
| **Prompt injection через инструменты** | вредоносные данные (issue, веб-страница) могут «перехватить» агента |
| **Стоимость** | много вызовов модели = деньги и время |

<b class="text-on-semi-light">Как работать с агентами</b> - <span class="text-gray">Чёткая постановка и **ограничения** (guardrails), **human-in-the-loop** (ревью диффов, подтверждение опасных действий), изоляция (отдельная ветка/песочница), запрет на доступ к секретам без надзора. Агент ускоряет, но ответственность за результат остаётся на инженере.</span>

---

## Траектория

```
автодополнение → чат-ассистент → агент → много агентов (оркестрация)
        инженер всё больше становится ПОСТАНОВЩИКОМ и РЕВЬЮЕРОМ
```

Роль смещается от «пишу код руками» к «ставлю задачи, направляю агентов, проверяю и отвечаю за результат». Понимание систем при этом не уходит - оно становится тем, чем ты **руководишь** агентами.

## Вопросы на собеседовании

<b class="text-on-semi-light">Чем AI-агент отличается от ассистента?</b>
<span class="text-gray">Ассистент подсказывает фрагменты, агент автономно выполняет задачу целиком: планирует, действует инструментами (правит файлы, запускает команды), наблюдает результат и итерирует. Инженер задаёт цель и проверяет итог.</span>

<b class="text-on-semi-light">Что такое MCP и зачем он нужен?</b>
<span class="text-gray">Model Context Protocol - открытый стандарт подключения AI к инструментам и данным («USB-C для AI»). Превращает «M инструментов × N сервисов» в «M + N»: сервис пишет один MCP-сервер, его видят все совместимые клиенты.</span>

<b class="text-on-semi-light">Как агент взаимодействует с системой?</b>
<span class="text-gray">Через tool use: вызывает инструменты (чтение/запись файлов, команды, поиск, API), наблюдает реальный результат и реагирует на него в цикле - не угадывает состояние, а узнаёт его.</span>

<b class="text-on-semi-light">Что такое context engineering?</b>
<span class="text-gray">Управление тем, что агент видит в ограниченном окне модели: какие файлы подать, что запомнить, как найти нужное и сжать историю. Новый ключевой навык на смену prompt engineering.</span>

<b class="text-on-semi-light">Какие риски у агентного программирования?</b>
<span class="text-gray">Нужен надзор (агент может ошибиться уверенно), проверка диффов, безопасность (запуск команд - песочница, права), prompt injection через инструменты, стоимость вызовов. Решается guardrails и human-in-the-loop.</span>
