# Эволюция веб-платформы

Как платформа забирает задачи у библиотек: что стало встроенным — модальные окна, всплывающие панели, родительский селектор, контейнерные запросы, вложенность CSS, привязка к якорю, переходы между состояниями, утилиты языка, — как понять, можно ли уже пользоваться возможностью, что такое Baseline и Interop, прогрессивное улучшение и когда библиотека всё ещё нужна. Спрашивают, какие задачи раньше требовали библиотек, что такое Baseline и Interop и нужна ли теперь библиотека. Глубже — почему возможность работает в Chrome, но не «Baseline», почему «широко доступно» наступает через два с половиной года и чего встроенный `<dialog>` даёт бесплатно.

::tldr
- **Платформа догоняет библиотеки:** `<dialog>` и `popover` вместо модальных библиотек, `:has()` и контейнерные запросы вместо JavaScript для стилей, вложенность CSS вместо препроцессора, привязка к якорю вместо расчёта позиций, View Transitions, `structuredClone`, `Object.groupBy`, `Intl` и `Temporal`.
- **Встроенное приходит с поведением, которое трудно повторить:** фокус внутрь и обратно, Escape, верхний слой, закрытие по клику снаружи, доступность — без строчки JavaScript.
- **Baseline отвечает на вопрос «можно ли уже»:** «впервые доступно» — во всех основных браузерах, «широко доступно» — через 30 месяцев после этого. Данные — в пакете `web-features`, на MDN и caniuse.
- **Interop — совместная работа разработчиков браузеров** над одинаковым поведением выбранных областей каждый год.
- **Сначала проверить платформу, потом брать зависимость:** меньше кода и уязвимостей, лучше доступность. Библиотеки остаются для сложных случаев и единого API поверх различий браузеров.
::

## Платформа догоняет

Сквозной пример — магазин: модальное окно оформления, панель фильтров, карточки с картинками и без, подсказка у иконки корзины, переход между каталогом и товаром.

| Раньше — библиотека или JavaScript | Теперь — платформа |
| --- | --- |
| модальные окна с ловушкой фокуса | `<dialog>` и `showModal()` |
| всплывающие меню и панели | атрибут `popover` и `popovertarget` |
| стиль родителя по содержимому | `:has()` |
| адаптивность компонента по своей ширине | контейнерные запросы `@container` |
| вложенность стилей из Sass | вложенность CSS |
| расчёт позиции подсказки | привязка к якорю `anchor-name`, `position-anchor` |
| анимация переходов между состояниями | View Transitions |
| глубокое копирование, группировка | `structuredClone`, `Object.groupBy`, `Array.prototype.at` |
| moment и date-fns для форматирования | `Intl`, `Temporal` |
| axios для простых запросов | `fetch` с `AbortController` |

Подробно о самих возможностях: современный CSS — в [Современном CSS](/content/css/modern-css), браузерные API — в [Браузерных API](/content/web/browser-apis), язык — в [Современном JavaScript](/content/javascript/modern-js). Здесь — сам сдвиг и как принимать решения.

## Что даёт встроенное

В проверке в Chromium каждая возможность работала без библиотеки:

- **`<dialog>`** — после `showModal()` фокус сам перешёл на поле с `autofocus`, диалог совпал с `:modal`, Escape закрыл его, и фокус вернулся на кнопку «Оформить». Повторить это руками — ловушка фокуса, восстановление, блокировка фона, — значит написать маленькую библиотеку;
- **`popover`** — кнопка с `popovertarget` открыла панель фильтров без единой строки JavaScript, а клик снаружи закрыл её;
- **`:has()`** — карточка с картинкой получила `padding: 0`, без картинки — `16px`;
- **контейнерные запросы** — заголовок в контейнере шириной 300 px был 14 px, а после расширения контейнера до 600 px стал 24 px, без изменения окна;
- **вложенность** — `.menu { & .item { … } }` применилась, как в Sass;
- **привязка к якорю** — подсказка «3 товара» встала ровно под корзиной: разница координат — ноль, без расчётов в JavaScript;
- **View Transitions** — `document.startViewTransition` выполнил обновление и анимировал переход (подробно — в [Анимации](/content/ecosystem-libs/animation));
- **`structuredClone`** — глубокая копия с `Date` и `Map`, **`Object.groupBy`** — группировка заказов.

Встроенное обычно ещё и доступно из коробки: верхний слой, фокус, роли и клавиатура реализованы браузером (подробно — в [Доступности](/content/html/accessibility)).

## Baseline

Раньше «можно ли уже» было сверкой таблиц версий. **Baseline** даёт один ответ:

| Статус | Значение |
| --- | --- |
| нет | ещё не во всех основных браузерах |
| впервые доступно | появилось в последних версиях Chrome, Edge, Firefox и Safari на компьютерах и телефонах |
| широко доступно | прошло 30 месяцев с момента «впервые доступно» |

В проверке по данным пакета `web-features`, на котором построены значки Baseline на MDN и caniuse, у `:has()`, контейнерных запросов, вложенности и `<dialog>` дата «широко доступно» ровно на 30 месяцев позже даты «впервые доступно». Например, `:has()` — впервые 19 декабря 2023 года, широко — 19 июня 2026 года.

| Возможность | Статус Baseline |
| --- | --- |
| `<dialog>`, `structuredClone`, контейнерные запросы, `:has()`, вложенность CSS | широко доступно |
| `popover`, View Transitions | впервые доступно |
| привязка к якорю, `Temporal` | нет |

Актуально на ноябрь 2026, `web-features` 3.46. Статус «нет» не значит «нигде не работает»: в проверочном Chromium привязка к якорю работала, а `Temporal` был доступен. Это значит, что в каком-то из основных браузеров возможности пока нет, — и для неё нужен запасной вариант.

Baseline подключают и в инструменты: browserslist умеет цель `baseline widely available`, ESLint — правила по Baseline, а данные `web-features` доступны программно (подробно о целях сборки — в [Транспиляции](/content/advanced-tooling/transpilation)).

## Interop

**Interop** — ежегодный совместный проект разработчиков Chrome, Edge, Firefox и Safari. Они выбирают области, где поведение браузеров расходится или возможность нужна разработчикам, и доводят их до одинакового поведения, измеряя прогресс тестами web-platform-tests. Отсюда же быстрое появление возможностей сразу во всех браузерах: многое из таблицы выше дошло до Baseline благодаря Interop.

Для фронтендера это значит меньше «работает в Chrome, ломается в Safari» — но не ноль: проверка в нескольких движках остаётся (подробно — в [Браузерных движках](/content/web/browser-engines)).

## Прогрессивное улучшение

Новая возможность не обязана работать у всех одинаково, если базовый сценарий работает:

```css
.card { padding: 16px; }
@supports selector(:has(img)) {
  .card:has(img) { padding: 0; }
}
```

```js
if (document.startViewTransition) {
  document.startViewTransition(() => render(next));
} else {
  render(next);   // без анимации, но работает
}
```

Подход: **базовое — для всех, лучшее — где поддерживается**. Проверка возможности — `@supports`, `CSS.supports`, наличие API, — а не версии браузера. Для критичного поведения, которого нет в части браузеров, — полифил или библиотека.

## Когда библиотека всё ещё нужна

- **сложные компоненты** — комбобокс с асинхронным поиском, таблица с виртуализацией, редактор (подробно — в [UI-библиотеках](/content/ecosystem-libs/ui-component-libraries));
- **различия браузеров**, которые платформа ещё не сгладила;
- **возможность не во всех основных браузерах**, а аудитория на них есть;
- **единый API** и удобство команды поверх нескольких встроенных механизмов.

Правило — не «никаких библиотек», а **сначала проверить платформу**: часто нужная возможность уже есть, проще и легче (подробно о цене зависимостей — во [Введении в экосистему](/content/ecosystem-libs/introduction)).

---

## Красные флаги в ответе

- **«Для модального окна нужна библиотека».** `<dialog>` даёт фокус, Escape и верхний слой сам.
- **«Работает в моём Chrome — значит, можно».** Проверяют Baseline и аудиторию, а не свой браузер.
- **«Baseline — это значит работает везде давно».** «Впервые доступно» — только в последних версиях.
- **«Нет в Baseline — значит, нигде не работает».** Часть браузеров уже поддерживает, нужен запасной вариант.
- **«Проверю версию браузера в user agent».** Проверяют саму возможность через `@supports` и наличие API.
- **«Use the platform — значит, без библиотек вообще».** Сложные компоненты и различия браузеров всё ещё требуют их.

## Как спрашивают на собеседовании

::question
Какие задачи раньше требовали библиотек, а теперь встроены?

#answer
Модальные окна и всплывающие панели — `<dialog>` и `popover`, стиль родителя — `:has()`, адаптивность компонента — контейнерные запросы, вложенность стилей, позиционирование подсказок — привязка к якорю, анимация переходов — View Transitions, глубокое копирование и группировка — `structuredClone` и `Object.groupBy`, даты — `Intl` и `Temporal`.

#more
Встроенное часто даёт поведение, которое трудно повторить руками: `<dialog>` переводит фокус внутрь и возвращает его, закрывается по Escape, блокирует фон; `popover` закрывается по клику снаружи — без JavaScript.
::

::question
Что такое Baseline?

#answer
Единый статус готовности возможности: «впервые доступно» — она есть в последних версиях всех основных браузеров на компьютерах и телефонах, «широко доступно» — прошло 30 месяцев с этого момента.

#more
Данные — в пакете `web-features`, значки — на MDN и caniuse. Статус «нет» значит, что в каком-то основном браузере возможности пока нет: её используют как прогрессивное улучшение или с запасным вариантом.
::

::question
Что такое Interop?

#answer
Ежегодный совместный проект разработчиков основных браузеров: выбирают области с расхождениями или нужные разработчикам возможности и доводят поведение до одинакового, измеряя прогресс общими тестами.

#more
Это ускоряет появление возможностей во всех браузерах одновременно и уменьшает различия, но не отменяет проверку в нескольких движках.
::

::question
Как использовать возможность, которая есть не во всех браузерах?

#answer
Прогрессивное улучшение: базовый сценарий работает у всех, улучшение включается при поддержке. Поддержку проверяют самой возможностью — `@supports`, `CSS.supports`, наличием API, — а не версией браузера.

#more
Если поведение критично, нужен полифил или библиотека. Решение принимают по Baseline и реальной аудитории сайта, а не по своему браузеру.
::

::question
Нужны ли ещё библиотеки, если платформа догоняет?

#answer
Да — для сложных компонентов, сглаживания различий браузеров, возможностей, которых ещё нет у части аудитории, и единого API для команды. Но базовые задачи всё чаще решаются встроенным, и это стоит проверять первым.

#more
Меньше зависимостей — меньше бандл, обновлений и уязвимостей, а встроенные компоненты обычно доступнее самописных.
::

## Практика

::practice{title="Модальное окно на 30 килобайт"}
Окно оформления заказа сделано на библиотеке модальных окон: свой портал, ловушка фокуса, блокировка прокрутки. Библиотека весит 30 КБ и иногда теряет фокус при закрытии.

#solution
Встроенный `<dialog>` делает это сам. В проверке после `showModal()` фокус перешёл в поле, Escape закрыл окно, а фокус вернулся на кнопку, которая его открыла.

```html
<button id="checkout">Оформить</button>
<dialog id="checkout-dialog" aria-labelledby="checkout-title">
  <h2 id="checkout-title">Оформление заказа</h2>
  <input name="phone" autofocus>
  <form method="dialog"><button>Закрыть</button></form>
</dialog>
```

```js
document.getElementById('checkout').onclick = () => document.getElementById('checkout-dialog').showModal();
```

```css
dialog::backdrop { background: rgb(0 0 0 / 0.4); }
```

`<dialog>` — «широко доступно» по Baseline. Блокировку прокрутки страницы под окном при необходимости добавляют одной строкой CSS — `body:has(dialog[open]) { overflow: hidden; }`.
::

::practice{title="Подсказка у корзины на привязке к якорю"}
Подсказку «3 товара» под иконкой корзины хотят позиционировать через привязку к якорю вместо JavaScript-библиотеки. Аудитория — все основные браузеры.

#solution
В проверке привязка к якорю в Chromium поставила подсказку ровно под корзиной, но по Baseline она ещё не во всех основных браузерах. Делают прогрессивно: базовое позиционирование для всех, точная привязка — где поддерживается:

```css
.cart { position: relative; }
.tip { position: absolute; top: 100%; left: 0; }       /* работает везде */

@supports (anchor-name: --cart) {
  .cart { anchor-name: --cart; }
  .tip { position: fixed; position-anchor: --cart; top: anchor(bottom); left: anchor(left); }
}
```

Если подсказка должна оставаться видимой у края экрана и переворачиваться, а аудитории без поддержки много, — оставляют библиотеку позиционирования вроде Floating UI до того, как возможность станет Baseline.
::
