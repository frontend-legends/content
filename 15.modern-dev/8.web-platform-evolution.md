# Эволюция веб-платформы

Долгие годы фронтенд тянул библиотеки для того, чего не умел браузер. Теперь **платформа догоняет**: модалки, переходы, родительский селектор, контейнерные запросы - всё это стало **нативным**. Тренд «you might not need a library» и инициативы Baseline/Interop определяют современную разработку.

---

## Платформа догоняет библиотеки

Многое, что раньше требовало зависимостей, теперь есть в браузере:

| Раньше нужна была библиотека | Теперь нативно |
|------------------------------|----------------|
| анимация переходов между состояниями | **View Transitions API** |
| модалки, тултипы, поповеры | **Popover API** + `<dialog>` |
| «родительский» селектор | **`:has()`** |
| адаптивность по компоненту | **Container queries** |
| вложенность стилей (Sass) | **нативный CSS nesting** |
| ленивая загрузка картинок | `loading="lazy"` |
| lodash-утилиты | `structuredClone`, `Object.groupBy`, `Array.at` |
| moment (даты) | `Intl`, **Temporal** |
| axios (базово) | `fetch` + `AbortController` |

```css
/* раньше - только через JS, теперь нативно */
.card:has(img) { padding: 0; }        /* родительский селектор */
@container (min-width: 400px) { ... }  /* запрос по контейнеру, не вьюпорту */
```

> Подробно про современный CSS (`:has`, container queries, nesting, cascade layers, subgrid) - в [главе CSS](/content/css). Здесь важен сам **сдвиг**: платформа берёт на себя то, за что отвечали библиотеки.

## Знаковые новые API

- **View Transitions** - плавные анимированные переходы между состояниями и страницами (включая cross-document) - без библиотек анимации для переходов.
- **Popover API** / **`<dialog>`** - доступные модалки и поповеры с управлением фокусом нативно (меньше нужды в headless-библиотеках для базовых случаев).
- **Container queries** - адаптивность по размеру **контейнера**, а не вьюпорта - то, чего годами не хватало.
- **Scroll-driven animations**, **anchor positioning** - анимации по скроллу и позиционирование относительно якоря - на CSS, без JS.

---

## Baseline

Раньше «можно ли уже использовать фичу» было гаданием по таблицам совместимости. **Baseline** - инициатива, которая чётко определяет, когда возможность **безопасно использовать** во всех основных браузерах.

```
Newly available  - только что во всех основных браузерах
Widely available - доступна 2.5 года, можно использовать без оглядки
```

<b class="text-on-semi-light">Зачем</b> - <span class="text-gray">Baseline даёт единый понятный сигнал «эта фича готова к проду» вместо ручной сверки версий Safari/Chrome/Firefox. MDN и caniuse показывают статус Baseline у каждой возможности - это упрощает решение, нужен ли полифил.</span>

---

## Interop

**Interop** - совместный проект вендоров браузеров (Chrome, Safari, Firefox), которые **согласованно** устраняют расхождения и выпускают важные фичи вместе. Каждый год выбираются приоритетные области, и браузеры доводят их до одинакового поведения.

> Это снижает старую боль «работает в Chrome, ломается в Safari»: вендоры целенаправленно сближают реализации. Платформа становится **предсказуемее**.

---

## Почему это важно

- **Меньше зависимостей** - меньше бандл, меньше поддержки, меньше уязвимостей ([выбор библиотек](/content/ecosystem-libs/introduction)).
- **Больше стандартов** - нативное переживёт смену фреймворков и библиотек.
- **Лучше производительность** - нативные API оптимизированы браузером.
- **Доступность** - нативные `<dialog>`/popover приходят с правильной a11y.

---

## Компромиссы

- **Поддержка браузеров** - новые API нужно сверять с Baseline; иногда нужны полифилы или **прогрессивное улучшение** (работает везде, лучше - где поддержано).
- Библиотеки всё ещё полезны: для сложных кейсов, кросс-браузерных краёв, лучшего DX и единого API поверх разных браузеров.

<b class="text-on-semi-light">Здравый подход</b> - <span class="text-gray">«Use the platform» - не догма «никаких библиотек», а привычка **сначала проверить, нет ли нативного решения**, прежде чем тянуть зависимость. Часто оно уже есть и проще.</span>

## Вопросы на собеседовании

<b class="text-on-semi-light">Какие задачи раньше требовали библиотек, а теперь нативны?</b>
<span class="text-gray">Переходы (View Transitions), модалки/поповеры (Popover API, `<dialog>`), родительский селектор (`:has`), адаптивность по контейнеру (container queries), даты (Intl/Temporal), многие lodash-утилиты (structuredClone, Object.groupBy).</span>

<b class="text-on-semi-light">Что такое Baseline?</b>
<span class="text-gray">Инициатива, определяющая, когда фича безопасно используется во всех основных браузерах: «newly available» (только появилась) и «widely available» (доступна ~2.5 года). Единый сигнал готовности вместо ручной сверки версий.</span>

<b class="text-on-semi-light">Что такое Interop?</b>
<span class="text-gray">Совместный проект вендоров браузеров по согласованному устранению расхождений и выпуску фич вместе. Снижает боль «работает в Chrome, ломается в Safari».</span>

<b class="text-on-semi-light">Что даёт «use the platform»?</b>
<span class="text-gray">Меньше зависимостей и бандла, больше стандартов и долговечности, лучше производительность и встроенная доступность. Привычка сначала проверить нативное решение, прежде чем тянуть библиотеку.</span>

<b class="text-on-semi-light">Нужны ли ещё библиотеки, если платформа догоняет?</b>
<span class="text-gray">Да - для сложных случаев, кросс-браузерных краёв, лучшего DX и единого API. Но многие базовые задачи уже решаются нативно, и это стоит проверять первым делом (с оглядкой на Baseline и полифилы).</span>
