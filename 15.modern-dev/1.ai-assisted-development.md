# ИИ в разработке

Как ИИ-ассистенты меняют работу инженера: виды инструментов, как они получают контекст, как ставить задачу, в чём они сильны, какие ошибки делают и как их ловить, безопасность и приватность, сдвиг навыков и что это значит для собеседований. Спрашивают, в чём ассистенты сильны и опасны, почему их код «правдоподобный, а не правильный» и обесценивает ли ИИ знание основ. Глубже — какие ошибки сгенерированного кода проходят ревью глазами и почему тесты и типы стали важнее, а не наоборот.

::tldr
- **Инструменты — от подсказок к агентам:** автодополнение в редакторе, чат, редактор с правками по нескольким файлам, ревью PR, агенты, которые сами выполняют команды.
- **Качество зависит от контекста и постановки:** конкретная задача с ограничениями, примерами и критерием готовности даёт результат, размытая — размытый код.
- **Модель выдаёт правдоподобное, а не проверенное:** несуществующие и устаревшие API, ошибки на краях, уязвимости. Код выглядит правильно и иногда даже работает на первом примере.
- **Ловят это тесты, типы, линтер и ревью** — те же инструменты, что и для кода людей, но теперь без них нельзя. Принятый, но не понятый код — долг.
- **Основы важнее, а не наоборот:** без понимания нельзя ни поставить задачу, ни проверить ответ. На собеседовании проверяют именно это.
::

---

## Инструменты

Сквозной пример — команда магазина пишет фильтры каталога, миграцию на новую версию React и отчёт по заказам с ассистентом.

| Вид | Что делает | Примеры |
| --- | --- | --- |
| автодополнение | продолжает код по мере набора | GitHub Copilot, подсказки в JetBrains и Zed |
| чат | объясняет, генерирует, отлаживает по запросу | Claude, ChatGPT, Gemini |
| редактор с ИИ | правки по нескольким файлам по описанию | Cursor, Windsurf, Zed |
| агент в терминале или облаке | сам читает код, запускает команды и тесты, готовит PR | Claude Code, Codex, Copilot coding agent |
| ревью PR | комментирует изменения | CodeRabbit, Copilot review, Graphite |

Граница между видами размывается: почти каждый инструмент умеет и подсказывать, и вести диалог, и работать агентом. Как устроены агенты и протокол MCP — в [Агентах и MCP](/content/modern-dev/ai-agents-and-mcp). ИИ как функция продукта — чат, поиск по смыслу — разобран в [ИИ во фронтенде](/content/additional-topics/ai-in-the-frontend).

## Как это работает

В основе — языковая модель, обученная в том числе на огромных объёмах кода. Инструмент собирает **контекст** — открытый файл, соседние файлы, найденные поиском фрагменты репозитория, ошибки, вывод команд, — отправляет его вместе с запросом и получает продолжение или ответ.

Отсюда два следствия:

- **качество зависит от контекста:** модель не знает соглашений проекта, если их ей не показали; файлы с правилами — `CLAUDE.md`, `AGENTS.md`, правила редактора — дают ей эти соглашения;
- **модель знает мир на дату обучения:** API, вышедшие позже, ей неизвестны, а удалённые — она продолжает предлагать.

## Как ставить задачу

Ассистент усиливает ясное мышление и наказывает за расплывчатое.

| Размыто | Конкретно |
| --- | --- |
| «улучши поиск» | «добавь задержку 300 мс к поиску в каталоге и отменяй предыдущий запрос через AbortController» |
| «напиши тесты» | «покрой `applyDiscount` тестами на 0, 9, 10 и 11 штук и на дробную цену» |
| «переведи на React 19» | «замени `ReactDOM.render` на `createRoot` в `main.tsx`, ничего больше не меняй, после — запусти тесты» |

Что работает:

- **контекст** — файлы, типы, пример похожего кода из проекта;
- **ограничения** — стек и версии, «без новых зависимостей», «только этот файл»;
- **критерий готовности** — «тесты проходят», «tsc без ошибок»;
- **маленькие шаги** — одна задача за раз, а не «перепиши модуль»;
- **итерации** — уточнять ответ, а не начинать заново.

---

## Сильные стороны

- **шаблонный код** — формы, типы, конфиги, повторяющиеся компоненты;
- **разбор незнакомого кода** — объяснить модуль, найти, где что вызывается;
- **механические изменения** — переименования, миграции по образцу, кодмоды;
- **черновики тестов и документации**, которые ты доводишь;
- **гипотезы при отладке** — по стеку ошибки и логам;
- **обучение** — объяснить концепцию, сравнить подходы (подробно — в [Непрерывном обучении](/content/final-steps/continuous-learning)).

---

## Правдоподобное, а не правильное

Модель предсказывает вероятное продолжение. Код выглядит правильно, компилируется в голове — и ломается. В проверке каждая из этих «подсказок» встречается в сгенерированном коде:

| Подсказка | Что не так |
| --- | --- |
| `orders.groupBy((o) => o.status)` | такого метода нет — `TypeError`; есть `Object.groupBy` |
| `ReactDOM.render(<App />, root)` | удалён в React 19 — `undefined`; нужен `createRoot` |
| `import { useChat } from 'ai/react'` | путь удалён в новых версиях — `ERR_PACKAGE_PATH_NOT_EXPORTED` |
| `prices.sort()[0]` как минимальная цена | сортировка строковая: `[1200, 300, 90]` остаётся `[1200, 300, 90]` |
| `new Date(2026, 11, 1)` как «1 ноября» | месяцы с нуля — это 1 декабря |
| `` `select … where name = '${name}'` `` | SQL-инъекция: `' or '1'='1` вернул всех пользователей |

Ни одна из них не выглядит подозрительно при беглом чтении. Поэтому риски такие:

- **выдуманные и устаревшие API** — уверенно, с правильным синтаксисом;
- **ошибки на краях** — работает на первом примере, ломается на втором;
- **уязвимости** — склейка SQL и HTML, ключи в клиентском коде, `dangerouslySetInnerHTML`;
- **выдуманные пакеты** — несуществующее имя, которое злоумышленник может занять в реестре; зависимость проверяют перед установкой (подробно — в [Цепочке поставок](/content/security-perfomance/supply-chain-and-vulnerabilities));
- **принятое без понимания** — долг, который проявится в продакшене.

---

## Как ловить

Те же инструменты, что и для кода людей, — но без них работать с ассистентом нельзя. В проверке:

- `tsc` нашёл выдуманный метод сразу: `Property 'groupBy' does not exist on type`;
- тест «самая низкая цена» поймал строковую сортировку: `expected 1200 to be 90`;
- подготовленный запрос с `?` вернул ноль строк на ту же инъекцию.

Практика:

- **ревьюй как чужой PR** — каждую строку, а не «выглядит нормально»;
- **сначала тест или критерий**, потом генерация — и прогон перед принятием (подробно — во [Введении в тестирование](/content/testing-deploying/introduction));
- **проверяй API по документации** установленной версии, а не по памяти модели;
- **просить объяснение** — «почему здесь так?» — и проверять, что оно сходится с кодом;
- **маленькие диффы** — их реально прочитать.

### Приватность и безопасность

- не отправлять секреты, ключи и данные пользователей в сторонний сервис;
- соблюдать правила компании: какие инструменты разрешены, куда уходит код, учится ли на нём провайдер;
- агенту с доступом к терминалу — минимальные права и подтверждение опасных действий (подробно — в [Агентах и MCP](/content/modern-dev/ai-agents-and-mcp)).

## Сдвиг навыков

```text
было:  больше всего времени — написание кода
стало: больше — постановка задачи, чтение, проверка и решение, что принять
```

Когда писать код дёшево, дорожает **суждение**: хороша ли архитектура, где сломается, что проверить, стоит ли это вообще делать. Основы не обесцениваются — они нужны, чтобы направлять ассистента и отличать хороший ответ от плохого. Без них в таблице выше не заметить ни одной ошибки.

### Собеседования

На интервью по-прежнему проверяют понимание: почему компонент перерисовался, что произойдёт в этом коде, как отладить. Часть компаний разрешает ассистента на техническом этапе — тогда смотрят, как кандидат ставит задачу, проверяет ответ и объясняет каждую принятую строку. Кандидат, который не понимает сгенерированный код, виден по первому уточняющему вопросу (подробно — в [Техническом интервью](/content/preparing-for-interviews/technical-interview)).

---

## Красные флаги в ответе

- **«ИИ пишет код, мне остаётся вставить».** Ответственность за корректность и безопасность — на инженере.
- **«Компилируется — значит, правильно».** Ошибки на краях и уязвимости компилируются.
- **«Модель знает актуальный API».** Она знает мир на дату обучения.
- **«Тесты теперь не нужны — модель напишет правильно».** Наоборот: тесты и типы — главный способ поймать ошибки.
- **«Вставлю ключ, чтобы ассистент проверил запрос».** Секреты не отправляют в сторонние сервисы.
- **«Основы больше не нужны».** Без них нельзя проверить ответ.

## Как спрашивают на собеседовании

::question
В чём ИИ-ассистенты сильны, а в чём опасны?

#answer
Сильны в шаблонном коде, объяснении незнакомого кода, механических изменениях, черновиках тестов и гипотезах при отладке. Опасны выдуманными и устаревшими API, ошибками на краях, уязвимостями и тем, что код выглядит правильно.

#more
Пример — `orders.groupBy`, которого нет, `ReactDOM.render`, удалённый в React 19, строковая `sort()` для чисел, склейка SQL. Всё это ловят типы, тесты и ревью.
::

::question
Почему говорят, что ИИ генерирует правдоподобное, а не правильное?

#answer
Модель предсказывает вероятное продолжение, а не проверяет корректность. Код может быть синтаксически верным и работать на первом примере, но содержать ошибку на краях, уязвимость или несуществующий API.

#more
Поэтому критерий готовности задают заранее — тест, проверка типов, — и принимают код только после прогона. Объяснение модели тоже проверяют: оно может не совпадать с тем, что делает код.
::

::question
Как пользоваться ассистентом осознанно?

#answer
Давать конкретную задачу с контекстом, ограничениями и критерием готовности, работать маленькими шагами, ревьюить каждую строку как чужой PR, прогонять тесты и типы и проверять API по документации.

#more
Не отправлять секреты и приватные данные, соблюдать правила компании об инструментах, агентам давать минимальные права. И сохранять способность сделать задачу самому — иначе не оценить результат.
::

::question
Как меняется работа инженера с ИИ?

#answer
Меньше времени на набор кода, больше — на постановку задачи, чтение, проверку и решения. Дорожает суждение: архитектура, компромиссы, умение заметить ошибку.

#more
Тесты, типы и ревью становятся важнее, потому что кода больше, а написан он быстрее, чем прочитан. Хорошие навыки письма — ясная постановка задачи — переходят из документов в работу с ассистентом.
::

::question
Обесценивает ли ИИ знание основ?

#answer
Нет. Основы нужны, чтобы поставить задачу, проверить ответ и заметить ошибку. Без понимания event loop, рендеринга или SQL нельзя отличить правильный сгенерированный код от правдоподобного.

#more
На собеседованиях это видно сразу: кандидат должен объяснить каждую строку решения, а уточняющие вопросы проверяют понимание, а не набор кода.
::

## Практика

::practice{title="Подсказка с отчётом по заказам"}
Ассистент предложил функцию для отчёта, и она «работает» на тестовых данных из одного заказа:

```js
export function report(orders, db, status) {
  const rows = db.prepare(`select * from orders where status = '${status}'`).all();
  const byDay = rows.groupBy((o) => new Date(o.created_at).getMonth() + '-' + new Date(o.created_at).getDate());
  const cheapest = rows.map((o) => o.total).sort()[0];
  return { byDay, cheapest };
}
```

#solution
Четыре ошибки, каждая из таблицы выше: склейка SQL, несуществующий `groupBy`, месяц с нуля в ключе и строковая сортировка. Исправленная версия и то, чем это ловят:

```js
export function report(db, status) {
  const rows = db.prepare('select * from orders where status = ?').all(status);
  const byDay = Object.groupBy(rows, (o) => o.created_at.slice(0, 10));   // 2026-11-15
  const cheapest = Math.min(...rows.map((o) => o.total));
  return { byDay, cheapest };
}
```

В проверке `tsc` нашёл `groupBy`, тест на трёх ценах поймал сортировку, а подготовленный запрос не вернул ни одной строки на инъекцию. Правило: тест с несколькими разными значениями и краями пишут до того, как принимать подсказку.
::

::practice{title="Миграция по подсказке сломала сборку"}
Ассистент перевёл приложение «на последнюю версию» React и AI SDK. Сборка падает: `ReactDOM.render is not a function` и `Package subpath './react' is not defined by "exports"`.

#solution
Модель предложила API из своих обучающих данных, а установлены более новые версии: в React 19 `ReactDOM.render` удалён, а `ai/react` больше не экспортируется. В проверке оба вызова повторили эти ошибки.

```tsx
// main.tsx
import { createRoot } from 'react-dom/client';
createRoot(document.getElementById('root')!).render(<App />);

// Chat.tsx
import { useChat } from '@ai-sdk/react';
```

Для миграций — документация и руководство по обновлению установленной версии, кодмоды от авторов (`npx codemod react/19/...`) и прогон тестов после каждого шага. Ассистенту дают ссылку на руководство и версию из `package.json`, а не просьбу «обнови до последней».
::
