# Производительность

Оптимизация React - это в первую очередь **борьба с лишними ререндерами** и тяжёлыми вычислениями в рендере. Но главное правило: **сначала измерь**. Преждевременная мемоизация усложняет код и часто не ускоряет ничего.

---

## Что вообще тормозит

- Ререндер большого поддерева в ответ на мелкое изменение.
- Дорогие вычисления (сортировка/фильтрация больших массивов) на каждый рендер.
- Рендер длинных списков (тысячи DOM-узлов).
- Слишком большой бандл - долгая загрузка и парсинг JS.

Сам по себе ререндер дёшев и **не означает изменения DOM** (см. [согласование и Fiber](/content/reactjs/reconciliation-and-fiber)). Проблема - когда их много и они тяжёлые.

---

## React.memo

Оборачивает компонент и **пропускает ререндер, если props не изменились** (поверхностное сравнение).

```jsx
const Row = React.memo(function Row({ item }) {
  return <li>{item.name}</li>;
});
```

Теперь `Row` не перерисуется при рендере родителя, если `item` (по ссылке) тот же.

<b class="text-on-semi-light">Почему memo часто «не работает»</b> - <span class="text-gray">Потому что родитель передаёт **новый объект/функцию каждый рендер**: `<Row item={{...}} onClick={() => ...} />`. Новая ссылка ≠ предыдущая → memo считает props изменёнными. Поэтому memo идёт в паре с `useMemo`/`useCallback` для пропсов.</span>

```jsx
// memo бесполезен: style и onClick новые каждый рендер
<Row item={item} style={{ color: 'red' }} onClick={() => select(item)} />

// чинится мемоизацией пропсов
const handleClick = useCallback(() => select(item), [item]);
const style = useMemo(() => ({ color: 'red' }), []);
```

---

## useMemo и useCallback на службе memo

- `useMemo` - стабилизирует **значения** (объекты, массивы, результат вычислений).
- `useCallback` - стабилизирует **функции**.

Их смысл - **сохранить ссылку**, чтобы мемоизированный потомок не перерисовывался, а эффект не перезапускался. Механика - в [продвинутых хуках](/content/reactjs/advanced-hooks).

> Без мемоизированного потребителя `useMemo`/`useCallback` чаще вредят, чем помогают: добавляют память и сравнение зависимостей, не давая выигрыша.

## React Compiler

В React 19 появился **React Compiler** (бывший React Forget) - компилятор, который **автоматически мемоизирует** компоненты и значения на этапе сборки. С ним ручные `React.memo`/`useMemo`/`useCallback` в большинстве случаев не нужны - компилятор расставляет их сам, анализируя зависимости.

<b class="text-on-semi-light">Что отвечать на собесе</b> - <span class="text-gray">Ручная мемоизация - это «оптимизация по требованию» после профайлинга. React Compiler смещает индустрию к автоматической мемоизации, но понимать механику (почему ссылки ломают memo) всё равно нужно.</span>

## Композиция вместо мемоизации

Часто ререндеры лечатся не `memo`, а **структурой**. Два приёма:

**Опустить состояние вниз** - чтобы частое обновление перерисовывало маленький компонент, а не весь экран.

```jsx
// ❌ ввод в поле перерисовывает всё App
// ✅ вынести поле и его state в отдельный компонент SearchBox
```

**Поднять контент наверх через children** - то, что приходит как `children`, не перерисовывается при ререндере обёртки.

```jsx
function Wrapper({ children }) {
  const [n, setN] = useState(0);
  return <div onClick={() => setN(n + 1)}>{children}</div>;
}
// <Wrapper><HeavyTree /></Wrapper> - HeavyTree не ререндерится при изменении n
```

## Code splitting

Не грузить весь JS сразу. `React.lazy` + `Suspense` разбивают бандл и подгружают код по требованию - обычно **по маршрутам**.

```jsx
const Dashboard = lazy(() => import('./Dashboard'));

<Suspense fallback={<Spinner />}>
  <Dashboard />
</Suspense>
```

Это снижает время до интерактивности: пользователь грузит только текущую страницу. Подробнее про загрузку - в [рендеринге](/content/reactjs/rendering-and-hydration).

## Виртуализация списков

Рендерить 10 000 строк в DOM - дорого. **Виртуализация** рендерит только видимые строки (+ небольшой буфер), переиспользуя узлы при скролле.

```jsx
import { useVirtualizer } from '@tanstack/react-virtual';
// рендерим ~20 видимых строк вместо 10 000
```

Библиотеки: `@tanstack/react-virtual`, `react-window`. Спрашивают как решение проблемы «длинный список тормозит».

---

## Профайлинг

Оптимизация без измерения - угадывание. Инструменты:

- **React DevTools Profiler** - показывает, какие компоненты рендерились, как долго и **почему** (включи «Record why each component rendered»).
- **`<Profiler>`** - программно замерить поддерево.
- **Lighthouse / Performance-вкладка** браузера - для метрик загрузки и Core Web Vitals.

```jsx
<Profiler id="List" onRender={(id, phase, actualDuration) => log(id, actualDuration)}>
  <List />
</Profiler>
```

## Отзывчивость через конкурентность

Иногда задача не «меньше рендеров», а «не блокировать ввод». `useTransition`/`useDeferredValue` помечают тяжёлые обновления как несрочные, и React держит интерфейс отзывчивым (см. [продвинутые хуки](/content/reactjs/advanced-hooks)).

---

## Чеклист оптимизации

1. Измерь профайлером - найди реальный источник.
2. Опусти состояние вниз / подними контент в `children`.
3. Мемоизируй (`memo` + стабильные props) точечно там, где доказано.
4. Виртуализируй длинные списки.
5. Разбей бандл по маршрутам (`lazy`).
6. Тяжёлое и несрочное - в `useTransition`.

## Вопросы на собеседовании

<b class="text-on-semi-light">Что делает React.memo?</b>
<span class="text-gray">Пропускает ререндер компонента, если его props не изменились по поверхностному сравнению. Помогает, только если props стабильны по ссылке.</span>

<b class="text-on-semi-light">Почему memo часто не срабатывает?</b>
<span class="text-gray">Родитель передаёт новые объекты/функции каждый рендер - новые ссылки ломают сравнение. Нужны `useMemo`/`useCallback` для пропсов.</span>

<b class="text-on-semi-light">Когда НЕ нужно мемоизировать?</b>
<span class="text-gray">Когда вычисление дешёвое и нет мемоизированного потребителя. Преждевременная мемоизация усложняет код и тратит память без выигрыша.</span>

<b class="text-on-semi-light">Как ускорить длинный список?</b>
<span class="text-gray">Виртуализация - рендерить только видимые строки (react-window, react-virtual).</span>

<b class="text-on-semi-light">Как уменьшить ререндеры без memo?</b>
<span class="text-gray">Опустить состояние ниже к месту использования и поднять тяжёлый контент в `children`, который не перерисовывается при обновлении обёртки.</span>

<b class="text-on-semi-light">Что меняет React Compiler?</b>
<span class="text-gray">Автоматически мемоизирует компоненты и значения при сборке, делая ручные memo/useMemo/useCallback во многом избыточными.</span>
