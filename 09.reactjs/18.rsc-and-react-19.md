# Server Components и React 19

**React Server Components (RSC)** - самый крупный сдвиг в модели React со времён хуков, и горячая тема собеседований 2025–2026. Идея: часть компонентов выполняется **только на сервере** и никогда не попадает в браузер. React 19 сделал RSC и связанные API стабильными.

---

## Что такое Server Components

Обычный (клиентский) компонент в итоге грузится в браузер как JS. **Серверный компонент выполняется на сервере, а в браузер уходит только результат** - его код в бандл не попадает.

```jsx
// Server Component (по умолчанию в RSC-окружении)
async function ProductPage({ id }) {
  const product = await db.products.find(id); // прямой доступ к БД - на сервере!
  return <article><h1>{product.title}</h1></article>;
}
```

Преимущества:

- **Ноль JS в бандле** за такой компонент - меньше кода у клиента.
- **Прямой доступ к данным** - БД, файловая система, внутренние API без отдельного REST-слоя.
- **Секреты остаются на сервере** - ключи и токены не утекают в бандл.
- **Async/await прямо в компоненте** - данные грузятся на сервере без `useEffect`.

## Server vs Client компоненты

| | Server Component | Client Component |
|--|------------------|------------------|
| Где выполняется | только сервер | сервер (SSR) + клиент |
| Попадает в бандл | нет | да |
| State / хуки / эффекты | ❌ | ✅ |
| Обработчики событий (`onClick`) | ❌ | ✅ |
| Доступ к БД/секретам | ✅ | ❌ |
| Доступ к `window`/браузеру | ❌ | ✅ |

Граница задаётся директивой **`"use client"`** в начале файла - всё в этом файле и импортируемое им становится клиентским.

```jsx
'use client';
import { useState } from 'react';

export function LikeButton() {           // интерактивность - клиентский
  const [liked, setLiked] = useState(false);
  return <button onClick={() => setLiked(!liked)}>{liked ? '♥' : '♡'}</button>;
}
```

<b class="text-on-semi-light">Модель композиции</b> - <span class="text-gray">Серверные компоненты рендерят клиентские и **передают им props** (включая JSX через `children`). Но клиентский компонент не может импортировать серверный - граница односторонняя. Типичный приём: серверная обёртка с данными, внутри - островки интерактивности «use client».</span>

## RSC ≠ SSR

Частая путаница на собесе.

- **SSR** - рендерит **клиентские** компоненты в HTML-строку на сервере, чтобы ускорить первый показ; этот код **всё равно** грузится в браузер для гидратации.
- **RSC** - компоненты, которые **в принципе** не попадают в браузер. Результат сериализуется в специальный **RSC-payload** (описание дерева), а не в HTML.

> SSR про *когда* рендерить (на сервере для скорости). RSC про *где живёт компонент* (только на сервере, без отправки кода клиенту). Они дополняют друг друга, а не заменяют.

## Server Actions

Директива **`"use server"`** помечает функцию, которая выполняется **на сервере**, но вызывается из клиента - встроенный способ делать мутации без ручного API-эндпоинта.

```jsx
async function createTodo(formData) {
  'use server';
  await db.todos.create({ text: formData.get('text') });
}

// форма вызывает серверное действие напрямую
<form action={createTodo}>
  <input name="text" />
  <button type="submit">Добавить</button>
</form>
```

`<form action={...}>` теперь принимает функцию - это **Actions**, новая модель работы с формами и асинхронными мутациями.

---

## Хуки React 19 для Actions

**`useActionState`** - управляет состоянием действия (результат, pending) вокруг формы.

```jsx
const [state, formAction, isPending] = useActionState(createTodo, null);
<form action={formAction}>...</form>
```

**`useFormStatus`** - читает статус родительской формы из вложенного компонента (например, дизейблить кнопку при отправке).

```jsx
function SubmitButton() {
  const { pending } = useFormStatus();
  return <button disabled={pending}>{pending ? '...' : 'OK'}</button>;
}
```

**`useOptimistic`** - оптимистичное состояние: показать результат сразу, откатить при ошибке.

```jsx
const [optimisticTodos, addOptimistic] = useOptimistic(todos);
// показываем новый todo мгновенно, до ответа сервера
```

## Безопасность Server Actions

Критичный senior-нюанс. Server Action - это **публичный HTTP-эндпоинт**, даже если выглядит как обычная функция. Кто угодно может вызвать его напрямую с любыми аргументами.

```jsx
async function deletePost(id) {
  'use server';
  // ❌ нет проверки прав - любой удалит любой пост
  await db.posts.delete(id);
}
```

<b class="text-on-semi-light">Правила</b> - <span class="text-gray">Внутри **каждого** Server Action заново проверяй авторизацию и валидируй вход (как в любом API): права текущего пользователя, схема аргументов (Zod), ничего из клиента не считается доверенным. Не полагайся на то, что UI «не покажет кнопку». Аргументы и результат должны быть **сериализуемыми**. Это та же истина «не доверяй клиенту» из [безопасности](/content/security-perfomance/security-fundamentals) - просто новая поверхность атаки.</span>

## use()

Новый «читатель» ресурсов. В отличие от хуков, `use()` **можно вызывать условно** и в циклах.

```jsx
function Comments({ commentsPromise }) {
  const comments = use(commentsPromise); // приостановит компонент через Suspense
  return comments.map((c) => <p key={c.id}>{c.text}</p>);
}

// также умеет читать контекст условно
const theme = use(ThemeContext);
```

## Прочие изменения React 19

- **`ref` как обычный prop** - `forwardRef` больше не нужен и помечен устаревшим (см. [refs](/content/reactjs/refs-portals-a11y)).
- **`<Context>` как провайдер** - можно писать `<Ctx value={...}>` вместо `<Ctx.Provider>`.
- **Метаданные документа** - `<title>`, `<meta>`, `<link>` можно рендерить прямо в компонентах, React поднимет их в `<head>`.
- **Preload-API** (`preload`, `preinit`) - управление предзагрузкой ресурсов.
- **Улучшенные ошибки гидратации** - понятный дифф вместо простыни.
- **React Compiler** - автоматическая мемоизация (см. [производительность](/content/reactjs/performance)).

## Вопросы на собеседовании

<b class="text-on-semi-light">Что такое React Server Components?</b>
<span class="text-gray">Компоненты, выполняющиеся только на сервере; их код не попадает в браузерный бандл. Дают нулевой JS, прямой доступ к данным и сохранность секретов, но без state/эффектов/событий.</span>

<b class="text-on-semi-light">Чем RSC отличается от SSR?</b>
<span class="text-gray">SSR рендерит клиентские компоненты в HTML, но их JS всё равно грузится для гидратации. RSC-компоненты в браузер не отправляются вообще; их результат сериализуется в RSC-payload.</span>

<b class="text-on-semi-light">Что значит директива "use client"?</b>
<span class="text-gray">Помечает файл как клиентский - его компоненты гидратируются и могут использовать state, эффекты, события. Граница между серверной и клиентской частью.</span>

<b class="text-on-semi-light">Что такое Server Actions?</b>
<span class="text-gray">Функции с `"use server"`, выполняемые на сервере, но вызываемые из клиента (например, через `<form action>`). Мутации без ручного API-эндпоинта.</span>

<b class="text-on-semi-light">Зачем нужен useOptimistic?</b>
<span class="text-gray">Показать ожидаемый результат действия мгновенно, до ответа сервера, и автоматически откатить при ошибке - встроенные оптимистичные обновления.</span>

<b class="text-on-semi-light">Чем use() отличается от обычных хуков?</b>
<span class="text-gray">`use()` можно вызывать условно и в циклах; он читает промис (с интеграцией в Suspense) или контекст.</span>
