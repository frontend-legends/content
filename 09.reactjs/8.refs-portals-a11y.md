# Refs, порталы и доступность

Иногда декларативной модели мало: нужно дотянуться до реального DOM-узла (фокус, измерения, медиа), отрендерить что-то вне текущего поддерева (модалка) или позаботиться о доступности. Это «императивная граница» React - refs, порталы и работа с a11y.

---

## Refs для доступа к DOM

`useRef` + атрибут `ref` дают ссылку на реальный DOM-узел после монтирования.

```jsx
function SearchInput() {
  const inputRef = useRef(null);

  useEffect(() => {
    inputRef.current.focus(); // императивно фокусируем
  }, []);

  return <input ref={inputRef} />;
}
```

`ref.current` равен `null` до монтирования и DOM-узлу после. Это «escape hatch» - использовать, когда декларативно задачу не решить (фокус, скролл, измерения, интеграция с не-React библиотеками).

<b class="text-on-semi-light">Ref vs state</b> - <span class="text-gray">Ref хранит значение, которое **не должно вызывать ререндер** (DOM-узел, id таймера, предыдущее значение). State - то, от чего зависит UI. Меняешь ref - картинка не перерисовывается.</span>

## Передача ref в компонент

Свой компонент не может напрямую принять `ref` - это не обычный prop. Раньше для этого был `forwardRef`.

```jsx
// React 18 и раньше
const Input = forwardRef(function Input({ label }, ref) {
  return <input ref={ref} aria-label={label} />;
});
```

<b class="text-on-semi-light">React 19</b> - <span class="text-gray">`ref` можно принимать как обычный prop функционального компонента - `forwardRef` больше не нужен (и постепенно объявляется устаревшим).</span>

```jsx
// React 19
function Input({ label, ref }) {
  return <input ref={ref} aria-label={label} />;
}
```

## useImperativeHandle

Позволяет компоненту отдать наружу **не сам DOM-узел, а кастомный императивный API**.

```jsx
function Modal({ ref }) {
  const dialogRef = useRef(null);
  useImperativeHandle(ref, () => ({
    open: () => dialogRef.current.showModal(),
    close: () => dialogRef.current.close(),
  }));
  return <dialog ref={dialogRef}>...</dialog>;
}

// родитель: modalRef.current.open()
```

> Используй редко. Императивный API ломает декларативность; обычно лучше управлять через props/состояние. Оправдан для виджетов вроде модалок, плееров, форм с `focus()`.

## Порталы

`createPortal` рендерит детей в **другой DOM-узел**, не там, где компонент стоит в дереве React.

```jsx
import { createPortal } from 'react-dom';

function Modal({ children }) {
  return createPortal(
    <div className="overlay">{children}</div>,
    document.body // физически рендерим в body
  );
}
```

**Зачем:** модалки, тултипы, дропдауны, тосты - элементы, которые визуально должны быть поверх всего и не обрезаться родительским `overflow: hidden` или `z-index`-контекстом.

<b class="text-on-semi-light">Важная тонкость про события</b> - <span class="text-gray">Хотя узел физически в `body`, в **дереве React** портал остаётся ребёнком своего компонента. Поэтому события всплывают по React-дереву, а не по DOM: клик внутри модалки «увидит» обработчик родителя, даже если в DOM модалка лежит в `body`. Контекст тоже работает.</span>

## Доступность (a11y)

React рендерит обычный DOM, поэтому доступность - это в первую очередь **семантический HTML**. Но есть React-специфика, которую спрашивают.

### Семантика вместо div

```jsx
// ❌ div с onClick - не доступен с клавиатуры, не читается скринридером
<div onClick={submit}>Отправить</div>

// ✅ нативный button - фокус, Enter/Space, роль - бесплатно
<button onClick={submit}>Отправить</button>
```

### ARIA-атрибуты

В JSX ARIA пишется как в HTML (через дефис), в отличие от camelCase-атрибутов:

```jsx
<button aria-label="Закрыть" aria-expanded={isOpen} aria-controls="menu">×</button>
```

### Управление фокусом

В SPA фокус не сбрасывается сам. После открытия модалки фокус переводят внутрь, после закрытия - возвращают на триггер; в модалке фокус «запирают» (focus trap), чтобы Tab не уходил на фон.

```jsx
function Modal({ onClose }) {
  const ref = useRef(null);
  useEffect(() => {
    const prev = document.activeElement; // запомнили, откуда пришли
    ref.current.focus();
    return () => prev?.focus();          // вернули фокус при закрытии
  }, []);
  return <div ref={ref} role="dialog" aria-modal="true" tabIndex={-1}>...</div>;
}
```

> На практике focus trap, `aria-modal`, обработку Esc берут на себя доступные примитивы - Radix UI, React Aria, Headless UI. Писать самому редко стоит.

### Подписи и формы

Каждому полю - подпись через `htmlFor`/`id` (в JSX `htmlFor`, не `for`):

```jsx
<label htmlFor="email">Email</label>
<input id="email" type="email" />
```

Подробнее про семантику и ARIA - в главе [HTML](/content/html). Здесь важно запомнить, что React не делает приложение доступным автоматически - это ответственность разработчика.

## Вопросы на собеседовании

<b class="text-on-semi-light">Когда использовать ref вместо state?</b>
<span class="text-gray">Когда значение не влияет на рендер: DOM-узел, id таймера, предыдущее значение, мутабельный «ящик». Изменение ref не вызывает ререндер.</span>

<b class="text-on-semi-light">Что изменилось с ref в React 19?</b>
<span class="text-gray">`ref` можно принимать как обычный prop функционального компонента; `forwardRef` больше не обязателен и считается устаревшим.</span>

<b class="text-on-semi-light">Зачем нужен createPortal?</b>
<span class="text-gray">Отрендерить элемент в другой DOM-узел (обычно body), чтобы модалка/тултип не обрезались `overflow` и `z-index` родителя.</span>

<b class="text-on-semi-light">Как всплывают события из портала?</b>
<span class="text-gray">По дереву React, а не по DOM. Хотя узел физически в body, событие дойдёт до React-родителя портала.</span>

<b class="text-on-semi-light">Что нужно для доступной модалки?</b>
<span class="text-gray">`role="dialog"`/`aria-modal`, перевод фокуса внутрь, возврат фокуса на триггер при закрытии, focus trap, закрытие по Esc. Обычно через Radix/React Aria.</span>

<b class="text-on-semi-light">Делает ли React приложение доступным автоматически?</b>
<span class="text-gray">Нет. Доступность - это семантический HTML, ARIA и управление фокусом, которые пишет разработчик.</span>
