# Механика хуков

**Хуки** - это функции, которые «подцепляют» функциональный компонент к возможностям React: состоянию, эффектам, контексту. Появились в React 16.8 (2019) и заменили классы как основной способ работы с состоянием. На собесе важно понимать не список хуков, а **как они устроены** - почему есть правила и откуда берутся баги с замыканиями.

---

## Зачем понадобились хуки

До хуков состояние жило только в классах, а переиспользовать логику между компонентами приходилось через HOC и render props - это давало «wrapper hell» и размазывало логику. Хуки решили три проблемы:

- **Переиспользование логики** - через кастомные хуки, без обёрток.
- **Связность** - логика группируется по смыслу, а не растаскивается по методам жизненного цикла.
- **Функции вместо классов** - нет `this`, нет путаницы с биндингом.

---

## Правила хуков

Их всего два, но они не стилистические - на них держится вся механика.

1. **Вызывать только на верхнем уровне.** Не внутри условий, циклов, вложенных функций.
2. **Вызывать только из React-функций** - компонентов или других хуков.

```jsx
// ❌ Нельзя - хук в условии
function Bad({ show }) {
  if (show) {
    const [x, setX] = useState(0); // сломает порядок вызовов
  }
}

// ✅ Хук всегда вызывается, условие - внутри
function Good({ show }) {
  const [x, setX] = useState(0);
  if (show) { /* ... */ }
}
```

## Как хуки хранят состояние

Вот ключ к пониманию правил. React **не знает имён** твоих переменных. Он связывает состояние с хуком по **порядку вызова**.

Каждый компонент (точнее, его Fiber-узел) хранит список хуков. При первом рендере React создаёт ячейки по порядку, при последующих - читает их в том же порядке.

```jsx
function Form() {
  const [name, setName] = useState('');   // хук #1
  const [age, setAge] = useState(0);      // хук #2
  useEffect(() => {}, []);                // хук #3
}
```

Упрощённая модель того, что происходит внутри:

```js
let hooks = [];      // список ячеек для этого компонента
let cursor = 0;      // указатель, сбрасывается перед каждым рендером

function useState(initial) {
  const i = cursor++;
  hooks[i] = hooks[i] ?? initial;        // первый рендер - инициализация
  const setState = (v) => { hooks[i] = v; rerender(); };
  return [hooks[i], setState];
}
```

<b class="text-on-semi-light">Теперь понятно правило</b> - <span class="text-gray">Если вызвать хук в условии, на одном рендере он будет под индексом 1, на другом - его пропустят, и индексы «съедут». React свяжет `age` с ячейкой `name`. Поэтому хуки всегда вызываются в одном и том же порядке.</span>

> На самом деле хуки хранятся не в массиве, а в связном списке на Fiber-узле - но модель «по порядку вызова» точна.

## Замыкания и stale state

Самая частая ловушка хуков. Каждый рендер создаёт **новые** функции, которые «замыкают» значения состояния **этого** рендера. Если функция переживает рендер (таймер, подписка), она видит **устаревшее** значение.

```jsx
function Timer() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      console.log(count); // всегда 0!
      setCount(count + 1); // всегда setCount(0 + 1)
    }, 1000);
    return () => clearInterval(id);
  }, []); // пустые зависимости - эффект «заморозил» count = 0
}
```

Интервал создан один раз, в рендере где `count === 0`, и навсегда замкнул этот ноль.

**Решения:**

```jsx
// 1. Функциональный апдейтер - не зависит от внешнего count
setCount((c) => c + 1);

// 2. Указать count в зависимостях (эффект пересоздастся)
useEffect(() => { /* ... */ }, [count]);

// 3. useRef для «всегда актуального» значения
const countRef = useRef(count);
countRef.current = count;
```

> Stale closure - не баг React, а следствие того, как работают замыкания в JS. Хуки просто делают это заметным.

---

## Корректность массива зависимостей

Зависимости (`[deps]`) у `useEffect`/`useMemo`/`useCallback` говорят React, когда пересчитать. Главное правило: **в зависимостях должно быть всё реактивное, что используется внутри** (props, state, функции из рендера).

```jsx
// ❌ userId используется, но не в зависимостях - эффект не среагирует на смену пользователя
useEffect(() => { fetchUser(userId); }, []);

// ✅
useEffect(() => { fetchUser(userId); }, [userId]);
```

<b class="text-on-semi-light">Линтер `exhaustive-deps`</b> - <span class="text-gray">Правило ESLint `react-hooks/exhaustive-deps` подсказывает пропущенные зависимости. Не отключай его «чтобы не пересоздавалось» - это маскирует баг. Если зависимость лишняя, лечи причину (вынеси функцию, используй апдейтер), а не глуши предупреждение.</span>

## useRef как «ящик» вне рендера

`useRef` даёт объект `{ current }`, который **сохраняется между рендерами** и **не вызывает ререндер** при изменении. Два применения:

```jsx
// 1. Ссылка на DOM
const inputRef = useRef(null);
<input ref={inputRef} />;

// 2. Мутабельное значение, которое не должно триггерить рендер
const latest = useRef(value);
latest.current = value; // всегда актуально, без ререндера
```

Это и есть решение проблемы stale closure: ref читается в момент вызова, а не замыкается. Подробнее про `useRef` и DOM - в [refs и порталах](/content/reactjs/refs-portals-a11y).

## Кастомные хуки

Кастомный хук - это функция с префиксом `use`, которая вызывает другие хуки. Так переиспользуют **логику** (не состояние - у каждого вызова своё состояние).

```jsx
function useToggle(initial = false) {
  const [on, setOn] = useState(initial);
  const toggle = useCallback(() => setOn((v) => !v), []);
  return [on, toggle];
}

// использование
const [isOpen, toggleOpen] = useToggle();
```

> Два компонента, использующие один кастомный хук, **не делят состояние** - они делят логику. Каждый получает свой изолированный экземпляр. Глубже - в [продвинутых хуках](/content/reactjs/advanced-hooks).

## Вопросы на собеседовании

<b class="text-on-semi-light">Почему хуки нельзя вызывать в условиях и циклах?</b>
<span class="text-gray">React связывает состояние с хуком по порядку вызова. Условный вызов ломает порядок, и состояние «съезжает» на другой хук.</span>

<b class="text-on-semi-light">Как React понимает, какому useState принадлежит какое значение?</b>
<span class="text-gray">По индексу/порядку вызова в рамках рендера. Хуки хранятся в связном списке на Fiber-узле компонента.</span>

<b class="text-on-semi-light">Что такое stale closure и как с ним бороться?</b>
<span class="text-gray">Функция из старого рендера замкнула устаревшее состояние. Лечится функциональным апдейтером, правильными зависимостями или `useRef` с актуальным значением.</span>

<b class="text-on-semi-light">Зачем нужен массив зависимостей и правило exhaustive-deps?</b>
<span class="text-gray">Он говорит React, когда пересчитать эффект/мемо. В зависимостях должно быть всё реактивное, что используется внутри, иначе получаем устаревшие данные или пропущенные обновления.</span>

<b class="text-on-semi-light">Делят ли состояние компоненты с одним кастомным хуком?</b>
<span class="text-gray">Нет. Кастомный хук переиспользует логику, но состояние у каждого вызова своё, изолированное.</span>

<b class="text-on-semi-light">Чем `useRef` отличается от `useState`?</b>
<span class="text-gray">`useRef` сохраняет значение между рендерами, но его изменение не вызывает ререндер. `useState` вызывает. Ref - для DOM и для значений «вне рендера».</span>
