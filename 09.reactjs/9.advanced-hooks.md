# Продвинутые хуки

Помимо `useState`/`useEffect` есть набор хуков для сложного состояния, мемоизации, конкурентности и интеграции с внешними хранилищами. Их знание - маркер уверенного middle+/senior.

---

## useReducer

Альтернатива `useState` для **сложного состояния со связанными переходами**. Логика обновления выносится в чистую функцию-редьюсер.

```jsx
function reducer(state, action) {
  switch (action.type) {
    case 'increment': return { count: state.count + 1 };
    case 'set':       return { count: action.payload };
    case 'reset':     return { count: 0 };
    default:          throw new Error('unknown action');
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });
  return <button onClick={() => dispatch({ type: 'increment' })}>{state.count}</button>;
}
```

<b class="text-on-semi-light">useState или useReducer?</b> - <span class="text-gray">`useState` - для независимых простых значений. `useReducer` - когда следующее состояние сложно зависит от предыдущего, переходов много, или их хочется протестировать отдельно (редьюсер - чистая функция). Плюс `dispatch` стабилен по ссылке - удобно прокидывать через контекст.</span>

---

## useMemo

Кеширует **результат вычисления** между рендерами. Пересчитывает только при изменении зависимостей.

```jsx
const visibleItems = useMemo(
  () => items.filter((i) => i.matches(query)),
  [items, query]
);
```

Нужен в двух случаях: дорогое вычисление или **стабильная ссылка** на объект/массив, который идёт в зависимости другого хука или в мемоизированный компонент.

---

## useCallback

Частный случай `useMemo` для функций: кеширует **саму функцию**, сохраняя её ссылку между рендерами.

```jsx
const handleClick = useCallback(() => {
  doSomething(id);
}, [id]);
```

`useCallback(fn, deps)` ≡ `useMemo(() => fn, deps)`.

<b class="text-on-semi-light">Зачем стабильная ссылка</b> - <span class="text-gray">Каждый рендер создаёт новую функцию. Если передать её в `React.memo`-компонент или в зависимости `useEffect`, новая ссылка каждый раз «ломает» мемоизацию/перезапускает эффект. `useCallback` это чинит.</span>

> Без мемоизированного потребителя `useCallback`/`useMemo` бесполезны - они сами не ускоряют. Подробнее, когда они реально нужны, - в [производительности](/content/reactjs/performance). А **React Compiler** (React 19) умеет расставлять мемоизацию автоматически, делая ручные `useMemo`/`useCallback` во многом ненужными.

## useId

Генерирует **стабильный уникальный id**, одинаковый на сервере и клиенте - для связки `label`/`input`, `aria-describedby` и т.п.

```jsx
function Field({ label }) {
  const id = useId();
  return (
    <>
      <label htmlFor={id}>{label}</label>
      <input id={id} />
    </>
  );
}
```

> Не используй для `key` в списках. `useId` - про доступность и стабильность id между SSR и гидратацией (иначе будет mismatch).

---

## useTransition

Помечает обновление состояния как **несрочное**. React сначала отрисует срочное (например, ввод в поле), а тяжёлый ререндер отложит, не блокируя интерфейс.

```jsx
const [isPending, startTransition] = useTransition();

function handleChange(e) {
  setQuery(e.target.value);            // срочно: поле реагирует мгновенно
  startTransition(() => {
    setResults(search(e.target.value)); // несрочно: можно прервать/отложить
  });
}
// isPending - показать спиннер на время перехода
```

Это часть **конкурентного рендеринга**: React 18+ умеет прерывать несрочный рендер, если пришло что-то важнее.

---

## useDeferredValue

Тот же эффект, но «снаружи»: возвращает **отложенную** версию значения, отстающую при быстрых изменениях.

```jsx
const deferredQuery = useDeferredValue(query);
const results = useMemo(() => search(deferredQuery), [deferredQuery]); // считается по «отстающему» query
```

<b class="text-on-semi-light">useTransition vs useDeferredValue</b> - <span class="text-gray">`useTransition` оборачивает **обновление, которое ты сам инициируешь**. `useDeferredValue` откладывает **значение, которое тебе пришло** (например, prop), когда обернуть сам сеттер нельзя.</span>

---

## useSyncExternalStore

Хук для **подписки на внешние хранилища** (Redux, Zustand, браузерные API). Решает проблему **tearing** - когда при конкурентном рендеринге разные части UI видят разные версии внешних данных.

```jsx
const width = useSyncExternalStore(
  (cb) => { window.addEventListener('resize', cb); return () => window.removeEventListener('resize', cb); },
  () => window.innerWidth,   // снимок для клиента
  () => 1024                 // снимок для сервера (SSR)
);
```

> Это API «для авторов библиотек». В обычном коде ты его почти не пишешь, но стейт-менеджеры используют его внутри. Знать стоит - спрашивают про tearing.

---

## useImperativeHandle

Позволяет компоненту отдать наружу через `ref` **кастомный императивный API** вместо самого DOM-узла.

```jsx
function Modal({ ref }) {            // React 19: ref как обычный prop (раньше - forwardRef)
  const dialogRef = useRef(null);
  useImperativeHandle(ref, () => ({
    open: () => dialogRef.current.showModal(),
    close: () => dialogRef.current.close(),
  }));
  return <dialog ref={dialogRef}>...</dialog>;
}
// родитель: modalRef.current.open()
```

<b class="text-on-semi-light">Когда использовать</b> - <span class="text-gray">Редко. Императивный API ломает декларативность - обычно лучше управлять через props/состояние. Оправдан для виджетов (модалки, плееры, управление фокусом), где родителю нужно «приказать» действие. Подробнее про refs - в [refs и порталах](/content/reactjs/refs-portals-a11y).</span>

## Кастомные хуки - композиция

Кастомные хуки - главный способ переиспользования логики. Они комбинируют встроенные хуки и друг друга.

```jsx
function useDebouncedValue(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);
  return debounced;
}

// использование
const query = useDebouncedValue(input, 500);
```

**Конвенции:** имя начинается с `use`; возвращай кортеж `[value, setter]` (как `useState`) для пары или объект для нескольких значений; не вызывай условно.

## Вопросы на собеседовании

<b class="text-on-semi-light">Когда useReducer лучше useState?</b>
<span class="text-gray">Сложное состояние со связанными переходами, много действий, желание вынести логику в тестируемую чистую функцию, стабильный dispatch для контекста.</span>

<b class="text-on-semi-light">В чём разница useMemo и useCallback?</b>
<span class="text-gray">`useMemo` кеширует результат вычисления, `useCallback` - саму функцию. `useCallback(fn, d)` это `useMemo(() => fn, d)`.</span>

<b class="text-on-semi-light">useTransition vs useDeferredValue?</b>
<span class="text-gray">Оба помечают работу как несрочную. `useTransition` оборачивает обновление, которое инициируешь сам; `useDeferredValue` откладывает уже полученное значение.</span>

<b class="text-on-semi-light">Что такое tearing и при чём тут useSyncExternalStore?</b>
<span class="text-gray">Tearing - когда при конкурентном рендере разные части UI видят разные версии внешнего стора. `useSyncExternalStore` даёт консистентный снимок, поэтому его используют стейт-менеджеры.</span>

<b class="text-on-semi-light">Зачем useId?</b>
<span class="text-gray">Стабильный уникальный id, совпадающий на сервере и клиенте, - для связки label/input и ARIA без hydration mismatch.</span>

<b class="text-on-semi-light">Что меняет React Compiler для useMemo/useCallback?</b>
<span class="text-gray">Он автоматически мемоизирует компоненты и значения на этапе компиляции, делая большую часть ручной мемоизации ненужной.</span>
