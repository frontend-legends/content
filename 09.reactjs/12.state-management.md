# Управление состоянием

Вопрос «какой стейт-менеджер выбрать?» на собесе - это проверка, понимаешь ли ты, что состояние **бывает разным**. Главный senior-инсайт: большая часть того, что называют «глобальным состоянием», - это на самом деле **серверные данные**, которым стейт-менеджер не нужен.

---

## Таксономия состояния

Прежде чем выбирать инструмент, классифицируй состояние:

| Тип | Что это | Чем управлять |
|-----|---------|-----------|
| **Local UI state** | открыт ли дропдаун, значение поля, активный таб | `useState`/`useReducer` |
| **Server state** | данные с бэкенда: список товаров, профиль | React Query / SWR |
| **Global client state** | тема, авторизация, корзина, фичефлаги | Context / стор |
| **URL state** | фильтры, страница, поисковый запрос | роутер / query params |

<b class="text-on-semi-light">Ключевая мысль</b> - <span class="text-gray">Server state - это не состояние, а **кэш** удалённых данных: он асинхронный, устаревает, шарится между вкладками. Пытаться держать его в Redux вручную (loading/error/data) - переизобретать кэш. Для него есть [React Query/SWR](/content/reactjs/data-fetching). После выноса server state в нужный инструмент «глобального состояния» часто почти не остаётся.</span>

---

## Лестница решений

Не начинай с Redux. Поднимайся по сложности только когда упёрся:

1. **`useState`/`useReducer`** - локальное состояние компонента.
2. **Lifting state up** - общее состояние для нескольких компонентов.
3. **Context** - редко меняющиеся глобальные данные (тема, юзер). Помни про ререндеры всех потребителей.
4. **Стейт-менеджер** - когда состояние большое, часто меняется и нужны точечные подписки (селекторы).

## Redux Toolkit (RTK)

Стандарт «классического» Redux сегодня. Старый Redux ругали за бойлерплейт - RTK его убирает: `createSlice` генерирует экшены и редьюсеры, внутри можно писать «мутабельно» (Immer).

```js
import { createSlice, configureStore } from '@reduxjs/toolkit';

const counter = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: (state) => { state.value += 1; }, // Immer: «мутация» безопасна
    addBy: (state, action) => { state.value += action.payload; },
  },
});

export const { increment, addBy } = counter.actions;
export const store = configureStore({ reducer: { counter: counter.reducer } });
```

```jsx
const value = useSelector((s) => s.counter.value); // подписка на срез
const dispatch = useDispatch();
dispatch(increment());
```

<b class="text-on-semi-light">Плюсы</b> - <span class="text-gray">Предсказуемость (единый стор, чистые редьюсеры), мощный DevTools с time-travel, middleware, **RTK Query** для серверных данных. **Минус** - всё ещё многословнее лёгких аналогов, обычно избыточен для небольших приложений.</span>

## Zustand

Минималистичный стор на хуках. Без провайдеров, без бойлерплейта.

```js
import { create } from 'zustand';

const useStore = create((set) => ({
  count: 0,
  increment: () => set((s) => ({ count: s.count + 1 })),
}));
```

```jsx
const count = useStore((s) => s.count); // селектор - подписка только на count
const increment = useStore((s) => s.increment);
```

Подписка через селектор: компонент перерисуется, только если изменился выбранный срез. Популярен за простоту и малый размер.

## Jotai

Атомарный подход «снизу вверх». Состояние - набор маленьких **атомов**, компоненты подписываются на конкретные атомы.

```js
import { atom, useAtom } from 'jotai';

const countAtom = atom(0);
const doubledAtom = atom((get) => get(countAtom) * 2); // производный атом
```

```jsx
const [count, setCount] = useAtom(countAtom); // как useState, но глобально
```

Удобен, когда состояние естественно дробится на независимые кусочки; производные атомы пересчитываются автоматически.

## Сравнение

| | Redux Toolkit | Zustand | Jotai | Context |
|--|---------------|---------|-------|---------|
| Модель | единый стор, редьюсеры | стор на хуках | атомы | транспорт |
| Бойлерплейт | средний | минимальный | минимальный | минимальный |
| Точечные подписки | селекторы | селекторы | по атомам | нет |
| DevTools / time-travel | отличные | базовые | базовые | нет |
| Когда | большой сложный стейт, команды | большинство приложений | дробное состояние | тема/юзер/локаль |

## Legacy: Recoil и MobX

- **Recoil** - атомарный стор от Meta, но проект фактически заброшен; в новых приложениях не выбирают.
- **MobX** - реактивность через наблюдаемые объекты и мутации, ООП-стиль. Всё ещё встречается в legacy, но доля падает.

> Знать стоит для собеседований по старым проектам, начинать новое - на RTK/Zustand/Jotai.

---

## Селекторы и ререндеры

Главное преимущество сторов над контекстом - **селекторы**: компонент подписывается на конкретный срез и перерисовывается только при его изменении. Под капотом современные сторы используют [`useSyncExternalStore`](/content/reactjs/advanced-hooks), чтобы избегать tearing при конкурентном рендеринге.

```jsx
// перерисуется только при смене user.name, а не любого поля стора
const name = useStore((s) => s.user.name);
```

## Вопросы на собеседовании

<b class="text-on-semi-light">Как выбрать стейт-менеджер?</b>
<span class="text-gray">Сначала классифицируй состояние. Server state → React Query, локальное → useState, глобальное редкое → Context, большое частое → стор с селекторами. Redux не должен быть выбором по умолчанию.</span>

<b class="text-on-semi-light">Почему серверные данные не стоит держать в Redux?</b>
<span class="text-gray">Это кэш: асинхронный, устаревающий, общий. Ручное управление loading/error/data переизобретает React Query, который даёт кэш, инвалидацию и дедупликацию из коробки.</span>

<b class="text-on-semi-light">Чем RTK лучше «старого» Redux?</b>
<span class="text-gray">Убирает бойлерплейт: `createSlice` генерирует экшены/редьюсеры, Immer разрешает «мутабельный» код, есть RTK Query. Меньше кода, меньше ошибок.</span>

<b class="text-on-semi-light">Чем стор отличается от Context по ререндерам?</b>
<span class="text-gray">Стор даёт селекторы - точечную подписку на срез, перерисовываются только зависящие компоненты. Context перерисовывает всех потребителей при смене value.</span>

<b class="text-on-semi-light">Когда Redux/стор вообще не нужен?</b>
<span class="text-gray">Когда server state вынесен в React Query, а остальное - локальное состояние или редкие глобальные данные в Context. Часто глобального стора не требуется вовсе.</span>
