# Продвинутые типы

Когда базовых типов и утилит уже не хватает - приходит время продвинутых техник. Mapped types, conditional types, infer, template literal types - всё это позволяет строить по-настоящему мощные системы типов. Разберём каждую технику.

---

## Mapped types

Mapped type проходит по ключам типа и создаёт новый тип на основе каждого ключа.

### Базовый синтаксис

```ts
type Mapped<T> = {
  [K in keyof T]: T[K];
};
```

Это просто копирует тип. Но сила в том, что мы можем трансформировать и ключи, и значения.

### Все свойства optional - так работает Partial

```ts
type MyPartial<T> = {
  [K in keyof T]?: T[K];
};

interface User {
  id: number;
  name: string;
  email: string;
}

type OptionalUser = MyPartial<User>;
// { id?: number; name?: string; email?: string }
```

### Модификаторы: readonly, ?, +/-

```ts
// Добавить readonly
type Frozen<T> = {
  +readonly [K in keyof T]: T[K];
};

// Убрать readonly
type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};

// Убрать optional
type Concrete<T> = {
  [K in keyof T]-?: T[K];
};
```

`+` добавляет модификатор, `-` убирает. По умолчанию `+` подразумевается, поэтому `readonly` и `+readonly` - одно и то же.

### Key remapping - переименование ключей

```ts
interface User {
  name: string;
  age: number;
  email: string;
}

type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type UserGetters = Getters<User>;
// {
//   getName: () => string;
//   getAge: () => number;
//   getEmail: () => string;
// }
```

Ключевое слово `as` позволяет переименовать ключ. Можно даже отфильтровать ключи, вернув `never`:

```ts
// Только строковые свойства
type StringProps<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
};

type UserStrings = StringProps<User>;
// { name: string; email: string }
```

## Conditional types

Conditional types позволяют выбирать тип в зависимости от условия.

### Базовый синтаксис

```ts
type IsString<T> = T extends string ? true : false;

type A = IsString<string>;  // true
type B = IsString<number>;  // false
```

### Практический пример

```ts
interface UserResponse {
  id: number;
  name: string;
}

interface PostResponse {
  id: number;
  title: string;
  body: string;
}

type ApiResponse<T extends string> =
  T extends 'user' ? UserResponse :
  T extends 'post' ? PostResponse :
  never;

type UserData = ApiResponse<'user'>; // UserResponse
type PostData = ApiResponse<'post'>; // PostResponse
```

## Ключевое слово infer

`infer` позволяет извлекать типы внутри conditional type. Думай о нём как о "захвати этот тип в переменную".

### Извлечение типа элемента массива

```ts
type ElementType<T> = T extends (infer E)[] ? E : T;

type A = ElementType<string[]>;  // string
type B = ElementType<number>;    // number (не массив - вернули как есть)
```

### Так работает ReturnType

```ts
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

function getUser() {
  return { id: 1, name: 'Иван' };
}

type UserResult = MyReturnType<typeof getUser>;
// { id: number; name: string }
```

### Вложенный infer - извлечение типа из Promise

```ts
type UnwrapPromise<T> = T extends Promise<infer U>
  ? U extends Promise<any>
    ? UnwrapPromise<U>  // рекурсивно разворачиваем вложенные Promise
    : U
  : T;

type A = UnwrapPromise<Promise<string>>;           // string
type B = UnwrapPromise<Promise<Promise<number>>>;   // number
type C = UnwrapPromise<boolean>;                    // boolean
```

### Извлечение аргументов из события

```ts
type EventHandler<T> = T extends (event: infer E) => void ? E : never;

type ClickHandler = (event: MouseEvent) => void;
type ClickEvent = EventHandler<ClickHandler>; // MouseEvent
```

## Distributive conditional types

Когда conditional type применяется к union, он работает для каждого члена union отдельно - это называется distribution (распределение).

### Как работает распределение

```ts
type ToArray<T> = T extends any ? T[] : never;

// Union распределяется:
type Result = ToArray<string | number>;
// string[] | number[]  (НЕ (string | number)[])
```

TypeScript как бы раскрывает:
- `ToArray<string> | ToArray<number>`
- `string[] | number[]`

Именно так работает `Exclude`:

```ts
type Exclude<T, U> = T extends U ? never : T;

type Result = Exclude<'a' | 'b' | 'c', 'a'>;
// 'a' extends 'a' -> never
// 'b' extends 'a' -> 'b'
// 'c' extends 'a' -> 'c'
// Итого: 'b' | 'c'
```

### Как предотвратить распределение

Если нужно работать с union как с целым типом, оберни в tuple:

```ts
type ToArrayNonDist<T> = [T] extends [any] ? T[] : never;

type Result = ToArrayNonDist<string | number>;
// (string | number)[]  - один массив, а не union массивов
```

⚠️ Это частый источник багов. Если conditional type ведёт себя неожиданно с union - проверь, не происходит ли нежелательное распределение.

## Template literal types

Строковые шаблонные типы позволяют конструировать строковые типы из шаблонов.

### Базовый синтаксис

```ts
type EventName = `on${Capitalize<string>}`;
// Принимает: 'onClick', 'onHover', 'onAnything' - любая строка с префиксом on

type HttpMethod = 'GET' | 'POST' | 'PUT' | 'DELETE';
type ApiPath = `/${string}`;
type Endpoint = `${HttpMethod} ${ApiPath}`;
// 'GET /users', 'POST /auth/login', etc.
```

### Типизированные CSS-свойства

```ts
type CSSUnit = 'px' | 'em' | 'rem' | '%' | 'vh' | 'vw';
type CSSValue = `${number}${CSSUnit}`;

function setWidth(value: CSSValue) {
  // ...
}

setWidth('100px');  // OK
setWidth('2.5rem'); // OK
setWidth('100');    // Ошибка - нет единицы измерения
```

### Типизированные роуты

```ts
type Route = '/' | '/users' | '/users/:id' | '/posts' | '/posts/:id';

type ExtractParam<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? Param | ExtractParam<Rest>
    : T extends `${string}:${infer Param}`
      ? Param
      : never;

type UserRouteParams = ExtractParam<'/users/:id'>;  // 'id'
type NestedParams = ExtractParam<'/org/:orgId/user/:userId'>; // 'orgId' | 'userId'
```

## Рекурсивные типы

TypeScript поддерживает рекурсивные определения типов.

### DeepPartial - рекурсивный Partial

```ts
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object
    ? DeepPartial<T[K]>
    : T[K];
};

interface AppConfig {
  server: {
    host: string;
    port: number;
    ssl: {
      enabled: boolean;
      cert: string;
    };
  };
  database: {
    url: string;
  };
}

// Можно передать любую часть конфига на любом уровне вложенности
const partialConfig: DeepPartial<AppConfig> = {
  server: {
    ssl: {
      enabled: true,
    },
  },
};
```

### Рекурсивный тип JSON

```ts
type JSONValue =
  | string
  | number
  | boolean
  | null
  | JSONValue[]
  | { [key: string]: JSONValue };

const data: JSONValue = {
  name: 'Иван',
  age: 30,
  hobbies: ['code', 'music'],
  address: {
    city: 'Москва',
    coords: [55.75, 37.61],
  },
};
```

### DeepReadonly

```ts
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object
    ? DeepReadonly<T[K]>
    : T[K];
};

const config: DeepReadonly<AppConfig> = {
  server: { host: 'localhost', port: 3000, ssl: { enabled: false, cert: '' } },
  database: { url: 'postgres://localhost' },
};

config.server.port = 8080; // Ошибка: Cannot assign to 'port'
config.server.ssl.enabled = true; // Ошибка: Cannot assign to 'enabled'
```

## Branded types (номинальная типизация)

TypeScript использует структурную типизацию - если структура совпадает, типы совместимы. Иногда это проблема:

```ts
type USD = number;
type EUR = number;

function payInUSD(amount: USD) { /* ... */ }

const euros: EUR = 50;
payInUSD(euros); // Никакой ошибки! Оба просто number
```

Branded types решают это, добавляя уникальную "метку":

```ts
type USD = number & { readonly __brand: unique symbol };
type EUR = number & { readonly __brand: unique symbol };

function usd(amount: number): USD {
  return amount as USD;
}

function eur(amount: number): EUR {
  return amount as EUR;
}

function payInUSD(amount: USD) { /* ... */ }

const price = usd(100);
const euroPrice = eur(50);

payInUSD(price);      // OK
payInUSD(euroPrice);  // Ошибка: Type 'EUR' is not assignable to type 'USD'
payInUSD(42);         // Ошибка: Type 'number' is not assignable to type 'USD'
```

### Типобезопасные ID

```ts
type Brand<T, B extends string> = T & { readonly __brand: B };

type UserId = Brand<number, 'UserId'>;
type PostId = Brand<number, 'PostId'>;

function getUser(id: UserId) { /* ... */ }
function getPost(id: PostId) { /* ... */ }

const userId = 1 as UserId;
const postId = 2 as PostId;

getUser(userId); // OK
getUser(postId); // Ошибка: нельзя перепутать UserId и PostId
```

Этот паттерн особенно полезен в больших проектах, где легко перепутать разные ID, которые по структуре одинаковы.

## Сводная таблица продвинутых техник

| <b class="text-on-semi-light">Техника</b> | <span class="text-gray">Когда использовать</span> |
|---|---|
| Mapped types | Трансформация всех свойств объекта |
| Key remapping (`as`) | Переименование или фильтрация ключей |
| Conditional types | Выбор типа по условию |
| `infer` | Извлечение типа из структуры |
| Distributive conditional | Работа с каждым членом union отдельно |
| Template literal types | Конструирование строковых типов из шаблонов |
| Recursive types | Работа с вложенными структурами |
| Branded types | Номинальная типизация для примитивов |

## Частые вопросы на собесе

<b class="text-on-semi-light">Что такое distributive conditional type и как его отключить?</b>
<span class="text-gray">Когда conditional type `T extends U ? X : Y` получает union в качестве T, условие применяется к каждому члену union отдельно. Чтобы отключить это поведение, нужно обернуть T и U в tuple: `[T] extends [U] ? X : Y`.</span>

<b class="text-on-semi-light">Как работает infer?</b>
<span class="text-gray">`infer` объявляет типовую переменную внутри conditional type. TypeScript пытается вывести (infer) тип из структуры. Например, `T extends Array<infer E> ? E : never` - если T является массивом, то E захватывает тип элемента.</span>

<b class="text-on-semi-light">Зачем нужны branded types, если есть интерфейсы?</b>
<span class="text-gray">Branded types решают проблему с примитивами. UserId и PostId - оба number, но это разные сущности. Интерфейсы не помогут, потому что number нельзя расширить интерфейсом. Brand добавляет виртуальное свойство, которое TypeScript отслеживает, но которого нет в рантайме.</span>

<b class="text-on-semi-light">В чём разница между mapped type и conditional type?</b>
<span class="text-gray">Mapped type трансформирует каждое свойство объекта: `{ [K in keyof T]: ... }`. Conditional type выбирает один тип из двух по условию: `T extends U ? X : Y`. Часто они используются вместе - mapped type на внешнем уровне, conditional на внутреннем.</span>
