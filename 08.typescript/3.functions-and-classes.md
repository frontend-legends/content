# Функции и классы

Функции и классы - основные строительные блоки любого приложения. TypeScript добавляет к ним систему типов, которая делает код надёжнее и понятнее.

---

## Типизация функций

<b class="text-on-semi-light">Function type annotations</b> - <span class="text-gray">указание типов параметров и возвращаемого значения.</span>

```ts
// Типы параметров и return type
function add(a: number, b: number): number {
  return a + b;
}

// Arrow function
const multiply = (a: number, b: number): number => a * b;

// Return type можно опустить - TS выведет сам
function greet(name: string) {
  return `Hello, ${name}!`; // TS выведет return type: string
}
```

Хорошая практика - явно указывать return type для публичных функций и API. Это помогает ловить ошибки, когда реализация случайно возвращает не тот тип.

```ts
// Без явного return type - TS выведет string | undefined
// С явным - компилятор сразу укажет на проблему
function getUserName(id: number): string {
  const user = findUser(id);
  if (!user) {
    // Ошибка! Функция должна вернуть string, а тут ничего
    return; // Type 'undefined' is not assignable to type 'string'
  }
  return user.name;
}
```

## Optional и default параметры

```ts
// Optional parameter - может быть undefined
function greet(name: string, greeting?: string): string {
  return `${greeting || 'Hello'}, ${name}!`;
}

greet('Alice');           // 'Hello, Alice!'
greet('Alice', 'Hi');     // 'Hi, Alice!'

// Default parameter - значение по умолчанию
function greet(name: string, greeting: string = 'Hello'): string {
  return `${greeting}, ${name}!`;
}

greet('Alice');           // 'Hello, Alice!'
greet('Alice', 'Hi');     // 'Hi, Alice!'
```

Разница: optional параметр имеет тип `string | undefined`, а параметр с default value - просто `string` (TypeScript знает, что undefined заменится дефолтом).

## Rest параметры

```ts
function sum(...numbers: number[]): number {
  return numbers.reduce((acc, n) => acc + n, 0);
}

sum(1, 2, 3);       // 6
sum(1, 2, 3, 4, 5); // 15

// Rest с другими параметрами
function log(level: string, ...messages: string[]): void {
  console.log(`[${level}]`, ...messages);
}
```

## Function overloads

<b class="text-on-semi-light">Overloads</b> - <span class="text-gray">несколько сигнатур для одной функции. TS выбирает подходящую сигнатуру на основе переданных аргументов.</span>

```ts
// Overload signatures
function createElement(tag: 'a'): HTMLAnchorElement;
function createElement(tag: 'canvas'): HTMLCanvasElement;
function createElement(tag: 'input'): HTMLInputElement;
// Implementation signature - не видна снаружи
function createElement(tag: string): HTMLElement {
  return document.createElement(tag);
}

const link = createElement('a');     // HTMLAnchorElement
const canvas = createElement('canvas'); // HTMLCanvasElement
```

Практический пример - функция, которая ведёт себя по-разному в зависимости от аргументов:

```ts
// Overloads
function parseInput(input: string): string[];
function parseInput(input: number): number[];
function parseInput(input: string | number): string[] | number[] {
  if (typeof input === 'string') {
    return input.split(',');
  }
  return Array.from({ length: input }, (_, i) => i);
}

const strings = parseInput('a,b,c'); // string[]
const numbers = parseInput(5);        // number[]
```

⚠️ Overloads - мощный инструмент, но часто можно обойтись generics или union types. Используй overloads, когда return type зависит от типа аргумента.

## Типизация callback-ов

```ts
// Callback как параметр
function fetchData(url: string, callback: (err: Error | null, data: string) => void): void {
  try {
    const data = '...'; // fetch logic
    callback(null, data);
  } catch (e) {
    callback(e as Error, '');
  }
}

// С generic
function fetchData<T>(
  url: string,
  callback: (err: Error | null, data: T) => void
): void {
  // ...
}
```

## void vs undefined

Эти типы похожи, но есть важная разница:

```ts
// void - функция не должна использовать возвращаемое значение
type VoidFunc = () => void;

// Функция с void может вернуть что-то - TS не будет ругаться
const fn: VoidFunc = () => {
  return 42; // Ок! Но возвращаемое значение будет проигнорировано
};

const result = fn(); // type: void - нельзя использовать

// undefined - функция явно возвращает undefined
type UndefinedFunc = () => undefined;

const fn2: UndefinedFunc = () => {
  return 42; // Ошибка! Type 'number' is not assignable to type 'undefined'
};
```

`void` в callback-ах означает "мне не важно, что ты вернёшь". Это позволяет передавать функции, которые что-то возвращают, туда, где return value не используется (например, `forEach`).

## Параметр this

В TypeScript можно явно указать тип `this` в первой позиции параметров. Этот параметр не влияет на вызов функции - он только для проверки типов.

```ts
interface User {
  name: string;
  greet(this: User): string;
}

const user: User = {
  name: 'Alice',
  greet() {
    return `Hi, I'm ${this.name}`; // TS знает, что this - User
  },
};

user.greet(); // Ок
const greet = user.greet;
greet(); // Ошибка! The 'this' context of type 'void' is not assignable to type 'User'
```

## Function type expressions

<b class="text-on-semi-light">Function type expression</b> - <span class="text-gray">описание типа функции как отдельной конструкции.</span>

```ts
// Type alias для функции
type Logger = (message: string) => void;
type Comparator<T> = (a: T, b: T) => number;
type AsyncAction = (id: string) => Promise<void>;

// Использование
const log: Logger = (msg) => console.log(msg);

function sort<T>(items: T[], compare: Comparator<T>): T[] {
  return [...items].sort(compare);
}

// Call signature в object type (когда функция имеет properties)
type DescribableFunction = {
  description: string;
  (arg: number): boolean;
};
```

## Классы в TypeScript

TypeScript значительно расширяет JS-классы, добавляя типы для свойств, модификаторы доступа и абстрактные классы.

### Property declarations

```ts
class User {
  // Свойства нужно объявить с типами
  name: string;
  age: number;
  email: string | null;

  constructor(name: string, age: number) {
    this.name = name;
    this.age = age;
    this.email = null;
  }
}
```

### Constructor parameter shorthand

Вместо объявления свойств и присваивания в конструкторе - можно сделать всё в одну строку:

```ts
class User {
  // Автоматически создаёт свойства и присваивает значения
  constructor(
    public name: string,
    public age: number,
    private email: string,
    protected role: string = 'user',
  ) {}
  // Эквивалентно ручному объявлению + this.name = name и т.д.
}

const user = new User('Alice', 30, 'alice@example.com');
console.log(user.name); // 'Alice'
```

## Модификаторы видимости

| Модификатор | Доступ | Рантайм |
|---|---|---|
| `public` | Везде (по умолчанию) | Нет ограничений |
| `private` | Только внутри класса | Нет ограничений (только TS проверка) |
| `protected` | Класс + наследники | Нет ограничений (только TS проверка) |
| `#` (private fields) | Только внутри класса | Реальная приватность в рантайме |

```ts
class Account {
  public name: string;         // Доступен везде
  private balance: number;     // Только внутри Account (TS-only)
  protected currency: string;  // Account + наследники (TS-only)
  #secret: string;             // Реально приватное (JS runtime)

  constructor(name: string, balance: number) {
    this.name = name;
    this.balance = balance;
    this.currency = 'USD';
    this.#secret = 'hidden';
  }

  // private метод
  private validate(): boolean {
    return this.balance >= 0;
  }
}

const acc = new Account('Alice', 100);
acc.name;      // Ок
acc.balance;   // Ошибка TS (но в JS работает!)
acc.#secret;   // Ошибка и в TS, и в JS
```

## readonly свойства

```ts
class Point {
  readonly x: number;
  readonly y: number;

  constructor(x: number, y: number) {
    this.x = x; // Ок - можно присвоить в конструкторе
    this.y = y;
  }

  move() {
    this.x = 10; // Ошибка! Cannot assign to 'x' because it is a read-only property
  }
}
```

## Абстрактные классы

<b class="text-on-semi-light">Abstract class</b> - <span class="text-gray">класс, который нельзя инстанциировать напрямую. Служит базой для наследников и может содержать абстрактные методы.</span>

```ts
abstract class Shape {
  abstract area(): number;     // Нет реализации - наследники обязаны реализовать
  abstract perimeter(): number;

  // Обычные методы с реализацией - наследуются
  describe(): string {
    return `Area: ${this.area()}, Perimeter: ${this.perimeter()}`;
  }
}

class Circle extends Shape {
  constructor(private radius: number) {
    super();
  }

  area(): number {
    return Math.PI * this.radius ** 2;
  }

  perimeter(): number {
    return 2 * Math.PI * this.radius;
  }
}

// const shape = new Shape(); // Ошибка! Cannot create an instance of an abstract class
const circle = new Circle(5);
circle.describe(); // 'Area: 78.54, Perimeter: 31.42'
```

## implements

Классы могут реализовывать интерфейсы. Это контракт - класс обязан иметь все поля и методы интерфейса.

```ts
interface Serializable {
  serialize(): string;
  deserialize(data: string): void;
}

interface Loggable {
  log(): void;
}

// Класс может реализовывать несколько интерфейсов
class User implements Serializable, Loggable {
  constructor(public name: string, public age: number) {}

  serialize(): string {
    return JSON.stringify({ name: this.name, age: this.age });
  }

  deserialize(data: string): void {
    const parsed = JSON.parse(data);
    this.name = parsed.name;
    this.age = parsed.age;
  }

  log(): void {
    console.log(`User: ${this.name}, Age: ${this.age}`);
  }
}
```

⚠️ Важно: `implements` - это только проверка на этапе компиляции. Он не добавляет никаких типов к классу автоматически. Все методы и свойства нужно реализовать вручную.

## Static members

```ts
class MathHelper {
  static PI: number = 3.14159;

  static square(n: number): number {
    return n * n;
  }

  // Static block (ES2022)
  static {
    console.log('MathHelper initialized');
  }
}

MathHelper.PI;         // 3.14159
MathHelper.square(5);  // 25
```

## Decorators

<b class="text-on-semi-light">Decorators</b> - <span class="text-gray">функции, которые модифицируют классы, методы, свойства или параметры. Stage 3 TC39, поддержка с TS 5.0+.</span>

```ts
// Decorator для логирования вызовов метода
function log(target: any, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  descriptor.value = function (...args: any[]) {
    console.log(`Calling ${key} with`, args);
    const result = original.apply(this, args);
    console.log(`${key} returned`, result);
    return result;
  };
}

class Calculator {
  @log
  add(a: number, b: number): number {
    return a + b;
  }
}
```

Decorators активно используются в Angular и NestJS. В повседневном React/Vue-коде они встречаются редко, но знать о них полезно.

В `tsconfig.json` нужно включить `experimentalDecorators: true` для legacy-декораторов или использовать новый синтаксис TC39 (TS 5.0+).

## Частые вопросы на собесе

- **Чем отличается private от #?** - `private` - только TS-проверка, в скомпилированном JS поле доступно. `#` - реальная приватность на уровне JS-рантайма.
- **Что такое function overloads?** - Несколько сигнатур для одной функции. TS выбирает подходящую на основе аргументов. Implementation signature не видна снаружи.
- **Чем void отличается от undefined как return type?** - `void` означает "не используй возвращаемое значение". Функция с `void` callback может что-то возвращать. `undefined` требует явного возврата `undefined`.
- **Зачем нужны abstract классы?** - Для определения общего интерфейса и частичной реализации. Наследники обязаны реализовать абстрактные методы.
- **Что даёт implements?** - Гарантирует, что класс соответствует интерфейсу. Это только compile-time проверка.
- **Как типизировать this?** - Через первый параметр функции с именем `this`. Он не влияет на вызов, но TS проверяет контекст.
