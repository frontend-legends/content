# Дженерики

Допустим, вы написали функцию, которая оборачивает значение в массив. Для строк - одна функция, для чисел - другая, для объектов - третья? Конечно нет. Дженерики позволяют писать **один** код, который работает с **любым** типом, не теряя при этом типизацию.

## Зачем нужны дженерики

Без дженериков у нас два пути - оба плохие:

```ts
// Путь 1: конкретный тип - негибко
function wrapInArrayString(value: string): string[] {
  return [value];
}

// Путь 2: any - теряем типизацию
function wrapInArrayAny(value: any): any[] {
  return [value];
}

const result = wrapInArrayAny(42);
// result: any[] - TypeScript ничего не знает о содержимом
```

С дженериками:

```ts
function wrapInArray<T>(value: T): T[] {
  return [value];
}

const strings = wrapInArray('hello');  // string[]
const numbers = wrapInArray(42);       // number[]
const users = wrapInArray({ name: 'Иван' }); // { name: string }[]
```

TypeScript **выводит** `T` из аргумента. Можно указать явно: `wrapInArray<number>(42)`.

## Базовый синтаксис

Типовой параметр `T` объявляется в угловых скобках перед аргументами:

```ts
function identity<T>(arg: T): T {
  return arg;
}

// T = string (выведено)
const a = identity('hello'); // string

// T = number (явно)
const b = identity<number>(42); // number
```

Букву `T` выбирают по традиции (от "Type"), но можно использовать любое имя. Для нескольких параметров часто используют `T`, `U`, `V` или более описательные имена:

```ts
function swap<TFirst, TSecond>(a: TFirst, b: TSecond): [TSecond, TFirst] {
  return [b, a];
}

const [num, str] = swap('hello', 42); // [number, string]
```

## Стрелочные функции и TSX

В стрелочных функциях синтаксис такой же, но есть нюанс с TSX-файлами:

```ts
// Обычный .ts файл - работает
const identity = <T>(arg: T): T => arg;

// В .tsx файле <T> выглядит как JSX-тег
// Нужна запятая после T:
const identity = <T,>(arg: T): T => arg;
```

<b class="text-on-semi-light">Запятая после T</b> <span class="text-gray">- это не ошибка и не опечатка. Это подсказка парсеру, что `<T,>` - это дженерик, а не JSX-тег `<T>`.</span>

## Generic Interfaces

```ts
interface Box<T> {
  value: T;
  isEmpty: boolean;
}

const stringBox: Box<string> = { value: 'hello', isEmpty: false };
const numberBox: Box<number> = { value: 42, isEmpty: false };
```

Интерфейсы с дженериками часто используются для описания коллекций и контейнеров:

```ts
  async update(id: string, data: Partial<User>): Promise<User> { /* ... */ }

```

## Generic Type Aliases

```ts
type Result<T> =
  | { success: true; data: T }
  | { success: false; error: Error };

function parseJSON<T>(json: string): Result<T> {
  try {
    const data = JSON.parse(json) as T;
    return { success: true, data };
  } catch (e) {
    return { success: false, error: e as Error };
  }
}

const result = parseJSON<number[]>('[1, 2, 3]');
if (result.success) {
  console.log(result.data); // number[]
}
```

## Generic Classes

```ts
class Stack<T> {
  private items: T[] = [];

  push(item: T): void {
    this.items.push(item);
  }

  pop(): T | undefined {
    return this.items.pop();
  }

  peek(): T | undefined {
    return this.items[this.items.length - 1];
  }

  get size(): number {
    return this.items.length;
  }
}

const numberStack = new Stack<number>();
numberStack.push(1);
numberStack.push(2);
const top = numberStack.pop(); // number | undefined
```

## Constraints - ограничения

Не всегда `T` должен быть чем угодно. `extends` ограничивает допустимые типы:

```ts
function getLength<T extends { length: number }>(value: T): number {
  return value.length;
}

getLength('hello');     // OK - string имеет length
getLength([1, 2, 3]);  // OK - массив имеет length
getLength({ length: 5, custom: true }); // OK

// getLength(42);       // Ошибка! number не имеет length
```

<b class="text-on-semi-light">Ключевое слово `extends` в дженериках</b> <span class="text-gray">- это не наследование классов. Это ограничение: "T должен быть подтипом указанного типа" или проще - "T должен содержать как минимум эти свойства".</span>

## keyof Constraint

Классический паттерн - типобезопасный доступ к свойствам объекта:

```ts
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { name: 'Иван', age: 30, active: true };

const name = getProperty(user, 'name');   // string
const age = getProperty(user, 'age');     // number
// getProperty(user, 'email');            // Ошибка! 'email' не является ключом
```

`K extends keyof T` гарантирует, что `key` - это реальный ключ объекта. А `T[K]` - это тип значения по этому ключу. Полная типобезопасность.

## Default Type Parameters

Как аргументы по умолчанию в функциях, только для типов:

```ts
interface ApiResponse<T = unknown> {
  data: T;
  status: number;
  timestamp: Date;
}

// Можно не указывать T
const response: ApiResponse = { data: 'anything', status: 200, timestamp: new Date() };

// Или указать конкретный тип
const typedResponse: ApiResponse<string[]> = {
  data: ['item1', 'item2'],
  status: 200,
  timestamp: new Date(),
};
```

```ts
function createState<T = string>(initial: T): { value: T; set: (v: T) => void } {
  let value = initial;
  return {
    value,
    set: (v: T) => { value = v; },
  };
}

const state = createState('hello'); // T = string (выведено из аргумента)
```

## Multiple Type Parameters

Когда нужно отслеживать несколько типов:

```ts
function map<T, U>(arr: T[], fn: (item: T) => U): U[] {
  return arr.map(fn);
}

const lengths = map(['hello', 'world'], s => s.length);
// T = string, U = number -> number[]

const parsed = map([1, 2, 3], n => n.toString());
// T = number, U = string -> string[]
```

```ts
function zip<T, U>(arr1: T[], arr2: U[]): [T, U][] {
  const length = Math.min(arr1.length, arr2.length);
  const result: [T, U][] = [];
  for (let i = 0; i < length; i++) {
    result.push([arr1[i], arr2[i]]);
  }
  return result;
}

const pairs = zip([1, 2, 3], ['a', 'b', 'c']); // [number, string][]
```

## Const Type Parameters (TS 5.0+)

Модификатор `const` перед типовым параметром заставляет TypeScript выводить **литеральный** тип вместо расширенного:

```ts
// Без const
function routes<T extends string[]>(paths: T) {
  return paths;
}
const r1 = routes(['/', '/about']); // string[]

// С const
function routesConst<const T extends string[]>(paths: T) {
  return paths;
}
const r2 = routesConst(['/', '/about']); // readonly ['/', '/about']
```

Это значительно упрощает вывод литеральных типов. Раньше для этого приходилось использовать `as const`:

```ts
// До TS 5.0
function defineConfig<T>(config: T): T { return config; }
const config = defineConfig({ mode: 'production' } as const);

// С TS 5.0
function defineConfig<const T>(config: T): T { return config; }
const config = defineConfig({ mode: 'production' });
// { readonly mode: 'production' } - без as const!
```

## Практические паттерны

### Generic API Response

```ts
interface ApiResponse<T> {
  data: T;
  status: number;
  message: string;
}

async function fetchData<T>(url: string): Promise<ApiResponse<T>> {
  const response = await fetch(url);
  return response.json();
}

interface User { id: number; name: string; }
interface Product { id: number; title: string; price: number; }

const users = await fetchData<User[]>('/api/users');
// users.data: User[]

const product = await fetchData<Product>('/api/products/1');
// product.data: Product
```

### Generic Event Handler

```ts
interface Events {
  click: { x: number; y: number };
  change: { value: string };
  submit: { formData: FormData };
}

function on<K extends keyof Events>(
  event: K,
  handler: (data: Events[K]) => void
): void {
  // ...
}

on('click', (data) => {
  // data: { x: number; y: number }
  console.log(data.x, data.y);
});

on('change', (data) => {
  // data: { value: string }
  console.log(data.value);
});

// on('unknown', () => {}); // Ошибка! 'unknown' не является ключом Events
```

### Generic Factory

```ts
interface ComponentProps {
  className?: string;
}

function createComponent<P extends ComponentProps>(
  render: (props: P) => string
): (props: P) => string {
  return (props) => {
    console.log(`Rendering with class: ${props.className}`);
    return render(props);
  };
}

interface ButtonProps extends ComponentProps {
  label: string;
  onClick: () => void;
}

const Button = createComponent<ButtonProps>((props) => {
  return `<button class="${props.className}">${props.label}</button>`;
});
```

## Частые вопросы на собесе

<b class="text-on-semi-light">Что такое дженерики и зачем они нужны?</b>
<span class="text-gray">Дженерики - это параметризованные типы. Позволяют создавать компоненты (функции, классы, интерфейсы), которые работают с любыми типами, сохраняя при этом типобезопасность. Альтернатива - `any`, но с ним теряется вся информация о типах.</span>

<b class="text-on-semi-light">Что значит T extends keyof U?</b>
<span class="text-gray">`T` ограничен union-ом ключей типа `U`. Если `U = { name: string; age: number }`, то `T` может быть только `'name'` или `'age'`. Используется для типобезопасного доступа к свойствам.</span>

<b class="text-on-semi-light">Зачем запятая в `<T,>` в стрелочных функциях?</b>
<span class="text-gray">В `.tsx` файлах парсер воспринимает `<T>` как JSX-тег. Запятая после `T` подсказывает, что это дженерик, а не JSX. В обычных `.ts` файлах запятая не обязательна.</span>

<b class="text-on-semi-light">Можно ли задать значение по умолчанию для типового параметра?</b>
<span class="text-gray">Да: `function fn<T = string>(arg: T): T`. Если `T` не указан явно и не может быть выведен из аргументов, используется значение по умолчанию.</span>

<b class="text-on-semi-light">Что такое const type parameters?</b>
<span class="text-gray">Фича TypeScript 5.0. Модификатор `const` перед типовым параметром заставляет выводить литеральный тип вместо расширенного. `<const T>` превращает `['a', 'b']` из `string[]` в `readonly ['a', 'b']`.</span>
