# TypeScript + Vue

Vue 3 проектировался с учётом TypeScript, и с каждым минорным релизом поддержка становится лучше. Composition API, `<script setup>`, defineProps, defineEmits - всё это работает с типами из коробки. Разберём, как правильно типизировать Vue-компоненты, composables и stores.

---

## Setup: script setup lang="ts"

Рекомендуемый способ писать Vue + TypeScript:

```vue
<script setup lang="ts">
import { ref, computed } from 'vue';

const count = ref(0);
const doubled = computed(() => count.value * 2);
</script>

<template>
  <button @click="count++">{{ count }} (x2 = {{ doubled }})</button>
</template>
```

`<script setup lang="ts">` - это Composition API + TypeScript + компактный синтаксис. Всё, что объявлено в script, автоматически доступно в template.

## defineProps

Два способа объявить пропсы: runtime и type-only.

```vue
<!-- Type-only (рекомендуется) -->
<script setup lang="ts">
interface Props {
  title: string;
  count?: number;
}

const props = defineProps<Props>();
</script>
```

```vue
<!-- С дефолтными значениями -->
<script setup lang="ts">
interface Props {
  title: string;
  count?: number;
  variant?: 'primary' | 'secondary';
}

const props = withDefaults(defineProps<Props>(), {
  count: 0,
  variant: 'primary',
});
</script>
```

<b class="text-on-semi-light">Type-only vs runtime</b> - <span class="text-gray">Type-only декларация чище и мощнее - поддерживает union типы, imported интерфейсы и сложные типы. Runtime-декларация (`defineProps({ count: Number })`) проще, но ограничена примитивными конструкторами.</span>

## defineEmits

Типизированные события:

```vue
<script setup lang="ts">
// Полная форма
const emit = defineEmits<{
  (e: 'update', value: string): void;
  (e: 'delete', id: number): void;
}>();

emit('update', 'new value'); // OK
emit('delete', 42);          // OK
emit('delete', 'oops');      // Error: Argument of type 'string' is not assignable
</script>
```

```vue
<script setup lang="ts">
// Короткая форма (Vue 3.3+)
const emit = defineEmits<{
  update: [value: string];
  delete: [id: number];
}>();
</script>
```

Короткая форма с именованными кортежами появилась в Vue 3.3 и стала предпочтительным способом.

## defineModel (Vue 3.4+)

Типизированный v-model без бойлерплейта:

```vue
<script setup lang="ts">
const modelValue = defineModel<string>({ required: true });
// Заменяет пару defineProps + defineEmits для v-model

// Именованные модели
const firstName = defineModel<string>('firstName', { required: true });
const lastName = defineModel<string>('lastName', { default: '' });
</script>
```

## ref() и типизация

`ref()` возвращает `Ref<T>`. Тип обычно выводится из начального значения:

```ts
import { ref } from 'vue';
import type { Ref } from 'vue';

const count = ref(0);              // Ref<number>
const name = ref('Vue');           // Ref<string>
const user = ref<User | null>(null); // Ref<User | null> - explicit

// Доступ к значению через .value
count.value++;            // OK
user.value = { id: 1, name: 'Alice' }; // OK
```

<b class="text-on-semi-light">Когда нужен явный generic?</b> - <span class="text-gray">Когда начальное значение не содержит достаточно информации: null, пустой массив, или когда тип шире, чем начальное значение.</span>

```ts
const items = ref<string[]>([]);       // без generic было бы Ref<never[]>
const status = ref<'idle' | 'loading'>('idle'); // сужаем до union
```

## reactive() и computed()

`reactive()` не оборачивает в Ref - тип выводится из аргумента:

```ts
const form = reactive<{ name: string; age: number | null }>({
  name: '',
  age: null,
});
form.name = 'Alice'; // OK, без .value
```

⚠️ `reactive` работает только с объектами. Для примитивов используй `ref`.

`computed()` возвращает `ComputedRef<T>`, тип выводится из return:

```ts
const total = computed(() => price.value * quantity.value);
// ComputedRef<number> - выведен автоматически
```

## Composables

Типизированный composable - обычная функция, возвращающая реактивные данные:

```ts
import { ref, type Ref } from 'vue';

function useFetch<T>(url: string) {
  const data = ref<T | null>(null) as Ref<T | null>;
  const error = ref<Error | null>(null);
  const loading = ref(true);

  async function refresh() {
    loading.value = true;
    error.value = null;
    try {
      const res = await fetch(url);
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      data.value = await res.json();
    } catch (e) {
      error.value = e instanceof Error ? e : new Error(String(e));
    } finally {
      loading.value = false;
    }
  }

  refresh();
  return { data, error, loading, refresh };
}

const { data: users, loading } = useFetch<User[]>('/api/users');
```

<b class="text-on-semi-light">Зачем as Ref?</b> - <span class="text-gray">TypeScript иногда не может вывести generic-тип ref при null. Каст `as Ref<T | null>` помогает.</span>

## Template refs

```vue
<!-- Vue 3.5+ (рекомендуется) -->
<script setup lang="ts">
import { useTemplateRef } from 'vue';
const inputRef = useTemplateRef<HTMLInputElement>('email');
</script>

<template>
  <input ref="email" />
</template>
```

```ts
// Vue 3.0-3.4: имя переменной должно совпадать с ref в шаблоне
const email = ref<HTMLInputElement | null>(null);
```

`useTemplateRef` (Vue 3.5) убирает неявное связывание по имени переменной.

## provide / inject

Типизация через `InjectionKey`:

```ts
import { provide, inject, type InjectionKey } from 'vue';

const UserKey: InjectionKey<User> = Symbol('user');

// Родитель
provide(UserKey, { id: 1, name: 'Alice' });

// Потомок
const user = inject(UserKey);           // User | undefined
const safe = inject(UserKey, fallback); // User (без undefined)
```

<b class="text-on-semi-light">Зачем Symbol?</b> - <span class="text-gray">Symbol гарантирует уникальность ключа. `InjectionKey<T>` добавляет типизацию, которую подхватывает inject.</span>

## Pinia store

```ts
import { defineStore } from 'pinia';

interface Todo { id: number; text: string; done: boolean; }

export const useTodoStore = defineStore('todos', {
  state: () => ({
    items: [] as Todo[],
    filter: 'all' as 'all' | 'active' | 'done',
  }),
  getters: {
    filtered(state): Todo[] {
      if (state.filter === 'active') return state.items.filter((t) => !t.done);
      if (state.filter === 'done') return state.items.filter((t) => t.done);
      return state.items;
    },
  },
  actions: {
    add(text: string) {
      this.items.push({ id: Date.now(), text, done: false });
    },
  },
});
```

State выводится из return-типа функции. Getters и actions типизируются через аннотации параметров.

import MyComponent from './MyComponent.vue';

type MyComponentInstance = InstanceType<typeof MyComponent>;
const compRef = ref<MyComponentInstance | null>(null);

// Дочерний компонент делает defineExpose({ reset })
compRef.value?.reset(); // TypeScript знает о reset()

## Частые вопросы на собесе

<b class="text-on-semi-light">Как типизировать props во Vue 3?</b>
<span class="text-gray">Через type-only `defineProps<Props>()`. Дефолты задаются через `withDefaults`. Это рекомендуемый подход с Vue 3.3+.</span>

<b class="text-on-semi-light">Разница ref и reactive с точки зрения типов?</b>
<span class="text-gray">`ref<T>()` возвращает `Ref<T>`, доступ через `.value`. `reactive<T>()` возвращает `T` напрямую, но работает только с объектами.</span>

<b class="text-on-semi-light">Как типизировать provide/inject?</b>
<span class="text-gray">Через `InjectionKey<T>` из vue. Создаёшь `const key: InjectionKey<T> = Symbol()`, используешь его в provide и inject.</span>

<b class="text-on-semi-light">Что такое defineModel?</b>
<span class="text-gray">Макрос Vue 3.4+ для типизированного v-model. Заменяет пару props + emit одной строкой: `defineModel<string>()`.</span>

<b class="text-on-semi-light">Как получить тип экземпляра компонента?</b>
<span class="text-gray">`InstanceType<typeof MyComponent>`. Используется для типизации ref на дочерний компонент.</span>
