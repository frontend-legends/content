# TypeScript с Vue

Как типизировать Vue-код: `<script setup lang="ts">`, `defineProps`, `defineEmits`, `defineModel`, `ref` и `reactive`, ссылки на элементы шаблона, `provide` и `inject`, дженерик-компоненты и сторы Pinia, а также проверка шаблонов через `vue-tsc`. Спрашивают, как типизировать пропсы, чем `ref` отличается от `reactive` с точки зрения типов и как типизировать `provide/inject`. Глубже — как тип пропсов превращается в рантайм-описание, почему `inject` возвращает `undefined` в типе и зачем нужен отдельный `vue-tsc`.

::tldr
- **Пропсы и события описывают типом:** `defineProps<{ product: Product }>()`, `defineEmits<{ add: [id: number] }>()`. Компилятор SFC превращает тип в рантайм-описание, поэтому тип должен быть ему понятен.
- **`ref` — обёртка с `.value`, `reactive` — прокси объекта.** Внутри `reactive` и шаблона `ref` разворачивается, а деструктуризация `reactive` теряет связь, и тип этого не показывает.
- **`inject` возвращает `T | undefined`:** провайдера может не быть. Тип связывают с ключом через `InjectionKey<T>`.
- **Шаблон тоже проверяется, но не `tsc`, а `vue-tsc`:** он понимает `.vue` и ловит опечатки в шаблоне, неверные пропсы и события.
- **Дженерик-компонент объявляется атрибутом `generic="T"`,** слоты — через `defineSlots`, и тип данных доходит до содержимого слота.
::

## script setup и проверка

TypeScript во Vue включают атрибутом:

```vue
<script setup lang="ts">
const count = ref(0);
</script>
```

Сам `tsc` файлы `.vue` не понимает: для него это неизвестное расширение. Проверку делает **`vue-tsc`** — обёртка над компилятором TypeScript, которая превращает `.vue` в виртуальный TypeScript-код, включая шаблон, и проверяет его. В CI вместо `tsc --noEmit` запускают `vue-tsc --noEmit` (подробно — в [Инструментах TypeScript](/content/advanced-tooling/typescript-tooling)). Та же технология (Volar) работает в редакторе.

`vue-tsc` встраивается в компилятор через его программный API. У нативного TypeScript 7 такого API пока нет, поэтому Vue-проекты проверяют на TypeScript 6. Примеры этой истории проверены `vue-tsc` с TypeScript 6 и включённым `strictTemplates`.

Начнём с того, что компонент получает снаружи.

## Пропсы, события и v-model

### defineProps

Пропсы описывают типом:

```vue
<script setup lang="ts">
type Product = { id: number; title: string; price: number };

const { product, currency = '₽', compact = false } = defineProps<{
  product: Product;
  currency?: string;
  compact?: boolean;
}>();
</script>
```

`defineProps` — макрос: его нет в рантайме, компилятор SFC заменяет вызов на рантайм-описание `props: { product: { type: Object, required: true }, ... }`. Отсюда ограничение: компилятор должен понять тип **статически**. Литералы объектов, интерфейсы и импортированные типы он разбирает, а сложные условные типы — нет.

Значения по умолчанию задают деструктуризацией. Деструктурированные пропсы остаются реактивными: компилятор переписывает обращения к `currency` на `props.currency`. Старая форма — `withDefaults(defineProps<...>(), { currency: '₽' })`, она ещё встречается в коде.

Тип проверяется в месте использования, и это работает в шаблонах родителя:

```vue
<ProductCard />                                 <!-- ошибка: нет обязательного product -->
<ProductCard :product="product" compact="yes" />   <!-- ошибка: compact ждёт boolean -->
```

Вторая ошибка — частая: атрибут без `:` передаёт строку, а булев проп требует `:compact="true"` или просто `compact`.

### defineEmits

События — объект, где ключ — имя, а значение — кортеж аргументов с именами:

```ts
const emit = defineEmits<{
  add: [id: number, qty: number];
  remove: [id: number];
}>();

emit('add', product.id, 1);   // ок
emit('add', product.id);      // ошибка: не хватает qty
emit('buy', product.id);      // ошибка: нет такого события
```

Родитель получает типизированный обработчик: `@add="onAdd"` проверит, что `onAdd` принимает `(id: number, qty: number)`.

### defineModel

`v-model` на своём компоненте — пара «проп и событие обновления». `defineModel` объявляет их одной строкой и возвращает `ref`:

```ts
const qty = defineModel<number>({ required: true });   // Ref<number>
const note = defineModel<string>('note');              // Ref<string | undefined>

qty.value++;   // родитель получит update:modelValue
```

Без `required: true` значение может быть `undefined`, и тип это отражает. Родитель пишет `<QtyInput v-model="qty" />` и `v-model:note="text"`.

Пропсы пришли. Дальше — собственное состояние компонента.

## ref, reactive и computed

```ts
const count = ref(0);                                        // Ref<number>
const user = ref<{ id: number; name: string } | null>(null);   // Ref<... | null>
const items = ref([]);                                        // Ref<never[]> — нужен параметр
const double = computed(() => count.value * 2);               // ComputedRef<number>
```

Правила вывода те же, что у `useState` в React: из пустого массива получается `never[]`, а `null` до загрузки требует явного параметра.

### Развёртывание

`ref` — объект с полем `.value`. Но в двух местах `.value` писать не нужно, и типы это знают:

- **в шаблоне** — `{{ count }}` вместо `{{ count.value }}`;
- **внутри `reactive`** — `ref` в свойстве разворачивается:

```ts
const cart = reactive({ total: ref(0), items: [] as string[] });
cart.total;   // number, не Ref<number>
```

Тип `reactive` повторяет исходный объект с развёрнутыми ссылками, и поэтому ловушку деструктуризации он не показывает:

```ts
const { total } = cart;   // number — копия, связь с cart потеряна
cart.total = 10;
total;                    // всё ещё старое значение
```

Тип `total` — `number`, и это правда: просто число больше не реактивно. Чтобы сохранить связь, берут `toRefs(cart)` — тогда `total` будет `Ref<number>` (подробно — в [Основах реактивности](/content/vuejs/reactivity-fundamentals)). Из-за этой разницы в типах многие команды используют `ref` везде: по типу сразу видно, где реактивная ссылка.

Состояние описано. Иногда компоненту нужен доступ к элементу или дочернему компоненту.

## Ссылки на шаблон

`useTemplateRef` связывает переменную с атрибутом `ref` в шаблоне:

```vue
<script setup lang="ts">
const input = useTemplateRef<HTMLInputElement>('search');   // ShallowRef<HTMLInputElement | null>
onMounted(() => input.value?.focus());
</script>

<template>
  <input ref="search">
</template>
```

`null` в типе честный: до монтирования и после `v-if="false"` элемента нет.

Для дочернего компонента параметр — тип его экземпляра:

```ts
const card = useTemplateRef<InstanceType<typeof ProductCard>>('card');
card.value?.focus();
```

`<script setup>` закрыт по умолчанию: снаружи видно только то, что компонент отдал через `defineExpose({ focus })`. Тип экземпляра это учитывает — обращение к внутреннему методу не скомпилируется.

## provide и inject

Строковый ключ ничего не говорит о типе: `inject('theme')` возвращает `unknown`. Тип связывают с ключом-символом:

```ts
type Theme = { color: string };
export const ThemeKey: InjectionKey<Theme> = Symbol('theme');

provide(ThemeKey, { color: 'green' });    // проверяется по Theme
provide(ThemeKey, { colour: 'green' });   // ошибка

const theme = inject(ThemeKey);                      // Theme | undefined
const theme2 = inject(ThemeKey, { color: 'black' }); // Theme — есть значение по умолчанию
```

`undefined` в типе — не перестраховка: компонент можно отрисовать без провайдера, и тогда `inject` вернёт `undefined` с предупреждением «injection not found». Это проверено. Как в React с контекстом, удобно обернуть `inject` в функцию, которая бросает понятную ошибку и возвращает `Theme` без `undefined` (подробно о самом механизме — в [Provide и inject](/content/vuejs/provide-inject)).

## Дженерик-компоненты и слоты

Список, который сохраняет тип элементов, объявляют атрибутом `generic`:

```vue
<script setup lang="ts" generic="T extends { id: number }">
defineProps<{ items: T[] }>();
defineSlots<{ item(props: { item: T; index: number }): any }>();
</script>

<template>
  <ul>
    <li v-for="(item, index) in items" :key="item.id">
      <slot name="item" :item="item" :index="index" />
    </li>
  </ul>
</template>
```

`T` выводится из `items` у родителя, и содержимое слота получает точный тип:

```vue
<List :items="rows">
  <template #item="{ item }">{{ item.title }}</template>   <!-- item: { id: number; title: string } -->
</List>
```

Обращение к `item.price`, которого нет в `rows`, — ошибка в шаблоне родителя. `defineSlots` описывает, какие слоты есть и что они получают, иначе параметры слота — `any`.

## Сторы Pinia

Setup-стор пишется как композабл, и типы выводятся из него без аннотаций:

```ts
export const useCart = defineStore('cart', () => {
  const lines = ref<{ sku: string; qty: number }[]>([]);
  const total = computed(() => lines.value.reduce((s, l) => s + l.qty, 0));
  function add(sku: string) { lines.value.push({ sku, qty: 1 }); }
  return { lines, total, add };
});

const store = useCart();
store.total;    // number — ref и computed развёрнуты, как в reactive
store.add(1);   // ошибка: add принимает строку
```

Стор — `reactive`-объект, поэтому деструктуризация теряет реактивность так же, как у `reactive`. Для состояния и геттеров берут `storeToRefs(store)`, действия деструктурируют напрямую (подробно — в [Управлении состоянием](/content/vuejs/state-management)).

## Красные флаги в ответе

- **«`tsc` проверит и `.vue`-файлы».** Он их не видит, нужен `vue-tsc`, и он проверяет шаблон тоже.
- **«`defineProps` принимает любой тип».** Тип разбирает компилятор SFC, сложные условные типы он не поймёт.
- **«`inject` с `InjectionKey` всегда возвращает значение».** Тип — `T | undefined`, без провайдера будет `undefined`.
- **«Деструктуризация `reactive` безопасна, раз типы совпадают».** Тип `number` верен, но значение больше не реактивно.
- **«Пропсы и события в шаблоне не проверяются».** С `vue-tsc` проверяются: обязательные пропсы, типы значений, сигнатуры обработчиков.

## Как спрашивают на собеседовании

::question
Как типизировать пропсы во Vue 3?

#answer
Через тип в `defineProps<{ title: string; count?: number }>()` в `<script setup lang="ts">`. Значения по умолчанию — деструктуризацией: `const { count = 0 } = defineProps<...>()`.

#more
`defineProps` — макрос: компилятор SFC превращает тип в рантайм-описание пропсов, поэтому тип должен разбираться статически — интерфейсы и импортированные типы можно, сложные условные нельзя. Деструктурированные пропсы остаются реактивными. Альтернатива — `withDefaults`. Проверку в шаблонах родителя делает `vue-tsc`.
::

::question
Чем ref отличается от reactive с точки зрения типов?

#answer
`ref(0)` — `Ref<number>`, значение в `.value`. `reactive(obj)` — тип исходного объекта, где вложенные `ref` развёрнуты. В шаблоне `ref` тоже разворачивается.

#more
Тип `reactive` не показывает, что деструктуризация теряет реактивность: `const { total } = cart` — `number`, просто не реактивный. `toRefs` возвращает `Ref` для каждого свойства. `reactive` не принимает примитивы. Поэтому часто используют `ref` везде: по типу видно реактивную ссылку.
::

::question
Как типизировать provide и inject?

#answer
Ключом `InjectionKey<T>`: `const ThemeKey: InjectionKey<Theme> = Symbol('theme')`. `provide(ThemeKey, value)` проверяет значение, `inject(ThemeKey)` возвращает `Theme | undefined`.

#more
`undefined` — потому что провайдера может не быть. Со значением по умолчанию `inject(ThemeKey, fallback)` возвращает `Theme`. Удобно обернуть в функцию `useTheme()`, которая бросает ошибку без провайдера. Строковый ключ даёт `unknown`. Ключ-символ ещё и исключает коллизии имён.
::

::question
Что такое defineModel?

#answer
Макрос для двусторонней привязки: объявляет проп `modelValue` и событие `update:modelValue` и возвращает `ref`. Запись в него отправляет событие родителю. `defineModel<number>({ required: true })` — `Ref<number>`.

#more
Без `required` тип — `Ref<T | undefined>`. Именованные модели — `defineModel<string>('note')` и `v-model:note` у родителя. Модификаторы `v-model` тоже доступны через `defineModel`. До него то же самое писали вручную через `props` и `emit`.
::

::question
Как получить тип экземпляра компонента?

#answer
`InstanceType<typeof MyComponent>`. Его передают в `useTemplateRef<InstanceType<typeof ProductCard>>('card')`, чтобы вызывать методы дочернего компонента.

#more
`<script setup>` закрыт: в экземпляре видно только то, что отдано через `defineExpose`. Пропсы компонента достают через `ComponentProps` из вспомогательных библиотек или повторно используют экспортированный тип. Ссылка на элемент — `useTemplateRef<HTMLInputElement>('name')`, тип `ShallowRef<HTMLInputElement | null>`.
::

::question
Зачем нужен vue-tsc?

#answer
`tsc` не понимает `.vue`-файлы. `vue-tsc` превращает их, включая шаблон, в виртуальный TypeScript и проверяет: опечатки в шаблоне, обязательные пропсы, типы значений, обработчики событий, параметры слотов.

#more
В CI запускают `vue-tsc --noEmit`, а `strictTemplates` делает проверку шаблонов строже, например запрещает неизвестные атрибуты на компонентах. `vue-tsc` работает через программный API TypeScript, которого нет в нативном TypeScript 7, поэтому Vue-проекты пока проверяют на TypeScript 6.
::

## Практика

::practice{title="Счётчик с v-model"}
Сделай компонент `QtyInput`, который работает через `v-model`: значение — число, обязательно. Дополнительно — необязательная модель `note`.

#solution
```vue
<script setup lang="ts">
const qty = defineModel<number>({ required: true });
const note = defineModel<string>('note');
</script>

<template>
  <input v-model.number="qty" type="number">
  <input v-model="note" placeholder="Комментарий">
</template>
```

```vue
<QtyInput v-model="qty" v-model:note="comment" />
```

`qty` — `Ref<number>`, `note` — `Ref<string | undefined>`: без `required` модель может быть не передана. Это видно и у родителя: событие `update:note` несёт `string | undefined`, поэтому `v-model:note` на `ref('')` с типом `Ref<string>` не скомпилируется. Переменная родителя должна допускать `undefined`, либо модели задают значение по умолчанию: `defineModel<string>('note', { default: '' })` — тогда тип `Ref<string>`. Модификатор `.number` приводит строку из поля к числу. В проверке `v-model:note` на `Ref<string>` дал ошибку, а с `default` — прошёл.
::

::practice{title="Почему не видно опечатку?"}
В проекте проверка типов в CI — `tsc --noEmit`, и она проходит. Но в шаблоне опечатка:

```vue
<template>
  <p>{{ product.prise }}</p>
</template>
```

#solution
`tsc` не открывает `.vue`-файлы — шаблоны и `<script setup>` для него не существуют. Шаг в CI меняют на `vue-tsc`:

```json
{
  "scripts": {
    "typecheck": "vue-tsc --noEmit"
  }
}
```

`vue-tsc` находит `Property 'prise' does not exist on type 'Product'. Did you mean 'price'?` прямо в шаблоне. В `tsconfig.json` стоит включить `"vueCompilerOptions": { "strictTemplates": true }`. Сам `vue-tsc` нужно держать на TypeScript 6, пока у TypeScript 7 нет программного API. В проверке `vue-tsc` нашёл опечатку в шаблоне с подсказкой `price`.
::

::practice{title="Список с типизированным слотом"}
Компонент `List` принимает массив элементов с `id` и даёт слот `item` для отрисовки. Сделай так, чтобы у родителя в слоте был точный тип элемента.

#solution
```vue
<script setup lang="ts" generic="T extends { id: number }">
defineProps<{ items: T[] }>();
defineSlots<{ item(props: { item: T; index: number }): any }>();
</script>

<template>
  <ul>
    <li v-for="(item, index) in items" :key="item.id">
      <slot name="item" :item="item" :index="index" />
    </li>
  </ul>
</template>
```

```vue
<List :items="products">
  <template #item="{ item }">{{ item.title }}</template>
</List>
```

`generic` делает компонент дженериком, `T` выводится из `items`. Ограничение `extends { id: number }` нужно для `:key`. `defineSlots` описывает параметры слота, без него `item` — `any`. В проверке `item.title` прошёл, а `item.price` — ошибка в шаблоне родителя.
::
