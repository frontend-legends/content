# Композиция типов

Когда базовых типов не хватает - а их не хватает почти сразу - начинается самое интересное. TypeScript позволяет комбинировать типы как конструктор: склеивать, пересекать, давать псевдонимы. Именно здесь раскрывается настоящая мощь системы типов.

## Union Types - объединение

Union (объединение) говорит: "значение может быть одним из нескольких типов". Записывается через вертикальную черту `|`.

```ts
type Status = 'loading' | 'success' | 'error';
type ID = string | number;

function printId(id: string | number) {
  // Здесь id может быть и string, и number
  // Нужно сузить тип перед использованием
  if (typeof id === 'string') {
    console.log(id.toUpperCase());
  } else {
    console.log(id.toFixed(2));
  }
}
```

Практический пример - статус ответа от API:

```ts
type ApiStatus = 'idle' | 'loading' | 'success' | 'error';

interface AppState {
  status: ApiStatus;
  data: string[] | null;
  error: string | null;
}
```

> ⚠️ Чтобы работать с конкретным типом из union, нужно выполнить **narrowing** - сужение типа. Подробнее - в разделе [Type Narrowing](/content/typescript/type-narrowing).

## Intersection Types - пересечение

Intersection (пересечение) объединяет несколько типов в один через `&`. Результат содержит все свойства всех типов.

```ts
interface Role {
  role: 'admin' | 'user' | 'moderator';
}

interface Permissions {
  canEdit: boolean;
  canDelete: boolean;
}

type AdminUser = Role & Permissions;

const admin: AdminUser = {
  role: 'admin',
  canEdit: true,
  canDelete: true,
};
```

Intersection полезен, когда нужно "подмешать" дополнительные свойства:

```ts
type WithTimestamps = {
  createdAt: Date;
  updatedAt: Date;
};

type Product = {
  name: string;
  price: number;
};

type ProductRecord = Product & WithTimestamps;
```

## Type Aliases - псевдонимы типов

Ключевое слово `type` создает псевдоним для любого типа - примитива, объекта, union, функции, чего угодно.

```ts
// Примитив
type ID = string;

// Union
type Theme = 'light' | 'dark';

// Функция
type Formatter = (value: number) => string;

// Объект
type Point = { x: number; y: number };

// Кортеж
type Pair<T> = [T, T];

// Сложная комбинация
type EventHandler = (event: MouseEvent | KeyboardEvent) => void;
```

## Interfaces - интерфейсы

Ключевое слово `interface` описывает форму объекта. Поддерживает наследование (`extends`) и declaration merging.

```ts
interface User {
  id: number;
  name: string;
}

interface Employee extends User {
  department: string;
  salary: number;
}

const employee: Employee = {
  id: 1,
  name: 'Иван',
  department: 'Frontend',
  salary: 150000,
};
```

<b class="text-on-semi-light">Declaration merging</b> <span class="text-gray">- уникальная способность интерфейсов. Два одноименных интерфейса автоматически объединяются:</span>

```ts
interface Window {
  myCustomProperty: string;
}

// Теперь глобальный Window содержит myCustomProperty
window.myCustomProperty = 'hello';
```

Это активно используется для расширения сторонних библиотек.

## Type vs Interface - сравнение

Один из самых частых вопросов на собеседованиях. Вот полная таблица:

| Возможность | type | interface |
|---|---|---|
| Расширение | `&` intersection | `extends` |
| Declaration merging | Нет | Да |
| Union / intersection | Да | Нет |
| Mapped types | Да | Нет |
| Computed properties | Да | Нет |
| Примитивы | Да (`type ID = string`) | Нет |
| `implements` в классе | Да | Да |
| Производительность | Чуть медленнее для сложных типов | Чуть быстрее |
| Рекомендация | Сложные типы, union-ы | Формы объектов, публичные API |

<b class="text-on-semi-light">Практическое правило</b> <span class="text-gray">- используйте `interface` для описания объектов и публичных контрактов, `type` - для union-ов, пересечений и сложных вычислений над типами.</span>

## Index Signatures - индексные подписи

Когда заранее неизвестны точные имена свойств:

```ts
interface StringMap {
  [key: string]: number;
}

const scores: StringMap = {
  math: 95,
  physics: 88,
  chemistry: 72,
};

// Можно добавить любой строковый ключ
scores.biology = 90;
```

Можно комбинировать с конкретными свойствами:

```ts
interface Config {
  version: number;
  [key: string]: string | number;
}
```

## Операторы типов

### keyof - получение ключей

`keyof T` возвращает union всех ключей типа `T`:

```ts
interface User {
  id: number;
  name: string;
  email: string;
}

type UserKey = keyof User; // 'id' | 'name' | 'email'

function getValue(user: User, key: keyof User) {
  return user[key];
}
```

### typeof в контексте типов

`typeof` в позиции типа извлекает тип из значения:

```ts
const config = {
  host: 'localhost',
  port: 3000,
  debug: true,
};

type Config = typeof config;
// { host: string; port: number; debug: boolean }

function updateConfig(newConfig: Partial<typeof config>) {
  Object.assign(config, newConfig);
}
```

### Indexed Access Types

Извлечение типа свойства по ключу:

```ts
interface User {
  id: number;
  name: string;
  address: {
    city: string;
    zip: string;
  };
}

type UserName = User['name'];       // string
type UserAddress = User['address'];  // { city: string; zip: string }
type City = User['address']['city']; // string

// С массивами
type Statuses = ['active', 'inactive', 'banned'];
type Status = Statuses[number]; // 'active' | 'inactive' | 'banned'
```

## Module Augmentation - расширение сторонних типов

Бывает, что типы из библиотеки нужно дополнить. Для этого используется `declare module`:

```ts
// types/express.d.ts
declare module 'express' {
  interface Request {
    user?: {
      id: string;
      role: string;
    };
  }
}
```

Теперь `req.user` доступен без ошибок во всех обработчиках Express.

Аналогично можно расширить глобальные типы:

```ts
declare global {
  interface Window {
    analytics: {
      track: (event: string) => void;
    };
  }
}
```

## Частые вопросы на собесе

<b class="text-on-semi-light">В чем разница между type и interface?</b>
<span class="text-gray">`interface` поддерживает declaration merging и `extends`, оптимизирован для описания объектов. `type` поддерживает union, intersection, mapped types и может описывать примитивы. Для объектов предпочтительнее `interface`, для сложных типов - `type`.</span>

<b class="text-on-semi-light">Что такое declaration merging?</b>
<span class="text-gray">Если объявить два интерфейса с одинаковым именем, TypeScript автоматически объединит их в один. С `type` это невозможно - будет ошибка. Merging используется для расширения типов сторонних библиотек.</span>

<b class="text-on-semi-light">Когда использовать union, а когда intersection?</b>
<span class="text-gray">Union (`A | B`) - когда значение может быть одним из нескольких типов. Intersection (`A & B`) - когда значение должно удовлетворять всем типам одновременно.</span>

<b class="text-on-semi-light">Что делает keyof?</b>
<span class="text-gray">`keyof T` возвращает union всех ключей типа `T`. Это основа для многих utility types и типобезопасного доступа к свойствам.</span>

<b class="text-on-semi-light">Можно ли расширить типы из node_modules?</b>
<span class="text-gray">Да, через module augmentation (`declare module 'library-name'`). Для интерфейсов сработает declaration merging. Типы (`type`) расширить таким образом нельзя.</span>
