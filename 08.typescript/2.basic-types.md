# Базовые типы

TypeScript предоставляет набор базовых типов, которые покрывают большинство повседневных задач. Понимание этих типов - фундамент для работы с более сложными конструкциями.

---

## Примитивные типы

<b class="text-on-semi-light">string, number, boolean</b> - <span class="text-gray">три основных примитива, с которыми ты работаешь каждый день.</span>

```ts
let name: string = 'Alice';
let age: number = 30;
let isActive: boolean = true;

// number включает целые, дробные, Infinity, NaN
let float: number = 3.14;
let hex: number = 0xff;
let inf: number = Infinity;
let notANumber: number = NaN; // да, NaN - это number
```

---

## null и undefined

В strict mode (`strictNullChecks: true`) - а он должен быть включён всегда - `null` и `undefined` являются отдельными типами. Ты не можешь присвоить `null` переменной типа `string`.

```ts
// strictNullChecks: true
let name: string = null;      // Ошибка!
let name: string | null = null; // Ок, используем union type

// Опциональные параметры автоматически включают undefined
function greet(name?: string) {
  // name имеет тип string | undefined
  console.log(name?.toUpperCase());
}
```

## symbol и bigint

```ts
// symbol - уникальный идентификатор
const id: symbol = Symbol('id');
const uniqueKey: unique symbol = Symbol('key'); // конкретный символ

// bigint - для чисел больше Number.MAX_SAFE_INTEGER
const big: bigint = 9007199254740991n;
const alsoBig: bigint = BigInt(9007199254740991);
```

## Специальные типы

Это тема, на которой часто проваливаются на собеседованиях. Разберём каждый тип подробно.

### any

<b class="text-on-semi-light">any</b> - <span class="text-gray">полностью отключает проверку типов. Переменная с типом any может быть чем угодно и использоваться как угодно.</span>

```ts
let value: any = 42;
value = 'hello';       // Ок
value = true;          // Ок
value.foo.bar.baz;     // Ок для компилятора, но упадёт в рантайме
value();               // Ок для компилятора, но упадёт в рантайме
```

⚠️ Использование `any` - это антипаттерн в большинстве случаев. Оно лишает тебя всех преимуществ TypeScript.

### unknown

<b class="text-on-semi-light">unknown</b> - <span class="text-gray">безопасная альтернатива any. Ты можешь присвоить что угодно, но не можешь использовать значение без сужения типа.</span>

```ts
let value: unknown = 42;
value = 'hello'; // Ок - присвоить можно

// Но использовать напрямую нельзя
value.toUpperCase(); // Ошибка!

// Нужно сначала сузить тип
if (typeof value === 'string') {
  value.toUpperCase(); // Ок - TS знает, что тут string
}
```

### never

<b class="text-on-semi-light">never</b> - <span class="text-gray">тип для значений, которые никогда не возникают. Функция, которая всегда бросает ошибку или содержит бесконечный цикл.</span>

```ts
// Функция, которая никогда не завершается
function throwError(msg: string): never {
  throw new Error(msg);
}

// Exhaustive check - самое полезное применение
type Shape = 'circle' | 'square' | 'triangle';

function getArea(shape: Shape): number {
  switch (shape) {
    case 'circle': return Math.PI * 10;
    case 'square': return 100;
    case 'triangle': return 50;
    default:
      // Если добавят новый shape и забудут case - TS покажет ошибку
      const _exhaustive: never = shape;
      return _exhaustive;
  }
}
```

### void

<b class="text-on-semi-light">void</b> - <span class="text-gray">функция ничего не возвращает (или возвращает undefined).</span>

```ts
function logMessage(msg: string): void {
  console.log(msg);
  // Нет return
}
```

### Сравнительная таблица

| Тип | Можно присвоить что угодно | Можно использовать без сужения | Когда использовать |
|---|---|---|---|
| `any` | Да | Да (опасно!) | Миграция с JS, крайние случаи |
| `unknown` | Да | Нет - нужно сужение | Входные данные, API-ответы |
| `never` | Нет | Нет | Exhaustive check, функции с throw |
| `void` | Нет | Нет | Return type функций без возврата |

## Literal types

Ты можешь использовать конкретные значения как типы. Это мощный инструмент для создания точных типов.

```ts
// Строковые литералы
type Direction = 'up' | 'down' | 'left' | 'right';
let dir: Direction = 'up'; // Ок
let dir2: Direction = 'diagonal'; // Ошибка!

// Числовые литералы
type DiceRoll = 1 | 2 | 3 | 4 | 5 | 6;

// Булевы литералы
type Success = true;
```

Literal types особенно полезны в union types для создания discriminated unions - об этом подробнее в следующих разделах.

## Enum

<b class="text-on-semi-light">Enum</b> - <span class="text-gray">набор именованных констант.</span>

```ts
// Numeric enum (значения автоинкрементируются)
enum Direction {
  Up,    // 0
  Down,  // 1
  Left,  // 2
  Right, // 3
}

// String enum (нужно указать каждое значение)
enum Status {
  Active = 'ACTIVE',
  Inactive = 'INACTIVE',
  Pending = 'PENDING',
}

// const enum - инлайнится при компиляции
const enum Color {
  Red = 'RED',
  Green = 'GREEN',
  Blue = 'BLUE',
}
```

### Gotchas с enum

```ts
// Numeric enum имеет reverse mapping - можно получить имя по значению
enum Direction {
  Up,    // 0
  Down,  // 1
}

console.log(Direction[0]); // 'Up' - reverse mapping
console.log(Direction.Up); // 0

// Проблема: numeric enum принимает ЛЮБОЕ число
let dir: Direction = 42; // Нет ошибки! TS это пропускает
```

⚠️ Tree-shaking проблемы: обычные enum компилируются в IIFE, которые бандлеры не могут удалить при tree-shaking. Решение - `const enum` или объекты с `as const`.

### Альтернатива enum - as const объект

```ts
// Рекомендуемый подход
const Direction = {
  Up: 'UP',
  Down: 'DOWN',
  Left: 'LEFT',
  Right: 'RIGHT',
} as const;

type Direction = typeof Direction[keyof typeof Direction];
// type Direction = 'UP' | 'DOWN' | 'LEFT' | 'RIGHT'
```

Этот подход лучше enum, потому что: нет проблем с tree-shaking, работает как обычный JS-объект, и тип получается точным union литералов.

## Объекты

```ts
// Inline object type
let user: { name: string; age: number } = {
  name: 'Alice',
  age: 30,
};

// Optional properties
let config: { host: string; port?: number } = {
  host: 'localhost',
  // port не обязателен
};

// readonly - нельзя изменить после создания
let point: { readonly x: number; readonly y: number } = { x: 10, y: 20 };
point.x = 30; // Ошибка!
```

## Массивы

```ts
// Два синтаксиса - эквивалентны
let numbers: number[] = [1, 2, 3];
let strings: Array<string> = ['a', 'b', 'c'];

// Readonly массивы - нельзя push, pop, splice
let items: readonly number[] = [1, 2, 3];
items.push(4); // Ошибка!

// ReadonlyArray generic
let data: ReadonlyArray<string> = ['hello'];
```

## Tuples

<b class="text-on-semi-light">Tuple</b> - <span class="text-gray">массив фиксированной длины, где каждый элемент имеет свой тип.</span>

```ts
// Базовый tuple
let pair: [string, number] = ['Alice', 30];

// Labeled tuple (TS 4.0+) - улучшает читаемость
type UserTuple = [name: string, age: number, isActive: boolean];
let user: UserTuple = ['Alice', 30, true];

// Optional elements
type Config = [string, number?];
let c1: Config = ['host'];
let c2: Config = ['host', 3000];

// Rest elements
type StringAndNumbers = [string, ...number[]];
let data: StringAndNumbers = ['header', 1, 2, 3, 4, 5];
```

Tuples полезны для функций, возвращающих несколько значений (как `useState` в React):

```ts
function useState<T>(initial: T): [T, (value: T) => void] {
  let state = initial;
  const setState = (value: T) => { state = value; };
  return [state, setState];
}

const [count, setCount] = useState(0);
// count: number, setCount: (value: number) => void
```

## as const

<b class="text-on-semi-light">as const</b> - <span class="text-gray">делает значение readonly и сужает тип до литерального. Крайне полезная конструкция.</span>

```ts
// Без as const
const colors = ['red', 'green', 'blue']; // type: string[]

// С as const
const colors = ['red', 'green', 'blue'] as const; // type: readonly ['red', 'green', 'blue']

// Без as const
const config = { host: 'localhost', port: 3000 };
// type: { host: string; port: number }

// С as const
const config = { host: 'localhost', port: 3000 } as const;
// type: { readonly host: 'localhost'; readonly port: 3000 }
```

`as const` незаменим, когда ты хочешь извлечь union type из объекта или массива:

```ts
const ROLES = ['admin', 'user', 'moderator'] as const;
type Role = typeof ROLES[number]; // 'admin' | 'user' | 'moderator'
```

## satisfies

<b class="text-on-semi-light">satisfies</b> - <span class="text-gray">оператор из TS 4.9, который проверяет соответствие типу без расширения (widening).</span>

```ts
type Colors = Record<string, [number, number, number] | string>;

// С обычной аннотацией - теряем точный тип
const palette: Colors = {
  red: [255, 0, 0],
  green: '#00ff00',
};
palette.red.map(c => c); // Ошибка! TS не знает, что red - массив

// С satisfies - проверяем тип, но сохраняем inference
const palette = {
  red: [255, 0, 0],
  green: '#00ff00',
} satisfies Colors;

palette.red.map(c => c);        // Ок! TS знает, что red - tuple
palette.green.toUpperCase();     // Ок! TS знает, что green - string
```

`satisfies` решает давнюю проблему: раньше приходилось выбирать между проверкой типа и точным inference. Теперь можно получить оба.

## Частые вопросы на собесе

- **В чём разница между any и unknown?** - `any` отключает проверку типов полностью, `unknown` требует сужения перед использованием. Всегда предпочитай `unknown`.
- **Когда использовать never?** - Для exhaustive check в switch, для функций, которые всегда бросают ошибки, и как результат пересечения несовместимых типов.
- **Enum или as const?** - В большинстве случаев `as const` объект лучше: нет проблем с tree-shaking, работает как обычный JS, тип точнее.
- **Что делает satisfies?** - Проверяет, что значение соответствует типу, но не расширяет тип - сохраняет точный inference.
- **Чем tuple отличается от массива?** - Tuple имеет фиксированную длину и конкретные типы для каждой позиции. Массив - произвольная длина одного типа.
- **Что такое as const?** - Делает всё readonly и сужает типы до литералов. Позволяет извлекать union types из значений.
