# Сужение типов

Union типы - это мощно, но работать с ними напрямую нельзя. Если переменная имеет тип `string | number`, TypeScript не позволит вызвать `.toUpperCase()` - а вдруг это число? Нужно **сузить** тип, то есть доказать компилятору, что в конкретной ветке кода значение имеет конкретный тип. Это и есть narrowing.

## typeof guards

Самый простой способ - оператор `typeof`. Работает для примитивов:

```ts
function format(value: string | number): string {
  if (typeof value === 'string') {
    // Здесь TypeScript знает: value - string
    return value.toUpperCase();
  }
  // Здесь TypeScript знает: value - number
  return value.toFixed(2);
}
```

`typeof` возвращает одну из строк: `'string'`, `'number'`, `'boolean'`, `'bigint'`, `'symbol'`, `'undefined'`, `'object'`, `'function'`.

> ⚠️ `typeof null === 'object'` - это историческая ошибка JavaScript. Для проверки на `null` используйте строгое сравнение.

## instanceof guards

Для объектов, созданных через классы, подходит `instanceof`:

```ts
function formatDate(value: string | Date): string {
  if (value instanceof Date) {
    // value: Date
    return value.toISOString();
  }
  // value: string
  return new Date(value).toISOString();
}
```

```ts
class ApiError extends Error {
  constructor(public statusCode: number, message: string) {
    super(message);
  }
}

function handleError(error: Error | ApiError) {
  if (error instanceof ApiError) {
    // error: ApiError
    console.log(`HTTP ${error.statusCode}: ${error.message}`);
  } else {
    // error: Error
    console.log(error.message);
  }
}
```

## Оператор in

Проверяет наличие свойства в объекте:

```ts
interface Bird {
  fly(): void;
  layEggs(): void;
}

interface Fish {
  swim(): void;
  layEggs(): void;
}

function move(animal: Bird | Fish) {
  if ('fly' in animal) {
    // animal: Bird
    animal.fly();
  } else {
    // animal: Fish
    animal.swim();
  }
}
```

<b class="text-on-semi-light">Когда использовать `in`</b> <span class="text-gray">- когда у типов есть уникальные свойства, но нет общего дискриминанта. Это менее надежно, чем discriminated unions, но иногда это единственный вариант.</span>

## Truthiness narrowing

Проверка на "правдивость" убирает `null`, `undefined`, `0`, `""`, `NaN`:

```ts
function printName(name: string | null | undefined) {
  if (name) {
    // name: string (null и undefined отсечены)
    console.log(name.toUpperCase());
  }
}
```

Двойное отрицание для boolean-контекста:

```ts
function processItems(items?: string[]) {
  if (items?.length) {
    // items: string[] и длина > 0
    items.forEach(item => console.log(item));
  }
}
```

> ⚠️ Truthiness narrowing "отсекает" и пустую строку `""`, и число `0`. Если это допустимые значения - используйте строгие проверки.

## Equality narrowing

Строгое сравнение сужает тип:

```ts
function handle(value: string | number | null) {
  if (value === null) {
    // value: null
    return;
  }
  // value: string | number

  if (value !== undefined) {
    // value: string | number (undefined уже и так убран)
  }
}
```

Сравнение двух переменных:

```ts
function compare(a: string | number, b: string | boolean) {
  if (a === b) {
    // Единственный общий тип - string
    // a: string, b: string
    console.log(a.toUpperCase(), b.toLowerCase());
  }
}
```

## Discriminated Unions - размеченные объединения

Это **самый важный паттерн** для работы с union типами в реальных проектах. Каждый вариант union-а содержит общее свойство-дискриминант с литеральным типом.

```ts
interface Circle {
  kind: 'circle';
  radius: number;
}

interface Square {
  kind: 'square';
  side: number;
}

interface Triangle {
  kind: 'triangle';
  base: number;
  height: number;
}

type Shape = Circle | Square | Triangle;
```

`kind` - дискриминант. По нему TypeScript определяет, какой именно вариант перед нами:

```ts
function getArea(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      // shape: Circle
      return Math.PI * shape.radius ** 2;
    case 'square':
      // shape: Square
      return shape.side ** 2;
    case 'triangle':
      // shape: Triangle
      return (shape.base * shape.height) / 2;
  }
}
```

### Практический пример - ответ API

Это паттерн, который встречается буквально в каждом проекте:

```ts
interface SuccessResponse<T> {
  status: 'success';
  data: T;
}

interface ErrorResponse {
  status: 'error';
  message: string;
  code: number;
}

interface LoadingResponse {
  status: 'loading';
}

type ApiResponse<T> = SuccessResponse<T> | ErrorResponse | LoadingResponse;

function renderResponse(response: ApiResponse<string[]>) {
  switch (response.status) {
    case 'success':
      // response.data доступен
      return response.data.join(', ');
    case 'error':
      // response.message и response.code доступны
      return `Ошибка ${response.code}: ${response.message}`;
    case 'loading':
      return 'Загрузка...';
  }
}
```

## Custom Type Guards - пользовательские защитники типов

Когда встроенных проверок не хватает, пишем свою функцию-guard. Возвращаемый тип - `value is Type`:

```ts
interface Cat {
  meow(): void;
}

interface Dog {
  bark(): void;
}

function isCat(animal: Cat | Dog): animal is Cat {
  return 'meow' in animal;
}

function interact(animal: Cat | Dog) {
  if (isCat(animal)) {
    animal.meow(); // OK - TypeScript знает, что это Cat
  } else {
    animal.bark(); // OK - TypeScript вывел, что это Dog
  }
}
```

Более реалистичный пример - валидация данных из API:

```ts
interface User {
  id: number;
  name: string;
  email: string;
}

function isUser(data: unknown): data is User {
  return (
    typeof data === 'object' &&
    data !== null &&
    'id' in data &&
    typeof (data as User).id === 'number' &&
    'name' in data &&
    typeof (data as User).name === 'string' &&
    'email' in data &&
    typeof (data as User).email === 'string'
  );
}

async function fetchUser(): Promise<User> {
  const response = await fetch('/api/user');
  const data: unknown = await response.json();

  if (isUser(data)) {
    return data; // Типобезопасно!
  }

  throw new Error('Invalid user data');
}
```

## Assertion Functions - функции-утверждения

Assertion function бросает ошибку, если условие не выполнено, и сужает тип, если выполнено:

```ts
function assertIsString(value: unknown): asserts value is string {
  if (typeof value !== 'string') {
    throw new Error(`Expected string, got ${typeof value}`);
  }
}

function process(input: unknown) {
  assertIsString(input);
  // После вызова TypeScript знает: input - string
  console.log(input.toUpperCase());
}
```

<b class="text-on-semi-light">Разница между type guard и assertion</b>

| Аспект | Type Guard | Assertion Function |
|---|---|---|
| Возвращаемый тип | `value is Type` | `asserts value is Type` |
| Как работает | Возвращает `boolean` | Бросает ошибку или ничего |
| Где используется | В `if` / тернарнике | Как отдельная инструкция |
| Поток выполнения | Две ветки (if/else) | Одна ветка (после assertion) |

Assertion-функции удобны для валидации входных данных:

```ts
function assertNonNull<T>(
  value: T | null | undefined,
  message = 'Value is null or undefined'
): asserts value is T {
  if (value === null || value === undefined) {
    throw new Error(message);
  }
}

function processOrder(orderId: string | null) {
  assertNonNull(orderId, 'Order ID is required');
  // orderId: string
  console.log(orderId.toUpperCase());
}
```

## Exhaustive Checking с never

`never` - тип, который не может содержать значение. Это позволяет ловить необработанные варианты на этапе компиляции:

```ts
function getArea(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2;
    case 'square':
      return shape.side ** 2;
    case 'triangle':
      return (shape.base * shape.height) / 2;
    default:
      // Если все варианты обработаны, shape имеет тип never
      const _exhaustive: never = shape;
      return _exhaustive;
  }
}
```

Если кто-то добавит новый вариант в `Shape` (например, `Rectangle`), но забудет обработать его в `switch` - TypeScript выдаст ошибку компиляции. Это спасает от целого класса багов.

Можно вынести проверку в утилиту:

```ts
function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${value}`);
}

function getArea(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2;
    case 'square':
      return shape.side ** 2;
    case 'triangle':
      return (shape.base * shape.height) / 2;
    default:
      return assertNever(shape);
  }
}
```

## Частые вопросы на собесе

<b class="text-on-semi-light">Что такое type narrowing?</b>
<span class="text-gray">Механизм TypeScript, позволяющий сузить тип переменной в определенной ветке кода через проверки (`typeof`, `instanceof`, `in`, сравнения). Компилятор анализирует control flow и выводит более конкретный тип.</span>

<b class="text-on-semi-light">Что такое discriminated union?</b>
<span class="text-gray">Union тип, где каждый вариант содержит общее свойство с уникальным литеральным значением (дискриминант). Позволяет TypeScript точно определить вариант через `switch` или `if`. Самый надежный паттерн для работы со сложными union-ами.</span>

<b class="text-on-semi-light">Как написать custom type guard?</b>
<span class="text-gray">Это функция, возвращающая `value is Type`. Внутри - произвольная проверка. TypeScript доверяет результату: если функция вернула `true`, тип сужается.</span>

<b class="text-on-semi-light">Что такое exhaustive checking?</b>
<span class="text-gray">Паттерн, при котором в `default`-ветке `switch` присваиваем значение переменной типа `never`. Если не все варианты union-а обработаны, TypeScript выдаст ошибку компиляции. Гарантирует обработку всех случаев.</span>

<b class="text-on-semi-light">В чем разница между type guard и assertion function?</b>
<span class="text-gray">Type guard возвращает `boolean` и используется в условиях. Assertion function ничего не возвращает (или бросает ошибку) и сужает тип после вызова. Guard дает две ветки, assertion - одну.</span>
