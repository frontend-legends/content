# TypeScript + React

React и TypeScript - одна из самых популярных связок во фронтенде. Типизация компонентов, хуков, событий и контекста делает код предсказуемым и ловит баги ещё до рендера. Разберём основные паттерны, которые встречаются в каждом проекте.

---

## Типизация компонентов

Есть два подхода: `React.FC<Props>` и обычная функция с типизированными пропсами.

```tsx
// Подход 1: FC<Props> (не рекомендуется)
const Button: React.FC<ButtonProps> = ({ label }) => {
  return <button>{label}</button>;
};

// Подход 2: обычная функция (рекомендуется)
function Button({ label }: ButtonProps) {
  return <button>{label}</button>;
}
```

<b class="text-on-semi-light">Почему не FC?</b> - <span class="text-gray">FC неявно добавлял children (до React 18), не поддерживает generic-компоненты, и тип возврата менее гибкий. Обычная функция проще и прозрачнее.</span>

---

## Props interface

```tsx
interface ButtonProps {
  label: string;
  variant?: 'primary' | 'secondary';
  onClick: () => void;
  children?: React.ReactNode;
}

function Button({ label, variant = 'primary', onClick, children }: ButtonProps) {
  return (
    <button onClick={onClick} className={variant}>
      {children ?? label}
    </button>
  );
}
```

<b class="text-on-semi-light">Optional props</b> - <span class="text-gray">помечаются `?`. Дефолтные значения задаются через деструктуризацию.</span>

### Типы для children

| Тип | Что принимает |
|-----|---------------|
| `React.ReactNode` | Всё: строки, числа, элементы, массивы, null, undefined, boolean |
| `React.ReactElement` | Только JSX-элементы (не строки, не числа) |
| `string` | Только строки |
| `React.PropsWithChildren<P>` | Добавляет `children?: ReactNode` к пропсам P |

В 99% случаев используй `React.ReactNode` - это самый гибкий тип.

## useState

TypeScript выводит тип из начального значения:

```tsx
const [count, setCount] = useState(0);           // inferred: number
const [name, setName] = useState('');             // inferred: string
const [user, setUser] = useState<User | null>(null); // explicit: User | null
const [items, setItems] = useState<string[]>([]);    // explicit: string[]
```

<b class="text-on-semi-light">Когда нужен explicit generic?</b> - <span class="text-gray">Когда начальное значение null или пустой массив - TypeScript не может вывести конечный тип.</span>

## useRef

У `useRef` два режима работы - DOM-реф и мутабельный контейнер:

```tsx
// DOM ref - передаётся в ref={} элемента
const inputRef = useRef<HTMLInputElement>(null);

function handleFocus() {
  inputRef.current?.focus(); // current: HTMLInputElement | null
}

return <input ref={inputRef} />;
```

```tsx
// Мутабельный контейнер - как instance variable
const renderCount = useRef(0);
renderCount.current += 1; // можно мутировать напрямую
```

Разница: если передать `null` в `useRef<T>(null)`, TypeScript считает `current` readonly (DOM-паттерн). Если передать значение типа T, `current` будет мутабельным.

## useReducer

Идеальное место для discriminated unions:

```tsx
type Action =
  | { type: 'increment' }
  | { type: 'reset'; payload: number }
  | { type: 'error'; payload: string };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'increment': return { ...state, count: state.count + 1 };
    case 'reset':     return { ...state, count: action.payload, error: null };
    case 'error':     return { ...state, error: action.payload };
  }
}

const [state, dispatch] = useReducer(reducer, { count: 0, error: null });
```

TypeScript проверит, что payload есть только у тех action, которые его требуют.

## useContext

Типизированный контекст с защитой от null:

```tsx
interface ThemeContext {
  theme: 'light' | 'dark';
  toggle: () => void;
}

const ThemeCtx = createContext<ThemeContext | null>(null);

function useTheme(): ThemeContext {
  const ctx = useContext(ThemeCtx);
  if (!ctx) throw new Error('useTheme must be used within ThemeProvider');
  return ctx;
}

function ThemeProvider({ children }: { children: React.ReactNode }) {
  const [theme, setTheme] = useState<'light' | 'dark'>('light');
  const toggle = () => setTheme((t) => (t === 'light' ? 'dark' : 'light'));

  return (
    <ThemeCtx.Provider value={{ theme, toggle }}>
      {children}
    </ThemeCtx.Provider>
  );
}
```

<b class="text-on-semi-light">Зачем null в createContext?</b> - <span class="text-gray">Чтобы не передавать дефолтное значение, которое никогда не будет использоваться. Хук useTheme бросит ошибку, если провайдера нет - это лучше, чем молчаливый баг.</span>

## Event handlers

React использует свои синтетические события. Основные типы:

| Тип | Когда |
|-----|-------|
| `React.ChangeEvent<HTMLInputElement>` | onChange на input |
| `React.FormEvent<HTMLFormElement>` | onSubmit на form |
| `React.MouseEvent<HTMLButtonElement>` | onClick на button |
| `React.KeyboardEvent<HTMLInputElement>` | onKeyDown, onKeyUp |
| `React.FocusEvent<HTMLInputElement>` | onFocus, onBlur |

```tsx
function SearchForm() {
  const [query, setQuery] = useState('');

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    setQuery(e.target.value);
  };

  const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    console.log('Search:', query);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input value={query} onChange={handleChange} />
      <button type="submit">Search</button>
    </form>
  );
}
```

## Generic-компоненты

Компонент может принимать generic-параметр - это мощный паттерн для переиспользуемых UI-элементов:

```tsx
interface ListProps<T> {
  items: T[];
  renderItem: (item: T) => React.ReactNode;
  keyExtractor: (item: T) => string;
}

function List<T>({ items, renderItem, keyExtractor }: ListProps<T>) {
  return (
    <ul>
      {items.map((item) => (
        <li key={keyExtractor(item)}>{renderItem(item)}</li>
      ))}
    </ul>
  );
}

// Использование - T выводится автоматически
<List
  items={users}
  renderItem={(user) => <span>{user.name}</span>}
  keyExtractor={(user) => String(user.id)}
/>
```

⚠️ Generic-компоненты нельзя написать через `React.FC` - это одна из причин, почему предпочитают обычные функции.

## forwardRef

```tsx
const Input = forwardRef<HTMLInputElement, InputProps>(
  ({ label, error }, ref) => (
    <div>
      <label>{label}</label>
      <input ref={ref} />
      {error && <span>{error}</span>}
    </div>
  )
);
```

Первый generic-параметр - тип ref, второй - тип props.

## Polymorphic "as" prop

Паттерн для компонентов, которые рендерятся как разные HTML-элементы:

```tsx
type BoxProps<C extends React.ElementType> = {
  as?: C;
} & Omit<React.ComponentPropsWithoutRef<C>, 'as'>;

function Box<C extends React.ElementType = 'div'>({ as, ...rest }: BoxProps<C>) {
  const Component = as || 'div';
  return <Component {...rest} />;
}

<Box as="a" href="/home">link</Box>
<Box as="button" onClick={() => {}}>button</Box>
```

Продвинутый паттерн - используй в UI-библиотеках, а не в каждом компоненте.

## Частые ошибки

<b class="text-on-semi-light">children как string</b> - <span class="text-gray">Если указать `children: string`, компонент не примет JSX. Используй `React.ReactNode`.</span>

<b class="text-on-semi-light">Забытый null в useRef</b> - <span class="text-gray">`useRef<HTMLInputElement>()` без null создаёт мутабельный ref, а не DOM-ref. Для DOM всегда передавай `null`.</span>

<b class="text-on-semi-light">Event type mismatch</b> - <span class="text-gray">React-события - это `React.MouseEvent`, а не нативный `MouseEvent`. Не путай их.</span>

<b class="text-on-semi-light">Лишний as</b> - <span class="text-gray">Если приходится часто писать `as`, скорее всего, типы описаны неправильно. Ищи корневую причину.</span>

## Частые вопросы на собесе

<b class="text-on-semi-light">FC vs обычная функция - что выбрать?</b>
<span class="text-gray">Обычную функцию. FC не поддерживает generics, добавлял неявный children до React 18, и менее прозрачен.</span>

<b class="text-on-semi-light">Как типизировать контекст без дефолтного значения?</b>
<span class="text-gray">`createContext<T | null>(null)` + кастомный хук с проверкой на null и throw Error.</span>

<b class="text-on-semi-light">Разница между ReactNode и ReactElement?</b>
<span class="text-gray">ReactNode - любое рендерабельное значение (строки, числа, null, элементы). ReactElement - только JSX-элемент.</span>

<b class="text-on-semi-light">Как сделать generic-компонент?</b>
<span class="text-gray">Обычная функция с generic-параметром: `function List<T>(props: ListProps<T>)`. Через FC нельзя.</span>
