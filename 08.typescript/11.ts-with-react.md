# TypeScript с React

Как типизировать React-код: пропсы и `children`, `ReactNode` и `ReactElement`, хуки, события, контекст, `ref` как обычный prop, дженерик-компоненты, пропсы-объединения и полиморфный `as`. Спрашивают, чем `FC` отличается от обычной функции, как типизировать контекст без значения по умолчанию и чем `ReactNode` отличается от `ReactElement`. Глубже — почему `useState([])` даёт `never[]`, почему `e.target` не элемент и как типизировать prop `as`.

::tldr
- **Компонент — функция, принимающая объект пропсов.** Пропсы описывают типом и деструктурируют. `FC` ничего не добавляет: `children` неявно не даёт, дженериком быть не может.
- **`ReactNode` — всё, что React умеет отрисовать,** включая строки, числа, `null` и массивы. `ReactElement` — только результат JSX. Для `children` почти всегда нужен `ReactNode`.
- **Хуки выводят типы из начального значения.** Параметр нужен, когда начальное значение не описывает все возможные: `useState<User | null>(null)`, `useRef<HTMLInputElement>(null)`.
- **В обработчике React `currentTarget` типизирован элементом, а `target` — нет:** событие могло произойти на потомке. Значение поля читают из `e.currentTarget.value`.
- **Пропсы нативных элементов и чужих компонентов не переписывают, а берут:** `ComponentProps<'input'>`, `ComponentProps<typeof Button>`. На этом же строится полиморфный `as`.
::

## Компоненты и пропсы

```tsx
type ButtonProps = {
  label: string;
  variant?: 'primary' | 'ghost';
  onClick?: () => void;
};

function Button({ label, variant = 'primary', onClick }: ButtonProps) {
  return <button className={variant} onClick={onClick}>{label}</button>;
}

<Button />;                            // ошибка: нет label
<Button label="Купить" variant="danger" />;   // ошибка: нет такого варианта
```

Компонент — обычная функция с параметром-объектом. Значения по умолчанию задают в деструктуризации: `defaultProps` у функциональных компонентов React 19 в JSX игнорирует (подробно — в [Компонентах и JSX](/content/reactjs/components-and-jsx)). Возвращаемый тип обычно не пишут — он выводится.

### FC или функция

Вторая форма — тип `FC`:

```tsx
const Card: FC<{ title: string }> = ({ title }) => <h2>{title}</h2>;

<Card title="Чай">описание</Card>;   // ошибка: Property 'children' does not exist
```

Раньше `FC` добавлял `children` в пропсы неявно, и это была главная причина его избегать. Сейчас неявного `children` нет, и разница сводится к двум пунктам: `FC` нельзя сделать дженериком (параметр типа есть у функции, а не у константы с аннотацией), и он многословнее. Поэтому стандартом стала обычная функция. Ошибкой `FC` не является — это вопрос стиля.

### children

`children` — обычный prop, его тип пишут явно:

```tsx
function Panel({ children }: { children: ReactNode }) {
  return <section>{children}</section>;
}
```

| Тип | Что принимает |
| --- | --- |
| `ReactNode` | всё отрисовываемое: элементы, строки, числа, `bigint`, `boolean`, `null`, `undefined`, массивы и итерируемые объекты из них |
| `ReactElement` | только результат JSX или `createElement` |
| `React.JSX.Element` | то же, что `ReactElement` с любыми пропсами: тип выражения `<div />` |
| `string` | только текст |

Для `children` почти всегда нужен `ReactNode`: `ReactElement` не примет строку, а `string` — разметку. Объект не входит ни в один из них: `{{ a: 1 }}` в `children` — ошибка компиляции, потому что React не знает, как его отрисовать.

Глобального пространства имён `JSX` в типах React 19 больше нет: вместо `JSX.Element` пишут `React.JSX.Element` или импортируют тип: `import type { JSX } from 'react'`.

`ReactNode` разрешает `number`, поэтому `{count && <Badge />}` проходит проверку — и при `count === 0` выводит `0`. Компилятор этот баг не ловит, слева от `&&` ставят логическое выражение `count > 0`.

### Пропсы элементов и чужих компонентов

Свои пропсы для обёртки над `input` не переписывают, а берут готовые:

```tsx
type FieldProps = ComponentProps<'input'> & { label: string };

function Field({ label, ...rest }: FieldProps) {
  return <label>{label}<input {...rest} /></label>;
}

<Field label="Email" type="email" required autoComplete="email" />;
```

`ComponentProps<'input'>` — все атрибуты `input`, включая обработчики и `ref`. `ComponentProps<typeof Button>` достаёт пропсы чужого компонента, даже если библиотека их не экспортирует.

В React 19 `ref` — обычный prop функционального компонента, и `forwardRef` не нужен (подробно — в [Рефах, порталах и доступности](/content/reactjs/refs-portals-a11y)). В типах это выражено напрямую: `ComponentProps<'input'>['ref']` — `Ref<HTMLInputElement> | undefined`, его можно деструктурировать и передать дальше. `ComponentPropsWithoutRef` нужен, когда `ref` не должен входить в пропсы.

Пропсы описаны. Дальше — состояние внутри компонента.

## Хуки

### useState

Тип выводится из начального значения:

```tsx
const [count, setCount] = useState(0);           // number
const [items, setItems] = useState([]);          // never[] — в такой массив ничего не добавить
const [user, setUser] = useState<User | null>(null);
const [query, setQuery] = useState<string>();    // string | undefined
```

Параметр нужен, когда начальное значение не описывает всех будущих: `null` до загрузки, пустой массив. `useState([])` без параметра даёт `never[]`, и первый же `setItems([product])` — ошибка. Правильно: `useState<Product[]>([])`.

### useRef

Ref на DOM-элемент создают с `null`: элемент появится после монтирования.

```tsx
const inputRef = useRef<HTMLInputElement>(null);   // RefObject<HTMLInputElement | null>
<input ref={inputRef} />;
inputRef.current?.focus();
```

В типах React 19 `useRef` всегда требует аргумент, а `current` у результата изменяемый. Для изменяемого значения, которое не влияет на отрисовку, — `useRef<number | undefined>(undefined)` и прямое присваивание `timer.current = id`. Разделения на «ref для DOM» и «изменяемый ref», которое было в старых типах, больше нет.

### useReducer

Тип состояния и экшенов выводится из редьюсера, поэтому типизируют сам редьюсер. Экшены — размеченное объединение:

```tsx
type Action =
  | { type: 'add'; item: string }
  | { type: 'clear' }
  | { type: 'save' };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'add': return { ...state, items: [...state.items, action.item] };
    case 'clear': return { ...state, items: [] };
    case 'save': return { ...state, status: 'saving' };
  }
}

const [state, dispatch] = useReducer(reducer, { items: [], status: 'idle' });
dispatch({ type: 'add' });      // ошибка: нет item
dispatch({ type: 'remove' });   // ошибка: нет такого экшена
```

В ветке `case 'add'` компилятор знает, что `item` есть (подробно — в [Сужении типов](/content/typescript/type-narrowing)). Явные параметры типа у `useReducer` не нужны.

### Контекст без значения по умолчанию

Значение по умолчанию у контекста нужно, только если компонент может работать без провайдера. Для контекста авторизации или формы осмысленного значения нет, а заглушка `{ user: '', logout: () => {} }` прячет ошибку «забыли провайдер». Поэтому — `null` и свой хук:

```tsx
const AuthContext = createContext<Auth | null>(null);

function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth must be used inside <AuthProvider>');
  return ctx;   // Auth — null отсечён
}
```

Потребители получают `Auth` без проверок, а компонент без провайдера сразу падает с понятным сообщением — в проверке так и вышло. В React 19 провайдер — сам контекст: `<AuthContext value={...}>`.

От состояния — к событиям.

## События

Обработчики React получают не нативные события, а свои обёртки с общим интерфейсом: `MouseEvent`, `ChangeEvent`, `FormEvent`, `KeyboardEvent` из `react`. Их легко спутать с одноимёнными глобальными типами DOM, поэтому импортируют явно.

Если обработчик написан прямо в JSX, тип выводится сам:

```tsx
<input onChange={(e) => setQuery(e.currentTarget.value)} />;   // e: ChangeEvent<HTMLInputElement>
```

Если вынесен — тип пишут:

```tsx
const handleChange = (e: ChangeEvent<HTMLInputElement>) => onSearch(e.currentTarget.value);
const handleSubmit = (e: FormEvent<HTMLFormElement>) => { e.preventDefault(); };
```

### currentTarget и target

У события React `currentTarget` — элемент с обработчиком, и его тип известен: `EventTarget & HTMLButtonElement`. А `target` у `MouseEvent` — просто `EventTarget`: клик мог прийти с иконки внутри кнопки. Поэтому значение поля читают из `currentTarget`. В нативном DOM оба свойства — `EventTarget | null`, там React-удобства нет (подробно — в [Асинхронности и DOM](/content/typescript/async-and-dom)).

Исключение — `ChangeEvent`: его `target` для совместимости тоже типизирован элементом. На него полагаются в старом коде (`e.target.value`), но надёжнее `currentTarget`.

Хуки и события — повседневная работа. Остались приёмы, на которых строятся переиспользуемые компоненты.

## Переиспользуемые компоненты

### Дженерик-компоненты

Список, таблица, выпадающий список работают с любыми данными и должны сохранять их тип:

```tsx
type ListProps<T> = {
  items: T[];
  getKey: (item: T) => string | number;
  render: (item: T) => ReactNode;
};

function List<T>({ items, getKey, render }: ListProps<T>) {
  return <ul>{items.map((i) => <li key={getKey(i)}>{render(i)}</li>)}</ul>;
}

<List items={products} getKey={(p) => p.sku} render={(p) => p.title} />;   // p: Product
<List items={products} getKey={(p) => p.sku} render={(p) => p.price} />;   // ошибка: нет price
```

`T` выводится из `items`, и колбэки получают точный тип. Параметр можно указать и явно: `<List<Product> items={...} />`. Для стрелочной функции в `.tsx` нужна запятая: `<T,>(props) => ...` (подробно — в [Дженериках](/content/typescript/generics)). Здесь и становится видна разница с `FC`: у `const List: FC<ListProps<T>>` взять `T` неоткуда.

### Пропсы-объединения

Компонент, который бывает ссылкой или кнопкой, описывают размеченным объединением, а не набором необязательных пропсов:

```tsx
type ActionProps =
  | { kind: 'link'; href: string; children: ReactNode }
  | { kind: 'button'; onClick: () => void; children: ReactNode };

<Action kind="link" href="/cart">Корзина</Action>;      // ок
<Action kind="button" href="/cart" onClick={buy}>x</Action>;   // ошибка: у кнопки нет href
<Action kind="link">x</Action>;                          // ошибка: нужен href
```

Тип `{ href?: string; onClick?: () => void }` разрешил бы оба пропса сразу или ни одного. Если такие пропсы потом обернуть через `Omit`, объединение схлопнется — нужен распределяющий вариант (подробно — в [Утилитарных типах](/content/typescript/utility-types)).

### Полиморфный as

Компонент дизайн-системы меняет корневой тег: `<Box as="a" href="/cart">`. Требование к типам — пропсы должны зависеть от `as`: у ссылки есть `href`, у кнопки — `type` и `disabled`.

```tsx
type BoxProps<C extends ElementType> = {
  as?: C;
  children?: ReactNode;
} & Omit<ComponentPropsWithoutRef<C>, 'as' | 'children'>;

function Box<C extends ElementType = 'div'>({ as, children, ...rest }: BoxProps<C>) {
  const Tag: ElementType = as ?? 'div';
  return <Tag {...rest}>{children}</Tag>;
}

<Box as="a" href="/cart">Корзина</Box>;           // ок
<Box href="/cart">x</Box>;                        // ошибка: у div нет href
<Box as="button" type="submit" disabled>Купить</Box>;
<Box as={Price} value={490} />;                   // пропсы компонента Price
<Box as={Price} />;                               // ошибка: Price требует value
```

`C` выводится из значения `as`, `ComponentPropsWithoutRef<C>` даёт пропсы этого тега или компонента, а значение по умолчанию `'div'` срабатывает, когда `as` не передан. Внутри приходится ослабить тип до `ElementType`: компилятор не может проверить спред пропсов для произвольного `C`. Такие типы тяжелы для компилятора и подсказок, поэтому часть библиотек выбирает другой путь — `asChild` в Radix UI (подробно — в [Паттернах и дизайне компонентов](/content/reactjs/patterns-and-component-design)).

## Красные флаги в ответе

- **«`FC` нужен, чтобы получить `children`».** Неявного `children` в `FC` нет, их добавляют в пропсы явно.
- **«`children: ReactElement` — универсальный тип».** Он не принимает строки и числа, универсальный — `ReactNode`.
- **«`useState([])` — массив чего угодно».** Это `never[]`, нужен параметр.
- **«`e.target.value` — правильный способ прочитать поле».** Типизированный элемент — `currentTarget`, `target` может быть потомком.
- **«Для `ref` на свой компонент нужен `forwardRef`».** В React 19 `ref` — обычный prop и входит в `ComponentProps`.

## Как спрашивают на собеседовании

::question
FC или обычная функция — что выбрать?

#answer
Обычную функцию с типом пропсов: `function Button(props: ButtonProps)`. Она проще, может быть дженериком и не отличается по возможностям.

#more
Раньше `FC` неявно добавлял `children`, сейчас нет. `FC` нельзя сделать дженериком: у константы с аннотацией нет своего параметра типа. Возвращаемый тип компонента обычно выводится. `defaultProps` у функциональных компонентов в React 19 для JSX не применяется — значения по умолчанию задают в деструктуризации.
::

::question
Как типизировать контекст без значения по умолчанию?

#answer
`createContext<Auth | null>(null)` и свой хук, который проверяет `null` и бросает понятную ошибку. Потребители получают `Auth` без проверок.

#more
Заглушка вместо `null` прячет ошибку «забыли провайдер»: компонент молча работает с пустыми данными. Хук `useAuth` делает падение явным и сужает тип. В React 19 провайдер — сам контекст, `<AuthContext value={...}>`.
::

::question
В чём разница между ReactNode и ReactElement?

#answer
`ReactElement` — результат JSX или `createElement`. `ReactNode` — всё, что React может отрисовать: элементы, строки, числа, `boolean`, `null`, `undefined` и массивы. Для `children` нужен `ReactNode`.

#more
`React.JSX.Element` — тип выражения JSX, по сути `ReactElement` с любыми пропсами. Глобального `JSX` в типах React 19 нет. Объект не входит в `ReactNode` — это ошибка компиляции. `number` входит, поэтому `{count && <Badge />}` при нуле выведет `0`, и компилятор это пропустит.
::

::question
Как сделать дженерик-компонент?

#answer
Объявить функцию с параметром типа: `function List<T>(props: ListProps<T>)`. `T` выводится из пропсов, например из `items`, и колбэки вроде `render` получают точный тип элемента.

#more
Явно — `<List<Product> items={...} />`. Стрелка в `.tsx` требует запятую: `<T,>`. `FC` для дженерик-компонента не подходит. Если нужно ограничить данные, — `<T extends { id: string }>`.
::

::question
Как типизировать обработчик onChange?

#answer
`(e: ChangeEvent<HTMLInputElement>) => void` из `react`, значение — `e.currentTarget.value`. Если обработчик написан прямо в JSX, тип выводится сам.

#more
React-события — свои обёртки, не нативные `Event`, их импортируют из `react`. `currentTarget` типизирован элементом с обработчиком, `target` у большинства событий — просто `EventTarget`, потому что событие могло прийти с потомка. У `ChangeEvent` `target` для совместимости тоже элемент, но надёжнее `currentTarget`.
::

::question
Как типизировать полиморфный prop as?

#answer
Дженерик по типу элемента: `<C extends ElementType = 'div'>`, пропсы — `{ as?: C } & ComponentPropsWithoutRef<C>`. Тогда `<Box as="a">` принимает `href`, а `<Box as="button">` — `disabled`.

#more
Из `ComponentPropsWithoutRef<C>` убирают свои ключи через `Omit`, чтобы не было конфликтов. Внутри компонента тип тега ослабляют до `ElementType`. Такие типы дорогие для компилятора, поэтому есть альтернатива `asChild`, где поведение передаётся единственному ребёнку.
::

## Практика

::practice{title="Почему не добавляется товар?"}
```tsx
function Cart() {
  const [items, setItems] = useState([]);
  const add = (p: Product) => setItems([...items, p]);
  // Type 'Product' is not assignable to type 'never'
}
```

#solution
Из пустого массива компилятор вывел `never[]`: элементов нет, и их тип неизвестен. В массив `never` ничего добавить нельзя.

```tsx
const [items, setItems] = useState<Product[]>([]);
const add = (p: Product) => setItems((prev) => [...prev, p]);
```

Параметр типа нужен всегда, когда начальное значение не описывает будущие: пустой массив, `null` до загрузки. Функциональное обновление `prev => ...` заодно убирает зависимость от замкнутого `items` (подробно — в [Состоянии и событиях](/content/reactjs/state-and-events)). В проверке `useState([])` дал `never[]`, с параметром — `Product[]`.
::

::practice{title="Поле ввода с меткой"}
Сделай компонент `Field`: принимает `label` и любые атрибуты `input`, включая `ref`, и передаёт их полю. Неизвестные атрибуты должны давать ошибку.

#solution
```tsx
type FieldProps = ComponentProps<'input'> & { label: string };

function Field({ label, id, ...rest }: FieldProps) {
  const autoId = useId();
  const inputId = id ?? autoId;
  return (
    <>
      <label htmlFor={inputId}>{label}</label>
      <input id={inputId} {...rest} />
    </>
  );
}

const ref = useRef<HTMLInputElement>(null);
<Field label="Email" type="email" ref={ref} required />;   // ок
<Field label="Email" colour="red" />;                       // ошибка: нет такого атрибута
```

`ComponentProps<'input'>` включает все атрибуты, обработчики и в React 19 — `ref`, поэтому `forwardRef` не нужен: `ref` уходит в `rest` и попадает на `input`. `useId` связывает метку и поле, если `id` не передали. В проверке `ref` из пропсов дошёл до DOM-элемента, а лишний атрибут не скомпилировался.
::

::practice{title="Кнопка-ссылка без невозможных пропсов"}
Компонент `Action` рисует ссылку или кнопку. Сейчас тип такой, и можно передать и `href`, и `onClick`, или ни одного:

```tsx
type ActionProps = { href?: string; onClick?: () => void; children: ReactNode };
```

#solution
```tsx
type ActionProps =
  | { kind: 'link'; href: string; children: ReactNode }
  | { kind: 'button'; onClick: () => void; type?: 'button' | 'submit'; children: ReactNode };

function Action(props: ActionProps) {
  if (props.kind === 'link') return <a href={props.href}>{props.children}</a>;
  return <button type={props.type ?? 'button'} onClick={props.onClick}>{props.children}</button>;
}
```

Каждый вариант описывает только свои пропсы, и `href` у кнопки — ошибка. Внутри компонента сужение по `kind` даёт доступ к `href` или `onClick` без `!`. `type="button"` по умолчанию защищает от случайной отправки формы. В проверке `<Action kind="button" href="/cart">` и `<Action kind="link">` не скомпилировались, а оба корректных варианта отрисовали `a` и `button`.
::
