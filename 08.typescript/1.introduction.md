# Введение в TypeScript

Если ты пишешь на JavaScript больше пары месяцев, ты наверняка сталкивался с ситуацией: код работает, тесты проходят, а потом в проде вылезает `Cannot read property of undefined`. TypeScript создан именно для того, чтобы ловить такие ошибки ещё до запуска кода.

---

## Что такое TypeScript

<b class="text-on-semi-light">TypeScript</b> - <span class="text-gray">это superset над JavaScript, который добавляет статическую типизацию.</span>

Любой валидный JS-код - это валидный TS-код. TypeScript просто добавляет сверху систему типов, которая помогает находить баги на этапе компиляции, а не в рантайме.

```ts
// Обычный JS - работает и в TS
const name = 'Alice';
const age = 30;

// TS добавляет типы
const greeting: string = 'Hello';
const count: number = 42;
```

TypeScript разработан Microsoft, первый релиз вышел в 2012 году. Сейчас это стандарт индустрии - большинство крупных проектов на фронтенде и бэкенде используют его.

---

## Ключевые характеристики

| Характеристика | Описание |
|---|---|
| Статическая типизация | Типы проверяются на этапе компиляции, а не в рантайме |
| Компилируемый | Код проходит через компилятор `tsc`, который выдаёт чистый JS |
| Structural type system | Совместимость типов определяется структурой, а не именем |
| Type erasure | Все типы удаляются при компиляции - в JS не остаётся ничего от TS |

---

## Как работает TypeScript

Цепочка простая: `.ts` -> `tsc` -> `.js`. Компилятор проверяет типы, и если всё ок - генерирует JavaScript. Если есть ошибки типов - сообщает о них.

```ts
// input.ts
function greet(name: string): string {
  return `Hello, ${name}!`;
}

greet(42); // Ошибка компиляции: Argument of type 'number' is not assignable to parameter of type 'string'
```

```js
// output.js (после компиляции)
function greet(name) {
  return `Hello, ${name}!`;
}
```

Обрати внимание - в скомпилированном JS нет никаких типов. Это и есть <b class="text-on-semi-light">type erasure</b> - <span class="text-gray">типы существуют только на этапе разработки и компиляции, в рантайме их нет.</span>

Это значит, что ты не можешь проверить тип TypeScript в рантайме через `typeof` или `instanceof` (для интерфейсов и type alias). Для рантайм-проверок нужны другие подходы - type guards, Zod и подобные библиотеки.

---

## Преимущества

- **Ошибки на этапе компиляции** - ловишь баги до запуска кода, а не в проде
- **Автодополнение** - IDE точно знает, какие поля и методы доступны
- **Рефакторинг** - переименовал поле в интерфейсе, и компилятор покажет все места, которые нужно обновить
- **Документация через типы** - типы описывают контракт лучше, чем комментарии
- **Масштабируемость** - в проекте на 100k+ строк без типов ориентироваться почти невозможно

## Недостатки

- **Learning curve** - система типов TS может быть очень сложной (conditional types, mapped types, template literal types)
- **Build step** - нужен этап компиляции, что замедляет цикл разработки
- **Boilerplate** - для простых вещей иногда приходится писать много типов
- **Не все библиотеки типизированы** - хотя ситуация сильно улучшилась благодаря DefinitelyTyped

## Structural typing (Duck typing)

Это одна из самых важных концепций в TS. В отличие от Java или C#, где типы проверяются по имени, TypeScript проверяет структуру.

```ts
interface Point {
  x: number;
  y: number;
}

function logPoint(point: Point) {
  console.log(`${point.x}, ${point.y}`);
}

// Это НЕ Point, но имеет ту же структуру
const myObj = { x: 10, y: 20, z: 30 };

logPoint(myObj); // Работает! У объекта есть x и y - этого достаточно
```

<span class="text-gray">"Если что-то ходит как утка и крякает как утка - это утка." TS не волнует, как ты назвал тип. Важна только структура.</span>

## Type inference

TypeScript умеет автоматически выводить типы без явных аннотаций. И делает это очень хорошо.

```ts
// TS сам понимает, что это string
let name = 'Alice'; // type: string

// TS выводит тип возвращаемого значения
function add(a: number, b: number) {
  return a + b; // return type: number
}

// TS выводит тип массива
const numbers = [1, 2, 3]; // type: number[]

// TS выводит тип на основе условия
const value = Math.random() > 0.5 ? 'hello' : 42; // type: string | number
```

Хорошая практика - полагаться на inference там, где тип очевиден, и добавлять явные аннотации там, где это улучшает читаемость или предотвращает ошибки.

## Type annotations

<b class="text-on-semi-light">Type annotations</b> - <span class="text-gray">явное указание типов через двоеточие после имени переменной, параметра или возвращаемого значения.</span>

```ts
// Переменные
let age: number = 30;
let isActive: boolean = true;

// Параметры функции и возвращаемый тип
function getUser(id: number): { name: string; age: number } {
  return { name: 'Alice', age: 30 };
}

// Массивы
let items: string[] = ['a', 'b', 'c'];
```

## Type assertion

Иногда ты знаешь о типе больше, чем компилятор. Для этого есть type assertion.

```ts
// Синтаксис "as"
const input = document.getElementById('my-input') as HTMLInputElement;
input.value = 'hello';

// Angle bracket синтаксис (не работает в JSX)
const element = <HTMLInputElement>document.getElementById('my-input');

// Двойное assertion через unknown - крайняя мера
const value = 'hello' as unknown as number; // ⚠️ Опасно! Используй только если точно знаешь, что делаешь
```

Type assertion - это не приведение типов (casting). Оно не меняет значение в рантайме, а только говорит компилятору: "поверь мне, я знаю что это за тип".

## Инструменты

| Инструмент | Назначение |
|---|---|
| `tsc` | Официальный компилятор TypeScript |
| `ts-node` | Запуск TS-файлов напрямую в Node.js |
| `tsx` | Быстрая альтернатива ts-node (на основе esbuild) |
| `TS Playground` | Онлайн-среда для экспериментов с TypeScript |
| `SWC` | Сверхбыстрый компилятор на Rust (Vite, Next.js) |
| `esbuild` | Быстрый бандлер с поддержкой TS (но без проверки типов) |

⚠️ Важно: SWC и esbuild только убирают типы, но НЕ проверяют их. Для проверки типов всё равно нужен `tsc`.

## Частые вопросы на собесе

- **Что такое TypeScript и чем он отличается от JavaScript?** - TS - это superset JS, добавляющий статическую типизацию. Типы проверяются при компиляции и удаляются в рантайме.
- **Что такое type erasure?** - Все типы удаляются при компиляции в JS. В рантайме нет никакой информации о типах TS.
- **Что такое structural typing?** - TS проверяет совместимость типов по структуре (набору полей и их типов), а не по имени типа.
- **Чем type assertion отличается от type casting?** - Assertion не меняет значение, а только подсказывает компилятору. Casting (как в C++) реально преобразует значение.
- **Когда стоит использовать explicit annotations, а когда полагаться на inference?** - Inference - для локальных переменных и очевидных случаев. Annotations - для параметров функций, возвращаемых типов публичных API, и сложных выражений.
