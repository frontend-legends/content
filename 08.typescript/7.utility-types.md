# Utility types

TypeScript из коробки даёт набор готовых generic-типов, которые решают типовые задачи трансформации типов. Вместо того чтобы писать всё руками - берёшь готовый utility type и применяешь. Давай разберём каждый.

---

## Трансформация объектов

### Partial - все свойства становятся optional

```ts
interface User {
  id: number;
  name: string;
  email: string;
}

type PartialUser = Partial<User>;
// { id?: number; name?: string; email?: string }

function updateUser(id: number, updates: Partial<User>): void {
  // можно передать только те поля, которые меняем
}

updateUser(1, { name: 'Иван' }); // OK - email и id не обязательны
```

### Required - все свойства становятся обязательными

```ts
interface Config {
  host?: string;
  port?: number;
  debug?: boolean;
}

type StrictConfig = Required<Config>;
// { host: string; port: number; debug: boolean }

// Теперь нельзя пропустить ни одно поле
const config: StrictConfig = {
  host: 'localhost',
  port: 3000,
  debug: false,
};
```

### Readonly - все свойства только для чтения

```ts
interface Settings {
  theme: string;
  language: string;
}

const settings: Readonly<Settings> = {
  theme: 'dark',
  language: 'ru',
};

settings.theme = 'light'; // Ошибка: Cannot assign to 'theme' because it is a read-only property
```

## Выбор и исключение свойств

### Pick - выбрать конкретные свойства

```ts
interface Article {
  id: number;
  title: string;
  body: string;
  author: string;
  createdAt: Date;
}

type ArticlePreview = Pick<Article, 'id' | 'title' | 'author'>;
// { id: number; title: string; author: string }
```

### Omit - исключить свойства

```ts
type ArticleCreate = Omit<Article, 'id' | 'createdAt'>;
// { title: string; body: string; author: string }

// Удобно для форм создания - без id и даты
function createArticle(data: ArticleCreate): Article {
  return { ...data, id: Date.now(), createdAt: new Date() };
}
```

## Record - объект с типизированными ключами и значениями

```ts
type Role = 'admin' | 'user' | 'guest';

interface Permissions {
  canRead: boolean;
  canWrite: boolean;
  canDelete: boolean;
}

const rolePermissions: Record<Role, Permissions> = {
  admin: { canRead: true, canWrite: true, canDelete: true },
  user: { canRead: true, canWrite: true, canDelete: false },
  guest: { canRead: true, canWrite: false, canDelete: false },
};
```

`Record<K, T>` гарантирует, что для каждого ключа из `K` будет значение типа `T`. Если забудешь одну из ролей - TypeScript подскажет.

## Манипуляции с union-типами

### Exclude - исключить типы из union

```ts
type AllEvents = 'click' | 'hover' | 'focus' | 'blur';
type MouseEvents = Exclude<AllEvents, 'focus' | 'blur'>;
// 'click' | 'hover'
```

### Extract - извлечь типы из union

```ts
type StringOrNumber = Extract<string | number | boolean, string | number>;
// string | number
```

### NonNullable - убрать null и undefined

```ts
type MaybeString = string | null | undefined;
type DefiniteString = NonNullable<MaybeString>;
// string
```

## Утилиты для функций

### Parameters - типы параметров функции

```ts
function createUser(name: string, age: number, active: boolean) {
  // ...
}

type CreateUserParams = Parameters<typeof createUser>;
// [string, number, boolean]

// Можно использовать для spread
function wrappedCreateUser(...args: Parameters<typeof createUser>) {
  console.log('Creating user...');
  return createUser(...args);
}
```

### ReturnType - тип возвращаемого значения

```ts
function fetchData() {
  return { data: [] as string[], error: null as string | null };
}

type FetchResult = ReturnType<typeof fetchData>;
// { data: string[]; error: string | null }
```

### ConstructorParameters - параметры конструктора

```ts
class HttpClient {
  constructor(baseUrl: string, timeout: number) {}
}

type HttpClientArgs = ConstructorParameters<typeof HttpClient>;
// [string, number]
```

### InstanceType - тип экземпляра класса

```ts
class UserService {
  getUser(id: number) { return { id, name: 'test' }; }
}

type UserServiceInstance = InstanceType<typeof UserService>;
// UserService
```

## Работа с Promise

### Awaited - unwrap типа Promise

```ts
type PromiseString = Promise<string>;
type Result = Awaited<PromiseString>;
// string

// Работает с вложенными Promise
type Nested = Promise<Promise<number>>;
type FlatResult = Awaited<Nested>;
// number

// Полезно с ReturnType для async-функций
async function loadUser() {
  return { id: 1, name: 'Иван' };
}

type UserData = Awaited<ReturnType<typeof loadUser>>;
// { id: number; name: string }
```

## Строковые утилиты

```ts
type EventName = 'click';

type Upper = Uppercase<EventName>;      // 'CLICK'
type Lower = Lowercase<'HELLO'>;        // 'hello'
type Cap = Capitalize<EventName>;       // 'Click'
type Uncap = Uncapitalize<'Click'>;     // 'click'

// Практическое применение - генерация имён методов
type Getter<T extends string> = `get${Capitalize<T>}`;
type NameGetter = Getter<'name'>; // 'getName'
```

## Практические примеры

### Типизированная функция обновления через API

```ts
interface Product {
  id: number;
  name: string;
  price: number;
  description: string;
  inStock: boolean;
}

async function updateProduct(
  id: number,
  updates: Partial<Omit<Product, 'id'>>
): Promise<Product> {
  const response = await fetch(`/api/products/${id}`, {
    method: 'PATCH',
    body: JSON.stringify(updates),
  });
  return response.json();
}

// Передаём только нужные поля, id исключён из обновляемых
updateProduct(42, { price: 999, inStock: true });
```

### Конфиг через Record

```ts
type Environment = 'development' | 'staging' | 'production';

interface EnvConfig {
  apiUrl: string;
  debug: boolean;
  logLevel: 'verbose' | 'info' | 'error';
}

const configs: Record<Environment, EnvConfig> = {
  development: { apiUrl: 'http://localhost:3000', debug: true, logLevel: 'verbose' },
  staging: { apiUrl: 'https://staging.api.com', debug: true, logLevel: 'info' },
  production: { apiUrl: 'https://api.com', debug: false, logLevel: 'error' },
};
```

### Состояние формы с Pick и Omit

```ts
interface UserProfile {
  id: number;
  username: string;
  email: string;
  avatar: string;
  createdAt: Date;
  role: 'admin' | 'user';
}

// Форма редактирования - только изменяемые поля
type EditableFields = Pick<UserProfile, 'username' | 'email' | 'avatar'>;

// Или наоборот - все поля кроме системных
type UserFormData = Omit<UserProfile, 'id' | 'createdAt' | 'role'>;

// Состояние формы - все поля optional + флаги
interface FormState {
  values: Partial<EditableFields>;
  errors: Partial<Record<keyof EditableFields, string>>;
  touched: Partial<Record<keyof EditableFields, boolean>>;
}
```

## Таблица всех utility types

| <b class="text-on-semi-light">Utility Type</b> | <span class="text-gray">Описание</span> |
|---|---|
| `Partial<T>` | Все свойства становятся optional |
| `Required<T>` | Все свойства становятся обязательными |
| `Readonly<T>` | Все свойства становятся readonly |
| `Pick<T, K>` | Выбрать указанные свойства |
| `Omit<T, K>` | Исключить указанные свойства |
| `Record<K, T>` | Объект с ключами K и значениями T |
| `Exclude<T, U>` | Исключить типы U из union T |
| `Extract<T, U>` | Извлечь типы U из union T |
| `NonNullable<T>` | Убрать null и undefined |
| `Parameters<T>` | Tuple типов параметров функции |
| `ReturnType<T>` | Тип возвращаемого значения функции |
| `ConstructorParameters<T>` | Типы параметров конструктора |
| `InstanceType<T>` | Тип экземпляра класса |
| `Awaited<T>` | Развернуть тип из Promise |
| `Uppercase<S>` | Строку в верхний регистр |
| `Lowercase<S>` | Строку в нижний регистр |
| `Capitalize<S>` | Первая буква в верхний регистр |
| `Uncapitalize<S>` | Первая буква в нижний регистр |

## Частые вопросы на собесе

<b class="text-on-semi-light">В чём разница между Pick и Omit?</b>
<span class="text-gray">`Pick` - выбираем что оставить (белый список). `Omit` - выбираем что убрать (чёрный список). Результат может быть одинаковым, но подход разный. Если оставляем 2 из 10 свойств - проще Pick. Если убираем 2 из 10 - проще Omit.</span>

<b class="text-on-semi-light">Зачем Partial, если можно просто поставить ? на каждое свойство?</b>
<span class="text-gray">Partial работает с существующим типом - не нужно дублировать интерфейс. Если оригинальный тип изменится, Partial автоматически подхватит изменения.</span>

<b class="text-on-semi-light">Как работает Exclude на уровне реализации?</b>
<span class="text-gray">Это distributive conditional type: `type Exclude<T, U> = T extends U ? never : T`. Каждый член union проверяется отдельно - если он наследуется от U, то заменяется на never (и исчезает из union).</span>

<b class="text-on-semi-light">Можно ли комбинировать utility types?</b>
<span class="text-gray">Да, это основной паттерн. Например, `Partial<Omit<User, 'id'>>` - все поля кроме id, и все необязательные. Или `Readonly<Required<Config>>` - все поля обязательны и неизменяемы.</span>
