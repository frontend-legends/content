# Async и DOM

TypeScript отлично дружит с асинхронным кодом и DOM API. Но без явной типизации легко получить `any` там, где ожидаешь конкретный тип. Разберём, как правильно типизировать промисы, fetch-запросы, события и DOM-элементы.

---

## Типизация Promise

Каждый промис параметризован типом значения, которое он резолвит:

```ts
const p: Promise<string> = new Promise((resolve) => {
  resolve('hello');
});
```

<b class="text-on-semi-light">async-функции</b> - <span class="text-gray">всегда возвращают Promise. TypeScript это знает и автоматически оборачивает возвращаемый тип.</span>

```ts
async function getNumber(): Promise<number> {
  return 42; // return type - Promise<number>, не number
}
```

Даже если ты напишешь `return 42`, тип функции будет `Promise<number>`. Это не магия - так работает async/await на уровне спецификации.

---

## Awaited - разворачиваем вложенные промисы

Иногда промисы оказываются вложенными. `Awaited<T>` рекурсивно разворачивает тип до "голого" значения:

```ts
type A = Awaited<Promise<string>>;           // string
type B = Awaited<Promise<Promise<number>>>;  // number
type C = Awaited<boolean | Promise<string>>; // boolean | string
```

Это особенно полезно в generic-функциях, где ты не знаешь заранее, будет ли тип обёрнут в промис.

## Generic fetch wrapper

Самый частый паттерн - типизированная обёртка над fetch:

```ts
async function fetchJson<T>(url: string): Promise<T> {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json() as Promise<T>;
}

interface User {
  id: number;
  name: string;
}

const user = await fetchJson<User>('/api/user/1');
// user: User
```

⚠️ Важно: `res.json()` возвращает `Promise<any>`. Мы делаем `as Promise<T>` - это утверждение типа, а не реальная валидация. Если сервер вернёт не того формата данные, TypeScript тебя не спасёт в рантайме.

## Typed API client

Для больших проектов удобнее создать типизированный клиент:

```ts
interface ApiClient {
  get<T>(url: string): Promise<T>;
  post<T>(url: string, body: unknown): Promise<T>;
}

function createApiClient(baseUrl: string): ApiClient {
  async function request<T>(url: string, options?: RequestInit): Promise<T> {
    const res = await fetch(`${baseUrl}${url}`, {
      headers: { 'Content-Type': 'application/json' },
      ...options,
    });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json() as Promise<T>;
  }

  return {
    get: <T>(url: string) => request<T>(url),
    post: <T>(url: string, body: unknown) =>
      request<T>(url, { method: 'POST', body: JSON.stringify(body) }),
  };
}

const api = createApiClient('https://api.example.com');
const user = await api.get<User>('/users/1');
```

Можно добавить interceptors, refresh-токены, retry-логику - и всё это будет типизировано.

## Иерархия DOM-типов

DOM-типы в TypeScript выстроены в цепочку наследования:

```
EventTarget -> Node -> Element -> HTMLElement -> HTMLInputElement
                                              -> HTMLDivElement
                                              -> HTMLButtonElement
                                              ...
```

Чем конкретнее тип, тем больше свойств доступно. У `Element` нет `.value`, а у `HTMLInputElement` - есть.

### Основные DOM-типы

| Тип | Описание |
|-----|----------|
| `HTMLDivElement` | `<div>` |
| `HTMLInputElement` | `<input>` - есть `.value`, `.checked` |
| `HTMLButtonElement` | `<button>` - есть `.disabled`, `.type` |
| `HTMLFormElement` | `<form>` - есть `.submit()`, `.reset()` |
| `HTMLAnchorElement` | `<a>` - есть `.href`, `.target` |
| `HTMLImageElement` | `<img>` - есть `.src`, `.alt` |
| `HTMLSelectElement` | `<select>` - есть `.value`, `.options` |
| `HTMLTextAreaElement` | `<textarea>` - есть `.value`, `.rows` |

## document.querySelector и типизация

По умолчанию `querySelector` возвращает `Element | null`. Чтобы получить конкретный тип, используй generic:

```ts
// Без generic - Element | null
const el = document.querySelector('#email');

// С generic - HTMLInputElement | null
const input = document.querySelector<HTMLInputElement>('#email');

if (input) {
  input.value = 'test@mail.com'; // OK - value есть у HTMLInputElement
}
```

<b class="text-on-semi-light">Тег-селекторы</b> - <span class="text-gray">TypeScript автоматически выводит тип для тег-селекторов без generic.</span>

```ts
const div = document.querySelector('div');   // HTMLDivElement | null
const btn = document.querySelector('button'); // HTMLButtonElement | null
```

Это работает благодаря встроенной карте `HTMLElementTagNameMap`.

## Типизация событий

Основные типы событий:

| Тип | Когда |
|-----|-------|
| `Event` | Базовый тип для всех событий |
| `MouseEvent` | click, dblclick, mousedown, mousemove |
| `KeyboardEvent` | keydown, keyup, keypress |
| `InputEvent` | input (ввод текста) |
| `SubmitEvent` | submit формы |
| `FocusEvent` | focus, blur |
| `WheelEvent` | scroll колёсиком |
| `DragEvent` | drag and drop |

### addEventListener

```ts
const button = document.querySelector<HTMLButtonElement>('#btn');

button?.addEventListener('click', (e: MouseEvent) => {
  console.log(e.clientX, e.clientY);
});

const input = document.querySelector<HTMLInputElement>('#search');

input?.addEventListener('input', (e: Event) => {
  const target = e.target as HTMLInputElement;
  console.log(target.value);
});
```

TypeScript автоматически выводит тип события из имени в `addEventListener`. Так что явная аннотация `e: MouseEvent` не обязательна - она выведется из `'click'`.

## AbortController

`AbortController` полностью типизирован из коробки:

```ts
async function fetchWithTimeout<T>(url: string, ms: number): Promise<T> {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), ms);

  try {
    const res = await fetch(url, { signal: controller.signal });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json() as Promise<T>;
  } finally {
    clearTimeout(timeoutId);
  }
}
```

`AbortSignal` имеет свойство `aborted: boolean` и метод `addEventListener('abort', handler)`. Всё типизировано.

## Типизация ответов axios

Если используешь axios, generic работает ещё проще:

```ts
import axios from 'axios';

interface User {
  id: number;
  name: string;
}

// axios.get возвращает AxiosResponse<T>
const { data } = await axios.get<User>('/api/user/1');
// data: User
```

Axios из коробки поддерживает generic-параметр, который типизирует поле `data` в ответе.

## Частые вопросы на собесе

<b class="text-on-semi-light">Что возвращает async-функция?</b>
<span class="text-gray">Всегда `Promise<T>`, даже если внутри return не промис. TypeScript оборачивает автоматически.</span>

<b class="text-on-semi-light">Что делает Awaited?</b>
<span class="text-gray">Рекурсивно разворачивает вложенные Promise-типы до финального значения. `Awaited<Promise<Promise<string>>>` -> `string`.</span>

<b class="text-on-semi-light">Почему querySelector возвращает null?</b>
<span class="text-gray">Потому что элемент может не существовать в DOM. TypeScript заставляет тебя обработать этот случай через проверку или optional chaining.</span>

<b class="text-on-semi-light">Как получить value из input?</b>
<span class="text-gray">Нужно сузить тип до `HTMLInputElement` - через generic `querySelector<HTMLInputElement>()` или через `as HTMLInputElement`.</span>

<b class="text-on-semi-light">Безопасен ли as Promise при fetch?</b>
<span class="text-gray">Нет. Это утверждение типа, не валидация. Для рантайм-безопасности нужны схемы валидации (zod, valibot).</span>
